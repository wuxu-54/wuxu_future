# 项目规范

了解并建立清晰的 Figma 项目规范，是提升团队协作效率和保持产品设计一致性的关键。下面这个表格汇总了 Figma 项目规范的核心构成，希望能帮助你建立一个系统性的认知。

| 规范类别 | 主要内容与细分项 | 说明与示例 |
| :--- | :--- | :--- |
| **🎨 样式系统** | **颜色样式**  | 包含**主色、辅助色、中性色**等角色化分类 。建议使用语义化命名（如 `sys-primary`）而非视觉命名（如 `blue-500`）。支持**渐变**与**图像填充**样式 。 |
| | **文字样式**  | 通常按**功能/层级**分类，如 `Display`、`Headline`、`Body`、`Label` 等 。包含字体、字重、字号、行高、字距等属性 。Figma 中文字样式**不控制对齐方式**，需单独设置 。 |
| | **效果样式**  | 主要包括**阴影**（Drop Shadow）和**图层模糊/背景模糊**（Layer Blur/Background Blur）效果 。可将多个效果（如两个阴影加一个内阴影）保存为一个综合样式 。 |
| | **布局网格样式**  | 定义画布的**栅格系统**（行、列、网格），用于规范页面布局 。可以保存常用的栅格配置（如间距、边距），方便在不同画布中快速应用，保证布局统一 。 |
| **🧩 组件规范** | **基础组件**  | 指按钮、输入框、单选/复选框、下拉菜单、开关、图标等基础的、原子级的交互元素 。 |
| | **复杂容器组件**  | 由基础组件组合而成，如卡片、列表、导航栏、对话框等，是组织页面内容的"骨架" 。 |
| | **组件状态**  | 定义组件的不同交互状态，例如按钮的默认、悬停、聚焦、按下、禁用等状态 。 |
| | **组件属性**  | - **变体属性**：管理同一组件的不同状态、尺寸或样式 。<br>- **实例交换属性**：方便快速切换嵌套组件（如图标）。<br>- **文本属性**：允许在右侧面板直接修改组件内的文字内容 。<br>- **布尔属性**：控制组件内特定图层（如图标）的显示或隐藏 。 |
| **📐 设计原则与变量** | **布局与间距**  | 通常基于**网格系统**（如 4px 或 8px 基准网格）来定义间距尺度，并创建间距组件以保持一致性 。 |
| | **形状与圆角**  | 定义如圆角、锐角等形状样式，并规范各类组件（如按钮、卡片）的圆角值 。 |
| | **设计令牌/变量**  | 通过"规范映射表"或变量来关联设计元素与开发代码，提高协作效率，例如将颜色、字体等常用变量与代码关联 。 |
| **📚 资源与管理** | **设计资源**  | 提供设计套件（如 Figma 文件链接）和开发资源（如 Storybook 链接），方便同步使用 。 |
| | **文件与命名管理**  | 建立清晰的**文件和文件夹组织结构**、**图层和组件的命名规范**（如使用 BEM 方法），方便团队查找和维护 。 |
| | **版本控制与更新日志**  | 利用 Figma 的版本历史功能，并维护更新日志，记录组件的迭代、优化或废弃情况，确保设计开发同步 。 |

## 💁 规范的使用与管理建议

建立规范很重要，但有效地使用和管理它们才能发挥其最大价值。

* **发布与启用团队库**：将定义好的样式和组件**发布为团队库**（Team Library）。团队成员在自己的设计文件中**启用这些库**后，就可以直接使用并保持同步更新 。
* **利用组件属性**：对于组件，尤其是复杂组件，善用**变体、实例交换、文本和布尔属性**，可以极大提升组件的灵活性和使用效率，减少为微小变化而创建大量组件的情况 。
* **保持简洁与可扩展**：在创建样式和组件初期，建议保持**克制**，优先满足核心需求，避免体系过于臃肿 。同时，结构要具有可扩展性，以适应未来的业务发展。
* **规范落地与协作**：定期的**设计审查**有助于确保规范被正确遵循 。同时，利用 Figma 内置的**评论功能**等工具，可以促进团队沟通和反馈，让规范在迭代中不断完善 。

## 💎 总结

一个优秀的 Figma 项目规范体系，通常以**样式系统**和**组件库**为核心，并辅以清晰的**布局原则、设计变量**以及**资源管理**流程。这一切最好再搭配上**团队库**的发布，从而实现设计一致性、协作高效性和快速迭代的终极目标。
