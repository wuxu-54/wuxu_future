# Frame（画框）和 Group（组）

在 Figma 中，`Frame`（画框）和 `Group`（组）是组织设计元素的两个核心容器，理解它们的区别对提升设计效率至关重要。虽然它们都能把多个图层归拢在一起，但其能力和适用场景完全不同。

下面这个表格清晰地展示了它们的核心区别。

| 特性维度 | 🎯 Frame（画框） | 👥 Group（组） |
| :--- | :--- | :--- |
| **容器类型** | **独立容器**，可脱离内容单独存在 | **依赖容器**，尺寸由内容决定 |
| **尺寸行为** | 尺寸独立，不随子元素自动调整 | 尺寸自动适应子元素组合后的外边界 |
| **调整大小时** | 子元素可通过 **Constraints（约束）** 定义响应规则 | 子元素通常会**等比缩放** |
| **核心功能** | 支持**自动布局**、**裁切内容**、**布局网格**、**用作原型画板**、**滚动设置** | 主要用于**临时组合**、**统一移动/缩放** |
| **快捷键** | `⌘ + Option + G` (Mac) / `Ctrl + Alt + G` (Win)  | `⌘ + G` (Mac) / `Ctrl + G` (Win)  |

## 🔎 深入理解与使用场景

了解基础差异后，我们来看看它们各自在哪些场景下能大放异彩。

### 何时使用 Frame？

当你的设计需要**结构、规则和响应性**时，Frame 是你的不二之选。它非常适合以下情况：

- **创建界面画板**：为网页或应用屏幕创建一个固定的设计区域，就像传统设计工具中的画板。
- **构建可复用的组件**：Frame 是创建 **Component（组件）** 的基础。在开始制作组件前，先用 Frame 构建好结构。
- **应用自动布局**：这是 Frame 最强大的功能之一。当你需要元素在**水平或垂直方向上有序、等间距排列**，并且希望它们能在内容改变时自动调整尺寸，就必须使用 **Auto Layout Frame（自动布局画框）**。按钮、列表和导航栏是典型的例子。
- **需要滚动或裁切内容**：在制作原型时，如果希望一个区域可以滚动（如一个长长的列表），必须将内容放在 Frame 中并开启滚动设置。同样，如果需要隐藏超出边界的内容（例如一个圆形头像），开启 **Clip Content（裁切内容）** 功能即可。

### 何时使用 Group？

Group 更像是一个**临时性的管理工具**，它简单、轻量，适用于：

- **临时整理图层**：当你想把几个零散的元素（如图标和说明文字）临时捆绑在一起，方便同时移动或选择，用 Group 非常合适。
- **保持相对比例的组合**：如果你有一个由多个形状组成的 Logo，并且希望缩放时所有部分能**严格保持比例**，那么成组是很好的选择。
- **快速归类**：在设计的探索阶段，快速将一堆元素归组，让图层列表更清晰。由于可以随时无损耗地取消编组，用它来做临时整理几乎没有风险。

## 💡 实践技巧与常见误区

1. **Frame 是更优的默认选择**
    在现代 UI 设计中，由于响应式布局和组件化的需求，**绝大多数情况下，你都应该优先使用 Frame**。它提供了更强大的控制力，并且可以轻松地转换为组件。

2. **“成组”的缩放陷阱**
    使用常规方法调整 Group 的大小时，其内部的**文字大小、描边和阴影效果不会智能缩放**，这可能导致视觉不一致。如果需要对包含此类属性的元素进行精细缩放，建议使用专门的缩放工具（快捷键 `K`），或者更佳的做法是：将它们放入 Frame 中并设置好约束。

3. **嵌套使用**
    一个强大的工作流往往涉及嵌套。你可以在一个大的 Frame（如整个屏幕）内，使用多个嵌套的 Auto Layout Frame 来构建复杂的界面模块，同时在局部使用 Group 进行简单的元素管理。

总而言之，你可以这样理解：**`Frame` 是为构建现代、响应式用户界面而生的“智能建筑模块”，而 `Group` 则更像是一把方便的“临时打包绳”**。
