# 交互简介

>动效要单独处理，不要与设计图夹杂在一起，动效会破坏原设计稿。 复杂高端的动效需要AE等专业软件实现。

Figma 的交互功能是连接设计元素、模拟用户操作流程的核心工具，能够将静态设计转化为可交互原型，帮助团队预览产品体验、验证逻辑合理性。以下从 **核心构成、交互类型、设置方法、高级功能** 及 **注意事项** 等方面详细解析：

## **一、交互的核心构成**  

Figma 交互的本质是“触发条件→目标→过渡效果”的逻辑链，三要素缺一不可：  

| **构成要素**       | **说明**                                                                 |
|--------------------|--------------------------------------------------------------------------|
| **触发条件（Trigger）** | 用户触发交互的行为（如点击、悬停、滑动等），决定“何时执行交互”。         |
| **目标（Destination）** | 交互指向的对象（如另一页面、组件变体、叠加层等），决定“去哪里”。         |
| **过渡动画（Animation）** | 从触发到目标的过渡效果（如滑动、淡入、智能动画等），决定“如何过去”。     |  

## **二、触发条件（Trigger）：交互的“开关”**  

Figma 支持多种触发方式，覆盖不同设备（桌面端/移动端）和操作场景：  

| **触发类型**       | **适用场景**                                                                 | **注意事项**                                                                 |
|--------------------|------------------------------------------------------------------------------|------------------------------------------------------------------------------|
| **On Click（点击）** | 最常用触发方式，模拟按钮、链接的点击操作。                                   | 移动端和桌面端通用，是交互的基础触发条件。                                   |
| **On Hover（悬停）** | 桌面端场景，如导航菜单展开、按钮状态变化（默认→悬停）。                       | 移动端无“悬停”行为，需替换为“On Tap（点击）”或“On Long Press（长按）”。     |
| **On Tap（轻触）**  | 移动端专用，模拟屏幕点击（与 On Click 功能类似，但更贴合移动端交互逻辑）。     | 建议移动端原型优先使用，增强真实感。                                         |
| **On Long Press（长按）** | 移动端场景，如弹出操作菜单（如微信长按消息弹出“转发”选项）。                  | 可设置长按时长（默认0.5秒，支持0.1-2秒）。                                   |
| **On Drag（拖动）** | 模拟滑动操作，如拖拽元素、滑动切换图片（轮播图）。                             | 需配合“滚动区域”或“位置变化”使用，适合滑动切换场景。                         |
| **After Delay（延迟后）** | 自动触发，无需用户操作，如页面加载完成后自动弹出弹窗、倒计时结束跳转。         | 可设置延迟时间（默认0.5秒，支持0.1-10秒），适合自动流程（如引导页）。         |
| **On Scroll（滚动时）** | 滚动到特定位置触发，如滚动到页面底部显示“回到顶部”按钮、滚动时导航栏样式变化。 | 需先为帧开启“滚动”属性（在右侧面板设置滚动方向），否则无法触发。               |

## **三、目标（Destination）：交互的“终点”**  

触发交互后，原型会跳转到指定目标，常见目标类型如下：  

| **目标类型**       | **说明**                                                                 | **适用场景**                                                                 |
|--------------------|--------------------------------------------------------------------------|------------------------------------------------------------------------------|
| **Frame（帧）**    | 跳转至同一文件中的其他帧（如从“首页”帧跳转到“详情页”帧）。                 | 页面级跳转，是最基础的目标类型。                                             |
| **Component Variant（组件变体）** | 切换同一组件的不同变体（如按钮从“默认”变体切换到“点击”变体）。             | 组件状态变化（如开关的“开/关”、输入框的“默认/聚焦”）。                       |
| **Overlay（叠加层）** | 在当前帧上方显示悬浮内容（如弹窗、下拉菜单、侧边栏）。                       | 无需离开当前页面的临时内容（如确认弹窗、筛选菜单）。                           |
| **Previous（返回）** | 跳转回上一帧（模拟“返回”按钮功能）。                                       | 多级页面跳转中，方便用户回溯（如详情页→列表页→首页）。                       |
| **URL（链接）**    | 跳转到外部网页（如点击“帮助中心”跳转到官网文档）。                           | 需要关联外部资源的场景，需输入完整URL（如<https://example.com）。>              |

## **四、过渡动画（Animation）：交互的“过渡效果”**  

动画决定了从起点到目标的过渡方式，影响原型的流畅度和真实感。Figma 提供多种预设动画：  

| **动画类型**         | **效果说明**                                                                 | **适用场景**                                                                 |
|----------------------|------------------------------------------------------------------------------|------------------------------------------------------------------------------|
| **None（无动画）**   | 瞬间切换，无过渡效果。                                                       | 快速跳转场景（如后台系统的页面切换）。                                         |
| **Dissolve（淡入淡出）** | 起点帧淡出，目标帧淡入，适合无关联元素的切换。                               | 页面风格差异大的场景（如从列表页到表单页）。                                   |
| **Push（推送）**     | 目标帧从指定方向（上/下/左/右）“推走”起点帧，模拟物理滑动。                   | 线性流程的页面切换（如引导页、步骤条），增强方向感。                           |
| **Slide（滑动）**    | 目标帧从指定方向滑入，起点帧保留在后方（不被推走）。                           | 层级化页面跳转（如从首页滑入详情页，可暗示“返回路径”）。                       |
| **Smart Animation（智能动画）** | 自动识别同名元素的属性变化（位置、大小、颜色等），生成平滑过渡。               | 元素状态变化（如按钮移动、卡片缩放、数字变化），无需手动设置关键帧（详见前文）。 |
| **Scale（缩放）**    | 目标帧从起点帧中心缩放显示，增强聚焦感。                                     | 从缩略图到详情页的切换（如图片点击放大）。                                   |

**动画参数设置**：  

- **Duration（时长）**：控制动画持续时间（0.1-5秒），越快越简洁（如0.2秒），越慢越强调（如0.5秒）。  
- **Easing（缓动）**：控制动画节奏（如 `Ease Out` 适合点击反馈，`Linear` 适合匀速滑动）。  

## **五、高级交互功能**  

### 1. **叠加层（Overlays）交互**  

叠加层是悬浮在当前帧上方的内容（如弹窗），支持特殊交互设置：  

- **触发方式**：从起点帧拖线到叠加层帧，在右侧面板选择“Overlay”。  
- **位置设置**：可固定在屏幕中心、顶部、底部等（如底部弹窗、顶部通知条）。  
- **关闭方式**：  
  - 为叠加层内的“关闭按钮”添加交互，目标选择“Close Overlay”；  
  - 勾选“Dismiss on Click Outside”（点击外部关闭），模拟真实弹窗行为。  

### 2. **嵌套交互（Nested Interactions）**  

组件内部或叠加层内的交互，不影响父级页面：  

- 例：在“弹窗”叠加层中，点击“确定”按钮触发弹窗关闭（内部交互），而不影响底层页面。  
- 注意：嵌套交互的目标需在同一组件/叠加层内，避免层级混乱。  

### 3. **滚动行为（Scroll Behavior）**  

为帧设置滚动属性，实现长页面或横向滑动效果：  

- 在右侧面板勾选“Scrolling”，选择滚动方向（Vertical/Horizontal）；  
- 结合“On Scroll”触发条件，实现滚动时的动态效果（如导航栏吸顶）。  

### 4. **条件逻辑模拟**  

Figma 无原生“if-else”逻辑，但可通过以下方式模拟：  

- **多交互分支**：同一元素添加多个触发条件（如按钮点击时，根据不同场景跳转到A帧或B帧）；  
- **变体切换**：用组件变体表示不同状态（如“登录成功”“登录失败”），通过交互切换变体。  

### 5. **键盘与游戏手柄交互**  

适合桌面应用或游戏原型：  

- 在触发条件中选择“Key Press”，支持Enter、Esc、方向键等键盘事件；  
- 游戏手柄交互（如A键、方向键）需在“Gamepad”中设置，适合主机端原型。  

## **六、交互设置步骤（完整流程）**  

1. **准备设计元素**：创建帧（页面）、组件（含变体），确保图层/帧命名清晰（避免重名导致交互错乱）。  
2. **进入原型模式**：点击顶部工具栏「Prototype」（或按 `Shift + E`），此时帧边缘会显示蓝色交互区域。  
3. **添加交互线**：从起点元素（帧边缘或组件）拖动蓝色连接线到目标（另一帧/变体/叠加层）。  
4. **配置三要素**：在右侧面板设置触发条件（如On Click）、过渡动画（如Push）、动画参数（时长0.3秒，Ease Out）。  
5. **预览与调试**：点击顶部「Play」按钮（或按 `Cmd/Ctrl + Enter`）进入预览模式，测试交互是否符合预期。  

## **七、注意事项与最佳实践**  

1. **命名规范**：  
   - 帧和组件需命名清晰（如“首页-导航栏”“按钮-主要-点击态”），避免同名导致Smart Animation识别错误。  
   - 叠加层帧建议命名为“弹窗-确认”“菜单-下拉”，便于团队理解。  

2. **设备适配**：  
   - 移动端原型避免使用“On Hover”（无悬停行为），改用“On Tap”或“On Long Press”。  
   - 不同尺寸的帧（如手机/平板）建议分开设置交互，避免适配问题。  

3. **性能优化**：  
   - 同一帧内避免超过10个同时触发的动画，复杂动画（如多元素Smart Animation）可能导致卡顿。  
   - 大尺寸图片（如超过2000px）会拖慢原型预览，建议压缩后使用。  

4. **逻辑一致性**：  
   - 相同类型元素保持交互统一（如所有“返回”按钮都用“Previous”目标+“Slide Left”动画）。  
   - 复杂流程（如支付）建议先用Flow功能梳理路径，再添加交互，避免逻辑漏洞。  

5. **测试场景覆盖**：  
   - 测试所有分支场景（如表单提交成功/失败、登录正确/错误）。  
   - 在目标设备（如iPhone、Android手机）上预览，确保交互手感符合真实设备。  

## **总结**  

Figma 交互功能通过“触发条件→目标→动画”的逻辑，实现了从静态设计到可交互原型的转化。掌握基础要素后，可通过叠加层、嵌套交互、滚动行为等高级功能模拟复杂用户体验。核心原则是：**逻辑清晰、适配场景、保持一致**，让原型既能准确传达设计意图，又能提供接近真实产品的体验。
