# coroutineScope + awaitAll()

## 一、核心概念：`coroutineScope` + `awaitAll()` 是什么？

`coroutineScope` 是 Kotlin 协程的**作用域构建器**，`awaitAll()` 是挂起函数，两者结合是「批量执行异步任务、等待所有任务完成并统一获取结果」的经典写法，核心价值是：

- `coroutineScope`：创建子协程作用域，**挂起当前协程**（非阻塞线程），直到所有子协程执行完毕；若任意子协程抛异常，会取消所有子协程并向上传播异常。
- `awaitAll()`：接收多个 `Deferred<T>`（`async` 创建的异步任务），**挂起等待所有任务完成**，返回与入参顺序一致的结果列表；若任意任务失败，立即抛出异常，未完成的任务会被取消。

## 二、基础用法（Android 场景示例）

### 场景：批量请求多个网络接口，等待所有结果返回后统一处理

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.async

// 模拟网络请求函数（挂起函数）
suspend fun fetchData(api: String): String {
    delay(1000) // 模拟网络耗时
    return "Result from $api"
}

// 核心逻辑：coroutineScope + awaitAll()
suspend fun batchFetchData(): List<String> = coroutineScope {
    // 1. 用 async 创建多个异步任务（Deferred），并行执行
    val task1 = async { fetchData("API-1") }
    val task2 = async { fetchData("API-2") }
    val task3 = async { fetchData("API-3") }

    // 2. awaitAll() 等待所有任务完成，返回结果列表
    return@coroutineScope listOf(task1, task2, task3).awaitAll()
}

// 调用示例（如在 ViewModel 中）
fun doBatchRequest() {
    viewModelScope.launch(Dispatchers.IO) {
        try {
            val results = batchFetchData()
            // 所有任务完成后处理结果（顺序：API-1 → API-2 → API-3）
            results.forEach { println(it) }
        } catch (e: Exception) {
            // 处理任意任务的异常
            println("请求失败：${e.message}")
        }
    }
}
```

### 输出结果（约 1 秒后，并行执行总耗时 = 最长单个任务耗时）：

```
Result from API-1
Result from API-2
Result from API-3
```

## 三、异常处理

### 1. 默认行为：「快速失败」+ 取消所有任务

若任意子任务抛异常，`awaitAll()` 会**立即抛出该异常**，`coroutineScope` 会取消所有未完成的子协程，且异常向上传播：

```kotlin
suspend fun batchFetchWithError(): List<String> = coroutineScope {
    val task1 = async { fetchData("API-1") }
    val task2 = async { 
        delay(500)
        throw RuntimeException("API-2 请求失败") // 中途抛异常
    }
    val task3 = async { fetchData("API-3") }

    return@coroutineScope listOf(task1, task2, task3).awaitAll()
}

// 调用后会立即捕获到 API-2 的异常，task1/task3 被取消
```

### 2. 容错处理：单个任务失败不影响其他（结合 `supervisorScope`）

若需要「即使部分任务失败，也要等待所有任务完成并获取成功结果」，需替换 `coroutineScope` 为 `supervisorScope`（异常不传播、不取消其他子协程），并手动捕获每个任务的异常：

```kotlin
suspend fun batchFetchWithTolerance(): List<String?> = supervisorScope {
    val task1 = async { runCatching { fetchData("API-1") }.getOrNull() }
    val task2 = async { runCatching { 
        delay(500)
        throw RuntimeException("API-2 失败") 
    }.getOrNull() } // 捕获异常，返回 null
    val task3 = async { runCatching { fetchData("API-3") }.getOrNull() }

    return@supervisorScope listOf(task1, task2, task3).awaitAll()
}

// 调用结果：[Result from API-1, null, Result from API-3]
```

## 四、关键特性 & 注意事项

| 特性                | 说明                                                                 |
|---------------------|----------------------------------------------------------------------|
| 执行方式            | 所有 `async` 任务**并行执行**（默认复用协程池线程），总耗时 = 最长单个任务耗时 |
| 结果顺序            | `awaitAll()` 返回的列表顺序 ≡ 传入 `Deferred` 的顺序（与任务完成顺序无关） |
| 线程调度            | 可通过 `async(Dispatchers.IO) { ... }` 为单个任务指定调度器          |
| 作用域生命周期      | `coroutineScope` 会**挂起当前协程**（非阻塞线程），适合在挂起函数中使用 |
| 与 `joinAll()` 区别 | `joinAll()` 仅等待任务完成，不获取结果；`awaitAll()` 等待并获取结果    |

## 五、常见场景对比

| 需求                          | 推荐写法                                  |
|-------------------------------|-------------------------------------------|
| 批量执行任务 + 获取所有结果    | `coroutineScope + async + awaitAll()`     |
| 批量执行任务 + 不关心结果      | `coroutineScope + launch + joinAll()`     |
| 容错：单个任务失败不影响其他  | `supervisorScope + async + runCatching + awaitAll()` |
| 串行执行任务（按顺序）        | 直接顺序调用挂起函数（无需 `awaitAll()`） |

## 六、Android 实战小贴士

1. **避免主线程阻塞**：务必在 `Dispatchers.IO`/`Dispatchers.Default` 中执行 `awaitAll()`，不要在主线程（`Dispatchers.Main`）执行耗时批量任务；
2. **生命周期绑定**：在 Android 中，建议结合 `viewModelScope`/`lifecycleScope` 使用（自动取消协程，避免内存泄漏）；
3. **大数据/高耗时任务**：若任务数过多（如 >100），可配合 `CoroutineDispatcher` 限制并发数（如 `newFixedThreadPoolContext(5, "BatchPool")`）。

## 异常处理

以下是 `coroutineScope + awaitAll()` 异常处理的 **3 个核心场景代码示例**（基于 Android ViewModel 实战场景），覆盖「快速失败」「容错执行」「全量结果/错误收集」，注释详细且可直接复用：

## 前置准备：基础工具类 & 模拟任务

先定义「模拟异步任务」和「结果封装类」（用于精准收集成功/失败信息）：

```kotlin
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.*
import kotlinx.coroutines.async
import java.lang.RuntimeException

// 封装任务结果：区分成功/失败（比返回 null 更清晰）
sealed class TaskResult<out T> {
    data class Success<out T>(val data: T) : TaskResult<T>()
    data class Failure(val error: Throwable) : TaskResult<Nothing>()
}

// 模拟异步任务（如网络请求/数据库操作）
// 参数：taskName 任务名，fail 是否强制失败，delayMs 耗时
suspend fun simulateAsyncTask(
    taskName: String,
    fail: Boolean = false,
    delayMs: Long = 1000
): String {
    delay(delayMs) // 模拟耗时
    if (fail) {
        throw RuntimeException("[$taskName] 执行失败")
    }
    return "[$taskName] 执行成功，结果：$taskName-result"
}
```

## 场景 1：默认快速失败（任意任务失败 → 立即抛异常 + 取消所有任务）

**行为**：只要有一个任务失败，`awaitAll()` 会立即抛出异常，`coroutineScope` 会取消所有未完成的任务，适合「所有任务必须全部成功」的场景（如批量提交表单）。

```kotlin
class TaskViewModel : ViewModel() {
    // 快速失败模式：任意任务失败则整体失败
    fun executeFastFailTask() {
        viewModelScope.launch(Dispatchers.IO) {
            try {
                val results = coroutineScope {
                    // 创建3个异步任务（任务2强制失败）
                    val task1 = async { simulateAsyncTask("任务1") }
                    val task2 = async { simulateAsyncTask("任务2", fail = true) } // 失败任务
                    val task3 = async { simulateAsyncTask("任务3") }

                    // 等待所有任务完成（任务2失败会立即抛异常）
                    listOf(task1, task2, task3).awaitAll()
                }

                // 所有任务成功才会执行到这里
                println("所有任务执行成功：$results")
            } catch (e: Exception) {
                // 捕获到任务2的异常，任务1/3已被取消
                println("快速失败：${e.message}") 
                // 输出：快速失败：[任务2] 执行失败
            }
        }
    }
}
```

## 场景 2：容错执行（单个任务失败 → 不影响其他，仅返回 null）

**行为**：用 `supervisorScope` 替代 `coroutineScope`（异常不传播、不取消其他任务），结合 `runCatching` 捕获单个任务异常，失败时返回 `null`，适合「部分任务失败不影响整体」的场景（如批量加载列表数据）。

```kotlin
class TaskViewModel : ViewModel() {
    // 容错模式：单个任务失败，其他任务继续执行
    fun executeTolerantTask() {
        viewModelScope.launch(Dispatchers.IO) {
            val results: List<String?> = supervisorScope {
                // 每个任务用 runCatching 捕获异常，失败返回 null
                val task1 = async { runCatching { simulateAsyncTask("任务1") }.getOrNull() }
                val task2 = async { runCatching { simulateAsyncTask("任务2", fail = true) }.getOrNull() }
                val task3 = async { runCatching { simulateAsyncTask("任务3") }.getOrNull() }

                listOf(task1, task2, task3).awaitAll()
            }

            // 处理结果：成功返回字符串，失败返回 null
            results.forEachIndexed { index, result ->
                println("任务${index+1}结果：${result ?: "执行失败"}")
            }
            // 输出：
            // 任务1结果：[任务1] 执行成功，结果：任务1-result
            // 任务2结果：执行失败
            // 任务3结果：[任务3] 执行成功，结果：任务3-result
        }
    }
}
```

## 场景 3：全量结果收集（收集成功+失败详情）

**行为**：基于 `TaskResult` 封装类，不仅返回成功结果，还记录每个任务的失败原因，适合「需要精准知道每个任务状态」的场景（如批量上传文件，需展示每个文件的上传结果）。

```kotlin
class TaskViewModel : ViewModel() {
    // 全量结果收集：记录每个任务的成功/失败详情
    fun executeCollectAllResultTask() {
        viewModelScope.launch(Dispatchers.IO) {
            val taskResults: List<TaskResult<String>> = supervisorScope {
                // 每个任务封装为 TaskResult（成功/失败）
                val task1 = async {
                    runCatching { simulateAsyncTask("任务1") }
                        .fold(
                            onSuccess = { TaskResult.Success(it) },
                            onFailure = { TaskResult.Failure(it) }
                        )
                }
                val task2 = async {
                    runCatching { simulateAsyncTask("任务2", fail = true) }
                        .fold(
                            onSuccess = { TaskResult.Success(it) },
                            onFailure = { TaskResult.Failure(it) }
                        )
                }
                val task3 = async {
                    runCatching { simulateAsyncTask("任务3") }
                        .fold(
                            onSuccess = { TaskResult.Success(it) },
                            onFailure = { TaskResult.Failure(it) }
                        )
                }

                listOf(task1, task2, task3).awaitAll()
            }

            // 遍历结果，区分成功/失败
            taskResults.forEachIndexed { index, result ->
                when (result) {
                    is TaskResult.Success -> println("任务${index+1}成功：${result.data}")
                    is TaskResult.Failure -> println("任务${index+1}失败：${result.error.message}")
                }
            }
            // 输出：
            // 任务1成功：[任务1] 执行成功，结果：任务1-result
            // 任务2失败：[任务2] 执行失败
            // 任务3成功：[任务3] 执行成功，结果：任务3-result
        }
    }
}
```

## 关键总结 & 实战建议

| 异常处理模式       | 核心用法                          | 适用场景                     |
|--------------------|-----------------------------------|------------------------------|
| 快速失败           | `coroutineScope + awaitAll()`     | 所有任务必须全部成功（如提交） |
| 容错执行（返回null）| `supervisorScope + runCatching + awaitAll()` | 部分失败不影响整体（如加载数据） |
| 全量结果收集       | `supervisorScope + TaskResult + awaitAll()` | 需记录每个任务成败（如上传/下载） |

### Android 实战小贴士：

1. **避免主线程阻塞**：所有批量任务必须在 `Dispatchers.IO`/`Dispatchers.Default` 中执行，切勿在 `Dispatchers.Main` 中调用；
2. **协程取消**：`viewModelScope`/`lifecycleScope` 会随组件生命周期自动取消协程，无需手动处理；
3. **并发限制**：若任务数过多（如 >20），建议自定义协程池限制并发（避免线程耗尽）：

   ```kotlin
   // 限制最大并发数为5
   val limitedDispatcher = newFixedThreadPoolContext(5, "LimitedPool")
   val task1 = async(limitedDispatcher) { simulateAsyncTask("任务1") }
   ```
