# SAM

Kotlin中SAM（Single Abstract Method，单抽象方法）机制的全部细节，包括它的定义、底层原理、适用范围、具体使用方式，以及和`fun interface`的关联、使用限制等，这是理解Kotlin简化单方法接口使用的核心知识点。

## 一、SAM 核心概念

先明确两个核心术语，避免概念混淆：

- **SAM接口**（Single Abstract Method Interface）：本质是**仅包含一个抽象方法**的接口（无论接口定义在Kotlin还是Java中），这是SAM机制的基础；
- **SAM转换**（SAM Conversion）：Kotlin编译器提供的语法糖——允许将**lambda表达式/方法引用**自动转换为SAM接口的实现类实例，替代繁琐的匿名内部类，这是SAM机制的核心价值。

关键关联：Kotlin中的`fun interface`是专门为SAM接口设计的语法（Kotlin 1.4+引入），而SAM转换是对SAM接口的简化使用方式——前者是“接口定义”，后者是“接口使用”。

## 二、SAM的适用范围

SAM转换并非对所有接口生效，核心区分**接口的来源**和**接口的定义方式**，以下是清晰的规则表：

| 接口类型                | 是否支持SAM转换 | 核心说明                     |
|-------------------------|----------------|------------------------------|
| Kotlin `fun interface`  | 是             | 专门为SAM转换设计的语法      |
| Java 中的SAM接口        | 是             | Kotlin对Java SAM接口天然兼容 |
| Kotlin普通接口（无fun） | 否             | 即使只有1个抽象方法也不支持  |
| 含多个抽象方法的接口    | 否             | 违背“单抽象方法”核心规则     |

## 三、SAM转换的底层原理

SAM转换本质是**编译器自动生成匿名类**，你写的lambda会被编译器“包装”成接口的实现类实例，运行时逻辑和匿名类完全一致，只是代码书写更简洁。

示例对比（编译器自动完成的转换）：

```kotlin
// 你写的SAM转换代码（简洁）
val calculator: Calculator = { a, b -> a + b }

// 编译器自动生成的等价代码（底层逻辑）
val calculator = object : Calculator {
    override fun calculate(a: Int, b: Int): Int {
        return a + b
    }
}
```

## 四、SAM的详细使用示例

### 1. 基础场景：Kotlin自定义fun interface

```kotlin
// 1. 定义SAM接口（fun interface）
fun interface ClickListener {
    // 唯一抽象方法
    fun onCLick(viewId: Int)

    // 允许包含非抽象成员（默认方法）
    fun logClick() {
        println("点击事件已触发")
    }
}

// 2. 传统匿名类（无SAM转换，代码繁琐）
val clickListener1 = object : ClickListener {
    override fun onCLick(viewId: Int) {
        println("点击了视图：$viewId")
    }
}

// 3. SAM转换（lambda简化，核心优势）
val clickListener2: ClickListener = { viewId ->
    println("SAM转换：点击了视图：$viewId")
}

// 调用效果完全一致
clickListener1.onCLick(100)
clickListener1.logClick()
clickListener2.onCLick(200)
clickListener2.logClick()
```

### 2. 跨语言场景：Java SAM接口在Kotlin中的使用

Kotlin对Java定义的SAM接口天然支持SAM转换（无需任何额外修饰），这是跨语言交互的重要优势：

#### 步骤1：Java中定义SAM接口（或直接用JDK自带接口）

```java
// 自定义Java SAM接口
public interface JavaCallback {
    void onComplete(String result);
}

// JDK自带的Java SAM接口（如Runnable、Comparator）
```

#### 步骤2：Kotlin中使用SAM转换

```kotlin
// 1. 自定义Java SAM接口的SAM转换
val callback: JavaCallback = { result ->
    println("Java接口回调结果：$result")
}
callback.onComplete("操作成功") // 输出：Java接口回调结果：操作成功

// 2. JDK Runnable的SAM转换
val task: Runnable = {
    println("异步任务执行中...")
}
Thread(task).start()

// 3. JDK Comparator的SAM转换（排序场景）
val numbers = listOf(5, 2, 8, 1)
// SAM转换简化排序逻辑
val sortedNumbers = numbers.sortedWith { a, b -> a - b }
println(sortedNumbers) // 输出：[1, 2, 5, 8]
```

### 3. 进阶场景：泛型SAM接口

SAM接口支持泛型，SAM转换也完全兼容泛型场景，适配多类型转换需求：

```kotlin
// 泛型SAM接口
fun interface Transformer<IN, OUT> {
    fun transform(input: IN): OUT
}

// SAM转换使用泛型
val stringToInt: Transformer<String, Int> = { it.toInt() } // 字符串转数字
val intToBoolean: Transformer<Int, Boolean> = { it > 0 }    // 数字转布尔值

// 调用
println(stringToInt.transform("123")) // 输出：123
println(intToBoolean.transform(-5))   // 输出：false
```

### 4. 高级技巧：方法引用实现SAM转换

除了lambda，还可以用**方法引用（::）** 实现SAM转换，代码更简洁（适用于已有现成函数的场景）：

```kotlin
// 定义SAM接口
fun interface Logger {
    fun log(message: String)
}

// 已有现成函数
fun printToFile(message: String) {
    println("写入文件：$message")
}

// 方法引用实现SAM转换
val fileLogger: Logger = ::printToFile
fileLogger.log("SAM方法引用示例") // 输出：写入文件：SAM方法引用示例
```

## 五、SAM转换的限制与注意事项

1. **仅支持单抽象方法**：如果接口有2个及以上抽象方法，无论是否加`fun`，都无法使用SAM转换（本质不再是SAM接口）；
2. **Kotlin普通接口无SAM转换**：即使只有1个抽象方法，不加`fun`修饰的Kotlin接口也不支持lambda转换（必须用匿名类）；
3. **SAM接口可扩展非抽象成员**：`fun interface`允许包含默认方法、伴生对象、属性等，不影响SAM转换；
4. **SAM vs 函数类型**：
   - 需和Java交互、需要语义化命名/默认方法 → 用SAM接口；
   - 纯Kotlin代码、简单函数传递 → 用函数类型（如`(Int) -> String`）。

## 总结

1. SAM包含**SAM接口**（单抽象方法接口）和**SAM转换**（lambda自动转接口实例），Kotlin `fun interface`是专门的SAM接口定义方式；
2. SAM转换支持Kotlin `fun interface`和Java SAM接口，但不支持无`fun`的Kotlin普通接口；
3. SAM转换是编译器语法糖，可通过lambda/方法引用简化代码，且兼容泛型、默认方法，是Kotlin简化回调/监听器的核心语法。
