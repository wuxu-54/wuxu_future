# 泛型-java上下限与kotlin的协变逆变

我在学习java的上下界时总理不清，再次学习kotlin的逆变与协变又一次理不清了，这里重点梳理一下我经常遗忘的细节点。

说明：

1. 学习是要根据泛型的类型擦除来理解，构建工具在编译前会处理泛型（即根据<>进行类型确定、替换），转换为不带泛型的语法
2. java 上下界与kotlin 协变逆变是一样的，并且kotlin的<*> 与 java的<?> 也一样。

## 关键知识

- <?> 通配符（kotlin中的<*>），表示不限制类型
- <? extends Animal> 上界（kotlin的协变（out关键字修饰）， 协变是指 协同一致，表示类型转换方向是子到父，与隐式类型转换一致）类型需要是Animal及其子类;  只读不可写，读取出来是Animal。
- <? super Dog> 下界（kotlin的逆变（in关键字修饰），逆变是指 逆向， 表示类型转换方向是由父到子）类型需要是Dog及其父类； 只写，如果读取，只能是Object类（注意不是父类）

## 一眼看懂的示例

关键知识里面有个只读、只写，是什么意思？一般拿List举例，其实是指从List中读取数据和存入数据时的类型转换约束。

java：生产者（往外拿数据）：`?extends T`，消费者（接收 / 存入数据）：`?super T`

- 上界 `? extends T` （读，不能写） 。`? extends T`：**只能是 T 或者 T 的子类**

    ```java
    // 上界：只能取出来，不能存进去
    List<? extends Animal> list;
    Animal a = list.get(0);  // ✅读，可以，一定是Animal
    list.add(new Dog());     // ❌写，编译报错，不知道具体子类. 原因：无法确定具体子类是什么，类型擦除List<Animal> list，list可能真实类型可能是List<Cat>也可能是List<Dog>,所以这种无法明确的情况下编译时会直接报错。
    ```

  - 场景：**只读取数据**
  - 记忆：`extends` → 向外取数据

- 下界 `? super T`（写，读只能拿 Object）。`? super T`：只能是 T 或者 T 的父类

    ```java
    List<? super Dog> list;
    list.add(new Dog());     // ✅可以存入Dog及其子类
    Dog d = list.get(0);     // ❌读拿不到Dog，只能拿到Object
    Object obj = list.get(0);// ✅只能接收Object， 原因: Dog->Animal->Object ，看这层继承关系，所以读取时只能是取最上层Object
    ```

  - 场景：**只存入数据**
  - 记忆：`super` → 往里放数据

kotlin：

- `out T` 协变（ Java `? extends T`）：**只能往外输出 T，函数返回值可以是 T，不能把 T 当参数传入**。

    ```kotlin
    interface Source<out T> {
        fun get(): T   // 只能返回T，不能接收T作为入参
    }

    val src: Source<Dog> = SourceImpl()
    val animalSrc: Source<Animal> = src // ✅协变，Dog可以赋值给Animal
    ```

- `in T` 逆变 （ Java `? super T`）：**只能接收传入 T，函数参数可以是 T，不能返回 T**。

    ```kotlin
    interface Sink<in T> {
        fun set(value:T) // 只能接收T作为参数，不能返回T
    }

    val sink:Sink<Animal> = SinkImpl()
    val dogSink:Sink<Dog> = sink // ✅逆变，Animal的sink可以接收Dog
    ```
