# 类中的变量需要初始化吗？

在 JavaScript 和 TypeScript 中，全局变量是否必须初始化取决于**声明方式**和**语言特性**，具体规则如下：

## 1. JavaScript 中的全局变量

在 JavaScript 中，全局变量可以不初始化，未初始化的全局变量会被默认赋值为 `undefined`。

### 示例：

```javascript
// 未初始化的全局变量
var globalVar1;
let globalVar2;

console.log(globalVar1); // 输出：undefined
console.log(globalVar2); // 输出：undefined
```

### 特殊情况：`const` 声明的全局变量**必须初始化**

`const` 用于声明常量，一旦声明必须初始化，且后续不能修改，否则会报错：

```javascript
const globalConst; // 报错：Missing initializer in const declaration
```

## 2. TypeScript 中的全局变量

TypeScript 由于增加了类型检查，规则更严格，需结合**类型声明**和**初始化**判断：

### （1）`let`/`var` 声明的全局变量：可以不初始化，但建议指定类型

- 未初始化且未指定类型时，TypeScript 会默认推断为 `any` 类型（非严格模式下）。
- 若开启严格模式（`strict: true`，包含 `noImplicitAny`），未指定类型且未初始化的变量会报错（需显式声明类型）。

### 示例：

```typescript
// 非严格模式下：允许，默认推断为 any
let tsGlobal1; 
tsGlobal1 = "hello"; // 允许赋值任意类型

// 严格模式下：必须显式指定类型（否则报错）
let tsGlobal2: string; // 声明类型，不初始化（允许）
tsGlobal2 = "world"; // 后续可赋值

// 错误示例（严格模式）：未指定类型且未初始化
let tsGlobal3; // 报错：Variable 'tsGlobal3' implicitly has type 'any' in some locations where its type cannot be determined
```

### （2）`const` 声明的全局变量：**必须初始化**

与 JavaScript 一致，`const` 声明的全局变量必须初始化，且类型由初始值推断（或显式指定）：

```typescript
const tsConst1 = 100; // 正确：初始化，类型推断为 number
const tsConst2: string = "test"; // 正确：显式指定类型并初始化

const tsConst3: number; // 报错：'const' declarations must be initialized
```

### （3）全局变量的类型声明（`.d.ts` 文件中）

在 TypeScript 中，若需声明全局变量的类型（而非实际定义），可在 `.d.ts` 声明文件中使用 `declare`，此时**无需初始化**（仅声明类型）：

```typescript
// global.d.ts（声明文件）
declare let globalConfig: {
  appName: string;
  version: string;
};
```

上述代码仅声明 `globalConfig` 的类型，实际初始化需在其他脚本中完成（如全局环境中赋值）。

## 总结

- **`var`/`let` 声明的全局变量**：在 JavaScript 和 TypeScript 中均可不初始化（默认值为 `undefined`），但 TypeScript 严格模式下需显式指定类型。
- **`const` 声明的全局变量**：无论 JavaScript 还是 TypeScript，**必须初始化**（否则报错），因为常量不可后续赋值。
- **类型声明文件（`.d.ts`）中的全局变量**：使用 `declare` 时无需初始化，仅声明类型结构。

实际开发中，建议全局变量在声明时明确初始化或指定类型，以避免类型错误和逻辑隐患。
