# Pydantic Model 大白话详解

Pydantic Model 是**Python 中最流行的数据验证和类型定义工具**，你可以把它理解成一个**"智能表格模板"**：你先定义好表格有哪些列、每列应该填什么类型的数据、有什么格式要求，然后任何人（包括大模型）往这个表格里填数据时，它都会自动检查：

- 有没有漏掉必填项
- 数据类型对不对（比如不能把数字写成字符串）
- 格式合不合规（比如邮箱是不是正确格式、日期是不是 YYYY-MM-DD）
- 数值在不在合理范围内（比如年龄不能是负数）

如果数据有问题，它会立刻告诉你哪里错了、应该怎么改；如果没问题，就会把数据整理成一个干净、规范的对象供你使用。

## 一、为什么它在大模型领域这么重要？

这是因为**大模型生成的内容天生是"自由散漫"的**，而工具调用（Function Calling）要求参数必须是严格、标准的格式。Pydantic 完美解决了这个矛盾：

1. **它能自动生成大模型能看懂的参数说明书（JSON Schema）**
2. **它能自动校验大模型生成的参数是否合法**
3. **它能把大模型生成的原始 JSON 转换成方便 Python 代码操作的对象**

没有 Pydantic 之前，你需要手动写几百行 JSON Schema 来描述参数，还要自己写一堆校验逻辑，非常容易出错。现在只需要写一个简单的 Python 类，剩下的都交给 Pydantic。

## 二、最简单的例子：一看就懂

### 不用 Pydantic 的痛苦

假设你有一个查询天气的函数，需要接收城市和日期两个参数：

```python
def get_weather(city, date):
    print(f"查询{date}{city}的天气")

# 大模型可能会生成各种奇怪的参数
get_weather(123, "明天")  # ❌ city 应该是字符串，不是数字
get_weather("北京", "2026/5/20")  # ❌ 日期格式不对，应该是 2026-05-20
get_weather(date="今天")  # ❌ 漏掉了必填参数 city
```

这些错误都会导致函数运行失败，而大模型根本不知道自己错了。

### 用 Pydantic 的快乐

```python
from pydantic import BaseModel, Field
from typing import Optional

# 定义一个"表格模板"，规定参数的类型和要求
class GetWeatherInput(BaseModel):
    """查询指定城市的天气信息"""
    city: str = Field(description="要查询的城市名称，例如：北京、上海")
    date: Optional[str] = Field(
        default="今天",
        description="查询日期，格式为 YYYY-MM-DD，默认为今天"
    )

# 现在用这个模板来校验大模型生成的参数
# 1. 正确的参数：顺利通过
data = GetWeatherInput(city="北京", date="2026-05-20")
print(data.city)  # 输出：北京
print(data.date)  # 输出：2026-05-20

# 2. 错误的参数：立刻报错，告诉你哪里错了
GetWeatherInput(city=123)
# ❌ 错误：Input should be a valid string [type=string_type, input_value=123, input_type=int]

GetWeatherInput(date="2026/5/20")
# ❌ 错误：Field required [type=missing, input_value={'date': '2026/5/20'}, input_type=dict]
```

## 三、Pydantic Model 的三大核心能力

### 1. 自动类型校验

它会严格检查每个字段的类型，不允许任何类型错误：

```python
class User(BaseModel):
    name: str
    age: int
    is_student: bool

User(name="张三", age=20, is_student=True)  # ✅ 正确
User(name="李四", age="20", is_student="是")  # ❌ 错误：age 应该是 int，is_student 应该是 bool
```

### 2. 丰富的数据验证

除了基本类型，它还能验证各种复杂规则：

```python
from pydantic import Field, EmailStr

class User(BaseModel):
    username: str = Field(min_length=3, max_length=20)  # 用户名长度 3-20
    age: int = Field(ge=0, le=120)  # 年龄 0-120 岁
    email: EmailStr  # 自动验证邮箱格式
    phone: str = Field(pattern=r"^1[3-9]\d{9}$")  # 正则验证手机号

User(username="zhangsan", age=25, email="zhangsan@example.com", phone="13800138000")  # ✅
User(username="a", age=150, email="zhangsan", phone="123456")  # ❌ 4 个错误全部报出来
```

### 3. 自动生成 JSON Schema

这是它在大模型领域最有用的功能。大模型工具调用需要用 JSON Schema 来描述参数，Pydantic 可以一行代码生成：

```python
schema = GetWeatherInput.model_json_schema()
print(schema)
```

输出的就是大模型能直接理解的标准参数描述：

```json
{
  "properties": {
    "city": {
      "description": "要查询的城市名称，例如：北京、上海",
      "title": "City",
      "type": "string"
    },
    "date": {
      "default": "今天",
      "description": "查询日期，格式为 YYYY-MM-DD，默认为今天",
      "title": "Date",
      "type": "string"
    }
  },
  "required": ["city"],
  "title": "GetWeatherInput",
  "type": "object"
}
```

## 四、总结

Pydantic Model 不是什么高深的技术，它就是一个**"数据守门员"**：

- 对外：给大模型提供清晰、标准的参数说明书
- 对内：严格检查所有输入数据，确保只有合法的数据才能进入你的代码

这就是为什么所有主流大模型平台（OpenAI、Anthropic、豆包）和框架（LangChain、LangGraph）都把 Pydantic 作为默认的参数定义工具。它已经成为大模型工具调用和 Agent 开发的**基础设施**。
