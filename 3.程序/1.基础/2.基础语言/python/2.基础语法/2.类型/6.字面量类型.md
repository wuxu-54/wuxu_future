# Python 中的 `Literal` 类型（字面量类型）

`Literal` 是 Python 的 `typing` 模块提供的一种特殊类型，用于**将变量的取值范围限制为固定的几个字面量值**。它本质上是一种**类型级别的约束**，主要供静态类型检查器（如 mypy、Pyright、PyLance）以及 IDE 进行验证，运行时不会强制检查（除非你手动实现）。

## 1. 基本语法

```python
from typing import Literal

# 单个字面量
type MyConst = Literal["hello"]

# 多个可选值（字面量的联合）
type Status = Literal["active", "inactive", "pending"]
```

支持的 Python 字面量包括：

- 字符串字面量 `"foo"`
- 字节串字面量 `b"bar"`
- 整数字面量 `42`
- 布尔字面量 `True` / `False`
- 枚举成员（但通常直接用枚举类型更合适）

**注意**：`None`、浮点数、复数**不能**作为 `Literal` 的参数。

## 2. 使用示例

```python
from typing import Literal

def set_log_level(level: Literal["DEBUG", "INFO", "WARNING", "ERROR"]) -> None:
    print(f"Log level set to {level}")

# ✅ 正确
set_log_level("INFO")

# ❌ 类型检查错误（mypy 会报错）
set_log_level("VERBOSE")
```

**允许多种字面量混合**（自动形成联合类型）：

```python
def handle_response(code: Literal[200, 404, 500]) -> None:
    ...
```

## 3. 与 `Union` 的区别

`Literal` 是 `Union` 的一个特例，但其成员必须是字面量。  
你也可以显式写成 `Union[Literal["a"], Literal["b"]]`，但 `Literal["a", "b"]` 是更简洁的写法。

```python
from typing import Union, Literal

# 等价写法
T1 = Literal["a", "b"]
T2 = Union[Literal["a"], Literal["b"]]
```

## 4. 类型检查行为

- **精确匹配**：只能赋值为指定的那几个字面量值，不能是计算出的同值字符串（即使运行时值相等也不行）。

  ```python
  val = "INFO"   # val 的类型被推断为 str
  set_log_level(val)   # ❌ 类型错误：val 是 str，不是 Literal
  ```

  解决方案：使用 `# type: ignore` 或显式转换为 `Literal`（但通常意味着设计需要调整）。

- **类型收窄**：类型检查器会利用 `Literal` 进行分支条件收窄。

  ```python
  def f(x: Literal["a", "b"]) -> str:
      if x == "a":
          return "alpha"
      else:
          return "beta"   # 此处 x 被收窄为 Literal["b"]
  ```

- **重载与模式匹配**：结合 `@overload` 或 `match` 语句非常有用。

## 5. 与 `Enum` 的比较

| 特性 | `Literal` | `Enum` |
|------|-----------|--------|
| 定义方式 | 直接列出字面值 | 定义类继承 `Enum` |
| 运行时有实体 | ❌ 没有对象，只是字符串/整数 | ✅ 每个成员是独立的枚举对象 |
| 类型安全性 | 检查器确保值固定 | 运行时也确保值不超出成员 |
| 反向映射/方法 | 无 | 可以添加属性和方法 |
| 序列化（JSON等） | 直接是字符串/整数 | 需要自定义 encoder 或取 `.value` |

**选择建议**：

- 简单、一次性的小范围值 → `Literal`
- 需要附带行为、遍历所有成员、或严格运行时校验 → `Enum`

## 6. 与 `LiteralString` 的区别（Python 3.11+）

Python 3.11 引入了 `typing.LiteralString`，它表示**任何字面字符串**（即源代码中直接写出的字符串常量），而不是预定义的几个值。

```python
from typing import LiteralString

def run_sql(query: LiteralString) -> None:   # 只能接受字面SQL，防止注入
    ...

run_sql("SELECT * FROM users")   # ✅
user_input = input()
run_sql(user_input)               # ❌ 类型错误：user_input 是 str，不是 LiteralString
```

`Literal["a","b"]` 是**有限集合**，`LiteralString` 是**无限集合**（所有字符串字面量）。

## 7. 运行时行为

`Literal` 在运行时只是一个普通对象（`typing.Literal` 的实例），**不会自动执行校验**：

```python
>>> from typing import Literal
>>> def f(x: Literal[1,2]) -> None: pass
>>> f(999)   # 运行时不会报错，类型检查器才会报错
```

如果你需要运行时校验，可以借助库（如 `typeguard`）或手动检查：

```python
from typing import Literal, get_args

def f(x: Literal[1,2]):
    allowed = get_args(f.__annotations__['x'])
    if x not in allowed:
        raise ValueError(f"x must be one of {allowed}")
```

`get_args` 可在运行时提取 `Literal` 包含的值。

## 8. 常见陷阱

- **变量重新赋值**：如果变量被标注为 `Literal["a"]`，再赋值 `"b"` 会报错。
- **嵌套字面量**：`Literal[Literal["a"]]` 等价于 `Literal["a"]`。
- **重复值**：`Literal["a", "a"]` 会自动去重为 `Literal["a"]`。
- **不能包含变量**：`value = "foo"; Literal[value]` 不合法，因为 `value` 不是字面量。
- **Python 版本**：`Literal` 从 Python 3.8 开始正式加入 `typing`（3.7 需要 `typing_extensions`）。

## 9. 实际应用场景

- **API 返回状态**：`Literal["success", "failure"]`
- **配置键名**：`Literal["host", "port", "timeout"]`
- **限定模式参数**：`open(mode: Literal["r", "w", "a"])`
- **类型安全的命令分发**：`Command = Literal["start", "stop", "restart"]`

---

总结：`Literal` 将类型系统从“是什么类型”下沉到“是什么具体的值”，让静态检查更精细、代码更自文档化。它非常适用于**有限的、已知的常量集合**，但若需要运行时多态或丰富的方法，请改用 `Enum`。
