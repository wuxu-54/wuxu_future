# Java InvocationHandler 详解

`InvocationHandler` 是 **Java 动态代理** 的核心接口，位于 `java.lang.reflect` 包。
> 动态代理：**在运行期动态生成代理类字节码，不需要手写 .java 代理类**，用来对目标对象做增强（AOP底层实现）。

## 1. 基础定义

```java
public interface InvocationHandler {
    /**
     * 代理对象调用任何方法，都会走到这个 invoke 方法
     * @param proxy 代理对象本身（注意：不要在invoke里调用proxy的方法，会递归死循环）
     * @param method 当前被调用的目标方法的Method对象
     * @param args 调用方法传入的参数数组
     * @return 方法执行后的返回值
     * @throws Throwable 可以抛出异常
     */
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable;
}
```

> ⚠️ JDK动态代理**只能代理接口**，不能直接代理普通类；底层依靠 `java.lang.reflect.Proxy` 生成代理类。

## 2. 完整示例

### 1）业务接口

```java
public interface UserService {
    void addUser(String name);
    void deleteUser();
}
```

### 2）目标实现类（被代理对象）

```java
public class UserServiceImpl implements UserService{
    @Override
    public void addUser(String name) {
        System.out.println("添加用户：" + name);
    }
    @Override
    public void deleteUser() {
        System.out.println("删除用户");
    }
}
```

### 3）自定义 InvocationHandler

我们在这里做增强：打印日志，在目标方法前后插入逻辑

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;

public class MyInvocationHandler implements InvocationHandler {
    // 保存真实被代理的目标对象
    private final Object target;

    public MyInvocationHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        // ==========方法执行前增强==========
        System.out.println("【前置日志】准备执行方法：" + method.getName());

        // 执行真实目标对象的方法，method.invoke(目标对象, 参数)
        Object result = method.invoke(target, args);

        // ==========方法执行后增强==========
        System.out.println("【后置日志】方法执行完成");
        return result;
    }
}
```

### 4）使用 Proxy 创建代理对象

```java
import java.lang.reflect.Proxy;

public class TestProxy {
    public static void main(String[] args) {
        // 真实目标对象
        UserService target = new UserServiceImpl();

        // 创建handler，传入目标对象
        InvocationHandler handler = new MyInvocationHandler(target);

        // JDK生成代理对象
        UserService proxy = (UserService) Proxy.newProxyInstance(
                target.getClass().getClassLoader(), // 类加载器
                target.getClass().getInterfaces(),  // 需要实现的接口数组
                handler                              // 调用处理器
        );

        // 调用代理对象的方法
        proxy.addUser("张三");
        proxy.deleteUser();
    }
}
```

输出：

```
【前置日志】准备执行方法：addUser
添加用户：张三
【后置日志】方法执行完成
【前置日志】准备执行方法：deleteUser
删除用户
【后置日志】方法执行完成
```

## 3. InvocationHandler 三大参数深度解析

1. **Object proxy**
动态生成出来的**代理实例对象**。

> ❗坑：不要写 `proxy.someMethod()` 在 invoke 内部，会再次触发 invoke，无限递归栈溢出。
> 如果要执行真实逻辑，永远用 `method.invoke(target, args)`，target是原始对象。

2. **Method method**
当前触发的接口方法的反射对象，可以拿到方法名、注解、参数类型等元信息。

3. **Object[] args**
调用方法传入的参数；无参时为 `null`，不是空数组。

返回值：会作为代理方法的返回值返回给调用方。

## 4. 底层原理（JDK动态代理原理）

### 4.1 Proxy.newProxyInstance 做了什么

1. 根据传入的**接口数组**，在内存动态拼接生成 `.class` 字节码字符串，**没有磁盘 .class 文件**。
2. 使用类加载器把动态字节码加载进JVM，生成代理类 Class 对象。
3. 通过反射创建代理类实例，把我们写的 `InvocationHandler` 传入代理对象。
4. 返回代理对象。

> 我们可以开启参数，把动态生成的class输出到磁盘查看真实代理类：

```java
// JDK8
System.getProperties().put("sun.misc.ProxyGenerator.saveGeneratedFiles","true");
// JDK9+
System.getProperties().put("jdk.proxy.ProxyGenerator.saveGeneratedFiles","true");
```

### 4.2 反编译出来的动态代理类伪代码

生成的代理类 `$Proxy0`，实现我们的 `UserService` 接口：

```java
public final class $Proxy0 extends Proxy implements UserService {
    private static Method m1;
    private static Method m3;
    private static Method m2;
    private static Method m0;

    public $Proxy0(InvocationHandler h) {
        super(h); // 父类Proxy保存handler
    }

    @Override
    public void addUser(String name) {
        // 重点！代理方法内部直接调用 h.invoke()
        super.h.invoke(this, m3, new Object[]{name});
    }

    @Override
    public void deleteUser() {
        super.h.invoke(this, m2, null);
    }
    // equals、hashCode、toString也同样转发给invoke
}
```

> **核心原理：代理类所有接口方法实现，全部转发调用 `InvocationHandler.invoke()`**。
当外部调用 `proxy.addUser()`，本质执行代理类 `$Proxy0.addUser()`，内部直接调用 `h.invoke(proxy, method, args)`，全部逻辑交给我们自定义的 `invoke`。
>
> 所以：**所有代理对象方法调用，都会进入 invoke，这就是拦截的本质**。

> Proxy父类持有 `InvocationHandler h` 属性，代理类继承 Proxy。Java是单继承，所以JDK代理只能实现接口，不能继承普通类。

## 5. invoke() 中 method.invoke(target, args) 原理

`method.invoke(obj, args)` 是Java反射API：

- `method`：要执行哪个方法
- `obj`：**哪个对象上执行这个方法（必须是目标实现类对象，不是proxy）**
- `args`：方法参数
内部通过反射调用目标对象真实方法，返回执行结果。

## 6. equals / hashCode / toString 也会走 invoke

代理对象调用这三个方法，同样会进入 `InvocationHandler#invoke`。
原因：动态代理类重写了这三个Object方法，同样转发给handler。

## 7. JDK动态代理的局限

1. **只能代理接口**，目标类必须实现接口；没有实现接口的类不能用JDK动态代理。
2. 不能代理 private 方法（接口不能有private）。

> 如果需要代理普通类，使用 CGLIB 动态代理，底层继承目标类生成子类。Spring AOP：目标有接口用JDK代理，无接口用CGLIB。

## 8. InvocationHandler 使用场景

1. Spring AOP JDK动态代理实现；
2. RPC框架：Dubbo等，客户端接口代理，接口调用转为网络请求；
3. 日志埋点、权限校验、事务包装、统计耗时；
4. Mock测试。

## 9. 常见坑总结

1. invoke内部调用 `proxy.xxx()`，递归调用，栈溢出；必须使用 `method.invoke(target, args)`。
2. 方法无参数时 `args` 是 null，直接遍历 args 会空指针。
3. JDK代理不能代理普通类，只能代理接口。
4. 异常：`IllegalArgumentException: no non‑public interface`，传入不是接口。
5. `method.invoke()` 会抛出受检异常，invoke方法声明 throws Throwable。

## 10. JDK动态代理完整流程

```
调用 proxy.addUser()
        ↓
执行动态代理类 $Proxy0.addUser()
        ↓
调用 InvocationHandler.invoke(proxy, addUserMethod, args)
        ↓
自定义前置增强逻辑
        ↓
method.invoke(target, args) 反射执行真实对象addUser
        ↓
自定义后置增强逻辑
        ↓
返回结果
```
