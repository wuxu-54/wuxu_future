# ThreadLocal 详解（Java）

## 一、ThreadLocal 是什么

`ThreadLocal` 是**线程本地变量**，作用：**为每个线程单独保存一份变量副本，线程之间相互隔离，互不干扰**。

>
> 一句话：同一个 `ThreadLocal` 对象，在不同线程 get/set，拿到的是**各自线程独立的数据**，天然线程安全，不需要加锁。

适用场景：

1. 保存**线程内上下文**，比如用户登录信息、请求链路 traceId（Spring、微服务链路追踪大量使用）
2. 工具类，避免频繁传参，贯穿整个方法调用链
3. 连接池：数据库连接、Session 绑定到当前线程

⚠️ **不是用来解决多线程共享变量**！它根本不是共享，每个线程一份副本。

---

## 二、底层原理（重点）

很多人误区：以为 ThreadLocal 里面是 `Map<Thread, T>`，**完全错**。

真实结构：

```
Thread 类内部有成员变量：
ThreadLocalMap threadLocals;
```

1. **每个 Thread 对象自带一个 ThreadLocalMap**
2. `ThreadLocalMap` 是 `ThreadLocal` 的静态内部类，**不是 HashMap**，自己实现的哈希表
3. Map 的 `key = ThreadLocal 对象（弱引用）`，`value = 你存的数据`

### 调用流程

```
ThreadLocal<String> tl = new ThreadLocal<>();
tl.set("abc");
```

1. 获取当前线程 `Thread.currentThread()`
2. 获取当前线程内部的 `threadLocals（ThreadLocalMap）`，为空就新建
3. 以**当前ThreadLocal实例作为key**，放入value

```
tl.get();
```

1. 获取当前线程的 ThreadLocalMap
2. 以当前ThreadLocal为key，取出value
3. 没有则返回 `null`

>
> 核心：**数据存在Thread里，不是ThreadLocal里！ThreadLocal只是一个存取入口，作为Map的key。**

### ThreadLocalMap 细节

- 底层数组 `Entry[] table`
- `Entry`：`static class Entry extends WeakReference<ThreadLocal<?>>`

```
Entry(ThreadLocal<?> k, Object v) {
    super(k); // key是弱引用
    value = v;
}
```

✅ **key 是弱引用（WeakReference）**：当外部没有强引用指向 ThreadLocal 对象时，key 会被GC回收，防止内存泄漏。
❌ **value 是强引用！** 这就是内存泄漏根源。

## 三、内存泄漏问题（高频面试）

### 泄漏原因

1. `Thread` 长期存活（线程池！），线程对象不会销毁
2. ThreadLocalMap 的 **key（ThreadLocal）被GC回收后，key变成null**
3. 但 `value` 还是**强引用**，只要线程不退出，value 就一直存在，无法GC，造成内存泄漏

>
> 场景：线程池复用线程，任务执行完不调用remove，key被回收，但value还在，堆积垃圾。

### 怎么避免内存泄漏

**必须在使用完毕调用 `threadLocal.remove()`**

- remove：直接删除map里这个Entry（key和value一起清空）
- 不要依赖自动清理，自动清理是被动触发（set/get时才会扫描清理key=null的entry，不可靠）

>
> 最佳实践：try-finally

```
ThreadLocal<String> tl = new ThreadLocal<>();
try {
    tl.set("数据");
    //业务逻辑
} finally {
    tl.remove(); //无论正常/异常，一定清除
}
```

### 补充：为什么key设计成弱引用？

如果key是强引用：就算外部不保留ThreadLocal引用，只要线程存活，ThreadLocalMap持有key强引用 → ThreadLocal对象永远无法GC，**整个Entry都泄漏**。
弱引用只是减少泄漏风险，**不能根除，value依然强引用，还是要手动remove**。

## 四、核心API

| 方法 | 作用 |
| --- | --- |
| `void set(T value)` | 设置当前线程的本地变量 |
| `T get()` | 获取当前线程的本地变量，无则返回null |
| `void remove()` | 删除当前线程对应的本地变量，推荐用完必调 |
| `protected T initialValue()` | 延迟初始化，get()不存在值时调用，默认返回null |

示例：重写 initialValue 设置初始值

```
ThreadLocal<Integer> tl = new ThreadLocal<Integer>(){
    @Override
    protected Integer initialValue() {
        return 0;
    }
};
```

Java8 简化写法：

```
ThreadLocal<Integer> tl = ThreadLocal.withInitial(() -> 0);
```

## 五、使用示例

```
public class ThreadLocalDemo {
    private static ThreadLocal<String> userTl = ThreadLocal.withInitial(() -> "默认用户");

    public static void main(String[] args) {
        new Thread(() -> {
            userTl.set("张三");
            System.out.println(Thread.currentThread().getName() + ":" + userTl.get());
            userTl.remove();
        }, "线程A").start();

        new Thread(() -> {
            userTl.set("李四");
            System.out.println(Thread.currentThread().getName() + ":" + userTl.get());
            userTl.remove();
        }, "线程B").start();
    }
}
```

输出：

```
线程A:张三
线程B:李四
```

两个线程使用同一个 ThreadLocal 静态变量，各自数据隔离。

>
> ⚠️ 一般把 ThreadLocal 定义为 `static`！
> 原因：ThreadLocal对象作为Map的key，如果不static，每次new ThreadLocal会创建大量不同key，浪费内存。**业务中几乎全部static修饰**。

## 六、常见坑

### 坑1：线程池使用 ThreadLocal（最容易踩坑）

线程池**复用线程**，线程不会销毁。

- 如果任务A设置了ThreadLocal，任务执行完忘记remove
- 下一个复用该线程的任务，get会拿到**上一个任务残留的数据** → **数据脏读 + 内存泄漏**
✅ 解决方案：任务执行完finally调用remove

### 坑2：ThreadLocal 存大对象

value是强引用，不remove，大对象长期驻留内存。

### 坑3：父子线程无法继承（默认）

主线程设置ThreadLocal，子线程get拿到null。
如果需要父子线程传递变量 → 使用 **InheritableThreadLocal**
原理：创建子线程时，会把父线程的inheritableThreadLocals拷贝一份到子线程。

>
> 限制：只有新建线程的时候拷贝；线程池复用线程场景，InheritableThreadLocal也失效。

### 坑4：不要用ThreadLocal传递共享数据

ThreadLocal不是锁，不是用来同步共享变量，每个线程是副本，修改互不影响，不能用来通信。

## 七、ThreadLocalMap 哈希冲突处理

HashMap用**链表+红黑树**
ThreadLocalMap 使用 **线性探测（开放寻址法）**

- hash冲突时，向后找下一个空位放Entry
- 好处：结构简单，适合小容量Map；缺点：冲突多性能差

扩容：默认容量16，负载阈值 2/3，达到后扩容为2倍。
清理机制：get/set时会顺带扫描table，清理key为null的Entry（过期entry）。

## 八、典型应用场景

1. Spring `TransactionSynchronizationManager`：事务信息绑定当前线程
2. Spring Security：SecurityContextHolder，保存登录用户信息
3. 链路追踪：MDC（日志埋点traceId底层就是ThreadLocal）
4. 数据库框架：MyBatis SqlSession 绑定线程
5. Web请求：保存request上下文，贯穿controller/service/mapper，不用层层传参

## 九、面试高频问题总结

1. ThreadLocal底层存储在哪？

>
> 在Thread对象的ThreadLocalMap里，key是ThreadLocal实例，value是存储数据。

2. key为什么是弱引用？value为什么是强引用？

>
> 弱引用防止ThreadLocal对象本身内存泄漏；value强引用是业务数据，需要开发者手动remove。

3. 内存泄漏怎么产生，怎么解决？

>
> 线程长期存活+key被GC，value强引用无法释放。finally中remove。

4. ThreadLocal是否线程安全？

>
> 它实现了线程隔离，所以**使用上天然安全**，但不是多线程访问同一个对象的同步方案。

5. InheritableThreadLocal原理与局限？

>
> 创建子线程拷贝父线程的本地变量；线程池复用线程场景不生效。
