# ThreadLocal 源码解析（JDK8）

>
> 前置回顾：
> `Thread` 类持有 `ThreadLocalMap threadLocals`，数据**存在 Thread 中**，`ThreadLocal` 只是操作这个 Map 的工具类。
> 源码路径：`java.lang.ThreadLocal`

## 一、Thread 类相关源码

```
// Thread.java
public class Thread implements Runnable {
    // 存储普通ThreadLocal变量
    ThreadLocal.ThreadLocalMap threadLocals = null;
    // 存储InheritableThreadLocal，父子线程继承用
    ThreadLocal.ThreadLocalMap inheritableThreadLocals = null;
}
```

每个线程自己持有一个 `ThreadLocalMap`，初始是 null，**懒加载**，第一次 set/get 的时候才创建。

# 二、ThreadLocal 核心方法源码

## 1. set() 方法

```
public void set(T value) {
    // 1. 获取当前线程
    Thread t = Thread.currentThread();
    // 2. 获取当前线程的ThreadLocalMap
    ThreadLocalMap map = getMap(t);
    if (map != null)
        // map存在，以当前ThreadLocal实例为key，存入value
        map.set(this, value);
    else
        // map为null，新建ThreadLocalMap
        createMap(t, value);
}

// 获取线程的threadLocals
ThreadLocalMap getMap(Thread t) {
    return t.threadLocals;
}

// 创建ThreadLocalMap
void createMap(Thread t, T firstValue) {
    t.threadLocals = new ThreadLocalMap(this, firstValue);
}
```

逻辑：

1. 获取当前线程
2. 拿到该线程的 ThreadLocalMap
3. map存在：`map.set(this, value)`，`this`就是当前ThreadLocal对象，作为key
4. map不存在，新建Map，把当前ThreadLocal和value放进去

## 2. get() 方法

```
public T get() {
    Thread t = Thread.currentThread();
    ThreadLocalMap map = getMap(t);
    if (map != null) {
        // 以this（ThreadLocal实例）为key获取entry
        ThreadLocalMap.Entry e = map.getEntry(this);
        if (e != null) {
            @SuppressWarnings("unchecked")
            T result = (T)e.value;
            return result;
        }
    }
    // map为空 / entry为空 → 返回初始值
    return setInitialValue();
}

// 初始化初始值
private T setInitialValue() {
    T value = initialValue();
    Thread t = Thread.currentThread();
    ThreadLocalMap map = getMap(t);
    if (map != null)
        map.set(this, value);
    else
        createMap(t, value);
    return value;
}

// 可重写，默认返回null
protected T initialValue() {
    return null;
}
```

`ThreadLocal.withInitial()` 本质就是重写这个方法，Java8 新增：

```
public static <S> ThreadLocal<S> withInitial(Supplier<? extends S> supplier) {
    return new SuppliedThreadLocal<>(supplier);
}
```

`SuppliedThreadLocal` 是 ThreadLocal 的内部子类，重写 `initialValue`，调用supplier。

## 3. remove() 【重点，解决内存泄漏】

```
public void remove() {
    ThreadLocalMap m = getMap(Thread.currentThread());
    if (m != null)
        m.remove(this);
}
```

调用 `ThreadLocalMap#remove`，直接找到key为当前ThreadLocal的Entry，清空key和value。

>
> 最佳实践：`try-finally` 执行remove。

# 三、核心内部类：ThreadLocalMap 源码（重中之重）

`ThreadLocalMap` 是**ThreadLocal静态内部类**，不是HashMap，**开放寻址法（线性探测）解决哈希冲突**。

```
static class ThreadLocalMap {
    // Entry，key是弱引用ThreadLocal
    static class Entry extends WeakReference<ThreadLocal<?>> {
        // value 强引用！！！内存泄漏关键点
        Object value;

        Entry(ThreadLocal<?> k, Object v) {
            super(k); // key交给父类WeakReference，弱引用
            value = v;
        }
    }

    // 初始容量，必须是2的幂，方便位运算取模
    private static final int INITIAL_CAPACITY = 16;
    private Entry[] table;
    private int size = 0;
    // 扩容阈值：容量的2/3，达到后扩容
    private int threshold;

    private void setThreshold(int len) {
        threshold = len * 2 / 3;
    }

    // 构造函数，第一次创建map时调用
    ThreadLocalMap(ThreadLocal<?> firstKey, Object firstValue) {
        table = new Entry[INITIAL_CAPACITY];
        // 哈希算法：ThreadLocal的threadLocalHashCode & (len-1)
        int i = firstKey.threadLocalHashCode & (INITIAL_CAPACITY - 1);
        table[i] = new Entry(firstKey, firstValue);
        size = 1;
        setThreshold(INITIAL_CAPACITY);
    }
```

### 3.1 ThreadLocal 的 hash值：threadLocalHashCode

```
private final int threadLocalHashCode = nextHashCode();

private static AtomicInteger nextHashCode = new AtomicInteger();
// 魔数，斐波那契散列，让hash分布均匀
private static final int HASH_INCREMENT = 0x61c88647;

private static int nextHashCode() {
    return nextHashCode.getAndAdd(HASH_INCREMENT);
}
```

>
> 每new一个ThreadLocal，就自动分配一个递增的hash，`0x61c88647` 保证哈希值在2的幂数组上分布均匀，减少冲突。
> 不是用 `hashCode()`，是自己维护的自增hash。

### 3.2 ThreadLocalMap.getEntry()

```
private Entry getEntry(ThreadLocal<?> key) {
    int i = key.threadLocalHashCode & (table.length - 1);
    Entry e = table[i];
    // 命中，且key相等，直接返回
    if (e != null && e.get() == key)
        return e;
    else
        // 未命中 / entry的key被GC变成null，调用线性探测查找 + 清理过期entry
        return getEntryAfterMiss(key, i, e);
}
```

`getEntryAfterMiss`：线性探测向后遍历数组，**途中遇到key=null的entry，会执行expungeStaleEntry清理**。

### 3.3 ThreadLocalMap.set()

```
private void set(ThreadLocal<?> key, Object value) {
    Entry[] tab = table;
    int len = tab.length;
    int i = key.threadLocalHashCode & (len-1);

    for (Entry e = tab[i]; e != null; e = tab[i = nextIndex(i, len)]) {
        ThreadLocal<?> k = e.get();
        // 找到相同key，覆盖value
        if (k == key) {
            e.value = value;
            return;
        }
        // k == null：key已经被GC，过期entry，替换这个位置
        if (k == null) {
            replaceStaleEntry(key, value, i);
            return;
        }
    }
    // 找到空位置，新建Entry
    tab[i] = new Entry(key, value);
    int sz = ++size;
    // cleanSomeSlots 尝试清理过期entry，清理后元素数量仍然>=阈值，触发rehash
    if (!cleanSomeSlots(i, sz) && sz >= threshold)
        rehash();
}
```

- 开放寻址：hash冲突，`nextIndex(i,len)` 向后+1，到数组末尾回到0（环形数组）
- 遇到`k==null`（key被GC的过期entry），`replaceStaleEntry` 复用这个位置，顺便清理周边过期数据
- 插入完成后，执行`cleanSomeSlots`，扫描清理过期Entry

### 3.4 核心清理方法 expungeStaleEntry（清除过期entry）

>
> 这就是ThreadLocal被动清理的核心！**只有get/set的时候才会触发，不会自动后台清理**

```
private int expungeStaleEntry(int staleSlot) {
    Entry[] tab = table;
    int len = tab.length;

    // 清空当前过期entry：value置null，entry引用清空
    tab[staleSlot].value = null;
    tab[staleSlot] = null;
    size--;

    // 继续向后遍历，清理后续过期entry，直到遇到null
    Entry e;
    int i;
    for (i = nextIndex(staleSlot, len); (e = tab[i]) != null; i = nextIndex(i, len)) {
        ThreadLocal<?> k = e.get();
        if (k == null) {
            // key为null，清理
            e.value = null;
            tab[i] = null;
            size--;
        } else {
            // key有效，重新rehash，放到正确位置（开放寻址，清理后需要重排）
            int h = k.threadLocalHashCode & (len - 1);
            if (h != i) {
                tab[i] = null;
                while (tab[h] != null)
                    h = nextIndex(h, len);
                tab[h] = e;
            }
        }
    }
    return i;
}
```

作用：

1. 清空当前过期Entry（value=null，entry=null）
2. 继续向后扫描，清理连续的过期entry
3. 存活的entry重新rehash，调整位置

>
> 关键点：**这个清理是被动触发**。如果线程一直存活，永远不调用get/set，expungeStaleEntry永远不会执行，value就一直存在，内存泄漏。

### 3.5 ThreadLocalMap.remove()

```
private void remove(ThreadLocal<?> key) {
    Entry[] tab = table;
    int len = tab.length;
    int i = key.threadLocalHashCode & (len-1);
    for (Entry e = tab[i]; e != null; e = tab[i = nextIndex(i, len)]) {
        if (e.get() == key) {
            // 把key的弱引用清除
            e.clear();
            // 调用expungeStaleEntry清理entry和value
            expungeStaleEntry(i);
            return;
        }
    }
}
```

`e.clear()`：清除WeakReference内部引用，然后`expungeStaleEntry`直接清空value和数组中的entry，**彻底释放**。

### 3.6 rehash & 扩容

```
private void rehash() {
    // 先全量清理所有过期entry
    expungeStaleEntries();
    // 清理后，size >= 容量的1/2，才真正扩容
    if (size >= table.length * 2 / 3)
        resize();
}

// 扩容，容量翻倍
private void resize() {
    Entry[] oldTab = table;
    int oldLen = oldTab.length;
    int newLen = oldLen * 2;
    Entry[] newTab = new Entry[newLen];
    int count = 0;

    for (int j = 0; j < oldLen; ++j) {
        Entry e = oldTab[j];
        if (e != null) {
            ThreadLocal<?> k = e.get();
            if (k == null) {
                // 过期entry直接清空
                e.value = null;
            } else {
                // 有效entry，重新hash放到新数组
                int h = k.threadLocalHashCode & (newLen - 1);
                while (newTab[h] != null)
                    h = nextIndex(h, newLen);
                newTab[h] = e;
                count++;
            }
        }
    }
    setThreshold(newLen);
    size = count;
    table = newTab;
}
```

扩容逻辑：

1. 先全量清理过期Entry
2. 如果清理后元素仍然达到阈值，数组扩容为原来2倍
3. 遍历旧数组，存活的entry重新hash放入新数组，过期entry直接丢弃

# 四、内存泄漏源码层面复盘

Entry定义：

```
static class Entry extends WeakReference<ThreadLocal<?>> {
    Object value;
    Entry(ThreadLocal<?> k, Object v) {
        super(k); // key弱引用
        value = v; // value强引用
    }
}
```

场景：线程池线程长期存活

1. 外部没有ThreadLocal强引用 → `k`（弱引用）被GC，`e.get() == null`
2. 但是 `value` 是强引用，Entry对象被table数组持有
3. 如果**再也不执行get/set**，`expungeStaleEntry`永远不会触发，`value`无法释放 → 内存泄漏
✅ 解决：手动调用`remove()`，主动执行`expungeStaleEntry`清空value和entry。

>
> 为什么key设计为弱引用？
> 如果key是强引用：就算外部ThreadLocal引用释放，ThreadLocalMap的Entry还持有key强引用 → ThreadLocal对象永远不能GC，**key和value全部泄漏**。
> 弱引用只是降低泄漏风险，**不能根治，value强引用问题还在**。

# 五、InheritableThreadLocal 简单源码

继承ThreadLocal，重写了 `getMap`、`createMap`，操作的是 `inheritableThreadLocals`。

```
public class InheritableThreadLocal<T> extends ThreadLocal<T> {
    @Override
    protected ThreadLocalMap getMap(Thread t) {
       return t.inheritableThreadLocals;
    }

    @Override
    void createMap(Thread t, T firstValue) {
        t.inheritableThreadLocals = new ThreadLocalMap(this, firstValue);
    }
}
```

**拷贝发生在Thread构造方法里**

```
// Thread构造器源码片段
if (parent.inheritableThreadLocals != null)
    this.inheritableThreadLocals = ThreadLocal.createInheritedMap(parent.inheritableThreadLocals);
```

只有新建子线程的时候才会拷贝父线程的inheritableThreadLocals；**线程池复用线程，不会再次拷贝，失效**。

# 六、面试高频源码问题

1. ThreadLocalMap为什么不用HashMap，用开放寻址？

>
> Entry很小，Entry继承WeakReference，对象轻量；开放寻址不需要链表节点，节省内存。ThreadLocal一般存放数量不多，性能尚可。缺点：冲突高时性能差，删除麻烦。

2. threadLocalHashCode为什么用0x61c88647？

>
> 斐波那契散列，乘以这个魔数后，对2的幂取模，hash值分布均匀，减少哈希冲突。

3. expungeStaleEntry做了什么？

>
> 清理key为null的过期entry，清空value，遍历后面元素，存活元素重新rehash。get/set时被动触发。

4. 什么时候触发扩容？

>
> set之后，cleanSomeSlots清理过期entry，如果清理后size >= 2/3阈值，触发rehash，rehash先全量清理，清理完size>=容量2/3才resize扩容，容量翻倍。
