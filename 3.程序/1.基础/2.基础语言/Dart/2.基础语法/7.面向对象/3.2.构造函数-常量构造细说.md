# `const` 构造函数

在 Dart 中，`const` 构造函数具有特殊的用途和重要的作用，下面从多个方面详细介绍其作用。

## 创建编译时常量对象

### 原理

`const` 构造函数允许你创建编译时常量对象，相同的参数会产生相同的实例（合并优化），性能极高，常用于 Flutter 的 Widget。编译时常量是在编译阶段就确定其值的对象，在程序运行期间不会改变。使用 `const` 构造函数创建的对象，只要传入的参数也是常量，那么这个对象就会被视为编译时常量。

### 示例

```dart
class Point {
  final int x;
  final int y;

  // 定义 const 构造函数
  const Point(this.x, this.y);
}

void main() {
  // 使用 const 构造函数创建常量对象
  const point = const Point(1, 2);
  // 由于 point 是常量对象，其属性值不能修改
  // point.x = 3; // 这行代码会导致编译错误

  print(point.x); // 输出: 1
  print(point.y); // 输出: 2
}
```

在上述代码中，`Point` 类定义了一个 `const` 构造函数。在 `main` 函数里，使用 `const` 关键字调用这个构造函数创建了 `point` 对象，它是一个编译时常量。

## 编译时常量对象与相同的实例（合并优化）

既然你专门点出这句话，那我们就把 `const` 构造函数的“编译期常量”和“实例合并”这层窗户纸彻底捅破。这绝对是 Dart/Flutter 性能优化的核心知识点，很多初级开发只知道“加了 const 快”，但不知道为什么快。

我分 **“底层原理”**、**“严格限制”**、**“性能真相”** 和 **“Flutter 实战避坑”** 四个维度给你讲透。

---

### 1. 底层原理：什么是“编译期常量”与“实例合并（规范化）”？

- **编译期常量（Compile-time constant）**：意味着这个对象在**代码编译阶段**（而不是运行到 `new` 那一行时）就已经被确定下来，并被写进了 Dart 的“常量表”里。运行时直接拿现成的，不需要在堆内存（Heap）里重新分配地址。
- **实例合并（Canonicalization / 常量折叠）**：这是最精髓的。Dart 编译器会维护一个全局的“常量缓存池（Constant Canonicalization Map）”。当你创建 `const Point(1, 2)` 时，编译器会以 `Point` + `1` + `2` 作为 Key 去缓存池里查找。如果找到了，则返回该对象。否则创
  >Dart 常量池的 Key 是：类的运行时类型（Type） + 所有参数的值（Value）。不包括参数名
  >常量池中创建不同的条目，绝对代表在物理内存（静态存储区）开辟了一段固定且永久的空间。这段空间在编译期就已经预留好，不归 GC 管。常量池的本质是一个编译期固化的地址映射表：不同的 Key（类+入参值）映射到这段内存中不同的固定地址；相同的 Key 则映射到同一段固定地址，实现零成本复用。
  - 如果找到了，直接返回之前那个对象的**内存地址**（引用）。
  - 如果没找到，建一个新的缓存条目（本质是再开辟内存，作为对象数据存储空间）。

**验证代码（记住，必须用 `const` 关键字调用才会触发）：**

```dart
class Point {
  final int x, y;
  const Point(this.x, this.y); // const 构造
}

void main() {
  const p1 = Point(1, 2);
  const p2 = Point(1, 2);
  
  // identical 用来判断是否指向同一块内存地址
  print(identical(p1, p2)); // 输出: true （完全相同的实例！）
  
  // 对比：不用 const，用 new 或者直接调用
  final p3 = Point(1, 2); // 注意这里没有 const 关键字
  final p4 = Point(1, 2);
  print(identical(p3, p4)); // 输出: false （堆内存中两个不同对象）
}
```

特别说明：“不同的条目”在内存中的物理表现

假设你有两行代码：

```dart
const p1 = Point(1, 2);
const p2 = Point(3, 4);
```

编译后的内存模型大致如下（简化版）：

|内存地址（虚拟）|存储内容|对应的变量|
|:-|:-|:-|
|0x00A1|x = 1, y = 2|常量池 Key 为 (Point,1,2) 指向这里，p1 存的就是 0x00A1|
|0x00B3|x = 3, y = 4|常量池 Key 为 (Point,3,4) 指向这里，p2 存的就是 0x00B3|

这两块内存大小固定（比如都是 8 字节），它们在编译时就确定了绝对偏移量。运行时执行 const p1 = Point(1,2)，翻译成 CPU 指令仅仅是 “把地址 0x00A1 这个数字复制给变量 p1”，这是一个纳秒级的寄存器操作，完全没有“向操作系统申请内存（malloc）”的开销。

### 2. 严格限制（什么情况下才能用 `const` 构造函数？）

不是所有 `final` 类都能随便加 `const`，编译器有极其严苛的要求，否则会报错。必须同时满足以下 **4 个铁律**：

1. **所有实例变量必须是 `final` 的**（这是你已知的）。
2. **构造函数不能有函数体（`{}`）**，只能有初始化列表（`:`）或干脆为空。

   ```dart
   // 正确
   const Point(this.x, this.y); 
   // 错误！const 构造函数不允许有函数体
   const Point(this.x, this.y) { print('hello'); } 
   ```

3. **类不能继承自其他类（除了 `Object`）**，也不能有 `mixin` 或 `extends` 带非默认构造。因为 `const` 必须保证父类部分也是完全常量确定的。
4. **传递给 `const` 构造函数的参数本身也必须是 `const` 的**。这是大多数新人翻车的地方！

```dart
// 翻车示例
const int a = 5;  // 编译期常量，正确
final int b = 5;  // 运行时常量，错误！不能用 final 传给 const

const p1 = Point(a, 5); // ✅ 正确
const p2 = Point(b, 5); // ❌ 编译报错！因为 b 不是编译时常量
```

### 3. 性能真相：“合并优化”到底快在哪里？

很多人的误区是以为 `const` 只是省了点内存。其实它的威力在于**消灭了运行时对象分配（Allocation）**。

- **普通构造（`new` / 直接调用）**：每次执行到这一行，CPU 都要去堆里申请一块内存（涉及内存锁、GC 扫描），耗时约 **几十到几百纳秒**。
- **常量构造（`const`）**：编译后，这个对象的引用直接硬编码在二进制指令里（类似立即数）。运行时执行到这一行，**只有一个指针复制的动作（纳秒级）**，且**不产生任何垃圾（Zero Garbage）**，永远不会被 GC 回收。

### 4. Flutter 实战中的“黄金法则”与“避坑”

Flutter 中 Widget 都是不可变的（配合 `@immutable` 注解），因此标准库中几乎所有 Widget 都提供了 `const` 构造函数（例如 `Text('hello')`、`Padding`、`Container`）。

**高频场景（性能优化实操）：**

在 `build` 方法中，如果你写成这样：

```dart
@override
Widget build(BuildContext context) {
  return Column(children: [
    Text('Hello'), // 这里其实是 const Text('Hello')，Dart 会自动推断吗？
    MyCustomWidget(), 
  ]);
}
```

**关键避坑点 1：Dart 的“常量上下文（Constant Context）”**
如果在 `const` 上下文里，子元素会自动变成 `const`。

```dart
// 手动加 const，告诉编译器我要缓存
const Column(children: [
  Text('Hello'),    // 因为父级是 const，这里 Text 自动就是 const，不需要再写一遍
  Icon(Icons.star), // 这也是 const
]);
```

**关键避坑点 2：自定义 Widget 忘了加 `const`，你会血亏**
如果你的自定义 StatelessWidget 的所有字段都是 `final`，**一定要加上 `const` 构造函数**。否则父级刷新时，即使参数没变，Flutter 也会重建你这个 Widget 实例，触发昂贵的 `build`。

```dart
class MyButton extends StatelessWidget {
  final String label;
  // 必须加 const，哪怕你不主动调用，别人也可以 const MyButton 调用
  const MyButton({super.key, required this.label}); 

  @override
  Widget build(BuildContext context) => Text(label);
}
```

**关键避坑点 3：动态参数会让 `const` 失效**
如果你这样写：

```dart
const Text(DateTime.now().toString()) // ❌ 编译报错！因为 now() 不是常量
```

或者：

```dart
String name = getUserName();
const Text(name) // ❌ 报错，变量不是常量
// 这时编译器会默默忽略你的 const，降级为普通构造（有些 IDE 会给你灰掉 const 关键字提示）
```

### 5. 终极拷问：`const` 构造 + `final` 变量是不是就彻底无敌了？

只要满足上述条件，**在 Dart 编译时就确定内容**的对象，全局共享一份数据。但如果你的 `final` 字段是**集合（List/Map）**呢？

```dart
class Data {
  final List<int> list;
  const Data(this.list);
}

// 这样写没问题，但要确保传入的 list 本身也是 const
const d1 = Data([1, 2, 3]); 
// ❌ 报错！因为 [1,2,3] 是运行时的 List，不是常量 List
// 必须改成：
const d1 = Data([1, 2, 3]); // 还是报错？ 
// 正解：要明确声明列表是 const 的
const d1 = Data(const [1, 2, 3]); 
// 或者利用常量上下文省略：const Data([1, 2, 3]) 也可以，因为父级是 const，子级自动推断为 const。
```

### 总结一句话：

`const` 构造函数 = **“编译期盖戳入库 + 运行时零开销指针复用”**。  
在 Flutter 中，**凡是 `build` 方法里不变的部分，能加 `const` 就加 `const`**，这是最廉价也最有效的性能压舱石。现在回过头看你引用的那句话，应该已经彻底吃透了吧！还有什么要拷问我的吗？ 😎
