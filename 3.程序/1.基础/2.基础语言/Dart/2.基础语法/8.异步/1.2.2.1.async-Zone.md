# Dart Zone 完全详解

## 一、Zone 是什么

### 1.1 概念定义

`Zone` 是 Dart 中的**代码执行沙箱（Sandbox）**，可以理解为代码运行的"上下文环境"。每一段 Dart 代码都运行在某个 Zone 中，默认的 Zone 是**根 Zone（root zone）**。

Zone 的本质是一个**代码执行的边界**，它可以：

- 拦截和修改代码的执行行为
- 捕获未处理的异常
- 存储和传递上下文数据
- 追踪异步操作的来源

### 1.2 类比理解

| 概念 | 类比 |
| --- | --- |
| Zone | 进程/沙箱 |
| ZoneValues | 环境变量 / ThreadLocal |
| ZoneSpecification | 系统调用拦截器 |
| 嵌套 Zone | 子进程继承父进程环境 |

---

## 二、Zone 的核心作用

### 2.1 异常捕获

捕获同步和异步代码中未被 `try-catch` 处理的异常。

### 2.2 行为拦截

可以重写 `print`、`Timer`、`microtask`、`Future` 等核心行为。

### 2.3 上下文传递

在异步调用链中保持上下文数据（类似线程局部变量）。

### 2.4 代码隔离

不同 Zone 中的代码互不干扰，一个 Zone 的异常不会影响其他 Zone。

## 三、Zone 的创建方式

### 3.1 `runZoned`（基础方式）

```
import 'dart:async';

void main() {
  runZoned(() {
    print('在新 Zone 中执行');
    print(Zone.current); // Instance of '_CustomZone'
  });
  
  print(Zone.current); // Instance of '_RootZone'
}
```

### 3.2 `runZonedGuarded`（带异常捕获）

```
runZonedGuarded(() {
  throw '同步异常'; // ✅ 被捕获
}, (error, stack) {
  print('捕获异常: $error');
});
```

### 3.3 `Zone.current.fork`（手动 fork）

最灵活的方式，可以完全自定义 Zone 行为：

```
final myZone = Zone.current.fork(
  specification: ZoneSpecification(
    print: (self, parent, zone, line) {
      parent.print(zone, '[PREFIX] $line');
    },
  ),
  zoneValues: {
    #key: 'value',
  },
);

myZone.run(() {
  print('hello'); // 输出: [PREFIX] hello
});
```

## 四、Zone 的核心属性与方法

### 4.1 获取当前 Zone

```
Zone currentZone = Zone.current;
```

### 4.2 父 Zone

```
Zone? parentZone = Zone.current.parent;
```

> 
> 根 Zone 的 parent 为 `null`

### 4.3 在 Zone 中执行代码

```
// 无返回值
zone.run(() {
  print('在 zone 中执行');
});

// 有返回值
final result = zone.run(() {
  return 42;
});

// 带一个参数
zone.runUnary((int value) {
  print('value: $value');
}, 100);

// 带两个参数
zone.runBinary((int a, int b) {
  return a + b;
}, 1, 2);
```

### 4.4 绑定回调

将回调函数绑定到当前 Zone，确保回调执行时在正确的 Zone 中：

```
// 绑定无参回调
final callback = Zone.current.bindCallback(() {
  print('回调执行');
});

// 绑定单参回调
final unaryCallback = Zone.current.bindUnaryCallback((int x) {
  print('x = $x');
});

// 绑定双参回调
final binaryCallback = Zone.current.bindBinaryCallback((int a, int b) {
  print('a + b = ${a + b}');
});
```

### 4.5 ZoneValues 操作

```
// 读取值
final value = Zone.current[#myKey];

// 检查是否存在
final exists = Zone.current[#myKey] != null;
```

> 
> 注意：ZoneValues 是**只读**的，不能在 Zone 运行时修改，只能在 fork 时设置。

## 五、ZoneSpecification 详解

`ZoneSpecification` 用于定制 Zone 的行为，可以拦截/重写 Zone 中的各种操作。

### 5.1 完整可拦截项

```
ZoneSpecification(
  // ===== 异常处理 =====
  handleUncaughtError: (self, parent, zone, error, stackTrace) {
    // 未捕获的异常
    parent.handleUncaughtError(zone, error, stackTrace);
  },

  // ===== 打印 =====
  print: (self, parent, zone, line) {
    // 拦截 print 调用
    parent.print(zone, '[LOG] $line');
  },

  // ===== 任务调度 =====
  scheduleMicrotask: (self, parent, zone, f) {
    // 拦截微任务调度
    parent.scheduleMicrotask(zone, f);
  },

  createTimer: (self, parent, zone, duration, callback) {
    // 拦截 Timer 创建
    return parent.createTimer(zone, duration, callback);
  },

  createPeriodicTimer: (self, parent, zone, period, callback) {
    // 拦截周期 Timer 创建
    return parent.createPeriodicTimer(zone, period, callback);
  },

  // ===== 代码执行 =====
  run: (self, parent, zone, f) {
    // 拦截同步执行
    return parent.run(zone, f);
  },

  runUnary: (self, parent, zone, f, arg) {
    // 拦截单参执行
    return parent.runUnary(zone, f, arg);
  },

  runBinary: (self, parent, zone, f, arg1, arg2) {
    // 拦截双参执行
    return parent.runBinary(zone, f, arg1, arg2);
  },

  // ===== 回调绑定 =====
  bindCallback: (self, parent, zone, f) {
    return parent.bindCallback(zone, f);
  },

  bindUnaryCallback: (self, parent, zone, f) {
    return parent.bindUnaryCallback(zone, f);
  },

  bindBinaryCallback: (self, parent, zone, f) {
    return parent.bindBinaryCallback(zone, f);
  },

  // ===== Zone 操作 =====
  fork: (self, parent, zone, specification, zoneValues) {
    // 拦截 Zone fork
    return parent.fork(zone, specification, zoneValues);
  },
)
```

### 5.2 参数说明

每个拦截回调都有统一的前三个参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `self` | `Zone` | 当前 Zone 对象本身 |
| `parent` | `ZoneDelegate` | 父 Zone 的委托，用于调用父 Zone 的原始行为 |
| `zone` | `Zone` | 当前执行代码所在的 Zone |

### 5.3 实际应用示例

#### 示例1：日志增强

```
runZoned(() {
  print('用户登录');
  print('数据加载完成');
}, zoneSpecification: ZoneSpecification(
  print: (self, parent, zone, line) {
    final timestamp = DateTime.now().toIso8601String();
    parent.print(zone, '[$timestamp] $line');
  },
));

// 输出:
// [2024-01-15T10:30:00.000] 用户登录
// [2024-01-15T10:30:00.001] 数据加载完成
```

#### 示例2：性能监控

```
runZoned(() {
  // 业务代码
  someAsyncOperation();
}, zoneSpecification: ZoneSpecification(
  run: (self, parent, zone, f) {
    final stopwatch = Stopwatch()..start();
    try {
      return parent.run(zone, f);
    } finally {
      stopwatch.stop();
      parent.print(zone, '执行耗时: ${stopwatch.elapsedMilliseconds}ms');
    }
  },
  
  createTimer: (self, parent, zone, duration, callback) {
    print('创建 Timer: ${duration.inMilliseconds}ms');
    return parent.createTimer(zone, duration, callback);
  },
));
```

#### 示例3：错误分级处理

```
runZoned(() {
  // 业务代码
}, zoneSpecification: ZoneSpecification(
  handleUncaughtError: (self, parent, zone, error, stackTrace) {
    if (error is NetworkError) {
      // 网络错误：提示用户重试
      _showRetryDialog();
    } else if (error is AuthError) {
      // 认证错误：跳转到登录页
      _redirectToLogin();
    } else {
      // 其他错误：上报并显示通用错误页
      _reportError(error, stackTrace);
      _showErrorPage(error);
    }
  },
));
```

## 六、ZoneValues 详解

### 6.1 基本使用

```
runZoned(() {
  // 读取 Zone 数据
  final userId = Zone.current[#userId];
  final traceId = Zone.current[#traceId];
  
  print('用户: $userId, 追踪ID: $traceId');
  
  // 异步回调中也能获取到
  Future.delayed(Duration(seconds: 1), () {
    print('异步中 - 用户: ${Zone.current[#userId]}');
  });
}, zoneValues: {
  #userId: 'user_123',
  #traceId: 'trace_abc_xyz',
  #role: 'admin',
});
```

### 6.2 为什么用 Symbol 作为 Key

使用 `#xxx` 形式的 Symbol 可以避免字符串拼写错误，并且在编译时优化：

```
// Symbol 形式（推荐）
Zone.current[#userId]

// 字符串形式（也可以）
Zone.current['userId']
```

### 6.3 继承与覆盖

子 Zone 会继承父 Zone 的所有 values，也可以覆盖：

```
runZoned(() {
  print('外层 a: ${Zone.current[#a]}'); // 1
  print('外层 b: ${Zone.current[#b]}'); // 2
  
  runZoned(() {
    print('内层 a: ${Zone.current[#a]}'); // 1（继承）
    print('内层 b: ${Zone.current[#b]}'); // 3（覆盖）
    print('内层 c: ${Zone.current[#c]}'); // 4（新增）
  }, zoneValues: {
    #b: 3,  // 覆盖父 Zone 的值
    #c: 4,  // 新增值
  });
}, zoneValues: {
  #a: 1,
  #b: 2,
});
```

### 6.4 典型应用场景

| 场景 | 说明 |
| --- | --- |
| 链路追踪 | 请求级别的 traceId、spanId |
| 用户上下文 | 当前登录用户信息 |
| 请求上下文 | HTTP 请求的相关数据 |
| 国际化 | 当前语言/地区设置 |
| 配置信息 | 环境配置、特性开关 |

## 七、Zone 与异步编程

### 7.1 异步回调的 Zone 绑定

**核心规则**：异步回调执行时，会回到**创建它时的 Zone** 中执行。

```
runZoned(() {
  final zoneName = Zone.current[#name];
  print('创建 Future 时的 Zone: $zoneName'); // Zone A
  
  Future.delayed(Duration(seconds: 1), () {
    // 回调执行时，回到创建 Future 时的 Zone
    print('回调执行时的 Zone: ${Zone.current[#name]}'); // Zone A
  });
}, zoneValues: {#name: 'Zone A'});
```

### 7.2 Zone 与 Future

```
Future<String> fetchData() {
  return Future(() {
    // 这个 Future 在哪个 Zone 创建，回调就在哪个 Zone 执行
    return 'data';
  });
}

runZoned(() {
  fetchData().then((data) {
    print('在 Zone A 中处理: $data');
  });
}, zoneValues: {#name: 'Zone A'});
```

### 7.3 Zone 与 Stream

```
runZoned(() {
  final controller = StreamController<int>();
  
  controller.stream.listen((data) {
    // 监听回调在创建 Stream 时的 Zone 执行
    print('收到数据: $data, Zone: ${Zone.current[#name]}');
  });
  
  controller.add(1);
  controller.add(2);
}, zoneValues: {#name: 'Stream Zone'});
```

### 7.4 跨 Zone 的异常传播

```
void main() {
  runZonedGuarded(() {
    final future = Future.error('错误');
    
    // 即使在另一个 Zone 中监听，异常还是会传播到创建 Future 的 Zone
    runZonedGuarded(() {
      future.then((_) {}); // 没有 catchError
    }, (e, s) {
      print('内层捕获: $e'); // ❌ 不会执行
    });
  }, (e, s) {
    print('外层捕获: $e'); // ✅ 执行
  });
}
```

## 八、嵌套 Zone

### 8.1 嵌套结构

```
Root Zone
  └── Zone A
       └── Zone B
            └── Zone C
```

### 8.2 嵌套规则

1. **继承**：子 Zone 继承父 Zone 的 specification 和 values
2. **覆盖**：子 Zone 可以覆盖父 Zone 的行为
3. **隔离**：子 Zone 的异常不会逃逸到父 Zone（除非主动传播）
4. **查找**：读取 value 时，从当前 Zone 向上查找

### 8.3 嵌套示例

```
void main() {
  // 第一层 Zone
  runZoned(() {
    print('Level 1: ${Zone.current[#level]}');
    
    // 第二层 Zone
    runZoned(() {
      print('Level 2: ${Zone.current[#level]}');
      
      // 第三层 Zone
      runZoned(() {
        print('Level 3: ${Zone.current[#level]}');
        print('app: ${Zone.current[#app]}'); // 继承自最外层
      }, zoneValues: {#level: 3});
      
    }, zoneValues: {#level: 2});
    
  }, zoneValues: {
    #level: 1,
    #app: 'MyApp',
  });
}

// 输出:
// Level 1: 1
// Level 2: 2
// Level 3: 3
// app: MyApp
```

## 九、Zone 的实际应用场景

### 9.1 全局异常监控

```
void main() {
  runZonedGuarded(() {
    runApp(MyApp());
  }, (error, stack) {
    // 上报到监控平台
    CrashReport.report(error, stack);
  });
}
```

### 9.2 请求级别的上下文

```
void handleRequest(Request request) {
  runZoned(() {
    // 整个请求处理过程中都可以获取 traceId
    processRequest(request);
  }, zoneValues: {
    #traceId: generateTraceId(),
    #requestId: request.id,
    #userId: request.userId,
  });
}

void processRequest(Request request) {
  final traceId = Zone.current[#traceId];
  print('[$traceId] 处理请求');
  
  // 异步调用中也能获取
  db.query().then((_) {
    print('[$traceId] 数据库查询完成');
  });
}
```

### 9.3 AOP 切面编程

```
runZoned(() {
  // 业务代码
  doSomething();
}, zoneSpecification: ZoneSpecification(
  // 统一日志
  print: (self, parent, zone, line) {
    parent.print(zone, '[${DateTime.now()}] $line');
  },
  
  // 统一性能监控
  run: (self, parent, zone, f) {
    final sw = Stopwatch()..start();
    try {
      return parent.run(zone, f);
    } finally {
      sw.stop();
      Metrics.record(sw.elapsed);
    }
  },
  
  // 统一异常处理
  handleUncaughtError: (self, parent, zone, error, stack) {
    Logger.error(error, stack);
    AlertService.notify(error);
  },
));
```

### 9.4 沙箱隔离执行

```
void executePlugin(Plugin plugin) {
  // 每个插件在独立的 Zone 中运行
  runZonedGuarded(() {
    plugin.run();
  }, (error, stack) {
    // 插件异常不影响主程序
    print('插件 ${plugin.name} 出错: $error');
    plugin.onError(error, stack);
  }, zoneValues: {
    #pluginId: plugin.id,
    #pluginVersion: plugin.version,
  });
}
```

## 十、Flutter 中的 Zone

### 10.1 Flutter 框架与 Zone

Flutter 框架内部大量使用 Zone：

- `runApp()` 会确保在合适的 Zone 中运行
- 手势事件、动画帧回调都有 Zone 绑定
- `compute()` 函数（Isolate）也涉及 Zone 概念

### 10.2 Flutter 中的完整异常捕获方案

```
void main() {
  runZonedGuarded(() {
    WidgetsFlutterBinding.ensureInitialized();

    // 1. Flutter 框架错误（构建/布局/渲染）
    FlutterError.onError = (details) {
      _reportError(details.exception, details.stack, 'Flutter');
    };

    // 2. 平台调度器错误（Flutter 3.3+）
    PlatformDispatcher.instance.onError = (error, stack) {
      _reportError(error, stack, 'Platform');
      return true;
    };

    runApp(const MyApp());
  }, (error, stack) {
    // 3. Dart 异步异常（Zone 捕获）
    _reportError(error, stack, 'Zone');
  });
}
```

### 10.3 Widget 构建中的 Zone

```
class MyWidget extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    // build 方法在哪个 Zone 执行？
    // 答案：在 runApp 所在的 Zone 中执行
    print(Zone.current);
    return Container();
  }
}
```

## 十一、注意事项与最佳实践

### 11.1 常见陷阱

#### ❌ 陷阱1：Zone 内创建的异步，异常不会跑到外层

```
runZonedGuarded(() {
  // 这个 Future 是在根 Zone 创建的
  final future = Future.error('error');
  
  runZonedGuarded(() {
    future.then((_) {}); // 没有 catch
    // 异常不会被内层 Zone 捕获，因为 Future 是在外层创建的
  }, (e, s) {
    print('内层捕获'); // ❌ 不会执行
  });
}, (e, s) {
  print('外层捕获'); // ✅ 执行
});
```

#### ❌ 陷阱2：zoneValues 不能运行时修改

```
runZoned(() {
  // ❌ 错误：不能直接修改
  Zone.current[#key] = 'newValue'; // 编译错误
  
  // ✅ 正确：fork 一个新 Zone
  Zone.current.fork(zoneValues: {#key: 'newValue'}).run(() {
    print(Zone.current[#key]); // newValue
  });
});
```

#### ❌ 陷阱3：Isolate 之间不共享 Zone

```
// Isolate 有自己独立的 Zone 体系
// 主 Isolate 的 Zone 配置不会影响新创建的 Isolate
compute(heavyTask, data); // 新 Isolate 使用默认的根 Zone
```

### 11.2 最佳实践

1. **顶层使用 `runZonedGuarded`**：作为全局异常兜底
2. **配合 `FlutterError.onError`**：覆盖框架层面的错误
3. **合理使用 `zoneValues`**：用于请求级别的上下文传递
4. **不要过度嵌套 Zone**：每层 Zone 都有性能开销
5. **错误处理要幂等**：`onError` 中不要抛出新异常
6. **开发/生产区分处理**：开发环境打印详细信息，生产环境只上报

### 11.3 性能考虑

- Zone 的创建和使用有一定开销，但通常可以忽略
- 避免在高频调用的代码中频繁创建 Zone
- 嵌套层级不宜过深（一般 2-3 层足够）

## 十二、总结

| 特性 | 说明 |
| --- | --- |
| **本质** | Dart 代码的执行沙箱/上下文 |
| **核心能力** | 异常捕获、行为拦截、数据传递、代码隔离 |
| **创建方式** | `runZoned` / `runZonedGuarded` / `Zone.fork` |
| **定制方式** | `ZoneSpecification`（行为）+ `zoneValues`（数据） |
| **异步关系** | 异步回调绑定创建时的 Zone |
| **继承规则** | 子 Zone 继承父 Zone，可覆盖 |
| **典型应用** | 异常监控、日志增强、上下文传递、沙箱隔离 |
