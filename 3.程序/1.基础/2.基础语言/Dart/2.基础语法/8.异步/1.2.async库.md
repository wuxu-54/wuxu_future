# Dart `dart:async` 完全指南

`dart:async` 是 Dart 标准库中最核心的库之一，提供了**异步编程**的全部基础设施。下面我从底层原理到上层 API 逐层拆解。

---

## 一、整体架构与核心概念

### 1.1 库的组成

```
dart:async
├── Future / Completer          —— 单次异步结果
├── Stream / StreamController   —— 多次异步事件流
├── StreamSubscription          —— 流的订阅句柄
├── StreamTransformer           —— 流的转换
├── StreamSink / EventSink      —— 流的写入端
├── Timer                       —— 定时器
├── Zone                        —— 执行上下文沙箱
├── scheduleMicrotask           —— 微任务调度
└── 各种辅助类 (StreamView, StreamIterator, DeferredLibrary 等)
```

### 1.2 Dart 的事件循环模型

Dart 是**单线程**模型，所有代码都在同一个 isolate 的主线程上执行，通过事件循环驱动异步：

```
┌──────────────────────────────────┐
│         事件循环 (Event Loop)      │
│                                  │
│  ┌────────────┐  优先执行         │
│  │ 微任务队列  │ ◄──────────────  │
│  │ (Microtask)│  每次事件循环开始  │
│  └─────┬──────┘                  │
│        │ 全部清空后                │
│        ▼                         │
│  ┌────────────┐                  │
│  │ 事件队列    │                  │
│  │ (Event)    │  每次取一个       │
│  └────────────┘                  │
└──────────────────────────────────┘
```

- **微任务队列 (Microtask Queue)**：优先级最高，`scheduleMicrotask()`、`Future.then()` 的回调会进入这里
- **事件队列 (Event Queue)**：I/O、手势、定时器、`Future.delayed()`、`Stream` 事件等进入这里

**执行顺序规则**：

1. 先把当前同步代码执行完
2. 清空所有微任务（微任务里产生的微任务也会在本轮清空）
3. 从事件队列取**一个**事件执行
4. 回到第 2 步，再次清空微任务
5. 循环往复

## 二、Future 详解

### 2.1 Future 的三种状态

| 状态 | 说明 |
| --- | --- |
| **未完成 (Incomplete / Pending)** | 异步操作还在进行中 |
| **已完成 - 带值 (Completed with value)** | 操作成功，返回一个结果 |
| **已完成 - 带错误 (Completed with error)** | 操作失败，返回一个错误 |

Future 一旦完成（无论成功还是失败），状态就**不可改变**。

### 2.2 创建 Future 的方式

#### 方式一：`Future(FutureOr<T> computation())`

```
// 把 computation 放到事件队列中异步执行
Future(() {
  print('在事件队列中执行');
  return 42;
});
```

#### 方式二：`Future.microtask(FutureOr<T> computation())`

```
// 把 computation 放到微任务队列中，优先级更高
Future.microtask(() {
  print('在微任务队列中执行');
  return 42;
});
```

#### 方式三：`Future.value(T value)`

```
// 立即以指定值完成（但 then 回调仍是异步的，会进入微任务）
Future.value(42).then(print); // 异步打印 42
```

#### 方式四：`Future.error(Object error, [StackTrace? stackTrace])`

```
// 立即以错误完成
Future.error(Exception('出错了'));
```

#### 方式五：`Future.delayed(Duration duration, [FutureOr<T> computation()?])`

```
// 延迟指定时间后执行
Future.delayed(Duration(seconds: 2), () => '2秒后');
```

#### 方式六：`Future.sync(FutureOr<T> computation())`

```
// 同步执行 computation，然后把结果包装成 Future
// 如果 computation 是同步的，它会立即在当前帧执行
Future.sync(() {
  print('同步执行');
  return 42;
});
```

### 2.3 链式调用：then / catchError / whenComplete

```
Future<String> fetchUser() async => 'Alice';

fetchUser()
  .then((user) {
    print('用户: $user');
    return user.length;          // 可以返回新的值，类型会变化
  })
  .then((length) {
    print('名字长度: $length');
    return Future.value(100);    // 也可以返回另一个 Future
  })
  .then((value) {
    print('值: $value');
  })
  .catchError((error) {
    print('捕获错误: $error');   // 捕获链中任何一步的错误
  }, test: (e) => e is FormatException) // 可选：按类型过滤
  .whenComplete(() {
    print('无论成功失败都执行');  // 类似 finally
  });
```

**关键细节**：

- `then` 返回的是新的 Future，链式调用中每一步都可以改变类型
- `catchError` 可以有 `test` 参数，只捕获特定类型的错误
- `catchError` 本身也返回 Future，如果在 catchError 中返回正常值，后续 then 会继续执行（相当于"恢复"）
- `whenComplete` 不改变 Future 的值或错误，只是在完成时执行副作用

### 2.4 async / await

`async/await` 是 Future 的语法糖，让异步代码看起来像同步代码：

```
Future<void> main() async {
  try {
    final user = await fetchUser();      // 等待 Future 完成
    final profile = await fetchProfile(user.id);
    print('$user - $profile');
  } catch (e) {
    print('错误: $e');
  } finally {
    print('结束');
  }
}
```

**重要规则**：

- `async` 函数**总是返回 Future**，即使函数体里没有 await
- `async` 函数中未被捕获的异常会变成返回 Future 的 error
- `await` 只能在 `async` 函数中使用
- `await for` 可以等待 Stream（后面讲）

### 2.5 Future 的静态工具方法

#### `Future.wait<T>(Iterable<Future<T>> futures, {bool eagerError = false, void cleanUp(T successValue)?})`

并行等待多个 Future：

```
// 等待所有 Future 完成，返回结果列表
final results = await Future.wait([
  fetchUser(),
  fetchPosts(),
  fetchComments(),
]);
```

- `eagerError: true`：任何一个 Future 出错就立即报错，不等其他的
- `cleanUp`：出错时，对已经成功完成的 Future 做清理

#### `Future.any<T>(Iterable<Future<T>> futures)`

返回第一个完成的 Future 的结果（无论成功还是失败）：

```
final first = await Future.any([
  fetchFromCache(),
  fetchFromNetwork(),
]); // 谁先完成用谁
```

#### `Future.doWhile(FutureOr<bool> action())`

重复执行直到返回 false：

```
var count = 0;
await Future.doWhile(() async {
  count++;
  print(count);
  await Future.delayed(Duration(milliseconds: 100));
  return count < 10;
});
```

#### `Future.forEach<T>(Iterable<T> elements, FutureOr<void> action(T element))`

对每个元素依次执行异步操作：

```
await Future.forEach([1, 2, 3], (n) async {
  await Future.delayed(Duration(seconds: 1));
  print(n);
});
```

#### `Future.microtask` vs `Future` vs `Future.delayed` 执行顺序

```
void main() {
  print('1. 同步开始');
  
  Future.delayed(Duration.zero, () => print('2. Future.delayed'));
  Future(() => print('3. Future()'));
  Future.microtask(() => print('4. Future.microtask'));
  Future.value().then((_) => print('5. Future.value.then'));
  
  print('6. 同步结束');
}
```

**输出顺序**：

```
1. 同步开始
6. 同步结束
4. Future.microtask      ← 微任务优先
5. Future.value.then     ← then 回调也是微任务
3. Future()              ← 事件队列
2. Future.delayed        ← 事件队列（定时器）
```

### 2.6 Completer：手动控制 Future

`Completer` 让你可以**手动**控制一个 Future 何时完成：

```
class AsyncCache<T> {
  final Completer<T> _completer = Completer<T>();
  
  Future<T> get future => _completer.future;
  
  void complete(T value) {
    if (!_completer.isCompleted) {
      _completer.complete(value);
    }
  }
  
  void completeError(Object error) {
    if (!_completer.isCompleted) {
      _completer.completeError(error);
    }
  }
}
```

**使用场景**：

- 把回调式 API 转换成 Future
- 手动控制完成时机
- 缓存异步结果

**注意**：

- `Completer.complete()` 只能调用一次，重复调用会报错
- 调用 `complete()` 后再调用 `completeError()` 也会报错
- 可以用 `isCompleted` 属性检查状态

## 三、Stream 详解

Stream 是 Dart 中**异步事件序列**的抽象，相当于"异步的 Iterable"。

### 3.1 Stream vs Future 对比

| 维度 | Future | Stream |
| --- | --- | --- |
| 事件数量 | 1 个（成功或失败） | 0 个或多个 |
| 完成方式 | 一次完成 | 可以有 done 事件 |
| 拉/推 | 拉模式（await 拿结果） | 推模式（订阅后推送事件） |
| 取消 | 不能取消 | 可以通过 subscription 取消 |

### 3.2 Stream 的两种类型

#### 单订阅 Stream (Single-Subscription)

```
final stream = Stream.fromIterable([1, 2, 3]);

stream.listen(print); // 可以
// stream.listen(print); // 报错：Bad state: Stream has already been listened to.
```

- 只能被监听一次
- 监听后才开始产生事件
- 取消订阅后不能再重新监听
- 大多数 Stream 默认是单订阅的

#### 广播 Stream (Broadcast)

```
final stream = Stream<int>.periodic(Duration(seconds: 1), (n) => n)
  .asBroadcastStream();

stream.listen((n) => print('订阅1: $n'));
stream.listen((n) => print('订阅2: $n')); // 可以，多个订阅者
```

- 可以有多个订阅者
- 没有订阅者时，事件会被丢弃（不会缓存）
- 新订阅者不会收到订阅前已经发出的事件

**转换方式**：

```
// 单订阅 → 广播
final broadcastStream = singleStream.asBroadcastStream();

// 广播 → 单订阅（取一个新的单订阅视图）
final singleStream = broadcastStream.asBroadcastStream().take(1); // 间接方式
```

### 3.3 创建 Stream 的方式

#### 方式一：`Stream.fromIterable(Iterable<T> elements)`

```
// 同步地依次发出所有元素
Stream.fromIterable([1, 2, 3, 4, 5]).listen(print);
```

#### 方式二：`Stream.fromFuture(Future<T> future)`

```
// Future 完成时发出一个事件，然后结束
Stream.fromFuture(Future.delayed(Duration(seconds: 1), () => 42))
  .listen(print);
```

#### 方式三：`Stream.fromFutures(Iterable<Future<T>> futures)`

```
// 每个 Future 完成时发出一个事件
// 注意：顺序不一定是 futures 的顺序，而是按完成顺序
Stream.fromFutures([
  Future.delayed(Duration(seconds: 2), () => '慢'),
  Future.delayed(Duration(seconds: 1), () => '快'),
]).listen(print); // 先打印"快"，再打印"慢"
```

#### 方式四：`Stream.periodic(Duration period, [T computation(int computationCount)?])`

```
// 周期性地发出事件
Stream.periodic(Duration(seconds: 1), (count) => count * 2)
  .take(5)
  .listen(print); // 0, 2, 4, 6, 8
```

#### 方式五：`Stream.empty()`

```
// 空流，立即发送 done 事件
Stream.empty().listen(
  print,
  onDone: () => print('结束'),
);
```

#### 方式六：`Stream.error(Object error, [StackTrace? stackTrace])`

```
// 只发出一个错误事件
Stream.error(Exception('出错了')).listen(
  print,
  onError: (e) => print('错误: $e'),
);
```

#### 方式七：`async* / yield`（生成器函数）

最常用、最灵活的方式：

```
Stream<int> countStream(int max) async* {
  for (int i = 1; i <= max; i++) {
    await Future.delayed(Duration(seconds: 1));
    yield i;              // 发出一个事件
  }
}

// 递归 yield
Stream<int> countdown(int n) async* {
  if (n > 0) {
    yield n;
    yield* countdown(n - 1); // yield* 委托给另一个 Stream
  }
}
```

#### 方式八：StreamController（最底层、最灵活）

后面单独讲。

### 3.4 监听 Stream：`listen`

```
final subscription = stream.listen(
  (data) {
    print('数据: $data');          // 数据事件回调
  },
  onError: (error, stackTrace) {
    print('错误: $error');         // 错误事件回调
  },
  onDone: () {
    print('完成');                  // 完成事件回调
  },
  cancelOnError: false,            // 遇到错误是否自动取消订阅
);
```

**cancelOnError 行为**：

- `false`（默认）：错误后继续接收后续事件
- `true`：遇到第一个错误就取消订阅，流结束

### 3.5 StreamSubscription：订阅句柄

```
final subscription = stream.listen(print);

// 暂停订阅
subscription.pause();
subscription.pause(Future.delayed(Duration(seconds: 2))); // 2秒后自动恢复

// 检查是否暂停
print(subscription.isPaused);

// 恢复订阅
subscription.resume();

// 替换回调
subscription.onData((data) => print('新回调: $data'));
subscription.onError((e) => print('新错误回调: $e'));
subscription.onDone(() => print('新完成回调'));

// 取消订阅
await subscription.cancel();
```

**重要细节**：

- `pause()` 后，单订阅 Stream 的事件会被缓存，恢复后依次发出
- 广播 Stream 的事件在暂停期间会被丢弃
- `cancel()` 返回一个 Future，表示取消完成
- 取消后再调用 `pause/resume` 没有效果

### 3.6 Stream 的常用操作方法

Stream 有大量类似 Iterable 的操作方法，返回的都是新的 Stream：

#### 转换类

```
stream.map((e) => e * 2);                    // 转换每个元素
stream.where((e) => e.isEven);               // 过滤元素
stream.expand((e) => [e, e * 10]);           // 一对多展开
stream.cast<int>();                          // 类型转换
stream.typeToken<int>();                     // 运行时类型检查
```

#### 截取/跳过类

```
stream.take(5);                              // 只取前 5 个
stream.takeWhile((e) => e < 10);             // 满足条件时取
stream.skip(3);                              // 跳过前 3 个
stream.skipWhile((e) => e < 10);             // 满足条件时跳过
stream.distinct();                           // 去重（相邻相同的去掉）
stream.distinct((a, b) => a.id == b.id);     // 自定义相等判断
```

#### 异步转换类

```
stream.asyncMap((e) async => await process(e));     // 异步 map，保持顺序
stream.asyncExpand((e) => processStream(e));        // 异步 expand
stream.asyncMap((e) => Future.delayed(...));        // 每个事件异步处理
```

**`asyncMap` vs `map` + `async`**：

- `map((e) async => ...)` 返回的是 `Stream<Future<T>>`
- `asyncMap((e) async => ...)` 返回的是 `Stream<T>`，会自动 await

#### 累积/归约类

```
stream.fold<int>(0, (sum, e) => sum + e);     // 累积，返回 Future
stream.reduce((a, b) => a + b);               // 归约，返回 Future
stream.toList();                              // 收集到 List，返回 Future
stream.toSet();                               // 收集到 Set
```

#### 组合类

```
stream.concat(otherStream);                   // 连接两个流（等第一个结束再接第二个）
stream.merge(otherStream);                    // 合并两个流（同时进行）— 注意：dart:async 没有 merge，需要 rxdart
stream.transform(transformer);                // 使用 StreamTransformer 转换
```

#### 条件/检查类

```
stream.any((e) => e > 10);                    // 是否有任意一个满足
stream.every((e) => e > 0);                   // 是否全部满足
stream.contains(5);                           // 是否包含
stream.first;                                 // 第一个元素 (Future)
stream.last;                                  // 最后一个元素 (Future)
stream.single;                                // 唯一元素（不是唯一则报错）
stream.isEmpty;                               // 是否为空
stream.length;                                // 元素个数
```

#### 副作用类

```
stream.handleError((e) => print('处理错误'));  // 处理错误但不终止
stream.whereType<int>();                      // 按类型过滤
```

### 3.7 `await for`：异步 for 循环

```
Future<void> main() async {
  // 等待流的每个事件
  await for (final value in countStream(5)) {
    print(value);
    if (value == 3) break;  // break 会自动取消订阅
  }
}
```

**等价于**：

```
final subscription = stream.listen(print);
await subscription.asFuture();
```

### 3.8 StreamController：手动创建 Stream

StreamController 是创建自定义 Stream 的最底层方式：

```
final controller = StreamController<int>(
  onListen: () => print('有人监听了'),
  onPause: () => print('暂停了'),
  onResume: () => print('恢复了'),
  onCancel: () => print('取消了'),
  sync: false,  // false: 异步发送; true: 同步发送
);

// 发送事件
controller.add(1);
controller.add(2);
controller.addError(Exception('出错了'));
controller.close();  // 发送 done 事件

// 获取流
controller.stream.listen(
  print,
  onError: print,
  onDone: () => print('完成'),
);
```

#### 回调详解

| 回调 | 触发时机 | 用途 |
| --- | --- | --- |
| `onListen` | 第一次被监听时 | 初始化资源、开始产生事件 |
| `onPause` | 订阅者暂停时 | 暂停资源（如停止下载） |
| `onResume` | 订阅者恢复时 | 恢复资源 |
| `onCancel` | 最后一个订阅者取消时 | 释放资源 |

#### 单订阅 vs 广播 Controller

```
// 单订阅 Controller（默认）
final singleController = StreamController<int>();

// 广播 Controller
final broadcastController = StreamController<int>.broadcast(
  onListen: () => print('第一个订阅者'),
  onCancel: () => print('最后一个订阅者取消了'),
);
```

**广播 Controller 的特殊行为**：

- `onListen` 在**第一个**订阅者到来时触发
- `onCancel` 在**最后一个**订阅者取消时触发
- 没有订阅者时 `add` 的事件会被丢弃
- `stream` 属性可以被多次 `listen`

#### sync 参数

```
// 同步 Controller：add 时立即调用订阅者的回调
final syncController = StreamController<int>(sync: true);

// 异步 Controller（默认）：add 的事件会被调度到下一个事件循环
final asyncController = StreamController<int>(sync: false);
```

**建议**：一般用默认的异步模式（`sync: false`），避免同步回调导致的重入问题。

### 3.9 StreamSink / EventSink

`StreamSink` 是 StreamController 的"写入端"抽象：

```
// StreamController 实现了 StreamSink
StreamSink<int> sink = controller.sink;

sink.add(1);
sink.addError(Exception('错'));
sink.close();
sink.done;  // 返回一个 Future，在 sink 关闭时完成
```

**层次关系**：

```
Sink<T>              —— 最基础的 add/close
└── EventSink<T>     —— 增加 addError
    └── StreamSink<T> —— 增加 done Future 和 stream 属性
```

### 3.10 StreamTransformer：流的转换

`StreamTransformer<S, T>` 定义了从 `Stream<S>` 到 `Stream<T>` 的转换：

```
// 自定义一个过滤 + 转换的 transformer
final myTransformer = StreamTransformer<int, String>.fromHandlers(
  handleData: (int data, EventSink<String> sink) {
    if (data.isEven) {
      sink.add('偶数: $data');
    }
  },
  handleError: (error, stackTrace, sink) {
    sink.addError('转换错误: $error', stackTrace);
  },
  handleDone: (sink) {
    sink.close();
  },
);

// 使用
stream.transform(myTransformer).listen(print);
```

#### 方式一：`fromHandlers`

最简单的方式，分别处理数据、错误、完成事件。

#### 方式二：`fromStreamTransformer`（绑定）

用于绑定已有的 transformer 逻辑。

#### 方式三：手动实现 `bind` 方法

```
class MyTransformer<S, T> implements StreamTransformer<S, T> {
  @override
  Stream<T> bind(Stream<S> stream) {
    return stream.asyncMap((event) async {
      // 自定义转换逻辑
      return event as T;
    });
  }

  @override
  StreamTransformer<RS, RT> cast<RS, RT>() =>
      StreamTransformer.castFrom<S, T, RS, RT>(this);
}
```

#### 内置的 Transformer

```
// 限制流的速率（丢弃超出速率的事件）
stream.transform(StreamTransformer.fromHandlers(
  handleData: (data, sink) { ... },
));

// 常用的转换操作本质上都是用 transformer 实现的
// map / where / expand 等内部都是创建对应的 StreamTransformer
```

### 3.11 StreamView

`StreamView<T>` 是 Stream 的包装类，只暴露 Stream 接口，隐藏 Controller 的写入能力：

```
final controller = StreamController<int>();
final Stream<int> publicStream = StreamView<int>(controller.stream);

// 外部只能监听，不能 add 事件
publicStream.listen(print);
```

常用于 API 设计：内部用 Controller 发事件，外部只暴露只读的 StreamView。

### 3.12 StreamIterator

`StreamIterator<T>` 让你可以用"拉"的方式逐个取 Stream 事件：

```
final iterator = StreamIterator<int>(stream);

while (await iterator.moveNext()) {
  print(iterator.current);
}

await iterator.cancel(); // 取消
```

- `moveNext()` 返回 `Future<bool>`，有下一个事件时完成 true，流结束时完成 false
- `current` 在 `moveNext()` 返回 true 后可用
- 本质上是把"推模式"的 Stream 变成"拉模式"

## 四、Timer 详解

### 4.1 一次性定时器

```
// 延迟执行一次
Timer(Duration(seconds: 2), () {
  print('2秒后执行');
});

// 立即执行（放入事件队列）
Timer.run(() {
  print('尽快执行（在事件队列中）');
});
```

### 4.2 周期性定时器

```
var count = 0;
final timer = Timer.periodic(Duration(seconds: 1), (timer) {
  count++;
  print('第 $count 次');
  if (count >= 5) {
    timer.cancel(); // 取消定时器
  }
});

// 检查定时器是否活跃
print(timer.isActive); // true / false
```

### 4.3 重要细节

- `Timer` 的回调在**事件队列**中执行，不是微任务
- `Timer(Duration.zero, callback)` 不等于同步执行，会在当前同步代码结束后执行
- 周期性定时器的间隔是**回调开始之间的间隔**，如果回调执行时间长，实际间隔会变长
- 取消后 `isActive` 变为 false
- `Timer.run()` 等价于 `Timer(Duration.zero, callback)`

## 五、Zone 详解

Zone 是 Dart 中最强大也最容易被忽视的概念之一。它是**代码执行的沙箱/上下文**，可以捕获和修改代码的行为。

### 5.1 Zone 的概念

可以把 Zone 想象成"代码运行的环境"，它可以：

- 捕获未处理的异常
- 重写 `print` 行为
- 拦截 `Timer` 和微任务的创建
- 存储 zone-local 变量（类似线程局部变量）
- 跟踪异步操作的上下文

### 5.2 当前 Zone

```
final zone = Zone.current;
print(zone); // Instance of '_RootZone'
```

每个代码都运行在某个 Zone 中，默认是根 Zone (`_RootZone`)。

### 5.3 创建新 Zone：`runZoned`

```
runZoned(
  () {
    print('在新 zone 中运行');
    throw Exception('出错了');
  },
  zoneSpecification: ZoneSpecification(
    print: (self, parent, zone, line) {
      parent.print(zone, '[自定义前缀] $line');
    },
    handleUncaughtError: (self, parent, zone, error, stackTrace) {
      parent.print(zone, '捕获未处理错误: $error');
    },
  ),
);
```

### 5.4 ZoneSpecification 可重写的方法

| 方法 | 作用 |
| --- | --- |
| `run` | 拦截同步代码执行 |
| `runUnary` | 拦截带一个参数的同步执行 |
| `runBinary` | 拦截带两个参数的同步执行 |
| `scheduleMicrotask` | 拦截微任务调度 |
| `createTimer` | 拦截定时器创建 |
| `createPeriodicTimer` | 拦截周期性定时器创建 |
| `print` | 拦截 print 调用 |
| `handleUncaughtError` | 捕获未处理的异常 |
| `errorCallback` | 错误回调拦截 |
| `fork` | 拦截子 zone 创建 |

### 5.5 Zone 局部变量

```
// 定义一个 zone 变量的 key
final userKey = ZoneKey<String>('user');

void main() {
  runZoned(() {
    print(Zone.current[userKey]); // Alice
    innerFunction();
  }, zoneValues: {
    userKey: 'Alice',
  });
}

void innerFunction() {
  // 嵌套函数中也能访问
  print(Zone.current[userKey]); // Alice
}
```

**关键特性**：

- Zone 变量是**不可变**的，子 zone 可以覆盖父 zone 的值
- 异步回调会保持创建时的 zone 上下文
- 类似于 Java 的 ThreadLocal，但适用于单线程异步模型

### 5.6 Zone 与异步回调

Zone 最强大的特性之一：**异步回调会记住创建时的 Zone**。

```
void main() {
  runZoned(() {
    final zone = Zone.current;
    
    Future.delayed(Duration(seconds: 1), () {
      // 这里的 Zone.current 仍然是上面的 zone
      assert(Zone.current == zone); // ✅
      print('回调中的 zone: ${Zone.current[#name]}');
    });
  }, zoneValues: {#name: 'MyZone'});
}
```

这意味着：

- `Future.then` 的回调会在创建 Future 时的 Zone 中执行
- `Stream.listen` 的回调会在 listen 时的 Zone 中执行
- `Timer` 的回调会在创建 Timer 时的 Zone 中执行

这就是为什么 `runZoned` 能捕获异步错误——即使错误发生在异步回调中，也会被对应的 Zone 捕获。

### 5.7 `runZonedGuarded`

更安全的版本，专门用于捕获错误：

```
runZonedGuarded(
  () {
    // 你的代码
    Future(() => throw Exception('异步错误'));
  },
  (error, stackTrace) {
    print('捕获到错误: $error');
    print('堆栈: $stackTrace');
  },
);
```

### 5.8 Zone 的实际应用场景

1. **错误监控**：Flutter 中用 Zone 捕获全局未处理异常
2. **日志系统**：重写 print，添加时间戳、级别等
3. **请求上下文**：在服务端，每个请求用独立 Zone 存储用户信息
4. **测试**：在测试中用 Zone 模拟时间、捕获副作用
5. **AOP 编程**：拦截特定操作做埋点统计

## 六、微任务调度

### 6.1 `scheduleMicrotask`

```
scheduleMicrotask(() {
  print('在微任务中执行');
});
```

### 6.2 微任务 vs 事件队列

```
void main() {
  print('1');
  
  Timer.run(() => print('2 (事件队列)'));
  scheduleMicrotask(() => print('3 (微任务)'));
  Future(() => print('4 (事件队列)'));
  Future.microtask(() => print('5 (微任务)'));
  
  print('6');
}
```

**输出**：

```
1
6
3 (微任务)
5 (微任务)
2 (事件队列)
4 (事件队列)
```

### 6.3 什么时候用微任务

- 需要在当前事件循环结束前、下一个事件之前执行
- 保证某些代码在所有同步代码之后、任何事件之前执行
- 实现"稍后但尽快"的语义

**注意**：不要滥用微任务。微任务队列如果堆积太多，会导致事件队列饥饿（UI 不更新、I/O 不处理）。

## 七、其他重要类与概念

### 7.1 `FutureOr<T>`

`FutureOr<T>` 是一个特殊的类型，表示"可以是 T，也可以是 Future"：

```
// 很多 API 的参数是 FutureOr，允许同步或异步返回
Future<T> doSomething(FutureOr<T> computation()) {
  return Future(computation);
}

// 调用时可以传同步函数
doSomething(() => 42);

// 也可以传异步函数
doSomething(() async => 42);
```

`FutureOr<T>` 不是一个真正的类，它是 `T | Future<T>` 的联合类型（Dart 类型系统的特殊处理）。

### 7.2 `SynchronousStreamController`

同步版本的 StreamController，事件会立即发送给订阅者：

```
final controller = StreamController<int>.broadcast(sync: true);
```

### 7.3 `MultiStream` / `StreamGroup`（不在 dart:async 核心中）

这些在 `package:async` 中提供，用于组合多个 Stream。

### 7.4 `DeferredLibrary`（已废弃）

以前用于延迟加载库，现在用 `deferred as` 语法替代：

```
import 'package:foo/foo.dart' deferred as foo;

void main() async {
  await foo.loadLibrary();
  foo.Bar();
}
```

## 八、异步编程模式与最佳实践

### 8.1 错误处理模式

#### Future 的错误处理

```
// 方式一：try-catch（推荐，最清晰）
try {
  final result = await riskyOperation();
} catch (e) {
  print('错误: $e');
}

// 方式二：catchError
riskyOperation().catchError((e) {
  print('错误: $e');
});

// 方式三：then 的 onError 参数
riskyOperation().then(
  (result) => print('成功: $result'),
  onError: (e) => print('错误: $e'),
);
```

#### Stream 的错误处理

```
// 方式一：listen 的 onError
stream.listen(
  print,
  onError: (e) => print('错误: $e'),
  cancelOnError: false, // 错误后继续
);

// 方式二：handleError
stream.handleError((e) => print('错误: $e')).listen(print);

// 方式三：await for + try-catch
try {
  await for (final event in stream) {
    print(event);
  }
} catch (e) {
  print('错误: $e');
}
```

### 8.2 资源释放模式

#### 使用 `try-finally` 释放资源

```
Future<void> processFile() async {
  final file = await openFile();
  try {
    await file.read();
  } finally {
    await file.close(); // 确保关闭
  }
}
```

#### Stream 订阅的取消

```
StreamSubscription<int>? subscription;

void startListening() {
  subscription = stream.listen(print);
}

void dispose() {
  subscription?.cancel(); // 必须取消，否则内存泄漏
  subscription = null;
}
```

### 8.3 常见陷阱

#### 陷阱一：忘记 await

```
// ❌ 错误：忘记 await，函数返回前操作还没完成
void fetchData() {
  http.get(url); // 没有 await，错误也不会被捕获
}

// ✅ 正确
Future<void> fetchData() async {
  await http.get(url);
}
```

#### 陷阱二：async 函数中抛异常

```
// ✅ 这是对的：async 函数中的异常会变成 Future 的 error
Future<void> bad() async {
  throw Exception('错了'); // 会被 Future 包装
}

// ❌ 但如果在非 async 函数中返回 Future 且抛异常
Future<void> bad2() {
  throw Exception('错了'); // 这是同步抛出，不会被 Future 包装！
  return Future.value();
}
```

#### 陷阱三：Stream 监听后不取消

```
// ❌ 内存泄漏
void setup() {
  stream.listen(print); // 没有保存 subscription，无法取消
}

// ✅ 保存 subscription，适时取消
```

#### 陷阱四：广播 Stream 丢失事件

```
final controller = StreamController<int>.broadcast();
controller.add(1); // 还没有订阅者，事件丢失了

controller.stream.listen(print); // 收不到 1
controller.add(2); // 能收到 2
```

#### 陷阱五：Completer 重复 complete

```
final completer = Completer();
completer.complete(1);
completer.complete(2); // ❌ 报错：Bad state: Future already completed
```

### 8.4 性能建议

1. **优先用 `async/await`**：代码更清晰，编译器优化更好
2. **避免在微任务中做重活**：会阻塞事件循环
3. **Stream 及时取消**：不再需要的订阅一定要 cancel
4. **合理使用 broadcast**：不需要多订阅就用单订阅，更高效
5. **用 `sync: true` 要小心**：同步 StreamController 可能导致重入问题

## 九、完整示例：自定义异步流

下面是一个综合运用 dart:async 各种概念的完整例子：

```
import 'dart:async';

/// 一个模拟的异步计数器
class AsyncCounter {
  final _controller = StreamController<int>.broadcast(
    onListen: () => print('🎧 第一个订阅者来了'),
    onCancel: () => print('👋 最后一个订阅者走了'),
  );
  
  Timer? _timer;
  int _count = 0;
  bool get isRunning => _timer != null;
  
  Stream<int> get stream => _controller.stream;
  
  void start() {
    if (_timer != null) return;
    
    _timer = Timer.periodic(Duration(seconds: 1), (timer) {
      _count++;
      _controller.add(_count);
      
      if (_count >= 10) {
        stop();
        _controller.close();
      }
    });
  }
  
  void stop() {
    _timer?.cancel();
    _timer = null;
  }
  
  void dispose() {
    stop();
    _controller.close();
  }
}

Future<void> main() async {
  // 在 Zone 中运行，捕获所有未处理错误
  runZonedGuarded(() async {
    final counter = AsyncCounter();
    
    print('=== 订阅者 1 开始监听 ===');
    final sub1 = counter.stream.listen(
      (n) => print('订阅者1: $n'),
      onDone: () => print('订阅者1: 完成'),
    );
    
    counter.start();
    
    // 3秒后第二个订阅者加入
    await Future.delayed(Duration(seconds: 3));
    print('=== 订阅者 2 开始监听 ===');
    final sub2 = counter.stream.listen(
      (n) => print('  订阅者2: $n'),
      onDone: () => print('  订阅者2: 完成'),
    );
    
    // 5秒后订阅者1取消
    await Future.delayed(Duration(seconds: 2));
    print('=== 订阅者 1 取消 ===');
    await sub1.cancel();
    
    // 等待结束
    await sub2.asFuture();
    counter.dispose();
    
    print('=== 全部结束 ===');
  }, (error, stackTrace) {
    print('💥 未捕获错误: $error');
  });
}
```

## 十、总结：dart:async 知识体系

```
dart:async
│
├── 基础抽象
│   ├── Future          → 单次异步结果
│   ├── Stream          → 多次异步事件流
│   └── FutureOr        → 同步/异步联合类型
│
├── 生产者（创建端）
│   ├── Completer       → 手动控制 Future
│   ├── StreamController → 手动控制 Stream
│   ├── StreamSink      → 流的写入接口
│   └── async*/yield    → 生成器语法
│
├── 消费者（监听端）
│   ├── .then/.catchError → Future 回调
│   ├── await           → Future 语法糖
│   ├── .listen()       → Stream 订阅
│   ├── StreamSubscription → 订阅句柄
│   └── await for       → Stream 语法糖
│
├── 转换与组合
│   ├── StreamTransformer → 流转换
│   ├── StreamView      → 只读包装
│   ├── StreamIterator  → 拉模式迭代
│   └── Future.wait/any/doWhile → Future 组合
│
├── 调度与时间
│   ├── Timer           → 定时器
│   ├── scheduleMicrotask → 微任务
│   └── 事件循环模型     → 底层驱动
│
└── 执行上下文
    └── Zone            → 沙箱/上下文/错误捕获
```

dart:async 是 Dart 异步编程的基石，理解了 Future、Stream 和事件循环模型，再加上 Zone 的高级用法，就能掌握 Dart 异步编程的全部精髓。如果你对某个具体部分想再深入（比如 StreamTransformer 的高级用法、Zone 的 AOP 应用、或者 Flutter 中的异步模式），可以继续问我。
