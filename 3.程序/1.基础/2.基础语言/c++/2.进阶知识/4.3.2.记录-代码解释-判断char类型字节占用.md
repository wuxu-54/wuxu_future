# 代码逐行解析

```
size_t pos = 0;
while (pos < mock_response_.size()) {
    unsigned char c = static_cast<unsigned char>(mock_response_[pos]);
    size_t char_len = 1;
    if ((c & 0xE0) == 0xC0) char_len = 2;
    else if ((c & 0xF0) == 0xE0) char_len = 3;
    else if ((c & 0xF8) == 0xF0) char_len = 4;
    pos += char_len;

    if (metrics_) {
        metrics_->record_token();
    }
    std::this_thread::sleep_for(std::chrono::milliseconds(5));
}
```

## 整体功能

**模拟大模型流式输出（SSE/stream），遍历一段UTF-8字符串`mock_response_`，按UTF-8多字节字符逐个前进，每解析完一个UTF8字符，就记录一个token，然后休眠5ms，模拟逐字输出的延迟。**

>
> 一般是单元测试、mock假推理后端，用来仿真流式返回文本。

## 1. UTF-8 编码判断部分（核心位运算）

UTF-8编码规则：

| 首字节高位 | 占用字节 |
| --- | --- |
| 0xxxxxxx | 1字节(ASCII) |
| 110xxxxx | 2字节 `0xC0` 开头，掩码`0xE0`(11100000) |
| 1110xxxx | 3字节 `0xE0` 开头，掩码`0xF0`(11110000) |
| 11110xxx | 4字节 `0xF0` 开头，掩码`0xF8`(11111000) |

```
unsigned char c = static_cast<unsigned char>(mock_response_[pos]);
size_t char_len = 1;
if ((c & 0xE0) == 0xC0) char_len = 2;
else if ((c & 0xF0) == 0xE0) char_len = 3;
else if ((c & 0xF8) == 0xF0) char_len = 4;
pos += char_len;
```

- `c & 0xE0`：按位与，**取出首字节前3个bit**，判断是不是`110xxxxx`，是就代表这个UTF8字符占2个字节
- `c & 0xF0`：取前4bit，`1110xxxx` → 3字节
- `c & 0xF8`：取前5bit，`11110xxx` →4字节
- `pos += char_len`：一次性跳过这个UTF8字符全部字节，**pos跳到下一个字符的起始位置**

>
> 重点：`mock_response_`是`std::string`，里面存UTF-8。中文汉字UTF8是**3字节**，英文字母1字节，生僻字/emoji可能4字节。
> 这里是**按【字符】遍历，不是按单个字节遍历**，防止把一个中文汉字拆成多段输出。

## 2. metrics_->record_token();

```
if (metrics_) {
    metrics_->record_token();
}
```

- `metrics_`是指标统计对象，指针。先判断非空，防止空指针崩溃。
- `record_token()`：**记录生成了1个token**，用于统计token数量、吞吐量、首token延迟等指标，就是你前面看到的latency统计模块。

## 3. sleep 模拟推理耗时

```
std::this_thread::sleep_for(std::chrono::milliseconds(5));
```

当前线程休眠 5ms。
👉 作用：**模拟大模型生成下一个token的推理耗时**，模拟流式输出的节奏。
每处理1个UTF8字符，等5ms再处理下一个。

# 完整逻辑流程

假设mock_response_ = `"你好"`（两个汉字，每个汉字UTF8占3字节）

1. pos=0，拿到首字节，识别char_len=3 → pos +=3 → pos=3
2. 调用record_token，指标计数+1
3. sleep 5ms
4. 进入循环，pos=3 < 总长度，取第3位置字节，识别char_len=3 → pos +=3 → pos=6
5. record_token，sleep5ms
6. pos=6，不满足`pos < size()`，循环结束

>
> ⚠️ 这里有个业务上的关键点：
> **代码把1个UTF8字符 = 1个token**。
> 真实LLM不是这样！LLM的token和文字字符不是一一对应的：一个汉字可能占2个token，英文单词可能1个token。
> 但这是**mock模拟代码**，做测试用，简化模型，直接1个字符当成1个token，没问题。

## ⚠️ 代码缺陷（可以记下来，面试/改代码用）

1. **只校验首字节，没有校验后续的续字节**
UTF-8续字节固定是`10xxxxxx`，这段代码没有做合法性检查。如果字符串是损坏的非法UTF8，pos会跳错，数组越界风险。mock测试场景一般够用，正式生产不能这么写。
2. 休眠`sleep_for`精度不高，操作系统调度，不一定精准5ms。
3. 把UTF8字符直接等同于token，**仅mock测试使用，不能用于真实推理**。

## 精简笔记

1. 位运算识别UTF8首字节，算出当前字符占几个字节，pos一次性跳过整个字符，避免中文被截断。
2. 每读完一个UTF8字符，统计1个token，然后sleep 5ms，模拟LLM流式逐token输出。
3. 这是**mock假后端**，用于单元测试，不是真实推理逻辑。
4. 真实LLM的token ≠ 文字字符，只是这里简化仿真。

# 为啥pos要+=不同字节长度

## 一句话核心

UTF-8 是**变长编码**：一个字符占用的字节数不固定（英文1字节、中文3字节、emoji有的4字节）。
`pos` 是**字节下标**（不是字符下标），所以不能简单 `pos++`，要一次性加上这个UTF8字符占用的全部字节数量 `char_len`，直接跳到**下一个字符的起始字节**。

---

### 1. 先分清两个概念（非常关键）

- **字节（byte）**：`std::string` 底层是**字节数组**。`mock_response_[pos]`，`pos` 是**字节索引**。

```
"你" 的UTF8编码：0xE4 0xBD 0xA0  → 一共3个字节
```

`mock_response_[0]` = 0xE4（首字节）
`mock_response_[1]` = 0xBD（续字节）
`mock_response_[2]` = 0xA0（续字节）

- **字符（char，文字）**：上面3个字节合起来，才是**1个汉字字符**。

#### 如果写 `pos++` 会发生什么（错误写法）

```cpp
// ❌ 错误！
while(pos < size) {
    auto c = mock_response_[pos];
    pos++;
}
```

对于汉字，会**逐个取出3个字节**，循环跑3次：

1. pos=0，拿到0xE4 → 算1个token，sleep
2. pos=1，拿到0xBD（这只是汉字中间的续字节，**不是新字符**！），代码又当成新字符处理，又记录一次token
3. pos=2，拿到0xA0，再次当成新字符，再记录token

> 后果：**一个中文汉字，被拆成3次输出、记3个token**，流式输出乱掉、指标统计错误。
> 这就是这段代码要避免的问题！

### 2. 代码思路

1. 读当前`pos`位置的**首字节**，通过高位判断：这个UTF8字符一共占几个字节 `char_len`（1/2/3/4）
2. `pos += char_len`：直接跳过**整个字符的所有字节**，`pos` 直接移动到**下一个字符的开头字节**
3. 此时代表成功解析**1个完整文字字符**，再执行`record_token()`、sleep模拟流式输出

举例子：字符串`"你好"`

- 你：3字节，好：3字节，总字节长度=6

1. pos=0：首字节判断 char_len=3 → pos = 0+3 = 3；解析完【你】，记录token
2. pos=3：首字节判断 char_len=3 → pos =3+3=6；解析完【好】，记录token
3. pos=6，等于字符串总长度，循环退出

✅ 循环一共2次，正好2个字符，2次token记录，符合预期。

### 3. UTF8编码为什么靠首字节判断长度

UTF-8 设计规则，全部信息存在**第一个字节**：

- `0xxxxxxx`（最高位0）：1字节 ASCII字符
- `110xxxxx`：2字节字符
- `1110xxxx`：3字节字符（绝大多数中文）
- `11110xxx`：4字节字符（生僻字、emoji）
后面跟着的字节，固定以`10xxxxxx`开头，**不能作为字符的起始位置**。

> 所以我们只看每个字符的**首字节**，就能知道这个字符一共占多少字节。

### 4. 回到业务目的：mock流式输出

这个是模拟大模型**逐字流式返回文本**，要求：
> 每输出**一个完整文字**，才推一段、统计一个token，不能把汉字拆成半截输出。

如果按单个字节循环，中文会被切碎，前端收到半个汉字，会出现乱码。
所以必须**按UTF8完整字符跳转字节**。

### 5. 重要提醒再回顾
>
> 这里只是mock测试代码：把**1个文字字符直接当成1个token**。
> 真实LLM里面token和文字字符不是1:1。
> 但在这个模拟逻辑里，业务目标是：**一次吐出完整字符，不乱码**，所以要这么写。

## 精简笔记

1. `std::string`是字节数组，`pos`是**字节下标**，不是字符下标。
2. UTF8变长：1个文字占1~4个字节。
3. `pos += char_len`：一次性跳过当前字符全部字节，跳到**下一个字符的起始位置**。
4. 如果只 pos++，中文的多个字节会被分开处理，导致**乱码、token统计错误**。
