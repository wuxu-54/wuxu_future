# LLDB 详解：C++ 调试利器

LLDB 是 LLVM 项目中的下一代高性能调试器，基于 LLVM/Clang 工具链构建，是 macOS、iOS、watchOS、tvOS 等 Apple 平台上 Xcode 默认的调试器，同时也支持 Linux、FreeBSD、Windows 等操作系统。它以模块化设计、强大的脚本能力和现代调试体验著称，非常适合 C、C++、Objective-C、Swift 等语言的调试。

>主要是C++调试

---

## 1. LLDB 的背景与定位

- **出身**：LLDB 是 LLVM 官方项目的一部分，最初由 Apple 主导开发，用于替代 GDB 在 Xcode 中的地位。现在由社区共同维护。
- **架构**：LLDB 大量复用 LLVM/Clang 的组件，例如使用 Clang 的表达式解析器来求值调试表达式，使用 LLVM 的 JIT 来执行这些表达式。这使得 LLDB 在 C++ 表达式求值方面非常强大，能够理解复杂的 C++ 语法、模板、重载等。
- **许可证**：与 LLVM 相同的 Apache 2.0 with LLVM Exception，比 GPL 更宽松。

---

## 2. LLDB 的主要特点

| 特点 | 说明 |
|------|------|
| **模块化设计** | 命令行、调试核心、脚本接口分层清晰，易于扩展 |
| **强大的表达式求值** | 基于 Clang，可以在调试时运行任意 C++ 表达式并调用函数 |
| **脚本化** | 内嵌 Python 解释器，可以用 Python 编写自定义命令、格式化器、自动化脚本 |
| **远程调试** | 支持通过 TCP/gdb-remote 协议调试远程设备或程序 |
| **多语言支持** | C、C++、Objective-C、Swift、Rust（部分）等 |
| **高性能** | 对大型程序和核心转储文件处理速度较快 |
| **跨平台** | macOS、Linux、FreeBSD、Windows（有限支持） |

## 3. 安装 LLDB

### macOS

安装 Xcode 或 Command Line Tools 后自带 LLDB：

```bash
xcode-select --install
lldb --version
```

### Linux (Debian/Ubuntu)

```bash
sudo apt update
sudo apt install lldb
```

### Linux (Fedora/RHEL)

```bash
sudo dnf install lldb
```

### 源码编译

需要 LLVM/Clang 源码，使用 CMake 构建，适合需要最新功能或调试 LLDB 本身的情况。

### Windows

可通过 LLVM 官方安装包获取，但功能相对有限，推荐使用 Visual Studio 的调试器或 WinDbg。

## 4. 基本使用流程

### 4.1 编译程序时加入调试信息

使用 `-g` 生成 DWARF 调试信息，同时建议关闭优化以便变量可读：

```bash
clang++ -g -O0 -o myapp myapp.cpp
# 或使用 g++ -g -O0 -o myapp myapp.cpp
```

### 4.2 启动 LLDB

```bash
lldb ./myapp
```

或先启动 LLDB 再加载程序：

```bash
lldb
(lldb) target create "./myapp"
```

## 5. 常用命令详解

LLDB 命令采用“名词 动词”的结构，例如 `breakpoint set`、`thread backtrace`。大部分命令支持缩写。

### 5.1 程序加载与运行

| 命令 | 说明 |
|------|------|
| `target create <file>` | 加载可执行文件 |
| `file <file>` | 同上，简写 |
| `run` / `r` | 启动程序（可带参数：`run arg1 arg2`） |
| `process launch` | 更详细的启动命令 |
| `process launch -- <args>` | 启动并传递参数 |
| `process kill` | 终止当前进程 |
| `quit` / `q` | 退出 LLDB |

### 5.2 断点（Breakpoint）

设置断点：

```bash
# 按函数名
breakpoint set --name main
# 按文件和行号
breakpoint set --file myapp.cpp --line 8
# 按地址
breakpoint set --address 0x0000000000401122
# 按正则表达式匹配符号
breakpoint set --func-regex '^.*foo.*$'
# 条件断点
breakpoint set --file myapp.cpp --line 8 --condition 'n == 3'
# 忽略前 N 次命中
breakpoint set --file myapp.cpp --line 8 --ignore-count 5
# 一次性断点（命中后自动删除）
breakpoint set --one-shot --name main
```

管理断点：

```bash
breakpoint list                  # 列出所有断点
breakpoint delete 1              # 删除 1 号断点
breakpoint disable 1             # 禁用 1 号断点
breakpoint enable 1              # 启用 1 号断点
breakpoint modify --condition 'x > 10' 1   # 修改条件
```

为断点附加命令（命中后自动执行）：

```bash
breakpoint command add 1
Enter your debugger command(s). Type 'DONE' to end.
> frame variable
> continue
> DONE
```

### 5.3 执行控制

| 命令 | 缩写 | 说明 |
|------|------|------|
| `continue` | `c` | 继续运行 |
| `next` | `n` | 单步步过（不进入函数） |
| `step` | `s` | 单步步入（进入函数） |
| `finish` | `fin` | 执行直到当前函数返回 |
| `thread step-inst` | `si` | 单步一条机器指令 |
| `thread step-over-inst` | `ni` | 步过一条机器指令 |
| `thread return` |  | 强制当前函数返回（可指定返回值） |

### 5.4 查看变量与内存

```bash
frame variable [name]            # 查看当前栈帧的局部变量
frame variable -L                # 查看变量声明位置
frame variable -g                # 查看全局变量
frame variable --format x var    # 以十六进制显示

expression <expr>                # 求值任意 C++ 表达式
expression -- <expr>             # 避免与 LLDB 命令冲突
expression -- (int)printf("hello\n")  # 调用函数

memory read --outfile /tmp/dump.bin --binary --count 100 0x7fff5fbff000
memory read --format x --size 4 --count 8 0x7fff5fbff000
x/8xw 0x7fff5fbff000            # GDB 风格简写
```

LLDB 自带 libc++ 的 STL 容器美化显示，能直接打印 `std::vector`、`std::map` 等。也可以自定义：

```bash
type summary add --summary-string "size=${var.size()}" std::vector
```

### 5.5 调用栈

```bash
backtrace / bt                   # 显示当前线程调用栈
backtrace all / bt all           # 显示所有线程调用栈
frame select <n>                 # 切换到第 n 帧
frame info                       # 显示当前帧详细信息
up / down                        # 在栈帧间移动
```

### 5.6 线程

```bash
thread list                      # 列出所有线程
thread select <id>               # 切换到指定线程
thread backtrace                 # 当前线程调用栈
thread backtrace all             # 所有线程调用栈
thread step-inst                 # 单步指令
thread continue                  # 继续当前线程（其他线程暂停）
```

### 5.7 监视点（Watchpoint）

监视变量或内存地址的读写：

```bash
watchpoint set variable globalVar         # 监视变量
watchpoint set expression -- &globalVar   # 监视地址
watchpoint list
watchpoint delete 1
```

### 5.8 模块与符号

```bash
image list                       # 列出加载的动态库/模块
image lookup --address 0x...     # 查找地址对应的符号
image lookup --name printf       # 查找符号
image lookup --type std::string  # 查找类型定义
```

### 5.9 反汇编

```bash
disassemble --frame              # 反汇编当前函数
disassemble --name main          # 反汇编 main 函数
disassemble --pc                 # 反汇编当前指令附近
```

### 5.10 其他常用命令

```bash
help [command]                   # 获取帮助
apropos <keyword>                # 搜索相关命令
settings list                    # 查看设置
settings set target.env-vars DEBUG=1   # 设置环境变量
settings set target.run-args arg1 arg2 # 设置运行参数
log enable lldb all              # 开启日志（调试 LLDB 自身）
```

## 6. LLDB 与 GDB 命令对照

| GDB 命令 | LLDB 命令 | 说明 |
|----------|-----------|------|
| `break main` | `breakpoint set --name main` | 设置断点 |
| `break file.cpp:42` | `breakpoint set --file file.cpp --line 42` | 文件行断点 |
| `run` | `run` | 运行 |
| `next` | `next` | 步过 |
| `step` | `step` | 步入 |
| `continue` | `continue` | 继续 |
| `finish` | `finish` | 完成当前函数 |
| `print x` | `expression x` 或 `frame variable x` | 查看变量 |
| `info locals` | `frame variable` | 查看局部变量 |
| `bt` | `backtrace` | 调用栈 |
| `info threads` | `thread list` | 线程列表 |
| `thread 2` | `thread select 2` | 切换线程 |
| `watch x` | `watchpoint set variable x` | 监视点 |
| `disassemble` | `disassemble` | 反汇编 |
| `x/8xw $rsp` | `memory read --format x --size 4 --count 8 $rsp` | 查看内存 |
| `set args` | `settings set target.run-args` | 设置参数 |
| `quit` | `quit` | 退出 |

## 7. 高级功能

### 7.1 Python 脚本扩展

LLDB 内嵌 Python 解释器，可以用 Python 编写自定义命令、美化器、自动化调试流程。

**示例：自定义命令**

```python
# mycommands.py
import lldb

def hello_command(debugger, command, result, internal_dict):
    print("Hello from Python! Current target:", debugger.GetSelectedTarget())
    return None

def __lldb_init_module(debugger, internal_dict):
    debugger.HandleCommand('command script add -f mycommands.hello_command hello')
    print("Custom command 'hello' loaded.")
```

在 LLDB 中加载：

```bash
(lldb) command script import mycommands.py
Custom command 'hello' loaded.
(lldb) hello
Hello from Python! Current target: a.out
```

**自动导入**：将 `command script import` 添加到 `~/.lldbinit` 文件。

### 7.2 远程调试

LLDB 使用 `gdb-remote` 协议或 `lldb-server` 进行远程调试。

**Linux 远程调试步骤**：

1. 在目标机上启动 `lldb-server`：

   ```bash
   lldb-server platform --server --listen *:1234
   ```

2. 在本地 LLDB 中连接：

   ```bash
   (lldb) platform select remote-linux
   (lldb) platform connect connect://remote-host:1234
   (lldb) target create /path/to/remote/binary
   (lldb) run
   ```

对于 Apple 设备，Xcode 自动处理远程调试，命令行也可通过 `process connect connect://device-ip:port` 连接。

### 7.3 核心转储（Core Dump）调试

```bash
lldb --core core.12345 ./myapp
```

或启动后加载：

```bash
(lldb) target create ./myapp
(lldb) target modules search-paths add /usr/lib/debug /usr/lib/debug
(lldb) process load core.12345
```

### 7.4 批处理模式

适合自动化测试或脚本调用：

```bash
lldb -b -o 'breakpoint set --name main' -o 'run' -o 'bt' -o 'quit' ./myapp
```

### 7.5 REPL / 表达式求值

LLDB 的 `expression` 可以执行任意 C++ 代码，甚至定义新变量、调用函数：

```bash
(lldb) expression int $x = 10
(lldb) expression $x * 2
(int) $1 = 20
(lldb) expression -- std::vector<int> temp = {1,2,3}; temp.size()
(size_t) $2 = 3
```

注意：执行表达式可能修改程序状态，需谨慎。

### 7.6 自定义数据格式化器

LLDB 支持为任意类型定制显示格式。通过 Python 脚本可实现复杂的 STL 容器美化（通常 libc++ 已内置）。

```bash
type summary add --summary-string "point(${var.x}, ${var.y})" Point
type format add --format hex int
```

## 8. 调试 C++ 特性的注意事项

### 8.1 STL 容器

LLDB 对 libc++（Clang 标准库）的 STL 容器支持很好，能直接展开 `std::vector`、`std::map` 等。但如果使用 libstdc++（GCC 标准库），部分容器显示可能不佳，可考虑安装 pretty printers（通常 GDB 的 Python pretty printers 可移植到 LLDB）。

### 8.2 模板与重载

基于 Clang 的表达式求值器能够处理复杂的模板表达式、运算符重载、类型推断。但某些情况下（如调试优化代码）可能无法正确求值。

### 8.3 优化代码调试

编译时使用 `-O0 -g` 可获得最佳调试体验。若必须使用优化，可尝试 `-Og`（Clang/GCC 支持），它专门为调试优化。优化后部分变量可能被优化掉，显示为 `<optimized out>`，此时可以通过查看汇编或使用 `-fno-omit-frame-pointer` 缓解。

### 8.4 命名空间与作用域

LLDB 命令中符号名可能因命名空间而需要完整限定，例如：

```bash
breakpoint set --name mynamespace::MyClass::method
```

可以使用 `--func-regex` 模糊匹配。

### 8.5 调试多线程程序

- 使用 `thread list` 查看线程，`thread select` 切换。
- 设置线程特定断点：`breakpoint set --name foo --thread-id 3`。
- 使用 `thread backtrace all` 查看所有线程栈，排查死锁。
- 注意 LLDB 默认在断点命中时暂停所有线程，可通过 `settings set target.process.stop-on-sharedlibrary-events true` 等调整。

## 9. 常见问题与技巧

### 9.1 权限问题（Linux ptrace）

在 Linux 上调试程序可能遇到“ptrace: Operation not permitted”，可通过以下方式解决：

```bash
sudo sysctl -w kernel.yama.ptrace_scope=0
```

或临时使用 `sudo lldb ./app`。

### 9.2 加载符号

如果程序引用了外部动态库，LLDB 会自动加载其符号。若符号缺失，可手动指定：

```bash
target modules add /path/to/libfoo.so
```

### 9.3 调试信息丢失

确保编译时用了 `-g`，且链接时未剥离符号（`-s` 会剥离）。对于发布版程序，可安装对应的 debug 符号包。

### 9.4 使用 `.lldbinit`

在用户主目录下创建 `.lldbinit` 文件，可以预设命令、导入脚本、设置别名。例如：

```bash
# ~/.lldbinit
settings set target.env-vars DEBUG=1
command alias b breakpoint set
command script import ~/my_lldb_scripts.py
```

### 9.5 查看寄存器

```bash
register read                   # 通用寄存器
register read rax rbx rsp       # 指定寄存器
register write rax 0x1234       # 修改寄存器（慎用）
```

### 9.6 调试子进程

```bash
settings set target.process.follow-fork-mode child   # 调试子进程
settings set target.process.follow-fork-mode parent  # 调试父进程
```

### 9.7 附加到运行中的进程

```bash
lldb -p <pid>
```

或

```bash
(lldb) process attach --pid <pid>
(lldb) process attach --name myapp
```

## 10. 总结

LLDB 是一个功能强大、架构现代的调试器，尤其适合 C++ 开发。它的优势在于与 Clang/LLVM 深度集成，具备出色的 C++ 表达式求值能力和脚本扩展能力。虽然命令结构与 GDB 不同，但学习曲线平缓，且官方文档和社区资源丰富。无论是日常开发调试、性能分析、核心转储分析，还是嵌入式/远程调试，LLDB 都是一个值得掌握的工具。

**推荐资源**：

- 官方文档：<https://lldb.llvm.org/>
- 命令手册：`help` 命令或 <https://lldb.llvm.org/use/map.html>
- LLDB 教程：Apple 官方文档及各种在线博客
