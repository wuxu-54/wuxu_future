# 代码逐行解析

```
// tasks_ 是一个任务队列，比如 std::queue<std::function<void()>> tasks_;
tasks_.emplace([promise, task = std::move(task)]() mutable {
    try {
        promise->set_value(task());
    } catch (...) {
        promise->set_exception(std::current_exception());
    }
});
```

整体场景：**简易线程池，把任务包装后扔进任务队列；工作线程取出并执行这个lambda，通过`promise`把返回值/异常回传给调用方**。

> 
> 先明确几个变量：
> 
> 
> 1. `tasks_`：队列，存的是无参可执行对象，一般是 `std::queue<std::function<void()>>`。
> 2. `task`：原始用户任务，可以是一个有返回值的可调用对象（函数/lambda）。
> 3. `promise`：`std::promise<T>*` 裸指针（或者智能指针），用来往外传递任务结果。

## 1. `tasks_.emplace(...)`

`emplace` 直接在队列容器内部**原地构造lambda对象**，避免拷贝。
等价于：构造一个lambda，然后push到tasks_队列。
队列里存的是这个包装好的**无参void() lambda**，线程池的worker线程后面会取出并调用这个lambda。

## 2. lambda捕获：`[promise, task = std::move(task)]`

```
[promise, task = std::move(task)]
```

- `promise`：按值捕获指针，lambda内部持有这个promise指针，后面用来设置结果。
- `task = std::move(task)`：**捕获初始化（C++14特性）**
  - 用户传进来的`task`（用户的任务）使用`std::move`**移动到lambda闭包里面**，不再拷贝原始任务。
  - 如果task是带移动语义的lambda、function，避免昂贵拷贝。

> 
> ⚠️ 如果不写`std::move(task)`，就是拷贝task；大的functor会有开销。

## 3. `() mutable`

```
]() mutable {
```

- lambda默认`operator()`是`const`，闭包内捕获的成员**不允许修改**。
- 这里`task`是被移动进来存放在闭包内部的可调用对象；调用`task()`的时候，部分任务对象的`operator()`是非const（mutable lambda），**所以必须加mutable，允许修改闭包内捕获的task成员**。> 
> 如果不加mutable，调用`task()`编译报错。

## 4. try‑catch块核心逻辑

```
try {
    promise->set_value(task());
} catch (...) {
    promise->set_exception(std::current_exception());
}
```

这段lambda，**会在工作线程中执行**。

1. `task()`：执行用户原始任务，拿到返回值。
2. `promise->set_value(返回值)`：把任务返回值存入promise；外面对应的`future.get()`就能拿到这个结果。
3. `catch(...)`：捕获任意类型异常。
4. `std::current_exception()`：拿到当前正在抛出的异常对象，包装成`std::exception_ptr`。
5. `promise->set_exception(...)`：把异常存入promise。> 
> 后续外部调用 `future.get()` 的时候，会**重新throw抛出这个异常**，异常从工作线程传递回发起任务的线程。

### 关键点：异常跨线程传递

> 
> 用户任务在子线程抛异常，如果不捕获，直接会导致整个程序崩溃。
> 这里把异常捕获，存入promise，异常被搬运到调用`future.get()`的线程再抛出来，实现异常跨线程传递。

# 整体数据流

1. 用户提交任务：`submit(task)`，函数内部构造 `promise<T>`。
2. 将promise指针、原始task移动捕获，包装成一个无参lambda。
3. `emplace`把包装lambda推入 `tasks_`任务队列。
4. 线程池worker从tasks_弹出这个lambda，执行。
   - 成功：`promise->set_value(结果)`
   - 抛异常：`promise->set_exception(异常)`
5. 用户那边拿着和promise配对的`future`，调用 `.get()`：拿到返回值，或者收到抛出的异常。

> 
> 这个代码片段就是简易版`std::async`内部的核心逻辑。

## 潜在风险点（面试重点）

1. `promise`是裸指针：要保证当worker线程执行lambda的时候，promise对象还活着。
   - 如果promise在主线程提前销毁，worker执行`promise->xxx`就是野指针，UB崩溃。
   - 工程一般不会用裸指针；改用`std::shared_ptr<std::promise<T>>`捕获，用共享所有权保证生命周期。

> 
> 优化后写法（更安全，不用裸指针）：

```
auto prom = std::make_shared<std::promise<int>>();
tasks_.emplace([prom, task = std::move(task)]() mutable {
    try {
        prom->set_value(task());
    } catch (...) {
        prom->set_exception(std::current_exception());
    }
});
```

prom作为shared_ptr按值捕获进lambda；lambda持有一份shared_ptr，promise对象生命周期被延长，直到任务执行完毕。

2. `mutable`：不要漏，否则调用非const的task会编译失败。
3. `task = std::move(task)`：C++14特性，C++11不支持捕获初始化。C++11只能通过std::bind或者包装function来移动。

## 配套伪代码看完整链路

```
// tasks_队列
std::queue<std::function<void()>> tasks_;
std::mutex mtx_;
std::condition_variable cv_;

// 提交任务函数
template<typename F>
auto submit(F&& func) -> std::future<decltype(func())>
{
    using RetType = decltype(func());
    auto prom = std::make_shared<std::promise<RetType>>();
    auto fut = prom->get_future();

    {
        std::lock_guard<std::mutex> lk(mtx_);
        tasks_.emplace([prom, task = std::forward<F>(func)]() mutable {
            try {
                prom->set_value(task());
            } catch(...) {
                prom->set_exception(std::current_exception());
            }
        });
    }
    cv_.notify_one();
    return fut;
}
```

worker工作线程循环：

```
void worker_thread()
{
    while(true) {
        std::function<void()> job;
        {
            std::unique_lock<std::mutex> lk(mtx_);
            cv_.wait(lk, [&](){ return !tasks_.empty(); });
            job = std::move(tasks_.front());
            tasks_.pop();
        }
        job(); //执行我们上面包装好的lambda
    }
}
```

## 总结一句话

> 
> 将用户的带返回值任务`task`移动捕获，包装成一个无参lambda放进任务队列；worker执行lambda，运行task，**把返回值或者捕获到的异常，通过promise传递给外部future**。
