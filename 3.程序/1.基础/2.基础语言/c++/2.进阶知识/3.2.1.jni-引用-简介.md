# JNI 引用：局部引用 LocalRef / 全局引用 GlobalRef / 弱全局 WeakGlobalRef
>
> 核心背景：**Java 对象在 GC 堆上，native C/C++ 代码不能直接保存对象裸指针**。JNI 通过「引用（jobject）」来代表 Java 对象，本质是 JVM 给 native 层的句柄，不是直接内存地址。
> `NewLocalRef`、`NewGlobalRef` 就是创建这两种句柄的API。

## 一、先分清 3 种引用类型

1. **局部引用 Local Reference（LocalRef）**
    - 函数：`jobject NewLocalRef(JNIEnv* env, jobject ref)`
    - 删除：`DeleteLocalRef(env, localRef)`
2. **全局引用 Global Reference（GlobalRef）**
    - 函数：`jobject NewGlobalRef(JNIEnv* env, jobject obj)`
    - 删除：`DeleteGlobalRef(env, globalRef)`
3. **弱全局引用 Weak Global Reference**
    - `jweak NewWeakGlobalRef(JNIEnv* env, jobject obj)`
    - `DeleteWeakGlobalRef(env, jweak ref)`，不会阻止GC，可以用`IsSameObject`判断是否被回收

> 注意：`jclass / jstring / jarray` 全部继承自 `jobject`，它们本质也是引用句柄，同样遵守引用规则。

---

# 二、局部引用 LocalRef（NewLocalRef）

## 1. 什么是局部引用

**默认绝大多数 JNI 函数返回的 jobject 都是局部引用**，例如 `FindClass`、`NewObject`、`GetObjectArrayElement` 返回的就是 LocalRef。
局部引用**只在当前 JNI 调用帧有效**，当 native 函数返回 Java 层后，JVM 会**自动回收这个局部引用**。

### `NewLocalRef` 作用

```c
jobject NewLocalRef(JNIEnv* env, jobject ref);
```

- 输入：一个已经存在的引用（可以是局部/全局）
- 输出：**新建一个新的局部引用，指向同一个Java对象**

> 一句话：给同一个Java对象，多创建一个局部句柄。

### 使用场景举例

```c
// clazz 是FindClass返回的局部引用
jclass clazz = env->FindClass("java/lang/String");
jclass clazz2 = (jclass)env->NewLocalRef(clazz); // 新建另一个局部引用，指向同一个Class对象

// 使用完必须手动删除
env->DeleteLocalRef(clazz);
env->DeleteLocalRef(clazz2);
```

## 2. 局部引用重要特性

✅ **不会阻止GC**：只要当前native栈帧还活着，对象不会被GC；一旦native方法return，局部引用全部自动失效。
✅ 生命周期：**绑定 JNIEnv 的当前调用栈**，跨函数调用可以传，但**不能跨线程保存，不能存到全局静态变量！**
✅ 有上限：JVM 默认局部引用表有容量限制（比如512）。**循环大量创建局部引用不删除，会局部引用表溢出崩溃**。

> 坑点：
>
> 1. 循环里 `FindClass/NewObject` 反复创建局部引用，不DeleteLocalRef → 爆引用表 OOM / crash
> 2. 把局部引用存入全局静态变量，native函数返回后，引用变成**野句柄**，后续使用直接崩溃
> 3. Android旧版本：局部引用自动回收机制有差异，**最佳实践：用完手动DeleteLocalRef**

## 3. 什么时候需要手动调用 NewLocalRef？

一般场景**不需要**，因为很多API直接返回LocalRef。
只有：

- 需要在同一帧，对同一个对象**持有多个独立局部句柄**；
- 传入的ref可能是全局引用，想临时创建局部句柄使用。

> 不要重复创建不必要的LocalRef，会占用局部引用表。

## 4. DeleteLocalRef

```c
void DeleteLocalRef(JNIEnv* env, jobject localRef);
```

**提前销毁局部引用**，释放局部引用表位置，不等函数返回自动清理。
> ⚠️ 不能删同一个LocalRef多次，会未定义行为。

# 三、全局引用 GlobalRef（NewGlobalRef）

```c
jobject NewGlobalRef(JNIEnv* env, jobject obj);
```

## 1. 作用

**创建一个全局句柄，永久持有Java对象，阻止GC回收对象，直到手动删除**。
> 局部引用出了native函数就失效；全局引用**跨函数、跨线程，可以存到C/C++全局静态变量**。

✅ 典型场景：
native层静态变量保存Java对象，比如保存回调的`jobject listener`、保存jclass类对象长期复用。

示例：

```c
static jobject g_listener = nullptr;

// 保存Java层传入的listener对象
void setListener(JNIEnv* env, jobject listener) {
    // 如果之前已经保存全局引用，先删掉旧的，防止内存泄漏
    if(g_listener != nullptr) {
        env->DeleteGlobalRef(g_listener);
    }
    // 创建全局引用
    g_listener = env->NewGlobalRef(listener);
}
```

## 2. 全局引用特性

1. **强引用，阻止GC**：只要全局引用不Delete，Java对象永远不会被GC，极易**内存泄漏**！忘记DeleteGlobalRef就是内存泄漏。
2. **生命周期手动管理**：JVM不会自动释放，**必须手动调用 DeleteGlobalRef**
3. **可以跨线程使用**：不同线程的JNIEnv，只要拿到这个全局引用，都可以操作对象。
4. 输入obj可以是局部引用，`NewGlobalRef`会把它升级为全局句柄，**原局部引用依然需要单独DeleteLocalRef**。

> 例子拆解：

```c
jobject local_obj = env->NewObject(...); // local ref
jobject global_obj = env->NewGlobalRef(local_obj); // 新建全局引用，指向同一个java对象

env->DeleteLocalRef(local_obj); // 局部引用可以删掉，global依然有效

// 用完全局引用后，一定要释放
env->DeleteGlobalRef(global_obj);
global_obj = nullptr;
```

删除globalRef之后，这个句柄就失效，不能再使用。

## 3. 坑点

1. **忘记DeleteGlobalRef → 内存泄漏**，对象永久存活
2. Delete之后继续使用globalRef → 野引用，crash
3. 不要频繁大量创建全局引用

---

# 四、弱全局引用 NewWeakGlobalRef（顺带对比）

```c
jweak NewWeakGlobalRef(JNIEnv* env, jobject obj);
```

弱全局引用，**全局、跨线程，但是不阻止GC**。
GC在内存不足时可以回收对象。
使用前要用`IsSameObject(ref, nullptr)`判断对象是否已经被回收。
适用场景：缓存，不想强持有造成内存泄漏。

删除：`DeleteWeakGlobalRef(env, weakRef)`

# 五、关键对比表

| 项目 | LocalRef 局部引用 | GlobalRef 全局引用 | WeakGlobalRef弱全局 |
|------|-------------------|--------------------|--------------------|
| 创建 | 默认API返回 / NewLocalRef | NewGlobalRef | NewWeakGlobalRef |
| 删除 | DeleteLocalRef，函数返回自动回收 | DeleteGlobalRef，**不会自动释放** | DeleteWeakGlobalRef |
| GC影响 | 栈帧存活期间阻止GC；函数返回释放 | **强阻止GC，容易泄漏** | 不阻止GC，对象可被回收 |
| 跨线程 | ❌ 不可以 | ✅ 可以 | ✅ 可以 |
| 存静态全局变量 | ❌ 禁止，函数返回后野句柄 | ✅ 允许 | ✅ 允许 |
| 句柄失效时机 | native方法返回 | DeleteGlobalRef之后 | Delete / 对象被GC后 |

# 六、常见易错场景

## 场景1：把FindClass的局部引用存到静态变量（经典错误）

```c
// ❌错误！FindClass返回LocalRef，函数返回后引用失效
static jclass g_cls;
JNIEXPORT void JNICALL test(JNIEnv* env, jobject thiz){
    jclass cls = env->FindClass("android/os/Handler");
    g_cls = cls; // 保存局部引用到静态变量，方法返回后g_cls野句柄！
}
```

✅正确：要用全局引用

```c
static jclass g_cls = nullptr;
JNIEXPORT void JNICALL test(JNIEnv* env, jobject thiz){
    jclass cls_local = env->FindClass("android/os/Handler");
    g_cls = (jclass) env->NewGlobalRef(cls_local);
    env->DeleteLocalRef(cls_local);
}
// 在不需要的时候 DeleteGlobalRef(g_cls)
```

## 场景2：循环创建局部引用不释放，引用表溢出

```c
// ❌ 循环大量创建LocalRef，不删除，引用表爆满
for(int i=0; i<10000; i++){
    jstring str = env->NewStringUTF("test");
    // 使用str
    // 忘记 DeleteLocalRef
}
```

✅每次用完DeleteLocalRef

# 七、补充：NewLocalRef 什么时候不能用

`NewLocalRef` 只是复制一个句柄，**不会复制Java对象本身**，两个LocalRef指向同一个Java对象。
如果传入`nullptr`给`NewLocalRef`，返回`nullptr`。

# 八、JNI引用底层简单理解

JVM内部维护**局部引用表、全局引用表**：

- 局部引用表：每个JNI调用栈一张，记录当前帧所有LocalRef；方法退出，批量清理。
- 全局引用表：全局共享，每NewGlobalRef增加一条记录，DeleteGlobalRef移除。

> jobject本质就是这个表里面的索引/句柄，不是对象内存地址。JVM通过这个句柄查找真实Java对象。GC扫描全局引用表，标记里面引用的对象为存活。

# 九、一句话总结

1. **LocalRef（NewLocalRef）**：临时句柄，仅限当前native函数栈，函数返回自动失效；不能跨线程、不能存静态变量；用完建议DeleteLocalRef释放引用表。
2. **GlobalRef（NewGlobalRef）**：长期强句柄，可以跨线程、存静态变量；**会阻止GC，必须手动DeleteGlobalRef，否则内存泄漏**。
3. NewLocalRef一般很少主动调用，大多时候我们拿到的就是局部引用；NewGlobalRef是native长期持有Java对象的核心API。
