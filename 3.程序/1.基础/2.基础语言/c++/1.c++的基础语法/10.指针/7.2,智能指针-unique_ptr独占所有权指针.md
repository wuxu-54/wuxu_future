# unique_ptr 与 make_unique 完整讲解

`std::unique_ptr` 是C++11引入的**独占所有权智能指针**，头文件 `<memory>`，管理堆内存，**同一时刻只能有一个 unique_ptr 拥有对象所有权**，当 unique_ptr 析构时，自动 delete 托管的堆对象，防止内存泄漏。

>
> 核心特性：**独占、不可拷贝、只能移动、自动释放资源**

## 一、unique_ptr 基础用法（默认方式）

### 1. 原始写法：直接构造 unique_ptr

```
#include <memory>
#include <iostream>

struct Data {
    int x;
    Data(int v):x(v) { std::cout<<"构造\n"; }
    ~Data() { std::cout<<"析构\n"; }
};

int main() {
    // 直接new传给unique_ptr构造函数
    std::unique_ptr<Data> p1(new Data(100));

    // unique_ptr 禁止拷贝！下面代码编译报错
    // std::unique_ptr<Data> p2 = p1;

    // 只能std::move转移所有权，p1变成空
    std::unique_ptr<Data> p2 = std::move(p1);

    if(!p1) {
        std::cout << "p1现在为空\n";
    }
    // 离开作用域，p2析构，自动delete Data对象
    return 0;
}
```

- `unique_ptr<T>` 接收裸指针，接管堆对象；出作用域调用 `delete ptr`。
- **禁止拷贝构造、拷贝赋值**，只支持移动语义 `std::move`。所有权移交之后，原指针变为空(nullptr)。
- 可以像裸指针一样：`p2->x`、`(*p2).x`；`get()` 获取裸指针；`reset()` 释放对象。

### 2. 管理数组版本 unique_ptr<T[]>

```
// 管理数组，会调用 delete[]
std::unique_ptr<int[]> arr(new int[10]);
arr[0] = 10;
```

## 二、make_unique（C++14）

`std::make_unique<T>(args)` 是工厂函数，用来**创建 unique_ptr，替代手动 `new`**。

```
// 等价于 std::unique_ptr<Data> p(new Data(200));
auto p = std::make_unique<Data>(200);

// 数组版本 make_unique<T[]>(size)
auto arr = std::make_unique<int[]>(10);
arr[0] = 99;
```

>
> C++11没有 `make_unique`，需要自己实现；C++14标准正式加入。

### make_unique 做了什么？

1. 在内部执行 `new T(args)`；
2. 将返回的裸指针包装成 `unique_ptr<T>` 返回；
3. 参数直接转发给T的构造函数。

## 三、make_unique VS 直接 new + unique_ptr构造 的区别

写法对比：

```
// 方式A：直接new传给unique_ptr构造
std::unique_ptr<Data> p1(new Data(10));

// 方式B：make_unique（推荐）
auto p2 = std::make_unique<Data>(10);
```

### 区别1：异常安全（最重要）

考虑这样一个函数调用场景：

```
void func(std::unique_ptr<Data> a, int b);

// 危险写法！
func(std::unique_ptr<Data>(new Data(10)), get_b());

// 安全写法
func(std::make_unique<Data>(10), get_b());
```

C++函数参数求值顺序是**未定义**：

- 危险版本执行顺序可能：`new Data(10)` → 调用`get_b()`抛出异常 → `unique_ptr` 对象还没构造出来！**new出来的内存直接泄漏！**
- `make_unique`：先在函数内部完成`new`并且马上包装进unique_ptr对象。就算后续其它参数抛异常，unique_ptr已经生成，内存会被释放，**不会内存泄漏**。

>
> ✅ make_unique 提供更强的异常安全，这是标准推荐使用它的首要理由。

### 区别2：内存开销

- `new + unique_ptr{}`：先`new`对象，然后把指针传入unique_ptr。
- `make_unique<T>`：同样一次`new`，**对于普通对象两者内存开销完全一样**。

>
> ⚠️注意：`make_unique`**不能自定义deleter**！

```
// 如果需要自定义删除器，只能直接构造unique_ptr，make_unique做不到
auto del = [](Data* p){ delete p; };
std::unique_ptr<Data, decltype(del)> p(new Data(1), del);
```

`make_unique` 默认使用默认deleter（`delete`/`delete[]`），不支持传入自定义删除器。这是它的短板。

### 区别3：返回类型与代码简洁

```
// make_unique：auto自动推导，少写一遍类型
auto p = make_unique<Data>(10);

// new方式：要写两遍Data
std::unique_ptr<Data> p(new Data(10));
```

### 区别4：不能获取裸指针参与某些表达式

`make_unique`返回的是unique_ptr临时对象，你拿不到中间的裸指针；
而 `new T` 会产出裸指针，可以传给别的函数（不推荐）。

### 总结对比表

| 特性 | unique_ptr(new T(...)) | make_unique(...) |
| --- | --- | --- |
| 异常安全 | ❗存在内存泄漏风险 | ✅安全 |
| 自定义deleter | ✅支持 | ❌不支持 |
| 代码简洁 | 重复写类型 | ✅auto推导，简洁 |
| 普通对象性能 | 相同 | 相同 |
| 数组支持 | `unique_ptr<T[]>(new T[N])` | `make_unique<T[]>(N)` |
| C++版本 | C++11 | C++14（C++11可手动实现） |

>
> 最佳实践：**绝大多数场景优先用 make_unique；只有要自定义删除器的时候，才手动 new + unique_ptr构造**。

## 四、unique_ptr核心要点回顾

1. **独占所有权**：不允许多个unique_ptr管理同一个对象；不能拷贝，只能`std::move`转移所有权。

```
auto a = make_unique<Data>(1);
auto b = std::move(a);
// a现在是空，b持有对象
```

2. 生命周期：离开作用域自动释放；`reset()`主动释放；`release()`返回裸指针并且放弃所有权（**不会delete对象，要小心内存泄漏**）。

```
Data* raw = b.release(); // b置空，你要手动delete raw
delete raw;
```

3. `get()` 获取内部裸指针，**不要delete get()返回的指针！否则双重释放崩溃**。

## 五、应用场景 unique_ptr

### 场景1：函数内部拥有堆对象，离开自动释放，替代裸指针new/delete

局部堆对象，不想手动写delete，防止异常提前return导致泄漏。

```
void test() {
    auto obj = std::make_unique<Data>(100);
    // ...业务逻辑，中间return/抛异常都不会泄漏
}
```

### 场景2：作为函数返回值，返回堆对象

unique_ptr支持移动，函数返回时所有权转移，不需要手动管理内存。

```
std::unique_ptr<Data> create_data(int v) {
    return std::make_unique<Data>(v);
}

int main() {
    auto p = create_data(50);
    return 0;
}
```

### 场景3：类成员变量，管理类内部资源

类拥有某个堆资源，对象销毁自动释放资源，不用手写析构释放；遵循RAII。

```
class Demo {
private:
    std::unique_ptr<Data> m_ptr;
public:
    Demo(int v): m_ptr(std::make_unique<Data>(v)) {}
    // 不需要手写~Demo，unique_ptr自动释放
};
```

>
> 注意：类有unique_ptr成员时，**拷贝构造被隐式删除**，该类对象不能拷贝，只能move。

### 场景4：容器存放独占对象

`vector<unique_ptr<Data>>`，保存一堆堆对象，容器销毁时全部释放。

```
std::vector<std::unique_ptr<Data>> vec;
vec.push_back(std::make_unique<Data>(1));
vec.push_back(std::make_unique<Data>(2));
// vec销毁，全部Data自动释放
```

### 场景5：pimpl惯用法（指针实现，隐藏实现细节）

头文件只放前向声明，实现放在cpp，减少编译依赖，`unique_ptr`作为pimpl指针。

```
// .h
struct Impl;
class MyClass {
    std::unique_ptr<Impl> m_impl;
public:
    MyClass();
    ~MyClass();
};
// .cpp
struct Impl { /*实现细节*/ };
MyClass::MyClass():m_impl(std::make_unique<Impl>()){}
MyClass::~MyClass() = default;
```

### 什么时候不能用make_unique

1. 需要**自定义删除器**（文件句柄、socket、第三方库资源），只能手动构造unique_ptr传入deleter。

```
//示例：管理FILE*
auto file_del = [](FILE* f){ if(f) fclose(f); };
using FilePtr = std::unique_ptr<FILE, decltype(file_del)>;
FilePtr fp(fopen("a.txt","r"), file_del);
```

## 六、unique_ptr vs shared_ptr简单区分（容易混淆）

- `unique_ptr`：独占，开销极小（几乎和裸指针一样，没有引用计数）；只能move。优先选。
- `shared_ptr`：共享所有权，内部原子引用计数，有额外开销，可以拷贝；多份智能指针共享同一个对象。

>
> 能用unique_ptr就不要用shared_ptr；独占语义性能更好。

## 补充：C++11下没有make_unique怎么办

你可以自己简易实现：

```
template<typename T, typename... Args>
std::unique_ptr<T> make_unique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
```

## 易错坑点

1. ❌不要 `unique_ptr<T> p = new T;`，不能裸指针隐式转换！构造函数是explicit，必须显式构造。
2. ❌不要对同一个裸指针构造两个unique_ptr，会双重释放崩溃。
3. ❌不要`delete p.get()`，会双重释放。
4. ❌不要忽略release()返回的裸指针，会内存泄漏。
5. ❌尝试拷贝unique_ptr直接编译报错，要用std::move。
