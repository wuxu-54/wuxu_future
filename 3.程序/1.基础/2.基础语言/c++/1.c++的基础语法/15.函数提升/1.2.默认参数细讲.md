# C++ 默认参数（Default Arguments）

>
> 默认参数：**在函数声明里给形参指定默认值**，调用函数时如果不提供这个实参，编译器自动使用预先写好的默认值。
> 核心：**默认参数是编译期替换，发生在调用点，不是函数内部**。

## 1. 基础语法

```
// 声明：给b设置默认值
void func(int a, int b = 10);

// 调用
func(1);   // 等价 func(1,10)，编译器自动补第二个参数
func(1,20);// 自己传参，覆盖默认
```

✅ 规则1：**默认参数必须从右往左连续定义，不能中间断**

```
void f(int a, int b = 1, int c = 2); // ✅ 合法

void f(int a = 1, int b); // ❌ 非法，带默认的参数后面不能有无默认的参数
```

>
> 原因：调用传参是按位置匹配，不能跳过中间参数只给后面传。

## 2. 声明 vs 定义（分离编译重点，刚才聊的）

>
> 默认参数属于**函数声明的信息**，不属于函数实现（定义）。
> 分离编译：**只在头文件(.h)的声明写默认值；cpp里面的实现不能再写**。

```
// .h
void foo(int x, int y = 100);

// .cpp
void foo(int x, int y) { // ❗不能写 y=100，会编译报错
}
```

如果函数**声明和定义写在同一个地方**（inline、模板函数），默认参数写在定义上：

```
template<typename T>
void print(T val, int flag = 0) {
}
```

>
> 原理：编译调用代码的时候，编译器**查找当前可见的函数声明**，来补全默认参数。
> 如果调用处看不到带默认参数的声明，就不能省略实参。

## 3. 默认参数的求值时机【高频面试】

>
> **默认参数表达式，在【调用点】求值，不是函数定义处！**

```
int getNum() {
    static int x = 0;
    return ++x;
}
void func(int a = getNum()) {
    std::cout << a << "\n";
}

// 调用
func(); // getNum()执行，返回1
func(); // getNum()执行，返回2
func(100); // 不传默认，getNum不执行
```

每次省略实参调用，都会重新执行一遍默认参数表达式。

⚠️ 不要用带副作用的函数当默认参数，容易产生难以预料的行为。

## 4. 默认参数 + 函数重载：容易产生二义性

```
void test(int a);
void test(int a, int b = 10);

test(1); // ❌ 编译歧义！编译器不知道调用哪一个
```

>
> 编译器看到`test(1)`，两个版本都能匹配，直接报错。

## 5. 默认参数可以是哪些类型？

1. 常量字面量

```
void f(int a = 10, const char* s = "hello");
```

2. 全局变量 / static变量（不推荐，依赖外部状态）

```
int g_val = 20;
void f(int a = g_val);
```

3. 函数调用（上面例子）
4. 构造函数的默认参数（非常常用）

```
class Person {
public:
    Person(int age = 18);
};
Person p; // Person(18)
```

## 6. 类成员函数的默认参数

同样遵循：**声明写.h，实现cpp不带默认值**

```
// .h
class Pool {
public:
    void resize(int size = 4);
};

// .cpp
void Pool::resize(int size) {
}
```

### 构造函数默认参数（大坑：会生成默认构造函数）

```
class A {
public:
    A(int x = 0) {}
};
A a; // ✅ 合法，调用A(0)，这个构造函数同时充当默认构造函数
```

只要构造所有参数都带默认值，这个构造函数就可以**无参调用**，等价默认构造函数。

## 7. 默认参数和虚函数

>
> 虚函数的默认参数**静态绑定！** 这是超级经典面试坑。
> 默认参数是编译期根据**指针/引用的静态类型**决定，不是运行时动态类型。

```
#include <iostream>
struct Base {
    virtual void func(int a = 10) {
        std::cout << "base " << a << "\n";
    }
};
struct Derive : Base {
    void func(int a = 20) override {
        std::cout << "derive " << a << "\n";
    }
};

int main() {
    Base* p = new Derive();
    p->func(); // 输出 derive 10
    // ✅ 函数是动态绑定（调用子类func）
    // ✅ 默认参数是静态绑定，看Base声明，取a=10！！
    delete p;
    return 0;
}
```

>
> 结论：虚函数重写时，**不要写不一样的默认参数，极易造成诡异bug**。工程上建议虚函数不要使用默认参数。

## 8. 模板函数的默认模板参数（区分：函数默认参数）

注意区分两个东西，很容易混淆：

1. **函数参数默认值**（运行传入的参数）

```
template<typename T>
void f(T v, int flag = 0) {}
```

2. **模板参数默认值**（模板类型参数，编译期）

```
template<typename T = int>
void f(T v) {}
f(10); // T=int
```

## 9. 常见坑汇总

1. 默认参数**只能从右往左写**，不能中间空缺。
2. 分离编译：.h写默认值，cpp实现不能重复写，否则编译报错。
3. 默认参数表达式**在调用点求值**，慎用带副作用函数。
4. 虚函数重写，默认参数静态绑定，不要子类修改默认值。
5. 和重载一起使用，容易产生调用歧义。
6. 默认参数不会参与函数签名，不影响重载决议。

## 10. 什么时候适合用默认参数？

适合：参数有**非常高频的固定默认取值**，省略这个参数可读性很好。

```
// 线程池，默认4个线程
void start(int thread_num = 4);
```

不适合：

- 默认值容易变、有业务逻辑；
- 虚函数；
- 参数多，默认值太多，可读性变差；>

> 替代方案：重载函数，多个版本函数，可读性往往更好。

# 一句话面试总结

默认参数是在**函数声明**指定，调用点编译器补全实参；默认参数表达式在调用点求值；虚函数的默认参数是静态绑定，由静态类型决定，不是运行时对象类型。
