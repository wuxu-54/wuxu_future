# C++ `#include ""` 和 `#include <>` 区别

>
> 核心：**搜索顺序不一样**，都去查编译器的头文件搜索目录列表，只是起始搜索位置不同。

## 1. `#include "xxx.h"` 双引号

搜索顺序：

1. **首先搜索当前源文件所在目录**（`.cpp` 文件本身的文件夹）
2. 再去编译器的包含搜索路径列表（CMake `target_include_directories` 设置的目录、系统目录）

```
#include "nexus/logger.h"
```

适合：**自己项目的头文件、业务头文件**。

## 2. `#include <xxx.h>` 尖括号

搜索顺序：

- **跳过当前cpp所在目录，直接去编译器的包含搜索路径列表（target_include_directories + 系统库路径）查找**。

```
#include <vector>
#include <mutex>
#include <spdlog/spdlog.h>
```

适合：**标准库、第三方库头文件**。

---

## 举例子，结合你现在的项目结构

```
nexus/
├── CMakeLists.txt
├── include/
│   └── nexus/logger.h
└── src/
    └── main.cpp
```

CMake设置：

```
target_include_directories(nexus PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)
```

`main.cpp` 在 `src/` 目录：

✅写法1

```
#include "nexus/logger.h"
```

1. 先找 `src/nexus/logger.h` → 找不到
2. 再走CMake设置的include目录：`include/nexus/logger.h` → 找到。

✅写法2（也能工作，但风格不推荐）

```
#include <nexus/logger.h>
```

直接去CMake的搜索目录找，跳过src目录，也能找到。

>
> 功能上可以跑，但是工程编码规范：**本项目头文件用 `""`；系统/第三方库用 `<>`**。

### 一个容易踩坑场景

假设：`src/utils.h`，`src/main.cpp`。
main.cpp和utils.h**在同一个文件夹src下面**。

```
// main.cpp
#include "utils.h" // ✅第一步就在当前目录找到，不需要target_include_directories
```

如果写成：

```
#include <utils.h> // ❗不会搜当前src目录，如果CMake没有把src加入include路径，直接报找不到头文件
```

# 重点澄清误区

### 误区1：`""`代表本地文件，`<>`代表系统文件，仅此而已？

不完全。
`""` 搜完本地目录之后，**一样会去系统路径搜索**。
所以你写 `#include "vector"` 也能找到标准库，只是不符合编码规范。

### 误区2：`""` 是相对路径，`<>`是绝对路径？

不是。两者都使用编译器的include搜索目录列表。

### 误区3：尖括号不会读target_include_directories设置的路径

❌错误。
`target_include_directories` 添加的目录，**双引号、尖括号两者都会使用**。唯一差别就是：`""`多一步先查当前cpp所在文件夹。

---

# 结合你CMake的逻辑梳理

当你写：

```
target_include_directories(nexus PRIVATE
   ${CMAKE_CURRENT_SOURCE_DIR}/include
)
```

这个目录，会同时加入编译器搜索列表。

- `#include "nexus/logger.h"`：先看cpp本地目录，再到`include/`
- `#include <nexus/logger.h>`：直接到`include/`

>
> 如果你把`src`加入`target_include_directories`，那么尖括号也可以直接找到src下面的头文件。

## 编码实践规范（工业项目、JNI项目通用）

1. ✅项目内部自己写的头文件：**双引号 `#include "xxx/yyy.h"`**
2. ✅C++标准库、STL：尖括号 `#include <mutex> <memory> <string>`
3. ✅第三方库(spdlog/abseil等)：尖括号 `#include <spdlog/spdlog.h>`
4. ❌不要写 `#include "../include/xxx.h"` 这种回溯相对路径，依靠target_include_directories，写干净的`"xxx/yyy.h"`。

## 简短记忆口诀

>
> **双引号：先查当前cpp所在文件夹，再查配置的include路径。**
> **尖括号：直接查配置的include路径，跳过当前cpp目录。**

---

## 补充：GCC / MSVC微小差异

绝大多数行为一致。MSVC下`""`搜索目录顺序会多几个额外目录；写跨平台JNI代码，按上面规范写即可，不用关心编译器细微差异。

### 面试高频小问题

>
> 问：如果头文件既在当前cpp目录，又在target_include_directories目录存在同名头文件，include ""会取哪一个？
> 答：优先取**当前源文件目录下的那一个**，这也是双引号的风险：本地同名文件会覆盖库头文件。尖括号不会受这个问题影响。
