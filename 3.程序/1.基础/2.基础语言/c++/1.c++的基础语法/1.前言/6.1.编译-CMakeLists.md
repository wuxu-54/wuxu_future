# C++ CMakeLists.txt 完整配置指南

CMake 是目前 C++ 生态最主流的跨平台构建系统生成器。下面按"从最小可用 → 现代工程化 → 高级特性"的顺序，把一份生产级 `CMakeLists.txt` 里会用到的东西讲透。

## 精简概叙

用一句话概括这份文档的精髓：**现代 CMake 就是围绕“目标（Target）”打转，所有配置都挂在目标上，并通过 `PUBLIC/PRIVATE/INTERFACE` 严格控制依赖的传递性。**

拆解成最精简的 5 条核心法则：

1. **核心对象**：一切皆目标（`add_executable` 或 `add_library`）。可执行文件、静态库、动态库、甚至纯头文件库（`INTERFACE`）都是目标。
2. **黄金命令**：永远用 `target_*` 系列命令（如 `target_include_directories`、`target_link_libraries`），**坚决不用**全局的 `include_directories` 或 `link_libraries`。
3. **传递规则（最重点）**：
   - **`PRIVATE`**：自己用，不给依赖者（仅 `.cpp` 需要）。
   - **`PUBLIC`**：自己用，也传给依赖者（头文件里需要）。
   - **`INTERFACE`**：自己不用，只传给依赖者（纯头文件库）。
4. **依赖获取**：优先用 `find_package` 找现成的导入目标（如 `fmt::fmt`），次选 `FetchContent` 在配置期拉取源码，避免手写路径。
5. **工程组织**：用 `add_subdirectory` 拆分模块；用 `install` + `EXPORT` 让别人能 `find_package` 找到你。

**最后的“避坑”三板斧**：

- 别用 `GLOB` 收集源文件（显式列出来更可靠）。
- 别在代码里硬编码编译器选项（用生成器表达式 `$<$<CXX_COMPILER_ID:MSVC>:/W4>` 区分平台）。
- 启动 `CMAKE_EXPORT_COMPILE_COMMANDS` 让 IDE 和 clangd 能读懂你的项目。

## 一、CMake 基础概念

### 1.1 CMake 是什么

- CMake 不直接编译代码，而是**生成构建文件**（Makefile、Ninja、Visual Studio 解决方案、Xcode 工程等）。
- 工作流：`CMakeLists.txt` → `cmake` 配置（configure）→ 生成构建系统 → 调用原生构建工具编译。

### 1.2 标准构建流程（out-of-source 构建）

```
# 配置
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

# 编译
cmake --build build -j

# 运行
./build/myapp
```

- `-S`：源码目录（含顶层 CMakeLists.txt）
- `-B`：构建目录（产物输出位置）
- `--build`：跨构建器统一编译命令，避免直接敲 `make`/`msbuild`

## 二、最小可运行示例

```
cmake_minimum_required(VERSION 3.15)
project(MyApp VERSION 1.0.0 LANGUAGES CXX)

add_executable(myapp main.cpp)
```

三行核心：

1. **`cmake_minimum_required`**：声明最低 CMake 版本，决定可用策略和语法。
2. **`project`**：定义项目名、版本、语言。
3. **`add_executable`**：声明一个可执行目标。

---

## 三、项目级配置详解

### 3.1 `cmake_minimum_required`

```
cmake_minimum_required(VERSION 3.15...3.28)
```

- 范围写法 `3.15...3.28`：若当前 CMake 版本在区间内，使用该版本策略；低于 3.15 报错。
- 建议**至少 3.15**（`target_link_libraries` 对普通库的 PUBLIC/PRIVATE 语义稳定）；新项目推荐 3.20+。

### 3.2 `project`

```
project(MyApp
  VERSION     1.2.3
  DESCRIPTION "A sample C++ application"
  HOMEPAGE_URL "https://example.com"
  LANGUAGES    CXX
)
```

`project()` 会自动设置一批变量：

- `PROJECT_NAME`、`PROJECT_VERSION`、`PROJECT_VERSION_MAJOR/MINOR/PATCH`
- `PROJECT_SOURCE_DIR`、`PROJECT_BINARY_DIR`
- `MyApp_SOURCE_DIR`、`MyApp_BINARY_DIR`（带项目名前缀，子项目里很有用）

`LANGUAGES` 可写 `C CXX Fortran ASM` 等；只写 CXX 能避免 C 编译器探测，加快配置。

### 3.3 全局默认设置（放在 project() 之后）

```
# C++ 标准
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)   # 不支持就报错，而不是静默降级
set(CMAKE_CXX_EXTENSIONS OFF)         # 禁用 GNU 扩展（-std=c++17 而非 -std=gnu++17）

# 构建类型默认值（单配置生成器如 Make/Ninja 才生效）
if(NOT CMAKE_BUILD_TYPE AND NOT CMAKE_CONFIGURATION_TYPES)
  set(CMAKE_BUILD_TYPE Release CACHE STRING "Build type" FORCE)
  set_property(CACHE CMAKE_BUILD_TYPE PROPERTY STRINGS
    Debug Release RelWithDebInfo MinSizeRel)
endif()

# 输出目录统一
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)
set(CMAKE_LIBRARY_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/lib)
set(CMAKE_ARCHIVE_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/lib)

# 把 compile_commands.json 导出（给 clangd / IDE 用）
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)
```

>
> **现代 CMake 原则**：能用 target 属性就别用全局变量。上面这些是"项目级默认"，真正的编译选项应通过 `target_*` 命令绑定到具体目标。

## 四、目标（Target）——现代 CMake 的核心

CMake 3.x 的核心抽象是 **target**。每个目标自带一组属性：源文件、include 路径、编译选项、宏定义、依赖库等，并通过 `PUBLIC/PRIVATE/INTERFACE` 决定**是否传递给依赖者**。

### 4.1 三种目标

```
# 可执行文件
add_executable(myapp src/main.cpp)

# 静态库 (.a / .lib)
add_library(mylib STATIC src/mylib.cpp)

# 动态库 (.so / .dll / .dylib)
add_library(mylib SHARED src/mylib.cpp)

# 接口库（纯头文件库，无编译产物）
add_library(headeronly INTERFACE)

# 对象库（编译为 .o 但不归档，可被多个目标复用，避免重复编译）
add_library(myobj OBJECT src/common.cpp)
```

### 4.2 PUBLIC / PRIVATE / INTERFACE 语义

| 关键字 | 自己用 | 传递给依赖者 |
| --- | --- | --- |
| `PRIVATE` | 是 | 否 |
| `PUBLIC` | 是 | 是 |
| `INTERFACE` | 否 | 是 |

记忆口诀：

- 出现在 **头文件**（对外暴露）→ `PUBLIC`
- 只在 **.cpp 内部**使用 → `PRIVATE`
- 纯头文件库 / 纯接口 → `INTERFACE`

```
target_include_directories(mylib
  PUBLIC  ${CMAKE_CURRENT_SOURCE_DIR}/include   # 头文件里用了，必须公开
  PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/src       # 仅内部实现用
)

target_link_libraries(myapp
  PRIVATE mylib        # myapp 内部用 mylib
  PUBLIC  some_public_dep
)
```

### 4.3 目标上的常用命令

```
# 源文件（也可在 add_executable 里直接列）
target_sources(myapp PRIVATE src/a.cpp src/b.cpp)

# 头文件搜索路径
target_include_directories(myapp PRIVATE include)

# 预处理器宏定义
target_compile_definitions(myapp
  PRIVATE MYAPP_INTERNAL=1
  PUBLIC  MYAPP_VERSION="1.0.0"
)

# 编译选项
target_compile_options(myapp PRIVATE -Wall -Wextra)

# C++ 标准（目标级，优先于全局变量）
target_compile_features(myapp PRIVATE cxx_std_17)

# 链接选项
target_link_options(myapp PRIVATE -Wl,--as-needed)

# 链接库
target_link_libraries(myapp PRIVATE Threads::Threads)
```

`target_compile_features` 比 `CMAKE_CXX_STANDARD` 更精细，可指定具体特性如 `cxx_lambda`、`cxx_constexpr`，CMake 会自动推导所需标准。

## 五、源文件管理

### 5.1 显式列出（推荐）

```
add_executable(myapp
  src/main.cpp
  src/network/client.cpp
  src/network/server.cpp
  src/utils/logger.cpp
)
```

显式列表的好处：CMake 能准确知道依赖关系，新增文件必须改 CMakeLists（避免漏编译）。

### 5.2 `file(GLOB)`（不推荐，但常见）

```
file(GLOB MYAPP_SOURCES CONFIGURE_DEPENDS "src/*.cpp")
add_executable(myapp ${MYAPP_SOURCES})
```

- `CONFIGURE_DEPENDS`（3.12+）：让构建器在文件增删时自动重新 cmake。
- 缺点：某些生成器（尤其是 VS）下检查不稳定；大项目里 glob 会把测试文件、临时文件卷进来。
- **生产项目建议显式列表**，或用 glob 后配合 `list(FILTER)` 排除。

### 5.3 分组（IDE 里的文件树）

```
source_group(TREE ${CMAKE_CURRENT_SOURCE_DIR} FILES ${MYAPP_SOURCES})
```

让 Visual Studio / Xcode 按真实目录结构显示文件，而不是平铺。

## 六、编译选项与警告

### 6.1 跨编译器警告配置

```
if(MSVC)
  target_compile_options(myapp PRIVATE /W4 /permissive- /Zc:__cplusplus)
else()
  target_compile_options(myapp PRIVATE
    -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wold-style-cast
  )
endif()
```

### 6.2 用生成器表达式按构建类型加选项

```
target_compile_options(myapp PRIVATE
  $<$<CXX_COMPILER_ID:GNU,Clang,AppleClang>:-Wall -Wextra>
  $<$<CXX_COMPILER_ID:MSVC>:/W4>
  $<$<CONFIG:Debug>:-g -O0>
  $<$<CONFIG:Release>:-O3>
)
```

生成器表达式 `$<condition:value>` 在**生成阶段**求值，能区分编译器、配置、平台，是现代 CMake 的瑞士军刀。

### 6.3 预编译头（PCH，3.16+）

```
target_precompile_headers(myapp PRIVATE
  <iostream>
  <vector>
  <string>
  "pch.h"
)
```

大幅加快重复编译，尤其头文件巨大的项目。注意 PCH 会影响某些工具（如 include-what-you-use）。

### 6.4 Unity Build（3.16+）

```
set_target_properties(myapp PROPERTIES
  UNITY_BUILD ON
  UNITY_BUILD_BATCH_SIZE 10
)
```

把多个 cpp 合并成一个翻译单元编译，显著加快全量编译，但可能暴露匿名命名空间 / 宏冲突。

## 七、查找与链接库

### 7.1 `find_package`——最常用的依赖引入方式

```
find_package(Boost 1.74 REQUIRED COMPONENTS system filesystem)
find_package(OpenSSL REQUIRED)
find_package(Threads REQUIRED)
find_package(fmt REQUIRED)

target_link_libraries(myapp PRIVATE
  Boost::system
  Boost::filesystem
  OpenSSL::SSL
  OpenSSL::Crypto
  Threads::Threads
  fmt::fmt
)
```

- `REQUIRED`：找不到就报错终止。
- `COMPONENTS`：指定子模块。
- 现代包都提供 **导入目标（Imported Target）**，形如 `Boost::system`，链接它会自动带上 include 路径、定义、依赖——**不要再手写 `include_directories(${Boost_INCLUDE_DIRS})`**。

### 7.2 `find_package` 的两种模式

1. **Module 模式**：查找 `Find<Package>.cmake` 模块（CMake 自带或 CMAKE_MODULE_PATH 下）。
2. **Config 模式**：查找 `<Package>Config.cmake`（包自己安装时生成，信息更全）。

优先 Config 模式，找不到才回退 Module。强制 Config 模式：

```
find_package(fmt CONFIG REQUIRED)
```

### 7.3 系统库直接链接

```
target_link_libraries(myapp PRIVATE m dl pthread)
```

但 pthread 推荐用 `Threads::Threads`，跨平台更稳。

### 7.4 子模块 / 本地库

```
add_subdirectory(third_party/fmt)   # 里面有自己的 CMakeLists.txt
target_link_libraries(myapp PRIVATE fmt::fmt)
```

配合 Git submodule 使用，是不依赖包管理器时的常见做法。

## 八、依赖管理：FetchContent（3.11+）

在配置阶段自动下载并构建第三方依赖，无需预装：

```
include(FetchContent)

FetchContent_Declare(
  fmt
  GIT_REPOSITORY https://github.com/fmtlib/fmt.git
  GIT_TAG        10.2.1
)
FetchContent_MakeAvailable(fmt)

target_link_libraries(myapp PRIVATE fmt::fmt)
```

- `FetchContent_MakeAvailable` 会同时 `add_subdirectory`，让目标直接可用。
- 适合小依赖；大依赖（Boost、Qt）仍建议系统包或 vcpkg/conan。
- 可配合 `FETCHCONTENT_BASE_DIR` 改缓存位置。

## 九、多目录工程组织

### 9.1 典型目录结构

```
myproject/
├── CMakeLists.txt          # 顶层
├── src/
│   ├── CMakeLists.txt
│   └── main.cpp
├── libs/
│   ├── core/
│   │   ├── CMakeLists.txt
│   │   ├── include/core/...
│   │   └── src/...
│   └── utils/
│       └── CMakeLists.txt
├── tests/
│   └── CMakeLists.txt
└── third_party/
```

### 9.2 顶层 CMakeLists.txt

```
cmake_minimum_required(VERSION 3.20)
project(MyProject VERSION 1.0.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# 只有当前是顶层项目时才开启测试/安装，避免被 add_subdirectory 引入时污染
if(CMAKE_PROJECT_NAME STREQUAL PROJECT_NAME)
  include(CTest)
  option(MYPROJECT_BUILD_TESTS "Build tests" ON)
endif()

add_subdirectory(libs/core)
add_subdirectory(libs/utils)
add_subdirectory(src)

if(MYPROJECT_BUILD_TESTS AND BUILD_TESTING)
  add_subdirectory(tests)
endif()
```

### 9.3 库子目录 `libs/core/CMakeLists.txt`

```
add_library(core
  src/engine.cpp
  src/config.cpp
)

target_include_directories(core
  PUBLIC  ${CMAKE_CURRENT_SOURCE_DIR}/include
  PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/src
)

target_link_libraries(core PUBLIC utils)
```

注意：`PUBLIC utils` 意味着任何链接 `core` 的目标都会自动链接 `utils` 并获得其 include 路径——这正是传递依赖的正确表达。

### 9.4 可执行子目录 `src/CMakeLists.txt`

```
add_executable(myapp main.cpp)
target_link_libraries(myapp PRIVATE core utils)
```

## 十、变量、选项与条件判断

### 10.1 变量基础

```
# 普通变量（当前作用域）
set(MYVAR "hello")

# 缓存变量（出现在 cmake-gui / ccmake，可被 -D 覆盖）
set(MYPROJECT_PORT 8080 CACHE STRING "Server port")

# 选项（BOOL 型缓存变量）
option(MYPROJECT_ENABLE_LOG "Enable logging" ON)
option(BUILD_SHARED_LIBS "Build shared libraries" OFF)
```

- `cmake -DMYPROJECT_PORT=9090 ..` 覆盖缓存变量。
- `set(... CACHE ...)` 第二次不会覆盖已有值，除非加 `FORCE`。

### 10.2 条件判断

```
if(MYPROJECT_ENABLE_LOG)
  target_compile_definitions(core PRIVATE MYPROJECT_LOG=1)
endif()

if(WIN32)
  target_compile_definitions(core PRIVATE WIN32_LEAN_AND_MEAN NOMINMAX)
elseif(APPLE)
  target_link_libraries(core PRIVATE "-framework CoreFoundation")
elseif(UNIX)
  target_link_libraries(core PRIVATE dl)
endif()

if(CMAKE_CXX_COMPILER_ID STREQUAL "GNU")
  # ...
elseif(CMAKE_CXX_COMPILER_ID MATCHES "Clang")
  # 匹配 Clang 和 AppleClang
endif()
```

常用平台变量：`WIN32`、`APPLE`、`UNIX`、`MINGW`、`MSVC`、`CYGWIN`。

### 10.3 列表与循环

```
set(LIBS core utils net)
foreach(lib IN LISTS LIBS)
  message(STATUS "Configuring lib: ${lib}")
endforeach()

list(APPEND MY_SOURCES extra.cpp)
list(FILTER MY_SOURCES EXCLUDE REGEX ".*_test\\.cpp$")
```

## 十一、构建类型（Build Type）

CMake 预置四种配置，各自对应一组编译标志：

| 类型 | 典型标志（GCC） | 用途 |
| --- | --- | --- |
| `Debug` | `-g -O0` | 调试 |
| `Release` | `-O3 -DNDEBUG` | 发布 |
| `RelWithDebInfo` | `-O2 -g -DNDEBUG` | 带调试信息的发布（性能分析） |
| `MinSizeRel` | `-Os -DNDEBUG` | 最小体积 |

单配置生成器（Make/Ninja）：

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
```

多配置生成器（Visual Studio / Xcode）：

```
cmake --build build --config Release
```

自定义构建类型标志：

```
set(CMAKE_CXX_FLAGS_RELWITHDEBINFO "-O2 -g -DNDEBUG -fno-omit-frame-pointer")
```

## 十二、安装与导出（install）

让项目支持 `make install` / `cmake --install`，并能被其他项目 `find_package` 找到。

### 12.1 基本安装规则

```
include(GNUInstallDirs)   # 定义 CMAKE_INSTALL_LIBDIR / INCLUDEDIR / BINDIR 等标准路径

install(TARGETS myapp core
  RUNTIME  DESTINATION ${CMAKE_INSTALL_BINDIR}       # 可执行 / dll
  LIBRARY  DESTINATION ${CMAKE_INSTALL_LIBDIR}       # .so / .dylib
  ARCHIVE  DESTINATION ${CMAKE_INSTALL_LIBDIR}       # .a / .lib
  INCLUDES DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
)

install(DIRECTORY include/
  DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
  FILES_MATCHING PATTERN "*.h" PATTERN "*.hpp"
)

install(FILES README.md LICENSE
  DESTINATION ${CMAKE_INSTALL_DOCDIR}
)
```

### 12.2 导出目标，让别人能 find_package

```
install(TARGETS core
  EXPORT MyProjectTargets
  ...
)

install(EXPORT MyProjectTargets
  FILE MyProjectTargets.cmake
  NAMESPACE MyProject::
  DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/MyProject
)

# 生成 config 文件
include(CMakePackageConfigHelpers)
configure_package_config_file(
  ${CMAKE_CURRENT_SOURCE_DIR}/cmake/MyProjectConfig.cmake.in
  ${CMAKE_CURRENT_BINARY_DIR}/MyProjectConfig.cmake
  INSTALL_DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/MyProject
)
write_basic_package_version_file(
  ${CMAKE_CURRENT_BINARY_DIR}/MyProjectConfigVersion.cmake
  VERSION ${PROJECT_VERSION}
  COMPATIBILITY SameMajorVersion
)
install(FILES
  ${CMAKE_CURRENT_BINARY_DIR}/MyProjectConfig.cmake
  ${CMAKE_CURRENT_BINARY_DIR}/MyProjectConfigVersion.cmake
  DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/MyProject
)
```

安装后，外部项目可：

```
find_package(MyProject 1.0 REQUIRED)
target_link_libraries(otherapp PRIVATE MyProject::core)
```

## 十三、测试集成（CTest + GoogleTest）

### 13.1 启用 CTest

```
include(CTest)   # 等价于 enable_testing() + 提供 BUILD_TESTING 选项

if(BUILD_TESTING)
  add_subdirectory(tests)
endif()
```

### 13.2 接入 GoogleTest

```
# tests/CMakeLists.txt
include(FetchContent)
FetchContent_Declare(
  googletest
  GIT_REPOSITORY https://github.com/google/googletest.git
  GIT_TAG v1.14.0
)
FetchContent_MakeAvailable(googletest)

add_executable(mytests test_main.cpp test_core.cpp)
target_link_libraries(mytests PRIVATE core GTest::gtest GTest::gtest_main)

include(GoogleTest)
gtest_discover_tests(mytests)   # 自动把每个 TEST 注册为 ctest 用例
```

运行：

```
ctest --test-dir build --output-on-failure
```

## 十四、生成器表达式（Generator Expressions）

在**生成阶段**（不是配置阶段）求值，用于根据编译器、配置、平台、目标属性动态生成内容。

### 14.1 常用形式

```
# 条件值
$<$<CONFIG:Debug>:-DDEBUG>
$<$<CXX_COMPILER_ID:MSVC>:/W4>

# 逻辑
$<AND:cond1,cond2>
$<OR:cond1,cond2>
$<NOT:cond>

# 字符串比较
$<STREQUAL:${VAR},foo>

# 目标属性
$<TARGET_PROPERTY:core,INCLUDE_DIRECTORIES>

# 构建目录相关
$<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
$<INSTALL_INTERFACE:include>
```

### 14.2 经典用法：构建/安装双接口 include 路径

```
target_include_directories(core
  PUBLIC
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
    $<INSTALL_INTERFACE:include>
)
```

- 构建时用绝对源码路径。
- 安装后用相对安装前缀的路径。
- 这是库能同时被源码内和安装后正确使用的关键。

## 十五、自定义命令与目标

### 15.1 自定义构建命令（生成源文件）

```
add_custom_command(
  OUTPUT  ${CMAKE_CURRENT_BINARY_DIR}/generated.cpp
  COMMAND ${PYTHON_EXECUTABLE} ${CMAKE_CURRENT_SOURCE_DIR}/gen.py
          -o ${CMAKE_CURRENT_BINARY_DIR}/generated.cpp
  DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/gen.py
          ${CMAKE_CURRENT_SOURCE_DIR}/data.json
  COMMENT "Generating generated.cpp"
  VERBATIM
)

add_executable(myapp main.cpp ${CMAKE_CURRENT_BINARY_DIR}/generated.cpp)
```

- `OUTPUT` + `DEPENDS` 构成依赖关系，输入变了才重跑。
- `VERBATIM` 保证参数跨平台正确转义，**务必加上**。

### 15.2 自定义目标（总是执行 / 手动触发）

```
add_custom_target(format
  COMMAND clang-format -i ${MY_SOURCES}
  WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}
  COMMENT "Running clang-format"
)
```

`cmake --build build --target format` 触发。

### 15.3 编译后拷贝资源 / 运行后处理

```
add_custom_command(TARGET myapp POST_BUILD
```

## 二十、现代 CMake 最佳实践清单

1. **以 target 为中心**：用 `target_*` 系列命令，少用全局 `include_directories` / `add_definitions` / `link_libraries`。
2. **明确 PUBLIC/PRIVATE/INTERFACE**：不要偷懒全写 PUBLIC，会污染依赖者。
3. **优先导入目标**：`Boost::system` 而非 `${Boost_LIBRARIES}`。
4. **避免 glob 源文件**：显式列表更可靠；必须 glob 时加 `CONFIGURE_DEPENDS`。
5. **out-of-source 构建**：永远不要在源码目录里 cmake。
6. **顶层项目判断**：`if(CMAKE_PROJECT_NAME STREQUAL PROJECT_NAME)` 决定是否开测试/安装，便于被 `add_subdirectory` 嵌入。
7. **用 `CMAKE_*_OUTPUT_DIRECTORY` 统一产物路径**。
8. **导出 `compile_commands.json`**：给 clangd、IDE、静态分析用。
9. **版本号写在 `project(VERSION ...)`**：通过 `PROJECT_VERSION` 传递，可生成 config version 文件。
10. **安装时用 `GNUInstallDirs` + BUILD_INTERFACE/INSTALL_INTERFACE**。
11. **自定义命令加 `VERBATIM`**。
12. **避免在 CMakeLists 里硬编码编译器标志**：用生成器表达式按编译器区分，或放到 toolchain / preset。

## 二十二、常见坑与排查

| 问题 | 原因 / 解决 |
| --- | --- |
| 改了 CMakeLists 没生效 | 多配置生成器需重新 configure；检查是否改对了当前 active 的 preset |
| 链接时找不到头文件 | 依赖库的 include 没设成 PUBLIC，或用了旧的 `${XXX_INCLUDE_DIRS}` 而非导入目标 |
| 循环依赖 | `target_link_libraries(A B)` 且 `B A`，用 OBJECT 库或拆分接口 |
| Windows 下 dll 找不到 | 运行时 dll 需在 PATH 或 exe 同目录；用 POST_BUILD 拷贝或设置 RUNTIME_OUTPUT |
| `find_package` 找不到 | 检查 `CMAKE_PREFIX_PATH`、vcpkg/conan toolchain、包是否提供 Config 文件 |
| 标志被覆盖 | 全局 `CMAKE_CXX_FLAGS` 会与 target 选项叠加；调试用 `cmake --build . --verbose` 看实际命令 |
| 变量作用域混乱 | `add_subdirectory` 创建新作用域；需向上传递用 `set(... PARENT_SCOPE)` 或缓存变量 / target 属性 |

调试技巧：

```
cmake -S . -B build --trace-source=CMakeLists.txt   # 跟踪执行
cmake -LAH build                                     # 列出所有缓存变量
cmake --build build --verbose                        # 看完整编译/链接命令
```

## 二十三、一份生产级模板（综合示例）

```
cmake_minimum_required(VERSION 3.20)
project(MyProject
  VERSION 1.0.0
  DESCRIPTION "A production-grade C++ project"
  LANGUAGES CXX
)

# ---- 全局默认 ----
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)

if(NOT CMAKE_BUILD_TYPE AND NOT CMAKE_CONFIGURATION_TYPES)
  set(CMAKE_BUILD_TYPE Release CACHE STRING "" FORCE)
endif()

set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)
set(CMAKE_LIBRARY_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/lib)
set(CMAKE_ARCHIVE_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/lib)

# ---- 选项 ----
option(MYPROJECT_BUILD_TESTS  "Build unit tests"  ON)
option(MYPROJECT_BUILD_SHARED "Build shared libs" OFF)
option(MYPROJECT_ENABLE_ASAN  "Enable ASan"       OFF)

# ---- 依赖 ----
find_package(Threads REQUIRED)
find_package(fmt REQUIRED)

# ---- 子目录 ----
add_subdirectory(libs/core)
add_subdirectory(src)

if(MYPROJECT_BUILD_TESTS AND CMAKE_PROJECT_NAME STREQUAL PROJECT_NAME)
  enable_testing()
  add_subdirectory(tests)
endif()
```

```
# libs/core/CMakeLists.txt
add_library(core src/engine.cpp)
add_library(MyProject::core ALIAS core)

target_include_directories(core
  PUBLIC
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
    $<INSTALL_INTERFACE:include>
  PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/src
)

target_compile_features(core PUBLIC cxx_std_17)

if(MYPROJECT_ENABLE_ASAN)

```

```
add_executable(myapp main.cpp)
target_link_libraries(myapp PRIVATE MyProject::core)
```

## 总结

掌握 CMake 的关键是建立三个心智模型：

1. **目标（target）是一等公民**：所有编译/链接/包含信息都挂在目标上，通过 PUBLIC/PRIVATE/INTERFACE 传递。
2. **配置阶段 vs 生成阶段 vs 构建阶段**：普通变量/if 在配置阶段求值；生成器表达式在生成阶段；`add_custom_command` 在构建阶段执行。
3. **导入目标 + find_package + 导出安装**：让你的库既能被源码内 `add_subdirectory` 使用，也能安装后被 `find_package` 使用，是"库作者"的分水岭。
