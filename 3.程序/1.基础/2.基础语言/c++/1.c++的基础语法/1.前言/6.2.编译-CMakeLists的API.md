# CMake 核心 API 详解（功能 + 参数 + 示例）

下面按类别逐一讲解，每个命令都包含：**做什么的 → 参数详解 → 用法示例**。

## 分类

| 分类 | 代表命令 | 核心作用（你的原版） | **通俗大白话解释（新增）** |
| :--- | :--- | :--- | :--- |
| **目标定义类** | `add_executable`<br>`add_library`<br>`add_custom_target` | 告诉 CMake “我要生成什么东西”（二进制产物或执行动作） | **`add_executable`**：告诉编译器“给我生成一个可执行的 `.exe` 程序”。<br>**`add_library`**：告诉编译器“给我生成一个库文件（静态 `.a` 或动态 `.so/.dylib`）”。<br>**`add_custom_target`**：定义一个“虚拟任务”，比如“帮我复制文件”或“运行脚本”，不一定是编译代码。 |
| **依赖组织类** | `add_subdirectory`<br>`target_link_libraries`<br>`add_dependencies` | 组织项目目录结构和构建顺序 | **`add_subdirectory`**：引入子文件夹里的另一个 CMake 配置，让大项目分模块管理。<br>**`target_link_libraries`**：告诉某个目标“你需要链接隔壁那个库才能工作”。<br>**`add_dependencies`**：强制规定“必须先编译 A，再编译 B”（常用于保证编译顺序）。 |
| **变量/缓存操作类** | `set`<br>`option`<br>`unset` | `set` = 万能赋值（普通变量、缓存变量、环境变量都归它管）；`option` = 专门给用户设置的布尔开关；`unset` = 删除变量定义 | **`set`**：给任何一个变量起名字并塞进去内容（字符串、列表、路径都行）。<br>**`option`**：专门用来定义“是否开启某功能”的复选框（只能选 `ON` 或 `OFF`），方便用户命令行修改。<br>**`unset`**：让 CMake 彻底忘掉这个变量，跟没定义过一样。 |
| **属性配置类** | `target_compile_definitions`<br>`target_include_directories`<br>`set_property` | 给特定目标添加编译宏、头文件路径等（现代 CMake 推荐） | **`target_compile_definitions`**：给某个目标加宏定义（相当于代码里的 `#define`，或 gcc 的 `-D` 参数）。<br>**`target_include_directories`**：告诉某个目标去哪里找头文件（相当于 gcc 的 `-I` 参数）。<br>**`set_property`**：一种万能修改工具，可以修改目标、文件等各种对象的属性（但通常有专用命令时不用它）。 |
| **条件/流程控制** | `if`, `else`<br>`foreach`<br>`list` | 纯脚本逻辑，决定哪些代码被包含或循环执行 | **`if` / `else`**：根据条件（比如“是不是苹果系统”）决定走哪段构建逻辑。<br>**`foreach`**：遍历一个列表，把里面所有的值挨个处理一遍（比如处理多个源文件）。<br>**`list`**：专门用来操作列表的工具包（比如往列表里追加、删除、查找某个元素）。 |

## 一、项目基础

### 1. `cmake_minimum_required`

**做什么的**：声明构建本项目所需的最低 CMake 版本。如果用户的 CMake 版本低于此值，会报错并停止。同时会设置相应的策略（policy）行为。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `VERSION <min>` | 最低版本号，如 `3.15` |
| `...<max>` | 可选，最高版本范围（3.19+ 支持），如 `3.15...3.28` |
| `FATAL_ERROR` | 旧版本兼容参数，现已隐含，无需显式写 |

**示例**：

```
cmake_minimum_required(VERSION 3.20)
```

---

### 2. `project`

**做什么的**：定义项目名称、版本、描述、主页和使用的编程语言。调用后会设置一系列 `PROJECT_*` 变量，是 CMakeLists.txt 中必不可少的命令。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<PROJECT-NAME>` | 项目名称，设置后 `PROJECT_NAME` 变量为此值 |
| `VERSION <major>[.<minor>[.<patch>[.<tweak>]]]` | 项目版本号，设置 `PROJECT_VERSION` 等变量 |
| `DESCRIPTION <string>` | 项目简短描述，设置 `PROJECT_DESCRIPTION` |
| `HOMEPAGE_URL <url>` | 项目主页，设置 `PROJECT_HOMEPAGE_URL` |
| `LANGUAGES <lang>...` | 使用的编程语言，可选 `C`、`CXX`、`Fortran`、`ASM`、`CUDA`、`OBJC`、`OBJCXX`、`Swift` 等。默认 `C CXX`。写 `NONE` 表示不启用任何语言 |

**示例**：

```
project(MyApp
    VERSION 2.1.0
    DESCRIPTION "A modern C++ application"
    HOMEPAGE_URL "https://example.com/myapp"
    LANGUAGES CXX)
```

---

### 3. `message`

**做什么的**：向用户输出信息，是调试 CMake 脚本最常用的工具。不同模式会影响输出前缀和是否终止构建。

**参数**：

| 参数/模式 | 作用 |
| --- | --- |
| `STATUS` | 普通状态信息，输出前缀 `--` |
| `WARNING` | 警告信息，前缀 `CMake Warning at`，继续执行 |
| `AUTHOR_WARNING` | 开发者警告，仅在 `CMAKE_SUPPRESS_DEVELOPER_ERRORS` 关闭时显示 |
| `SEND_ERROR` | 错误信息，继续执行但跳过生成步骤 |
| `FATAL_ERROR` | 致命错误，输出后立即终止 CMake |
| `DEPRECATION` | 弃用警告，受 `CMAKE_ERROR_DEPRECATED` / `CMAKE_WARN_DEPRECATED` 控制 |
| `DEBUG` | 调试信息，仅在 `--debug-output` 时显示 |
| `TRACE` | 追踪信息，仅在 `--trace` 时显示 |
| `CHECK_START` / `CHECK_PASS` / `CHECK_FAIL` | 配合输出"正在检测... 检测到/未检测到"的格式化输出 |
| `"text"` | 要输出的文本内容，支持变量展开 |

**示例**：

```
message(STATUS "Configuring ${PROJECT_NAME} v${PROJECT_VERSION}")
message(WARNING "This feature is experimental")
message(FATAL_ERROR "Compiler not supported: ${CMAKE_CXX_COMPILER_ID}")
```

## 二、变量与列表

### 4. `set`

**做什么的**：设置普通变量、缓存变量或环境变量的值。是 CMake 中最基础的变量操作命令。

**参数（三种形式）**：

**形式一：普通变量**

| 参数 | 作用 |
| --- | --- |
| `<variable>` | 变量名 |
| `<value>...` | 变量值，多个值会组成列表（用分号分隔） |
| `PARENT_SCOPE` | 在父作用域中设置变量（函数/子目录中向上传递） |

**形式二：缓存变量**

| 参数 | 作用 |
| --- | --- |
| `CACHE <type>` | 缓存变量类型：`BOOL`、`FILEPATH`、`PATH`、`STRING`、`INTERNAL` |
| `<docstring>` | 变量说明，显示在 cmake-gui 中 |
| `FORCE` | 强制覆盖已有的缓存值（默认不覆盖） |

**形式三：环境变量**

| 参数 | 作用 |
| --- | --- |
| `ENV{<variable>}` | 环境变量名 |
| `[<value>]` | 环境变量值，留空则清除 |

**示例**：

```
set(MY_VAR "hello")              # 普通变量
set(SRCS a.cpp b.cpp c.cpp)      # 列表变量
set(CMAKE_CXX_STANDARD 17 CACHE STRING "C++ standard")  # 缓存变量
set(ENV{MY_ENV} "value")         # 环境变量
set(PARENT_VAR "data" PARENT_SCOPE)  # 向上传递
```

#### 1. 普通变量 —— “现场随手记的便利贴”

- **通俗解释**：你开会时随手拿了一张便利贴，写上 `会议纪要 = "下午3点"`。**这张便利贴只在这间会议室（当前 CMake 文件及其子目录）里有效**，会议结束（CMake 配置阶段结束）就扔掉了，不会保存到任何文件中。
- **CMake 特性**：
  - **只在内存中**，不会写入 `CMakeCache.txt`。
  - **作用域**：只在当前 `CMakeLists.txt` 和 `add_subdirectory` 引入的子文件中有效；子文件修改它不影响父文件（除非用 `PARENT_SCOPE`）。
  - **命令行无法修改**：你不能在 `cmake -D` 里传参给它（除非它同时是缓存变量）。
- **典型写法**：`set(MY_TEMP_LIST "a;b;c")`（不加 `CACHE` 关键字）。

#### 2. 缓存变量 —— “挂在公司墙上的白板通告”

- **通俗解释**：你把“是否开启 JNI”写在公司公共白板上（`CMakeCache.txt` 文件）。**只要不擦掉，全公司（所有 CMake 文件）都能看到，并且下次开会（下次运行 cmake 命令）时白板上的字还在**。你想改这个值，要么拿白板笔直接擦（用 `unset(... CACHE)`），要么在门口喊一声“改成 OFF”（命令行 `-D` 传参）。
- **CMake 特性**：
  - **持久化**：存储在项目根目录的 `CMakeCache.txt` 文件中。
  - **全局可见**：所有子目录都能读取到这个值。
  - **用户可配置**：用户可以在命令行用 `cmake -D<变量>=值 ..` 覆盖，也可以在 cmake-gui 里勾选修改。
- **典型写法**：`set(MY_FEATURE ON CACHE BOOL "开启某功能")` 或直接用 `option(MY_FEATURE "desc" ON)`。

#### 3. 环境变量 —— “天气预报（外部系统）”

- **通俗解释**：这不是公司内部写的，而是**大楼物业（操作系统）**决定的。比如今天气温 30°C（`PATH` 路径），你走进会议室时自带了这个信息。CMake 可以**看**（读取）它，也可以**临时改**（设置自己进程里的副本），但**改不了外面真正的天气**（改不了系统 Shell 的环境变量，只影响当前 CMake 进程及其子进程）。
- **CMake 特性**：
  - **来源外部**：继承自启动 CMake 的终端（Shell）。
  - **访问方式特殊**：必须用 `$ENV{变量名}` 包裹，例如 `message($ENV{PATH})`。
  - **临时覆盖**：可以用 `set(ENV{MY_VAR} "new")` 修改，但**这个修改只影响当前 CMake 进程内部**，CMake 运行结束后，终端里 `echo $MY_VAR` 还是原来的值。
- **典型场景**：用 `$ENV{JAVA_HOME}` 来找 JDK 安装路径。

#### 终极区分口诀（帮你加深记忆）

| 变量类型 | 别名（记住这个） | 存在哪里？ | 跨 `cmake ..` 还记住吗？ | 命令行能改吗？ |
| :--- | :--- | :--- | :--- | :--- |
| **普通变量** | **内存便利贴** | 内存（RAM） | **不记得**（每次运行重新算） | **不能** |
| **缓存变量** | **硬盘白板** | `CMakeCache.txt` | **记得**（除非手动删除） | **能**（`-D`） |
| **环境变量** | **操作系统天气** | 系统 Shell（终端外） | 取决于 Shell，CMake 不保存 | 不能（只能读） |

#### 针对你之前代码的实战对应

- 你写的 `option(BUILD_JNI "..." OFF)` → 这个 `BUILD_JNI` 是**缓存变量**，所以你在命令行用 `-DBUILD_JNI=ON` 能生效，并且下次 cmake 时它还保留着。
- 你写的 `set(CMAKE_OSX_DEPLOYMENT_TARGET "10.15")`（未加 `CACHE`）→ **如果在 `if(APPLE)` 里面且没写 `CACHE`，它其实是普通变量**，只在当前文件中起作用。但 CMake 特殊的是，`CMAKE_OSX_DEPLOYMENT_TARGET` 是**具有特殊行为的普通变量**，CMake 工具链会读取它的值传给编译器，但不会把它存进 `CMakeCache.txt`。这也是为什么你想永久固定这个版本时，很多模板会写成 `set(CMAKE_OSX_DEPLOYMENT_TARGET "10.15" CACHE STRING "" FORCE)` 来强行塞进缓存。
- 环境变量例子：如果你的终端 `export JAVA_HOME=/usr/lib/jvm/java-11`，CMake 里用 `$ENV{JAVA_HOME}` 就能读到这个系统路径。

**一句话总结**：普通变量是你自己临时记的，缓存变量是你让大家记住并保存下来的，环境变量是操作系统自带进来的“外来信息”。三者相互独立，修改其中一个通常不影响另外两个（除非你刻意拷贝赋值）。

### 5. `list`

**做什么的**：对列表变量进行各种操作，包括追加、移除、查找、排序、连接等。

**参数（按子命令）**：

| 子命令 | 参数 | 作用 |
| --- | --- | --- |
| `APPEND` | `<list> [<element>...]` | 向列表末尾追加元素 |
| `PREPEND` | `<list> [<element>...]` | 向列表开头插入元素 |
| `INSERT` | `<list> <index> [<element>...]` | 在指定索引处插入元素 |
| `REMOVE_ITEM` | `<list> <value>...` | 移除指定值的元素 |
| `REMOVE_AT` | `<list> <index>...` | 移除指定索引的元素 |
| `REMOVE_DUPLICATES` | `<list>` | 去重 |
| `LENGTH` | `<list> <out_var>` | 获取列表长度 |
| `GET` | `<list> <index>... <out_var>` | 获取指定索引的元素 |
| `FIND` | `<list> <value> <out_var>` | 查找值的索引，找不到返回 -1 |
| `JOIN` | `<list> <glue> <out_var>` | 用连接符合并为字符串 |
| `SORT` | `<list> [COMPARE ...] [CASE ...] [ORDER ...]` | 排序 |
| `FILTER` | ` {INCLUDE | EXCLUDE} REGEX ` |
| `TRANSFORM` | `<list> <ACTION> [...]` | 对每个元素做变换（如 TOLOWER） |
| `POP_FRONT` | `<list> [<out_var>...]` | 弹出头部元素 |
| `POP_BACK` | `<list> [<out_var>...]` | 弹出尾部元素 |

**示例**：

```
set(FRUITS apple banana cherry)
list(APPEND FRUITS date)          # apple;banana;cherry;date
list(REMOVE_ITEM FRUITS banana)   # apple;cherry;date
list(LENGTH FRUITS COUNT)         # COUNT = 3
list(FIND FRUITS cherry IDX)      # IDX = 1
list(JOIN FRUITS ", " STR)        # "apple, cherry, date"
```

### 6. `string`

**做什么的**：对字符串进行查找、替换、正则匹配、大小写转换、截取、拼接等操作。

**参数（按子命令）**：

| 子命令 | 参数 | 作用 |
| --- | --- | --- |
| `REPLACE` | `<match> <replace> <out_var> <input>...` | 字符串替换（支持正则） |
| `REGEX MATCH` | `<regex> <out_var> <input>` | 匹配第一个结果 |
| `REGEX MATCHALL` | `<regex> <out_var> <input>` | 匹配所有结果，返回列表 |
| `REGEX REPLACE` | `<regex> <replace> <out_var> <input>` | 正则替换 |
| `TOLOWER` | `<string> <out_var>` | 转小写 |
| `TOUPPER` | `<string> <out_var>` | 转大写 |
| `LENGTH` | `<string> <out_var>` | 获取长度 |
| `SUBSTRING` | `<string> <begin> <length> <out_var>` | 截取子串，`length=-1` 表示到末尾 |
| `CONCAT` | `<out_var> [<input>...]` | 拼接字符串 |
| `COMPARE` | `<op> <string1> <string2> <out_var>` | 比较，op 为 `EQUAL`/`LESS`/`GREATER` 等 |
| `FIND` | `<string> <substring> <out_var> [REVERSE]` | 查找子串位置 |
| `MD5` / `SHA1` / `SHA256` | `<string> <out_var>` | 计算哈希 |
| `UUID` | `<out_var> NAMESPACE <ns> NAME <name> TYPE <type>` | 生成 UUID |
| `JSON` | ... | 解析 JSON（3.19+） |

**示例**：

```
string(TOUPPER "hello" UP)        # UP = "HELLO"
string(REPLACE ".cpp" ".o" OBJ "main.cpp")  # OBJ = "main.o"
string(REGEX MATCH "[0-9]+" NUM "version 123")  # NUM = "123"
string(SUBSTRING "abcdef" 1 3 SUB)  # SUB = "bcd"
```

## 三、控制流

### 7. `if / elseif / else / endif`

**做什么的**：条件判断，根据条件执行不同的代码块。CMake 的 `if` 有特殊的变量求值规则（不加 `${}` 也会自动解引用变量）。

**条件表达式**：

| 表达式 | 作用 |
| --- | --- |
| `if(<constant>)` | `ON`/`YES`/`TRUE`/`Y`/非零数字为真；`OFF`/`NO`/`FALSE`/`N`/`IGNORE`/空/`NOTFOUND` 为假 |
| `if(<variable>)` | 变量值为假常量则为假，否则为真（未定义为假） |
| `if(NOT <cond>)` | 逻辑非 |
| `if(<cond1> AND <cond2>)` | 逻辑与 |
| `if(<cond1> OR <cond2>)` | 逻辑或 |
| `if(COMMAND cmd)` | 命令/函数是否存在 |
| `if(POLICY policy-id)` | 策略是否存在 |
| `if(TARGET target)` | 目标是否已定义 |
| `if(EXISTS path)` | 文件/目录是否存在 |
| `if(IS_DIRECTORY path)` | 是否为目录 |
| `if(IS_SYMLINK path)` | 是否为符号链接 |
| `if(IS_ABSOLUTE path)` | 是否为绝对路径 |
| `if(file1 IS_NEWER_THAN file2)` | 文件1是否比文件2新 |
| `if(v1 STREQUAL v2)` | 字符串相等 |
| `if(v1 STRLESS v2)` | 字符串字典序小于 |
| `if(v1 STRGREATER v2)` | 字符串字典序大于 |
| `if(v1 VERSION_EQUAL v2)` | 版本号相等 |
| `if(v1 VERSION_LESS v2)` | 版本号小于 |
| `if(v1 VERSION_GREATER v2)` | 版本号大于 |
| `if(v1 EQUAL v2)` | 数值相等 |
| `if(v1 LESS v2)` | 数值小于 |
| `if(v1 GREATER v2)` | 数值大于 |
| `if(DEFINED var)` | 变量是否已定义 |
| `if(CMAKE_VERSION VERSION_GREATER_EQUAL 3.20)` | 版本比较常用写法 |

**示例**：

```
if(WIN32)
    message(STATUS "Building on Windows")
elseif(APPLE)
    message(STATUS "Building on macOS")
elseif(UNIX)
    message(STATUS "Building on Linux/Unix")
endif()

if(CMAKE_CXX_COMPILER_ID STREQUAL "GNU" AND CMAKE_CXX_COMPILER_VERSION VERSION_GREATER_EQUAL 11)
    target_compile_options(myapp PRIVATE -fconcepts)
endif()
```

### 8. `foreach / endforeach`

**做什么的**：循环遍历列表、范围或键值对，对每个元素执行代码块。

**参数（四种形式）**：

| 形式 | 参数 | 作用 |
| --- | --- | --- |
| 列表遍历 | `<loop_var> <items>...` | 遍历给定的元素列表 |
| `IN LISTS` | `<loop_var> IN LISTS <list_var>` | 遍历列表变量的所有元素 |
| `RANGE` | `<loop_var> RANGE <start> <stop> [<step>]` | 遍历整数范围，含端点 |
| `IN ZIP_LISTS` | `<loop_var>... IN ZIP_LISTS <list1> [<list2>...]` | 并行遍历多个列表 |

**控制关键字**：

- `break()`：跳出循环
- `continue()`：跳过当前迭代

**示例**：

```
# 遍历列表
foreach(file IN LISTS SRCS)
    message(STATUS "Source: ${file}")
endforeach()

# 范围遍历
foreach(i RANGE 0 9 2)
    message(STATUS "i = ${i}")  # 0, 2, 4, 6, 8
endforeach()

# 并行遍历
foreach(a b IN ZIP_LISTS LIST1 LIST2)
    message(STATUS "${a} -> ${b}")
endforeach()
```

---

### 9. `while / endwhile`

**做什么的**：当条件为真时重复执行代码块，用法与 `if` 条件相同。

**示例**：

```
set(i 0)
while(i LESS 5)
    math(EXPR i "${i} + 1")
    message(STATUS "i = ${i}")
endwhile()
```

## 四、目标创建

### 10. `add_executable`

**做什么的**：创建一个可执行文件目标，指定源文件后 CMake 会编译并链接生成可执行程序。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<name>` | 目标名称，在项目内必须唯一，也是默认的输出文件名 |
| `WIN32` | Windows 下使用 WinMain 入口（不显示控制台窗口），对应 `WIN32_EXECUTABLE` 属性 |
| `MACOSX_BUNDLE` | macOS 下生成 `.app` 应用包 |
| `EXCLUDE_FROM_ALL` | 不加入默认构建，需要显式构建该目标 |
| `[source1] [source2] ...` | 源文件列表，也可以后续用 `target_sources` 追加 |

**其他形式**：

- `add_executable(<name> IMPORTED [GLOBAL])`：导入外部已存在的可执行文件
- `add_executable(<name> ALIAS <target>)`：为目标创建别名（常用于命名空间）

**示例**：

```
add_executable(myapp main.cpp util.cpp)

# Windows GUI 程序
add_executable(mygui WIN32 main.cpp window.cpp)

# 别名
add_executable(MyApp::app ALIAS myapp)
```

---

### 11. `add_library`

**做什么的**：创建一个库目标，可以是静态库、动态库、模块库、对象库或接口库（头文件库）。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<name>` | 库目标名称，项目内唯一 |
| `STATIC` | 静态库（`.a` / `.lib`），编译进可执行文件 |
| `SHARED` | 动态/共享库（`.so` / `.dll` / `.dylib`），运行时链接 |
| `MODULE` | 模块库，运行时通过 `dlopen` 加载，不参与链接 |
| `OBJECT` | 对象库，仅编译为 `.o`，不归档，可被其他目标复用 |
| `INTERFACE` | 接口库，无编译产物，用于纯头文件库或传递编译选项 |
| `EXCLUDE_FROM_ALL` | 不加入默认构建 |
| `[source...]` | 源文件列表 |

**说明**：

- 不指定类型时，由 `BUILD_SHARED_LIBS` 变量决定（ON→SHARED，OFF→STATIC）
- `INTERFACE` 库不能有源文件

**示例**：

```
add_library(mylib STATIC src/lib.cpp)
add_library(mydll SHARED src/dll.cpp)
add_library(myheader INTERFACE)  # 纯头文件库

# 对象库
add_library(myobj OBJECT src/common.cpp)
target_link_libraries(myapp PRIVATE myobj)
```

---

### 12. `add_custom_target`

**做什么的**：创建一个没有输出文件的自定义目标，始终执行指定命令。常用于文档生成、代码格式化、运行脚本等"伪目标"。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `Name` | 目标名称 |
| `ALL` | 加入默认构建，否则需显式 `make Name` |
| `COMMAND <cmd> [args...]` | 要执行的命令，可指定多个 |
| `DEPENDS <depend>...` | 依赖的文件或其他目标 |
| `BYPRODUCTS <files>...` | 命令产生的副产物文件 |
| `WORKING_DIRECTORY <dir>` | 命令执行的工作目录 |
| `COMMENT <text>` | 执行前显示的注释信息 |
| `VERBATIM` | 确保参数被正确转义，推荐始终加上 |
| `USES_TERMINAL` | 命令直接使用终端（不捕获输出） |
| `COMMAND_EXPAND_LISTS` | 命令参数中的列表变量会展开为多个参数 |

**示例**：

```
add_custom_target(format
    COMMAND clang-format -i ${SRCS}
    WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}
    COMMENT "Formatting source code"
    VERBATIM)

add_custom_target(docs ALL
    COMMAND doxygen Doxyfile
    DEPENDS ${PUBLIC_HEADERS}
    WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}
    COMMENT "Generating API documentation"
    VERBATIM)
```

## 五、目标属性操作（现代 CMake 核心）

### 13. `target_include_directories`

**做什么的**：为指定目标添加头文件搜索路径（即编译器的 `-I` 参数）。这是现代 CMake 中管理头文件路径的标准方式，替代了旧的全局 `include_directories`。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<target>` | 目标名称，必须已通过 `add_executable` 或 `add_library` 创建 |
| `PRIVATE` | 头文件路径仅用于该目标自身的编译，不传递给链接此目标的其他目标 |
| `PUBLIC` | 头文件路径既用于该目标自身编译，也传递给所有链接此目标的目标（因为它们需要这些头文件来编译） |
| `INTERFACE` | 头文件路径不用于该目标自身，仅传递给链接者（适用于纯头文件库） |
| `BEFORE` | 将路径添加到列表前面而非后面 |
| `[items...]` | 一个或多个目录路径，支持生成器表达式 |
| `SYSTEM` | 标记这些路径为系统头文件路径（编译器可能抑制其中的警告） |

**关键说明**：

- `PUBLIC` = `PRIVATE` + `INTERFACE`
- 选择原则：如果头文件路径出现在该库的**公开头文件**中（即 `.h` 里 `#include` 了这些路径下的头文件），用 `PUBLIC`；如果只在 `.cpp` 内部使用，用 `PRIVATE`

**示例**：

```
target_include_directories(mylib
    PUBLIC
        $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
        $<INSTALL_INTERFACE:include>
    PRIVATE
        ${CMAKE_CURRENT_SOURCE_DIR}/src
)

# 系统头文件路径（抑制警告）
target_include_directories(myapp SYSTEM PRIVATE /usr/include/thirdparty)
```

---

### 14. `target_link_libraries`

**做什么的**：为目标指定需要链接的库或其他目标。这是管理库依赖关系的核心命令，同时会自动传递依赖目标的 `PUBLIC` 和 `INTERFACE` 属性（头文件路径、编译选项、定义等）。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<target>` | 目标名称 |
| `PRIVATE` | 仅该目标链接此库，不传递 |
| `PUBLIC` | 该目标链接此库，且链接此目标的其他目标也需要链接此库（传递） |
| `INTERFACE` | 该目标不链接，但链接者需要链接 |
| `<item>...` | 库名、目标名、库文件路径或链接选项 |
| `debug <item>` | 仅在 Debug 配置下链接 |
| `optimized <item>` | 仅在非 Debug 配置下链接 |
| `general <item>` | 所有配置下链接（默认） |

**关键说明**：

- 可以链接 CMake 目标名（如 `mylib`），CMake 会自动处理依赖传递和构建顺序
- 可以链接系统库名（如 `pthread`、`m`、`dl`）
- 可以链接导入目标（如 `Threads::Threads`、`Boost::system`）
- 可以用生成器表达式按配置选择：`$<$<CONFIG:Debug>:debug_lib>`

**示例**：

```
target_link_libraries(myapp
    PRIVATE
        mylib
        Threads::Threads
        fmt::fmt
)

# 按配置链接
target_link_libraries(myapp PRIVATE
    optimized Qt5::Core
    debug Qt5::Core_debug
)
```

---

### 15. `target_compile_options`

**做什么的**：专门用来给指定的某个目标（而不是全局所有文件）添加编译器的命令行参数（如 `-Wall`、`-O2`、`/W4` 等）。替代旧的全局 `add_definitions` 和 `CMAKE_CXX_FLAGS` 修改。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<target>` | 目标名称 |
| `BEFORE` | 添加到选项列表前面 |
| `PRIVATE` / `PUBLIC` / `INTERFACE` | 可见性，含义同上 |
| `[items...]` | 一个或多个编译选项，支持生成器表达式 |

**示例**：

```
target_compile_options(myapp PRIVATE
    $<$<CXX_COMPILER_ID:GNU,Clang,AppleClang>:-Wall -Wextra -Wpedantic>
    $<$<CXX_COMPILER_ID:MSVC>:/W4 /permissive->
)

# 仅 Debug 配置
target_compile_options(myapp PRIVATE
    $<$<AND:$<CXX_COMPILER_ID:GNU>,$<CONFIG:Debug>>:-fsanitize=address>
)
```

### 16. `target_compile_definitions`

**做什么的**：为目标添加预处理器宏定义（即编译器的 `-D` 参数）。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<target>` | 目标名称 |
| `PRIVATE` / `PUBLIC` / `INTERFACE` | 可见性 |
| `[items...]` | 宏定义，格式为 `NAME` 或 `NAME=value` |

**示例**：

```
target_compile_definitions(myapp PRIVATE
    VERSION_MAJOR=2
    VERSION_MINOR=1
    $<$<CONFIG:Debug>:DEBUG_MODE=1>
)
```

### 17. `target_compile_features`

**做什么的**：指定目标需要的 C/C++ 语言特性，CMake 会根据这些特性自动推导出所需的编译器标准版本，并设置相应的编译标志。比直接设置 `CMAKE_CXX_STANDARD` 更精细。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<target>` | 目标名称 |
| `PRIVATE` / `PUBLIC` / `INTERFACE` | 可见性 |
| `<feature>...` | 特性名称，如 `cxx_std_17`、`cxx_auto_type`、`cxx_lambda` 等 |

**常用特性**：

- `cxx_std_11` / `cxx_std_14` / `cxx_std_17` / `cxx_std_20` / `cxx_std_23`：直接指定标准
- `cxx_auto_type`：auto 类型推导
- `cxx_lambda`：Lambda 表达式
- `cxx_range_for`：范围 for 循环
- `cxx_constexpr`：constexpr
- `cxx_variadic_templates`：可变参数模板

**示例**：

```
target_compile_features(myapp PRIVATE cxx_std_17)
```

### 18. `target_sources`

**做什么的**：向已存在的目标追加源文件。常用于在子目录中逐步为顶层目标添加文件，或按条件添加源文件。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<target>` | 目标名称 |
| `PRIVATE` / `PUBLIC` / `INTERFACE` | 可见性。源文件通常用 `PRIVATE` |
| `[items...]` | 源文件路径，支持生成器表达式 |

**示例**：

```
if(WIN32)
    target_sources(myapp PRIVATE platform_win.cpp)
else()
    target_sources(myapp PRIVATE platform_unix.cpp)
endif()
```

### 19. `set_target_properties`

**做什么的**：批量设置一个或多个目标的属性。属性控制目标的各种行为，如输出名称、版本号、C++ 标准、输出目录等。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `target1 target2 ...` | 一个或多个目标名称 |
| `PROPERTIES` | 关键字，后面跟属性键值对 |
| `prop1 value1 prop2 value2 ...` | 属性名和值的交替列表 |

**常用目标属性**：

| 属性 | 作用 |
| --- | --- |
| `OUTPUT_NAME` | 输出文件名（不包括前缀和扩展名） |
| `OUTPUT_NAME_DEBUG` / `OUTPUT_NAME_RELEASE` | 按配置的输出名 |
| `VERSION` | 完整版本号（用于共享库） |
| `SOVERSION` | API 版本号（soname） |
| `CXX_STANDARD` | C++ 标准版本 |
| `CXX_STANDARD_REQUIRED` | 是否强制要求该标准 |
| `CXX_EXTENSIONS` | 是否允许编译器扩展（如 `-std=gnu++17`） |
| `POSITION_INDEPENDENT_CODE` | 是否生成位置无关代码（PIC） |
| `RUNTIME_OUTPUT_DIRECTORY` | 可执行文件输出目录 |
| `LIBRARY_OUTPUT_DIRECTORY` | 动态库输出目录 |
| `ARCHIVE_OUTPUT_DIRECTORY` | 静态库输出目录 |
| `RUNTIME_OUTPUT_NAME` | 运行时输出名 |
| `INSTALL_RPATH` | 安装后的 RPATH |
| `BUILD_RPATH` | 构建时的 RPATH |
| `MACOSX_RPATH` | macOS 是否使用 RPATH |
| `WIN32_EXECUTABLE` | 是否为 Windows GUI 程序 |
| `MACOSX_BUNDLE` | 是否为 macOS .app 包 |
| `EXCLUDE_FROM_ALL` | 是否排除在默认构建之外 |
| `LINK_FLAGS` | 额外链接选项 |
| `COMPILE_FLAGS` | 额外编译选项 |
| `DEBUG_POSTFIX` | Debug 配置下的文件名后缀（如 `d`） |
| `PREFIX` | 库文件名前缀（覆盖默认 `lib`） |
| `SUFFIX` | 库文件名后缀（覆盖默认 `.so`/`.a`） |
| `IMPORTED` | 是否为导入目标 |
| `INTERFACE_INCLUDE_DIRECTORIES` | 接口头文件目录 |
| `ALIASED_TARGET` | 别名指向的目标 |

**示例**：

```
set_target_properties(mylib PROPERTIES
    VERSION 1.2.3
    SOVERSION 1
    POSITION_INDEPENDENT_CODE ON
    CXX_STANDARD 17
    CXX_STANDARD_REQUIRED ON
    CXX_EXTENSIONS OFF
    DEBUG_POSTFIX d
)

set_target_properties(myapp PROPERTIES
    RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin
    OUTPUT_NAME "myapp_v2"
)
```

| --- | --- |
| `<VAR>` | 存储结果的变量名 |
| `target` | 目标名称 |
| `property` | 要读取的属性名 |

**示例**：

```
get_target_property(LIB_VERSION mylib VERSION)
```

## 六、依赖查找

### 21. `find_package`

**做什么的**：查找并加载外部项目的设置。是 CMake 中引入第三方库的标准方式。有两种工作模式：Module 模式（查找 `Find<Package>.cmake` 模块）和 Config 模式（查找 `<Package>Config.cmake` 配置文件）。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<PackageName>` | 包名，如 `Boost`、`Threads`、`OpenCV` |
| `[version]` | 最低版本要求，如 `1.70` |
| `EXACT` | 要求版本精确匹配 |
| `QUIET` | 不输出查找信息 |
| `MODULE` | 强制使用 Module 模式 |
| `CONFIG` | 强制使用 Config 模式 |
| `REQUIRED` | 找不到则报错终止 |
| `COMPONENTS <comp>...` | 需要的组件列表 |
| `OPTIONAL_COMPONENTS <comp>...` | 可选组件 |
| `NO_POLICY_SCOPE` | 不创建新的策略作用域 |
| `GLOBAL` | 将导入目标设为全局可见 |
| `BYPASS_PROVIDER` | 绕过包提供者（3.24+） |

**查找结果**：

- 成功后通常会设置 `<PackageName>_FOUND` 变量
- 可能提供导入目标（如 `Boost::system`、`OpenCV::OpenCV`）
- 可能设置变量（如 `<PackageName>_INCLUDE_DIRS`、`<PackageName>_LIBRARIES`）

**示例**：

```
find_package(Threads REQUIRED)
find_package(Boost 1.74 REQUIRED COMPONENTS system filesystem)
find_package(OpenCV QUIET)
if(OpenCV_FOUND)
    target_link_libraries(myapp PRIVATE ${OpenCV_LIBS})
endif()
```

### 22. `find_library`

**做什么的**：在系统标准路径和指定路径中查找库文件（`.so`/`.a`/`.dll`/`.lib`/`.dylib`），将找到的完整路径存入变量。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<VAR>` | 存储结果的变量名 |
| `name1 [name2 ...]` | 要查找的库名（不含前缀 `lib` 和扩展名） |
| `[path1 path2 ...]` | 额外搜索路径 |
| `PATHS <paths>...` | 指定搜索路径 |
| `PATH_SUFFIXES <suffix>...` | 路径后缀（如 `lib64`、`x86_64-linux-gnu`） |
| `DOC <text>` | 缓存变量说明 |
| `NO_DEFAULT_PATH` | 不搜索默认路径 |
| `NO_CMAKE_ENVIRONMENT_PATH` | 不搜索 CMake 环境变量指定路径 |
| `REQUIRED` | 找不到则报错（3.18+） |

**示例**：

```
find_library(MATH_LIBRARY m)
find_library(DL_LIBRARY dl REQUIRED)
target_link_libraries(myapp PRIVATE ${MATH_LIBRARY} ${DL_LIBRARY})
```

### 23. `find_path`

**做什么的**：查找包含指定头文件的目录路径。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<VAR>` | 存储结果的变量名 |
| `name1 [name2 ...]` | 要查找的头文件名 |
| `[path1 ...]` | 额外搜索路径 |
| `PATHS <paths>...` | 指定搜索路径 |
| `PATH_SUFFIXES <suffix>...` | 路径后缀 |
| `DOC <text>` | 缓存变量说明 |
| `REQUIRED` | 找不到则报错 |

**示例**：

```
find_path(ZLIB_INCLUDE_DIR zlib.h REQUIRED)
target_include_directories(myapp PRIVATE ${ZLIB_INCLUDE_DIR})
```

**做什么的**：查找可执行程序的完整路径。

**参数**：与 `find_path` 类似，查找对象是可执行文件。

**示例**：

```
find_program(CLANG_TIDY_EXE NAMES clang-tidy)
```

## 七、FetchContent

### 25. `FetchContent_Declare`

**做什么的**：声明一个外部内容（通常是 Git 仓库或压缩包），描述如何获取它。声明后不会立即下载，需要调用 `FetchContent_MakeAvailable` 或 `FetchContent_Populate`。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<name>` | 内容名称，用于标识 |
| `GIT_REPOSITORY <url>` | Git 仓库 URL |
| `GIT_TAG <tag>` | Git 标签、分支或 commit hash |
| `GIT_SHALLOW TRUE` | 浅克隆（只取最近一次提交） |
| `URL <url>` | 压缩包下载 URL |
| `URL_HASH MD5=...` / `SHA256=...` | 压缩包哈希校验 |
| `SOURCE_DIR <dir>` | 源码存放目录 |
| `BINARY_DIR <dir>` | 构建目录 |
| `DOWNLOAD_DIR <dir>` | 下载文件存放目录 |
| `PATCH_COMMAND <cmd>` | 下载后执行的补丁命令 |
| `UPDATE_DISCONNECTED TRUE` | 不自动更新 |
| `FIND_PACKAGE_ARGS ...` | 优先用 find_package，找不到再下载（3.24+） |

**示例**：

```
include(FetchContent)
FetchContent_Declare(
    fmt
    GIT_REPOSITORY https://github.com/fmtlib/fmt.git
    GIT_TAG 10.2.1
    GIT_SHALLOW TRUE
)
```

### 26. `FetchContent_MakeAvailable`

**做什么的**：确保声明的外部内容已被下载并添加到构建中（相当于自动执行下载 + `add_subdirectory`）。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<name>...` | 一个或多个已声明的内容名称 |

**示例**：

```
FetchContent_MakeAvailable(fmt)
target_link_libraries(myapp PRIVATE fmt::fmt)
```

## 八、文件操作

### 27. `file`

**做什么的**：CMake 的文件操作瑞士军刀，支持读写文件、glob 匹配、复制、下载、压缩、创建目录等数十种操作。

**常用子命令及参数**：

| 子命令 | 参数 | 作用 |
| --- | --- | --- |
| `READ` | `<filename> <var> [OFFSET <n>] [LIMIT <n>] [HEX]` | 读取文件内容到变量 |
| `WRITE` | `<filename> <content>...` | 写入文件（覆盖） |
| `APPEND` | `<filename> <content>...` | 追加写入文件 |
| `STRINGS` | `<filename> <var> [LIMIT_COUNT <n>] [LENGTH_MINIMUM <n>] [REGEX <re>]` | 读取文件中的非二进制行 |
| `GLOB` | `<var> [LIST_DIRECTORIES true\|false] [RELATIVE <path>] [CONFIGURE_DEPENDS] [<globs>...]` | 通配符匹配文件（不递归） |
| `GLOB_RECURSE` | `<var> [FOLLOW_SYMLINKS] [LIST_DIRECTORIES ...] [RELATIVE <path>] [CONFIGURE_DEPENDS] [<globs>...]` | 递归通配符匹配 |
| `COPY` | `<files>... DESTINATION <dir> [FILE_PERMISSIONS ...] [NO_SOURCE_PERMISSIONS]` | 复制文件/目录 |
| `INSTALL` | 同 COPY，但遵循安装规则 |  |
| `MAKE_DIRECTORY` | `<dirs>...` | 创建目录 |
| `REMOVE` | `<files>...` | 删除文件 |
| `REMOVE_RECURSE` | `<files>...` | 递归删除文件/目录 |
| `DOWNLOAD` | `<url> <file> [INACTIVITY_TIMEOUT <s>] [TIMEOUT <s>] [STATUS <var>] [LOG <var>] [SHOW_PROGRESS]` | 下载文件 |
| `UPLOAD` | `<file> <url> ...` | 上传文件 |
| `SIZE` | `<filename> <var>` | 获取文件大小 |
| `READ_SYMLINK` | `<link> <var>` | 读取符号链接目标 |
| `CREATE_LINK` | `<original> <link> [SYMBOLIC \| COPY_ON_ERROR]` | 创建链接 |
| `CHMOD` | `<files>... <permissions>... [RECURSE]` | 修改权限（3.20+） |
| `ARCHIVE_CREATE` | `<out> PATHS <paths>... [FORMAT zip\|7z\|tar\|pax] [COMPRESSION gzip\|bzip2\|xz\|zstd]` | 创建压缩包 |
| `ARCHIVE_EXTRACT` | `<input> [DESTINATION <dir>] [PATTERNS <patterns>]` | 解压 |
| `LOCK` | `<dir> [DIRECTORY] [GUARD FUNCTION\|FILE\|PROCESS] [RELEASE] [TIMEOUT <s>]` | 文件锁 |
| `TIMESTAMP` | `<filename> <var> [<format>] [UTC]` | 获取文件时间戳 |
| `GET_RUNTIME_DEPENDENCIES` | ... | 获取运行时依赖（3.16+） |

**⚠️ 重要提示**：`file(GLOB)` 收集源文件不推荐，因为新增文件不会触发 CMake 重新配置。推荐显式列出源文件。如果要用，加上 `CONFIGURE_DEPENDS` 让 CMake 在构建时检查文件变化。

**示例**：

```
file(GLOB_RECURSE SRCS CONFIGURE_DEPENDS "src/*.cpp" "src/*.h")
file(COPY ${CMAKE_SOURCE_DIR}/assets DESTINATION ${CMAKE_BINARY_DIR})
file(MAKE_DIRECTORY ${CMAKE_BINARY_DIR}/output)
file(DOWNLOAD https://example.com/data.dat ${CMAKE_BINARY_DIR}/data.dat SHOW_PROGRESS)
file(WRITE ${CMAKE_BINARY_DIR}/version.txt "${PROJECT_VERSION}")
```

### 28. `configure_file`

**做什么的**：将输入文件复制到输出位置，并将其中的 CMake 变量引用（`@VAR@` 或 `${VAR}`）替换为实际值。常用于生成配置头文件、版本文件等。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<input>` | 输入模板文件路径 |
| `<output>` | 输出文件路径 |
| `COPYONLY` | 仅复制，不做变量替换 |
| `ESCAPE_QUOTES` | 转义引号 |
| `@ONLY` | 只替换 `@VAR@` 形式，不替换 `${VAR}`（推荐用于代码文件，避免与代码中的 `${}` 冲突） |
| `NO_SOURCE_PERMISSIONS` | 不保留源文件权限 |
| `USE_SOURCE_PERMISSIONS` | 保留源文件权限 |
| `NEWLINE_STYLE <style>` | 换行符风格：`UNIX`/`LF`、`DOS`/`WIN32`/`CRLF` |

**示例**：

`version.h.in`：

```
#pragma once
#define APP_NAME "@PROJECT_NAME@"
#define APP_VERSION "@PROJECT_VERSION@"
#define APP_BUILD_TYPE "@CMAKE_BUILD_TYPE@"
```

CMakeLists.txt：

```
configure_file(
    ${CMAKE_CURRENT_SOURCE_DIR}/version.h.in
    ${CMAKE_CURRENT_BINARY_DIR}/version.h
    @ONLY)
target_include_directories(myapp PRIVATE ${CMAKE_CURRENT_BINARY_DIR})
```

## 九、安装

### 29. `install(TARGETS)`

**做什么的**：将构建目标（可执行文件、库）安装到指定目录。同时可以导出目标信息供其他项目使用。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `TARGETS <target>...` | 要安装的目标列表 |
| `EXPORT <export-name>` | 关联到一个导出名，后续用 `install(EXPORT)` 导出 |
| `RUNTIME DESTINATION <dir>` | 可执行文件和 DLL 的安装目录 |
| `LIBRARY DESTINATION <dir>` | 动态库（非 DLL）的安装目录 |
| `ARCHIVE DESTINATION <dir>` | 静态库和 DLL 导入库的安装目录 |
| `OBJECTS DESTINATION <dir>` | 对象库的安装目录 |
| `FRAMEWORK DESTINATION <dir>` | macOS Framework 安装目录 |
| `BUNDLE DESTINATION <dir>` | macOS .app 安装目录 |
| `PUBLIC_HEADER DESTINATION <dir>` | 公开头文件安装目录 |
| `RESOURCE DESTINATION <dir>` | 资源文件安装目录 |
| `INCLUDES DESTINATION <dir>` | 头文件目录（写入导出目标的 INTERFACE_INCLUDE_DIRECTORIES） |
| `DESTINATION <dir>` | 默认安装目录（未指定类型时） |
| `PERMISSIONS <perms>...` | 文件权限 |
| `CONFIGURATIONS <config>...` | 仅在指定配置下安装 |
| `COMPONENT <component>` | 所属组件名（用于组件化安装） |
| `NAMELINK_COMPONENT <component>` | 符号链接所属组件 |
| `OPTIONAL` | 文件不存在时不报错 |
| `EXCLUDE_FROM_ALL` | 排除在默认安装之外 |
| `RUNTIME_DEPENDENCY_SET <set>` | 运行时依赖集合（3.21+） |

**示例**：

```
include(GNUInstallDirs)
install(TARGETS myapp mylib
    EXPORT MyProjectTargets
    RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR}
    LIBRARY DESTINATION ${CMAKE_INSTALL_LIBDIR}
    ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR}
    INCLUDES DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
)
```

### 30. `install(FILES) / install(DIRECTORY)`

**做什么的**：安装文件或目录。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `FILES <files>...` | 要安装的文件列表 |
| `DIRECTORY <dirs>...` | 要安装的目录列表 |
| `DESTINATION <dir>` | 安装目标目录 |
| `PERMISSIONS <perms>...` | 文件权限 |
| `DIR_PERMISSIONS <perms>...` | 目录权限（DIRECTORY 专用） |
| `FILES_MATCHING` | 目录安装时的文件匹配规则 |
| `PATTERN <pattern>` | 匹配模式（配合 FILES_MATCHING） |
| `REGEX <regex>` | 正则匹配 |
| `EXCLUDE` | 排除匹配的文件 |
| `COMPONENT <component>` | 组件名 |
| `RENAME <name>` | 重命名（仅 FILES） |
| `OPTIONAL` | 文件不存在不报错 |

**示例**：

```
install(FILES README.md LICENSE DESTINATION ${CMAKE_INSTALL_DOCDIR})

install(DIRECTORY include/ DESTINATION ${CMAKE_INSTALL_INCLUDEDIR})

install(DIRECTORY include/ DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
    FILES_MATCHING
        PATTERN "*.h"
        PATTERN "*.hpp"
        PATTERN "internal" EXCLUDE
)
```

### 31. `install(EXPORT)`

**做什么的**：将之前通过 `install(TARGETS ... EXPORT)` 关联的目标信息导出为 CMake 文件，使其他项目可以通过 `find_package` 找到并使用这些目标。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `EXPORT <export-name>` | 与 `install(TARGETS)` 中的 EXPORT 名对应 |
| `DESTINATION <dir>` | 导出文件安装目录 |
| `NAMESPACE <ns>` | 目标名前缀，如 `MyProject::` |
| `FILE <name>.cmake` | 导出文件名，默认 `<export-name>.cmake` |
| `EXPORT_LINK_INTERFACE_LIBRARIES` | 包含链接接口库（旧行为） |
| `COMPONENT <component>` | 组件名 |

**示例**：

```
install(EXPORT MyProjectTargets
    FILE MyProjectTargets.cmake
    NAMESPACE MyProject::
    DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/MyProject
)
```

### 32. `enable_testing`

**做什么的**：在当前目录及子目录启用测试功能。必须在顶层 CMakeLists.txt 调用一次，`add_test` 才会生效。

### 33. `add_test`

**做什么的**：添加一个测试用例，CTest 会运行指定命令并根据退出码判断测试是否通过（0 为通过）。

**常用测试属性**：

| 属性 | 作用 |

## 十一、自定义命令

### 35. `add_custom_command`

**做什么的**：有两种形式。形式一生成输出文件（如代码生成），当其他目标依赖该输出时自动执行；形式二在目标构建的特定阶段（构建前/链接前/构建后）执行命令。

**形式一：生成文件**

| 参数 | 作用 |
| --- | --- |
| `OUTPUT <output>...` | 命令生成的输出文件列表 |
| `COMMAND <cmd> [args...]` | 要执行的命令，可多个 |
| `MAIN_DEPENDENCY <depend>` | 主依赖文件（主要输入） |
| `DEPENDS <depend>...` | 依赖的文件或目标 |
| `BYPRODUCTS <files>...` | 副产物文件（Ninja 生成器需要） |
| `IMPLICIT_DEPENDS <lang> <file>` | 隐式依赖扫描 |
| `WORKING_DIRECTORY <dir>` | 工作目录 |
| `COMMENT <text>` | 执行前显示的注释 |
| `VERBATIM` | 正确转义参数，推荐始终加 |
| `APPEND` | 追加到已有 OUTPUT 的命令 |
| `USES_TERMINAL` | 直接使用终端 |
| `JOB_POOL <pool>` | Ninja 作业池 |
| `DEPFILE <file>` | 依赖文件（Ninja） |

**形式二：构建事件**

| 参数 | 作用 |
| --- | --- |
| `TARGET <target>` | 关联的目标 |
| `PRE_BUILD` | 目标编译前执行（仅 Visual Studio 真正支持预构建） |
| `PRE_LINK` | 编译后、链接前执行 |
| `POST_BUILD` | 目标构建完成后执行 |
| `COMMAND <cmd> [args...]` | 要执行的命令 |
| `WORKING_DIRECTORY <dir>` | 工作目录 |
| `COMMENT <text>` | 注释 |
| `VERBATIM` | 正确转义 |
| `USES_TERMINAL` | 直接使用终端 |
| `BYPRODUCTS <files>...` | 副产物 |

**示例**：

```
# 形式一：代码生成
add_custom_command(
    OUTPUT parser.cpp parser.h
    COMMAND bison -d -o parser.cpp ${CMAKE_CURRENT_SOURCE_DIR}/parser.y
    MAIN_DEPENDENCY parser.y
    DEPENDS parser.y
    COMMENT "Generating parser with bison"
    VERBATIM
)
add_executable(myapp main.cpp parser.cpp)

# 形式二：构建后复制
add_custom_command(TARGET myapp POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy
        $<TARGET_FILE:myapp>
        ${CMAKE_BINARY_DIR}/dist/
    COMMENT "Copying binary to dist directory"
    VERBATIM
)
```

## 十二、函数与宏

### 36. `function / endfunction`

**做什么的**：定义一个可复用的函数。函数有自己的作用域，变量默认不影响外部（除非 `PARENT_SCOPE`）。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<name>` | 函数名 |
| `[<arg1> ...]` | 命名参数 |
| `ARGC` | 实际参数总数（自动变量） |
| `ARGV` | 所有参数的列表（自动变量） |
| `ARGN` | 超出命名参数的额外参数列表（自动变量） |
| `ARGV0, ARGV1, ...` | 第 N 个参数（自动变量） |

**示例**：

```
function(add_gtest target)
    add_executable(${target} ${ARGN})
    target_link_libraries(${target} PRIVATE gtest_main)
    add_test(NAME ${target} COMMAND ${target})
endfunction()

# 使用
add_gtest(test_math test_math.cpp)
add_gtest(test_string test_string.cpp test_string_extra.cpp)
```

---

### 37. `macro / endmacro`

**做什么的**：定义一个宏。与函数不同，宏在调用处直接展开（类似 C 预处理器宏），没有独立作用域，变量会直接影响调用者的作用域。

**参数**：与 `function` 相同。

**函数 vs 宏的选择**：

- 优先用 `function`，因为作用域隔离更安全
- 用 `macro` 的场景：需要在调用者作用域设置变量、需要 `return()` 跳出调用者等

---

### 38. `cmake_parse_arguments`

**做什么的**：在函数/宏中解析命名参数，支持选项（无值）、单值参数、多值参数。是编写复杂 CMake 函数的标准工具。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<prefix>` | 输出变量前缀，解析结果为 `<prefix>_<KEYWORD>` |
| `<options>` | 选项列表（无值参数，出现即为 TRUE），空格分隔 |
| `<one_value_keywords>` | 单值参数列表 |
| `<multi_value_keywords>` | 多值参数列表 |
| `<args>...` | 要解析的参数，通常传 `${ARGN}` |

**输出变量**：

- `<prefix>_<OPTION>`：选项是否被指定（TRUE/FALSE）
- `<prefix>_<KEYWORD>`：单值/多值参数的值
- `<prefix>_UNPARSED_ARGUMENTS`：未被识别的参数
- `<prefix>_KEYWORDS_MISSING_VALUES`：缺少值的关键字

**示例**：

```
function(my_add_library)
    set(options STATIC SHARED INTERFACE)
    set(oneValueArgs NAME)
    set(multiValueArgs SOURCES DEPENDS)
    cmake_parse_arguments(MY
        "${options}"
        "${oneValueArgs}"
        "${multiValueArgs}"
        ${ARGN}
    )

    if(MY_STATIC)
        add_library(${MY_NAME} STATIC ${MY_SOURCES})
    elseif(MY_SHARED)
        add_library(${MY_NAME} SHARED ${MY_SOURCES})
    endif()

    if(MY_DEPENDS)
        target_link_libraries(${MY_NAME} PUBLIC ${MY_DEPENDS})
    endif()
endfunction()

# 使用
my_add_library(
    NAME mylib
    STATIC
    SOURCES src/a.cpp src/b.cpp
    DEPENDS Threads::Threads
)
```

## 十三、属性通用操作

### 39. `set_property`

**做什么的**：通用属性设置命令，可以设置全局、目录、目标、源文件、测试、缓存、安装等各种作用域的属性。比 `set_target_properties` 更通用。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `GLOBAL` | 全局作用域 |
| `DIRECTORY [dir]` | 目录作用域，默认当前目录 |
| `TARGET [target...]` | 目标作用域 |
| `SOURCE [src...]` | 源文件作用域 |
| `TEST [test...]` | 测试作用域 |
| `CACHE [var...]` | 缓存变量作用域 |
| `INSTALL [name...]` | 安装规则作用域 |
| `APPEND` | 追加到属性值列表 |
| `APPEND_STRING` | 以字符串方式追加 |
| `PROPERTY <name> [value...]` | 属性名和值 |

**示例**：

```
# 设置全局属性
set_property(GLOBAL PROPERTY USE_FOLDERS ON)

# 设置源文件属性（禁用特定文件的优化）
set_property(SOURCE slow_file.cpp PROPERTY COMPILE_FLAGS -O0)

# 设置目录属性
set_property(DIRECTORY PROPERTY COMPILE_DEFINITIONS DEBUG=1)
```

---

### 40. `get_property`

**做什么的**：通用属性读取命令，对应 `set_property`，可读取各种作用域的属性值。

**参数**：

| 参数 | 作用 |
| --- | --- |
| `<variable>` | 存储结果的变量 |
| `GLOBAL` / `DIRECTORY [dir]` / `TARGET <t>` / `SOURCE <f>` / `TEST <t>` / `CACHE <v>` / `VARIABLE` | 作用域 |
| `PROPERTY <name>` | 属性名 |
| `SET` | 返回属性是否已设置（TRUE/FALSE）而非值 |
| `DEFINED` | 返回属性是否已定义（CMake 是否知道该属性） |
| `BRIEF_DOCS` / `FULL_DOCS` | 返回属性的文档 |

**示例**：

```
get_property(LIBS TARGET myapp PROPERTY LINK_LIBRARIES)
message(STATUS "myapp links: ${LIBS}")
```

| `cmake -E echo_append <text>` | 输出文本（不换行） |
| `cmake -E env [VAR=value...] <cmd>` | 设置环境变量后执行命令 |
| `cmake -E chdir <dir> <cmd>` | 切换目录后执行命令 |
| `cmake -E touch <file>` | 创建空文件或更新时间戳 |
| `cmake -E touch_nocreate <file>` | 更新时间戳（不创建新文件） |
| `cmake -E tar cf <archive> <files>` | 创建压缩包 |
| `cmake -E tar xf <archive>` | 解压 |
| `cmake -E md5sum <file>` | 计算 MD5 |
| `cmake -E sha1sum / sha224sum / sha256sum` | 计算 SHA |
| `cmake -E compare_files <f1> <f2>` | 比较文件 |
| `cmake -E create_symlink <target> <link>` | 创建符号链接 |
| `cmake -E true / false` | 返回成功/失败 |
| `cmake -E sleep <seconds>` | 休眠 |
| `cmake -E cat <files>...` | 输出文件内容 |
| `cmake -E ls [-l] <dir>` | 列出目录 |
| `cmake -E server` | 启动服务器模式 |
| `cmake -E capabilities` | 输出 CMake 能力信息 |
| `cmake -E runtime` | 运行时相关操作（3.28+） |

**示例**：

```
add_custom_command(TARGET myapp POST_BUILD
```

## 十八、生成器表达式（Generator Expressions）

**做什么的**：在构建阶段（而非配置阶段）求值的表达式，语法为 `$<...>`。用于根据编译器、平台、配置等条件动态设置编译选项、路径等。

**常用表达式**：

| 表达式 | 作用 |
| --- | --- |
| `$<CONFIG:cfg>` | 当前配置为 cfg 时为 1 |
| `$<CONFIG>` | 当前配置名 |
| `$<CXX_COMPILER_ID:id>` | C++ 编译器 ID 匹配时为 1（GNU/Clang/MSVC/AppleClang） |
| `$<CXX_COMPILER_VERSION>` | 编译器版本 |
| `$<PLATFORM_ID:id>` | 平台 ID 匹配时为 1（Linux/Windows/Darwin） |
| `$<COMPILE_LANGUAGE:lang>` | 编译语言匹配时为 1 |
| `$<TARGET_FILE:tgt>` | 目标的完整输出文件路径 |
| `$<TARGET_FILE_NAME:tgt>` | 目标输出文件名 |
| `$<TARGET_FILE_DIR:tgt>` | 目标输出目录 |
| `$<TARGET_NAME:...>` | 目标名 |
| `$<TARGET_PROPERTY:tgt,prop>` | 目标属性值 |
| `$<IF:cond,then,else>` | 条件选择 |
| `$<AND:cond1,cond2>` | 逻辑与 |
| `$<OR:cond1,cond2>` | 逻辑或 |
| `$<NOT:cond>` | 逻辑非 |
| `$<BOOL:cond>` | 转为布尔值 |
| `$<0:>` / `$<1:value>` | 常量假/真 |
| `$<BUILD_INTERFACE:...>` | 构建时使用的值 |
| `$<INSTALL_INTERFACE:...>` | 安装时使用的值 |
| `$<JOIN:list,glue>` | 列表连接为字符串 |
| `$<REMOVE_DUPLICATES:list>` | 列表去重 |
| `$<FILTER:list,INCLUDE | EXCLUDE,regex>` |
| `$<SHELL_PATH:path>` | 转为 shell 风格路径 |
| `$<LOWER_CASE:...>` / `$<UPPER_CASE:...>` | 大小写转换 |
| `$<GENEX_EVAL:...>` | 求值嵌套的生成器表达式 |

**示例**：

```
target_compile_options(myapp PRIVATE
    # GCC/Clang 下启用警告
    $<$<CXX_COMPILER_ID:GNU,Clang,AppleClang>:-Wall -Wextra -Wpedantic>
    # MSVC 下启用警告
    $<$<CXX_COMPILER_ID:MSVC>:/W4 /permissive->
    # Debug 下禁用优化加调试信息
    $<$<CONFIG:Debug>:-g -O0>
    # Release 下优化
    $<$<CONFIG:Release>:-O3 -DNDEBUG>
)

target_include_directories(mylib PUBLIC
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
    $<INSTALL_INTERFACE:include>
)
```
