# 宏（Macro）

在 C++ 中，**宏（Macro）** 是一种由**预处理器（Preprocessor）**处理的文本替换机制。它在编译前的预处理阶段对源代码进行纯文本的替换，而**不涉及类型检查、作用域或C++的语法规则**。

理解宏的核心在于记住一句话：**宏不是C++语言的一部分，它是另一个独立的文本处理系统。**

以下是关于 C++ 宏的全面深度解析：

## 1. 宏的基本分类

- **无参宏（对象宏）**：用于定义常量和占位符。

    ```cpp
    #define PI 3.14159
    #define PATH "/usr/local/bin"
    ```

- **带参宏（函数宏）**：类似函数调用，但本质是文本展开。

    ```cpp
    #define SQUARE(x) ((x)*(x))
    #define LOG(msg) std::cout << msg << std::endl
    ```

## 2. 特殊的预定义宏

C++ 标准规定了几个编译器内置的宏，非常实用：

- `__LINE__`：当前源代码的行号（整数）。
- `__FILE__`：当前源文件的文件名（字符串）。
- `__FUNCTION__` / `__func__`：当前函数名（字符串）。
- `__DATE__`：编译日期（字符串）。
- `__TIME__`：编译时间（字符串）。
- `__cplusplus`：C++标准版本号（如 `201703L` 代表 C++17）。

## 3. 宏的核心陷阱（为什么现代C++提倡“少用宏”）

由于宏发生在编译前，它不遵守C++作用域和类型规则，容易引发难以调试的 bug：

**陷阱一：运算符优先级错误**

```cpp
#define SQUARE(x) x * x
int a = SQUARE(1 + 2); // 展开为 1 + 2 * 1 + 2 = 5，而不是 9！
// 修正：必须加括号 #define SQUARE(x) ((x)*(x))
```

**陷阱二：副作用（多次求值）**

```cpp
#define MAX(a, b) ((a) > (b) ? (a) : (b))
int x = 1, y = 2;
int z = MAX(++x, y); // 展开后：((++x) > (y) ? (++x) : (y))，x自增了两次！
```

**陷阱三：分号吞噬问题**

```cpp
#define CALL_FUNC(x) x()
// 如果在 if 语句中使用，分号会导致悬空 else，极其隐蔽。
```

**陷阱四：无作用域**
宏没有命名空间，无法被 `namespace` 包含，会污染全局命名空间。一旦 `#define` 定义，只能通过 `#undef` 取消，否则贯穿整个翻译单元。

## 4. 宏的“正确打开方式”（何时必须用）

尽管有很多缺陷，但在某些场景下，**宏是无可替代的**：

- **头文件守卫（Header Guards）**：

    ```cpp
    #ifndef MY_HEADER_H
    #define MY_HEADER_H
    // ... 代码 ...
    #endif
    ```

    （注：现代编译器推荐用 `#pragma once`，但宏守卫是标准写法）

- **条件编译（跨平台/调试模式）**：
    这是宏最强大的功能，可以剔除调试代码，不影响最终运行性能。

    ```cpp
    #ifdef _WIN32
        // Windows特定代码
    #elif __linux__
        // Linux特定代码
    #endif

    // 调试日志：在 Release 版本中自动删除
    #ifdef DEBUG_MODE
        #define DEBUG_LOG(msg) std::cerr << __FILE__ << ":" << __LINE__ << " " << msg << std::endl
    #else
        #define DEBUG_LOG(msg) // 展开为空
    #endif
    ```

- **生成错误信息和断言**：
    利用 `#`（字符串化）和 `##`（连接）操作符，可以打印出变量的名字。

    ```cpp
    #define ASSERT(expr) \
        if (!(expr)) { \
            std::cerr << "Assertion failed: " #expr << " in " << __FILE__ << std::endl; \
            std::abort(); \
        }
    // 调用 ASSERT(x > 0); 报错时会打印出 "x > 0" 这个字符串，而非值。
    ```

## 5. 现代 C++（C++11 起）的替代方案

C++ 标准委员会强烈建议：**能不用宏，就不用宏**。以下现代特性可以完美替代 90% 的宏场景：

| 宏的用途 | 现代 C++ 替代方案 | 优点 |
| :--- | :--- | :--- |
| `#define PI 3.14` | `constexpr double PI = 3.14;` | 有作用域，有类型，调试可见 |
| `#define MAX(a,b) ...` | **模板函数** `std::max<T>()` | 类型安全，无副作用求值 |
| `#define LOG(msg) ...` | **内联函数（inline）** + 模板 | 类型安全，且可通过 `std::source_location`（C++20）获取行号 |
| `#ifdef DEBUG` | **`if constexpr`**（编译期分支） | 保持语法结构完整，不会破坏代码缩进 |
| 重复代码模板 | **可变参数模板（Variadic Templates）** | 高度类型安全 |

**C++20 的最佳实践示例（替代日志宏）**：

```cpp
#include <source_location>
#include <iostream>

void log(const std::string& msg, 
         const std::source_location& loc = std::source_location::current()) {
    std::cout << loc.file_name() << ":" << loc.line() << " " << msg << std::endl;
}
// 调用 log("Hello"); 不再需要丑陋的 __FILE__ 宏了。
```

## 6. 高级技巧（慎用）

- **`#` 运算符（字符串化）**：将参数转换为字符串。`#x` -> `"x"`。
- **`##` 运算符（连接）**：将两个标记连接成一个新标记。

    ```cpp
    #define VAR(name, num) name##num
    int VAR(my_var, 1) = 10; // 展开为 int my_var1 = 10;
    ```

---

## 总结建议

1. **头文件守卫** 和 **平台/编译环境检测**（`#ifdef _WIN32`）请放心使用，这是不可替代的。
2. **定义常量** 请用 `constexpr`。
3. **定义“类似函数的计算”** 请用 `inline` 函数或 `constexpr` 函数模板。
4. **如果你必须写一个宏来处理日志并捕获文件名/行号**，请确保宏体极其简单，将所有复杂逻辑交给一个普通的 C++ 函数去处理（即宏只负责传参，不负责计算）。

**口诀**：宏是“暴力粘贴”，能看懂它，能避开坑，但在日常编码中把它当成“最后的救急工具”而非“常用武器”。
