# C++ 异步详解

C++ 的异步编程核心是**把任务放到别的执行流去跑，不阻塞当前线程**。C++11 引入了基础异步组件，C++20 增加协程（`co_await`），C++23 又扩展了一些异步工具。

>
> 区分两个概念：
>
>
> 1. **线程（thread）**：操作系统层面的执行单元。
> 2. **异步（asynchronous）**：编程模型，任务发起后不等它马上完成，可以先做别的，之后再获取结果。异步**不一定新建线程**（可以线程池、事件循环、协程）。

## 一、C++11 标准异步：`std::async`、`std::future`、`std::promise`、`std::packaged_task`

### 1. std::future / std::shared_future

`std::future` 用来**获取异步任务的返回值或者异常**，是一次性的通道：

- `.get()`：阻塞等待任务完成，取回结果；只能调用一次，调用后 future 失效。
- `.wait()`：只等待，不拿结果，阻塞。
- `.wait_for(duration)` / `.wait_until(time_point)`：带超时等待，返回状态：
  - `std::future_status::ready`：任务完成
  - `std::future_status::timeout`：超时
  - `std::future_status::deferred`：任务延迟执行（只有调用 get/wait 才跑）

`std::shared_future`：可以拷贝，多个地方同时等待同一个结果。

### 2. std::async（最常用的高层异步接口）

```
#include <iostream>
#include <future>
#include <chrono>

int heavy_work(int n) {
    std::this_thread::sleep_for(std::chrono::seconds(2));
    return n * n;
}

int main() {
    // 启动异步任务
    std::future<int> fut = std::async(std::launch::async, heavy_work, 10);

    std::cout << "主线程继续干活...\n";

    // 阻塞，直到任务完成拿到结果
    int res = fut.get();
    std::cout << "result = " << res << "\n";
    return 0;
}
```

#### launch 策略（重点）

1. `std::launch::async`：**强制新开一个线程**执行函数。
2. `std::launch::deferred`：**不新建线程**，任务延迟到 `.get()` / `.wait()` 的时候，在当前线程同步执行。
3. `std::launch::async | std::launch::deferred`（默认）：由标准库自行选择，可能开线程也可能延迟执行。

>
> ⚠️ 坑：默认模式下，你无法确定会不会新建线程。如果必须并发，一定要显式写 `std::launch::async`。

### 3. std::promise

`promise` 是**生产者端**，手动设置值/异常；`future` 是消费者端等待。适合：**在线程内部动态返回结果**。

```
#include <future>
#include <thread>

void set_value(std::promise<int> p) {
    std::this_thread::sleep_for(std::chrono::seconds(1));
    p.set_value(42); // 设置返回值
    // p.set_exception(std::make_exception_ptr(std::runtime_error("err"))); // 设置异常
}

int main() {
    std::promise<int> prom;
    std::future<int> fut = prom.get_future();

    std::thread t(set_value, std::move(prom));

    std::cout << fut.get() << std::endl;
    t.join();
    return 0;
}
```

>
> promise 只能 `set_value` 一次，多次调用会抛异常。

### 4. std::packaged_task

把一个可调用对象（函数、lambda）包装成“带 future 的任务”，可以放到线程池里保存、延迟执行。

```
#include <future>
#include <iostream>

int foo(int x) { return x + 1; }

int main() {
    std::packaged_task<int(int)> task(foo);
    std::future<int> fut = task.get_future();

    task(100); // 执行任务，可以放到别的线程执行
    std::cout << fut.get();
    return 0;
}
```

### 小结 C++11 这套关系

- `std::async`：高层封装，一键启动异步任务，返回 future
- `std::packaged_task`：包装函数，产出 future
- `std::promise`：手动写入值，产出 future
- `std::future`：等待、获取结果

缺点：

1. **粗粒度，基于线程**，每个 async(async) 都会创建 OS 线程，开销大；大量任务不能直接用。
2. `.get()` 是阻塞调用，没法写出“非阻塞回调”风格。
3. 没有原生的异步链式调用（不能 `fut.then()`，C++23 才进标准）。

## 二、回调式异步（C++11/14 常用，标准库没有内置，自己实现）

很多网络库（asio）用回调：发起异步操作，传一个回调函数，操作完成后自动调用回调。

```
// 伪代码示例
async_read(socket, buffer, [](std::error_code ec, size_t len) {
    if (!ec) {
        std::cout << "read " << len << " bytes\n";
    }
});
// 主线程继续跑，不阻塞
```

缺点：回调地狱（callback hell），多层嵌套代码可读性差。

## 三、C++20 协程（Coroutine）：现代异步方案

C++20 协程不是操作系统线程，是**用户态可挂起恢复的函数**，非常适合写异步代码，解决回调地狱。关键字：`co_await`、`co_return`、`co_yield`。

协程函数调用时，**不会立刻执行函数体**，返回一个协程句柄；遇到 `co_await` 时可以挂起函数，让出执行权；等异步事件完成后再恢复执行。

>
> C++20 只提供协程底层语法，**没有内置异步运行时**（没有默认调度器），需要自己写 awaiter，或者使用库如 libunifex、asio。

极简伪示例：

```
task<int> async_work() {
    std::cout << "开始任务\n";
    int v = co_await some_async_op(); // 挂起，等待操作完成
    co_return v + 1;
}
```

优点：

- 代码是**顺序写法**，但是执行是异步的，没有回调嵌套
- 轻量，内存开销远小于线程，可以大量并发协程
缺点：
- 底层比较复杂，需要自己实现 awaiter / promise_type
- C++标准库直到 C++23 才逐步补全异步工具

## 四、C++23 std::future::then

C++23 给 `std::future` 增加 `.then()`，支持异步链式调用：当 future 完成后自动执行回调，返回新 future，不用阻塞。

```
// C++23 伪代码
auto f = std::async(task)
    .then([](auto res){ return res * 2; })
    .then([](auto v){ std::cout << v; });
```

解决了旧 future 无法链式异步回调的痛点。

## 五、异步 vs 多线程，容易混淆的点

1. **多线程 ≠ 异步**
   - 多线程：多个线程同时跑，CPU 并行。
   - 异步：任务可以挂起，当前线程可以去处理别的任务；**单线程也可以异步**（比如事件循环：epoll/select + 回调，node.js 模型）。
2. **阻塞异步 vs 非阻塞异步**
   - `std::future.get()`：**阻塞等待**，属于异步任务，但等待的时候卡住当前线程。
   - 协程 / 回调事件循环：**非阻塞异步**，等待时线程不卡住，可以处理其他任务。

## 六、常见坑

1. `std::async` 默认策略下 deferred 延迟执行：你以为是后台跑，实际等到 get 才执行。
2. `std::future` 只能 get 一次，取完值就失效。
3. `std::promise` / `packaged_task` 如果销毁时还没设置值，会自动设置 `broken_promise` 异常。
4. 大量使用 `std::launch::async` 会创建大量 OS 线程，造成内存/内核开销暴涨，这时候要用线程池。
5. 协程：挂起时注意对象生命周期，局部变量在挂起时仍然保存在协程帧，容易踩生命周期坑。

## 七、选型建议

- 简单小任务，不想自己管理线程：C++11 `std::async` + `future`
- 需要自己管理任务队列、线程池：`std::packaged_task`
- IO密集型高并发（网络）：C++20 协程 + asio / unifex
- 需要链式异步回调：C++23 `future.then`
