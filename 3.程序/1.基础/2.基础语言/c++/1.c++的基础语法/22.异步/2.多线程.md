# C++ 多线程详解（C++11 起标准线程库）

C++11 引入了 `<thread>` 标准库，从此 C++ 有了跨平台的多线程 API，不再依赖 Windows CreateThread / pthread。

>
> 核心概念
>
>
> - **线程**：操作系统调度的最小执行单元，一个进程内可以有多个线程，共享进程内存（全局变量、堆），每个线程拥有独立栈。
> - **并发**：多个任务同时进行（单核时间片轮转，多核真正并行）。
> - **竞态条件(Race Condition)**：多个线程**同时读写共享可变数据**，没有同步保护，结果不可预测。
> - **同步原语**：用来解决竞态条件：mutex、condition_variable、atomic 等。

# 一、std::thread 基础 API

头文件：`#include <thread>`

## 1. 创建线程

```
#include <iostream>
#include <thread>

void func(int a) {
    std::cout << "thread func, a = " << a << std::endl;
}

int main() {
    // 创建线程对象，立刻启动线程
    std::thread t(func, 100);

    // 主线程等待子线程完成
    t.join();
    std::cout << "thread finished\n";
    return 0;
}
```

### 构造 std::thread 的几种形式

```
// 普通函数
std::thread t1(func, 1);

// lambda
std::thread t2([](int x){ std::cout << x; }, 2);

// 类成员函数
struct Foo {
    void bar(int x) {}
};
Foo obj;
std::thread t3(&Foo::bar, &obj, 10); // 第一个参数传对象地址
```

>
> ⚠️ 重要：`std::thread` 的参数**默认按值拷贝**；想要传引用，必须用 `std::ref` / `std::cref`

```
void f(int& x) { x++; }
int v = 10;
std::thread t(f, std::ref(v));
```

## 2. join() / detach()

**每个 thread 对象，必须调用 join() 或者 detach()，否则 thread 对象析构时程序直接 terminate！**

1. `t.join()`
   - 阻塞当前线程，直到子线程执行完毕。
   - join 之后，thread 对象不再关联底层线程（joinable() = false）。
2. `t.detach()`
   - 分离线程：底层线程独立运行，不再和 `t` 对象绑定。
   - 分离后的线程由操作系统接管，主线程退出时，detach 的线程会被强行杀死。
   - 调用 detach 后 `joinable() == false`。

```
bool joinable() const noexcept;
```

判断这个线程对象是否还关联着可 join 的原生线程。

## 3. 获取线程 id

```
std::thread::id tid = t.get_id(); // 获取线程id
std::thread::id self_tid = std::this_thread::get_id(); // 获取当前线程id
```

## 4. 线程休眠（std::this_thread）

头文件 `<thread>`

```
// 休眠一段时间
std::this_thread::sleep_for(std::chrono::seconds(2));

// 休眠到某个时间点
std::this_thread::sleep_until(std::chrono::steady_clock::now() + std::chrono::milliseconds(100));

// 让出CPU时间片，主动放弃当前时间片，交给其他线程
std::this_thread::yield();
```

## 5. std::thread 不支持拷贝

```
std::thread t1(func);
std::thread t2 = t1; // ❌ 编译报错，不能拷贝
std::thread t3 = std::move(t1); // ✅ 可以移动所有权
```

# 二、同步原语（解决多线程共享数据竞争）

## 1. std::mutex 互斥锁

头文件：`#include <mutex>`

>
> 同一时刻**只能有一个线程持有锁**。

```
std::mutex mtx;
int cnt = 0;

void add() {
    mtx.lock();       // 加锁，如果已经被占用，阻塞等待
    cnt++;
    mtx.unlock();     // 解锁
}
```

### std::lock_guard（RAII 自动解锁，推荐）

栈上对象，构造时 lock，析构时自动 unlock，**防止异常导致忘记 unlock**

```
void add() {
    std::lock_guard<std::mutex> guard(mtx);
    cnt++;
} // 离开作用域，guard析构自动unlock
```

### std::unique_lock（更灵活的 RAII 锁）

支持：延迟加锁、手动 unlock、转移锁所有权、配合条件变量使用

```
std::unique_lock<std::mutex> lk(mtx);
lk.unlock(); // 手动解锁
lk.lock();   // 再次加锁
```

### std::shared_mutex (C++17，读写锁)

- 多个线程可以**共享读锁**（同时读）
- 写锁是独占：写的时候其他读写都阻塞
适合读多写少场景

```
std::shared_mutex smtx;

void read_func() {
    std::shared_lock<std::shared_mutex> lk(smtx); // 共享读锁
}
void write_func() {
    std::unique_lock<std::shared_mutex> lk(smtx); // 独占写锁
}
```

## 2. std::condition_variable 条件变量

头文件 `<condition_variable>`

>
> 用于**线程等待某个条件成立**，配合 mutex 使用，典型：生产者消费者模型。

API：

- `cv.wait(lk, predicate)`：释放锁，阻塞等待；收到通知并且 predicate 返回 true 才唤醒。
- `cv.notify_one()`：唤醒**一个**等待的线程
- `cv.notify_all()`：唤醒**所有**等待的线程

>
> wait 存在**虚假唤醒**：线程可能被意外唤醒，所以必须带判断条件（第二个参数 predicate）。

生产者消费者完整示例：

```
#include <thread>
#include <mutex>
#include <condition_variable>
#include <queue>
#include <iostream>

std::mutex mtx;
std::condition_variable cv;
std::queue<int> q;

void producer() {
    for(int i=0; i<5; i++) {
        std::lock_guard<std::mutex> lk(mtx);
        q.push(i);
        std::cout << "produce " << i << "\n";
        cv.notify_one();
    }
}

void consumer() {
    for(int i=0; i<5; i++) {
        std::unique_lock<std::mutex> lk(mtx);
        // 等待队列非空，防止虚假唤醒
        cv.wait(lk, [](){ return !q.empty(); });
        int val = q.front();
        q.pop();
        std::cout << "consume " << val << "\n";
    }
}

int main() {
    std::thread t1(producer);
    std::thread t2(consumer);
    t1.join();
    t2.join();
    return 0;
}
```

## 3. std::atomic 原子类型（C++11）

头文件 `<atomic>`
对变量做原子操作，**不需要 mutex**，无锁并发。常见：计数器、标志位。
支持类型：`atomic<int> atomic<bool> atomic<long>`

API：

- `.store(val)`：原子写入
- `.load()`：原子读取
- `++` `--` `fetch_add` `fetch_sub` 原子加减

```
#include <atomic>
#include <thread>
#include <iostream>

std::atomic<int> cnt{0};

void add() {
    for(int i=0;i<10000;i++) {
        cnt++;
    }
}

int main() {
    std::thread t1(add);
    std::thread t2(add);
    t1.join();
    t2.join();
    std::cout << cnt << std::endl;
    return 0;
}
```

>
> 注意：`atomic` 只保证**单个操作原子**；多个原子操作组合依然不是原子。

内存序（memory_order）：`memory_order_relaxed` / `acquire` / `release` / `seq_cst`，默认 `seq_cst`（最强序，开销最大）。

## 4. std::once_flag / std::call_once

保证函数**只执行一次**，典型：懒加载单例。

```
#include <mutex>
std::once_flag flag;

void init() {
    std::cout << "init once\n";
}

void worker() {
    std::call_once(flag, init);
}
```

# 三、线程本地存储 std::thread_local

`thread_local int x;`
每个线程拥有独立一份 x，互不干扰。
生命周期：线程创建分配，线程销毁自动销毁。

```
thread_local int num = 0;
void f() {
    num++;
    std::cout << num << "\n";
}
```

# 四、和之前异步章节关联：std::future / std::promise / packaged_task

这一组是**线程间传递结果/异常**，也属于多线程配套API：

- `std::promise<T>`：生产者线程设置值/异常
- `std::future<T>`：另一个线程等待并获取结果
- `std::packaged_task<T()>`：包装函数，返回future
- `std::async`：高层封装，内部创建线程+packaged_task

>
> 这部分前面异步章节已经讲过，它们**是多线程工具，不是线程本身**。

# 五、多线程常见坑

1. **竞态条件**：共享变量读写不加锁。
2. **死锁**：多个线程互相持有对方需要的锁。
   - 避免：固定锁获取顺序；使用 `std::lock` 同时加多个锁。
3. **忘记 join/detach**：thread 对象析构直接崩溃。
4. detach 线程访问栈上局部变量：主线程退出，栈销毁，野引用。
5. 虚假唤醒：condition_variable wait 不加判断条件。
6. 原子类型误用：误以为连续多个原子操作等于事务。
7. 锁粒度太大：持有锁期间做耗时IO，并发性能极差。

死锁示例：

```
std::mutex m1, m2;
void t1_work() {
    std::lock_guard<std::mutex> lk1(m1);
    std::lock_guard<std::mutex> lk2(m2); // 拿m1等m2
}
void t2_work() {
    std::lock_guard<std::mutex> lk1(m2);
    std::lock_guard<std::mutex> lk2(m1); // 拿m2等m1，死锁
}
```

# 六、多线程 vs 异步（简单区分）

1. `std::thread`：操作系统原生线程，有独立栈，开销重；多个线程可以并行跑。
2. 异步：是模型。`std::async` 底层可以开 thread；协程是用户态轻量执行流，**不一定绑定OS线程**。

>
> 多线程是**执行载体**；异步是**任务调度模型**。多线程可以实现异步；异步不一定多线程（单线程事件循环）。
