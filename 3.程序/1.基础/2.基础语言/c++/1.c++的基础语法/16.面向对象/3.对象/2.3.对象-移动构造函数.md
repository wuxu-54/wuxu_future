# 移动构造函数

```
NexusEngine(NexusEngine&&) noexcept;
```

这是 **移动构造函数的声明**。

拆解每一段：

1. `NexusEngine(…)`：构造函数，类名和类同名，没有返回值。
2. `NexusEngine&&`：**右值引用**参数。`&&` 不是逻辑与，是类型修饰。
3. `noexcept`：表示这个函数承诺**不会抛出异常**。

---

# 基础概念：左值 / 右值

- **左值 lvalue**：有名字、能取地址的对象。

```
NexusEngine e; // e 是左值
NexusEngine e2 = e; // 调用拷贝构造
```

- **右值 rvalue**：临时对象，没有变量名，表达式产生的临时值。

```
NexusEngine{}; // 临时对象，右值
func(NexusEngine{}); // 传入临时，是右值
```

`Type&&` = 右值引用，**专门绑定到右值（临时对象）**。

>
> 移动构造函数：接收一个**同类型的右值引用**，把源对象内部的资源（堆指针、文件句柄）**抢夺过来，而不是完整拷贝**。
> 对于持有堆内存的类（比如你的PIMPL，内部有`unique_ptr`），移动是廉价的，只是拷贝几个指针，不需要深拷贝。

---

## 完整对照四种特殊成员函数

```
// 1.拷贝构造：接收 const 左值引用，复制资源
NexusEngine(const NexusEngine&);

// 2.拷贝赋值
NexusEngine& operator=(const NexusEngine&);

// 3.移动构造：接收右值引用，抢夺资源，源对象变成空壳
NexusEngine(NexusEngine&&) noexcept;

// 4.移动赋值
NexusEngine& operator=(NexusEngine&&) noexcept;
```

### noexcept 的作用

`noexcept`：告诉编译器，这个函数**保证不会抛异常**。

- 容器（`std::vector`）在扩容的时候：
  - 如果移动构造是`noexcept`，vector会**调用移动，把旧对象资源搬走**；
  - 如果没有写`noexcept`，vector**宁可回退去调用拷贝构造**（怕移动中途抛异常，资源损坏无法回滚）。

>
> 对于PIMPL类，移动只是转移`unique_ptr`指针，完全不会抛异常，所以一定要加上`noexcept`。

# 结合你的PIMPL场景举例

你的 `NexusEngine` 使用PIMPL模式，内部只有一个 `std::unique_ptr<NexusEngineImpl> m_impl;`。

头文件（只做声明）

```
class NexusEngine
{
public:
    NexusEngine();
    ~NexusEngine();

    // 移动构造声明
    NexusEngine(NexusEngine&&) noexcept;
    NexusEngine& operator=(NexusEngine&&) noexcept;

    // 禁用拷贝，unique_ptr不支持拷贝
    NexusEngine(const NexusEngine&) = delete;
    NexusEngine& operator=(const NexusEngine&) = delete;
private:
    std::unique_ptr<NexusEngineImpl> m_impl;
};
```

cpp实现：

```
// Impl定义放在cpp内部
class NexusEngineImpl {
    // ...
};

NexusEngine::NexusEngine()
    : m_impl(std::make_unique<NexusEngineImpl>())
{}

NexusEngine::~NexusEngine() = default;

// 移动构造：直接转移unique_ptr，仅仅拷贝指针，不拷贝底层数据
NexusEngine::NexusEngine(NexusEngine&& other) noexcept
    : m_impl(std::move(other.m_impl))
{
    // other.m_impl 被置为空
}

// 移动赋值
NexusEngine& NexusEngine::operator=(NexusEngine&& other) noexcept
{
    m_impl = std::move(other.m_impl);
    return *this;
}
```

### 使用场景

```
NexusEngine CreateEngine()
{
    NexusEngine eng;
    return eng; // 返回临时对象，触发移动构造（RVO返回值优化会直接消除）
}

int main()
{
    NexusEngine e1 = CreateEngine(); // 移动构造
    NexusEngine e2(std::move(e1));   // std::move把左值强转成右值，触发移动构造
    // e1 变成空壳，不要再使用 e1！
}
```

>
> `std::move`：不是移动，只是**强制把左值转换成右值引用**，真正移动发生在移动构造函数内部。

# 高频坑点

1. **`T&&` 只有在函数参数、变量声明的时候才是右值引用；模板中会发生引用折叠，是万能引用，和这里不一样。**
这里是类的构造函数参数，确定是右值引用。
2. 如果你类里面有`unique_ptr`，编译器**自动删除拷贝构造**，但是会生成默认移动构造。
但是PIMPL场景下，如果析构函数在头文件声明，实现写在cpp，编译器**无法在头文件生成默认移动构造**，所以你必须手动**声明移动构造、移动赋值，然后在cpp里写`=default`或者手写实现**。

>
> 这是PIMPL+unique_ptr非常经典的坑！
> 因为头文件看不到Impl完整定义，编译器无法生成默认的移动/析构，必须自己声明，实现放到cpp。

3. 如果移动构造不写`noexcept`，`std::vector<NexusEngine>`扩容时不会使用移动，会尝试拷贝，但是拷贝已经`=delete`，直接编译报错。

---

## 一句话总结

`NexusEngine(NexusEngine&&) noexcept;`

>
> **移动构造函数声明：接收本类的右值引用，用来抢夺临时对象内部资源，避免昂贵的深拷贝；noexcept承诺不抛异常。多用于PIMPL、持有堆资源的类。**

补充区分：

- `const NexusEngine&`：const左值引用，可以绑定左值、右值，用于拷贝构造；
- `NexusEngine&&`：右值引用，**只绑定右值**，用于移动构造。
