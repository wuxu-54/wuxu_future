# 独占所有权 vs 共享所有权

C++智能指针核心两种所有权模型：

1. **独占所有权：`std::unique_ptr`** —— 同一时间，**有且只能有一个智能指针拥有这个堆对象**
2. **共享所有权：`std::shared_ptr`** —— **多个智能指针可以同时拥有同一个堆对象**，引用计数管理生命周期

>
> 所有权含义：**谁负责最终delete释放堆上对象**。

头文件：`<memory>`

---

## 1. std::unique_ptr 独占所有权

### 核心规则

- 资源**只能属于一个unique_ptr**，**禁止拷贝**，只支持移动 `std::move`
- 没有引用计数，没有控制块；开销几乎等于裸指针
- 当unique_ptr析构，立刻释放对象；reset也会立刻释放
- 不能复制：复制语义被删除，编译直接报错

```
#include <memory>

int main() {
    std::unique_ptr<int> u1 = std::make_unique<int>(100);

    // std::unique_ptr<int> u2 = u1;  // ❌ 编译报错！禁止拷贝，独占不能分享

    std::unique_ptr<int> u2 = std::move(u1); // ✅ 移动：所有权转移给u2
    // u1 现在变成空(nullptr)，不再管理资源

    *u2 = 200;
    return 0;
}
```

对象释放时机：

>
> `u2`出作用域析构 → 直接delete堆内存。**没有计数，马上释放**。

### unique_ptr特点总结

✅ 优点

1. **零额外开销**，只有一个指针大小；没有控制块、没有原子引用计数，性能接近裸指针
2. 没有循环引用问题（根本没有共享）
3. 支持自定义删除器

❌ 缺点

1. 不能多方同时持有同一个对象；只能move转移所有权
2. 不能复制传参，想要传递对象必须move，原指针失效

>
> 最佳实践：**默认优先用unique_ptr**，大部分场景不需要共享。

## 2. std::shared_ptr 共享所有权

### 核心规则

- 多个`shared_ptr`可以指向同一个堆对象；**引用计数（强计数use_count）记录有多少个持有者**
- 可以自由拷贝、赋值；拷贝一次，强引用计数+1
- 只有当**所有shared_ptr全部销毁（use_count == 0）**，才会析构业务对象；
内存释放还要看weak_ptr弱计数（`make_shared`的坑）

```
#include <memory>
int main() {
    auto s1 = std::make_shared<int>(100);
    auto s2 = s1; // ✅ 允许拷贝！共享所有权 use_count = 2
    auto s3 = s1; // use_count =3

    s1.reset(); // 计数 2；对象不会释放，s2 s3还持有
    s2.reset(); // 计数 1
    s3.reset(); // use_count=0，释放堆内存
    return 0;
}
```

底层：
`shared_ptr`除了保存对象裸指针，还会指向**控制块**：

- `use_count`：强引用计数（shared_ptr数量，原子变量）
- `weak_count`：弱引用计数（weak_ptr数量）

>
> 拷贝shared_ptr会原子递增use_count；析构原子递减。**原子操作会带来微小性能开销**。

✅优点

- 多处可以同时持有同一个对象，不用手动管理谁该释放
❌缺点

1. 额外控制块内存开销，原子计数带来性能损耗
2. **循环引用会造成内存泄漏**（两个对象互相保存shared_ptr），需要`weak_ptr`打破
3. make_shared场景下，weak_ptr存活会延迟内存释放

# 对比总表

| 项目 | 独占所有权 unique_ptr | 共享所有权 shared_ptr |
| --- | --- | --- |
| 所有权数量 | 同一时刻**只能一个持有者** | **多个持有者同时拥有** |
| 拷贝 | ❌禁止拷贝；只允许std::move移动 | ✅可以自由拷贝赋值 |
| 释放时机 | unique_ptr析构/reset，**立刻释放** | 所有shared_ptr全部销毁才释放 |
| 底层机制 | 裸指针，无控制块 | 对象指针 + 控制块(原子引用计数) |
| 性能开销 | 几乎为0，和裸指针接近 | 有原子计数、控制块，开销更大 |
| 循环引用 | 不存在该问题 | 会泄漏，需要weak_ptr |
| 创建方式 | `std::make_unique<T>()` | `std::make_shared<T>()` |
| 能否转为对方 | `std::move(unique_ptr)`可以构造shared_ptr | 不能转回unique_ptr |

### 转换小知识点

```
std::unique_ptr<int> u = std::make_unique<int>(10);
// unique_ptr move 转为 shared_ptr，允许
std::shared_ptr<int> s = std::move(u);
// ❌ shared_ptr 不能变回 unique_ptr，做不到
```

## 3. weak_ptr是什么？（配套shared_ptr）

`std::weak_ptr`：**不拥有所有权**，只是“旁观/观察者”。

- 拷贝weak_ptr**不会增加use_count强计数**，只增加弱计数
- 不会阻止对象销毁；对象销毁后lock()得到空shared_ptr
- 专门解决shared_ptr循环引用

```
auto s = std::make_shared<int>(100);
std::weak_ptr<int> w = s; // 观察，不增加use_count

if(auto temp = w.lock()){
    // 对象还活着，拿到临时shared_ptr使用
}
```

>
> weak_ptr没有独占/共享所有权，属于**无所有权的观察者**。

## 4. 怎么选型（工作写代码标准思路）

1. **优先选独占所有权 unique_ptr / make_unique**

>
> 大部分场景：对象逻辑上就该只有一个主人，不需要多处共享。性能最好，无循环引用坑。
> 要传递对象就`std::move`转移所有权。

2. 什么时候才用共享所有权 `shared_ptr/make_shared`？

- **确实需要多处、多个模块同时持有同一个对象，且谁也说不准谁最后销毁**
比如：缓存、事件回调、多线程任务对象，多方都要用，无法确定生命周期谁先结束。

>
> 不要上来就无脑用shared_ptr，它是有成本的。

## 5.通俗大白话比喻

- **独占所有权 unique_ptr：一把钥匙，同一时间只能一个人拿钥匙。要给别人，自己必须把钥匙交出去（move），自己手里就没钥匙了；钥匙销毁，门直接拆掉。**
- **共享所有权 shared_ptr：多把相同钥匙，每个人都能复制一把钥匙。只有**全部钥匙都丢掉**，门才拆掉。**
- **weak_ptr：没有钥匙，只是趴在窗户外面看；不能开门；房子什么时候拆和观察者无关。**

## 面试高频问题

>
> Q：unique_ptr为什么不能拷贝？
> A：因为独占所有权语义，如果允许拷贝，就会出现两个unique_ptr管理同一个对象，出作用域各自执行delete，造成**double free双重释放崩溃**，所以直接把拷贝构造/拷贝赋值函数delete禁用。

>
> Q：shared_ptr拷贝的时候发生了什么？
> A：拷贝构造shared_ptr，复制对象指针，复制控制块指针；原子操作把use_count++。

>
> Q：循环引用如何产生？
> A：A持有shared_ptr，B持有shared_ptr；两个对象use_count都至少为1；离开作用域计数只能减到1，永远不会为0，内存泄漏，用weak_ptr打破。
