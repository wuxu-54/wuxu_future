# 代码

```
workers_.emplace_back(&Dispatcher::worker_loop, this);
```

`workers_`：`std::vector<std::thread>`，存放线程对象。
`emplace_back`：vector 的成员函数，**在vector尾部原地构造对象**，这里构造的是 `std::thread`。

## 1. std::thread 的构造函数原型

```
template< class Function, class... Args >
explicit thread( Function&& f, Args&&... args );
```

创建一个线程，线程执行函数是 `f`，args 是传给f的参数。

## 2. 参数拆解：`&Dispatcher::worker_loop, this`

- `&Dispatcher::worker_loop`：**成员函数指针**，Dispatcher类里面的成员函数 `worker_loop`。> 
> 成员函数不是普通函数，它隐含第一个参数是类对象指针 `this`。
- `this`：当前 Dispatcher 对象的指针，作为成员函数的隐式this参数。

等价含义：**启动新线程，执行 `this->worker_loop()`**

> 
> 类成员函数指针调用语法：`(obj.*mem_func_ptr)()`
> std::thread内部就会帮你完成这个调用：`(this->*&Dispatcher::worker_loop)();`

## 3. emplace_back 在这里做了什么

`emplace_back(a,b,c)` 会把参数 `a,b,c` 转发给容器元素（`std::thread`）的构造函数，**原地构造thread对象，没有临时对象拷贝**。

对比 push_back 写法：

```
// push_back 需要先构造临时thread，再移动进vector
workers_.push_back(std::thread(&Dispatcher::worker_loop, this));
// emplace_back：直接在vector内存里构造thread，少一次临时对象
workers_.emplace_back(&Dispatcher::worker_loop, this);
```

✅ emplace_back 更高效，推荐。

## 4. worker_loop 长这样（配套）

```
class Dispatcher {
private:
    std::vector<std::thread> workers_;
    void worker_loop() {
        // 线程循环：wait任务队列，取任务执行
        while(true) {
            // ...
        }
    }
};
```

> 
> ⚠️注意：`worker_loop` 是**非静态成员函数**，所以必须传入类实例指针`this`。
> 如果是static静态成员函数，就不需要this。

## 5. 完整线程创建逻辑

```
workers_.reserve(num_threads);
for(int i=0; i<num_threads; i++)
{
    // 创建一个thread，绑定当前对象的worker_loop，放到workers_ vector尾部
    workers_.emplace_back(&Dispatcher::worker_loop, this);
}
```

循环执行完，就有 `num_threads` 个子线程，全部跑 `this->worker_loop()`，也就是线程池的工作循环。

## 6. 高频坑点

### 坑1：对象生命周期问题

新线程持有`this`裸指针。**如果Dispatcher对象提前析构，子线程还在运行，访问this就是野指针，UB崩溃！**
线程池析构的时候，必须先通知所有worker退出，join等待所有线程结束，再销毁成员变量。

线程池析构标准写法：

```
~Dispatcher()
{
    // 1. 设置退出标记
    stop_flag_ = true;
    // 2. 唤醒全部等待线程
    cv_.notify_all();
    // 3. join等待每一个工作线程结束
    for(auto& t : workers_)
    {
        if(t.joinable())
            t.join();
    }
}
```

### 坑2：joinable

`std::thread`对象析构时，如果线程还没join（joinable=true），程序直接terminate崩溃。
所以线程池析构必须逐个join，不能放任thread对象销毁。

## 7. 两种写法对比

```
// 写法1：成员函数指针 + this（你现在的代码）
workers_.emplace_back(&Dispatcher::worker_loop, this);

// 写法2：lambda捕获this，更直观，工程里也很常用
workers_.emplace_back([this](){ worker_loop(); });
```

效果完全一样。

- 成员函数指针写法：简洁一点
- lambda写法：可读性更好，还可以捕获更多变量

## 一句话总结

`workers_.emplace_back(&Dispatcher::worker_loop, this);`
在vector尾部原地构造一个`std::thread`，新线程执行当前Dispatcher实例的成员函数`worker_loop()`，也就是启动线程池的一个工作线程。
