# LeetCode 算法分类解题技巧大全（列表版）

## 一、数组篇

### 核心技巧

1. 遍历优化：优先使用「for-each」遍历（无索引需求），需索引时用普通for循环，避免冗余计算（如提前缓存数组长度 `n = nums.length`）。
2. 原地修改：用「快慢指针」处理去重、删除元素（如 LeetCode 26. 删除有序数组中的重复项），避免额外空间开销。
3. 区间操作：  
   - 前缀和：快速计算任意子数组和（预处理 `preSum[i] = preSum[i-1] + nums[i-1]`，区间 `[l,r]` 和为 `preSum[r+1]-preSum[l]`）。  
   - 差分数组：高效处理多次区间增减（如 LeetCode 370. 区间加法），构造 `diff` 数组后，仅需修改区间两端，最后还原为原数组。
4. 双指针联动：左右指针（如二分查找、两数之和）、同向指针（如滑动窗口），减少嵌套循环（时间复杂度从 O(n²) 降为 O(n)）。

### 常见场景

- 去重/删除元素：有序数组用快慢指针，无序数组可结合哈希表。
- 子数组问题：优先考虑前缀和、滑动窗口（连续子数组）、动态规划（非连续子序列）。
- 极值问题：遍历一次维护 max/min（如 LeetCode 53. 最大子数组和），或排序后取首尾（需有序场景）。

### 注意事项

- 边界处理：避免数组越界（如 `i < n` 而非 `i <= n`），空数组/单元素数组单独判断。
- 空间优化：能原地修改则不新建数组（如 LeetCode 283. 移动零），大规模数据需注意内存限制。

## 二、链表篇

### 核心技巧

1. 遍历方式：  
   - 迭代：用 `cur` 指针遍历，避免修改原头节点（如 `ListNode cur = head`）。  
   - 递归：适合链表反转、深度处理（如 LeetCode 206. 反转链表的递归实现）。
2. 虚拟头节点（Dummy Node）：处理头节点可能被删除的场景（如 LeetCode 203. 移除链表元素），统一节点操作逻辑（无需单独判断头节点）。
3. 核心操作实现：  
   - 反转：迭代用「prev/cur/next」三指针，递归用「子问题反转后连接」。  
   - 环检测：快慢指针（快指针走2步，慢指针走1步，相遇则有环；再找环入口需二次遍历）。  
   - 相交判断：先计算两链表长度差，让长链表指针先走差值步，再同步遍历找相同节点。
4. 辅助工具：用栈存储节点（如 LeetCode 234. 回文链表，后序遍历对比）、哈希表存节点地址（快速判断节点是否存在）。

### 常见场景

- 节点增删：虚拟头节点+指针定位目标节点前驱。
- 链表长度/中间节点：快慢指针（慢指针走1步，快指针走2步，快指针到尾时慢指针在中间）。
- 链表拼接/分割：记录分割点前后指针，避免断链（如 LeetCode 86. 分隔链表）。

### 注意事项

- 空指针处理：访问 `cur.next` 前先判断 `cur != null`，避免 NPE。
- 引用断开：删除节点后需断开前驱节点与目标节点的连接（如 `prev.next = cur.next`），防止内存泄漏。

## 三、哈希表篇

### 核心技巧

1. 核心作用：**O(1) 快速查找/计数/映射**，解决“键-值”对应问题。
2. 常见结构选择：  
   - HashMap：无序，允许 key 为 null（仅1个），value 可 null；适合普通映射场景（如两数之和的“值-索引”映射）。  
   - HashSet：无序，元素唯一；适合去重、存在性判断（如 LeetCode 187. 重复的DNA序列）。  
   - LinkedHashMap：有序（插入顺序/访问顺序）；适合需要保留顺序的场景（如 LRU 缓存的简易实现）。  
   - TreeMap：按键排序（自然排序/自定义比较器）；适合需要有序遍历键的场景（如区间查找）。
3. 优化点：  
   - 哈希冲突：默认链表+红黑树（JDK 8+），无需手动处理，但需合理设置初始容量（避免频繁扩容）。  
   - key 选择：优先用不可变类型（如 Integer、String），避免自定义对象未重写 `hashCode()` 和 `equals()`。

### 常见场景

- 计数问题：统计元素出现次数（如 LeetCode 387. 字符串中的第一个唯一字符）。
- 映射转换：如“字符-频率”“数组值-索引”“旧节点-新节点”（链表复制）。
- 两集合关系：交集、并集、差集（用 HashSet 快速计算）。

### 注意事项

- null 处理：HashMap 允许 key 为 null，但 HashSet 元素可为 null（仅1个），TreeMap 不允许 key 为 null。
- 时间复杂度：理想 O(1)，哈希冲突严重时退化为 O(n)，需避免 key 的哈希值分布不均。

## 四、栈与队列篇

### （一）栈（先进后出，LIFO）

#### 核心技巧

1. 单调栈：维护栈内元素“递增”或“递减”顺序，解决“下一个更大/更小元素”问题（如 LeetCode 496. 下一个更大元素 I），时间复杂度 O(n)。
2. 应用场景适配：  
   - 括号匹配：左括号入栈，右括号出栈匹配（如 LeetCode 20. 有效的括号），栈空/不匹配则无效。  
   - 表达式求值：中缀转后缀（栈存运算符）、后缀求值（栈存数字），处理优先级（如 LeetCode 227. 基本计算器 II）。  
   - 逆序处理：栈存元素后弹出，实现逆序（如链表逆序打印）。
3. 辅助栈：用额外栈存储中间状态（如 LeetCode 155. 最小栈，用辅助栈存当前最小值）。

### （二）队列（先进先出，FIFO）

#### 核心技巧

1. 单调队列：维护队列内元素“递增”或“递减”顺序，解决“滑动窗口最值”问题（如 LeetCode 239. 滑动窗口最大值），时间复杂度 O(n)。
2. 应用场景适配：  
   - BFS 遍历：队列存待访问节点（如树的层序遍历、图的最短路径），避免递归栈溢出。  
   - 任务调度：按顺序处理任务（如 LeetCode 622. 设计循环队列）。
3. 栈与队列转换：  
   - 用2个栈实现队列：入队栈存元素，出队时将入队栈元素倒入出队栈（为空时倒）。  
   - 用2个队列实现栈：入队后将其他队列元素依次入队，保证队首为栈顶。

### 注意事项

- 栈：避免访问空栈的 `pop()`/`peek()`，需先判断 `isEmpty()`。  
- 队列：循环队列需注意“空”和“满”的判断（如用计数器或预留一个空位）。

## 五、字符串篇

### 核心技巧

1. 基础操作优化：  
   - 拼接：避免频繁用 `+`（Java 中 String 不可变，会生成新对象），用 `StringBuilder`（单线程）或 `StringBuffer`（多线程）。  
   - 截取：`substring(start, end)` 注意区间是 [start, end)，避免越界。  
   - 字符遍历：用 `charAt(i)` 或转换为 `char[]` 数组（遍历更快，适合频繁访问）。
2. 匹配算法：  
   - KMP 算法：预处理模式串生成 `next` 数组，解决字符串匹配的“部分匹配”问题，时间复杂度 O(m+n)（m 为主串长度，n 为模式串长度）。  
   - Rabin-Karp 算法：用哈希值快速比较子串，适合多模式匹配。  
   - Manacher 算法：O(n) 解决最长回文子串问题（避免中心扩展的 O(n²) 复杂度）。
3. 双指针：  
   - 回文判断：左右指针从两端向中间靠拢，对比字符（如 LeetCode 125. 验证回文串）。  
   - 子串问题：滑动窗口（如 LeetCode 3. 无重复字符的最长子串）。

### 常见场景

- 回文问题：中心扩展（奇数/偶数长度）、Manacher 算法、双指针。  
- 子串/子序列：滑动窗口（连续子串）、动态规划（非连续子序列，如 LeetCode 1143. 最长公共子序列）。  
- 字符计数：哈希表（统计频率）、数组（字符集较小时，如小写字母用 `int[26]`）。

### 注意事项

- 字符编码：区分大小写（如 `A` 和 `a`）、处理非字母数字字符（如回文判断中跳过符号）。  
- 空字符串：单独判断 `s.isEmpty()`，避免后续操作报错。

## 六、数与位篇

### 核心技巧

1. 基础运算优化：  
   - 取模：`(a + b) % mod` 避免溢出（需先加括号，再取模）；负数取模需调整为正数（如 `(x % mod + mod) % mod`）。  
   - 整除：判断奇偶用 `x & 1`（1 为奇，0 为偶），代替 `x % 2`；除以 2 用 `x >> 1`，效率更高。
2. 快速幂/快速乘：  
   - 快速幂：O(logn) 计算 `a^b mod mod`（如 LeetCode 50. Pow(x, n)），通过二进制拆分 b，减少乘法次数。  
   - 快速乘：O(logn) 计算 `a*b`（避免溢出，如 LeetCode 43. 字符串相乘），用加法+位运算模拟乘法。
3. 数位操作：  
   - 分离数位：用 `x % 10` 取末位，`x /= 10` 删末位（如 LeetCode 7. 整数反转）。  
   - 进制转换：十进制转二进制用 `x & 1` + 右移，二进制转十进制用累加+左移。

### 常见场景

- 素数判断：试除法（优化到 sqrt(n)）、埃氏筛（批量找素数，如 LeetCode 204. 计数质数）。  
- 因子分解：试除法（分解为质因子）、 Pollard-Rho 算法（大整数分解，LeetCode 难题场景）。  
- 大数处理：用字符串/数组存储（如 LeetCode 415. 字符串相加），避免整数溢出。

### 注意事项

- 溢出处理：Java 中 int 范围是 [-2³¹, 2³¹-1]，超过需用 long 或 BigInteger；计算前预判溢出（如 `x > Integer.MAX_VALUE / 2` 时，`x*2` 溢出）。  
- 负数处理：整数反转、数位分离时，先将负数转为正数（或单独处理符号位）。

## 七、递归篇

### 核心技巧

1. 三要素明确：  
   - 终止条件：避免无限递归（如树遍历到 null 节点返回）。  
   - 递归公式：将原问题拆解为子问题（如 `f(n) = f(n-1) + f(n-2)` 斐波那契）。  
   - 参数设计：传递子问题所需的最小信息（如树遍历传递当前节点，无需传递整个树）。
2. 优化手段：  
   - 记忆化递归：用哈希表/数组存储已计算的子问题结果（如 LeetCode 322. 零钱兑换，避免重复计算）。  
   - 尾递归优化：递归调用在函数最后一步（部分语言如 Scala 支持，Java 暂不支持，需手动转为迭代）。
3. 递归类型：  
   - 分治型：拆分多个子问题（如归并排序、快速排序）。  
   - 回溯型：尝试-回溯-再尝试（如排列组合、迷宫问题）。

### 常见场景

- 树/图遍历：前中后序遍历（递归天然适配树的层级结构）、DFS（深度优先搜索）。  
- 排列组合：如 LeetCode 46. 全排列，递归选择当前元素，剩余元素递归处理。  
- 问题分解：如 LeetCode 104. 二叉树的最大深度，当前深度=1+max(左子树深度, 右子树深度)。

### 注意事项

- 栈溢出风险：递归深度过大（如 n=1e4 的斐波那契）会触发 StackOverflowError，需转为迭代或增加栈空间。  
- 重复计算：无记忆化时，子问题重复计算（如斐波那契 `f(5)` 需计算 `f(4)` 和 `f(3)`，`f(4)` 又需 `f(3)`），必须用记忆化优化。

## 八、分治篇

### 核心技巧

1. 三步流程：  
   - 分解（Divide）：将原问题拆分为多个独立的子问题（子问题与原问题结构一致，规模更小）。  
   - 解决（Conquer）：递归求解每个子问题（子问题足够小时直接求解，如数组长度为1时返回）。  
   - 合并（Combine）：将子问题的解合并为原问题的解（分治的核心，如归并排序的合并步骤）。
2. 子问题划分原则：  
   - 均衡划分：如归并排序将数组分为左右两半，避免子问题规模差距过大（否则时间复杂度退化）。  
   - 独立性：子问题之间无依赖，可并行求解（如快速排序的左右分区）。

### 常见场景

- 排序算法：归并排序（合并有序子数组）、快速排序（分区后递归排序）。  
- 数组查找：如 LeetCode 4. 寻找两个正序数组的中位数，分治缩小查找范围。  
- 矩阵问题：如 LeetCode 240. 搜索二维矩阵 II，分治排除无效区域。  
- 大规模数据处理：如统计海量数据中的逆序对（归并排序过程中计数）。

### 注意事项

- 合并逻辑复杂度：合并步骤的时间复杂度决定整体复杂度（如归并排序合并为 O(n)，整体 O(nlogn)）。  
- 空间开销：部分分治算法需额外空间（如归并排序需 O(n) 临时数组），需权衡空间与时间。

## 九、贪心篇

### 核心技巧

1. 核心原则：**局部最优 → 全局最优**，需满足两个条件：  
   - 贪心选择性质：每一步的局部最优选择能导向全局最优。  
   - 最优子结构：全局最优解包含子问题的最优解。
2. 常见贪心策略：  
   - 排序后贪心：先按某一维度排序（如区间问题按起始/结束位置排序），再依次选择最优（如 LeetCode 435. 无重叠区间，按结束位置排序后选最早结束的）。  
   - 优先队列辅助：用堆维护当前最优解（如 LeetCode 621. 任务调度，优先选择剩余次数最多的任务）。  
   - 局部取舍：如 LeetCode 122. 买卖股票的最佳时机 II，只要当天价格高于前一天，就卖出获利（局部最优累加）。

### 常见场景

- 区间问题：区间选点、区间合并、无重叠区间（排序+贪心选择）。  
- 资源分配：如任务调度、 Huffman 编码（优先处理高频元素）。  
- 路径问题：Dijkstra 算法（单源最短路径，每次选当前距离最近的节点）。  
- 数值问题：如 LeetCode 322. 零钱兑换（贪心仅适用于特定硬币系统，如美元硬币，需验证正确性）。

### 注意事项

- 策略正确性验证：贪心策略易“短视”，需严格证明（如反证法），避免错误（如硬币系统 [1,3,4] 找 6，贪心选 4+1+1=6，最优为 3+3=6）。  
- 与动态规划区分：若无法证明贪心性质，需用动态规划（如零钱兑换通用解法为 DP）。

## 十、排序算法篇

### 核心技巧

1. 算法特性与适用场景：  

   | 排序算法 | 时间复杂度（平均） | 空间复杂度 | 稳定性 | 适用场景 |
   |----------|--------------------|------------|--------|----------|
   | 冒泡排序 | O(n²)              | O(1)       | 稳定   | 小规模数据、近乎有序数据 |
   | 插入排序 | O(n²)              | O(1)       | 稳定   | 小规模数据、近乎有序数据 |
   | 选择排序 | O(n²)              | O(1)       | 不稳定 | 小规模数据、对稳定性无要求 |
   | 归并排序 | O(nlogn)           | O(n)       | 稳定   | 大规模数据、需稳定性 |
   | 快速排序 | O(nlogn)           | O(logn)    | 不稳定 | 大规模数据、平均情况最优 |
   | 堆排序   | O(nlogn)           | O(1)       | 不稳定 | TopK 问题、内存受限场景 |
   | 计数排序 | O(n+k)             | O(n+k)     | 稳定   | 数据范围小（k 小，如年龄、分数） |
   | 桶排序   | O(n+k)             | O(n+k)     | 稳定   | 数据分布均匀（如区间 [0,1) 的小数） |
   | 基数排序 | O(d(n+k))          | O(n+k)     | 稳定   | 多位数、字符串（按位排序） |

2. 自定义排序：重写比较器（如 Java 的 `Comparator`），注意排序规则（升序/降序、多维度排序）。  
3. 排序后联动：排序后结合双指针（如两数之和）、二分查找（如有序数组找目标值）、贪心（如区间问题）。

### 常见场景

- 预处理步骤：将无序数组转为有序，降低后续操作复杂度（如 LeetCode 15. 三数之和，排序后用双指针）。  
- TopK 问题：堆排序（O(nlogK)）、快速选择（O(n) 平均，LeetCode 215. 数组中的第K个最大元素）。  
- 去重：排序后相邻元素对比（如 LeetCode 26. 删除有序数组中的重复项）。

### 注意事项

- 稳定性需求：若需保留相同元素的原始顺序（如按成绩排序后保留同班同学的录入顺序），选择稳定排序（归并、计数、桶、基数）。  
- 数据规模：小规模数据（n<100）用 O(n²) 算法即可，大规模数据（n>1e4）必须用 O(nlogn) 或更优算法。

## 十一、树与二叉树篇

### 核心技巧

1. 树的类型与特性：  
   - 二叉搜索树（BST）：左子树所有节点 < 根节点 < 右子树所有节点，中序遍历为有序序列（可用于快速查找、排序）。  
   - 平衡二叉树（AVL）：左右子树高度差 ≤1，保证 O(logn) 操作复杂度（LeetCode 中多作为背景，无需手动实现平衡）。  
   - 完全二叉树：除最后一层外，每一层节点数满，最后一层左对齐（可用数组存储，父节点 i 的左子节点 2i+1，右子节点 2i+2）。
2. 遍历方式：  
   - 深度优先（DFS）：  
     - 递归：前序（根→左→右）、中序（左→根→右）、后序（左→右→根），代码简洁。  
     - 迭代：用栈模拟递归（前序：根入栈，弹出后右左入栈；中序：左链入栈，弹出后右链入栈；后序：用辅助栈或标记法）。  
   - 广度优先（BFS）：用队列实现层序遍历（按层访问，如 LeetCode 102. 二叉树的层序遍历）。
3. 辅助工具：  
   - 哈希表：存储节点的父节点（如 LeetCode 236. 二叉树的最近公共祖先，先记录父节点再找路径）。  
   - 栈/队列：迭代遍历的核心容器。

### 常见场景

- 路径问题：如 LeetCode 112. 路径总和（递归判断当前路径和）、LeetCode 124. 二叉树中的最大路径和（后序遍历计算子树贡献）。  
- 子树问题：如 LeetCode 572. 另一棵树的子树（递归对比当前节点+左子树+右子树）。  
- 树的构造/转换：如 LeetCode 105. 从前序与中序遍历序列构造二叉树（前序找根，中序分左右子树）、二叉树转链表（前序遍历+指针修改）。

### 注意事项

- 空树处理：递归时先判断 `root == null`，避免 NPE。  
- 迭代遍历细节：栈/队列的入队顺序（如前序遍历需先右后左，保证左子树先处理）、标记法（区分节点是否已访问，用于后序遍历）。

## 十二、动态规划篇

### 核心技巧

1. 四步流程：  
   - 定义 DP 状态：明确 `dp[i]` 或 `dp[i][j]` 代表的含义（如 `dp[i]` 为“前 i 个元素的最优解”），状态定义是 DP 的核心。  
   - 推导转移方程：根据子问题与原问题的关系，写出 `dp[i]` 如何由 `dp[i-1]`、`dp[i-2]` 等推导（如 LeetCode 70. 爬楼梯，`dp[i] = dp[i-1] + dp[i-2]`）。  
   - 初始化：确定 base case（如 `dp[0] = 1`、`dp[1] = 1`），避免后续计算出错。  
   - 计算顺序：按依赖关系确定遍历顺序（如 `dp[i]` 依赖 `dp[i-1]` 则从左到右遍历，`dp[i][j]` 依赖 `dp[i-1][j]` 和 `dp[i][j-1]` 则按行/列遍历）。
2. 优化手段：  
   - 空间压缩：若 `dp[i]` 仅依赖前 1~2 个状态，用变量代替数组（如爬楼梯用 `a` 和 `b` 代替 `dp` 数组，空间从 O(n) 降为 O(1)）。  
   - 滚动数组：二维 DP 可压缩为一维（如 0-1 背包问题，`dp[j]` 从后向前遍历，避免覆盖未使用的 `dp[j-weight[i]]`）。
3. DP 类型：  
   - 线性 DP：如爬楼梯、最长递增子序列（LIS）。  
   - 区间 DP：如最长回文子串（`dp[i][j]` 为“区间 [i,j] 是否为回文”）。  
   - 背包 DP：0-1 背包（物品选/不选）、完全背包（物品可多选）、多重背包（物品有数量限制）。  
   - 状态压缩 DP：如 LeetCode 52. N 皇后 II，用位掩码表示皇后位置，减少状态维度。

### 常见场景

- 子序列/子串问题：LIS（最长递增子序列）、LCS（最长公共子序列）、最长回文子串。  
- 背包问题：如 LeetCode 416. 分割等和子集（0-1 背包变体，判断能否选子集和为总和一半）。  
- 路径计数：如 LeetCode 62. 不同路径（`dp[i][j]` 为“到 (i,j) 的路径数”）。  
- 状态转移：如 LeetCode 198. 打家劫舍（`dp[i]` 为“前 i 间房的最大金额”，依赖 `dp[i-1]` 和 `dp[i-2]+nums[i]`）。

### 注意事项

- 状态定义准确性：错误的状态定义会导致转移方程无法推导（如 LIS 中 `dp[i]` 必须定义为“以第 i 个元素结尾的最长递增子序列长度”，而非“前 i 个元素的最长长度”）。  
- 边界条件：初始化需覆盖所有 base case（如二维 DP 的第一行、第一列），避免遗漏。

## 十三、图篇

### 核心技巧

1. 图的表示：  
   - 邻接矩阵：用二维数组 `graph[i][j]` 表示节点 i 到 j 的边（有权值则存权值，无则存 0/∞）；适合稠密图，查询边是否存在 O(1)，但空间 O(n²)。  
   - 邻接表：用 `List<List<Integer>>` 或 `Map<Integer, List<Integer>>` 表示，每个节点对应一个列表，存储其邻接节点；适合稀疏图，空间 O(n+m)（n 为节点数，m 为边数）。
2. 核心算法：  
   - 遍历算法：  
     - DFS（深度优先搜索）：用栈/递归实现，适合找路径、环检测（如 LeetCode 797. 所有可能的路径）。  
     - BFS（广度优先搜索）：用队列实现，适合找最短路径（无权图）、层序遍历（如 LeetCode 127. 单词接龙）。  
   - 最短路径：  
     - Dijkstra 算法：单源最短路径，适用于非负权图，用优先队列维护当前最短路径（如 LeetCode 743. 网络延迟时间）。  
     - Floyd-Warshall 算法：多源最短路径，用动态规划实现，时间 O(n³)，适合小规模图。  
     - Bellman-Ford 算法：单源最短路径，可处理负权边，能检测负权环（如 LeetCode 787. K 站中转内最便宜的航班）。  
   - 连通性与环检测：  
     - 并查集（Union-Find）：高效判断节点是否连通、合并连通分量（如 LeetCode 684. 冗余连接，找环的边）。  
     - Tarjan 算法：找强连通分量（有向图）、割点/割边（无向图）。  
   - 拓扑排序：处理有向无环图（DAG），输出节点的线性顺序（如 LeetCode 207. 课程表，判断是否存在拓扑序），用 Kahn 算法（入度表+队列）或 DFS 实现。

### 常见场景

- 路径问题：所有路径（DFS）、最短路径（BFS/Dijkstra）、路径计数（DP+图遍历）。  
- 环检测：有向图（拓扑排序判断是否存在环）、无向图（DFS 标记父节点，避免误判父节点为环）。  
- 连通性问题：岛屿数量（DFS/BFS/并查集，如 LeetCode 200. 岛屿数量）、网络连通分量（并查集）。  
- 拓扑排序：任务依赖（如课程安排、任务调度）。

### 注意事项

- visited 数组：遍历图时必须标记已访问节点，避免重复访问（尤其是有环图）。  
- 权值处理：负权边不能用 Dijkstra 算法，需用 Bellman-Ford 或 SPFA（Bellman-Ford 优化）。  
- 节点编号：若节点编号不连续（如从 1 开始或非整数），用邻接表更灵活，避免邻接矩阵空间浪费。

## 十四、滑动窗口专题

### 核心技巧

1. 窗口类型与框架：  
   - 固定窗口：窗口大小固定（如 LeetCode 438. 找到字符串中所有字母异位词），步骤：  
     1. 初始化窗口（左=0，右=窗口大小-1），计算初始窗口内数据。  
     2. 右指针右移，左指针同步右移，更新窗口内数据，判断是否满足条件。  
   - 可变窗口：窗口大小动态调整（如 LeetCode 3. 无重复字符的最长子串），步骤：  
     1. 初始化左=0，右=0，遍历右指针（扩大窗口）。  
     2. 当窗口内数据不满足条件时，左指针右移（缩小窗口）。  
     3. 记录每次满足条件的窗口状态（如最大/最小长度）。
2. 窗口内数据维护：  
   - 计数：用哈希表（如 `Map<Character, Integer>` 统计字符频率）或数组（字符集较小时，如 `int[26]`）。  
   - 最值：用单调队列（如 LeetCode 239. 滑动窗口最大值，维护递减队列，队首为当前最大值）。  
   - 合法性判断：用计数器（如 `valid` 变量记录满足条件的字符数量，避免每次遍历窗口判断）。

### 常见场景

- 子数组/子串问题：  
  - 固定长度：如“长度为 k 的子数组最大和”。  
  - 满足条件：如“无重复字符的最长子串”“和大于等于 target 的最短子数组”（LeetCode 209）。  
- 字符串匹配：如“找到所有字母异位词”“最小覆盖子串”（LeetCode 76，可变窗口+哈希表）。

### 注意事项

- 窗口收缩条件：明确“何时需要缩小窗口”（如可变窗口中出现重复字符、窗口和超过目标值），避免收缩过度或不足。  
- 边界处理：右指针遍历到数组/字符串末尾时，需判断是否还有有效窗口（如固定窗口最后一个窗口需处理）。  
- 时间复杂度：均为 O(n)（每个元素入窗、出窗各一次），避免在窗口内嵌套循环（否则退化为 O(n²)）。

## 十五、二分查找专题

### 核心技巧

1. 区间定义与框架：  
   - 左闭右闭区间 `[left, right]`（推荐，逻辑清晰）：  
     1. 初始化 `left=0`，`right=n-1`（n 为数组长度）。  
     2. 循环条件 `while(left <= right)`（区间不为空）。  
     3. 计算 `mid = left + (right - left) / 2`（避免 `left+right` 溢出）。  
     4. 调整区间：  
        - 目标值 `target < nums[mid]`：`right = mid - 1`（mid 不可能是答案，排除）。  
        - 目标值 `target > nums[mid]`：`left = mid + 1`（同理排除 mid）。  
        - 目标值 `target == nums[mid]`：找到答案（可返回，或继续找边界）。  
   - 左闭右开区间 `[left, right)`：  
     1. 初始化 `left=0`，`right=n`。  
     2. 循环条件 `while(left < right)`（区间不为空）。  
     3. 调整区间：`target < nums[mid]` 时 `right=mid`，`target > nums[mid]` 时 `left=mid+1`。
2. 查找类型：  
   - 存在性查找：判断 target 是否在数组中（找到返回索引，否则返回 -1）。  
   - 左边界查找：找第一个 ≥ target 的元素（如 LeetCode 35. 搜索插入位置），找到 `target == nums[mid]` 后，不返回，继续缩小右边界（`right=mid-1`）。  
   - 右边界查找：找最后一个 ≤ target 的元素，找到 `target == nums[mid]` 后，继续缩小左边界（`left=mid+1`）。

### 常见场景

- 有序数组查找：直接应用二分（如 LeetCode 704. 二分查找）。  
- 旋转数组查找：如 LeetCode 33. 搜索旋转排序数组，先判断 mid 所在的半区是否有序，再缩小查找范围。  
- 单调函数求解：如“找到满足 f(x) ≥ target 的最小 x”（如 LeetCode 69. x 的平方根，f(x)=x²）。  
- 资源分配：如“最小能力分配”（LeetCode 1011. 在 D 天内送达包裹的能力，二分能力范围）。

### 注意事项

- 溢出避免：计算 mid 用 `left + (right - left)/2`，而非 `(left + right)/2`（当 left 和 right 均为大整数时，后者会溢出）。  
- 区间一致性：全程保持区间定义一致（如左闭右闭就一直用 `left <= right` 和 `right=mid-1`），避免逻辑混乱。  
- 边界判断：查找左/右边界时，循环结束后需判断 left/right 是否越界（如左边界查找后，left 可能等于 n，需返回 -1）。

## 十六、双指针专题

### 核心技巧

1. 指针类型与应用：  
   - 同向双指针（快慢指针）：  
     - 快指针 `fast` 先行，慢指针 `slow` 后行，快指针遍历数组，慢指针维护目标状态（如去重、筛选）。  
     - 应用：数组去重（LeetCode 26）、移除元素（LeetCode 27）、链表环检测（LeetCode 141）、找到倒数第 k 个节点（快指针先走 k 步）。  
   - 相向双指针（左右指针）：  
     - 左指针 `left` 从起点，右指针 `right` 从终点，向中间靠拢，根据条件调整指针位置。  
     - 应用：两数之和（有序数组，LeetCode 167）、三数之和（排序+左右指针，LeetCode 15）、回文判断（LeetCode 125）、反转数组（LeetCode 344）。  
   - 分离双指针：  
     - 两个指针分别遍历两个数组，按条件合并（如归并排序的合并步骤、两个有序数组的交集，LeetCode 349）。
2. 指针移动条件：  
   - 同向：快指针每次移动1步，慢指针在“满足条件”时移动（如去重时，`nums[fast] != nums[slow]` 则慢指针移动）。  
   - 相向：根据目标调整（如两数之和，和小于 target 则左指针右移，和大于则右指针左移）。

### 常见场景

- 数组操作：去重、移除元素、反转、筛选（如 LeetCode 283. 移动零，快指针找非零元素，慢指针放非零元素）。  
- 求和问题：两数之和（有序）、三数之和、四数之和（排序+多层双指针，LeetCode 18）。  
- 链表操作：环检测、倒数节点、链表相交（LeetCode 160，分离双指针遍历两个链表）。

### 注意事项

- 越界处理：相向指针需判断 `left < right`，同向指针需判断 `fast < n`（n 为数组长度）。  
- 排序前提：部分相向指针问题需先排序（如三数之和，否则无法按和调整指针）。  
- 重复元素处理：如三数之和，需跳过重复的 `nums[left]` 和 `nums[right]`，避免重复答案（如 `while(left < right && nums[left] == nums[left+1]) left++`）。

## 十七、前缀和专题

### 核心技巧

1. 前缀和定义与构建：  
   - 一维前缀和：对于数组 `nums`，前缀和数组 `preSum` 满足 `preSum[0] = 0`，`preSum[i] = preSum[i-1] + nums[i-1]`（`preSum[i]` 为前 i 个元素的和，即 `nums[0..i-1]` 的和）。  
     - 区间和计算：子数组 `nums[l..r]`（0-based）的和 = `preSum[r+1] - preSum[l]`。  
   - 二维前缀和：对于矩阵 `matrix`（m 行 n 列），前缀和矩阵 `preSum`（m+1 行 n+1 列）满足：  
     - `preSum[0][*] = 0`，`preSum[*][0] = 0`。  
     - `preSum[i][j] = matrix[i-1][j-1] + preSum[i-1][j] + preSum[i][j-1] - preSum[i-1][j-1]`（容斥原理，避免重复加左上角区域）。  
     - 子矩阵和计算：左上角 (x1,y1)、右下角 (x2,y2) 的子矩阵和 = `preSum[x2+1][y2+1] - preSum[x1][y2+1] - preSum[x2+1][y1] + preSum[x1][y1]`。
2. 核心应用：  
   - 快速计算区间和/子矩阵和，避免多次遍历（时间复杂度从 O(n) 降为 O(1)）。  
   - 结合哈希表：解决“子数组和等于 target”问题（LeetCode 560），用哈希表存储 `preSum` 出现的次数，`preSum[i] - target` 存在则累加次数。  
   - 结合二分查找：解决“子数组和大于等于 target 的最短长度”（LeetCode 209，前缀和有序时用二分）。

### 常见场景

- 一维问题：子数组和、子数组平均、子数组奇偶性（前缀和模 2）。  
- 二维问题：子矩阵和（如 LeetCode 304. 二维区域和检索 - 矩阵不可变）、最大子矩阵和（前缀和+暴力枚举，LeetCode 85）。  
- 计数问题：如“和为 K 的子数组个数”（LeetCode 560）、“连续的子数组和”（LeetCode 523，前缀和模 k 相等）。

### 注意事项

- 前缀和数组初始化：一维前缀和 `preSum` 长度为 `n+1`，二维为 `(m+1) x (n+1)`，避免边界判断（如 `preSum[0] = 0` 处理 `l=0` 的情况）。  
- 哈希表初始值：解决“子数组和等于 target”时，需初始化为 `preSum[0] = 1`（对应子数组从 0 开始的情况）。  
- 数据类型：前缀和可能很大（如 `nums` 元素为正，n=1e5，每个元素 1e4，前缀和达 1e9），需用 long 类型存储（避免 int 溢出）。

## 十八、位运算专题

### 核心技巧

1. 常用位运算符与作用：  

   | 运算符 | 作用 | 示例 |
   |--------|------|------|
   | &（与） | 1. 判断奇偶（x & 1 == 1 为奇）；2. 清除最后一位 1（x & (x-1)）；3. 取指定位（x & mask） | 6（110）& 3（011）= 2（010） |
   | \|（或） | 1. 置指定位为 1（x \| mask）；2. 合并二进制位 | 6（110）\| 3（011）= 7（111） |
   | ^（异或） | 1. 交换两数（a = a^b; b = a^b; a = a^b）；2. 去重（相同数异或为 0）；3. 翻转指定位 | 6（110）^ 3（011）= 5（101） |
   | ~（非） | 按位取反（注意符号位，Java 中为补码） | ~6（000...0110）= -7（111...1001） |
   | <<（左移） | 乘以 2^k（x << k = x * 2^k），效率高于乘法 | 6（110）<< 1 = 12（1100） |
   | >>（右移） | 除以 2^k（正数高位补 0，负数补 1） | 6（110）>> 1 = 3（011） |
   | >>>（无符号右移） | 除以 2^k（高位补 0，适用于正数） | -6 >>> 1 = 2147483645（正数） |

2. 核心技巧：  
   - 位掩码（Mask）：用特定二进制数提取/修改指定位（如 `mask = 1 << k` 提取第 k 位）。  
   - 清除最后一位 1：`x & (x-1)`（如 LeetCode 191. 位1的个数，循环清除并计数）。  
   - 判断是否为 2 的幂：`x > 0 && (x & (x-1)) == 0`（2 的幂二进制只有一个 1）。  
   - 找到最后一位 1：`x & -x`（补码特性，如 x=6（110），-x=...11111010，x&-x=2（10））。

### 常见场景

- 位计数：统计二进制中 1 的个数（LeetCode 191）、计算汉明距离（两数异或后统计 1 的个数，LeetCode 461）。  
- 状态压缩：用二进制位表示状态（如 LeetCode 52. N 皇后 II，用 3 个整数表示列、左对角线、右对角线的占用状态）。  
- 数值运算：快速乘（`a * b = (a << k) + ...`）、快速幂（用位运算拆分指数）、整数反转（用位运算处理符号和溢出）。  
- 集合操作：用二进制位表示集合（如子集问题，LeetCode 78. 子集，每个二进制数对应一个子集）。

### 注意事项

- 符号位处理：Java 中 int 为 32 位，最高位为符号位（0 正，1 负），右移时负数高位补 1，需注意结果正确性（如 `-1 >> 1` 仍为 -1）。  
- 溢出处理：位运算可能导致溢出（如 `1 << 31` 超出 int 范围），需用 long 类型接收（如 `(long)1 << 31`）。  
- 运算符优先级：位运算符优先级低于算术运算符和关系运算符，需加括号（如 `(x & 1) == 1`，而非 `x & 1 == 1`）。
