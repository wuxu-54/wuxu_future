# 剪枝（Pruning）算法详解

## 一、剪枝的核心概念

剪枝是**搜索与优化算法中的关键优化手段**，核心目标是在暴力搜索（如回溯、递归、深度优先搜索DFS）过程中，**主动舍弃“不可能得到最优解”或“明显无效”的分支路径**，从而减少不必要的计算量，降低时间复杂度（通常从指数级O(2ⁿ)、O(n!)优化到更可控的级别）。

简单来说，剪枝就像“走迷宫时提前避开死胡同”——不需要走到路的尽头，就能判断这条路径无法到达终点，直接折返去尝试其他路径，从而节省时间。

剪枝的本质是**牺牲少量判断成本，换取大量无效计算的省略**，但必须满足一个前提：**不遗漏任何有效解**（即不能误剪“可能得到正确答案”的分支）。

## 二、剪枝的核心思想与关键要素

### 1. 核心思想

- **无效分支识别**：通过某种“判断条件”，提前识别出当前分支“无论后续如何选择，都无法满足问题要求（或无法超越当前最优解）”。
- **及时终止分支**：一旦识别出无效分支，立即终止该分支的后续搜索（如回溯中直接`return`），回到上一层继续尝试其他路径。

### 2. 关键要素

- **剪枝判断条件**：剪枝的核心，需精准、高效（判断逻辑不能太复杂，否则“剪枝成本”超过“节省的计算成本”）。
- **剪枝时机**：越早剪枝效果越好（比如在递归/回溯的“选择当前元素”后立即判断，避免进入更深层的无效递归）。
- **正确性保障**：判断条件必须严格——仅舍弃“100%无效”的分支，绝不能剪掉“可能包含正确解”的分支。

## 三、剪枝的常见分类（按策略划分）

根据剪枝的判断逻辑，可分为以下几类，每类均有明确的适用场景和典型案例：

### 1. 可行性剪枝（Feasibility Pruning）

#### 核心逻辑

- 若当前分支的选择**已违反问题的基本约束条件**（如“数值超过上限”“位置冲突”），则后续无论如何选择都无法得到合法解，直接剪枝。
- 本质：“当前状态已非法，无需继续”。

#### 适用场景

- 存在明确约束条件的问题（如N皇后、数独、背包问题、路径规划）。

#### 典型案例：N皇后问题（LeetCode 51）

- 问题约束：任意两个皇后不能在同一行、同一列、同一对角线。
- 剪枝逻辑：
  1. 递归尝试在第`row`行的第`col`列放置皇后。
  2. 检查当前`col`列是否已有皇后（用数组`colUsed`标记）。
  3. 检查当前左上→右下对角线（`row - col`为固定值，用数组`diag1`标记）是否已有皇后。
  4. 检查当前右上→左下对角线（`row + col`为固定值，用数组`diag2`标记）是否已有皇后。
  5. 若任意一项冲突，直接跳过当前`col`列（剪枝），无需递归到下一行。

#### 代码片段（剪枝部分）

```java
// colUsed[col]：第col列是否有皇后；diag1[row-col]：左上对角线；diag2[row+col]：右下对角线
private void backtrack(int n, int row, boolean[] colUsed, boolean[] diag1, boolean[] diag2, List<List<String>> result) {
    if (row == n) { // 递归终止：所有行都放好皇后
        result.add(generateBoard(n));
        return;
    }
    for (int col = 0; col < n; col++) {
        // 可行性剪枝：若当前列/对角线已有皇后，直接跳过（剪枝当前分支）
        if (colUsed[col] || diag1[row - col + n] || diag2[row + col]) {
            continue; // 剪枝：不进入下一层递归
        }
        // 选择：放置皇后
        colUsed[col] = true;
        diag1[row - col + n] = true;
        diag2[row + col] = true;
        // 递归：处理下一行
        backtrack(n, row + 1, colUsed, diag1, diag2, result);
        // 回溯：撤销选择
        colUsed[col] = false;
        diag1[row - col + n] = false;
        diag2[row + col] = false;
    }
}
```

### 2. 最优性剪枝（Optimality Pruning）

#### 核心逻辑

- 若当前分支的“已获得的收益/代价”**已不可能超越当前已知的最优解**，则后续无论如何选择都无法更新最优解，直接剪枝。
- 本质：“当前状态再好，也比不过已有最优解，无需继续”。
- 前提：需提前维护一个“当前最优解”（如最大和、最小代价），并在搜索过程中动态更新。

#### 适用场景

- 求最优解的问题（如最大子集和、旅行商问题TSP、最小路径和、剪绳子问题）。

#### 典型案例：0-1背包问题（求最大价值）

- 问题背景：有`n`个物品，每个物品有重量`w[i]`和价值`v[i]`，背包容量为`C`，选若干物品放入背包，求最大价值。
- 暴力搜索：枚举所有子集，计算总重量≤C的子集的最大价值，时间复杂度O(2ⁿ)。
- 最优性剪枝逻辑：
  1. 提前计算“剩余物品的最大价值之和”（预排序后用后缀和数组`remainMaxVal`存储，`remainMaxVal[i]`表示第`i`到`n-1`个物品的最大价值和）。
  2. 递归过程中，记录当前已选物品的总重量`currW`和总价值`currV`，以及当前处理到的物品索引`index`。
  3. 若`currV + remainMaxVal[index] ≤ 当前最优价值maxVal`：即使把剩余所有物品都选上，总价值也超不过`maxVal`，直接剪枝。

#### 代码片段（剪枝部分）

```java
private int maxVal = 0; // 当前最优解：最大价值
private int[] w; // 物品重量
private int[] v; // 物品价值
private int[] remainMaxVal; // 后缀最大价值和：remainMaxVal[i] = v[i] + ... + v[n-1]

// currW：当前总重量；currV：当前总价值；index：当前处理的物品索引；C：背包容量
private void backtrack(int currW, int currV, int index, int C) {
    if (index == w.length) { // 递归终止：所有物品处理完
        if (currV > maxVal) {
            maxVal = currV; // 更新最优解
        }
        return;
    }
    // 最优性剪枝：当前价值 + 剩余物品最大价值 ≤ 已知最优解，剪枝
    if (currV + remainMaxVal[index] <= maxVal) {
        return; // 无需继续搜索当前分支
    }
    // 分支1：不选当前物品index
    backtrack(currW, currV, index + 1, C);
    // 分支2：选当前物品index（先做可行性剪枝：重量不超过容量）
    if (currW + w[index] <= C) {
        backtrack(currW + w[index], currV + v[index], index + 1, C);
    }
}
```

### 3. 记忆化剪枝（Memoization Pruning）

#### 核心逻辑

- 若当前分支的“子问题”**已被计算过**（且结果已存储），则直接复用之前的结果，无需重新计算，本质是“避免重复计算重叠子问题”。
- 与动态规划（DP）的关系：记忆化剪枝是“递归+缓存”，是DP的递归实现形式，本质也是一种剪枝（剪去“重复计算的子问题分支”）。

#### 适用场景

- 存在大量重叠子问题的问题（如斐波那契数列、爬楼梯、最长递增子序列LIS、矩阵路径和）。

#### 典型案例：斐波那契数列（求第n项）

- 暴力递归：`fib(n) = fib(n-1) + fib(n-2)`，时间复杂度O(2ⁿ)（大量重复计算，如`fib(5)`需计算`fib(4)`和`fib(3)`，`fib(4)`又需计算`fib(3)`）。
- 记忆化剪枝逻辑：
  1. 用哈希表/数组`memo`存储已计算的`fib(k)`结果（`memo[k]`表示第k项的值）。
  2. 递归前先检查`memo[k]`是否存在：若存在，直接返回结果；若不存在，计算后存入`memo`。

#### 代码片段（剪枝部分）

```java
private int[] memo; // 记忆化缓存：memo[n] = fib(n)

public int fib(int n) {
    if (n <= 1) return n;
    memo = new int[n + 1];
    Arrays.fill(memo, -1); // 初始化：-1表示未计算
    memo[0] = 0;
    memo[1] = 1;
    return dfs(n);
}

private int dfs(int k) {
    if (memo[k] != -1) { // 记忆化剪枝：子问题已计算，直接返回
        return memo[k];
    }
    // 计算子问题并缓存结果
    memo[k] = dfs(k - 1) + dfs(k - 2);
    return memo[k];
}
```

### 4. 顺序剪枝（Order Pruning）

#### 核心逻辑

- 通过**调整搜索顺序**（如将“更可能产生有效解”或“更可能剪枝”的分支放在前面），提前触发剪枝，减少后续无效分支的搜索。
- 本质：“先试大概率有效的路径，尽早找到最优解或排除无效方向”。

#### 适用场景

- 搜索顺序不影响结果正确性，但影响剪枝效率的问题（如子集和、组合总和、旅行商问题）。

#### 典型案例：组合总和II（LeetCode 40，去重+剪枝）

- 问题约束：给定数组（含重复元素）和目标值`target`，找出所有不重复的组合，使组合和为`target`（每个元素仅用一次）。
- 顺序剪枝逻辑：
  1. 先对数组**排序**：将相同元素放在一起，便于去重（跳过重复元素），同时让“大元素”在前（若当前元素已超过`target`，后续元素更大，可直接剪枝）。
  2. 递归过程中，若当前元素`nums[i] > target - currSum`（`currSum`为当前组合和）：由于数组有序，后续元素≥`nums[i]`，加入后总和必超`target`，直接剪枝。
  3. 若`i > startIndex && nums[i] == nums[i-1]`（`startIndex`为当前递归的起始索引）：跳过重复元素，避免生成重复组合（本质是剪去“重复选择的分支”）。

#### 代码片段（剪枝部分）

```java
private void backtrack(int[] nums, int target, int startIndex, int currSum, List<Integer> path, List<List<Integer>> result) {
    if (currSum == target) { // 找到合法组合
        result.add(new ArrayList<>(path));
        return;
    }
    for (int i = startIndex; i < nums.length; i++) {
        // 顺序剪枝1：当前元素太大，后续元素更大，总和必超target，剪枝
        if (currSum + nums[i] > target) {
            break; // 数组有序，后续i+1、i+2...都更大，直接跳出循环
        }
        // 顺序剪枝2：跳过重复元素，避免重复组合（同一层递归中，相同元素只选一次）
        if (i > startIndex && nums[i] == nums[i - 1]) {
            continue;
        }
        // 选择：加入当前元素
        path.add(nums[i]);
        currSum += nums[i];
        // 递归：下一层从i+1开始（元素仅用一次）
        backtrack(nums, target, i + 1, currSum, path, result);
        // 回溯：撤销选择
        path.remove(path.size() - 1);
        currSum -= nums[i];
    }
}
```

### 5. 其他常见剪枝类型

| 剪枝类型       | 核心逻辑                                                                 | 适用场景                          |
|----------------|--------------------------------------------------------------------------|-----------------------------------|
| 重复状态剪枝   | 若当前分支的“状态”（如位置、已选集合、剩余资源）与之前某分支完全一致，直接剪枝（避免重复搜索同一状态） | 状态可表示的问题（如BFS、DFS）    |
| 冗余分支剪枝   | 若当前分支与另一分支“等价”（如选择A再选B，与选择B再选A效果相同），仅保留一条分支 | 组合问题（不考虑顺序）            |
| 边界剪枝       | 若当前分支的“参数”（如索引、重量）超出问题边界（如索引≥n、重量>C），直接剪枝 | 所有带参数约束的递归问题          |

## 四、剪枝的关键原则

1. **正确性优先**：剪枝不能“误杀”有效分支（即不能剪掉可能包含正确解或最优解的路径），否则会导致结果错误。  
   - 验证方法：可先关闭剪枝运行（暴力搜索），对比剪枝后的结果是否一致，确保剪枝逻辑无错。

2. **及时性原则**：剪枝越早，效果越好（在递归/搜索的“浅层”剪枝，可避免深层大量无效计算）。  
   - 例：N皇后问题中，在“放置当前皇后”后立即判断冲突（浅层剪枝），比递归到最后一行才发现冲突（深层剪枝）效率高得多。

3. **高效性原则**：剪枝的“判断成本”需远低于“节省的计算成本”。  
   - 反例：若剪枝判断需要遍历整个数组（O(n)成本），而节省的计算仅为O(1)，则剪枝反而会降低效率。

4. **简洁性原则**：剪枝逻辑需简洁清晰，避免复杂的条件判断（降低代码复杂度，减少bug）。

## 五、剪枝的典型应用场景总结

| 算法/问题类型       | 常用剪枝策略                  | 典型LeetCode题目                |
|---------------------|-------------------------------|---------------------------------|
| 回溯法（Backtracking）| 可行性剪枝、最优性剪枝、顺序剪枝 | N皇后（51）、组合总和II（40）、子集II（90） |
| 深度优先搜索（DFS）  | 记忆化剪枝、重复状态剪枝      | 斐波那契数列（509）、矩阵中的最长递增路径（329） |
| 广度优先搜索（BFS）  | 重复状态剪枝、边界剪枝        | 单词接龙（127）、打开转盘锁（752） |
| 动态规划（DP）       | 记忆化剪枝（递归DP）          | 最长公共子序列（1143）、编辑距离（72） |
| 暴力搜索优化        | 所有剪枝策略均适用            | 0-1背包、旅行商问题             |

## 六、总结

剪枝是“以小换大”的优化思想——通过少量的判断逻辑，省去大量无效的计算路径，是解决“暴力搜索超时”问题的核心手段。掌握剪枝的关键在于：

1. 理解不同剪枝策略的适用场景（如可行性剪枝对应约束条件，最优性剪枝对应最优解问题）；
2. 能在具体问题中识别“无效分支”，设计精准的剪枝判断条件；
3. 遵循“正确性优先、及时性优先”的原则，确保剪枝有效且不引入错误。

在LeetCode中，中等/困难难度的回溯、DFS类题目（如N皇后、组合总和、子集问题）几乎都需要剪枝优化，否则会因时间复杂度太高而超时。因此，剪枝是算法进阶的必备技能之一。
