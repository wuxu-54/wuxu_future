## 6. 语言特性陷阱与最佳实践 (Pitfalls & Tips)

### 🐍 Python

* **优势**：代码最短，内置 `sorted`, `set`, `dict`, `heapq` 极其好用。
* **陷阱**：列表切片 `lst[:]` 是浅拷贝；整数除法 [//](file:///Users/admin/AndroidStudioProjects/wx/wuxu/github/wuxu_future/1.生活/健康/1.心血管快走锻炼时间计划.md) 向下取整（负数时注意）；全局变量在函数内修改需 `global`。

### ☕ Java

* **优势**：类型安全，`HashMap` 和 `ArrayList` 性能稳定。
* **陷阱**：`==` 比较的是引用，内容比较用 `.equals()`；`String` 不可变；`Arrays.sort()` 对基本类型使用双轴快排，对对象使用 TimSort。

### ⚡ C++

* **优势**：速度最快，STL 强大 (`algorithm`, `unordered_map`)。
* **陷阱**：`vector` 扩容可能失效迭代器；`map` 是红黑树（有序），`unordered_map` 是哈希表（无序）；注意 `int` 溢出，多用 `long long`。

### 🟨 JavaScript / TypeScript

* **优势**：前端必备，`Map` 和 `Set` 兼容性好。
* **陷阱**：`+` 运算符可能进行字符串拼接；`sort()` 默认按字符串 Unicode 排序（需传入比较函数 `(a,b)=>a-b`）；浮点数精度问题。

### 🦀 Rust

* **优势**：内存安全，零成本抽象。
* **陷阱**：所有权机制导致刷题时代码冗长（频繁 `.clone()` 或 `&`借用）；索引访问 `vec[i]` 越界会 Panic，建议用 `get()`；没有原生的 `PriorityQueue`（需用 `BinaryHeap` 并取反模拟最小堆）。

### 🐹 Go

* **优势**：语法简单，并发强。
* **陷阱**：没有泛型前版本需写重复代码；`map` 未初始化时为 `nil`，写入会 Panic，需用 `make`；`slice` 是引用类型，修改会影响底层数组。

### 🟣 Kotlin

* **优势**：空安全，扩展函数丰富 (`list.map`, `filter`)。
* **陷阱**：`val` 是不可变引用，`var` 是可变引用；集合默认不可变，需用 `mutableListOf`。

### 🍎 Swift

* **优势**：语法现代，安全性高。
* **陷阱**：可选类型 `Optional` 处理繁琐（需 `?` 或 `!`）；`String` 索引不是整数，需用 `index(after:)` 等方法，刷题时建议转为 `[Character]`。

## 💡 如何使用此表？

1. **选定主语言**：建议在 **Python** (快速原型) 和 **Java/C++** (面试标准) 中选择一门作为主力。
2. **制作闪卡 (Anki)**：将容易混淆的 API（如 Java 的 `substring` vs C++ 的 `substr`）制成闪卡，利用碎片时间记忆。
3. **模板化**：在你的 IDE 或 LeetCode 编辑器中保存常用模板（如 Java 的 `HashMap` 初始化，C++ 的 `include` 头文件）。
4. **查阅而非死记**：初期允许查阅此表，随着刷题量增加（约 50-100 题后），高频 API 会形成肌肉记忆。
