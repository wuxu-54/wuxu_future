# Kotlin DSL (KTS) 替代 Groovy 配置 Gradle 完整指南

## 一、整体结构对比

### 1.1 文件后缀变化

| Groovy | Kotlin DSL | 说明 |
|--------|-----------|------|
| `build.gradle` | `build.gradle.kts` | 模块级 / 项目级构建脚本 |
| `settings.gradle` | `settings.gradle.kts` | 项目设置文件 |
| `gradle.properties` | `gradle.properties` | 属性文件不变 |
| `*.gradle` (如 `config.gradle`) | `*.gradle.kts` | 自定义脚本文件 |

### 1.2 典型 Android 项目结构

```
MyApp/
├── settings.gradle.kts          ← 根设置文件
├── build.gradle.kts             ← 根构建文件
├── gradle.properties            ← 全局属性
├── gradle/
│   └── libs.versions.toml       ← 版本目录（推荐）
└── app/
    └── build.gradle.kts         ← 模块构建文件
```

## 二、核心 API 用法详解

### 2.1 `settings.gradle.kts` — 项目设置

**Groovy 写法：**

```groovy
include ':app', ':core'
rootProject.name = "MyApp"
```

**KTS 写法：**

```kotlin
rootProject.name = "MyApp"
include(":app", ":core")
```

**新增：依赖解析管理（推荐方式）**

```kotlin
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        google()
        mavenCentral()
        // 自定义 Maven 仓库
        maven {
            url = uri("https://jitpack.io")
            // 或：setUrl("https://jitpack.io")
        }
    }
}
```

> ⚠️ KTS 中字符串必须用**双引号**，单引号是 `Char` 类型。

---

### 2.2 根 `build.gradle.kts` — 顶层配置

**Groovy 写法：**

```groovy
plugins {
    id 'com.android.application' version '8.2.0' apply false
    id 'org.jetbrains.kotlin.android' version '1.9.20' apply false
}
```

**KTS 写法：**

```kotlin
plugins {
    id("com.android.application") version "8.2.0" apply false
    id("org.jetbrains.kotlin.android") version "1.9.20" apply false
}
```

**使用版本目录（Version Catalog）更优雅：**

```kotlin
plugins {
    alias(libs.plugins.android.application) apply false
    alias(libs.plugins.kotlin.android) apply false
    alias(libs.plugins.kotlin.compose) apply false
}
```

### 2.3 模块级 `build.gradle.kts` — 核心配置

#### 2.3.1 `plugins` 块

```kotlin
plugins {
    id("com.android.application")
    id("org.jetbrains.kotlin.android")
    id("kotlin-kapt")          // Kotlin 注解处理
    id("kotlin-parcelize")     // Parcelable 生成
}
```

#### 2.3.2 `android` 块 — 完整示例

```kotlin
android {
    namespace = "com.example.myapp"
    compileSdk = 34

    defaultConfig {
        applicationId = "com.example.myapp"
        minSdk = 24
        targetSdk = 34
        versionCode = 1
        versionName = "1.0"

        // 清单占位符
        manifestPlaceholders["appAuthRedirectScheme"] = "myapp"

        // BuildConfig 字段
        buildConfigField("String", "API_BASE_URL", "\"https://api.example.com\"")
        buildConfigField("int", "MAX_RETRY_COUNT", "3")

        // 资源配置
        resValue("string", "app_name", "MyApp")

        // 测试相关
        testInstrumentationRunner = "androidx.test.runner.AndroidJUnitRunner"
    }

    // Build Types
    buildTypes {
        release {
            isMinifyEnabled = true
            isShrinkResources = true
            proguardFiles(
                getDefaultProguardFile("proguard-android-optimize.txt"),
                "proguard-rules.pro"
            )
            // 签名配置
            signingConfig = signingConfigs.getByName("release")
        }
        debug {
            isMinifyEnabled = false
            applicationIdSuffix = ".debug"
            versionNameSuffix = "-debug"
        }
        // 自定义 build type
        create("staging") {
            initWith(getByName("debug"))
            isMinifyEnabled = true
        }
    }

    // 签名配置
    signingConfigs {
        create("release") {
            storeFile = file("release-key.jks")
            storePassword = "password"
            keyAlias = "release"
            keyPassword = "password"
        }
    }

    // Product Flavors
    flavorDimensions += listOf("environment", "market")

    productFlavors {
        create("dev") {
            dimension = "environment"
            applicationIdSuffix = ".dev"
            buildConfigField("String", "BASE_URL", "\"https://dev.api.com\"")
        }
        create("prod") {
            dimension = "environment"
            buildConfigField("String", "BASE_URL", "\"https://api.com\"")
        }
        create("google") {
            dimension = "market"
        }
        create("huawei") {
            dimension = "market"
        }
    }

    // 编译选项
    compileOptions {
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }

    kotlinOptions {
        jvmTarget = "17"
        // 编译器参数
        freeCompilerArgs += listOf(
            "-opt-in=kotlin.RequiresOptIn",
            "-Xcontext-receivers"
        )
    }

    // Compose 支持
    buildFeatures {
        compose = true
        viewBinding = true
        dataBinding = true
        buildConfig = true
    }

    composeOptions {
        kotlinCompilerExtensionVersion = "1.5.4"
    }

    // 打包选项
    packaging {
        resources {
            excludes += listOf("/META-INF/{AL2.0,LGPL2.1}")
            merges += listOf("META-INF/LICENSE.md")
        }
    }

    // 过滤变体
    variantFilter {
        if (buildType.name == "release" && flavors.any { it.name == "dev" }) {
            ignore = true
        }
    }

    // 源集配置
    sourceSets {
        getByName("main") {
            java.srcDirs("src/main/kotlin")
            res.srcDirs("src/main/res-custom")
        }
    }
}
```

#### 2.3.3 `dependencies` 块

```kotlin
dependencies {
    // 基础依赖
    implementation("androidx.core:core-ktx:1.12.0")
    implementation("androidx.appcompat:appcompat:1.6.1")

    // 使用版本目录（推荐）
    implementation(libs.androidx.core.ktx)
    implementation(libs.androidx.appcompat)

    // 平台 BOM
    implementation(platform(libs.androidx.compose.bom))
    implementation(libs.bundles.compose)

    // 项目模块依赖
    implementation(project(":core"))
    implementation(project(":feature:home"))

    // 文件依赖
    implementation(files("libs/some-sdk.aar"))
    implementation(fileTree(mapOf("dir" to "libs", "include" to listOf("*.jar"))))

    // 测试依赖
    testImplementation(libs.junit)
    androidTestImplementation(libs.androidx.junit)
    androidTestImplementation(libs.androidx.espresso.core)

    // kapt / ksp
    kapt(libs.room.compiler)
    ksp(libs.moshi.ksp)

    // 仅编译时
    compileOnly(libs.lombok)

    // 运行时
    runtimeOnly(libs.timber.debug)

    // 按 flavor / build type 依赖
    "devImplementation"(libs.leakcanary)
    "googleImplementation"(libs.play.services.base)
}
```

### 2.4 Version Catalog（`libs.versions.toml`）

这是现代 Android 项目的**推荐做法**，统一管理所有依赖版本。

**位置：** `gradle/libs.versions.toml`

```toml
[versions]
agp = "8.2.0"
kotlin = "1.9.20"
coreKtx = "1.12.0"
appcompat = "1.6.1"
lifecycle = "2.7.0"
compose-bom = "2024.01.00"

[libraries]
androidx-core-ktx = { group = "androidx.core", name = "core-ktx", version.ref = "coreKtx" }
androidx-appcompat = { group = "androidx.appcompat", name = "appcompat", version.ref = "appcompat" }

# 简写形式
androidx-lifecycle-runtime-ktx = "androidx.lifecycle:lifecycle-runtime-ktx:2.7.0"

# BOM
androidx-compose-bom = { group = "androidx.compose", name = "compose-bom", version.ref = "compose-bom" }

[bundles]
lifecycle = [
    "androidx-lifecycle-runtime-ktx",
    "androidx-lifecycle-viewmodel-ktx",
    "androidx-lifecycle-livedata-ktx",
]

[plugins]
android-application = { id = "com.android.application", version.ref = "agp" }
kotlin-android = { id = "org.jetbrains.kotlin.android", version.ref = "kotlin" }
```

在 `build.gradle.kts` 中使用：

```kotlin
dependencies {
    implementation(libs.androidx.core.ktx)       // 单个依赖
    implementation(libs.bundles.lifecycle)        // 依赖组
    implementation(platform(libs.androidx.compose.bom))  // BOM
}
```

### 2.5 `gradle.properties` 中的配置

```properties
# 启用 KTS 脚本缓存
org.gradle.kotlin.dsl.caching=true

# 启用配置缓存
org.gradle.configuration-cache=true

# 并行执行
org.gradle.parallel=true

# 自定义属性（可在 build.gradle.kts 中读取）
MY_CUSTOM_PROP=hello
```

在脚本中读取：

```kotlin
val myProp: String by project  // 委托属性方式
// 或
val myProp = project.findProperty("MY_CUSTOM_PROP") as? String ?: "default"
```

## 三、Groovy → KTS 语法对照表

| 场景 | Groovy | Kotlin DSL |
|------|--------|-----------|
| 字符串 | `'single'` 或 `"double"` | **必须** `"double"` |
| 方法调用 | `method arg1, arg2` | `method(arg1, arg2)` |
| 布尔属性 | `minifyEnabled true` | `isMinifyEnabled = true` |
| 赋值 | `compileSdk 34` | `compileSdk = 34` |
| 列表 | `['a', 'b']` | `listOf("a", "b")` |
| Map | `[key: value]` | `mapOf("key" to value)` |
| 访问已有元素 | `release { ... }` | `getByName("release") { ... }` |
| 创建新元素 | `staging { ... }` | `create("staging") { ... }` |
| `it` 隐式参数 | 可用 | 显式写出或用 lambda |
| 类型安全 | ❌ 运行时才报错 | ✅ 编译期检查 |
| IDE 补全 | 较弱 | **强**（完整代码提示） |

## 四、快速入门（有 Groovy+Gradle 经验）

### 第一步：理解核心差异

你已经懂 Gradle 了，KTS 只是换了一种**语法**，底层模型完全一样。记住三个关键点：

1. **Kotlin 语法**：双引号、括号、等号赋值
2. **`is` 前缀**：布尔型属性 getter 变成 `isXxx`
3. **`getByName` / `create`**：NamedDomainObjectContainer 的访问方式变了

### 第二步：迁移步骤

**1. 重命名文件**

```bash
# 根目录
mv settings.gradle settings.gradle.kts
mv build.gradle build.gradle.kts

# app 模块
mv app/build.gradle app/build.gradle.kts
```

**2. 按语法对照表逐块改写**，建议顺序：

- `settings.gradle.kts` → 最简单
- 根 `build.gradle.kts` → plugins 块
- `app/build.gradle.kts` → plugins → android → dependencies

**3. 处理常见坑点：**

```kotlin
// ❌ Groovy 习惯
// buildConfigField "String", "KEY", "value"

// ✅ KTS 写法
buildConfigField("String", "KEY", "\"value\"")  // 注意字符串值需要内部引号

// ❌
// proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'

// ✅
proguardFiles(
    getDefaultProguardFile("proguard-android-optimize.txt"),
    "proguard-rules.pro"
)

// ❌ 直接访问 release
// release { ... }

// ✅ 先获取再配置
getByName("release") { ... }
// 或创建新的
create("staging") { ... }
```

### 第三步：利用 IDE 优势

KTS 的最大优势是**编译期类型安全 + 完整代码补全**：

- `Ctrl + 空格`：完整补全
- `Ctrl + 点击`：跳转到源码
- `Alt + Enter`：快速修复
- 红色波浪线：**编译前**就知道哪里错了（Groovy 要等构建失败才知道）

### 第四步：进阶优化

1. **引入 Version Catalog**：把所有版本号集中到 `libs.versions.toml`
2. **使用 `buildSrc` 或 `included builds`**：抽取公共配置
3. **约定插件（Convention Plugin）**：多模块项目中统一配置

## 五、常见问题速查

### Q1: 怎么引用 `buildConfigField` 中的字符串？

```kotlin
// 值本身需要带引号
buildConfigField("String", "API_URL", "\"https://api.example.com\"")
// 或用三引号
buildConfigField("String", "API_URL", """"https://api.example.com"""")
```

### Q2: 怎么写 task？

```kotlin
tasks.register("hello") {
    doLast {
        println("Hello from KTS!")
    }
}

// 已有 task 配置
tasks.named("preBuild") {
    dependsOn("hello")
}
```

### Q3: 怎么动态应用插件？

```kotlin
plugins {
    id("com.android.application")
    id("org.jetbrains.kotlin.android")
    // 条件应用
    if (project.hasProperty("enableCrashlytics")) {
        id("com.google.firebase.crashlytics")
    }
}
```

### Q4: `apply from` 怎么替代？

Groovy 的 `apply from: 'config.gradle'` 在 KTS 中：

```kotlin
apply(from = "config.gradle.kts")
```

但更推荐用 **included builds + convention plugins** 替代。

## 六、迁移建议

| 项目规模 | 建议方案 |
|---------|---------|
| 小项目（1-2 模块） | 直接全量迁移，半天搞定 |
| 中项目（3-10 模块） | 先迁 settings + 根 build，再逐个模块迁 |
| 大项目（多模块 + 自定义插件） | 先引入 Version Catalog，再逐步迁模块，最后做 convention plugin |

**最佳实践：**

- 利用 Android Studio 的 `Refactor → Convert to Kotlin DSL`（右键 `build.gradle`）
- 迁移过程中保持 Groovy 和 KTS **混合使用**是支持的，不必一步到位
- 优先迁移**改动频繁**的模块，享受类型安全带来的好处
