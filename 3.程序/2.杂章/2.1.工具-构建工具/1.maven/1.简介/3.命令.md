# Maven命令

## 一、先理解Maven命令的核心逻辑

在讲具体命令前，必须先明确3个核心概念（否则命令易用错）：

1. **生命周期（Lifecycle）**：Maven定义了3套独立的生命周期，命令本质是执行生命周期的「阶段」或插件的「目标」
   - `clean`：清理项目（删除编译产物）
   - `default`：核心构建流程（编译、测试、打包、部署等）
   - `site`：生成项目文档站点
2. **阶段（Phase）**：生命周期的最小执行单元（如`compile`、`package`），执行某个阶段会自动执行其之前的所有阶段（如执行`package`会先执行`compile`、`test`等）
3. **目标（Goal）**：插件的具体执行动作（如`dependency:tree`），格式为`插件前缀:目标名`

## 二、核心生命周期命令（最常用）

### 1. clean生命周期（清理）

| 命令 | 作用 | 示例 | 注意事项 |
|------|------|------|----------|
| `mvn clean` | 执行`clean`生命周期的`clean`阶段，删除项目根目录的`target`目录 | `mvn clean` | 仅清理，不做任何构建操作 |
| `mvn pre-clean` | 执行`clean`生命周期的`pre-clean`阶段（自定义前置清理逻辑，极少用） | `mvn pre-clean` | 需在pom.xml中配置插件绑定该阶段才会有效果 |

### 2. default生命周期（核心构建，按执行顺序）

这是最核心的生命周期，以下阶段按「执行顺序」排列，执行后序阶段会自动执行前序所有阶段：

| 命令（阶段） | 核心作用 | 关键示例 | 注意事项 |
|--------------|----------|----------|----------|
| `mvn validate` | 验证项目配置是否有效（如POM是否完整、依赖是否可用） | `mvn validate` | 基础校验，一般不单独执行 |
| `mvn initialize` | 初始化构建环境（如创建目录、初始化变量） | `mvn initialize` | 自动执行，极少单独用 |
| `mvn generate-sources` | 生成源码（如通过插件生成Java代码） | `mvn generate-sources` | 常用于MyBatis Generator、OpenAPI代码生成 |
| `mvn process-sources` | 处理源码（如编码转换、过滤模板） | `mvn process-sources` | 可配置插件过滤资源文件 |
| `mvn compile` | 编译`src/main/java`下的源码到`target/classes` | `mvn compile` <br> `mvn compile -Dencoding=UTF-8`（指定编码） | 1. 仅编译主代码，不编译测试代码 <br> 2. 需JDK环境（JRE不行） |
| `mvn process-classes` | 处理编译后的类文件（如字节码增强、添加注解） | `mvn process-classes` | 常用于Lombok、AspectJ等字节码插件 |
| `mvn generate-test-sources` | 生成测试源码 | `mvn generate-test-sources` | 极少单独执行 |
| `mvn process-test-sources` | 处理测试源码 | `mvn process-test-sources` | 自动执行 |
| `mvn test-compile` | 编译`src/test/java`下的测试源码到`target/test-classes` | `mvn test-compile` | 仅编译测试代码，不执行测试 |
| `mvn process-test-classes` | 处理测试类文件 | `mvn process-test-classes` | 自动执行 |
| `mvn test` | 执行测试用例（如JUnit、TestNG） | `mvn test` <br> `mvn test -Dtest=UserServiceTest`（仅执行指定测试类） <br> `mvn test -Dtest=UserServiceTest#testAdd`（仅执行指定测试方法） | 1. 依赖`test-compile`阶段 <br> 2. 测试失败会终止构建 |
| `mvn package` | 将编译后的代码打包（默认jar/war，由`<packaging>`决定） | `mvn package` <br> `mvn package -DskipTests`（跳过测试打包） | 1. 打包产物在`target`目录 <br> 2. 仅保存在本地，未安装到仓库 |
| `mvn install` | 将打包产物安装到**本地仓库**（默认`~/.m2/repository`） | `mvn install` <br> `mvn clean install -DskipTests` | 1. 其他本地项目可依赖该产物 <br> 2. 多模块项目中，子模块install后父模块才能引用 |
| `mvn deploy` | 将产物部署到**远程仓库**（如Nexus、Artifactory） | `mvn deploy` | 1. 需在pom.xml中配置`<distributionManagement>` <br> 2. 需在settings.xml中配置远程仓库账号密码 <br> 3. 一般仅在正式发布时使用 |

> 关键简化：日常开发中，`mvn clean install`是最常用的完整构建命令（清理→编译→测试→打包→安装到本地仓库）。

### 3. site生命周期（文档站点）

| 命令 | 作用 | 示例 | 注意事项 |
|------|------|------|----------|
| `mvn site` | 生成项目文档站点（如API文档、测试报告、依赖报告） | `mvn site` | 产物在`target/site`目录 |
| `mvn site-deploy` | 将生成的站点部署到远程服务器 | `mvn site-deploy` | 需配置站点远程仓库 |

## 三、依赖管理专用命令（解决依赖问题核心）

这类命令是`dependency`插件的目标，格式为`mvn dependency:目标名`，用于分析、排查、管理依赖：

| 命令 | 核心作用 | 关键示例 | 适用场景 |
|------|----------|----------|----------|
| `mvn dependency:tree` | 生成依赖树（展示所有依赖及层级关系） | `mvn dependency:tree` <br> `mvn dependency:tree -Dverbose`（显示冲突/可选依赖） <br> `mvn dependency:tree -DgroupId=org.springframework`（仅显示指定groupId的依赖） <br> `mvn dependency:tree -Doutput=dep-tree.txt`（输出到文件） | 排查依赖冲突、确认依赖版本、找到依赖来源 |
| `mvn dependency:analyze` | 分析依赖使用情况（未使用的依赖、缺失的依赖） | `mvn dependency:analyze` | 清理无用依赖、发现漏加的依赖 |
| `mvn dependency:copy` | 复制指定依赖到本地目录 | `mvn dependency:copy -Dartifact=org.springframework:spring-core:5.3.25:jar -DoutputDirectory=./lib` | 提取单个依赖到指定目录 |
| `mvn dependency:get` | 从远程仓库下载指定依赖到本地仓库 | `mvn dependency:get -Dartifact=org.springframework:spring-core:5.3.25` | 手动下载缺失的依赖 |
| `mvn dependency:purge-local-repository` | 清理本地仓库中指定依赖的缓存 | `mvn dependency:purge-local-repository -DgroupId=org.springframework -DartifactId=spring-core` | 解决本地依赖缓存损坏导致的构建问题 |
| `mvn dependency:resolve` | 解析并打印项目所有依赖（仅显示坐标，无层级） | `mvn dependency:resolve` | 快速查看项目依赖列表 |
| `mvn dependency:resolve-plugins` | 解析并打印构建过程中使用的插件依赖 | `mvn dependency:resolve-plugins` | 排查插件依赖冲突 |

## 四、多模块项目专用命令（核心参数）

多模块项目的命令核心是通过参数控制构建范围，需结合基础命令使用（如`clean install`）：

| 参数 | 作用 | 示例 | 注意事项 |
|------|------|------|----------|
| `-pl <模块列表>`（--projects） | 仅构建指定模块（模块名与pom.xml的artifactId一致） | `mvn clean install -pl e-commerce-web` <br> `mvn clean install -pl module1,module2`（多个模块用逗号分隔） | 模块名需与目录名/artifactId一致，区分大小写 |
| `-am`（--also-make） | 构建指定模块，并自动构建其**依赖的所有模块** | `mvn clean install -pl e-commerce-web -am` | 如web依赖service，service依赖core，则会构建core→service→web |
| `-amd`（--also-make-dependents） | 构建指定模块，并自动构建**依赖该模块的所有模块** | `mvn clean install -pl e-commerce-core -amd` | 如core被service、web依赖，则会构建core→service→web |
| `-rf <模块名>`（--resume-from） | 从指定模块开始恢复构建（跳过之前的模块） | `mvn clean install -rf e-commerce-service` | 适用于多模块构建失败后，跳过已成功的模块，仅构建后续模块 |
| `-nsu`（--no-snapshot-updates） | 构建时不更新快照版本依赖 | `mvn clean install -pl e-commerce-web -nsu` | 加速构建，避免拉取最新快照 |

## 五、仓库管理命令

| 命令 | 作用 | 示例 | 适用场景 |
|------|------|------|----------|
| `mvn help:effective-settings` | 查看有效仓库配置（合并全局+用户settings.xml） | `mvn help:effective-settings` | 确认仓库地址、镜像、账号是否配置正确 |
| `mvn repository:list` | 列出本地仓库的所有依赖（需仓库插件） | `mvn org.apache.maven.plugins:maven-repository-plugin:3.2.0:list` | 查看本地仓库已下载的依赖 |
| `mvn archetype:generate` | 从模板创建Maven项目（如快速创建Java/Web项目） | `mvn archetype:generate -DgroupId=com.example -DartifactId=demo -DarchetypeArtifactId=maven-archetype-quickstart -Dversion=1.0.0` | 快速初始化项目结构 |

## 六、调试与排查命令（解决构建问题）

| 命令/参数 | 作用 | 示例 | 适用场景 |
|-----------|------|------|----------|
| `-X`（--debug） | 打印DEBUG级别的日志（包含插件执行细节、依赖解析过程） | `mvn clean install -X` | 排查构建失败、插件报错、依赖解析异常 |
| `-e`（--errors） | 打印详细的异常堆栈信息 | `mvn clean install -e` | 构建报错时，查看完整异常原因 |
| `-U`（--update-snapshots） | 强制更新快照版本依赖（默认每天更新一次） | `mvn clean install -U` | 依赖快照版本时，拉取最新的快照包 |
| `mvn help:effective-pom` | 生成「有效POM」（合并父POM、全局配置后的最终POM） | `mvn help:effective-pom` | 排查POM配置继承问题、版本覆盖问题 |
| `mvn help:system` | 打印系统属性和环境变量（Maven运行时的环境） | `mvn help:system` | 确认Maven使用的JDK、环境变量是否正确 |
| `mvn compiler:help` | 查看指定插件的帮助文档（含目标、参数） | `mvn compiler:help -Ddetail`（显示详细信息） | 了解插件的所有可用参数和用法 |
| `mvn enforcer:enforce` | 执行规则检查（如JDK版本、依赖版本） | `mvn enforcer:enforce` | 强制校验项目构建环境是否符合规范 |

## 七、常用全局参数（所有命令均可搭配）

这些参数是日常使用中最高频的，需重点区分易混淆的参数：

| 参数 | 作用 | 示例 | 注意事项 |
|------|------|------|----------|
| `-DskipTests` | 跳过测试**执行**，但仍编译测试代码 | `mvn package -DskipTests` | 测试代码有语法错误时，该参数仍会报错 |
| `-Dmaven.test.skip=true` | 跳过测试**执行+编译**，完全忽略测试代码 | `mvn package -Dmaven.test.skip=true` | 测试代码报错时，用该参数可绕过 |
| `-Dmaven.compiler.source=8` | 指定编译源码的JDK版本 | `mvn compile -Dmaven.compiler.source=8 -Dmaven.compiler.target=8` | 临时覆盖pom.xml中的编译版本配置 |
| `-Dfile.encoding=UTF-8` | 指定文件编码（解决中文乱码） | `mvn compile -Dfile.encoding=UTF-8` | 需与源码编码一致，否则编译报错 |
| `-P <配置文件>`（--activate-profiles） | 激活指定的Profile | `mvn clean install -P prod` | 切换环境（如开发/测试/生产）的配置 |
| `-o`（--offline） | 离线构建（仅使用本地仓库，不访问远程仓库） | `mvn clean install -o` | 无网络时使用，需确保本地仓库已有所有依赖 |
| `-q`（--quiet） | 静默模式，仅打印ERROR级别的日志 | `mvn clean install -q` | 减少日志输出，只关注错误 |

## 八、高级命令与最佳实践

### 1. 批量更新模块版本

```bash
# 使用versions插件更新父项目版本
mvn versions:set -DnewVersion=2.0.0
# 确认版本更新（删除备份文件）
mvn versions:commit
# 回滚版本更新（恢复备份文件）
mvn versions:revert
```

### 2. 自定义构建输出目录

```bash
mvn clean install -Dproject.build.directory=./build  # 将target改为build目录
```

### 3. 排除指定插件执行

```bash
mvn clean install -Dmaven.javadoc.skip=true  # 跳过生成Javadoc
```

## 总结

Maven命令的核心知识点可归纳为以下3点：

1. **核心生命周期**：日常开发最常用`clean`（清理）、`compile`（编译）、`test`（测试）、`package`（打包）、`install`（安装到本地）、`deploy`（部署到远程），执行后序阶段会自动执行前序阶段；
2. **关键参数**：多模块用`-pl/-am/-amd`控制构建范围，排查问题用`-X/-e`，跳过测试区分`-DskipTests`（仅跳过执行）和`-Dmaven.test.skip=true`（跳过编译+执行）；
3. **依赖排查**：`dependency:tree`是解决依赖冲突的核心命令，结合`-Dverbose`可查看冲突依赖的来源和版本。

掌握这些命令和参数，能覆盖从日常开发、依赖排查、多模块构建到发布部署的所有Maven使用场景。
