# scope标签：runtime与import

## 一、`<scope>runtime</scope>`：运行时依赖

### 1. 核心定义

`runtime`（运行时）作用域表示：**依赖仅在「运行阶段」和「测试阶段」生效，编译主代码时不生效**。换句话说，你的项目源码（`src/main/java`）在编译时不会依赖该包，但运行/测试时必须有这个包，否则会报`ClassNotFoundException`。

### 2. 生效阶段对比（与默认`compile`对比）

| 阶段                | `compile`（默认） | `runtime` |
|---------------------|-------------------|-----------|
| 编译主代码（`compile`） | ✅ 生效           | ❌ 不生效 |
| 编译测试代码（`test-compile`） | ✅ 生效 | ✅ 生效 |
| 运行主程序（`package/run`） | ✅ 生效 | ✅ 生效 |
| 运行测试用例（`test`） | ✅ 生效 | ✅ 生效 |
| 打包（`package`）| ✅ 打入包内（如jar/war） | ✅ 打入包内 |
| 依赖传递            | ✅ 传递给下游项目 | ✅ 传递（下游生效阶段仍为`runtime`） |

### 3. 典型使用场景

`runtime` 适用于「编译时仅需接口，运行时需具体实现」的场景，最经典的例子：

- **JDBC驱动**：编译时只需要`java.sql`包（JDK自带），运行时才需要具体数据库的驱动（如MySQL/Oracle驱动）；
- **接口与实现分离**：如JAXB API（编译时依赖）和JAXB实现（运行时依赖）；
- **插件/工具类的运行时依赖**：如日志框架的实现包（SLF4J API为`compile`，Logback实现为`runtime`）。

### 4. 配置示例

以MySQL JDBC驱动为例（最常用的`runtime`场景）：

```xml
<dependencies>
    <!-- MySQL驱动：编译时无需引用，运行时才需要 -->
    <dependency>
        <groupId>mysql</groupId>
        <artifactId>mysql-connector-java</artifactId>
        <version>8.0.33</version>
        <scope>runtime</scope> <!-- 核心：运行时依赖 -->
    </dependency>
</dependencies>
```

- 效果：编译你的项目时，不会将`mysql-connector-java`加入编译类路径；但运行项目（如启动Spring Boot应用）时，必须有这个包，否则无法连接MySQL。

### 5. 关键注意事项

- 若你的代码中**直接import了runtime依赖的类**（如`com.mysql.cj.jdbc.Driver`），编译时会报错（找不到类）——这是`runtime`的核心特征，也是新手最容易踩的坑；
- 若需要编译时引用，但运行时才需要具体实现，应将API包设为`compile`，实现包设为`runtime`（如SLF4J API + Logback）。

## 二、`<scope>import</scope>`：导入式依赖（仅用于`dependencyManagement`）

### 1. 核心定义

`import`（导入）是**极其特殊的作用域**，仅满足两个条件时有效：

- 只能用在 `<dependencyManagement>` 标签内（不能用在`<dependencies>`中）；
- 依赖的`<type>`必须是`pom`（不能是`jar`/`war`）。

其核心作用是：**将另一个POM文件中的`<dependencyManagement>`配置「导入」到当前POM的`<dependencyManagement>`中**，实现依赖版本的统一管理（尤其是第三方大框架如Spring Boot）。

### 2. 生效逻辑

`import` 不会「引入依赖」（也不会传递依赖），仅「导入版本管理规则」。简单说：

- 被导入的POM中的`<dependencyManagement>`会合并到当前POM的`<dependencyManagement>`；
- 你仍需在`<dependencies>`中显式引入依赖，只是无需指定版本（继承导入的版本）。

### 3. 典型使用场景

- **Spring Boot依赖管理**：导入Spring Boot的`spring-boot-dependencies`，统一Spring Boot生态的依赖版本；
- **多模块项目拆分依赖管理**：将项目的`dependencyManagement`拆分为单独的`pom`文件，再通过`import`导入，简化父POM；
- **第三方框架版本统一**：导入如MyBatis、Dubbo等框架的官方`dependencyManagement` POM。

### 4. 配置示例

#### 示例1：导入Spring Boot的依赖管理（最常用）

```xml
<dependencyManagement>
    <dependencies>
        <!-- 导入Spring Boot的dependencyManagement：统一所有Spring Boot依赖版本 -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>2.7.15</version>
            <type>pom</type> <!-- 必须：pom类型 -->
            <scope>import</scope> <!-- 核心：导入作用域 -->
        </dependency>
    </dependencies>
</dependencyManagement>

<!-- 实际引入依赖：无需指定版本（继承上面导入的版本） -->
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
        <!-- 无version，自动使用spring-boot-dependencies中定义的版本 -->
    </dependency>
</dependencies>
```

#### 示例2：导入自定义的依赖管理POM

```xml
<!-- 第一步：创建单独的dependency-management.pom（仅含dependencyManagement） -->
<!-- 第二步：在主POM中导入 -->
<dependencyManagement>
    <dependencies>
        <!-- 导入自定义的依赖管理POM -->
        <dependency>
            <groupId>com.example</groupId>
            <artifactId>dependency-management</artifactId>
            <version>1.0.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

### 5. 关键注意事项

- ❌ 禁止在`<dependencies>`中使用`import`：会直接报错（Maven不支持）；
- ❌ 禁止非`pom`类型依赖使用`import`：如`<type>jar</type>` + `<scope>import</scope>`无效；
- ✅ `import`仅导入`<dependencyManagement>`：被导入POM中的`<dependencies>`、`<build>`等配置不会生效；
- ✅ 支持多个`import`：可导入多个POM的`dependencyManagement`，后导入的会覆盖先导入的同依赖版本（优先级：本地定义 > 后导入 > 先导入）。

## 三、`runtime` vs `import` 核心差异对比

| 维度                | `runtime`                | `import`                  |
|---------------------|--------------------------|---------------------------|
| 适用位置            | `<dependencies>`         | 仅`<dependencyManagement>` |
| 依赖类型            | 任意（通常是`jar`）      | 仅`pom`                   |
| 核心作用            | 控制依赖的生效阶段       | 导入其他POM的版本管理规则 |
| 是否引入依赖        | 是（运行时引入）         | 否（仅导入版本规则）      |
| 是否传递依赖        | 是（下游为`runtime`）    | 否（无依赖可传递）        |
| 典型场景            | JDBC驱动、运行时实现包   | Spring Boot依赖管理、自定义版本管理 |

## 总结

1. **`runtime` 核心**：编译不生效、运行/测试生效，适用于「接口-实现分离」的场景（如JDBC驱动），需注意避免编译时引用其类；
2. **`import` 核心**：仅用于`<dependencyManagement>` + `pom`类型依赖，作用是「导入版本管理规则」，不实际引入依赖，是Spring Boot等框架统一版本的核心方式；
3. 关键区分：`runtime`是「控制依赖生效阶段」，`import`是「导入版本配置」，二者无交集，且`import`是Maven中唯一仅用于`dependencyManagement`的作用域。
