## 错题 ：布局约束冲突（BoxConstraints forces an infinite width）

- **报错现象**：`BoxConstraints forces an infinite width`
- **错误代码**：在 `Row` 内部直接给子 `Container` 设置 `width: double.infinity`
- **根本原因**：
  - `Row` 会将可用宽度分配给子级。
  - 子级却向父级索要“无限宽”，两者约束冲突，渲染引擎无法计算具体像素。
- **正确写法**：
  - 将 `Row` 内的子 `Container` 替换为 **`Expanded`**（自动填充剩余宽度）。
  - 移除手动设置的 `width` 和 `height` 的无穷大值。

## 错题 ：ImageIcon 显示为纯黑色

- **报错现象**：图片能加载，但显示出来是一个**黑色的方块**（或纯黑色图标）。
- **错误代码**：用 `ImageIcon` 去加载一张彩色照片或带背景的 WebP/JPG 图片。
- **根本原因**：
  - `ImageIcon` 本质上是一个**遮罩（Mask）**。
  - 它**丢弃**了图片的彩色信息（RGB），只读取**透明度（Alpha）**通道，并用主题默认的 `IconTheme` 颜色（通常为黑色）填充不透明区域。
  - 如果图片没有透明背景，整个区域被识别为“不透明”，就会显示为纯黑。
- **正确写法**（二选一）：
  - **场景 A（彩色头像/普通图）**：改用 **`Image.asset(chatData.icon, width: 48, height: 48)`**。
  - **场景 B（纯白/矢量透明图标）**：保留 `ImageIcon`，但手动指定颜色，如 `color: Colors.grey`。

## ListView.separated 首尾边距

现象：希望第一个 item 左边距、最后一个 item 右边距，中间间隔固定。

错误写法：在 itemBuilder 中手动为第一个和最后一个包裹 Padding，代码臃肿且易出错（尤其是单元素列表）。

正确做法：直接使用 padding 属性，一行搞定。

示例：

```dart
ListView.separated(
  padding: const EdgeInsets.symmetric(horizontal: 16), // 左右首尾边距
  scrollDirection: Axis.horizontal,
  itemBuilder: (context, index) => ...,
  separatorBuilder: (context, index) => const SizedBox(width: 12),
  itemCount: data.length,
)
```

## 关于 double. 自动补全的误解

现象：输入 double. 时 IDE 弹出很多选项（infinity、nan、parse 等）。

原因：这只是自动补全列表，并非报错。

各选项含义：

- infinity：正无穷大（布局中常用，但需父级有限）。
- negativeInfinity：负无穷大（极少使用）。
- maxFinite：最大有限数（很少直接使用）。
- minPositive：最小正数（数学用途）。
- nan：非数字（绝对不要在布局中使用）。
- parse / tryParse：将字符串转为数字。

注意：使用 double.infinity 时务必确认父级约束有限，否则会触发布局异常。

## 容器如何按内容尺寸包裹（wrap_content）

现象：想要容器的高度（或宽度）刚好等于子视图的大小。

错误写法：强行设置 height: double.infinity 或固定大数值。

正确做法：不指定 width / height，让容器默认根据 child 尺寸自动适应。

示例：

dart
Container(
  color: Colors.blue,
  child: Text('我多高，容器就多高'), // 容器高度 = 文字高度
)
注意：若父级强制拉伸（如直接在 Scaffold body 中），用 Center 或 Align 包裹可恢复包裹行为

## Center 不居中（子组件高度等于父级时）

现象：Center 包裹水平滚动 ListView 后，垂直方向没有居中效果。

错误写法：

```dart
Center(
  child: ListView.separated(
    scrollDirection: Axis.horizontal,
    ...
  ),
)
```

原因：水平 ListView 默认在垂直方向拉伸填满父级，因此其高度等于父级可用高度（如 400），Center 没有多余空间来移动它。

正确做法：给 ListView 加上固定高度 SizedBox，使其高度小于父级，此时 Center 才会生效。

示例：

```dart
SizedBox(
  height: 400,
  child: Center(
    child: SizedBox(
      height: 100, // 固定高度，小于 400
      child: ListView.separated(
        scrollDirection: Axis.horizontal,
        ...
      ),
    ),
  ),
)
```

或者直接用 Container 的 alignment，省去 Center 组件。

## TextField 图标大小不生效（prefixIcon 与 ImageIcon 冲突）

现象：在 `TextField` 中使用 `prefixIcon` 嵌入图标，明明给 `ImageIcon` 设置了 `size: 20`，但图标视觉上**依然很大**（看起来像 48px），且与边框间距不对。

根本原因（双重压制）

- 原因 1：`ImageIcon` 的 `size` 不是绝对约束，`Icon(Icons.xxx, size: 20)`控件本身仅会**严格限制**自身绘制尺寸。`size` 只是**绘制参考值**，实际渲染时会**拉伸填充父容器**。父容器多大，它就撑多大。

- 原因 2：`prefixIcon` 自带强制最小宽高，为了符合 Material 设计规范的触控热区（至少 48px）`InputDecoration` 的 `prefixIcon` 默认约束为：`BoxConstraints(minWidth: 48, minHeight: 48)`。即使你的图片只有 20px，外层容器强制撑到 48px，导致 `ImageIcon` 被拉伸，视觉上 20px 完全失效。

解决方案：使用 `prefix` 替代 `prefixIcon`（最推荐，代码最干净）

- `prefix` 没有默认的 48x48 触控约束，完全按内容尺寸包裹。
- 配合 `Image.asset` 精准控制宽高，**无需调整 `prefixIconConstraints`**。

```dart
TextField(
  decoration: InputDecoration(
    hintText: '搜索对话...',
    border: OutlineInputBorder(borderRadius: BorderRadius.circular(12)),
    filled: true,
    fillColor: Colors.grey.shade100,
    contentPadding: const EdgeInsets.symmetric(vertical: 12, horizontal: 16),
    // 核心：使用 prefix，天然无 48 约束
    prefix: Padding(
      padding: const EdgeInsetsDirectional.only(start: 8, end: 6),
      child: Image.asset(
        'assets/icons/icon_search.webp',
        width: 20,
        height: 20,
        fit: BoxFit.contain,
      ),
    ),
  ),
)
```
