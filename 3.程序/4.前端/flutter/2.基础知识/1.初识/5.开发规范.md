# Flutter 完整开发规范

覆盖**代码格式、命名、目录结构、组件、状态管理、Dart语法、注释、资源、Git、性能、工程规范**，适配团队多人协作，适配Android/iOS双端统一。

## 一、基础环境规范

### 1. 版本统一

1. 团队固定 Flutter SDK 版本、Dart 版本，统一写入`fvm`配置，全员使用FVM管理版本，禁止本地随意切换。
2. 所有第三方依赖锁定版本号（`pubspec.yaml`禁止`^`大范围版本），使用`pubspec.lock`统一依赖。
3. 插件兼容双端最低版本：Android minSdk 21+；iOS iOS 12.0+。

### 2. 工具强制统一

- 格式化：使用`dart format`，IDE开启保存自动格式化
- 静态检查：启用`flutter analyze`，CI必须过检，禁止warning打包
- IDE：VS Code / Android Studio统一配置缩进：2空格，不使用Tab

## 二、目录分层规范（推荐模块化分层）

采用**功能模块化**，而非按控件类型分文件夹，适配大型项目；小型项目可简化。

```
lib
├── main.dart               # 程序入口，只初始化路由、SDK、全局配置
├── common                  # 全局公共层
│   ├── constants           # 常量：颜色、尺寸、字符串、正则、枚举
│   ├── utils               # 工具类：日期、加密、吐司、文件、权限
│   ├── widgets             # 全局通用UI组件：按钮、输入框、空页面、加载弹窗
│   ├── theme               # App主题、TextStyle、Decoration统一管理
│   ├── routes              # 路由管理：路由名常量、路由表、跳转工具
│   ├── dio                 # 网络封装：拦截器、请求封装、错误统一处理
│   └── extension           # Dart扩展：String/List/Widget扩展方法
├── models                  # 全局实体模型（Json序列化）
│   ├── request             # 请求入参model
│   └── response            # 返回数据model（统一json_serializable生成）
├── service                 # 业务服务层（网络请求聚合、本地存储逻辑）
│   ├── user_service.dart
│   └── goods_service.dart
├── modules                 # 业务功能模块（核心）
│   ├── login               # 登录模块，一个功能一个文件夹
│   │   ├── login_page.dart
│   │   ├── login_controller.dart
│   │   ├── login_state.dart
│   │   └── widgets         # 当前页面私有小控件
│   ├── home
│   └── mine
├── local_storage           # 本地缓存：sp、数据库封装
└── global                  # 全局状态：全局用户信息、APP全局变量
```

**规则**：

1. 单个页面私有组件放在当前模块`widgets`，不要丢进全局common。
2. 禁止页面直接写Dio请求，必须经过service层。

## 三、命名规范（严格区分大小写）

### 1. Dart 文件命名：蛇形小写 `snake_case`

全部小写，下划线分隔
✅ `user_info_page.dart`、`login_controller.dart`、`http_utils.dart`
❌ `UserInfo.dart`、`userInfoPage.dart`

主要原因是：跨平台文件，避免不同系统可能出现的名称大小限制。
>macOS（默认 APFS）和 Windows（默认 NTFS）不区分大小写，而 Linux 和 Android（ext4）严格区分大小写。在 Windows/macOS（不区分大小写） 下，UserData.dart 和 userdata.dart 被认为是同一个文件。如果你在 IDE 里新建了这两个文件，后一个会直接覆盖前一个。

### 2. 类名：大驼峰 PascalCase

Widget、State、Model、枚举、工具类全部大驼峰

```
class UserInfoPage extends StatelessWidget {}
class LoginController extends GetxController {}
enum PayType {}
```

### 3. 变量、函数、常量、参数：小驼峰 camelCase

```
String userName = '';
void getUserInfo() {}
```

### 4. 静态常量/全局常量：全大写下划线 `UPPER_SNAKE_CASE`

```
// constants里常量统一大写
const String BASE_URL = 'https://xxx.com';
const int MAX_UPLOAD_SIZE = 1024;
```

>
> final普通变量用小驼峰；const编译期常量大写。

### 5. 私有变量：前缀下划线`_`

```
String _token = '';
void _parseData() {}
```

### 6. 资源命名（图片、字体）：蛇形小写

图片按模块分类：

- 公共图：`ic_back.png`、img\_empty.png
- 登录页图片：`login_logo.png`、`login_bg.png`

### 7. 路由命名

路由常量统一：`/模块/页面`

```
static const String routeLogin = '/login/loginPage';
static const String routeHome = '/home/homePage';
```

## 四、Dart 代码语法规范

### 1. 空安全强制遵守（Dart 2.12+）

1. 能非空绝不加`?`，减少空判断；必须可空才使用可空类型
2. 慎用`!`空断言；优先用`?.`、`if (x != null)`判断，禁止滥用`!`
3. 初始化必给默认值，late只用于无法立即赋值的场景

### 2. 禁止魔法值

颜色、字号、间距、接口地址、文案全部抽入`constants`
❌ `Colors.white, fontSize: 16`
✅ `Color(AppColors.textPrimary), fontSize: AppFontSize.normal`

### 3. 字符串用单引号优先，多行用三引号

```
final tips = '登录失败，请重试';
final desc = '''
第一行
第二行
''';
```

### 4. 集合简写优先

```
// 推荐
final list = <String>[];
final map = <String, dynamic>{};
// 不推荐
List<String> list = List<String>();
```

### 5. 箭头函数只适合单行逻辑

多行必须大括号

```
// 单行可用箭头
list.map((e) => e.name);
// 多行禁止箭头
list.map((e) {
  final name = e.name;
  return name.trim();
});
```

### 6. 导入顺序规范（dart analyze校验）

导入从上到下：

1. Dart内置库（dart:xxx）
2. Flutter框架包（flutter/xxx）
3. 第三方pub包
4. 项目内部相对路径
每组空一行分隔，禁止乱序；禁止`import show hide`滥用。

## 五、Widget 组件编写规范

### 1. 组件拆分原则

1. 单个页面文件代码不超过**300行**，超过必须拆分为子Widget。
2. 重复UI抽全局CommonWidget；页面独有UI拆当前目录私有Widget。
3. 禁止巨型build方法，build只做组装，所有UI片段抽成方法/子组件。

### 2. Stateless / Stateful 选择

- 无状态、数据由外部传入：用`StatelessWidget`
- 需要自身持有状态：`StatefulWidget`
- 全局状态/跨页面：交给状态管理（GetX/Bloc/Provider），不要滥用Stateful

### 3. 构造函数规范

1. 所有可选参数使用**命名可选参数**`{}`，必填参数放前面
2. 控件参数一律required，默认值写在入参

```
// 标准写法
class CommonButton extends StatelessWidget {
  final String text;
  final double height;
  final VoidCallback onTap;

  const CommonButton({
    super.key,
    required this.text,
    required this.onTap,
    this.height = 44,
  });

  @override
  Widget build(BuildContext context) {}
}
```

3. 必须携带`super.key`，方便Flutter树查找刷新。

### 4. Build 书写规范

1. 层级嵌套深（超过3层）使用变量拆分

```
Widget build(BuildContext context) {
  final titleWidget = Text('标题');
  final contentWidget = _buildContent();
  return Scaffold(body: Column(children: [titleWidget, contentWidget]));
}

Widget _buildContent() {
  return Container();
}
```

2. 禁止大量内联样式，样式统一抽Theme/常量
3. Container 能用Padding、Align、SizedBox替代就不要用Container
   - 只加间距：SizedBox / Padding
   - 只设置宽高：SizedBox
   - 只有需要 decoration、margin、transform 才用Container

### 5. 列表规范

1. 长列表一律`ListView.builder`/`GridView.builder`，禁止ListView()一次性渲染
2. 列表item单独抽`_buildListItem`方法或独立Widget
3. 列表添加缓存：`addAutomaticKeepAlives`、`RepaintBoundary`减少重绘

### 6. 禁止滥用Expanded

Row/Column中需要占剩余空间才用Expanded；固定尺寸用SizedBox。

## 六、状态管理规范（团队统一一种）

以主流GetX举例；如果用Bloc/Provider同理统一规则：

1. 页面Controller和页面一一对应：`LoginPage` <=> `LoginController`
2. Controller只存放业务数据、接口请求；不要写UI代码
3. 页面只做UI展示，不写业务逻辑，逻辑全部下沉Controller
4. 全局状态放`global`，页面私有状态放当前Controller
5. 禁止跨页面直接操作其他Controller变量，必须提供方法调用

### GetX强制规则

- 不要随处`Get.put`，统一路由绑定`GetPage( binding: LoginBinding() )`
- 不用全局Get.off随意跳转，封装路由工具类
- Rx变量命名加rx前缀：`RxString rxName = ''.obs;`

## 七、网络&Model规范

1. 所有接口统一Dio封装，统一请求头、loading、错误码、token过期拦截
2. Model 全部使用`json_serializable`自动生成，禁止手写fromJson
3. 响应体统一外层包装：code、msg、data，基类BaseResponse

```
@JsonSerializable()
class BaseResponse {
  final int code;
  final String msg;
  final dynamic data;
}
```

4. 接口函数命名规范：`getXXX`、`postXXX`，例如`getUserInfo()`、`submitLogin()`
5. 所有请求加超时时间，区分普通请求/上传下载超时

## 八、注释规范

### 1. 文件头部

复杂模块文件顶部加简单说明：功能、创建人、修改记录。

### 2. 类、公共方法必须文档注释`///`

```
/// 通用圆角按钮
/// [text] 按钮文字
/// [onTap] 点击回调
class CommonButton {}
```

### 3. 复杂业务逻辑行内//注释

简单代码不需要注释；难懂算法、业务规则必须加注释。

### 4. 不要注释废弃代码，直接删除；需要恢复用Git追溯。

## 九、资源&图片规范

1. 图片使用`asset`，统一配置`pubspec.yaml`路径，禁止拼写错误
2. 多倍图按2.0x、3.0x目录存放，适配不同分辨率
3. 图标优先使用Flutter IconData，减少图片体积
4. 图片路径抽常量：`AppImages.loginLogo`，禁止字符串硬编码路径
5. 大图缓存使用`cached_network_image`，本地图片缓存用`Image.asset`

## 十、Git 协作规范

1. 分支管理：main（线上）、dev（开发）、feature/xxx（需求分支）、hotfix（紧急bug）
2. commit 格式统一：`类型: 描述`
   - feat: 新功能
   - fix: 修复bug
   - refactor: 重构（无功能变化）
   - style: 格式调整
   - docs: 注释文档
3. 禁止提交：无用print、debug代码、本地配置文件、.idea、build文件夹
4. .gitignore必须包含：build、.dart\_tool、.idea、flutter编译产物

## 十一、性能规范强制约束

1. 重复绘制控件包裹`RepaintBoundary`隔离重绘
2. 图片指定宽高，避免无约束图片布局抖动
3. 避免build创建大量对象；复杂对象放到initState/Controller初始化
4. 动画使用`AnimatedBuilder`，不要整个页面rebuild
5. 滚动列表禁止全部item重绘，用缓存、懒加载
6. 不用Opacity，能用Clip、ColorFilter替代就替换（Opacity离屏渲染耗性能）

## 十二、兼容性&多端规范

1. 适配深色模式：颜色不要写死，从Theme拿，区分light/dark两套配色
2. 适配屏幕：使用`MediaQuery`、`ScreenUtil`做适配，禁止写死固定像素
3. 安全区：页面加`SafeArea`，区分刘海、底部手势条
4. 安卓iOS差异化使用`Platform.isAndroid`/`Platform.isIOS`，差异化代码收拢到工具类，不要散落页面
5. 横竖屏统一配置，需要强制方向在main配置，不要页面单独设置

## 十三、禁止事项黑名单

1. ❌ 到处写print，正式代码必须用日志工具类，打包清空debug日志
2. ❌ 硬编码颜色、文字、尺寸、接口地址
3. ❌ 一个页面上千行，不拆分组件
4. ❌ 直接在build写大量业务逻辑、网络请求
5. ❌ 滥用Stateful，能用状态管理非要setState刷新整页
6. ❌ 导入混乱、文件命名大小写随意
7. ❌ 线上代码保留测试死代码、注释大段代码
8. ❌ 异步不做try-catch，接口报错无兜底

## 十四、linter配置推荐（analysis\_options.yaml）

```
linter:
  rules:
    always_declare_return_types: true
    camel_case_extensions: true
    camel_case_types: true
    constant_identifier_names: true
    file_names: true
    library_private_types_in_public_api: true
    prefer_const_constructors: true
    prefer_const_literals_to_create_immutables: true
    sized_box_for_whitespace: true
    unnecessary_new: true
    use_key_in_widget_constructors: true
```

强制开启常量构造，能加`const`全部加上，优化性能。

## 十五、分包&打包规范

1. 资源按模块分包，不需要的资源不要打包进安装包
2. Flutter打包开启混淆，Android开启R8压缩，iOS开启编译优化
3. 版本号统一管理在pubspec，渠道号、环境（测试/生产）通过环境变量区分，代码不要写死环境地址。
