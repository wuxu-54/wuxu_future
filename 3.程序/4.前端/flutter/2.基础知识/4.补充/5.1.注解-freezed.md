# Freezed 完整指南：从配置到真实场景全流程

Freezed 是 Flutter/Dart 生态中最流行的代码生成库之一，由 Riverpod 作者 **Rémi Rousselet** 开发。它能帮你自动生成**不可变数据类**、**Union/Sealed Class（联合类型）**、`copyWith`、`==`、`hashCode`、`toString` 以及 JSON 序列化代码，本质上是 Dart 版的 "Lombok"。

---

## 一、为什么要用 Freezed

| 痛点 | Freezed 解决方案 |
| --- | --- |
| 手写 `==` / `hashCode` 容易出错且枯燥 | 自动生成，深比较 |
| `copyWith` 手写繁琐，嵌套对象更痛苦 | 自动生成，支持嵌套深拷贝 |
| Dart 没有原生 data class | 用注解 + 代码生成实现 |
| 状态枚举无法携带数据（enum 太弱） | Union / Sealed Class，每个状态可带独立数据 |
| JSON 序列化样板代码多 | 配合 `json_serializable` 一键生成 |
| 不可变性难以保证 | 所有字段默认 `final`，编译期强制不可变 |

## 二、环境配置

### 2.1 添加依赖

在 `pubspec.yaml` 中添加以下三个包：

```
dependencies:
  flutter:
    sdk: flutter
  freezed_annotation: ^3.0.0   # 注解包（运行时依赖）
  json_annotation: ^4.9.0       # JSON 注解（需要 JSON 时才加）

dev_dependencies:
  flutter_test:
    sdk: flutter
  build_runner: ^2.4.0          # 代码生成引擎
  freezed: ^3.2.0               # Freezed 代码生成器
  json_serializable: ^6.8.0     # JSON 代码生成器（需要 JSON 时才加）
```

或者用命令行一键添加：

```
# 基础版（不需要 JSON）
flutter pub add freezed_annotation
flutter pub add dev:build_runner
flutter pub add dev:freezed

# 完整版（含 JSON 序列化）
flutter pub add freezed_annotation json_annotation
flutter pub add dev:build_runner freezed json_serializable
```

### 2.2 三个包各自的职责

| 包 | 作用 |
| --- | --- |
| `freezed_annotation` | 提供 `@freezed`、`@Freezed()`、`@Default` 等注解，运行时需要 |
| `freezed` | 代码生成器，只在开发/构建时运行 |
| `build_runner` | Dart 官方代码生成调度器，负责扫描并调用生成器 |

### 2.3 运行代码生成

```
# 单次生成
dart run build_runner build

# 持续监听文件变化，自动生成（开发时推荐）
dart run build_runner watch

# 清除缓存后重新生成（遇到奇怪问题时用）
dart run build_runner build --delete-conflicting-outputs
```

### 2.4 IDE 辅助

- **VS Code**：安装 `Flutter Freezed Snippets` 或 `Dart Freezed` 插件，输入 `frf` / `frj` 等快捷指令快速生成模板
- **Android Studio / IntelliJ**：安装 `Flutter Freezed` 插件

### 2.5 build.yaml 配置（可选但推荐）

在项目根目录创建 `build.yaml`，可以精细控制生成行为：

```
targets:
  $default:
    builders:
      freezed:
        options:
          # 统一为所有 freezed 类开启泛型参数工厂
          generic_argument_factories: true
          # 是否生成 map/maybeMap 方法（Dart 3 推荐关闭，用 switch）
          map: false
          # 是否生成 when/maybeWhen 方法
          when: true
```

## 三、基础使用：不可变数据类

### 3.1 最简单的例子

创建 `lib/models/user.dart`：

```
import 'package:freezed_annotation/freezed_annotation.dart';

// 1. 关联生成的代码文件（必须写）
part 'user.freezed.dart';

// 2. 注解 + with 混入生成的抽象类
@freezed
class User with _$User {
  // 3. factory 构造函数定义字段
  const factory User({
    required String id,
    required String name,
    required int age,
    String? email,          // 可选字段
  }) = _User;
}
```

运行 `dart run build_runner build` 后，会自动生成 `user.freezed.dart`，其中包含：

- 私有实现类 `_User`
- `==` 运算符和 `hashCode`（深比较）
- `copyWith` 方法
- `toString` 方法

### 3.2 copyWith 的使用

```
final user = User(id: '1', name: '张三', age: 25);

// 修改单个字段
final updated = user.copyWith(name: '李四');
// User(id: '1', name: '李四', age: 25)

// 把字段设为 null（特殊语法）
final noEmail = user.copyWith(email: null); // ❌ 不行，会被忽略
final noEmail = user.copyWith(email: Value(null)); // ✅ 正确方式
```

>
> **注意**：`copyWith` 中直接传 `null` 会被忽略（表示"不修改"）。要显式把字段设为 `null`，用 `Value(null)` 包裹。

### 3.3 默认值 @Default

```
@freezed
class User with _$User {
  const factory User({
    required String id,
    required String name,
    @Default(18) int age,          // 默认 18
    @Default('') String avatar,    // 默认空字符串
    @Default([]) List<String> tags, // 默认空列表
  }) = _User;
}
```

### 3.4 私有构造函数 + 自定义方法/getter

如果要在 freezed 类里加自己的方法或 getter，**必须添加一个私有构造函数**，否则 Dart 会报错：

```
@freezed
class User with _$User {
  // 私有构造函数（关键！添加自定义方法必须有这个）
  const User._();

  const factory User({
    required String id,
    required String firstName,
    required String lastName,
  }) = _User;

  // 自定义 getter
  String get fullName => '$firstName $lastName';

  // 自定义方法
  String greet() => '你好，我是 $fullName';
}
```

>
> **Freezed 3.x 重要变化**：3.x 版本生成的类默认是 `abstract interface class`，所以添加自定义成员**必须**有私有构造函数，这是强制要求。

## 四、JSON 序列化

Freezed 本身不生成 JSON 代码，而是**委托给 `json_serializable`**。

### 4.1 配置

```
import 'package:freezed_annotation/freezed_annotation.dart';

part 'user.freezed.dart';
part 'user.g.dart';  // 新增：JSON 生成文件

@freezed
class User with _$User {
  const factory User({
    required String id,
    required String name,
    required int age,
    String? email,
  }) = _User;

  // 新增：fromJson 工厂方法
  factory User.fromJson(Map<String, dynamic> json) => _$UserFromJson(json);
}
```

使用：

```
// JSON → 对象
final user = User.fromJson({'id': '1', 'name': '张三', 'age': 25});

// 对象 → JSON
final json = user.toJson();
```

### 4.2 @JsonKey：字段名映射

当 JSON 字段名和 Dart 字段名不一致时：

```
@freezed
class User with _$User {
  const factory User({
    required String id,
    required String name,
    @JsonKey(name: 'user_age') required int age, // JSON 中是 user_age
    @JsonKey(name: 'created_at') DateTime? createdAt,
    @JsonKey(ignore: true) String? tempField,    // 忽略此字段，不参与序列化
  }) = _User;

  factory User.fromJson(Map<String, dynamic> json) => _$UserFromJson(json);
}
```

### 4.3 嵌套模型

Freezed + json\_serializable 天然支持嵌套：

```
@freezed
class Post with _$Post {
  const factory Post({
    required String id,
    required String title,
    required User author,           // 嵌套另一个 freezed 类
    required List<Comment> comments, // 嵌套列表
  }) = _Post;

  factory Post.fromJson(Map<String, dynamic> json) => _$PostFromJson(json);
}

@freezed
class Comment with _$Comment {
  const factory Comment({
    required String id,
    required String content,
  }) = _Comment;

  factory Comment.fromJson(Map<String, dynamic> json) => _$CommentFromJson(json);
}
```

### 4.4 嵌套对象的深拷贝

`copyWith` 对嵌套对象也有支持，但默认是浅拷贝。深度修改嵌套字段：

```
// 方式1：手动逐层 copyWith
final updated = post.copyWith(
  author: post.author.copyWith(name: '新名字'),
);

// 方式2：Freezed 2.x+ 的嵌套 copyWith 语法（更简洁）
final updated = post.copyWith.author(name: '新名字');
```

## 五、Union / Sealed Class（联合类型）

这是 Freezed **最强大的功能**之一。它让你定义"一组互斥的状态/类型"，每个状态可以携带不同的数据，并且编译器会强制你处理所有情况。

### 5.1 基本定义

```
@freezed
sealed class ApiResult<T> with _$ApiResult<T> {
  const factory ApiResult.success(T data) = Success<T>;
  const factory ApiResult.loading() = Loading<T>;
  const factory ApiResult.error(String message, {int? code}) = ErrorState<T>;
}
```

关键点：

- 用 `sealed class`（Freezed 3.x + Dart 3 推荐）或 `abstract class` 声明
- 多个 `factory` 构造函数，每个代表一种状态
- 每个构造函数用 `= 类名` 重定向到一个具体的实现类
- 支持泛型

### 5.2 when：穷尽式匹配（必须处理所有情况）

```
final result = ApiResult<User>.success(user);

result.when(
  success: (data) => print('成功：${data.name}'),
  loading: () => print('加载中...'),
  error: (message, code) => print('错误：$message，代码：$code'),
);
```

>
> `when` 是**穷尽的**——少写一个分支编译就会报错，保证你不会遗漏任何状态。

### 5.3 maybeWhen：非穷尽匹配（有默认兜底）

```
result.maybeWhen(
  success: (data) => print('成功'),
  orElse: () => print('其他状态'), // 兜底分支
);
```

### 5.4 map / maybeMap：类似 when，但回调参数是整个对象

```
result.map(
  success: (successState) => print(successState.data),
  loading: (loadingState) => print('加载中'),
  error: (errorState) => print(errorState.message),
);
```

**when vs map 的区别**：

- `when`：回调参数是**解构后的字段**（直接拿到 data、message 等）
- `map`：回调参数是**完整的状态对象**（拿到 Success / Loading / ErrorState 实例）

### 5.5 Dart 3 模式匹配（推荐替代 when/map）

Dart 3 引入了原生的 **sealed class** 和 **switch 表达式**，Freezed 3.x 完全兼容。官方更推荐用 Dart 3 原生语法：

```
// switch 表达式（穷尽检查，少写分支直接编译报错）
final message = switch (result) {
  Success(data: final data) => '成功：${data.name}',
  Loading() => '加载中...',
  ErrorState(message: final msg, code: final code) => '错误：$msg ($code)',
};

// switch 语句
switch (result) {
  case Success(data: final data):
    print('拿到数据：$data');
  case Loading():
    print('请稍候...');
  case ErrorState():
    print('出错了');
}
```

**为什么推荐 Dart 3 switch 而不是 when/map？**

1. 语法更灵活，支持守卫条件（`when` 子句）、嵌套解构
2. 不依赖代码生成，纯语言特性
3. 性能更好（直接走 Dart 原生调度）
4. 可以通过 `build.yaml` 关闭 when/map 生成，减少生成代码体积

## 六、Freezed 3.x 新特性与迁移

### 6.1 核心变化

Freezed 3.0（2025 年 2 月发布）最大的变化是支持 **mixed mode（混合模式）**，并对齐 Dart 3 的 sealed class 特性。

### 6.2 两种语法风格

**风格一：传统 factory 重定向（推荐老项目迁移）**

```
@freezed
sealed class User with _$User {
  const factory User({
    required String id,
    required String name,
  }) = _User;
}
```

- 单一数据类 → 用 `abstract class`
- 联合类型 → 用 `sealed class`

**风格二：纯 Dart 字段声明（新增，更像普通 Dart 类）**

```
@freezed
class User with _$User {
  User({
    required this.id,
    required this.name,
    this.email,
  });

  final String id;
  final String name;
  final String? email;
}
```

这种风格更接近普通 Dart 类，适合简单的数据类，不需要写 `= _User` 重定向。

### 6.3 从 2.x 迁移到 3.x

迁移步骤：

1. **升级依赖**：`freezed_annotation: ^3.0.0`，`freezed: ^3.0.0`
2. **添加关键字**：
   - 单一数据类 → class 前加 `abstract`（或不加，mixed mode 兼容）
   - 联合类型 → class 前加 `sealed`
3. **重新生成**：`dart run build_runner build --delete-conflicting-outputs`
4. **修复自定义方法**：如果类里有自定义 getter/method，确保有私有构造函数

>
> 社区有迁移工具（如 `freezed 3.x 迁移工具` VS Code 插件）可以批量添加 `sealed` / `abstract` 关键字。

## 七、高级用法

### 7.1 泛型 Union

```
@freezed
sealed class Result<T> with _$Result<T> {
  const factory Result.data(T value) = Data<T>;
  const factory Result.loading() = Loading<T>;
  const factory Result.error(Object error, StackTrace stackTrace) = ErrorResult<T>;
}
```

使用：

```
Result<User> result = Result.data(user);
```

### 7.2 泛型 + JSON 序列化

需要开启 `genericArgumentFactories`：

```
@Freezed(genericArgumentFactories: true)
sealed class ApiResponse<T> with _$ApiResponse<T> {
  const factory ApiResponse.success(T data) = Success<T>;
  const factory ApiResponse.failure(String message) = Failure<T>;

  factory ApiResponse.fromJson(
    Map<String, dynamic> json,
    T Function(Object? json) fromJsonT,
  ) => _$ApiResponseFromJson(json, fromJsonT);
}
```

使用时传入具体类型的解析函数：

```
final response = ApiResponse<User>.fromJson(
  json,
  (json) => User.fromJson(json as Map<String, dynamic>),
);
```

### 7.3 @With 和 @Implements

让 freezed 类继承/实现其他类：

```
abstract class GeographicArea {
  int get population;
  String get name;
}

@freezed
class City with _$City implements GeographicArea {
  const factory City({
    required String name,
    required int population,
  }) = _City;
}
```

### 7.4 联合类型中的公共属性

强制所有 union case 都有某个属性：

```
@freezed
sealed class Union with _$Union {
  const factory Union.left(int value) = _Left;
  const factory Union.right(int value) = _Right;

  // 强制所有 case 都有 value 属性
  @override
  int get value;
}
```

### 7.5 枚举 + Freezed 组合

```
enum Status { active, inactive, banned }

@freezed
class User with _$User {
  const factory User({
    required String id,
    required String name,
    required Status status,
  }) = _User;
}
```

如果枚举也需要 JSON 序列化，用 `@JsonEnum`：

```
@JsonEnum()
enum Status {
  @JsonValue('active') active,
  @JsonValue('inactive') inactive,
  @JsonValue('banned') banned,
}
```

### 7.6 自定义 fromJson / toJson

对某个字段自定义序列化逻辑：

```
@freezed
class User with _$User {
  const factory User({
    required String id,
    required String name,
    // 自定义转换器
    @JsonKey(fromJson: _dateTimeFromJson, toJson: _dateTimeToJson)
    required DateTime birthday,
  }) = _User;

  factory User.fromJson(Map<String, dynamic> json) => _$UserFromJson(json);
}

DateTime _dateTimeFromJson(int timestamp) =>
    DateTime.fromMillisecondsSinceEpoch(timestamp);

int _dateTimeToJson(DateTime date) => date.millisecondsSinceEpoch;
```

或者用 `JsonConverter`：

```
class DateTimeConverter implements JsonConverter<DateTime, int> {
  const DateTimeConverter();

  @override
  DateTime fromJson(int timestamp) => DateTime.fromMillisecondsSinceEpoch(timestamp);

  @override
  int toJson(DateTime date) => date.millisecondsSinceEpoch;
}

// 使用
@freezed
class User with _$User {
  const factory User({
    required String id,
    @DateTimeConverter() required DateTime birthday,
  }) = _User;
}
```

## 八、真实场景接入

### 场景 1：API 统一响应封装

**需求**：所有接口返回统一格式 `{code, message, data}`，需要统一处理成功/失败。

```
// lib/models/api_response.dart
@Freezed(genericArgumentFactories: true)
sealed class ApiResponse<T> with _$ApiResponse<T> {
  const factory ApiResponse.success({
    required int code,
    required String message,
    required T data,
  }) = ApiSuccess<T>;

  const factory ApiResponse.error({
    required int code,
    required String message,
  }) = ApiError<T>;

  factory ApiResponse.fromJson(
    Map<String, dynamic> json,
    T Function(Object? json) fromJsonT,
  ) => _$ApiResponseFromJson(json, fromJsonT);
}
```

在 Repository 层使用：

```
class UserRepository {
  final ApiClient _api;

  Future<ApiResponse<User>> getUser(String id) async {
    final json = await _api.get('/users/$id');
    return ApiResponse<User>.fromJson(
      json,
      (data) => User.fromJson(data as Map<String, dynamic>),
    );
  }
}
```

在 UI 层使用：

```
final response = await repo.getUser('1');

// Dart 3 switch 模式匹配
return switch (response) {
  ApiSuccess(data: final user) => UserProfile(user: user),
  ApiError(message: final msg) => ErrorView(message: msg),
};
```

### 场景 2：Riverpod + Freezed 状态管理

**需求**：一个登录页面，状态有：未输入、加载中、成功、失败。

```
// lib/features/auth/auth_state.dart
@freezed
sealed class AuthState with _$AuthState {
  const factory AuthState.initial() = AuthInitial;
  const factory AuthState.loading() = AuthLoading;
  const factory AuthState.authenticated(User user) = Authenticated;
  const factory AuthState.error(String message) = AuthError;
}
```

```
// lib/features/auth/auth_notifier.dart
class AuthNotifier extends StateNotifier<AuthState> {
  AuthNotifier(this._repo) : super(const AuthState.initial());

  final AuthRepository _repo;

  Future<void> login(String username, String password) async {
    state = const AuthState.loading();

    final result = await _repo.login(username, password);

    result.when(
      success: (user) => state = AuthState.authenticated(user),
      error: (message) => state = AuthState.error(message),
    );
  }

  void logout() {
    state = const AuthState.initial();
  }
}

final authNotifierProvider =
    StateNotifierProvider<AuthNotifier, AuthState>((ref) {
  return AuthNotifier(ref.watch(authRepoProvider));
});
```

UI 层使用：

```
Consumer(
  builder: (context, ref, child) {
    final authState = ref.watch(authNotifierProvider);

    return authState.when(
      initial: () => LoginForm(),
      loading: () => const Center(child: CircularProgressIndicator()),
      authenticated: (user) => HomePage(user: user),
      error: (message) => LoginForm(errorMessage: message),
    );
  },
)
```

### 场景 3：Bloc / Cubit + Freezed

**需求**：列表页状态：加载中、加载成功（带数据）、加载失败、空状态。

```
// states
@freezed
sealed class PostState with _$PostState {
  const factory PostState.initial() = PostInitial;
  const factory PostState.loading() = PostLoading;
  const factory PostState.success(List<Post> posts, {bool? hasMore}) = PostSuccess;
  const factory PostState.empty() = PostEmpty;
  const factory PostState.failure(String message) = PostFailure;
}

// events
@freezed
sealed class PostEvent with _$PostEvent {
  const factory PostEvent.fetch() = PostFetch;
  const factory PostEvent.refresh() = PostRefresh;
  const factory PostEvent.loadMore() = PostLoadMore;
}
```

```
class PostBloc extends Bloc<PostEvent, PostState> {
  PostBloc(this._repo) : super(const PostState.initial()) {
    on<PostFetch>(_onFetch);
    on<PostRefresh>(_onRefresh);
    on<PostLoadMore>(_onLoadMore);
  }

  final PostRepository _repo;

  Future<void> _onFetch(PostFetch event, Emitter<PostState> emit) async {
    emit(const PostState.loading());

    final result = await _repo.getPosts();

    result.when(
      success: (posts) {
        if (posts.isEmpty) {
          emit(const PostState.empty());
        } else {
          emit(PostState.success(posts, hasMore: true));
        }
      },
      error: (message) => emit(PostState.failure(message)),
    );
  }
  // ... 其他事件处理
}
```

### 场景 4：表单状态管理

**需求**：注册表单，每个字段有验证状态，整体有提交状态。

```
@freezed
class RegisterForm with _$RegisterForm {
  const factory RegisterForm({
    required String username,
    required String email,
    required String password,
    required String confirmPassword,
    @Default(false) bool isSubmitting,
    @Default(false) bool showValidationErrors,

    String? emailError,
    String? passwordError,
    String? confirmPasswordError,

  // 计算属性：表单是否整体有效

      username.isNotEmpty &&
      email.contains('@') &&
      password.length >= 6 &&
      password == confirmPassword;
}

```

### 场景 5：UI 状态机（加载/成功/失败/空）

这是最经典的 freezed union 使用场景，几乎每个列表页/详情页都能用：

```
@freezed
sealed class UiState<T> with _$UiState<T> {
  const factory UiState.idle() = Idle<T>;
  const factory UiState.loading() = Loading<T>;
  const factory UiState.data(T data) = Data<T>;
  const factory UiState.empty() = Empty<T>;
  const factory UiState.error(String message, {StackTrace? stackTrace}) = UiError<T>;
}
```

封装一个通用的 Widget：

```
class StateView<T> extends StatelessWidget {
  final UiState<T> state;
  final Widget Function(T data) dataBuilder;
  final VoidCallback? onRetry;

  const StateView({
    super.key,
    required this.state,
    required this.dataBuilder,
    this.onRetry,
  });

  @override
  Widget build(BuildContext context) {
    return switch (state) {
      Idle() => const SizedBox.shrink(),
      Loading() => const Center(child: CircularProgressIndicator()),
      Data(data: final data) => dataBuilder(data),
      Empty() => const Center(child: Text('暂无数据')),
      UiError(message: final msg) => Center(
          child: Column(
            mainAxisAlignment: MainAxisAlignment.center,
            children: [
              Text(msg),
              if (onRetry != null)
                ElevatedButton(onPressed: onRetry, child: const Text('重试')),
            ],
          ),
        ),
    };
  }
}
```

## 九、常见问题与最佳实践

### 9.1 常见报错与解决

| 报错信息 | 原因 | 解决方案 |
| --- | --- | --- |
| `Missing concrete implementation of getter` | 类里有自定义方法/getter但没有私有构造函数 | 添加 `const ClassName._();` 私有构造 |
| `The method 'copyWith' isn't defined` | 没运行 build\_runner 或生成失败 | 运行 `dart run build_runner build --delete-conflicting-outputs` |
| `part 'xxx.freezed.dart'` 报红 | 还没生成文件 | 运行代码生成命令 |
| `Invalid annotation target` | `@JsonKey` 用错了位置 | 确保注解在 factory 构造函数的参数上 |
| 泛型 fromJson 报错 | 没开 `genericArgumentFactories` | 在 `@Freezed(genericArgumentFactories: true)` 中开启 |

### 9.2 build\_runner 慢怎么办

```
# 1. 使用 watch 模式（增量生成，只改变化的文件）
dart run build_runner watch

# 2. 排除不需要生成的目录（在 build.yaml 中配置）
targets:
  $default:
    sources:
      - lib/**
      - test/**
      # 排除 example 等
```

### 9.3 Freezed vs Equatable

| 特性 | Freezed | Equatable |
| --- | --- | --- |
| 不可变 | ✅ 默认 final | ❌ 需要手动写 final |
| copyWith | ✅ 自动生成 | ❌ 需手写 |
| Union 类型 | ✅ 强大的 sealed class | ❌ 不支持 |
| JSON 序列化 | ✅ 配合 json\_serializable | ❌ 不支持 |
| 代码生成 | 需要 build\_runner | 不需要 |
| 学习成本 | 较高 | 低 |

>
> **选型建议**：简单项目、只需要 `==` 比较 → Equatable；中大型项目、需要 copyWith/union/JSON → Freezed。

### 9.4 最佳实践清单

1. **所有数据模型都用 freezed**：保证不可变性，避免意外修改
2. **状态用 Union（sealed class）**：让编译器帮你做穷尽检查
3. **Dart 3 项目优先用 switch 模式匹配**：替代 when/map，更灵活
4. **联合类型用 `sealed` 关键字**：明确告诉编译器这是封闭类型
5. **嵌套模型深拷贝用链式 copyWith**：`state.copyWith.user(name: 'xxx')`
6. **JSON 字段统一用 `@JsonKey` 映射**：不要依赖字段名自动匹配
7. **添加自定义方法必须加私有构造函数**：`const ClassName._();`
8. **生成的文件（.freezed.dart / .g.dart）提交到 git**：CI/CD 环境可能不跑 build\_runner
9. **配合 `build_runner watch` 开发**：保存即生成，不用手动跑命令
10. **泛型响应类统一封装**：`ApiResponse<T>` / `Result<T>` 全项目复用

### 9.5 生成文件要不要提交 Git？

**建议提交**，理由：

- 团队成员拉代码后直接能跑，不需要先跑 build
- CI/CD 流水线不需要额外安装 build\_runner
- 代码审查时能看到生成了什么

如果不提交，需要在 `.gitignore` 中添加：

```
*.freezed.dart
*.g.dart
```

**总结**：Freezed 的核心价值是用**极少量的注解代码**，生成**大量类型安全的样板代码**，同时通过 **Union / Sealed Class** 让你的状态管理变得**编译器可验证**（穷尽检查）。在中大型 Flutter 项目中，它几乎是基础设施级别的依赖。
