# freezed 完整讲解（结合 Flutter、Redux、Provider 场景）

## 一、freezed 是什么

`freezed` 是 Dart 代码生成工具，配合 `build_runner`，**自动生成不可变数据类、联合枚举（密封类）、序列化、拷贝、相等判断**，解决 Dart 原生写实体类极其繁琐的痛点。
配套常用包：

```
dependencies:
  freezed_annotation
dev_dependencies:
  freezed
  build_runner
  json_serializable # json序列化可选
```

### 核心定位

专门做**不可变模型**，Redux 最推荐搭配 freezed；Provider+ChangeNotifier 也大量用来封装状态。

## 二、原生 Dart 痛点（不用 freezed 有多麻烦）

写一个计数器状态类，原生必须手写：

1. 所有字段 final（保证不可变）
2. 构造函数必填所有参数
3. `copyWith` 拷贝修改（Redux 必须靠 copyWith 返回新 state）
4. `==`、hashCode 重写做等值比较
5. toString 打印日志
6. fromJson/toJson 序列化

字段一多，几十行重复模板代码。freezed 一行不用手写，全部自动生成。

## 三、freezed 核心能力详解

### 1. 自动生成不可变类（最重要，适配Redux）

Redux 硬性要求：State 必须**不可变 immutable**，不能直接修改属性，只能新建对象。freezed 默认所有字段强制 final。

基础示例：

```
import 'package:freezed_annotation/freezed_annotation.dart';
part 'counter_state.freezed.dart';

@freezed
class CounterState with _$CounterState {
  const factory CounterState({
    required int count,
    required bool loading,
  }) = _CounterState;
}
```

运行生成命令：

```
dart run build_runner build
# 监听实时生成
dart run build_runner watch
```

自动产出：

- 全参构造
- **copyWith**：Redux Reducer 修改状态必备

```
// 只改count，loading保留旧值
final newState = oldState.copyWith(count: oldState.count + 1);
```

- 重写 `==` 和 hashCode：两个对象字段一样就相等，不用手动重写
- 好看的 toString，方便日志调试
- 全字段只读，无法随意修改

### 2. copyWith：Redux 灵魂搭档

Redux Reducer 是纯函数：旧state+action → 新state。
没有 freezed：手写巨长 copyWith；
有 freezed：一键拷贝局部更新。

#### Reducer标准写法搭配freezed

```
CounterState reducer(CounterState state, dynamic action) {
  if (action is Increment) {
    return state.copyWith(count: state.count + 1);
  }
  if (action is ToggleLoading) {
    return state.copyWith(loading: true);
  }
  return state;
}
```

完全符合 Redux 不可变规范。

### 3. 联合类型（密封类）替代枚举：状态多分支管理

freezed 最强杀手锏：**密封联合类（Sealed Class）**，用来表达「多种互斥状态」，非常适合网络请求、页面状态。

比如接口请求：加载中 / 成功 / 失败，传统要用3个字段标记；freezed一键区分。

```
@freezed
class UserFetchState with _$UserFetchState {
  // 三种互斥状态，同一时间只会是其中一种
  const factory UserFetchState.loading() = UserLoading;
  const factory UserFetchState.success(User user) = UserSuccess;
  const factory UserFetchState.error(String msg) = UserError;
}
```

配合 Dart 模式匹配 switch 精准分支：

```
switch(state) {
  case UserLoading():
    return CircularProgressIndicator();
  case UserSuccess(data: final user):
    return Text(user.name);
  case UserError(msg: final err):
    return Text(err);
}
```

大量用于：

- Redux全局页面状态
- Provider/Notifier里的接口状态
- 所有多分支UI状态管理

### 4. JSON 序列化一键生成

搭配 json\_serializable，自动生成 fromJson/toJson，不用手写序列化：

```
@freezed
class User with _$User {
  factory User.fromJson(Map<String,dynamic> json) = _User.fromJson;
  const factory User({required String name, required int age}) = _User;
}
```

生成后直接：

```
User u = User.fromJson(jsonMap);
Map<String,dynamic> json = u.toJson();
```

### 5. 默认值、可选字段、可空友好

支持默认值、@Default、@JsonKey映射后端字段：

```
const factory User({
  @Default(0) int age,
  @JsonKey(name: "user_name") String? name,
}) = _User;
```

## 四、freezed 和 Redux / Provider 的搭配关系（重点）

### 1. Redux + freezed：黄金组合

1. Redux 要求 State 不可变 → freezed 默认不可变
2. Reducer 需要大量 copyWith 生成新状态 → freezed 自动生成 copyWith
3. 多业务分支（请求成功/失败）用 freezed 联合类管理，替代一堆布尔变量
4. Action 也可以用 freezed 定义（所有Action统一管理）

```
@freezed
class CounterAction with _$CounterAction {
  const factory CounterAction.inc() = IncAction;
  const factory CounterAction.dec() = DecAction;
}
```

Reducer 匹配 Action 极其清爽。

### 2. Provider+ChangeNotifier + freezed

Notifier 内部推荐把所有业务状态封装成一个 freezed 对象，而不是零散变量：
❌ 不好：零散变量容易漏 notify、乱改

```
class CounterNotifier extends ChangeNotifier {
  int count=0;
  bool loading=false;
}
```

✅ 规范写法：用 freezed 聚合状态

```
class CounterNotifier extends ChangeNotifier {
  CounterState _state = const CounterState(count:0, loading:false);
  CounterState get state => _state;

  void inc() {
    // copyWith更新，不可变
    _state = _state.copyWith(count: _state.count+1);
    notifyListeners();
  }
}
```

好处：

- 状态收敛为单一对象，可追溯
- 天然不可变，不会出现字段被外部篡改
- 方便Selector精准监听某个字段
- 方便日志打印全量状态

## 五、freezed 常用注解补充

1. `@freezed`：标准不可变类
2. `@unfreezed`：允许可变字段（极少用，不推荐Redux）
3. `@Default`：json解析默认值
4. `@JsonKey`：字段重命名、忽略字段
5. `@late`：延迟初始化

## 六、优缺点总结

### 优点

1. 消灭实体类模板代码，解放双手
2. 强制不可变，完美适配Redux单向数据流
3. 密封类轻松管理多分支状态（加载/成功/失败）
4. 自动等值判断，状态对比、缓存判断方便
5. Json序列化开箱即用
6. 支持解构、模式匹配，代码可读性极强

### 缺点

1. 需要代码生成，多一步 build 命令
2. 新手需要理解 part 碎片文件
3. 过于简单的小页面状态没必要用（有点重）

## 七、最佳实践总结

1. **Redux项目：所有State、Action全部用freezed定义，行业标准写法**
2. **Provider/ChangeNotifier：复杂业务用freezed封装整体state；简单零散小状态可不用**
3. 接口请求、分页、多UI分支，一律用freezed联合密封类
4. 禁止手动手写copyWith、==，交给freezed维护
