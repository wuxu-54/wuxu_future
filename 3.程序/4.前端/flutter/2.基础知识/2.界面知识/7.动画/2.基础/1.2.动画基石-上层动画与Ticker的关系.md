# Flutter 动画底层都是 Ticker 驱动的吗？

**核心结论：是的，几乎所有 Flutter 动画的底层都是 `Ticker` 驱动的。** 不管是隐式动画、显式动画、Hero 动画，还是 `AnimatedFoo` 系列 widget，追到底层，最终都是靠 **Ticker 逐帧回调 → 更新值 → 触发重绘** 这条链路在跑。

但不同类型的动画，**Ticker 暴露给你的程度不一样**——有的你直接操作，有的藏在框架内部。

---

## 一、全景图：动画的分层结构

Flutter 动画体系是分层的，从底到上：

```
┌─────────────────────────────────────────┐
│  第 5 层：高级动画组件（你最常用）        │
│  - Hero / AnimatedSwitcher             │
│  - AnimatedContainer / AnimatedOpacity │ ← 隐式动画
│  - FadeTransition / ScaleTransition    │ ← 显式动画的便捷封装
├─────────────────────────────────────────┤
│  第 4 层：动画 Widget                   │
│  - AnimatedBuilder / AnimatedWidget    │
│  - CustomPainter + Listenable          │
├─────────────────────────────────────────┤
│  第 3 层：动画值系统                    │
│  - Animation<T>                        │
│  - Tween / CurveTween                  │
│  - Curves（曲线映射）                   │
├─────────────────────────────────────────┤
│  第 2 层：动画控制器                    │
│  - AnimationController                 │
│  - TabController（内部也有 Animation）  │
├─────────────────────────────────────────┤
│  第 1 层：逐帧驱动                      │
│  - Ticker                              │ ← 所有动画的心跳
├─────────────────────────────────────────┤
│  第 0 层：调度系统                      │
│  - SchedulerBinding                    │
│  - 屏幕 VSync 信号                      │
└─────────────────────────────────────────┘
```

**越往上，封装程度越高，你写的代码越少；越往下，控制力越强，但代码越多。**

---

## 二、逐个拆解：各类动画的 Ticker 来源

### 1. 显式动画：你直接接触 Ticker

显式动画就是你手动创建 `AnimationController` 的场景：

```
_controller = AnimationController(vsync: this, duration: Duration(seconds: 1));
```

**Ticker 来源：** 你通过 `vsync: this` 显式提供了 `TickerProvider`，`AnimationController` 内部创建 Ticker。

这条链路最清晰：

```
你 → 创建 AnimationController → 内部创建 Ticker → 逐帧驱动
```

### 2. 隐式动画：Ticker 藏在内部

隐式动画（`AnimatedContainer`、`AnimatedOpacity`、`AnimatedAlign` 等）看起来"自动"就动起来了，你不需要创建 controller，但**它们内部照样有 AnimationController 和 Ticker**。

以 `AnimatedContainer` 为例，它的内部大致是这样的：

```
// AnimatedContainer 内部（简化版）
class _AnimatedContainerState extends State<AnimatedContainer>
    with SingleTickerProviderStateMixin {  // ← 混入了！
  
  late AnimationController _controller;  // ← 内部自己创建了！

  @override
  void initState() {
    super.initState();
    _controller = AnimationController(
      vsync: this,  // ← 也用了 vsync
      duration: widget.duration,
    );
  }

  @override
  void didUpdateWidget(AnimatedContainer oldWidget) {
    super.didUpdateWidget(oldWidget);
    // 当属性变化时，自动启动动画
    if (widget.width != oldWidget.width) {
      _controller.forward(from: 0);
    }
  }
}
```

**Ticker 来源：** `AnimatedFoo` 内部的 State 自己 mixin 了 `SingleTickerProviderStateMixin`，自己创建了 `AnimationController`，自己管理 Ticker。

你看到的"隐式"，只是框架把 controller 的创建和管理**帮你做了**，底层机制完全一样。

### 3. Transition 系列：半显式半隐式

`FadeTransition`、`ScaleTransition`、`SlideTransition` 这些，你需要传一个 `Animation<double>` 进去：

```
FadeTransition(
  opacity: _animation,  // 你传一个 Animation 对象
  child: ...,
)
```

它们本身**不创建 Ticker**，而是**消费**你传进来的 Animation。Ticker 来自你创建的 `AnimationController`。

>
> 所以 Transition 系列本质上是"显式动画的 UI 封装"——驱动还是你提供的 controller，只是把动画值映射到具体属性的逻辑帮你写好了。

### 4. Hero 动画：跨路由的 Ticker

Hero 动画看起来很神奇——两个页面之间自动飞过去，但底层也是 Ticker 驱动的。

Hero 动画的 Ticker 来源比较特殊：

- 它不依赖某个具体页面的 State
- 它由 **Flutter 的导航器（Navigator）和 Overlay** 管理
- 内部同样有 `AnimationController`，用的是全局的 `TickerProvider`

```
// Hero 内部大致逻辑（简化版）
class _HeroFlightState extends State<_HeroFlight> with SingleTickerProviderStateMixin {
  late AnimationController _controller;
  
  @override
  void initState() {
    super.initState();
    _controller = AnimationController(
      vsync: this,
      duration: widget.flightShuttleBuilder != null ? ... : _kFlightDuration,
    );
    _controller.forward();  // 自动开始飞
  }
}
```

**本质没变：还是 Ticker + AnimationController。** 只是这个 controller 是 Hero 框架内部创建的，挂在 Overlay 上，跟着路由走。

### 5. 动画曲线（Curves）：和 Ticker 无关

`Curves.easeIn`、`Curves.bounceOut` 这些**不是驱动机制**，它们是**值的映射函数**。

```
Ticker 产生的是线性时间 → Curve 把它映射成非线性的值 → 最终动画值
```

比如 `Curves.easeIn` 就是一个数学函数：

- 输入 0.0 → 输出 0.0
- 输入 0.5 → 输出 0.25（前慢后快）
- 输入 1.0 → 输出 1.0

**Curves 不产生帧，不驱动动画，它只是"值的变形器"。** Ticker 才是"发动机"，Curves 是"变速箱"。

### 6. Tween：也和 Ticker 无关

`Tween` 同样是**值的映射**，和 Ticker 没有直接关系：

```
Ticker → AnimationController 产生 0.0~1.0 的值
                    ↓
              Tween.animate(controller)
                    ↓
         把 0.0~1.0 映射成 begin~end
```

Tween 是"值转换器"，不产生帧，不管理时间。

## 三、为什么所有动画都必须用 Ticker？

这是由 Flutter 的**渲染机制**决定的：

### Flutter 的渲染流水线

```
屏幕发出 VSync 信号（60/120/90 Hz）
    ↓
SchedulerBinding 调度帧
    ↓
Animate 阶段（动画更新值）
    ↓
Build 阶段（重建 Widget）
    ↓
Layout 阶段（计算布局）
    ↓
Paint 阶段（绘制）
    ↓
Composite 阶段（合成）
    ↓
Rasterize 阶段（光栅化）
    ↓
送到屏幕显示
```

**动画必须在"Animate 阶段"更新值**，这样才能保证：

1. **每一帧都更新一次**——不会多画（浪费）也不会少画（卡顿）
2. **更新时机正确**——在 build 之前更新，确保这一帧就能看到最新状态
3. **和屏幕同步**——60Hz 屏幕更新 60 次，120Hz 屏幕更新 120 次，自适应

如果不用 Ticker，用 `Timer` 或者 `while` 循环：

- 可能一帧更新多次（白做了）
- 可能几帧才更新一次（卡顿）
- 可能在 build 之后才更新（延迟一帧）
- 页面不可见了还在跑（浪费资源）

**所以 Ticker 不是"可选优化"，而是 Flutter 动画机制的必然选择。**

## 四、有没有例外？不用 Ticker 的动画？

严格来说，**所有"随时间变化的连续动画"都必须用 Ticker**。但有一些"看起来像动画"的东西，底层不是 Ticker：

### 1. 物理模拟动画（SpringSimulation 等）

`SpringSimulation`、`GravitySimulation` 这些物理模拟，**也是用 Ticker 驱动的**——只是动画值的计算方式不一样（不是线性插值，而是物理公式）。

```
// SpringSimulation 也是通过 AnimationController 驱动的
final simulation = SpringSimulation(
  SpringDescription(mass: 1, stiffness: 100, damping: 10),
  0.0,  // 起始位置
  1.0,  // 结束位置
  0.0,  // 初始速度
);
controller.animateWith(simulation);  // 内部还是 Ticker
```

`animateWith` 只是换了一种"计算每一帧的值"的方式，驱动还是 Ticker。

### 2. 手势驱动的动画（拖动、缩放）

比如你用手指拖动一个 widget：

- 拖动过程中，位置跟着手指走 → 这不是 Ticker 驱动的，是**手势事件**驱动的
- 松手后回弹 → 这是 Ticker 驱动的（用 `AnimationController` 或 `SpringSimulation`）

```
// 拖动时：手势驱动，不需要 Ticker
onPanUpdate: (details) {
  setState(() {
    _position += details.delta;  // 直接更新位置
  });
}

// 松手后：回弹动画，需要 Ticker
onPanEnd: (details) {
  _controller.forward();  // 内部用 Ticker
}
```

### 3. 逐帧动画（Sprite 动画）

如果你用 `AnimationController` 驱动帧切换，那还是 Ticker。

但如果你用 `Timer` 手动切换图片帧……那是 Timer，不是 Ticker。**但强烈不推荐这么做**，会有同步问题。

### 4. 滚动（Scrollable）

`ListView`、`ScrollView` 的滚动看起来也是"动"的，但它底层是 **手势 + 物理模拟 + SchedulerBinding** 驱动的，不经过 `AnimationController`，但**本质上还是每帧更新一次**（用的是 `ScrollActivity` 和 `ScrollPosition`，内部也注册了帧回调）。

可以理解为"另一种形式的 Ticker"——都是跟屏幕刷新走的，只是 API 不一样。

## 五、验证：怎么证明隐式动画用了 Ticker？

你可以做个实验：在 `AnimatedContainer` 动画进行中，按 Home 键把 App 退到后台。

```
AnimatedContainer(
  duration: Duration(seconds: 5),
  width: _width,
  color: Colors.blue,
)
```

**现象：** 动画会暂停，回到前台后继续。

**结论：** 这就是 Ticker 的 `muted` 机制在起作用——App 退后台时，Ticker 被自动静音。如果是 Timer 驱动的，退后台还会继续跑。

---

## 六、总结

| 动画类型 | 是否用 Ticker | Ticker 在哪 | 你能看到吗 |
| --- | --- | --- | --- |
| 显式动画（AnimationController） | ✅ 是 | 你自己创建的 controller 里 | 能，vsync: this |
| 隐式动画（AnimatedContainer 等） | ✅ 是 | widget 内部的 State 里 | 不能，被封装了 |
| Transition 系列（FadeTransition 等） | ✅ 是 | 你传的 Animation 里 | 半透明，你提供 controller |
| Hero 动画 | ✅ 是 | Hero 框架内部的 Overlay 里 | 不能，完全隐藏 |
| 物理模拟（SpringSimulation） | ✅ 是 | AnimationController 里 | 半透明 |
| 动画曲线（Curves） | ❌ 不是 | 纯数学映射函数 | N/A |
| Tween | ❌ 不是 | 纯值转换器 | N/A |
| 手势拖动 | ❌ 不是 | 手势事件驱动 | N/A |

**一句话总结：**

>
> **只要是"随时间自动变化的连续动画"，底层一定是 Ticker 驱动的。区别只是 Ticker 是你亲手创建的，还是框架帮你创建的。**

这就是为什么我前面说 Ticker 是 Flutter 动画的"心跳"——它是所有动画的底层动力源，上层各种花里胡哨的动画 API，本质上都是对 Ticker 的封装和抽象。
