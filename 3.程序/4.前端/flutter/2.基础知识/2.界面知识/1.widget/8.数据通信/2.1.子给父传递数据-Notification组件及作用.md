# Flutter 中的 Notification 组件详解

## 一、什么是 Notification

`Notification` 是 Flutter 中一种**从子节点向父节点（向上）传递信息**的机制。它与 `InheritedWidget`（向下传递数据）形成互补，共同构成了 Flutter 组件树中的数据双向通信体系。

简单来说：**子组件发出通知，祖先组件监听通知**。

---

## 二、核心机制

### 1. 传递方向

Notification 沿着 **Element 树向上冒泡**（从子到父），所有祖先节点都有机会收到通知。

### 2. 两个核心角色

| 角色 | 类 | 作用 |
| --- | --- | --- |
| 发送方 | `Notification`（及其子类） | 封装要传递的信息，调用 `dispatch(context)` 发出 |
| 接收方 | `NotificationListener<T>` | 监听指定类型的通知，通过 `onNotification` 回调处理 |

### 3. 传递过程

```
子组件 dispatch() 
    → 找到最近的 RenderObject 
    → 沿着 Element 树向上遍历 
    → 遇到匹配的 NotificationListener 就触发回调
    → 回调返回 true → 停止冒泡
    → 回调返回 false → 继续向上传递
```

---

## 三、Flutter 内置的 Notification 子类

Flutter 框架内部大量使用 Notification，常见的有：

### 1. ScrollNotification（滚动通知）

最常用的一类，用于监听滚动视图的状态变化：

- `ScrollStartNotification`：滚动开始
- `ScrollUpdateNotification`：滚动中（持续触发）
- `ScrollEndNotification`：滚动结束
- `UserScrollNotification`：用户滚动方向改变

```
NotificationListener<ScrollNotification>(
  onNotification: (notification) {
    if (notification is ScrollStartNotification) {
      print('开始滚动');
    } else if (notification is ScrollUpdateNotification) {
      print('滚动中: ${notification.metrics.pixels}');
    } else if (notification is ScrollEndNotification) {
      print('滚动结束');
    }
    return false; // 继续向上传递
  },
  child: ListView.builder(
    itemCount: 100,
    itemBuilder: (_, i) => ListTile(title: Text('Item $i')),
  ),
)
```

### 2. SizeChangedLayoutNotification

监听子组件尺寸变化。

### 3. LayoutChangedNotification

布局变化通知。

### 4. KeepAliveNotification

用于 `SliverChildBuilderDelegate` 的保活机制。

### 5. DraggableScrollableNotification

可拖动滚动组件的通知。

## 四、自定义 Notification

你可以创建自己的通知类型，用于业务层的组件间通信：

```
// 1. 定义通知类
class MyCustomNotification extends Notification {
  final String message;
  final int count;

  const MyCustomNotification(this.message, this.count);
}

// 2. 子组件中发送
class ChildWidget extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return ElevatedButton(
      onPressed: () {
        // 发送通知
        MyCustomNotification('按钮被点击了', 42).dispatch(context);
      },
      child: Text('发送通知'),
    );
  }
}

// 3. 父组件中监听
class ParentWidget extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return NotificationListener<MyCustomNotification>(
      onNotification: (notification) {
        print('收到通知: ${notification.message}, count: ${notification.count}');
        return true; // 返回 true 阻止继续向上传递
      },
      child: ChildWidget(),
    );
  }
}
```

## 五、NotificationListener 的关键属性

```
NotificationListener<T extends Notification>(
  {
    Key? key,
    required Widget child,
    required bool Function(T notification) onNotification,
  }
)
```

### onNotification 返回值的意义

- **返回 `true`**：通知被"消费"，**停止**向上冒泡
- **返回 `false`**：通知继续向上传递，更外层的祖先也能收到

```
// 多层监听示例
NotificationListener<ScrollNotification>(
  onNotification: (n) {
    print('外层收到通知');
    return false; // 外层返回 false，让内层也能收到（注意：实际是从内到外传递）
  },
  child: NotificationListener<ScrollNotification>(
    onNotification: (n) {
      print('内层收到通知');
      return true; // 内层返回 true，阻止向外层传递
    },
    child: ListView(...),
  ),
)
```

>
> **注意传递顺序**：通知从内向外传递，先触发最内层的 `NotificationListener`，再逐层向外。

## 六、实际应用场景

### 场景 1：滚动到顶部/底部检测

```
NotificationListener<ScrollNotification>(
  onNotification: (notification) {
    if (notification is ScrollEndNotification) {
      final metrics = notification.metrics;
      if (metrics.pixels >= metrics.maxScrollExtent) {
        print('已经滑到底部了，加载更多');
        // loadMore();
      }
      if (metrics.pixels <= metrics.minScrollExtent) {
        print('已经滑到顶部了，刷新数据');
        // refresh();
      }
    }
    return false;
  },
  child: ListView.builder(...),
)
```

### 场景 2：子组件向父组件传值（避免层层回调）

当嵌套层级很深时，用 Notification 替代一层层的 `callback` 传递，代码更简洁。

### 场景 3：监听键盘弹出/收起

配合 `MediaQuery` 或自定义通知，监听键盘状态变化。

### 场景 4：列表项点击事件冒泡

列表中某个 item 被点击，需要通知外层页面做跳转或状态更新。

## 七、与其他状态管理方式的对比

| 方案 | 传递方向 | 适用场景 | 性能 |
| --- | --- | --- | --- |
| **Notification** | 向上（子→父） | 事件通知、状态冒泡 | 轻量，按需触发 |
| **InheritedWidget** | 向下（父→子） | 共享数据、主题、配置 | 依赖变更时重建 |
| **Provider / Bloc** | 全局/跨层 | 复杂状态管理 | 功能强大，稍重 |
| **回调函数** | 向上（子→父） | 单层父子通信 | 最直接，但深层嵌套繁琐 |

---

## 八、注意事项

1. **泛型指定**：`NotificationListener<T>` 必须指定具体类型 `T`，否则监听不到。
2. **context 要求**：`dispatch(context)` 中的 context 必须是**子树中的 context**，确保通知能向上找到 listener。
3. **性能考量**：`ScrollUpdateNotification` 滚动时会高频触发，回调中避免做重计算。
4. **异步问题**：Notification 是同步传递的，`dispatch` 调用后立即遍历祖先树。
5. **不要滥用**：简单的父子通信用回调即可，Notification 更适合跨多层级的事件冒泡场景。

---

## 总结

Notification 是 Flutter 内置的**轻量级向上事件冒泡机制**，核心就三步：

1. 定义/选择 Notification 子类
2. 子组件调用 `dispatch(context)` 发送
3. 父组件用 `NotificationListener<T>` 监听并处理

它在滚动监听、自定义组件通信等场景中非常实用，是 Flutter 开发者必须掌握的基础组件之一。
