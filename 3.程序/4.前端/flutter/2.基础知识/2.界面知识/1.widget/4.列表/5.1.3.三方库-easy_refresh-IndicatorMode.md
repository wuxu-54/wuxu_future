# EasyRefresh `IndicatorMode` 完整枚举说明
>
> 适用 easy_refresh 3.x 版本
文件：`package:easy_refresh/easy_refresh.dart`

```dart
enum IndicatorMode {
  inactive,
  drag,
  armed,
  ready,
  processing,
  processed,
  done,
}
```

> 注意：Header（下拉刷新）、Footer（上拉加载）共用这套枚举，流转逻辑略有区别。

## 全部状态释义

### 1. `IndicatorMode.inactive`

**闲置状态 / 未触发**

- 列表正常滚动，没有拉出Header/Footer；offset = 0
- 视觉上：头部/底部组件应当隐藏 `SizedBox.shrink()`
- 触发时机：回弹完全结束、初始页面状态

### 2. `IndicatorMode.drag`

**拖拽中（未达到触发阈值）**

- 用户正在下拉/上拉，拉出距离 **小于 triggerOffset**
- 例子：下拉一点点，文案：`下拉刷新`
- 松手后直接回弹，**不会执行刷新/加载逻辑**

### 3. `IndicatorMode.armed`

**达到触发阈值（待命状态）**

- 拉出距离 **≥ triggerOffset**
- 此时松手就会触发刷新；继续拖拽依然保持该状态
- 文案建议：`释放立即刷新`

> ⚠️ 很多人容易混淆：`armed ≠ ready`
> armed = 拖拽到位等待松手；ready = 松手之后正式进入刷新预备

### 4. `IndicatorMode.ready`

**已经松手，准备进入执行阶段**

- 用户松开手指，框架准备执行 `onRefresh` / `onLoad`
- 持续时间很短，紧接着进入 `processing`

> 适合展示：保持「刷新中」动画过渡

### 5. `IndicatorMode.processing`

**正在执行业务逻辑（刷新/加载网络请求）**

- 网络请求、业务耗时操作进行中
- **重点状态！** 你调用 `controller.finishRefresh()` 之前一直处于这个状态
- UI：转圈加载动画

### 6. `IndicatorMode.processed`

**业务逻辑执行完毕，等待展示完成状态**

- 你调用 `finishRefresh()` 瞬间切换到此状态
- 短暂过渡态，马上进入 `done`

### 7. `IndicatorMode.done`

**完成展示阶段**

- 业务执行完成，展示「刷新成功/加载完成」UI
- 持续时长由 `finishRefreshDuration` 控制
- 倒计时结束后，开始回弹，最终切回 `inactive`

# Header【下拉刷新】标准状态流转顺序

```
inactive
    ↓（手指下拉）
drag →（拉到阈值）→ armed
    ↓（松手）
ready → processing（网络请求）
    ↓（调用finishRefresh()）
processed → done（展示完成文案）
    ↓（倒计时结束，回弹）
inactive
```

# Footer【上拉加载】补充差异

Footer 会多出 **noMore** 场景（无更多数据）
当调用 `controller.finishLoad(noMore: true)`
状态不会走到 `done`，会固定停留在无更多模式。

> 重点：`IndicatorMode` 没有单独的 noMore，无更多属于 Footer 独立参数判断，不是枚举状态。

# 结合你之前自定义Header踩坑说明

## 你遇到BUG根本原因复盘

流转：
`processing(刷新中)` → `processed` → `done(刷新完成)`
当 `done` 倒计时结束，页面回弹滚动，**状态会短暂回到 `drag`**
你的旧代码判断顺序：先判断进度progress，导致回弹瞬间切回「下拉刷新」，一闪而过。

✅ 正确状态判断优先级（从上到下）

1. done（最高优先级，刷新完成）
2. processing（请求中）
3. ready
4. armed
5. drag
6. inactive

## 开发实用判断模板（直接复制）

```dart
String text;
Widget icon;

if (mode == IndicatorMode.done) {
  text = "刷新完成";
  icon = const Icon(Icons.check);
} else if (mode == IndicatorMode.processing) {
  text = "正在刷新...";
  icon = const CircularProgressIndicator(strokeWidth:2);
} else if (mode == IndicatorMode.ready || mode == IndicatorMode.armed) {
  text = "释放刷新";
  icon = const Icon(Icons.arrow_upward);
} else if (mode == IndicatorMode.drag) {
  text = "下拉刷新";
  icon = const Icon(Icons.arrow_downward);
} else {
  // inactive
  return const SizedBox.shrink();
}
```

# 额外高频踩坑知识点

1. **不要依赖 offset/progress 覆盖状态判断！**
回弹过程 offset 变化剧烈，会干扰UI，状态枚举优先级更高。
2. `armed` 只在**手指按住拖拽**时存在；松手立刻变成 ready。
3. 如果不调用 `finishRefresh()`，会永久卡在 `processing`。
4. `finishRefreshDuration` 只控制 `done` 状态停留时长，调整这个参数可以让用户看清“刷新完成”文案。
