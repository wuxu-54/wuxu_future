# Widget宽高设置

在Flutter中，Widget的宽高行为始终遵循**「约束向下传递，尺寸向上传递」**的核心布局协议：父组件向子组件传递宽高约束（最小/最大宽度、最小/最大高度），子组件只能在该约束范围内决定自身尺寸。所有宽高设置的效果，都依赖于父组件的约束上下文，这也是很多“宽高设置不生效”问题的根源。

以下是按场景分类的宽高设置方案，包含用法、适用场景与常见坑点：

## 一、固定尺寸设置

### 1. `SizedBox`（轻量首选）

专门用于设置固定宽高的容器，无多余装饰属性，性能开销最低，是单纯限制尺寸的首选方案。

```dart
// 同时设置固定宽高
SizedBox(
  width: 100.0,
  height: 100.0,
  child: Container(color: Colors.blue),
);

// 仅限制宽度/高度
SizedBox(width: 100, child: ...);
SizedBox(height: 100, child: ...);

// 快捷构造：创建指定尺寸的SizedBox
SizedBox.fromSize(size: Size(100, 100), child: ...);
```

- **适用场景**：单纯需要固定尺寸的占位、间距、组件尺寸限制。
- **注意**：若父组件的最大约束小于设置的宽高，组件会被强制压缩到父约束范围内，设置值不生效。

### 2. `Container` 的 `width` / `height` 属性

`Container` 本质是组合了尺寸、装饰、内边距等能力的多功能容器，其宽高最终通过约束实现。

```dart
Container(
  width: 100.0,
  height: 100.0,
  color: Colors.blue,
  child: Text("固定尺寸"),
);
```

- **适用场景**：需要同时设置尺寸 + 背景、边框、圆角、内边距等装饰效果。
- **注意**：仅需尺寸限制时优先用 `SizedBox`，避免 `Container` 多余的绘制开销。

## 二、填充父容器尺寸

### 1. `double.infinity`

表示“尽可能大，填满父组件的可用空间”，本质是让组件取父约束的最大值。

```dart
Container(
  width: double.infinity, // 宽度填满父容器
  height: 200,
  color: Colors.green,
);
```

- **适用场景**：单方向撑满父容器，另一个方向固定。
- **高频坑点**：在滚动容器（`ListView`、`SingleChildScrollView`）的滚动方向上，父约束为无限大，此时设置 `double.infinity` 会触发布局溢出错误。

### 2. `SizedBox.expand`

快捷构造一个宽高都填满父容器的组件，等价于 `width: double.infinity` + `height: double.infinity`。

```dart
SizedBox.expand(
  child: Container(color: Colors.green),
);
```

### 3. `Expanded` 与 `Flexible`（Flex布局专属）

在 `Row`、`Column`、`Flex` 等弹性布局中，按比例分配剩余空间，是弹性布局下控制尺寸的核心方式。

```dart
Row(
  children: [
    // Expanded：强制填满分配的空间
    Expanded(
      flex: 2, // 占2份
      child: Container(color: Colors.red),
    ),
    // Flexible：默认不强制填满，子组件可小于分配空间
    Flexible(
      flex: 1, // 占1份
      fit: FlexFit.loose, // 宽松模式，子组件按需取尺寸
      child: Container(color: Colors.blue, width: 50),
    ),
  ],
)
```

- **核心区别**：
  - `Expanded` 是 `Flexible(fit: FlexFit.tight)` 的简写，强制子组件填满分配的空间；
  - `Flexible` 默认 `fit: FlexFit.loose`，子组件最大为分配空间，可按需缩小。
- **适用场景**：横向/纵向按比例分配空间、自适应屏幕宽度的布局。

## 三、比例与相对尺寸

### 1. `FractionallySizedBox`（父容器比例）

根据父组件的可用尺寸，按比例设置子组件的宽高，比例是相对于父组件的最大约束。

```dart
FractionallySizedBox(
  widthFactor: 0.8,  // 宽度 = 父容器最大宽度 × 0.8
  heightFactor: 0.5, // 高度 = 父容器最大高度 × 0.5
  alignment: Alignment.center,
  child: Container(color: Colors.orange),
);
```

- **适用场景**：子组件尺寸按父容器百分比适配，不依赖屏幕全局尺寸。
- **注意**：`widthFactor` / `heightFactor` 为 `null` 时，对应方向使用子组件自身尺寸。

### 2. `AspectRatio`（固定宽高比）

强制子组件按照指定的宽高比渲染，始终先遵守父约束，再按比例计算尺寸。

```dart
AspectRatio(
  aspectRatio: 16 / 9, // 宽:高 = 16:9
  child: Container(
    color: Colors.red,
    child: Image.network("xxx", fit: BoxFit.cover),
  ),
);
```

- **计算逻辑**：优先在父约束内取一个方向的最大值，再按比例算出另一方向。例如父容器最大宽度为360，则高度 = 360 ÷ 16 × 9。
- **适用场景**：图片、视频、卡片等需要固定比例的容器。

### 3. `MediaQuery`（屏幕尺寸比例）

获取屏幕全局尺寸，基于屏幕百分比设置组件宽高，属于全局响应式方案。

```dart
@override
Widget build(BuildContext context) {
  // 获取屏幕逻辑尺寸
  Size screenSize = MediaQuery.of(context).size;
  // 扣除状态栏、底部安全区后的可用高度
  double safeHeight = screenSize.height 
      - MediaQuery.of(context).padding.top 
      - MediaQuery.of(context).padding.bottom;
  
  return Container(
    width: screenSize.width * 0.8, // 屏幕宽度的80%
    height: safeHeight * 0.3,
    color: Colors.blue,
  );
}
```

- **适用场景**：全局级别的响应式适配、基于屏幕的尺寸计算。
- **注意**：
  - 直接使用 `size.height` 会包含状态栏、导航栏、键盘高度，用于布局时需扣除 `padding` 和 `viewInsets`；
  - 局部布局优先用 `LayoutBuilder` 或 `FractionallySizedBox`，避免依赖全局屏幕尺寸。

## 四、约束限制类

### 1. `ConstrainedBox` + `BoxConstraints`

对子组件施加额外的宽高约束（最小/最大宽高），子组件最终尺寸必须同时满足父约束和该约束（取交集）。

```dart
ConstrainedBox(
  // 约束：宽度100~200，高度50~100
  constraints: BoxConstraints(
    minWidth: 100,
    maxWidth: 200,
    minHeight: 50,
    maxHeight: 100,
  ),
  child: Container(
    width: 300, // 超出maxWidth，最终被限制为200
    color: Colors.purple,
  ),
);
```

#### 常用命名构造函数

- `BoxConstraints.tight(Size(100, 100))`：紧约束，强制子组件尺寸严格等于指定值；
- `BoxConstraints.loose(Size(200, 200))`：松约束，子组件最大不超过指定尺寸，最小为0；
- `BoxConstraints.expand()`：紧约束，强制填满父容器。

### 2. `LimitedBox`（无限约束下的限制）

仅当组件在某个轴上受到**无限约束**时（如ListView的滚动方向），才将该轴的最大尺寸限制为指定值。

```dart
ListView(
  children: [
    LimitedBox(
      maxHeight: 200, // 垂直滚动时，限制子组件最大高度为200
      child: Container(color: Colors.teal),
    ),
  ],
)
```

- **适用场景**：滚动容器内的自适应组件，防止子组件因无限约束而无限拉伸。

### 3. `UnconstrainedBox`（解除父约束）

解除父组件传递的约束，允许子组件按自身固有尺寸渲染，不受父约束限制。

```dart
UnconstrainedBox(
  alignment: Alignment.center,
  child: Container(
    width: 300, // 即使父容器宽度只有200，也按300渲染
    height: 100,
    color: Colors.red,
  ),
)
```

- **注意**：若子组件尺寸超过父容器，会出现溢出警告；生产环境可配合裁剪组件使用。

## 五、内容自适应类

### 1. `IntrinsicWidth` / `IntrinsicHeight`

让子组件按照其**固有尺寸**渲染，常用于让多个子组件统一尺寸。

```dart
// 让Row内所有子组件的高度，统一为最高子项的高度
IntrinsicHeight(
  child: Row(
    crossAxisAlignment: CrossAxisAlignment.stretch,
    children: [
      Container(width: 50, color: Colors.blue, height: 80),
      Container(width: 50, color: Colors.red, height: 120),
      // 分割线自动撑满整个Row的高度
      VerticalDivider(width: 1, color: Colors.grey),
    ],
  ),
)
```

- **适用场景**：行内分割线等高、文字宽度对齐、多组件尺寸统一。
- **性能警告**：该组件会触发两次布局（先遍历子项计算固有尺寸，再二次布局），长列表中慎用，避免性能损耗。

### 2. `FittedBox`（缩放适配）

在自身约束范围内，对子组件进行缩放与对齐，不改变子组件的逻辑尺寸，仅做视觉缩放。

```dart
FittedBox(
  fit: BoxFit.contain, // 缩放模式
  alignment: Alignment.center,
  child: Text(
    "超长文字自动缩放",
    style: TextStyle(fontSize: 100),
  ),
)
```

#### 常用 `BoxFit` 模式

| 模式 | 效果 |
|------|------|
| `contain` | 等比例缩放，完整显示子组件，可能留白 |
| `cover` | 等比例缩放，填满容器，可能裁剪子组件 |
| `fill` | 不等比例拉伸，完全填满容器，会变形 |
| `fitWidth` | 宽度适配容器，高度等比例缩放 |
| `fitHeight` | 高度适配容器，宽度等比例缩放 |
| `scaleDown` | 仅缩小不放大，子组件小于容器时按原尺寸显示 |

- **适用场景**：文字自适应缩放、图标/图片适配容器、大尺寸组件压缩显示。

## 六、动态响应式尺寸

### `LayoutBuilder`

通过回调获取父组件传递的实时约束，根据约束动态构建不同尺寸的子组件。

```dart
LayoutBuilder(
  builder: (BuildContext context, BoxConstraints constraints) {
    // 根据父容器宽度切换布局
    if (constraints.maxWidth > 600) {
      // 宽屏：双列布局
      return Row(
        children: [
          Expanded(child: Container(color: Colors.red)),
          Expanded(child: Container(color: Colors.blue)),
        ],
      );
    } else {
      // 窄屏：单列布局
      return Column(
        children: [
          Container(color: Colors.red, height: 100),
          Container(color: Colors.blue, height: 100),
        ],
      );
    }
  },
)
```

- **与 `MediaQuery` 的区别**：`LayoutBuilder` 获取的是**父组件的局部约束**，而非全局屏幕尺寸，更适合局部响应式布局。
- **适用场景**：自适应宽度的响应式布局、根据父容器尺寸动态调整子组件。

## 核心注意事项与常见问题

### 1. 宽高不生效？先查约束

绝大多数“设置宽高无效”的问题，都源于父组件的紧约束：

- 若父组件传递紧约束（`minWidth == maxWidth` 且 `minHeight == maxHeight`），子组件无论设置什么宽高，都会强制等于父约束尺寸。
- 典型场景：`Scaffold` 的 `body` 本身是松约束，但如果子组件嵌套了 `SizedBox.expand`，就会变成紧约束。

### 2. 性能优化建议

- 单纯限制尺寸优先用 `SizedBox`，避免无意义的 `Container` 嵌套。
- 长列表中避免使用 `IntrinsicWidth` / `IntrinsicHeight`，其二次布局会显著影响滚动性能。
- 避免在 `build` 方法中重复计算尺寸，可将计算结果缓存到 `initState` 或局部变量。

### 3. 选型速查表

| 需求场景 | 推荐组件 |
|----------|----------|
| 固定宽高、轻量占位 | `SizedBox` |
| 固定尺寸 + 装饰效果 | `Container` |
| 弹性布局按比例分配空间 | `Expanded` / `Flexible` |
| 按父容器百分比设置尺寸 | `FractionallySizedBox` |
| 固定宽高比（如图片、视频） | `AspectRatio` |
| 限制最大/最小宽高 | `ConstrainedBox` |
| 滚动容器内限制最大尺寸 | `LimitedBox` |
| 文字/组件自动缩放适配 | `FittedBox` |
| 子组件按内容统一尺寸 | `IntrinsicWidth` / `IntrinsicHeight` |
| 根据父容器动态适配布局 | `LayoutBuilder` |
| 全局屏幕比例适配 | `MediaQuery` |
