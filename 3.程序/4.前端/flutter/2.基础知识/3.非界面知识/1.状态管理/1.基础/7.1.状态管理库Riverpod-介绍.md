# Riverpod 完整指南：从配置到真实场景全流程

Riverpod 是 Flutter/Dart 生态中最强大的状态管理库之一，由 **Rémi Rousselet**（Freezed、Provider 同一作者）开发。它是 Provider 的"进化版"，解决了 Provider 依赖 BuildContext、运行时异常、难以测试等痛点，同时引入了代码生成、自动销毁、异步状态统一封装等现代特性。

---

## 一、为什么选择 Riverpod

| 痛点 | Riverpod 解决方案 |
| --- | --- |
| Provider 依赖 BuildContext，跨层传递麻烦 | 完全不依赖 context，Provider 全局可访问 |
| Provider 找不到时运行时报错 | 编译期安全，类型安全 |
| 状态难以测试 | ProviderContainer 可独立测试，支持 override 注入 |
| 异步状态处理繁琐（loading/error/data） | AsyncValue 统一封装，`when` 穷尽匹配 |
| 内存泄漏风险 | autoDispose 自动销毁不再使用的状态 |
| 相同逻辑难以复用 | family 修饰符参数化 Provider |
| 依赖注入不灵活 | override 机制，可在任意层级替换实现 |

**核心设计理念**：

- **可编译安全**：所有 Provider 在编译期就确定，不会有运行时找不到的问题
- **单向数据流**：状态由 Provider 持有，UI 只读，通过 Notifier 修改
- **声明式**：Provider 之间的依赖关系是声明式的，自动追踪和更新
- **可测试**：每个 Provider 都可以独立测试和替换

## 二、环境配置

### 2.1 添加依赖

**标准写法（手动定义 Provider）**：

```
dependencies:
  flutter:
    sdk: flutter
  flutter_riverpod: ^3.3.0    # 核心包

dev_dependencies:
  flutter_test:
    sdk: flutter
```

**推荐写法（代码生成 + lint）**：

```
dependencies:
  flutter:
    sdk: flutter
  flutter_riverpod: ^3.3.0
  riverpod_annotation: ^3.0.0   # 注解包

dev_dependencies:
  flutter_test:
    sdk: flutter
  build_runner: ^2.4.0          # 代码生成引擎
  riverpod_generator: ^3.0.0    # Riverpod 代码生成器
  custom_lint: ^0.6.0           # lint 引擎
  riverpod_lint: ^3.1.0         # Riverpod 代码检查规则
```

命令行一键安装：

```
# 基础版
flutter pub add flutter_riverpod

# 完整版（代码生成 + lint）
flutter pub add flutter_riverpod riverpod_annotation
flutter pub add dev:build_runner dev:riverpod_generator dev:custom_lint dev:riverpod_lint
```

### 2.2 四个核心包的职责

| 包 | 作用 |
| --- | --- |
| `flutter_riverpod` | 核心库，提供 Provider、ConsumerWidget、ProviderScope 等 |
| `riverpod_annotation` | 提供 `@riverpod`、`@Riverpod()` 等注解 |
| `riverpod_generator` | 代码生成器，根据注解自动生成 Provider 定义 |
| `riverpod_lint` | 代码检查规则，帮你写出符合最佳实践的代码 |

### 2.3 配置 ProviderScope

在应用根节点包裹 `ProviderScope`：

```
void main() {
  runApp(
    const ProviderScope(    // 必须包裹根 Widget
      child: MyApp(),
    ),
  );
}
```

`ProviderScope` 是所有 Provider 的容器，负责存储状态和管理生命周期。

### 2.4 配置 riverpod\_lint

在项目根目录创建 `analysis_options.yaml`：

```
analyzer:
  plugins:
    - custom_lint

custom_lint:
  rules:
    # 启用所有 riverpod_lint 规则（推荐）
    - riverpod_all_providers_depend_on_ref
    - riverpod_avoid_manual_providers
    - riverpod_provider_parameters
    # ... 更多规则

linter:
  rules:
    - prefer_const_constructors
    # ... 其他 lint 规则
```

或者更简单，直接启用所有规则：

```
analyzer:
  plugins:
    - custom_lint
```

### 2.5 运行代码生成

```
# 单次生成
dart run build_runner build

# 监听模式（开发时推荐）
dart run build_runner watch

# 清除缓存后重新生成
dart run build_runner build --delete-conflicting-outputs
```

## 三、核心概念

### 3.1 Provider（提供者）

Provider 是 Riverpod 的核心概念，它是一个**状态的封装**。每个 Provider：

- 持有一份状态（数据）
- 可以被其他 Provider 或 Widget 监听
- 状态变化时自动通知监听者重建

Provider 是**全局声明**的，但状态是**存储在 ProviderContainer 中**的，所以可以被 override 和测试。

### 3.2 ProviderScope / ProviderContainer

- `ProviderScope`：Flutter 端的容器 Widget，包裹应用根节点
- `ProviderContainer`：Dart 端的底层容器，ProviderScope 内部就是用它

所有 Provider 的状态都存储在容器中。不同的容器可以有不同的状态（比如测试时用假数据）。

### 3.3 Ref（引用）

`Ref` 是操作 Provider 的"遥控器"，每个 Provider 创建时都会获得一个 ref，通过它可以：

- 读取其他 Provider 的状态
- 监听其他 Provider 的变化
- 监听自身销毁事件
- 使 Provider 失效、刷新

`WidgetRef` 是 Flutter Widget 中使用的 ref，功能和 Ref 类似，但绑定了 Widget 的生命周期。

### 3.4 Provider 生命周期

1. **创建**：第一次被 `watch` / `read` 时创建状态
2. **存活**：有监听者时保持活跃
3. **销毁**（autoDispose）：所有监听者都移除后，自动销毁状态
4. **重新创建**：再次被监听时重新创建

>
> **注意**：使用代码生成时，Provider **默认开启 autoDispose**，即没有监听者时自动销毁。

## 四、所有 Provider 类型详解

Riverpod 提供了多种 Provider，适用于不同场景。**选择原则**：根据你的状态是"同步/异步"、"可变/不可变"来选。

### 4.1 Provider — 只读依赖（不可变）

**场景**：注入服务、仓库、配置等不会变化的对象。

```
// 手动写法
final loggerProvider = Provider<Logger>((ref) => Logger());

// 代码生成写法
@riverpod
Logger logger(LoggerRef ref) => Logger();
```

使用：

```
final logger = ref.watch(loggerProvider);
logger.log('hello');
```

### 4.2 StateProvider — 简单可变状态

**场景**：简单的单一值状态，如计数器、开关、当前选中项。

```
// 手动写法
final counterProvider = StateProvider<int>((ref) => 0);

// 代码生成写法
@riverpod
class Counter extends _$Counter {
  @override
  int build() => 0;

  void increment() => state++;
  void decrement() => state--;
}
```

使用：

```
// 读取值
final count = ref.watch(counterProvider);

// 修改值
ref.read(counterProvider.notifier).state++;
// 或
ref.read(counterProvider.notifier).update((state) => state + 1);
```

>
> **注意**：StateProvider 在 Riverpod 3.x 中已标记为 legacy（遗留），推荐用 Notifier 替代。

### 4.3 NotifierProvider — 复杂同步可变状态 ⭐

**场景**：需要多个方法修改的复杂状态，如 Todo 列表、购物车、表单状态。

这是 **Riverpod 最常用的 Provider**，替代了旧的 StateNotifierProvider。

```
// 手动写法
final todoListProvider = NotifierProvider<TodoListNotifier, List<Todo>>(
  TodoListNotifier.new,
);

class TodoListNotifier extends Notifier<List<Todo>> {
  @override
  List<Todo> build() => [];  // 初始状态

  void add(Todo todo) {
    state = [...state, todo];
  }

  void toggle(String id) {
    state = [
      for (final todo in state)
        if (todo.id == id) todo.copyWith(completed: !todo.completed)
        else todo,
    ];
  }

  void remove(String id) {
    state = state.where((todo) => todo.id != id).toList();
  }
}
```

**代码生成写法（推荐）**：

```
part 'todo_provider.g.dart';

@riverpod
class TodoList extends _$TodoList {
  @override
  List<Todo> build() => [];

  void add(Todo todo) {
    state = [...state, todo];
  }

  void toggle(String id) {
    state = state.map((todo) {
      return todo.id == id ? todo.copyWith(completed: !todo.completed) : todo;
    }).toList();
  }
}
```

使用：

```
// 监听状态
final todos = ref.watch(todoListProvider);

// 调用方法
ref.read(todoListProvider.notifier).add(Todo(id: '1', title: '学习 Riverpod'));
```

### 4.4 FutureProvider — 异步一次性数据（不可变）

**场景**：单次异步请求，如获取用户信息、加载配置。

```
// 手动写法
final userProvider = FutureProvider<User>((ref) async {
  final repo = ref.watch(userRepositoryProvider);
  return repo.fetchUser();
});

// 代码生成写法
@riverpod
Future<User> user(UserRef ref) async {
  final repo = ref.watch(userRepositoryProvider);
  return repo.fetchUser();
}
```

使用：

```
final userAsync = ref.watch(userProvider);

return userAsync.when(
  data: (user) => Text(user.name),
  loading: () => const CircularProgressIndicator(),
  error: (error, stackTrace) => Text('错误: $error'),
);
```

### 4.5 AsyncNotifierProvider — 异步可变状态 ⭐⭐

**场景**：异步初始化 + 可以修改的状态，如文章列表（可刷新、可加载更多、可删除）。

这是 **实际项目中最常用的 Provider 类型**。

```
part 'articles_provider.g.dart';

@riverpod
class Articles extends _$Articles {
  @override
  Future<List<Article>> build() async {
    // 初始化时获取数据
    final repo = ref.watch(articlesRepositoryProvider);
    return repo.fetchArticles();
  }

  /// 刷新列表
  Future<void> refresh() async {
    state = const AsyncValue.loading();
    final repo = ref.read(articlesRepositoryProvider);
    state = await AsyncValue.guard(() => repo.fetchArticles());
  }

  /// 添加文章
  Future<void> addArticle(String title) async {
    final repo = ref.read(articlesRepositoryProvider);
    // guard 自动捕获异常，转为 AsyncError
    state = await AsyncValue.guard(() async {
      await repo.create(title);
      return repo.fetchArticles();
    });
  }

  /// 加载更多
  Future<void> loadMore() async {
    final current = state.valueOrNull ?? [];
    final repo = ref.read(articlesRepositoryProvider);
    state = await AsyncValue.guard(() async {
      final more = await repo.fetchMore(page: current.length ~/ 20 + 1);
      return [...current, ...more];
    });
  }
}
```

使用：

```
final articlesAsync = ref.watch(articlesProvider);

return articlesAsync.when(
  data: (articles) => ListView.builder(
    itemCount: articles.length,
    itemBuilder: (context, index) => ListTile(title: Text(articles[index].title)),
  ),
  loading: () => const Center(child: CircularProgressIndicator()),
  error: (error, _) => Center(child: Text('加载失败: $error')),
);
```

### 4.6 StreamProvider — 流式数据（不可变）

**场景**：实时数据流，如 WebSocket、Firebase 实时数据库、计时器。

```
// 手动写法
final clockProvider = StreamProvider<DateTime>((ref) {
  return Stream.periodic(const Duration(seconds: 1), (_) => DateTime.now());
});

// 代码生成写法
@riverpod
Stream<DateTime> clock(ClockRef ref) {
  return Stream.periodic(const Duration(seconds: 1), (_) => DateTime.now());
}
```

使用和 FutureProvider 一样，用 `when` 处理三种状态。

### 4.7 StreamNotifierProvider — 流式可变状态

**场景**：需要主动控制的流式数据，如聊天消息列表（可以发送消息、接收消息）。

```
@riverpod
class ChatMessages extends _$ChatMessages {
  @override
  Stream<List<Message>> build(String roomId) {
    final socket = ref.watch(socketServiceProvider);
    return socket.messagesStream(roomId);
  }

  Future<void> sendMessage(String content) async {
    final socket = ref.read(socketServiceProvider);
    await socket.send(roomId, content);
  }
}
```

### 4.8 Provider 选型速查表

| Provider 类型 | 同步/异步 | 可变/不可变 | 适用场景 |
| --- | --- | --- | --- |
| `Provider` | 同步 | 不可变 | 服务、仓库、配置注入 |
| `StateProvider` | 同步 | 可变（简单） | 计数器、开关、选中项（legacy） |
| `NotifierProvider` | 同步 | 可变（复杂） | Todo列表、购物车、表单 |
| `FutureProvider` | 异步 | 不可变 | 单次 API 请求 |
| `AsyncNotifierProvider` | 异步 | 可变 | 列表页、详情页（可刷新/操作） |
| `StreamProvider` | 流式 | 不可变 | WebSocket、实时数据 |
| `StreamNotifierProvider` | 流式 | 可变 | 聊天、实时可操作数据 |

## 五、代码生成详解（riverpod\_generator）

Riverpod 2.0+ 强烈推荐使用代码生成，它能：

- 自动推断 Provider 类型（不用手动选 FutureProvider 还是 NotifierProvider）
- 自动生成正确的泛型类型
- 支持 family 参数自动生成
- 减少样板代码

### 5.1 函数式 Provider

最简单的写法，给函数加 `@riverpod` 注解：

```
part 'providers.g.dart';

// 普通 Provider
@riverpod
String appName(AppNameRef ref) => '我的应用';

// FutureProvider（返回 Future 自动识别）
@riverpod
Future<User> user(UserRef ref, int userId) async {
  final repo = ref.watch(userRepositoryProvider);
  return repo.fetchUser(userId);
}

// StreamProvider（返回 Stream 自动识别）
@riverpod
Stream<int> timer(TimerRef ref) {
  return Stream.periodic(const Duration(seconds: 1), (i) => i);
}
```

生成的 Provider 名字：函数名 + `Provider` 后缀

- `appName` → `appNameProvider`
- `user` → `userProvider`

### 5.2 类式 Notifier

给类加 `@riverpod` 注解，继承 `_$类名`：

```
part 'counter.g.dart';

@riverpod
class Counter extends _$Counter {
  @override
  int build() => 0;  // build 方法返回初始状态

  void increment() => state++;
  void decrement() => state--;
}
```

AsyncNotifier 同理：

```
@riverpod
class Products extends _$Products {
  @override
  Future<List<Product>> build() async {
    final repo = ref.watch(productsRepositoryProvider);
    return repo.fetchAll();
  }

  Future<void> refresh() async {
    state = const AsyncLoading();
    state = await AsyncValue.guard(
      () => ref.read(productsRepositoryProvider).fetchAll(),
    );
  }
}
```

### 5.3 @Riverpod 注解配置

`@Riverpod()` 可以传参数自定义行为：

```
@Riverpod(
  keepAlive: true,          // 保持状态，不自动销毁（默认 false）
  dependencies: [           // 声明依赖，用于 lint 检查
    userRepositoryProvider,
  ],
)
class UserProfile extends _$UserProfile {
  @override
  Future<User> build() async {
    // ...
  }
}
```

| 参数 | 作用 | 默认值 |
| --- | --- | --- |
| `keepAlive` | 是否保持状态（关闭 autoDispose） | `false`（代码生成默认自动销毁） |
| `dependencies` | 声明依赖的 Provider，用于 lint | 无 |

### 5.4 命名约定

- 函数式 Provider：函数名用小写开头，生成 `xxxProvider`
- 类式 Notifier：类名用大写开头，生成 `xxxProvider`
- Ref 类型：函数名 + `Ref`，如 `userProvider` 对应 `UserRef`

## 六、Ref 方法全解

`Ref` 是操作 Provider 的核心，所有方法都通过它调用。

### 6.1 watch — 监听状态变化

**最常用的方法**。监听 Provider，状态变化时触发重建。

```
// 监听值
final count = ref.watch(counterProvider);

// 监听 Notifier（不推荐在 build 中用 notifier）
final notifier = ref.watch(counterProvider.notifier);
```

**规则**：

- ✅ 在 `build` 方法中使用
- ✅ 在另一个 Provider 的 `build` 中使用
- ❌ 不要在回调函数（如 `onPressed`）中用，用 `read` 代替

### 6.2 read — 一次性读取

读取当前值，**不监听**变化。适合在事件回调中使用。

```
ElevatedButton(
  onPressed: () {
    // 读取当前值，不监听变化
    final count = ref.read(counterProvider);
    print('当前计数: $count');

    // 读取 Notifier 并调用方法
    ref.read(counterProvider.notifier).increment();
  },
  child: const Text('增加'),
)
```

### 6.3 listen — 监听变化（副作用）

监听 Provider 变化，执行副作用（如弹 SnackBar、导航）。**不会触发重建**。

```
@override
Widget build(BuildContext context, WidgetRef ref) {
  // 监听用户登录状态变化
  ref.listen(authProvider, (previous, next) {
    next.whenOrNull(
      authenticated: (user) {
        ScaffoldMessenger.of(context).showSnackBar(
          SnackBar(content: Text('欢迎回来，${user.name}')),
        );
      },
      error: (message) {
        ScaffoldMessenger.of(context).showSnackBar(
          SnackBar(content: Text(message)),
        );
      },
    );
  });

  return const Scaffold(body: LoginForm());
}
```

`listen` 会自动在 Widget 销毁时取消监听，不用担心内存泄漏。

### 6.4 invalidate — 使 Provider 失效

标记 Provider 为"需要重新计算"，下次读取时会重新执行 `build`。

```
// 刷新用户数据
ref.invalidate(userProvider);
```

**特点**：

- 不立即重新计算，下次 `watch`/`read` 时才重新计算
- 不返回新值
- 适合"标记为脏，下次读取时自动刷新"的场景

### 6.5 refresh — 立即刷新

立即重新计算 Provider，并返回新值。

```
// 立即刷新并获取新值
final newValue = ref.refresh(userProvider);
```

**特点**：

- 立即重新计算
- 返回新的 Future/值
- 适合"手动刷新按钮"的场景

**invalidate vs refresh 怎么选**：

- 只需要标记为脏，下次读取自动刷新 → `invalidate`
- 需要立即拿到新值 → `refresh`
- UI 上的下拉刷新 → `invalidate`（配合 `RefreshIndicator`）

### 6.6 onDispose — 销毁回调

监听 Provider 自身的销毁事件，做清理工作。

```
@riverpod
StreamController<int> timer(TimerRef ref) {
  final controller = StreamController<int>();
  final timer = Timer.periodic(const Duration(seconds: 1), (t) {
    controller.add(t.tick);
  });

  // Provider 销毁时自动关闭
  ref.onDispose(() {
    timer.cancel();
    controller.close();
  });

  return controller;
}
```

### 6.7 keepAlive — 临时保持存活

在 autoDispose 的 Provider 中，临时阻止自动销毁。

```
@riverpod
Future<User> user(UserRef ref, int id) async {
  final user = await fetchUser(id);

  // 数据加载成功后，保持状态不被销毁
  final keepAlive = ref.keepAlive();
  ref.onDispose(keepAlive.close);

  return user;
}
```

### 6.8 mounted — 检查是否仍挂载（Riverpod 3.x）

异步操作完成后，检查 Provider 是否还在，避免在销毁后设置状态。

```
@riverpod
class UserProfile extends _$UserProfile {
  @override
  Future<User> build(String userId) async {
    final response = await api.getUser(userId);

    // 异步间隙后检查是否仍挂载
    if (!ref.mounted) return state.value!;

    return User.fromJson(response.data);
  }
}
```

### 6.9 方法对比总结

| 方法 | 监听变化 | 触发重建 | 返回值 | 适用场景 |
| --- | --- | --- | --- | --- |
| `watch` | ✅ | ✅ | 当前值 | build 中获取响应式数据 |
| `read` | ❌ | ❌ | 当前值 | 回调中一次性读取 |
| `listen` | ✅ | ❌ | 无 | 副作用（弹框、导航） |
| `invalidate` | - | - | 无 | 标记为脏，下次自动刷新 |
| `refresh` | - | - | 新值 | 立即刷新并获取结果 |
| `onDispose` | - | - | 无 | 清理资源 |
| `keepAlive` | - | - | 无 | 临时阻止自动销毁 |
| `mounted` | - | - | bool | 异步后检查是否存活 |

## 七、修饰符（Modifiers）

### 7.1 autoDispose — 自动销毁

**代码生成默认开启**。当 Provider 没有任何监听者时，自动销毁状态。

**手动写法**：

```
final userProvider = FutureProvider.autoDispose<User>((ref) async {
  return fetchUser();
});
```

**代码生成写法**：

```
// 默认就是 autoDispose（keepAlive: false）
@riverpod
Future<User> user(UserRef ref) async => fetchUser();

// 关闭 autoDispose（保持状态）
@Riverpod(keepAlive: true)
Future<User> user(UserRef ref) async => fetchUser();
```

**适用场景**：

- ✅ 页面级别的临时状态（离开页面就销毁）
- ✅ 搜索结果（每次搜索重新获取）
- ✅ 详情页数据（不同 ID 不同实例）
- ❌ 全局状态（如登录状态、主题）

### 7.2 family — 参数化 Provider

让 Provider 接受参数，根据参数生成不同的状态实例。

**手动写法**：

```
final userProvider = FutureProvider.autoDispose.family<User, int>((ref, userId) async {
  return fetchUser(userId);
});
```

**代码生成写法（推荐）**：

```
@riverpod
Future<User> user(UserRef ref, {required int userId}) async {
  final repo = ref.watch(userRepositoryProvider);
  return repo.fetchUser(userId);
}
```

使用：

```
// 传入参数
final userAsync = ref.watch(userProvider(userId: 123));
```

**family 的缓存机制**：

- 相同参数 → 复用同一个状态实例
- 不同参数 → 不同的状态实例
- 配合 autoDispose → 没有监听者时自动销毁该参数的实例

**多参数 family**：

代码生成天然支持多个参数：

```
@riverpod
Future<List<Post>> posts(
  PostsRef ref, {
  required int page,
  required int pageSize,
  String? keyword,
}) async {
  return api.getPosts(page: page, pageSize: pageSize, keyword: keyword);
}
```

使用：

```
final posts = ref.watch(postsProvider(page: 1, pageSize: 20, keyword: 'flutter'));
```

### 7.3 autoDispose + family 组合

这是最常用的组合，代码生成默认就是这种模式：

```
@riverpod
Future<Article> article(ArticleRef ref, String id) async {
  return api.getArticle(id);
}
```

- 不同的 `id` → 不同的 Article 实例
- 页面离开 → 自动销毁
- 再次进入相同 id → 重新获取（除非 keepAlive）

## 八、AsyncValue 详解

`AsyncValue` 是 Riverpod 对异步状态的统一封装，替代了手写 loading/error/data 的三重判断。它是一个 **sealed class**（联合类型），有三个子类：

- `AsyncData`：成功，携带数据
- `AsyncLoading`：加载中
- `AsyncError`：失败，携带错误和堆栈

### 8.1 when — 穷尽匹配

最常用的方法，必须处理所有三种状态：

```
final asyncValue = ref.watch(userProvider);

return asyncValue.when(
  data: (user) => Text(user.name),       // 成功
  loading: () => const CircularProgressIndicator(), // 加载中
  error: (error, stackTrace) => Text('错误: $error'), // 失败
);
```

**when 的可选参数**：

```
asyncValue.when(
  data: (data) => Text('$data'),
  loading: () => const CircularProgressIndicator(),
  error: (error, stack) => Text('$error'),
  skipLoadingOnReload: true,   // 重新加载时不显示 loading，显示旧数据
  skipLoadingOnRefresh: true,  // 手动刷新时不显示 loading
  skipError: false,            // 是否跳过错误状态
);
```

### 8.2 whenData — 只处理数据态

只关心成功时的 UI，loading 和 error 用默认处理：

```
// 只有 data 时执行回调，其他时候返回 SizedBox
final widget = asyncValue.whenData((user) => Text(user.name));
```

### 8.3 maybeWhen / whenOrNull — 非穷尽匹配

只处理部分状态，其他走 `orElse`：

```
asyncValue.maybeWhen(
  data: (user) => Text(user.name),
  orElse: () => const SizedBox.shrink(),  // 其他状态的兜底
);

// whenOrNull：不匹配的状态返回 null
final user = asyncValue.whenOrNull(
  data: (user) => user,
);
```

### 8.4 AsyncValue.guard — 安全执行异步

自动捕获异常，把 Future 的结果包装成 AsyncValue：

```
// 在 Notifier 方法中使用
Future<void> refresh() async {
  state = const AsyncValue.loading();
  state = await AsyncValue.guard(() async {
    return api.fetchData();  // 成功 → AsyncData，失败 → AsyncError
  });
}
```

相当于：

```
try {
  final data = await api.fetchData();
  state = AsyncData(data);
} catch (e, st) {
  state = AsyncError(e, st);
}
```

### 8.5 copyWithPrevious — 保留旧数据刷新

刷新时保留上一次的数据，不显示全屏 loading：

```
Future<void> refresh() async {
  // 标记为 loading，但保留旧数据
  state = AsyncValue.loading().copyWithPrevious(state);

  state = await AsyncValue.guard(() => api.fetchData());
}
```

UI 上配合 `skipLoadingOnReload: true`：

```
asyncValue.when(
  skipLoadingOnReload: true,  // 重新加载时显示旧数据，而不是 loading
  data: (data) => ListView(...),
  loading: () => const Center(child: CircularProgressIndicator()),
  error: (e, _) => Text('$e'),
);
```

### 8.6 常用属性

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `value` | `T?` | 数据（可能为 null） |
| `valueOrNull` | `T?` | 同 value |
| `requireValue` | `T` | 强制获取数据，没有则抛异常 |
| `hasValue` | `bool` | 是否有数据 |
| `isLoading` | `bool` | 是否加载中 |
| `isReloading` | `bool` | 是否在重新加载（有旧数据） |
| `hasError` | `bool` | 是否有错误 |
| `error` | `Object?` | 错误对象 |
| `stackTrace` | `StackTrace?` | 堆栈 |

### 8.7 AsyncValue 的 map / maybeMap

和 when 类似，但回调参数是完整的 AsyncValue 子类对象：

```
asyncValue.map(
  data: (asyncData) => Text(asyncData.value.name),
  loading: (asyncLoading) => const CircularProgressIndicator(),
  error: (asyncError) => Text('${asyncError.error}'),
);
```

## 九、Riverpod 3.0 新特性与迁移

### 9.1 核心变化

Riverpod 3.0（2025 年发布）是一次大规模重构，主要变化：

#### 1. 统一 API 接口

- 移除了 `AutoDisposeNotifier`、`FamilyNotifier`、`AutoDisposeFamilyNotifier` 等大量子类
- 统一为 `Notifier`、`AsyncNotifier`，通过修饰符控制行为
- Ref 类型统一为 `Ref`，不再有 `ProviderRef`、`NotifierProviderRef` 等子类

#### 2. StateNotifier 正式废弃

- `StateNotifier` / `StateNotifierProvider` → 用 `Notifier` / `NotifierProvider` 替代
- `StateProvider` → 标记为 legacy，推荐用简单 Notifier 替代

#### 3. 自动重试

Provider 计算失败时自动重试，对短暂性网络错误更友好：

```
ProviderScope(
  // 全局配置重试策略
  retry: (retryCount, error) {
    if (retryCount < 3) return const Duration(seconds: 1);
    return null; // 不再重试
  },
  child: const MyApp(),
)
```

#### 4. 暂停/恢复监听

Widget 不在屏幕上时（如在路由栈底部），监听器自动暂停，节省资源。

#### 5. 新的测试工具

```
test('my test', () {
  // 自动创建和销毁 container
  final container = ProviderContainer.test();
  // ...
});
```

#### 6. ref.mounted

异步操作后检查 Provider 是否仍存活，避免销毁后 setState。

### 9.2 从 2.x 迁移到 3.0

**步骤 1：升级依赖**

```
dependencies:
  flutter_riverpod: ^3.0.0
  riverpod_annotation: ^3.0.0

dev_dependencies:
  riverpod_generator: ^3.0.0
  riverpod_lint: ^3.0.0
```

**步骤 2：运行自动迁移**

```
# riverpod_lint 提供了 dart fix 自动迁移
dart fix --apply
```

**步骤 3：手动修复**

主要迁移点：

| 2.x 写法 | 3.x 写法 |
| --- | --- |
| `StateNotifier` + `StateNotifierProvider` | `Notifier` + `NotifierProvider` |
| `AutoDisposeNotifier` | `Notifier`（默认 autoDispose） |
| `FamilyNotifier` | `Notifier` + family 参数 |
| `AutoDisposeFamilyNotifier` | `Notifier`（默认 autoDispose + family） |
| `ProviderRef` / `NotifierProviderRef` | `Ref` |
| `ref.watch(provider.future)` | `AsyncNotifier.future` |

**StateNotifier → Notifier 迁移示例**：

```
// 旧写法（2.x）
class CounterNotifier extends StateNotifier<int> {
  CounterNotifier() : super(0);
  void increment() => state++;
}

final counterProvider = StateNotifierProvider<CounterNotifier, int>(
  (ref) => CounterNotifier(),
);

// 新写法（3.x）
@riverpod
class Counter extends _$Counter {
  @override
  int build() => 0;
  void increment() => state++;
}
```

### 场景 1：文章列表页（AsyncNotifier + 下拉刷新 + 加载更多）

**需求**：列表页，支持下拉刷新、上拉加载更多、错误重试。

```
// lib/features/articles/articles_provider.dart
part 'articles_provider.g.dart';

@riverpod
class Articles extends _$Articles {
  static const _pageSize = 20;

  @override
  Future<List<Article>> build() async {
    // 自动取消请求：页面销毁时取消
    final cancelToken = CancelToken();
    ref.onDispose(cancelToken.cancel);

    final repo = ref.watch(articlesRepositoryProvider);
    return repo.fetchList(page: 1, pageSize: _pageSize, cancelToken: cancelToken);
  }

  /// 下拉刷新
  Future<void> refresh() async {
    state = const AsyncLoading().copyWithPrevious(state);
    final repo = ref.read(articlesRepositoryProvider);
    state = await AsyncValue.guard(
      () => repo.fetchList(page: 1, pageSize: _pageSize),
    );
  }

  /// 加载更多
  Future<void> loadMore() async {
    final current = state.valueOrNull;
    if (current == null || current.length < _pageSize) return;

    // 标记为重新加载（保留旧数据）
    state = AsyncLoading().copyWithPrevious(state);

    final repo = ref.read(articlesRepositoryProvider);
    final nextPage = current.length ~/ _pageSize + 1;

    state = await AsyncValue.guard(() async {
      final more = await repo.fetchList(page: nextPage, pageSize: _pageSize);
      return [...current, ...more];
    });
  }
}
```

@riverpod
class Auth extends _$Auth {
  @override
  AuthState build() => const AuthState.unauthenticated();

  Future<void> login(String username, String password) async {
    state = const AuthState.loading();

    final repo = ref.read(authRepositoryProvider);
    final result = await repo.login(username, password);

    result.when(
      success: (user) {
        state = AuthState.authenticated(user);
        // 保存到本地存储
        ref.read(secureStorageProvider).writeToken(user.token);
      },
      error: (message) {
        state = AuthState.error(message);
      },
    );
  }

  Future<void> logout() async {
    final storage = ref.read(secureStorageProvider);
    await storage.deleteToken();
    state = const AuthState.unauthenticated();
  }

  /// 应用启动时检查登录状态
  Future<void> checkAuth() async {
    final storage = ref.read(secureStorageProvider);
    final token = await storage.readToken();
    if (token != null) {
      final repo = ref.read(authRepositoryProvider);
      final user = await repo.getCurrentUser();
      state = AuthState.authenticated(user);
    }
  }
}

## 十三、常见问题与最佳实践

### 13.1 常见报错与解决

| 报错 | 原因 | 解决方案 |
| --- | --- | --- |
| `Unhandled Exception: ProviderException` | Provider 计算时抛出异常 | 检查 Provider 的 build 方法，用 AsyncValue.guard 包裹 |
| `type 'Null' is not a subtype of type 'Future'` | 在非 async Provider 中返回了 null | 确保返回类型正确，或用 `T?` |
| `A package:riverpod import is missing` | 忘记 import riverpod 包 | 检查 import |
| `The method 'xxx' isn't defined` | 代码生成没跑或失败 | 运行 `dart run build_runner build` |
| `Bad state: Tried to use xxxRef after it was disposed` | Provider 销毁后仍在使用 | 使用 `ref.mounted` 检查 |

### 13.2 最佳实践清单

#### Provider 定义

1. **优先使用代码生成**：`@riverpod` 注解，减少样板代码，类型更安全
2. **默认使用 autoDispose**：页面级 Provider 都用 autoDispose，避免内存泄漏
3. **全局状态用 keepAlive: true**：如登录状态、主题、用户信息
4. **按功能模块组织文件**：每个 feature 目录下有自己的 providers 文件
5. **命名规范**：Notifier 类名用名词（如 `TodoList`），方法用动词（如 `addTodo`）

#### Ref 使用

6. **build 中用 watch，回调中用 read**：黄金法则
7. **不要在 build 中调用 notifier 方法**：会导致每次重建都执行
8. **副作用用 listen**：弹 SnackBar、导航等用 `ref.listen`
9. **刷新用 invalidate，需要新值用 refresh**：下拉刷新用 invalidate
10. **清理资源用 onDispose**：Timer、StreamController、CancelToken 等

#### 架构

11. **分层架构**：UI → Notifier → UseCase → Repository → DataSource
12. **依赖注入用 Provider**：所有服务、仓库都通过 Provider 注入
13. **优先覆盖底层依赖**：测试时 override Repository，而不是 override Notifier
14. **状态用 Freezed**：复杂状态用 Freezed union，配合 when 穷尽匹配
15. **异步状态用 AsyncValue**：不要自己写 loading/error 三态判断

#### 性能

16. **合理拆分 Provider**：避免一个大 Provider 包含所有状态，导致频繁重建
17. **用 select 精准监听**：只监听需要的字段，减少不必要的重建
18. **autoDispose 及时释放**：页面级数据用完就释放
19. **family 参数注意缓存**：参数变化会创建新实例

#### 代码质量

20. **启用 riverpod\_lint**：帮你发现问题和不规范写法
21. **给 Provider 写文档注释**：说明用途、依赖、生命周期
22. **每个 Notifier 方法只做一件事**：保持方法单一职责

### 13.3 select — 精准监听，减少重建

只监听状态的某个字段，字段不变就不重建：

```
// 只监听 user 的 name 字段
final userName = ref.watch(
  userProvider.select((user) => user.name),
);
```

当 `user` 对象变化但 `name` 没变时，Widget 不会重建。

### 13.4 Provider 之间的依赖

Provider 可以自由依赖其他 Provider，Riverpod 自动追踪依赖关系：

```
@riverpod
UserRepository userRepository(UserRepositoryRef ref) {
  // 依赖 apiClientProvider
  final api = ref.watch(apiClientProvider);
  return UserRepository(api);
}

@riverpod
Future<User> currentUser(CurrentUserRef ref) {
  // 依赖 userRepositoryProvider
  final repo = ref.watch(userRepositoryProvider);
  return repo.getCurrentUser();
}
```

当 `apiClientProvider` 变化时，`userRepositoryProvider` 和 `currentUserProvider` 都会自动重新计算。

### 13.5 与 Provider 包的区别

| 特性 | Provider | Riverpod |
| --- | --- | --- |
| 依赖 BuildContext | ✅ 是 | ❌ 否 |
| 编译期安全 | ❌ 运行时可能找不到 | ✅ 编译期检查 |
| 多个同类型 Provider | 需要 tag | 天然支持（不同实例） |
| 异步状态 | 自己处理 | AsyncValue 统一封装 |
| 自动销毁 | ❌ | ✅ autoDispose |
| 测试难度 | 较难（需要 context） | 简单（ProviderContainer） |
| 代码生成 | 不支持 | ✅ riverpod\_generator |
