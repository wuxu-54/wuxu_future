# FlutterView

`FlutterView` 是 Flutter 在 Android 上的**渲染容器、触控网关与平台视图管理者**。它并不直接执行绘制，而是作为一个 `FrameLayout`，在内部持有一个真正的渲染表面（`FlutterSurfaceView` 或 `FlutterTextureView`），把所有渲染、触控、文本输入等工作代理出去。

---

## 一、FlutterView 的定位与源码结构

新版 `io.flutter.embedding.android.FlutterView` 继承自 `FrameLayout`，并实现 `RenderSurface` 接口。它本身只是一个**容器**，真正的渲染能力由其内部的 `renderSurface` 对象提供：

```java
public class FlutterView extends FrameLayout implements RenderSurface {
  @NonNull private final RenderSurface renderSurface; // 实际是 FlutterSurfaceView 或 FlutterTextureView
  @Nullable private FlutterEngine flutterEngine;
  // 触摸、输入、系统 UI 等相关字段...
}
```

构造时根据 `RenderMode` 决定创建哪种表面：

- `RenderMode.surface` → `FlutterSurfaceView`
- `RenderMode.texture` → `FlutterTextureView`

该子视图被添加为 `FlutterView` 的唯一子 View（填满父容器），`FlutterView` 只是把 `RenderSurface` 接口的所有方法透明转发给它。

## 二、渲染表面：FlutterSurfaceView 与 FlutterTextureView

### 2.1 FlutterSurfaceView

基于 `SurfaceView`。系统会在独立的窗口中分配一个 Drawing Surface，并由 GPU 直接绘制，**零拷贝**合成到 View 层次上。

- **优点**：性能最佳，帧延迟最低，无需额外纹理拷贝。
- **缺点**：SurfaceView 的窗口独立于 View 层级，导致：
  - 无法进行 View 动画（如平移、缩放），因为它不随 View 系统移动（除非使用 `setZOrderOnTop` 等）。
  - 不支持透明度叠放（背景总是黑色或不透明），除非显式设置 Z 顺序并留出透明区域（但性能会下降）。
  - 其他 View 无法覆盖在它上面（除非手动控制 Z order）。

### 2.2 FlutterTextureView

基于 `TextureView`。它将渲染内容绘制到一张 GPU 纹理上，然后将该纹理合成到 View 层次中。

- **优点**：完全融入 View 系统，支持所有 View 动画、透明度和层叠（如覆盖原生 Toolbar）。
- **缺点**：多了一次纹理拷贝，增加 GPU 带宽和延迟。在低端设备上可能影响性能。

`FlutterActivity` 默认使用 `FlutterSurfaceView`，而 `FlutterFragment` 在需要透明背景时会自动切换为 `FlutterTextureView`。

## 三、与引擎的连接与 Surface 提供

### 3.1 绑定引擎

`FlutterView.attachToFlutterEngine(FlutterEngine engine)` 做三件事：

1. 保存引擎引用。
2. 调用 `engine.getRenderer().attachToRenderSurface(renderSurface)`，将渲染表面（Surface 提供者）注册到引擎的 Raster 线程。
3. 设置事件通道：触摸、文本输入、系统 UI 等。

`RenderSurface` 接口的核心方法：

```java
void attachToRenderer(@NonNull FlutterRenderer flutterRenderer);
void detachFromRenderer();
Surface getSurface();  // 返回当前可绘制的 Surface
```

这些由 `FlutterSurfaceView`/`FlutterTextureView` 具体实现。

### 3.2 Surface 的生命周期与引擎同步

`FlutterSurfaceView` 通过 `SurfaceHolder.Callback` 管理 Surface 的创建、改变与销毁。当 surface 可用时，它调用 `FlutterJNI.nativeSurfaceCreated(surface)`，引擎的 Raster 线程拿到 `ANativeWindow`，开始光栅化。Surface 大小变化时调用 `nativeSurfaceChanged`，销毁时调用 `nativeSurfaceDestroyed`。

`FlutterTextureView` 则通过 `TextureView.SurfaceTextureListener`，在 `onSurfaceTextureAvailable` 中将 `SurfaceTexture` 转为 `Surface` 传给引擎；每一帧渲染完成后，引擎会要求 TextureView 的 `SurfaceTexture` 更新纹理（通过 `updateTexImage`），然后 View 系统在绘制时合成它。

## 四、触摸事件处理：从 MotionEvent 到 Flutter 手势

### 4.1 事件的转换与发送

`FlutterView` 重写 `onTouchEvent`，获取所有触控事件。处理流程：

1. 将 Android 的 `MotionEvent` 转换为引擎可识别的 `FlutterPointerEvent` 列表（多个手指）。
2. 通过 `flutterEngine.getRenderer().dispatchPointerDataPacket(ByteBuffer)` 将事件数据编码后送入引擎。
3. 引擎在 Platform 线程接收，再转发到 UI 线程的消息循环，最终由 Dart 层的 `GestureBinding` 处理。

**注意：** 如果 `FlutterView` 没有绑定引擎，事件会被忽略。

### 4.2 命中测试与手势竞技

在 Dart 层，事件经过命中测试（hit test），找到最深的 `RenderObject`；手势识别器在竞技场中竞争，决定最终响应手势。这一整套机制对 Android 侧完全透明。

### 4.3 拦截与冲突处理

`FlutterView` 是 `ViewGroup`，但它不会将触摸事件传递给子 View（因为子 View 只有渲染表面）。所有触控事件都被拦截，统一发给引擎。如果需要原生视图（如 `AndroidView`）响应触摸，则由平台视图系统特殊处理。

## 五、文本输入与输入法连接

当 Flutter 中的 `TextField` 获得焦点时，Dart 通过 `SystemChannels.textInput` 发送消息给引擎，引擎最终调用 `FlutterView` 的输入法相关方法。

`FlutterView` 重写 `onCreateInputConnection(EditorInfo outAttrs)`，返回一个 `InputConnection`：

- 内部使用 `InputConnectionAdaptor`，它将 Android 的 `InputConnection` 协议桥接到 Dart 的 `TextInput` 系统。
- 处理 `commitText`、`deleteSurroundingText`、`setComposingRegion` 等编辑命令。
- 所有文本状态由 Dart 侧维护，Android 输入法只作为输入前端。

当需要显示虚拟键盘时，`FlutterView` 通过 `InputMethodManager` 请求显示/隐藏，完全听从 Dart 侧的指令。

## 六、系统 UI 可见性与窗口 insets

Flutter 的 `SystemChrome` API 允许 Dart 代码控制系统栏（状态栏、导航栏）的显隐和样式。实现通道是 `flutter/platformviews` 或 `flutter/system`（实际上是通过 `SystemChannels.platform` 的消息）。

`FlutterView` 注册了对应的通道处理器，调用 Android 的 `WindowInsetsController` 或 `setSystemUiVisibility`，直接修改宿主 Activity 的窗口属性。同时，它监听系统栏变化，将新的 `WindowInsets` 传回 Dart 层，以便 Flutter 用 `MediaQuery` 获取安全区域。

## 七、平台视图（AndroidView/UIKitView）的嵌入

当 Dart 代码中嵌入一个原生 Android View（例如 WebView）时，`FlutterView` 承担容器角色。

### 7.1 创建原生视图

Dart 通过 `PlatformViewChannel` 请求创建一个原生视图。引擎生成一个 `PlatformViewTask`，在 Android 侧由 `PlatformViewsController` 创建真正的 `View`，并将其添加到 `FlutterView` 中（作为子 View）。同时，引擎会在图层树中生成一个 `PlatformViewLayer`，指示该原生视图的位置和裁剪区域。

### 7.2 层级与裁剪处理

由于原生视图是附加在 `FlutterView` 上的普通 View，它们与 Flutter 渲染内容通过 Z 轴顺序混合。

- `FlutterView` 使用 `FlutterMutatorView` 包装原生视图，该包装器负责：
  - 应用变换矩阵（位移、缩放、旋转）。
  - 处理裁剪（`clipPath` 转为 View 的裁剪区域）。
- 对于 Android 10 以下，平台视图存在 Z 顺序限制，引擎会使用 `FlutterImageView`（一个特殊的 `ImageView`）作为 Flutter UI 的纹理覆盖层，实现正确的层叠。Android 10+ 则直接利用系统原生 Z 顺序支持。

### 7.3 触摸事件的协同

当触摸发生在原生视图区域时，`FlutterView` 不再将事件传给引擎，而是直接交给原生 View 处理。`PlatformViewsController` 会拦截 `onTouchEvent`，判断触摸点是否落在某个原生视图内，从而正确地分发事件。

## 八、屏幕截图与 PixelCopy

`FlutterView` 提供 `getBitmap()` 方法，用于截取当前渲染内容为 `Bitmap`。

- 对于 `FlutterSurfaceView`，无法直接从 Surface 读取像素（因为独立窗口），需要通过 `PixelCopy` API 异步获取。
- 对于 `FlutterTextureView`，可以直接通过 `getBitmap()` 获取，因为它本身就是一个纹理。

实现时，`FlutterView` 委托给内部的 `RenderSurface` 实现具体截图逻辑。

## 九、生命周期优化与资源管理

### 9.1 暂停/恢复渲染

`FlutterView` 的 `onWindowFocusChanged` 会通知引擎窗口焦点变化。失去焦点时可以暂停渲染循环，节省 CPU/GPU。引擎的 `FlutterRenderer` 提供 `startRenderingToSurface` 和 `stopRenderingToSurface` 方法，`FlutterView` 在适当时候调用它们。

### 9.2 与宿主生命周期的联动

虽然 `FlutterView` 是一个 View，它本身没有 Activity 生命周期，但它通过 `FlutterActivity` 或 `FlutterFragment` 的委托接收到生命周期回调，进而调整引擎状态。`FlutterView` 只是被动提供 Surface 和事件通道。

### 9.3 内存回收

当 `FlutterView` 从窗口剥离时 (`onDetachedFromWindow`)，它分离引擎，释放 Surface，确保不会在不可见时继续渲染。

---

## 十、总结

`FlutterView` 在 Android 上的本质是：

- **容器 + 代理**：内部封装了一个真正的渲染表面（`FlutterSurfaceView` 或 `FlutterTextureView`），并将所有的渲染、触摸、输入法、系统 UI 等操作转发给引擎或具体实现。
- **平台视图管理器**：承载并协调原生 Android View 与 Flutter UI 的混合显示、裁剪与触控。
- **无缝桥接点**：把 Android 的视图生命周期、输入协议和窗口系统精准地映射为引擎期望的原语。

理解了 `FlutterView`，你就能明白：

- 为什么透明背景必须用 `FlutterTextureView`
- 为什么嵌入 `WebView` 时会有层级问题及不同的实现策略
- 触摸延迟究竟发生在哪里（View → Platform线程 → UI线程）
- 以及如何为自定义混合栈设计一个可靠的渲染容器

这就打通了 Android 平台与 Flutter 引擎之间最核心的视觉与交互管道。
