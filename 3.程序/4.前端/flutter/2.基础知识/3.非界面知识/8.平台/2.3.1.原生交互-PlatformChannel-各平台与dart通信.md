## 一、概述

Platform Channel 是 Flutter 与原生平台（Android / iOS）之间进行通信的核心机制。由于 Flutter 运行在 Dart 虚拟机中，无法直接调用平台特定的 API（如摄像头、蓝牙、传感器、电池等），Platform Channel 提供了一套**异步消息传递系统**，让 Dart 代码与原生代码能够互相调用和交换数据。

**核心特征：**

- **异步**：所有调用都是非阻塞的，Dart 侧返回 `Future` / `Stream`。
- **跨语言**：Dart ↔ Kotlin/Java ↔ Swift/Objective-C。
- **序列化**：通过 `MessageCodec` 将 Dart 对象编码为二进制字节，跨引擎传递后再解码。
- **名称路由**：每个 Channel 有一个全局唯一的字符串名称，引擎据此将消息分发到正确的处理器。

## 二、整体架构

### 2.1 三层结构

Flutter 应用分为三层：

1. **Dart 层（Framework）** —— 你写的 Flutter 业务代码和 UI。
2. **引擎层（Engine，C/C++）** —— 负责光栅化、文本布局、Dart VM 管理、Platform Channel 消息转发。
3. **平台层（Platform，Android/iOS）** —— 原生系统 API 和代码。

Platform Channel 连接 **Dart 层**和**平台层**，通信经过引擎层转发：

```
Dart (Flutter)  <--channel-->  Engine (C++)  <--platform thread-->  Android/iOS
```

### 2.2 精确通信链路

```
Dart 侧                          Engine (C++)                       原生侧
┌─────────────┐               ┌──────────────────┐               ┌──────────────┐
│ MethodChannel│  send()       │  Shell           │  PostTask    │ Platform     │
│  .invokeMethod│ ───────────► │  PlatformView    │ ───────────► │ Thread       │
│              │  ByteBuffer   │  (UI Thread)     │   主线程      │ (UI Thread)  │
│              │               │                  │              │              │
│  Completer   │ ◄───────────  │  Dart_PostCObject│ ◄─────────── │ Result/      │
│  .complete   │  ByteBuffer   │  (回到 Dart isolate)│  回调       │ EventSink    │
└─────────────┘               └──────────────────┘               └──────────────┘
```

**流程说明：**

1. Dart 侧调用 `invokeMethod`，`MethodCodec` 将方法名和参数编码为 `ByteBuffer`。
2. `BinaryMessenger` 将字节数据交给引擎 Shell。
3. 引擎通过 `PostTask` 将消息投递到平台主线程，调用原生侧注册的 handler。
4. 原生 handler 执行后通过 `Result` / `EventSink` 返回结果。
5. 引擎通过 `Dart_PostCObject` 将结果字节投递回 Dart isolate，完成 `Future`。

### 2.3 BinaryMessenger —— 所有 Channel 的底层

三种 Channel 都不直接通信，而是委托给 `BinaryMessenger`：

```
abstract class BinaryMessenger {
  Future<ByteData?>? send(String channel, ByteData? message);
  void setMessageHandler(String channel, MessageHandler? handler);
}
```

- `MethodChannel` / `EventChannel` / `BasicMessageChannel` 内部都持有一个 `BinaryMessenger` 引用。
- 默认实现是 `_DefaultBinaryMessenger`，绑定到 `ServicesBinding.instance`。
- 测试时替换为 `TestDefaultBinaryMessenger`，即可拦截所有消息实现 mock。

## 三、三种 Channel 类型

Flutter 提供三种 Channel，对应不同通信模式：

| Channel | 通信模式 | 典型场景 |
| --- | --- | --- |
| `MethodChannel` | 请求-响应（一问一答） | 调用原生方法、获取电池电量 |
| `EventChannel` | 原生→Dart 持续事件流 | 传感器、GPS、网络状态变化 |
| `BasicMessageChannel` | 双向半双工消息传递 | 自定义协议、长连接消息转发 |

### 3.1 MethodChannel

**用途**：一次性的方法调用（请求-响应模式）。Dart 调用原生方法，原生执行后返回结果；**也支持原生反向调用 Dart**。

**Dart 侧核心 API：**

```
static const platform = MethodChannel('com.example/battery'); //'com.example/battery' 是通道标识符，两端必须一致，底层以此确认是统一通道。

// 调用原生方法，返回 Future<T>
final int level = await platform.invokeMethod<int>('getBatteryLevel');

// 传递参数（必须是标准编解码支持的类型）
await platform.invokeMethod('setVolume', {'level': 0.8});

// 注册原生→Dart 的反向调用处理器
platform.setMethodCallHandler((MethodCall call) async {
  switch (call.method) {
    case 'onNativePush':
      print('收到原生事件: ${call.arguments}');
      return {'received': true};       // 返回值回传给原生
    default:
      throw MissingPluginException();  // 未实现的方法必须抛此异常
  }
});
```

**关键 API 说明：**

| 方法 | 说明 |
| --- | --- |
| `invokeMethod<T>(String method, [dynamic arguments])` | 调用原生方法，返回 `Future<T>`。method：是方法名，arguments：是参数 |
| `invokeListMethod<T>` / `invokeMapMethod<K,V>` | 泛型便捷方法，直接返回 List/Map |
| `setMethodCallHandler(handler)` | 注册原生→Dart 回调，传 `null` 可注销 |
| `MethodCall` | 封装 `method`（String）和 `arguments`（dynamic） |

**原生侧（Android Kotlin）：**

```
MethodChannel(flutterEngine.dartExecutor.binaryMessenger, "com.example/battery")
    .setMethodCallHandler { call, result ->
        when (call.method) {
            "getBatteryLevel" -> result.success(getBatteryLevel())
            "setVolume" -> {
                val level = call.argument<Double>("level")
                result.success(null)
            }
            else -> result.notImplemented()
        }
    }

// 原生反向调用 Dart， 必须在主线程，底层会有线程校验：io.flutter.embedding.engine.FlutterJNI.ensureRunningOnMainThread
channel.invokeMethod("onNativePush", mapOf("key" to "value"),
    object : MethodChannel.Result {
        override fun success(result: Any?) { /* Dart 返回值 */ }
        override fun error(code: String, msg: String?, details: Any?) {}
        override fun notImplemented() {}
    })
```

**Result 回调三选一（必须且只能调用一次）：**

- `result.success(data)` — 成功，返回任意可序列化对象
- `result.error(code, message, details)` — 失败，Dart 侧收到 `PlatformException`
- `result.notImplemented()` — 方法不存在，Dart 侧收到 `MissingPluginException`

**原生侧（iOS Swift）：**

```
let channel = FlutterMethodChannel(name: "com.example/battery",
                                   binaryMessenger: controller.binaryMessenger)
channel.setMethodCallHandler { call, result in
    switch call.method {
    case "getBatteryLevel":
        result(self.getBatteryLevel())
    case "setVolume":
        if let args = call.arguments as? [String: Any],
           let level = args["level"] as? Double {
            result(nil)
        } else {
            result(FlutterError(code: "BAD_ARGS", message: "参数错误", details: nil))
        }
    default:
        result(FlutterMethodNotImplemented)
    }
}

// 原生反向调用 Dart
channel.invokeMethod("onNativePush", arguments: ["key": "value"]) { result in
    // result 是 Dart 的返回值
}
```

**FlutterResult 三种返回值：**

- 成功值（含 `nil`）→ Dart 侧 `Future` 正常完成
- `FlutterError(code:message:details:)` → Dart 侧抛 `PlatformException`
- `FlutterMethodNotImplemented` → Dart 侧抛 `MissingPluginException`

### 3.2 EventChannel

**用途**：原生侧向 Dart 侧持续推送事件流。Dart 侧通过 `Stream` 订阅，原生侧通过 `EventSink` 发送。（EventChannel 本身不支持反向传递即Dart向原生持续推送）

**Dart 侧核心 API：**

```
static const eventChannel = EventChannel('com.example/sensor');

StreamSubscription<dynamic>? _subscription;

void startListening() {
  // arguments 可选，会传递给原生 onListen
  _subscription = eventChannel
      .receiveBroadcastStream({'interval': 1000})//这就是arguments的设置，原生可以拿到'interval'.
      .listen(
        (event) => print('收到事件: $event'),
        onError: (error) {
          if (error is PlatformException) print('错误: ${error.message}');
        },
        onDone: () => print('流结束'),
        cancelOnError: false,
      );
}

void stopListening() {
  _subscription?.cancel();   // 触发原生 onCancel
  _subscription = null;
}
```

**多订阅行为：**

- `receiveBroadcastStream()` 返回 **BroadcastStream**，可多次 `listen`。
- 原生 `onListen` **只在第一个 listener 订阅时调用一次**，后续 listener 共享流。
- `onCancel` 在**最后一个** listener 取消时调用。

**原生侧（Android Kotlin）：**

```
class SensorStreamHandler(private val context: Context) : EventChannel.StreamHandler {
    private var sensorManager: SensorManager? = null
    private var listener: SensorEventListener? = null

    override fun onListen(arguments: Any?, events: EventChannel.EventSink?) {
        sensorManager = context.getSystemService(Context.SENSOR_SERVICE) as SensorManager
        val sensor = sensorManager?.getDefaultSensor(Sensor.TYPE_ACCELEROMETER)
        listener = object : SensorEventListener {
            override fun onSensorChanged(event: SensorEvent?) {
                event?.let {
                    events?.success(mapOf("x" to it.values[0],
                                          "y" to it.values[1],
                                          "z" to it.values[2]))
                }
            }
            override fun onAccuracyChanged(s: Sensor?, accuracy: Int) {}
        }
        sensorManager?.registerListener(listener, sensor, SensorManager.SENSOR_DELAY_NORMAL)
    }

    override fun onCancel(arguments: Any?) {
        sensorManager?.unregisterListener(listener)   // 必须释放资源
        sensorManager = null
        listener = null
    }
}

// 注册
EventChannel(messenger, "com.example/sensor")
    .setStreamHandler(SensorStreamHandler(context))
```

**EventSink 三个方法：**

- `events.success(data)` — 正常事件
- `events.error(code, message, details)` — 错误事件
- `events.endOfStream()` — 流结束

**原生侧（iOS Swift）：**

```
class SensorStreamHandler: NSObject, FlutterStreamHandler {
    private let motionManager = CMMotionManager()

    func onListen(withArguments arguments: Any?,
                  eventSink events: @escaping FlutterEventSink) -> FlutterError? {
        if motionManager.isAccelerometerAvailable {
            motionManager.accelerometerUpdateInterval = 0.1
            motionManager.startAccelerometerUpdates(to: .main) { data, _ in
                if let d = data {
                    events(["x": d.acceleration.x,
                            "y": d.acceleration.y,
                            "z": d.acceleration.z])
                }
            }
        }
        return nil   // 返回 nil 表示成功；返回 FlutterError 表示初始化失败
    }

    func onCancel(withArguments arguments: Any?) -> FlutterError? {
        motionManager.stopAccelerometerUpdates()
        return nil
    }
}
```

### 3.3 BasicMessageChannel

**用途**：最底层的通用消息通道，支持双向消息传递，可自定义编解码器。适合传递字符串、JSON 或自定义二进制格式。

**Dart 侧：**

```
// 不同 Codec 对应不同的泛型类型
static const stringChannel = BasicMessageChannel<String>(
    'com.example/chat', StringCodec());

static const jsonChannel = BasicMessageChannel<dynamic>(
    'com.example/data', JSONMessageCodec());

static const binaryChannel = BasicMessageChannel<ByteData>(
    'com.example/raw', BinaryCodec());

// 发送消息并等待回复
Future<void> send() async {
  final reply = await stringChannel.send('Hello from Dart');
  print('原生回复: $reply');
}

// 接收原生主动推送
stringChannel.setMessageHandler((message) async {
  print('收到原生: $message');
  return '已收到';   // 返回值作为对原生的回复，必须返回
});
```

>
> ⚠️ `setMessageHandler` 的回调**必须返回一个值**（即使是 `null`），否则原生侧的 reply 永远不会触发。

**原生侧（Android Kotlin）：**

```
val msgChannel = BasicMessageChannel<String>(
    messenger, "com.example/chat", StringCodec.INSTANCE)

msgChannel.setMessageHandler { message, reply ->
    println("收到 Dart: $message")
    reply.reply("Hello from Android")   // 必须调用 reply.reply(...)
}

msgChannel.send("Native push") { reply ->  // 主动推给 Dart
    println("Dart 回复: $reply")
}
```

**原生侧（iOS Swift）：**

```
let msgChannel = FlutterBasicMessageChannel(
    name: "com.example/chat",
    binaryMessenger: controller.binaryMessenger,
    codec: FlutterStringCodec.sharedInstance())

msgChannel.setMessageHandler { message, reply in
    print("收到 Dart: \(message ?? "")")
    reply("Hello from iOS")
}

msgChannel.sendMessage("Native push") { reply in
    print("Dart 回复: \(reply ?? "")")
}
```

## 四、消息编解码与数据类型

所有通过 Platform Channel 传递的数据都需要序列化和反序列化，由 `MessageCodec` 完成。

### 4.1 MethodCodec 与 MessageCodec 的关系

```
MethodCodec（方法调用编解码）
  └── 内部组合两个 MessageCodec：
        ├── encodeMethodCall / decodeMethodCall
        └── encodeSuccessEnvelope / decodeEnvelope
            （envelope = [result] 或 [code, message, details]）
```

- **MessageCodec**：只负责 `T ↔ ByteBuffer`，是基础编解码。
- **MethodCodec**：在 MessageCodec 之上封装了「方法调用」和「结果信封」结构。
- `StandardMethodCodec` = `StandardMessageCodec` + 标准信封格式。
- `JSONMethodCodec` = `JSONMessageCodec` + 信封格式（用于调试或 JSON 兼容场景）。

### 4.2 四种内置 Codec 对比

| Codec | 泛型类型 | 传输格式 | 典型用途 |
| --- | --- | --- | --- |
| `StandardMessageCodec` | `dynamic` | 二进制紧凑格式 | 绝大多数场景（默认） |
| `StringCodec` | `String` | UTF-8 字符串 | 纯文本协议 |
| `JSONMessageCodec` | `dynamic` | JSON 字符串 | 调试、与 Web 端对齐 |
| `BinaryCodec` | `ByteData` | 原始字节，零拷贝 | 大数据、图片字节、FFI 对接 |

>
> `BinaryCodec` 是唯一不做任何序列化的 Codec，Dart 侧直接拿到 `ByteData`，性能最高，但需自行约定二进制格式。

### 4.3 StandardMessageCodec 类型映射

| Dart 类型 | Android (Java) 类型 | iOS (Objective-C) 类型 |
| --- | --- | --- |
| `null` | `null` | `nil` / `NSNull` |
| `bool` | `java.lang.Boolean` | `NSNumber` (BOOL) |
| `int` | `Integer`（32位内），否则 `Long` / `BigInteger` | `NSNumber` (int32/int64) |
| `double` | `java.lang.Double` | `NSNumber` (double) |
| `String` | `java.lang.String` | `NSString` |
| `Uint8List` | `byte[]` | `FlutterStandardTypedData` (NSData) |
| `Int32List` | `int[]` | `FlutterStandardTypedData` |
| `Int64List` | `long[]` | `FlutterStandardTypedData` |
| `Float64List` | `double[]` | `FlutterStandardTypedData` |
| `List` | `java.util.ArrayList` | `NSArray` |
| `Map` | `java.util.HashMap` | `NSDictionary` |

自定义类无法直接传递，需序列化为 `Map` / `List`，或实现自定义 `MessageCodec`（如 Protobuf、FlatBuffers）。

## 五、线程模型

### 5.1 原生侧：回调始终在主线程

引擎将 MethodChannel 和 EventChannel 的回调派发到**平台主线程**（Android 主线程、iOS 主线程）。这意味着：

- 可以直接操作 UI 相关 API。
- **耗时操作必须切到后台线程**，否则阻塞平台 UI 线程导致掉帧或 ANR。

**Android 异步返回（Flutter 2.0+ embedding v2）：**

```
override fun onMethodCall(call: MethodCall, result: Result) {
    if (call.method == "heavyTask") {
        CoroutineScope(Dispatchers.IO).launch {
            val data = heavyComputation()
            // 可在 IO 线程直接调用，引擎自动切回主线程投递
            result.success(data)
        }
        // 不能在此处 return result，因为是异步
    }
}
```

>
> Flutter 2.0+ 的 `Result` 可在任意线程调用；早期 1.x embedding 要求必须在主线程调用。`Result` 对象只能使用一次。

**iOS 异步返回：**

```
channel.setMethodCallHandler { call, result in
    if call.method == "heavyTask" {
        DispatchQueue.global().async {
            let data = heavyComputation()
            DispatchQueue.main.async { result(data) }   // 回主队列回调
        }
    }
}
```

### 5.2 Dart 侧：异步不阻塞 UI

- 通道调用返回 `Future` / `Stream`，不会阻塞 Dart UI 线程。
- Dart 侧的 handler（`MethodCallHandler` 等）运行在对应 isolate 的主事件循环，应避免耗时计算。

### 5.3 后台 isolate 使用 Platform Channel

- Platform Channel 默认只能从 **root isolate** 发送。在后台 isolate 调用时，引擎会转发到 root isolate 再发出，有额外开销。
- Flutter 3.x 起支持 `BackgroundIsolateBinaryMessenger`，让后台 isolate 直接绑定：

```
// root isolate 中获取 token
final token = RootIsolateToken.instance;
Isolate.spawn(backgroundTask, token);

// 后台 isolate 中
void backgroundTask(RootIsolateToken token) {
    BackgroundIsolateBinaryMessenger.ensureInitialized(token);
    // 现在可以直接使用 MethodChannel
}
```

>
> 即便如此，原生侧 handler 仍在平台主线程执行，后台 isolate 只是省掉了 Dart 侧的转发开销。

## 六、完整示例

### 6.1 MethodChannel：获取电池电量

**Dart 侧：**

```
import 'package:flutter/services.dart';

class Battery {
  static const _channel = MethodChannel('samples.flutter.dev/battery');

  static Future<int> getBatteryLevel() async {
    try {
      final level = await _channel.invokeMethod<int>('getBatteryLevel');
      return level ?? 0;
    } on PlatformException catch (e) {
      print('错误: ${e.code} - ${e.message}');
      return -1;
    } on MissingPluginException {
      return -1;
    }
  }
}
```

**Android 侧（Kotlin）：**

```
class MainActivity : FlutterActivity() {
    private val CHANNEL = "samples.flutter.dev/battery"

    override fun configureFlutterEngine(flutterEngine: FlutterEngine) {
        super.configureFlutterEngine(flutterEngine)
        MethodChannel(flutterEngine.dartExecutor.binaryMessenger, CHANNEL)
            .setMethodCallHandler { call, result ->
                if (call.method == "getBatteryLevel") {
                    val level = getBatteryLevel()
                    if (level != -1) result.success(level)
                    else result.error("UNAVAILABLE", "无法获取电量", null)
                } else {
                    result.notImplemented()
                }
            }
    }

    private fun getBatteryLevel(): Int {
        val bm = getSystemService(Context.BATTERY_SERVICE) as BatteryManager
        return bm.getIntProperty(BatteryManager.BATTERY_PROPERTY_CAPACITY)
    }
}
```

**iOS 侧（Swift）：**

```
@main
@objc class AppDelegate: FlutterAppDelegate {
    override func application(_ app: UIApplication,
                              didFinishLaunchingWithOptions opts: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
        let controller = window?.rootViewController as! FlutterViewController
        FlutterMethodChannel(name: "samples.flutter.dev/battery",
                             binaryMessenger: controller.binaryMessenger)
            .setMethodCallHandler { [weak self] call, result in
                if call.method == "getBatteryLevel" {
                    let level = self?.getBatteryLevel() ?? -1
                    if level >= 0 { result(level) }
                    else { result(FlutterError(code: "UNAVAILABLE", message: "无法获取电量", details: nil)) }
                } else { result(FlutterMethodNotImplemented) }
            }
        return super.application(app, didFinishLaunchingWithOptions: opts)
    }

    private func getBatteryLevel() -> Int {
        let device = UIDevice.current
        device.isBatteryMonitoringEnabled = true
        if device.batteryState == .unknown { return -1 }
        return Int(device.batteryLevel * 100)
    }
}
```

### 6.3 BasicMessageChannel：双向聊天

**Dart 侧：**

```
static const _channel = BasicMessageChannel<dynamic>(
    'samples.flutter.dev/chat', StandardMessageCodec());

Future<void> sendMessage(String text) async {
  final reply = await _channel.send({'type': 'text', 'content': text});
  print('原生回复: $reply');
}

void listenFromNative() {
  _channel.setMessageHandler((message) async {
    print('收到原生: $message');
    return {'ack': true};
  });
}
```

**Android 侧（Kotlin）：**

```
val channel = BasicMessageChannel<Any>(messenger, "samples.flutter.dev/chat",
    StandardMessageCodec.INSTANCE)
channel.setMessageHandler { msg, reply ->
    println("收到 Dart: $msg")
    reply.reply(mapOf("status" to "ok"))
}
channel.send(mapOf("event" to "pong"))   // 主动推送
```

## 七、异常处理

Dart 侧可能捕获的异常类型：

| 异常 | 触发条件 |
| --- | --- |
| `PlatformException` | 原生侧调用 `result.error(...)` / `events.error(...)` |
| `MissingPluginException` | 原生侧返回 `notImplemented`，或未注册 handler |
| `FormatException` | 原生返回的数据无法被 Codec 解码 |
| `ArgumentError` | 方法名或参数不合法 |

**统一处理模式：**

```
try {
  await channel.invokeMethod('foo');
} on PlatformException catch (e) {
  print('业务错误: ${e.code} - ${e.message} - ${e.details}');
} on MissingPluginException {
  print('原生未实现该方法');
} catch (e) {
  print('其他错误: $e');
}
```

## 八、插件开发与生命周期管理

正式插件应实现 `FlutterPlugin` 接口，而非直接在 `Activity` / `AppDelegate` 中注册，以支持多 Engine、缓存等场景。

### 8.1 Android 插件完整骨架

```
class MyPlugin : FlutterPlugin, MethodCallHandler, ActivityAware {
    private var channel: MethodChannel? = null

    override fun onAttachedToEngine(binding: FlutterPlugin.FlutterPluginBinding) {
        channel = MethodChannel(binding.binaryMessenger, "com.example/my_plugin")
        channel?.setMethodCallHandler(this)
    }

    override fun onDetachedFromEngine(binding: FlutterPlugin.FlutterPluginBinding) {
        channel?.setMethodCallHandler(null)
        channel = null
    }

    override fun onMethodCall(call: MethodCall, result: Result) {
        when (call.method) {
            "methodName" -> result.success("reply")
            else -> result.notImplemented()
        }
    }

    // ActivityAware：获取/释放 Activity 上下文
    override fun onAttachedToActivity(binding: ActivityPluginBinding) {}
    override fun onDetachedFromActivityForConfigChanges() {}
    override fun onReattachedToActivityForConfigChanges(binding: ActivityPluginBinding) {}
    override fun onDetachedFromActivity() {}
}
```

### 8.2 iOS 插件完整骨架

```
public class MyPlugin: NSObject, FlutterPlugin {
    public static func register(with registrar: FlutterPluginRegistrar) {
        let channel = FlutterMethodChannel(name: "com.example/my_plugin",
                                           binaryMessenger: registrar.messenger())
        let instance = MyPlugin()
        registrar.addMethodCallDelegate(instance, channel: channel)
    }

    public func handle(_ call: FlutterMethodCall, result: @escaping FlutterResult) {
        switch call.method {
        case "methodName": result("reply")
        default: result(FlutterMethodNotImplemented)
        }
    }
}
```

### 8.3 多 Engine（Multi-Engine）场景

Flutter 支持一个进程内创建多个 `FlutterEngine`，每个 Engine 有独立的 `BinaryMessenger` 和 Dart isolate。

- 插件的 `onAttachedToEngine` 会被**每个 Engine 调用一次**，插件实例可能有多个。
- Channel 名称在**同一个 Engine 内**唯一即可，不同 Engine 互不影响。
- 多个 Engine 共享原生资源（如蓝牙管理器）时，用单例或依赖注入，不要在每个插件实例重复创建。

## 九、Pigeon：类型安全的代码生成方案

手写 Platform Channel 有三个痛点：方法名字符串易拼错、参数类型无编译期检查、三端代码重复维护。**Pigeon** 是 Flutter 官方的 IDL 代码生成工具，通过一份 Dart 接口定义自动生成三端类型安全代码。

### 9.1 定义接口

创建 `pigeons/api.dart`：

```
import 'package:pigeon/pigeon.dart';

// Dart 调用原生
@HostApi()
abstract class BatteryApi {
  int getBatteryLevel();
  void setVolume(double level);
}

// 原生调用 Dart
@FlutterApi()
abstract class EventCallbackApi {
  void onEvent(String name, Map<String?, Object?> data);
}
```

### 9.2 生成代码

```
dart run pigeon \
  --input pigeons/api.dart \
  --dart_out lib/src/api.g.dart \
  --kotlin_out android/app/src/main/kotlin/com/example/Api.kt \
  --kotlin_package "com.example" \
  --swift_out ios/Runner/Api.swift
```

### 9.3 使用生成的代码

**Dart 侧：**

```
final api = BatteryApi();
final level = await api.getBatteryLevel();   // 编译期类型检查，无字符串
await api.setVolume(0.8);
```

**Android 侧（Kotlin）：**

```
class BatteryApiImpl : Api.BatteryApi {
    override fun getBatteryLevel(): Long = /* ... */
    override fun setVolume(level: Double) { /* ... */ }
}
Api.BatteryApi.setUp(messenger, BatteryApiImpl())
```

**本质：** Pigeon 生成的代码底层仍然是 `MethodChannel`，只是把方法名、参数、返回值变成了强类型接口。**中大型项目和团队协作强烈推荐使用**。

## 十一、性能与选型

### 11.1 单次调用开销参考

| 操作 | 耗时（约） |
| --- | --- |
| 空方法调用（无参数无返回） | 50 ~ 200 μs |
| 传递 1KB Map | 200 ~ 500 μs |
| 传递 100KB 字节（StandardCodec） | 2 ~ 5 ms |
| 传递 100KB 字节（BinaryCodec） | 0.5 ~ 1 ms |

>
> 数据为参考值，因设备和 Flutter 版本而异。

### 11.2 选型决策树

```
需要与原生交互？
├─ 一次性请求-响应 → MethodChannel
├─ 持续数据流 → EventChannel
├─ 自定义协议 / 双向高频消息 → BasicMessageChannel
├─ 传递大量二进制（图片/音频帧） → BasicMessageChannel + BinaryCodec
├─ 嵌入原生 UI 组件 → PlatformView（不是 Channel）
└─ 极致性能 / 已有 C/C++ 库 → dart:ffi（绕过 Engine）
```

### 11.3 与其他跨端方案对比

| 方案 | 通信方向 | 延迟 | 适用场景 |
| --- | --- | --- | --- |
| Platform Channel | 双向 | 中（百μs ~ ms级） | 绝大多数原生 API 调用 |
| PlatformView | 原生 UI 嵌入 | 高（有合成开销） | 地图、WebView、原生相机预览 |
| dart:ffi | Dart ↔ C/C++ | 极低（纳秒级） | 高性能计算、音视频编解码 |
| Texture | 原生 → Dart（视频帧） | 低 | 相机预览、视频渲染 |
| Isolate | Dart ↔ Dart | 低 | 纯 Dart 后台计算 |

## 十二、常见陷阱与最佳实践

### 12.1 通道名称唯一且一致

跨 Dart 和原生必须严格匹配，建议使用反向域名格式：`com.example.app/feature`。不同功能用不同 Channel，不要复用一个 Channel 处理所有方法。

### 12.2 避免阻塞原生主线程

耗时任务（网络、文件 I/O、复杂计算）必须切到后台线程，完成后再通过 `result.success()` 返回。Android 用 Coroutine / Executor，iOS 用 `DispatchQueue.global()`。

### 12.3 正确处理错误

用 `result.error(code, message, details)` 返回业务错误，不要让原生异常直接导致应用崩溃。Dart 侧根据 `PlatformException.code` 做分支处理。

### 12.4 避免内存泄漏

- EventChannel 的 `onCancel` 中**必须**反注册传感器、关闭定时器、移除监听。
- Android 插件 `onDetachedFromEngine` 中设置 handler 为 `null`，避免持有已销毁的 Context。
- iOS 闭包中使用 `[weak self]` 避免循环引用。

### 12.5 Result / FlutterResult 只能调用一次

原生侧的 `Result` 对象和 `FlutterResult` 闭包必须且只能调用一次。重复调用会抛出异常或导致未定义行为。

### 12.6 类型安全

Dart 侧调用 `invokeMethod<T>` 指定期望返回类型。原生返回的数据必须符合标准编解码映射，否则会编码异常。中大型项目优先使用 Pigeon。

### 12.7 减少高频调用

每帧画面级别的数据传输不适合 Platform Channel（序列化和引擎转发开销大）。应使用 `TextureRegistry`、`PlatformView` 或 `dart:ffi`。

### 12.8 热重载 / 热重启的影响

| 操作 | Dart VM | 原生 Handler | 注意事项 |
| --- | --- | --- | --- |
| 热重载（hot reload） | 不重启 | 保留 | 无需重新注册 |
| 热重启（hot restart） | 重启 | 保留 | Dart 侧 handler 丢失，需重新注册；原生调用 Dart 可能暂时收到 notImplemented |
| 完整重启 | 重启 | 重启 | 一切重新初始化 |

>
> 开发时遇到"原生调用 Dart 没反应"，先热重启一次确保两端 handler 对齐。

### 12.9 复杂参数传递约定

`invokeMethod` 的 `arguments` 只能是标准编解码支持的类型。传递复杂对象时约定用 `Map`：

```
await channel.invokeMethod('createUser', {
  'name': '张三',
  'age': 25,
  'tags': ['admin', 'vip'],
  'profile': {'city': '北京'},
});
```

Android 侧用 `call.argument<T>("key")` 便捷取值，iOS 侧手动 `call.arguments as? [String: Any]`。

### 12.10 并发控制

Dart 侧快速多次调用同一方法时，原生侧按调用顺序依次在主线程执行。若原生实现中有共享状态访问，注意加锁或用队列串行化。

## 总结

Platform Channel 的本质是**基于唯一名称路由的异步二进制消息传递**：`BinaryMessenger` 负责底层传输，`MessageCodec` 负责序列化，三种 Channel（Method / Event / Basic）分别对应请求响应、事件流、通用消息三种通信模式。

- **简单场景**：直接使用 MethodChannel / EventChannel。
- **中大型项目**：优先使用 Pigeon 生成类型安全代码。
- **大数据 / 高性能**：考虑 BasicMessageChannel + BinaryCodec，或 dart:ffi。
- **原生 UI**：使用 PlatformView，而非 Channel。

理解其原理、线程模型和限制，是开发稳定高效 Flutter 应用的基础。
