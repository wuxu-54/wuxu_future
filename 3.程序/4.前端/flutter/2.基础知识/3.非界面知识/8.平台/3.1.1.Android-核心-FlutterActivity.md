# FlutterActivity

要在 Android 平台上让一段 Dart 代码变成屏幕上可交互的界面，**`FlutterActivity`** 就是那条最关键的主线。它不只是一个 Activity，更是 Flutter 引擎在 Android 上的**生命周期控制器、渲染容器和交互代理**。下面我会从源码设计到运行原理，把它的内脏全部摊开来讲。

---

## 一、FlutterActivity 的定位

`FlutterActivity` 继承自 `androidx.activity.ComponentActivity`，并且**几乎把所有核心逻辑都委托出去**了——这也是它能与 `FlutterFragment` 共享同一套实现的关键。源码中你会看到：

```java
public class FlutterActivity extends ComponentActivity
    implements FlutterActivityAndFragmentDelegate.Host {
  
  private final FlutterActivityAndFragmentDelegate delegate = 
      new FlutterActivityAndFragmentDelegate(this);
  // ...
  @Override protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    delegate.onAttach(this);
    // 设置视图、创建引擎等
  }
}
```

**真正的“大脑”是 `FlutterActivityAndFragmentDelegate`**。这个委托类负责：

- FlutterEngine 的创建/获取与配置
- FlutterView（渲染视图）的创建与生命周期
- 应用生命周期到引擎的传递
- 平台通道的建立
- 插件注册
- Activity 结果与权限回调的转发

这种设计使得同一套逻辑能够同时用在 `FlutterActivity` 和 `FlutterFragment` 中，两者只需要实现 `Host` 接口提供上下文、生命周期等依赖即可。

---

## 二、委托启动全流程（以自动创建引擎为例）

假设你直接调用 `startActivity(FlutterActivity.class)`，没有使用缓存的引擎。

### 2.1 委托的附着与配置

`FlutterActivity.onCreate` 调用 `delegate.onAttach(this)`，委托内部进行：

1. **获取 FlutterEngine 的意图配置**：`Intent` 中可携带引擎 ID、初始路由、入口点、后台模式等。
2. **决定引擎来源**：
   - 如果有 `CachedEngineId`，从 `FlutterEngineCache` 取。
   - 如果指定了引擎组，则通过 `FlutterEngineGroup` 创建（共享 Dart VM）。
   - 否则，**创建全新引擎**。
3. 调用 `setupFlutterEngine()`，在这里设置 Dart 入口点、初始路由等，并调用 `GeneratedPluginRegistrant.registerWith(engine)` 注册所有自动生成的插件。

### 2.2 渲染视图的创建

委托调用 `createFlutterView()` 创建实际的渲染视图。Android 上有两种选择：

- `FlutterSurfaceView`：基于 `SurfaceView`，渲染在自己的独立窗口上，**性能最好**（零拷贝），但不支持 Z 轴透明叠放。
- `FlutterTextureView`：基于 `TextureView`，渲染在 View 层次结构内，**支持透明度和 View 动画**，但性能稍差（多一次纹理拷贝）。

`FlutterActivity` 默认使用 `FlutterSurfaceView`，除非主题要求透明背景或显式指定使用 `FlutterTextureView`（比如在 FlutterFragment 中需要覆盖在原生视图上）。

创建出来的 `FlutterView` 会被设置为 `Activity` 的内容视图。

### 2.3 引擎与视图的绑定

渲染视图必须连接到引擎才能显示内容。委托调用：

```java
flutterEngine.getRenderer().attachToRenderSurface(flutterView.getRenderSurface());
```

`RenderSurface` 是一个抽象，`FlutterSurfaceView` 和 `FlutterTextureView` 分别实现了它，负责提供 Android `Surface` 给引擎的 Raster 线程，以便引擎可以将像素提交到屏幕上。

## 三、引擎的生命周期管理

Flutter 引擎需要感知 Android 的前后台变化，以便：

- 停止/开始渲染循环（节省 CPU/GPU）
- 暂停/恢复 Dart 定时器和动画
- 管理 Platform Channels 的可用性

委托在 `onStart`、`onResume`、`onPause`、`onStop`、`onDestroy` 中调用引擎的对应方法，映射关系如下：

| Activity 生命周期 | 引擎方法 | 效果 |
|------------------|----------|------|
| `onCreate` → `onStart` | `FlutterEngine.getLifecycleChannel().appIsResumed()` ？非直接 | 完整映射见下 |
| `onResume` | `FlutterEngine.getLifecycleChannel().appIsResumed()` | 应用在前台且可见，恢复渲染和定时器 |
| `onPause` | `FlutterEngine.getLifecycleChannel().appIsPaused()` | 应用失去焦点但可能还可见（如分屏），暂停计时器 |
| `onStop` | `FlutterEngine.getLifecycleChannel().appIsInactive()` | 应用不可见，停止渲染循环 |
| `onDestroy` | `flutterEngine.destroy()` 或引擎回收 | 彻底释放引擎资源 |

引擎的生命周期状态通过 `AppLifecycleListener` 在 Dart 层也可以监听到，原理就是 Platform Channel 传递。

对于**缓存的引擎**，`FlutterActivity` 关闭时不会销毁引擎，只会调用 `appIsInactive()` 等，引擎保留在缓存中等待下一次使用。

## 四、渲染流程：从 Surface 到屏幕

### 4.1 Surface 的准备与提供

在 `FlutterSurfaceView` 中，系统提供的 `SurfaceHolder.Callback` 会在 surface 创建/改变/销毁时被调用。引擎的 Raster 线程通过 `FlutterRenderer` 与此 Surface 对接：

1. 当 surface 可用时，引擎调用 `FlutterJNI.nativeSurfaceCreated(surface)`。
2. Raster 线程拿到 native window，开始光栅化帧到该 window 上。
3. 由于 SurfaceView 有独立的窗口，它可以由系统合成器直接与 View 系统混合，不需要额外的拷贝。

### 4.2 VSync 与帧调度

Android 的 VSync 信号通过 `Choreographer` 获取。引擎内部有一个 `AndroidVsyncWaiter`，注册 `Choreographer.FrameCallback`。每次回调，引擎的 UI 线程被唤醒，驱动 Dart 代码构建帧，然后 Raster 线程光栅化并提交到 Surface。

## 五、触摸事件的传递

用户触摸屏幕 → `FlutterView`（作为 Android View）收到 `onTouchEvent` → 包装成引擎理解的格式（`FlutterPointerEvent`） → 通过 `FlutterRenderer.dispatchPointerDataPacket` 送入引擎。

引擎内部：

1. Platform 线程收到事件后，将其放入 UI 线程的事件队列。
2. UI 线程的 Dart 代码通过 `GestureBinding` 处理命中测试（hit test），分发到对应的 `RenderObject`。
3. 竞争者（手势竞技场）决定谁是最终响应者。

这个过程使得 Flutter 的触摸响应完全在引擎内部闭环，只有原始触摸数据来自原生。

---

## 六、系统按键与返回键

`FlutterActivity` 重写了 `onKeyDown`/`onKeyUp`，将键盘事件发送给引擎。引擎内部通过 `HardwareKeyboard` 和 `RawKeyboard` 传递到 Dart 层。

返回键（`KEYCODE_BACK`）的处理比较特殊：

1. `FlutterActivity.onBackPressed` 被触发。
2. 委托调用 `flutterEngine.getNavigationChannel().popRoute()`，通知 Dart 层。
3. Dart 框架的 `WillPopScope` 可以决定是否拦截。如果 Dart 层未拦截，Activity 才执行默认的 `super.onBackPressed()`。

## 七、平台通道与插件注册

### 7.1 内置通道

引擎在初始化时自动创建几个核心平台通道：

- `flutter/navigation`：系统返回、路由跳转。
- `flutter/lifecycle`：应用前后台状态。
- `flutter/keyevent`：键盘事件。
- `flutter/platform`：剪切板、系统文字、初始路由。
- `flutter/settings`：文本缩放系数、24 小时制等。
- `flutter/localization`：本地化信息。

这些通道的接收端都在引擎 C++ 中，部分会再转发到 Dart 的 framework。

### 7.2 插件注册

`GeneratedPluginRegistrant` 是构建时自动生成的，它会遍历所有依赖的插件，调用它们的 `registerWith()` 方法，把自己挂到引擎上。插件可以获取 `BinaryMessenger`（用于双向通信），从而建立起 Dart ↔ Android 的方法调用通道。

`FlutterActivity` 可以通过 `configureFlutterEngine` 覆盖手动注册插件，这在需要延迟初始化插件时有用。

## 八、Activity 结果与权限回调

由于 Flutter 插件可能需要在原生侧启动 Activity（如拍照）或请求权限，但 `onActivityResult`、`onRequestPermissionsResult` 等回调是 Activity 级别的，引擎必须把这些回调转发给对应的插件。

### 8.1 插件注册活动感知

通过 `ActivityPluginBinding`，插件可以注册：

- `ActivityAware` 接口：告知插件当前 Activity 的生命周期。
- `ActivityResultListener`：拦截 `onActivityResult`。
- `RequestPermissionsResultListener`：拦截权限结果。
- `OnNewIntentListener`：拦截新 Intent。
- `UserLeaveHintListener`：监听用户按下 Home 键。

引擎维护一个 `ActivityControlSurface`，在 Activity 的各种回调中通知所有已注册的监听器。

**流程**（以拍照为例）：

1. 插件通过 `ActivityPluginBinding` 注册一个 `ActivityResultListener`。
2. 插件启动 `Intent` 调用 `startActivityForResult`，引擎会将请求转发给宿主 Activity。
3. 当 Activity 的 `onActivityResult` 被调用，引擎遍历所有监听器，找到匹配的 `requestCode`，调用对应回调。
4. 插件将结果返回给 Dart 侧。

## 九、配置更改与状态保存

当屏幕旋转或语言更改时，Activity 会重建。Flutter 引擎本身不需要重建（因为它在 C++ 堆中独立于 Activity），但需要做两件事：

1. **恢复引擎与视图的连接**：销毁旧的 `FlutterView`，创建新的，调用 `attachToRenderSurface`。
2. **保存和恢复 Flutter 状态**：引擎内部有状态保存机制（Dart 层的 `RestorationManager`），`FlutterActivity` 利用 `onSaveInstanceState` 将引擎状态序列化到 `Bundle` 中，在重建时恢复。

委托在 `onRestoreInstanceState` 中会调用 `flutterEngine.getRestorationChannel().setRestorationData(bundle)`，使得旋转后界面状态不丢失。

---

## 十、FlutterFragment 的复用

`FlutterFragment` 也实现了 `Host` 接口，并同样使用 `FlutterActivityAndFragmentDelegate`。这意味着一个 Fragment 也能承载完整的 Flutter 体验，且可以嵌入到现有原生页面中。

Fragment 的 `onCreateView` 会创建 `FlutterView`，其余逻辑几乎与 `FlutterActivity` 一致。引擎的共享（缓存引擎或引擎组）使得 Fragment 和 Activity 可以非常轻量地集成。

---

## 十一、引擎组的高性能启动

`FlutterEngineGroup` 允许多个 `FlutterActivity`/`Fragment` 共享同一个 Dart VM 和代码堆，但拥有独立的 Isolate（可选）、引擎上下文和渲染表面。第二个引擎的启动几乎只有几十毫秒，不需要重新加载 AOT 快照和初始化 Dart VM。

`FlutterActivity` 通过 `withCachedEngine` 或引擎组构造方式，可以轻松实现混合栈页面的快速打开。

---

## 十二、总结

`FlutterActivity` 的原理就是**通过委托模式，将 Android 的 Activity 生命周期转化为 Flutter 引擎的应用生命周期，将原生渲染表面、输入事件、系统回调全部桥接到 C++ 引擎中，并借助引擎自身的线程模型和 Platform Channels，让 Dart 代码获得完整的原生能力**。

这张网的核心节点是：

- **委托**：让 Activity 和 Fragment 共享逻辑
- **引擎管理**：创建/缓存/共享引擎的多种策略
- **渲染绑定**：SurfaceView/TextureView 的选择与数据流
- **事件桥接**：触摸、按键、返回、权限等全转发
- **生命周期同步**：精确对应 App 状态，保证资源效率

理解透 `FlutterActivity`，你就等于摸清了 Flutter 在 Android 上的所有“接线口”，无论是做性能优化、解决混合栈问题还是自定义嵌入方案，都会有稳固的底层认知。
