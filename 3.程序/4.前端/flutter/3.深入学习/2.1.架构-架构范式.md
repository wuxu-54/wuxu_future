# Flutter 数据层完整架构方案

下面给出一套**生产级可落地**的 Flutter 数据层架构，采用 **Repository 模式 + 分层设计**，兼顾可维护性、可测试性与扩展性。
>注意这是作为参考，我们不必拘泥于此。  细看此架构范式跟之前学的[**项目架构层次**](/3.程序/2.杂章/1.1.架构设计/架构模式/5.1.项目架构层次.md)核心本质是一样的，只不过强调了Clean架构在Flutter的应用。

---

## 一、整体架构分层

```
┌─────────────────────────────────────────┐
│            Presentation Layer           │  (UI / Bloc / Provider / Riverpod)
├─────────────────────────────────────────┤
│             Domain Layer                │  (Repository 抽象 / Entity / UseCase)
├─────────────────────────────────────────┤
│              Data Layer                 │  (Repository 实现 / DataSource / DTO / Mapper)
└─────────────────────────────────────────┘
```

| 层级 | 职责 | 核心产物 |
| --- | --- | --- |
| **Domain 层** | 定义业务契约，不依赖任何外部框架 | `abstract class Repository`、`Entity`、`UseCase` |
| **Data 层** | 真正的数据获取与转换 | `RepositoryImpl`、`RemoteDataSource`、`LocalDataSource`、`DTO`、`Mapper` |
| **Presentation 层** | 消费数据、驱动 UI | `Bloc` / `ViewModel` / `Controller` |

## 三、核心组件详解

### 1. Entity（领域实体）

**作用**：纯 Dart 类，代表业务核心模型，不依赖任何外部库，是整个 App 的"真理来源"。

```
// domain/entities/user.dart
class User {
  final String id;
  final String name;
  final String email;
  final int age;

  const User({
    required this.id,
    required this.name,
    required this.email,
    required this.age,
  });

  User copyWith({String? name, int? age}) => User(
        id: id,
        name: name ?? this.name,
        email: email,
        age: age ?? this.age,
      );
}
```

---

### 2. DTO（数据传输对象）

**作用**：与 API / 本地存储结构一一对应，负责序列化/反序列化。**DTO 不等于 Entity**，API 字段可能变化，但 Entity 保持稳定。

```
// data/models/user_dto.dart
class UserDTO {
  final String userId;
  final String userName;
  final String userEmail;
  final int? userAge;

  UserDTO({
    required this.userId,
    required this.userName,
    required this.userEmail,
    this.userAge,
  });

  factory UserDTO.fromJson(Map<String, dynamic> json) => UserDTO(
        userId: json['user_id'] as String,
        userName: json['user_name'] as String,
        userEmail: json['user_email'] as String,
        userAge: json['user_age'] as int?,
      );

  Map<String, dynamic> toJson() => {
        'user_id': userId,
        'user_name': userName,
        'user_email': userEmail,
        'user_age': userAge,
      };
}
```

---

### 3. Mapper（转换器）

**作用**：隔离 DTO 与 Entity，当 API 字段变化时，只需改 Mapper，不影响业务层。

```
// data/mappers/user_mapper.dart
import '../../domain/entities/user.dart';
import '../models/user_dto.dart';

class UserMapper {
  static User toEntity(UserDTO dto) => User(
        id: dto.userId,
        name: dto.userName,
        email: dto.userEmail,
        age: dto.userAge ?? 0,
      );

  static UserDTO toDTO(User entity) => UserDTO(
        userId: entity.id,
        userName: entity.name,
        userEmail: entity.email,
        userAge: entity.age,
      );
}
```

---

### 4. DataSource（数据源）

**作用**：直接与数据来源交互，分远程和本地两种。**只做原始数据读写，不做业务逻辑**。

#### 远程数据源

```
// data/datasources/remote/user_remote_datasource.dart
import 'package:dio/dio.dart';
import '../../models/user_dto.dart';

abstract class UserRemoteDataSource {
  Future<UserDTO> getUser(String id);
  Future<List<UserDTO>> getUsers();
}

class UserRemoteDataSourceImpl implements UserRemoteDataSource {
  final Dio dio;

  UserRemoteDataSourceImpl(this.dio);

  @override
  Future<UserDTO> getUser(String id) async {
    final response = await dio.get('/users/$id');
    return UserDTO.fromJson(response.data);
  }

  @override
  Future<List<UserDTO>> getUsers() async {
    final response = await dio.get('/users');
    return (response.data as List)
        .map((json) => UserDTO.fromJson(json))
        .toList();
  }
}
```

#### 本地数据源

```
// data/datasources/local/user_local_datasource.dart
import 'package:hive/hive.dart';
import '../../models/user_dto.dart';

abstract class UserLocalDataSource {
  Future<UserDTO?> getCachedUser(String id);
  Future<void> cacheUser(UserDTO user);
}

class UserLocalDataSourceImpl implements UserLocalDataSource {
  final Box<UserDTO> userBox;

  UserLocalDataSourceImpl(this.userBox);

  @override
  Future<UserDTO?> getCachedUser(String id) async {
    return userBox.get(id);
  }

  @override
  Future<void> cacheUser(UserDTO user) async {
    await userBox.put(user.userId, user);
  }
}
```

### 5. Repository（仓库）

**作用**：数据层的统一入口，决定数据从哪里来（远程/本地/混合），处理缓存策略，将 DTO 转为 Entity 交给上层。

#### 抽象接口（Domain 层）

```
// domain/repositories/user_repository.dart
import '../entities/user.dart';
import '../../core/error/failure.dart';
import 'package:dartz/dartz.dart';

abstract class UserRepository {
  Future<Either<Failure, User>> getUser(String id);
  Future<Either<Failure, List<User>>> getUsers();
}
```

#### 实现（Data 层）

```
// data/repositories/user_repository_impl.dart
import '../../domain/entities/user.dart';
import '../../domain/repositories/user_repository.dart';
import '../../core/error/failure.dart';
import '../../core/error/exceptions.dart';
import '../../core/network/network_info.dart';
import '../datasources/remote/user_remote_datasource.dart';
import '../datasources/local/user_local_datasource.dart';
import '../mappers/user_mapper.dart';
import 'package:dartz/dartz.dart';

class UserRepositoryImpl implements UserRepository {
  final UserRemoteDataSource remoteDataSource;
  final UserLocalDataSource localDataSource;
  final NetworkInfo networkInfo;

  UserRepositoryImpl({
    required this.remoteDataSource,
    required this.localDataSource,
    required this.networkInfo,
  });

  @override
  Future<Either<Failure, User>> getUser(String id) async {
    try {
      if (await networkInfo.isConnected) {
        // 有网：先拉远程，再缓存
        final remoteUser = await remoteDataSource.getUser(id);
        await localDataSource.cacheUser(remoteUser);
        return Right(UserMapper.toEntity(remoteUser));
      } else {
        // 无网：读本地缓存
        final localUser = await localDataSource.getCachedUser(id);
        if (localUser != null) {
          return Right(UserMapper.toEntity(localUser));
        }
        return Left(CacheFailure('暂无缓存数据'));
      }
    } on ServerException catch (e) {
      return Left(ServerFailure(e.message));
    } on CacheException catch (e) {
      return Left(CacheFailure(e.message));
    }
  }

  @override
  Future<Either<Failure, List<User>>> getUsers() async {
    // 类似实现...
    throw UnimplementedError();
  }
}
```

### 6. 统一错误处理

**作用**：将各种异常（网络错误、服务器错误、缓存错误）统一为 `Failure`，上层只处理 `Failure`，不感知底层细节。

```
// core/error/failure.dart
abstract class Failure {
  final String message;
  const Failure(this.message);
}

class ServerFailure extends Failure {
  const ServerFailure(super.message);
}

class CacheFailure extends Failure {
  const CacheFailure(super.message);
}

class NetworkFailure extends Failure {
  const NetworkFailure(super.message) : super('网络连接失败，请检查网络');
}
```

```
// core/error/exceptions.dart
class ServerException implements Exception {
  final String message;
  final int? statusCode;
  const ServerException(this.message, {this.statusCode});
}

class CacheException implements Exception {
  final String message;
  const CacheException(this.message);
}
```

### 7. UseCase（用例，可选但推荐）

**作用**：封装单个业务动作，让 Bloc/ViewModel 更薄，业务逻辑更集中。

```
// domain/usecases/get_user_usecase.dart
import '../entities/user.dart';
import '../repositories/user_repository.dart';
import '../../core/error/failure.dart';
import 'package:dartz/dartz.dart';

class GetUserUseCase {
  final UserRepository repository;

  GetUserUseCase(this.repository);

  Future<Either<Failure, User>> call(String id) async {
    // 可在此添加业务校验、参数处理等
    if (id.isEmpty) {
      return const Left(ServerFailure('用户ID不能为空'));
    }
    return repository.getUser(id);
  }
}
```

## 四、完整数据流转流程

```
UI 触发事件
    │
    ▼
Bloc / ViewModel
    │ 调用 UseCase
    ▼
UseCase (业务逻辑编排)
    │ 调用 Repository
    ▼
RepositoryImpl (决策数据来源)
    ├─→ 检查网络状态
    ├─→ RemoteDataSource → Dio → API 返回 JSON → DTO
    ├─→ LocalDataSource  → Hive/Isar → 缓存数据 → DTO
    │
    ▼
Mapper (DTO → Entity)
    │
    ▼
Repository 返回 Either<Failure, Entity>
    │
    ▼
UseCase 返回结果
    │
    ▼
Bloc / ViewModel 发出新状态
    │
    ▼
UI 刷新
```

## 五、依赖注入配置

使用 `get_it` 管理所有依赖，实现解耦：

```
// core/di/injection.dart
import 'package:get_it/get_it.dart';
import 'package:dio/dio.dart';
import 'package:hive/hive.dart';

final sl = GetIt.instance;

Future<void> initDependencies() async {
  // ========== Core ==========
  sl.registerLazySingleton<Dio>(() => DioClient().dio);
  sl.registerLazySingleton<NetworkInfo>(() => NetworkInfoImpl());

  // ========== Local DataSources ==========
  final userBox = await Hive.openBox<UserDTO>('users');
  sl.registerLazySingleton<Box<UserDTO>>(() => userBox);
  sl.registerLazySingleton<UserLocalDataSource>(
    () => UserLocalDataSourceImpl(sl()),
  );

  // ========== Remote DataSources ==========
  sl.registerLazySingleton<UserRemoteDataSource>(
    () => UserRemoteDataSourceImpl(sl()),
  );

  // ========== Repositories ==========
  sl.registerLazySingleton<UserRepository>(
    () => UserRepositoryImpl(
      remoteDataSource: sl(),
      localDataSource: sl(),
      networkInfo: sl(),
    ),
  );

  // ========== UseCases ==========
  sl.registerLazySingleton(() => GetUserUseCase(sl()));
}
```

## 六、缓存策略设计

根据业务场景选择不同策略：

| 策略 | 适用场景 | 实现方式 |
| --- | --- | --- |
| **Cache First** | 不频繁变化的数据（配置、字典） | 先读本地，没有再请求远程 |
| **Network First** | 实时性要求高的数据 | 先请求远程，失败再降级到缓存 |
| **Stale-While-Revalidate** | 既要快又要新 | 立即返回缓存，同时后台刷新 |
| **Refresh Every N min** | 定时更新的数据 | 加时间戳判断是否过期 |

```
// Stale-While-Revalidate 示例
Future<Either<Failure, User>> getUser(String id) async {
  // 1. 先返回缓存（如果有）
  final cached = await localDataSource.getCachedUser(id);
  if (cached != null) {
    // 后台静默刷新
    _refreshInBackground(id);
    return Right(UserMapper.toEntity(cached));
  }

  // 2. 没有缓存则走网络
  try {
    final remote = await remoteDataSource.getUser(id);
    await localDataSource.cacheUser(remote);
    return Right(UserMapper.toEntity(remote));
  } catch (e) {
    return Left(ServerFailure(e.toString()));
  }
}
```

## 七、各层职责边界总结

| 层级 | 可以做什么 | **禁止做什么** |
| --- | --- | --- |
| **Entity** | 纯数据 + 业务方法 | 依赖 JSON 序列化、依赖 Flutter |
| **DTO** | JSON 序列化/反序列化 | 包含业务逻辑 |
| **Mapper** | DTO ↔ Entity 转换 | 包含业务判断 |
| **DataSource** | 原始数据读写（API/DB） | 业务逻辑、DTO→Entity 转换 |
| **Repository** | 数据源选择、缓存策略、错误转换 | UI 相关、复杂业务编排 |
| **UseCase** | 业务规则编排、参数校验 | 直接操作 DataSource |
| **Bloc/VM** | 状态管理、UI 逻辑 | 直接调用 DataSource |

## 八、推荐技术栈

| 功能 | 推荐库 | 备选 |
| --- | --- | --- |
| 网络请求 | **Dio** | http |
| 类型安全 API | **Retrofit** | 手写 |
| 本地存储 | **Isar** / **Hive** | Drift(SQLite) |
| 依赖注入 | **get\_it** | injectable |
| 函数式错误处理 | **dartz** | 自实现 Either |
| 状态管理 | **Bloc** / **Riverpod** | Provider |
| JSON 序列化 | **json\_serializable** | 手写 |
| 连接状态 | **connectivity\_plus** | - |

这套架构的核心价值是**关注点分离**：API 改字段改 Mapper、换数据库改 DataSource、加业务逻辑加 UseCase，每层变化都不会波及其他层，长期维护成本极低。
