# readonly

## 一、`readonly` 核心定义

`readonly` 是 Vue3 提供的核心响应式 API，用于**创建一个只读的响应式对象**。你可以读取这个对象的所有属性，但无法直接修改它的任何属性（包括嵌套属性）；如果尝试直接修改，Vue 会在**开发环境**中抛出警告，生产环境则静默失败，以此保护数据不被意外篡改。

它与 `reactive` 互补：`reactive` 创建可修改的响应式对象，`readonly` 则创建仅可读的响应式对象。

## 二、基本用法

### 1. 基础使用（深层只读）

`readonly` 默认是「深层只读」，所有嵌套属性都无法直接修改：

```vue
<template>
  <div>
    <p>姓名：{{ readonlyUser.name }}</p>
    <p>城市：{{ readonlyUser.address.city }}</p>
    <button @click="tryModify">尝试直接修改</button>
  </div>
</template>

<script setup>
import { readonly } from 'vue'

// 原始对象（也可以是 reactive 创建的响应式对象）
const originalUser = {
  name: '张三',
  age: 20,
  address: { city: '北京' }
}

// 创建只读的响应式对象
const readonlyUser = readonly(originalUser)

// 尝试直接修改：开发环境告警，修改无效
const tryModify = () => {
  readonlyUser.name = '李四' // 顶层属性修改无效
  readonlyUser.address.city = '上海' // 嵌套属性修改也无效
  console.log(readonlyUser) // 仍为原始值
}
</script>
```

### 2. 浅层只读：`shallowReadonly`

如果只需限制「顶层属性」只读，嵌套属性允许修改，可使用 `shallowReadonly`：

```javascript
import { shallowReadonly } from 'vue'

const shallowUser = shallowReadonly({
  name: '张三',
  address: { city: '北京' }
})

// 顶层属性修改：告警，无效
shallowUser.name = '李四'
// 嵌套属性修改：无告警，有效
shallowUser.address.city = '上海'
console.log(shallowUser.address.city) // 输出 "上海"
```

## 三、核心特性

1. **响应式保留**：`readonly` 返回的对象仍具备响应式（原始数据源变化时，视图会同步更新），只是无法手动修改自身；
2. **引用关联**：`readonly` 是对原始对象的「只读代理」，而非独立拷贝。若原始对象是 `reactive` 创建的响应式对象，修改原始对象会同步更新 `readonly` 对象：

   ```javascript
   import { reactive, readonly } from 'vue'
   
   const reactiveUser = reactive({ name: '张三' })
   const readonlyUser = readonly(reactiveUser)
   
   // 修改原始响应式对象，readonly 对象同步更新
   reactiveUser.name = '李四'
   console.log(readonlyUser.name) // 输出 "李四"
   ```

## 四、常见使用场景

1. **全局状态保护**：在 Pinia/Vuex 中，对外暴露的状态用 `readonly` 包装，防止组件直接修改全局状态（仅允许通过 action/mutation 修改）；
2. **组件传参隔离**：父组件向子组件传递响应式数据时，用 `readonly` 包装，避免子组件意外修改父组件数据；
3. **常量配置封装**：封装工具类、全局配置项时，用 `readonly` 确保配置数据不被业务代码篡改。

## 五、如何修改 `readonly` 对象的值？

**核心结论**：`readonly` 对象本身无法直接修改（无论内部还是外部），必须通过修改它的「原始数据源」实现更新。

### 1. 基础场景：修改原始响应式对象

如果 `readonly` 基于 `reactive` 对象创建，直接修改原始 `reactive` 对象即可同步更新 `readonly` 对象：

```vue
<template>
  <div>
    <p>只读对象的值：{{ readonlyObj.msg }}</p>
    <button @click="updateValue">修改值</button>
  </div>
</template>

<script setup>
import { reactive, readonly } from 'vue'

// 步骤1：创建原始响应式数据源
const originalObj = reactive({
  msg: '初始值'
})

// 步骤2：创建只读代理
const readonlyObj = readonly(originalObj)

// 步骤3：修改原始对象 → readonlyObj 同步更新
const updateValue = () => {
  originalObj.msg = '修改后的值' // ✅ 正确方式
  // readonlyObj.msg = '直接修改' // ❌ 错误：直接修改只读对象无效
}
</script>
```

### 2. 实战场景：Pinia 中受控修改（推荐）

实际项目中，通常通过「受控方法（action）」修改原始状态，对外仅暴露 `readonly` 状态，保证修改行为可追溯：

```javascript
// stores/counter.js
import { defineStore } from 'pinia'
import { reactive, readonly } from 'vue'

export const useCounterStore = defineStore('counter', () => {
  // 1. 内部原始响应式状态（可修改）
  const state = reactive({ count: 0 })

  // 2. 对外暴露只读版本的状态（防止直接修改）
  const readonlyState = readonly(state)

  // 3. 提供受控的修改方法（唯一修改入口）
  const increment = () => {
    state.count++ // 内部修改原始状态
  }

  // 对外暴露：只读状态 + 受控方法
  return { readonlyState, increment }
})
```

组件中使用：

```vue
<script setup>
import { useCounterStore } from '@/stores/counter'
const store = useCounterStore()

// ✅ 正确：通过受控方法修改
const add = () => store.increment()
// ❌ 错误：直接修改只读状态（告警，无效）
// store.readonlyState.count++
</script>

<template>
  <p>计数：{{ store.readonlyState.count }}</p>
  <button @click="add">+1</button>
</template>
```

## 六、关键注意事项

1. 无法「绕过」只读限制：任何直接修改 `readonly` 对象的操作都会被拦截，开发环境告警、生产环境静默失败；
2. 代理而非拷贝：`readonly` 与原始对象共享引用，修改原始对象会实时同步到 `readonly` 代理；
3. 普通对象的特殊情况：若 `readonly` 基于「非响应式普通对象」创建，修改普通对象虽能同步值，但视图不会响应式更新（因此实际开发中建议先将原始对象转为 `reactive`）。

## 总结

1. `readonly` 用于创建只读的响应式对象，默认深层只读，浅层只读可使用 `shallowReadonly`，核心作用是保护数据不被意外篡改；
2. `readonly` 对象本身无法直接修改，必须通过修改它所代理的**原始响应式对象**实现更新，实战中推荐通过受控方法（如 Pinia 的 action）修改；
3. 常见应用场景包括全局状态保护、组件传参隔离、常量配置封装等。
