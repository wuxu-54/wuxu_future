# @uni-helper/vite-plugin-uni-pages 超详细深度指南

**@uni-helper/vite-plugin-uni-pages** 是 **uni-app (Vue3/Vite) 生态下唯一官方推荐的文件系统路由自动化插件**，核心作用是**基于目录结构自动生成 `pages.json`**，彻底解放手动维护路由的繁琐工作，同时提供全局配置、页面级配置、分包、类型安全等完整工程化能力。

以下从**核心原理、安装配置、路由规则、全局/页面配置、分包、类型系统、高级特性、常见问题**等维度，进行最完整、精准的详解。

---

## 一、插件核心定位与设计理念

### 1. 定位

- **uni-app Vite 专用**：仅适配 uni-app Vue3 + Vite 环境，不兼容 Webpack 与非 uni-app 项目
- **编译时插件**：开发/构建时扫描文件、生成 `pages.json`，**无运行时损耗**
- **约定优于配置**：以 `src/pages` 目录结构为路由映射，减少冗余配置
- **配置合并策略**：**手动路由 > 页面内 `<route>` 块 > 自动扫描路由 > 全局配置**

### 2. 解决的核心痛点

- 新增/删除页面必须手动修改 `pages.json`，易遗漏、易出错
- 分包（subPackages）配置繁琐、路径易写错
- 全局样式、tabBar、页面样式分散维护
- 大型项目路由表庞大、可读性差、协作成本高
- 无类型安全，路由路径拼写错误难以及时发现

## 二、完整安装流程

### 1. 环境要求

- uni-app ≥ 3.99.0（Vue3 + Vite 版）
- Node ≥ 16
- Vite ≥ 4.0

### 2. 安装命令

```bash
# npm
npm install -D @uni-helper/vite-plugin-uni-pages

# yarn
yarn add -D @uni-helper/vite-plugin-uni-pages

# pnpm（推荐）
pnpm add -D @uni-helper/vite-plugin-uni-pages
```

### 3. vite.config.ts 基础配置（**必须放在 Uni() 之前**）

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'
// 1. 导入插件
import UniPages from '@uni-helper/vite-plugin-uni-pages'

export default defineConfig({
  plugins: [
    // 2. 注册插件（必须在 uni() 之前）
    UniPages({
      // 基础配置（可选）
      configPath: 'src/pages.config.ts', // 全局配置文件路径
      pagesJsonPath: 'src/pages.json',  // 生成的 pages.json 路径
      dts: 'src/uni-pages.d.ts',        // 类型文件输出路径
      exclude: ['**/components/**', '**/composables/**'], // 排除目录
      routeBlockLang: 'json5',          // 默认 <route> 块语法：json/json5/yaml
    }),
    uni(), // uni 核心插件（后置）
  ],
})
```

**关键约束**：插件顺序**绝对不能颠倒**，否则无法生成 `pages.json`。

## 三、路由映射规则（精准约定）

插件默认扫描 `src/pages` 目录，**目录结构 = 路由路径**，规则如下：

### 1. 基础路由（最常用）

```
src/pages/
├── index/index.vue       →  path: "pages/index/index"（首页）
├── user/login.vue        →  path: "pages/user/login"
├── user/profile.vue      →  path: "pages/user/profile"
└── about.vue             →  path: "pages/about"
```

- `index.vue`：目录默认页（如 `pages/index/index.vue` → 首页）
- 单文件页面：直接映射为路径（如 `about.vue` → `/pages/about`）

### 2. 首页指定规则

- 方式1：`pages/index/index.vue` 默认识别为首页
- 方式2：在 `pages.config.ts` 或 `<route>` 块显式声明 `home: true`
- 方式3：插件配置 `homePage: 'pages/index/index'` 强制指定

### 3. 忽略规则

- 排除 `components/`、`utils/`、`composables/` 等目录（可通过 `exclude` 自定义）
- 以下划线开头的文件/目录（如 `_components/`、`_utils.vue`）默认忽略
- 非 `.vue` 文件默认忽略

## 四、全局配置：pages.config.ts（核心）

替代原生 `pages.json`，支持 **TS 类型提示、条件编译、集中管理全局配置**。

### 1. 创建与基础结构

```typescript
// src/pages.config.ts
import { defineUniPages } from '@uni-helper/vite-plugin-uni-pages'

export default defineUniPages({
  // 1. 全局样式（等同 pages.json globalStyle）
  globalStyle: {
    navigationBarTextStyle: 'black',
    navigationBarTitleText: '应用名称',
    navigationBarBackgroundColor: '#ffffff',
    backgroundColor: '#f5f5f5',
    // 平台专属配置（条件编译）
    'mp-weixin': {
      navigationStyle: 'custom', // 微信小程序自定义导航栏
    },
    'h5': {
      titleNView: false,
    },
  },

  // 2. 手动路由（优先级最高，用于特殊页面）
  pages: [
    {
      path: 'pages/index/index',
      style: {
        navigationBarTitleText: '首页',
      },
    },
  ],

  // 3. 分包配置（自动/手动）
  subPackages: [],

  // 4. TabBar 配置
  tabBar: {
    color: '#666666',
    selectedColor: '#07c160',
    backgroundColor: '#ffffff',
    list: [
      {
        pagePath: 'pages/index/index',
        text: '首页',
        iconPath: 'static/tab/home.png',
        selectedIconPath: 'static/tab/home-active.png',
      },
      {
        pagePath: 'pages/user/profile',
        text: '我的',
      },
    ],
  },

  // 5. 其他配置（easycom、uniIdRouter 等）
  easycom: {
    autoscan: true,
    custom: {
      '^u-(.*)': 'uview-plus/components/u-$1/u-$1.vue',
    },
  },

  // 6. 条件编译（支持 #ifdef、#ifndef）
  // #ifdef H5
  h5: {
    devServer: {
      port: 3000,
    },
  },
  // #endif
})
```

### 2. 核心特性

- **TS 类型安全**：`defineUniPages` 提供完整类型提示，杜绝配置错误
- **条件编译**：原生支持 `#ifdef H5/MP-WEIXIN` 等平台差异化配置
- **合并规则**：自动扫描路由 + 手动路由合并，手动路由覆盖自动路由
- **全配置兼容**：支持 `pages.json` 所有字段（`globalStyle`、`tabBar`、`subPackages`、`easycom` 等）

## 五、页面级配置：SFC 内联 <route> 块（最强大）

在 `.vue` 文件中使用 `<route>` 块，**单页面自治配置**，覆盖全局样式与自动路由。

### 1. 语法支持（3 种）

- `lang="json"`（标准 JSON）
- `lang="json5"`（推荐，支持注释、逗号省略）
- `lang="yaml"`（YAML 语法）

### 2. 完整示例（json5）

```vue
<!-- src/pages/user/profile.vue -->
<route lang="json5">
{
  // 1. 设为首页（优先级最高）
  home: false,

  // 2. 页面样式（覆盖 globalStyle）
  style: {
    navigationBarTitleText: "个人中心",
    navigationBarHidden: true, // 隐藏导航栏
    enablePullDownRefresh: true, // 开启下拉刷新
    "mp-weixin": {
      app-plus: {
        titleNView: false
      }
    }
  },

  // 3. 路由别名（uni-app 跳转可用）
  alias: "/profile",

  // 4. 指定分包（自动归类到对应分包）
  subPackage: "user",

  // 5. 路由元信息（自定义参数，代码中可读取）
  meta: {
    requiresAuth: true, // 需要登录
    keepAlive: true,    // 页面缓存
    title: "个人中心"
  }
}
</route>

<template>
  <view class="profile">个人中心页面</view>
</template>

<script setup>
// 代码中读取路由元信息（需配合 uni-app API）
const pages = getCurrentPages()
const currentPage = pages[pages.length - 1]
const routeMeta = currentPage?.routeOptions?.meta
</script>
```

### 3. 核心能力

- **页面自治**：路由、样式、权限配置与页面绑定，便于维护
- **覆盖优先级**：`<route>` 块 > 全局配置
- **平台差异化**：支持 `mp-weixin`/`h5`/`app-plus` 等平台专属配置
- **元信息传递**：自定义 `meta` 字段，用于权限、缓存、埋点等

## 六、分包（subPackages）完整配置（核心能力）

uni-app 分包用于**按需加载、减少包体积**，插件**自动识别 + 手动配置**双模式。

### 1. 自动识别分包（推荐）

#### 规则

- 目录名包含 `sub`/`package`/`pages-sub` → 自动识别为分包根目录
- 示例结构：

```
src/
├── pages/               # 主包
│   └── index/index.vue
└── pages-sub/           # 自动识别为分包（root: "pages-sub"）
    ├── user/            # 分包页面
    │   ├── login.vue
    │   └── profile.vue
    └── order/
        └── list.vue
```

#### 自动生成结果（pages.json）

```json
{
  "subPackages": [
    {
      "root": "pages-sub",
      "pages": [
        { "path": "user/login" },
        { "path": "user/profile" },
        { "path": "order/list" }
      ]
    }
  ]
}
```

### 2. 手动指定分包（精准控制）

#### 方式1：vite.config.ts 配置

```typescript
// vite.config.ts
UniPages({
  subPackages: [
    // 分包1：src/pages-sub/user
    { root: 'pages-sub/user', pages: [] },
    // 分包2：src/pages-sub/order
    { root: 'pages-sub/order', pages: [] },
  ],
})
```

#### 方式2：页面 <route> 块指定

```vue
<!-- src/pages-sub/user/login.vue -->
<route lang="json5">
{
  subPackage: "user" // 强制归属 user 分包
}
</route>
```

#### 方式3：pages.config.ts 手动配置

```typescript
// pages.config.ts
subPackages: [
  {
    root: 'pages-sub/user',
    pages: [
      // 手动添加（覆盖自动扫描）
      { path: 'login', style: { navigationBarTitleText: '登录' } }
    ]
  }
]
```

### 3. 分包优势

- 自动扫描分包页面，无需手动维护 `subPackages.pages`
- 支持跨目录分包、嵌套分包
- 主包/分包路由自动合并，无冲突

## 七、TypeScript 类型系统（类型安全）

插件自动生成 **路由路径类型文件**，杜绝跳转路径拼写错误。

### 1. 开启类型生成

```typescript
// vite.config.ts
UniPages({
  dts: 'src/uni-pages.d.ts', // 输出路径
})
```

### 2. 自动生成的类型文件（uni-pages.d.ts）

```typescript
// 自动生成，请勿手动修改
declare module '~uni-pages' {
  export type Pages = {
    'pages/index/index': { /* 路由元信息 */ }
    'pages/user/login': { /* 路由元信息 */ }
    'pages/user/profile': { /* 路由元信息 */ }
  }

  export type PagePaths = keyof Pages
}
```

### 3. 代码中使用类型提示

```typescript
// 跳转时获得路径智能提示
import type { PagePaths } from '~uni-pages'

// 正确：自动提示所有路由路径
uni.navigateTo({
  url: `/pages/user/profile` as PagePaths
})

// 错误：拼写错误时 TS 直接报错
uni.navigateTo({
  url: `/pages/user/profil` // TS 报错：不存在该路径
})
```

## 八、完整配置项清单（精准参数）

### 1. 插件配置（vite.config.ts 内 UniPages）

| 参数 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `configPath` | `string` | `src/pages.config.ts` | 全局配置文件路径 |
| `pagesJsonPath` | `string` | `src/pages.json` | 生成的 pages.json 路径 |
| `dirs` | `string[]` | `['src/pages']` | 扫描目录列表 |
| `exclude` | `string[]` | `['**/components/**']` | 排除的文件/目录 |
| `subPackages` | `string[]/object[]` | `[]` | 分包根目录配置 |
| `routeBlockLang` | `string` | `json5` | `<route>` 块默认语法 |
| `dts` | `string/boolean` | `false` | 类型文件路径，`false` 关闭 |
| `homePage` | `string` | - | 强制指定首页路径 |
| `mergePages` | `boolean` | `true` | 合并手动路由与自动路由 |
| `minify` | `boolean` | `true` | 压缩生成的 pages.json |
| `debug` | `boolean` | `false` | 开启调试日志 |
| `onBeforeWriteFile` | `(ctx) => void` | - | 写入 pages.json 前钩子 |

### 2. <route> 块配置项

| 参数 | 类型 | 说明 |
| :--- | :--- | :--- |
| `home` | `boolean` | 是否为首页 |
| `path` | `string` | 自定义路由路径（覆盖自动路径） |
| `style` | `object` | 页面样式（覆盖全局） |
| `alias` | `string` | 路由别名 |
| `subPackage` | `string` | 归属分包名称 |
| `meta` | `object` | 自定义路由元信息 |

## 九、高级特性与最佳实践

### 1. 条件编译（全场景支持）

- **pages.config.ts**：

```typescript
// #ifdef MP-WEIXIN
globalStyle: { navigationBarBackgroundColor: '#123456' }
// #endif
```

- **<route> 块**：

```vue
<route lang="json5">
{
  // #ifdef H5
  style: { navigationBarHidden: true },
  // #endif
}
</route>
```

### 2. 自定义首页（多场景）

- 单首页：`pages/index/index.vue` 或 `home: true`
- 多平台首页：

```typescript
// pages.config.ts
// #ifdef MP-WEIXIN
pages: [{ path: 'pages/weixin/index', home: true }]
// #endif
// #ifdef H5
pages: [{ path: 'pages/h5/index', home: true }]
// #endif
```

### 3. 忽略特定页面

```typescript
// vite.config.ts
UniPages({
  exclude: [
    '**/components/**',
    '**/test/**',       // 忽略测试目录
    '**/draft/**',      // 忽略草稿页面
  ]
})
```

### 4. 配合 uni-helper 生态

- `@uni-helper/vite-plugin-uni-manifest`：自动生成 `manifest.json`
- `@uni-helper/uni-env`：环境变量管理
- 组合使用实现 **全配置自动化**

## 十、常见问题与解决方案

### 1. pages.json 不生成/不更新

- 检查插件顺序：`UniPages()` 必须在 `uni()` 之前
- 清除缓存：`pnpm dev --force` 或删除 `.uni_modules`
- 检查 `exclude` 配置是否误屏蔽页面目录

### 2. 分包不生效

- 分包目录必须在 `src/` 下，且命名符合规则
- 检查 `subPackages` 配置路径是否正确
- 页面 `<route>` 块 `subPackage` 字段是否正确

### 3. 类型文件不生成/无提示

- 配置 `dts: 'src/uni-pages.d.ts'`
- VSCode 重启 TypeScript 服务：`Ctrl+Shift+P > TypeScript: Restart TS Server`
- 确保 `src/` 下有 `tsconfig.json`

### 4. 路由冲突/覆盖

- 遵循优先级：**手动路由 > <route> 块 > 自动路由**
- 避免重复路径，检查目录命名

## 十一、总结：为什么选择它？

- **uni-app 生态最优**：完全适配 `pages.json`、分包、tabBar、多端差异
- **零运行时成本**：编译时生成，不影响应用性能
- **双配置模式**：全局集中 + 页面自治，灵活适配大小项目
- **类型安全**：彻底杜绝路由路径拼写错误
- **工程化完善**：条件编译、调试日志、钩子函数、类型生成全覆盖

**适用场景**：所有 uni-app Vue3 + Vite 项目（小程序/App/H5），尤其**中大型分包项目、团队协作项目**。
