
# unplugin-vue-router

**unplugin-vue-router** 是由 Vue Router 作者 posva 开发的 **下一代、官方级别的 Vue 自动化路由插件**，核心是基于**文件系统约定**自动生成路由配置，并提供**极致的 TypeScript 类型安全**。它已在 **Vue Router 5** 中被合并为核心功能，是 Vue 生态路由开发的未来标准。

以下从**核心原理、安装配置、路由命名规则、类型系统、高级特性、数据加载器、常见问题**等维度，进行最完整、精准的深度详解。

---

## 一、核心定位与设计理念

### 1. 官方定位

- **Vue Router 官方自动化路由方案**：已合并至 `vuejs/router` 仓库，是 Vue Router 5+ 的核心功能。
- **构建时插件**：基于 `unplugin` 构建，在编译阶段扫描文件、生成路由与类型，**无运行时额外开销**。
- **跨构建工具**：支持 Vite、Webpack、Rollup、esbuild 全生态。
- **约定优于配置**：以 `src/pages` 目录结构映射路由，减少冗余代码。
- **类型安全**：最大亮点，路由名称、路径、参数、查询全链路 TS 类型校验。

### 2. 解决的核心痛点

- 手动维护路由表（`routes` 数组）繁琐、易遗漏、易拼写错误。
- 动态路由、嵌套路由配置复杂，可读性差。
- 路由跳转时无类型提示，`params`/`query` 类型错误只能运行时暴露。
- 中大型项目路由结构复杂，协作维护成本高。
- 数据预加载与路由耦合度低，状态管理混乱。

### 3. 核心优势总结

- ✅ **零配置启动**：创建文件即生成路由。
- ✅ **极致类型安全**：编译期拦截所有路由错误。
- ✅ **嵌套/动态/通配路由**：完美支持复杂路由结构。
- ✅ **布局系统**：`+layout.vue` 实现页面布局复用。
- ✅ **数据加载器（实验）**：路由级数据预获取。
- ✅ **官方维护**：与 Vue/Vite/TS 深度协同，长期稳定。

## 二、环境要求与安装

### 1. 版本依赖

- **Vue 3** ≥ 3.2
- **Vue Router** ≥ 4.4.0（推荐 ≥ 5.0，已内置）
- **TypeScript** ≥ 4.9（类型安全必需）
- **构建工具**：Vite ≥ 4.0 / Webpack ≥ 5.0

### 2. 安装命令

```bash
# npm

npm install vue-router@4 # 或 vue-router@5

# pnpm (推荐)
pnpm add -D unplugin-vue-router
pnpm add vue-router@next
```

## 三、完整配置（Vite 示例）

### 1. vite.config.ts（核心配置）

**必须在 Vue 插件之前注册**。

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import Vue from '@vitejs/plugin-vue'
// 1. 导入插件
import VueRouter from 'unplugin-vue-router/vite'

export default defineConfig({
  plugins: [
    // 2. 注册路由插件 (必须在 Vue() 之前)
    VueRouter({
      // 👇 核心配置项（完整清单见下文）
      routesFolder: 'src/pages', // 扫描目录（默认）
      dts: 'src/typed-router.d.ts', // 类型文件输出路径
      exclude: ['**/components/**', '**/hooks/**'], // 排除目录
      extensions: ['.vue'], // 扫描文件扩展名
      layoutFilename: '+layout.vue', // 布局组件文件名
      routeNameSeparator: '-', // 路由名称分隔符
      importMode: 'async', // 懒加载模式：async | sync
    }),
    Vue(), // Vue 插件 (后置)
  ],
})
```

### 2. 路由入口配置 (router/index.ts)

从虚拟模块 `vue-router/auto-routes` 导入自动生成的路由。

```typescript
// src/router/index.ts
import { createRouter, createWebHistory } from 'vue-router'
// 👇 自动生成的路由（虚拟模块）
import { routes } from 'vue-router/auto-routes'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes, // 直接使用自动生成的路由
  scrollBehavior(to, from, savedPosition) {
    return savedPosition || { top: 0 }
  },
})

// 全局守卫等正常配置
router.beforeEach((to, from) => {
  // 可访问 to.meta 类型安全
  if (to.meta.requiresAuth && !isAuthenticated) {
    return { name: 'login' }
  }
})

export default router
```

### 3. TypeScript 类型配置

为了获得完整的编辑器提示，需在 `env.d.ts` 或 `tsconfig.json` 中声明类型。

**方式 1：env.d.ts（推荐）**

```typescript
// src/env.d.ts
/// <reference types="vite/client" />
/// <reference types="unplugin-vue-router/client" />
```

**方式 2：tsconfig.json**

```json
{
  "compilerOptions": {
    "types": ["unplugin-vue-router/client"]
  }
}
```

## 四、文件系统路由规则（精准详解）

### 1. 基础路由规则（静态）

**目录结构 = 路由路径**，`index.vue` 为目录默认页。

```
src/pages/
├── index.vue          →  /            (name: 'index')
├── about.vue          →  /about       (name: 'about')
├── user/
│   ├── index.vue      →  /user        (name: 'user')
│   └── profile.vue    →  /user/profile (name: 'user-profile')
└── dashboard/
    └── settings.vue   →  /dashboard/settings (name: 'dashboard-settings')
```

### 2. 动态路由规则（核心）

使用**方括号 `[]`** 定义动态参数。

| 文件命名 | 生成路由 | 路由名称 | 说明 |
|:--- |:--- |:--- |:--- |
| `user/[id].vue` | `/user/:id` | `user-id` | 必选参数 |
| `post/[pid]/comment/[cid].vue` | `/post/:pid/comment/:cid` | `post-pid-comment-cid` | 多级嵌套 |
| `user/[[id]].vue` | `/user/:id?` | `user-id` | **可选参数**（双括号） |
| `blog/[slugs]+.vue` | `/blog/:slugs+` | `blog-slugs` | **可重复参数**（1个及以上） |
| `blog/[[slugs]]+.vue` | `/blog/:slugs*` | `blog-slugs` | **可选可重复**（0个及以上） |
| `[...notFound].vue` | `/:pathMatch(.*)*` | `notFound` | **通配 404**（三个点） |

### 3. 嵌套路由与布局（+layout.vue）

目录下的 `+layout.vue` 自动成为父路由（包含 `<router-view />`）。

**文件结构：**

```
pages/
├── +layout.vue       # 父路由布局（/dashboard）
└── dashboard/
    ├── index.vue    # /dashboard (子路由默认页)
    ├── stats.vue    # /dashboard/stats
    └── settings.vue # /dashboard/settings
```

**`+layout.vue` 内容：**

```vue
<template>
  <div class="dashboard-layout">
    <Sidebar />
    <!-- 子路由出口 -->
    <router-view />
  </div>
</template>
```

### 4. 路由命名规则

- 默认：路径转驼峰，用 `-` 分隔（如 `user-profile`）。
- 可通过 `routeNameSeparator` 配置分隔符。
- 支持在 `<route>` 块或 `defineRouteMeta` 中自定义 `name`。

### 5. 忽略规则

- 默认忽略：`components/`、`utils/`、`test/`、`__tests__/`。
- 以下划线 `_` 开头的文件/目录（如 `_components/`、`_draft.vue`）。
- 可通过 `exclude` 配置自定义忽略路径。

## 五、页面级配置：路由元信息与自定义

### 1. defineRouteMeta (组合式 API)

在 `<script setup>` 中定义路由元信息（**类型安全**）。

```vue
<!-- src/pages/user/profile.vue -->
<script setup lang="ts">
// 定义路由元信息
defineRouteMeta({
  title: '个人中心',
  requiresAuth: true, // 自定义权限字段
  keepAlive: true,
  layout: 'admin', // 自定义布局
  // 支持嵌套对象
  permissions: ['user:read', 'user:write'],
})
</script>

<template>...</template>
```

### 2. 自定义路由名称与路径

```vue
<script setup lang="ts">
defineRouteMeta({
  name: 'UserProfilePage', // 自定义路由 name
  path: '/me', // 自定义路径（覆盖自动生成）
})
</script>
```

### 3. 路由守卫（组件内）

```vue
<script setup lang="ts">
// 路由进入守卫
definePageGuard((to, from) => {
  console.log('Leaving', from)
  if (!confirm('确定离开？')) return false
})

// 路由离开守卫
definePageGuard((to, from) => {
  // ...
})
</script>
```

## 六、TypeScript 类型安全（最强特性）

### 1. 自动生成类型文件

运行项目后，自动生成 `typed-router.d.ts`，包含所有路由的**名称、路径、参数、查询**的精确类型定义。

### 2. 路由跳转类型提示

**`router.push` 完全类型安全**：

```typescript
// ✅ 正确：自动提示路由 name 和 params
router.push({
  name: 'user-id', // 编辑器自动提示所有路由名
  params: { id: 123 }, // 提示必须参数 id: string | number
})

// ✅ 正确：带查询参数
router.push({
  name: 'post-pid-comment-cid',
  params: { pid: 1, cid: 2 },
  query: { q: 'search' }, // query 也有类型
})

// ❌ 错误：TS 直接报错
router.push({ name: 'uer' }) // 拼写错误
router.push({ name: 'user-id', params: {} }) // 缺少 id 参数
router.push({ name: 'user-id', params: { id: 'str' } }) // 类型错误
```

### 3. 模板中路由类型安全

```vue
<template>
  <!-- ✅ 正确 -->
  <RouterLink :to="{ name: 'user-id', params: { id: 1 } }">
    用户详情
  </RouterLink>

  <!-- ❌ 错误：Volar 直接标红 -->
  <RouterLink :to="{ name: 'uer' }">错误链接</RouterLink>
</template>
```

### 4. 类型优势总结

- **编译期报错**：杜绝运行时路由错误。
- **自动补全**：编辑器智能提示，提升效率。
- **重构安全**：修改文件名/路径，TS 全局提示所有引用。
- **文档即代码**：路由结构一目了然。

## 七、完整配置项清单

### 1. 插件配置（VueRouter 选项）

| 参数 | 类型 | 默认值 | 说明 |
|:--- |:--- |:--- |:--- |
| `routesFolder` | `string/object[]` | `'src/pages'` | 扫描目录，支持多目录与前缀 |
| `dts` | `string/boolean` | `false` | 类型文件路径，`true` 生成到 `node_modules` |
| `exclude` | `string[]` | `['**/components/**']` | 排除路径 |
| `extensions` | `string[]` | `['.vue']` | 扫描扩展名 |
| `layoutFilename` | `string` | `'+layout.vue'` | 布局文件名 |
| `routeNameSeparator` | `string` | `'-'` | 路由名称分隔符 |
| `importMode` | `'async'/'sync'` | `'async'` | 懒加载/同步导入 |
| `defaultRouteName` | `string` | `'index'` | 默认路由名 |
| `root` | `string` | `process.cwd()` | 项目根目录 |
| `debug` | `boolean` | `false` | 调试日志 |

**多目录配置示例：**

```typescript
routesFolder: [
  'src/pages', // 默认前缀 /
  { src: 'src/admin/pages', path: '/admin' }, // 前缀 /admin
  { src: 'src/docs', path: '/docs/:lang/' }, // 带动态前缀
]
```

### 2. defineRouteMeta 配置项

```typescript
defineRouteMeta({
  name?: string; // 自定义路由名
  path?: string; // 自定义路径
  meta?: Record<string, any>; // 元信息
  props?: boolean | Record<string, any>; // 路由 props
  beforeEnter?: RouteGuard; // 路由独享守卫
  // ... 其他 Vue Route 配置
})
```

## 八、高级特性

### 1. 数据加载器（Data Loaders，实验性）

**路由级数据预获取**，在路由激活前自动获取数据，组件直接使用。

```vue
<!-- src/pages/user/[id].vue -->
<script setup>
// 定义数据加载器
const loader = defineLoader(async (to) => {
  const res = await fetch(`/api/users/${to.params.id}`)
  return res.json()
})

// 组件内直接访问数据
const user = loader.data.value
const isLoading = loader.isLoading.value
</script>
```

### 2. 自定义页面中间件

```typescript
// src/middleware/auth.ts
export default defineMiddleware((to, from) => {
  if (to.meta.requiresAuth && !store.isLoggedIn) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
})
```

```vue
<script setup>
// 页面使用中间件
definePageMeta({
  middleware: 'auth'
})
</script>
```

### 3. 路由合并与扩展

可手动扩展自动生成的路由：

```typescript
// router/index.ts
import { routes as autoRoutes } from 'vue-router/auto-routes'

const routes = [
  ...autoRoutes,
  // 手动添加特殊路由
  { path: '/:pathMatch(.*)*', redirect: { name: 'notFound' } },
]
```

## 十、常见问题与解决方案

### 1. 类型文件不生成 / 无提示

- 确保 `dts` 配置正确，运行 `dev` 命令触发生成。
- VSCode：`Ctrl+Shift+P` → `TypeScript: Restart TS Server`。
- 检查 `env.d.ts` 是否正确引用类型。

### 2. 路由不更新 / 热更新失效

- 清除 Vite 缓存：`node_modules/.vite`。
- 重启开发服务器。
- 检查文件名是否含特殊字符或中文。

### 3. 动态路由参数类型错误

- 确保参数名与文件 `[param]` 完全一致。
- 类型为 `string`，如需数字需手动转换。

### 4. 布局组件不生效

- 布局文件名必须是 `+layout.vue`（默认）。
- 布局组件必须包含 `<router-view />`。

## 十一、总结与最佳实践

### 1. 适用场景

- **所有 Vue 3 + Vue Router 项目**（Web SPA）。
- **中大型项目**：追求可维护性、类型安全、团队协作。
- **快速开发**：减少样板代码，专注业务。
- **未来兼容**：准备升级 Vue Router 5+。

### 2. 最佳实践

- **目录规范**：`src/pages` 存放路由页面，`src/components` 存放公共组件。
- **类型优先**：全程使用 `name` 跳转（`router.push({ name: 'xxx' })`），而非路径字符串。
- **布局拆分**：使用 `+layout.vue` 拆分公共布局（如后台、前台）。
- **元信息**：用 `defineRouteMeta` 管理权限、标题、缓存。
- **数据加载**：使用实验性 `defineLoader` 统一管理路由数据。

**unplugin-vue-router** 彻底终结了 Vue 手动维护路由表的时代，是**官方标准、类型安全、工程化完善**的下一代路由解决方案。
