# vue2 测试概览

## 一、测试核心基础

### 1. 测试类型（Vue2项目常用）

先明确不同测试的目标，避免盲目写测试：

| 测试类型       | 核心目标                                                                 | 适用场景                          |
|----------------|--------------------------------------------------------------------------|-----------------------------------|
| 单元测试       | 测试**最小可独立运行的单元**（如单个函数、组件、Vuex mutation），隔离外部依赖 | 工具函数、Vuex方法、纯展示组件    |
| 组件测试       | 测试Vue组件的渲染、交互、生命周期，验证组件行为符合预期                   | 业务组件（按钮、表单、列表）      |
| 集成测试       | 测试多个模块/组件的协作（如组件+Vuex+路由），验证整体流程                 | 页面级组件、核心业务流程          |
| E2E测试（端到端） | 模拟用户真实操作，测试整个应用的流程（从页面跳转、交互到结果）             | 核心业务链路（登录→下单→支付）    |

### 2. 核心框架选型（Vue2专属）

Vue2测试的「黄金组合」：

- **Jest**：JavaScript测试运行器，提供测试框架、断言库、模拟（mock）、覆盖率统计，开箱即用；
- **Vue Test Utils 1.x**：Vue2官方测试工具库，专门用于挂载Vue组件、模拟交互、访问组件内部状态；
- **可选补充**：
  - `vue-jest`：让Jest能解析`.vue`文件；
  - `babel-jest`：兼容ES6+语法；
  - `axios-mock-adapter`：模拟接口请求；
  - `vue-router/test-utils`：模拟路由。

### 3. 版本对应关系（关键！避免兼容问题）

| 框架               | 适配Vue版本 | 安装命令                          |
|--------------------|-------------|-----------------------------------|
| Vue Test Utils     | Vue2        | `npm install @vue/test-utils@1 --save-dev` |
| Jest               | 任意        | `npm install jest --save-dev`     |
| vue-jest           | Vue2        | `npm install vue-jest@3 --save-dev` |

## 二、环境搭建

### 1. 快速体验（CDN版，无需配置，新手入门）

适合快速理解测试逻辑，无需搭建项目：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>Vue2测试快速体验</title>
  <!-- 引入依赖 -->
  <script src="https://cdn.jsdelivr.net/npm/vue@2.7.16/dist/vue.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/jest-browser-globals@1.0.1/dist/index.umd.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/@vue/test-utils@1.3.6/dist/vue-test-utils.umd.js"></script>
</head>
<body>
  <script>
    // 1. 定义待测试的Vue组件
    const Button = {
      template: `<button @click="handleClick">{{ text }}</button>`,
      props: ['text'],
      methods: {
        handleClick() {
          this.$emit('click');
        }
      }
    };

    // 2. 编写测试用例
    describe('Button组件', () => {
      // 每个测试用例
      it('渲染正确的文本', () => {
        // 挂载组件
        const wrapper = VueTestUtils.mount(Button, {
          propsData: { text: '测试按钮' }
        });
        // 断言：按钮文本等于"测试按钮"
        expect(wrapper.text()).toBe('测试按钮');
      });

      it('点击触发click事件', () => {
        const wrapper = VueTestUtils.mount(Button);
        // 触发点击事件
        wrapper.trigger('click');
        // 断言：组件触发了click事件
        expect(wrapper.emitted('click')).toBeTruthy();
      });
    });

    // 运行测试（浏览器控制台查看结果）
    jest.runAllTests();
  </script>
</body>
</html>
```

打开浏览器控制台，会看到测试结果（2个测试用例通过）。

### 2. 项目级配置（Vue CLI创建的Vue2项目）

Vue CLI创建的项目可直接添加测试依赖，无需手动配置webpack/jest：

#### 步骤1：创建Vue2项目（已有的话跳过）

```bash
vue create vue2-test-demo
# 选择Vue2 + Babel + ESLint
```

#### 步骤2：安装测试依赖

```bash
cd vue2-test-demo
# 安装核心依赖
npm install jest @vue/test-utils@1 vue-jest@3 babel-jest --save-dev
```

#### 步骤3：配置package.json

```json
{
  "scripts": {
    "test": "jest", // 运行所有测试
    "test:coverage": "jest --coverage" // 运行测试并生成覆盖率报告
  },
  "jest": {
    "moduleFileExtensions": ["js", "vue"],
    "transform": {
      "^.+\\.js$": "babel-jest",
      "^.+\\.vue$": "vue-jest"
    },
    "moduleNameMapper": {
      "^@/(.*)$": "<rootDir>/src/$1" // 映射@到src目录
    }
  }
}
```

## 三、Vue Test Utils 1.x 核心API（组件测试基础）

Vue Test Utils的核心是「挂载组件」和「操作/断言组件」，先掌握这些核心API：

| API                | 作用                                                                 |
|--------------------|----------------------------------------------------------------------|
| `mount(component, options)` | 全量挂载组件（渲染所有子组件），返回wrapper对象                       |
| `shallowMount()`   | 浅挂载组件（不渲染子组件），避免子组件干扰，优先使用                   |
| `wrapper.text()`   | 获取组件渲染后的文本内容                                             |
| `wrapper.html()`   | 获取组件渲染后的HTML字符串                                           |
| `wrapper.find(selector)` | 查找组件内的元素/子组件（支持CSS选择器、组件名）                     |
| `wrapper.trigger(event)` | 触发组件/元素的事件（如click、input）                                |
| `wrapper.setProps(props)` | 给组件设置props                                                      |
| `wrapper.emitted(event)` | 获取组件触发的事件列表（验证$emit是否生效）                          |
| `wrapper.vm`       | 访问组件实例（等同于this，可调用方法、访问data/props）                |

## 四、基础组件测试实战

以一个简单的「计数器组件」为例，完整演示测试流程：

### 步骤1：编写组件（src/components/Counter.vue）

```vue
<template>
  <div class="counter">
    <p class="count">{{ count }}</p>
    <button @click="increment">+1</button>
    <button @click="decrement">-1</button>
  </div>
</template>

<script>
export default {
  name: 'Counter',
  data() {
    return {
      count: 0
    };
  },
  methods: {
    increment() {
      this.count++;
      this.$emit('change', this.count);
    },
    decrement() {
      if (this.count > 0) {
        this.count--;
        this.$emit('change', this.count);
      }
    }
  }
};
</script>
```

### 步骤2：编写测试用例（src/components/**tests**/Counter.spec.js）

测试文件命名规范：`组件名.spec.js` 或 `组件名.test.js`，放在`__tests__`目录下。

```javascript
import { shallowMount } from '@vue/test-utils';
import Counter from '../Counter.vue';

// 测试套件：描述组件的整体测试
describe('Counter.vue', () => {
  // 测试用例1：初始渲染正确的计数
  it('初始计数为0', () => {
    // 浅挂载组件
    const wrapper = shallowMount(Counter);
    // 断言：计数文本为"0"
    expect(wrapper.find('.count').text()).toBe('0');
  });

  // 测试用例2：点击+1按钮，计数增加并触发change事件
  it('点击+1按钮，计数变为1并触发change事件', () => {
    const wrapper = shallowMount(Counter);
    // 找到+1按钮并触发点击
    wrapper.find('button:nth-child(2)').trigger('click');
    // 断言1：计数变为1
    expect(wrapper.vm.count).toBe(1);
    // 断言2：触发了change事件，且参数为1
    expect(wrapper.emitted('change')).toBeTruthy();
    expect(wrapper.emitted('change')[0]).toEqual([1]);
  });

  // 测试用例3：点击-1按钮，计数为0时不减少
  it('计数为0时点击-1，计数仍为0', () => {
    const wrapper = shallowMount(Counter);
    // 点击-1按钮
    wrapper.find('button:nth-child(3)').trigger('click');
    // 断言：计数仍为0
    expect(wrapper.vm.count).toBe(0);
    // 断言：未触发change事件
    expect(wrapper.emitted('change')).toBeFalsy();
  });
});
```

### 步骤3：运行测试

```bash
npm test
```

控制台会输出测试结果：3个测试用例全部通过。

## 五、复杂场景测试

### 1. 测试带Vuex的组件

核心：**模拟Vuex Store**，避免依赖真实的Store实例。

#### 示例：带Vuex的组件（src/components/HelloVuex.vue）

```vue
<template>
  <div>
    <p>{{ $store.state.msg }}</p>
    <button @click="updateMsg">修改消息</button>
  </div>
</template>

<script>
export default {
  methods: {
    updateMsg() {
      this.$store.commit('UPDATE_MSG', '新消息');
    }
  }
};
</script>
```

#### 测试用例（src/components/**tests**/HelloVuex.spec.js）

```javascript
import { shallowMount } from '@vue/test-utils';
import HelloVuex from '../HelloVuex.vue';

// 模拟Vuex Store
const mockStore = {
  state: {
    msg: '原始消息'
  },
  commit: jest.fn() // 模拟commit方法，用于断言是否被调用
};

it('渲染Vuex中的msg', () => {
  const wrapper = shallowMount(HelloVuex, {
    // 注入模拟的store
    mocks: {
      $store: mockStore
    }
  });
  // 断言：渲染的文本是"原始消息"
  expect(wrapper.text()).toContain('原始消息');
});

it('点击按钮触发UPDATE_MSG mutation', () => {
  const wrapper = shallowMount(HelloVuex, {
    mocks: { $store: mockStore }
  });
  // 点击按钮
  wrapper.find('button').trigger('click');
  // 断言：commit被调用，参数正确
  expect(mockStore.commit).toHaveBeenCalledWith('UPDATE_MSG', '新消息');
});
```

### 2. 测试带路由的组件

核心：**模拟$router/$route**，避免依赖真实路由实例。

#### 示例：带路由的组件（src/components/HelloRouter.vue）

```vue
<template>
  <div>
    <p>{{ $route.params.id }}</p>
    <button @click="goHome">返回首页</button>
  </div>
</template>

<script>
export default {
  methods: {
    goHome() {
      this.$router.push('/home');
    }
  }
};
</script>
```

#### 测试用例（src/components/**tests**/HelloRouter.spec.js）

```javascript
import { shallowMount } from '@vue/test-utils';
import HelloRouter from '../HelloRouter.vue';

// 模拟路由
const mockRouter = {
  push: jest.fn()
};
const mockRoute = {
  params: { id: '1001' }
};

it('渲染路由参数id', () => {
  const wrapper = shallowMount(HelloRouter, {
    mocks: {
      $router: mockRouter,
      $route: mockRoute
    }
  });
  // 断言：渲染的id是1001
  expect(wrapper.text()).toContain('1001');
});

it('点击按钮跳转到首页', () => {
  const wrapper = shallowMount(HelloRouter, {
    mocks: { $router: mockRouter, $route: mockRoute }
  });
  // 点击按钮
  wrapper.find('button').trigger('click');
  // 断言：$router.push被调用，参数是'/home'
  expect(mockRouter.push).toHaveBeenCalledWith('/home');
});
```

### 3. 测试异步逻辑（接口请求）

核心：**模拟接口请求**，避免依赖真实后端服务。

#### 示例：带异步请求的组件（src/components/HelloAsync.vue）

```vue
<template>
  <div>
    <p v-if="loading">加载中...</p>
    <p v-else>{{ data.name }}</p>
  </div>
</template>

<script>
import axios from 'axios';

export default {
  data() {
    return {
      loading: true,
      data: {}
    };
  },
  mounted() {
    this.fetchData();
  },
  methods: {
    async fetchData() {
      const res = await axios.get('/api/user');
      this.data = res.data;
      this.loading = false;
    }
  }
};
</script>
```

#### 测试用例（src/components/**tests**/HelloAsync.spec.js）

```javascript
import { shallowMount } from '@vue/test-utils';
import HelloAsync from '../HelloAsync.vue';
import axios from 'axios';
import MockAdapter from 'axios-mock-adapter';

// 创建axios mock实例
const mockAxios = new MockAdapter(axios);

describe('HelloAsync.vue', () => {
  beforeEach(() => {
    // 每次测试前重置mock
    mockAxios.reset();
  });

  it('挂载后加载数据并渲染', async () => {
    // 模拟接口返回数据
    mockAxios.onGet('/api/user').reply(200, { name: '测试用户' });

    const wrapper = shallowMount(HelloAsync);
    // 断言：初始状态是加载中
    expect(wrapper.text()).toContain('加载中...');

    // 等待异步操作完成
    await wrapper.vm.$nextTick();

    // 断言：加载完成后渲染用户名
    expect(wrapper.text()).toContain('测试用户');
    expect(wrapper.vm.loading).toBe(false);
  });
});
```

## 六、测试最佳实践

### 1. 优先使用浅挂载（shallowMount）

避免子组件的逻辑干扰当前组件的测试，只有需要测试子组件协作时才用mount。

### 2. 测试行为而非实现细节

- ❌ 错误：测试`wrapper.vm.increment`方法是否被调用（实现细节）；
- ✅ 正确：测试点击按钮后计数是否增加（用户可见的行为）。

### 3. 模拟外部依赖

所有外部依赖（Vuex、路由、接口、定时器）都要模拟，保证测试的独立性和稳定性。

### 4. 合理拆分测试用例

每个测试用例只测试一个点，用清晰的命名描述测试目标（如「计数为0时点击-1不减少」）。

### 5. 统计测试覆盖率

运行`npm run test:coverage`，生成覆盖率报告（在`coverage`目录），重点关注：

- Statements（语句覆盖率）：执行了多少代码语句；
- Branches（分支覆盖率）：执行了多少条件分支（if/else）；
- Functions（函数覆盖率）：执行了多少函数；
- Lines（行覆盖率）：执行了多少代码行。

## 七、E2E测试（补充）

对于核心业务流程，推荐使用`Cypress`（Vue2/3通用），无需配置复杂的Selenium，开箱即用：

```bash

```

## 总结

### 关键点回顾

1. **核心框架**：Vue2测试用「Jest + Vue Test Utils 1.x」，注意版本对应（VTU 1.x适配Vue2）；
2. **组件测试核心**：挂载组件（shallowMount）→ 操作组件（trigger/setProps）→ 断言结果（expect）；
3. **复杂场景处理**：模拟Vuex/路由/接口，避免依赖外部服务，保证测试独立性；
4. **最佳实践**：测试行为而非实现细节、优先浅挂载、模拟外部依赖、统计覆盖率。

### 核心原则

- 测试的目标是「验证功能符合预期」，不是「追求100%覆盖率」；
- 单元测试保证基础模块稳定，集成/E2E测试保证核心流程稳定；
- 测试代码要简洁、可维护，避免过度复杂的mock逻辑。
