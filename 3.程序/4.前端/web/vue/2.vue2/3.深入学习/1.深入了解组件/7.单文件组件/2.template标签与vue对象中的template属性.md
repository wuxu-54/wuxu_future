# `<template>`标签和Vue对象里的`template`属性

**核心功能一致（都是定义组件模板），但存在形式、使用场景、生效条件不同，并非完全一样**

## 一、核心相同点：本质都是定义Vue模板

无论是`<template>`标签（单文件组件中），还是Vue对象的`template`属性（字符串形式），**最终目的都是为Vue组件提供HTML模板结构**，且都支持Vue2的模板语法（`{{ }}`插值、`v-for`/`v-if`指令、组件引用等）。

举个例子，以下两种写法的**渲染结果完全一致**：

### 写法1：单文件组件的`<template>`标签

```vue
<!-- Hello.vue -->
<template>
  <div>{{ msg }}</div>
</template>
<script>
export default {
  data() {
    return { msg: 'Vue2 Template' }
  }
}
</script>
```

### 写法2：Vue对象的`template`属性

```javascript
// 全局编译版本下的Vue实例
const Hello = {
  template: '<div>{{ msg }}</div>', // template属性（字符串模板）
  data() {
    return { msg: 'Vue2 Template' }
  }
}
new Vue({
  el: '#app',
  components: { Hello }
})
```

两者最终都会被Vue编译为`render`函数，渲染出`<div>Vue2 Template</div>`，这是它们的核心共性。

## 二、核心不同点：存在形式与生效条件

| 特性                | `<template>`标签（单文件组件中） | Vue对象的`template`属性                |
|---------------------|----------------------------------|----------------------------------------|
| **存在形式**        | 独立的HTML标签（.vue文件中）     | Vue实例/组件配置中的字符串属性         |
| **编译时机**        | 构建阶段（预编译）               | 运行阶段（客户端编译）                 |
| **生效条件**        | 所有Vue2版本支持（包括仅运行时） | 仅支持「Runtime + Compiler版本」       |
| **语法灵活性**      | 支持多行模板（无需反引号）       | 多行需用反引号/拼接字符串，易出错      |
| **根节点要求**      | 必须有唯一根节点（Vue2规则）     | 同样要求唯一根节点，否则编译报错       |
| **工具支持**        | IDE语法高亮/格式化/提示完善      | 字符串模板无语法提示，易写错           |

### 关键差异拆解

#### 1. 编译时机（最核心差异）

- **`<template>`标签（单文件组件）**：  
  在项目构建阶段（npm run build/serve），`vue-loader`会将`<template>`标签的内容**预编译为`render`函数**，最终打包后的代码中只有`render`函数，没有模板字符串。  
  因此，即使使用Vue2的「仅运行时版本（Runtime-only）」，也能正常运行（体积更小，推荐）。

- **`template`属性（字符串模板）**：  
  模板字符串不会在构建阶段编译，而是在浏览器运行时，由Vue的内置模板编译器编译为`render`函数。  
  因此，必须使用Vue2的「Runtime + Compiler版本」（包含编译器），否则会报错：`You are using the runtime-only build of Vue where the template compiler is not available`。

#### 2. 使用场景与开发体验

- `<template>`标签：  
  是Vue2工程化开发的**标准写法**，几乎所有业务组件都用这种方式，开发体验好（语法高亮、自动格式化、指令提示），且兼容仅运行时版本（体积优化）。

- `template`属性：  
  仅适用于**非工程化场景**（如CDN引入Vue、动态生成模板），或快速测试小组件。工程化开发中极少使用，因为字符串模板易出错、无语法提示，且会增加包体积（需包含编译器）。

## 三、补充：容易混淆的“其他`<template>`用法”

Vue2中还有一种`<template>`标签的特殊用法（无渲染占位符），和`template`属性无关，需注意区分：

```vue
<template>
  <div>
    <!-- 这种<template>是占位符，不生成DOM，仅用于分组指令 -->
    <template v-if="show">
      <p>文本1</p>
      <p>文本2</p>
    </template>
  </div>
</template>
```

这种`<template>`标签**不是模板定义**，只是逻辑容器，和Vue对象的`template`属性（定义组件整体模板）完全是两回事。

## 四、实战示例：两种写法的对比

### 场景1：工程化开发（推荐`<template>`标签）

```vue
<!-- src/components/Hello.vue -->
<template>
  <!-- 预编译模板，支持所有Vue2语法，开发体验好 -->
  <div class="hello">
    <h1>{{ title }}</h1>
    <button @click="updateTitle">修改标题</button>
  </div>
</template>
<script>
export default {
  data() {
    return { title: '工程化开发' }
  },
  methods: {
    updateTitle() {
      this.title = 'Vue2 Template标签'
    }
  }
}
</script>
```

- 构建时`vue-loader`将`<template>`编译为`render`函数；
- 可使用仅运行时版本，包体积更小；
- IDE有完整的语法提示。

### 场景2：CDN引入（使用`template`属性）

```html
<!DOCTYPE html>
<html>
<head>
  <!-- CDN引入Runtime + Compiler版本 -->
  <script src="https://cdn.jsdelivr.net/npm/vue@2.7.16/dist/vue.js"></script>
</head>
<body>
  <div id="app"></div>
  <script>
    // 运行时编译模板字符串
    new Vue({
      el: '#app',
      template: `
        <div class="hello">
          <h1>{{ title }}</h1>
          <button @click="updateTitle">修改标题</button>
        </div>
      `,
      data() {
        return { title: 'CDN开发' }
      },
      methods: {
        updateTitle() {
          this.title = 'Vue2 template属性'
        }
      }
    })
  </script>
</body>
</html>
```

- 无构建步骤，直接在浏览器编译模板；
- 必须引入包含编译器的Vue版本；
- 字符串模板需用反引号包裹，无语法提示。

## 总结

### 关键点回顾

1. **核心共性**：两者都是定义Vue2组件的模板结构，支持相同的模板语法，最终都会被编译为`render`函数；
2. **核心差异**：
   - `<template>`标签（单文件组件）：预编译、支持所有Vue2版本、开发体验好，是工程化开发的标准写法；
   - `template`属性：运行时编译、仅支持Runtime + Compiler版本、开发体验差，仅适用于CDN/动态模板场景；
3. **易混淆点**：作为“占位符”的`<template>`标签（配合v-if/v-for），和`template`属性无关联。

### 核心建议

- 工程化开发Vue2项目：**优先使用`<template>`标签**（单文件组件），兼容仅运行时版本，体积更小、开发更高效；
- CDN/动态模板场景：使用`template`属性（需引入包含编译器的Vue版本）；
- 避免在工程化项目中使用`template`属性，除非有特殊动态模板需求。
