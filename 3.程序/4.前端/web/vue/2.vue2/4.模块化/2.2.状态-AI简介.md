# vuex

## 一、核心背景：为什么需要Vuex？

在Vue2项目中，组件通信的痛点：

- 父子组件：`props/$emit` 能解决，但跨层级（爷孙/曾孙）会层层透传，代码冗余；
- 兄弟组件/跨层级组件：`EventBus` 可临时解决，但事件名混乱、难以维护；
- 复杂场景（如购物车、用户信息）：全局状态分散在多个组件，数据同步困难。

**Vuex的核心作用**：提供一个**集中式的“全局仓库（Store）”**，统一管理所有组件的共享状态，遵循“单向数据流”规则，让状态变化可预测、可追踪。

### 版本匹配

- Vue2 → **Vuex 3.x**（必须匹配，否则报错）；
- Vue3 → Pinia（推荐）/ Vuex 4.x。

### 安装方式

#### （1）CDN方式（新手推荐，无需配置）

```html
<!-- 先引入Vue2，再引入Vuex 3.x -->
<script src="https://cdn.jsdelivr.net/npm/vue@2.7.16/dist/vue.js"></script>
<script src="https://cdn.jsdelivr.net/npm/vuex@3.6.2/dist/vuex.js"></script>
```

#### （2）npm方式（项目开发常用）

```bash
# 安装Vuex 3.x（Vue2专用）
npm install vuex@3 --save
# 或 yarn add vuex@3
```

## 二、Vuex核心概念与单向数据流

### 1. 核心结构（Store的5大模块）

Vuex的Store是一个对象，包含5个核心部分，遵循**单向数据流**规则：

```
View（组件）→ 触发Action（异步）→ 提交Mutation（同步）→ 修改State（状态）→ 响应式更新View
```

| 核心模块   | 作用                                                                 | 核心规则                                   |
|------------|----------------------------------------------------------------------|--------------------------------------------|
| State      | 存储全局共享状态（唯一数据源）                                       | 只读，不能直接修改，只能通过Mutation修改   |
| Mutation   | 唯一能修改State的方法（同步函数）                                    | 必须同步执行，接收State作为第一个参数      |
| Action     | 处理异步逻辑（如接口请求），执行完后提交Mutation修改State             | 可异步执行，接收context（上下文）作为参数  |
| Getter     | 类似组件的computed，基于State派生新数据（缓存、复用）                | 依赖State，数据变化自动更新                |
| Module     | 拆分复杂Store为多个模块（如用户模块、购物车模块），避免Store臃肿      | 可开启命名空间，隔离模块内的状态/方法      |

### 2. 单向数据流核心原则

![Vuex单向数据流](https://vuex.vuejs.org/vuex.png)
（文字描述：组件通过`dispatch`触发Action，Action通过`commit`提交Mutation，Mutation修改State，State的变化通过Getter（可选）映射到组件，组件视图自动更新；组件也可直接`commit`Mutation（同步场景）。）

## 三、Vuex基础使用（完整最小示例）

### 1. 完整代码（CDN版）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>Vuex 3.x基础使用</title>
  <script src="https://cdn.jsdelivr.net/npm/vue@2.7.16/dist/vue.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/vuex@3.6.2/dist/vuex.js"></script>
</head>
<body>
  <div id="app">
    <!-- 1. 访问State：直接通过$store.state -->
    <p>当前计数：{{ $store.state.count }}</p>
    <!-- 2. 访问Getter：通过$store.getters -->
    <p>翻倍计数：{{ $store.getters.doubleCount }}</p>

    <!-- 3. 触发Mutation（同步） -->
    <button @click="$store.commit('increment')">+1（同步）</button>
    <!-- 4. 触发Action（异步） -->
    <button @click="$store.dispatch('incrementAsync')">+1（异步）</button>
  </div>

  <script>
    // 1. 创建Vuex Store实例
    const store = new Vuex.Store({
      // ① State：存储状态
      state: {
        count: 0
      },

      // ② Mutation：唯一修改State的方式（同步）
      mutations: {
        // 第一个参数是state，第二个是载荷（payload，传递的参数）
        increment(state, payload = 1) {
          state.count += payload; // 只能在这里修改state
        },
        decrement(state) {
          state.count--;
        }
      },

      // ③ Action：处理异步，提交Mutation
      actions: {
        // context包含：state、commit、dispatch、getters等
        incrementAsync(context) {
          // 模拟异步请求（如接口调用）
          setTimeout(() => {
            // 提交Mutation修改state
            context.commit('increment', 2); // 传递载荷2，异步+2
          }, 1000);
        }
      },

      // ④ Getter：派生状态（类似computed）
      getters: {
        // 第一个参数是state，第二个是其他getters
        doubleCount(state, getters) {
          return state.count * 2;
        }
      }
    });

    // 2. 挂载Store到Vue根实例（所有子组件可通过this.$store访问）
    new Vue({
      el: '#app',
      store // 注入store，全局可用
    });
  </script>
</body>
</html>
```

### 2. 核心代码解释

#### （1）State：全局状态

- 唯一数据源，所有共享状态都存在这里；
- 组件中访问：`this.$store.state.xxx`（模板中可省略`this`）；
- 特点：响应式，修改后组件视图自动更新。

#### （2）Mutation：同步修改State

- **必须同步**：如果在Mutation中写异步代码（如setTimeout），Vuex无法追踪状态变化，调试工具会失效；
- 触发方式：组件中通过`this.$store.commit('mutation名', 载荷)`；
- 载荷（payload）：可选，传递参数（可以是单个值或对象），比如`commit('increment', { num: 2 })`。

#### （3）Action：异步处理

- **可异步**：专门处理接口请求、定时器等异步逻辑；
- 触发方式：组件中通过`this.$store.dispatch('action名', 载荷)`；
- context参数：等价于`store`实例，可解构简化：

  ```javascript
  actions: {
    incrementAsync({ commit }) { // 解构context，只取commit
      setTimeout(() => {
        commit('increment', 2);
      }, 1000);
    }
  }
  ```

#### （4）Getter：派生状态

- 缓存特性：依赖的State不变时，Getter结果会缓存，避免重复计算；
- 组件中访问：`this.$store.getters.xxx`，支持传参（返回函数）：

  ```javascript
  getters: {
    // 带参数的Getter（比如根据ID筛选数据）
    getCountById: (state) => (id) => {
      // 模拟根据ID筛选，实际可用于列表筛选
      return state.count + id;
    }
  }
  // 组件中使用：$store.getters.getCountById(5)
  ```

## 四、辅助函数（简化组件代码）

直接使用`this.$store.state.xxx`/`this.$store.commit()`会让代码冗余，Vuex提供4个辅助函数，将Store中的状态/方法映射到组件的`computed`/`methods`中：

| 辅助函数      | 作用                          | 映射到组件的哪个选项 |
|---------------|-------------------------------|----------------------|
| `mapState`    | 映射State到组件的computed     | computed             |
| `mapGetters`  | 映射Getter到组件的computed    | computed             |
| `mapMutations`| 映射Mutation到组件的methods   | methods              |
| `mapActions`  | 映射Action到组件的methods     | methods              |

### 示例：使用辅助函数

```html
<div id="app">
  <!-- 直接使用映射后的属性/方法 -->
  <p>计数：{{ count }}</p>
  <p>翻倍：{{ doubleCount }}</p>
  <button @click="increment">+1</button>
  <button @click="incrementAsync">异步+2</button>
</div>

<script>
  const store = new Vuex.Store({
    state: { count: 0 },
    mutations: { increment(state) { state.count++ } },
    actions: { incrementAsync({ commit }) { setTimeout(() => commit('increment', 2), 1000) } },
    getters: { doubleCount: state => state.count * 2 }
  });

  new Vue({
    el: '#app',
    store,
    // 1. 映射State和Getter到computed
    computed: {
      // 方式1：数组形式（名称一致）
      ...Vuex.mapState(['count']),
      ...Vuex.mapGetters(['doubleCount']),

      // 方式2：对象形式（自定义名称）
      // ...Vuex.mapState({ myCount: 'count' }),
      // ...Vuex.mapGetters({ myDouble: 'doubleCount' })
    },
    // 2. 映射Mutation和Action到methods
    methods: {
      ...Vuex.mapMutations(['increment']),
      ...Vuex.mapActions(['incrementAsync'])
    }
  });
</script>
```

**核心**：`...`是ES6扩展运算符，将映射的属性/方法合并到组件的`computed`/`methods`中，简化代码。

## 五、模块化（Module）：拆分复杂Store

当项目复杂时，所有状态都放在根Store会导致代码臃肿，Module允许将Store拆分为多个模块，每个模块有自己的`state`/`mutation`/`action`/`getter`。

### 1. 基础模块化（无命名空间）

```javascript
// 1. 定义用户模块
const userModule = {
  state: { name: '张三', age: 20 }, // 模块内的state
  mutations: {
    updateName(state, newName) { // state是模块内的state
      state.name = newName;
    }
  },
  actions: {
    updateNameAsync({ commit }, newName) {
      setTimeout(() => commit('updateName', newName), 1000);
    }
  },
  getters: {
    userInfo(state) {
      return `${state.name}(${state.age}岁)`;
    }
  }
};

// 2. 定义购物车模块
const cartModule = {
  state: { goods: ['商品1', '商品2'] },
  mutations: {
    addGoods(state, good) {
      state.goods.push(good);
    }
  }
};

// 3. 创建根Store，注册模块
const store = new Vuex.Store({
  modules: {
    user: userModule, // 用户模块
    cart: cartModule  // 购物车模块
  }
});

// 4. 组件中访问模块内的状态/方法
new Vue({
  el: '#app',
  store,
  mounted() {
    // 访问模块内的state：$store.state.模块名.属性
    console.log(this.$store.state.user.name); // 张三

    // 访问模块内的getter：直接$store.getters.xxx（无命名空间时，getter全局唯一）
    console.log(this.$store.getters.userInfo); // 张三(20岁)

    // 触发模块内的mutation：直接commit（无命名空间时，mutation全局唯一）
    this.$store.commit('updateName', '李四');

    // 触发模块内的action：直接dispatch
    this.$store.dispatch('updateNameAsync', '王五');
  }
});
```

### 2. 命名空间（namespaced: true）：隔离模块

无命名空间时，多个模块的mutation/action/getter名称冲突会覆盖，开启`namespaced: true`可隔离模块：

```javascript
// 改造用户模块：开启命名空间
const userModule = {
  namespaced: true, // 开启命名空间
  state: { name: '张三' },
  mutations: { updateName(state, newName) { state.name = newName } },
  actions: { updateNameAsync({ commit }, newName) { setTimeout(() => commit('updateName', newName), 1000) } },
  getters: { userInfo(state) { return state.name } }
};

// 组件中访问（需指定模块名）
new Vue({
  el: '#app',
  store,
  mounted() {
    // 1. 访问state：不变，还是$store.state.模块名.属性
    console.log(this.$store.state.user.name);

    // 2. 访问getter：$store.getters['模块名/getter名']
    console.log(this.$store.getters['user/userInfo']);

    // 3. 触发mutation：commit('模块名/mutation名', 参数)
    this.$store.commit('user/updateName', '李四');

    // 4. 触发action：dispatch('模块名/action名', 参数)
    this.$store.dispatch('user/updateNameAsync', '王五');

    // 5. 辅助函数使用命名空间（两种方式）
    // 方式1：映射时指定模块名
    ...Vuex.mapState('user', ['name']),
    // 方式2：createNamespacedHelpers创建命名空间辅助函数
    const { mapState, mapMutations } = Vuex.createNamespacedHelpers('user');
    ...mapState(['name']),
    ...mapMutations(['updateName'])
  }
});
```

## 六、核心注意事项

1. **State只能通过Mutation修改**：直接修改`this.$store.state.count = 1`会导致状态变化不可追踪，调试工具失效；
2. **Mutation必须同步**：异步逻辑必须放在Action中，否则Vuex调试工具无法记录状态变化；
3. **模块化命名空间**：复杂项目务必开启`namespaced: true`，避免方法名冲突；
4. **辅助函数简化代码**：组件中频繁访问Store时，优先使用`mapState`/`mapMutations`等辅助函数；
5. **State响应式**：新增State属性时，需用`Vue.set(state, 'newProp', value)`（或替换整个对象），否则不响应式。

## 七、综合示例（带接口请求的模块化Store）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>Vuex模块化综合示例</title>
  <script src="https://cdn.jsdelivr.net/npm/vue@2.7.16/dist/vue.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/vuex@3.6.2/dist/vuex.js"></script>
  <!-- 模拟接口请求 -->
  <script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
</head>
<body>
  <div id="app">
    <h3>用户信息：{{ userName }}</h3>
    <button @click="fetchUser">异步获取用户信息</button>
    <h3>购物车：{{ cartGoods.join(', ') }}</h3>
    <button @click="addGoods('新商品')">添加商品</button>
  </div>

  <script>
    // 1. 用户模块（带异步请求）
    const userModule = {
      namespaced: true,
      state: { name: '' },
      mutations: {
        SET_USER_NAME(state, name) {
          state.name = name;
        }
      },
      actions: {
        // 模拟接口请求获取用户信息
        async fetchUserInfo({ commit }) {
          try {
            // 模拟接口返回
            // const res = await axios.get('/api/user');
            const res = { data: { name: 'Vuex用户' } };
            commit('SET_USER_NAME', res.data.name);
          } catch (err) {
            console.error('获取用户信息失败：', err);
          }
        }
      },
      getters: {
        userName: state => state.name || '未登录'
      }
    };

    // 2. 购物车模块
    const cartModule = {
      namespaced: true,
      state: { goods: [] },
      mutations: {
        ADD_GOODS(state, good) {
          state.goods.push(good);
        }
      },
      getters: {
        cartGoods: state => state.goods
      }
    };

    // 3. 创建Store
    const store = new Vuex.Store({
      modules: {
        user: userModule,
        cart: cartModule
      }
    });

    // 4. 根实例
    new Vue({
      el: '#app',
      store,
      computed: {
        // 映射用户模块的getter
        ...Vuex.mapGetters('user', ['userName']),
        // 映射购物车模块的getter
        ...Vuex.mapGetters('cart', ['cartGoods'])
      },
      methods: {
        // 映射用户模块的action
        ...Vuex.mapActions('user', ['fetchUser']),
        // 映射购物车模块的mutation
        ...Vuex.mapMutations('cart', ['ADD_GOODS']),
        // 自定义方法（调用映射后的方法）
        addGoods(good) {
          this.ADD_GOODS(good);
        }
      }
    });
  </script>
</body>
</html>
```

## 总结

### 关键点回顾

1. **核心定位**：Vuex 3.x是Vue2的官方状态管理库，用于集中管理全局共享状态，解决复杂组件通信问题；
2. **核心规则**：State只读，仅能通过同步的Mutation修改，异步逻辑放在Action中；
3. **核心结构**：State（存状态）、Mutation（同步改状态）、Action（异步调Mutation）、Getter（派生状态）、Module（拆分Store）；
4. **模块化**：复杂项目需开启`namespaced: true`隔离模块，避免方法名冲突；
5. **辅助函数**：`mapState`/`mapMutations`等可简化组件中对Store的访问代码。

### 核心原则

- Vuex遵循“单向数据流”，所有状态变化可追踪、可调试；
- 非共享状态（如组件私有数据）无需放入Vuex，避免过度设计；
- 小型项目可不用Vuex（用EventBus/Props），中大型项目必须用Vuex保证状态管理的规范性。
