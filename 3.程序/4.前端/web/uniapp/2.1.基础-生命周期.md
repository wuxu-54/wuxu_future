# uniapp 组件生命周期与跳转场景执行规则全总结

uniapp的生命周期分为**Vue标准组件生命周期**（通用自定义子组件）、**uniapp页面专属生命周期**（pages.json注册的页面组件）两大类，跳转行为的核心差异集中在页面生命周期的触发规则上，以下为完整规范与实测执行顺序。

## 一、核心生命周期基础定义

### 1. 通用自定义组件生命周期（Vue标准）

只有页面组件能触发onLoad、onShow等页面专属钩子，**普通自定义子组件仅支持Vue标准生命周期**，全平台兼容，分为Vue2和Vue3两个版本：

| Vue2 生命周期 | 触发核心时机 | 核心用途 |
| --- | --- | --- |
| beforeCreate | 实例初始化前，数据/方法未初始化 | 极少使用，无法访问this |
| created | 实例创建完成，数据/方法已就绪，DOM未生成 | 同步数据初始化，无DOM操作的逻辑 |
| beforeMount | 挂载开始前，模板编译完成，DOM未挂载 | 挂载前最后一次数据修改 |
| mounted | DOM挂载完成，可访问节点信息 | 异步DOM操作、第三方插件初始化 |
| beforeUpdate | 数据更新，虚拟DOM打补丁前（仅H5全支持） | 更新前数据状态捕获 |
| updated | 数据更新，虚拟DOM重渲染完成后（仅H5全支持） | 更新后的DOM操作 |
| beforeDestroy | 实例销毁前，实例仍完全可用 | 清除定时器、事件监听、订阅消息 |
| destroyed | 实例完全销毁，所有子实例同步销毁 | 最终资源释放，避免内存泄漏 |

Vue3 组合式API对应关系：

- `setup()` 替代 `beforeCreate` + `created`，为组件最先执行的钩子
- `onBeforeMount`/`onMounted` 对应 `beforeMount`/`mounted`
- `onBeforeUpdate`/`onUpdated` 对应 `beforeUpdate`/`updated`
- `onBeforeUnmount`/`onUnmounted` 对应 `beforeDestroy`/`destroyed`

### 2. 页面组件专属生命周期（跳转核心）

页面是pages.json中注册的特殊根组件，除支持上述Vue标准生命周期外，额外拥有uniapp专属页面生命周期，其中与跳转强相关的核心钩子如下：

| 页面生命周期 | 触发核心时机 | 触发次数 | 核心用途 |
| --- | --- | --- | --- |
| onLoad | 页面加载时触发，可接收跳转传递的query参数 | 仅1次 | 接收路由参数、发起页面核心初始化请求 |
| onShow | 页面显示/切入前台时触发 | 多次 | 每次页面出现都需执行的逻辑（刷新状态、检查登录态） |
| onReady | 页面初次渲染完成，视图层DOM已就绪 | 仅1次 | 获取节点信息、操作DOM、初始化Canvas |
| onHide | 页面隐藏/切入后台时触发 | 多次 | 页面切走时暂停任务（暂停定时器、视频播放） |
| onUnload | 页面卸载时触发 | 仅1次 | 释放页面独占资源、清除全局监听、取消未完成请求 |

## 二、页面+子组件 基础执行顺序（首次加载）

以Vue2版本为例，页面首次打开且包含自定义子组件时，完整执行顺序如下，这是所有跳转场景的基础：

```
App.onLaunch（应用启动仅执行1次）
→ App.onShow
→ 页面 beforeCreate
→ 页面 created
→ 页面 onLoad（接收路由参数）
→ 页面 onShow
→ 页面 beforeMount
→ 子组件 beforeCreate
→ 子组件 created
→ 子组件 beforeMount
→ 子组件 mounted
→ 页面 mounted
→ 页面 onReady
```

核心要点：子组件的`mounted` 先于 页面的`mounted`、`onReady` 执行；子组件不会触发任何页面专属生命周期。

## 三、核心重点：不同跳转场景的生命周期执行顺序

以下场景均默认：页面A为当前页，页面B为目标页，两页面均包含子组件，基于Vue2版本规范。

### 场景1：uni.navigateTo（最常用，保留当前页跳转）

日常开发最主流的跳转方式，当前页面A保留在页面栈中，仅隐藏不销毁。
**完整执行顺序**：

1. 页面A 仅触发 `onHide`（无销毁钩子，页面实例完整保留）
2. 页面B 完整执行首次加载全流程：
    页面B beforeCreate → created → onLoad（接收跳转参数） → onShow → beforeMount
    → 页面B子组件 beforeCreate → created → beforeMount → mounted
    → 页面B mounted → onReady

**反向操作：B页面 navigateBack 返回A页面**
执行顺序：

1. 页面B 完整销毁流程：`onUnload` → beforeDestroy → 页面B子组件 beforeDestroy → destroyed → 页面B destroyed
2. 页面A 仅触发 `onShow`（onLoad、created、mounted、onReady 均不会重复触发，实例未被销毁）
3. 若A页面数据无更新，其子组件不会触发任何生命周期；仅数据变化时触发beforeUpdate/updated

### 场景2：uni.redirectTo（关闭当前页跳转）

当前页面A会被完全卸载销毁，不保留在页面栈中，无法通过返回键回到A页面。
**完整执行顺序**：

1. 页面A 完整销毁流程：`onUnload` → beforeDestroy → 页面A子组件 beforeDestroy → destroyed → 页面A destroyed
2. 页面B 完整执行首次加载全流程（同场景1的B页面）

### 场景3：uni.switchTab（tabBar页面切换）

tabBar页面有特殊常驻机制：**一旦首次加载完成，就会常驻内存，不会被卸载**，仅切换显示/隐藏状态。
分两种核心情况：

#### 情况1：首次打开目标tabBar页面B

执行顺序：

1. 原页面A（非tab页）触发完整销毁流程（同redirectTo的A页面）
2. 页面B 完整执行首次加载全流程

#### 情况2：已加载过的tabBar页面之间切换（A→B）

执行顺序：

1. 页面A 触发 `onHide`
2. 页面B 仅触发 `onShow`
3. 两个页面的子组件均不会触发销毁/初始化钩子，仅数据变化时触发更新钩子

### 场景4：uni.reLaunch（关闭所有页面，打开目标页）

会销毁当前应用中所有已打开的页面（包括tabBar页面），仅保留目标页面B。
**完整执行顺序**：

1. 所有已打开的页面，依次触发 `onUnload` + 完整销毁流程，对应子组件同步全部销毁
2. 页面B 完整执行首次加载全流程

### 场景5：应用前后台切换

- App切后台：当前页面触发 `onHide`
- App切回前台：当前页面触发 `onShow`
- 页面和子组件均不会被销毁，无初始化/销毁钩子触发。

## 四、高频踩坑避坑指南

1. 禁止在子组件中使用`onLoad`、`onShow`等页面生命周期，子组件无法触发这些钩子，只会静默失效。
2. tabBar页面的`onLoad`仅执行一次，每次切换tab都要执行的逻辑必须写在`onShow`中，而非`onLoad`。
3. `navigateTo`跳转的页面，禁止在`onHide`中写销毁逻辑，`onHide`仅代表页面隐藏，实例仍保留，销毁逻辑必须写在`onUnload`中。
4. 页面跳转参数仅能在`onLoad`中稳定获取，`onShow`无法直接接收路由参数，需在`onLoad`中将参数存入data或全局状态。
5. 不要在`mounted`/`onReady`中默认子组件已完全挂载，若需等待子组件全部挂载完成，需使用`$nextTick`包裹逻辑。
6. Vue3版本中，页面生命周期钩子需在setup中导入使用，执行顺序与Vue2完全一致。
