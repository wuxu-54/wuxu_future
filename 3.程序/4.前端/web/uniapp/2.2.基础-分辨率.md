# uniapp 分辨率

要彻底搞懂 uniapp 中 Canvas 的分辨率适配，必须先夯实 **物理像素、逻辑像素、设备像素比（dpr）** 等核心基础，再结合 uniapp 旧版/新版 Canvas API 的差异选择方案。以下是完整知识体系与实操指南：

## 一、核心基础：先搞懂像素与 dpr

这是所有适配的底层逻辑，必须吃透。

### 1. 物理像素（Physical Pixel）

- **定义**：屏幕上最小的物理发光点，出厂即固定（如 iPhone 13 屏幕有 2532×1170 个物理像素）。
- **特点**：物理像素的数量决定了屏幕的“硬件分辨率”，无法通过软件改变。

### 2. 逻辑像素（Logical Pixel，也叫 CSS 像素）

- **定义**：程序员写代码时用的抽象像素单位（如 CSS 里的 `px`、uniapp 里的 `rpx` 最终也会转换为逻辑 px）。
- **特点**：逻辑像素是“软件层面”的单位，由操作系统/浏览器统一映射到物理像素上。

### 3. 设备像素比（dpr = Device Pixel Ratio）

- **核心公式**：`dpr = 物理像素 / 逻辑像素`
- **直观理解**：1 个逻辑像素需要用多少个物理像素来渲染。
- **常见例子**：
  - 普通屏幕（dpr=1）：1逻辑像素 = 1物理像素（早期非高清屏）；
  - Retina 屏（dpr=2）：1逻辑像素 = 2×2=4个物理像素（如 iPhone SE）；
  - 超高清屏（dpr=3）：1逻辑像素 = 3×3=9个物理像素（如 iPhone 13 Pro）。

### 4. uniapp 中的 rpx 与逻辑 px 的关系

uniapp 规定：`750rpx = 屏幕宽度（逻辑 px）`，因此：

```javascript
// 1rpx 对应的逻辑 px 值
const rpxToPx = (screenWidthInLogicalPx) => screenWidthInLogicalPx / 750;
```

例如：屏幕逻辑宽度为 375px，则 28rpx = 28 × (375/750) = 14逻辑px。

## 二、为什么 Canvas 需要特殊适配？

普通 CSS 元素（如 `<view>`、`<text>`）不需要手动处理 dpr，因为**浏览器/小程序框架会自动完成“逻辑像素 → 物理像素”的映射**，保证高清显示。

但 Canvas 是个例外：

- Canvas 有**两套尺寸**：`画布尺寸`（物理像素，决定清晰度）和 `样式尺寸`（逻辑像素，决定页面上的显示大小）；
- Canvas 2D 上下文（`ctx`）的绘制单位默认是**逻辑像素**，若不手动对齐 dpr，会出现两个问题：
  1. **文字/图形模糊**：用 1逻辑像素绘制，实际只用 1物理像素渲染（浪费了高清屏的物理像素）；
  2. **大小与 CSS 不一致**：Canvas 绘制的 14px 可能和 CSS 的 14px 视觉大小不同（因平台映射逻辑差异）。

## 三、uniapp 两套 Canvas API 的适配方案

uniapp 有 **旧版 Canvas API**（`uni.createCanvasContext`）和 **Canvas 2.0 API**（`type="2d"`），适配逻辑完全不同，**强烈推荐新项目用 Canvas 2.0**。

---

### 方案 1：Canvas 2.0（推荐，全平台统一）

Canvas 2.0 是目前 uniapp 官方主推的方案，dpr 处理逻辑全平台统一，兼容性最好。

#### 适配核心步骤

1. **区分两套尺寸**：
   - `样式尺寸`：Canvas 标签 `style` 中的 `width`/`height`（逻辑像素，控制页面显示大小）；
   - `画布尺寸`：Canvas 节点的 `width`/`height` 属性（物理像素，控制清晰度，需设为 `样式尺寸 × dpr`）。
2. **缩放坐标系**：用 `ctx.scale(dpr, dpr)` 将 Canvas 坐标系放大 dpr 倍，让绘制单位直接等于逻辑像素。

#### 完整代码示例

```html
<template>
  <view class="container">
    <!-- Canvas 2.0 必须加 type="2d"，用 id 不用 canvas-id -->
    <canvas 
      id="myCanvas" 
      type="2d" 
      style="width: 300px; height: 200px;" <!-- 样式尺寸：逻辑像素 -->
      class="canvas-box"
    ></canvas>
  </view>
</template>

<script setup>
import { ref, onMounted, getCurrentInstance } from 'vue'

const instance = getCurrentInstance()
const dpr = ref(1)
const screenWidth = ref(0)

const initCanvas2d = async () => {
  // 1. 获取系统信息（dpr、屏幕宽度）
  const systemInfo = uni.getSystemInfoSync()
  dpr.value = systemInfo.pixelRatio
  screenWidth.value = systemInfo.screenWidth

  // 2. 获取 Canvas 2.0 节点
  const query = uni.createSelectorQuery().in(instance)
  const canvasRes = await new Promise((resolve) => {
    query.select('#myCanvas')
      .fields({ node: true, size: true })
      .exec((res) => resolve(res[0]))
  })
  if (!canvasRes) return

  const canvas = canvasRes.node
  const ctx = canvas.getContext('2d')

  // 3. 设置画布物理尺寸 = 样式逻辑尺寸 × dpr（解决模糊）
  canvas.width = canvasRes.width * dpr.value
  canvas.height = canvasRes.height * dpr.value

  // 4. 缩放坐标系：让绘制单位 = 逻辑像素（后续直接用逻辑 px 绘制）
  ctx.scale(dpr.value, dpr.value)

  // 5. 绘制示例：对齐 CSS 的 28rpx
  const targetRpx = 28
  const fontSizeInPx = targetRpx * (screenWidth.value / 750) // rpx 转逻辑 px
  ctx.font = `${fontSizeInPx}px sans-serif` // 字体大小直接用逻辑 px
  ctx.fillStyle = '#333'
  ctx.textBaseline = 'top'
  ctx.fillText('Canvas 2.0 文字', 20, 20)
}

onMounted(() => {
  initCanvas2d()
})
</script>

<style scoped>
.canvas-box {
  background-color: #f5f5f5;
}
</style>
```

### 方案 2：旧版 Canvas API（`uni.createCanvasContext`，仅维护旧项目用）

旧版 API 已逐步被弃用，且不同平台（微信小程序、H5、App）的 dpr 处理逻辑有差异，仅建议用于无法迁移的旧项目。

#### 适配核心逻辑

旧版 API 无需手动设置画布物理尺寸（平台会部分处理），核心是**将 rpx 转换为逻辑 px 后直接喂给 `setFontSize`**，部分平台需额外处理模糊。

#### 完整代码示例

```html
<template>
  <view class="container">
    <!-- 旧版用 canvas-id，不用 type="2d" -->
    <canvas 
      canvas-id="oldCanvas" 
      style="width: 300px; height: 200px;"
      class="canvas-box"
    ></canvas>
  </view>
</template>

<script setup>
import { ref, onMounted } from 'vue'

const screenWidth = ref(0)

const drawOldCanvas = () => {
  // 1. 创建旧版上下文
  const ctx = uni.createCanvasContext('oldCanvas', this)

  // 2. rpx 转逻辑 px（核心对齐 CSS）
  const targetRpx = 28
  const fontSizeInPx = targetRpx * (screenWidth.value / 750)

  // 3. 设置字体并绘制
  ctx.setFontSize(fontSizeInPx)
  ctx.setFillStyle('#333')
  ctx.setTextBaseline('top')
  ctx.fillText('旧版 Canvas 文字', 20, 20)

  // 4. 旧版必须调用 draw() 才渲染
  ctx.draw()
}

onMounted(() => {
  const systemInfo = uni.getSystemInfoSync()
  screenWidth.value = systemInfo.screenWidth
  // 延迟绘制确保节点初始化
  setTimeout(() => drawOldCanvas(), 100)
})
</script>

<style scoped>
.canvas-box {
  background-color: #f5f5f5;
}
</style>
```

#### 旧版 API 额外注意

- 若部分平台仍模糊，可尝试将绘制尺寸整体 × dpr 后，再通过 CSS 缩小 Canvas 样式尺寸（但此方法会增加性能消耗，优先迁移到 2.0）；
- 旧版 `ctx.font` 兼容性差，优先用 `setFontSize` 设置大小。

## 四、适配方案选择建议

| 场景 | 推荐方案 | 理由 |
|------|----------|------|
| 新项目 | Canvas 2.0 | 全平台 dpr 处理统一，官方长期维护，性能更好 |
| 旧项目维护 | 旧版 API（短期） + 逐步迁移 2.0（长期） | 旧版 API 已进入弃用周期，新功能仅支持 2.0 |
| 需复杂图形/高性能绘制 | Canvas 2.0 | 2.0 支持 WebGL 扩展，绘制效率更高 |

## 五、避坑核心总结

1. **永远记住 Canvas 有两套尺寸**：样式尺寸（逻辑 px，控制大小）+ 画布尺寸（物理 px，控制清晰度）；
2. **dpr 是连接两者的桥梁**：画布尺寸 = 样式尺寸 × dpr，再用 `ctx.scale(dpr, dpr)` 统一绘制单位；
3. **rpx 不能直接喂给 Canvas**：必须先转成逻辑 px（`rpx × (屏幕宽度/750)`）；
4. **字体族和基线要统一**：即使大小一致，`font-family` 和 `textBaseline` 不同也会导致视觉差异。
