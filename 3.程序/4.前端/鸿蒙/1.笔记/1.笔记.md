# 笔记

1. FA模型是初版模型（早期仿照Android那一套），现在被Stage模型取代。
2. State模型主要包含：
    - UIAbility：替代 Page Ability，负责 UI 页面与用户交互
    - ExtensionAbility：替代 Service/Data Ability，扩展不同场景能力（如服务、数据共享、表单、通知等，细分更多类型）
    - AbilityStage：模块生命周期管理者（新增核心组件）
4. 生命周期分为模块级和组件级：
    - 模块级：AbilityStage的onCreate()（模块初始化）、onDestroy()（模块销毁）
    - 组件级：UIAbility 的onCreate()→onWindowStageCreate()（窗口创建）→onWindowStageDestroy()→onDestroy()
    （侧重 “窗口与模块的生命周期绑定”）

## State模型

1. app.json5  是应用全局信息和特定设备类型的配置信息。
2. module.json5 包括模块的基本配置信息，UIAbility组件、ExtensionAbility组件信息，和应用运行过程中需要的权限信息，用于向编译工具、操作系统和应用市场提供应用的基本信息。

## 基础

1. 图标和名称的设置：json5中设置icon、label；
    - 优先级：1. 多module.json5，取mainElement中的icon与label；2. module.json5>app.json5；
    - module.json5必须包含：skills `entity.system.home`，`ohos.want.action.home`:

        ```json
            {
        "module": {
            // ...
            "abilities": [
            {
                "icon": "$media:icon",
                "label": "$string:EntryAbility_label", // 需要在entry/src/main/resources/base/element/string.json配置name为EntryAbility_label的资源，已存在可以忽略
                "skills": [
                {
                    "entities": [
                    "entity.system.home"
                    ],
                    "actions": [
                    "ohos.want.action.home"
                    ]
                }
                ],
            }
            ]
        }
        }
        ```
