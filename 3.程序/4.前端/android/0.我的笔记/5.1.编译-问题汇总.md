# android 编译问题

请记住，Android里百分之99的疑难编译问题都是Gradle版本与AGP版本兼容性导致的。

## jdk版本导致的编译报错

问题：

```txt
java.lang.IllegalAccessError: superclass access check failed: class org.jetbrains.kotlin.kapt3.base.javac.KaptJavaCompiler (in unnamed module @0x2aeebf25) cannot access class com.sun.tools.javac.main.JavaCompiler (in module jdk.compiler) because module jdk.compiler does not export com.sun.tools.javac.main to unnamed module @0x2aeebf25
at java.base/java.lang.ClassLoader.defineClass1(Native Method)
at java.base/java.lang.ClassLoader.defineClass(Unknown Source)
```

问题原因是gradle的编译时jdk版本过高，导致 kapt 找不到某些类（因为java高版本将其隐藏了）

解决：

1. jdk版本问题，修改jdk版本.

    >注意，Android里JDK有三个地方配置jdk，其作用是不一样的。下面的1是编译时用的java版本，2是项目源码编译时用到的。 3.是全局jdk如果1,2没有配置，则使用3。
    >
    >1. **Gradle 构建 JDK**：Gradle 执行编译、kapt 注解处理时使用的 JDK。**你遇到的 kapt 报错完全由它决定**，是排查重点。
    >2. **项目源码编译版本**：代码编译时遵循的 Java 语法版本（如 Java 8、Java 11），和本次模块访问报错无关。
    >3. **系统全局 JDK**：终端里 `java -version` 看到的版本，Gradle 不一定会使用它。

2. jdk 已经是 11 了为什么还会这样？答：设置jdk版本为11，但通过 `./gradlew --version` 查看的版本还是`17.0.17`，需要进一步修改，保证gradle使用的jdk版本是11。

    - 方式 A：IDE 中修改（Android Studio / IDEA）。
        打开 `Settings → Build, Execution, Deployment → Build Tools → Gradle`，找到 **Gradle JDK** 选项，选择你本地安装的 JDK 11，确认后重新构建即可。
    - 方式 B：配置文件强制指定（命令行也生效，Mac 推荐）
        如果终端执行命令时依然用 JDK 17（系统默认 `JAVA_HOME` 指向 Homebrew 的 JDK 17），可以在**项目根目录 `gradle.properties`** 中强制指定 JDK 路径：

        ```
        # 替换成你本地 JDK 11 的实际路径
        org.gradle.java.home=/Library/Java/JavaVirtualMachines/jdk-11.0.xx.jdk/Contents/Home
        ```

        >
        > Mac 上查看所有已安装 JDK 的路径，可执行命令：`/usr/libexec/java_home -V`

    - **配置后必做操作**:修改完成后，执行 `./gradlew clean` 清理构建缓存，再重新编译，避免旧缓存导致异常持续。
