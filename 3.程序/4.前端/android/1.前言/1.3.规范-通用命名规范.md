# 通用命名规范

## 一、通用基础命名规范（Java/Kotlin 通用）

这是所有Android代码的基础约定，适用于类、方法、变量、常量、包名等核心元素：

| 元素类型 | 命名规则 | 示例 |
|----------|----------|------|
| 包名     | 全小写，采用**反向域名**格式，层级清晰且唯一 | `com.example.myapp`、`com.example.myapp.ui.login` |
| 类名     | 帕斯卡命名法（PascalCase）：每个单词首字母大写；组件类需加明确后缀（Activity/Fragment/Service等） | `MainActivity`、`UserListFragment`、`UserModel`、`LoginService` |
| 方法名   | 驼峰命名法（camelCase）：首字母小写，**动词开头**（体现动作）；回调方法以`on`开头 | `getUserInfo()`、`saveUserData()`、`onCreate()`、`onClick()` |
| 变量名   | 驼峰命名法：首字母小写，**名词为主**，直观反映用途；布尔变量以`is/has/can`开头 | `userName`、`userAge`、`isLoginSuccess`、`hasPermission` |
| 常量     | 全大写，下划线分隔；Java用`final static`，Kotlin用`const val` | `MAX_LOGIN_COUNT`、`BASE_URL`、`DEFAULT_TIMEOUT` |
| 缩写     | 仅使用通用缩写（如ID、URL、HTTP），禁止自创缩写；统一大小写（如`userId`而非`userID`） | `userUrl`（正确）、`usrNm`（错误，禁止自创缩写） |

## 二、Android 特有组件/资源命名规范

这是谷歌针对Android专属的布局、资源、控件等制定的核心规范，也是新手最容易出错的部分：

### 1. 布局文件命名

全小写 + 下划线分隔，**前缀区分布局类型**，格式：`类型_功能描述`

| 布局类型 | 命名前缀 | 示例 |
|----------|----------|------|
| Activity布局 | `activity_` | `activity_main.xml`、`activity_login.xml` |
| Fragment布局 | `fragment_` | `fragment_user_list.xml`、`fragment_profile.xml` |
| 对话框布局 | `dialog_` | `dialog_confirm.xml` |
| 列表项布局 | `item_` | `item_user.xml`、`item_order.xml` |
| 通用布局（include） | `layout_` | `layout_title_bar.xml` |

### 2. 控件ID命名

布局中控件的`android:id`，全小写 + 下划线分隔，格式：`控件类型缩写_功能描述`
常用控件缩写：

- `btn`（Button）、`tv`（TextView）、`et`（EditText）、`rv`（RecyclerView）
- `iv`（ImageView）、`cb`（CheckBox）、`sp`（Spinner）、`sw`（Switch）

示例：

```xml
<!-- 正确示例 -->
<Button android:id="@+id/btn_login" ... />
<TextView android:id="@+id/tv_user_name" ... />
<EditText android:id="@+id/et_phone_number" ... />
<RecyclerView android:id="@+id/rv_user_list" ... />
```

### 3. 资源文件命名（drawable/color/string等）

- **字符串资源（strings.xml）**：键名小写 + 下划线，按“模块_功能”划分，示例：`app_name`、`btn_login`、`toast_network_error`
- **颜色资源（colors.xml）**：`color_`前缀 + 功能，示例：`color_primary`、`color_text_hint`、`color_bg_login`
- **图片资源（drawable/mipmap）**：按“类型_名称_状态”命名，示例：`ic_home`（ic=图标）、`bg_login`（bg=背景）、`btn_login_pressed`（带状态）
- **样式/主题（styles.xml）**：帕斯卡命名法，示例：`AppTheme`、`LoginButtonStyle`

### 3. 其他Android组件

- **枚举**：枚举类名帕斯卡命名法，枚举值全大写 + 下划线，示例：

  ```kotlin
  enum class NetworkState {
      IDLE, LOADING, SUCCESS, ERROR
  }
  ```

- **接口**：帕斯卡命名法，通常以`able/ible`结尾（体现能力），示例：`Clickable`、`DataProvider`

## 三、补充规范（谷歌推荐的最佳实践）

1. **注释规范**：类注释用Javadoc（Java）/KDoc（Kotlin）说明用途；方法注释说明参数、返回值、异常；复杂逻辑加行内注释。
2. **组件后缀统一**：自定义View/ViewModel等需加明确后缀，示例：`RoundCornerView`、`UserViewModel`。
3. **避免冗余**：命名不重复体现上下文，比如在`LoginActivity`中，变量名用`userName`而非`loginActivityUserName`。

---

### 总结

1. 基础核心：类用帕斯卡命名法，方法/变量用驼峰命名法，常量全大写+下划线，包名全小写反向域名。
2. Android特有：资源文件/控件ID全小写+下划线，布局文件前缀区分类型（activity_/fragment_），控件ID按“类型缩写_功能”命名。
3. 核心原则：命名**直观反映功能**，缩写通用且统一，组件后缀明确（如Activity/Fragment），确保代码易读、易维护。
