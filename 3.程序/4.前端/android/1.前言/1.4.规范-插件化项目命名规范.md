# 插件化项目命名规范

## 一、基础命名规范（强化细节 + 工程场景适配）

谷歌基础规范以Java/Kotlin为核心，以下补充插件化/模块化场景的细化约定：

| 元素类型 | 核心规则 | 插件化/工程适配细节 | 正确示例 | 错误示例 |
|----------|----------|---------------------|----------|----------|
| 包名     | 全小写 + 反向域名 + 层级划分 | 1. 分层规则：`反向域名.模块类型.模块名.功能` <br> 2. 插件包名：`com.example.app.plugin.插件名.功能` <br> 3. 宿主包名：`com.example.app.host.功能` <br> 4. 核心库包名：`com.example.app.core.功能` | `com.example.app.plugin.user.api`（用户插件API）<br>`com.example.app.host.ui.main`（宿主主界面）<br>`com.example.app.core.router`（核心路由库） | `com.example.app.Plugin.User`（含大写）<br>`com.example.app.plugin.orderlist`（无层级）<br>`com.example.app.plugin.1user`（含数字） |
| 类名     | 帕斯卡命名法（PascalCase） + 明确后缀 | 1. 插件类后缀：Plugin/PluginManager/PluginRouter/PluginApi <br> 2. 通用后缀：Activity/Fragment/ViewModel/Repository/Entity <br> 3. 插件类需体现归属：`UserPluginManager`（而非`PluginManager`） | `UserPluginLoginActivity`、`OrderPluginRouter`<br>`HostMainViewModel`、`CoreNetworkUtil` | `userpluginloginactivity`（全小写）<br>`PluginMgr`（自创缩写）<br>`User`（无后缀，无法区分类型） |
| 方法名   | 驼峰命名法（camelCase） + 动词开头 | 1. 插件专属动词前缀：<br> - 插件加载：loadXxxPlugin <br> - 插件通信：routeToXxxPlugin/invokeXxxPluginApi <br> - 插件生命周期：initXxxPlugin/unloadXxxPlugin <br> 2. 异步方法：fetchXxx（异步）/getXxx（同步） | `loadUserPlugin()`、`routeToOrderPlugin()`<br>`fetchUserInfoAsync()`、`initAllPlugins()` | `LoadUserPlugin()`（大写开头）<br>`doPlugin()`（无意义动词）<br>`pluginLoad()`（动词后置） |
| 变量名   | 驼峰命名法 + 语义化 + 类型标识 | 1. 插件相关变量：体现插件名 + 功能 <br> 2. 布尔变量：is/has/can + 插件状态 <br> 3. 集合变量：复数名词 + 插件标识 | `userPluginConfig`、`isPluginLoaded`<br>`orderPluginList`、`hasPluginPermission` | `plugin1`（数字后缀）<br>`flag`（无意义）<br>`UserPluginConfig`（大写开头） |
| 常量     | 全大写 + 下划线 + 作用域区分 | 1. 插件常量：PLUGIN_插件名_功能_类型 <br> 2. Intent Action：反向域名 + 插件标识 <br> 3. 状态常量：PLUGIN_STATE_XXX | `PLUGIN_USER_LOGIN_ACTION`<br>`PLUGIN_STATE_LOADED`、`EXTRA_ORDER_PLUGIN_ID` | `plugin_user_action`（小写）<br>`State_Loaded`（混合大小写）<br>`KEY_ID`（无插件标识） |
| 缩写     | 仅通用缩写 + 统一大小写 | 谷歌认可的通用缩写：<br> - 基础：id/url/http/api/json <br> - 插件：plugin/router/host/core <br> - 控件：btn/tv/et/rv/iv <br> 规则：2字母缩写小写（userId），≥3字母小写（httpClient） | `userId`、`pluginRouter`、`httpClient` | `userID`（混合）<br>`usrNm`（自创缩写）<br>`PluginRouter`（变量大写开头） |

## 二、Android核心组件命名（插件化适配版）

### 1. 四大组件（插件化隔离）

| 组件类型 | 命名规则 | 插件化示例 |
|----------|----------|------------|
| Activity | PascalCase + [插件名] + 功能 + Activity | `HostMainActivity`（宿主）、`UserPluginLoginActivity`（用户插件） |
| Service | PascalCase + [插件名] + 功能 + Service | `HostPushService`（宿主）、`OrderPluginPayService`（订单插件） |
| BroadcastReceiver | PascalCase + [插件名] + 功能 + Receiver | `UserPluginLoginStatusReceiver`、`HostPluginLoadedReceiver` |
| ContentProvider | PascalCase + [插件名] + 数据类型 + Provider | `OrderPluginOrderProvider`、`HostUserProvider` |

### 2. Intent通信（插件化核心）

插件化的跨组件通信是命名冲突重灾区，需严格遵循：

- **Action命名**：`com.example.app.[plugin/host].插件名.功能.ACTION_XXX`  
  示例：`com.example.app.plugin.user.ACTION_LOGIN`、`com.example.app.host.ACTION_PLUGIN_LOADED`
- **Extra Key命名**：`EXTRA_插件名_功能_参数名`  
  示例：`EXTRA_USER_PLUGIN_USER_ID`、`EXTRA_ORDER_PLUGIN_ORDER_NO`
- **Intent Filter命名**（Manifest中）：`intent_filter_插件名_功能`  
  示例：`intent_filter_plugin_user_login`

## 三、资源命名（全品类 + 插件化隔离）

谷歌要求资源全小写 + 下划线，插件化场景需**强制加插件标识前缀**避免冲突：

| 资源类型 | 命名规则 | 插件化示例 |
|----------|----------|------------|
| 布局（layout） | 前缀_功能[_插件标识] <br> 前缀：activity/fragment/item/dialog | `activity_plugin_user_login.xml`<br>`fragment_host_main.xml`<br>`item_plugin_order_list.xml` |
| 控件ID | 控件缩写_功能[_插件标识] | `btn_plugin_user_login`、`tv_host_title`、`rv_plugin_order_list` |
| 字符串（string） | [模块_插件]_功能_类型 <br> 类型：hint/title/toast/error | `plugin_user_login_hint`、`host_network_error_toast`、`core_common_confirm` |
| 颜色（color） | color_用途[_插件][_状态] | `color_plugin_user_btn_pressed`、`color_host_bg_main` |
| 尺寸（dimen） | dimen_用途[_插件][_类型] <br> 类型：size/padding/margin | `dimen_plugin_user_btn_height`、`dimen_host_margin_horizontal` |
| 图标（drawable） | 类型_名称[_插件][_状态] <br> 类型：ic/bg/selector | `ic_plugin_user_avatar.xml`、`selector_plugin_order_btn.xml` |

### 插件化资源隔离关键配置

在插件模块的`build.gradle`中配置**资源前缀**，强制所有资源以指定前缀命名（编译时校验）：

```gradle
android {
    // 强制user插件的所有资源以plugin_user_开头，否则编译报错
    resourcePrefix "plugin_user_" 
}
```

## 四、插件化/模块化专属命名规范（核心）

### 1. 模块/工程命名

| 模块类型 | 命名规则 | 目录示例 |
|----------|----------|----------|
| 宿主工程 | 全小写 + 下划线：app_host / app | `app_host` |
| 插件工程 | 全小写 + 下划线：plugin_插件名 | `plugin_user`、`plugin_order` |
| 核心库 | 全小写 + 下划线：lib_core_功能 | `lib_core_base`、`lib_core_router`、`lib_core_net` |
| 业务组件 | 全小写 + 下划线：lib_component_业务名 | `lib_component_cart`、`lib_component_pay` |

### 2. 插件通信相关

| 通信元素 | 命名规则 | 示例 |
|----------|----------|------|
| 路由类 | PascalCase + 插件名 + PluginRouter | `UserPluginRouter`、`OrderPluginRouter` |
| 路由路径 | 小写 + 斜杠 + 插件名 + 功能 | `/plugin/user/login`、`/host/main` |
| 插件管理器 | PascalCase + [Global/插件名] + PluginManager | `GlobalPluginManager`、`UserPluginManager` |
| 插件API接口 | PascalCase + 插件名 + PluginApi + 版本（可选） | `UserPluginApiV1`、`OrderPluginApi` |
| 插件API实现 | PascalCase + 插件名 + PluginApiImpl | `UserPluginApiImpl` |
| 插件回调 | PascalCase + 插件名 + Plugin + 功能 + Callback | `UserPluginLoginCallback` |

### 3. 插件生命周期相关

| 生命周期元素 | 命名规则 | 示例 |
|--------------|----------|------|
| 初始化方法 | camelCase + init + 插件名 + Plugin | `initUserPlugin()`、`initAllPlugins()` |
| 加载方法 | camelCase + load + 插件名 + Plugin | `loadUserPlugin()`、`loadPluginByPath()` |
| 卸载方法 | camelCase + unload + 插件名 + Plugin | `unloadUserPlugin()` |
| 状态常量 | 全大写 + PLUGIN_STATE_状态 | `PLUGIN_STATE_LOADED`、`PLUGIN_STATE_ERROR`、`PLUGIN_STATE_UNLOADED` |

## 五、Jetpack组件命名（谷歌官方+插件化适配）

| Jetpack组件 | 命名规则 | 插件化示例 |
|-------------|----------|------------|
| ViewModel | PascalCase + [插件名] + 功能 + ViewModel | `UserPluginLoginViewModel`、`HostMainViewModel` |
| LiveData/Flow | camelCase + 数据名 + LiveData/Flow | `userPluginInfoLiveData`、`orderPluginStateFlow` |
| Room实体 | PascalCase + 表名 + Entity | `UserEntity`、`OrderEntity`（插件内无需加插件名） |
| Room DAO | PascalCase + 表名 + Dao | `UserDao`、`OrderDao` |
| Repository | PascalCase + [插件名] + 功能 + Repository | `UserPluginUserRepository`、`HostOrderRepository` |
| WorkManager | PascalCase + [插件名] + 任务 + Worker | `PluginUserSyncWorker`、`HostCleanCacheWorker` |

## 六、工程文件/目录命名（工程级规范）

| 工程元素 | 命名规则 | 示例 |
|----------|----------|------|
| 模块目录 | 全小写 + 下划线 | `plugin_user`、`lib_core_router`、`app_host` |
| Gradle文件 | 全小写 + 下划线 + 功能 | `build.gradle`、`plugin_user_config.gradle` |
| Assets文件 | 全小写 + 下划线 + 插件标识 | `plugin_user_config.json`、`host_app_config.properties` |
| ProGuard规则 | 全小写 + 下划线 + 插件标识 | `proguard_plugin_user.pro`、`proguard_host.pro` |

## 七、插件化命名避坑最佳实践

1. **禁止无标识命名**：插件内的类/资源/常量必须加插件名标识（如`plugin_user_`），对外暴露的组件需在类名体现插件归属；
2. **避免冗余命名**：插件内部的私有类无需重复加插件名（如`UserPlugin`内部的`LoginViewModel`而非`UserPluginLoginViewModel`）；
3. **版本化API命名**：跨插件API需版本化（如`UserPluginApiV1`、`UserPluginApiV2`），避免升级冲突；
4. **统一团队约定**：所有插件的路由路径、Action、参数Key需遵循统一前缀（如`/plugin/xxx/`、`PLUGIN_XXX_`）。

---

### 总结

1. 基础核心：类用帕斯卡命名法、方法/变量用驼峰命名法、常量全大写+下划线，包名/资源全小写+下划线，**插件化场景必须在命名中体现插件标识**（如`plugin_user_`）；
2. 插件化关键：资源通过`resourcePrefix`强制加前缀隔离，通信元素（Action/路由/参数Key）统一前缀，跨模块API版本化命名；
3. 工程适配：模块目录全小写+下划线，宿主/插件/核心库分层命名（`host_`/`plugin_xxx_`/`core_`），对外组件需明确后缀（Router/Manager/Api）。
