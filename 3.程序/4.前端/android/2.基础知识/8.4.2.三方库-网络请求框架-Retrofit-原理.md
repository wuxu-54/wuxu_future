# Retrofit 实现原理深度解析（核心源码+逐行解释）

Retrofit 本质是**基于动态代理封装 OKHttp** 的网络请求框架，核心目标是将「接口方法+注解」转化为可执行的 OKHttp 请求，并完成请求/响应的序列化/反序列化、返回类型适配。以下从核心流程拆解原理，并结合关键源码逐一解释。

## 一、核心原理总览

Retrofit 执行一次网络请求的完整链路：

```
定义接口 → Retrofit.create() 生成动态代理类 → 调用接口方法触发代理逻辑 → 
解析注解生成 ServiceMethod（请求规则） → 通过 CallAdapter 适配返回类型 → 
通过 Converter 处理数据序列化/反序列化 → 封装 OkHttpCall 执行 OKHttp 请求 → 
解析响应并返回适配后的结果
```

核心设计亮点：

- 动态代理：解耦接口定义与请求执行；
- 注解驱动：通过注解声明式定义请求规则；
- 插件化扩展：CallAdapter（返回类型适配）、Converter（数据转换）支持自定义；
- 完全复用 OKHttp 核心能力（连接池、拦截器、超时等）。

## 二、核心流程拆解（附源码解析）

以下源码基于 Retrofit 2.9.0（与前文依赖版本一致），仅保留核心逻辑，简化非关键代码。

### 2.1 动态代理：生成接口代理类（Retrofit.create()）

Retrofit 的入口是 `create(Class<T> service)` 方法，其核心是通过 JDK 动态代理生成接口的代理实例——**当调用接口方法时，不会执行真实方法（接口无实现），而是触发代理的 `invoke` 方法**。

#### 核心源码（Retrofit.java）

```java
public final class Retrofit {
  // 核心方法：创建接口的动态代理实例
  public <T> T create(final Class<T> service) {
    // 校验接口合法性（是否为接口、是否有泛型等）
    Utils.validateServiceInterface(service);
    // 动态代理核心：Proxy.newProxyInstance
    return (T) Proxy.newProxyInstance(
        service.getClassLoader(),
        new Class<?>[] {service},
        new InvocationHandler() { // 代理逻辑核心
          private final Platform platform = Platform.get();
          private final Object[] emptyArgs = new Object[0];

          @Override
          public @Nullable Object invoke(Object proxy, Method method, @Nullable Object[] args)
              throws Throwable {
            // 处理 Object 类的方法（equals/hashCode/toString），直接执行
            if (method.getDeclaringClass() == Object.class) {
              return method.invoke(this, args);
            }
            // 平台相关处理（如 Kotlin 协程的 suspend 方法）
            if (platform.isDefaultMethod(method)) {
              return platform.invokeDefaultMethod(method, service, proxy, args);
            }
            // 核心逻辑：将方法+参数转化为 ServiceMethod → 生成可执行的 Call
            return loadServiceMethod(method).invoke(args != null ? args : emptyArgs);
          }
        });
  }

  // 缓存 ServiceMethod（避免重复解析注解）
  private final Map<Method, ServiceMethod<?>> serviceMethodCache = new ConcurrentHashMap<>();

  ServiceMethod<?> loadServiceMethod(Method method) {
    ServiceMethod<?> result = serviceMethodCache.get(method);
    if (result != null) return result;

    synchronized (serviceMethodCache) {
      result = serviceMethodCache.get(method);
      if (result == null) {
        // 解析注解，构建 ServiceMethod
        result = ServiceMethod.parseAnnotations(this, method);
        serviceMethodCache.put(method, result);
      }
    }
    return result;
  }
}
```

#### 关键解释：

1. `Proxy.newProxyInstance`：JDK 动态代理的核心 API，生成接口的代理类实例；
2. `InvocationHandler.invoke`：所有接口方法调用都会走到这里，是 Retrofit 逻辑的入口；
3. `loadServiceMethod`：解析方法注解生成 `ServiceMethod`（请求规则），并缓存（避免重复解析，提升性能）；
4. 过滤 `Object` 方法：避免代理 `equals()`/`hashCode()` 等通用方法。

### 2.2 注解解析：ServiceMethod 构建请求规则

`ServiceMethod` 是 Retrofit 的「请求规则载体」，其 `Builder` 会解析接口方法上的**请求方法注解（@GET/@POST）**、**参数注解（@Path/@Body）**，最终生成 `RequestFactory`（描述如何构建 OKHttp 的 `Request`）。

#### 核心源码（ServiceMethod.java + RequestFactory.java）

```java
// ServiceMethod 核心：解析注解并构建请求执行逻辑
abstract class ServiceMethod<T> {
  static <T> ServiceMethod<T> parseAnnotations(Retrofit retrofit, Method method) {
    // 第一步：解析注解生成 RequestFactory（描述请求的 URL、方法、参数等）
    RequestFactory requestFactory = RequestFactory.parseAnnotations(retrofit, method);

    // 第二步：获取返回类型（如 Call<User>）
    Type returnType = method.getGenericReturnType();
    // 校验返回类型合法性
    if (Utils.hasUnresolvableType(returnType)) {
      throw methodError(method, "Method return type must not have generic type variables: %s", returnType);
    }

    // 第三步：获取 CallAdapter（适配返回类型）
    CallAdapter<Object, T> callAdapter =
        (CallAdapter<Object, T>) retrofit.callAdapter(returnType, method.getAnnotations());
    // 第四步：获取 Converter（处理请求/响应序列化）
    Type responseType = callAdapter.responseType();
    Converter<ResponseBody, ?> responseConverter =
        retrofit.responseBodyConverter(responseType, method.getAnnotations());

    // 构建 ServiceMethod（最终生成 OkHttpCall 并适配返回类型）
    return HttpServiceMethod.parseAnnotations(retrofit, method, requestFactory, callAdapter, responseConverter);
  }

  abstract @Nullable T invoke(Object[] args);
}

// RequestFactory：解析注解生成请求构建规则
final class RequestFactory {
  static RequestFactory parseAnnotations(Retrofit retrofit, Method method) {
    return new Builder(retrofit, method).build();
  }

  static final class Builder {
    private final Retrofit retrofit;
    private final Method method;
    private final Annotation[] methodAnnotations;
    private final Parameter[] parameters;
    private HttpUrl baseUrl;
    private String httpMethod; // 请求方法：GET/POST 等
    private String relativeUrl; // 接口注解中的 URL 路径
    private boolean hasBody; // 是否有请求体
    // ... 其他字段（请求头、参数规则等）

    Builder(Retrofit retrofit, Method method) {
      this.retrofit = retrofit;
      this.method = method;
      this.methodAnnotations = method.getAnnotations();
      this.parameters = Parameter.parse(method); // 解析方法参数注解
    }

    RequestFactory build() {
      // 1. 解析方法注解（@GET/@POST/@HTTP 等）
      parseMethodAnnotations();
      // 2. 解析参数注解（@Path/@Query/@Body 等）
      parseParameters();
      // 3. 构建 RequestFactory
      return new RequestFactory(this);
    }

    // 解析方法注解（核心：确定请求方法、URL、是否有请求体）
    private void parseMethodAnnotations() {
      for (Annotation annotation : methodAnnotations) {
        if (annotation instanceof GET) {
          parseHttpMethodAndPath("GET", ((GET) annotation).value(), false);
        } else if (annotation instanceof POST) {
          parseHttpMethodAndPath("POST", ((POST) annotation).value(), true);
        } else if (annotation instanceof PUT) {
          parseHttpMethodAndPath("PUT", ((PUT) annotation).value(), true);
        } 
        // ... 其他请求方法注解（DELETE/PATCH/HEAD/OPTIONS/HTTP）的解析逻辑
      }
      if (httpMethod == null) {
        throw methodError(method, "HTTP method annotation is required (e.g., @GET, @POST, etc.).");
      }
    }

    // 解析参数注解（核心：将参数映射到 URL/请求体/请求头）
    private void parseParameters() {
      for (Parameter parameter : parameters) {
        Annotation[] annotations = parameter.annotations;
        if (annotations.length == 0) {
          throw parameterError(parameter, "No Retrofit annotation found.");
        }
        // 遍历参数注解，解析 @Path/@Query/@Body 等
        for (Annotation annotation : annotations) {
          if (annotation instanceof Path) {
            parsePathParameter(parameter, (Path) annotation);
          } else if (annotation instanceof Query) {
            parseQueryParameter(parameter, (Query) annotation);
          } else if (annotation instanceof Body) {
            parseBodyParameter(parameter, (Body) annotation);
          } 
          // ... 其他参数注解（@QueryMap/@Field/@Part/@Header 等）的解析逻辑
        }
      }
    }

    // 构建 OKHttp 的 Request 对象（核心：将参数填充到 URL/请求体）
    Request create(Object[] args) throws IOException {
      RequestBuilder requestBuilder = new RequestBuilder(httpMethod, baseUrl, relativeUrl, hasBody);
      // 1. 填充静态请求头（@Headers 注解）
      // 2. 填充参数（根据参数注解规则，将 args 映射到 RequestBuilder）
      // 3. 构建最终的 Request
      return requestBuilder.build();
    }
  }
}
```

#### 关键解释：

1. `RequestFactory` 是「注解解析的核心产物」：它存储了请求方法、URL 模板、参数映射规则等，最终可通过 `create(args)` 方法生成 OKHttp 的 `Request` 对象；
2. `parseMethodAnnotations`：解析 `@GET/@POST` 等方法注解，确定 HTTP 方法、相对 URL、是否有请求体；
3. `parseParameters`：解析 `@Path/@Query/@Body` 等参数注解，记录每个参数的映射规则（比如 `@Path` 对应 URL 占位符，`@Body` 对应请求体）；
4. `RequestFactory.create(args)`：执行时将接口方法的入参（args）填充到 RequestBuilder，生成最终的 OKHttp Request。

### 2.3 请求适配：CallAdapter 转换返回类型

Retrofit 允许接口方法返回多种类型（`Call<T>`/`Observable<T>`/suspend 函数），核心是 `CallAdapter` 完成「Retrofit 内部 Call → 用户指定类型」的转换。

#### 核心源码（CallAdapter + HttpServiceMethod）

```java
// CallAdapter 接口：定义返回类型适配规则
public interface CallAdapter<R, T> {
  // 原始响应类型（如 User）
  Type responseType();
  // 将 Retrofit 的 Call<R> 适配为 T 类型（如 Observable<User>）
  T adapt(Call<R> call);

  // 工厂类：用于创建 CallAdapter
  abstract class Factory {
    // 根据返回类型和注解，创建对应的 CallAdapter
    public abstract @Nullable CallAdapter<?, ?> get(Type returnType, Annotation[] annotations, Retrofit retrofit);
  }
}

// HttpServiceMethod：ServiceMethod 的核心实现，绑定 CallAdapter 和 Converter
final class HttpServiceMethod<ResponseT, ReturnT> extends ServiceMethod<ReturnT> {
  private final RequestFactory requestFactory;
  private final CallAdapter<ResponseT, ReturnT> callAdapter;
  private final Converter<ResponseBody, ResponseT> responseConverter;

  @Override
  ReturnT invoke(Object[] args) {
    // 1. 根据参数生成 OKHttp Request
    Call<ResponseT> call = new OkHttpCall<>(requestFactory, args, callFactory, responseConverter);
    // 2. 通过 CallAdapter 适配返回类型（核心）
    return callAdapter.adapt(call);
  }
}

// 内置 CallAdapter 示例：DefaultCallAdapter（适配 Retrofit 的 Call<T>）
final class DefaultCallAdapterFactory extends CallAdapter.Factory {
  @Override
  public @Nullable CallAdapter<?, ?> get(Type returnType, Annotation[] annotations, Retrofit retrofit) {
    // 校验返回类型是否为 Call<T>
    if (getRawType(returnType) != Call.class) {
      return null;
    }
    // 提取泛型类型（如 Call<User> 中的 User）
    Type responseType = Utils.getParameterUpperBound(0, (ParameterizedType) returnType);
    // 创建 CallAdapter：将 OkHttpCall 包装为 Retrofit 的 Call
    return new DefaultCallAdapter<>(responseType, executor);
  }

  private static final class DefaultCallAdapter<R> implements CallAdapter<R, Call<R>> {
    @Override
    public Type responseType() {
      return responseType;
    }

    @Override
    public Call<R> adapt(Call<R> call) {
      // 直接返回 OkHttpCall（因为默认返回类型就是 Call<T>）
      return call;
    }
  }
}
```

#### 关键解释：

1. `CallAdapter` 的核心是 `adapt` 方法：将 Retrofit 内部的 `OkHttpCall` 转换为用户需要的类型；
2. `DefaultCallAdapter` 是默认实现：适配 Retrofit 自带的 `Call<T>` 类型，逻辑最简单（直接返回 OkHttpCall）；
3. 扩展实现（如 RxJavaCallAdapter）：会将 `OkHttpCall` 转换为 `Observable<T>`，并处理线程切换、订阅逻辑；
4. 协程适配（CoroutineCallAdapter）：会将 `OkHttpCall` 包装为 suspend 函数的挂起逻辑，实现异步非阻塞。

### 2.4 数据转换：Converter 处理序列化/反序列化

`Converter` 负责「双向数据转换」：

- 请求侧：将用户传入的对象（如 `User`）转为 OKHttp 的 `RequestBody`（如 JSON 字符串）；
- 响应侧：将 OKHttp 的 `ResponseBody`（如 JSON 字符串）转为用户需要的对象（如 `User`）。

#### 核心源码（Converter + GsonConverterFactory）

```java
// Converter 接口：定义数据转换规则
public interface Converter<F, T> {
  @Nullable T convert(F value) throws IOException;

  // 工厂类：创建 Converter
  abstract class Factory {
    // 创建请求体转换器（Object → RequestBody）
    public @Nullable Converter<?, RequestBody> requestBodyConverter(Type type, Annotation[] parameterAnnotations, Annotation[] methodAnnotations, Retrofit retrofit) {
      return null;
    }

    // 创建响应体转换器（ResponseBody → Object）
    public @Nullable Converter<ResponseBody, ?> responseBodyConverter(Type type, Annotation[] annotations, Retrofit retrofit) {
      return null;
    }
  }
}

// GsonConverterFactory 核心实现（响应体转换）
public final class GsonConverterFactory extends Converter.Factory {
  @Override
  public Converter<ResponseBody, ?> responseBodyConverter(Type type, Annotation[] annotations, Retrofit retrofit) {
    // 创建 Gson 解析器，适配目标类型（如 User）
    TypeAdapter<?> adapter = gson.getAdapter(TypeToken.get(type));
    // 返回响应体转换器
    return new GsonResponseBodyConverter<>(gson, adapter);
  }

  // 请求体转换（Object → RequestBody）
  @Override
  public Converter<?, RequestBody> requestBodyConverter(Type type, Annotation[] parameterAnnotations, Annotation[] methodAnnotations, Retrofit retrofit) {
    TypeAdapter<?> adapter = gson.getAdapter(TypeToken.get(type));
    return new GsonRequestBodyConverter<>(gson, adapter);
  }
}

// Gson 响应体转换器实现
final class GsonResponseBodyConverter<T> implements Converter<ResponseBody, T> {
  private final Gson gson;
  private final TypeAdapter<T> adapter;

  @Override
  public T convert(ResponseBody value) throws IOException {
    try {
      // 将 ResponseBody 转为字符串，通过 Gson 解析为目标对象
      JsonReader jsonReader = gson.newJsonReader(value.charStream());
      return adapter.read(jsonReader);
    } finally {
      value.close(); // 必须关闭响应体流，避免内存泄漏
    }
  }
}
```

#### 关键解释：

1. `Converter.Factory` 分两类转换器：`requestBodyConverter`（请求体）和 `responseBodyConverter`（响应体）；
2. `GsonResponseBodyConverter` 核心逻辑：读取响应体的字符流，通过 Gson TypeAdapter 解析为目标对象；
3. 必须关闭 `ResponseBody`：`convert` 方法中通过 `finally` 关闭流，避免 OKHttp 连接池资源泄漏；
4. 扩展实现（如 ScalarsConverter）：可处理 String/Int 等基本类型，无需 Gson 解析。

### 2.5 请求执行：OkHttpCall 封装 OKHttp 执行逻辑

`OkHttpCall` 是 Retrofit 对 OKHttp `Call` 的封装，负责执行同步/异步请求，并通过 `Converter` 解析响应。

#### 核心源码（OkHttpCall.java）

```java
final class OkHttpCall<T> implements Call<T> {
  private final RequestFactory requestFactory;
  private final Object[] args;
  private final okhttp3.Call.Factory callFactory; // 实际是 OkHttpClient
  private final Converter<ResponseBody, T> responseConverter;

  private okhttp3.Call rawCall; // OKHttp 的真实 Call
  private boolean executed; // 标记是否已执行（OKHttp Call 不可重复执行）

  // 同步执行（阻塞线程）
  @Override
  public Response<T> execute() throws IOException {
    okhttp3.Call call;
    synchronized (this) {
      if (executed) throw new IllegalStateException("Already executed.");
      executed = true;
      // 创建 OKHttp Call
      call = rawCall = createRawCall();
    }
    // 执行 OKHttp 请求
    return parseResponse(call.execute());
  }

  // 异步执行（回调）
  @Override
  public void enqueue(final Callback<T> callback) {
    okhttp3.Call call;
    synchronized (this) {
      if (executed) throw new IllegalStateException("Already executed.");
      executed = true;
      call = rawCall = createRawCall();
    }
    // 调用 OKHttp 的异步执行
    call.enqueue(new okhttp3.Callback() {
      @Override
      public void onResponse(okhttp3.Call call, okhttp3.Response rawResponse) {
        Response<T> response;
        try {
          // 解析响应（通过 Converter 转成目标类型）
          response = parseResponse(rawResponse);
        } catch (Throwable e) {
          callback.onFailure(OkHttpCall.this, e);
          return;
        }
        callback.onResponse(OkHttpCall.this, response);
      }

      @Override
      public void onFailure(okhttp3.Call call, IOException e) {
        callback.onFailure(OkHttpCall.this, e);
      }
    });
  }

  // 创建 OKHttp Call
  private okhttp3.Call createRawCall() throws IOException {
    // 通过 RequestFactory 生成 OKHttp Request
    Request request = requestFactory.create(args);
    // 通过 OkHttpClient 创建 Call
    okhttp3.Call call = callFactory.newCall(request);
    if (call == null) {
      throw new NullPointerException("Call.Factory returned null.");
    }
    return call;
  }

  // 解析 OKHttp 响应为 Retrofit Response
  private Response<T> parseResponse(okhttp3.Response rawResponse) throws IOException {
    ResponseBody rawBody = rawResponse.body();
    // 构建 Retrofit Response 基础信息（状态码、响应头）
    Response.Builder<T> responseBuilder = Response.success(null, rawResponse);
    if (rawResponse.isSuccessful()) {
      // 成功响应：通过 Converter 解析响应体
      T body = responseConverter.convert(rawBody);
      responseBuilder.body(body);
    } else {
      // 失败响应：封装错误体
      responseBuilder.errorBody(rawBody);
      responseBuilder.code(rawResponse.code());
    }
    return responseBuilder.build();
  }

  // 克隆 Call（用于重试）
  @Override
  public Call<T> clone() {
    return new OkHttpCall<>(requestFactory, args, callFactory, responseConverter);
  }

  // 其他方法：cancel()/isCanceled()/isExecuted() 均委托给 OKHttp Call
}
```

#### 关键解释：

1. `createRawCall()`：核心是通过 `RequestFactory` 生成 OKHttp `Request`，再通过 `OkHttpClient` 创建可执行的 `okhttp3.Call`；
2. `execute()`/`enqueue()`：完全委托给 OKHttp 的同步/异步执行逻辑，仅在回调中增加响应解析；
3. `parseResponse()`：将 OKHttp 的 `Response` 转为 Retrofit 的 `Response`，成功时通过 `Converter` 解析响应体，失败时封装错误体；
4. `clone()`：创建新的 `OkHttpCall`（因为 OKHttp Call 执行后不可重复执行，重试需克隆）。

## 三、Retrofit 核心设计总结

1. **动态代理**：将接口方法调用转化为请求逻辑，无需手动实现接口；
2. **注解驱动**：通过注解声明请求规则，解析后生成 Request；
3. **插件化扩展**：CallAdapter（返回类型）、Converter（数据转换）支持自定义，适配不同场景（RxJava/协程/JSON/XML）；
4. **完全复用 OKHttp**：Retrofit 仅做「规则解析+类型适配」，底层网络请求、连接池、拦截器等均由 OKHttp 负责；
5. **缓存优化**：ServiceMethod 缓存避免重复解析注解，提升性能。
