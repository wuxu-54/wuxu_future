# Retrofit 全量 API、注解及详细用法

Retrofit 是 Square 出品的基于 OKHttp 的 RESTful 网络请求框架，核心通过**注解**定义请求规则，通过**核心 API** 构建请求实例并执行。以下是其所有核心注解、API 的详细分类、作用及示例。

## 一、前置依赖（基础环境）

使用 Retrofit 需引入核心库及配套转换器/适配器（按需选择）：

```gradle
// Retrofit 核心（必选）
implementation 'com.squareup.retrofit2:retrofit:2.9.0'
// Gson 序列化/反序列化（最常用）
implementation 'com.squareup.retrofit2:converter-gson:2.9.0'
// RxJava3 适配器（适配 Observable/Flowable）
implementation 'com.squareup.retrofit2:adapter-rxjava3:2.9.0'
// Kotlin 协程适配器（适配 suspend 函数）
implementation 'com.squareup.retrofit2:adapter-coroutines:2.9.0'
// 字符串/基本类型转换器（适配 String/Int 响应）
implementation 'com.squareup.retrofit2:converter-scalars:2.9.0'
```

## 二、核心注解（全量分类）

Retrofit 注解分为**请求方法注解**、**参数注解**、**配置/标记注解**三类，覆盖 HTTP 请求的所有核心场景。

### 1. 请求方法注解（定义 HTTP 方式）

标注接口方法，指定 HTTP 请求类型，必须配合相对 URL 使用。

| 注解       | 作用                     | 核心参数       | 示例                                                                 |
|------------|--------------------------|----------------|----------------------------------------------------------------------|
| @GET       | GET 请求                 | 无             | `@GET("users/{id}") Call<User> getUser(@Path("id") int id);`         |
| @POST      | POST 请求                | 无             | `@POST("users") Call<User> createUser(@Body User user);`             |
| @PUT       | PUT 请求（全量更新）| 无             | `@PUT("users/{id}") Call<User> updateUser(@Path("id") int id, @Body User user);` |
| @DELETE    | DELETE 请求              | 无             | `@DELETE("users/{id}") Call<Void> deleteUser(@Path("id") int id);`   |
| @PATCH     | PATCH 请求（部分更新）| 无             | `@PATCH("users/{id}") Call<User> patchUser(@Path("id") int id, @Body Map<String, Object> update);` |
| @HEAD      | HEAD 请求（仅返回响应头） | 无             | `@HEAD("users") Call<Void> checkUserExist();`                        |
| @OPTIONS   | OPTIONS 请求（获取允许的方法） | 无         | `@OPTIONS("users") Call<Response<Void>> getUsersOptions();`          |
| @HTTP      | 自定义 HTTP 请求（万能） | method（请求方法）、path（URL）、hasBody（是否有请求体） | `@HTTP(method = "DELETE", path = "users/{id}", hasBody = false) Call<Void> deleteUser(@Path("id") int id);` |

**关键说明**：

- @HTTP 是“万能注解”，可替代所有内置请求方法（如自定义非标准 HTTP 方法）；
- HEAD/OPTIONS 请求的返回体建议用 `Void`，仅关注响应头。

### 2. 参数注解（绑定请求参数）

标注接口方法参数，将参数映射到 HTTP 请求的 URL、请求体、请求头等位置。

| 注解                 | 作用                                                                 | 核心参数                | 示例                                                                 |
|----------------------|----------------------------------------------------------------------|-------------------------|----------------------------------------------------------------------|
| @Path                | 替换 URL 中的路径占位符（{xxx}）| value（占位符名称）、encoded（是否跳过编码，默认 false） | `@GET("files/{path}") Call<File> getFile(@Path(value = "path", encoded = true) String path);` |
| @Query               | 添加 URL 查询参数（?key=value）| value（参数名）、encoded（是否跳过编码） | `@GET("users") Call<List<User>> getUsers(@Query("page") int page);`  |
| @QueryMap            | 批量添加 URL 查询参数                                               | encoded（是否跳过编码） | `@GET("users") Call<List<User>> getUsers(@QueryMap Map<String, Object> params);` |
| @Body                | 作为请求体（JSON/XML 等，需转换器支持）| 无                      | `@POST("users") Call<User> createUser(@Body User user);`             |
| @Field               | 表单字段（需配合 @FormUrlEncoded）| value（字段名）| `@FormUrlEncoded @POST("login") Call<Token> login(@Field("username") String username);` |
| @FieldMap            | 批量表单字段（需配合 @FormUrlEncoded）| 无                      | `@FormUrlEncoded @POST("register") Call<User> register(@FieldMap Map<String, String> fields);` |
| @Part                | 多部分表单部件（文件/表单，需配合 @Multipart）| value（部件名）| `@Multipart @POST("upload") Call<UploadResult> upload(@Part MultipartBody.Part file);` |
| @PartMap             | 批量多部分表单部件（需配合 @Multipart）| 无                      | `@Multipart @POST("upload") Call<UploadResult> upload(@PartMap Map<String, RequestBody> parts);` |
| @Header              | 动态添加单个请求头                                                   | value（头名称）| `@GET("users") Call<List<User>> getUsers(@Header("Authorization") String token);` |
| @HeaderMap           | 批量添加动态请求头                                                   | 无                      | `@GET("users") Call<List<User>> getUsers(@HeaderMap Map<String, String> headers);` |
| @Headers             | 静态添加请求头（编译期固定）| 字符串数组              | `@Headers({"Authorization: Bearer 123", "Content-Type: application/json"}) @GET("users") Call<List<User>> getUsers();` |
| @Url                 | 替换整个请求 URL（覆盖注解中的 URL）| 无                      | `@GET Call<User> getUserByUrl(@Url String url);`                     |

**关键说明**：

- @Body 不能与 @FormUrlEncoded/@Multipart 同时使用（请求体格式冲突）；
- @Headers 是静态的（编译后不可变），@Header/@HeaderMap 是动态的（运行期传值），动态优先级更高；
- @Part 上传文件时，需通过 `MultipartBody.Part` 构建文件部件。

### 3. 配置/标记注解（修改请求行为）

标注接口方法，修改请求的处理逻辑（如表单格式、流式响应、线程回调）。

| 注解                 | 作用                                                                 | 示例                                                                 |
|----------------------|----------------------------------------------------------------------|----------------------------------------------------------------------|
| @FormUrlEncoded      | 标记请求为 `application/x-www-form-urlencoded` 格式（配合 @Field/@FieldMap） | 见 @Field 示例                                                       |
| @Multipart           | 标记请求为 `multipart/form-data` 格式（配合 @Part/@PartMap，用于文件上传） | 见 @Part 示例                                                        |
| @Streaming           | 流式处理响应体（避免大文件加载到内存，用于下载）| `@Streaming @GET("files/large.zip") Call<ResponseBody> downloadFile();` |
| @SkipCallbackExecutor | 跳过 Retrofit 默认的回调线程池（回调在 OKHttp 后台线程）| `@SkipCallbackExecutor @GET("users") Call<List<User>> getUsers();`   |
| @IgnoreExtraArgs     | 忽略接口方法中未标注的参数（避免编译报错）| `@IgnoreExtraArgs @GET("users") Call<List<User>> getUsers(int unused);` |

**关键说明**：

- @Streaming 必须配合 `ResponseBody` 接收响应体，且需手动关闭流（避免内存泄漏）；
- Android 中默认回调线程是主线程，@SkipCallbackExecutor 会让回调落在 OKHttp 的后台线程。

## 三、核心 API（全量解析）

Retrofit 的核心 API 围绕 `Retrofit` 构建器、`Call` 执行器、`Response` 响应封装展开，是请求执行的核心载体。

### 1. Retrofit 类（核心构建器）

用于创建 Retrofit 实例，配置基础 URL、转换器、适配器、OKHttp 客户端等，是所有请求的入口。

#### 核心方法

| 方法                          | 作用                                                                 |
|-------------------------------|----------------------------------------------------------------------|
| Retrofit.Builder()            | 创建构建器（必用）|
| baseUrl(String/HttpUrl)       | 设置基础 URL（必须以 `/` 结尾，或接口 URL 以 `/` 开头）|
| client(OkHttpClient)          | 自定义 OKHttp 客户端（配置超时、拦截器、Cookie 等）|
| addConverterFactory(Converter.Factory) | 添加序列化/反序列化工厂（如 GsonConverterFactory）|
| addCallAdapterFactory(CallAdapter.Factory) | 添加 Call 适配器工厂（如 RxJava3CallAdapterFactory）|
| callbackExecutor(Executor)    | 自定义回调线程池（Android 默认主线程执行器）|
| build()                       | 构建 Retrofit 实例                                                     |
| create(Class<T> service)      | 生成接口代理类（核心，通过动态代理实现请求逻辑）|

#### 示例（完整构建）

```java
// 1. 配置 OKHttp 客户端（可选，自定义超时/拦截器）
OkHttpClient okHttpClient = new OkHttpClient.Builder()
        .connectTimeout(10, TimeUnit.SECONDS)
        .readTimeout(10, TimeUnit.SECONDS)
        .writeTimeout(10, TimeUnit.SECONDS)
        .addInterceptor(chain -> { // 全局添加 Token 拦截器
            Request original = chain.request();
            Request newRequest = original.newBuilder()
                    .header("Authorization", "Bearer " + getToken())
                    .build();
            return chain.proceed(newRequest);
        })
        .build();

// 2. 构建 Retrofit 实例
Retrofit retrofit = new Retrofit.Builder()
        .baseUrl("https://api.example.com/") // 基础 URL 以 / 结尾
        .client(okHttpClient)
        .addConverterFactory(GsonConverterFactory.create()) // Gson 序列化
        .addCallAdapterFactory(RxJava3CallAdapterFactory.create()) // 支持 RxJava3
        .build();

// 3. 生成接口代理类
UserService service = retrofit.create(UserService.class);
```

### 2. Call<T> 接口（请求执行器）

Retrofit 默认的请求返回类型，封装了请求的同步/异步执行、取消、克隆等能力。

#### 核心方法

| 方法                          | 作用                                                                 |
|-------------------------------|----------------------------------------------------------------------|
| execute()                     | 同步执行请求（阻塞线程，Android 主线程禁止调用）|
| enqueue(Callback<T>)          | 异步执行请求（回调在指定线程，Android 默认主线程）|
| cancel()                      | 取消请求（如页面销毁时调用）|
| isCanceled()                  | 判断请求是否已取消                                                   |
| isExecuted()                  | 判断请求是否已执行（执行后不可重复执行）|
| clone()                       | 克隆 Call 实例（用于重试请求）|
| request()                     | 获取底层 OKHttp 的 Request 对象（查看 URL、请求头、请求体）|

#### 示例（异步执行）

```java
Call<User> call = service.getUser(1);
call.enqueue(new Callback<User>() {
    @Override
    public void onResponse(Call<User> call, Response<User> response) {
        if (response.isSuccessful()) { // 状态码 200-299
            User user = response.body(); // 成功响应体
        } else {
            // 非成功响应，获取错误体（string() 仅能调用一次）
            String errorMsg = response.errorBody().string();
            int code = response.code(); // 响应状态码
        }
    }

    @Override
    public void onFailure(Call<User> call, Throwable t) {
        // 网络错误、超时、解析失败等
        t.printStackTrace();
    }
});

// 取消请求（如 Activity 销毁）
if (!call.isCanceled()) {
    call.cancel();
}
```

### 3. Response<T> 类（响应封装）

封装 HTTP 响应的所有信息，包括状态码、响应头、响应体、错误体等。

#### 核心方法/属性

| 方法/属性                     | 作用                                                                 |
|-------------------------------|----------------------------------------------------------------------|
| code()                        | 获取响应状态码（200、404、500 等）|
| message()                     | 获取状态码对应的消息（OK、Not Found 等）|
| isSuccessful()                | 判断响应是否成功（状态码 200-299）|
| body()                        | 获取成功响应体（T 类型，成功时非 null）|
| errorBody()                   | 获取错误响应体（ResponseBody 类型，失败时非 null）|
| headers()                     | 获取所有响应头（Headers 对象）|
| header(String name)           | 获取指定名称的响应头（第一个值）|
| raw()                         | 获取底层 OKHttp 的 Response 对象（原生能力）|

### 4. 其他核心 API

#### （1）Converter & Converter.Factory

用于将 Java/Kotlin 对象与 HTTP 报文互转（序列化/反序列化），常用实现：

- `GsonConverterFactory`：Gson 解析 JSON；
- `MoshiConverterFactory`：Moshi 解析 JSON（更轻量）；
- `SimpleXmlConverterFactory`：解析 XML；
- `ScalarsConverterFactory`：解析 String/Int 等基本类型。

#### （2）CallAdapter & CallAdapter.Factory

用于将默认的 `Call<T>` 适配为其他类型，常用实现：

- `RxJava3CallAdapterFactory`：适配 RxJava3 的 Observable/Flowable；
- `CoroutineCallAdapterFactory`：适配 Kotlin 协程的 suspend 函数；
- `Java8CallAdapterFactory`：适配 CompletableFuture。

#### （3）HttpUrl

用于构建/解析 URL，配合 @Url 注解实现动态 URL：

```java
// 构建动态 URL
HttpUrl url = HttpUrl.parse("https://api.example.com/")
        .newBuilder()
        .addPathSegment("users")
        .addQueryParameter("page", "1")
        .build();

// 调用接口
Call<List<User>> call = service.getUsersByUrl(url.toString());
```

## 四、典型场景实战示例

### 1. 文件上传（Multipart 格式）

```java
// 接口定义
@Multipart
@POST("upload/file")
Call<UploadResult> uploadFile(
        @Part MultipartBody.Part file, // 文件部件
        @Part("desc") RequestBody desc // 描述字段
);

// 调用逻辑
File file = new File("/sdcard/avatar.jpg");
// 构建文件请求体
RequestBody fileBody = RequestBody.create(file, MediaType.parse("image/jpeg"));
// 构建文件部件（指定文件名）
MultipartBody.Part filePart = MultipartBody.Part.createFormData(
        "file", // 接口约定的字段名
        file.getName(), 
        fileBody
);
// 构建描述字段
RequestBody descBody = RequestBody.create("用户头像", MediaType.parse("text/plain"));

// 执行上传
Call<UploadResult> call = service.uploadFile(filePart, descBody);
```

### 2. 大文件下载（Streaming 流式）

```java
// 接口定义
@Streaming
@GET("download/large.zip")
Call<ResponseBody> downloadLargeFile();

// 调用逻辑
Call<ResponseBody> call = service.downloadLargeFile();
call.enqueue(new Callback<ResponseBody>() {
    @Override
    public void onResponse(Call<ResponseBody> call, Response<ResponseBody> response) {
        if (response.isSuccessful()) {
            // 将响应流写入本地文件
            writeToFile(response.body(), new File("/sdcard/large.zip"));
        }
    }

    @Override
    public void onFailure(Call<ResponseBody> call, Throwable t) {}
});

// 流写入文件工具方法
private boolean writeToFile(ResponseBody body, File targetFile) {
    try (InputStream in = body.byteStream();
         FileOutputStream out = new FileOutputStream(targetFile)) {
        byte[] buffer = new byte[4096];
        int len;
        while ((len = in.read(buffer)) != -1) {
            out.write(buffer, 0, len);
        }
        out.flush();
        return true;
    } catch (IOException e) {
        e.printStackTrace();
        return false;
    }
}
```

### 3. Kotlin 协程适配（suspend 函数）

```kotlin
// 接口定义（suspend 关键字）
interface UserService {
    @GET("users/{id}")
    suspend fun getUser(@Path("id") id: Int): User
}

// 调用逻辑（协程作用域）
lifecycleScope.launch(Dispatchers.IO) {
    try {
        val user = service.getUser(1)
        // 主线程更新 UI
        withContext(Dispatchers.Main) {
            tvName.text = user.name
        }
    } catch (e: Exception) {
        // 处理异常（网络错误、解析失败等）
        e.printStackTrace()
    }
}
```

## 五、核心注意事项

1. URL 拼接规则：baseUrl 必须以 `/` 结尾，或接口注解的 URL 以 `/` 开头（否则会拼接错误）；
2. 线程安全：`execute()` 是同步阻塞方法，Android 主线程禁止调用；`enqueue()` 回调默认在主线程；
3. 响应体释放：`ResponseBody`（包括 errorBody）的 `string()` 方法仅能调用一次，调用后流会关闭；
4. 重复执行：Call 实例执行后（execute/enqueue）不可重复执行，需调用 `clone()` 克隆后重试；
5. 空安全：`response.body()` 可能为 null（即使 isSuccessful() 为 true），需判空。
