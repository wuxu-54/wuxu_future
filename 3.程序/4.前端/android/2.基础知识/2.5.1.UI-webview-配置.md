# Android WebView完整配置 + JS<->Native通信 + 手势冲突处理

## 一、WebView基础配置（Kotlin，Java同理）

### 1. xml布局

```
<WebView
    android:id="@+id/webview"
    android:layout_width="match_parent"
    android:layout_height="match_parent"/>
```

### 2. Activity初始化配置

```
val webView = findViewById<WebView>(R.id.webview)
val settings = webView.settings

// 基础设置
settings.javaScriptEnabled = true // 开启JS，通信必须打开
settings.domStorageEnabled = true
settings.databaseEnabled = true
settings.allowFileAccess = true
settings.loadsImagesAutomatically = true
settings.defaultTextEncodingName = "UTF-8"
settings.useWideViewPort = true
settings.loadWithOverviewMode = true

// 缩放
settings.builtInZoomControls = false
settings.displayZoomControls = false

// 缓存策略
settings.cacheMode = WebSettings.LOAD_DEFAULT

// WebView客户端，拦截url、页面加载
webView.webViewClient = object : WebViewClient() {
    override fun shouldOverrideUrlLoading(view: WebView?, request: WebResourceRequest?): Boolean {
        // 拦截url，可以做URL Scheme通信
        return super.shouldOverrideUrlLoading(view, request)
    }
}
webView.webChromeClient = WebChromeClient() // 支持alert、console、进度

// 加载页面
webView.loadUrl("https://xxx/index.html")
```

>
> 权限：`AndroidManifest.xml`添加网络权限

```
<uses-permission android:name="android.permission.INTERNET"/>
```

## 二、H5与Native数据通信（4种方案，推荐优先级从上到下）

### ✅方案1：addWebMessageListener（Google官方推荐，API30+，安全）

>
> 安全：**限制允许的域名**，不像addJavascriptInterface有注入风险；支持双向异步postMessage

```
// 注册（必须loadUrl之前注册）
WebViewCompat.addWebMessageListener(
    webView,
    "nativeBridge", // JS全局对象 window.nativeBridge
    setOf("[https://your-trusted-domain.com](https://your-trusted-domain.com)"), // 白名单域名
    WebViewCompat.WebMessageListener { webView, message, sourceOrigin, isMainFrame, replyProxy ->
        // 接收JS发来的数据
        val data = message.data
        Log.d("JS_MSG", "收到H5消息：$data")
        // 回复JS
        replyProxy.postMessage("原生收到了，返回结果")
    }
)
```

**H5 JS代码**

```
// 发消息给原生
window.nativeBridge.postMessage({type:"test", data:"h5数据"})
// 监听原生返回
window.nativeBridge.onmessage = function(e){
    console.log("native返回：",e.data)
}
```

### ✅方案2：addJavascriptInterface（传统方案，兼容低版本，⚠️安全风险）

>
> 注意：暴露的方法必须加注解 `@JavascriptInterface`，否则4.4+不会被JS调用；**不可信网页严禁使用**

```
class JsBridgeInterface(private val ctx:Context){
    @JavascriptInterface
    fun callNative(json:String):String{
        // JS调用原生方法
        return "原生返回数据"
    }
}
// 注入
webView.addJavascriptInterface(JsBridgeInterface(this), "androidObj")
```

H5调用：

```
let res = window.androidObj.callNative("h5传给原生的数据")
```

原生调用JS：

```
// evaluateJavascript 异步调用JS函数（推荐，不会阻塞）
webView.evaluateJavascript("javascript:h5Func('原生调用h5')"){ result ->
    // result是js返回值
}
// 旧方式（不推荐）webView.loadUrl("javascript:h5Func()")
```

### ✅方案3：URL Scheme拦截（JSBridge经典，兼容性最好，无版本限制）

原理：H5创建iframe跳转自定义协议 `jsbridge://method?params=xxx`，`shouldOverrideUrlLoading`拦截url，解析参数执行原生逻辑。
适合老项目、跨端JSBridge库，缺点：传大数据不方便。

```
override fun shouldOverrideUrlLoading(view: WebView?, request: WebResourceRequest?): Boolean {
    val url = request.url.toString()
    if(url.startsWith("jsbridge://")){
        // 解析url，拿到方法、参数，执行原生逻辑
        return true //消费掉，不真正跳转
    }
    return super.shouldOverrideUrlLoading(view, request)
}
```

### ✅方案4：queryString / header传参（页面初始化一次性传参）

原生loadUrl拼接url参数，或者`WebResourceRequest`添加自定义请求头，页面加载时H5读取，适合页面初始化一次性传递数据，**不适合双向实时通信**。

>
> 通信选型总结
>
>
> 1. 新项目minSdk>=30：**addWebMessageListener**（官方推荐，安全双向）
> 2. 需要兼容低版本：addJavascriptInterface（只用于可信域名）
> 3. 通用JSBridge框架、老项目：URL Scheme

## 三、手势问题解决（WebView手势冲突，高频问题）

### 常见手势问题：

1. WebView放在ScrollView/NestedScrollView/SwipeRefreshLayout里面，**上下滑动冲突**
2. 横向H5滑动（轮播、横向列表）被父View抢占触摸事件
3. 长按复制菜单、长按图片保存
4. 系统侧边返回手势与H5侧滑冲突
5. WebView内部点击失效、触摸无响应

### 核心原理：Android Touch事件分发 `dispatchTouchEvent -> onInterceptTouchEvent -> onTouchEvent`

父View的`onInterceptTouchEvent`一旦返回true，会拦截触摸事件，WebView收不到touch。

#### 方案1：动态禁止父View拦截（最常用）

给WebView设置onTouchListener，**滑动时通知父控件不要拦截**

```
webView.setOnTouchListener { v, event ->
    when(event.action){
        MotionEvent.ACTION_DOWN -> {
            // 按下：请求父不要拦截
            v.parent.requestDisallowInterceptTouchEvent(true)
        }
        MotionEvent.ACTION_UP, MotionEvent.ACTION_CANCEL -> {
            // 抬起：恢复父拦截
            v.parent.requestDisallowInterceptTouchEvent(false)
        }
    }
    false // 必须返回false，把事件继续交给WebView本身处理！返回true会直接消费事件，webview点击失效
}
```

#### 方案2：父View根据滑动方向选择性拦截（精确控制，NestedScrollView）

自定义父容器，在`onInterceptTouchEvent`判断滑动方向：

- **竖直滑动交给父ScrollView**
- **水平滑动交给WebView**

```
// 在父View中
override fun onInterceptTouchEvent(ev: MotionEvent): Boolean {
    when(ev.action){
        MotionEvent.ACTION_DOWN->{
            lastX = ev.x
            lastY = ev.y
        }
        MotionEvent.ACTION_MOVE->{
            val dx = ev.x - lastX
            val dy = ev.y - lastY
            if(Math.abs(dx) > Math.abs(dy)){
                // 横向滑动，不拦截，交给webview
                return false
            }else{
                // 垂直滑动，父控件拦截
                return true
            }
        }
    }
    return super.onInterceptTouchEvent(ev)
}
```

#### 方案3：禁止长按弹出复制菜单

```
webView.setOnLongClickListener {
    true //消费长按事件，阻止系统弹出复制菜单
}
```

#### 方案4：系统返回手势冲突（Android10+侧边滑动返回，挡住H5侧滑菜单）

使用`setSystemGestureExclusionRects`，标记WebView左右边缘区域，告诉系统**这块区域不触发系统返回手势**

```
val excludeRects = mutableListOf<Rect>()
excludeRects.add(Rect(0,0,200, webView.height)) //左侧200px不触发返回
ViewCompat.setSystemGestureExclusionRects(webView, excludeRects)
```

#### 方案5：SwipeRefreshLayout + WebView下拉刷新冲突

在WebView滚动到**顶部**才允许SwipeRefresh下拉，否则禁止刷新：

```
webView.setOnScrollChangeListener { _, _, scrollY, _, _ ->
    swipeRefreshLayout.isEnabled = scrollY == 0
}
```

## 四、踩坑重点

1. `addJavascriptInterface`**必须加@JavascriptInterface注解**，否则JS无法调用
2. `evaluateJavascript`是异步，有回调；loadUrl("javascript:xxx")无返回，不推荐
3. onTouchListener返回**true会吃掉触摸事件，WebView点击/滑动失效**，一般返回false
4. WebView内存泄漏：页面销毁`onDestroy`时，先`webView.stopLoading()`、`webView.removeAllViews()`、`webView.destroy()`，不要直接销毁
5. 通信尽量传递JSON字符串，复杂对象转JSON传输

## 五、简单架构建议

混合开发推荐封装JSBridge，底层优先用`addWebMessageListener`，低版本降级addJavascriptInterface，URLScheme做兜底；手势统一封装自定义WebView，内置touch冲突处理逻辑，减少重复代码。
