# 路由插件

## 1. 选型

java+kotlin混合项目，所以采用 `kapt`注解处理+`kotlinpoet`生成kotlin代码

## 2. 制作组件

必须要单独创建组件（不是插件，是独立组件库，以kapt 等方式引入，仅编译时生效），进行项目注解处理，每个组件模块需要引入才能实现注解自动注册路由逻辑。

1. 插件gradle配置（依赖库版本需要适配项目，可以直接问AI选择合适的版本或找官网资料来确定）

```kotlin
plugins {
    id 'java-library'
    id 'org.jetbrains.kotlin.jvm'
    id 'kotlin-kapt'
}

java {
    sourceCompatibility = JavaVersion.VERSION_1_8
    targetCompatibility = JavaVersion.VERSION_1_8
}

dependencies {
    // Kotlin 标准库
    implementation "org.jetbrains.kotlin:kotlin-stdlib:1.6.21"
    
    // 注解处理器 API
    implementation 'com.google.auto.service:auto-service:1.0.1'
    kapt 'com.google.auto.service:auto-service:1.0.1'
    
    // KotlinPoet 用于生成 Kotlin 代码（使用与 Kotlin 1.6 兼容的版本）
    implementation 'com.squareup:kotlinpoet:1.12.0'
    
    // 显式声明对 Kotlin 编译器的依赖，确保注解处理器能正确处理 Kotlin 代码
    implementation "org.jetbrains.kotlin:kotlin-compiler-embeddable:1.6.21"
}
```

2. 代码开发:按kapt语法、kotlinpoet语法进行开发配置（说明：AutoService会自动生成`META-INF文件`,这是编译时扫描执行此注解处理器的关键）

```kotlin

import com.google.auto.service.AutoService
import com.squareup.kotlinpoet.*
import javax.annotation.processing.*
import javax.lang.model.SourceVersion
import javax.lang.model.element.Element
import javax.lang.model.element.Modifier
import javax.lang.model.element.TypeElement
import javax.lang.model.type.TypeKind
import javax.lang.model.type.TypeMirror
import javax.tools.Diagnostic

@AutoService(Processor::class)
@SupportedSourceVersion(SourceVersion.RELEASE_8)
@SupportedAnnotationTypes("com.wuxu.main.basic.router.annotation.RoutePage")
class RouteProcessor : AbstractProcessor() {

    private companion object {
        const val ANNOTATION_NAME = "com.wuxu.main.basic.router.annotation.RoutePage"
        const val GENERATED_PACKAGE = "com.wuxu.main.basic.router.generated"
        const val GENERATED_CLASS_NAME = "RouteRegistryGenerator"
        const val ACTIVITY_CLASS_NAME = "android.app.Activity"
    }
    
    private var activityTypeMirror: TypeMirror? = null

    override fun process(annotations: MutableSet<out TypeElement>, roundEnv: RoundEnvironment): Boolean {
        try {
            // 初始化 Activity 类型引用
            if (activityTypeMirror == null) {
                activityTypeMirror = processingEnv.elementUtils.getTypeElement(ACTIVITY_CLASS_NAME)?.asType()
                if (activityTypeMirror == null) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.ERROR,
                        "Cannot find android.app.Activity class"
                    )
                    return false
                }
            }
            
            val routePages = mutableMapOf<String, String>()

            // 收集所有带 @RoutePage 注解的类
            val routePageAnnotation = processingEnv.elementUtils.getTypeElement(ANNOTATION_NAME)
            if (routePageAnnotation == null) {
                processingEnv.messager.printMessage(
                    Diagnostic.Kind.ERROR,
                    "Cannot find RoutePage annotation class"
                )
                return false
            }
            
            for (element in roundEnv.getElementsAnnotatedWith(routePageAnnotation)) {
                if (element !is TypeElement) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.WARNING,
                        "@RoutePage can only be applied to classes, skipping: ${element.simpleName}"
                    )
                    continue
                }
                
                // 验证1: 检查是否为 public 类
                if (!element.modifiers.contains(Modifier.PUBLIC)) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.ERROR,
                        "@RoutePage annotated class must be public: ${element.qualifiedName}"
                    )
                    return false
                }
                
                // 验证2: 检查是否为顶层类或静态内部类（非内部类）
                if (element.enclosingElement is TypeElement && 
                    !element.modifiers.contains(Modifier.STATIC)) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.ERROR,
                        "@RoutePage cannot be applied to non-static inner classes: ${element.qualifiedName}. " +
                        "Use top-level class or static nested class instead."
                    )
                    return false
                }
                
                // 验证3: 检查是否包含泛型参数
                if (element.typeParameters.isNotEmpty()) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.ERROR,
                        "@RoutePage cannot be applied to generic classes: ${element.qualifiedName}. " +
                        "Activity classes should not have type parameters."
                    )
                    return false
                }
                
                // 验证4: 检查是否继承自 Activity
                if (!processingEnv.typeUtils.isSubtype(element.asType(), activityTypeMirror!!)) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.ERROR,
                        "@RoutePage annotated class must extend android.app.Activity: ${element.qualifiedName}"
                    )
                    return false
                }
                
                // 验证5: 检查类是否可实例化（非 abstract、非接口）
                if (element.modifiers.contains(Modifier.ABSTRACT)) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.ERROR,
                        "@RoutePage cannot be applied to abstract classes: ${element.qualifiedName}. " +
                        "Activity must be instantiable."
                    )
                    return false
                }
                
                // 通过反射获取注解值（避免直接依赖注解类）
                val annotationMirror = element.annotationMirrors.find { 
                    it.annotationType.asElement().toString() == ANNOTATION_NAME 
                }
                
                if (annotationMirror == null) {
                    continue
                }
                
                var index = ""
                var category = ""
                
                annotationMirror.elementValues.forEach { (executableElement, value) ->
                    when (executableElement.simpleName.toString()) {
                        "index" -> index = value.value.toString()
                        "category" -> category = value.value.toString()
                    }
                }
                val qualifiedName = element.qualifiedName.toString()
                
                // 验证6: 检查 index 格式，建议包含模块前缀以实现命名空间隔离
                if (index.isBlank()) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.ERROR,
                        "Route index cannot be empty: ${element.qualifiedName}"
                    )
                    return false
                }
                
                // 警告：如果 index 不包含 '/' 分隔符，可能缺少命名空间
                if (!index.contains('/')) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.WARNING,
                        "Route index '$index' does not contain namespace separator '/'. " +
                        "Recommended format: 'module/ClassName' to avoid conflicts: ${element.qualifiedName}"
                    )
                }
                
                if (routePages.containsKey(index)) {
                    processingEnv.messager.printMessage(
                        Diagnostic.Kind.ERROR,
                        "Duplicate route index: '$index' already registered for ${routePages[index]}, " +
                        "conflict with: ${element.qualifiedName}"
                    )
                    return false
                }
                
                routePages[index] = qualifiedName
            }

            // 生成路由注册代码
            if (routePages.isNotEmpty()) {
                generateRouteRegistry(routePages)
            }

            return true
        } catch (e: Exception) {
            processingEnv.messager.printMessage(
                Diagnostic.Kind.ERROR,
                "Error processing annotations: ${e.message}\n${e.stackTraceToString()}"
            )
            return false
        }
    }

    private fun generateRouteRegistry(routePages: Map<String, String>) {
        val fileSpec = FileSpec.builder(GENERATED_PACKAGE, GENERATED_CLASS_NAME)
            .addType(
                TypeSpec.objectBuilder(GENERATED_CLASS_NAME)
                    .addFunction(
                        FunSpec.builder("registerRoutes")
                            .addParameter("navigator", ClassName("com.wuxu.main.basic.router.config", "PageNavigator"))
                            .addComment("自动生成的路由注册代码，请勿手动修改")
                            .apply {
                                routePages.forEach { (index, className) ->
                                    // 使用完整的包名，避免类加载冲突
                                    addStatement(
                                        "navigator.registerPageDestination(%S, %T::class.java)",
                                        index,
                                        ClassName.bestGuess(className)
                                    )
                                }
                            }
                            .build()
                    )
                    .build()
            )
            .build()

        try {
            fileSpec.writeTo(processingEnv.filer)
            processingEnv.messager.printMessage(
                Diagnostic.Kind.NOTE,
                "Generated route registry with ${routePages.size} routes"
            )
        } catch (e: Exception) {
            processingEnv.messager.printMessage(
                Diagnostic.Kind.ERROR,
                "Failed to write generated file: ${e.message}"
            )
        }
    }
}
```

### 2.1 为什么不合并到普通组件中？

1. APK体积暴增: `kotlin-compiler-embeddable` 约 50MB 会被打包进 APK,实际只在编译期使用，运行时完全不需要
2. 编译性能下降: 每次编译都要加载完整的 Kotlin 编译器,即使不生成路由代码也会增加编译时间
3. 依赖冲突风险高:`kotlin-compiler-embeddable:1.6.21` 可能与项目其他 Kotlin 插件版本冲突,难以排查和解决
4. 违反架构原则:注解处理器 = 编译时工具,普通组件 = 运行时业务模块. 职责混淆，不符合单一职责原则
5. 行业标准做法:`ARouter、Dagger、Room` 等主流框架都采用独立模块,经过大量项目验证的最佳实践
6. Gradle 已优化:独立的 `annotation processor` 模块自动不会打包到 APK,无需额外配置，零运行时开销

### 2.2. 多组件怎么自动注册避免冲突?

利用`SPI`机制，设定注册接口，通过ServiceLoader机制进行不同模块的实现类的调用，从而完成统一的注册处理。

SPI机制要求在`META-INF`设定配置文件，文件内容是接口的所有实现类全限定名,在APK/aar中会包括此文件。 那多个模块SPI文件怎么管理整合呢？答：不需要关注，Android 会自动合并文件内容，最终的APK是包括完整的内容。

例如：

```md
SPI机制的工作原理：
每个模块独立生成自己的SPI文件
message模块生成：包含MessageRouteRegistrar
device模块生成：包含DeviceRouteRegistrar
scene模块生成：包含SceneRouteRegistrar
Gradle打包时自动合并
Gradle会将所有模块的META-INF/services/文件内容合并
最终APK中的SPI文件包含所有注册器
ServiceLoader运行时加载所有
```

## 3.使用组件

`kapt` 方式引入组件（仅编译时生效，不会打入正式包）

```kotlin
// build.gradle中直接引入
kapt project(':router-compiler') // 本地方式，也可以上传maven
```
