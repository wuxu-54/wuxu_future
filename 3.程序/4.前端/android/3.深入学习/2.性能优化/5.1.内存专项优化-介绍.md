# Android内存专项优化

## 1. 内存问题类型

### 1.1 内存泄漏（Memory Leak）

- **定义**：对象已经不再被使用，但由于被其他对象持有引用而无法被垃圾回收器回收
- **常见场景**：
  - 静态变量持有Activity/Context引用
  - 匿名内部类持有外部类引用（如Handler、Runnable）
  - 单例模式中持有Context引用
  - 未注销的广播接收器、监听器
  - WebView未正确销毁

### 1.2 内存抖动（Memory Churn）

- **定义**：短时间内频繁创建和销毁大量对象，导致GC频繁触发
- **影响**：增加CPU负担，可能导致UI卡顿

### 1.3 内存溢出（OOM - Out Of Memory）

- **定义**：应用使用的内存超过系统分配的内存限制
- **常见原因**：
  - 加载大图片未进行压缩
  - 缓存策略不当
  - 内存泄漏累积

## 2. 内存检测工具

### 2.1 Android Studio Profiler

- **Memory Profiler功能**：
  - 实时监控内存使用情况
  - 强制GC操作
  - 捕获堆转储（Heap Dump）
  - 查看内存分配记录

### 2.2 MAT（Memory Analyzer Tool）

- **主要功能**：
  - 分析Heap Dump文件
  - 查找内存泄漏路径
  - 统计对象实例数量和内存占用

### 2.3 LeakCanary

- **集成方式**：

  ```gradle
  debugImplementation 'com.squareup.leakcanary:leakcanary-android:2.12'
  ```

- **优势**：自动检测内存泄漏并生成报告

## 3. 内存优化策略

### 3.1 对象复用

- 使用对象池（Object Pool）减少对象创建
- 复用Bitmap对象
- RecyclerView ViewHolder复用机制

### 3.2 资源管理

- 及时释放资源（关闭流、数据库连接等）
- 使用WeakReference/SoftReference处理非必需对象
- Context使用Application Context替代Activity Context

### 3.3 图片优化

- 使用合适的图片格式（WebP优于PNG/JPEG）
- 按需加载适当尺寸的图片
- 使用图片缓存库（Glide、Picasso）

### 3.4 集合优化

- 初始化集合时指定合理容量
- 避免在循环中创建集合
- 使用ArrayMap/SparseArray替代HashMap（小数据量场景）

## 4. 常见内存泄漏解决方案

### 4.1 Handler内存泄漏

```java
// 错误写法
private Handler mHandler = new Handler() {
    @Override
    public void handleMessage(Message msg) {
        // 处理消息
    }
};

// 正确写法 - 静态内部类 + WeakReference
private static class MyHandler extends Handler {
    private final WeakReference<MainActivity> mActivityRef;
    
    public MyHandler(MainActivity activity) {
        mActivityRef = new WeakReference<>(activity);
    }
    
    @Override
    public void handleMessage(Message msg) {
        MainActivity activity = mActivityRef.get();
        if (activity != null) {
            // 处理消息
        }
    }
}
```

### 4.2 单例内存泄漏

```java
// 错误写法
public class Singleton {
    private static Singleton instance;
    private Context context;
    
    private Singleton(Context context) {
        this.context = context; // 持有Activity引用
    }
    
    public static Singleton getInstance(Context context) {
        if (instance == null) {
            instance = new Singleton(context);
        }
        return instance;
    }
}

// 正确写法
public class Singleton {
    private static Singleton instance;
    private Context context;
    
    private Singleton(Context context) {
        this.context = context.getApplicationContext(); // 使用Application Context
    }
    
    public static Singleton getInstance(Context context) {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton(context);
                }
            }
        }
        return instance;
    }
}
```

## 5. 内存优化最佳实践

### 5.1 开发阶段

- 使用Lint工具检查潜在内存问题
- 定期使用Profiler监控内存使用
- 编写单元测试验证资源释放逻辑

### 5.2 测试阶段

- 进行压力测试，模拟长时间运行场景
- 监控内存增长趋势
- 使用自动化工具检测内存泄漏

### 5.3 上线后监控

- 集成崩溃分析工具（Firebase Crashlytics、Bugly等）
- 监控OOM发生率
- 收集用户反馈的内存相关问题

## 6. 实战案例分析

### 6.1 案例：RecyclerView图片加载内存优化

**问题**：列表滚动时内存持续增长，出现OOM
**解决方案**：

1. 使用Glide等图片加载库，自动处理内存缓存
2. 设置合理的缓存大小
3. 在Adapter中正确处理图片加载生命周期

### 6.2 案例：WebView内存泄漏

**问题**：包含WebView的Activity退出后内存不释放
**解决方案**：

1. 在Activity onDestroy中调用WebView.destroy()
2. 移除WebView的所有引用
3. 在布局中动态添加WebView，避免XML直接引用
