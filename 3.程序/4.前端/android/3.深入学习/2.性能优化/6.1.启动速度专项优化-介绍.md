# Android启动速度专项优化

## 1. 启动类型分类

### 1.1 冷启动（Cold Start）

- **定义**：应用完全从零开始启动，进程不存在
- **特点**：耗时最长，包含完整的初始化过程
- **优化重点**：Application初始化、首屏Activity创建

### 1.2 温启动（Warm Start）

- **定义**：应用进程存在，但Activity被销毁
- **特点**：跳过Application初始化，直接创建Activity
- **优化重点**：Activity生命周期方法优化

### 1.3 热启动（Hot Start）

- **定义**：应用在后台，直接切换到前台
- **特点**：耗时最短，主要执行onResume等方法
- **优化重点**：减少onResume中的耗时操作

## 2. 启动时间测量

### 2.1 系统日志测量

```bash
# 查看启动时间
adb logcat -s ActivityManager | grep "Displayed"
```

### 2.2 手动埋点测量

```java
// Application中记录启动开始时间
public class MyApplication extends Application {
    @Override
    public void onCreate() {
        super.onCreate();
        long startTime = System.currentTimeMillis();
        // ... 初始化代码
        long endTime = System.currentTimeMillis();
        Log.d("StartupTime", "Application init time: " + (endTime - startTime));
    }
}
```

### 2.3 使用Startup库

Google推荐使用`App Startup`库来管理组件初始化：

```kotlin
// 在AndroidManifest.xml中声明
<provider
    android:name="androidx.startup.InitializationProvider"
    android:authorities="${applicationId}.androidx-startup"
    android:exported="false"
    tools:node="merge">
    
    <!-- 延迟初始化组件 -->
    <meta-data
        android:name="com.example.MyInitializer"
        android:value="androidx.startup" />
</provider>
```

## 3. 启动优化策略

### 3.1 Application优化

- **延迟初始化**：非必要组件延迟到使用时再初始化
- **异步初始化**：将耗时操作放到子线程执行
- **按需初始化**：根据业务场景选择性初始化

### 3.2 首屏Activity优化

- **布局优化**：减少布局层级，使用ViewStub延迟加载
- **资源优化**：避免在onCreate中加载大图片或复杂资源
- **网络请求**：首屏数据预加载或缓存

### 3.3 类加载优化

- **Dex分包**：合理分包减少主Dex大小
- **类预加载**：在空闲时预加载常用类
- **避免反射**：减少反射调用，使用代码生成替代

## 4. 常用优化工具

### 4.1 Systrace

- 分析启动过程中的CPU调度情况
- 识别主线程阻塞点

### 4.2 Profiler

- Memory Profiler：监控内存分配
- CPU Profiler：分析方法调用耗时
- Network Profiler：监控网络请求

### 4.3 Startup Time Analyzer

自定义启动时间分析工具，记录各个阶段耗时。

## 5. 最佳实践

### 5.1 启动页设计

- 使用Splash Screen API（Android 12+）
- 避免纯静态启动页，展示品牌同时进行初始化

### 5.2 数据预加载

- 在Application初始化时预加载必要数据
- 使用Room数据库的预填充功能

### 5.3 监控与报警

- 建立启动时间监控体系
- 设置性能基线，超出阈值自动报警

## 6. 常见问题排查

### 6.1 启动白屏/黑屏

- **原因**：主题设置问题或布局过于复杂
- **解决方案**：设置合适的windowBackground，优化布局

### 6.2 ANR问题

- **原因**：主线程执行耗时操作
- **解决方案**：将耗时操作移至子线程

### 6.3 内存抖动

- **原因**：频繁创建临时对象
- **解决方案**：对象复用，减少不必要的对象创建
