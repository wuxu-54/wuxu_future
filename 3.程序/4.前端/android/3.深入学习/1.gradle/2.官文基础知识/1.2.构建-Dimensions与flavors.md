# flavors与Dimension

在 Android Gradle 构建体系中，`flavors`（产品风味）和 `Dimension`（维度）是用于**创建应用不同变体（Variant）** 的核心概念，主要解决“在同一个项目中管理多个版本的应用（如免费/付费版、不同渠道版、不同功能版）”的问题。

## 一、Flavors（产品风味）：应用的不同“版本”

`flavors` 本质是**应用的不同变体配置**，用于在同一个项目中生成功能、资源、代码有差异的应用版本，而无需复制整个项目。

### 核心作用：

- 分离不同版本的代码、资源、依赖（如免费版有广告代码，付费版无）。
- 统一管理不同版本的公共配置（如包名、版本号的差异化）。
- 配合构建类型（`buildTypes`，如 `debug`/`release`）生成最终可安装的变体（如 `freeDebug`、`paidRelease`）。

### 配置示例：

在模块的 `build.gradle` 中定义产品风味：

```groovy
android {
    // 定义产品风味（以“免费版”和“付费版”为例）
    productFlavors {
        // 免费版风味
        free {
            // 应用ID（包名）差异化：免费版包名为 com.example.app.free
            applicationIdSuffix ".free"
            // 版本名差异化
            versionNameSuffix "-free"
            // 自定义属性（可在代码中通过 BuildConfig 访问）
            buildConfigField "boolean", "HAS_AD", "true" // 免费版有广告
            buildConfigField "int", "MAX_FEATURES", "3"   // 免费版最多3个功能
        }

        // 付费版风味
        paid {
            applicationIdSuffix ".paid"
            versionNameSuffix "-paid"
            buildConfigField "boolean", "HAS_AD", "false" // 付费版无广告
            buildConfigField "int", "MAX_FEATURES", "10"  // 付费版最多10个功能
        }
    }
}
```

### 代码与资源的差异化管理：

通过目录结构分离不同风味的代码和资源，Gradle 会自动合并公共部分和风味特有部分：

```txt
app/
├── src/
│   ├── main/               // 公共代码和资源（所有风味共享）
│   │   ├── java/           // 公共Java/Kotlin代码
│   │   └── res/            // 公共资源（布局、字符串等）
│   ├── free/               // free风味特有代码和资源
│   │   ├── java/           // 免费版特有代码（如广告逻辑）
│   │   └── res/            // 免费版特有资源（如“升级付费”按钮）
│   └── paid/               // paid风味特有代码和资源
│       ├── java/           // 付费版特有代码（如高级功能）
│       └── res/            // 付费版特有资源（如“已购买”标识）
```

构建时，Gradle 会将 `main` 中的内容与当前风味（如 `free`）的内容合并，生成该风味的应用。

## 二、Dimension（维度）：风味的“分组”

`Dimension`（维度）是 Gradle 3.0+ 引入的概念，用于**对多个风味进行分组**，支持“多维度交叉组合”生成更多变体。

### 为什么需要维度？

如果直接定义多个风味（如 `free`/`paid`、`china`/`global`），默认只能选一个风味构建。而通过维度，可以让不同维度的风味“交叉组合”，例如：  

- 维度1（版本类型）：`free`/`paid`  
- 维度2（地区）：`china`/`global`  
组合后可生成 `freeChina`、`freeGlobal`、`paidChina`、`paidGlobal` 等变体。

### 核心作用：

- 将风味按“维度”分类（如“版本类型”“地区”“API级别”等）。
- 允许不同维度的风味自由组合，生成更多细分变体。
- 解决单一维度无法覆盖多维度差异的问题（如同时区分“免费/付费”和“国内/国际”）。

### 配置示例：

1. 先定义维度（`flavorDimensions`），再在每个风味中指定所属维度：

```groovy
android {
    // 1. 定义维度（顺序影响变体名称排序）
    flavorDimensions "versionType", "region" // 维度1：版本类型；维度2：地区

    // 2. 定义产品风味，并指定所属维度
    productFlavors {
        // 属于“versionType”维度的风味
        free {
            dimension "versionType" // 指定维度
            // 其他配置（同前）
        }
        paid {
            dimension "versionType"
            // 其他配置
        }

        // 属于“region”维度的风味
        china {
            dimension "region"
            buildConfigField "String", "SERVER_URL", "\"https://china.example.com\""
        }
        global {
            dimension "region"
            buildConfigField "String", "SERVER_URL", "\"https://global.example.com\""
        }
    }
}
```

2. 生成的变体组合：  
维度顺序决定变体名称的前缀（`维度1+维度2+构建类型`），最终生成的变体包括：  
`freeChinaDebug`、`freeChinaRelease`、`freeGlobalDebug`、`freeGlobalRelease`、  
`paidChinaDebug`、`paidChinaRelease`、`paidGlobalDebug`、`paidGlobalRelease`。

3. 构建特定变体：  
通过 Android Studio 的 `Build Variants` 面板选择变体，或通过命令行构建：

```bash
# 构建 freeChinaRelease 变体
./gradlew assembleFreeChinaRelease
```

## 三、Flavors 与 Dimension 的关系

- **从属关系**：每个 `flavor` 必须属于一个 `dimension`（Gradle 3.0+ 强制要求），否则会报错。
- **组合逻辑**：不同维度的 `flavor` 会交叉组合，生成变体的数量 = 维度1风味数 × 维度2风味数 × ... × 构建类型数（`debug`/`release` 等）。
- **优先级**：当多个维度的资源/代码冲突时，Gradle 按 `flavorDimensions` 定义的顺序优先级递减（靠前的维度覆盖靠后的）。

## 四、与 Build Types 的区别

- `buildTypes`（构建类型）：用于控制构建过程的差异（如是否混淆、是否启用调试），默认有 `debug`（调试版）和 `release`（发布版）。  
- `productFlavors`（产品风味）：用于控制应用本身的功能/资源差异（如免费/付费、地区版本）。  

最终的应用变体 = `flavor组合 + buildType`（如 `freeChinaRelease` = `free`+`china` 风味 + `release` 构建类型）。

## 五、典型使用场景

1. **功能版本**：免费版（基础功能+广告） vs 付费版（全功能+无广告）。
2. **渠道版本**：应用市场版（华为/小米/应用宝），各自有不同的渠道标识和统计代码。
3. **环境版本**：开发环境（连接测试服务器） vs 生产环境（连接正式服务器）。
4. **硬件适配**：针对不同设备（如平板/手机）的适配版本，有不同的布局和功能。

## 总结

- `flavors` 是应用的具体变体（如免费版、国内版），用于分离功能、资源、代码差异。  
- `dimension` 是风味的分组（如“版本类型”“地区”），用于支持多维度交叉组合，生成更多细分变体。  

通过两者的配合，Android 项目可以高效管理多个应用版本，避免代码冗余，简化多版本维护成本。
