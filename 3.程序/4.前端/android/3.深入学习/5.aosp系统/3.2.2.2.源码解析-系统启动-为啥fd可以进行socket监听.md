# 为啥fd可以进行socket监听

在 Linux（Android内核）里：**一切皆文件，Socket 本质就是一种特殊文件，文件描述符 fd 就是内核给这个“文件”分配的整数句柄。**
操作socket，本质就是操作这个特殊文件，读/写这个fd，就等于收发网络/Unix域socket数据。

## 1. fd 是什么？

fd（file descriptor，文件描述符），就是**一个int数字**，属于当前进程的资源索引：

- 0：标准输入 stdin
- 1：标准输出 stdout
- 2：标准错误 stderr
打开文件、管道、socket，内核都会返回一个数字fd。

> 进程内部有一张**文件描述符表**，fd就是这张表的下标，指向内核里的内核对象（file结构体）。

当你创建socket：

```c
int server_fd = socket(AF_UNIX, SOCK_STREAM, 0);
```

内核创建socket内核对象，返回一个整数 `server_fd`，用户态程序拿着这个数字，就能让内核帮你操作这个socket。

## 2. Socket 是内核对象，fd是用户态的“把手”

- Socket的缓冲区、连接状态、端口/地址，**全部在内核里面**，不在App/Zygote用户空间。
- 用户程序**不能直接访问内核socket结构体**，只能拿着fd这个数字，调用系统调用：
  - `accept(fd)`：在监听socket上接受新连接
  - `read(fd)` / `write(fd)`：收发数据
  - `poll(fd)`：监听fd是否可读/可写事件（就是runSelectLoop里面用到的）
  - `close(fd)`：关闭socket，释放内核资源

👉 **fd只是一个索引，不是socket本身**，通过fd，让内核找到对应的socket对象。

## 3. Zygote里Unix Socket（/dev/socket/zygote）的过程，结合你刚才runSelectLoop

1. Zygote 创建Unix域socket，调用`socket()`系统调用 → 内核返回`mServerFd`（一个int）
2. bind到 `/dev/socket/zygote`，listen监听。
3. Zygote把这个fd放进poll监听列表，`Os.poll` 系统调用交给内核：

> “帮我盯着这个fd，如果有客户端来连接（POLLIN可读事件），唤醒我”

4. AMS（system_server）去connect这个Unix socket文件，内核发现监听socket有新连接，poll返回。
5. Zygote调用`accept(server_fd)` → 内核建立新连接，**返回一个新的client_fd**（新数字，代表AMS和Zygote之间这条连接socket）
6. Zygote把这个client_fd加入poll数组继续监听；AMS往这个client_fd写消息（创建app进程参数）。
7. 当client_fd可读，poll唤醒Zygote，调用read(client_fd)读取AMS发送的数据。

> 两个进程（AMS、Zygote），**各自有自己的fd表**。AMS这边有一个fd指向同一条内核socket连接，Zygote这边有另一个fd指向同一个内核socket对象。fd数字在两个进程里可以不一样，**内核的socket对象是唯一的**。

## 4. 为什么 poll 可以监听fd？

`poll`是**IO多路复用系统调用**：你给内核一组fd列表，告诉内核：
> 监视这些fd，只要任意fd发生事件（可读、可写），内核唤醒用户进程。

它不关心fd对应的是什么类型：可以是普通文件、管道、socket。只要是内核file对象，就可以被poll监听。
所以runSelectLoop可以同时监听**服务监听socket fd** + **多条已经建立的client连接fd**。

## 5. Unix Socket 和普通网络socket区别（补充）

Zygote用的是**Unix域socket（AF_UNIX）**，不是IP socket：

- 不走网卡，内核内存直接拷贝，速度快；
- 以文件路径 `/dev/socket/zygote` 作为地址；
- 支持传递fd（进程间传递文件句柄，这是AMS/Zygote很重要的特性）
但是底层模型完全一样：**Unix socket依然是内核对象，靠fd操作**。

## 6. 容易混淆的点

❌ 错误理解：fd = socket
✅ 正确理解：
socket = 内核中的通信对象
fd = 用户态用来引用这个内核对象的**数字编号**

> 就像：房子（socket在内核），门牌号（fd）。程序拿着门牌号，让内核去操作这个房子。

## 精简总结，对应你Zygote场景

1. socket是内核创建的通信对象；
2. socket()系统调用返回fd（整数句柄）；
3. 用户进程只持有fd，调用系统调用(read/poll/accept)，内核通过fd找到对应的socket；
4. runSelectLoop的poll，本质就是让内核监控一批fd对应的内核对象有没有可读事件。

如果你想，我可以简单讲：**Unix Socket怎么跨进程传递fd**（Android很多地方用到这个能力）。
