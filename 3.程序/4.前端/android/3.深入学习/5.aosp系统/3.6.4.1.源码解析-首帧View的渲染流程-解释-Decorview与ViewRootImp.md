# Android DecorView与ViewRootImpl

## 一、DecorView

1. **类型**：`DecorView extends FrameLayout`，属于**View**，是当前窗口View树的**根View**。
2. **创建时机**
    - 正常情况：`Activity.onCreate()`中调用`setContentView()` → `PhoneWindow.setContentView()` → `installDecor()`，**在此处new DecorView**，同时解析布局xml，构建完整View树。
    - 特殊情况：Activity没有调用`setContentView()`，DecorView会延迟到`handleResumeActivity`阶段执行`getDecorView()`时，才调用`installDecor()`创建。
3. **特点**
    - 创建完成后，View树已经构建，但**还没有ViewRootImpl，未和WMS绑定，不会上屏绘制**。
    - 绘制起点：三大流程`measure/layout/draw`从DecorView开始递归遍历整棵View树，**DecorView参与绘制**。

## 二、ViewRootImpl

1. **类型**：**不是View**，不继承View；实现`ViewParent`等接口。
2. **创建时机**：`ActivityThread.handleResumeActivity()`中执行`wm.addView(decor, params)`，在`WindowManagerGlobal.addView()`内部**new ViewRootImpl**。
3. **定位**：桥梁+调度器，连接**App端DecorView ↔ WMS ↔ Choreographer**。
4. **核心职责**
    - 接收Vsync信号；
    - `performTraversals()`：调度`performMeasure`、`performLayout`、`performDraw`三大流程；
    - 分发触摸输入事件；
    - Surface管理、跨进程和WMS通信。
5. 关键：ViewRootImpl**没有onDraw方法，本身不绘制任何画面**，只是调度，调用`mView.draw(canvas)`，mView就是DecorView。

> 特别说明：ViewRootImpl **注册 Vsync 回调，收到 Vsync 信号后，回调里向主线程 Handler 发送消息**；主线程 Handler 收到消息，执行`performTraversals()`；在 performTraversals 内部依次执行`performMeasure`、`performLayout`、`performDraw`，这几个方法内部会调用**DecorView**对应的`measure()`、`layout()`、`draw()`，递归遍历整个 View 树完成绘制。】

Vsync信号监听的注册时机：

```txt
wm.addView(decor, layoutParams)
    → new ViewRootImpl()（获取Choreographer，不申请Vsync）
    → root.setView()
        → requestLayout()
            → scheduleTraversals()
                → mChoreographer.postCallback() 【申请Vsync信号】
                → 插入同步屏障
→ 等待Vsync信号到来
→ Choreographer.doFrame() → mTraversalRunnable → doTraversal → performTraversals()
→ performMeasure / performLayout / performDraw → DecorView.measure/layout/draw → 递归子View
```

## 三、完整时序（AOSP13+，Activity启动View渲染流程）

1. `ActivityThread.handleLaunchActivity`
    - `WindowManagerGlobal.initialize()`：获取SystemServer的binder代理
    - `performLaunchActivity()`
        - 创建Activity、ContextImpl对象
        - `activity.attach()`：创建PhoneWindow对象，此时`mDecor=null`
        - `callActivityOnCreate` → `Activity.onCreate()`回调
        - onCreate中`setContentView` → PhoneWindow.setContentView
          → `installDecor()`：**创建DecorView，inflate xml生成View树**
          > ✅ View树对象准备好了，但无ViewRootImpl，不绘制，看不到界面
2. AMS事务，执行LifecycleItem，依次触发onStart、onResume
3. `ActivityThread.handleResumeActivity()`
    - `performResumeActivity()`：回调onResume、Activity生命周期回调
    - 获取`DecorView`：`r.window.getDecorView()`（**一般只是获取已有DecorView，只有没写setContentView时才会在这里新建DecorView**）
    - `wm.addView(decor, layoutParams)`
        - 创建ViewRootImpl
        - `root.setView()` → `requestLayout()`
        - 等待Vsync，执行`performTraversals()`，正式开启measure、layout、draw，界面上屏

## 四、易错点纠正（原笔记错误修正）

❌ 错误原话：DecorView是根容器，但不是真正的参与绘制的View
✅ 修正：**DecorView是View树的根View，是参与绘制的顶层View；ViewRootImpl不是View，只负责调度绘制流程，本身不绘制画面。**

## 五、面试一句话总结

1. DecorView：**View子类，窗口根View，setContentView阶段创建，是绘制的起点**；
2. ViewRootImpl：**不是View，wm.addView时创建，接收Vsync，调度View树的measure/layout/draw**。

## 六、绘制调用链

```
ViewRootImpl.performTraversals()
    → performDraw()
        → mView.draw(canvas) // mView = DecorView
            → DecorView.draw()，递归绘制所有子View
```
