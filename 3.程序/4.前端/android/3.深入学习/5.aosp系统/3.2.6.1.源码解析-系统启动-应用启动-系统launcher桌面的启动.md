# Android10+ 开机 SystemServer 启动 Launcher（桌面）
>
> Launcher本质就是一个Home Activity。**开机不是App主动startActivity，是system_server主动发起启动Home**，复用咱们前面讲的ATMS/ATSupervisor/ClientTransaction整套Activity启动流程。

## 整体前置大背景

```
Bootloader → Linux kernel → init → Zygote → fork SystemServer
SystemServer依次启动三类服务：
1. startBootstrapServices：ATMS、AMS、PMS、Power、Display（核心！）
2. startCoreServices：Battery、UsageStats等
3. startOtherServices：WMS、IMS、AudioService……
```

等**所有核心服务初始化完成**，`SystemServer`调用 `mActivityManagerService.systemReady()`，**这就是触发Launcher启动的入口**

```java
// SystemServer.java startOtherServices()
mActivityManagerService.systemReady(() -> {
    // 回调，系统就绪后的工作
});
```

## 1. AMS.systemReady → ATMS启动Home（Launcher）

`AMS.systemReady()` 内部，调用 ATMS（ActivityTaskManagerService）方法：

```java
// AMS.java
public void systemReady(final Runnable goingCallback) {
    ...
    // 调用ATMS，在所有屏幕上启动Home Activity
    mAtmService.startHomeOnAllDisplays(mCurrentUserId, "systemReady");
}
```

`startHomeOnAllDisplays` → `RootWindowContainer.startHomeOnAllDisplays` → `startHomeOnTaskDisplayArea` → `ActivityStartController.startHomeActivity()`

### 构造Home专用Intent

```java
Intent homeIntent = new Intent(Intent.ACTION_MAIN);
homeIntent.addCategory(Intent.CATEGORY_HOME);
homeIntent.setPackage(null);
```

交给PMS查询：找到系统默认Home应用（Launcher3）的ActivityInfo。

> PMS作用：扫描所有apk，找到匹配`ACTION_MAIN + CATEGORY_HOME`的Activity，就是Launcher桌面。

## 2. ActivityStarter：决策阶段（和普通startActivity一样）

`ActivityStartController.startHomeActivity()` 最终走到 `ActivityStarter`，做这些事：

1. 构造ActivityRecord（Launcher的记录）
2. 查找/创建**Home专属Task（rootHomeTask）**
3. 处理启动参数，准备resume这个Home Activity
4. 走到 `RootWindowContainer.resumeFocusedTasksTopActivities()`
    → `Task.resumeTopActivityInnerLocked()`
    → `mTaskSupervisor.startSpecificActivity(r, andResume=true, checkConfig)`

👉 到这里就接上**你前面一直在看的 ActivityTaskSupervisor.startSpecificActivity**！

## 3. ActivityTaskSupervisor：判断进程（Launcher进程此时不存在！）

```java
final WindowProcessController wpc = mService.getProcessController(r.processName, r.info.applicationInfo.uid);
```

- 开机阶段，Launcher从来没跑过 → **wpc=null**
- 进入 `mService.startProcessAsync(r, knownToBeDead,...)`
- ATMS通知Zygote，fork新进程（Launcher进程）

### Zygote fork Launcher进程之后

1. 新进程执行 `ActivityThread.main()`
2. new ActivityThread，创建主线Looper
3. 创建内部类 `ApplicationThread`（Binder服务端）
4. `ActivityThread.attach()`，调用AMS的`attachApplication(mAppThread)`
    - 把ApplicationThread Binder传给system_server
    - AMS把IApplicationThread保存进WindowProcessController.mThread
    - `proc.hasEverLaunchedActivity() = false`，所以后面传IActivityClientController
5. AMS回调ATMS，再次回到`startSpecificActivity`
6. 此时WPC已经存在，`hasThread() = true`，执行 `realStartActivityLocked`

## 4. realStartActivityLocked 构建ClientTransaction（P+模型）

```java
final IActivityClientController activityClientController = 
    proc.hasEverLaunchedActivity() ? null : mService.mActivityClientController;

final ClientTransaction clientTransaction = ClientTransaction.obtain(proc.getThread(), r.token);
clientTransaction.addTransactionItem(LaunchActivityItem.obtain(..., activityClientController,...));
clientTransaction.addTransactionItem(ResumeActivityItem.obtain());

mService.getLifecycleManager().scheduleTransaction(clientTransaction);
```

一次性Binder把事务发给Launcher进程的ApplicationThread。

## 5. Launcher App进程侧执行（和普通Activity完全一致）

1. Binder线程：`ApplicationThread.scheduleTransaction()`
    → `ActivityThread.this.scheduleTransaction()`
    → sendMessage H.EXECUTE_TRANSACTION
2. 主线TransactionExecutor依次执行Item：
    - LaunchActivityItem：new Launcher Activity → attach → onCreate → onStart
    - ResumeActivityItem：onResume
3. handleResumeActivity里面 addView(DecorView)，添加到WMS，开始测量布局绘制，**桌面画面显示出来，开机动画退出**

# 生命周期（开机启动Launcher）

Launcher是**全新进程冷启动**，没有上一个Activity，所以没有A.onPause。

```
fork Launcher进程 → attachApplication → Launcher.onCreate → Launcher.onStart → Launcher.onResume → DecorView添加、绘制，桌面显示
```

# 🔥 对比：普通App里A startActivity启动B vs 开机启动Launcher

1. **A启动B**：ATMS先pause前台A，pause回调回来，才启动B；
2. **开机启动Launcher**：系统开机阶段**没有任何前台Activity**，不需要pause任何页面，直接走冷启动流程。

# 面试高频考点

1. **谁发起Launcher启动？**
SystemServer服务全部就绪后，AMS.systemReady调用ATMS.startHomeOnAllDisplays主动拉起Home Activity。不是任何App调用startActivity。
2. Launcher是不是普通Activity？
是的，它是一个带CATEGORY_HOME的Activity，启动复用完整ATMS/ATSupervisor流程。
3. 开机为什么不需要pause？
开机阶段不存在任何前台Activity，没有旧页面。
4. 开机启动和普通Activity启动的共用模块？
ActivityStarter、ActivityTaskSupervisor、realStartActivityLocked、ClientTransaction，**全部复用同一套代码**，差别只在于：有没有旧前台Activity需要pause、进程是否存在。

# 完整精简调用链（背诵版）

```
SystemServer.startOtherServices
→ AMS.systemReady()
→ ATMS.startHomeOnAllDisplays
→ ActivityStartController.startHomeActivity
→ ActivityStarter 构建ActivityRecord，创建Home Task
→ RootWindowContainer.resumeFocusedTasksTopActivities
→ Task.resumeTopActivityInnerLocked
→ ActivityTaskSupervisor.startSpecificActivity
    发现Launcher进程不存在 → startProcessAsync通知Zygote fork Launcher进程
Launcher进程起来后 attachApplication，把ApplicationThread Binder传给system_server
再次回到startSpecificActivity
→ realStartActivityLocked 组装ClientTransaction（LaunchItem + ResumeItem）
→ Binder发送scheduleTransaction到Launcher进程
→ Launcher主线TransactionExecutor执行：onCreate → onStart → onResume，渲染桌面
```
