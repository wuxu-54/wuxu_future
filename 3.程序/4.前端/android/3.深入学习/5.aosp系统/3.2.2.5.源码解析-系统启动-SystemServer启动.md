# 一、SystemServer 完整启动流程

SystemServer 是怎么完整启动的流程，以及 普通进程怎么被启动，怎么进行 service 绑定通信?

> 一句话：**Zygote在自己初始化阶段，主动调用forkSystemServer一次性fork出来system_server，它是Zygote孵化的第一个进程；AMS/WMS/PMS全部跑在这个进程**

```
init进程 → app_process → runtime.start → ZygoteInit.main()
```

## 1. ZygoteInit.main 内部

1. 预加载类、资源（preload()）
2. **forkSystemServer()** 【重点，主动fork，不是socket触发】

```java
pid = Zygote.forkSystemServer(xxx);
if (pid == 0) {
    // ======子进程：system_server======
    handleSystemServerProcess(parsedArgs);
} else {
    // ======父Zygote======
    // 回到ZygoteInit.main，继续往下执行，启动ZygoteServer，进入runSelectLoop监听socket
}
```

## 2. 子进程 handleSystemServerProcess

1. 调用 `ZygoteInit.zygoteInit()`
    - `nativeZygoteInit()`：**启动Binder线程池**（SystemServer所有系统服务Binder通信基础）
    - `RuntimeInit.applicationInit()` → `findStaticMain()`，反射拿到`SystemServer.main`，封装Runnable
2. 执行 `SystemServer.main()`

## 3. SystemServer.main() 分3阶段启动系统服务

```java
public static void main(String[] args) {
    new SystemServer().run();
}
```

`run()`里面分三段启动服务，**严格顺序，有依赖关系**：

1. **startBootstrapServices() 引导核心服务**
    - Installer、Watchdog、**ActivityManagerService(AMS)**、PackageManagerService(PMS)
    ✅ AMS在这里完成初始化，AMS是四大组件大管家
2. **startCoreServices() 核心服务**
    - PowerManagerService、BatteryService等
3. **startOtherServices() 其他服务**
    - WindowManagerService(WMS)、InputManagerService、AudioService等
    - 全部服务启动完成后，AMS调用 `systemReady()`
        - AMS.systemReady → 启动Launcher桌面应用

> 关键点：
>
> - SystemServer 是Zygote**一次性主动fork**，不走ZygoteSocket；
> - 启动完所有系统服务之后，AMS就绪，才去启动Launcher；
> - SystemServer内部所有系统服务，通过**Binder**注册到ServiceManager（ServiceManager是Binder的注册表）

## 4. 父Zygote在fork完SystemServer之后

继续往下执行，创建`ZygoteServer`，调用`runSelectLoop()`，**进入poll死循环，监听/dev/socket/zygote，等待AMS请求孵化普通App进程**

# 二、普通App进程完整启动流程（你前面ZygoteSocket/forkAndSpecialize那套）
>
> 普通App进程：**AMS通过Unix Socket发送请求给Zygote，Zygote.forkAndSpecialize孵化App进程**

1. 用户点击App图标 → Launcher调用 `startActivity`，**Binder调用AMS**
2. AMS检查：这个App没有进程，需要新建进程
3. AMS（SystemServer进程）通过 **ZygoteProcess**，向 `/dev/socket/zygote` 发送socket请求，携带参数（uid、包名、目标类ActivityThread）
4. Zygote的`runSelectLoop`中poll收到socket事件
    - `connection.processCommand()`
        - `Zygote.forkAndSpecialize()`
            - 父Zygote：返回pid，把pid写回AMS，回到poll循环
            - 子App进程：进入`handleChildProc()`
                - `ZygoteInit.zygoteInit()`
                - `RuntimeInit.findStaticMain`，生成Runnable，目标`ActivityThread.main`
5. runSelectLoop执行`command.run()` → 反射调用 `ActivityThread.main()`
6. ActivityThread.main：
    - `Looper.prepareMainLooper()` 创建主线程消息队列
    - new ActivityThread，`attach(false)` → Binder连接AMS，注册ApplicationThread（App端的Binder代理，AMS用来回调App）
    - `Looper.loop()` 主线程消息循环
7. AMS收到App进程就绪，发送`bindApplication`，App端`handleBindApplication`：
    - 创建ClassLoader
    - 实例化Application，调用`Application.onCreate()`
    - 继续启动目标Activity

> ✅通信区分（高频面试）
>
> 1. AMS ↔ Zygote：**Unix Socket**（创建进程的时候用，传递进程创建参数）
> 2. AMS ↔ App进程：**Binder**（四大组件、组件生命周期通信）

# 三、Service绑定 bindService 跨进程通信（App绑定另一个进程Service）

## 3.1 整体流程（客户端App 绑定 远端Service）
>
> 客户端调用 `bindService()` → Binder调用AMS → AMS管理Service生命周期；如果Service进程不存在，**AMS会再次请求Zygote孵化Service所在进程**

```java
// 客户端代码
bindService(intent, serviceConnection, BIND_AUTO_CREATE);
```

1. 客户端App（Client）`bindService`，底层通过IPC Binder调用 `AMS.bindService()`，传入`ServiceConnection`的Binder代理
2. AMS查询PMS，找到目标Service组件信息；
    - 如果**Service进程还没创建**：AMS走上面那套流程，向Zygote发送socket请求，fork新进程；新进程启动ActivityThread，创建Service，调用`onCreate()`
    - 如果进程已经存在：直接通知目标进程启动Service
3. AMS通知Service所在App进程（通过ApplicationThread Binder），在目标进程主线程：
    - 实例化Service，调用`Service.onCreate()`
    - 调用`Service.onBind()`，**返回IBinder对象（AIDL的Stub）**
4. Service把IBinder通过Binder传给AMS；AMS再把IBinder的BinderProxy传给**客户端ServiceConnection**
5. 客户端回调 `serviceConnection.onServiceConnected(IBinder binder)`
    - 拿到IBinder，生成AIDL Proxy代理对象，之后客户端就可以**直接跨进程调用Service的AIDL接口方法**

## 3.2 Binder通信原理（Service之间怎么通信）

- Service端：继承`Binder`（Stub），运行在服务端进程；`onBind()`返回这个Binder对象
- Binder驱动：内核负责跨进程数据传递
- 客户端：拿到的是`BinderProxy`，是Stub在客户端的代理
- 客户端调用proxy.xxx() → 数据打包，进入Binder驱动，唤醒服务端Binder线程池，执行Stub对应方法，返回结果

> 关键：
>
> - AMS只负责**管理Service生命周期、进程创建**；
> - 一旦bind建立成功，**业务方法调用直接客户端 ↔ Service进程Binder直连，不再经过AMS**。AMS只做管理，不转发业务调用。

## 3.3 Service生命周期（跨进程bind）

1. Service进程不存在：`onCreate()` → `onBind()`
2. 后续其他客户端再bind：**不会再调用onBind，复用同一个IBinder**
3. 全部客户端unbind之后，触发`onUnbind()`，可以选择`onRebind`；没有绑定者AMS会杀掉Service进程，触发`onDestroy()`

# 四、一张总对比（SystemServer vs 普通App进程）

| 项目 | SystemServer | 普通App/Service进程 |
|---|---|---|
| 创建触发 | Zygote启动阶段**主动forkSystemServer** | AMS发起，Zygote通过Unix Socket收到请求后forkAndSpecialize |
| 创建时机 | Zygote刚启动，preload之后，进入socket循环**之前** | 系统运行中，AMS需要App进程时动态创建 |
| 入口类 | SystemServer.main | ActivityThread.main |
| 通信 | 内部启动Binder线程池，注册大量系统服务到ServiceManager | ApplicationThread Binder和AMS通信；组件之间用Binder |
| 失败影响 | SystemServer崩溃 → 系统重启 | 单个App进程崩溃，只杀当前App，不影响系统 |

# 五、完整全局链路串联

```
init
├─ ServiceManager（Binder注册表，native）
├─ app_process → Zygote
    ├─ ZygoteInit.main()
        ├─ preload()
        ├─ forkSystemServer → system_server进程
        │   └─ SystemServer.main → 启动AMS/WMS/PMS，AMS注册到ServiceManager
        └─ ZygoteServer.runSelectLoop() 【阻塞等待AMS的socket请求】
                ← AMS（system_server）请求创建App进程（Unix Socket）
                → forkAndSpecialize → App进程
                    → ActivityThread.main → Application.onCreate
                    → App内部调用bindService(Binder)
                        → AMS 管理Service，必要时创建Service进程
                        → Service.onBind 返回IBinder，客户端拿到BinderProxy，直接IPC调用
```
