# 同步屏障（Sync Barrier）完整详解

## 一、一句话概括同步屏障作用

**同步屏障是主线程 MessageQueue 里的一个特殊标记，作用是：一旦队列设置了屏障，Looper 在取消息的时候，会跳过所有普通【同步消息】，只优先执行【异步消息】；屏障移除后，同步消息才恢复正常执行。**

> 核心目的：**保证UI绘制、VSync回调这类系统高优先级任务，不会被前面堆积的普通业务消息阻塞，避免掉帧**。

## 二、基础概念回顾

Message 有一个布尔标记 `isAsynchronous`：

1. **同步消息（默认）**：我们普通`new Handler()`发送的消息，`isAsynchronous=false`；遇到同步屏障会被跳过。
2. **异步消息**：`msg.setAsynchronous(true)` / `Handler.createAsync()` 发送的消息；**不受同步屏障拦截**。

同步屏障本身就是一个特殊的 Message：

```
msg.target = null
```

- 它**不会被分发执行**（`msg.target`是Handler，null就没有handler去处理），仅仅是一个**标记节点**插入消息链表。
- API中 `postSyncBarrier()` 用来插入屏障；`removeSyncBarrier(token)` 移除屏障；这两个API是`@hide`，**应用不能直接调用，只有Framework内部使用**。

## 三、同步屏障完整工作流程（ViewRootImpl绘制场景，最经典场景）
>
> 这个是Android系统使用同步屏障的唯一核心场景：UI渲染。

1. 界面需要刷新（`invalidate()` / 请求绘制），`ViewRootImpl.scheduleTraversals()` 被调用。
2. **第一步：插入同步屏障**
    调用 `postSyncBarrier()`，往主线程MessageQueue链表插入`target=null`的屏障消息。
    > 屏障插入到**当前队列尾部**，在即将要执行绘制消息之前。
3. **第二步：发送绘制异步消息**
    发送`doTraversal()`的消息，**这条消息标记为异步消息**。
4. 此时消息队列链表顺序示例：
    > [同步消息A] → [同步消息B] → **【同步屏障(target=null)】** → [异步消息：doTraversal绘制] → [同步消息C]
5. Looper 在`nextLegacy()`遍历链表取消息：
    - 依次取消息，读到**屏障节点**；
    - 触发屏障逻辑：**不再取出同步消息，持续向后遍历链表，只寻找异步消息**；
    - 找到`doTraversal`异步消息，取出执行，执行UI测量、布局、绘制。
    - 后面的同步消息C会被暂时卡住，不会执行。
6. **第三步：绘制完成，移除屏障**
    `doTraversal()`绘制执行完毕，调用`removeSyncBarrier()`把屏障从链表删掉。
7. 屏障消失，Looper恢复正常逻辑：同步消息、异步消息按照when时间顺序正常排队执行，消息C才会被处理。

### 如果**没有同步屏障会发生什么？（灾难场景）**

假设队列：
> [耗时业务同步消息A] → [绘制同步消息]

消息A先执行，如果A是耗时任务（比如复杂业务计算），会**卡住绘制消息**，UI迟迟无法刷新，直接掉帧、卡顿。

就算绘制消息放到A后面，也必须等A执行完才能跑绘制。
> 同步屏障解决的就是这个问题：**哪怕屏障前面有一堆同步消息，屏障之后的异步绘制消息可以优先插队执行**。

⚠️ 注意：不是把绘制消息直接挪到队头！
屏障**不会移动任何消息节点**，只是修改Looper遍历的规则：**遇到屏障后，只读异步，忽略同步**。消息在链表的位置不变，只是读取策略变了。

## 四、源码里屏障判断逻辑（Legacy nextLegacy）

```java
// MessageQueue.nextLegacy
Message msg = mMessages;
// 如果当前消息是屏障（target == null）
if (msg != null && msg.target == null) {
    // 遇到屏障，开始跳过同步消息，只找异步消息
    do {
        prevMsg = msg;
        msg = msg.next;
    } while (msg != null && !msg.isAsynchronous());
}
```

逻辑拆解：

1. 拿到链表头`mMessages`；
2. 如果头部消息是屏障`target == null`；
3. 进入循环，不断向后遍历：
    - 如果消息**不是异步消息**，跳过；
    - 直到找到**异步消息**，或者遍历到链表末尾；
4. 找到异步消息，取出执行；
5. 如果遍历到末尾没有异步消息，Looper进入nativePollOnce阻塞休眠。

> 关键点：屏障生效范围：**屏障节点之后的消息**，屏障前面的消息，还是会正常按顺序执行。

举例子：
队列：[同步A] →【屏障】→ [同步B] → [异步绘制Msg]

- A在屏障**前面**：A会正常执行；
- 执行完A，下一个读到屏障；
- 屏障生效，跳过同步B，找到异步绘制消息执行。

## 五、同步屏障的核心特性

1. ✅ **屏障只影响屏障节点之后的消息**，屏障之前的消息不受影响，正常执行。
2. ✅ **屏障只拦截同步消息，不拦截异步消息**。
3. ✅ 屏障本身不会执行，只是标记，不会触发`dispatchMessage`。
4. ✅ 同一个队列可以存在**多个同步屏障**（很少用），屏障是链式生效。
5. ✅ 屏障只是**读取规则的改变，不会修改原有消息的when时间、不会移动消息节点**。
6. ✅ 屏障只存在主线程MessageQueue（ViewRootImpl使用），子线程Looper一般不会使用同步屏障。

## 六、同步屏障和异步消息的常见误区（面试高频）

### 误区1：异步消息优先级永远最高，任何时候都插队

❌ 错误。
✅ 正确：**只有队列存在同步屏障的时候，异步消息才有特权；没有屏障，同步和异步消息完全按照when时间顺序排队，公平调度。**

### 误区2：同步屏障会把绘制消息插到队首

❌ 错误。
✅ 正确：绘制消息本身位置不变，只是Looper遍历规则改变，跳过中间同步消息。

### 误区3：异步消息=在子线程运行

❌ 错误。
✅ 正确：同步/异步只是**消息调度标记**；消息最终依然在Looper所在线程执行（主线程）。和是否多线程无关！名字很容易误导。

### 误区4：App可以自己postSyncBarrier来插队业务消息

❌ 错误。
`postSyncBarrier()`是@hide系统私有API，应用无法直接调用；**只有系统框架使用**。
API29开放的`Handler.createAsync()`，只是允许App发送异步消息，**但App不能自己插入屏障**。
也就是说：**App创建的异步消息，只有系统插入屏障（UI绘制时），才会体现出“穿过屏障”的能力；平时没有屏障，和普通消息一样排队**。

> 举个例子：你业务代码创建`Handler.createAsync()`发异步消息。
> 只有当View在刷新UI，系统插入了同步屏障，你的异步消息才会跳过同步消息优先跑；
> 平时界面静止，没有屏障，你的异步消息和普通消息一样按时间排队。

## 七、使用异步消息的风险（为什么官方不建议随便滥用createAsync）

当界面在绘制（存在同步屏障），你的业务异步消息和系统绘制异步消息**都是异步消息**，会一起参与调度。
如果大量业务异步消息不断入队：

- 系统绘制消息会被你的业务异步消息排队挤压；
- 反而阻塞UI绘制，造成更严重的掉帧。

> 结论：异步消息不是“万能高优先级通行证”，**只适合少量、实时性强、简短的事件**（传感器、音视频回调），不能用来做大量业务逻辑。

## 八、DeliQueue（API37）下同步屏障的变化

API37 DeliQueue重构MessageQueue底层存储，**但是同步屏障对外行为完全不变**：

1. 上层`postSyncBarrier`/`removeSyncBarrier`依然是@hide；
2. 异步消息`isAsynchronous`标记保留；
3. 遇到屏障，依然跳过同步消息优先执行异步消息；
4. 底层不再用单向链表存储消息，屏障不再是链表上的特殊节点，DeliQueue内部改用专门标记来实现屏障逻辑；

> 👉 **行为完全对齐，只是内部存储实现改了，上层业务感知不到任何变化**。

## 九、面试一句话总结同步屏障
>
> 同步屏障是Android Framework给主线程消息队列设置的调度标记，UI绘制前插入屏障，让Looper跳过屏障后的普通同步业务消息，优先执行异步的绘制消息；绘制完成移除屏障，恢复正常消息调度，目的是保障UI渲染不被业务消息阻塞，减少掉帧。
