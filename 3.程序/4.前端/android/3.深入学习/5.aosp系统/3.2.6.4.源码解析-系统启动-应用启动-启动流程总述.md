# Android Activity 完整启动全集（合并：开机Zygote→SystemServer→Launcher + A启动B页面）
>
> Android P+ 模型，ClientTransaction，ATMS/ActivityTaskSupervisor；包含两套场景：
> 场景1：开机流程：init → Zygote → fork system_server → SystemServer拉起Launcher桌面
> 场景2：App内页面跳转：A Activity startActivity 启动B Activity

Q：为啥不在系统启动阶段使用 ipc 机制进行通信，而是设定 socket?

A：Zygote 选用 **Linux Socket（Unix Domain Socket，域套接字）** 而不是 Binder IPC，**是因为 Zygote 启动的时候，Binder 驱动、Binder IPC 环境还没准备就绪**；

>SystemServer 和 App 之间才用 Binder，因为那时 Binder 已经就绪。
>
> 注意：Zygote 的 socket 是 **Unix Domain Socket（本地域 socket，不走网络）**，不是网络 socket。

# 场景一：开机启动链路（init → Zygote → SystemServer → Launcher）

```
init进程
    → 启动Zygote（ZygoteInit.main）
        → ZygoteInit.startSystemServer()
            → Zygote.forkSystemServer()
                → nativeForkSystemServer（JNI com_android_internal_os_Zygote.cpp）
                    → ForkAndSpecializeCommon(is_system_server=true)
                        → Linux fork()系统调用
                        ├─【父进程 Zygote，pid>0】返回，进入 runSelectLoop，监听socket，等待孵化App进程
                        └─【子进程 system_server，pid=0】
                            → zygoteServer.closeServerSocket(); // system_server不再接收zygote创建app请求
                            → handleSystemServerProcess()
                                → invokeStaticMain 反射找到SystemServer.main()
                                → throw MethodAndArgsCaller 异常（清栈技巧）
        ZygoteInit.main捕获MethodAndArgsCaller异常
            → caller.run()，反射执行 SystemServer.main()
                → new SystemServer().run()
                    1. Looper.prepareMainLooper() // 初始化主线Looper
                    2. System.loadLibrary("android_servers") // 加载native系统服务
                    3. startBootstrapServices()  // ATMS、AMS、PMS、PowerManagerService
                    4. startCoreServices()       // BatteryService、UsageStatsService
                    5. startOtherServices()      // WMS、IMS、AudioService、AlarmService
                    6. mActivityManagerService.systemReady()
                        → mAtmService.startHomeOnAllDisplays() // ATMS主动拉起Home Launcher
                            → ActivityStartController.startHomeActivity()
                                // 构造Home Intent：ACTION_MAIN + CATEGORY_HOME，PMS查询Launcher组件信息
                                → ActivityStarter：创建Home Task、创建Launcher ActivityRecord
                                → RootWindowContainer.resumeFocusedTasksTopActivities()
                                    → Task.resumeTopActivityInnerLocked()
                                        → mTaskSupervisor.startSpecificActivity(r, andResume=true, checkConfig)
                                            // 开机Launcher进程不存在
                                            → mService.startProcessAsync() 通知Zygote创建Launcher进程
```

### Zygote孵化Launcher进程

```
Zygote收到socket请求 → nativeForkAndSpecialize（ForkAndSpecializeCommon，is_system_server=false）
    fork出Launcher App进程
        → ActivityThread.main()
            new ActivityThread();
            创建主线Looper；创建内部Binder对象 ApplicationThread
            → ActivityThread.attach(true)
                → AMS.attachApplication(mAppThread) // 将ApplicationThread(Binder)传给system_server
                    AMS内部保存IApplicationThread到WindowProcessController(WPC)
                    AMS回调ATMS，再次进入startSpecificActivity
                        ✅ 此时WPC有效，进程就绪
                        → ActivityTaskSupervisor.realStartActivityLocked
                            // 组装ClientTransaction事务
                            ClientTransaction clientTransaction = ClientTransaction.obtain(proc.getThread(), r.token);
                            clientTransaction.addTransactionItem(LaunchActivityItem.obtain(...));
                            clientTransaction.addTransactionItem(ResumeActivityItem.obtain());
                            mService.getLifecycleManager().scheduleTransaction(clientTransaction);
                            // Binder IPC，一次性把事务发送Launcher进程ApplicationThread
```

### Launcher App进程执行事务

```
// ApplicationThread（Binder线程）
@Override 
public void scheduleTransaction(ClientTransaction transaction) throws RemoteException { 
    ActivityThread.this.scheduleTransaction(transaction); 
}
```

`ActivityThread`继承`ClientTransactionHandler`，scheduleTransaction在父类：

```java
// ClientTransactionHandler.java
void scheduleTransaction(ClientTransaction transaction) {
    transaction.preExecute(this);
    sendMessage(ActivityThread.H.EXECUTE_TRANSACTION, transaction);
}
```

ActivityThread实现sendMessage，发送消息到主线Handler H。主线收到`EXECUTE_TRANSACTION`，TransactionExecutor串行执行Item：

1. **LaunchActivityItem.execute()**
    → handleLaunchActivity → performLaunchActivity
        - 反射new Launcher Activity对象
        - activity.attach() 绑定Context、WindowManager
        - mInstrumentation.callActivityOnCreate(activity) → onCreate()
        - mInstrumentation.callActivityOnStart(activity) → onStart()
2. **ResumeActivityItem.execute()**
    → handleResumeActivity → performResumeActivity
        - onResume()
        - addView(DecorView, LayoutParams)，交给WMS，View开始measure/layout/draw，桌面画面渲染显示

> 生命周期：Launcher.onCreate → Launcher.onStart → Launcher.onResume
> 开机无前台Activity，**不需要pause任何页面**

# 场景二：A Activity 调用 startActivity 启动 B Activity（同进程普通跳转）
>
> A是前台页面，调用startActivity启动B；ATMS流程，P+ ClientTransaction模型

```
A页面代码：startActivity(intent)
    → Activity.startActivity → Instrumentation.execStartActivity
        → IActivityManager.startActivity() // Binder调用ATMS
            → ATMS.startActivity
                → ActivityStarter.startActivityUnchecked()【决策层】
                    解析Intent、flag、launchMode；查找/创建TaskRecord；构建B的ActivityRecord
                    → RootWindowContainer.resumeFocusedTasksTopActivities()
                        → Task.resumeTopActivityInnerLocked()
                            // 【关键点：先暂停当前前台A】
                            // ATMS构造PauseActivityItem，发送事务给A所在进程
                            // A执行onPause，完成后，A进程通过IActivityClientController回调ATMS：pause完成
                            // ATMS收到pause回调，才继续往下执行
                            → mTaskSupervisor.startSpecificActivity(B的ActivityRecord, andResume=true, checkConfig)
```

## startSpecificActivity 分支判断

1. **同进程（A、B同一个App，进程已经存在）**
    - WindowProcessController wpc 存在，wpc.hasThread() = true
    - 直接进入 `realStartActivityLocked(B, wpc, andResume=true, checkConfig)`
2. **跨进程（B属于别的应用，进程未创建）**
    - wpc为空，调用`startProcessAsync`通知Zygote fork B的进程，进程起来后attachApplication，再回调回来执行realStartActivityLocked

## realStartActivityLocked 组装事务（同进程举例）

```java
final ClientTransaction clientTransaction = ClientTransaction.obtain(proc.getThread(), r.token);
clientTransaction.addTransactionItem(LaunchActivityItem.obtain(...));
clientTransaction.addTransactionItem(ResumeActivityItem.obtain());
mService.getLifecycleManager().scheduleTransaction(clientTransaction);
```

Binder一次性发送ClientTransaction给App进程ApplicationThread。

## App进程执行事务

```
Binder线程 ApplicationThread.scheduleTransaction()
    → ActivityThread.this.scheduleTransaction(transaction)
    → sendMessage H.EXECUTE_TRANSACTION
主线TransactionExecutor依次执行Item
1. LaunchActivityItem：B new、attach、onCreate、onStart
2. ResumeActivityItem：B onResume；addView(DecorView)渲染B页面
```

## B onResume成功之后，ATMS发送StopActivityItem给A

A收到Stop事务 → A.onStop()

✅ 完整生命周期顺序：
**A.onPause → B.onCreate → B.onStart → B.onResume → A.onStop**
> 如果B是透明对话框Activity：A不会执行onStop，仅onPause。

> launchMode特殊场景补充：
> singleTop：复用B实例，不走onCreate，执行onNewIntent，然后resume
> singleTask：弹出B上方所有Activity，依次onPause/onStop/onDestroy，之后resume B

# 旧版本Android O（8.x，无ClientTransaction，对比理解）

O及更早，**没有ClientTransaction、TransactionItem**，IApplicationThread定义一堆独立AIDL接口，每次生命周期单独一次Binder IPC
A启动B：

1. AMS调用`schedulePauseActivity`（Binder#1）→ A.onPause，回调AMS
2. AMS调用`scheduleLaunchActivity`（Binder#2）→ B onCreate + onStart
3. AMS调用`scheduleResumeActivity`（Binder#3）→ B onResume
4. B resume后AMS调用`scheduleStopActivity`（Binder#4）→ A.onStop

App端ApplicationThread收到不同AIDL方法，分别发送不同Handler消息：LAUNCH_ACTIVITY / RESUME_ACTIVITY / PAUSE_ACTIVITY。
> Android P引入ClientTransaction目的：合并多个生命周期为**单次Binder调用**，减少Binder开销。

# 核心概念汇总（面试背诵）

## 1. Zygote两次fork的区别

- `nativeForkSystemServer`：开机**仅执行一次**，is_system_server=true；fork出system_server，子进程关闭Zygote socket。
- `nativeForkAndSpecialize`：后续所有App进程（Launcher、三方App），is_system_server=false；子进程保留逻辑，attach到AMS。

## 2. SystemServer 三大阶段服务

1. startBootstrapServices：ATMS、AMS、PMS、PowerManagerService（最先启动，基础依赖）
2. startCoreServices：BatteryService、UsageStatsService
3. startOtherServices：WMS、IMS、Audio、Alarm、Connectivity等

> 全部服务初始化完成后执行`AMS.systemReady()`，拉起Launcher桌面。

## 3. ATMS启动Activity统一流程（Launcher / A启动B 共用这套框架）

ActivityStarter（构建ActivityRecord/Task） → resumeFocusedTasksTopActivities → Task.resumeTopActivityInnerLocked → ActivityTaskSupervisor.startSpecificActivity

- 进程不存在：通知Zygote fork进程，attachApplication回调后继续
- 进程存在：直接realStartActivityLocked，组装ClientTransaction发送App进程

## 4. ClientTransaction执行规则

1. Binder线程ApplicationThread收到scheduleTransaction，**不能直接执行生命周期**，切到主线Handler
2. TransactionExecutor串行遍历Item：LaunchActivityItem（create+start）、ResumeActivityItem（resume）
3. handleResumeActivity内部addView(DecorView)，才会触发WMS、View绘制，页面才可见

## 5. 两种场景最大差异

- 开机启动Launcher：无前台Activity，**不需要pause页面**；冷启动，需要Zygote新建进程。
- A启动B：**必须先pause前台A，pause回调成功后，才会启动B**；可同进程/跨进程。

# 完整总调用链（合并整条大链路）

```
init
└─ ZygoteInit.main()
   ├─ startSystemServer()
   │  └─ Zygote.forkSystemServer() → nativeForkSystemServer → fork()
   │     ├─父Zygote：runSelectLoop，监听socket
   │     └─子system_server：closeSocket → handleSystemServerProcess → invokeStaticMain抛异常
   └─捕获MethodAndArgsCaller → SystemServer.main()
      └─SystemServer.run()
         ├─startBootstrapServices(ATMS,AMS,PMS)
         ├─startCoreServices
         ├─startOtherServices(WMS,IMS)
         └─AMS.systemReady() → ATMS.startHomeOnAllDisplays 启动Launcher
             └─ActivityStarter构建Launcher ActivityRecord
                └─ActivityTaskSupervisor.startSpecificActivity
                    └─Launcher进程不存在，通知Zygote fork Launcher
Zygote socket收到请求 → nativeForkAndSpecialize → fork Launcher进程
    → ActivityThread.main → attach → AMS.attachApplication
        → ATMS回到realStartActivityLocked，组装ClientTransaction发送Launcher
Launcher主线TransactionExecutor：LaunchItem(onCreate,onStart) → ResumeItem(onResume)，渲染桌面

【桌面运行后，用户点击App，A startActivity启动B】
A.startActivity → Binder ATMS
    → ActivityStarter
    → resumeFocusedTasksTopActivities
        → 先pauseA，A pause回调ATMS
        → startSpecificActivity(B)
            同进程：realStartActivityLocked，组装ClientTransaction发给App进程
            跨进程：Zygote fork B进程，attachApplication后执行realStartActivityLocked
App主线TransactionExecutor执行B的LaunchItem+ResumeItem
B.onResume后，ATMS发送StopItem，执行A.onStop
```
