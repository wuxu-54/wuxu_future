# APK安装流程【阶段1：安装会话创建 + APK上传拷贝】

>
> 版本区分：
>
>
> - **旧方案（Android 7及以下，N及更早）**：`PackageManager.installPackage()` 一次性安装，无Session机制
> - **新方案（Android 8.0 / O，API26+）**：`PackageInstaller` Session会话式安装，也就是现在主流方案
> 源码基线：AOSP Android13，关键源码路径标注；源码只贴核心片段，附带解释；
> 主体链路：**调用方（应用市场/adb） → PackageInstaller（应用侧API） → PackageInstallerService(PIS，SystemServer内) → PMS → installd**

>
> 核心目标：创建安装会话，开辟staging临时目录，将APK（含split包）安全拷贝到`/data/app-staging/`，完成基础文件校验，commit提交会话，触发阶段2。

# 一、Android 7及更早 旧版安装机制（无Session，作为对比）

## 1.1 旧版入口 API

```
// Android N(7.x)及以下
@Deprecated
public void installPackage(Uri packageURI, IPackageInstallObserver observer,
        int flags, String installerPackageName);
```

- 入参：APK的Uri、安装回调observer、flags、安装来源包名
- 工作逻辑：
  1. 上层App拿到APK Uri，直接调用`installPackage` Binder接口；
  2. PMS收到请求，直接把APK拷贝到临时目录（`/data/local/tmp`）；
  3. 一次性串行执行：解析APK、签名校验、安装；
  4. 没有分包分批上传机制，不支持断点续传；
  5. 没有独立会话管理，安装中途取消，容易残留临时垃圾文件。

## 1.2 旧版缺陷（为什么Android O引入Session）

1. 不支持Split APK（base + split分包一次性传入，无法分批上传）；
2. 上传和安装耦合在一起，APK很大时，一旦中途出错，全部重来；
3. 缺少沙箱隔离，临时文件容易产生脏数据；
4. 无法精准管理多任务并发安装（多个应用同时安装，任务混杂）。

>
> 一句话总结旧版：**单步一次性调用，上传+安装耦合，没有会话隔离，能力弱**。

## 阶段1-1：创建安装会话 createSession

### 应用侧调用代码示例（应用市场App）

```java
// 1. 获取PackageInstaller对象（ApplicationPackageManager内部获取IPackageManager Binder代理）
PackageInstaller packageInstaller = getPackageManager().getPackageInstaller();

// 2. 构造会话参数
PackageInstaller.SessionParams params = new PackageInstaller.SessionParams(
        PackageInstaller.SessionParams.MODE_FULL_INSTALL);
params.setAppPackageName("com.demo.app"); // 预期包名
params.setInstallLocation(PackageInfo.INSTALL_LOCATION_AUTO);
params.setSize(1024 * 1024 * 50); // 预估APK总大小（base+split）
params.setInstallReason(PackageManager.INSTALL_REASON_USER);

// 3. Binder调用PIS，创建Session，拿到sessionId
int sessionId = packageInstaller.createSession(params);
```

Q：`PackageInstaller packageInstaller = getPackageManager().getPackageInstaller();`将这个最终是获取的什么？

A：`getPackageManager()` 返回 `ApplicationPackageManager` 实例；
`ApplicationPackageManager.getPackageInstaller()` 返回 **`PackageInstaller` 本地客户端对象**（应用侧封装，内部持有 Binder 代理 `IPackageManager`，后续通过它跨进程调用 SystemServer 里面的`PackageInstallerService`）。

   ```java

   import android.content.pm.PackageInstaller;
   import android.os.Bundle;
   import androidx.appcompat.app.AppCompatActivity;

   //示例demo
   public class InstallDemoActivity extends AppCompatActivity {
      @Override
      protected void onCreate(Bundle savedInstanceState) {
         super.onCreate(savedInstanceState);

         // 完整这一行
         PackageInstaller packageInstaller = getPackageManager().getPackageInstaller();

         // 拿到packageInstaller之后，就可以创建会话
         PackageInstaller.SessionParams params = new PackageInstaller.SessionParams(
                  PackageInstaller.SessionParams.MODE_FULL_INSTALL);
         try {
               int sessionId = packageInstaller.createSession(params);
         } catch (IOException e) {
               e.printStackTrace();
         }
      }
   }
      
   ```

### 服务端 PackageInstallerService.createSession 核心源码片段

```java
// PackageInstallerService.java
public int createSession(SessionParams params, String installerPackageName,
        int userId) throws IOException {
    // 权限校验：校验调用者是否拥有安装包权限
    checkCreateSessionPermission(installerPackageName, userId);

    // 分配全局唯一sessionId
    final int sessionId = allocateSessionIdLocked();

    // 创建会话专属staging目录：/data/app-staging/<sessionId>/
    final File stagingDir = getStagingDir(sessionId);
    if (!stagingDir.mkdirs()) {
        throw new IOException("Failed to create staging dir " + stagingDir);
    }

    // 构造PackageInstallerSession对象，保存会话信息
    final PackageInstallerSession session = new PackageInstallerSession(
            this, mPm, params, sessionId, stagingDir, installerPackageName, userId);

    // 存入内存会话表，mSessions：SparseArray<PackageInstallerSession>
    synchronized (mSessions) {
        mSessions.put(sessionId, session);
    }

    // 调用installd，设置staging目录权限、SELinux上下文
    mPm.mInstaller.createStagingDir(stagingDir.getAbsolutePath(), userId);

    // 持久化会话元数据，写入 /data/system/package_installer_sessions.xml
    writeSessionsLocked();

    return sessionId;
}
```

#### 细节解读

1. **权限校验**：PIS校验调用App是否拥有`REQUEST_INSTALL_PACKAGES`，不通过直接抛异常；
2. `allocateSessionIdLocked()`：自增分配唯一sessionId，防止多安装任务冲突；
3. `getStagingDir(sessionId)`：目录路径固定：`/data/app-staging/${sessionId}`>

> staging目录是**独立隔离目录，一个安装任务一个目录**，多包（split）全部放这个目录下；

4. `mPm.mInstaller`：就是PMS里面的Installer（Java代理类），**通过Socket和installd(native)通信**；
`createStagingDir` 下发指令给installd，创建目录、chmod、chown、设置selinux标签；
5. 内存缓存 `mSessions` 保存所有活跃会话；同时持久化会话信息到`package_installer_sessions.xml`，防止系统重启丢失会话；
6. 返回sessionId给上层调用方，**后续所有文件写入操作都必须携带sessionId**。

>
> 此时会话状态：`STATE_OPEN`，允许写入APK文件；还没有任何APK。

## 阶段1-2：打开Session，写入APK文件（上传拷贝）

### 应用侧代码

```java
// 通过sessionId打开会话
try (PackageInstaller.Session session = packageInstaller.openSession(sessionId)) {
    // 在会话目录创建base.apk，返回输出流
    try (OutputStream out = session.openWrite("base.apk", 0, apkFile.length())) {
        // 本地源文件（应用市场私有缓存目录）拷贝到staging
        Files.copy(apkFile.toPath(), out);
    }

    // 如果是split分包，可以继续 openWrite("split_config_arm64.apk", ...)
}
```

`session.openWrite(name, offset, size)`：支持断点写入，offset支持续传，这是旧版本installPackage不具备的能力。

### 服务端核心实现 PackageInstallerSession.openWrite

```java
// PackageInstallerSession.java
public OutputStream openWrite(String name, long offset, long length) throws IOException {
    // 状态校验：必须STATE_OPEN才能写入，commit之后禁止写入
    synchronized (this) {
        if (mState != STATE_OPEN) {
            throw new SecurityException("Session not open");
        }
    }
    // 目标文件：/data/app-staging/sessionId/base.apk
    final File target = new File(mStagingDir, name);
    // 随机访问文件，支持offset断点续写
    final RandomAccessFile raf = new RandomAccessFile(target, "rw");
    raf.seek(offset);
    return new FileOutputStream(raf.getFD());
}
```

#### 细节解读

1. **状态机强校验**：会话一旦commit，状态不再是STATE_OPEN，再次openWrite直接抛异常，防止篡改；
2. 支持多文件写入：base.apk + 多个split apk，全部写入同一个staging会话目录；
3. 是**数据拷贝**，不是move。应用市场源APK还保存在自己私有`/data/data/xxx/cache`目录；
4. 文件句柄跨Binder传递，框架完成数据流转发；
5. 每写完一个APK，PIS会记录该文件大小，做基础长度校验。

>
> adb install 的场景：
> adb -> adbd进程，adbd调用PackageInstaller，同样走这套Session创建+openWrite写入staging，逻辑和应用市场完全一致。

## 阶段1-3：文件写入完成，轻量基础校验

>
> ⚠️【重要】**阶段1只做轻量文件校验，不解析AndroidManifest，不做V2/V3签名校验**
> 校验内容：

1. 文件读写完整性：检查写入后的文件size是否和预期size匹配，判断文件是否截断；
2. 文件类型基础校验：校验是否是合法ZIP文件头（仅简单校验文件魔数，不完整解析ZIP）；
3. 权限刷新：再次调用installd（socket），给新写入的APK设置正确uid/gid、SELinux标签；
4. 检查staging目录剩余磁盘空间。

源码调用位置：在`session.commit()`内部前置校验逻辑

```
// PackageInstallerSession.java commit前置校验片段
private void verifyFiles() throws IOException {
    for (File f : mStagingDir.listFiles()) {
        // 检查文件是否可读
        if (!f.canRead()) {
            throw new IOException("File " + f + " cannot be read");
        }
        // 校验文件大小
        final long actualSize = f.length();
        if (actualSize == 0) {
            throw new IOException("Empty file found in staging");
        }
        // 简单校验ZIP魔数 0x504B
        try (RandomAccessFile raf = new RandomAccessFile(f, "r")) {
            int magic = raf.readInt();
            if (magic != 0x04034B50) {
                throw new IOException("Not a zip file");
            }
        }
    }
}
```

仅仅校验zip文件头，**不遍历zip条目，不读取APK签名块，不做V2/V3验签**。

## 阶段1-4：会话 commit / abandon（提交或取消）

### 上层代码 commit

```
// 提交会话，传入PendingIntent，安装结果回调
PendingIntent pendingIntent = PendingIntent.getBroadcast(context,
        0, new Intent("INSTALL_COMPLETE"), PendingIntent.FLAG_IMMUTABLE);
session.commit(pendingIntent.getIntentSender());
```

### commit 服务端核心逻辑

```
// PackageInstallerSession.java
public void commit(IntentSender statusReceiver) {
    synchronized (this) {
        if (mState != STATE_OPEN) {
            throw new IllegalStateException("Can't commit session, state:" + mState);
        }
        // 修改状态：STATE_OPEN → STATE_COMMITTING
        mState = STATE_COMMITTING;
    }
    mStatusReceiver = statusReceiver;
    try {
        // 1. 执行文件基础校验 verifyFiles()
        verifyFiles();
        // 2. 锁定目录，禁止继续写入
        lockStagingDir();
        // 3. 把本次安装任务交给PMS，进入正式安装流程（阶段2）
        mPm.installStage(mStagingDir, mParams, mUserId, this);
    } catch (Exception e) {
        // 异常则自动abandon，删除staging目录
        abandon();
    }
}
```

### abandon取消安装（中断场景）

```
public void abandon() {
    synchronized (this) {
        if (mState == STATE_ABANDONED) return;
        mState = STATE_ABANDONED;
    }
    // 调用installd 删除整个staging会话目录
    mPm.mInstaller.rmdir(mStagingDir.getAbsolutePath());
    synchronized (mPis.mSessions) {
        mPis.mSessions.remove(mSessionId);
    }
    mPis.writeSessionsLocked();
}
```

#### commit / abandon 关键点

1. commit：只是**文件上传阶段结束**，切换状态为COMMITTING，把staging目录交给PMS开始阶段2（解析、V2/V3签名校验）；
2. abandon：无论创建会话后任意阶段取消，直接调用installd删除整个`/data/app-staging/sessionId`目录，清理所有临时文件，会话从内存和xml中移除；
3. 安装失败（阶段2校验失败），PMS内部也会自动触发类似abandon清理staging目录。

## 阶段1完整时序图

```
【应用市场App】
    ↓ Binder IPC PackageInstaller.createSession()
【PackageInstallerService(SystemServer)】
    权限校验 → 分配sessionId → 创建/data/app-staging/sessionId目录
    → 调用installd(socket)设置目录权限 → 存入mSessions + 持久化xml
    ↓ 返回sessionId
【应用市场】拿到sessionId，openSession，openWrite写入base.apk / split apk
    ↓ Binder写入文件到staging目录
【PackageInstallerSession】记录文件信息，基础文件size/zip魔数校验
    ↓ 上层调用session.commit()
【PackageInstallerSession】
    状态改为STATE_COMMITTING → verifyFiles文件校验 → lock目录
    → 调用PMS.installStage()，移交任务给PMS
    ======阶段1结束，进入阶段2 APK解析+V2/V3签名校验======
```

| 对比项 | Android7及更早（旧installPackage） | Android O+ Session安装方案 |
| --- | --- | --- |
| API入口 | installPackage（废弃） | PackageInstaller + createSession / openWrite / commit |
| 临时目录 | `/data/local/tmp` | `/data/app-staging/<sessionId>`，每个任务独立目录 |
| 分包支持 | 不支持split apk | 原生支持base+多split分批上传 |
| 断点续传 | 无 | 支持openWrite指定offset续传大APK |

| 文件写入和安装 | 上传和安装耦合，一次性串行执行 | 上传阶段（阶段1）和解析校验安装（阶段2）解耦 |
| 失败清理 | 容易残留临时文件 | abandon自动调用installd删除整个staging目录，干净清理 |
| 会话持久化 | 不持久化 | 写入package_installer_sessions.xml，保留会话信息 |

# 四、高频面试考点 & 易错细节

1. `createStagingDir`、`rmdir` 是PMS的Installer代理通过**socket**和installd通信，**不是Binder**；
2. staging目录`/data/app-staging`只是临时目录，**校验全部成功后，才迁移APK到最终/data/app目录**；校验失败直接删除staging；
3. 阶段1只校验zip魔数、文件大小；**V2/V3签名校验、AndroidManifest解析全部在阶段2**；
4. Session有严格状态机：`STATE_OPEN`（可写） → `STATE_COMMITTING` → 成功/失败；commit之后禁止写入；
5. 旧版本没有状态机，没有分包能力，上传安装耦合；Android O引入Session的核心目的：支持Split APK、大文件断点续传、安装任务隔离；
6. adb install底层在新版本也是走这套PackageInstaller Session，不是旧installPackage。

# 源码拆解：`PackageInstaller packageInstaller = getPackageManager().getPackageInstaller();`

> 源码基线：AOSP Android13
> 结论先行：
> `getPackageManager()` 返回 `ApplicationPackageManager` 实例；
> `ApplicationPackageManager.getPackageInstaller()` 返回 **`PackageInstaller` 本地客户端对象**（应用侧封装，内部持有Binder代理 `IPackageManager`，后续通过它跨进程调用SystemServer里面的`PackageInstallerService`）。

## 完整可运行Demo代码片段（应用侧）

```java
import android.content.pm.PackageInstaller;
import android.os.Bundle;
import androidx.appcompat.app.AppCompatActivity;

public class InstallDemoActivity extends AppCompatActivity {

        super.onCreate(savedInstanceState);

        // 完整这一行
        PackageInstaller packageInstaller = getPackageManager().getPackageInstaller();

        // 拿到packageInstaller之后，就可以创建会话
        PackageInstaller.SessionParams params = new PackageInstaller.SessionParams(
```

## 第一层：`getPackageManager()` 拿到什么

```java
// Context.java
public abstract PackageManager getPackageManager();
```

`Context`的抽象方法，**Activity继承Context**，所以可以直接调用`getPackageManager()`。

**实际返回实现类：`ApplicationPackageManager`**

```java
// ApplicationPackageManager.java
// frameworks/base/core/java/android/app/ApplicationPackageManager.java
public class ApplicationPackageManager extends PackageManager {
    // 内部持有IPackageManager Binder代理
    private final IPackageManager mPM;

    protected ApplicationPackageManager(ContextImpl context, IPackageManager pm) {
        mContext = context;
        mPM = pm; // pm就是IPackageManager.Stub.Proxy，PMS的Binder代理
    }
}
```

- `PackageManager`：**抽象父类（API对外接口）**
- `ApplicationPackageManager`：**框架内部的具体实现类**
- `mPM`：`IPackageManager` Binder代理，用来跨进程访问PMS（SystemServer进程）

> 一句话：`getPackageManager()` 返回 `ApplicationPackageManager` 对象，内部封装了PMS的Binder代理`IPackageManager`。

## 第二层：`ApplicationPackageManager.getPackageInstaller()`

```java
// ApplicationPackageManager.java
@Override
public PackageInstaller getPackageInstaller() {
    synchronized (this) {
        if (mPackageInstaller == null) {
            // 实例化应用侧PackageInstaller客户端
            mPackageInstaller = new PackageInstaller(this);
        }
        return mPackageInstaller;
    }
}
```

- `mPackageInstaller`：**应用侧的PackageInstaller客户端对象（本地对象，不是跨进程服务！）**
- 构造传入`this`，也就是当前`ApplicationPackageManager`实例，让PackageInstaller内部可以拿到`IPackageManager` Binder代理。

## 第三层：`PackageInstaller` 类内部

```java
// frameworks/base/core/java/android/content/pm/PackageInstaller.java
public class PackageInstaller {
    private final PackageManager mPm; // 就是ApplicationPackageManager

    // 构造函数
    PackageInstaller(PackageManager pm) {
        mPm = pm;
    }

    // 创建会话方法，内部会通过mPm拿到IPackageManager，Binder调用PMS
    public int createSession(SessionParams params) throws IOException {
        return createSession(params, null, getUserId());
    }

    private int createSession(SessionParams params, String installerPackageName, int userId)
            throws IOException {
        try {
            // 底层通过IPackageManager Binder调用PMS的方法
            return mPm.getIPackageManager().createSession(params, installerPackageName, userId);
        } catch (RemoteException e) {
            throw e.rethrowAsIOException();
        }
    }
}
```

### 重点区分（非常容易混淆）

1. **应用端 `PackageInstaller`**：普通本地Java对象，运行在**应用市场App进程**，只是API封装，**不是Binder服务**。
2. **服务端 `PackageInstallerService`**：运行在 **SystemServer进程**，属于PMS内部的服务，**真正干活的Binder服务**。

> 调用链路：
> App进程 `PackageInstaller`(客户端API)
> → `ApplicationPackageManager`
> → `IPackageManager` Binder代理
> → SystemServer里 PMS → PackageInstallerService

## 第四层：IPackageManager.aidl（AIDL定义）

```aidl
// frameworks/base/core/java/android/content/pm/IPackageManager.aidl
interface IPackageManager {
    int createSession(in PackageInstaller.SessionParams params,
            in String installerPackageName, int userId);
    // ...其他PMS接口
}
```

`IPackageManager`是PMS对外的Binder接口，`createSession`是新增给PackageInstaller会话安装的接口。

# 整体链路总结（笔记用）

```
Activity.getPackageManager()
    ↓ 返回 ApplicationPackageManager（PackageManager子类）
ApplicationPackageManager.getPackageInstaller()
    ↓ new 一个【应用本地PackageInstaller客户端对象】
PackageInstaller.createSession()
    ↓ 内部通过 ApplicationPackageManager 的 mPM（IPackageManager Binder Proxy）
    ↓ Binder IPC
SystemServer PMS → PackageInstallerService.createSession()
```

# 核心问题回答：这行代码最终获取的是什么？
>
> 获取的是**应用侧本地的PackageInstaller客户端实例**。
> 这个客户端本身不具备任何安装能力，只是封装API，内部持有ApplicationPackageManager，最终依靠`IPackageManager` Binder代理，跨进程调用SystemServer中PMS的PackageInstallerService，完成安装会话创建、文件上传、commit等操作。

# 新旧版本对比（补充到笔记）

- Android7及更早：**没有PackageInstaller类**，直接调用`pm.installPackage()`（IPackageManager里面旧接口）。
- Android O(API26)+：废弃`installPackage`，新增这套`PackageInstaller`客户端 + PackageInstallerService服务端的会话模型。

# 高频面试坑点

❌ 误区：拿到的PackageInstaller是SystemServer里面的远程Binder对象
✅ 正解：**PackageInstaller是App进程内的本地包装对象**；真正跨进程Binder入口是`IPackageManager`。PackageInstaller只是一层API封装。

❌ 误区：PackageInstallerService是独立进程
✅ 正解：PackageInstallerService是PMS的内部组件，运行在SystemServer进程。
