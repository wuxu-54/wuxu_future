# APK完整安装、包解析、校验全流程（Android 高版本，核心参与者：PackageInstaller、PMS、PackageParser、installd）

>
> PMS（PackageManagerService）运行在 **system_server进程**，是包管理核心；`installd` 是独立native守护进程，负责底层文件、dex2oat；**PackageParser负责解析APK，提取AndroidManifest，获取包信息**；签名/完整性校验由PMS调用签名校验模块完成。
> 触发入口：点击APK文件（PackageInstaller）、adb install、应用市场。

## 阶段1：安装会话创建 + APK文件上传/拷贝（PackageInstaller）

1. 用户触发安装，打开系统`PackageInstaller`，申请**安装会话（Session）**，向PMS创建安装session，分配临时目录 `/data/app-staging/`。
2. 将APK文件写入staging临时目录（adb是PC推送到手机；应用市场直接把下载好的apk放入staging）。>

> staging是临时暂存目录，**安装失败直接删除，不会污染正式目录**。

3. 会话准备完成，通知PMS：准备开始安装。>

> 这一步只是文件落地，**还没有解析Manifest，没有校验签名**。

## 阶段2：包信息解析（PackageParser，提取Manifest，获取包信息）

PMS调用`PackageParser`解析staging目录里的APK，**获取包基础信息**，核心解析`AndroidManifest.xml`（二进制AAPT编译后的xml）

1. `AssetManager`加载APK，读取二进制AndroidManifest.xml，XmlPullParser解码二进制标签。
2. 从`<manifest>`标签提取：
   - packageName（包名）、versionCode、versionName、minSdkVersion、targetSdkVersion
   - 应用权限列表`<uses-permission>`
   - 四大组件：Activity/Service/BroadcastReceiver/Provider
   - application标签：icon、label、debuggable、allowBackup等
3. 构建内存`Package`对象，后续PMS会把这个包信息存入内存缓存 + `/data/system/packages.xml`。>

> 对应API `getPackageArchiveInfo` 底层就是走这套PackageParser解析逻辑，**不安装也可以直接解析本地APK拿到包信息**。

4. 初步合法性检查：Manifest格式是否合法，包名是否为空，版本号合法。解析失败 → 直接终止安装，返回`INSTALL_FAILED_INVALID_APK`。

>
> ⚠️ 区分：**解析包信息 ≠ 签名校验**，解析只是读Manifest元数据；签名校验是独立安全环节。

## 阶段3：APK完整性校验 + 签名校验（安全校验核心）

高版本Android优先校验 **v2/v3签名（全文件哈希校验）**，v1只是旧版兜底。v2签名保护整个APK文件（除签名块本身），只要APK任何字节被篡改，哈希校验失败直接拒绝安装

1. **APK文件完整性校验**
 读取APK签名块，计算APK文件哈希，对比签名中保存的摘要；文件被篡改、重新打包、添加资源 → 摘要不一致，安装失败。
2. **数字签名校验**
   - 使用证书里面的公钥，解密签名，验证哈希摘要；确认APK是私钥持有者打包，没有被二次篡改。
   - 读取签名证书信息：证书公钥、证书有效期。
3. **升级安装额外签名校验（覆盖安装）**
 如果设备**已经安装同名包**：
   - 新APK签名证书公钥必须和已安装包一致（默认）；
   - 版本号检查：默认不允许versionCode降级（adb加`-d`才允许debug包降级）。>
   > 签名不一致，覆盖安装直接失败`INSTALL_FAILED_UPDATE_INCOMPATIBLE`。
4. 额外系统规则校验
   - 校验minSdkVersion，不能低于设备系统版本；
   - 校验是否是禁止安装的包（系统黑名单、特权包）；
   - 校验sharedUserId规则：同sharedUserId的包，签名必须一致。

>
> 任何校验失败：直接终止安装，删除staging临时文件，返回错误码。**校验全部通过，才进入文件部署阶段**。

## 阶段4：预安装检查、分配用户ID、权限预处理

PMS继续做业务规则校验：

1. 判断安装类型：全新安装 / 覆盖升级 / 多Split APK（App Bundle）。
2. 分配Linux UID/GID（应用沙盒ID，每个普通应用独立UID）。
3. 处理权限：Manifest声明的权限，标记为未授予；运行时权限需要App运行时再弹窗申请。
4. 预留应用数据目录：`/data/data/包名`（用户私有数据目录）。

## 阶段5：installd执行底层文件操作 + ART dex优化（dex2oat）

PMS通过Binder调用`Installer`，再交给native守护进程`installd`做底层 heavy 操作：

1. 将staging临时目录的APK，移动/复制到正式应用目录 `/data/app/包名/`。
   - 目录权限、SELinux上下文设置，应用只能读写自己目录。
2. 提取APK里的classes.dex，执行 **dex2oat**，编译生成ART的oat/odex文件（预编译AOT），放到`/data/app/包名/oat/`目录。>

> 目的：App启动时不需要实时解释dex，提升启动速度。dex2oat耗时就是安装转圈的主要耗时来源。

3. 创建应用私有数据目录 `/data/data/包名`，设置目录权限。

## 阶段6：PMS持久化包信息、内存缓存更新

1. PMS把PackageParser解析出来的包信息（包名、版本、组件列表、签名证书、权限、安装路径）写入持久化文件：
   - `/data/system/packages.xml`：所有已安装应用主清单
   - `/data/system/packages.list`：记录包名和对应的UID
2. 更新PMS内存中的包缓存表，后续`PackageManager`查询已安装应用信息，直接读取内存缓存。>

> 开机的时候PMS会扫描packages.xml，重建内存里所有包信息。

## 阶段7：系统广播通知 + Launcher更新图标

1. PMS发送系统广播 `Intent.ACTION_PACKAGE_ADDED`（全新安装） / `ACTION_PACKAGE_REPLACED`（覆盖升级）。
2. Launcher（桌面应用）收到广播，读取PMS中该应用的icon、label，在桌面添加应用图标。
3. 通知PackageInstaller安装成功，结束安装会话，清理临时资源。

## 阶段8：应用运行时，获取包信息的流程（getPackageInfo / getApplicationInfo）

应用通过`Context.getPackageManager()`拿到`PackageManager`（ApplicationPackageManager，本地代理），底层走Binder调用PMS：

1. App调用`getPackageInfo(packageName, flags)`。
2. Binder跨进程请求system_server里PMS。
3. PMS查询内存缓存（packages.xml加载到内存），组装PackageInfo对象（版本、权限、组件、签名信息）。
4. 通过Parcel序列化返回给App。>

> flags可以控制是否返回权限、签名、组件信息；`GET_SIGNATURES`可以拿到证书。

# 关键目录汇总

- 临时安装：`/data/app-staging/`
- APK本体：`/data/app/<包名>/base.apk`
- ART编译产物：`/data/app/<包名>/oat/`
- App私有数据：`/data/data/<包名>/`
- PMS包数据库：`/data/system/packages.xml`、packages.list

# 高频面试要点（精简背诵）

1. **PackageParser：负责解析AndroidManifest，提取包名、版本、四大组件、权限等包信息；解析不等于签名校验。**
2. **签名校验在PMS中执行，v2/v3校验整个APK文件哈希，篡改直接失败；覆盖安装必须签名一致。**
3. **installd是独立native进程，负责文件移动、目录创建、dex2oat编译，PMS通过Installer代理Binder调用installd。**
4. packages.xml持久化保存所有已安装包元信息；开机PMS扫描该文件加载全部包信息。
5. 安装时序：会话创建 → 拷贝apk到staging → PackageParser解析Manifest获取包信息 → 完整性+签名校验 → installd部署文件+dex2oat → PMS写入packages.xml + 更新内存缓存 → 发广播通知Launcher。

# 常见误区

❌ 解析Manifest的时候做签名校验 → **错。先解析Manifest拿到基础信息，之后单独做签名完整性校验。**
❌ dex2oat是PMS Java层执行 → **错，dex2oat由installd（native）调用。**
❌ APK安装后，每次获取包信息都重新解析APK文件 → **错。只安装时解析一次，之后读PMS内存缓存/packages.xml。**
❌ adb install直接拷贝apk到/data/app → **错，先放到staging临时目录，全部校验通过，才迁移到正式目录。**
