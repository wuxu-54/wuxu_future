# Android Handler 完整实现原理详解

> 
> 适用：Android 主线程消息机制，`Handler + Looper + MessageQueue + Message` 整套模型。
> ⚠️ 注意：Android 消息机制在 API 29 之后有部分改动，底层 MessageQueue 是 C++ 实现。

- [ThreadLocal](/3.程序/1.基础/2.基础语言/java/2.进阶/异步/4.1.ThreadLocal.md)

## 一、整体作用

Android 主线程（UI线程）不能执行耗时操作，子线程**不能直接更新UI**。
`Handler` 核心作用：**跨线程消息通信**。

- 子线程通过 Handler 发送消息；
- 主线程的 Looper 循环取出消息，交给 Handler 在主线程执行。

核心四件套：

1. **Message**：消息载体，存放数据、回调、target（目标Handler）
2. **MessageQueue**：消息队列，存放Message，底层C++实现
3. **Looper**：消息循环器，不断从MessageQueue取消息，分发给Handler
4. **Handler**：消息发送+消息处理

## 二、类之间关系

```
Handler --sendMessage--> MessageQueue
        <--dispatchMessage-- Looper (loop()循环读取队列)
```

1. 一个**线程只能有一个 Looper**（ThreadLocal存储）
2. 一个 Looper 绑定一个 MessageQueue
3. 一个 MessageQueue 可以被**多个Handler共用**
4. 每个 Message 持有 target，指向发送它的那个 Handler

> 
> 主线程 Activity 启动时，`ActivityThread.main()` 会初始化主线程Looper。

## 三、源码分步解析

### 1. Looper（消息循环）

#### 1.1 创建Looper

```
// Looper.java
private static final ThreadLocal<Looper> sThreadLocal = new ThreadLocal<Looper>();

private Looper(boolean quitAllowed) {
    mQueue = new MessageQueue(quitAllowed);
    mThread = Thread.currentThread();
}

// 在当前线程创建Looper
public static void prepare() {
    prepare(true);
}

private static void prepare(boolean quitAllowed) {
    if (sThreadLocal.get() != null) {
        throw new RuntimeException("Only one Looper may be created per thread");
    }
    sThreadLocal.set(new Looper(quitAllowed));
}
```

- `ThreadLocal`：保证每个线程独立持有自己的Looper，线程隔离。
- 主线程：`Looper.prepareMainLooper()`，`quitAllowed=false`，主线程不允许退出Looper。
- 子线程手动使用Handler必须调用：

```
new Thread(){
    @Override
    public void run() {
        Looper.prepare(); // 创建Looper+MessageQueue
        Handler handler = new Handler();
        Looper.loop();   // 开启循环
    }
}.start();
```

#### 1.2 Looper.loop() 核心循环

```
public static void loop() {
    final Looper me = myLooper();
    if (me == null) {
        throw new RuntimeException("No Looper; Looper.prepare() wasn't called on this thread.");
    }
    final MessageQueue queue = me.mQueue;

    for (;;) { // 死循环
        // 从队列取出message，next()是阻塞方法
        Message msg = queue.next(); 
        if (msg == null) {
            // msg==null 代表消息队列退出，跳出循环
            return;
        }

        try {
            // 关键：交给msg.target（就是handler）处理消息
            msg.target.dispatchMessage(msg);
        } finally {
            // ...
        }
        // 回收消息
        msg.recycleUnchecked();
    }
}
```

重点：

- `queue.next()`：**阻塞方法**，队列无消息时，线程休眠，不占用CPU；有消息唤醒。
- `msg.target.dispatchMessage(msg)`：消息交给Handler处理，**执行在Looper所在线程**（主线程）。
- loop是死循环，但不是卡死：底层依靠Linux的epoll监听fd，无消息阻塞等待。

### 2. MessageQueue（消息队列，C++底层）

Java层只是封装，**核心逻辑在native层（C++）**

```
MessageQueue(boolean quitAllowed) {
    mQuitAllowed = quitAllowed;
    mPtr = nativeInit(); // 创建NativeMessageQueue
}
```

两个核心native方法：

1. `nativePollOnce(ptr, timeoutMillis)`：`next()`内部调用，阻塞等待消息，epoll实现
2. `nativeWake(ptr)`：唤醒阻塞的队列

#### 入队 enqueueMessage

Handler发送消息最终调用 `MessageQueue.enqueueMessage`

```
boolean enqueueMessage(Message msg, long when) {
    if (msg.target == null) {
        throw new IllegalArgumentException("Message must have a target.");
    }
    synchronized (this) {
        if (msg.isInUse()) {
            throw new IllegalStateException(msg + " This message is already in use.");
        }
        msg.markInUse();
        msg.when = when;
        Message p = mMessages;
        boolean needWake;
        // 按时间when排序插入队列，不是FIFO！
        if (p == null || when == 0 || when < p.when) {
            // 插到队头
            msg.next = p;
            mMessages = msg;
            needWake = mBlocked;
        } else {
            // 遍历链表，找到合适位置插入
            needWake = mBlocked && p.target == null && msg.isAsynchronous();
            Message prev;
            for (;;) {
                prev = p;
                p = p.next;
                if (p == null || when < p.when) {
                    break;
                }
                if (needWake && p.isAsynchronous()) {
                    needWake = false;
                }
            }
            msg.next = p;
            prev.next = msg;
        }
        if (needWake) {
            nativeWake(mPtr); // 唤醒
        }
    }
    return true;
}
```

> 
> ✅ 关键点：MessageQueue**不是普通队列，是单向链表**，消息按执行时间`when`排序。postDelay就是修改when。

### 3. Message 消息对象

```
public final class Message implements Parcelable {
    public int what; // 消息类型标记
    public Object obj;
    public Bundle data;
    long when; // 执行时间
    Runnable callback; // post传入的Runnable
    Handler target; // 消息所属Handler
    Message next; // 链表下一个节点

    // 消息池复用，避免频繁new对象
    private static Message sPool;
    public static Message obtain() { ... }
    public void recycle() { ... }
}
```

- `obtain()`：从消息池拿复用对象，减少GC；不推荐直接new Message
- `recycle()`：用完放回消息池

### 4. Handler（发送+处理消息）

#### 4.1 构造方法

```
// 默认构造，绑定当前线程Looper
public Handler() {
    this(null, false);
}

public Handler(Callback callback, boolean async) {
    // ... 省略内存泄漏警告日志
    mLooper = Looper.myLooper();
    if (mLooper == null) {
        throw new RuntimeException(
            "Can't create handler inside thread " + Thread.currentThread()
                    + " that has not called Looper.prepare()");
    }
    mQueue = mLooper.mQueue;
    mCallback = callback;
    mAsynchronous = async;
}
```

Handler持有：Looper、MessageQueue、Callback。

#### 4.2 发送消息 sendMessage / post

所有发送方法最终都会走到 `sendMessageAtTime`

```
public boolean sendMessageAtTime(Message msg, long uptimeMillis) {
    MessageQueue queue = mQueue;
    if (queue == null) {
        RuntimeException e = new RuntimeException(
                this + " sendMessageAtTime() called with no mQueue");
        Log.w("Looper", e.getMessage(), e);
        return false;
    }
    msg.target = this; // 关键！给message绑定当前handler
    return queue.enqueueMessage(msg, uptimeMillis);
}
```

- `post(Runnable r)`：内部把Runnable赋值给message.callback
- `postDelay(r, delay)`：uptimeMillis = SystemClock.uptimeMillis() + delay

#### 4.3 消息分发 dispatchMessage

Looper拿到msg后调用 `msg.target.dispatchMessage(msg)`

```
public void dispatchMessage(@NonNull Message msg) {
    if (msg.callback != null) {
        // post(Runnable)走这里，执行run()
        handleCallback(msg);
    } else {
        if (mCallback != null) {
            // Handler构造传入Callback
            if (mCallback.handleMessage(msg)) {
                return;
            }
        }
        // 子类重写handleMessage
        handleMessage(msg);
    }
}
```

执行优先级：
`msg.callback(Runnable)` > Handler的Callback > 重写`handleMessage()`

```
public void handleMessage(@NonNull Message msg) {
    // 空方法，子类重写
}
```

## 四、核心机制细节

### 1. 阻塞原理（epoll）

MessageQueue.next() 调用 `nativePollOnce`，底层 Linux epoll：

- 有消息：返回message
- 无消息：阻塞，释放CPU，等待fd事件唤醒
当插入消息到队头，调用`nativeWake`写管道，epoll被唤醒。> 
> loop死循环不会ANR，ANR是**主线程消息处理超时**，不是loop循环本身。

### 2. 同步屏障 SyncBarrier（重要）

Message里有同步/异步消息：

- **同步消息**：普通handler消息
- **异步消息**：async=true，如View的绘制消息（`ViewRootImpl`）

同步屏障：往队列插入target=null的消息，标记屏障。
遇到屏障时，Looper会跳过所有**同步消息**，优先处理异步消息。

> 
> 作用：保证UI绘制优先执行。

### 3. IdleHandler

MessageQueue.IdleHandler，队列空闲（没有消息）时回调，例如`ViewTreeObserver`。

## 五、常见问题

### 1. 为什么主线程可以new Handler？

`ActivityThread.main()`

```
public static void main(String[] args) {
    Looper.prepareMainLooper();
    ActivityThread thread = new ActivityThread();
    thread.attach(false, null);
    Looper.loop();
}
```

App启动就prepare主线程Looper，所以主线程直接new Handler不用手动prepare。

### 2. Handler内存泄漏原因

- Handler是非静态内部类，隐式持有外部Activity引用；
- Message持有target=handler；
- 消息长时间没执行，MessageQueue持有Message，间接持有Activity，页面销毁无法GC。

✅ 解决方案：静态Handler + 弱引用WeakReference；页面销毁removeCallbacksAndMessages。

### 3. postDelay 精准吗？

不绝对精准。`when`是消息**准备被取出的时间**，不是立即执行时间。
如果前面有其他消息排队，会延后。

### 4. quit() 和 quitSafely()

- `quit()`：直接清空所有消息，不安全
- `quitSafely()`：只移除未执行消息，正在执行的消息执行完再退出

主线程Looper不能quit。

## 六、整体流程一句话总结

1. 子线程调用handler.sendMessage，消息封装Message，绑定target=handler；
2. MessageQueue按时间排序插入链表；
3. Looper.loop()不断调用MessageQueue.next()，无消息时epoll阻塞；
4. 到时间取出Message，调用msg.target.dispatchMessage；
5. 在Looper所在线程（主线程）执行回调/handleMessage；
6. 消息执行完毕，Message回收放入消息池复用。

## 七、API 29+ 改动补充

Android 10 后引入 `Handler.createAsync()`，异步Handler，不受同步屏障限制；同时增加很多校验。
另外推荐使用 `View.post()` / `postOnAnimation()`，本质也是Handler。
