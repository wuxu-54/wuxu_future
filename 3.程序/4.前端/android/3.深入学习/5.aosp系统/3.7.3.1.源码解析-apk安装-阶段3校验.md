# 阶段3：APK完整性校验 + 签名校验（PMS内执行，PackageParser解析完成之后）
>
> 前置条件：
>
> 1. APK已经放到 `/data/app-staging` 临时目录；
> 2. PackageParser解析APK成功，拿到Package内存对象；
> 3. **本阶段不属于PackageParser工作**，是PMS单独的安全校验环节；
> 4. Android推荐优先V2/V3签名，V1是旧版JAR签名兜底。
>
> 核心目标：确认APK文件**没有被篡改**、确认**签名证书可信**；覆盖安装时还要校验新旧包签名一致性。
> 任何一项校验失败 → 直接终止安装，删除staging目录，返回安装失败码。

## 3.1 先理解APK签名块（APK Signing Block）

V2/V3签名是在APK（ZIP）文件末尾，追加一块独立的 **APK Signing Block**（签名块），和ZIP中央目录相邻。

- 签名块里面存储：APK文件的哈希摘要、签名、证书链、签名算法信息。
- V2：对**除签名块本身以外整个APK全部字节**做哈希；只要APK里任何资源、dex被修改，哈希立刻对不上。
- V1（JAR签名）：只对APK内每个文件单独做摘要（META-INF里MANIFEST.MF、CERT.SF、CERT.RSA）；**不会校验ZIP目录本身**，存在漏洞，只能兜底。
- V3：在V2基础上增加**证书轮换**支持，可以升级签名证书，覆盖安装不需要保持旧证书。

> 校验顺序：优先检测是否存在V3签名 → 有就走V3校验；没有V3就检测V2；V2不存在才降级走V1。

## 3.2 步骤1：读取APK签名块，选择签名版本

PMS调用系统签名校验库（`apksig`，native层）：

1. 读取APK文件末尾，查找APK Signing Block；
2. 判断签名版本：V3 / V2 / V1；
3. 如果V2/V3签名存在，**不会信任V1签名**（高版本Android安全策略）。
4. 如果签名块损坏、找不到合法签名信息 → 直接失败：`INSTALL_FAILED_INVALID_APK`。

## 3.3 步骤2：文件完整性校验（哈希校验）

以V2举例：

1. 按照V2签名规则，把APK划分为若干区域，**排除签名块本身**；
2. 逐段计算文件内容的哈希（SHA256/SHA512）；
3. 和签名块中预先保存的**原始哈希摘要对比**。

✅ 一致：文件内容完整，没有被篡改。
❌ 不一致：APK被修改、二次打包、资源替换、dex篡改 → 校验失败，拒绝安装。

> V1完整性校验逻辑不一样：遍历APK内所有文件，读取MANIFEST.MF里每个文件的摘要，逐个校验文件，**不校验ZIP元信息**。

## 3.4 步骤3：数字签名校验（验证证书、验签）

完整性只是确认文件哈希没变；**数字签名用来确认这个哈希摘要是私钥持有者生成的**，不是别人伪造的。

1. 从签名块取出**签名证书链（公钥证书）**；
2. 使用证书里面的**公钥**，解密签名数据，还原出原始摘要；
3. 对比：前面计算得到的APK文件哈希 == 解密得到的摘要。
    - 相等：验签通过，证明APK是持有对应私钥的开发者打包；
    - 不等：签名伪造，安装失败。
4. 校验证书本身基础属性：
    - 证书有效期：不能过期；
    - 证书格式合法；
    - 证书链可验证（系统根证书校验，普通自签名应用证书没有CA链，Android允许）。

> 区分两个概念（面试高频）
>
> - **完整性校验**：文件有没有被改（哈希比对）
> - **数字签名验签**：确认这个哈希是谁签的，防止伪造摘要

## 3.5 步骤4：安装类型分支：全新安装 VS 覆盖升级（重点）

### 分支A：全新安装（设备上没有同名包）

只需要通过上面的完整性+验签。
校验成功，把**证书公钥信息保存到内存Package对象**，后续安装成功后写入`packages.xml`永久保存。

### 分支B：覆盖安装（已存在同packageName）

增加额外强校验：

1. 取出系统里已安装包记录的**旧包签名公钥**；
2. 对比新APK证书公钥：
    - V2：新证书公钥必须和旧包完全一致；
    - V3：支持证书轮换，如果在V3签名块里声明了证书轮换历史，允许使用新证书；
3. 版本号检查：默认不允许versionCode降级；adb install -d 才允许debug包降级。

签名不一致 → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（更新不兼容），这是面试高频错误码。

> 注意：对比的是**公钥**，不是证书文字信息。证书可以续期，但只要公私钥对不变，公钥不变，覆盖安装没问题。

## 3.6 步骤5：附加系统规则校验（除签名之外的额外规则）

PMS除签名外，继续做一系列业务合法性检查：

1. minSdkVersion校验：APK的minSdk > 当前设备SDK版本 → 安装失败 `INSTALL_FAILED_OLDER_SDK`；
2. sharedUserId校验：
    如果manifest声明sharedUserId，**同一sharedUserId下所有应用签名必须完全一致**，否则禁止安装；
3. 系统包/特权包校验：系统分区包不允许普通APK替换；
4. 禁止安装黑名单：设备管理、企业策略禁止的包；
5. 版本Code合法性，versionCode不能为负数。

## 3.7 校验结果处理

- ✅ **全部校验通过**：PMS保留证书信息，进入阶段4（分配UID、权限预处理，然后调用installd做文件部署、dex2oat）。
- ❌ **任意校验失败**：终止整个安装流程，删除 `/data/app-staging` 临时APK文件，释放资源，返回对应的错误码给PackageInstaller。

## 3.8 关键面试区分点

1. **PackageParser只解析Manifest，不做签名校验；签名校验是PMS调用apksig库独立执行**；
2. V2/V3保护整个APK文件；V1仅校验APK内部独立文件，ZIP结构可篡改；
3. 完整性（哈希）≠ 数字签名验签，两步是独立；
4. 覆盖安装对比**公钥**，不是证书名称；V3支持证书轮换；
5. 签名证书过期：安装阶段会校验证书有效期，过期APK无法安装（部分旧系统有差异）。

## 3.9 常见错误码

- `INSTALL_FAILED_INVALID_APK`：APK损坏、签名块非法、解析失败
- `INSTALL_FAILED_UPDATE_INCOMPATIBLE`：覆盖安装，新旧签名不一致
- `INSTALL_FAILED_OLDER_SDK`：minSdk高于当前手机系统版本

## 简化时序

```
PackageParser解析APK成功，返回Package对象
        ↓
PMS读取APK签名块，识别V3/V2/V1签名版本
        ↓
完整性校验：计算APK哈希，和签名内摘要对比
        ↓
数字验签：公钥校验签名，验证证书有效性
        ↓
如果是覆盖安装：对比新旧包签名公钥，versionCode检查
        ↓
附加规则校验（minSdk、sharedUserId、黑名单）
        ↓
校验成功 → 进入分配UID阶段；失败 → 删除staging，返回失败
```
