# KeyEvent + 焦点分发 + 寻焦机制（承接上一节 ViewRootImpl InputStage）
>
> 一句话核心区分：
> **Touch事件：按坐标找View；KeyEvent：按【当前焦点View】投递；方向键(Dpad上下左右/Tab)如果焦点View不消费按键，就触发【寻焦(focusSearch)】，去找下一个可聚焦View，然后切换焦点**

## 一、KeyEvent 在 InputStage 链路的完整流程（和触摸共用同一套ViewRootImpl输入管道）

```
InputDispatcher → InputEventReceiver
→ ViewRootImpl.enqueueInputEvent
→ doProcessInputEvents
→ deliverInputEvent
→ InputStage责任链：
EarlyInputStage → ViewPreImeInputStage → ViewInputStage → PostImeInputStage(ViewPostImeInputStage)
```

**KeyEvent 真正业务分发、焦点导航逻辑在：ViewPostImeInputStage.processKeyEvent()**

### KeyEvent 分发顺序（自上而下）

1. `mView(DecorView).dispatchKeyEvent(event)`
    - 先调用 `Activity.dispatchKeyEvent()`
    - 再走 PhoneWindow → DecorView 向下**递归分发到当前焦点View**
    > KeyEvent 不是像Touch那样按坐标遍历，是**从根往下，一直路由到当前持有焦点的View**
2. 回调顺序：
`Activity.dispatchKeyEvent` → DecorView.dispatchKeyEvent → ViewGroup.dispatchKeyEvent → **当前焦点View.dispatchKeyEvent**
    - View内部：`OnKeyListener.onKey()` 优先，再调用 `onKeyDown / onKeyUp`
3. 返回值规则：

- 返回`true`：事件被消费，链路终止，不做焦点跳转
- 返回`false`：**事件未被消费 → 进入【寻焦逻辑】**（Dpad上下左右、Tab才会触发寻焦；返回键、字母键一般不寻焦）

> 重点：**只有方向导航类按键（Dpad_UP/DOWN/LEFT/RIGHT、Tab/Shift+Tab）在没有被消费时，才会执行寻焦，寻找下一个焦点控件**；普通按键如BACK、字母、数字不会触发焦点查找。

## 二、焦点基础概念（先理清）

1. **焦点窗口**：system_server InputDispatcher层面，先找到**焦点Window**，KeyEvent只会发给焦点窗口，没有焦点窗口直接丢弃按键事件
2. **View焦点**：一个Window内同一时刻**最多只有1个View持有焦点**（`view.isFocused() = true`）
3. 可聚焦条件：
    - `view.isFocusable() = true`
    - 可见 `VISIBILITY_VISIBLE`，enabled=true
    - 触摸模式额外要求：`isFocusableInTouchMode=true`，默认普通控件触摸模式下不能获取焦点（Android9+默认页面不会自动分配初始焦点，需要手动`requestFocus()`）
4. 两个关键API
    - `rootView.findFocus()`：从DecorView整棵树**查找当前正在持有焦点的View**，找不到返回null
    - `view.focusSearch(direction)`：**寻焦入口方法，查找该方向下一个候选焦点View**

## 三、寻焦机制（重点）

### 3.1 寻焦触发入口（ViewPostImeInputStage源码逻辑）

```java
// processKeyEvent伪代码
View focused = mView.findFocus(); // 获取当前焦点View
if (focused != null) {
    int direction = keyCode转成方向常量：FOCUS_UP / FOCUS_DOWN / FOCUS_LEFT / FOCUS_RIGHT / FOCUS_FORWARD(Tab) / FOCUS_BACKWARD(Shift+Tab)
    View nextFocus = focused.focusSearch(direction); // 核心寻焦调用
    if (nextFocus != null && nextFocus != focused) {
        nextFocus.requestFocus(); // 让新View获取焦点，旧View自动失去焦点
        return FINISH_HANDLED; // 焦点移动完成，按键事件消费
    }
}
// 找不到下一个焦点，事件继续兜底处理（Activity.onKeyDown）
```

> 关键点：**focusSearch 是逐级向上冒泡查询的**，不是一次性全局遍历。

### 3.2 focusSearch 冒泡调用流程（非常核心）

`focusSearch` 是View/ViewGroup都有的方法，**从当前焦点View开始，一层一层向上找父容器**

1. 当前焦点View调用 `focusSearch(focused, direction)`
    - View的focusSearch默认直接交给父容器 `getParent().focusSearch(this, direction)`
2. 到 ViewGroup 的 `focusSearch()`
    - ① 优先读取xml手动指定：`nextFocusUp/Down/Left/Right`，如果用户写了这个id，直接返回指定View，**跳过自动算法**
    - ② 没有手动指定 → 调用 `FocusFinder.getInstance().findNextFocus(this, focused, direction)`，在**当前ViewGroup的子树内部搜索候选焦点**
    - ③ 如果在自己子树找不到，继续向上调用 `super.focusSearch`，交给上一级父ViewGroup继续查找
3. 一直冒泡到DecorView（根ViewGroup）；根里面找不到，返回null，本次方向导航无法移动焦点

> 一句话：**focusSearch 是向上冒泡，每一层ViewGroup先在自己的子View范围内搜索；找不到就交给外层父布局继续搜索**

### 3.3 FocusFinder 寻焦算法（底层核心）

`FocusFinder` 是单例，负责在给定ViewGroup范围内，收集所有可聚焦View，按几何矩形做距离计算，选出最优候选。
两步：

1. `addFocusables()`：遍历ViewGroup子树，收集**满足可聚焦条件的View**，放入列表，过滤GONE/INVISIBLE、不可focus控件
2. 分两种算法：
    1）**绝对方向算法（上下左右 FOCUS_UP/DOWN…）findNextFocusInAbsoluteDirection**
    - 拿当前焦点View的屏幕矩形 `focusedRect`
    - 筛选：候选View必须在**指定方向一侧**（例如FOCUS_DOWN，候选top必须 >= 当前View bottom）
    - 计算优先级：**优先投影重叠，再计算最短距离**，选出最优View
        > 例：垂直列表，按钮A在上面、B在A下方，按下Dpad_DOWN，优先选B；
        > 如果横向有多个控件在下方，取水平投影重叠最多、距离最近的
    2）**顺序导航算法（Tab / Shift+Tab，FOCUS_FORWARD / FOCUS_BACKWARD）findNextFocusInRelativeDirection**
    - 不看屏幕坐标，**按View树遍历顺序（pre-order前序遍历）排序可聚焦控件**，向前/向后依次切换，适合Tab键盘导航，不受位置影响

> 优先级规则：**xml nextFocusXX > 手动指定 > FocusFinder几何自动算法**

### 3.4 焦点切换完整动作：requestFocus()

找到nextFocus后调用 `nextFocus.requestFocus()`：

1. 旧焦点View：`onFocusChange(false)`，失去焦点
2. 新View：`onFocusChange(true)`，获取焦点
3. 回调父容器 `onRequestChildFocus`，更新整棵树的焦点标记
4. 触发invalidate绘制焦点高亮框

## 四、完整时序举例：按下Dpad_DOWN，焦点从ButtonA → ButtonB

1. KeyEvent(DOWN) 经过InputStage，分发到ButtonA（当前焦点View）
2. ButtonA dispatchKeyEvent 返回 false，**没有消费方向键**
3. ViewPostImeInputStage 拿到当前焦点View：ButtonA
4. ButtonA.focusSearch(FOCUS_DOWN) → 向上冒泡父LinearLayout
5. LinearLayout.focusSearch：没有nextFocusDown属性，调用FocusFinder
6. FocusFinder收集所有子可聚焦View，按方向+距离，找到ButtonB
7. 返回ButtonB，调用 `ButtonB.requestFocus()`
8. ButtonA失去焦点，ButtonB获取焦点；本次Dpad事件被标记消费，结束
9. 如果FocusFinder找不到任何下方控件 → 返回null，焦点不动，事件走到Activity.onKeyDown兜底

## 五、高频面试考点（重点）

1. **KeyEvent投递目标是当前焦点View，不是坐标；Touch是坐标命中View**。这是两类事件最本质区别。
2. **寻焦不是系统自动后台一直遍历树，是【方向按键未被消费时，实时触发focusSearch+FocusFinder查找】**；不按方向键，不会执行寻焦。
3. `focusSearch` 是**向上冒泡**，每层ViewGroup先在自己子空间查找，找不到再抛给父容器。
4. nextFocusUp/Down优先级高于FocusFinder自动几何算法，常用于电视/TV遥控器自定义焦点跳转。
5. findFocus：**自上而下遍历View树，找到当前持有焦点的View**；focusSearch：**查找指定方向下一个候选焦点View**（两个方法别搞混）
6. 触摸模式默认控件不能获取焦点，`focusableInTouchMode=true` 才支持触摸模式焦点；Android9之后页面不会自动给初始焦点，需要手动requestFocus。
7. 焦点只在**同一个窗口内**查找；跨窗口焦点由InputDispatcher/WMS管理，不属于App内focusSearch机制。

## 六、容易踩坑的误区

❌ 误区：KeyEvent从DecorView遍历所有View找目标
✅ 事实：直接路由到**当前已经持有焦点的View**，不需要遍历；只有方向导航才会主动搜索下一个焦点

❌ 误区：FocusFinder会全局遍历整个ViewTree
✅ 事实：focusSearch逐级向上，**每一级只在当前ViewGroup子树搜索**；上层父容器才会扩大搜索范围

❌ 误区：只要按下方向键就一定会移动焦点
✅ 事实：如果当前View消费了事件（return true），直接终止，**完全不会触发寻焦**
