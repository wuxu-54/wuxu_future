# Android 触摸事件完整链路：硬件 → system_server(IMS/WMS) → App进程 → View树

>
> 基于 Android 13/14 源码，**system_server 是 InputManagerService(IMS)、WindowManagerService(WMS) 所在进程**。
> 整体链路：`触摸屏驱动/dev/input → EventHub → InputReader(线程) → InputDispatcher(线程) → InputChannel(socketpair跨进程) → App进程ViewRootImpl → DecorView → ViewGroup → View`

## 总流程图

```
硬件触屏 → /dev/input/eventX
        ↓
【system_server进程 Native】EventHub(epoll监听)
        ↓
【system_server进程 Native】InputReaderThread：读原始事件，封装NotifyMotionArgs，投递给InputDispatcher
        ↓
【system_server进程 Native】InputDispatcherThread：命中测试(hitTest)，查询WMS窗口Z序，找到目标WindowState
        ↓
socketpair（InputChannel）跨进程写入事件
        ↓
【App进程 Native】InputConsumer 读取fd事件，回调Java层 WindowInputEventReceiver
        ↓
【App进程 UI主线程】ViewRootImpl.enqueueInputEvent → doProcessInputEvents → deliverInputEvent → InputStage链（InputStage 责任链最终触发view树的事件 ：**ViewInputStage** → DecorView → 按view树分发，优先是**Activity.dispatchTouchEvent()**）
        ↓
ViewRootImpl 调用 mDecor.dispatchTouchEvent()
        ↓
DecorView(PhoneWindow根View) → ViewGroup.dispatchTouchEvent() （拦截、寻找TouchTarget、递归子View）
        ↓
叶子View.dispatchTouchEvent() → onTouch() / onTouchEvent()
```

特别说明，下面是DecorView的源码：

```java
@Override
public boolean dispatchTouchEvent(MotionEvent ev) {
    if (interceptBackProgress(ev)) {
        return true;
    }
    final Window.Callback cb = mWindow.getCallback();//mWindow获取的callback其实就是Activity，attach时注入到PhoneWindow的
    return cb != null && !mWindow.isDestroyed() && mFeatureId < 0
            ? cb.dispatchTouchEvent(ev) : super.dispatchTouchEvent(ev);
}
```

**DecorView.dispatchTouchEvent（窗口根 View 的分发入口）**

- 收到事件，**先执行 `cb.dispatchTouchEvent(ev)`（Activity.dispatchTouchEvent）**
- 如果 Activity.dispatchTouchEvent 返回 `true`：直接 return true，**事件终止，View 树完全收不到任何事件（Button 也拿不到！）** ✅ 可以全局前置拦截！
- 如果 Activity.dispatchTouchEvent 返回 `false`：DecorView 才会执行 `super.dispatchTouchEvent()`，进入 ViewGroup 分发，交给页面 View 树。

## 阶段细讲

### 一、SystemServer启动IMS（Java层，system_server进程）

```
}
```

nativeStart 会创建 **InputReaderThread、InputDispatcherThread** 两个常驻线程，属于system_server进程。

### 二、Native层：EventHub + InputReader（system_server native）

`frameworks/native/services/inputflinger/reader/InputReader.cpp`
EventHub 通过epoll监听 `/dev/input` 设备节点，读取内核上报的原始坐标、压力、触点信息。
InputReader 循环 `getEvents()`，将原始evdev事件转换成Android MotionEvent，调用 `notifyMotion` 投递给 InputDispatcher。

```
// InputReaderThread 主循环
bool InputReader::threadLoop() {
    RawEvent rawEvent;
    mEventHub->getEvents(&rawEvent, 1); // 阻塞读取内核输入事件

    // 解析原始事件，封装成NotifyMotionArgs
    NotifyMotionArgs args;
    args.action = AMOTION_EVENT_ACTION_DOWN;
    args.x = rawEvent.x;
    args.y = rawEvent.y;
    // ...填充触摸点、压力、事件时间

    mDispatcher->notifyMotion(args); // 投递到InputDispatcher入队
    return true;
}
```

### 三、InputDispatcher：命中测试 + 查找目标窗口（system_server native，核心）

`frameworks/native/services/inputflinger/dispatcher/InputDispatcher.cpp`
InputDispatcher 收到 notifyMotion 后，事件进入 `mInboundQueue`，在 `dispatchOnce()` 循环处理。

>
> 关键：**hitTest 命中测试**，向WMS查询窗口列表（Z-order，从上往下遍历），找到触摸点落在哪个窗口，窗口必须可见、非NOT_TOUCHABLE。
> WMS维护所有WindowState，同步窗口信息给InputDispatcher。

```
void InputDispatcher::notifyMotion(const NotifyMotionArgs& args) {
    std::unique_ptr<EventEntry> newEntry = std::make_unique<MotionEntry>(args);
    bool needWake = enqueueInboundEventLocked(std::move(newEntry));
    if (needWake) {
        mLooper->wake(); // 唤醒InputDispatcher线程
    }
}

// 主线循环
bool InputDispatcher::dispatchOnce() {
    nsecs_t timeout = -1;
    mLooper->pollOnce(timeout);
    dispatchOnceInnerLocked(&timeout);
    return true;
}

void InputDispatcher::dispatchOnceInnerLocked(nsecs_t* timeout) {
    EventEntry* entry = mInboundQueue.front();
    mInboundQueue.pop_front();

    // 触摸DOWN时执行hitTest，找到目标窗口
    if (entry->type == EventEntry::TYPE_MOTION) {
        MotionEntry* motionEntry = static_cast<MotionEntry*>(entry);
        if (motionEntry->action == AMOTION_EVENT_ACTION_DOWN) {
            // hitTest：从顶层窗口往下找，匹配触摸坐标
            findTouchedWindowTargetsLocked(motionEntry, &targets);
        }
        // 将事件放入目标窗口Connection的outbound队列
        enqueueDispatchEntriesLocked(motionEntry, targets);
        startDispatchCycleLocked(currentTime, connection);
    }
}
```

#### InputChannel 跨进程通信原理

App调用 `ViewRootImpl.setView()` 时，会向WMS `addWindow`。
WMS的`WindowState.openInputChannel()` 创建一对`socketpair`：

- server端fd：保存在system_server的InputDispatcher Connection
- client端fd：通过Binder传给App进程，保存到App端`InputChannel`

InputDispatcher 通过socket write把事件发给App进程，App端InputConsumer在fd上epoll监听，收到事件后回调Java层。

>
> **注意：触摸事件不是Binder传递，是socket fd，效率更高。**

### 四、App进程接收事件：ViewRootImpl + WindowInputEventReceiver

`frameworks/base/core/java/android/view/ViewRootImpl.java`
App主线程Looper监听InputChannel的fd，事件到来回调 `onInputEvent`。

```
// ViewRootImpl内部类：接收native层上来的输入事件
final class WindowInputEventReceiver extends InputEventReceiver {
    public WindowInputEventReceiver(InputChannel inputChannel, Looper looper) {
        super(inputChannel, looper);
    }

    @Override
    public void onInputEvent(InputEvent event) {
        // 入队，加入mPendingInputEvent链表
        enqueueInputEvent(event, this, 0, true);
    }
}

void enqueueInputEvent(InputEvent event, InputEventReceiver receiver, int flags, boolean processImmediately) {
    QueuedInputEvent q = obtainQueuedInputEvent(event, receiver, flags);
    // 尾插链表
    if (mPendingInputEventTail == null) {
        mPendingInputEventHead = q;
    } else {
        mPendingInputEventTail.mNext = q;
    }
    mPendingInputEventTail = q;
    mPendingInputEventCount++;

    if (processImmediately) {
        doProcessInputEvents(); // UI线程处理事件
    }
}

void doProcessInputEvents() {
    // 循环处理所有排队输入事件
    while (mPendingInputEventHead != null) {
        QueuedInputEvent q = mPendingInputEventHead;
        mPendingInputEventHead = q.mNext;
        deliverInputEvent(q);
    }
}
```

#### deliverInputEvent 进入InputStage流水线

InputStage是责任链模式：`PreImeInputStage -> ImeInputStage -> PostImeInputStage -> ViewInputStage`
ViewInputStage 最终把事件交给DecorView：

```
private void deliverInputEvent(QueuedInputEvent q) {
    InputStage stage;
    if (q.shouldSkipIme()) {
        stage = mFirstPostImeInputStage;
    } else {
        stage = mFirstInputStage;
    }
    stage.deliver(q);
}

// ViewInputStage 核心，调用DecorView
protected int onProcess(QueuedInputEvent q) {
    if (q.mEvent instanceof MotionEvent) {
        MotionEvent event = (MotionEvent) q.mEvent;
        // 事件交给DecorView（根View）
        boolean handled = mView.dispatchTouchEvent(event);
        return handled ? FINISH_HANDLED : FINISH_NOT_HANDLED;
    }
    return FORWARD;
}
```

`mView` 就是DecorView，PhoneWindow的根视图。

#### 4. ViewGroup.dispatchTouchEvent 【核心源码】

`frameworks/base/core/java/android/view/ViewGroup.java`

```
@Override
public boolean dispatchTouchEvent(MotionEvent ev) {
    boolean handled = false;
    if (onFilterTouchEventForSecurity(ev)) {
        final int action = ev.getAction();
        final int actionMasked = action & MotionEvent.ACTION_MASK;

        // ACTION_DOWN：清空上次触摸目标，重置状态
        if (actionMasked == MotionEvent.ACTION_DOWN) {
            cancelAndClearTouchTargets(ev);
            resetTouchState();
        }

        // 是否拦截事件
        final boolean intercepted;
        if (actionMasked == MotionEvent.ACTION_DOWN || mFirstTouchTarget != null) {
            // 子View调用requestDisallowInterceptTouchEvent 会修改 disallowIntercept
            final boolean disallowIntercept = (mGroupFlags & FLAG_DISALLOW_INTERCEPT) != 0;
            if (!disallowIntercept) {
                intercepted = onInterceptTouchEvent(ev); // 父View拦截回调
                ev.setAction(action);
            } else {
                intercepted = false;
            }
        } else {
            intercepted = true;
        }

        // 取消事件处理
        if (isCanceled) {
            intercepted = true;
        }

        // 没有拦截，遍历子View，寻找TouchTarget
        if (!intercepted) {
            if (actionMasked == MotionEvent.ACTION_DOWN) {
                final int childrenCount = mChildrenCount;
                for (int i = childrenCount - 1; i >= 0; i--) {
                    final View child = getChildAt(i);
                    // 判断子View是否可见，触摸点落在子View区域
                    if (!canViewReceivePointerEvents(child)
                            || !isTransformedTouchPointInView(x, y, child, null)) {
                        continue;
                    }
                    // 子View消费事件，建立mFirstTouchTarget
                    if (child.dispatchTouchEvent(ev)) {
                        newTouchTarget = addTouchTarget(child, idBitsToAssign);
                        break;
                    }
                }
            }
        }

        // 分发事件给TouchTarget子View
        if (mFirstTouchTarget == null) {
            // 没有子View消费，自己处理
            handled = super.dispatchTouchEvent(ev);
        } else {
            // 交给TouchTarget链表处理
            handled = dispatchTransformedTouchEvent(ev, canceled, null,
                    mFirstTouchTarget, idBitsToAssign);
        }
    }
    return handled;
}
```

#### 5. View.dispatchTouchEvent（叶子View）

`frameworks/base/core/java/android/view/View.java`

```
public boolean dispatchTouchEvent(MotionEvent event) {
    boolean result = false;

    if (onFilterTouchEventForSecurity(event)) {
        ListenerInfo li = mListenerInfo;
        // 优先执行 OnTouchListener
        if (li != null && li.mOnTouchListener != null
                && (mViewFlags & ENABLED_MASK) == ENABLED
                && li.mOnTouchListener.onTouch(this, event)) {
            result = true;
        }
        // onTouchListener没消费，调用onTouchEvent
        if (!result && onTouchEvent(event)) {
            result = true;
        }
    }
    return result;
}
```

>
> 优先级：`OnTouchListener.onTouch()` > `View.onTouchEvent()`，onTouchEvent内部会处理`onClick`。

## 六、事件消费与ACK回传（容易忽略）

App消费/不消费事件处理完成后，会通过同一个InputChannel socket，**发送finish信号（ack）给system_server的InputDispatcher**。
InputDispatcher收到ack，才会继续发送下一个触摸事件；如果长时间没有ack → Input ANR。

## 七、关键点总结

1. **InputReader / InputDispatcher 运行在system_server进程，两个独立native线程**；IMS是Java层壳。
2. 事件跨进程不是Binder，是`InputChannel(socketpair)`，内核fd通信，低延迟。
3. 命中测试在InputDispatcher（native），**不是WMS主动推事件**，DOWN事件才会重新hitTest，MOVE/UP复用同一个target窗口。
4. 事件到达App后，在**UI主线程**执行View树分发，所以触摸操作不能阻塞主线程。
5. View分发顺序：`Activity → PhoneWindow → DecorView → ViewGroup递归 → View`；**由外向内分发，消费后逐层return true向上返回**。

## 常见误区澄清

- ❌ WMS直接把触摸事件通过Binder发给App：错，WMS只提供窗口信息给InputDispatcher，事件由InputFlinger socket发送。
- ❌ system_server把MotionEvent序列化通过binder传递：错，socket传递原始事件二进制，App端再构建MotionEvent。
- ❌ MOVE每次都hitTest：错，只有ACTION_DOWN做hitTest，后续MOVE/UP都发给同一个target窗口，除非窗口切换、ACTION_CANCEL。
