# DEX 文件结构 & DEX 与 Class 的关系

## 一、基础概念

- **Class 文件**：Java 编译器（javac）把 `.java` 编译得到 **`.class`**，是**JVM**的可执行文件，运行在 Java 虚拟机，基于**栈式虚拟机**。
- **DEX（Dalvik Executable）**：Android 的 **Dalvik / ART 虚拟机**的执行文件，后缀一般是 `classes.dex`。
  Android 打包时，会把**多个 .class 文件合并、优化**成一个 dex 文件。

> 一句话：**.class 是给JVM；dex 是给Android的Dalvik/ART。**

## 二、DEX 和 Class 的核心区别

1. **虚拟机不同**
    - class → JVM（栈虚拟机）
    - dex → Dalvik/ART（寄存器虚拟机）
2. **文件数量**
    - 一个 `.class` 只对应**一个Java类**（内部类会单独生成class）
    - 一个 `.dex` 可以存放**成千上万个类**，合并多个class而来
3. **指令集**
    - class：JVM字节码
    - dex：Dalvik字节码（smali就是dex的汇编文本）
4. **常量池**
    - class：每个class**独立常量池**，多个class会有大量重复字符串、类名
    - dex：**全局唯一常量池**，所有类共享，大幅减少冗余，这是dex体积更小的关键
5. **运行方式**
    - JVM：直接加载class解释/JIT
    - Android：早期Dalvik解释dex；ART采用AOT预编译，安装时把dex转成oat/odex本地机器码

## 三、DEX 文件整体结构

dex是**连续二进制文件**，头部 + 多个区域（都是偏移+长度引用），整体分为：

```
dex header（头部）
string_ids 字符串索引表
type_ids   类型索引表（类、接口类型）
proto_ids  方法原型索引表（方法签名）
field_ids  字段索引表
method_ids 方法索引表
class_defs 类定义表（核心！描述每个类）
data       数据区（存放字节码、注解、静态值等）
link_data  链接数据区
```

### 1. dex header（头部，固定0x70字节）

记录整个dex基础信息：

- magic：`dex\n035\0` 标识dex版本
- checksum：校验和
- signature：SHA-1签名
- file_size：整个dex文件大小
- header_size：头部大小固定0x70
- endian_tag：大小端标记
- 后面一堆偏移和数量：string_ids_off、string_ids_size、type_ids_off……

> 所有后面的表，都由header里的`xxx_off`（起始偏移）和`xxx_size`（条目数量）定位。

### 2. string_ids 字符串索引

每个条目是**偏移**，指向data区里的UTF-8字符串。
类名、方法名、字段名、常量字符串全都存在这里，**全局共享**。

### 3. type_ids 类型索引

每个条目指向string_id，代表一个类型（类名，如`Landroid/app/Activity;`）。

### 4. proto_ids 方法原型

记录方法返回值、参数列表，用于描述方法签名。

### 5. field_ids 字段索引

类 + 类型 + 字段名，对应Java的成员变量/静态变量。

### 6. method_ids 方法索引

类 + 方法原型 + 方法名，对应Java的方法。

### 7. class_defs 类定义数组【最重要】

每一项代表一个类，包含：

- class_idx：type_id索引，类本身
- superclass_idx：父类
- interfaces_off：接口列表偏移
- source_file_idx：源码文件名
- annotations_off：注解
- class_data_off：**类数据**（静态字段、实例字段、直接方法、虚方法）
- static_values_off：静态常量初始值

class_data里存放：

- static fields 静态成员
- instance fields 实例成员
- direct methods：静态方法、构造方法（非虚方法）
- virtual methods：普通成员虚方法

方法内部：指向`code_item`，code_item保存在data区，**存放Dalvik字节码**（smali对应的指令）。

### 8. data区

存储所有变长数据：字符串、code_item（方法字节码）、注解、调试信息等。

### 9. link_data

运行时链接用，一般为空。

## 四、class → dex 的转换流程（Android打包）

```
.java → javac → 一堆 .class 文件 → dx / d8 工具 → classes.dex
```

现代Android用 **D8**（替代旧dx）做编译：

1. 读取所有class文件
2. 提取所有常量，**合并去重，构建全局常量池**
3. 将JVM字节码，翻译成Dalvik字节码
4. 组织成上面的dex结构
5. 多个类打包进单个dex

> 当方法数超过65536（`method_ids`是u16，最多2^16=65536），就需要**多dex（multidex）**，生成classes1.dex、classes2.dex...

## 五、Class 和 DEX 对照表

| 项目 | .class（JVM） | .dex（Dalvik/ART） |
|---|---|---|
| 虚拟机 | JVM栈虚拟机 | Dalvik/ART寄存器虚拟机 |
| 类数量 | 1个文件=1个类 | 1个文件=多个类 |
| 常量池 | 每个class独立常量池，重复多 | 全局共享常量池，压缩 |
| 字节码 | JVM bytecode | Dalvik bytecode（smali） |
| 方法索引 | 无全局限制 | 单个dex方法ID上限65536 |
| 工具 | javac | d8/dx |

## 六、常见衍生概念

1. **smali**：dex的汇编文本，baksmali把dex转smali，smali编译回dex。
2. **odex / oat**：ART下，dex经过AOT编译生成机器码oat文件，运行更快。
3. multidex：解决dex 65536方法数限制。

## 七、一句话总结关系

**class是Java源码编译给JVM的文件；Android打包时，D8工具把一批class合并、去重、转码，生成dex，dex是给Android虚拟机执行的文件。dex不是class的简单拼接，做了大量优化和结构重构。**
