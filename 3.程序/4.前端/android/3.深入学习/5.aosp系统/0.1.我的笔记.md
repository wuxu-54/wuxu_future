# QA

## Q: “RefBase、sp、wp 等）、Vold 和 Rild”，Android 中 Native 层，这些是什么

这一套是 Android 为 C++‑Native 层自研的**引用计数智能指针**，替代裸指针，用来解决内存泄漏、野指针问题，源码位置：`system/libutils/RefBase.cpp`。

### 1. RefBase

- 基类，所有需要被 `sp/wp` 管理的类必须继承 `RefBase`。
- 内部维护两个计数器：
  1. `mStrong`：强引用计数（对应 sp）
  2. `mWeak`：弱引用计数（对应 wp）
- 核心规则：
  - 只要**强引用>0**，对象本体就不会释放；
  - 弱引用单独存在时不能持有对象，只能依靠强引用判断对象存活。
- 提供生命周期回调：`onFirstRef()`（第一次强引用创建时）、`onLastStrongRef()`、`onIncStrongAttempted()`，native 组件大量利用这几个回调做初始化和销毁工作。

### 2. sp（strong pointer，强智能指针）

1. 强引用，增加 `RefBase::mStrong` 计数；
2. 只要还有 sp 持有对象，对象就不会析构；
3. 赋值、拷贝时计数+1，sp 生命周期结束（出作用域）计数‑1；
4. 当 `mStrong` 降到 0，C++ 对象就会 delete；
5. 使用方式：`sp<XXX> obj = new XXX();`。

### 3. wp（weak pointer，弱智能指针）

1. 只增加弱引用计数 `mWeak`，**不会阻止对象销毁**；
2. wp 不能直接使用对象，必须调用 `promote()` 尝试升级为 sp：
   - 如果此时强引用还 >0：promote 成功，得到 sp，可以正常访问对象；
   - 强引用已经为0：promote 返回空，说明对象已经销毁，避免野指针。
3. 典型用途：打破循环引用问题（A持有sp，B持有wp），防止内存泄漏。

> 
> 简单总结：
> 
> 
> - RefBase：给类加上引用计数能力；
> - sp：强引用，保活对象；
> - wp：弱引用，不保活，使用前提升为sp校验有效性。
> Android Native 的 Binder、Surface、ANativeWindow、各种Service底层对象几乎全部基于这套机制管理生命周期。

### 二、Vold（Volume Daemon）

## 全称：Volume Daemon，存储管理守护进程，Native 可执行程序（运行在独立进程）

源码路径：`system/vold`，开机后常驻后台。

### 核心职责：

1. 磁盘、分区、外置存储（SD卡、U盘、OTG、内置分区）管理；
2. 磁盘格式化、挂载、卸载、fstab 解析、加密（Adoptable Storage）；
3. 监听内核uevent事件（插拔U盘、SD卡）；
4. 和 Framework 层 `MountService` 通过 socket 通信：
   - Framework 下发指令：挂载、格式化、弹出U盘；
   - vold 把磁盘状态上报给 Java 层；
5. 处理加密分区：FDE/FBE（文件级加密），配合 cryptfs 完成加解密。

### 通信模型

```
Framework MountService(Java) <--socket--> vold(Native) <--ioctl--> Linux内核块设备驱动
```

# 三、RILD（Radio Interface Layer Daemon）

全称：Radio Interface Layer Daemon，**电话 modem 通信的守护进程**，源码：`hardware/ril`。

## 作用分层（RIL体系分为两层）

1. RILD（rild 进程，Native）：
   - 开机常驻的 native 进程；
   - 加载厂商提供的 `libril‑vendor.so`，和 modem（基带芯片）通信；
   - 通过 AT‑命令或者厂商私有协议和基带交互；
2. Java‑RIL（Framework层）：`RILJ`；

### 数据流向

```
Telephony‑Framework(RILJ Java) <--socket--> rild(Native) --> libril‑vendor.so --> Modem（基带）
```

### 管理的业务：

打电话、收发短信、4G/5G注册、信号查询、SIM卡读取、数据网络开启、拨号、漫游、紧急呼叫等全部指令都经过 rild。

---

# 整体归类概括

1. `RefBase/sp/wp`：**libutils 基础工具组件（C++类）**，Native层通用生命周期管理工具，所有native大型组件都会用到；
2. `vold`：**独立Native守护进程**，负责存储设备管理；
3. `rild`：**独立Native守护进程**，负责和手机基带通信。

## 层级区分

- RefBase/sp‑wp：代码库里面的C++类（动态库 libutils.so）；
- vold、rild：运行的可执行程序（独立进程）。
