# 阶段2：解析APK文件（PackageParser，运行在system_server进程，PMS调用）

>
> 前置：APK已经被拷贝到 `/data/app-staging` 临时目录，**这一步只做静态解析Manifest、提取包元信息；不做签名校验、不拷贝正式目录、不dex2oat**。
> 核心入口：`PackageParser.parsePackage()`；
> 解析对象：staging目录下的base.apk（支持split多分包App Bundle）；
> 核心依赖：`AssetManager`、二进制AXML解析器`XmlResourceParser`。

## 1. 初始化AssetManager，打开APK压缩包

1. 创建`AssetManager`实例，调用`addAssetPath(apk路径)`，把staging里的APK加入资源管理器；底层native代码打开ZIP格式APK，拿到cookie句柄。
2. 构建`Resources`对象，用于资源id、字符串、图标、label的解析。
3. 通过AssetManager打开APK内 **二进制AndroidManifest.xml（AXML）**，拿到`XmlResourceParser`。>

> ⚠️ 重点：APK里的AndroidManifest不是文本xml，是AAPT2编译后的**二进制AXML**，必须用系统专用XmlResourceParser解析，普通xml解析器无法读取。

## 2. 轻量预解析（PackageLite）

先执行`parsePackageLite`，快速扫包，生成轻量对象`PackageLite`，只提取极简信息：

- 是否是split分包、base包路径、abi信息、基础包名；
- 快速判断APK文件结构是否合法，ZIP是否损坏。>

> 目的：快速过滤损坏APK；多Split APK会循环解析每个split分包。

## 3. 解析AndroidManifest标签，逐层读取，构建ParsingPackage内存对象

核心方法：`parseBaseApk()` → `parseBaseApkTags()`，从根`<manifest>`标签递归解析，把信息存入内存`ParsingPackage`对象。

### 3.1 解析 manifest根标签

读取`<manifest>`属性：

- `package`：应用包名
- `versionCode / versionName`
- `minSdkVersion、targetSdkVersion`
- `sharedUserId、sharedUserLabel`
- `installLocation`（应用安装位置：内部/可移动存储）

基础合法性校验：包名不能为空、versionCode≥0，minSdk和当前设备SDK版本兼容。
**校验失败直接抛出PackageParserException，终止安装。**

### 3.2 解析顶层非application标签

- `<uses-permission>`、`<uses-permission-sdk23>`：收集应用声明权限列表；
- `<uses-feature>`：硬件特性声明（蓝牙、相机等）；
- `<queries>`：包可见性配置（Android11+）；
- `<permission>`：自定义权限。

### 3.3 解析  标签（parseBaseApplication）

读取application全局属性：
`android:name`(Application类名)、icon、label、debuggable、allowBackup、supportsRtl、largeHeap、theme等。

然后递归解析application内部**四大组件**，分别存入对应集合：

1. `<activity>`：Activity名称、exported、intent-filter、taskAffinity、launchMode；
2. `<receiver>`：广播接收器，intent-filter；
3. `<service>`：Service组件；
4. `<provider>`：ContentProvider，authority、exported、read/write权限。

>
> 每一个组件的`intent-filter`都会解析保存action/category/data，后续PMS用于隐式Intent匹配。

### 3.4 Split分包处理（App Bundle）

如果是split APK（base + config.xxx.apk）：
循环调用`parseSplitApk`，逐个解析每个split分包的manifest，合并资源、abi、语言、dpi信息到同一个Package对象。

## 4. 资源信息提取（图标、应用名称label）

借助前面创建的`Resources`对象：

- 读取application/activity的icon、label资源id；
- 把资源id转为字符串/图片信息；>

> 这里只是**读取资源引用**，不会把图片全部加载到内存。

## 5. 收集dex、native so信息

扫描APK内ZIP条目：

- 查找classes.dex / classes2.dex…记录dex文件列表；
- 扫描lib/目录，收集各个ABI的so库（arm64-v8a、armeabi-v7a、x86）；
记录代码路径、原生库路径，后续交给installd做dex2oat。

## 6. 解析完成，返回Package对象给PMS

解析成功，`PackageParser`返回完整内存Package对象给PMS，对象包含：
包名、版本、权限、四大组件、intent-filter、icon/label、dex列表、so库、minSdk、targetSdk、sharedUserId等全部清单信息。

>
> 注意：**PackageParser只解析Manifest和APK目录结构，不做签名校验！**
> 解析完成之后，PMS才进入下一个阶段：APK完整性 + v2/v3签名校验。

## 7. 解析失败场景（直接终止安装）

出现下面情况抛出异常，安装失败，返回`INSTALL_FAILED_INVALID_APK`：

1. APK不是合法ZIP压缩包，文件损坏；
2. AndroidManifest.xml缺失、AXML二进制格式损坏；
3. manifest语法非法、包名为空；
4. split分包信息不匹配，base包缺失；
5. minSdkVersion大于当前设备系统版本。

## 8. 补充：工具API `getPackageArchiveInfo`

`PackageManager.getPackageArchiveInfo`底层就是调用PackageParser，**不需要安装APK，直接解析本地APK文件，读取包信息**，原理和安装阶段的PackageParser完全一致。

## 时序简图

```
PMS → PackageParser.parsePackage()
    → AssetManager.addAssetPath 打开APK
    → parsePackageLite 轻量预扫描
    → XmlResourceParser读取二进制AndroidManifest.xml
    → parseBaseApk 解析manifest根标签
        → parseBaseApkTags：权限、uses-feature
        → parseBaseApplication：application + 四大组件+intent-filter
    → 扫描dex、so库、资源icon/label
    → 组装Package对象返回PMS
```

## 面试核心要点

1. PackageParser运行在 **system_server进程**，由PMS调用；
2. AndroidManifest是**二进制AXML**，AssetManager+XmlResourceParser解析；
3. 只做**静态清单解析**，**签名校验不属于PackageParser工作**；
4. 支持单APK、Split App Bundle多分包解析；
5. 产出内存Package对象，后续PMS用这个对象做签名校验、持久化写入packages.xml；
6. 只校验Manifest格式合法性，**不会校验代码是否能正常运行，不执行dex编译**。

## 高频误区

❌ PackageParser解析的时候校验签名 → 错。签名校验是PMS单独的阶段，在PackageParser解析完成之后。
❌ 解析会解压APK全部文件 → 错，AssetManager直接读取ZIP内条目，不会全量解压。
❌ 解析会加载完整图片资源到内存 → 错，只保存资源ID。
