# Android 所有核心进程完整梳理（最终笔记版）

## 前置总规则（必须先背）

1. **init 进程（PID=1）**：用户空间**一号祖宗进程**
   负责解析 `init.rc`，**直接启动所有 Native 守护进程**。
2. **Zygote 进程**：init 启动，**Java 世界孵化器**
   所有 **Java/App 进程** 全部由 Zygote fork 出来，init 不直接启动任何 App/SystemServer。
3. 进程两大阵营：
   - **init 直接启动：全部是 Native 守护进程（C++）**
   - **Zygote fork 启动：全部是 Java 虚拟机进程**

---

# 一、init 进程直接启动的所有核心进程（Native 进程）

## 1. ServiceManager（Binder 注册表）

### 归属

Native 进程，init 启动

### 核心职责

1. **Binder 全局服务注册中心**
2. 所有系统服务（PMS/AMS/WMS/SF）开机后主动注册到它这里
3. App 需要使用系统服务时，**先查 ServiceManager 获取 Binder 引用**

### 通俗理解

整个系统的 **Binder 通讯录**
只存：`服务名 → Binder 句柄`

### 关键特点

- **不处理任何业务逻辑**
- 不转发 IPC 调用
- 只负责「注册、查询」

## 2. installd（安装底层守护进程）

### 归属

Native 守护进程，root 权限，init 启动

### 核心职责

专门负责 **APK 安装的底层脏活累活**

1. 移动 / 创建 / 删除应用目录
2. 设置文件 **UID、GID、SELinux 权限**
3. 解压 so 库、ABI 适配
4. 执行 **dex2oat 预编译**

### 通信方式

SystemServer 内的 **PMS → Installer(Java代理) → socket → installd**

### 超级重要误区（必考）

❌ **installd 不解析 APK**
❌ **不校验签名 V2/V3**
❌ **不读取 Manifest**
✅ APK解析、签名校验、包信息解析 **全部是 PMS 做的**

## 3. Zygote（Java 孵化器）

### 归属

Native 入口 + Java 运行，init 启动

### 核心职责

1. 预加载 ART 虚拟机、系统类、资源、常用库
2. **fork 所有 Java 进程**
   - SystemServer
   - 所有 App（Launcher / 微信 / 抖音）

### 关键特性

- Zygote **本身不运行业务逻辑**
- 只负责孵化进程
- 子进程 fork 后替换执行入口（ActivityThread）

## 4. SurfaceFlinger（图形合成服务）

### 归属

Native 进程，init 启动

### 核心职责

Android **唯一屏幕合成引擎**

1. 接收所有 App / WMS 的 Surface 图层
2. 图层叠加、透明度、Z 轴排序、合成
3. 输出画面到屏幕

### 通信

WMS &amp; App 通过 Binder 与 SF 通信

## 5. logd（日志守护进程）

### 职责

1. 统一收集系统、App、内核日志
2. 管理日志缓冲区
3. 提供 logcat 读取

## 6. lmkd（低内存查杀进程）

### 职责

替代旧内核 lowmemorykiller
根据 oom_adj、内存水位 **主动杀后台 App**

## 7. ueventd（设备管理进程）

### 职责

监听内核设备热插拔
创建设备节点、分配设备权限

## 8. vold（存储守护进程）

### 职责

SD卡、U盘、分区挂载、卸载、加密存储管理

## 9. netd（网络守护进程）

### 职责

防火墙、iptables、网络策略、路由、网络管控

## 10. adbd（adb 调试进程）

### 职责

电脑与手机 adb 连接、命令传输

## 11. bootanim（开机动画进程）

### 职责

开机显示动画，系统就绪后退出

## 12. rild（无线基带进程）

### 职责

电话、短信、移动数据、和基带通信

## 13. healthd（电池守护进程）

### 职责

监控电池电量、充电状态

## 14. debuggerd（崩溃捕获进程）

### 职责

App/Native 崩溃时抓取 tombstone 崩溃日志

# 二、Zygote 孵化出来的进程（Java 进程）

## 1. SystemServer 进程（超级核心）

### 归属

Zygote fork 产生，**Java 进程**

### 关键认知（90%人答错）

✅ **PMS、AMS、WMS 都不是独立进程！**
✅ 它们只是 **SystemServer 内部跑的 Java 服务**

### 包含核心服务

- PMS 包管理服务（安装、解析、签名校验、开机扫描）
- AMS 组件管理、进程启停
- WMS 窗口管理
- 网络、电池、任务栈等所有系统服务

### 所有服务统一行为

启动后 **注册 Binder 到 ServiceManager**

## 2. Launcher 桌面进程

### 归属

Zygote 孵化 **普通 App 进程**

### 核心定位

1. **完全普通 App，没有特殊系统权限特权**
2. 只是配置了 **HOME 入口**，被系统选为默认桌面
3. 一般放在 priv-app，拥有少量特权权限

### Launcher 获取应用信息的完整真相（必背）

1. 新 App 安装：PMS 走完安装流程，发广播（**只带包名**）
2. Launcher 收到广播后 **主动 Binder 跨进程查询 PMS**
3. 查询图标、名称、Launcher Activity、组件信息
4. 缓存在 **Launcher 自己的本地数据库**

### 重点结论

- **Launcher 不参与 APK 安装、解析、校验**
- **所有包信息权威数据源：PMS 内存 mPackages**
- **所有跨进程：Binder**

## 3. 所有第三方 App 进程

微信、抖音、淘宝等
全部由 Zygote fork，独立虚拟机、独立沙盒、独立UID

# 三、最终最强总结（背诵版）

## 1. init 启动的进程（全部 Native）

servicemanager、installd、zygote、surfaceflinger、logd、lmkd、ueventd、vold、netd、adbd、bootanim、rild、healthd、debuggerd

## 2. Zygote 启动的进程（全部 Java）

SystemServer、Launcher、SystemUI、所有第三方App

## 3. 三大绝对真理（面试必杀）

1. **所有 Binder 服务都注册到 ServiceManager**
2. **所有 APK 安装业务逻辑：PMS**
   **所有 APK 底层文件操作：installd**
3. **所有 Java 进程都来自 Zygote，没有例外**

## 4. 高频易错点终极纠错

1. PMS/AMS/WMS **不是独立进程**，属于 SystemServer
2. installd 和 SystemServer 使用 **socket**，不是 Binder
3. ServiceManager **只做注册查询，不干活**
4. Launcher 是普通 App，不是系统服务
5. 广播不带数据，Launcher 必须主动 Binder 查询

# 配套文字小结（贴在图下面，笔记配套）

## 启动顺序简要

1. init 最先启动，拉起一堆native守护进程（必须先启动`servicemanager`，后面Binder服务才能注册）
2. init 启动 zygote
3. zygote fork 出 SystemServer
4. SystemServer 内部初始化 PMS、AMS、WMS 等服务，把这些服务注册 Binder 到 servicemanager
5. PMS开机扫描全部APK构建包信息缓存，完成后标记systemReady
6. AMS 拉起 Launcher 桌面进程

## 跨进程通信关系补充（拓扑图配套备注）

1. Launcher ↔ PMS（SystemServer内）：**Binder IPC**
2. PMS ↔ installd：**Socket通信（不是Binder！）**
3. 所有Binder服务注册、查询：找 servicemanager
4. SurfaceFlinger 与 WMS/App：Binder

## 一句话记忆

**init生native守护进程；zygote生全部Java进程；SystemServer是Java系统服务的容器。**
