# 核心一句话（Android P+ ClientTransaction模型）

`LaunchActivityItem` → `handleLaunchActivity` 里面只做：`new Activity` + `attach()` + `onCreate()` + **onStart()**
👉 **onResume不是handleLaunchActivity内部继续跑的！onResume是ClientTransaction里另外一个Item：ResumeActivityItem，由TransactionExecutor接着执行**

> 很多人踩坑：以为performLaunchActivity里面做完onCreate之后，代码继续往下直接onResume。P版本之后**不是串行在同一个函数里，而是同一个事务包里面多个Item依次执行**。

## 1. LaunchActivityItem 执行：ActivityThread.handleLaunchActivity

```java
// LaunchActivityItem.execute() 主线程TransactionExecutor调用
@Override
public void execute(ClientTransactionHandler client, IBinder token, PendingTransactionActions pendingActions) {
    ActivityThread.ActivityClientRecord r = client.getActivityClientRecord(token);
    client.handleLaunchActivity(r, pendingActions, mIntent, ...);
}
```

`handleLaunchActivity` → `performLaunchActivity(r, customIntent)`

```java
private Activity performLaunchActivity(ActivityClientRecord r, Intent customIntent) {
    // 1. 反射new Activity对象
    Activity activity = mInstrumentation.newActivity(cl, componentName, r.intent);
    // 2. attach 绑定Context、WindowManager等
    activity.attach(...);
    // 3. onCreate
    mInstrumentation.callActivityOnCreate(activity, r.state);
    // 4. 紧接着 onStart！！
    if (!r.activity.mFinished) {
        mInstrumentation.callActivityOnStart(activity);
    }
    return activity;
}
```

✅ **这里执行完：attach → onCreate → onStart**
到此，**performLaunchActivity就return退出**，**这里不会调用onResume！**

> 生命周期到这里：`onCreate() → onStart()` 停住。
> Activity状态：Started，**还没Resumed，不能和用户交互**。

## 2. 谁来执行onResume？同一个ClientTransaction包的 ResumeActivityItem

还记得 `realStartActivityLocked` 里面：

```java
clientTransaction.addTransactionItem(LaunchActivityItem.obtain(...));
if (andResume) {
    clientTransaction.addTransactionItem(ResumeActivityItem.obtain());
}
```

**两个Item打包在同一个ClientTransaction，一次性Binder发到App**
主线程TransactionExecutor循环遍历mItems，顺序执行：

1. 执行第1个Item：LaunchActivityItem → handleLaunchActivity → onCreate、onStart
2. **执行第2个Item：ResumeActivityItem**

```java
// ResumeActivityItem.execute()
@Override
public void execute(ClientTransactionHandler client, IBinder token, PendingTransactionActions pendingActions) {
    client.handleResumeActivity(...);
}
```

`ActivityThread.handleResumeActivity()`

```java
final void handleResumeActivity(...) {
    performResumeActivity(r, finalStateRequest, reason);
    // 内部：mInstrumentation.callActivityOnResume(activity)
    // → activity.onResume()
}
```

👉 执行 `onResume()`，Activity变成前台可交互。

# 完整App主线执行时序（TransactionExecutor）

```
H收到 EXECUTE_TRANSACTION消息
→ TransactionExecutor.execute(transaction)
    遍历 transaction.mItems：
    Item1 LaunchActivityItem.execute()
        → handleLaunchActivity
            → performLaunchActivity
                → new Activity
                → activity.attach()
                → onCreate()
                → onStart()
    Item2 ResumeActivityItem.execute()
        → handleResumeActivity
            → performResumeActivity
                → onResume()
```

# 🔥 对比Android O（老版本，没有ClientTransaction）

老版本是**两次独立Binder调用**：

1. system_server调用 `scheduleLaunchActivity` → App收到消息，`handleLaunchActivity` 执行 attach+onCreate+onStart
2. system_server再调用 `scheduleResumeActivity` → App收到第二条Handler消息，执行onResume

P版本优化：**两次Binder合并成一次Binder，两个Item放同一个事务包，主线程里面依次执行两个Item**

> 重点区分：
> 老版本：两个独立Handler Message（LAUNCH_ACTIVITY、RESUME_ACTIVITY）
> P+新版：**一个Handler消息 EXECUTE_TRANSACTION，事务里面包含多个Item**

# 3. onResume之后做什么（界面显示）

`handleResumeActivity` 里面，onResume执行完后：

```java
wm.addView(decor, l); // 添加DecorView到WindowManagerGlobal
```

触发WMS添加窗口、Surface创建、Choreographer触发View的绘制（measure/layout/draw），屏幕上才看到页面。

# 4. 面试高频坑点

Q：handleLaunchActivity里面执行完onCreate之后，为什么不会直接onResume？
A：P版本重构后生命周期拆成不同TransactionItem。LaunchItem只负责创建+onCreate+onStart；ResumeItem单独负责onResume。两个Item在同一个事务包，TransactionExecutor串行依次执行。不是函数内部直接往下跑。

Q：onStart是在LaunchActivityItem里面执行的？
A：是的，`performLaunchActivity` 内部callActivityOnStart，onStart属于LaunchItem。**onResume不属于LaunchItem**。

# 精简背诵

ClientTransaction包含LaunchActivityItem + ResumeActivityItem。主线程TransactionExecutor顺序执行：
LaunchItem：反射创建Activity、attach、onCreate、onStart；
ResumeItem：执行onResume；onResume后添加DecorView，开始View绘制，页面显示。
