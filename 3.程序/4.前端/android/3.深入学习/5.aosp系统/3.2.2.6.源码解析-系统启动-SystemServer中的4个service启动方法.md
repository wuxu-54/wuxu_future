# SystemServer中4个service启动方法

```java
startBootstrapServices(t);
startCoreServices(t);
startOtherServices(t);
startApexServices(t);
```

# SystemServer四大阶段：`startBootstrapServices` / `startCoreServices` / `startOtherServices` / `startApexServices`
>
> 核心原则：**严格顺序启动，依赖前置服务，前面的服务没起来，后面不能启动**；所有服务启动完成后，AMS调用`systemReady()`，启动Launcher桌面。
> `t`是Trace埋点对象，用来统计每个服务开机耗时，systrace可以查看开机性能。

## 1. startBootstrapServices(t) 【**引导基础服务，最优先启动**】
>
> 系统根基服务，AMS/PMS都在这里。**没有这些，系统完全无法跑App**。

```java
private void startBootstrapServices(@NonNull TimingsTraceAndSlog t) {
```

重点服务清单：

1. **Watchdog**：系统看门狗，监控AMS/PMS等关键服务死锁；卡死就杀掉SystemServer，系统重启。
2. **Installer**：和native `installd`守护进程Binder通信，负责APK安装、文件目录创建、dex2oat。PMS强依赖Installer。
3. **ActivityManagerService (AMS)**：四大组件、进程管理、任务栈，**整个Android的核心大管家**。
4. **ActivityTaskManagerService (ATMS)**：Android10之后拆分出来，专门管理Activity任务栈（原来属于AMS）。
5. **PackageManagerService (PMS)**：包管理，解析所有APK、权限管理、版本、组件信息，开机扫描所有应用。
6. **PowerManagerService (PMS电源)**：电源策略、屏幕亮灭、休眠、唤醒锁。
7. **DisplayManagerService (DMS)**：屏幕显示管理，多屏、分辨率、刷新率。
8. **LightsService**：背光、指示灯管理。
9. **SensorService**：传感器管理（加速度、陀螺仪等）
10. **UserManagerService**：多用户管理（工作资料、多账号）

一句话：**这一组是地基，AMS/PMS就在这里，没有它们，无法启动任何App**。

## 2. startCoreServices(t) 【核心常用服务，基础硬件/统计能力】

引导服务就绪后，启动这一组，都是系统运行必备，但不直接决定能不能启动App。

- **BatteryService**：电池状态、充电、电量、温度，发广播通知App。
- **UsageStatsService**：App使用统计，记录每个应用前台时长，用于权限、电池优化。
- **DropBoxManagerService**：系统崩溃、ANR日志收集，日志抓取。
- **WebViewUpdateService**：WebView组件版本管理、更新。
- **GpuService**：GPU信息管理。

> 特点：负责硬件状态采集、日志、统计，不负责组件/进程调度。

## 3. startOtherServices(t)【其他大量服务，UI、网络、多媒体、通知、输入法等】
数量最多，上千行代码，**依赖前面AMS、PMS、DMS**。
重点：

1. **WindowManagerService(WMS)**：窗口管理、Surface、动画、布局、弹窗。
2. **InputManagerService(IMS)**：触摸、按键输入事件分发。
3. **AlarmManagerService**：闹钟、定时任务。
4. **NotificationManagerService**：通知管理。
5. **ConnectivityService**：网络管理（wifi/移动网络）。
6. **WifiService / WifiScanningService**：Wi-Fi管理。
7. **InputMethodManagerService(IMMS)**：输入法管理。
8. **CameraService**：相机管理。
9. **VibratorService**：马达震动。
10. **AudioService**：音频音量、音频焦点。
11. **DevicePolicyManagerService**：设备管理，企业MDM。
12. **MountService**：存储、SD卡挂载。

✅ 关键节点：这组服务全部跑完之后，AMS执行`systemReady()`，**启动Launcher桌面**。

## 4. startApexServices(t)【Apex模块化服务（Android 10+新增）】
Apex是Android模块化方案，可以单独升级系统组件，不用整包OTA。
作用：

- 挂载Apex分区、读取apex模块配置、创建Apex的数据目录
- 启动由Apex模块提供的系统服务（放在apex包里面，不是写死在system.img）
- 更新动态链接器配置

> Apex服务在最后，因为Apex模块依赖前面PMS等基础服务。

# 整体启动时序（串联前面Zygote）

```
Zygote fork SystemServer
    → SystemServer.run()
        createSystemContext();
        mSystemServiceManager = new SystemServiceManager(); //统一管理所有系统服务
        startBootstrapServices(t); //AMS PMS Power 地基
        startCoreServices(t); //电池、日志、统计
        startOtherServices(t); //WMS IMS 网络、通知、输入法
        startApexServices(t); //模块化Apex服务
        AMS.systemReady();
            → 启动Launcher桌面
        Looper.loop(); //SystemServer主线程消息循环
```

# 面试高频问题

### Q：为什么AMS放在startBootstrapServices，WMS放在startOtherServices？

A：AMS是**进程、四大组件管理器**，最基础。WMS是窗口UI，AMS就绪之后才能启动WMS，WMS依赖AMS。
> 注意：AMS和WMS互相依赖，源码里AMS先启动，后面WMS启动完成再互相绑定。

### Q：systemReady() 什么时候调用，干什么？

在startOtherServices末尾，所有系统服务就绪后AMS.systemReady()：

1. 发送开机广播 `BOOT_COMPLETED`
2. 启动Launcher桌面
3. 启动所有persistent常驻应用

### Q：所有系统服务怎么对外通信？

每一个Service（AMS/WMS/PMS）启动时，**注册到ServiceManager（Binder注册表）**。App通过Binder拿到服务代理，跨进程调用。

# 区分两条主线（和前面你学习的Zygote/App启动串起来）

1. **SystemServer**：Zygote fork → SystemServer.run → 4个阶段启动AMS/WMS等系统服务，AMS负责管理App进程。
2. **普通App**：Launcher点击图标 → Binder调用AMS.startActivity → AMS通过Unix Socket通知Zygote → Zygote forkApp进程 → ActivityThread.main，App启动。
3. **bindService**：App客户端Binder调用AMS.bindService，AMS管理Service生命周期；Service启动后返回IBinder，两端Binder直连通信。
