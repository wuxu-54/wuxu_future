# handleBindApplication 中 mInstrumentation 总结笔记

源码：

```java
// Instrumentation info affects the class loader, so load it before
// setting up the app context.
final InstrumentationInfo ii;
if (data.instrumentationName != null) {
    ii = prepareInstrumentation(data);
} else {
    ii = null;
}
```

>
> 核心一句话：`Instrumentation` 是**App组件生命周期的回调钩子与实例工厂**。
> 普通App使用框架自带默认实现；Instrumentation测试场景，替换为自定义测试Runner，用来劫持、监控、干预App组件的创建与生命周期。
> 代码分支入口：`data.instrumentationName`（AMS传入，在AppBindData中），非空=测试模式；null=普通App正常启动。

## 一、两种启动模式分支（handleBindApplication内）

### 1）非测试场景（普通App，点击图标冷启动，`data.instrumentationName == null`，`ii = null`）

```
mInstrumentation = new Instrumentation();
mInstrumentation.basicInit(this);
```

1. 实例：**Android框架原生`Instrumentation`**，无测试逻辑。
2. 初始化：仅执行`basicInit`，只保存`ActivityThread`引用，**不调用`init()`、不初始化InstrumentationInfo**。
3. 作用（原生默认）：
   - 作为**组件对象工厂**：`newApplication`、`newActivity`，反射创建Application、Activity实例；
   - 作为**生命周期包装入口**：`callApplicationOnCreate`，调用`Application.onCreate`；
   - 提供基础回调钩子（默认空实现，不拦截）；
   - 不接管监控、不注入测试代码，只是框架标准调用层。
4. 上下文：App只有**一套LoadedApk / ClassLoader / Context**（当前业务App）。

### 2）测试场景（`am instrument`启动，`data.instrumentationName != null`，`ii != null`）

```
ii = prepareInstrumentation(data);
// prepareInstrumentation：向PackageManager查询<instrumentation>标签信息，得到InstrumentationInfo
// 单独创建测试包的Context、独立ClassLoader（测试Runner属于另外一个Test APK）
final ContextImpl instrContext = ContextImpl.createAppContext(this, piForInstr);
ClassLoader cl = instrContext.getClassLoader();
// 反射加载测试Runner类（AndroidJUnitRunner，继承Instrumentation）
mInstrumentation = (Instrumentation) cl.loadClass(data.instrumentationName.getClassName()).newInstance();
// 完整初始化
mInstrumentation.init(this, instrContext, appContext, component,
        data.instrumentationWatcher, data.instrumentationUiAutomationConnection);
```

1. `prepareInstrumentation(data)`
 查询清单中`<instrumentation>`标签信息，拿到`InstrumentationInfo ii`；>

> 注释原因：Instrumentation信息会影响类加载器，**必须在App主Context创建前解析**。

2. 存在两套APK，两套`LoadedApk`、两套ClassLoader，互相隔离：
   - `appContext`：被测App的Context（业务apk）
   - `instrContext`：测试Runner所在Test APK的Context
3. `mInstrumentation.init()`：
 绑定ActivityThread、被测App上下文、测试包上下文、watcher、UiAutomation通道，保存`InstrumentationInfo`。
4. 自定义Runner作用：
   - **劫持组件创建**：重写`newApplication`/`newActivity`，在组件实例创建前后插入测试逻辑；
   - **监听组件生命周期**：拦截onCreate/onResume等生命周期；
   - 提供测试API：UiAutomation、监控Activity启动、注入事件、收集测试结果；
   - `mInstrumentation.onCreate()`：测试Runner入口，在Application.onCreate**之前**执行测试初始化。

## 二、mInstrumentation 在 handleBindApplication 内部后续使用（两种模式共用）

1. `mInstrumentation.newApplication()`：反射创建Application对象；
2. `mInstrumentation.callApplicationOnCreate(app)`：调用`Application.onCreate()`；
3. 测试场景额外执行：`mInstrumentation.onCreate(instrumentationArgs)`，Runner的初始化入口；>

> ⚠️ 注意：Service、Activity实例创建，**不是在handleBindApplication里面**；等handleBindApplication执行完毕，后续收到AMS事务，依然使用`mInstrumentation`去创建Activity，它是全局单例，全程生效。

## 三、关键区别对比表（笔记用）

| 项目 | 普通App（非测试） | Instrumentation测试模式 |
| --- | --- | --- |
| data.instrumentationName | null | 不为null，AMS传入Runner组件名 |
| Instrumentation实例 | 框架原生`Instrumentation` | 自定义Runner（AndroidJUnitRunner，继承Instrumentation） |
| 初始化方法 | `basicInit(this)`（轻量初始化） | `init(...)`完整初始化，携带双Context、UiAutomation、watcher |
| APK/ClassLoader | 只有业务App一套LoadedApk | **两套**：被测App + TestRunner测试APK，ClassLoader隔离 |
| prepareInstrumentation | 不执行 | 执行，获取InstrumentationInfo |
| onCreate回调 | 不执行（原生空） | 执行Runner.onCreate，测试逻辑起点 |
| 核心用途 | 框架标准组件实例工厂，调用生命周期 | 拦截组件创建、注入测试代码、Ui自动化、收集测试结果 |

## 四、核心考点/笔记要点

1. `mInstrumentation`是ActivityThread的**全局单例**，在handleBindApplication完成创建，贯穿App整个进程生命周期；
2. 普通模式：只做**实例创建+生命周期转发**，没有任何劫持；
3. 测试模式：AMS在启动进程时就带上`instrumentationName`，App进程拿到后，**单独加载测试APK、独立ClassLoader**，替换Instrumentation为Runner；
4. 注释`Instrumentation info affects the class loader, so load it before setting up the app context`含义：测试Runner属于独立APK，必须提前解析它的包信息，**在主AppContext创建前**完成prepareInstrumentation；
5. 执行顺序：创建Instrumentation → makeApplication（attachBaseContext）→ installContentProviders → `mInstrumentation.onCreate`（仅测试）→ `mInstrumentation.callApplicationOnCreate`（Application.onCreate）。

## 五、一句话总结（可直接写在笔记头部）

>
> `mInstrumentation`是ActivityThread中负责**组件实例创建与生命周期调用**的钩子类。普通App使用框架默认实现，仅作为组件工厂；Instrumentation测试启动时，会加载独立测试APK的自定义Runner替换它，从而劫持Application/Activity创建、注入自动化测试逻辑。
