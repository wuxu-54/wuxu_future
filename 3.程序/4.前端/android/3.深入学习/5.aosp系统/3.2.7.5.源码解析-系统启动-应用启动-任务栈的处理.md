# Android 任务栈 & Activity启动模式 + App → ATMS(AMS) 全链路源码讲解

>
> 说明：Android 10+ 把任务栈、Activity调度逻辑从AMS剥离到 **ATMS ActivityTaskManagerService**，下面统一用ATMS指代任务栈管理服务，运行在`system_server`进程；App端是应用进程，二者通过**Binder**跨进程通信。

## 一、基础概念：Task / BackStack / 四大启动模式

### 1. Task & BackStack（任务栈/返回栈）

**Task**：用户的一个任务，由一组Activity组成，保存在`TaskRecord`（system_server侧）。
**BackStack**：就是任务内部的Activity返回栈，先进后出。

- 按打开顺序压栈；按返回键出栈；
- 系统侧核心数据结构（system_server）：
  - `ActivityRecord`：App中Activity在系统服务端的镜像，一个Activity实例对应一个ActivityRecord，保存launchMode、intent、状态、所属TaskRecord
  - `TaskRecord`：任务栈实体，持有一堆ActivityRecord，affinity任务亲和性、taskId
  - `ActivityStack`：管理多个TaskRecord，分桌面栈、全屏栈等
  - `ProcessRecord`：记录应用进程信息，pid、uid、IApplicationThread Binder句柄
- App进程侧：`ActivityThread`主线程，`ActivityClientRecord`是App端对应Activity的记录。

### 2. 四种launchMode（AndroidManifest.xml声明）

```
<activity android:name=".XXActivity" android:launchMode="standard" />
```

源码中定义枚举 `ActivityInfo`：

```
// frameworks/base/core/java/android/content/pm/ActivityInfo.java
public static final int LAUNCH_MULTIPLE = 0;      // standard 默认
public static final int LAUNCH_SINGLE_TOP = 1;
public static final int LAUNCH_SINGLE_TASK = 2;
public static final int LAUNCH_SINGLE_INSTANCE = 3;
```

1. **standard(LAUNCH_MULTIPLE)**
每次startActivity，**新建Activity实例**，压入当前发起者的Task栈。同一个Task可以存在多个同类Activity实例。

>
> 栈：A → B → B → B 多次打开B，多次新建。

2. **singleTop(LAUNCH_SINGLE_TOP)**
启动目标Activity，如果**目标实例已经在当前Task栈顶**，不复建新实例，调用`onNewIntent()`；否则新建实例入栈。

>
> 栈A-B-C，再启动C：栈顶是C，复用C，onNewIntent；栈A-B-C，启动B：B不在栈顶，新建B入栈 A-B-C-B。

3. **singleTask(LAUNCH_SINGLE_TASK)**
在**同一个affinity任务栈内全局单例**。
ATMS查找任务栈，如果找到该Activity实例，**销毁它上面所有ActivityRecord**，把该Activity挪到栈顶，回调`onNewIntent`；找不到则新建，作为Task根。

>
> 栈A-B-C，启动B：销毁C，栈变成A-B，B调用onNewIntent。
> ⚠️ singleTask默认会新建Task（affinity机制），很多人误以为全局单Task，**affinity是关键**。

4. **singleInstance(LAUNCH_SINGLE_INSTANCE)**
独占一个Task，这个Task**只能有这一个Activity**。
和singleTask类似，找到实例就onNewIntent；但是这个Task里面不能放任何其他Activity，从这个页面打开新页面，新页面会放到别的Task。

>
> 补充：Intent Flag（代码动态控制，优先级高于manifest launchMode）
> FLAG_ACTIVITY_NEW_TASK、FLAG_ACTIVITY_SINGLE_TOP、FLAG_ACTIVITY_CLEAR_TOP

## 二、全链路时序：App调用startActivity → ATMS处理任务栈/启动模式 → 回调App创建Activity

### 整体链路一句话

`App#startActivity` → `Instrumentation` → Binder调用`ATMS.startActivity` → ATMS内部`ActivityStarter`解析Intent、读取launchMode、查找/创建TaskRecord+ActivityRecord（**这里就是启动模式判断核心**）→ 判断目标进程是否存在，不存在通知Zygote fork进程 → 进程attach到ATMS → ATMS通过Binder回调`ApplicationThread.scheduleLaunchActivity` → App主线程Handler H接收消息 → `performLaunchActivity`反射创建Activity、调用onCreate/onStart/onResume。

### 阶段1：App应用进程发起 startActivity（客户端源码）

```
// Activity.java
@Override
public void startActivity(Intent intent) {
    this.startActivity(intent, null);
}

@Override
public void startActivity(Intent intent, @Nullable Bundle options) {
    if (options != null) {
        options.validate();
    }
    // Instrumentation 是App和ATMS之间的代理
    int result = mInstrumentation.execStartActivity(
            this, mMainThread.getApplicationThread(), mToken, this,
            intent, requestCode, options);
    checkStartActivityResult(result, intent);
}
```

`Instrumentation.execStartActivity`：

```
// Instrumentation.java
public int execStartActivity(Context who, IBinder contextThread, IBinder token, Activity target,
        Intent intent, int requestCode, Bundle options) {
    IActivityTaskManager service = ActivityTaskManager.getService();
    try {
        intent.prepareToLeaveProcess(who);
        // Binder跨进程调用进入system_server的ATMS
        int res = service.startActivity(
                whoThread, who.getOpPackageName(), ... intent, ...);
        return res;
    } catch (RemoteException e) {
        throw new RuntimeException("Failure from system", e);
    }
}
```

>
> `ActivityTaskManager.getService()`拿到ATMS的Binder代理，**请求进入system_server进程**。

### 阶段2：system_server ATMS 服务端处理（任务栈、启动模式判断核心）

源码路径：`frameworks/base/services/core/java/com/android/server/wm/ActivityTaskManagerService.java`

```
// ATMS
@Override
public final int startActivity(IApplicationThread caller, String callingPackage,
        String callingFeatureId, Intent intent, String resolvedType, IBinder resultTo,
        String resultWho, int requestCode, int startFlags, ProfilerInfo profilerInfo,
        Bundle bOptions) {
    return startActivityAsUser(caller, callingPackage, callingFeatureId, intent, resolvedType,
            resultTo, resultWho, requestCode, startFlags, profilerInfo, bOptions,
            UserHandle.getCallingUserId());
}

private int startActivityAsUser(...) {
    // 权限校验、用户校验
    // ActivityStarter是真正处理启动逻辑的类
    return getActivityStartController().obtainStarter(intent, "startActivityAsUser")
            .setCaller(caller)
            .setCallingPackage(callingPackage)
            .setIntent(intent)
            .execute();
}
```

**ActivityStarter.execute() 是launchMode、任务栈逻辑的核心**

```
// ActivityStarter.java
int execute() {
    // 1.解析Intent，读取目标ActivityInfo，拿到manifest里面的launchMode
    // 2.查找有没有匹配的TaskRecord、ActivityRecord（核心！判断启动模式）
    // 3.根据launchMode决定：复用实例 / 新建Task / 销毁上层Activity
    if (startActivityUncheckedLocked(r, sourceRecord, ...)) {
        // 成功，继续调度resume
    }
}
```

`startActivityUncheckedLocked`内部关键逻辑（伪源码）：

```
// 简化版：判断launchMode，决定是否复用ActivityRecord
final int launchMode = aInfo.launchMode;
if (launchMode == ActivityInfo.LAUNCH_SINGLE_TOP) {
    // 查找当前Task栈顶ActivityRecord是否匹配目标Component
    if (task.stackTopActivityMatchTarget()) {
        // 复用栈顶，调用onNewIntent，不新建ActivityRecord
        deliverOnNewIntent(r);
        return;
    }
} else if (launchMode == ActivityInfo.LAUNCH_SINGLE_TASK) {
    // 全局查找同affinity的Task，找里面是否存在目标ActivityRecord
    ActivityRecord existRec = findActivityInTaskByComponent(intent);
    if (existRec != null) {
        // 把该Activity之上所有ActivityRecord销毁
        existRec.task.removeAllAbove(existRec);
        // onNewIntent
        deliverOnNewIntent(existRec);
        return;
    } else {
        // 新建TaskRecord，创建ActivityRecord作为根
        createNewTaskAndActivityRecord(r);
    }
} else if (launchMode == ActivityInfo.LAUNCH_SINGLE_INSTANCE) {
    // 查找独占Task，找到就onNewIntent；找不到新建独立Task，只放这一个ActivityRecord
} else {
    // standard，直接新建ActivityRecord，压入当前task
    createNewActivityRecord(r);
}
```

>
> 这里**全部在system_server进程**，ATMS维护所有Task/ActivityRecord，**启动模式判断是系统服务端做的，不是App端**！
> 这是面试高频考点：App只发Intent，**栈逻辑、实例复用全部由ATMS控制**。

创建完/找到ActivityRecord后，ATMS检查目标进程是否存在：

1. 进程不存在：ATMS 通过Socket通知Zygote fork新应用进程；
2. 进程存在：拿到`ProcessRecord`，继续走realStartActivityLocked。

```
// ActivityStackSupervisor.java
final boolean realStartActivityLocked(ActivityRecord r, WindowProcessController proc,
        boolean andResume, boolean checkConfig) throws RemoteException {
    // 构建ClientTransaction，通过Binder回调App进程ApplicationThread
    final ClientTransaction clientTransaction = ClientTransaction.obtain(
            proc.getThread(), r.appToken);
    clientTransaction.addCallback(LaunchActivityItem.obtain(...));
    // Binder调用App进程的scheduleLaunchActivity
    proc.getThread().scheduleTransaction(clientTransaction);
    return true;
}
```

### 阶段3：Binder回调App进程，ActivityThread创建Activity实例

`ApplicationThread` 是App进程内的Binder服务（IApplicationThread.Stub），接收ATMS的跨进程回调：

```
// ActivityThread.java
private class ApplicationThread extends IApplicationThread.Stub {
    @Override
    public void scheduleTransaction(ClientTransaction transaction) throws RemoteException {
        // 把消息交给主线程Handler H
        ActivityThread.this.mH.post(transaction);
    }
}
```

主线程Handler `H` 处理`LaunchActivityItem`，调用`handleLaunchActivity`：

```
// ActivityThread.java
private void handleLaunchActivity(ActivityClientRecord r, Intent customIntent, String reason) {
    // 核心：创建Activity实例，执行生命周期
    Activity a = performLaunchActivity(r, customIntent);
    if (a != null) {
        handleResumeActivity(r.token, false, r.isForward,
                !r.activity.mFinished && !r.startsNotResumed, r.lastProcessedSeq, reason);
    }
}

private Activity performLaunchActivity(ActivityClientRecord r, Intent customIntent) {
    ActivityInfo aInfo = r.activityInfo;
    // 加载apk信息
    if (r.packageInfo == null) {
        r.packageInfo = getPackageInfo(aInfo.applicationInfo, r.compatInfo,
                Context.CONTEXT_INCLUDE_CODE);
    }
    ComponentName component = r.intent.getComponent();
    // 反射创建Activity实例
    ClassLoader cl = appContext.getClassLoader();
    Activity activity = mInstrumentation.newActivity(cl, component.getClassName(), r.intent);
    // attach，创建Window
    activity.attach(appContext, this, getInstrumentation(), r.token,
            r.ident, app, r.intent, r.activityInfo, title, r.parent,
            r.embeddedID, r.lastNonConfigurationInstances, config,
            r.referrer, r.voiceInteractor, window, r.configCallback,
            r.assistToken);

    // 调用onCreate
    if (r.isPersistable()) {
        mInstrumentation.callActivityOnCreate(activity, r.state, r.persistentState);
    } else {
        mInstrumentation.callActivityOnCreate(activity, r.state);
    }
    // onStart
    mInstrumentation.callActivityOnStart(activity);
    // onResume 在handleResumeActivity
    return activity;
}
```

>
> 当是**复用实例（singleTop/singleTask）**，ATMS不会走realStartActivityLocked创建新Activity，而是直接调用`onNewIntent`，不会走onCreate/onStart。

## 三、Affinity 任务亲和性（singleTask的重点）

`android:taskAffinity`，标记Activity倾向归属哪个Task。

- 默认：包名。
- singleTask Activity，ATMS会优先寻找**相同affinity的Task**；没有就新建Task。
- 所以singleTask不一定全局单Task，不同affinity可以存在多个singleTask的Task。

## 四、Intent Flag 和 launchMode 优先级

1. 代码Intent Flag优先级 > Manifest launchMode；
2. FLAG_ACTIVITY_NEW_TASK：新建Task，和singleTask类似；
3. FLAG_ACTIVITY_SINGLE_TOP：运行时singleTop；
4. FLAG_ACTIVITY_CLEAR_TOP：打开目标页面，销毁上面所有Activity，常和NEW_TASK配合。

## 五、常见坑总结

1. singleTask 不是全局单例，**affinity不同可以多个Task**；
2. 启动模式的判断逻辑在system_server ATMS，不是App；
3. 复用实例只回调`onNewIntent`，**不走onCreate**；
4. singleInstance独占Task，这个Task不能放其他任何Activity；
5. standard模式就算跨进程，默认加入调用方的Task，除非加FLAG_ACTIVITY_NEW_TASK。

## 六、完整时序简图

```
App Activity
    ↓ startActivity()
Instrumentation.execStartActivity()
    ↓ Binder IPC
ATMS.startActivity() (system_server)
    ↓
ActivityStarter.execute()
    ↓【核心：读取launchMode，查找TaskRecord/ActivityRecord】
    ├─ 复用实例 → 触发onNewIntent，直接resume
    └─ 需要新建
        ├─ 进程不存在 → Zygote fork App进程
        └─ 进程存在 → realStartActivityLocked
            ↓ Binder IPC
ApplicationThread.scheduleTransaction() 【App进程】
    ↓ H Handler消息
ActivityThread.handleLaunchActivity()
    ↓ performLaunchActivity
反射new Activity → attach → onCreate → onStart → onResume
```
