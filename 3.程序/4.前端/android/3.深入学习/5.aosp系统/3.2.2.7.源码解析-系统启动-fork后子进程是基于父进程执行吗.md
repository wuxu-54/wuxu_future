# fork后子进程是基于父进程执行吗？

✅ **是的，fork之后，子进程是父进程的副本，从fork调用点之后继续往下执行，不是从头跑。**

> 
> Linux `fork()`：调用fork的那条线程**返回两次**
> 
> 
> - 父进程：`fork()` 返回 **子进程pid（>0）**，继续执行fork之后代码
> - 子进程：`fork()` 返回 **0**，**从fork返回的位置，继续执行后面代码**，而不是重新启动程序、从头执行main。

> 
> 注意：**地址空间是复制（写时复制COW）**，fork瞬间父子进程内存内容一模一样，但后续各自独立。

# 1. 简单C示例理解底层行为

```
#include <unistd.h>
#include <stdio.h>
int main(){
    printf("fork之前\n");
    pid_t pid = fork();  // 【关键点】
    if(pid == 0){
        printf("我是子进程，pid=0分支\n");
    }else if(pid>0){
        printf("我是父进程，拿到子pid=%d\n",pid);
    }
    return 0;
}
```

执行输出：

```
fork之前
我是父进程，拿到子pid=1234
我是子进程，pid=0分支
```

解释：

1. `fork()`调用前代码，**只父进程跑一遍**（`fork之前`只打印一次）
2. 内核复制进程，`fork`返回
3. 父进程走到 `pid>0` 分支
4. 子进程直接从`pid_t pid = fork();`这一行的返回点继续执行，进入`pid ==0`分支。
👉 **子进程不会重新执行main开头，直接接着fork后面跑。**

# 2. 套入 Android Zygote 的场景（重点！）

Zygote 已经提前预加载大量class、资源（preload），**Zygote父进程执行nativeForkAndSpecialize里面的fork系统调用**。

```
// Zygote.java
int pid = nativeForkAndSpecialize(...); // JNI进入C++，调用linux fork()
// ===================== fork返回点 =====================
if (pid == 0) {
    // 子进程！从这里继续往下执行
    handleChildProc(...);
} else {
    // Zygote父进程，拿到子pid
}
```

时序：

1. Zygote（父）：执行到`nativeForkAndSpecialize`，进入C++，调用`fork()`，阻塞在内核
2. 内核复制Zygote进程（COW写时复制，预加载的类都在内存里，子进程直接共享）
3. fork返回：
   - 父进程：回到Java，pid=子进程id，走else分支
   - **子进程：直接回到这一行的返回位置，继续执行Java代码，进入 pid == 0 的分支 handleChildProc**

> 
> 👉 子进程继承Zygote所有已经预加载的类、内存、文件描述符，**不用重新preload**，这就是Zygote fork性能优势根源。

## 但是！子进程要做大量清理工作（native层+Java层）

虽然子进程是Zygote副本，但不能带着Zygote的环境跑App：

### Native层（fork之后子进程分支做）

1. 关闭Zygote服务端socket fd（非常关键，不然App进程持有socket会影响Zygote监听）
2. 设置uid/gid降权限、SELinux安全上下文
3. 关闭不需要的文件描述符

### Java层 handleChildProc

1. 关闭ZygoteServer
2. 准备App运行参数，最终调用 `ActivityThread.main()`> 
> ⚠️ 不是说fork完直接就是App！只是复制了Zygote内存，**必须清理Zygote相关资源，切换成App运行环境**。

# 3. 容易混淆的：fork vs exec

- **fork**：复制现有进程，从fork返回点继续运行，代码镜像不变（Zygote方案）
- **exec系列函数**：加载全新可执行文件，**替换整个进程镜像**，执行新程序的main；exec成功后**不会回到原来代码**。

> 
> Android app用Zygote fork，**没有exec**（普通App）；只有一些特殊场景会exec。

# 4. 几个重要特性：父子进程内存（COW写时复制）

fork瞬间：父子**共享同一块物理内存**，只读，不拷贝。
当任意一方**写内存**，内核才会单独拷贝这一页内存。

- Zygote预加载的类、常量，几乎不会修改，父子一直共享内存，节省内存。
- App写自己变量的时候，才触发页面拷贝。

# 5. 父子进程执行是并行的

fork返回之后，父、子进程是两个独立进程，操作系统调度，**并行运行**，没有固定谁先跑。

> 
> Zygote父进程拿到pid后，把pid写回socket给AMS；子进程并行初始化App环境。

# 6. 面试高频坑

Q：子进程会重新跑ZygoteInit.main吗？
A：**不会**。ZygoteInit.main是fork**之前**父进程执行完的逻辑。fork之后子进程直接在`forkAndSpecialize`返回点继续执行，进入handleChildProc。

# 完整Zygote时序精简

```
Zygote 父进程：
ZygoteInit.main → preload() → ZygoteServer.runSelectLoop 等待socket请求
收到AMS创建进程请求 → Zygote.forkAndSpecialize()
        → nativeForkAndSpecialize JNI → C++调用fork()
        【内核复制进程】
fork返回：
父：pid>0 → 返回pid写回socket，继续runSelectLoop等待下一个请求
子：pid=0 → 继续往下执行handleChildProc() → 最终ActivityThread.main()
```

# 补充一个关键点：线程

Linux fork**只复制调用fork的那一条线程**。
所以Zygote fork前必须`preFork()`暂停所有其他ART线程，否则子进程里其他线程消失，锁状态残留，造成死锁。
