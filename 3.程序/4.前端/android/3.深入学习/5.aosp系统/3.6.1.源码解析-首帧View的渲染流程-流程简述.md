# Android：Activity onCreate → View首帧可见完整流程（承接你前面学的ActivityThread、ATMS、ClientTransaction）
>
> 前提回顾：ATMS通过ClientTransaction，给App进程发送`LaunchActivityItem`，ActivityThread主线执行 `handleLaunchActivity`，开始走Activity生命周期：**onCreate → onStart → onResume**。
> 重点：**setContentView只是把View树构建好，并不会执行measure/layout/draw；真正绘制是在handleResumeActivity、ViewRootImpl、VSync信号到来之后才触发**。

## 总链路一句话

`handleLaunchActivity` → onCreate(setContentView) → onStart → `handleResumeActivity`(onResume) → WindowManager.addView → 创建ViewRootImpl → requestLayout → scheduleTraversals → Choreographer等待VSync → performTraversals（measure/layout/draw）→ 渲染到Surface → SurfaceFlinger合成 → 屏幕上View可见。

## 阶段1：ActivityThread.handleLaunchActivity → onCreate 构建View树（**View此时只是内存对象，看不见**）

源码入口：`ActivityThread.java handleLaunchActivity`

```java
private void handleLaunchActivity(ActivityClientRecord r, Intent customIntent) {
    // 创建Activity实例
    Activity a = performNewActivity(r, customIntent);
    if (a != null) {
        // 调用onCreate
        performCreate(r, customIntent);
    }
}
```

`performCreate` → `activity.onCreate()`

### onCreate 里 setContentView 源码流程

```java
@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.activity_main);
}
```

1. `Activity.setContentView` → `PhoneWindow.setContentView()`（每个Activity持有一个PhoneWindow）
2. `installDecor()`：**创建DecorView**（根View，包含系统状态栏、标题栏 + 内容区域mContentParent，也就是`android.R.id.content`）
3. LayoutInflater.inflate：解析xml，递归实例化所有View，添加到`mContentParent`，**构建完整View树**

> ⚠️关键点：**这里只做xml解析、创建View对象、建立父子树；完全没有measure、layout、draw！View不知道自己大小和位置，不会渲染到屏幕。**

### onCreate结束 → onStart

`performStart()` → `activity.onStart()`
> onStart：Activity即将可见，View树已经全部创建完毕，但**仍然没有执行绘制**，页面依旧看不到。
> onStart只是生命周期回调，不会触发UI绘制。

## 阶段2：handleResumeActivity（最重要！ViewRootImpl在这里创建，绘制起点）

ATMS发送`ResumeActivityItem`，ActivityThread主线执行 `handleResumeActivity()`

```java
final void handleResumeActivity(IBinder token, boolean finalStateRequest, boolean isForward, String reason) {
    // 1. 回调Activity.onResume()
    r.activity.performResume();

    // 2. 获取DecorView、WindowManager
    final Activity a = r.activity;
    View decor = a.getWindow().getDecorView();
    WindowManager wm = a.getWindowManager();

    // 3. 【核心】addView，把DecorView提交给WindowManager
    wm.addView(decor, l);
}
```

`WindowManagerImpl.addView` → `WindowManagerGlobal.addView()`

```java
public void addView(View view, ViewGroup.LayoutParams params, Display display, Window parentWindow) {
    // ① 新建ViewRootImpl（View树的总管，连接App和WMS）
    ViewRootImpl root = new ViewRootImpl(view.getContext(), display);
    // ② 将DecorView绑定给ViewRootImpl
    root.setView(view, params, display, parentWindow);
}
```

### ViewRootImpl.setView()

```java
public void setView(View view, WindowManager.LayoutParams attrs, Display display, Window parentWindow) {
    // 向WMS发起跨进程Binder调用，注册window窗口
    mWindowSession.addToDisplay(...);
    // 触发布局绘制请求
    requestLayout();
}
```

`requestLayout()`：标记需要重新测量布局，调用 `scheduleTraversals()`

```java
void scheduleTraversals() {
    if (!mTraversalScheduled) {
        mTraversalScheduled = true;
        // 主线Handler插入【同步屏障】，优先执行UI绘制任务，阻塞普通消息
        mTraversalBarrier = mHandler.getLooper().getQueue().postSyncBarrier();
        // 向Choreographer注册VSync回调任务 mTraversalRunnable
        mChoreographer.postCallback(Choreographer.CALLBACK_TRAVERSAL, mTraversalRunnable, null);
    }
}
```

- Choreographer：编舞者，负责监听硬件VSync垂直同步信号（60Hz≈16ms一次）
- 这里**不会立刻绘制**，只是注册回调，等待下一次VSync信号到来。

## 阶段3：VSync信号到来 → 执行mTraversalRunnable → performTraversals（View三大绘制流程）

VSync硬件信号到达 → `Choreographer`回调 `mTraversalRunnable.run()` → `ViewRootImpl.performTraversals()`
> performTraversals是View绘制总入口，一次性执行 measure → layout → draw
>
### 1）performMeasure() 测量

递归遍历View树，**从根DecorView往下深度优先**

- View.onMeasure( widthMeasureSpec, heightMeasureSpec )
- MeasureSpec = mode + size；由父View传递给子View，约束子View最大可用空间
- 每个View计算自己需要的宽高，保存mMeasuredWidth/mMeasuredHeight

> 此时拿到**测量尺寸，但View还没有最终的left/top/right/bottom坐标**

### 2）performLayout() 布局

递归调用 View.onLayout()（ViewGroup会遍历子view，调用child.layout(l,t,r,b)）

- 父ViewGroup根据子View测量结果，分配位置，设置四个坐标 left top right bottom

> 到此，**每个View的大小+屏幕位置全部确定**，但是还没有画到画布上。

### 3）performDraw() 绘制

```
performDraw() → drawSoftware() → mSurface.lockCanvas()拿到画布Canvas → draw(canvas)
```

1. DecorView.draw(canvas)，递归遍历View树
    - drawBackground() 绘制背景
    - onDraw()：控件自身绘制内容（TextView文字、Button背景）
    - dispatchDraw()：绘制子View
    - drawForeground()、滚动条等
2. 全部绘制完成：`mSurface.unlockCanvasAndPost(canvas)`
    将绘制好的buffer提交给Surface，交给SurfaceFlinger。

## 阶段4：SurfaceFlinger 合成，屏幕显示

SurfaceFlinger（系统native进程）收集所有App的Surface缓冲区，做图层叠加、合成、硬件渲染，输出到屏幕硬件。
✅ **到这一步，用户肉眼才能看到View。**

# 生命周期时序重点澄清（面试高频坑）

1. **onCreate / onStart：View对象存在，但没有测量、没有绘制，不可见**
2. **onResume执行完 ≠ 页面可见！**
onResume只是Activity状态回调；真正的绘制要等 `addView→ViewRootImpl→VSync→performTraversals` 首帧走完，SurfaceFlinger合成完成，View才可见。

> 一句话：onResume只是Activity进入前台状态，首帧绘制完成，才真正可见。

# 关键对象关系

```
Activity 持有 PhoneWindow
PhoneWindow 持有 DecorView（根View）
DecorView是整个View树根
ViewRootImpl：View树管理者，Binder连接WMS；触发三大绘制流程
Choreographer：VSync信号调度，控制帧时序
Surface：绘图缓冲区，App往里面画，SurfaceFlinger合成
```

# 常见面试追问

## Q1：requestLayout 和 invalidate 区别

- `requestLayout()`：**重新measure + layout**，不会draw；触发scheduleTraversals，等VSync执行完整遍历。View尺寸/位置变化调用。
- `invalidate()`：只触发draw，**不会重新measure/layout**，仅重绘当前View及脏区域。

## Q2：同步屏障作用

主线Looper插入同步屏障，屏障之后普通Message不能执行；**UI绘制任务优先执行**，保证UI绘制优先，减少卡顿。绘制完成移除屏障。

## Q3：为什么onCreate设置完setContentView，拿不到view宽高？

因为setContentView只实例化View树，**还没有执行performMeasure/performLayout**，mMeasuredWidth还没有值。
解决：`view.post{}` 放到主线消息队列，等首帧绘制前消息执行，此时已经measure/layout完成。

## Q4：View绘制在哪个线程？

**主线程（ActivityThread主线Looper）**；所有measure/layout/draw都在主线，这就是为什么主线不能做耗时操作，会阻塞VSync，丢帧卡顿。

# 完整串联（承接前面Activity启动链路）

>注意，下面的流程基于旧版本，Android14以后的版本都改为事务进行处理，通过LifecycleItem进行状态更换，从而触发onStart等中间状态。具体看上面文章。

```
ATMS发送LaunchActivityItem → ActivityThread.handleLaunchActivity
    → Activity实例创建
    → performCreate → Activity.onCreate()
        → setContentView() → PhoneWindow → 创建DecorView，inflate xml构建View树
    → performStart → onStart()
ATMS发送ResumeActivityItem → ActivityThread.handleResumeActivity
    → onResume()
    → wm.addView(DecorView)
        → WindowManagerGlobal创建ViewRootImpl
        → ViewRootImpl.setView()，向WMS注册窗口
        → requestLayout() → scheduleTraversals，插入同步屏障，Choreographer注册VSync回调
等待硬件VSync信号到达
    → mTraversalRunnable.run() → performTraversals
        → performMeasure 递归测量View树
        → performLayout 递归布局，确定View位置
        → performDraw 绘制到Surface的Canvas，unlockCanvasAndPost提交buffer
SurfaceFlinger合成图层，输出到屏幕 → View对用户可见
```
