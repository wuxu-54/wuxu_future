# IdleHandler 完整详解

>实际开发中可以进行空闲任务的执行。注意：依据下面的内容，不可以进行耗时任务。

## 一句话概括

`MessageQueue.IdleHandler` 是**MessageQueue 的回调接口**：
> 当主线程消息队列**当前没有需要马上执行的消息**（队列空闲）的时候，Looper 会回调 `IdleHandler.queueIdle()`；
> 如果回调返回 `false`，这个 IdleHandler 执行一次之后就自动移除；返回 `true` 则保留，下次空闲还会再次回调。

> 注意：它是 **MessageQueue 的内部接口**，不是 Handler、不是 Looper。

```java
public static interface IdleHandler {
    boolean queueIdle();
}
```

## 一、触发时机（Legacy 版本 nextLegacy 源码位置）

放在 `nextLegacy()` 的 synchronized 代码块里面，**当队列没有到期消息时**才会执行 IdleHandler。

```java
// nextLegacy 简化源码
synchronized (this) {
    // ...查找消息，没有找到到期消息
    // 消息队列为空 / 最近的消息还没到执行时间
    // 此时进入空闲，遍历执行 IdleHandler
    for (int i = 0; i < mIdleHandlers.size(); i++) {
        IdleHandler idler = mIdleHandlers.get(i);
        boolean keep = idler.queueIdle(); // 回调！
        if (!keep) {
            mPendingIdleHandlers.remove(idler);
        }
    }
}
```

触发的条件，**必须同时满足**：

1. Looper 拿到锁，遍历消息链表；
2. **没有已经到期可以立刻执行的消息**（要么队里没消息，要么下一条消息的`when`在未来，还没到时间）；
3. 才会依次执行 `mIdleHandlers` 列表里所有 IdleHandler 的 `queueIdle()`；
4. IdleHandler 执行完，继续调用 `nativePollOnce`，主线程进入休眠阻塞。

> ⚠️ 关键点：
> **IdleHandler 是在主线程执行！** 是在 `next()` 内部、synchronized 锁内执行的。
> 不要在 `queueIdle()` 写耗时逻辑！会卡住主线程，甚至ANR。

## 二、返回值含义（非常重要）

```java
boolean queueIdle();
```

1. **return false**：执行完本次，**把这个IdleHandler从列表移除，只执行一次**（最常用）
2. **return true**：保留，**下一次队列空闲时，还会再次执行**

## 三、添加和移除

```java
// 添加
mQueue.addIdleHandler(new MessageQueue.IdleHandler() {
    @Override
    public boolean queueIdle() {
        // 空闲时执行逻辑
        return false; // 执行一次就销毁
    }
});

// 移除
mQueue.removeIdleHandler(idleHandler);
```

> 获取主线程MessageQueue：`Looper.getMainLooper().getQueue()`

## 四、经典使用场景

### 场景1：ViewTreeObserver，监听View绘制完成

最典型的系统内部使用。
View 渲染完成后，主线程消息队列空闲，再回调 `OnGlobalLayoutListener`，本质底层就是依靠 IdleHandler。
> 因为onCreate/onResume的时候View还没完成测量布局，直接拿宽高拿到的是0；
> 放到IdleHandler，等主线程把当前所有绘制相关消息执行完毕，空闲时再获取View尺寸。

### 场景2：页面初始化做非紧急任务

页面onCreate的时候，很多非紧急任务：预加载图片、埋点统计、预初始化SDK，**不阻塞页面绘制**。
> 不要放在onCreate直接执行（会拖慢首帧），放到IdleHandler，等首帧绘制完成、主线程空闲再跑。

示例伪代码：

```java
Looper.getMainLooper().getQueue().addIdleHandler(new MessageQueue.IdleHandler() {
    @Override
    public boolean queueIdle() {
        // 首帧绘制完成，主线程空闲，执行低优先级任务
        preLoadImage();
        trackPageEnter();
        return false; // 只执行一次
    }
});
```

### 场景3：延迟清理、轻量GC建议、资源释放

等主线程空闲时做清理，避免抢占UI时间。

## 五、重要特性 & 容易踩坑的点

### 1. 不是一定会回调！

如果主线程消息**永远源源不断**，队列永远不空闲 → IdleHandler永远不会执行。
> 例如：持续不断发送post消息，消息一直排满，IdleHandler一直得不到机会执行。

### 2. IdleHandler 执行在 synchronized(this) 锁内（Legacy版本）

Legacy模式下，执行queueIdle的时候，**持有MessageQueue对象锁**！

- 不要在`queueIdle()`里面调用`sendMessage/post`这种会入队消息的操作，虽然可以，但要小心死锁风险；
- 尽量保持`queueIdle()`逻辑简短。

> API37 DeliQueue：依然保留IdleHandler，触发行为不变，只是锁模型变了，不再是legacy的全局synchronized。

### 3. IdleHandler 不属于Message，**不进消息链表**

IdleHandler 单独保存在 `mIdleHandlers` 列表，不是Message，不受同步屏障、when时间调度控制。
同步屏障只影响Message消息，**不影响IdleHandler**。

### 4. 和postDelayed的区别

- `post/postDelayed`：作为Message入消息队列，按when排队，优先级和普通消息一致；
- IdleHandler：**只有队列空闲才跑，没有固定时间，优先级最低**。

举个例子：
页面onCreate同时提交：

1. post 一个Runnable
2. addIdleHandler

执行顺序：
主线程优先执行所有普通消息（包括post的runnable、绘制消息），**全部处理完，队列空闲之后，才跑IdleHandler**。
> IdleHandler是主线程最低优先级任务。

## 六、IdleHandler 执行时序（主线程）

1. 主线程Looper循环调用`next()`
2. nativePollOnce唤醒
3. 拿到MessageQueue锁，查找到期消息
4. ✅ 如果找到到期消息：取出消息，执行dispatchMessage，**IdleHandler不会执行**
5. ❌ 如果没有到期消息：依次执行IdleHandler的queueIdle()
6. 执行完IdleHandler，释放锁，再次调用nativePollOnce，主线程休眠

## 七、DeliQueue（API37）的IdleHandler变化

DeliQueue重构了消息存储，但 **IdleHandler 行为完全保留，对外API不变**：

- 依然是队列无到期消息时触发IdleHandler；
- 同样支持返回true/false控制是否重复执行；
- 内部不再是legacy的synchronized大锁，但触发时机、业务表现完全一致。

## 八、面试高频问题

### Q1：IdleHandler 在哪个线程执行？

A：添加到哪个Looper的MessageQueue，就在哪个Looper线程执行；一般是主线程。

### Q2：IdleHandler 和同步屏障有关系吗？

A：没有直接关系。同步屏障是控制Message的调度；IdleHandler是队列空闲回调，独立逻辑。

### Q3：queueIdle里面做耗时操作会怎么样？

A：**主线程阻塞，丢帧、ANR**。因为它在主线程同步块里执行。

### Q4：IdleHandler一定会执行吗？

A：不一定。如果消息队列持续有消息，永远不会空闲，IdleHandler就永远不回调。

## 一句话总结面试背诵版
>
> IdleHandler是MessageQueue的内部回调接口，当Looper发现消息队列没有到期消息、处于空闲状态时，会回调queueIdle；返回false执行一次就移除，返回true则重复执行。它运行在Looper线程，优先级最低，常用来在页面首帧绘制完成后执行非紧急任务。
