# runSelectLoop 源码位置

**文件：`frameworks/base/core/java/com/android/internal/os/ZygoteServer.java`**

> 
> 旧版本写在 ZygoteInit.java，新版抽离到 ZygoteServer，**底层是 IO多路复用 poll（不是select，名字叫runSelectLoop是历史命名）**

## 核心思想

`while(true)` 死循环 + **Os.poll() 阻塞等待多个fd事件**

- fd列表保存两类文件描述符：
  1. **ServerSocket的fd（下标0）**：监听有没有新客户端（AMS）来建立连接
  2. 已建立连接的socket fd：AMS已经连上，正在发送创建App进程的命令

> 
> `Os.poll(pollFds, -1)`，第二个参数 `-1` = **无限阻塞**，没有消息时Zygote进程休眠，不耗CPU；只要任意fd可读，poll立刻返回，开始处理事件。

## 精简源码

```
void runSelectLoop(String abiList) throws Zygote.MethodAndArgsCaller {
    ArrayList<FileDescriptor> fds = new ArrayList<>();
    ArrayList<ZygoteConnection> peers = new ArrayList<>();

    // 【第0号fd：服务端监听socket】/dev/socket/zygote
    fds.add(mServerSocket.getFileDescriptor());
    peers.add(null);

    while (true) { // ✅死循环
        // 1. 把fds列表转为poll需要的结构体数组
        StructPollfd[] pollFds = new StructPollfd[fds.size()];
        for (int i = 0; i < pollFds.length; ++i) {
            pollFds[i] = new StructPollfd();
            pollFds[i].fd = fds.get(i);
            pollFds[i].events = (short) POLLIN; // 监听：是否有数据可读
        }

        try {
            // 2. 【阻塞点】poll，没有事件就卡在这，休眠
            Os.poll(pollFds, -1);
        } catch (ErrnoException ex) {
            throw new RuntimeException("poll failed", ex);
        }

        // 3. 遍历，找出哪个fd触发了可读事件
        for (int i = pollFds.length - 1; i >= 0; --i) {
            if ((pollFds[i].revents & POLLIN) == 0) {
                continue; // 这个fd没有事件，跳过
            }

            if (i == 0) {
                // =========情况1：下标0的ServerSocket可读 → 【AMS发起新连接】=========
                ZygoteConnection newPeer = acceptCommandPeer(abiList);
                peers.add(newPeer);
                fds.add(newPeer.getFileDescriptor());
                // 把新连接fd加入监听列表，下一轮poll会同时监听这个连接
            } else {
                // =========情况2：已存在的连接有数据 → 【AMS发送创建进程命令】=========
                ZygoteConnection connection = peers.get(i);
                // runOnce → processOneCommand，里面调用Zygote.forkAndSpecialize
                boolean done = connection.runOnce(this);

                if (done) {
                    // 本次请求处理完毕，移除这个连接，关闭fd
                    peers.remove(i);
                    fds.remove(i);
                }
            }
        }
    }
}
```

## 完整执行流程拆解

1. **初始化**：把 `/dev/socket/zygote` 服务端socket fd放入fds数组，peers[0]=null（服务socket没有连接对象）
2. **进入while(true)永久循环**
3. 构造poll数组，所有fd都监听`POLLIN`（可读事件）
4. **Os.poll 阻塞休眠**：没有AMS消息，线程卡在这，不跑CPU
5. AMS请求过来，poll返回，找到就绪fd
   - 如果`i ==0`：是**新连接**，`accept()`拿到client socket，封装`ZygoteConnection`，加到fds、peers列表；**下一轮poll就会同时监听这个新连接**
   - 如果`i>0`：**已有连接收到数据**，调用`connection.runOnce()`
     - `runOnce()` → `processOneCommand()` 解析AMS发来的参数（包名、uid等）
     - 调用 `Zygote.forkAndSpecialize()` fork子进程
     - ✅ **fork之后，父子进程分裂**
       - Zygote父进程：继续回到runSelectLoop循环，继续等待下一个App启动请求
       - App子进程：跳出循环，执行`ActivityThread.main()`，启动App
6. 单次命令处理完成，`done=true`，把这个连接从fds/peers删掉，关闭socket；回到循环，再次调用poll阻塞等待下一条消息

## 几个容易踩坑的知识点

1. **名字叫runSelectLoop，但底层是poll不是select**。早年Android用select，后来改成poll，方法名保留历史名字。
2. **单线程模型！** Zygote只有这一个主线程跑poll循环，串行处理AMS请求，一次只能处理一个App创建请求。
3. **为什么用Unix Socket而不是Binder？**
 AMS和Zygote之间：**Binder只发控制指令，真正的创建进程请求走Unix Socket**，方便传递文件描述符、安全身份校验。
4. fork发生在`ZygoteConnection.processOneCommand`，**不是在runSelectLoop本身**，runSelectLoop只负责监听socket事件、调度连接。

## 事件时序示例（点击App图标）

```
AMS（system_server）→ connect /dev/socket/zygote
    ↓
runSelectLoop poll唤醒，i=0，accept，新增ZygoteConnection
AMS在这个socket发送创建App参数
    ↓
poll再次唤醒，i>0 → connection.runOnce()
    ↓ Zygote.forkAndSpecialize()
父Zygote：回到while循环，继续poll等待
子App进程：ActivityThread.main()
```

## 补充：异常跳出

当`fork`之后**子进程**会抛出`Zygote.MethodAndArgsCaller`异常，**跳出runSelectLoop循环**，这个异常是设计好的，用来跳出多层调用栈，最后执行ActivityThread.main。**父Zygote不会抛异常，继续循环**。
