# systemctl服务控制

`systemctl` 是 Linux 系统中 **systemd 系统初始化管理器** 的核心命令，用于统一管理系统服务（Service）、运行级别（Target）、挂载点（Mount）、定时器（Timer）等“单元（Unit）”，替代了传统 SysVinit 系统的 `service`、`chkconfig`、`init` 等命令。它是现代 Linux 发行版（如 CentOS 7+、Ubuntu 15.04+、Debian 8+）中系统管理的“一站式工具”。

## 一、基础概念：systemd 与 Unit（单元）

在学习 `systemctl` 前，需先理解两个核心概念：

### 1. systemd

`systemd` 是 Linux 系统的初始化系统（Init System），负责系统启动时的进程管理、服务激活、硬件初始化等核心工作，其设计目标是解决传统 SysVinit 启动慢、依赖管理复杂的问题。

### 2. Unit（单元）

`systemd` 将系统中的资源（服务、挂载点、定时器等）抽象为“单元”，每个单元对应一个配置文件（通常位于 `/usr/lib/systemd/system/` 或 `/etc/systemd/system/`）。`systemctl` 的所有操作都围绕“单元”展开。

常见 Unit 类型及作用：

| Unit 类型 | 后缀名       | 作用描述                                                                 | 示例                          |
|-----------|--------------|--------------------------------------------------------------------------|-------------------------------|
| Service   | `.service`   | 系统服务（如 Nginx、SSH、MySQL），最常用的单元类型                         | `nginx.service`、`sshd.service` |
| Target    | `.target`    | 运行级别（类似传统 SysVinit 的 runlevel），用于分组相关服务                 | `multi-user.target`（命令行模式）、`graphical.target`（图形界面模式） |
| Mount     | `.mount`     | 文件系统挂载点，管理磁盘分区或网络文件系统的挂载                           | `mnt_data.mount`（挂载 `/mnt/data`） |
| Socket    | `.socket`    | 监听网络或本地 socket，用于“按需激活”服务（服务在有请求时才启动）           | `sshd.socket`、`nginx.socket` |
| Timer     | `.timer`     | 定时器（类似 `cron`），用于周期性执行任务或延迟启动服务                     | `logrotate.timer`（日志轮转定时器） |
| Path      | `.path`      | 路径监控，当指定路径的文件/目录发生变化时激活服务                           | `nginx-watch.path`（监控 Nginx 配置文件） |

## 二、`systemctl` 基本语法

```bash
systemctl [选项] [命令] [单元名]
```

- **选项**：可选，用于调整命令行为（如 `--now` 立即执行、`--no-pager` 不分页输出）。  
- **命令**：核心操作（如 `start` 启动、`enable` 开机启动）。  
- **单元名**：指定操作的单元（可省略后缀，如 `nginx` 等价于 `nginx.service`）。  

**关键简化规则**：  

- 操作 `Service` 单元时，可省略 `.service` 后缀（如 `systemctl start nginx` 等价于 `systemctl start nginx.service`）。  
- 操作 `Target` 单元时，可省略 `.target` 后缀（如 `systemctl isolate multi-user` 等价于 `systemctl isolate multi-user.target`）。

## 三、核心命令：按功能分类

### 1. 服务管理（Service 单元）

最常用的功能，用于控制系统服务的启动、停止、重启、状态查询等。

| 命令格式                          | 功能描述                                                                 | 示例                                  |
|-----------------------------------|--------------------------------------------------------------------------|---------------------------------------|
| `systemctl start <服务名>`        | 立即启动指定服务                                                         | `systemctl start nginx`（启动 Nginx） |
| `systemctl stop <服务名>`         | 立即停止指定服务                                                         | `systemctl stop nginx`（停止 Nginx） |
| `systemctl restart <服务名>`      | 重启指定服务（先停止再启动，适合服务配置修改后）                           | `systemctl restart nginx`（重启 Nginx） |
| `systemctl reload <服务名>`       | 重新加载服务配置（不停止服务，需服务支持此功能）                           | `systemctl reload nginx`（重载 Nginx 配置） |
| `systemctl status <服务名>`       | 查看服务状态（运行状态、PID、日志片段等）                                 | `systemctl status nginx`（查看 Nginx 状态） |
| `systemctl try-restart <服务名>`  | 仅当服务正在运行时才重启（避免服务未启动时的错误）                         | `systemctl try-restart nginx`         |
| `systemctl reload-or-restart <服务名>` | 优先重载配置，若重载失败则重启服务（更健壮的配置更新方式）             | `systemctl reload-or-restart nginx`   |
| `systemctl is-active <服务名>`    | 检查服务是否“活跃”（运行中），返回 `active` 或 `inactive`                 | `systemctl is-active nginx`           |

**`systemctl status <服务名>` 输出解读**（以 Nginx 为例）：

```bash
● nginx.service - A high performance web server and a reverse proxy server
     Loaded: loaded (/lib/systemd/system/nginx.service; enabled; vendor preset: enabled)
     Active: active (running) since Wed 2024-05-22 10:00:00 CST; 2h 30min ago
       Docs: man:nginx(8)
   Main PID: 1234 (nginx)
      Tasks: 2 (limit: 4915)
     Memory: 5.6M
     CGroup: /system.slice/nginx.service
             ├─1234 nginx: master process /usr/sbin/nginx -g daemon on; master_process on;
             └─5678 nginx: worker process
```

- `Loaded`：服务配置文件路径及开机启动状态（`enabled` 表示开机启动，`disabled` 表示否）。  
- `Active`：服务当前状态（`active (running)` 运行中，`inactive (dead)` 已停止，`failed` 启动失败）。  
- `Main PID`：服务主进程 ID。  
- `Tasks`：服务关联的进程数。  

### 2. 开机启动管理（Enable/Disable）

控制服务是否在系统启动时自动激活，核心是“建立/删除服务配置文件的软链接”。

| 命令格式                          | 功能描述                                                                 | 示例                                  |
|-----------------------------------|--------------------------------------------------------------------------|---------------------------------------|
| `systemctl enable <服务名>`       | 设置服务开机启动（创建软链接到 `multi-user.target.wants/` 等目录）        | `systemctl enable nginx`（Nginx 开机启动） |
| `systemctl disable <服务名>`      | 取消服务开机启动（删除软链接）                                           | `systemctl disable nginx`（取消 Nginx 开机启动） |
| `systemctl enable --now <服务名>` | 同时设置开机启动并立即启动服务（一步完成 enable + start）                 | `systemctl enable --now nginx`        |
| `systemctl disable --now <服务名>`| 同时取消开机启动并立即停止服务（一步完成 disable + stop）                 | `systemctl disable --now nginx`       |
| `systemctl is-enabled <服务名>`   | 检查服务是否“开机启动”，返回 `enabled`、`disabled` 或 `masked`（屏蔽）     | `systemctl is-enabled nginx`          |
| `systemctl mask <服务名>`         | 屏蔽服务（禁止启动，即使手动 `start` 也会失败，比 `disable` 更严格）       | `systemctl mask nginx`                |
| `systemctl unmask <服务名>`       | 解除服务屏蔽                                                             | `systemctl unmask nginx`              |

### 3. 运行级别管理（Target 单元）

`Target` 单元对应传统 SysVinit 的“运行级别”，用于分组启动一组服务（如图形界面需启动 X 服务、窗口管理器等）。

#### 常见 Target 与传统 Runlevel 对应关系：

| systemd Target          | 传统 Runlevel | 作用描述                                                                 |
|-------------------------|---------------|--------------------------------------------------------------------------|
| `poweroff.target`       | 0             | 关机                                                                     |
| `rescue.target`         | 1             | 单用户救援模式（无网络，仅基础服务，用于修复系统）                       |
| `multi-user.target`     | 3             | 多用户命令行模式（无图形界面，常用服务器模式）                           |
| `graphical.target`      | 5             | 多用户图形界面模式（包含 `multi-user.target` 的服务 + 图形相关服务）     |
| `reboot.target`         | 6             | 重启                                                                     |
| `emergency.target`      | -             | 紧急模式（仅加载最基础的内核和文件系统，需手动挂载其他分区，用于严重故障修复） |

#### Target 管理命令：

| 命令格式                          | 功能描述                                                                 | 示例                                  |
|-----------------------------------|--------------------------------------------------------------------------|---------------------------------------|
| `systemctl get-default`           | 查看当前默认的 Target（系统启动后进入的运行级别）                         | `systemctl get-default`（输出 `multi-user.target` 或 `graphical.target`） |
| `systemctl set-default <Target>`  | 设置默认 Target（永久生效，下次启动生效）                                 | `systemctl set-default graphical.target`（默认进入图形界面） |
| `systemctl isolate <Target>`      | 立即切换到指定 Target（临时生效，不影响默认设置）                         | `systemctl isolate multi-user.target`（从图形界面切换到命令行模式） |
| `systemctl list-dependencies <Target>` | 查看指定 Target 依赖的单元（哪些服务会随 Target 启动）                 | `systemctl list-dependencies graphical.target` |
| `systemctl reboot`                | 重启系统（等价于 `systemctl start reboot.target`）                        | `systemctl reboot`                    |
| `systemctl poweroff`              | 关机（等价于 `systemctl start poweroff.target`）                          | `systemctl poweroff`                  |
| `systemctl rescue`                | 进入救援模式（等价于 `systemctl isolate rescue.target`）                  | `systemctl rescue`                    |
| `systemctl emergency`             | 进入紧急模式（等价于 `systemctl isolate emergency.target`）               | `systemctl emergency`                 |

### 4. 单元查询与列表

查看系统中所有单元的状态、类型等信息，用于排查服务是否存在或运行异常。

| 命令格式                          | 功能描述                                                                 | 示例                                  |
|-----------------------------------|--------------------------------------------------------------------------|---------------------------------------|
| `systemctl list-units`            | 查看当前“活跃”的所有单元（默认输出，含服务、Target、挂载点等）             | `systemctl list-units`                |
| `systemctl list-units --all`      | 查看所有单元（含活跃和非活跃的）                                         | `systemctl list-units --all`          |
| `systemctl list-units --type=<类型>` | 查看指定类型的单元（如 `service`、`target`、`mount`）                   | `systemctl list-units --type=service`（查看所有服务） |
| `systemctl list-units --state=<状态>` | 查看指定状态的单元（如 `active`、`inactive`、`failed`）                 | `systemctl list-units --state=failed`（查看启动失败的单元） |
| `systemctl show <单元名>`         | 查看指定单元的详细配置（所有参数，如启动超时、用户、依赖等）               | `systemctl show nginx.service`        |
| `systemctl cat <单元名>`          | 查看指定单元的配置文件内容（直接输出 `.service` 等文件的内容）            | `systemctl cat nginx.service`         |

### 5. 挂载点管理（Mount 单元）

管理文件系统的挂载（替代传统 `mount` 命令的部分功能），尤其适合“永久挂载”（配置文件位于 `/etc/systemd/system/`）。

| 命令格式                          | 功能描述                                                                 | 示例                                  |
|-----------------------------------|--------------------------------------------------------------------------|---------------------------------------|
| `systemctl start <挂载单元>`      | 立即挂载指定挂载点                                                       | `systemctl start mnt_data.mount`（挂载 `/mnt/data`） |
| `systemctl stop <挂载单元>`       | 立即卸载指定挂载点                                                       | `systemctl stop mnt_data.mount`（卸载 `/mnt/data`） |
| `systemctl enable <挂载单元>`     | 设置挂载点开机自动挂载                                                   | `systemctl enable mnt_data.mount`     |
| `systemctl list-units --type=mount` | 查看所有挂载单元的状态                                                   | `systemctl list-units --type=mount`   |

### 6. 日志查看（配合 `journalctl`）

`systemctl` 本身不直接查看日志，但 `systemd` 配套的 `journalctl` 命令可查看单元的日志（`journalctl` 依赖 `systemd-journald` 服务）。

| 命令格式                          | 功能描述                                                                 | 示例                                  |
|-----------------------------------|--------------------------------------------------------------------------|---------------------------------------|
| `journalctl -u <服务名>`          | 查看指定服务的所有日志                                                   | `journalctl -u nginx.service`（查看 Nginx 日志） |
| `journalctl -u <服务名> -f`       | 实时跟踪指定服务的日志（类似 `tail -f`）                                 | `journalctl -u nginx.service -f`      |
| `journalctl -u <服务名> --since "1h ago"` | 查看指定服务1小时内的日志                                           | `journalctl -u nginx.service --since "1h ago"` |
| `journalctl -u <服务名> --no-pager` | 不分页输出日志（适合管道处理）                                         | `journalctl -u nginx.service --no-pager | grep "error"` |

### 7. 高级命令

| 命令格式                          | 功能描述                                                                 | 示例                                  |
|-----------------------------------|--------------------------------------------------------------------------|---------------------------------------|
| `systemctl daemon-reload`         | 重新加载 `systemd` 配置文件（当修改 `.service` 等文件后，需执行此命令生效） | `systemctl daemon-reload`（修改 Nginx 服务文件后执行） |
| `systemctl reset-failed`          | 重置“启动失败”的单元状态（清除 `failed` 标记，用于修复后重新尝试启动）     | `systemctl reset-failed nginx.service` |
| `systemctl kill <服务名>`         | 向服务进程发送信号（默认 `SIGTERM`，强制终止用 `-s SIGKILL`）              | `systemctl kill -s SIGKILL nginx`（强制杀死 Nginx） |
| `systemctl list-sockets`          | 查看所有 Socket 单元的状态（哪些服务通过 Socket 监听请求）                 | `systemctl list-sockets`              |

## 四、自定义 Service 单元（编写 `.service` 文件）

若需将自定义程序（如脚本、二进制程序）作为系统服务管理，需手动编写 `.service` 配置文件，步骤如下：

### 1. 配置文件路径

- 系统级服务（所有用户可用）：`/usr/lib/systemd/system/`（或 `/lib/systemd/system/`，软链接）。  
- 用户级服务（仅当前用户可用）：`~/.config/systemd/user/`。  

### 2. 基本配置模板（以自定义脚本 `my-script.sh` 为例）

创建 `/usr/lib/systemd/system/my-script.service`，内容如下：

```ini
[Unit]
Description=My Custom Script Service  # 服务描述
After=network.target  # 服务启动依赖：在 network.target 之后启动（确保网络可用）

[Service]
Type=simple  # 服务类型（simple：主进程启动后服务即激活；forking：主进程fork子进程后退出，子进程为服务进程）
ExecStart=/usr/local/bin/my-script.sh  # 服务启动命令（绝对路径）
ExecStop=/bin/kill -TERM $MAINPID  # 服务停止命令（$MAINPID 为服务主进程ID）
Restart=on-failure  # 重启策略：仅当服务失败时重启（可选：always 总是重启，on-abnormal 异常退出时重启）
User=root  # 运行服务的用户（建议用非root用户，如 appuser）
Group=root  # 运行服务的组

[Install]
WantedBy=multi-user.target  # 服务安装目标：随 multi-user.target 启动（开机启动时激活）
```

### 3. 生效与测试

```bash
# 1. 赋予脚本执行权限
chmod +x /usr/local/bin/my-script.sh

# 2. 重新加载 systemd 配置
systemctl daemon-reload

# 3. 启动服务并设置开机启动
systemctl enable --now my-script.service

# 4. 查看服务状态
systemctl status my-script.service
```

## 五、注意事项

1. **权限问题**：管理系统服务（如 `start`、`enable`、`daemon-reload`）需 `root` 权限，普通用户需加 `sudo`。  
2. **配置文件修改后需 `daemon-reload`**：修改 `.service`、`.mount` 等文件后，必须执行 `systemctl daemon-reload` 才能让 `systemd` 识别变更。  
3. **服务启动失败排查流程**：  
   1. 执行 `systemctl status <服务名>` 查看状态摘要；  
   2. 执行 `journalctl -u <服务名> --no-pager` 查看详细日志，定位错误原因（如路径错误、权限不足）；  
   3. 修复问题后，若服务状态为 `failed`，需执行 `systemctl reset-failed <服务名>` 重置状态，再重新启动。  
4. **用户级服务**：用户级服务需用 `systemctl --user` 命令管理（如 `systemctl --user start my-user-service`），且无需 `sudo`。  

## 六、总结

`systemctl` 是现代 Linux 系统的核心管理工具，其核心价值在于：  

1. **统一管理入口**：整合服务、挂载点、定时器等资源，替代传统多个命令；  
2. **依赖管理**：通过 `After`、`Requires` 等配置，精准控制服务启动顺序；  
3. **按需激活**：结合 Socket、Path、Timer 单元，实现服务“按需启动”，节省资源；  
4. **日志集成**：与 `journalctl` 无缝配合，便于服务故障排查。  

掌握 `systemctl` 的服务管理、Target 切换、自定义 Service 编写等能力，是 Linux 系统运维的必备技能。
