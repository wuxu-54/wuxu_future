# PATH 变量

`PATH` 是 Linux、macOS 等类 Unix 系统中最核心的环境变量之一，它决定了 **系统在哪些目录中查找可执行命令**。当你在终端输入一个命令（如 `ls`、`python`）时，系统会自动在 `PATH` 包含的目录中依次查找对应的可执行文件，找到后立即执行；若所有目录都找不到，则会提示 `command not found`。

## 一、PATH 变量的作用与格式

### 1. 核心作用  

解决「命令执行路径问题」：无需输入完整路径（如 `/usr/bin/ls`），直接输入命令名（如 `ls`）即可执行，因为系统会自动在 `PATH` 目录中搜索。

### 2. 格式  

`PATH` 是一个 **以冒号 `:` 分隔的目录列表**，例如：  

```bash
echo $PATH
# 输出示例（不同系统可能不同）：
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games
```  

每个目录是系统查找命令的「候选路径」，系统会按 **从左到右的顺序** 依次搜索。

## 二、查看 PATH 变量

通过 `echo` 命令直接查看当前 `PATH` 的值：  

```bash
echo $PATH  # 输出所有路径（冒号分隔）
```  

若想更清晰地分行显示（方便查看），可结合 `tr` 命令：  

```bash
echo $PATH | tr ':' '\n'  # 每个目录单独一行显示
# 输出示例：
# /usr/local/sbin
# /usr/local/bin
# /usr/sbin
# ...
```  

## 三、修改 PATH 变量（临时/永久）

根据需求，`PATH` 的修改分为「临时生效」（当前终端会话）和「永久生效」（所有会话）两种方式。

### 1. 临时修改（仅当前终端有效）  

直接通过 `export` 命令添加目录，关闭终端后失效，适合临时测试。  

**语法**：  

```bash
export PATH=$PATH:/新目录路径  # 将新目录添加到 PATH 末尾（推荐，避免覆盖原有路径）
# 或
export PATH=/新目录路径:$PATH  # 将新目录添加到 PATH 开头（可能覆盖系统默认命令，谨慎使用）
```  

**示例**：  
将 `~/my_scripts` 目录（存放自己写的脚本）添加到 `PATH` 末尾：  

```bash
export PATH=$PATH:~/my_scripts
```  

添加后，`~/my_scripts` 目录下的可执行脚本（如 `mytool.sh`）可直接输入 `mytool.sh` 执行，无需输入完整路径。

### 2. 永久修改（所有终端会话生效）  

需将修改命令写入 shell 的配置文件（如 `.bashrc`、`.zshrc`），不同 shell 对应的配置文件不同：  

| 所用 shell | 配置文件（用户级，仅当前用户生效） | 系统级配置文件（所有用户生效，需 root 权限） |
|------------|------------------------------------|---------------------------------------------|
| bash       | `~/.bashrc` 或 `~/.bash_profile`   | `/etc/profile` 或 `/etc/bash.bashrc`        |
| zsh        | `~/.zshrc`                         | `/etc/zsh/zshrc`                            |
| sh         | `~/.profile`                       | `/etc/profile`                              |

**步骤（以 bash 为例）**：  

1. 编辑配置文件：  

   ```bash
   vim ~/.bashrc  # 或用 nano、gedit 等编辑器
   ```  

2. 在文件末尾添加路径（推荐添加到末尾）：  

   ```bash
   # 追加自定义目录到 PATH（替换为你的目录）
   export PATH=$PATH:~/my_scripts:/opt/new_app/bin
   ```  

3. 使配置生效（无需重启终端）：  

   ```bash
   source ~/.bashrc  # 或 . ~/.bashrc
   ```  

4. 验证是否生效：  

   ```bash
   echo $PATH | tr ':' '\n'  # 查看新目录是否已添加
   ```  

## 四、关键注意事项

### 1. 路径顺序的影响  

系统按 `PATH` 中目录的 **左→右顺序** 查找命令，若多个目录存在同名命令，**左侧目录的命令会被优先执行**，即先查到的优先执行。  

例如：  

```bash
export PATH=~/bin:$PATH  # 个人目录在系统目录前
```  

若 `~/bin` 中有 `python`，而系统目录 `/usr/bin` 中也有 `python`，则会优先执行 `~/bin/python`（可能导致版本冲突，需谨慎）。

### 2. 避免覆盖原有 PATH  

错误写法（会直接覆盖原有路径，导致系统命令失效）：  

```bash
export PATH=/new/dir  # 错误！原有路径被删除，ls、cd 等命令会失效
```  

正确写法（保留原有路径，仅追加新目录）：  

```bash
export PATH=$PATH:/new/dir  # 正确！$PATH 代表原有路径
```  

### 3. 目录权限要求  

`PATH` 中的目录只需 **可执行权限（x）**（允许系统进入目录查找文件），无需读权限（r）；但目录下的可执行文件需要 **对当前用户有执行权限（x）**。  

### 4. 移除 PATH 中的目录  

若需删除某个目录，可重新定义 `PATH`（保留其他目录）：  

```bash
# 假设当前 PATH 为：/a:/b:/c，需删除 /b
export PATH=/a:/c  # 直接重新赋值（适用于临时移除）

# 永久移除：编辑配置文件，删除对应添加目录的行，再 source 生效
```  

## 五、常见问题解决

### 1. 命令提示 `command not found`  

原因：该命令的可执行文件不在 `PATH` 包含的目录中。  
解决：  

- 方法1：将命令所在目录添加到 `PATH`（推荐）；  
- 方法2：输入命令的完整路径执行（如 `/usr/local/bin/newcmd`）。  

### 2. 明明添加了目录，命令仍无法执行  

检查：  

- 目录路径是否正确（是否有拼写错误、相对路径/绝对路径问题）；  
- 命令文件是否有执行权限（`chmod +x 命令文件`）；  
- 是否重新 `source` 了配置文件（永久修改时）；  
- 退出终端重新打开（确保配置生效）。  

### 3. 想让所有用户都能使用某个命令  

将命令所在目录添加到 **系统级配置文件**（如 `/etc/profile`），需 `root` 权限：  

```bash
sudo vim /etc/profile  # 编辑系统级配置
# 添加：export PATH=$PATH:/path/to/command_dir
sudo source /etc/profile  # 生效（或重启系统）
```  

## 总结  

`PATH` 变量是系统查找命令的「导航地图」，掌握其查看、修改方法，能极大提升命令行效率（如无需输入完整路径执行脚本/程序）。核心原则：**追加路径而非覆盖，注意顺序避免冲突**，临时修改用 `export`，永久修改写配置文件。
