# `diff` 与 `patch`

## 一、diff 命令：比较文件/目录差异

`diff` 用于分析两个文件或目录的差异，输出修改指令，是文本对比和版本控制的基础工具。

### 1. 基本语法

```bash
diff [选项] 源文件/目录 目标文件/目录
```

- 比较文件：`diff file1 file2`  
- 比较目录：`diff dir1 dir2`（递归比较目录内文件）  

### 2. 输出格式

#### （1）标准格式（默认）

以“行操作指令”描述差异，结构：  

```txt
[旧文件行范围][操作符][新文件行范围]
< 旧文件需删除的行
---
> 新文件需添加的行
```

- 操作符：`a`（添加）、`d`（删除）、`c`（修改）。  

示例：  
`diff old.txt new.txt` 输出：  

```txt
2c2
< banana
---
> orange
4c4
< date
---
> grape
```

#### （2）上下文格式（`-c` 选项）

显示差异行前后的上下文（默认3行），结构：  

```txt
*** 旧文件信息
--- 新文件信息
***************
*** 旧文件行范围 ****
! 旧文件差异行（!标记）
--- 新文件行范围 ----
! 新文件差异行（!标记）
```

示例：  
`diff -c old.txt new.txt` 输出：  

```txt
*** old.txt	2025-09-15 10:00:00
--- new.txt	2025-09-15 10:05:00
***************
*** 1,4 ****
  apple
! banana
  cherry
! date
--- 1,4 ----
  apple
! orange
  cherry
! grape
```

#### （3）统一格式（`-u` 选项，最常用）

合并上下文，适合生成补丁，结构：  

```txt
--- 旧文件信息
+++ 新文件信息
@@ -旧文件行范围 +新文件行范围 @@
 相同行（无标记）
-旧文件删除行（-标记）
+新文件添加行（+标记）
```

示例：  
`diff -u old.txt new.txt` 输出：  

```txt
--- old.txt	2025-09-15 10:00:00
+++ new.txt	2025-09-15 10:05:00
@@ -1,4 +1,4 @@
 apple
-banana
+orange
 cherry
-date
+grape
```

### 3. 常用选项

| 类别         | 选项                | 作用描述                                                                 |
|--------------|---------------------|--------------------------------------------------------------------------|
| **比较逻辑** | `-i`                | 忽略大小写差异（如“A”与“a”视为相同）                                     |
|              | `-b`                | 忽略空格数量差异（如“a  b”与“a b”视为相同）                              |
|              | `-w`                | 忽略所有空格（仅比较非空格字符）                                         |
|              | `-B`                | 忽略空行差异                                                             |
| **输出格式** | `-c`                | 生成上下文格式差异（默认3行上下文）                                      |
|              | `-u`                | 生成统一格式差异（适合补丁）                                             |
|              | `-C n`              | 上下文格式显示 `n` 行上下文                                              |
|              | `-U n`              | 统一格式显示 `n` 行上下文                                                |
|              | `-q`                | 仅报告“文件是否不同”，不输出具体差异                                     |
|              | `-s`                | 显示“文件相同”的信息（默认相同文件不输出）                               |
|              | `-y`                | 左右并排显示文件内容（差异行用`|`标记）                                  |
| **目录比较** | `-r`                | 递归比较目录及子目录                                                     |
|              | `-N`                | 将“仅在一个目录存在的文件”视为空文件比较（显示新增内容）                  |
|              | `--exclude=PATTERN` | 排除匹配`PATTERN`的文件/目录                                             |
| **其他**     | `-a`                | 强制将所有文件视为文本文件（包括二进制文件）                             |
|              | `--strip-trailing-cr` | 忽略行尾回车符（处理Windows与Linux文件格式差异）                        |

## 二、patch 命令：应用补丁文件

`patch` 命令用于将 `diff` 生成的补丁文件应用到原文件，实现“旧文件→新文件”的更新，是 `diff` 的配套工具，广泛用于代码更新、配置同步等场景。

### 1. 基本语法

```bash
patch [选项] 原文件 < 补丁文件
```

- 功能：根据补丁文件中的差异指令，修改原文件以匹配目标文件。  
- 补丁文件：通常是 `diff -u` 生成的统一格式文件（`.patch` 或 `.diff` 后缀）。  

### 2. 核心选项

| 选项         | 作用描述                                                                 |
|--------------|--------------------------------------------------------------------------|
| `-pN`        | 忽略补丁文件中路径的前 `N` 级目录（解决路径不匹配问题，最常用）           |
| `-b`         | 备份原文件（默认生成 `原文件.orig` 备份）                                |
| `-b -V 版本` | 自定义备份文件名格式（如 `-V numbered` 生成 `原文件.~1~`、`原文件.~2~`）  |
| `-R`         | 反向应用补丁（撤销修改，将新文件还原为旧文件）                           |
| `-d 目录`    | 指定应用补丁的目标目录（无需进入该目录）                                 |
| `-t`         | 忽略错误，强制应用补丁（谨慎使用）                                       |
| `--dry-run`  | 模拟应用补丁（不实际修改文件，用于测试补丁是否可正常应用）                |

### 3. 典型用法

#### （1）基础：应用文件补丁

```bash
# 1. 生成补丁（old.txt → new.txt 的差异）
diff -u old.txt new.txt > update.patch

# 2. 应用补丁（将 old.txt 更新为 new.txt）
patch old.txt < update.patch

# 3. 应用时备份原文件（生成 old.txt.orig）
patch -b old.txt < update.patch
```

#### （2）处理路径问题（`-p` 选项）

补丁文件中可能包含完整路径（如 `diff -u src/old.txt src/new.txt` 生成的补丁含 `src/` 前缀），直接应用会报错，需用 `-pN` 剥离路径：  

示例补丁（`update.patch`）中路径为 `src/old.txt` 和 `src/new.txt`：  

```bash
# 剥离前1级目录（去掉“src/”），在当前目录应用补丁
patch -p1 old.txt < update.patch
```

- `-p0`：不剥离路径（使用完整路径）。  
- `-p1`：剥离第1级目录（如去掉 `src/`）。  
- `-p2`：剥离前2级目录（如去掉 `a/b/`）。  

#### （3）递归应用目录补丁

比较目录生成的补丁（`diff -urN`）可通过 `patch` 批量更新目录：  

```bash
# 1. 生成目录补丁（dir_old → dir_new 的差异）
diff -urN dir_old dir_new > dir_update.patch

# 2. 应用补丁到 dir_old（使其变为 dir_new）
patch -p1 -d dir_old < dir_update.patch
# -p1：剥离路径前缀；-d dir_old：指定目标目录
```

#### （4）反向应用补丁（撤销修改）

使用 `-R` 选项可撤销之前的修改，将文件还原为补丁应用前的状态：  

```bash
# 应用补丁后，如需撤销：
patch -R old.txt < update.patch  # 还原 old.txt 为修改前的状态
```

#### （5）测试补丁（`--dry-run`）

应用前测试补丁是否兼容，避免破坏文件：  

```bash
patch --dry-run old.txt < update.patch
# 输出“checking file old.txt”且无错误，说明补丁可正常应用
```

### 4. 注意事项

- **补丁格式**：`patch` 优先支持统一格式（`-u`）和上下文格式（`-c`），不支持默认的标准格式（需转换）。  
- **文件权限**：应用补丁需对原文件有写权限，否则会报错。  
- **冲突处理**：若原文件已被修改，可能导致补丁冲突，`patch` 会生成 `.rej` 文件（含冲突内容），需手动解决。  
- **备份清理**：多次应用补丁会生成多个备份文件（如 `file.orig`、`file.~1~`），需定期清理。  

## 三、diff 与 patch 配合工作流

1. **生成补丁**：用 `diff -u` 生成统一格式补丁，记录文件差异。  

   ```bash
   diff -urN old_file new_file > changes.patch
   ```

2. **应用补丁**：用 `patch` 将补丁应用到原文件，实现更新。  

   ```bash
   patch -p1 old_file < changes.patch
   ```

3. **撤销修改**：用 `patch -R` 反向应用补丁，恢复原文件。  

   ```bash
   patch -R -p1 old_file < changes.patch
   ```

## 总结

- `diff` 负责分析差异，生成补丁文件；`patch` 负责应用补丁，实现文件更新。  
- 统一格式（`-u`）是两者协作的标准格式，广泛用于代码版本控制、配置同步等场景。  
- 掌握 `-p`（路径处理）、`-b`（备份）、`-R`（反向）等选项，可灵活应对各种补丁应用需求。
