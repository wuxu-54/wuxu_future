# su与sudo

`su` 和 `sudo` 是 Linux/Unix 系统中用于权限管理的核心命令，主要用于切换用户身份或临时提升权限执行特权操作。以下是它们的详细解析，包括用法、选项、区别及注意事项：

## 一、`su` 命令：切换用户身份（Switch User）

`su` 的核心功能是**切换到另一个用户身份**（默认切换到 `root`），并以该用户的权限执行后续命令。

### 1. 基本语法

```bash
su [选项] [用户名]
```

- 若不指定 `用户名`，默认切换到 `root` 用户（需输入 `root` 密码）。
- 切换后会进入目标用户的 shell 环境，直到执行 `exit` 退出并返回原用户。

### 2. 常用选项及示例

| 选项 | 作用 | 示例 |
|------|------|------|
| `-l` 或 `--login` | 模拟完整登录（加载目标用户的环境变量、配置文件等，如 `.bash_profile`） | `su - root`（等同于 `su -`，完整切换到 root 环境） |
| `-c` 或 `--command` | 仅以目标用户身份执行单个命令，执行后返回原用户 | `su - root -c "ls /root"`（以 root 身份列出 `/root` 目录） |
| `-s` 或 `--shell` | 指定切换后使用的 shell（需目标用户有权限） | `su - root -s /bin/sh`（切换到 root 并使用 `sh`  shell） |
| `-p` 或 `--preserve-environment` | 保留当前用户的环境变量（不加载目标用户的环境） | `su -p root`（切换到 root 但保留原用户的 `PATH` 等变量） |
| `-` | 等同于 `-l`（简化写法） | `su -`（完整切换到 root，推荐使用） |

### 3. 工作原理

- 执行 `su 用户名` 时，系统会验证**目标用户的密码**（如切换到 root 需输入 root 密码）。
- 若验证通过，shell 进程的用户 ID（UID）和组 ID（GID）会切换为目标用户的 ID，后续命令以目标用户权限执行。
- 不加 `-l` 时，仅切换 UID/GID，但环境变量（如 `HOME`、`PATH`）仍为原用户的；加 `-l` 则完全模拟目标用户登录，环境变量会被替换。

### 4. 注意事项

- **安全性**：`su` 要求知道目标用户（尤其是 root）的密码，若多人需要权限，需共享 root 密码，存在安全风险。
- **退出**：切换用户后，执行 `exit` 或按 `Ctrl+D` 可返回原用户。
- **日志**：`su` 的操作日志默认记录在 `/var/log/auth.log`（Debian/Ubuntu）或 `/var/log/secure`（CentOS/RHEL）。

## 二、`sudo` 命令：临时提升权限（Superuser Do）

`sudo` 允许**普通用户以指定用户（默认 root）的身份临时执行命令**，无需知道目标用户密码，只需验证自身密码（或无需密码，取决于配置）。其核心是通过 `/etc/sudoers` 配置文件控制权限粒度。

### 1. 基本语法

```bash
sudo [选项] 命令
```

- 默认以 `root` 身份执行命令，需验证当前用户的密码（默认 5 分钟内无需重复验证，可配置）。
- 执行后返回原用户身份，不会切换 shell 环境（除非使用 `-s` 或 `-i`）。

### 2. 常用选项及示例

| 选项 | 作用 | 示例 |
|------|------|------|
| `-u 用户名` | 以指定用户身份执行命令（而非默认 root） | `sudo -u mysql bash`（以 `mysql` 用户身份启动 bash） |
| `-l` 或 `--list` | 列出当前用户可通过 `sudo` 执行的命令 | `sudo -l`（显示权限范围） |
| `-v` 或 `--validate` | 延长密码有效期（默认 5 分钟），无需执行命令 | `sudo -v`（刷新权限时效） |
| `-k` 或 `--reset-timestamp` | 立即失效密码有效期，下次使用 `sudo` 需重新验证 | `sudo -k`（重置时效） |
| `-s` 或 `--shell` | 以目标用户（默认 root）身份启动 shell | `sudo -s`（启动 root 的 shell，环境变量部分保留） |
| `-i` 或 `--login` | 以目标用户（默认 root）身份登录，加载完整环境 | `sudo -i`（等同于 `su -`，完整进入 root 环境） |
| `-n` 或 `--non-interactive` | 非交互模式（不提示输入密码，若需密码则失败） | 用于脚本中，需提前配置免密 |
| `-E` 或 `--preserve-env` | 保留当前用户的环境变量执行命令 | `sudo -E echo $PATH`（保留原用户的 `PATH`） |
| `-H` 或 `--set-home` | 将 `HOME` 环境变量设为目标用户的主目录 | `sudo -H bash`（`HOME` 设为 `/root`） |

### 3. 核心配置文件：`/etc/sudoers`

`sudo` 的权限完全由 `/etc/sudoers` 控制，**必须通过 `visudo` 命令编辑**（自动检查语法，避免配置错误导致权限丢失）。

#### 基本配置格式

```bash
# 用户名  主机=((用户身份))  可执行命令列表
用户名    ALL=(ALL:ALL)       ALL
```

- **用户名**：允许使用 `sudo` 的用户（或组，组名前加 `%`，如 `%admin`）。
- **主机**：限制在哪些主机上生效（`ALL` 表示所有主机）。
- `(ALL:ALL)`：允许切换到的用户（前 `ALL`）和组（后 `ALL`），`(root)` 表示仅允许切换到 root。
- **可执行命令列表**：允许执行的命令（绝对路径），`ALL` 表示所有命令；多个命令用逗号分隔。

#### 示例配置

```bash
# 允许 user1 以 root 身份执行所有命令（需输入 user1 密码）
user1    ALL=(ALL)       ALL

# 允许 group1 成员无需密码执行 /sbin/reboot 和 /sbin/shutdown
%group1  ALL=(ALL)       NOPASSWD: /sbin/reboot, /sbin/shutdown

# 允许 user2 以 mysql 用户身份执行 /usr/bin/mysqldump
user2    ALL=(mysql)     /usr/bin/mysqldump
```

#### 别名使用（简化配置）

```bash
# 定义命令别名（多个命令分组）
Cmnd_Alias SOFTWARE = /usr/bin/apt, /usr/bin/dpkg

# 允许 user3 使用 SOFTWARE 别名中的命令
user3    ALL=(ALL)       SOFTWARE
```

### 4. 工作原理

1. 用户执行 `sudo 命令` 时，系统检查 `/etc/sudoers`，确认该用户是否有权限执行此命令。
2. 若有权限，提示输入**当前用户的密码**（而非目标用户密码）。
3. 验证通过后，以配置中指定的用户身份（默认 root）执行命令。
4. 命令执行完毕，返回原用户身份，权限时效默认保持 5 分钟（可通过 `timestamp_timeout` 在 `sudoers` 中配置）。

### 5. 注意事项

- **安全性**：无需共享 root 密码，权限可精确到单个命令，便于审计（日志记录完整）。
- **日志**：所有 `sudo` 操作记录在 `/var/log/auth.log` 或 `/var/log/secure`，包含用户、时间、执行的命令。
- **免密配置**：`NOPASSWD` 选项可实现免密执行，但需谨慎使用（仅限信任场景）。
- **错误处理**：若 `sudoers` 配置有误，可能导致 `sudo` 失效，此时需通过单用户模式修复。

## 三、`su` 与 `sudo` 的核心区别

| 维度 | `su` | `sudo` |
|------|------|--------|
| 密码验证 | 需目标用户（如 root）的密码 | 需当前用户的密码（或免密，取决于配置） |
| 权限范围 | 切换后获得目标用户的所有权限 | 仅执行指定命令时临时获得权限，粒度可控 |
| 环境变量 | 不加 `-l` 保留原环境，加 `-l` 切换为目标用户环境 | 默认保留部分原环境，`-i` 可切换为目标用户完整环境 |
| 安全性 | 需共享目标用户密码，风险高 | 无需共享密码，权限可精确控制，更安全 |
| 典型用途 | 长期以 root 身份操作（不推荐） | 临时执行特权命令（推荐） |

## 四、相关命令：`sudoedit`

`sudoedit` 是 `sudo` 的专用变体，用于**安全编辑文件**（避免直接用 `sudo vim` 可能带来的风险）。  
语法：`sudoedit 文件名`  

- 原理：先以当前用户身份复制文件到临时目录，编辑完成后再以 root 身份写回原文件。  
- 示例：`sudoedit /etc/sudoers`（安全编辑 sudo 配置文件，等同于 `sudo -e /etc/sudoers`）。

## 总结

- `su` 适合**临时切换到其他用户**（尤其是 root）进行多步操作，但安全性较低。  
- `sudo` 适合**单次或少数特权命令执行**，权限粒度细、安全性高，是生产环境的首选。  
- 配置 `sudo` 时务必使用 `visudo`，并遵循“最小权限原则”（仅授予必要的命令权限）。
