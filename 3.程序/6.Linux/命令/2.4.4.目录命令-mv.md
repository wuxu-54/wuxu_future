# mv

`mv`（move）是 Linux/Unix 系统中用于**移动文件/目录**或**重命名文件/目录**的核心命令，其操作高效（同一文件系统内移动本质是“重命名inode链接”，不复制数据），选项简洁但功能关键。以下是 `mv` 命令的全面解析，涵盖基础用法、核心选项、实战场景及注意事项。

## 一、基础语法与核心概念

### 1. 基本语法

```bash
mv [选项] 源文件/目录... 目标文件/目录
```

- **核心功能**：  
  - 当“源”和“目标”在**同一目录**时：执行**重命名**（文件/目录名改变，位置不变）。  
  - 当“源”和“目标”在**不同目录**时：执行**移动**（位置改变，文件名可不变或改变）。  

### 2. 核心行为规则（关键区分场景）

| 场景 | 源类型 | 目标状态 | 结果 |
|------|--------|----------|------|
| 1 | 单个文件 | 目标是**不存在的路径** | 将源文件重命名为目标路径（可包含新目录，需确保父目录存在）。 |
| 2 | 单个文件 | 目标是**已存在的文件** | 覆盖目标文件（默认不提示，可用 `-i` 开启确认）。 |
| 3 | 单个文件 | 目标是**已存在的目录** | 将源文件移动到该目录下，文件名不变。 |
| 4 | 多个文件 | 目标必须是**已存在的目录** | 所有源文件都被移动到该目录下，文件名不变。 |
| 5 | 单个目录 | 目标是**不存在的路径** | 将源目录重命名为目标路径（直接重命名，不复制内容）。 |
| 6 | 单个目录 | 目标是**已存在的目录** | 将源目录移动到目标目录内（结果：`目标目录/源目录`）。 |  

### 3. 与 `cp` 的核心区别

- **效率**：同一文件系统内，`mv` 仅修改文件名/路径（inode不变），速度极快；`cp` 需复制文件内容，速度取决于文件大小。  
- **目录操作**：`mv` 移动目录**无需递归选项**（直接操作目录本身）；`cp` 复制目录必须加 `-r`。  
- **属性保留**：`mv` 默认保留文件所有属性（权限、时间戳等）；`cp` 默认不保留，需加 `-p` 或 `-a`。  

## 二、核心选项详解（按功能分类）

### 1. 覆盖控制（避免误操作）

`mv` 默认直接覆盖目标文件/目录且不提示，以下选项可控制覆盖行为（防止误删重要内容）。

| 选项 | 英文全称 | 功能描述 | 示例 |
|------|----------|----------|------|
| `-i` | `interactive` | 交互式覆盖：若目标已存在，提示 `是否覆盖？`（输入 `y` 确认，`n` 跳过）。 | `mv -i file.txt /backup/` → 若 `/backup/file.txt` 存在，提示确认。 |
| `-f` | `force` | 强制覆盖：无论目标是否存在、是否有写权限，直接覆盖（优先级高于 `-i`，root 用户常用）。 | `mv -f old.log new.log` → 强制用 `old.log` 覆盖 `new.log`，无提示。 |
| `-n` | `no-clobber` | 不覆盖：若目标已存在，直接跳过（不移动，也不提示），适合批量操作时保留目标。 | `mv -n *.txt /archive/` → 移动 `.txt` 文件到 `/archive`，但不覆盖已有文件。 |

### 2. 输出与显示（跟踪操作过程）

默认 `mv` 执行成功后无输出，以下选项可显示操作细节（便于确认或调试）。

| 选项 | 英文全称 | 功能描述 | 示例 |
|------|----------|----------|------|
| `-v` | `verbose` | 显示移动/重命名过程：输出 `'源' -> '目标'` 的路径。 | `mv -v file.txt docs/` → 输出：`'file.txt' -> 'docs/file.txt'`。 |
| `-v`（目录操作） |  | 移动目录时显示目录名的变化。 | `mv -v old_dir new_dir` → 输出：`'old_dir' -> 'new_dir'`。 |

### 3. 特殊文件处理（符号链接、跨文件系统）

| 选项 | 英文全称 | 功能描述 | 示例 |
|------|----------|----------|------|
| `-L` | `dereference` | 跟随符号链接：移动符号链接指向的**原文件**（而非链接本身）。 | `mv -L link.txt /tmp/` → 若 `link.txt` 指向 `data.txt`，则移动 `data.txt` 到 `/tmp/link.txt`。 |
| `-P` | `no-dereference` | 不跟随符号链接：移动符号链接本身（默认行为，显式指定更清晰）。 | `mv -P link.txt /tmp/` → `/tmp/link.txt` 仍是指向原目标的链接。 |
| `--strip-trailing-slashes` |  | 移除源路径末尾的斜杠（避免目录路径被误判为文件）。 | `mv --strip-trailing-slashes dir1/ dir2` → 等价于 `mv dir1 dir2`（忽略末尾 `/`）。 |

### 4. 路径与命名（简化操作）

| 选项 | 功能描述 | 示例 |
|------|----------|------|
| `-t 目标目录` | 指定目标目录（适合移动多个源文件到同一目录，简化命令）。 | `mv -t /backup/ a.txt b.txt c.txt` → 等价于 `mv a.txt b.txt c.txt /backup/`。 |
| `-T` | 将目标视为**文件**（而非目录）：避免“目标是目录时，将源移动到目录内”的默认行为。 | `mv -T file.txt /tmp/file.txt` → 强制将 `file.txt` 移动为 `/tmp/file.txt`（即使 `/tmp` 是目录）。 |

## 三、实战场景与示例

### 1. 重命名操作（同一目录内）

```bash
# 重命名文件
mv oldfile.txt newfile.txt  # 将 oldfile.txt 改名为 newfile.txt

# 重命名目录
mv project/ my_project/  # 将 project 目录改名为 my_project

# 批量重命名（结合通配符，配合 shell 循环）
# 示例：将所有 .txt 文件名后加 "_bak"
for file in *.txt; do mv -v "$file" "${file%.txt}_bak.txt"; done
# 输出：'a.txt' -> 'a_bak.txt'、'b.txt' -> 'b_bak.txt'
```

### 2. 移动操作（不同目录间）

```bash
# 移动单个文件到目标目录（文件名不变）
mv report.pdf /home/user/docs/  # report.pdf 被移动到 docs 目录下

# 移动文件到目标目录并改名
mv data.csv /archive/2023_data.csv  # data.csv 移动到 /archive 并改名为 2023_data.csv

# 移动多个文件到目标目录
mv image.jpg video.mp4 /media/usb/  # 两个文件都被移动到 U 盘目录

# 移动目录到另一个目录（目标目录存在）
mv docs/ /backup/  # docs 目录被移动到 /backup 内（结果：/backup/docs/）

# 移动目录到新路径（目标目录不存在，即重命名+移动）
mv /var/logs/ /tmp/logs_backup/  # 将 /var/logs 移动到 /tmp 并改名为 logs_backup
```

### 3. 覆盖控制（安全操作）

```bash
# 交互式移动（覆盖前确认）
mv -i important.txt /backup/  # 若目标存在，提示：mv: 是否覆盖'/backup/important.txt'?

# 批量移动但不覆盖已有文件
mv -n /downloads/*.zip /archive/  # 仅移动 /archive 中没有的 .zip 文件

# 强制覆盖（忽略只读权限或提示）
sudo mv -f /tmp/new_config.conf /etc/config.conf  # 强制替换系统配置文件（谨慎使用）
```

### 4. 特殊场景处理

```bash
# 处理含空格或特殊字符的文件名
mv "my document.txt" "your document.txt"  # 用引号包裹空格文件名
mv file\ with\ spaces.txt new_name.txt    # 用 \ 转义空格

# 移动符号链接本身（不移动原文件）
mv -v link_to_data /tmp/  # 输出：'link_to_data' -> '/tmp/link_to_data'（链接仍指向原文件）

# 移动符号链接指向的原文件（跟随链接）
mv -Lv link_to_data /tmp/  # 移动原文件到 /tmp/link_to_data（链接失效，原文件被移动）

# 用 -t 简化多文件移动
mv -t /var/www/html/ index.html style.css script.js  # 等价于移动三个文件到 html 目录
```

### 5. 跨文件系统移动（如从硬盘到U盘）

当源和目标在**不同文件系统**（如 `/` 分区到 `/mnt/usb` U盘）时，`mv` 会先复制文件内容到目标，再删除源文件（类似 `cp + rm`）：  

```bash
mv -v /home/user/photos/ /mnt/usb/  # 跨文件系统移动，本质是复制后删除
```

## 四、常见错误与解决

1. **提示“无法将目录移动到自身”**  
   原因：尝试将目录移动到它自己的子目录中（如 `mv dir1 dir1/subdir`）。  
   解决：确保目标目录不是源目录的子目录，或先移动到父目录再调整。

2. **提示“权限不够”**  
   原因：源文件/目录无读权限，或目标目录无写权限。  
   解决：用 `sudo` 获取权限（`sudo mv 源 目标`），或修改目录权限（`chmod +w 目标目录`）。

3. **移动后文件消失**  
   原因：目标是已存在的文件，被源文件覆盖（默认不提示）。  
   预防：用 `-i` 选项开启确认（`mv -i 源 目标`），或用 `-n` 避免覆盖。

4. **批量移动时“目标不是目录”**  
   原因：移动多个文件时，目标不是已存在的目录（`mv` 要求多源移动的目标必须是目录）。  
   解决：确保目标目录存在（`mkdir -p 目标目录`），再执行移动。

## 五、常用选项组合

| 场景 | 选项组合 | 作用 |
|------|----------|------|
| 安全移动文件 | `mv -iv` | 交互式覆盖，显示移动过程（清晰且安全）。 |
| 强制批量移动 | `mv -fv` | 强制覆盖，显示所有移动的文件（适合脚本）。 |
| 保守批量移动 | `mv -nv` | 不覆盖已有文件，显示成功移动的文件。 |
| 移动符号链接本身 | `mv -Pv` | 明确移动链接，不跟随原文件，显示过程。 |

## 总结

`mv` 命令的核心是“移动”和“重命名”，其高效性和简洁性使其成为文件管理的必备工具：  

- 基础操作：`mv 源 目标`（重命名或移动），多源移动需指定目标目录。  
- 安全控制：`-i`（确认覆盖）、`-n`（不覆盖）、`-f`（强制覆盖）。  
- 便捷选项：`-v`（显示过程）、`-t`（指定目标目录，简化多文件移动）。  

掌握这些用法，可轻松应对从简单文件重命名到复杂目录迁移的各种场景，尤其注意跨文件系统移动的特性和覆盖操作的风险。
