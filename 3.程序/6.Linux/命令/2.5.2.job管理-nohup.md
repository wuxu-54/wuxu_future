# nohup

`nohup`（全称：no hang up）是 Linux 中用于**让命令忽略 `SIGHUP` 信号**的工具，确保命令在终端关闭（或用户退出登录）后仍能继续运行。它常与后台运行符号 `&` 结合，是处理长时间任务（如数据备份、程序编译、服务部署）的必备工具。

## 一、基本概念：为什么需要 `nohup`？

在 Linux 中，终端（如 `bash`、`ssh` 会话）与启动的进程存在“父子关系”：  

- 当终端关闭（或用户执行 `exit` 退出）时，系统会向终端所有子进程发送 `SIGHUP`（Hang Up，挂断）信号。  
- 进程收到 `SIGHUP` 信号的默认行为是**终止运行**。  

`nohup` 的核心作用是：**让命令启动的进程忽略 `SIGHUP` 信号**，从而在终端关闭后继续运行。

## 二、基本语法

```bash
nohup 命令 [命令参数] [重定向符] &
```

- **`nohup`**：核心工具，标记命令忽略 `SIGHUP` 信号。  
- **`命令 [命令参数]`**：需要后台持续运行的命令（如 `python script.py`、`tar -czf backup.tar.gz /data`）。  
- **`[重定向符]`**：可选，指定输出（`stdout`）和错误（`stderr`）的存储位置（默认写入 `nohup.out`）。  
- **`&`**：可选但常用，将命令放入后台运行（不阻塞终端）。  

## 三、工作原理

1. **忽略 `SIGHUP` 信号**：`nohup` 启动命令时，会为进程设置“忽略 `SIGHUP` 信号”的属性，即使终端关闭，进程也不会因收到 `SIGHUP` 而终止。  
2. **输出重定向**：  
   - 若未指定输出文件，命令的标准输出（`stdout`）和标准错误（`stderr`）会默认写入当前目录的 `nohup.out` 文件。  
   - 若当前目录无写入权限，输出会被重定向到用户主目录的 `nohup.out`（如 `~/.nohup.out` 或 `$HOME/nohup.out`）。  
3. **脱离终端控制**：结合 `&` 使用时，进程在后台运行，终端可立即接收新命令；即使不结合 `&`，`nohup` 也会让命令在前台运行，但终端关闭后仍能继续。  

## 四、常用选项

`nohup` 是极简工具，选项极少，主要用于查看帮助和版本：  

- `--help`：显示帮助信息（包含语法和注意事项）。  
- `--version`：显示 `nohup` 的版本信息。  

示例：  

```bash
nohup --help  # 查看帮助
nohup --version  # 查看版本（通常显示为 coreutils 的版本）
```

## 五、典型用法示例

### 1. 基础用法：后台运行并默认输出到 `nohup.out`

```bash
# 启动一个需长时间运行的脚本，后台运行，输出写入 nohup.out
nohup python data_process.py &
```

- 执行后，终端会显示进程 ID（PID）和输出文件提示：  

  ```txt
  [1] 12345  # [1] 是 Job ID，12345 是 PID
  nohup: 忽略输入并将输出追加到 'nohup.out'
  ```

- 此时可关闭终端，`data_process.py` 会继续运行，输出持续写入 `nohup.out`。  

### 2. 自定义输出文件（避免 `nohup.out` 过大）

默认 `nohup.out` 会累积所有输出，可能占用大量磁盘空间。可通过重定向指定输出文件：  

```bash
# 将 stdout 写入 output.log，stderr 写入 error.log
nohup ./long_task.sh > output.log 2> error.log &

# 将 stdout 和 stderr 合并写入 all.log（推荐）
nohup ./long_task.sh > all.log 2>&1 &
```

- `2>&1` 表示“将标准错误（文件描述符 2）重定向到标准输出（文件描述符 1）”，最终两者都写入 `all.log`。  

### 3. 运行带参数的命令

```bash
# 备份 /data 目录到远程服务器，后台运行，输出写入 backup.log
nohup rsync -av /data user@remotehost:/backup > backup.log 2>&1 &
```

### 4. 在脚本中使用 `nohup`

若需批量启动多个后台任务，可在 Shell 脚本中嵌入 `nohup`：  

```bash
# 脚本：start_tasks.sh
#!/bin/bash
# 启动任务1，输出到 task1.log
nohup python task1.py > task1.log 2>&1 &
# 启动任务2，输出到 task2.log
nohup python task2.py > task2.log 2>&1 &
echo "所有任务已启动"
```

执行脚本：  

```bash
chmod +x start_tasks.sh
./start_tasks.sh  # 两个任务会在后台持续运行，不受终端关闭影响
```

### 5. 前台运行（不结合 `&`）

`nohup` 可单独使用（不加 `&`），命令会在前台运行（阻塞终端），但终端关闭后仍能继续：  

```bash
nohup tail -f /var/log/syslog  # 前台显示日志，关闭终端后仍在后台持续监控
```

- 此时若需退出终端，直接关闭即可；若需在当前终端继续操作，需按 `Ctrl+Z` 暂停后用 `bg` 放入后台（但此操作非必需，因 `nohup` 已确保终端关闭后任务不终止）。  

## 六、与相关命令的区别

### 1. `nohup` vs `&`（后台运行）

- **`&`**：仅将命令放入后台运行，**不处理 `SIGHUP` 信号**。若终端关闭，后台进程仍会收到 `SIGHUP` 并终止。  
- **`nohup`**：核心是忽略 `SIGHUP` 信号，**不直接控制前台/后台**，需结合 `&` 才会在后台运行。  

例：  

```bash
# 仅用 &：终端关闭后任务终止
sleep 3600 &

# 用 nohup + &：终端关闭后任务继续运行（推荐）
nohup sleep 3600 &
```

### 2. `nohup` vs `disown`

- **`disown`**：从当前 Shell 的 Job 列表中移除后台进程，使其**不受 Shell 退出影响**（不会收到 `SIGHUP`），但**不处理输出重定向**（需手动设置）。  
- **`nohup`**：自动忽略 `SIGHUP` 并处理输出重定向（默认 `nohup.out`），但进程仍会显示在 `jobs` 列表中（除非结合 `disown`）。  

场景差异：  

- 若命令已在后台运行（用 `&` 启动），需避免终端关闭导致终止，用 `disown`：  

  ```bash
  sleep 3600 &  # 已启动的后台任务
  disown %1  # 移除 Job 1，使其脱离 Shell 控制
  ```

- 若命令未启动，需长期运行且自动处理输出，用 `nohup + &`（更省心）。  

### 3. `nohup` vs `screen`/`tmux`

- **`screen`/`tmux`**：是**终端会话管理工具**，可创建独立会话，支持“断开连接后重新连接”，并能在会话中管理多个窗口/命令，功能更强大（适合复杂任务）。  
- **`nohup`**：仅解决“终端关闭后进程不终止”问题，不支持会话重连，功能单一（适合简单后台任务）。  

选择建议：  

- 短期后台任务（几小时）：用 `nohup + &` 足够。  
- 长期任务（几天/几周）或需中途重新控制：用 `screen`/`tmux`（如远程服务器部署服务）。  

## 七、管理 `nohup` 启动的进程

`nohup` 启动的进程脱离终端控制后，需通过以下方式管理：  

### 1. 查看 `nohup` 进程

- 用 `ps` 命令结合进程名/命令关键字查找：  

  ```bash
  # 查找所有 nohup 启动的进程（含命令详情）
  ps aux | grep "nohup" | grep -v "grep"

  # 查找特定命令（如 python 脚本）
  ps aux | grep "python data_process.py" | grep -v "grep"
  ```

  输出示例（包含 PID，用于后续操作）：  

  ```txt
  user      12345  0.1  0.5  12345  6789 ?        S    10:00   0:05 python data_process.py
  ```

  - `?` 表示进程与终端无关联（已脱离终端）。  

### 2. 终止 `nohup` 进程

`nohup` 进程不会因 `SIGHUP` 终止，但可通过 `kill` 命令发送其他信号终止：  

```bash
# 先查找 PID（如 12345）
ps aux | grep "data_process.py"

# 发送终止信号（SIGTERM，默认）
kill 12345

# 若进程顽固不终止，发送强制终止信号（SIGKILL）
kill -9 12345
```

### 3. 查看 `nohup` 进程输出

通过查看输出文件（如 `nohup.out` 或自定义的 `output.log`）监控进程运行状态：  

```bash
# 实时查看输出（类似 tail -f）
tail -f nohup.out

# 查看最后 100 行
tail -n 100 output.log

# 搜索关键词（如 "error"）
grep "error" all.log
```

## 八、注意事项

1. **`nohup.out` 的处理**：  
   - 默认输出文件 `nohup.out` 会不断增大（尤其日志类任务），需定期清理或在启动时指定输出到 `/dev/null`（丢弃输出）：  

     ```bash
     nohup ./silent_task.sh > /dev/null 2>&1 &  # 所有输出丢弃
     ```

   - 若当前目录无写入权限，`nohup` 会尝试写入 `$HOME/nohup.out`，若仍无权限则报错。  

2. **`nohup` 不保证进程“永不终止”**：  
   - `nohup` 仅忽略 `SIGHUP` 信号，进程仍可能因其他原因终止（如内存不足被 `OOM killer` 杀死、命令自身运行结束、收到 `SIGKILL` 信号等）。  

3. **`nohup` 对已运行的进程无效**：  
   - `nohup` 必须在命令启动时使用，无法对已运行的进程生效。若需让已运行的进程忽略 `SIGHUP`，需用 `disown`（见前文对比）。  

4. **特殊命令的兼容性**：  
   - 部分交互式命令（如 `top`、`vim`）依赖终端输入输出，即使使用 `nohup` 也可能无法正常运行（因缺少终端交互）。  

5. **`nohup` 与 `sudo` 结合**：  
   - 用 `sudo` 执行 `nohup` 时，需确保 `root` 用户对输出文件有写入权限，否则可能失败：  

     ```bash
     # 正确：指定 root 可写的输出文件
     sudo nohup /usr/local/bin/daemon > /var/log/daemon.log 2>&1 &
     ```

## 九、总结

`nohup` 是 Linux 中保障命令“终端关闭后持续运行”的轻量工具，核心特性：  

- 忽略 `SIGHUP` 信号，避免终端关闭导致进程终止。  
- 自动处理输出重定向（默认 `nohup.out`），结合 `&` 可实现后台运行。  
- 适合简单的长时间任务（如备份、脚本运行），复杂场景需配合 `screen`/`tmux`。  

掌握 `nohup` 的用法，能有效提升远程服务器管理和长时间任务处理的效率。
