# skill.md的属性说明

以下是 **skill.md** 文件的完整属性说明。该文件通常用于为大模型（如 Claude、GPT 等）定义一项技能（Skill），由 **Frontmatter（YAML 元数据）** 和 **Markdown 正文（指令）** 两部分组成。

---

## 一、Frontmatter（元数据）

Frontmatter 位于文件最顶部，使用 `---` 包裹，采用 YAML 格式。它描述技能的通用元信息，**通常不可省略**。

| 属性 | 子属性 | 类型 | 必填 | 说明与填写方法 |
|------|--------|------|------|----------------|
| `name` | 无 | 字符串 | ✅ | 技能的唯一标识名，应使用短横线命名（kebab-case）或驼峰命名。例如：`data-analyzer`、`emailSummarizer`。 |
| `description` | 无 | 字符串 | ✅ | 清晰描述技能的作用、适用场景和核心能力，供模型或用户判断何时调用。建议 20~150 字。例如：`从 CSV 文件中读取数据，生成统计摘要并可视化。` |
| `version` | 无 | 字符串 | ❌ | 遵循语义化版本（SemVer），如 `1.2.0`。用于追踪技能迭代。 |
| `author` | 无 | 字符串 / 对象 | ❌ | 作者信息。可以是名字 `张三`，或包含 `name`、`email`、`url` 的对象。例如：`name: 张三, email: zhang@example.com`。 |
| `tags` | 无 | 列表 | ❌ | 分类标签，便于索引和检索。例如：`[数据分析, 可视化, CSV]`。 |
| `triggers` | `keywords`<br>`patterns`<br>`intents` | 列表 / 字典 | ❌ | 定义自动激活该技能的条件。`keywords` 为关键词列表；`patterns` 为正则表达式；`intents` 为意图名称。例如：`keywords: ["分析", "统计"]`。 |
| `dependencies` | `skills`<br>`tools`<br>`packages` | 列表 | ❌ | 声明依赖的其他技能、外部工具或 Python/Node 包。例如：`skills: [web-scraper]`, `packages: [pandas, matplotlib]`。 |
| `license` | 无 | 字符串 | ❌ | 许可证类型，如 `MIT`、`Apache-2.0`、`CC BY-SA 4.0`。 |
| `metadata` | 任意自定义字段 | 字典 | ❌ | 扩展元数据，可包含 `priority`、`timeout`、`cost`、`required_permissions` 等。例如：`timeout: 30s`, `requires_internet: true`。 |

**示例 Frontmatter：**

```yaml
---
name: financial-report-generator
description: 根据提供的财务数据（JSON/CSV），生成季度或年度报告（包含图表、关键指标和文字摘要）。
version: 2.1.0
author:
  name: 李华
  email: li.hua@example.com
tags: [finance, reporting, data-viz]
triggers:
  keywords: [财报, 财务报告, 季度报告]
  intents: [generate_financial_report]
dependencies:
  packages: [pandas, plotly, jinja2]
metadata:
  timeout: 60s
  requires_internet: false
---
```

## 二、Markdown 正文（指令）

Frontmatter 之后的内容为 Markdown 正文，用于向大模型提供**具体的行为指令、规则和工作流**。建议按以下章节组织，但并非所有章节都必需。

| 章节 | 子属性 / 子章节 | 必填 | 说明与填写方法 |
|------|----------------|------|----------------|
| **1. 目标** | 无 | ✅ | 用一句话或一段话明确该技能要达成的最终目标。例如：`本技能旨在将用户提供的原始文本日志转换为结构化的 JSON 格式，并识别出所有错误和警告。` |
| **2. 适用场景** | 无 | ❌ | 列举使用该技能的典型用户输入、上下文或任务类型。例如：`当用户上传一个 .log 文件并说“帮我分析日志”时触发。` |
| **3. 输入要求** | `格式`<br>`参数`<br>`示例` | ❌ | 说明技能需要接收哪些输入，包括文件格式、参数名、数据类型、是否可选等。例如：`输入为 JSON 对象，必须包含 "data" 数组和 "threshold" 数值。` |
| **4. 执行步骤** | 每个步骤可包含：<br>- `动作`<br>- `输入`<br>- `输出`<br>- `错误处理` | ✅ | 逐步指导模型完成任务的**具体操作序列**。应使用编号列表，每个步骤清晰、可执行。例如：<br>1. 读取文件 `data.csv`。<br>2. 使用 `pandas` 计算每列均值。<br>3. 若缺失值超过 10%，则提示用户。<br>4. 生成 Markdown 表格输出结果。 |
| **5. 规则与约束** | `禁止行为`<br>`强制格式`<br>`优先级` | ❌ | 明确模型**必须遵守或避免**的行为。例如：`禁止修改原始数据`、`输出必须包含时间戳`、`优先使用用户指定的排序顺序`。 |
| **6. 示例** | 每个示例可包含：<br>- `输入`<br>- `输出`<br>- `说明` | ❌ | 提供至少 1~3 个具体示例，展示从输入到输出的完整转换。**示例应具有代表性**，覆盖常见边缘情况。例如：<br>**输入**：`“帮我总结：今天开会决定...（长文本）”`<br>**输出**：`总结要点：1. ... 2. ...` |
| **7. 输出格式** | `格式类型`<br>`字段说明`<br>`模板` | ✅ | 规定技能最终输出的结构。可指定为纯文本、JSON、Markdown 表格、HTML 等，并给出模板或字段描述。例如：<br>`输出应为 JSON：{"summary": "字符串", "topics": ["列表"]}` |
| **8. 注意事项** | `边界情况`<br>`性能提示`<br>`兼容性` | ❌ | 提醒模型可能遇到的陷阱、优化建议或与其他技能的交互问题。例如：`当输入文本超过 5000 字符时，自动分段处理。` |
| **9. 错误处理** | `错误类型`<br>`恢复动作`<br>`用户提示` | ❌ | 定义遇到异常（如缺文件、格式错误、API 超时）时的行为。例如：`若 CSV 文件缺少 "date" 列，则输出错误信息并停止执行。` |

**示例 Markdown 正文结构：**

```markdown
# 目标
将输入的自然语言日期表达式（如“下周三”、“2025年三月的第二个星期五”）转换为 ISO 日期字符串（YYYY-MM-DD）。

# 适用场景
- 用户询问会议安排、任务截止时间时
- 需要将模糊时间转换为具体日期的场景

# 输入要求
- 一个字符串，表示日期表达式。
- 可选的参考基准日期（缺省为当前系统日期），格式为 YYYY-MM-DD。

# 执行步骤
1. 提取用户消息中的日期表达式部分。
2. 若用户提供基准日期，使用该日期作为相对计算的锚点；否则调用系统获取当前日期。
3. 使用 `dateparser` 库（配置 `settings={'PREFER_DATES_FROM': 'future'}`）解析表达式。
4. 若解析失败，尝试移除修饰词（如“大约”“可能”）后再次解析。
5. 输出 ISO 格式日期字符串。

# 规则与约束
- 当日期为过去时，默认推断为最近的未来日期（例如“周一”指下一个周一，除非明确说“上一个周一”）。
- 禁止输出除 ISO 日期以外的任何额外解释文字。

# 示例
**输入**：下周五  
**输出**：2026-06-12

**输入**：2024年二月的最后一天 （基准日期：2024-01-01）  
**输出**：2024-02-29

# 输出格式
纯文本，格式为 YYYY-MM-DD。

# 注意事项
- 不支持包含时区的表达式（如“北京时间明天上午10点”），遇到时提示用户仅使用日期。
- 若表达式不可解析（如“猴年马月”），输出 `null` 并保持静默。
```

## 三、整体编写建议

1. **Frontmatter 要精准**：`name` 和 `description` 决定了模型何时调用该技能，要写清楚功能边界。
2. **正文指令要原子化**：每个步骤应是模型能直接执行的原子操作（调用库、查询、格式化等）。
3. **示例是强效约束**：特别是在输出格式模糊时，提供示例比文字描述更管用。
4. **保持与平台兼容**：部分平台（如 Claude Skills）对 Frontmatter 字段有严格限制，请参考其官方文档。
5. **版本迭代**：修改技能后记得更新 `version`，并在正文中增加变更日志（可选章节）。

按照以上规范编写 `skill.md`，可以确保大模型稳定、可预测地执行你的自定义技能。
