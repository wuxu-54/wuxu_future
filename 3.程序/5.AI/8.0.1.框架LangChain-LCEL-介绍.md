# LCEL 完整详解（LangChain Expression Language）

**一句话定义**：LCEL（LangChain Expression Language）是LangChain 1.0+的**核心声明式语法**，基于统一的`Runnable`协议，用管道符`|`将任意AI组件（提示词、模型、工具、检索器）自由组合成复杂链，彻底替代了传统的`LLMChain`、`ConversationChain`等类，是构建所有LangChain应用的基础。

---

## 一、为什么需要LCEL？

在LCEL出现之前，LangChain用各种`Chain`类（`LLMChain`、`RetrievalQAChain`等）来组合组件，存在三大致命问题：

1. **组合困难**：嵌套链需要大量样板代码，修改流程需要重构整个类
2. **接口不统一**：不同链的调用方式、参数格式不一致
3. **功能受限**：难以实现并行执行、动态分支、流式输出等高级功能
4. **调试麻烦**：黑盒执行，难以追踪每一步的输入输出

LCEL的核心价值在于：

- **声明式语法**：用`|`管道符直观表达数据流转
- **统一接口**：所有组件实现`Runnable`协议，调用方式完全一致
- **无限组合**：支持顺序、并行、分支、嵌套等任意复杂结构
- **原生支持**：流式输出、异步、批量、错误处理、可观测性

>我感觉像是设计模式中的责任链

## 二、核心基础：Runnable协议

所有LCEL组件（提示词、模型、输出解析器、检索器等）都实现了**Runnable协议**，这是LCEL的灵魂。它定义了5个标准调用方法，保证任何组件都可以互换和组合。

### 2.1 标准调用方法

| 方法 | 功能 | 返回值 | 适用场景 |
|------|------|--------|----------|
| `invoke(input, config=None)` | 同步调用 | 单个结果 | 简单请求、脚本 |
| `ainvoke(input, config=None)` | 异步调用 | 协程 | 高并发服务 |
| `stream(input, config=None)` | 同步流式输出 | 生成器 | 实时对话、长文本生成 |
| `astream(input, config=None)` | 异步流式输出 | 异步生成器 | 生产级Web服务 |
| `batch(inputs, config=None)` | 批量调用 | 结果列表 | 批量处理、评估 |

**示例**：

```python
from langchain_core.runnables import RunnableLambda

# 定义一个简单的Runnable
add_one = RunnableLambda(lambda x: x + 1)

# 所有Runnable都支持这5种调用方式
print(add_one.invoke(1))  # 输出: 2
print(add_one.batch([1, 2, 3]))  # 输出: [2, 3, 4]

for token in add_one.stream(5):
    print(token)  # 输出: 6
```

### 2.2 Runnable的特性

- **可组合**：用`|`连接任意Runnable，形成新的Runnable
- **可配置**：支持运行时传入参数（如模型温度、最大token）
- **可观测**：自动集成LangSmith，追踪每一步执行
- **可扩展**：自定义Runnable只需实现`invoke`方法

## 三、核心组合原语

LCEL提供了4个基础组合原语，可以构建任意复杂的工作流。

### 3.1 顺序执行（`|` 管道符）

最常用的组合方式，数据从左到右依次流过每个组件，前一个的输出是后一个的输入。

**语法**：

```python
chain = component1 | component2 | component3
```

**示例**：基础问答链

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

# 定义组件
prompt = ChatPromptTemplate.from_template("回答问题：{question}")
model = ChatOpenAI(model="gpt-4o", temperature=0)
parser = StrOutputParser()

# 组合成链
chain = prompt | model | parser

# 调用
result = chain.invoke({"question": "什么是LCEL？"})
print(result)
```

### 3.2 并行执行（`RunnableParallel`）

同时执行多个Runnable，返回一个字典，包含每个Runnable的输出结果。

**语法**：

```python
from langchain_core.runnables import RunnableParallel

parallel_chain = RunnableParallel({
    "key1": runnable1,
    "key2": runnable2,
    "key3": runnable3
})
```

**示例**：同时生成多个观点

```python
# 定义三个不同的提示词
prompt1 = ChatPromptTemplate.from_template("用一句话解释{topic}")
prompt2 = ChatPromptTemplate.from_template("用一个例子说明{topic}")
prompt3 = ChatPromptTemplate.from_template("列出{topic}的3个优点")

# 并行执行
parallel_chain = RunnableParallel({
    "definition": prompt1 | model | parser,
    "example": prompt2 | model | parser,
    "advantages": prompt3 | model | parser
})

# 调用
result = parallel_chain.invoke({"topic": "LCEL"})
print(result["definition"])
print(result["example"])
print(result["advantages"])
```

### 3.3 赋值（`RunnableAssign`）

向输入字典中添加新字段，不修改原有字段。常用于在流程中添加中间结果。

**语法**：

```python
from langchain_core.runnables import RunnableAssign

chain = RunnableAssign({"new_key": runnable})
```

**示例**：RAG链中的上下文注入

```python
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings

# 创建检索器
vectorstore = Chroma.from_texts(["LCEL是LangChain的表达式语言"], embedding=OpenAIEmbeddings())
retriever = vectorstore.as_retriever()

# 先检索上下文，再添加到输入字典
chain = RunnableAssign({"context": retriever}) | prompt | model | parser

# 调用
result = chain.invoke({"question": "什么是LCEL？"})
print(result)
```

### 3.4 条件分支（`RunnableBranch`）

根据输入动态选择执行哪个Runnable，实现if-else逻辑。

**语法**：

```python
from langchain_core.runnables import RunnableBranch

branch = RunnableBranch(
    (condition1, runnable1),  # 如果condition1为True，执行runnable1
    (condition2, runnable2),  # 如果condition2为True，执行runnable2
    default_runnable          # 否则执行default_runnable
)
```

**示例**：根据问题类型选择不同的回答策略

```python
# 定义条件函数
def is_math_question(inputs):
    return "数学" in inputs["question"] or "计算" in inputs["question"]

# 定义不同的提示词
math_prompt = ChatPromptTemplate.from_template("你是数学老师，详细解答：{question}")
general_prompt = ChatPromptTemplate.from_template("你是通用助手，回答：{question}")

# 条件分支
branch = RunnableBranch(
    (is_math_question, math_prompt | model | parser),
    general_prompt | model | parser
)

# 调用
print(branch.invoke({"question": "2+2等于多少？"}))  # 用数学老师提示词
print(branch.invoke({"question": "今天天气怎么样？"}))  # 用通用提示词
```

## 四、常用LCEL组件

### 4.1 提示词模板（`ChatPromptTemplate`）

将输入变量格式化为模型可理解的消息格式。

**常用方法**：

```python
# 从消息列表创建
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个{role}"),
    ("human", "{question}")
])

# 从字符串创建（自动转为human消息）
prompt = ChatPromptTemplate.from_template("回答问题：{question}")

# 带消息占位符（用于对话历史）
from langchain_core.prompts import MessagesPlaceholder
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个有用的助手"),
    MessagesPlaceholder(variable_name="chat_history"),
    ("human", "{question}")
])
```

### 4.2 聊天模型（`ChatModel`）

调用大语言模型，支持工具调用和结构化输出。

**常用方法**：

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o", temperature=0)

# 绑定工具
model_with_tools = model.bind_tools([add, multiply])

# 结构化输出（返回Pydantic对象）
from pydantic import BaseModel, Field
class Person(BaseModel):
    name: str = Field(description="姓名")
    age: int = Field(description="年龄")
structured_model = model.with_structured_output(Person)
```

### 4.3 输出解析器（`OutputParser`）

将模型的原始输出转换为结构化数据。

**常用解析器**：

```python
from langchain_core.output_parsers import (
    StrOutputParser,
    JsonOutputParser,
    PydanticOutputParser
)

# 字符串解析器（最常用）
parser = StrOutputParser()

# JSON解析器
json_parser = JsonOutputParser()

# Pydantic解析器
pydantic_parser = PydanticOutputParser(pydantic_object=Person)
```

### 4.4 检索器（`Retriever`）

从向量数据库中检索相关文档，是RAG系统的核心。

**用法**：

```python
# 检索器本身就是一个Runnable，可以直接用|组合
chain = retriever | prompt | model | parser
```

## 五、高级特性

### 5.1 错误处理与重试

#### 自动重试（`with_retry`）

处理模型调用失败、网络错误等临时问题：

```python
# 最多重试3次，指数退避
retry_chain = chain.with_retry(
    stop_after_attempt=3,
    wait_exponential_jitter=True
)
```

#### 降级策略（`with_fallbacks`）

主Runnable失败时，自动切换到备用Runnable：

```python
# 主模型失败时，切换到备用模型
fallback_chain = chain.with_fallbacks([backup_model_chain])
```

### 5.2 运行时配置

支持在调用时动态修改参数，无需重新定义链：

```python
# 运行时修改模型温度和最大token
result = chain.invoke(
    {"question": "什么是LCEL？"},
    config={"temperature": 0.7, "max_tokens": 100}
)
```

### 5.3 带记忆的对话链

使用`RunnableWithMessageHistory`实现对话记忆，替代传统的`ConversationChain`：

```python
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

# 定义聊天历史存储
store = {}

def get_session_history(session_id: str):
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

# 基础链
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个有用的助手"),
    MessagesPlaceholder(variable_name="history"),
    ("human", "{question}")
])
base_chain = prompt | model | parser

# 集成记忆
chain_with_history = RunnableWithMessageHistory(
    base_chain,
    get_session_history,
    input_messages_key="question",
    history_messages_key="history"
)

# 调用（用session_id区分不同会话）
config = {"configurable": {"session_id": "user_123"}}
print(chain_with_history.invoke({"question": "我叫张三"}, config=config))
print(chain_with_history.invoke({"question": "我叫什么名字？"}, config=config))
```

### 5.4 流式输出

LCEL原生支持流式输出，只需调用`stream`方法：

```python
# 流式输出模型生成的每个token
for chunk in chain.stream({"question": "什么是LCEL？"}):
    print(chunk, end="", flush=True)
```

### 5.5 批量处理

同时处理多个输入，自动并行执行：

```python
# 批量处理3个问题
results = chain.batch([
    {"question": "什么是LCEL？"},
    {"question": "什么是LangGraph？"},
    {"question": "什么是LangSmith？"}
])

for result in results:
    print(result)
```

## 六、实战案例

### 6.1 完整RAG链

```python
from langchain_core.runnables import RunnablePassthrough

# 1. 加载文档并创建向量存储
from langchain_community.document_loaders import WebBaseLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter

loader = WebBaseLoader("https://python.langchain.com/docs/concepts/lcel/")
documents = loader.load()
text_splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)
splits = text_splitter.split_documents(documents)
vectorstore = Chroma.from_documents(documents=splits, embedding=OpenAIEmbeddings())
retriever = vectorstore.as_retriever()

# 2. 定义RAG提示词
rag_prompt = ChatPromptTemplate.from_template("""
根据以下上下文回答问题：
上下文：{context}
问题：{question}
如果上下文没有相关信息，请回答"我不知道"。
""")

# 3. 构建RAG链
rag_chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | rag_prompt
    | model
    | StrOutputParser()
)

# 4. 调用
result = rag_chain.invoke("什么是LCEL？")
print(result)
```

### 6.2 工具调用链

```python
from langchain_core.tools import tool

# 定义工具
@tool
def add(a: int, b: int) -> int:
    """将两个整数相加"""
    return a + b

@tool
def multiply(a: int, b: int) -> int:
    """将两个整数相乘"""
    return a * b

# 绑定工具到模型
model_with_tools = model.bind_tools([add, multiply])

# 构建工具调用链
tool_chain = model_with_tools | (lambda x: x.tool_calls[0] if x.tool_calls else x)

# 调用
result = tool_chain.invoke("3加5等于多少？")
print(result)  # 输出工具调用信息
```

## 七、LCEL vs 传统Chain

| 特性 | LCEL | 传统Chain（LLMChain等） |
|------|------|-------------------------|
| 语法 | 声明式管道符`|` | 面向对象类 |
| 组合性 | 无限组合，支持顺序、并行、分支 | 有限组合，嵌套困难 |
| 接口 | 统一Runnable接口 | 每个Chain接口不同 |
| 流式输出 | 原生支持 | 部分支持，实现复杂 |
| 异步 | 原生支持 | 部分支持 |
| 错误处理 | 内置`with_retry`、`with_fallbacks` | 需要自定义 |
| 可观测性 | 自动集成LangSmith | 需要手动配置 |
| 状态 | 无状态（记忆通过RunnableWithMessageHistory实现） | 有状态，封装在Chain内部 |
| 推荐程度 | 推荐（LangChain 1.0+标准） | 已弃用，不建议使用 |

---

## 八、LCEL vs LangGraph

| 特性 | LCEL | LangGraph |
|------|------|-----------|
| 核心抽象 | 无环工作流 | 有状态有环图 |
| 循环支持 | 不支持 | 原生支持（ReAct循环、重试循环） |
| 状态管理 | 无状态（仅通过记忆实现简单状态） | 显式全局状态，支持任意复杂状态 |
| 人机交互 | 不支持 | 原生支持中断、人工干预 |
| 多智能体 | 难以实现 | 原生支持 |
| 适用场景 | 线性流程、简单分支、无循环任务 | 复杂多步任务、智能体、循环流程 |
| 关系 | LCEL是LangGraph的基础，LangGraph的节点可以是LCEL链 | LangGraph是LCEL的上层编排框架 |

---

## 九、最佳实践

1. **优先使用LCEL**：所有新应用都应该用LCEL，不要再使用已弃用的`LLMChain`、`ConversationChain`等
2. **保持链的简洁**：每个链只做一件事，复杂流程拆分为多个小链
3. **使用类型提示**：为输入输出添加类型提示，减少运行时错误
4. **开启LangSmith追踪**：所有链都会自动上报到LangSmith，方便调试和监控
5. **合理使用并行**：对于独立的任务，使用`RunnableParallel`并行执行，提升性能
6. **添加错误处理**：生产环境中必须添加`with_retry`和`with_fallbacks`
7. **避免过度嵌套**：复杂的嵌套链会降低可读性和可维护性

## 十、总结

LCEL是LangChain生态的基石，它用简单优雅的声明式语法解决了AI组件组合的难题。掌握LCEL是构建任何LangChain应用的前提：

- **核心**：基于`Runnable`协议的统一接口
- **灵魂**：`|`管道符和四大组合原语
- **优势**：灵活、强大、可观测、生产就绪
- **关系**：LCEL是基础，LangGraph是上层编排，LangSmith是工程化工具

**核心公式**：

```
任何LangChain应用 = 多个Runnable组件 | 组合成链
```
