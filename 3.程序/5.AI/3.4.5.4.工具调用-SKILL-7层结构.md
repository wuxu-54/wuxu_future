# 企业级SKILL 7层标准结构 逐行详解

这是**所有企业级大模型SKILL必须严格遵循的黄金标准结构**，每一层都有不可替代的作用，缺少任何一层都无法通过生产环境验收。我会结合之前的**代码审查SKILL**，逐行拆解每一层的设计目的、必须包含的内容、常见错误和最佳实践。

## 整体执行流程

SKILL被调用时，会严格按照**从上到下**的顺序执行这7层：

```
元数据层 → 输入模型层 → 安全校验层 → 日志审计层 → 核心业务逻辑层 → 错误处理层 → 输出规范层
```

任何一层失败，都会直接进入错误处理层，返回结构化错误信息，不会继续向下执行。

---

## 第1层：SKILL元数据层

### 设计目的

**让大模型能准确理解这个SKILL是做什么的、怎么用**。这是大模型决定是否调用这个SKILL的唯一依据，描述错误会导致100%调用错误。

### 必须包含的内容

1. `@tool`装饰器：标记这是一个LangChain工具
2. `args_schema`：指定输入模型（Pydantic类）
3. 函数docstring：完整的功能描述、参数说明、返回值说明
4. 语义化函数名：见名知意，动词+名词结构

### 代码示例（代码审查SKILL）

```python
@tool(args_schema=CodeReviewInput)  # 标记为工具，指定输入模型
def code_review(
    code: str,
    language: str,
    review_focus: Optional[List[str]] = None,
    strict_level: str = "medium",
    include_suggestions: bool = True
) -> Dict:
    """
    对代码片段进行智能审查。  # 一句话功能概述
    
    支持Python/JavaScript/Java/Go四种编程语言。  # 支持的能力
    审查维度包括：潜在bug、安全漏洞、性能问题、代码风格和最佳实践。  # 能力细节
    问题按严重程度分为：致命(critical)、严重(high)、中等(medium)、建议(low)。  # 输出说明
    
    返回结果包含：  # 详细返回值说明
    - success: 布尔值，表示审查是否成功
    - total_issues: 问题总数
    - critical_issues: 致命问题数
    - high_issues: 严重问题数
    - medium_issues: 中等问题数
    - low_issues: 建议问题数
    - issues: 问题列表，每个问题包含类型、严重程度、行号、描述和建议
    - summary: 审查总结
    - error_code: 失败时返回错误码
    - error_message: 失败时返回错误描述
    """
    # 后续逻辑...
```

### 常见错误

❌ 错误：docstring写得太简单，大模型无法理解

```python
def code_review(code):
    """审查代码"""
```

❌ 错误：函数名不语义化

```python
def cr(code):  # 没人知道cr是什么意思
```

### 最佳实践

- docstring采用**"一句话概述+能力细节+返回值说明"**的固定格式
- 函数名必须是**动词+名词**结构：`create_order`、`query_user`、`send_message`
- 所有参数和返回值都要有明确的类型注解

## 第2层：输入模型层

### 设计目的

**标准化输入格式，自动完成参数校验**，杜绝脏数据进入业务逻辑层。这是SKILL健壮性的第一道防线。

### 必须包含的内容

1. 继承`BaseModel`的Pydantic类
2. 每个字段的类型注解
3. 每个字段的`Field(description="...")`：大模型理解参数的唯一来源
4. 字段约束：默认值、范围限制、枚举值
5. 自定义校验器`@validator`：复杂格式校验

### 代码示例（代码审查SKILL）

```python
class CodeReviewInput(BaseModel):
    """代码审查的输入参数"""  # 模型描述
    
    # 字段定义：类型 + Field描述 + 约束
    code: str = Field(
        description="要审查的代码片段，纯文本格式"
    )
    
    language: Literal["python", "javascript", "java", "go"] = Field(
        description="代码的编程语言，支持python/javascript/java/go"
    )
    
    review_focus: Optional[List[Literal["bug", "security", "performance", "style", "best_practice"]]] = Field(
        description="审查重点，可选值：bug(潜在bug)、security(安全漏洞)、performance(性能问题)、style(代码风格)、best_practice(最佳实践)。默认全部审查",
        default=None
    )
    
    strict_level: Literal["low", "medium", "high"] = Field(
        description="审查严格程度：low(宽松)、medium(中等)、high(严格)",
        default="medium"
    )

    # 自定义校验器：复杂格式校验
    @validator("code")
    def code_must_not_be_empty_and_too_long(cls, v):
        if not v.strip():
            raise ValueError("代码不能为空")
        if len(v) > MAX_CODE_LENGTH:
            raise ValueError(f"代码长度不能超过{MAX_CODE_LENGTH}字符，当前长度：{len(v)}")
        return v
```

### 常见错误

❌ 错误：不使用Pydantic，直接用裸函数参数

```python
@tool
def code_review(code, language="python"):
    # 手动写100行校验代码，还容易漏
    if not code:
        return "代码不能为空"
```

❌ 错误：不给字段加description

```python
code: str  # 大模型不知道这个参数是干什么的
```

### 最佳实践

- 能用`Literal`枚举的字段，绝对不要用普通字符串
- 所有可选参数必须有默认值
- 复杂格式校验必须用`@validator`实现，不要写在业务逻辑里
- 校验失败时抛出明确的`ValueError`，说明错误原因

## 第3层：安全校验层

### 设计目的

**防止大模型被诱导执行未授权操作**，这是生产环境SKILL的生命线。没有这一层的SKILL绝对不能上线。

### 必须包含的内容

1. 权限校验：验证调用用户是否有权执行该操作
2. 输入安全过滤：防注入、防敏感内容、防恶意输入
3. 幂等性校验：防止重复调用产生副作用
4. 资源限制：防止消耗过多系统资源

### 代码示例（代码审查SKILL）

```python
# 3. 安全校验层
# 检查敏感内容
sensitive_patterns = [
    "password", "secret", "api_key", "token", "private_key",
    "os.system", "subprocess", "eval", "exec", "rm -rf"
]

for pattern in sensitive_patterns:
    if pattern in code.lower():
        raise PermissionError(f"代码包含敏感内容：{pattern}，禁止审查")

# 扩展：权限校验（生产环境必须实现）
# if not user_has_permission(current_user_id, "code_review"):
#     raise PermissionError("你没有代码审查权限")

# 扩展：资源限制
# if get_current_user_quota(current_user_id) <= 0:
#     raise PermissionError("今日审查次数已用完")
```

### 常见错误

❌ 错误：完全没有安全校验

```python
# 危险！大模型可能被诱导执行任意代码
@tool
def run_command(cmd):
    """执行系统命令"""
    return os.system(cmd)
```

### 最佳实践

- 所有写操作（创建、修改、删除）必须有权限校验
- 所有用户输入必须经过安全过滤
- 敏感操作必须有二次确认机制
- 所有SKILL都要有调用频率限制和资源配额

## 第4层：日志审计层

### 设计目的

**记录所有SKILL调用行为**，满足企业审计要求，同时便于问题排查和性能优化。

### 必须包含的内容

1. 调用入参：所有输入参数（敏感信息脱敏）
2. 调用上下文：用户ID、调用时间、全链路追踪ID
3. 执行结果：成功/失败、返回数据摘要、执行耗时
4. 错误信息：失败时的错误码和错误描述

### 代码示例（代码审查SKILL）

```python
# 4. 日志审计层
code_hash = hashlib.md5(code.encode()).hexdigest()  # 敏感信息脱敏，不记录完整代码
logger.info(
    f"调用code_review SKILL - "
    f"用户ID: {current_user_id}, "
    f"语言: {language}, "
    f"代码长度: {len(code)}, "
    f"代码哈希: {code_hash}, "
    f"审查重点: {review_focus}, "
    f"严格程度: {strict_level}"
)
start_time = time.time()

# ... 业务逻辑执行 ...

# 记录成功日志
elapsed_time = (time.time() - start_time) * 1000
logger.info(
    f"code_review SKILL执行成功 - "
    f"耗时: {elapsed_time:.2f}ms, "
    f"发现问题: {result['total_issues']}个, "
    f"致命问题: {result['critical_issues']}个"
)
```

### 常见错误

❌ 错误：完全没有日志

```python
def code_review(code):
    # 没有任何日志，出了问题根本无法排查
    return review_result
```

❌ 错误：记录敏感信息

```python
logger.info(f"用户密码：{password}")  # 严重违规！
```

### 最佳实践

- 所有SKILL调用必须有日志记录
- 敏感信息必须脱敏后再记录
- 日志必须包含执行耗时，便于性能优化
- 错误日志必须包含完整的错误堆栈信息

---

## 第5层：核心业务逻辑层

### 设计目的

**实现SKILL的核心功能**，这是SKILL唯一应该包含业务逻辑的地方。

### 必须包含的内容

1. 业务逻辑的具体实现
2. 调用内部系统API或第三方服务
3. 业务规则处理
4. 数据转换和处理

### 代码示例（代码审查SKILL）

```python
# 5. 核心业务逻辑层
engine = CodeReviewEngine()
result = engine.review(
    code=code,
    language=language,
    review_focus=review_focus,
    strict_level=strict_level,
    include_suggestions=include_suggestions
)
```

### 常见错误

❌ 错误：把参数校验、日志、错误处理都写在这里

```python
def code_review(code):
    # 参数校验（应该在输入模型层）
    if not code:
        return "代码不能为空"
    
    # 日志（应该在日志审计层）
    logger.info(f"审查代码：{code}")
    
    try:
        # 业务逻辑
        return review(code)
    except Exception as e:
        # 错误处理（应该在错误处理层）
        return f"错误：{e}"
```

### 最佳实践

- 核心业务逻辑层应该**尽可能薄**，只做业务相关的事情
- 复杂业务逻辑应该封装成独立的类或函数（如示例中的`CodeReviewEngine`）
- 这一层不应该有任何`if-else`校验逻辑，所有校验都应该在输入模型层和安全校验层完成
- 这一层可以抛出异常，由错误处理层统一捕获和处理

---

## 第6层：错误处理层

### 设计目的

**统一捕获和处理所有异常**，返回结构化的错误信息，确保大模型能正确理解错误原因。

### 必须包含的内容

1. 分级错误处理：区分参数错误、权限错误、业务错误、系统错误
2. 统一错误格式：包含`success`、`error_code`、`error_message`三个字段
3. 错误日志记录：记录所有错误信息
4. 不向大模型抛出Python原生异常

### 代码示例（代码审查SKILL）

```python
except PermissionError as e:
    # 权限错误处理
    elapsed_time = (time.time() - start_time) * 1000
    error_msg = str(e)
    logger.warning(
        f"code_review SKILL权限拒绝 - "
        f"耗时: {elapsed_time:.2f}ms, "
        f"错误: {error_msg}"
    )
    
    return {
        "success": False,
        "error_code": "PERMISSION_DENIED",
        "error_message": error_msg
    }

except ValueError as e:
    # 参数错误处理
    elapsed_time = (time.time() - start_time) * 1000
    error_msg = str(e)
    logger.warning(
        f"code_review SKILL参数错误 - "
        f"耗时: {elapsed_time:.2f}ms, "
        f"错误: {error_msg}"
    )
    
    return {
        "success": False,
        "error_code": "INVALID_PARAMETER",
        "error_message": error_msg
    }

except Exception as e:
    # 通用系统错误处理
    elapsed_time = (time.time() - start_time) * 1000
    error_msg = str(e)
    logger.error(
        f"code_review SKILL执行失败 - "
        f"耗时: {elapsed_time:.2f}ms, "
        f"错误: {error_msg}",
        exc_info=True  # 记录完整堆栈信息
    )

    return {
        "success": False,
        "error_code": "INTERNAL_ERROR",
        "error_message": f"代码审查失败：{error_msg}"
    }
```

### 常见错误

❌ 错误：直接抛出异常给大模型

```python
def code_review(code):
    if not code:
        raise ValueError("代码不能为空")  # 大模型无法处理Python原生异常
```

❌ 错误：返回非结构化错误信息

```python
return "出错了"  # 大模型不知道具体是什么错误
```

### 最佳实践

- 所有异常必须被捕获，绝对不能抛出给大模型
- 错误信息必须清晰明确，大模型能理解并采取相应措施
- 不同类型的错误使用不同的错误码，便于统计和分析
- 系统错误要记录完整的堆栈信息，便于排查问题

## 第7层：输出规范层

### 设计目的

**统一输出格式**，确保大模型能准确解析返回结果，同时便于下游系统处理。

### 必须包含的内容

1. 固定的JSON格式返回
2. 必须包含`success`字段，表示操作是否成功
3. 成功时返回业务数据
4. 失败时返回错误码和错误描述

### 代码示例（代码审查SKILL）

```python
# 成功返回格式
return {
    "success": True,
    **result  # 展开业务数据
}

# 失败返回格式
return {
    "success": False,
    "error_code": "ERROR_CODE",
    "error_message": "错误描述"
}
```

### 常见错误

❌ 错误：返回自由文本

```python
return "代码审查完成，发现3个问题"  # 大模型无法解析具体问题
```

❌ 错误：返回格式不固定

```python
# 有时返回字典，有时返回字符串
if success:
    return {"result": "ok"}
else:
    return "error"
```

### 最佳实践

- 所有SKILL的输出必须是**字典格式**，绝对不能返回字符串或其他类型
- 输出格式必须固定，成功和失败都要有统一的结构
- 返回的数据要尽可能简洁，只包含大模型需要的信息
- 避免返回大模型无法理解的复杂对象或二进制数据

---

## 总结：7层结构核心要点表

| 层级 | 核心职责 | 关键技术 | 失败处理 |
|------|----------|----------|----------|
| 元数据层 | 让大模型理解SKILL | `@tool`装饰器、docstring | 大模型不调用或调用错误 |
| 输入模型层 | 参数校验与标准化 | Pydantic、`Field`、`@validator` | 返回参数错误 |
| 安全校验层 | 防止未授权操作 | 权限校验、输入过滤、幂等性 | 返回权限错误 |
| 日志审计层 | 记录调用行为 | logging、脱敏处理 | 不影响业务执行，但无法审计 |
| 核心业务逻辑层 | 实现核心功能 | 业务代码、API调用 | 抛出异常，进入错误处理层 |
| 错误处理层 | 统一异常处理 | try-except、分级错误 | 返回结构化错误信息 |
| 输出规范层 | 统一返回格式 | 字典、JSON | 大模型无法解析结果 |
