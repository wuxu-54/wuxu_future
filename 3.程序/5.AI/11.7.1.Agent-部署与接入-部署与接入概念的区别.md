
# 部署与接入方式的区别

## 📌 概念区分

| 概念层 | 代表问题 | 典型选项 | 例子 |
| :--- | :--- | :--- | :--- |
| **部署方式** | Agent 跑在哪里？如何被托管和伸缩？ | 云端、本地/边缘、混合、Serverless、K8s | 把 Agent 打包成 Docker 镜像，部署在阿里云 ECS 上 |
| **集成形态** | Agent 以什么“样子”被外部系统调用？ | API、Step、Gateway、CLI、WebSocket | 对外暴露一个 `/chat` 接口（API 形态），或变成一个飞书机器人（Gateway 形态） |

> **部署方式 ≈ 房子的地基和结构**  
> **集成形态 ≈ 房子开的门、窗、电梯（你怎么进出）**

## 🔁 两者的关系

- 同一个 Agent，**可以先选一种部署方式（比如 K8s 部署）**，再同时对外提供 **API 形态** 和 **Step 形态**。
- **API 形态** 可以跑在云端部署上，也可以跑在本地部署上。
- **Step 形态** 通常需要 Agent 被 Harness 平台（或类似 CI/CD 平台）识别，这背后可能是插件机制或进程调用，本质上也是一种部署后的集成方式。

## 🎯 所以写进文章的正确表述应该是

> **API、Step、Gateway 不是部署方式，而是 Agent 对外提供的三种集成/接入形态。**
>
> - **API**：把 Agent 包装成 HTTP 服务端点
> - **Step**：把 Agent 包装成 CI/CD 流水线中的一个可执行单元
> - **Gateway**：把 Agent 接入多个 IM 平台（飞书、钉钉等），由一个网关统一路由
>
> 而 Agent 真正的**部署方式**，指的是它运行在哪里、如何被托管：比如云托管、本地服务器、边缘设备、Serverless、K8s 等。
