# Agent 项目标准结构与识别扫描机制完全指南（2026 最新权威版）

在生成式 AI 应用开发的下半场，AI Agent 已经从实验性概念转变为日常开发的核心工具。然而，不同 Agent 框架和工具之间碎片化的配置方式，一直是阻碍开发者效率提升的最大痛点之一。

一套**标准化的目录结构与自动发现机制**，能让 Agent 无需人工配置就能"看懂"你的项目、调用预定义技能、遵循团队规范。本文将基于 2025 年底正式确立的行业开放标准，从零开始完整讲解 Agent 项目的标准目录结构、各文件的核心作用，以及 Agent 如何自动扫描、识别并加载这些内容。

---

## 一、为什么需要标准目录结构？

在统一标准形成之前，每个 Agent 工具都有自己独特的配置体系：有的用 `config.yaml`，有的用 `agent.json`，有的直接把提示词硬编码在业务逻辑里。这种碎片化导致了三个严重问题：

- **难以跨工具复用**：从 Claude Code 换到 Cursor，所有项目配置和自定义技能都要重写一遍
- **团队协作混乱**：不同成员使用不同工具，项目规范无法通过 AI 自动执行
- **上下文严重浪费**：每个 Agent 都需要加载大量无关信息，既消耗 tokens 又降低响应质量

为了解决这些问题，行业逐渐形成了以 **`AGENTS.md`** 和 **`SKILL.md`** 为核心的标准化目录规范。这些规范遵循**渐进式披露**原则，让 Agent 只在必要时加载详细信息，极大地节约了宝贵的上下文窗口资源。

---

## 二、标准目录结构与文件说明

截至 2026 年 6 月，一个遵循行业开放标准的 Agent 项目目录通常包含以下内容：
> 注意这里是可以自动扫描AGENTS.md描述文件的情况，如果是使用Langchain等框架需要手动开发扫描识别及处理能力。

```
your-project/
├── AGENTS.md                      # 跨工具通用项目级 AI 指令（总纲）
├── .agents/                       # Agentic AI Foundation 通用标准目录
│   ├── AGENTS.md                  # 可选的补充指令
│   └── skills/                    # 跨工具通用技能存放处
│       └── skill-name/
│           ├── SKILL.md
│           ├── scripts/           # 技能关联的可执行脚本
│           └── references/        # 技能关联的参考文档
├── .claude/                       # Claude Code 专用目录
│   ├── CLAUDE.md                  # Claude 专属项目指令
│   ├── settings.json              # Claude 项目设置
│   └── skills/                    # Claude 专用技能
└── .cursor/                       # Cursor 专用目录（类似结构）
    ├── CURSOR.md
    └── rules/
```

### 2.1 根目录 `AGENTS.md`（最基础也最重要）

`AGENTS.md` 是一个专门为 AI 智能体设计的 Markdown 文件，提供**项目级别的工作指南**。它是所有支持标准的 Agent 工具都会自动读取的第一个文件。

它应该告诉 Agent：

- 项目的安装、构建、测试和运行命令
- 代码风格与命名规范
- PR 流程与 commit 信息格式
- 特殊依赖或安全注意事项
- 项目的整体架构和核心模块说明

**标准示例：**

```markdown
# Project Instructions for AI Agents

## Build & Test
- Install dependencies: `pip install -e .[dev]`
- Run all tests: `pytest tests/ -v`
- Run linting: `ruff check . && ruff format .`
- Start local server: `uvicorn main:app --reload`

## Code Style
- Use Ruff formatter with default settings
- Maximum line length: 88
- All functions must have type hints
- Write docstrings in Google style

## Important Rules
- Never commit secrets or API keys to the repository
- Always update CHANGELOG.md when making a release
- For database changes, create a migration file first
```

> **标准背景**：`AGENTS.md` 最初由 OpenAI、Google、Sourcegraph、Cursor 等行业巨头组成的工作组共同开发。2025 年 12 月 9 日，OpenAI 和 Anthropic 正式将其与 MCP（模型上下文协议）一起捐赠给 Linux 基金会，成立了 **Agentic AI Foundation(AAIF)** 来管理这些开放标准。目前已被 Cursor、Claude Code、Copilot、Devin、Windsurf、Gemini CLI 等所有主流 AI 开发工具支持。

### 2.2 `.agents/` – 跨工具通用标准目录

`.agents/` 目录是 Agentic AI Foundation 推动的核心标准，旨在成为 AI Agent 世界的".editorconfig"。任何支持该标准的工具都会自动读取此目录下的配置。

- **位置**：支持项目级（`./.agents/`）和用户级（`~/.agents/`）两种
- **内容**：可以包含 `AGENTS.md`、`skills/` 子目录等
- **核心优势**：一次配置，多工具共享。例如，你在 `.agents/skills/pdf-parser/SKILL.md` 中定义了一个 PDF 解析技能，那么 Claude Code、Cursor、Continue 等所有支持标准的工具都可以直接使用，无需重复编写

### 2.3 工具专用目录

不同的 AI 开发工具会提供自己的专用目录，用于存放只有该工具才能识别的高级配置：

- **`.claude/` 目录**：由 Anthropic 为 Claude Code 定义。`CLAUDE.md` 是 Claude 专属的项目指令文件，优先级高于通用的 `AGENTS.md`。`settings.json` 用于配置项目级的 Claude 设置，`skills/` 目录存放只能在 Claude Code 中使用的专用技能。
- **`.cursor/` 目录**：由 Cursor 编辑器定义。`CURSOR.md` 是 Cursor 专属指令，`rules/` 目录存放 Cursor 的自定义规则。

> **注意**：截至 2026 年 6 月，LangChain Deep Agents 主要通过代码方式配置技能和子代理，尚未官方定义 `.deepagents/` 标准目录；月之暗面的 Kimi Code 也有自己独立的技能管理系统，尚未官方支持 `.kimi/` 通用目录结构。

### 2.4 `skills/` – 规范级技能（核心扩展能力）

`skills/` 目录下存放一个个独立的 **Skill 文件夹**，每个文件夹必须包含一个 `SKILL.md` 文件。Skill 是对 AI 可复用能力单元的标准化封装，例如"智能代码审查"、"PDF 表单填写"、"SQL 查询生成与执行"等。

**标准 `SKILL.md` 结构：**

```markdown
---
name: code-review-skill
version: 1.0.0
description: 智能审查代码，检查 bug、安全漏洞、性能问题和代码风格，返回结构化的问题列表和修复建议。
inputs:
  - name: code
    type: string
    required: true
    description: 要审查的代码内容
  - name: language
    type: string
    required: true
    enum: [python, javascript, java, go]
    description: 代码的编程语言
outputs:
  - name: review_result
    type: json
    description: 结构化的审查结果
---

# 执行流程
1. 接收输入的 code 和 language 参数
2. 调用 `scripts/review.py` 脚本进行静态分析
3. 结合静态分析结果和 LLM 能力进行全面审查
4. 按照指定的 JSON 格式返回结果

# 输入输出示例
## 输入
```json
{
  "code": "def add(a, b): return a + b",
  "language": "python"
}
```

## 输出

```json
{
  "issues": [],
  "suggestions": ["添加类型提示", "添加 docstring"]
}
```

# 错误处理

- 如果输入的代码为空，返回错误信息"代码内容不能为空"
- 如果不支持输入的编程语言，返回错误信息"不支持的编程语言"

```

- **YAML 前置元数据**：约 100-200 tokens，包含 `name`、`description`、`inputs` 等核心信息。这部分会在 Agent 启动时被加载到系统提示中，用于**技能匹配**。
- **Markdown 正文**：详细的工作流程、输入输出示例、错误处理等，建议控制在 5000 token 以内。**只在技能被触发时才会加载**。
- **关联资源**：如 `scripts/` 中的可执行脚本、`references/` 中的参考文档，会在技能执行时按需加载。

这种设计就是**渐进式披露**的核心体现：Agent 首先知道有哪些技能可用，只有确定需要某个技能时才读取完整内容，极大地提高了上下文使用效率。

## 三、Agent 如何识别这些内容？—— 扫描与加载机制

Agent 并不会"看到"文件夹图标，而是通过**文件系统扫描 + 优先级规则**来自动发现并加载配置。整个过程完全开箱即用，无需你编写任何代码。

### 3.1 扫描的路径规则（优先级由低到高）

Agent 在启动时，会按照以下固定顺序扫描一系列预定义的目录。**优先级高的目录会覆盖优先级低的同名配置**。

| 优先级 | 级别 | 目录示例 | 说明 |
|--------|------|----------|------|
| 最低 | **内置** | 随 Agent 软件包安装的 `skills/` | 官方提供的基础技能，如通用计算器、网络搜索 |
| 中 | **用户级** | `~/.agents/skills/`<br>`~/.claude/skills/`<br>`~/.cursor/rules/` | 放在用户主目录下，对所有项目**全局生效**。适合存放个人常用技能 |
| 最高 | **项目级** | `./.agents/skills/`<br>`./.claude/skills/`<br>`./.cursor/rules/` | 仅在当前项目内生效，适合存放项目专属技能。项目级配置会覆盖用户级和内置级 |

#### 品牌组 vs 通用组

在同一级别内（如项目级），Agent 会同时扫描**品牌专用目录**（如 `.claude/skills/`、`.cursor/rules/`）和**通用目录**（`.agents/skills/`）。通常情况下，**品牌组的优先级高于通用组**，因为特定工具的配置往往更具体。

> 部分 Agent 支持通过配置项 `merge_all_available_skills = true` 来**合并所有目录中的技能**，而不是按优先级覆盖。

### 3.2 文件的发现与加载过程

#### `SKILL.md` 加载流程（渐进式披露的核心）

1. **启动扫描**：当你在项目目录中启动 Agent 时，它会立即按照上述优先级顺序遍历所有可能的技能目录
2. **定位 `SKILL.md`**：在每个技能子文件夹中，Agent 寻找名为 `SKILL.md` 的文件
3. **解析元数据**：Agent 只读取文件开头 `---` 包裹的 YAML 部分，提取 `name`、`description`、`inputs` 等字段
4. **注册工具**：Agent 将每个技能封装成一个可调用的"元工具"，添加到系统提示词中的"可用技能清单"里。**此时不会加载完整的 Markdown 正文**
5. **按需加载正文**：当用户发出请求时，LLM 根据技能清单判断需要调用哪个技能。一旦决定使用某个技能，Agent 才会去读取对应 `SKILL.md` 的完整正文，并将其作为执行指引注入上下文
6. **执行关联资源**：如果技能需要运行外部脚本或读取参考文档，Agent 会在执行工具调用时按需启动子进程或读取文件

#### `AGENTS.md` 加载流程

与技能不同，`AGENTS.md` 采用**分层覆盖机制**：

1. Agent 从项目根目录开始，向下遍历到当前工作目录
2. 加载所有遇到的 `AGENTS.md` 文件
3. 子目录的文件会覆盖根目录中冲突的指令
4. 最接近当前工作目录的文件优先级最高

例如，你可以在 `src/backend/` 目录下创建一个专门的 `AGENTS.md`，定义后端代码的特殊规范。当 Agent 在 `src/backend/` 目录下工作时，会自动应用这些规范，同时保留根目录中不冲突的全局指令。

### 3.3 文件命名与特殊覆盖

- **`AGENTS.override.md`**：所有支持标准的工具都支持这个优先级最高的覆盖文件。它的内容会完全取代同一目录下的普通 `AGENTS.md`，非常适合临时调整指令而不修改原文件（通常加入 `.gitignore`）
- **品牌专用指令文件**：如 `CLAUDE.md`、`CURSOR.md`，仅被对应工具识别。如果同时存在通用 `AGENTS.md` 和品牌专用指令文件，对应工具会优先使用品牌专用文件

## 四、四种配置方式对比

虽然 Agent 默认会自动扫描上述目录，但为了满足不同场景的需求，业界提供了多种方式来**定制扫描行为**：

| 方式 | 工作原理 | 使用场景 | 是否需要手动编码 |
|------|----------|----------|------------------|
| **1. 自动扫描默认路径** | Agent 启动时自动扫描内置、用户级、项目级的标准目录 | 绝大多数日常开发，零配置开箱即用 | 否 |
| **2. 代码显式指定** | 在自定义 Agent 代码中，通过参数传入技能目录列表 | 使用 LangChain 等框架开发定制 Agent 时，指定额外的技能路径 | 是 |
| **3. 命令行参数/环境变量** | 启动 Agent 时添加 `--skills-dir` 参数或设置 `AGENT_SKILLS_PATH` 环境变量 | 临时测试某个新技能，或者在不修改代码的情况下覆盖默认目录 | 否（但需要输入命令） |
| **4. 配置文件调整** | 修改 Agent 的配置文件（如 `config.toml`、`settings.json`）来改变扫描行为 | 希望永久修改优先级规则、启用合并所有技能、自定义根目录等 | 否（编辑配置文件） |

**代码显式指定示例（LangChain）：**

```python
from langchain_deep_agents import create_deep_agent

agent = create_deep_agent(
    model="gpt-4o",
    skill_directories=["./my-custom-skills", "/shared/team-skills"]
)
```

**命令行示例（Claude Code）：**

```bash
claude --skills-dir ./experimental-skills --skills-dir /tmp/test-skills
```

**配置文件示例：**

```toml
# config.toml
[agent]
merge_all_available_skills = true
additional_skills_dirs = ["~/.custom-skills", "./project-skills"]
```

## 五、实践建议与最佳实践

1. **从根目录 `AGENTS.md` 开始**：这是让 Agent 快速理解项目的最简单且最有效的方式。写出清晰、结构化的指令，避免冗长的人类叙述。
2. **优先使用通用目录**：将通用技能放在 `.agents/skills/` 目录下，实现跨工具复用。只有当某个技能只能在特定工具中使用时，才放在工具专用目录中。
3. **精心设计 `SKILL.md`**：
   - 在 YAML 元数据中提供精确的 `description`，这是 LLM 能否准确匹配技能的关键
   - Markdown 正文控制在 5000 token 以内，复杂细节放在 `references/` 目录中按需加载
   - 必须提供清晰的输入输出示例和错误处理说明
4. **善用分层覆盖机制**：在不同的子目录下创建专门的 `AGENTS.md`，定义该目录下代码的特殊规范。
5. **利用 `AGENTS.override.md` 测试**：在修改正式的 `AGENTS.md` 之前，先用 `AGENTS.override.md` 测试指令效果，验证无误后再合并到正式文件中。
6. **版本控制**：将项目级的 `AGENTS.md` 和 `.agents/skills/` 提交到 Git，实现团队共享。用户级和个人测试目录加入 `.gitignore`。

## 六、总结

Agent 项目的标准目录结构并非强制标准，而是行业在实践中演化出的最佳实践，并已通过 Agentic AI Foundation 正式成为开放标准。其核心价值在于三个方面：

- **统一认知**：无论你使用 Claude Code、Cursor 还是自研 Agent，`AGENTS.md` 和 `SKILL.md` 都能被准确理解
- **高效上下文**：通过"元数据常驻、正文按需加载"的渐进式披露机制，最大化利用有限的上下文窗口
- **自动发现**：Agent 启动时按照"内置 < 用户级 < 项目级"的优先级自动扫描预设目录，无需手动配置即可加载技能和指令

截至 2026 年 6 月，这套标准已经被所有主流 AI 开发工具广泛采用，并且还在快速完善中。理解并应用这套机制，将极大地提高你的 AI 辅助开发效率，让 Agent 真正成为你团队中最得力的"数字员工"。

现在就动手试试吧——在你的项目根目录创建一个 `AGENTS.md`，然后启动你的 Agent，看看它会如何响应。
