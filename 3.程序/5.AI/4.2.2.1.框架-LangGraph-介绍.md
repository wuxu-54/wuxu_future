# LangGraph 1.0 完整指南：生产级AI智能体编排框架

**一句话定义**：LangGraph是LangChain生态推出的**基于状态图的生产级AI智能体编排框架**，专门用于构建有状态、多步骤、可循环的复杂AI应用。它彻底解决了传统链式框架（如LangChain LCEL）无法处理循环、状态管理混乱、缺乏持久化的问题，是当前实现ReAct、多智能体协作等人机交互系统的首选工具。

## 一、概述与发展历程

### 1.1 为什么需要LangGraph？

传统大模型应用框架（如LangChain v0.1）基于**有向无环图（DAG）**设计，存在三个致命缺陷：

- **无法支持循环**：不能实现"思考-行动-观察"的ReAct循环，无法自我修正和重试
- **状态管理混乱**：上下文通过链式传递，难以维护全局状态，长任务易丢失信息
- **缺乏持久化**：服务器重启或任务中断后无法恢复，不适合生产环境
- **人机交互困难**：难以实现人工审批、中途修改等Human-in-the-loop场景

LangGraph的出现正是为了解决这些问题，它将智能体工作流建模为**有向有环图**，允许任意复杂的执行流程，同时提供了原生的状态管理、持久化和人机交互能力。

### 1.2 发展里程碑

- **2023年11月**：LangGraph首次发布，作为LangChain生态的实验性项目
- **2024年6月**：发布v0.2版本，引入Checkpointing和Human-in-the-loop
- **2025年10月22日**：正式发布**v1.0稳定版**，API完全固化，被Uber、LinkedIn、Klarna等公司大规模采用
- **2026年2月**：发布v1.1版本，优化流式输出和多智能体协作能力

### 1.3 与LangChain的关系

LangGraph不是LangChain的替代品，而是**互补和升级**：

- **LangChain**：提供模块化组件（LLM、工具、向量数据库、提示词模板）
- **LangGraph**：提供编排层，将这些组件组织成复杂的、有状态的工作流
- **LangSmith**：提供可观测性、调试和评估能力

三者共同构成了完整的LangChain AI应用开发栈。

## 二、核心概念：五大基石

LangGraph的所有功能都建立在五个核心概念之上，理解它们是掌握LangGraph的关键。

### 2.1 State（状态）：智能体的"记忆中枢"

State是贯穿整个图执行过程的**全局共享数据容器**，所有节点都可以读取和写入它。它是智能体所有记忆和上下文的唯一来源。

**定义方式**：通常使用Python的`TypedDict`或Pydantic `BaseModel`

```python
from typing import TypedDict, List
from langchain_core.messages import BaseMessage

class AgentState(TypedDict):
    messages: List[BaseMessage]  # 对话历史
    user_input: str             # 用户原始输入
    current_step: str           # 当前执行步骤
    final_answer: str           # 最终答案
```

**核心特性**：

- **增量更新**：节点只需返回需要更新的字段，不必返回整个State
- **类型安全**：支持类型提示，减少运行时错误
- **可定制合并规则**：可以为不同字段定义自定义Reducer（如消息列表的追加）

### 2.2 Node（节点）：业务逻辑的"最小执行单元"

Node是一个普通的Python函数，接收当前State作为输入，执行具体的业务逻辑，返回更新后的部分State。

**节点类型**：

- **LLM节点**：调用大语言模型进行推理或生成
- **工具节点**：调用外部工具（如搜索引擎、数据库、API）
- **逻辑节点**：执行纯计算或条件判断
- **子图节点**：将另一个完整的图作为节点嵌入

**示例**：一个简单的LLM节点

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o", temperature=0)

def call_llm(state: AgentState) -> dict:
    """调用LLM生成回答"""
    response = llm.invoke(state["messages"])
    return {"messages": [response]}  # 只更新messages字段
```

### 2.3 Edge（边）：流程流转的"规则定义者"

Edge定义了节点之间的连接关系，决定了"当前节点执行完成后，下一个执行哪个节点"。

**边的类型**：

1. **静态边（Static Edge）**：固定从一个节点流向另一个节点

   ```python
   graph.add_edge("call_llm", "call_tool")  # LLM执行完后固定调用工具
   ```

2. **条件边（Conditional Edge）**：根据当前State动态决定下一个节点

   ```python
   from langgraph.graph import END

   def should_continue(state: AgentState) -> str:
       """判断是否需要继续调用工具"""
       last_message = state["messages"][-1]
       if last_message.tool_calls:
           return "call_tool"  # 有工具调用，继续执行
       return END  # 没有工具调用，结束流程

   graph.add_conditional_edges(
       "call_llm",
       should_continue,
       {
           "call_tool": "call_tool",
           END: END
       }
   )
   ```

3. **入口边（Entry Point）**：定义图的起始节点

   ```python
   graph.set_entry_point("call_llm")
   ```

### 2.4 StateGraph（状态图）：智能体的"蓝图"

StateGraph是LangGraph的核心类，用于定义整个工作流的结构。它将节点和边组合成一个完整的图。

**基本使用**：

```python
from langgraph.graph import StateGraph

# 1. 创建状态图
graph = StateGraph(AgentState)

# 2. 添加节点
graph.add_node("call_llm", call_llm)
graph.add_node("call_tool", call_tool)

# 3. 添加边
graph.add_edge("call_tool", "call_llm")
graph.add_conditional_edges("call_llm", should_continue)

# 4. 设置入口点
graph.set_entry_point("call_llm")
```

### 2.5 Checkpointer（检查点）：持久化与"时光机"

Checkpointer是LangGraph最强大的特性之一，它会在图执行的每一步自动保存State的快照，实现：

- **持久化执行**：服务器重启或任务中断后可以从断点恢复
- **历史追溯**：查看智能体执行的完整历史轨迹
- **时光倒流**：回到任意历史节点，修改状态后重新执行
- **分支执行**：从同一个历史节点分叉出多个不同的执行路径

**内置Checkpointer实现**：

- `MemorySaver`：内存存储，适合开发调试
- `SqliteSaver`：SQLite数据库存储，适合单服务器生产环境
- `RedisSaver`：Redis存储，适合分布式部署

**使用示例**：

```python
from langgraph.checkpoint.sqlite import SqliteSaver

# 创建SQLite检查点
checkpointer = SqliteSaver.from_conn_string("agent_state.db")

# 编译图时传入检查点
app = graph.compile(checkpointer=checkpointer)

# 运行时指定thread_id，用于区分不同的会话
config = {"configurable": {"thread_id": "user_123"}}
result = app.invoke({"messages": [("user", "你好")]}, config=config)
```

## 三、核心工作原理

### 3.1 Pregel执行引擎

LangGraph基于Google的Pregel图计算引擎实现，采用**批量同步并行（BSP）**模型：

1. **超级步（Superstep）**：图的执行被划分为多个超级步
2. **节点执行**：在每个超级步中，所有可执行的节点并行运行
3. **全局同步**：所有节点执行完成后，进入下一个超级步
4. **状态更新**：在超级步之间，全局State被原子性地更新

这种执行模型保证了状态的一致性和执行的确定性。

### 3.2 完整执行流程

1. **编译**：将StateGraph编译成可执行的Pregel应用
2. **初始化**：加载初始State和Checkpoint（如果有）
3. **超级步循环**：
   - 确定当前可执行的节点
   - 并行执行所有可执行节点
   - 收集所有节点的输出，更新全局State
   - 保存Checkpoint
   - 根据边的规则确定下一个超级步的可执行节点
4. **终止**：当没有可执行节点或到达END节点时，执行结束

### 3.3 状态更新机制

LangGraph采用**增量合并**的方式更新State：

- 每个节点返回一个字典，包含需要更新的字段
- 框架自动将这些字段合并到全局State中
- 对于列表类型的字段（如messages），默认采用追加模式
- 可以通过自定义Reducer来改变合并行为

## 四、关键特性详解

### 4.1 原生循环支持：ReAct的完美实现

这是LangGraph与其他框架最本质的区别。通过条件边，LangGraph可以轻松实现任意复杂的循环逻辑，包括：

- **ReAct循环**：思考→行动→观察→思考
- **重试循环**：工具调用失败时自动重试
- **反思循环**：执行完成后反思结果，不满意则重新执行

**ReAct循环实现**：

```python
# 节点定义
def agent(state: AgentState) -> dict:
    """思考阶段：决定下一步行动"""
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

def tools(state: AgentState) -> dict:
    """行动阶段：调用工具并返回结果"""
    tool_calls = state["messages"][-1].tool_calls
    results = tool_executor.invoke(tool_calls)
    return {"messages": results}

# 边定义
def should_continue(state: AgentState) -> str:
    """判断是否需要继续循环"""
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "tools"
    return END

# 构建图
graph = StateGraph(AgentState)
graph.add_node("agent", agent)
graph.add_node("tools", tools)
graph.set_entry_point("agent")
graph.add_conditional_edges("agent", should_continue)
graph.add_edge("tools", "agent")  # 工具执行完后回到agent，形成循环

app = graph.compile()
```

### 4.2 Human-in-the-loop：原生人机交互

LangGraph提供了第一流的Human-in-the-loop支持，允许在任意节点暂停执行，等待人类介入：

- **人工审批**：高风险操作（如付款、发邮件）前等待人类确认
- **状态修改**：人类可以修改智能体的状态，纠正错误
- **继续执行**：人类确认后，智能体从断点继续执行

**实现示例**：

```python
# 编译图时设置中断点，在执行"send_email"节点前暂停
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=["send_email"]
)

# 运行智能体
config = {"configurable": {"thread_id": "1"}}
app.invoke({"messages": [("user", "给张三发一封邮件")]}, config=config)

# 此时智能体已暂停，等待人工审批
# 获取当前状态
state = app.get_state(config)
print("待发送邮件：", state.values["email_draft"])

# 人工修改邮件内容
app.update_state(config, {"email_draft": "修改后的邮件内容"})

# 继续执行
app.invoke(None, config=config)
```

### 4.3 多智能体协作

LangGraph天生支持多智能体系统，可以轻松构建多个智能体协作的复杂应用：

- **角色分工**：每个智能体有明确的角色（如研究员、分析师、作家）
- **信息共享**：所有智能体共享同一个全局State
- **动态调度**：根据任务状态动态决定哪个智能体执行

**多智能体架构示例**：

```python
# 定义三个智能体节点
def researcher(state: AgentState) -> dict:
    """研究员：负责收集信息"""
    pass

def analyst(state: AgentState) -> dict:
    """分析师：负责分析数据"""
    pass

def writer(state: AgentState) -> dict:
    """作家：负责生成报告"""
    pass

# 定义调度器
def supervisor(state: AgentState) -> str:
    """调度器：决定下一个执行哪个智能体"""
    last_message = state["messages"][-1]
    if "需要更多信息" in last_message.content:
        return "researcher"
    elif "需要分析" in last_message.content:
        return "analyst"
    elif "报告完成" in last_message.content:
        return END
    return "writer"

# 构建多智能体图
graph = StateGraph(AgentState)
graph.add_node("researcher", researcher)
graph.add_node("analyst", analyst)
graph.add_node("writer", writer)
graph.add_node("supervisor", supervisor)

graph.set_entry_point("supervisor")
graph.add_conditional_edges("supervisor", {
    "researcher": "researcher",
    "analyst": "analyst",
    "writer": "writer",
    END: END
})
graph.add_edge("researcher", "supervisor")
graph.add_edge("analyst", "supervisor")
graph.add_edge("writer", "supervisor")
```

### 4.4 其他重要特性

- **流式输出**：支持逐token输出，提升用户体验
- **并行执行**：支持同时调用多个工具或执行多个节点
- **子图**：支持将复杂工作流拆分为多个子图，提高代码复用性
- **错误处理**：支持节点级别的错误处理和重试
- **可观测性**：与LangSmith深度集成，提供完整的执行轨迹和调试信息

## 五、完整实战：构建一个ReAct智能体

下面我们用LangGraph构建一个完整的ReAct智能体，具备搜索和计算能力。

### 5.1 安装依赖

```bash
pip install langgraph langchain-openai langchain-community python-dotenv
```

### 5.2 导入模块和初始化

```python
from typing import TypedDict, List
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import BaseMessage, HumanMessage
from langgraph.graph import StateGraph, END
from langgraph.prebuilt import ToolNode
from langgraph.checkpoint.memory import MemorySaver
from dotenv import load_dotenv

load_dotenv()

# 初始化LLM
llm = ChatOpenAI(model="gpt-4o", temperature=0)
```

### 5.3 定义工具

```python
@tool
def search(query: str) -> str:
    """搜索互联网获取信息"""
    # 实际实现中调用搜索引擎API
    return f"搜索结果：{query}"

@tool
def calculate(expression: str) -> str:
    """计算数学表达式"""
    try:
        return str(eval(expression))
    except:
        return "计算错误，请检查表达式"

tools = [search, calculate]
tool_node = ToolNode(tools)
llm_with_tools = llm.bind_tools(tools)
```

### 5.4 定义状态和节点

```python
class AgentState(TypedDict):
    messages: List[BaseMessage]

def agent(state: AgentState) -> dict:
    """智能体节点：调用LLM生成回答或工具调用"""
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

def should_continue(state: AgentState) -> str:
    """判断是否需要继续调用工具"""
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "tools"
    return END
```

### 5.5 构建和编译图

```python
# 创建图
graph = StateGraph(AgentState)

# 添加节点
graph.add_node("agent", agent)
graph.add_node("tools", tool_node)

# 设置入口点
graph.set_entry_point("agent")

# 添加条件边
graph.add_conditional_edges("agent", should_continue)

# 添加静态边：工具执行完后回到agent
graph.add_edge("tools", "agent")

# 编译图
memory = MemorySaver()
app = graph.compile(checkpointer=memory)
```

### 5.6 运行智能体

```python
# 配置thread_id
config = {"configurable": {"thread_id": "1"}}

# 运行智能体
result = app.invoke(
    {"messages": [HumanMessage(content="2024年诺贝尔物理学奖得主是谁？他们的年龄分别是多少？")]},
    config=config
)

# 输出结果
print(result["messages"][-1].content)
```

### 5.7 可视化图

## 六、与其他框架的对比

| 对比维度 | LangGraph | LangChain Agents | CrewAI | AutoGen |
|---------|-----------|------------------|--------|---------|
| **设计理念** | 状态图工作流 | 链式执行 | 角色-团队协作 | 对话式多智能体 |
| **核心抽象** | State+Node+Edge | AgentExecutor | Agent+Task+Crew | ConversableAgent |
| **循环支持** | 原生支持 | 模拟实现（不稳定） | 有限支持 | 支持 |
| **状态管理** | 显式、类型安全 | 隐式、封装 | 隐式 | 隐式 |
| **持久化** | 原生支持 | 需要自定义 | 有限支持 | 有限支持 |
| **Human-in-the-loop** | 原生支持 | 困难 | 困难 | 支持 |
| **生产就绪性** | 高（v1.0稳定） | 中 | 中 | 中 |

**选型建议**：

- **简单单智能体**：LangChain Agents 或 LangGraph

## 七、应用场景

LangGraph几乎适用于所有复杂的AI应用场景，特别是：
