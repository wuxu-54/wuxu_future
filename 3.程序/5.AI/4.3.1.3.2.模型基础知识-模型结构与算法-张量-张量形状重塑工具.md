# 张量形状重塑工具

张量的形状操作是深度学习与端侧推理中最高频的操作之一，除了 `view` 和 `reshape` 之外，还有维度重排、增减维度、广播扩展、拼接拆分等十余种常用工具。它们的核心差异集中在**是否拷贝数据、输出是否连续、是否改变元素总数、是否改变元素顺序**这四点，直接决定了性能开销和使用限制。

下面按「纯形状重塑（元素总数不变）」和「组合式变形（元素总数变化）」两大类逐一讲解，最后给出完整对比和选型指南。

## 一、纯形状重塑：元素总数不变，仅调整维度结构

这类操作不增删元素、不修改元素数值，只调整张量的维度组织方式，是日常开发中最常用的一类。

### （一）维度划分类：仅改维度边界，不改变元素逻辑顺序

这类操作本质都是「重新划分维度边界」，元素的遍历顺序和物理内存顺序保持一致（连续时）。

#### 1. `view()`

- **核心作用**：重新划分张量维度，元素总数严格不变。
- **底层行为**：仅修改 `shape` 和 `stride` 元数据，**绝对零拷贝**，与原张量共享同一块内存。
- **核心限制**：输入张量必须内存连续（`is_contiguous() == True`），否则直接报错。
- **输出连续性**：始终连续。
- **典型场景**：确定张量连续时的高性能变形，例如卷积特征图展平后送入全连接层。

#### 2. `reshape()`

- **核心作用**：功能与 `view` 完全一致，是通用兼容版本。
- **底层行为**：智能判断——输入连续则等价于 `view`（零拷贝）；输入非连续则自动拷贝一份连续内存再变形（有拷贝开销）。
- **核心限制**：无前置条件，所有张量都可使用。
- **输出连续性**：始终连续。
- **典型场景**：通用开发、不确定输入连续性时使用，代码兼容性最强。

#### 3. `flatten(start_dim, end_dim)`

- **核心作用**：将指定维度范围内的所有维度展平为一维，是 `reshape` 的语法糖。
- **底层行为**：内部调用 `reshape`，拷贝行为与 `reshape` 完全一致。
- **典型场景**：CNN特征图展平、多维度特征合并，例如 `[B, C, H, W]` 展平为 `[B, C*H*W]`。

#### 4. `unsqueeze(dim)` / `squeeze(dim)`

- **`unsqueeze`**：在指定位置插入一个**大小为1**的新维度，维度总数+1。
- **`squeeze`**：移除指定位置大小为1的维度；不指定 `dim` 则移除所有大小为1的冗余维度。
- **底层行为**：本质是 `view` 的特例，零拷贝，仅修改元数据。
- **典型场景**：
  - `unsqueeze`：给单张图片增加batch维度、给向量增加通道维度
  - `squeeze`：去除模型输出中冗余的单维度，方便后处理

#### 5. `view_as(target)` / `reshape_as(target)`

- **核心作用**：语法糖，将自身形状变成与目标张量完全一致。
- **底层行为**：分别等价于 `view(target.shape)` 和 `reshape(target.shape)`。
- **典型场景**：两个张量做元素运算前快速对齐形状。

---

### （二）维度重排类：调换维度顺序，零拷贝但会导致非连续

这类操作只调换维度的逻辑顺序，**完全不移动内存数据**，速度极快，但会破坏内存连续性。

#### 1. `transpose(dim0, dim1)`

- **核心作用**：交换两个指定维度的位置。
- **底层行为**：仅交换对应维度的 `shape` 和 `stride`，零拷贝。
- **输出连续性**：几乎总是非连续（除非交换的维度大小均为1）。
- **典型场景**：简单两维交换，例如矩阵转置、单通道维度前后调换。

#### 2. `permute(*dims)`

- **核心作用**：按传入的顺序一次性重新排列所有维度，是 `transpose` 的高阶版，支持同时调整多个维度。
- **底层行为**：零拷贝，仅修改元数据。
- **输出连续性**：通常非连续。
- **典型场景**：多维度格式转换，例如图片格式 `NHWC ↔ NCHW` 转换，是端侧预处理最常见的操作之一。

#### 3. `swapdims(dim0, dim1)`

- **核心作用**：与 `transpose` 功能完全一致，语义更直观，部分框架（NumPy）中叫 `swapaxes`。
- **底层与输出**：同 `transpose`，零拷贝、输出非连续。

> 关键区别：`transpose` 只能两两交换；`permute` 一次性定义所有维度的最终顺序，适合多维度复杂重排。

---

### （三）广播与复制类：逻辑/物理扩展元素

这类操作会改变逻辑上的元素总数，分为「零拷贝逻辑扩展」和「真拷贝物理复制」两类。

#### 1. `expand(*sizes)`

- **核心作用**：将张量中**大小为1的维度**广播扩展到指定大小，属于“假扩展”。
- **底层行为**：**零拷贝**，仅将对应维度的步长（stride）设为0，所有位置都指向同一个内存元素。
- **核心限制**：只能扩展原本大小为1的维度，非1维度的大小必须与目标完全一致。
- **输出连续性**：非连续。
- **典型场景**：偏置广播、掩码广播，例如将 `[C]` 形的通道偏置扩展为 `[B, C, H, W]`，比复制数据更省内存。

#### 2. `repeat(*sizes)`

- **核心作用**：将整个张量在对应维度上重复指定次数，属于“真复制”。
- **底层行为**：完整拷贝所有元素数据，生成新的连续张量，有明确的内存与时间开销。
- **输出连续性**：连续。
- **典型场景**：需要真正复制多份数据的场景，例如特征重复叠加、多尺度特征对齐。

> 核心选型原则：能用 `expand` 广播实现的，绝对不要用 `repeat`，内存和性能差距极大。

---

### （四）特殊空间变形：针对图像/序列的滑窗操作

#### 1. `unfold(dim, size, step)`

- **核心作用**：在指定维度上滑动窗口，提取固定大小的局部块，常用于图像分块、序列滑窗。
- **底层行为**：通过修改步长实现零拷贝视图。
- **输出连续性**：非连续。
- **典型场景**：ViT图像分块、时间序列滑窗特征提取。

#### 2. `fold(output_size, kernel_size, stride)`

- **核心作用**：`unfold` 的逆操作，将滑动窗口块还原回原始空间形状。
- **底层行为**：包含求和计算，不是纯元数据修改，会生成新张量。
- **典型场景**：特征重建、滑窗式卷积的反向操作。

---

## 二、组合式变形：元素总数变化，多张量合并/单张量拆分

这类操作通过合并多个张量、或拆分单个张量来改变形状，元素总数会发生变化，常用于特征融合、输出拆分、批量构建。

### （一）拼接与堆叠：多张量合并

#### 1. `cat(tensors, dim)` / `concat`

- **核心作用**：多个张量沿**已有的维度**拼接，维度总数不变。
- **前提条件**：除拼接维度外，其余所有维度的大小必须完全一致。
- **底层行为**：生成新的连续张量，有数据拷贝开销。
- **典型场景**：多分支特征融合，例如在通道维度拼接纹理特征与语义特征。

#### 2. `stack(tensors, dim)`

- **核心作用**：多个张量沿**新增的维度**堆叠，维度总数+1。
- **前提条件**：所有输入张量的形状必须完全一致。
- **底层行为**：生成新的连续张量，有数据拷贝开销。
- **典型场景**：将单张图片堆叠成批量、将多通道特征组合成多通道张量。

> 直观区别：两个 `[3, 4]` 的张量
>
> - `cat(dim=0)` → 形状 `[6, 4]`，维度数不变
> - `stack(dim=0)` → 形状 `[2, 3, 4]`，多了一个维度

---

### （二）拆分与截取：单张量拆分

#### 1. `split(tensor, split_size_or_sections, dim)`

- **核心作用**：沿指定维度拆分为多个子张量，可按固定大小拆分，也可按自定义比例分段拆分。
- **底层行为**：零拷贝，所有子张量都是原张量的视图。
- **输出连续性**：子张量可能非连续。
- **典型场景**：模型多输出头拆分，例如检测模型拆分分类分支与回归分支。

#### 2. `chunk(tensor, chunks, dim)`

- **核心作用**：沿指定维度平均拆分为 `chunks` 份，是 `split` 的简化版。
- **底层行为**：零拷贝视图。
- **典型场景**：特征平均拆分、多路径计算分流。

#### 3. `narrow(dim, start, length)`

- **核心作用**：沿指定维度截取一段连续的子张量。
- **底层行为**：零拷贝，仅修改起始偏移和维度大小。
- **输出连续性**：原张量连续则输出仍连续。
- **典型场景**：截取指定通道范围、截取时间序列片段。

#### 4. `select(dim, index)`

- **核心作用**：沿指定维度选取单个切片，维度数减1。
- **底层行为**：零拷贝视图。
- **典型场景**：取某一个通道、某一个样本的特征。

---

## 三、所有工具核心区别对照表

| 操作 | 核心作用 | 是否拷贝数据 | 输出是否连续 | 维度数变化 | 元素总数变化 | 核心限制 |
|------|----------|--------------|--------------|------------|--------------|----------|
| `view` | 重划分维度 | 绝对不拷贝 | 是 | 可变 | 不变 | 输入必须连续 |
| `reshape` | 通用重划分维度 | 可能拷贝 | 是 | 可变 | 不变 | 无 |
| `flatten` | 展平指定维度 | 可能拷贝 | 是 | 减少 | 不变 | 无 |
| `unsqueeze/squeeze` | 增/减单维度 | 不拷贝 | 是 | +1 / -1 | 不变 | squeeze只能删大小为1的维度 |
| `transpose/permute` | 调换维度顺序 | 不拷贝 | 否 | 不变 | 不变 | 无 |
| `expand` | 广播扩展单维度 | 不拷贝 | 否 | 不变 | 逻辑增加、物理不变 | 只能扩展大小为1的维度 |
| `repeat` | 复制式扩展 | 一定拷贝 | 是 | 不变 | 增加 | 无 |
| `cat` | 沿已有维度拼接 | 一定拷贝 | 是 | 不变 | 增加 | 非拼接维度必须一致 |
| `stack` | 沿新维度堆叠 | 一定拷贝 | 是 | +1 | 增加 | 所有输入形状必须一致 |
| `split/chunk` | 拆分为多个子张量 | 不拷贝 | 不一定 | 不变 | 拆分后总和不变 | 无 |
| `narrow/select` | 截取子张量 | 不拷贝 | 不一定 | select减1 | 减少 | 无 |

## 四、实战选型原则与端侧注意事项

### 1. 通用选型优先级

1. **优先零拷贝操作**：能通过 `view`、`transpose`、`permute`、`expand`、`split` 实现的，就不要用会触发拷贝的接口。
2. **连续场景用 `view`，通用场景用 `reshape`**：明确张量连续时用 `view` 保证零开销；写通用代码、不确定连续性时用 `reshape`。
3. **广播优先于复制**：能用 `expand` 实现的广播，绝对不要用 `repeat` 复制数据。

### 2. 端侧推理场景特殊注意

端侧设备内存带宽有限、硬件加速对连续性要求高，形状操作的选择直接影响推理速度：

- **维度重排尽量固化在模型内**：`permute`、`transpose` 这类操作，能在模型转换阶段（ONNX/TFLite/NCNN转换）固化到计算图里的，就不要在端侧应用层每次推理都执行，避免推理中产生隐式拷贝。
- **避免推理循环内隐式拷贝**：非连续张量调用 `reshape`、`cat` 等操作会触发内存拷贝，造成卡顿；尽量在初始化阶段一次性完成形状对齐。
- **硬件算子要求连续输入**：NPU、GPU的卷积、矩阵乘算子，几乎都要求输入张量内存连续；非连续张量输入会触发框架隐式 `contiguous()`，增加不可控延迟。
- **小操作合并成大操作**：零散的多次形状调整，合并成一次 `reshape` 或 `permute`，减少元数据修改和内存跳转次数。

---

## 常见误区澄清

1. **“改形状就一定会拷贝数据”**：错。`view`、`transpose`、`permute`、`expand`、`split` 等都是纯元数据修改，零拷贝。
2. **`reshape` 比 `view` 慢**：不一定。输入连续时二者完全等价，零开销；只有非连续时 `reshape` 才会多拷贝开销。
3. **`expand` 和 `repeat` 效果一样**：逻辑效果相似，但底层完全不同；`expand` 零拷贝省内存，`repeat` 真复制占内存。
4. **`cat` 和 `stack` 差不多**：`cat` 不增加维度数，`stack` 会新增一个维度，输出形状差异很大。
