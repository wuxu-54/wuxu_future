# Agent 项目标准结构与识别扫描机制完全指南

在开发生成式 AI 应用时，我们经常需要让 Agent 理解项目结构、调用预定义技能、遵循团队规范。一套**标准化的目录结构与自动发现机制**，能让 Agent 无需人工配置就能“看懂”项目。本文将从零开始，完整讲解 Agent 项目的标准目录结构、各文件的作用，以及 Agent 如何自动扫描、识别并加载这些内容。

---

## 一、为什么需要标准目录结构？

在没有标准之前，每个 Agent 框架或工具都有自己独特的配置方式：有的用 `config.yaml`，有的用 `agent.json`，有的把提示词直接写在代码里。这导致：

- **难以跨工具复用**：从 LangChain 换到 Claude Code，所有配置要重写。
- **团队协作混乱**：不同成员使用不同工具，项目规范无法统一。
- **上下文浪费**：每个 Agent 都需要加载大量无关信息。

因此，社区逐渐形成了以 **`AGENTS.md`** 和 **`SKILL.md`** 为核心的标准化目录规范。这些规范遵循 **渐进式披露** 原则，让 Agent 只在必要时加载详细信息，极大地节约了上下文 tokens。

---

## 二、标准目录结构与文件说明

一个遵循当前主流规范的项目目录通常包含以下内容：

```
your-project/
├── AGENTS.md                      # 项目级 AI 指令（总纲）
├── .agents/                       # 跨工具通用标准目录
│   ├── AGENTS.md                  # 可选的补充指令
│   └── skills/                    # 规范级技能存放处
│       └── skill-name/
│           └── SKILL.md
├── .claude/                       # Claude Code 专用目录
│   ├── CLAUDE.md                  # Claude 项目指令
│   ├── settings.json              # Claude 项目设置
│   └── skills/                    # Claude 专用技能
├── .deepagents/                   # LangChain Deep Agents 专用
│   ├── AGENTS.md
│   ├── agents/                    # 自定义子代理
│   └── skills/
└── .kimi/                         # Kimi Code 专用目录（类似结构）
```

### 2.1 根目录 `AGENTS.md`（最基础）

`AGENTS.md` 是一个 Markdown 文件，专门为 AI 智能体提供**项目级别的工作指南**。它告诉 Agent：

- 项目的安装、构建、测试命令
- 代码风格与命名规范
- PR 流程与 commit 信息格式
- 特殊依赖或安全注意事项

示例：

```markdown
# Project Instructions for AI Agents

## Build & Test
- Install: `pip install -e .`
- Run tests: `pytest tests/`
- Lint: `ruff check .`

## Code Style
- Use black formatter
- Maximum line length: 88

## Important
- Never commit secrets to repo
- Always update CHANGELOG.md on release
```

> `AGENTS.md` 的设计目标是**跨工具通用**。OpenAI 已将其开源为一种标准格式，并被 Claude Code、Kimi Code 等多种工具支持。

### 2.2 `.agents/` – 跨工具通用标准目录

`.agents/` 目录由 **Agentic AI 基金会 / Linux 基金会** 推动，旨在成为 AI Agent 的“`.editorconfig`”。任何支持该标准的工具都会自动读取此目录下的配置。

- **位置**：项目级（`./.agents/`）或用户级（`~/.agents/`）
- **内容**：可以包含 `AGENTS.md`、`skills/` 子目录等。
- **优势**：一次配置，多工具共享。例如，你在 `.agents/skills/pdf-skill/SKILL.md` 中定义了一个 PDF 处理技能，那么 Claude Code、Kimi Code、Continue 等都可以直接使用。

### 2.3 `.claude/` – Claude Code 专用目录

由 Anthropic 为其 AI 编程工具 Claude Code 定义。如果你只使用 Claude Code，可以用这个目录获得更深入集成。

- **主要文件**：
  - `CLAUDE.md`：同 `AGENTS.md`，但仅对 Claude Code 生效。
  - `settings.json`：项目级设置，`settings.local.json` 用于本地覆盖（通常加入 `.gitignore`）。
  - `skills/`：存放 Claude 专用技能。
  - `agents/`：定义子代理。

### 2.4 `.deepagents/` – LangChain Deep Agents 专用

LangChain 框架为 Deep Agents 组件定义的数据目录，支持自定义子代理和技能。

### 2.5 `skills/` – 规范级技能（核心扩展能力）

`skills/` 目录下存放一个个独立的 **Skill 文件夹**，每个文件夹必须包含一个 `SKILL.md` 文件。Skill 是对 AI 可复用能力单元的封装，例如“代码审查”、“PDF 表单填写”、“SQL 查询”等。

**`SKILL.md` 的结构：**

```markdown
---
name: code-review-skill
description: 智能代码审查，检查 bug、安全漏洞、性能、风格，返回结构化问题列表。
inputs:
  - name: code
    type: string
    required: true
  - name: language
    type: string
    enum: [python, javascript, java, go]
---

# 执行流程
1. 接收 code 和 language
2. 调用 scripts/review.py 进行分析
3. 返回 JSON 格式结果
...
```

- **YAML 前置元数据**：约 100-200 tokens，包含 `name`、`description`、`inputs` 等。这部分会在 Agent 启动时被加载到系统提示中，用于**技能匹配**。
- **Markdown 正文**：详细的工作流程、输入输出示例、错误处理等，建议控制在 5000 token 以内。只在技能被触发时加载。
- **关联资源**：如 `scripts/` 中的可执行脚本、`references/` 中的参考文档，按需加载。

这种设计就是 **渐进式披露**：Agent 首先知道有哪些技能可用，只有确定需要某个技能时才读取完整内容，极大地节约了上下文。

## 三、Agent 如何识别这些内容？—— 扫描与加载机制

Agent 并不会“看到”文件夹图标，而是通过**文件系统扫描 + 优先级规则**来自动发现并加载配置。整个过程无需你手动编写代码，是开箱即用的。

### 3.1 扫描的路径规则（优先级由低到高）

Agent 在启动时，会按照以下顺序扫描一系列预定义的目录。**优先级高的目录会覆盖优先级低的同名配置**。

| 优先级 | 级别 | 目录示例 | 说明 |
|--------|------|----------|------|
| 最低 | **内置** | 随 Agent 软件包安装的 `skills/` | 官方提供的基础技能，如通用计算器、网络搜索。 |
| 中 | **用户级** | `~/.agents/skills/`<br>`~/.claude/skills/`<br>`~/.kimi/skills/` | 放在用户主目录下，对所有项目**全局生效**。你可以在这里放个人常用技能。 |
| 最高 | **项目级** | `./.agents/skills/`<br>`./.claude/skills/`<br>`./.deepagents/skills/`<br>`./skills/` | 仅在当前项目内生效，适合存放项目专属技能。项目级配置会覆盖用户级和内置级。 |

#### 品牌组 vs 通用组

在同一级别内（如项目级），Agent 会扫描**多个品牌目录**（如 `.claude/skills/`、`.kimi/skills/`、`.codex/skills/`）以及**通用目录**（`.agents/skills/`）。通常情况下，**品牌组的优先级高于通用组**，因为特定工具的配置往往更具体。

> 有些 Agent 支持通过配置项 `merge_all_available_skills = true` 来**合并所有品牌目录**中的技能，而不是按优先级覆盖。

### 3.2 文件的发现与加载过程（以 `SKILL.md` 为例）

1. **启动扫描**：当你启动 Agent（例如进入项目目录运行 `kimi`），它会立即按照上述优先级顺序遍历所有可能的技能目录。
2. **定位 `SKILL.md`**：在每个技能子文件夹中，Agent 寻找 `SKILL.md` 文件。
3. **解析元数据（YAML Frontmatter）**：Agent 读取文件开头的 `---` 包裹的部分，提取 `name`、`description`、`inputs` 等字段。这些信息被添加到系统提示词中，形成一张“可用技能清单”。此时**不会**加载完整的 Markdown 正文。
4. **注册工具**：Agent 将每个技能封装成一个可调用的“元工具”，工具名就是 `name`，描述就是 `description`。
5. **按需加载正文**：当用户发出请求（例如“帮我审查这段代码”），LLM 根据技能清单判断需要调用哪个技能。一旦决定使用某个技能，Agent 才会去读取对应 `SKILL.md` 的 Markdown 正文，并将其作为执行指引注入上下文。
6. **执行脚本与资源**：如果技能需要运行外部脚本（如 `scripts/review.py`）或读取参考文档，Agent 会在执行工具调用时按需启动子进程或读取文件。

对于 `AGENTS.md` 的加载则更简单：Agent 直接读取文件内容作为系统提示的一部分（或作为项目背景知识），不会分阶段加载。

### 3.3 文件命名与特殊覆盖

- **`AGENTS.override.md`**：某些工具支持优先级更高的覆盖文件。例如，你可以创建一个 `AGENTS.override.md`，它的内容会完全取代 `AGENTS.md`，方便临时调整指令而不修改原文件。
- **`CLAUDE.md` / `KIMI.md`**：品牌专用指令文件，仅被对应工具识别。如果同时存在 `AGENTS.md` 和 `CLAUDE.md`，Claude Code 会优先使用 `CLAUDE.md`。

## 四、四种配置方式对比

虽然 Agent 默认会自动扫描上述目录，但为了满足不同场景的需求，业界提供了多种方式来**定制扫描行为**。

| 方式 | 工作原理 | 使用场景 | 是否需要手动编码 |
|------|----------|----------|------------------|
| **1. 自动扫描默认路径** | Agent 启动时自动扫描内置、用户级、项目级的标准目录。 | 绝大多数日常开发，零配置开箱即用。 | 否 |
| **2. 代码显式指定** | 在自定义 Agent 代码中，通过参数传入技能目录列表。 | 使用 LangChain 等框架开发定制 Agent 时，指定额外的技能路径。 | 是 |
| **3. 命令行参数/环境变量** | 启动 Agent 时添加 `--skills-dir` 参数或设置 `AGENT_SKILLS_PATH` 环境变量。 | 临时测试某个新技能，或者在不修改代码的情况下覆盖默认目录。 | 否（但需要输入命令） |
| **4. 配置文件调整** | 修改 Agent 的配置文件（如 `config.toml`、`settings.json`）来改变扫描行为。 | 希望永久修改优先级规则、启用合并所有品牌目录、自定义根目录等。 | 否（编辑配置文件） |

**代码显式指定示例（LangChain）**：

```python
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="gpt-4o",
    skills=["./my-skills", "/shared/team-skills"]   # 显式指定技能目录
)
```

**命令行示例（Kimi Code）**：

```bash
kimi --skills-dir ./experimental-skills --skills-dir /tmp/test-skills
```

**配置文件示例（部分 Agent 支持）**：

```toml
# config.toml
[agent]
merge_all_available_skills = true
skills_dirs = ["~/.custom-skills", "./project-skills"]
```

## 五、实践建议与最佳实践

1. **从根目录 `AGENTS.md` 开始**：这是让 Agent 快速理解项目的最简单方式。写出清晰、结构化的指令（如构建命令、代码规范），避免冗长的人类叙述。
2. **按需引入 `skills/`**：当发现某些任务重复性高（如代码审查、数据库查询、文档生成），将其封装为 Skill，放到 `.agents/skills/` 下，实现跨工具复用。
3. **合理设计 `SKILL.md`**：
   - 在 YAML 元数据中提供精确的 `description`，帮助 LLM 准确匹配。
   - Markdown 正文控制在 5000 token 以内，复杂细节放 `references/`。
   - 提供清晰的输入输出示例和错误处理说明。
4. **利用优先级测试配置**：使用命令行参数临时添加技能目录，验证效果后再决定是否将其永久加入项目或用户级目录。
5. **版本控制**：将项目级的 `AGENTS.md` 和 `.agents/skills/` 提交到 Git，团队共享。用户级和个人测试目录加入 `.gitignore`。

## 六、总结

Agent 项目的标准目录结构并非强制标准，而是社区演化出的最佳实践。其核心价值在于：

- **统一认知**：无论你使用 Claude Code、Kimi Code 还是自研 Agent，`AGENTS.md` 和 `SKILL.md` 都能被理解。
- **渐进式披露**：通过元数据常驻、正文按需加载，高效利用有限的上下文窗口。
- **自动发现**：Agent 启动时按照**内置 < 用户级 < 项目级**的优先级自动扫描预设目录，无需手动配置即可加载技能和指令。

理解这一套机制后，你就可以轻松地为任何项目配置 AI 友好的工作环境，并开发出可复用的规范级技能。开始动手试试吧——在你的项目根目录创建一个 `AGENTS.md`，然后启动你的 Agent，看看它会如何响应。
