# LangChain如何定义工具

在LangChain中，工具（Tools）是连接大语言模型与外部世界的桥梁，使AI能够执行计算、查询数据库、调用API等操作。LangChain提供了多种灵活的工具定义方式，适用于不同场景和需求。

## 一、工具定义的核心概念

### 1.1 什么是工具（Tool）

工具是一个**可被大语言模型调用的函数**，具有以下特征：

- **明确的功能描述**：告诉模型这个工具能做什么
- **结构化的输入参数**：定义工具需要哪些参数以及参数类型
- **确定的返回值**：工具执行后的输出结果

### 1.2 工具的工作原理

```
用户问题 → 大模型思考 → 选择合适的工具 → 调用工具 → 获取结果 → 生成最终回答
```

大模型会根据用户的问题和可用工具的描述，自动决定是否需要调用工具以及调用哪个工具。

## 二、工具定义的四种主要方法

### 2.1 使用@tool装饰器（推荐方式）

这是最简单、最常用的工具定义方法，适用于大多数场景。

```python
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """将两个整数相乘"""
    return a * b

@tool
def get_weather(city: str) -> str:
    """获取指定城市的天气信息"""
    # 实际实现中会调用天气API
    return f"{city}今天晴天，气温20-25度"
```

**优点**：

- 语法简洁，易于理解
- 自动从函数签名和文档字符串提取参数信息
- 支持类型注解，提高参数准确性

### 2.2 使用Pydantic模型定义复杂参数

当工具需要复杂的参数结构时，使用Pydantic模型可以提供更好的类型安全和验证。

```python
from langchain_core.tools import tool
from pydantic import BaseModel, Field

class SearchInput(BaseModel):
    """搜索工具的输入参数"""
    query: str = Field(..., description="搜索关键词")
    max_results: int = Field(5, description="最大返回结果数量", ge=1, le=20)

@tool(args_schema=SearchInput)
def web_search(query: str, max_results: int = 5) -> str:
    """在互联网上搜索相关信息"""
    # 实际实现中会调用搜索引擎API
    return f"搜索'{query}'的结果：[模拟搜索结果...]"
```

**优点**：

- 参数验证严格，避免无效输入
- 支持复杂的嵌套数据结构
- 自动生成详细的工具描述

### 2.3 直接继承BaseTool类

对于需要更多控制权的高级场景，可以直接继承`BaseTool`类。

```python
from langchain_core.tools import BaseTool
from typing import Optional, Type
from pydantic import BaseModel, Field

class CalculatorInput(BaseModel):
    expression: str = Field(..., description="数学表达式，如'2+3*4'")

class CalculatorTool(BaseTool):
    name = "calculator"
    description = "安全的计算器工具，支持基本数学运算"
    args_schema: Type[BaseModel] = CalculatorInput
    
    def _run(self, expression: str) -> str:
        """执行计算"""
        try:
            # 安全的表达式求值
            result = eval(expression, {"__builtins__": {}}, {})
            return str(result)
        except Exception as e:
            return f"计算错误: {str(e)}"
    
    async def _arun(self, expression: str) -> str:
        """异步执行计算"""
        return self._run(expression)

# 创建工具实例
calculator = CalculatorTool()
```

**适用场景**：

- 需要自定义工具的元数据（name、description）
- 需要实现同步和异步两种调用方式
- 需要复杂的错误处理逻辑

### 2.4 使用StructuredTool创建工具

`StructuredTool`提供了更灵活的工具创建方式，适合动态创建工具。

```python
from langchain_core.tools import StructuredTool
from pydantic import BaseModel, Field

class EmailInput(BaseModel):
    to: str = Field(..., description="收件人邮箱地址")
    subject: str = Field(..., description="邮件主题")
    body: str = Field(..., description="邮件正文")

def send_email(to: str, subject: str, body: str) -> str:
    """发送邮件"""
    # 实际实现中会调用邮件服务
    return f"邮件已发送至{to}，主题：{subject}"

# 创建结构化工具
email_tool = StructuredTool.from_function(
    func=send_email,
    name="send_email",
    description="发送电子邮件",
    args_schema=EmailInput,
    return_direct=False  # False表示结果需要经过LLM处理后返回给用户
)
```

## 三、工具绑定与使用

### 3.1 绑定工具到模型

定义好工具后，需要将其绑定到大模型才能使用。

```python
from langchain_openai import ChatOpenAI

# 初始化模型
model = ChatOpenAI(model="gpt-4o")

# 绑定单个工具
model_with_calculator = model.bind_tools([calculator])

# 绑定多个工具
tools = [multiply, get_weather, web_search, email_tool]
model_with_tools = model.bind_tools(tools)
```

### 3.2 强制工具调用

有时需要强制模型调用特定工具，而不是让它自主选择。

```python
# 强制调用特定工具
model_force_weather = model.bind_tools(
    [get_weather],
    tool_choice={"type": "function", "function": {"name": "get_weather"}}
)

# 强制调用任意工具（但必须调用）
model_must_use_tool = model.bind_tools(
    tools,
    tool_choice="any"
)
```

### 3.3 在Agent中使用工具

在智能体（Agent）中使用工具是最常见的应用场景。

```python
from langgraph.prebuilt import create_react_agent
from langgraph.checkpoint.memory import MemorySaver

# 创建记忆
memory = MemorySaver()

# 创建ReAct Agent
agent = create_react_agent(
    model,
    tools,
    checkpointer=memory
)

# 运行Agent
config = {"configurable": {"thread_id": "1"}}
result = agent.invoke(
    {"messages": [("human", "北京明天的天气怎么样？如果下雨就发邮件提醒我")]},
    config=config
)
```

## 四、工具定义的最佳实践

### 4.1 安全性考虑

工具调用涉及外部系统访问，必须注意安全性：

```python
class SafeFileReaderTool(BaseTool):
    name = "safe_file_reader"
    description = "安全的文件读取工具，仅允许读取指定目录下的文件"
    
    def _run(self, filename: str) -> str:
        # 安全检查：限制文件路径
        allowed_directory = "/safe/documents/"
        if not filename.startswith(allowed_directory):
            return "不允许访问该文件"
        
        # 安全检查：限制文件类型
        if not filename.endswith(('.txt', '.md', '.pdf')):
            return "不支持的文件类型"
        
        try:
            with open(filename, 'r', encoding='utf-8') as f:
                return f.read()
        except Exception as e:
            return f"文件读取错误: {str(e)}"
```

### 4.2 错误处理

良好的错误处理能提高工具的可靠性：

```python
import requests
from langchain_core.tools import tool

@tool
def get_stock_price(symbol: str) -> str:
    """获取股票价格"""
    try:
        response = requests.get(f"https://api.example.com/stock/{symbol}")
        response.raise_for_status()
        data = response.json()
        return f"{symbol}当前价格: ${data['price']}"
    except requests.exceptions.RequestException as e:
        return f"网络请求失败: {str(e)}"
    except KeyError:
        return f"未找到股票代码: {symbol}"
    except Exception as e:
        return f"未知错误: {str(e)}"
```

### 4.3 性能优化

对于耗时的工具操作，考虑异步实现：

```python
import asyncio
from langchain_core.tools import BaseTool

class AsyncAPITool(BaseTool):
    name = "async_api_call"
    description = "异步调用外部API"
    
    async def _arun(self, endpoint: str) -> str:
        """异步执行API调用"""
        try:
            async with aiohttp.ClientSession() as session:
                async with session.get(endpoint) as response:
                    return await response.text()
        except Exception as e:
            return f"API调用失败: {str(e)}"
    
    def _run(self, endpoint: str) -> str:
        """同步版本，内部调用异步版本"""
        return asyncio.run(self._arun(endpoint))
```

## 五、高级工具模式

### 5.1 工具检索（Tool Retrieval）

当工具有很多个时（>50个），使用工具检索来提高效率：

```python
from langchain_community.embeddings import OpenAIEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_core.tools import Tool

# 创建工具列表
all_tools = [tool1, tool2, tool3, ...]  # 假设有100个工具

# 为工具创建向量索引
tool_descriptions = [f"{tool.name}: {tool.description}" for tool in all_tools]
embeddings = OpenAIEmbeddings()
vectorstore = FAISS.from_texts(tool_descriptions, embeddings)

def retrieve_relevant_tools(query: str, k: int = 5):
    """检索与查询最相关的工具"""
    relevant_docs = vectorstore.similarity_search(query, k=k)
    # 根据文档内容找到对应的工具
    relevant_tool_names = [doc.page_content.split(':')[0] for doc in relevant_docs]
    return [tool for tool in all_tools if tool.name in relevant_tool_names]

# 使用检索到的工具
relevant_tools = retrieve_relevant_tools("天气查询")
agent = create_react_agent(model, relevant_tools)
```

### 5.2 并行工具调用

让模型同时调用多个独立的工具：

```python
# LangChain会自动处理并行工具调用
# 当模型生成多个工具调用时，LangGraph会并行执行它们

result = agent.invoke(
    {"messages": [("human", "同时查询北京和上海的天气")]},
    config=config
)
# 模型可能会同时调用两次get_weather工具，LangGraph会并行执行
```

### 5.3 工具链规划

复杂任务需要多个工具按顺序调用：

```python
# LangChain的Agent会自动进行工具链规划
# 例如："先查天气，然后根据天气推荐衣服"

result = agent.invoke(
    {"messages": [("human", "查一下北京明天的天气，然后推荐合适的衣服")]},
    config=config
)
# Agent会先调用get_weather，然后调用recommend_clothes
```

## 六、MCP协议集成（2026年新特性）

MCP（Model Context Protocol）是新兴的标准协议，LangChain提供了原生支持：

```python
from langchain_mcp import MCPClient

# 创建MCP客户端
mcp_client = MCPClient(
    endpoint="https://mcp.example.com",
    api_key="your-mcp-key"
)

# 获取MCP工具
mcp_tools = mcp_client.get_tools()

# 在Agent中使用MCP工具
agent = create_react_agent(model, mcp_tools)
```

MCP的优势：

- **跨平台兼容**：支持所有主流AI应用
- **标准化**：统一的工具调用协议
- **安全性**：内置权限控制和用户确认机制

## 七、调试与监控

### 7.1 工具调用日志

记录工具调用过程以便调试：

```python
def log_tool_call(tool_name: str, args: dict, result: str):
    """记录工具调用日志"""
    print(f"工具调用: {tool_name}")
    print(f"参数: {args}")
    print(f"结果: {result}")

# 在工具中添加日志
@tool
def logged_multiply(a: int, b: int) -> int:
    """带日志的乘法工具"""
    result = a * b
    log_tool_call("multiply", {"a": a, "b": b}, str(result))
    return result
```

## 八、常见问题与解决方案

### 8.1 参数幻觉问题

**问题**：模型生成不存在的参数或错误的参数值

**解决方案**：

- 使用Pydantic模型进行严格的参数验证
- 在工具描述中明确说明参数格式和约束
- 添加参数校验逻辑

### 8.2 工具选择错误

**问题**：模型选择了不相关的工具

**解决方案**：

- 优化工具描述，使其更加准确和具体
- 添加少样本示例到系统提示词
- 使用工具检索技术

### 8.3 无限循环问题

**问题**：Agent反复调用同一个工具

**解决方案**：

- 设置最大迭代次数
- 在Agent配置中启用循环检测
- 实现工具状态跟踪

```python
# 设置最大步骤数
agent = create_react_agent(
    model,
    tools,
    max_iterations=10  # 最多执行10步
)
```

## 九、总结

LangChain提供了丰富而灵活的工具定义方式，从简单的装饰器到复杂的自定义类，满足不同场景的需求。选择合适的工具定义方法需要考虑以下因素：

- **简单性**：对于简单工具，使用`@tool`装饰器
- **复杂性**：对于复杂参数，使用Pydantic模型
- **控制权**：对于需要精细控制的场景，继承`BaseTool`
- **动态性**：对于运行时动态创建的工具，使用`StructuredTool`

记住，好的工具设计应该遵循以下原则：

1. **单一职责**：每个工具只做一件事
2. **安全第一**：始终考虑安全性和权限控制
3. **错误处理**：提供清晰的错误信息
4. **性能优化**：考虑异步和缓存策略
5. **可观测性**：便于调试和监控

通过合理定义和使用工具，你可以构建出功能强大、安全可靠的AI应用。
