# 模型量化：原理、方法与工程实践

量化是模型部署中最常用、最有效的压缩技术之一。它通过降低模型权重和/或激活值的数值精度，换取更小的存储体积、更少的内存带宽、更快的计算速度，同时尽量保持模型精度。

下面从**原理**、**类型**、**方法**、**工具**、精度损失与调试、**实战建议**六个方面详细展开。

---

## 一、量化原理

### 1.1 为什么可以用低精度表示？

深度学习模型的权重和激活值通常分布在有限的数值范围内，且对微小的噪声具有一定鲁棒性（ “抗干扰能力” 或 “容错能力”）。例如，一个 FP32 的权重 `0.23567812` 可能截断为 INT8 的 `60`（对应反量化后 `0.235294`），误差仅为 0.16%，对最终输出影响很小。

### 1.2 映射公式

量化的核心是将浮点数 \( x \) 映射到低精度整数 \( q \)：

**仿射量化（Affine Quantization，有零点）**：
\[
q = \text{round}\left(\frac{x}{\text{scale}} + \text{zero\_point}\right)
\]
反量化：
\[
x_{\text{dequant}} = (q - \text{zero\_point}) \times \text{scale}
\]

**对称量化（Symmetric Quantization，零点为 0）**：
\[
q = \text{round}\left(\frac{x}{\text{scale}}\right), \quad \text{scale} = \frac{\max(|x|)}{2^{b-1}-1}
\]
对称量化计算更简单，常用于权重量化。

其中 \( b \) 为量化位数（如 8、4），`scale` 是浮点缩放因子，`zero_point` 是整数零点（用于对齐非对称分布）。

## 二、量化的类型

| 分类维度 | 类型 | 说明 |
|----------|------|------|
| **按精度** | FP16、INT8、INT4、INT2、NF4 | FP16 本质是半精度浮点，也常归为量化；INT4/INT2 用于极致压缩 |
| **按对象** | 权重量化 (Weight-only) | 只量化模型权重，激活保持 FP16，适合大模型推理 |
| | 激活量化 (Activation quantization) | 同时量化权重和激活值，可实现整数运算（如 INT8 全整推理） |
| **按数据范围** | 对称量化 | 零点为 0，适用于近似正态分布的数据 |
| | 非对称量化 | 包含零点，适用于分布严重偏移（如 ReLU 后的激活值） |
| **按粒度** | 逐张量 (Per-tensor) | 整个张量共享一个 scale 和 zero_point |
| | 逐通道 (Per-channel) | 每个卷积输出通道独立 scale，精度更高，常用于权重量化 |
| | 逐组 (Per-group) | 将通道分组，每组独立参数（如 GPTQ 的 group size=128） |
| **按时机** | 训练后量化 (PTQ) | 不重新训练，仅用少量校准数据确定量化参数 |
| | 量化感知训练 (QAT) | 在训练/微调中模拟量化操作，使模型适应低精度 |

## 三、常用量化方法与算法

### 3.1 训练后量化（PTQ）

**优点**：无需训练数据（或只需少量校准集），速度快。  
**缺点**：大模型（>10B）或低精度（<INT8）时精度下降可能明显。

- **MinMax**：直接使用校准数据中每个张量的最小值/最大值作为量化边界。简单但对离群点敏感。
- **MSE (Mean Squared Error)**：搜索最优 scale，使量化前后的均方误差最小。
- **Percentile**：截断一定比例的离群值（例如选择 99.99% 的绝对值最大值），提升精度。
- **KL 散度**（TensorRT 所用）：最小化量化前后的概率分布差异。

### 3.2 量化感知训练（QAT）

在训练过程中插入伪量化节点（模拟 round+clamp），使梯度能适应低精度表示。  
**优点**：精度通常优于 PTQ，尤其是在低位宽（INT4）时。  
**缺点**：需要完整训练数据和时间。

**流程**：  
正常训练 → 插入 QAT 模块 → 微调几轮 → 导出真实量化模型。

### 3.3 面向大模型的先进量化算法

大模型（LLM）的激活值常存在**离群特征**（某些通道值远大于其他），传统量化方法失效。以下算法专门针对 LLM 设计：

| 算法 | 核心思想 | 精度 | 是否需要训练 |
|------|----------|------|--------------|
| **GPTQ** | 基于 Hessian 矩阵的逐层最优舍入，补偿量化误差 | INT4 损失 < 1% | 否（需少量校准数据） |
| **AWQ** | 保护 1% 的重要权重不减量，其他量化 | INT4 优于 GPTQ | 否 |
| **SmoothQuant** | 将激活值的难度转移到权重，使两者都易于量化 | INT8 无损 | 否 |
| **LLM.int8()** | 对离群特征使用 FP16，其他使用 INT8 | 几乎无损 | 否 |
| **QLoRA** | 4-bit 正态浮点 (NF4) 存储 + 双重量化，用于微调 | 接近 BF16 | 是（微调） |

## 四、量化工具与框架

| 工具 | 支持的量化方法 | 适用模型 | 输出格式 | 特点 |
|------|----------------|----------|----------|------|
| **PyTorch 原生** | PTQ (per-tensor/per-channel)、QAT | CNN、Transformer | `torch.quantized` | 集成方便，但大模型支持有限 |
| **TensorRT** | PTQ (INT8/FP8)、稀疏量化 | 通用 | `.engine` | 业界最佳性能，需要校准数据集 |
| **ONNX Runtime** | INT8 (Qlinear) | 通用 | ONNX + 量化属性 | 跨后端，支持多种量化算子 |
| **Intel Neural Compressor** | PTQ、QAT、混合精度 | 通用 | ONNX/OpenVINO | 自动调优量化参数 |
| **GPTQ (AutoGPTQ)** | 权重量化 INT2/3/4/8 | LLM (LLaMA、OPT 等) | 量化后模型文件 | 主流大模型量化工具 |
| **AWQ (llm-awq)** | 权重量化 INT4 | LLM | 量化权重 + scale | 精度高，推理速度快 |
| **llama.cpp** | GGUF 格式（2~8 bit） | LLM (LLaMA 系列) | `.gguf` | CPU 推理，内存占用极低 |
| **HuggingFace bitsandbytes** | 8-bit、4-bit (NF4) | 任意 HF 模型 | 模型对象 | 加载时自动量化，易用 |

## 五、精度损失与调试

### 5.1 常见损失原因

- **离群值**：少数极大或极小的值拉大量化范围，大部分值的分辨率下降。
- **分布不匹配**：校准集与真实数据分布差异大。
- **低位宽（INT4）**：表示精度太低，梯度近似误差累积。
- **逐张量量化**：通道间差异大时，局部误差放大。

### 5.2 评估方法

| 指标 | 适用场景 | 计算方式 |
|------|----------|----------|
| **逐层误差** | 定位哪一层量化后误差最大 | 量化后输出与 FP 输出的 MSE 或余弦相似度 |
| **最终任务精度** | 分类准确率、BLEU、EM | 下游任务评估（必须做） |
| **校准集困惑度** | 语言模型 | PPL 变化 < 5% 通常可接受 |

### 5.3 改进策略

- **换用 Per-channel 量化**：尤其对卷积层权重大有益处。
- **调整校准集**：覆盖更多边界情况。
- **尝试不同的截断方法**：MinMax → MSE → Percentile (99.9%)。
- **混合精度**：对敏感层（如 embedding、输出层）保持 FP16，其他层量化。
- **使用更先进的算法**：从简单 PTQ 升级到 GPTQ/AWQ。

## 六、实战建议与决策表

| 场景 | 推荐量化方案 | 预期精度损失 | 部署引擎 |
|------|--------------|--------------|----------|
| **云端 CNN（ResNet50）** | INT8 PTQ (MSE) | <0.5% | TensorRT / ONNX Runtime |
| **云端 BERT 分类** | INT8 QAT | <0.3% | ONNX Runtime / TensorRT |
| **云端 LLM 7B（高吞吐）** | INT4 GPTQ / AWQ | 1~2% | vLLM + GPTQ 后端 / TensorRT-LLM |
| **云端 LLM 70B（显存受限）** | INT4 GPTQ + group size 128 | 2~3% | vLLM / LMDeploy |
| **手机端视觉模型** | INT8 PTQ (per-channel) | <1% | TFLite / NCNN |
| **手机端 LLM 1-3B** | INT4 (GGUF) 或 NF4 | 1~2% | MNN / ExecuTorch / llama.cpp |
| **CPU 推理 LLM** | INT4 GGUF (Q4_K_M) | 1~3% | llama.cpp |
| **极致显存优化（仅推理）** | INT2 / 3 权重量化 | 5~10% | 实验性质，不建议生产 |

## 七、一个完整的量化流程示例（PyTorch + GPTQ 量化 LLM）

```python
# 1. 安装 auto-gptq
# pip install auto-gptq

from transformers import AutoModelForCausalLM, AutoTokenizer
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig

# 2. 加载 FP16 模型
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-chat-hf", torch_dtype=torch.float16)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-chat-hf")

# 3. 准备校准数据（可选，GPTQ 对数据不敏感）
calib_texts = ["Hello, how are you?", "What is deep learning?"] * 100

# 4. 配置量化
quantize_config = BaseQuantizeConfig(
    bits=4,                   # 4-bit
    group_size=128,           # 每组 128 个权重共享 scale
    desc_act=False,           # 是否按行顺序处理（True 稍慢但精度高）
)

# 5. 执行量化
model = AutoGPTQForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-chat-hf",
    quantize_config=quantize_config,
    use_cuda_fp16=True,
)
model.quantize(calib_texts)

# 6. 保存量化模型
model.save_quantized("llama-7b-4bit-gptq")

# 7. 推理时加载
quantized_model = AutoGPTQForCausalLM.from_quantized("llama-7b-4bit-gptq", device="cuda:0")
```

## 八、总结

量化是模型部署中性价比最高的优化手段。对于大多数模型：

- **优先尝试 INT8 PTQ**：快速见效，精度损失极小。
- **大模型（>7B）首选 INT4 GPTQ/AWQ**：单卡可部署，精度损失可控。
- **极致性能或 INT4 仍显存不足**：考虑 INT2/3 或混合精度，需充分验证任务指标。
- **移动端/嵌入式**：INT8 TFLite 或 MNN 是最成熟的选择。

**记住一个原则**：量化不是“免费午餐”，务必在目标任务上评估精度损失，并用真实数据校准。
