# LangGraph Memory

## 核心概念

在LangGraph中，**记忆（Memory）** 是通过 **Checkpointer（检查点）** 机制实现的，它负责状态的持久化存储，支持多轮会话、中断恢复和时间旅行等高级功能。与传统LangChain的记忆不同，LangGraph的记忆是**基于状态图的状态持久化**，而非简单的对话历史存储。

## 记忆类型与适用场景

| 记忆类型 | 类名 | 存储位置 | 适用场景 | 特点 |
|---------|------|----------|----------|------|
| 内存记忆 | `MemorySaver` | 内存 | 开发调试、短会话测试 | 快速、简单，重启后数据丢失 |
| SQLite记忆 | `SqliteSaver` | 本地SQLite文件 | 本地开发、小型应用 | 持久化、无需额外服务 |
| Redis记忆 | `RedisSaver` | Redis服务器 | 生产环境、分布式部署 | 高性能、支持集群 |
| PostgreSQL记忆 | `PostgresSaver` | PostgreSQL数据库 | 企业级应用、高可靠性要求 | ACID事务、成熟稳定 |

## 核心API详解

### 1. Checkpointer基础配置

```python
from langgraph.checkpoint.memory import MemorySaver
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.checkpoint.redis import RedisSaver

# 内存记忆（开发调试）
memory = MemorySaver()

# SQLite记忆（本地持久化）
sqlite_memory = SqliteSaver.from_conn_string("checkpoints.db")

# Redis记忆（生产环境）
redis_memory = RedisSaver.from_conn_info(host="localhost", port=6379)
```

### 2. 在StateGraph中集成记忆

```python
from langgraph.graph import StateGraph, MessagesState
from langgraph.checkpoint.memory import MemorySaver

# 定义状态图
graph_builder = StateGraph(MessagesState)

# 添加节点和边...
# graph_builder.add_node(...)
# graph_builder.add_edge(...)

# 编译图时传入checkpointer
memory = MemorySaver()
app = graph_builder.compile(checkpointer=memory)
```

### 3. 会话配置与调用

```python
# 配置会话ID（thread_id）
config = {"configurable": {"thread_id": "user_123_session_456"}}

# 调用带记忆的智能体
result = app.invoke(
    {"messages": [("human", "你好！")]},
    config=config
)

# 后续调用同一会话
result2 = app.invoke(
    {"messages": [("human", "我刚才说了什么？")]},
    config=config  # 相同的thread_id
)
```

## 记忆管理最佳实践

### 1. 会话ID设计原则

| 场景 | 会话ID格式 | 说明 |
|------|------------|------|
| 单用户单会话 | `user_{user_id}` | 用户级别的持久记忆 |
| 单用户多会话 | `user_{user_id}_session_{session_id}` | 支持用户创建多个独立会话 |
| 多租户应用 | `tenant_{tenant_id}_user_{user_id}` | 隔离不同租户的数据 |
| 临时会话 | `temp_{uuid4()}` | 临时会话，可定期清理 |

### 3. 性能优化建议

- **选择合适的存储后端**：开发用MemorySaver，生产用Redis或PostgreSQL
- **控制状态大小**：避免在状态中存储大对象，只保留必要信息
- **合理设置检查点频率**：不是每个步骤都需要保存，可根据业务需求调整
- **监控存储使用**：定期检查记忆存储的磁盘/内存使用情况

## 与传统LangChain记忆的对比

| 特性 | LangGraph记忆 | 传统LangChain记忆 |
|------|---------------|-------------------|
| **存储粒度** | 整个状态图状态 | 对话消息历史 |
| **持久化机制** | Checkpointer | ChatMessageHistory |
| **会话管理** | 基于thread_id | 基于session_id |
| **状态回滚** | 支持时间旅行 | 不支持 |
| **人工干预** | 支持运行时修改状态 | 仅能追加消息 |
| **复杂工作流** | 支持有状态、循环的工作流 | 仅支持线性对话 |
| **生产就绪** | 内置多种生产级存储 | 需要手动集成外部存储 |

## 完整示例：带记忆的ReAct智能体

```python
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langgraph.prebuilt import create_react_agent
from langgraph.checkpoint.memory import MemorySaver

# 1. 定义工具
@tool
def search_wikipedia(query: str) -> str:
    """安全的维基百科搜索工具"""
    return f"搜索结果：{query}"

@tool  
def safe_calculate(expression: str) -> str:
    """安全的计算器工具"""
    try:
        result = eval(expression, {"__builtins__": {}}, {})
        return str(result)
    except Exception as e:
        return f"计算错误：{str(e)}"

# 2. 初始化模型和记忆
model = ChatOpenAI(model="gpt-4o", temperature=0)
memory = MemorySaver()  # 生产环境替换为RedisSaver或PostgresSaver

# 3. 创建ReAct Agent
agent = create_react_agent(
    model,
    [search_wikipedia, safe_calculate],
    checkpointer=memory,
    max_iterations=8  # 限制最大迭代次数
)

# 4. 使用带记忆的Agent
config = {"configurable": {"thread_id": "user_001"}}

# 第一次调用
result1 = agent.invoke(
    {"messages": [("human", "爱因斯坦的出生年份是多少？")]},
    config=config
)

# 第二次调用（记住上下文）
result2 = agent.invoke(
    {"messages": [("human", "他活了多少岁？")]},
    config=config  # 相同的thread_id保持记忆
)

print("第一次回答:", result1["messages"][-1].content)
print("第二次回答:", result2["messages"][-1].content)
```

## 安全与合规考虑

### 1. 数据隐私保护

- **敏感信息过滤**：在状态保存前过滤掉PII（个人身份信息）
- **加密存储**：对存储的记忆数据进行加密
- **访问控制**：确保只有授权用户能访问其会话记忆

### 2. 资源限制

- **存储配额**：为每个会话设置最大存储空间
- **生命周期管理**：自动清理过期的会话数据
- **成本控制**：监控记忆存储的成本，设置预算告警

### 3. 审计与合规

- **操作日志**：记录所有记忆相关的操作（创建、读取、修改、删除）
- **数据保留策略**：根据法规要求设置数据保留期限
- **数据导出**：支持用户导出其个人数据（GDPR合规）

## 总结

LangGraph的记忆机制通过Checkpointer提供了强大的状态持久化能力，不仅支持传统的对话历史记忆，还支持复杂工作流的状态管理、时间旅行和人工干预。正确使用记忆机制可以显著提升智能体的用户体验和功能性，但在生产环境中需要注意性能、安全和合规性等方面的考量。
