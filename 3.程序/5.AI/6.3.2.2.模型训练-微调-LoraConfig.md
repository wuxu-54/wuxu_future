## 二、LoraConfig 完整入参分类详解+配置影响

### （一）基础核心必选参数

#### 1. `task_type: TaskType`

**作用**：指定微调任务类型，决定模型前向、损失计算、标签头适配逻辑
可选枚举值：

```python
TaskType.CAUSAL_LM       #  decoder模型：LLaMA、Qwen、GPT类（最常用）
TaskType.SEQ_2_SEQ_LM    # 编码器+解码器：T5、BART
TaskType.SEQ_CLASSIFICATION # 文本分类
TaskType.TOKEN_CLASSIFICATION # 命名实体、分词分类
TaskType.QUESTION_ANS    # 问答
TaskType.IMAGE_CLASSIFICATION # 图像分类
TaskType.SEMANTIC_SEGMENTATION # 语义分割
```

**配置影响**：

- 选错会导致训练loss异常、无法加载适配器、推理输出错乱；
- 大模型对话微调一律用 `TaskType.CAUSAL_LM`。

#### 2. `r: int` 【LoRA秩，最核心超参】

默认：`8`
**含义**：低秩矩阵的维度，A矩阵（d×r）、B矩阵（r×d），原始权重W(d×d)，增量权重 $\Delta W = BA$
**参数影响：**

1. r 越大：可学习参数越多、拟合能力越强，更容易拟合数据，不易欠拟合；但参数量上升、显存占用变高、更容易过拟合；
2. r 越小：参数极少、训练快、显存低，但表达能力弱，复杂任务容易欠拟合；
**常用取值**：4/8/16/32；对话微调常用8、16；小样本优先小r。

#### 3. `lora_alpha: int` 缩放系数

默认：`8`
**公式**：前向传播时增量权重缩放：
$$h = Wx + \frac{lora\_alpha}{r} \cdot BAx$$
**配置影响**：

- `lora_alpha/r` 为缩放因子，本质是控制LoRA增量权重的学习步长；
- 行业通用最佳实践：`lora_alpha = r`，此时缩放系数=1；
- alpha > r：放大LoRA更新权重，训练波动更大；alpha < r：抑制更新，训练更稳定但收敛慢；
- 推理合并权重时，该系数会被永久融合进权重，训练和推理必须保持一致。

#### 4. `target_modules: Union[List[str], str]`

**作用**：指定哪些层绑定LoRA，只在指定模块插入低秩矩阵

##### 两种写法：

1. 字符串正则匹配：`target_modules=".*q_proj|.*v_proj"`
2. 列表精准指定：`["q_proj", "v_proj", "k_proj", "o_proj"]`

**配置影响**：

1. 仅训练target_modules内的权重，其他模型参数**完全冻结**；
2. 只训练q/v：参数量最小、训练最快，通用场景够用；
3. 扩展到k/o/mlp层：拟合更强、适合复杂指令微调、角色人设、风格微调；
4. 写错层名：LoRA不生效，模型完全不更新，loss不下降；
5. 不同模型层名不一样：
   - LLaMA/Qwen：`q_proj, v_proj, k_proj, o_proj, gate_proj, up_proj, down_proj`
   - Bert：`query, key, value`

### （二）训练开关类参数

#### 5. `bias: str`

默认：`"none"`
可选值：`"none"` / `"all"` / `"lora_only"`

- `none`：所有bias参数冻结，不训练（推荐，最省显存，工业默认）
- `all`：训练模型全部bias参数，参数量大幅增加，容易过拟合
- `lora_only`：只训练LoRA层内部附带的bias

**配置影响**：
开启bias训练会增加可训练参数，小样本极易过拟合，绝大多数场景保持默认`none`。

#### 6. `inference_mode: bool`

默认：`False`

- `False`：训练模式，开启梯度、LoRA权重可更新；
- `True`：推理模式，冻结所有LoRA参数，只做前向预测，关闭梯度计算节省显存。

**注意**：训练阶段必须设为False；加载LoRA做推理自动设为True，不要手动修改。

#### 7. `use_rslora: bool`

默认：`False`，是否使用**Rank-Stabilized LoRA（秩稳定LoRA）**
**原理**：不再固定缩放系数 $\alpha/r$，改用归一化缩放，解决高r下训练不稳定、权重爆炸问题。
**配置影响**：

- 开启后，大r（32/64）训练更稳定，收敛更平稳；
- 传统LoRA权重和RSLoRA权重不互通，训练和推理必须保持该参数一致；
- 小r场景提升不明显，超大参数微调建议开启。

#### 8. `use_dora: bool`

默认：`False`，是否启用 **DoRA（Weight-Decomposed LoRA）**
在LoRA基础上额外学习权重的幅值缩放，解决LoRA微调后模型能力退化、灾难性遗忘问题。
**配置影响**：

1. 效果优于原生LoRA，小样本、领域微调、人设微调强烈推荐开启；
2. 训练显存开销略高于原生LoRA，收敛速度稍慢；
3. DoRA适配器不能直接和原生LoRA混用，加载时参数必须一致。

### （三）正则化/防过拟合参数

#### 9. `lora_dropout: float`

默认：`0.0`
LoRA分支的dropout概率，取值 `[0,1)`
**配置影响：**

- 0：不使用dropout，训练速度最快；
- 0.05~0.1：小样本场景推荐，抑制过拟合，防止LoRA记住训练集；
- 过大（>0.2）会导致欠拟合、收敛困难、loss居高不下。

#### 10. `modules_to_save: List[str]`

默认：`None`
作用：除了LoRA层之外，需要**全参数微调**的层名称列表。
示例：`modules_to_save=["lm_head"]`
**配置影响：**

1. 列表内的模块不会冻结，会完整训练所有权重；
2. 分类任务常用：训练分类头；LLM微调一般不需要，保持None；
3. 会大幅增加可训练参数，慎用，容易过拟合。

#### 11. `fan_in_fan_out: bool`

默认：`False`
仅针对 `Conv1D` 层（GPT2使用的卷积线性层），权重存储格式为 [fan_out, fan_in]，需要转置。
**配置影响：**

- GPT2系列必须设置为True；LLaMA、Qwen、BERT等标准nn.Linear模型保持False即可；
- 设置错误会导致前向结果完全错误，模型输出乱码。

### （四）LoRA高级扩展参数

#### 12. `init_lora_weights: Union[bool, str]`

默认：`True`
可选：`True / False / "gaussian"`

1. `True`：默认初始化：A矩阵高斯小噪声初始化，B矩阵初始化为全0；训练初始阶段LoRA分支输出为0，不破坏预训练权重；
2. `"gaussian"`：A、B均用高斯分布初始化，训练初始就有增量，收敛更快，但容易震荡；
3. `False`：不初始化，外部自定义权重（用于LoRA权重热重启、继续训练）。

**配置影响**：绝大多数场景用默认True，保证训练稳定，初始阶段不破坏基座模型能力。

#### 13. `layers_to_transform: Union[int, List[int], None]`

默认：`None`
指定只对模型**指定层序号**插入LoRA，比如只在第0、1、2层训练LoRA。
None=所有层都绑定LoRA。
**配置影响**：

- 可以大幅减少可训练参数，仅微调浅层/深层；
- 一般不推荐，LLM需要多层注意力微调才能学到指令能力。

#### 14. `layers_pattern: Optional[str]`

默认：`None`
正则表达式匹配层名前缀，配合layers_to_transform筛选层，多用于多编码器堆叠模型。

#### 15. `rank_pattern: Optional[Dict[str, int]]`

默认：`None`
**分层差异化秩配置**：给不同target模块设置不同的r值
示例：`{"q_proj":16, "v_proj":8}`
**配置影响**：精细化参数分配，关键注意力层用大r，次要层小r，平衡效果与显存，高级调参使用。

#### 16. `alpha_pattern: Optional[Dict[str, int]]`

默认：`None`
和rank_pattern对应，给不同模块设置独立lora_alpha缩放系数。

### （五）兼容性/权重合并相关参数

#### 17. `peft_model_id: Optional[str]`

预训练PEFT适配器本地路径或Hugging Face仓库地址，用于加载已有LoRA配置。

#### 18. `revision: Optional[str]`

拉取远端LoRA权重时指定git版本、分支、commit哈希。

#### 19. `loftq_config: Optional[LoftQConfig]`

LoftQ 量化LoRA配置，用于4/8bit量化场景下初始化LoRA权重，解决量化后微调效果衰减问题。
**配置影响**：仅量化训练（bitsandbytes）场景需要配置，FP16全精度训练无需设置。

#### 20. `use_gradient_checkpointing: bool`

默认：`False`
开启梯度检查点，牺牲少量训练速度，大幅降低激活值显存占用。
**配置影响**：超大模型、小显存显卡必开，会略微降低训练速度，不影响收敛精度。

### （六）新增进阶参数（peft>=0.10）

#### 21. `loraplus_lr_ratio: Optional[float]`

LoRA+优化策略：给A、B矩阵设置差异化学习率，一般B矩阵学习率是A的`loraplus_lr_ratio`倍，解决传统LoRA收敛慢问题。
推荐取值10~20，小样本微调收敛更快。

#### 22. `merge_weights: bool`

推理时是否自动将LoRA权重合并进基座模型权重；训练阶段必须False。

## 三、关键参数联动影响总结表

| 参数 | 调大带来的影响 | 调小/归零带来的影响 | 推荐默认 |
|------|----------------|---------------------|----------|
| r | 拟合变强、显存↑、易过拟合 | 拟合弱、易欠拟合、省显存 | 8 |
| lora_alpha | 梯度放大、训练震荡 | 梯度平滑、收敛慢 | = r |
| lora_dropout | 防过拟合、收敛变慢 | 训练快、小样本易过拟合 | 0 / 0.05 |
| target_modules越多 | 效果越好、参数量↑ | 训练快、效果上限低 | q_proj,v_proj起步 |
| use_dora=True | 效果更好、防遗忘、显存略高 | 原生LoRA、速度快 | 小样本建议True |

## 四、标准通用配置模板（LLM因果语言模型微调）

```python
from peft import LoraConfig, TaskType

lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=16,
    lora_alpha=16,
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
    lora_dropout=0.05,
    bias="none",
    inference_mode=False,
    use_rslora=False,
    use_dora=False,
    modules_to_save=None
)
```

## 五、常见错误配置导致的现象汇总

1. target_modules写错 → loss不下降，模型完全不学习；
2. r过大 + 无dropout → 训练集loss极低，验证集loss飙升（过拟合）；
3. lora_alpha远大于r → 训练loss剧烈震荡、不收敛；
4. 训练和推理use_dora/use_rslora不一致 → 模型输出乱码、效果暴跌；
5. fan_in_fan_out未对GPT2设True → 前向传播结果完全错误。
