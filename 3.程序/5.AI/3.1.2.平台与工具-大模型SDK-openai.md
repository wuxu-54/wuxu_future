## 三、Chat Completions API 详解

### 基本请求示例

```python
response = client.chat.completions.create(
    model="gpt-4o-mini",           # 模型名称
    messages=[                      # 对话历史
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "什么是函数调用？"}
    ],
    temperature=0.7,               # 随机性（0~2）
    max_tokens=500,                # 最大输出 token 数
    stream=False,                  # 是否流式输出
)
answer = response.choices[0].message.content
```

### 核心参数说明

| 参数 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `model` | str | ✅ | 模型 ID，如 `gpt-4o`, `gpt-4o-mini` |
| `messages` | list[dict] | ✅ | 消息列表，每条包含 `role`（system/user/assistant/tool）和 `content` |
| `temperature` | float | ❌ | 采样温度，0~2，越高越随机，默认 1 |
| `top_p` | float | ❌ | 核采样概率阈值，默认 1 |
| `max_tokens` | int | ❌ | 生成的最大 token 数 |
| `stream` | bool | ❌ | 是否流式返回，默认 False |
| `tools` | list[dict] | ❌ | 可供模型调用的工具列表（见后文） |
| `tool_choice` | str / dict | ❌ | 控制工具选择策略：`"auto"`, `"required"`, `"none"` 或指定函数 |
| `response_format` | dict | ❌ | 强制输出格式，如 `{"type": "json_object"}` |

### 安全取值实践

```python
response = client.chat.completions.create(...)
if response.choices:
    message = response.choices[0].message
    content = message.content if message.content else ""
else:
    content = ""
```

### 异步调用

```python
from openai import AsyncOpenAI
import asyncio

async def main():
    client = AsyncOpenAI()
    response = await client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "Hello"}]
    )
    print(response.choices[0].message.content)

asyncio.run(main())
```

## 四、Tool Calling（函数调用）

Tool Calling 允许模型在回应时请求调用你定义的外部函数，从而获取实时数据或执行操作。模型会返回结构化的函数名和参数，由你的代码实际执行，并将结果回送给模型，形成闭环。

### 第 1 步：定义一个工具（字典结构）

```python
weather_tool = {
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "获取指定城市的实时天气信息",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {
                    "type": "string",
                    "description": "城市名称，例如 'Beijing'"
                },
                "unit": {
                    "type": "string",
                    "enum": ["celsius", "fahrenheit"],
                    "description": "温度单位"
                }
            },
            "required": ["city"],
            "additionalProperties": False
        },
        "strict": True   # 推荐开启，强制模型遵循参数结构
    }
}
```

### ✨ 新增：多个工具的配置与使用

在实际应用中，你常常需要为模型提供多个不同功能的工具，比如：获取天气、查询日历、发送邮件、计算数学表达式等。OpenAI API 支持在单次请求中传入**多个工具**，模型会根据用户问题和工具描述，智能选择调用一个、多个（并行），或不调用任何工具。

#### 1. 定义多个工具

定义多个工具与定义单个工具的方式完全相同，只需将每个工具定义放在一个列表中。下面定义两个工具：`get_weather` 和 `send_email`。

```python
# 工具1：获取天气
weather_tool = {
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "获取指定城市的实时天气信息",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "城市名称"}
            },
            "required": ["city"],
            "additionalProperties": False
        },
        "strict": True
    }
}

# 工具2：发送邮件
email_tool = {
    "type": "function",
    "function": {
        "name": "send_email",
        "description": "发送一封邮件给指定收件人",
        "parameters": {
            "type": "object",
            "properties": {
                "to": {"type": "string", "description": "收件人邮箱地址"},
                "subject": {"type": "string", "description": "邮件主题"},
                "body": {"type": "string", "description": "邮件正文"}
            },
            "required": ["to", "subject", "body"],
            "additionalProperties": False
        },
        "strict": True
    }
}

# 工具列表
tools = [weather_tool, email_tool]
```

#### 2. 在请求中传入多个工具

将 `tools` 参数设置为包含所有工具定义的列表。

```python
messages = [{"role": "user", "content": "北京天气怎么样？顺便给我老板发个邮件说今天会晚到"}]

response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools,           # 同时提供两个工具
    tool_choice="auto"     # 让模型决定调用哪些
)
```

#### 3. 模型如何选择工具？

- 模型会分析用户消息和每个工具的 `description` 以及参数描述。
- 如果用户请求明显需要某个工具（例如询问天气），模型会调用对应的 `get_weather`。
- 如果用户一次性提出多个独立的需求（例如同时问天气和发邮件），模型可能会**并行调用多个工具**，即一次响应中返回多个 `tool_calls`，每个 `tool_calls` 元素对应一个工具调用。

**模型返回多个 tool_calls 的示例结构：**

```python
response_message = response.choices[0].message
tool_calls = response_message.tool_calls
print(len(tool_calls))   # 2
print(tool_calls[0].function.name)  # "get_weather"
print(tool_calls[1].function.name)  # "send_email"
```

#### 4. 处理多个工具调用的结果

你的代码需要遍历 `tool_calls` 列表，针对每个工具调用，根据 `function.name` 执行对应的真实函数，收集结果，然后将所有结果以 `tool` 角色消息的形式按顺序追加到对话历史中，最后再请求模型生成最终答案。

```python
import json

# 假设真实函数已实现
def real_get_weather(city):
    return f"{city}天气：晴，25°C"

def real_send_email(to, subject, body):
    # 模拟发送邮件
    print(f"发送邮件给 {to}: {subject}")
    return "邮件发送成功"

# 处理模型返回的多个工具调用
if response_message.tool_calls:
    # 先将模型的工具调用请求追加到历史记录
    messages.append(response_message)
    
    # 遍历每个工具调用，执行并收集结果
    for tool_call in response_message.tool_calls:
        func_name = tool_call.function.name
        func_args = json.loads(tool_call.function.arguments)
        
        if func_name == "get_weather":
            result = real_get_weather(func_args["city"])
        elif func_name == "send_email":
            result = real_send_email(func_args["to"], func_args["subject"], func_args["body"])
        else:
            result = f"未知工具: {func_name}"
        
        # 将每个工具的执行结果以 tool 角色追加
        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,   # 必须与对应的 tool_call 的 id 匹配
            "content": result
        })
    
    # 将所有工具结果返回给模型，获取最终回答
    final_response = client.chat.completions.create(
        model="gpt-4o",
        messages=messages
    )
    print(final_response.choices[0].message.content)
```

#### 5. 强制模型必须调用某个或某些工具

通过 `tool_choice` 参数可以控制模型的调用行为：

- `"auto"`（默认）：模型自主决定是否调用以及调用哪些。
- `"required"`：强制模型必须至少调用一个工具（可能调用多个）。
- `"none"`：强制模型不调用任何工具。
- `{"type": "function", "function": {"name": "get_weather"}}`：强制模型只调用指定的单个工具，忽略其他工具。

**示例：强制模型必须调用 get_weather**

```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=[weather_tool, email_tool],
    tool_choice={"type": "function", "function": {"name": "get_weather"}}
)
```

> **注意**：当使用 `tool_choice` 强制指定某个函数时，模型不会同时调用其他函数。如果需要模型同时调用多个函数，应使用 `"auto"` 或 `"required"`，并依赖于模型的自然判断。

#### 6. 多个工具的最佳实践

- **为每个工具提供清晰、具体的 `description`**：这直接影响模型判断何时调用该工具。例如，对于 `send_email`，可以写“当用户明确要求发送邮件时调用此工具”。
- **参数命名和描述要清晰**：避免模糊的命名，如 `arg1`。
- **并行调用时注意工具间的依赖**：如果工具 B 需要工具 A 的结果作为输入，模型通常不会自动编排顺序。这时应通过**多轮对话**（先调 A，拿到结果后再发给模型，模型再调 B）来解决。
- **控制工具数量**：不建议一次提供超过 10-20 个工具，过多的选择会降低模型判断的准确性和响应速度。
- **使用严格模式（`strict: true`）**：对所有工具都开启，确保模型输出参数完全符合 Schema，减少解析错误。

## 五、工具（Tool）结构每个参数详解

工具定义是一个字典，顶层包含 `type` 和 `function` 两个字段。下面逐一拆解。

### 1. `type`（字符串，必填）

- **作用**：指定工具的类型。当前 **仅支持** `"function"`。
- **示例**：`"type": "function"`

### 2. `function`（对象，必填）

包含函数的所有元数据。

#### 2.1 `function.name`（字符串，必填）

- **作用**：函数的唯一标识符。模型在返回的 `tool_calls[].function.name` 中使用此名称。
- **命名规范**：字母、数字、下划线，建议小写蛇形，且在 `tools` 列表中唯一。
- **示例**：`"name": "get_weather"`

#### 2.2 `function.description`（字符串，推荐）

- **作用**：自然语言描述函数的用途。模型据此判断何时调用。描述越清晰，调用准确率越高。
- **示例**：`"description": "获取指定城市的实时天气，支持全球主要城市"`

#### 2.3 `function.parameters`（对象，必填）

一个 **JSON Schema** 对象，定义函数接受的参数。

##### 2.3.1 `parameters.type`（字符串，必填）

- **固定值** `"object"`，表示参数是一个键值对对象。

##### 2.3.2 `parameters.properties`（对象，可选）

- **作用**：定义每个参数的具体规范。键为参数名，值为该参数的约束。
- **每个参数可包含**：
  - `type`：数据类型（`string`、`number`、`integer`、`boolean`、`array`、`object`）。
  - `description`：参数的自然语言描述。
  - `enum`：枚举值列表（如 `["celsius","fahrenheit"]`）。
  - 其他 JSON Schema 关键字（`minimum`、`pattern` 等）。
- **示例**：

  ```json
  "properties": {
    "city": { "type": "string", "description": "城市名称" },
    "unit": { "type": "string", "enum": ["celsius","fahrenheit"] }
  }
  ```

##### 2.3.3 `parameters.required`（字符串数组，可选）

- **作用**：列出必须由模型提供的参数名。模型生成的 `arguments` 必须包含这些字段。
- **示例**：`"required": ["city"]`

##### 2.3.4 `parameters.additionalProperties`（布尔值，推荐设为 `false`）

- **作用**：是否允许模型传入未在 `properties` 中定义的额外参数。
  - `false`：禁止额外参数，确保输出严格符合预期。
  - `true`：允许额外参数（不推荐）。
- **推荐值**：`false`（尤其在开启 `strict` 时强制为 `false`）。

#### 2.4 `function.strict`（布尔值，推荐设为 `true`）

- **作用**：启用高可靠性模式，强制模型严格遵循 JSON Schema 定义。
- **开启后的效果**：
  - 模型几乎不会生成不符合 Schema 的参数（类型、必填、额外属性等）。
  - 你的 `parameters` 必须符合 OpenAI 的 JSON Schema 子集限制（例如不支持 `default` 关键字）。
- **默认值**：对于新模型（如 `gpt-4o-2024-08-06`），未设置时可能默认为 `true`，但建议显式设置。
- **注意**：开启 `strict: true` 时，必须同时设置 `required`（可空数组）且 `additionalProperties` 必须为 `false`。

### 参数总结表

| 参数路径 | 必填 | 作用 |
| :--- | :--- | :--- |
| `type` | ✅ | 固定 `"function"` |
| `function.name` | ✅ | 函数唯一标识符 |
| `function.description` | 强烈推荐 | 描述函数用途，辅助模型决策 |
| `function.parameters` | ✅ | JSON Schema 定义参数 |
| `parameters.type` | ✅ | 固定 `"object"` |
| `parameters.properties` | ❌ | 参数具体定义 |
| `parameters.required` | ❌ | 必填参数列表 |
| `parameters.additionalProperties` | 推荐 `false` | 是否允许未定义参数 |
| `function.strict` | 推荐 `true` | 强制严格遵循 Schema |

## 六、最佳实践提示

1. **安全加载 API Key**：永远使用环境变量，不要硬编码。
2. **处理空响应**：通过 `if response.choices:` 防御性取值。
3. **开启 `strict: true`**：在定义工具时，始终开启严格模式，并设置 `additionalProperties: false` 和完整的 `required` 数组，大幅减少解析错误。
4. **并行工具调用**：模型可能一次返回多个 `tool_calls`，你的代码应支持并行或串行执行多个函数，然后将结果汇总返回。注意：如果工具之间有依赖关系，请使用多轮对话而非单次并行。
5. **工具数量控制**：一次请求建议不超过 20 个工具，以免模型决策困难。
6. **使用 Pydantic 简化工具定义**（可选）：

   ```python
   from pydantic import BaseModel
   import openai

   class GetWeather(BaseModel):
       city: str
       unit: str = "celsius"

   tool = openai.pydantic_function_tool(GetWeather)
   ```

   该辅助函数会自动生成符合 OpenAI 规范的字典。
