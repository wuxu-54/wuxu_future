# Harness系统完整实现指南：从48小时MVP到生产级部署

实现Harness系统的核心哲学是：**先建护栏，再给油门**。不要一开始就追求完美的六层架构，而是从投入产出比最高的"信息边界"和"约束验证"入手，用48小时搭建一个能跑通的MVP，然后在使用中持续迭代优化。

## 一、实现前的准备工作

### 1.1 明确你的第一个Harness目标

**不要一开始就做通用Harness**，先聚焦一个具体、高频、风险可控的任务：

- ✅ 推荐：代码生成助手、文档自动更新、测试用例生成
- ❌ 不推荐：生产环境部署、数据库修改、资金相关操作

**成功标准**：该任务在无人干预下成功率≥70%，且失败不会造成不可逆损失。

### 1.2 最小技术栈选择（2026年最佳实践）

| 组件 | 推荐工具 | 理由 |
|------|----------|------|
| 编排引擎 | LangGraph | 业界标准，支持状态管理、检查点和条件分支 |
| 工具协议 | MCP (Model Context Protocol) | 统一工具接口，可无缝切换不同AI助手 |
| 执行沙箱 | E2B/Daytona | 隔离执行AI生成的代码，防止安全风险 |
| 可观测性 | Langfuse | 追踪Agent决策链路，便于调试和优化 |
| 模型接口 | OpenAI SDK | 兼容大多数开源和闭源模型 |

### 1.3 三条不可动摇的设计原则

1. **硬约束优先**：能用代码强制的规则，绝对不要写在Prompt里
2. **渐进式披露**：Agent只获得当前步骤需要的信息，不多不少
3. **可验证性**：每个任务必须有独立于生成过程的验证方法

## 二、第一阶段：48小时搭建MVP（H1级）

我们将实现一个**代码修改助手Harness**，它能根据需求修改项目代码、运行测试并提交PR。

这是Harness最重要的部分，决定了Agent"知道什么"和"不知道什么"。

**步骤1：创建最小可行AGENTS.md**（50行以内）

```markdown

## 🔒 绝对禁止
1. 修改 `.harness/` 目录下的任何文件
2. 删除任何文件（只能创建和修改）
3. 提交包含密码、API密钥等敏感信息的代码
```

**步骤2：实现上下文加载器**（自动生成项目摘要）

```python
# .harness/context_loader.py
import os
from pathlib import Path

def generate_project_context(root_dir: str = ".") -> str:
    """生成Agent需要的项目上下文摘要"""
    context = []
    
    # 1. 项目结构（只显示关键目录）
    context.append("## 项目结构")
    for item in os.listdir(root_dir):
        if item.startswith((".", "__")):
            continue
        path = Path(root_dir) / item
        if path.is_dir() and item in ["src", "tests", "docs"]:
            context.append(f"- {item}/")
            # 显示子目录结构（最多2层）
            for subitem in os.listdir(path):
                subpath = path / subitem
                if subpath.is_dir() and not subitem.startswith((".", "__")):
                    context.append(f"  - {subitem}/")
    
    # 2. 关键文件列表
    context.append("\n## 关键文件")
    key_files = ["pyproject.toml", "requirements.txt", "README.md"]
    for file in key_files:
        if os.path.exists(file):
            context.append(f"- {file}")
    
    # 3. 测试命令
    context.append("\n## 验证命令")
    context.append("- 运行所有测试：pytest tests/ -v --tb=short")
    context.append("- 代码风格检查：ruff check src/")
    
    return "\n".join(context)

if __name__ == "__main__":
    print(generate_project_context())
```

```python
# .harness/tools/filesystem.py
from mcp.server.fastmcp import FastMCP
from pathlib import Path

mcp = FastMCP("project-filesystem")

# 允许写入的目录白名单
ALLOWED_WRITE_PATHS = ["./src", "./tests", "./docs"]

@mcp.tool()
def write_file(path: str, content: str) -> str:
    """写入文件内容（仅允许在白名单目录）"""
    normalized_path = Path(path).resolve()
    
    # 权限检查
    allowed = False
    for allowed_path in ALLOWED_WRITE_PATHS:
        if normalized_path.is_relative_to(Path(allowed_path).resolve()):
            allowed = True
            break
    
    if not allowed:
        return f"错误：不允许写入路径 {path}，仅允许写入：{ALLOWED_WRITE_PATHS}"
    
    # 写入文件
    normalized_path.parent.mkdir(parents=True, exist_ok=True)
    normalized_path.write_text(content)
    return f"成功写入文件：{path}"

if __name__ == "__main__":
    mcp.run()
```

### 2.4 核心组件3：基础执行编排（L3层）

用LangGraph实现"计划-批准-执行-验证"的基础工作流。

```python
# .harness/workflow.py
from typing import TypedDict, Annotated, Sequence
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver
from langchain_core.messages import BaseMessage, HumanMessage, SystemMessage
from langchain_openai import ChatOpenAI
from langchain_mcp_adapters.client import MultiServerMCPClient
import operator

# 定义状态
class AgentState(TypedDict):
    messages: Annotated[Sequence[BaseMessage], operator.add]
    task: str
    plan: str
    plan_approved: bool
    execution_result: str
    verification_result: str
    iteration: int

# 初始化模型和工具
llm = ChatOpenAI(model="gpt-4o", temperature=0)

async def load_tools():
    client = MultiServerMCPClient({
        "filesystem": {
            "command": "python",
            "args": [".harness/tools/filesystem.py"]
        },
        "git": {
            "command": "npx",
            "args": ["-y", "@modelcontextprotocol/server-git", "."]
        }
    })
    await client.connect()
    return client.get_tools(), client

# 节点1：生成计划
async def generate_plan(state: AgentState):
    system_prompt = SystemMessage(content="""
    你是一个严谨的代码助手。根据用户的任务，生成详细的修改计划。
    计划格式必须是：
    1. [文件路径] - [修改内容]
    2. [文件路径] - [修改内容]
    
    验证方法：
    - [运行什么命令来验证修改]
    """)
    
    context = open(".harness/AGENTS.md").read() + "\n\n" + open(".harness/project_context.md").read()
    
    response = await llm.ainvoke([
        system_prompt,
        HumanMessage(content=f"任务：{state['task']}\n\n项目上下文：{context}")
    ])
    
    return {"plan": response.content, "iteration": state["iteration"] + 1}

# 节点2：等待人类批准
def wait_for_approval(state: AgentState):
    print("\n=== 生成的计划 ===")
    print(state["plan"])
    approval = input("\n是否批准执行？(y/n): ")
    return {"plan_approved": approval.lower() == "y"}

# 节点3：执行修改
async def execute_modifications(state: AgentState):
    tools, client = await load_tools()
    llm_with_tools = llm.bind_tools(tools)
    
    messages = [
        SystemMessage(content=f"执行以下修改计划：{state['plan']}"),
        HumanMessage(content="开始执行")
    ]
    
    response = await llm_with_tools.ainvoke(messages)
    await client.close()
    
    return {"execution_result": response.content}

# 节点4：验证修改
async def verify_modifications(state: AgentState):
    import subprocess
    result = subprocess.run(
        ["pytest", "tests/", "-v", "--tb=short"],
        capture_output=True,
        text=True
    )
    
    verification_result = f"测试退出码：{result.returncode}\n\n标准输出：{result.stdout}\n\n标准错误：{result.stderr}"
    return {"verification_result": verification_result}

# 条件路由
def should_continue(state: AgentState):
    if not state["plan_approved"]:
        return END
    if state["iteration"] > 3:
        return END
    if "测试通过" in state["verification_result"] or result.returncode == 0:
        return END
    return "generate_plan"

# 构建图
builder = StateGraph(AgentState)
builder.add_node("generate_plan", generate_plan)
builder.add_node("wait_for_approval", wait_for_approval)
builder.add_node("execute_modifications", execute_modifications)
builder.add_node("verify_modifications", verify_modifications)

builder.set_entry_point("generate_plan")
builder.add_edge("generate_plan", "wait_for_approval")
builder.add_conditional_edges(
    "wait_for_approval",
    should_continue,
    {END: END, "execute_modifications": "execute_modifications"}
)
builder.add_edge("execute_modifications", "verify_modifications")
builder.add_conditional_edges(
    "verify_modifications",
    should_continue,
    {END: END, "generate_plan": "generate_plan"}
)

# 编译图
memory = MemorySaver()
graph = builder.compile(checkpointer=memory)

# 运行示例
if __name__ == "__main__":
    import asyncio
    
    async def main():
        # 生成项目上下文
        with open(".harness/project_context.md", "w") as f:
            f.write(generate_project_context())
        
        task = input("请输入任务：")
        initial_state = {
            "task": task,
            "messages": [],
            "plan_approved": False,
            "iteration": 0
        }
        
        config = {"configurable": {"thread_id": "1"}}
        async for event in graph.astream(initial_state, config):
            for value in event.values():
                if "plan" in value:
                    print("\n生成计划完成")
                elif "execution_result" in value:
                    print("\n执行修改完成")
                elif "verification_result" in value:
                    print("\n验证完成")
                    print(value["verification_result"])
    
    asyncio.run(main())
```

### 2.5 核心组件4：约束与验证系统（L6层）

这是防止Agent搞破坏的最后一道防线。

**步骤1：实现自定义Linter**

```python
# .harness/validation/linters.py
import ast
import re

def check_no_hardcoded_secrets(content: str) -> list[str]:
    """检查是否有硬编码的密钥"""
    errors = []
    secret_patterns = [
        r"api_key\s*=\s*['\"][A-Za-z0-9]{20,}['\"]",
        r"password\s*=\s*['\"].+['\"]",
        r"token\s*=\s*['\"][A-Za-z0-9]{20,}['\"]"
    ]
    
    for pattern in secret_patterns:
        matches = re.findall(pattern, content)
        for match in matches:
            errors.append(f"发现硬编码密钥：{match}")
    
    return errors

def check_architecture_rules(filepath: str, content: str) -> list[str]:
    """检查架构规则"""
    errors = []
    
    # 规则：service层不能直接导入controller层
    if "src/service/" in filepath:
        if "from src.controller" in content:
            errors.append("架构违规：service层不能导入controller层")
    
    return errors

def validate_file(filepath: str) -> list[str]:
    """验证文件是否符合所有规则"""
    try:
        with open(filepath, "r") as f:
            content = f.read()
        
        errors = []
        errors.extend(check_no_hardcoded_secrets(content))
        errors.extend(check_architecture_rules(filepath, content))
        
        return errors
    except Exception as e:
        return [f"验证文件时出错：{str(e)}"]
```

**步骤2：集成到Git钩子**（.git/hooks/pre-commit）

```bash
#!/bin/sh
echo "🔍 运行Harness验证规则..."

# 检查所有修改的文件
for file in $(git diff --cached --name-only --diff-filter=ACM); do
    if [[ $file == src/* || $file == tests/* ]]; then
        errors=$(python .harness/validation/linters.py "$file")
        if [ -n "$errors" ]; then
            echo "❌ 文件 $file 验证失败："
            echo "$errors"
            exit 1
        fi
    fi
done

echo "✅ 所有验证通过"
exit 0
```

## 三、第二阶段：升级到生产级Harness（H2级）

当MVP运行稳定后，按照以下顺序逐步添加功能，每个功能都要经过充分测试。

### 3.1 支柱一：完善上下文架构

- **实现渐进式披露**：AGENTS.md只作为目录，详细文档按需加载
- **添加滚动摘要**：每5轮对话自动总结历史，保留关键信息
- **上下文利用率监控**：当上下文超过40%时自动触发蒸馏

```python
# 上下文蒸馏示例
def distill_context(messages: list[BaseMessage], max_tokens: int = 2000) -> list[BaseMessage]:
    """将长对话历史蒸馏为摘要"""
    if len(messages) < 10:
        return messages
    
    # 保留最近3轮和系统提示
    recent_messages = messages[-3:]
    old_messages = messages[:-3]
    
    # 生成历史摘要
    summary_prompt = f"总结以下对话历史，保留关键决策和结果：\n{old_messages}"
    summary = llm.invoke(summary_prompt).content
    
    return [
        SystemMessage(content=f"历史对话摘要：{summary}"),
        *recent_messages
    ]
```

### 3.2 支柱二：强化架构约束

- **扩展自定义Linter规则**：覆盖命名规范、依赖关系、安全漏洞
- **实现操作分级授权**：
  - 读操作：无需确认
  - 写操作：自动验证通过后无需确认
  - 删除操作：必须人工确认
- **添加沙箱执行**：所有AI生成的代码在E2B沙箱中运行

### 3.3 支柱三：构建完整自验证循环

- **实现Generator-Evaluator分离**：一个AI生成，另一个独立AI评审
- **添加Plan-Build-Verify-Fix强制循环**
- **推理三明治策略**：规划和验证用高推理模型，实现用低推理模型

### 3.4 支柱四：实现上下文隔离

- **每个子任务启动新上下文**：避免上下文污染
- **Agent专业化分工**：代码生成Agent、测试生成Agent、文档生成Agent
- **信息接口化**：Agent之间通过结构化JSON消息传递

### 3.5 支柱五：基础熵治理

- **定期上下文垃圾回收**：删除过时的中间结果
- **文档园丁Agent**：自动扫描文档与代码的不一致
- **技术债扫描**：定期生成技术债报告

### 3.6 支柱六：可拆卸性设计

- **抽象模型接口**：不依赖具体模型实现
- **Prompt模板外置**：所有Prompt放在配置文件中
- **能力特性标记**：根据模型能力动态调整Harness行为

## 六、最佳实践与避坑指南

### 6.1 10条黄金法则

1. **从简单开始**：先做一个能跑的MVP，再逐步扩展
2. **硬约束优先**：能用代码强制的规则，绝对不要写在Prompt里
3. **最小权限原则**：只给Agent它需要的工具和权限
4. **可验证性**：每个任务必须有独立的验证方法
5. **渐进式披露**：Agent只获得当前步骤需要的信息
6. **失败是常态**：设计系统时假设Agent会失败
7. **记录一切**：完整记录Agent的所有决策和操作
8. **定期清理**：主动对抗系统熵增
9. **人类在回路**：关键操作必须有人工审核
10. **持续迭代**：Harness系统永远没有完成时

### 6.2 常见错误与解决方案

| 错误 | 解决方案 |
|------|----------|
| Agent陷入无限循环 | 添加最大迭代次数限制，检测重复状态 |
| 上下文溢出 | 实现上下文蒸馏和滚动摘要 |
| 生成的代码有安全漏洞 | 加强自定义Linter规则，使用安全扫描工具 |
| 多Agent协作混乱 | 明确每个Agent的职责，使用消息队列通信 |
| 系统越来越慢 | 优化状态管理，定期清理历史数据 |
