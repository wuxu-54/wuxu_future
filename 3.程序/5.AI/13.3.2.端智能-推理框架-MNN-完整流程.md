# MNN 在端侧大模型里完整工作流程（以 LLM‑大模型为例）

整体分为两大阶段：**PC 模型转换阶段** + **端侧设备推理运行阶段**。MNN 的核心作用：把 Pytorch/TensorFlow 训练出来的模型，适配手机、嵌入式设备，做轻量化推理。下面拆解完整链路。

## 一、前置阶段：PC 端模型导出 + MNN 模型转换（离线完成，只做一次）

### 1. 原始模型导出

大模型开发者在电脑上训练模型：PyTorch、Hugging‑Face Transformers。
1）把模型导出成 ONNX 文件。

- LLM 模型（Transformer）包含大量矩阵乘法、LayerNorm、RoPE、Softmax、K‑V Cache；
- 原生 PyTorch 代码无法直接放到手机运行，必须先导出 ONNX；
- 针对大模型，一般分开导出：Prefill 阶段（一次性处理输入prompt）、Decode阶段（逐 token 生成）两个 ONNX，方便KV‑Cache复用。

>
> 问题：原生ONNX对超长序列、动态KV缓存、动态seq\_len支持不好，这里MNN有专门的算子适配。

### 2. MNNConvert 模型转换（MNN核心工具）

命令行工具：`MNNConvert`，输入 ONNX → 输出 `.mnn` 文件。
内部做的事情：

1. **算子解析与替换**
   - 将 ONNX 的算子映射为 MNN 内置算子；
   - 对 Transformer 特有算子：RoPE、PagedAttention、Multi‑Head Attention、GLU、RMSNorm，MNN提供高性能手写算子替换掉通用ONNX算子，大幅提速；
   - 淘汰冗余节点：删除恒等算子、无用Reshape、多余Cast。
2. **量化（端侧大模型关键）**
 做 INT8 / INT4‑AWQ / GPTQ 量化：
   - FP32权重压缩成4bit或8bit；权重存在.mnn文件里；
   - MNN会记录缩放因子、零点参数；推理时再动态反量化；
    大模型只有量化之后才能放进手机内存。
3. **计算图重构与算子融合**
   - 算子融合：Conv‑Add、MatMul‑Add、Norm之后接乘法合并成一个算子，减少内存读写；
   - 布局优化：把权重从 NCHW 转成 MNN 专用内存排布（NC4HW4等）适配ARM CPU / NPU；
4. **内存预排布**
 权重预先分块，适配ARM的L1‑L2缓存，减少Cache miss。

输出产物：`llm.mnn`，这个文件会打包进APP或者嵌入式程序里。

## 二、端侧运行阶段：APP调用MNN推理引擎（运行时核心流程）

MNN runtime 分为：**Session、Interpreter、Backend、Tensor、算子库、内存管理器、线程池**。
APP（Java/Kotlin/C++）调用MNN的C++ API，完整执行步骤：

### 步骤1：初始化MNN运行时（启动阶段）

1. 创建 MNN::Interpreter，读取 `.mnn` 文件到内存；
2. 设置后端 Backend（非常关键）：
 MNN支持多种后端：
   - ARM CPU（默认，汇编手写NEON指令）；
   - OpenCL（GPU加速）；
   - Metal（苹果手机GPU）；
   - NPU（高通Hexagon、天玑NPU）；
    大模型场景优先选择：CPU‑NEON或者OpenCL；很多端侧LLM只用CPU运行。
3. 创建会话 Session：

```
Interpreter* net = Interpreter::createFromFile("llm.mnn");
ScheduleConfig config;
config.numThread = 4; // 设置CPU线程数（一般设为大核数量）
Session* session = net->createSession(config);
```

- Session：对应一次计算图实例；可以创建多个session；
- 权重只会加载1次，多个session共享权重节省内存；
- KV‑Cache在这里开辟一块持久化内存，全程复用，不用反复创建释放内存（PagedAttention分页缓存就在这里实现）。

### 步骤2：输入数据准备（Tensor构建）

MNN里面所有数据都是由 `MNN::Tensor` 管理：

1. 把输入文本经过分词器（Tokenizer，不在MNN内部，单独代码）转为int型token id数组；
2. 创建输入Tensor，把token\_ids、position\_ids传入MNN；
3. 区分两种Tensor模式：
   - Host Tensor：内存放在CPU内存；
   - Device Tensor：内存放到GPU显存（OpenCL Buffer）；
    MNN提供`map<float>`、`host<float>`实现CPU内存读写；>
   > 注意：权重Tensor是只读的，输入输出Tensor是可读写。

### 步骤3：推理执行（session‑run()，MNN内部最核心逻辑）

调用 `net->runSession(session)` 之后内部执行链路：

1. **调度层：Schedule**
 Schedule遍历计算图节点，根据Backend选择对应的算子实现：
   - 如果开启CPU：调用MNN用汇编手写的NEON优化算子：MatMul、RMSNorm、RoPE、Softmax；
   - 如果开启OpenCL：把算子编译成OpenCL‑Kernel代码在GPU运行；
    MNN不会逐个算子串行执行，线程池按照依赖关系调度算子并行运行。
2. **权重读取与动态反量化（INT4/INT8）**
 当执行矩阵乘法（Transformer里占用90%耗时）：
   - MNN从.mnn加载压缩后的INT4权重；
   - 在计算的时候实时解压缩成FP16；
   - 使用ARM NEON指令一次性并行处理8‑16个数值；
    这里MNN专门针对大模型的weight‑only量化做了优化：权重常驻内存，激活值用完就释放，节省RAM。
3. KV‑Cache更新（LLM独有逻辑）
   - Prefill阶段：输入整段Prompt，一次性算出Key、Value；存入提前开辟的缓存Tensor；
   - Decode阶段：每生成一个新token，只计算最新位置的K、V，拼接到KV缓存里；旧KV不再重新计算；
    MNN通过调整Tensor的shape，动态扩展缓存，避免每次重新分配内存。
4. 逐层计算：
 依次执行：多头注意力 → Feed‑Forward GLU → RMSNorm；
 最后输出logits张量（形状：\[1, vocab\_size\]）。

### 步骤4：取出推理结果，解码下一个token

1. 从输出Tensor读取logits数组；
2. 外部代码做采样（top‑p、top‑k）选出下一个token\_id；
3. 再把新token重新喂给MNN，循环调用runSession，直到遇到结束符EOS；>

> 采样逻辑不在MNN引擎内部，由上层应用代码实现。

### 步骤5：推理结束后释放资源

会话可以保留继续生成后续token；对话结束后销毁Session和Interpreter释放内存。

# 三、MNN内部核心组件在LLM里各自作用（底层视角）

1. **Backend（后端抽象层）**
 统一接口隔离CPU/GPU/NPU；算子实现分开编写；上层代码不用关心硬件。
2. **Tensor内存管理**
 MNN有自己内存池：大块内存一次性申请，小块复用，减少malloc/free开销，嵌入式设备malloc很慢，这一点非常重要。对于LLM的KV‑Cache，MNN采用分页内存（PagedAttention）防止内存碎片化。
3. 高性能算子库
   - CPU：手写NEON汇编实现FP16矩阵乘、INT4权重‑only矩阵乘法；
   - OpenCL：针对GPU寄存器分块，把大矩阵拆成小块矩阵运算；
    普通深度学习框架没有针对LLM做优化，MNN专门适配Transformer算子，比通用推理框架速度更快。
4. 计算图优化模块（Graph Optimize）
 运行前就完成算子融合、常量折叠、冗余节点删除，运行时不再做图分析，保证推理高速。

# 四、举一个通俗概括版

1. 电脑端：训练好的大模型 →导出ONNX →MNNConvert压缩量化生成mnn文件；
2. 手机APP：启动时MNN加载mnn文件，把权重读进内存；
3. 用户输入文字 →分词成数字；
4. MNN调用硬件优化算子逐层计算Transformer，借助KV缓存减少重复计算；
5. 返回预测的下一个字，循环生成句子；
整个过程MNN负责硬件适配、内存管理、量化计算、硬件加速。

# 五、对比其它引擎特点（帮你加深理解）

- TensorRT：只能英伟达GPU；
- ONNXRuntime‑Mobile：算子通用，但是没有针对ARM做极致汇编优化；
- MNN：针对移动端CPU手写汇编、支持INT4量化、KV‑Cache友好、体积小巧，所以现在端侧大模型（手机本地7B模型）大量采用MNN。
