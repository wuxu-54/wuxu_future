# Agent 完整详解：从概念到生产级实现

Agent 是继大模型和 Skill 之后，AI 应用工程的又一核心抽象。如果说 Skill 是“能力单元”，那么 Agent 就是“调度大脑”——它能够自主理解目标、规划步骤、调用 Skill 和工具、并根据执行结果动态调整，最终完成复杂任务。

本文将从概念、架构、实现、与 Skill 的关系、生产级落地等维度，全面介绍 Agent 的开发。

---

## 一、Agent 是什么？

**Agent（智能体）** 是一种能够**自主感知环境、做出决策、执行动作**的软件实体。在大模型应用语境下，Agent 通常指**基于 LLM 的推理引擎**，它接收用户目标，然后循环执行“思考-行动-观察”的过程，直到任务完成。

### 1.1 Agent vs Skill vs Tool vs Chain

| 概念 | 核心职责 | 抽象层次 | 是否包含推理 |
|------|----------|----------|--------------|
| **Tool** | 执行确定性操作（计算、查天气、发邮件） | 最低 | 否（纯函数） |
| **Skill** | 封装一个完整的任务能力（可包含多个 Tool 和模型调用） | 中 | 部分（可能包含内部 prompt） |
| **Agent** | 自主规划、决策、调用 Skill/Tool 完成任务 | 最高 | 是（核心是 LLM 推理） |
| **Chain** | 固定的执行步骤序列（无自适应） | 中 | 否 |

**一句话总结**：Agent 知道自己“要做什么、怎么做、做错了怎么办”，而 Skill 只知道“怎么做”。

### 1.2 Agent 的核心能力

一个完整的 Agent 应具备以下四种能力：

1. **规划能力**：将复杂目标拆解为可执行的子任务，并决定子任务的执行顺序。
2. **记忆能力**：包括短期记忆（当前对话上下文）和长期记忆（历史经验、用户偏好）。
3. **工具使用能力**：调用外部 Skill 或 Tool 来执行具体操作。
4. **反思能力**：根据执行结果判断是否达成目标，若失败则尝试其他策略或请求人类帮助。

## 二、Agent 的经典架构

现代 LLM Agent 普遍采用 **ReAct（Reasoning + Acting）** 模式，由以下三个循环组件构成：

```
用户输入 → 推理(Reasoning) → 行动(Acting) → 观察(Observation) → 推理...
                ↑                                      │
                └──────────────────────────────────────┘
                                  ↓
                            最终答案
```

### 2.1 推理（Reasoning）

Agent 调用 LLM，在给定上下文（历史、可用工具描述、当前目标）下，输出推理过程和下一步计划。推理内容通常包括：
- 对用户意图的理解
- 对当前状态的分析
- 决定下一步调用哪个工具或直接回答

### 2.2 行动（Acting）

根据推理结果，Agent 执行一个具体动作：
- 调用一个 Skill/Tool，传入参数
- 向用户提问以获取更多信息
- 直接输出最终答案

### 2.3 观察（Observation）

执行动作后，Agent 获得外部返回结果（函数返回值、用户回复等），并将该结果作为新的“观察”添加到上下文中，供下一轮推理使用。

### 2.4 三种典型 Agent 变体

| 类型 | 工作方式 | 适用场景 |
|------|----------|----------|
| **ReAct** | 每步都输出显式的推理和行动 | 需要可解释性的复杂任务 |
| **Plan-and-Execute** | 先生成完整计划，再逐步执行 | 步骤可预知的任务（如数据流水线） |
| **Self-Ask** | 通过反复“追问自己”来检索信息 | 需要大量外部知识检索的任务 |

## 三、Agent 的两种主要实现方式

### 3.1 使用现成框架（推荐生产环境）

目前主流框架提供了开箱即用的 Agent 实现：

| 框架 | Agent 类型 | 特点 |
|------|------------|------|
| **LangChain** | `AgentExecutor` + `create_react_agent` | 生态最丰富，支持大量工具 |
| **LangGraph** | 基于状态图的 Agent | 高度可控，支持复杂循环和分支 |
| **AutoGen** | 多 Agent 协作 | 微软出品，适合多角色对话 |
| **CrewAI** | 角色化 Agent 团队 | 面向任务分解的角色协作 |
| **OpenAI Swarm** | 轻量级 Agent 编排 | 实验性质，简洁易用 |

**示例（LangChain ReAct Agent）**：

```python
from langchain.agents import create_react_agent, AgentExecutor
from langchain_openai import ChatOpenAI
from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """获取指定城市天气"""
    return f"{city}：晴天，25度"

tools = [get_weather]
llm = ChatOpenAI(model="gpt-4o")

# ReAct 模板会自动提示模型按 Thought/Action/Observation 格式输出
agent = create_react_agent(llm, tools, prompt_template)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

executor.invoke({"input": "北京天气如何？"})
```

### 3.2 手写 Agent 循环（理解原理）

如果你希望深入理解或定制行为，可以手写 Agent 主循环：

```python
import json
from openai import OpenAI

client = OpenAI()

def run_agent(user_input, tools, max_steps=5):
    messages = [{"role": "user", "content": user_input}]
    for _ in range(max_steps):
        # 调用 LLM，同时提供工具列表
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,   # 工具定义（OpenAI function calling 格式）
            tool_choice="auto"
        )
        msg = response.choices[0].message
        messages.append(msg)
        
        # 如果没有工具调用，直接返回最终回复
        if not msg.tool_calls:
            return msg.content
        
        # 执行工具调用
        for tool_call in msg.tool_calls:
            func_name = tool_call.function.name
            args = json.loads(tool_call.function.arguments)
            result = call_actual_tool(func_name, args)  # 实际执行函数
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": str(result)
            })
    return "达到最大步数，任务未完成"
```

手写循环的优势是完全可控，但需要自己处理错误、重试、多轮、工具选择策略等。

## 四、Agent 与 Skill 的协作关系

这是很多开发者困惑的地方。明确两点：

1. **Agent 是调度器，Skill 是执行器**  
   Agent 负责判断“现在应该做什么”，Skill 负责“具体怎么做”。Agent 可以调用多个 Skill，也可以根据结果决定是否继续调用。

2. **规范级 Skill 天生适合被 Agent 调用**  
   因为规范级 Skill 通过 `SKILL.md` 描述了输入输出和执行命令，Agent 只需阅读该描述，就能像调用普通函数一样使用 `subprocess` 或 API 调用来执行它。

**典型流程**：
- Agent 启动时扫描所有规范级 Skill 文件夹，读取 YAML 元数据，构建工具列表（名称 + 描述 + 输入 schema）。
- 当用户提问时，Agent 的 LLM 根据工具描述决定调用哪个 Skill。
- Agent 构造对应的命令行或 HTTP 请求，执行脚本，获得输出。
- Agent 将输出整合进对话，继续推理或直接回答。

**代码示意（Agent 调用规范级 Skill）**：

```python
import subprocess
import json

def call_skill(skill_name, **kwargs):
    # 假设 skill 的入口脚本位于 skills/{skill_name}/scripts/run.py
    script_path = f"skills/{skill_name}/scripts/run.py"
    # 将参数转为命令行参数
    cmd = ["python", script_path]
    for k, v in kwargs.items():
        cmd.extend([f"--{k}", json.dumps(v) if isinstance(v, dict) else str(v)])
    result = subprocess.run(cmd, capture_output=True, text=True)
    return json.loads(result.stdout)
```

## 五、生产级 Agent 开发最佳实践

### 5.1 可观测性与调试

- **记录完整轨迹**：保存每一步的 Thought、Action、Observation，便于回放和分析。
- **Token 消耗监控**：统计每次 LLM 调用的输入/输出 token 数。
- **工具调用耗时**：记录每个 Skill/Tool 的执行时间，发现性能瓶颈。

### 5.2 稳定性与错误处理

- **设置最大步数**：防止无限循环。
- **工具调用重试**：对于网络超时等临时错误，自动重试 2-3 次。
- **优雅降级**：当某个关键工具失败时，Agent 应能告知用户并建议替代方案，而不是直接崩溃。

### 5.3 安全性

- **权限校验**：Agent 在调用敏感工具前，应验证用户是否具有相应权限。
- **输入过滤**：对用户输入和工具参数进行清洗，防止注入攻击。
- **审计日志**：记录所有用户输入、Agent 决策、工具调用及结果，满足合规要求。

### 5.4 成本控制

- **使用小模型做路由**：用一个便宜的小模型判断用户意图，只有复杂任务才启用大模型 Agent。
- **缓存常用结果**：对于不常变化的信息（如天气、汇率），缓存一段时间。
- **合理设计提示词**：避免把整个工具列表长提示重复注入，利用 `tool_choice` 或向量检索先筛选相关工具。

## 六、从零编写一个简易 Agent（代码示例）

以下是一个**不依赖任何框架**的纯 Python Agent，能够使用规范级 Skill 来完成代码审查任务。

### 6.1 目录结构

```
my_agent/
├── agent.py
├── skills/                    # 规范级 Skill 目录
│   └── code-review-skill/     # 刚才实现的代码审查 Skill
│       ├── SKILL.md
│       ├── scripts/
│       │   └── review.py
│       └── schema/
├── config.py
└── .env
```

### 6.2 Agent 实现 `agent.py`

```python
import os
import json
import subprocess
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# 扫描 skills 目录，构建工具描述列表（供 LLM 选择）
def discover_skills(skills_dir="skills"):
    tools = []
    for skill_name in os.listdir(skills_dir):
        skill_path = os.path.join(skills_dir, skill_name)
        if not os.path.isdir(skill_path):
            continue
        # 读取 SKILL.md 获取元数据（简化版：只读 YAML 头部）
        with open(os.path.join(skill_path, "SKILL.md"), "r") as f:
            content = f.read()
        # 非常简化的 YAML 提取，生产环境请用库
        import re
        match = re.search(r"description:\s*(.+)", content)
        desc = match.group(1) if match else skill_name
        # 构造 OpenAI function calling 格式
        tools.append({
            "type": "function",
            "function": {
                "name": skill_name,
                "description": desc,
                "parameters": {
                    "type": "object",
                    "properties": {
                        "code": {"type": "string", "description": "代码内容"},
                        "language": {"type": "string", "enum": ["python", "javascript", "java", "go"]}
                    },
                    "required": ["code", "language"]
                }
            }
        })
    return tools

def call_skill(skill_name, **kwargs):
    # 根据 skill_name 找到对应的入口脚本
    script_path = f"skills/{skill_name}/scripts/review.py"
    cmd = ["python", script_path]
    for k, v in kwargs.items():
        cmd.extend([f"--{k}", str(v)])
    result = subprocess.run(cmd, capture_output=True, text=True)
    try:
        return json.loads(result.stdout)
    except:
        return {"error": result.stderr or result.stdout}

def run_agent(user_input, max_steps=5):
    tools = discover_skills()
    messages = [{"role": "user", "content": user_input}]
    step = 0
    while step < max_steps:
        step += 1
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
            tool_choice="auto"
        )
        msg = response.choices[0].message
        messages.append(msg)
        if not msg.tool_calls:
            # 最终答案
            return msg.content
        # 执行所有工具调用
        for tc in msg.tool_calls:
            skill_name = tc.function.name
            args = json.loads(tc.function.arguments)
            result = call_skill(skill_name, **args)
            messages.append({
                "role": "tool",
                "tool_call_id": tc.id,
                "content": json.dumps(result, ensure_ascii=False)
            })
    return "达到最大步数，任务未完成。"

if __name__ == "__main__":
    user_input = "审查以下 Python 代码的安全性：\nimport os\nos.system('rm -rf /')"
    answer = run_agent(user_input)
    print("Agent 回答：", answer)
```

这个简易 Agent 演示了核心思想：**发现 Skill → 提供工具列表给 LLM → 循环执行工具调用 → 返回最终答案**。生产环境建议使用 LangGraph 等成熟框架。

## 七、Agent 的未来趋势

1. **多 Agent 协作**：不同 Agent 扮演不同角色（产品经理、开发、测试），通过对话协作完成复杂项目。
2. **自主 Skill 编写**：Agent 能够根据任务需求，动态生成新的 Skill 代码并注册使用。
3. **长期记忆与经验学习**：Agent 记住过去的成功路径，在相似任务中直接复用，提高效率。
4. **端侧 Agent**：小参数模型 + 本地工具，在手机、PC 上运行个人助理。

---

## 八、总结

- **Agent 是自主决策大脑**，Skill 是具体能力模块。
- **Agent 的核心模式是 ReAct**：推理 → 行动 → 观察，循环迭代。
- **开发 Agent** 有两种方式：使用框架（LangChain/LangGraph）或手写循环。
- **Agent 与规范级 Skill 配合**：Agent 通过扫描 `SKILL.md` 发现能力，通过执行命令调用脚本，实现框架无关的扩展。
- **生产级要点**：可观测性、错误处理、安全审计、成本控制。

掌握 Agent 编写是构建大模型应用的终极一步。建议先从框架示例开始，逐步理解底层原理，再根据业务需求定制自己的 Agent 架构。
