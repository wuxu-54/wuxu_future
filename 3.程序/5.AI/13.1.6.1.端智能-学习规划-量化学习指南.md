# 量化完全指南（纯工程落地视角 · 适配你的MNN学习目标）

先给你吃定心丸：**完全不用懂算法、不用看数学公式**。你可以把量化理解成「模型的微损压缩工具」，就像你给图片做WebP压缩、给APK做资源压缩一样——目标是用可接受的微小精度损失，换更小的体积、更快的推理速度、更低的内存占用和功耗。

所有底层计算、参数推导、算子适配，MNN工具链都已经封装好了。你**只需要知道选哪种量化、怎么跑命令、怎么验收效果、出问题怎么调**，全程不用碰算法原理。

---

## 一、量化对你的核心价值（直接看收益）

量化是端侧落地的必做步骤，没有量化，大多数模型在手机上要么跑不动、要么占空间太大、要么发热严重。以你项目里的模型为例，量化前后的直观收益：

| 指标 | 原始FP32（32位浮点数） | INT8量化（8位整数） | 4bit量化（大模型用） |
|------|------------------------|---------------------|----------------------|
| 模型文件体积 | 基准（如YOLOv8n约6MB） | 减少75%（约1.5MB） | 减少87.5%（约750KB） |
| 推理内存占用 | 基准 | 减少70%~75% | 减少85%左右 |
| 中端手机推理速度 | 基准（如YOLOv8n约180ms） | 提升2~4倍（约45ms） | 提升3~6倍 |
| CPU占用/功耗 | 高 | 降低50%+ | 降低更多 |

核心逻辑：神经网络对微小数值误差有很强的鲁棒性，把高精度浮点数换成低精度整数，用户几乎感知不到差异，但硬件计算效率会大幅提升——整数运算比浮点运算更快，也更省电。

## 二、工程上只用懂这3种量化（覆盖你所有项目）

不用管学术上的十几种量化分类，你做端侧落地，只需要掌握3种就够了，分别对应CV、语音、大模型三类场景。

### 1. 静态INT8量化（CV模型首选，你的YOLO用这个）

#### 大白话定义

提前用一批真实业务图片「校准」模型，把权重和推理时的中间数值全部提前转换成INT8整数，算好固定的转换参数。推理时直接用整数计算，全程不用动态转格式，速度最快、功耗最低。

#### 核心特点

- ✅ 速度最快、功耗最低，INT8是移动端CPU/NPU的原生支持格式
- ✅ 精度损失最小，做好了精度下降能控制在1%以内
- ❌ 需要准备校准数据集，操作稍麻烦一点

#### 适用场景

所有实时CV模型：目标检测、图像分类、OCR、人像分割等

#### 你的项目对应

YOLOv8家电检测、家电状态识别，**必须用静态INT8**

### 2. 动态INT8量化（NLP/语音快速落地，你的Whisper用这个）

#### 大白话定义

只把模型的固定权重提前量化成INT8，推理时的中间数值还是浮点数，边算边动态转换。

#### 核心特点

- ✅ 实现最简单，**不需要校准数据集**，一行命令搞定
- ✅ 模型体积减小75%，效果和静态差不多
- ❌ 速度比静态量化慢一些（因为要动态转格式）

#### 适用场景

语音模型、NLP小模型、快速原型验证

#### 你的项目对应

Whisper-Tiny离线语音识别，**用动态量化足够，省事性价比高**

### 3. 4bit权重量化（端侧大模型专属，你的Qwen2用这个）

#### 大白话定义

把大模型的权重压缩到4位整数，极致减小体积和内存占用，是大模型能装进手机内存的核心手段。激活值一般保留FP16，保证精度。

#### 核心特点

- ✅ 体积极小，1.5B参数模型从6GB压到不到1GB
- ✅ 内存占用极低，中端手机也能跑起来
- ❌ 精度损失比INT8大一点，但大模型参数多，体感不明显

#### 适用场景

所有端侧大语言模型、多模态大模型

#### 你的项目对应

Qwen2-1.5B智能家居大模型，**必须用4bit量化，否则手机装不下也跑不动**

> 补充一个不用碰的概念：量化感知训练（QAT）。这是算法工程师的活，需要改训练代码，在训练时模拟量化误差。95%的场景静态量化都能满足，实在精度掉得太多，优先换更大一点的模型（比如v8n换v8s），性价比远高于搞QAT。

## 三、MNN量化实操：复制命令就能跑

所有操作都用MNN官方的`MNNConvert`工具，不用写代码，传参数就行。

### 前置准备

1. 下载MNN官方工具包，拿到`MNNConvert`可执行文件
2. 准备好原始ONNX模型（先做onnxsim简化，再量化）

---

### 1. 静态INT8量化（YOLO家电检测用）

#### 第一步：准备校准集

这是静态量化唯一需要你做的准备，非常简单：

- 准备**200~500张真实业务场景的图片**（就是你线上用户会拍到的家电场景图，不要用网图通用图）
- 不需要标注，只要图片就行
- 图片要覆盖不同光照、角度、距离，和真实使用场景越像越好
- 生成一个图片路径列表`calib_list.txt`，每行一个图片路径

#### 第二步：执行量化命令

```bash
./MNNConvert -f ONNX \
  --modelFile yolov8n_simplified.onnx \       # 输入：简化后的ONNX模型
  --MNNModel yolov8n_int8.mnn \              # 输出：量化后的MNN模型
  --bizCode haier \                          # 业务标识，随便写
  --quantType static \                       # 量化类型：静态量化
  --calibrationData calib_list.txt \         # 校准图片列表
  --calibrationSize 200 \                    # 用多少张图片校准，200足够
  --weightQuantBits 8 \                      # 权重量化位数：8位
  --featureQuantBits 8                       # 激活值量化位数：8位
```

运行完直接得到量化好的`.mnn`模型，拿来就能部署。

---

### 2. 动态INT8量化（Whisper语音用）

更简单，不需要校准集，一行命令搞定：

```bash
./MNNConvert -f ONNX \
  --modelFile whisper-tiny.onnx \
  --MNNModel whisper-tiny_int8.mnn \
  --bizCode haier \
  --quantType dynamic \                      # 量化类型：动态量化
  --weightQuantBits 8
```

---

### 3. 大模型4bit量化（Qwen2-1.5B用）

用MNN-LLM专属的转换工具，直接把HuggingFace模型转成4bit MNN格式：

```bash
python convert.py \
  --model_path Qwen2-1.5B-Instruct \         # 原始大模型路径
  --output_path qwen2-1.5b_4bit.mnn \       # 输出MNN模型
  --quant_bit 4 \                            # 量化位数：4位
  --quant_method AWQ                         # 量化算法：AWQ（精度最好的4bit算法）
```

> 你甚至不用自己转，MNN官方已经提前转好了很多主流大模型的4bit版本，直接下载用就行。

## 四、量化完怎么验收（工程标准，不用算法知识）

量化完不能直接上线，必须做两步验收：精度验收 + 性能验收，都有明确的工程标准。

### 1. 精度验收：有没有掉点

#### 验收方法

1. 准备1000张左右的标注测试集（和业务场景一致）
2. 分别用原始FP32模型和量化后INT8模型跑一遍测试集
3. 对比核心指标：YOLO看mAP/准确率，语音看识别准确率，大模型看人工评估通顺度

#### 合格标准

- 优秀：精度下降 < 1%，用户完全感知不到，可直接上线
- 可接受：精度下降 1%~2%，对业务影响很小，可上线
- 不合格：精度下降 > 2%，需要排查优化，不能上线

#### 工具

MNN自带模型对比工具，一键对比两个模型的输出差异：

```bash
./MNNCompare --modelA yolov8n.mnn --modelB yolov8n_int8.mnn --input test.jpg
```

### 2. 性能验收：有没有达到预期

直接在目标手机上测四个核心指标，和FP32版本对比：

| 指标 | 测试工具 | 合格标准 |
|------|----------|----------|
| 模型文件体积 | 直接看文件大小 | INT8减小≥70%，4bit减小≥85% |
| 单帧推理速度 | MNN Profiler / 代码打时间戳 | INT8提速≥2倍，4bit提速≥3倍 |
| 内存峰值 | Android Studio Profiler | 减小≥60% |
| CPU占用 / 功耗 | PerfDog | 降低≥40% |

#### 参考值（你的项目）

- YOLOv8n INT8：中端手机推理 < 50ms，内存 < 5MB
- Whisper-Tiny INT8：单句推理 < 400ms
- Qwen2-1.5B 4bit：旗舰机解码速度 > 15 tokens/s，内存 < 1GB

## 五、量化后精度掉了？按这个步骤排查（全是工程手段）

按优先级从高到低排，90%的问题前两步就能解决：

### 第一步：先查校准集（最常见原因）

- 是不是用了通用网图、风景图，没用真实业务场景图？
  → 解决：换成和线上场景一致的实拍图，200张足够
- 是不是场景覆盖不全？比如只有白天图没有晚上图？
  → 解决：补充不同光照、角度、距离的图片

### 第二步：查预处理对齐

端侧推理的预处理逻辑，和量化时的预处理逻辑不一致，是第二大常见原因：

- 图片通道顺序是不是对的（RGB/BGR搞反了？）
- 归一化参数是不是一致（除以255了吗？均值方差对吗？）
- 缩放方式是不是一致（是保持宽高比的Letterbox，还是直接拉伸？）
  → 解决：严格对齐预处理逻辑，逐像素对比输入数值

### 第三步：调整量化策略

- 不要全量化所有层，**关键输出层保留FP16精度**
  比如YOLO的检测头、大模型的输出层，这些层对精度敏感，量化容易掉点，单独设置不量化，主干网络继续用INT8，体积增加很少，精度回升明显。
- 动态量化换静态量化，静态量化精度更高

### 第四步：换思路，不要死磕量化

如果以上都试了还是不行，优先换更大一号的轻量模型，比如从YOLOv8n换成YOLOv8s，再做量化。
> 换模型带来的精度提升，远大于你花几周抠量化细节的收益，工程上性价比最高。

### 终极方案（基本用不到）

找算法工程师配合做量化感知训练（QAT），这是算法的活，你不用碰。

## 七、工程必知的踩坑点

1. **不是位数越低越好**
   CV模型老老实实INT8，用INT4精度会崩；只有大模型才适合4bit。不要为了追求体积盲目降位数。

2. **校准集不能瞎凑**
   用通用ImageNet图片做校准，量化后在家电场景精度会掉很多。校准集一定要和真实业务场景一致，这是成本最低、收益最高的优化点。

3. **硬件加速要匹配**
   不是所有量化格式都能走NPU加速。比如高通NNAPI对INT8支持最好，4bit大模型很多NPU还不支持，只能跑CPU。不匹配的话会自动回退到CPU，速度反而更慢。

4. **模型改了必须重新量化**
   模型结构、权重调整后，不能复用旧的量化参数，必须重新跑量化、重新验收。

5. **不要量化所有层**
   检测头、后处理、输出层这些对精度敏感的层，保留FP16效果更好，体积增加可以忽略不计。
