# LangSmith 1.0 完整指南：AI智能体的全生命周期工程平台

**一句话定义**：LangSmith是**LangChain官方推出的框架无关AI智能体工程平台**，覆盖从开发调试、测试评估到生产监控的全生命周期。它解决了LLM应用"黑盒不可见、效果不可测、故障难排查"的核心痛点，是将AI智能体从Demo推向生产的必备工具。截至2026年5月，最新版本为v0.12.65，服务全球7万+开发者和5000+企业客户。

## 一、核心定位与价值

### 1.1 解决的行业痛点

传统软件的可观测性工具（Prometheus、Grafana）完全不适用于LLM应用，因为：

- **输出不确定性**：LLM的错误不是显式的崩溃，而是幻觉、逻辑错误、回答不相关
- **执行动态性**：智能体的执行路径由模型实时决定，无法预先规划
- **多步复杂性**：复杂Agent包含数十步工具调用、检索和推理，单步错误会导致全局失败
- **效果主观性**："回答好不好"没有统一的客观标准

LangSmith的核心价值在于**将AI智能体从"概率性黑盒"转化为"可观测、可量化、可迭代的工程系统"**。

### 1.2 与LangChain生态的关系

LangSmith不是LangChain或LangGraph的替代品，而是**互补的工程化基础设施**：

- **LangChain**：提供模块化组件（模型、工具、检索）
- **LangGraph**：提供智能体编排能力（状态、循环、多智能体）
- **LangSmith**：提供观测、评估、监控和部署能力

三者共同构成了完整的AI智能体开发栈：

```
AI应用 = LangChain组件 + LangGraph编排 + LangSmith工程化
```

### 1.3 框架无关性

虽然由LangChain团队开发，但LangSmith**完全框架无关**：

- 原生支持LangChain、LangGraph、LlamaIndex、CrewAI、AutoGen
- 支持纯OpenAI SDK、Anthropic SDK、Google Gemini SDK
- 提供Python、TypeScript、Go、Java多语言SDK
- 支持OpenTelemetry标准，可与现有可观测性系统集成

## 二、整体架构

LangSmith采用**云原生微服务架构**，分为客户端SDK和服务端两大部分：

### 2.1 客户端SDK

- 轻量级，低侵入性，仅需设置2个环境变量即可自动追踪
- 支持同步/异步数据采集，批量上传
- v0.3+版本采用gRPC流式传输，端到端延迟<100ms，CPU开销<1.2%
- 本地缓存机制，网络中断时不会丢失数据

### 2.2 服务端架构

| 组件 | 职责 |
|------|------|
| **前端服务** | 提供Web UI，处理用户交互和API路由 |
| **核心后端** | 处理CRUD请求，执行业务逻辑 |
| **平台后端** | 处理高并发的追踪数据 ingestion |
| **消息队列** | Kafka，异步处理追踪数据和评估任务 |
| **存储层** | ClickHouse（追踪数据）、PostgreSQL（元数据）、Redis（缓存） |
| **ACE后端** | 安全沙箱，执行自定义评估代码和工具 |
| **Playground服务** | 转发模型请求，支持在线提示词调试 |

### 2.3 数据流向

1. 应用运行时，SDK自动采集每一步执行的详细数据
2. 数据通过gRPC流式传输到LangSmith服务端
3. 服务端异步处理数据，生成追踪树和指标
4. 数据存储到ClickHouse和PostgreSQL
5. 用户通过Web UI查看、分析和评估数据

## 三、七大核心功能详解

### 3.1 全链路追踪（Tracing）：智能体的"行车记录仪"

这是LangSmith最基础也是最核心的功能，自动记录智能体执行的每一个细节。

**追踪内容**：

- 所有LLM调用的输入、输出、Token用量、延迟、模型参数
- 所有工具调用的参数、返回结果、执行时间
- RAG系统的检索查询、检索到的文档片段、相似度分数
- LangGraph的状态变化、节点执行顺序、条件分支决策
- 多智能体之间的消息传递和交互过程

**可视化展示**：

- 层级化树状结构，清晰展示执行流程
- 时序流视图，直观看到各步骤的时间分布
- 一键跳转到任意步骤，查看完整的输入输出
- 支持搜索和过滤，快速定位特定类型的调用

**AI辅助调试**：

- **Polly助手**：内置AI助手，自动分析复杂追踪，用自然语言总结执行过程，指出潜在问题
- **Insights Agent**：自动分析大量追踪数据，发现常见失败模式和性能瓶颈

**示例：LangGraph追踪**

```
📁 总任务：查询2024年诺贝尔物理学奖得主年龄 (总耗时4.2s, 总Token 3200)
├── 🤖 agent_node (思考) 0.8s, 800 token
│   Input: "2024年诺贝尔物理学奖得主是谁？他们的年龄分别是多少？"
│   Output: 决定调用search工具查询获奖者
├── 🛠️ tools_node (行动) 1.5s, 0 token
│   Tool: search["2024 Nobel Prize in Physics winners"]
│   Output: "获奖者是John Hopfield和Geoffrey Hinton"
├── 🤖 agent_node (思考) 0.6s, 600 token
│   Output: 决定调用search工具查询两人的出生日期
├── 🛠️ tools_node (行动) 1.3s, 0 token
│   Tool: search["John Hopfield Geoffrey Hinton date of birth"]
│   Output: "John Hopfield生于1933年7月15日，Geoffrey Hinton生于1947年12月6日"
└── 🤖 agent_node (思考) 0.5s, 1800 token
    Output: 计算年龄并生成最终答案
```

### 3.2 评估体系（Evaluation）：量化智能体效果

LangSmith提供了业界最完整的评估解决方案，支持从开发到生产的全流程评估。

#### 3.2.1 离线评估（Offline Evaluation）

- **数据集管理**：创建和管理测试数据集，支持从CSV、JSON导入，或从生产追踪中导出
- **多维度评估器**：
  - 预构建评估器：幻觉检测、回答相关性、事实准确性、有害性检测
  - 自定义评估器：支持Python代码、LLM-as-judge、多轮对话评估
  - 复合评估器：将多个评估器组合成综合评分
- **对比实验**：同时运行多个版本的智能体，在同一个数据集上进行对比，直观看到效果差异
- **A/B测试**：支持提示词、模型、参数的A/B测试，量化改进效果

#### 3.2.2 在线评估（Online Evaluation）

- 实时评估生产环境中的每一次用户交互
- 自动将低质量的交互标记出来，供人工审核
- 持续监控智能体的质量变化趋势，及时发现性能退化
- 支持基于评估结果的自动告警

#### 3.2.3 人工反馈（Human Feedback）

- 标注队列：自动将需要人工审核的追踪分配给专家
- 细粒度标注：支持对整个回答、单个步骤、甚至特定片段进行评分和评论
- 校准机制：将LLM-as-judge的评分与人类评分对齐，提高自动评估的准确性
- 反馈闭环：将人工标注的数据自动加入测试数据集，用于后续的离线评估

### 3.3 提示词管理（Prompt Hub）：团队协作的提示词仓库

- **版本控制**：记录提示词的每一次修改，支持回滚到任意历史版本
- **标签和分组**：按项目、功能、模型对提示词进行分类管理
- **在线调试**：在Playground中直接测试提示词，对比不同模型和参数的输出
- **部署与回滚**：一键部署提示词到生产环境，出现问题时一键回滚
- **权限管理**：细粒度的访问控制，支持团队协作

### 3.4 全栈成本追踪（Unified Cost Tracking）

2025年12月推出的重磅功能，解决了复杂Agent成本难以核算的问题：

- 自动追踪所有LLM调用的Token用量和成本，支持OpenAI、Anthropic、Gemini等主流模型
- 支持多模态Token计算和缓存命中成本
- 支持手动提交自定义成本数据，覆盖工具调用、检索、数据库查询等所有环节
- 提供按项目、按用户、按功能的成本分解报表
- 支持自定义模型定价，适配企业内部的成本核算体系

### 3.5 生产监控与告警

- **实时仪表盘**：展示核心指标（请求量、延迟、错误率、Token用量、成本）
- **自定义仪表盘**：拖拽式创建个性化仪表盘，关注特定业务指标
- **智能告警**：基于阈值、异常检测或评估结果触发告警，支持邮件、Slack、Webhook
- **SLO管理**：定义服务水平目标，监控SLO达成情况
- **根因分析**：告警时自动关联相关追踪，帮助快速定位问题根源

### 3.6 LangSmith Engine：AI驱动的智能体自动优化

2026年5月13日发布的革命性功能，彻底改变了智能体的迭代方式：

- **自动问题发现**：持续监控生产追踪，自动聚类相似的失败案例，生成命名问题
- **根因诊断**：分析失败案例，结合代码库自动诊断问题根源
- **自动生成修复**：生成提示词修改、代码修复或新的评估器
- **自动测试**：在测试数据集上运行修复后的版本，验证效果
- **反馈闭环**：将修复后的案例加入评估套件，防止回归

**工作流程**：

```
生产追踪 → 自动聚类失败案例 → 诊断根因 → 生成修复PR → 自动测试 → 人工审核合并
```

LangSmith Engine将智能体的迭代效率提升了10倍以上，让团队从"手动读Trace找问题"中解放出来。

## 四、快速上手：5分钟集成LangSmith

### 4.1 安装与配置

```bash
pip install langsmith langchain-openai
```

设置环境变量：

```python
import os

os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_API_KEY"] = "ls__your_api_key_here"
os.environ["LANGCHAIN_PROJECT"] = "my-first-project"  # 项目名称
```

**无需修改任何业务代码**，所有LangChain和LangGraph的执行都会自动被追踪。

### 4.2 运行一个简单的智能体

```python
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langgraph.prebuilt import create_react_agent

# 定义工具
@tool
def add(a: int, b: int) -> int:
    """将两个整数相加"""
    return a + b

# 初始化模型和智能体
model = ChatOpenAI(model="gpt-4o", temperature=0)
agent = create_react_agent(model, [add])

# 运行智能体
result = agent.invoke({"messages": [("human", "3加5等于多少？再乘以2是多少？")]})
print(result["messages"][-1].content)
```

运行后，打开LangSmith控制台（<https://smith.langchain.com），即可看到完整的追踪记录。>

### 4.3 创建并运行一个评估实验

```python
from langsmith import Client
from langsmith.evaluation import evaluate

# 初始化客户端
client = Client()

# 创建测试数据集
dataset = client.create_dataset(
    dataset_name="数学计算测试",
    description="测试智能体的数学计算能力"
)

# 添加测试用例
client.create_examples(
    inputs=[{"question": "3加5等于多少？"}],
    outputs=[{"answer": "8"}],
    dataset_id=dataset.id
)

# 定义评估器
def accuracy_evaluator(run, example):
    return {"score": 1 if run.outputs["answer"] == example.outputs["answer"] else 0}

# 运行评估
evaluate(
    agent.invoke,
    data=dataset.name,
    evaluators=[accuracy_evaluator]
)
```

## 五、与主流LLMOps工具的对比

| 对比维度 | LangSmith | LangFuse | Arize Phoenix |
|---------|-----------|----------|---------------|
| **开源性** | 闭源SaaS，自托管需企业版 | 完全开源（MIT） | 开源核心版，企业版付费 |
| **生态集成** | 与LangChain/LangGraph深度原生集成 | 框架无关 | 框架无关 |
| **评估能力** | 最强，支持离线/在线/多轮/人工反馈 | 基础，需自定义 | 中等，侧重模型监控 |
| **提示词管理** | 完整，支持版本控制和部署 | 完整 | 不支持 |
| **成本追踪** | 全栈，支持LLM/工具/检索 | 仅LLM | 仅LLM |
| **多智能体追踪** | 原生支持 | 基础支持 | 不支持 |
| **LangSmith Engine** | 有 | 无 | 无 |
| **数据主权** | 自托管需企业版 | 完全自托管 | 完全自托管 |
| **适用场景** | LangChain生态团队，对评估要求高 | 开源优先，数据主权要求高 | 侧重模型监控和漂移检测 |

**选型建议**：

- 如果你主要使用LangChain和LangGraph构建智能体，**LangSmith是首选**
- 如果你需要完全开源和数据主权，选择LangFuse
- 如果你主要关注模型性能监控和漂移检测，选择Arize Phoenix

### 6.4 生产环境运维

- 实时监控智能体的性能、成本和质量
