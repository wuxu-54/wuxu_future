# PQ乘积量化完全指南：原理、对比与工业界实践

**乘积量化（Product Quantization, PQ）** 是2011年由Herve Jegou等人提出的革命性向量压缩与检索算法，它彻底解决了高维向量在大规模场景下的存储和计算瓶颈。目前，PQ及其变种（IVF-PQ、OPQ）是所有主流向量数据库（FAISS、Milvus、Pinecone、Qdrant）的核心技术，支撑着全球90%以上的亿级向量检索系统。

## 一、核心本质与直观理解

### 1.1 解决的核心问题

高维向量检索的最大痛点是**"存储爆炸"和"计算爆炸"**：

- 一个768维的float32向量占用 **3072字节（3KB）**
- 1亿个这样的向量占用 **300GB** 内存
- 暴力检索一次需要 **768亿次浮点运算**

传统方法要么精度损失太大，要么压缩比不够。PQ通过"分而治之"的思想，在**压缩比和检索精度之间找到了完美的平衡点**。

### 1.2 通俗类比：快递打包法

想象你有一个768厘米长的精密仪器（高维向量），直接运输成本极高。PQ的做法是：

1. **拆分**：把长仪器平均切成16段，每段48厘米（子向量）
2. **标准化**：为每一段制作256种标准包装盒（聚类中心）
3. **编码**：把每一段放进最匹配的标准盒，用盒号（0-255）代替实物
4. **运输**：原来需要运768个零件，现在只需要运16个盒号（16字节）

最终效果：**3KB的向量被压缩成16字节，压缩比192:1**，同时还能保持90%以上的检索精度。

### 1.3 核心公式

```
原始向量：v ∈ R^d
拆分：v = [v₁, v₂, ..., v_M]，其中每个v_i ∈ R^(d/M)
量化：q(v_i) = c_{i,k_i}，其中c_{i,k_i}是第i个子空间的第k_i个聚类中心
编码：code(v) = [k₁, k₂, ..., k_M]，每个k_i ∈ {0, 1, ..., 2^nbits - 1}
```

## 二、PQ的完整工作原理

PQ分为两个独立阶段：**离线训练阶段**和**在线查询阶段**。

### 2.1 阶段一：离线训练（生成码本）

这是PQ最耗时但只需要做一次的步骤，目标是学习每个子空间的聚类中心（码本）。

**步骤详解**：

1. **向量拆分**：将所有训练向量平均拆分为M个低维子向量
   - 例：768维向量拆分为M=16个子向量，每个48维
2. **子空间聚类**：对每个子空间独立运行K-means聚类
   - 例：每个子空间生成k=256个聚类中心（nbits=8）
3. **生成码本**：保存M×k个聚类中心，形成全局码本
   - 例：16×256=4096个聚类中心，仅占用4096×48×4=768KB内存

**关键洞察**：

- 不是对整个向量空间聚类，而是对每个子空间分别聚类
- 总聚类中心数是M×k，而不是k^M（这是PQ能实现高压缩比的关键）
- 训练样本数建议至少为k×39，否则聚类中心会不稳定

### 2.2 阶段二：在线查询（距离查表法）

这是PQ最巧妙的部分，它将高维向量的距离计算转化为**查表+加法**操作，速度提升数十倍。

**传统距离计算**：

```
距离(q, v) = Σ_{i=1}^d (q_i - v_i)²  # 需要d次乘法和加法
```

**PQ非对称距离计算（ADC）**：

1. **查询向量拆分**：将查询向量q拆分为与训练时相同的M个子向量
2. **预计算距离表**：对每个子向量q_i，计算它与该子空间所有k个聚类中心的距离
   - 得到一个M×k的距离表D，其中D[i][j] = 距离(q_i, c_{i,j})
3. **查表求和**：对于每个数据库向量的编码[k₁, k₂, ..., k_M]，总距离为：

   ```
   距离(q, v) ≈ Σ_{i=1}^M D[i][k_i]  # 只需要M次查表和加法
   ```

**速度对比**：

- 768维向量，M=16
- 传统计算：768次运算
- PQ计算：16次运算
- **速度提升48倍**

## 三、工业界标准：IVF-PQ组合

纯PQ虽然压缩比高，但仍然需要遍历所有数据库向量的编码。当向量规模超过1000万时，遍历开销变得不可接受。因此，工业界几乎总是将**倒排文件（IVF）与PQ结合使用**，形成**IVF-PQ**架构。

### 3.1 IVF-PQ的两级检索架构

```
┌─────────────────┐    粗检索    ┌─────────────────┐    精检索    ┌─────────────────┐
│ 查询向量q       │ ──────────> │ 找到最近的nprobe │ ──────────> │ 对候选向量做PQ  │
│                 │             │ 个聚类中心       │             │ 距离计算        │
└─────────────────┘             └─────────────────┘             └─────────────────┘
                                      ↓
                          搜索范围缩小nlist/nprobe倍
```

**工作流程**：

1. **粗量化**：将整个向量空间划分为nlist个大簇（通常用K-means）
2. **存储**：每个向量先找到所属的大簇，然后将残差向量（向量-簇中心）进行PQ编码
3. **查询**：
   - 第一步：找到与查询向量最近的nprobe个大簇
   - 第二步：只对这nprobe个簇内的向量进行PQ距离计算
   - 第三步：返回距离最小的top-k个结果

### 3.2 IVF-PQ的核心优势

- **搜索范围大幅缩小**：nlist=4096, nprobe=20时，搜索范围缩小200倍
- **内存占用极低**：1亿个768维向量仅占用约1.6GB内存（IVF-PQ-16）
- **构建速度快**：比HNSW快5-10倍，适合动态更新频繁的场景
- **GPU友好**：大batch查询时能打满GPU的HBM带宽，速度优势更明显

## 四、PQ的主要变种与优化

### 4.1 OPQ（优化乘积量化）

**问题**：原始PQ假设子向量之间相互独立，但实际数据中往往存在相关性，导致量化误差增大。

**解决方案**：在PQ之前先对向量做一个正交线性变换，使得变换后的子向量之间相关性最小。

**效果**：在不增加任何计算和存储开销的情况下，召回率提升5%-10%，是工业界的标配优化。

### 4.2 PQFastScan

**问题**：普通PQ的距离计算虽然只有M次加法，但内存访问模式不规则，无法有效利用CPU的SIMD指令。

**解决方案**：将编码按字节重新排列，使得相同位置的字节连续存储，从而实现SIMD并行计算。

**效果**：在FAISS中，PQFastScan比普通PQ快3-4倍，同时保持相同的精度。

### 4.3 IVF-PQ-Refine

**问题**：PQ是有损压缩，距离计算存在误差，导致召回率下降。

**解决方案**：先用IVF-PQ快速找到top-k×r个候选（r=3-10），然后用原始向量重新计算距离，精排得到top-k个结果。

**效果**：在增加少量延迟的情况下，召回率提升到接近暴力检索的水平，是生产环境的标准做法。

## 五、与其他量化方法的对比

向量量化主要有三种主流方法：**标量量化（SQ）、乘积量化（PQ）、二值量化（BQ）**。

| 量化方法 | 压缩比（768维） | 精度损失 | 计算复杂度 | 核心思想 | 适用场景 |
|----------|------------------|----------|------------|----------|----------|
| 无量化（FP32） | 1:1 | 无 | 高 | 存储原始向量 | 万级以下小数据集 |
| 标量量化SQ8 | 4:1（768字节） | 极低 | 低 | 每个维度单独映射到int8 | 内存受限但要求高精度 |
| 标量量化SQ4 | 8:1（384字节） | 低 | 低 | 每个维度单独映射到int4 | 极度内存受限 |
| 乘积量化PQ-16 | 192:1（16字节） | 中 | 中 | 分块聚类量化 | 千万到亿级大规模数据集 |
| 乘积量化PQ-8 | 384:1（8字节） | 中高 | 中 | 分块聚类量化 | 亿级以上超大规模数据集 |
| 二值量化BQ | 32:1（96字节） | 高 | 极低 | 每个维度映射到0或1 | 十亿级以上，精度要求不高 |

**关键结论**：

- PQ的压缩比远高于标量量化，同时精度损失更小
- 二值量化压缩比最高，但精度损失太大，只适合特定场景
- PQ是唯一能在**10亿级向量规模**下保持可用精度的量化方法

### 6.2 IVF-PQ vs HNSW：工业界最常见的选择困境

这是向量数据库领域最经典的争论，两者没有绝对的优劣，只有适用场景的不同。

| 维度 | IVF-PQ | HNSW |
|------|--------|------|
| **核心优势** | 内存占用极低，构建速度快，动态更新好，GPU加速明显 | 检索速度快，精度高，参数调优简单 |
| **核心劣势** | 高维场景下精度下降，延迟稳定性稍差 | 内存占用极高，构建速度慢，动态更新差 |
| **内存放大率** | 0.05×（原始向量） | 4×（原始向量） |
| **1亿向量内存** | 1.6GB | 120GB |
| **构建时间** | 10分钟 | 2小时 |
| **动态更新** | 支持实时增删，无需重建索引 | 增删改需要加锁，吞吐量低 |
| **GPU友好性** | 极好，大batch速度提升100倍 | 一般，图结构难以并行 |
| **适用场景** | 亿级以上超大规模数据，内存受限，动态更新频繁，离线批量检索 | 百万到千万级数据，内存充足，高并发低延迟要求，静态数据集 |

**工业界真相**：

- 很多人误以为HNSW比IVF-PQ快，但这是在**内存足够**的前提下
- 当数据规模超过1亿时，HNSW无法全部放入内存，性能会急剧下降
- 而IVF-PQ即使在磁盘上也能保持不错的性能，因为它的索引极小
- 因此，**Elasticsearch、Milvus、阿里云OpenSearch等企业级产品默认使用IVF-PQ**，而不是HNSW

## 七、PQ参数调优最佳实践

IVF-PQ有四个关键参数，正确的参数调优能让性能提升数倍。

### 7.1 关键参数详解

| 参数 | 含义 | 影响 | 推荐值 | 调整策略 |
|------|------|------|--------|----------|
| **nlist** | 粗量化聚类中心数 | 越大，分桶越细，检索越快，但聚类开销越大 | `4×sqrt(N)` | 100万：4096；1000万：16384；1亿：65536 |
| **nprobe** | 查询时探查的分桶数 | 越大，召回率越高，但延迟越高 | `nlist的5%-10%` | 精度要求高：20-50；速度要求高：1-10 |
| **M** | 子空间数量 | 越大，精度越高，但压缩比越低，速度越慢 | `d/4 ~ d/16` | 768维：16；1536维：32；128维：8 |
| **nbits** | 每个子向量的量化位数 | 越大，精度越高，但压缩比越低 | 8 | 几乎所有场景都用8位（256个聚类中心） |

*数据来源：*

### 7.2 生产环境推荐配置

| 数据规模 | 推荐索引 | nlist | M | nprobe | 内存占用 |
|----------|----------|-------|---|--------|----------|
| <100万 | HNSW | - | - | ef=64 | 3GB/亿 |
| 100万-1000万 | IVF-PQ | 4096 | 16 | 20 | 1.6GB/亿 |
| 1000万-1亿 | IVF-PQ | 16384 | 16 | 20 | 1.6GB/亿 |
| >1亿 | 分布式IVF-PQ | 65536 | 32 | 30 | 3.2GB/亿 |

### 7.3 通用调优技巧

1. **先调nprobe**：这是最容易调整的参数，在运行时动态修改，不需要重建索引
2. **使用Refine机制**：设置k_factor=3-10，用少量延迟换取大幅精度提升
3. **GPU加速**：IVF-PQ在GPU上的速度是CPU的10-100倍，适合大batch查询
4. **数据分布均匀**：如果数据分布不均匀，增加nlist或使用k-means++初始化

## 八、工业界实现与应用

### 8.1 FAISS中的IVF-PQ实现（标准参考）

```python
import faiss
import numpy as np

# 向量维度
d = 768
# 粗量化聚类中心数
nlist = 4096
# 子空间数量
M = 16
# 每个子向量的量化位数
nbits = 8

# 初始化粗量化器
quantizer = faiss.IndexFlatL2(d)
# 创建IVF-PQ索引
index = faiss.IndexIVFPQ(quantizer, d, nlist, M, nbits)

# 训练索引（只需要做一次）
index.train(train_vectors)

# 添加向量
index.add(database_vectors)

# 查询
index.nprobe = 20  # 运行时调整
distances, indices = index.search(query_vectors, k=10)
```

### 8.2 主流向量数据库支持

- **Milvus**：支持IVF-PQ、HNSW-PQ，提供分布式部署

- **大规模图像检索**：Google Photos、百度图片使用PQ存储数十亿张图片特征
- **推荐系统**：淘宝、京东使用PQ存储用户和商品向量，实现实时推荐
- **RAG系统**：企业级知识库通常包含千万到亿级文档片段，IVF-PQ是唯一可行的选择

## 九、常见误区与挑战

### 9.1 常见误区

1. **误区一：PQ是一种索引结构**  
   真相：PQ是一种**向量压缩算法**，它可以和任何索引结构结合使用（IVF、HNSW、树结构等）。

2. **误区二：HNSW永远比IVF-PQ快**  
   真相：当数据规模超过1亿且内存不足时，HNSW需要频繁访问磁盘，性能会比IVF-PQ慢10倍以上。

3. **误区三：M越大越好**  
   真相：M超过d/4后，精度提升非常有限，但速度会急剧下降。

4. **误区四：PQ不适合高维向量**  
   真相：恰恰相反，向量维度越高，PQ的压缩优势越明显。1536维向量的PQ压缩比是384:1，远高于128维的32:1。

### 9.2 核心挑战

1. **训练数据代表性**：如果训练数据不能代表全量数据分布，量化误差会显著增大
2. **高维精度下降**：当维度超过2048时，PQ的精度会明显下降，需要结合PCA降维
3. **动态更新**：虽然IVF-PQ的动态更新能力比HNSW好，但频繁更新仍然会导致聚类中心漂移
4. **参数调优**：IVF-PQ的参数比HNSW多，需要根据具体数据分布进行调优
