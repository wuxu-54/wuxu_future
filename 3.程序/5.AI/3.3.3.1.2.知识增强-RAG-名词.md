# RAG系统核心名词术语完整词典

按**RAG全流程阶段**分类整理，包含所有工业界常用术语、英文缩写及通俗解释，覆盖从文档处理到生成增强的全部环节。

## 一、基础核心概念

| 术语 | 英文/缩写 | 核心解释 | 通俗比喻 |
|-----|----------|---------|---------|
| 检索增强生成 | Retrieval-Augmented Generation, RAG | 一种大模型应用架构，通过**检索外部知识库**获取相关信息，再将其与用户查询一起输入大模型生成回答，从根源上减少幻觉、解决知识过时问题 | 大模型的"开卷考试"：考试时允许翻书（知识库）找答案，而不是全靠记忆 |
| 大语言模型 | Large Language Model, LLM | 基于Transformer架构、在海量文本上预训练的深度学习模型，具备理解和生成自然语言的能力 | RAG系统的"答题人"，负责根据找到的资料组织答案 |
| 知识库 | Knowledge Base | 存储RAG系统所有外部知识的集合，通常由原始文档经过处理后转化为向量和文本数据 | 开卷考试用的"教科书和参考资料" |
| 幻觉 | Hallucination | 大模型生成的看似合理但与事实不符的内容，是大模型最核心的缺陷之一 | 答题人凭记忆瞎编了一个书上没有的答案 |
| 上下文窗口 | Context Window | 大模型一次能够处理的最大token数量，决定了可以输入给大模型的上下文长度 | 考试时答题卡的最大字数限制 |

## 二、文档处理阶段术语

| 术语 | 英文/缩写 | 核心解释 | 通俗比喻 |
|-----|----------|---------|---------|
| 文档加载 | Document Loading | 将不同格式（PDF、Word、HTML等）和来源的原始文档解析为纯文本，并提取元数据的过程 | 将不同格式的书籍扫描成可编辑的文字 |
| 文档清洗 | Document Cleaning | 去除原始文本中的噪声（页眉页脚、广告、特殊字符等）和冗余信息，提高文本质量 | 把扫描件里的水印、污渍和无关广告去掉 |
| 文档分块 | Document Chunking | 将长文本分割成大小合适的"块"（Chunk），使其既能包含完整语义，又能适配嵌入模型的输入长度限制 | 把厚书拆分成一个个独立的知识点卡片 |
| 块 | Chunk | 文档分块后得到的最小语义单元，是RAG系统检索和存储的基本单位 | 一张知识点卡片，上面写着一个完整的小知识点 |
| 分块大小 | Chunk Size | 每个Chunk包含的字符数或token数，通常为200-1000个token | 每张知识点卡片的字数限制 |
| 重叠分块 | Chunk Overlap | 相邻Chunk之间保留一定的重叠内容，避免语义被切断 | 相邻两张卡片重复写几个关键句子，防止知识点被拆分 |
| 语义分块 | Semantic Chunking | 根据文本的语义相似度进行分块，将语义相关的内容划分到同一个Chunk中 | 按照知识点的逻辑关系来拆分卡片，而不是简单按字数 |
| 结构分块 | Structural Chunking | 利用文档本身的结构信息（标题、章节、列表等）进行分块 | 按照书籍的章节和小标题来拆分卡片 |
| 父子分块 | Parent-Child Chunking | 将文档分成大的"父块"和小的"子块"，检索时匹配子块，返回父块给大模型 | 子块是具体的知识点，父块是包含这个知识点的完整章节 |
| 嵌入/向量化 | Embedding | 将离散的文本符号转换为连续的高维向量表示，使语义相似的文本在向量空间中距离更近 | 给每个知识点卡片生成一个唯一的"语义条形码" |
| 嵌入模型 | Embedding Model | 专门用于生成文本嵌入向量的深度学习模型 | 生成"语义条形码"的机器 |
| 向量数据库 | Vector Database | 专门用于存储和检索高维向量的数据库，支持毫秒级的相似性搜索 | 存放所有"语义条形码"和对应知识点卡片的图书馆 |
| 元数据 | Metadata | 描述文档属性的信息，如标题、作者、创建时间、页码、章节等，用于后续过滤和排序 | 知识点卡片上的备注信息，标明来自哪本书、哪一页 |

## 三、检索阶段术语

| 术语 | 英文/缩写 | 核心解释 | 通俗比喻 |
|-----|----------|---------|---------|
| 检索 | Retrieval | 根据用户查询，从知识库中找到最相关的文档块的过程 | 考试时根据题目去图书馆找相关的知识点卡片 |
| 检索器 | Retriever | 执行检索操作的组件，是RAG系统的核心组件之一 | 图书馆的图书管理员，负责帮你找书 |
| 向量检索 | Vector Retrieval | 计算查询向量与文档向量的余弦相似度，找到最相似的文档块 | 根据"语义条形码"的相似度来找卡片 |
| 稀疏向量检索 | Sparse Vector Retrieval | 基于关键词出现频率和重要性的检索方法，最经典的是BM25 | 根据题目中的关键词来找卡片 |
| BM25 | Best Match 25 | 目前最常用的稀疏向量检索算法，基于概率检索模型，效果优于传统的TF-IDF | 最经典的关键词匹配算法 |
| TF-IDF | Term Frequency-Inverse Document Frequency | 一种经典的文本权重计算方法，衡量一个词对文档的重要性 | 早期的关键词匹配算法 |
| 多路召回 | Multi-way Retrieval | 同时使用多种不同的检索策略（向量检索、BM25、元数据过滤等）召回相关文档，最大化召回率 | 同时让多个图书管理员从不同角度帮你找书，避免漏找 |
| 混合检索 | Hybrid Retrieval | 最常用的多路召回策略，结合向量检索（语义匹配）和BM25（关键词匹配）的优点 | 既看语义相似性，又看关键词匹配度 |
| 结果融合 | Result Fusion | 将多路召回得到的多个文档列表合并为一个统一的列表，同时去除重复文档 | 把多个图书管理员找到的卡片汇总到一起 |
| RRF融合 | Reciprocal Rank Fusion | 目前效果最好的结果融合算法，不需要调整参数，基于排名的倒数进行加权 | 最科学的汇总多个图书管理员结果的方法 |
| 元数据过滤 | Metadata Filtering | 在检索前或检索后，根据元数据过滤文档，缩小搜索范围 | 只找2023年之后出版的、关于人工智能的书籍 |
| 查询预处理 | Query Preprocessing | 对用户原始查询进行优化（重写、扩展、分解等），使其更适合检索 | 把口语化的题目转换成清晰、专业的检索式 |
| 查询重写 | Query Rewriting | 让LLM将模糊、口语化的查询转换为清晰、专业的检索式 | 把"大模型怎么干活"改成"大语言模型的工作原理" |
| 查询分解 | Query Decomposition | 将复杂的多问题查询分解为多个简单的子查询，分别检索 | 把"大模型是什么，怎么工作"拆成两个问题分别找答案 |
| HyDE | Hypothetical Document Embeddings | 让LLM先生成一个假设的答案文档，再用这个文档进行检索，解决语义差距问题 | 先猜一下答案可能是什么样子，再根据这个样子去找书 |

## 四、重排阶段术语

| 术语 | 英文/缩写 | 核心解释 | 通俗比喻 |
|-----|----------|---------|---------|
| 重排 | Reranking | 对召回阶段得到的候选文档列表进行更精细的相关性打分和排序，只保留最相关的几条 | 从图书管理员找到的50张卡片中，再仔细挑选出最相关的5张 |
| 重排器 | Reranker | 执行重排操作的组件，通常是交叉编码器模型 | 资深的学科老师，负责从一堆卡片中选出最贴合题目的 |
| 双编码器 | Bi-Encoder | 向量检索使用的模型架构，将查询和文档分别编码成向量后计算相似度 | 图书管理员，快速浏览卡片标题和摘要找书 |
| 交叉编码器 | Cross-Encoder | 重排使用的模型架构，将查询和文档拼接后联合编码，计算相关性得分 | 学科老师，仔细阅读每张卡片的内容，判断是否贴合题目 |
| 粗排 | Coarse Ranking | 重排的第一阶段，使用轻量级模型快速过滤掉明显不相关的文档 | 先快速翻一遍，把明显不相关的卡片扔掉 |
| 精排 | Fine Ranking | 重排的第二阶段，使用重型模型进行精细化排序 | 仔细阅读剩下的卡片，按相关性排序 |
| 终排 | Final Ranking | 重排的最后阶段，使用LLM进行最终审核，只保留最相关的几条 | 请特级老师做最后把关 |
| 上下文压缩 | Contextual Compression | 从每个相关文档中提取与查询最相关的核心片段，剔除冗余信息 | 把每张卡片中与题目无关的内容划掉，只保留关键句子 |

## 五、生成增强阶段术语

| 术语 | 英文/缩写 | 核心解释 | 通俗比喻 |
|-----|----------|---------|---------|
| 生成增强 | Generation Augmentation | 通过一系列技术手段约束大模型的行为，使其严格基于检索到的事实生成准确、忠实的回答 | 给答题人制定严格的考试规则，防止作弊和瞎编 |
| 提示词工程 | Prompt Engineering | 设计和优化输入给大模型的提示词，引导大模型生成符合要求的输出 | 给答题人写详细的考试说明和答题要求 |
| 结构化上下文 | Structured Context | 将检索到的文档块整理成包含编号、来源、内容的结构化格式，便于大模型利用和引用 | 把挑选出来的卡片按顺序整理好，每张卡片标上编号和来源 |
| 引用标注 | Citation | 要求大模型在回答中标注每个事实的来源，便于追溯和验证 | 要求答题人在每个答案后面注明来自哪张卡片 |
| 事实一致性验证 | Factual Consistency Verification | 在回答返回给用户之前，检查其是否与检索到的上下文一致，过滤幻觉 | 老师批改试卷，检查答案是否与书上的内容一致 |
| 自然语言推理 | Natural Language Inference, NLI | 判断两个句子之间的逻辑关系（蕴含、矛盾、中性）的技术，常用于事实一致性验证 | 检查答案和书上的内容是否一致，有没有矛盾 |
| 自我一致性 | Self-Consistency | 让大模型从不同角度多次回答同一个问题，然后选择最一致的一个 | 让答题人做三遍同一道题，取答案一致的结果 |
| 兜底机制 | Fallback Mechanism | 当检索不到相关信息时，明确告知用户"未找到相关内容"，而不是编造答案 | 考试时遇到不会的题，直接写"不会"，而不是瞎编 |
| 流式输出 | Streaming Output | 将大模型生成的回答逐字返回给用户，提升用户体验 | 答题人边写边给你看，而不是写完了一次性给你 |

## 六、高级RAG技术术语

| 术语 | 英文/缩写 | 核心解释 | 通俗比喻 |
|-----|----------|---------|---------|
| 分层检索 | Hierarchical Retrieval | 将文档组织成不同粒度的层次结构，先检索粗粒度的章节，再检索细粒度的段落 | 先找相关的书籍，再找相关的章节，最后找相关的句子 |
| 多向量检索 | Multi-vector Retrieval | 为每个文档块生成多个向量表示（标题、内容、摘要等），检索时同时匹配 | 给每张卡片生成多个"语义条形码"，提高找到的概率 |
| Self-RAG | Self-Retrieval Augmented Generation | 让大模型在生成过程中自主决定是否需要检索更多信息 | 答题人遇到不会的问题时，自己主动去翻书找答案 |
| GraphRAG | Graph Retrieval-Augmented Generation | 将文档中的实体和关系构建成知识图谱，基于知识图谱进行检索和推理 | 不仅能找到单个知识点，还能找到知识点之间的关系 |
| Agentic RAG | Agentic Retrieval-Augmented Generation | 将RAG与智能体技术结合，让系统能够自主规划查询、执行检索、整合信息、生成答案 | 一个会自己规划解题步骤、自己找资料、自己答题的智能助手 |
| 多模态RAG | Multimodal RAG | 支持图片、表格、音频等多模态内容的检索和生成 | 不仅能看文字书，还能看图片和表格 |

## 七、评估指标术语

| 术语 | 英文/缩写 | 核心解释 | 通俗比喻 |
|-----|----------|---------|---------|
| 召回率@K | Recall@K | 前K个检索结果中包含相关文档的比例，衡量"找得全"的能力 | 10道相关的题，你找到了8道，召回率就是80% |
| 精确率@K | Precision@K | 前K个检索结果中相关文档的比例，衡量"找得准"的能力 | 你找了10道题，其中8道是相关的，精确率就是80% |
| MRR | Mean Reciprocal Rank | 第一个相关结果排名的倒数的平均值，衡量"找得快"的能力 | 第一道相关的题出现在第2位，得分为1/2=0.5 |
| NDCG@K | Normalized Discounted Cumulative Gain | 综合考虑相关度等级和排名的指标，是评估排序质量的金标准 | 不仅看有没有找到相关的题，还看相关的题排得够不够靠前 |
| 忠实度 | Faithfulness | 衡量回答是否忠实于检索到的上下文，没有添加额外信息 | 答案中的每一句话都能在书上找到依据 |
| 相关性 | Relevance | 衡量回答是否与用户的问题相关，没有偏离主题 | 答案准确回答了用户的问题，没有答非所问 |
