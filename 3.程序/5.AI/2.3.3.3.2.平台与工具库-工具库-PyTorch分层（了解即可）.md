# PyTorch 分层结构逐层级完整释义

整体自上而下五层逻辑：**基础张量层 → 自动微分引擎层 → 神经网络组件层 → 优化更新层 → 数据与工程工具层**，外加扩展生态库。每一层依赖下一层，上层是封装、下层是底层支撑。

## 第一层：基础张量层 —— `torch` 主包（地基）

### 层级定位

整个框架最底层，所有计算的载体，对标Numpy数组，但支持GPU、梯度追踪；没有这一层，后面所有网络、求导都无法运行。

### 核心含义

Tensor（张量）是统一数据容器：标量(0维)、向量(1维)、矩阵(2维)、图像特征(3/4维)、时序/大模型高维参数全部用张量存储。

### 细分API功能拆解

1. **张量创建API**
`torch.tensor()`、`torch.zeros/ones/rand/randn`、`torch.arange`、`torch.from_numpy()`
作用：开辟内存空间，初始化数值，实现numpy与torch互通。
2. **张量属性查询API**
`.shape`/`.size()`、`.dtype`(float32/float64/int等)、`.device`(cpu/cuda)、`.requires_grad`(是否记录梯度)、`.grad`(存储梯度值)
3. **形变拼接拆分API**
`view()`/`reshape()`：重塑维度；`squeeze()`/`unsqueeze()`：增减维度；`cat()`拼接、`split()`拆分、`transpose()`/`permute()`交换轴
4. **数值数学运算API**
加减乘除、`matmul`矩阵乘法、`pow/log/sqrt/sin/cos`、`mean/sum/max/min/var`统计函数；广播机制和numpy一致
5. **设备硬件调度API**
`torch.cuda.is_available()`检测显卡；`.to(device)`/`.cuda()`/`.cpu()`张量迁移设备；`torch.cuda.empty_cache()`释放显存
6. **全局工具**
`torch.set_num_threads`设置CPU线程数、随机种子`torch.manual_seed()`保证复现

### 该层注意事项

1. `view`依赖内存连续，不连续张量要用`reshape`；
2. 整数张量默认`requires_grad=False`，做计算求导必须用浮点；
3. CPU张量和GPU张量不能直接运算，必须统一设备；
4. 原地运算符 `+=、*=` 容易破坏计算图，求导场景尽量不用。

## 第二层：自动微分引擎层 —— `torch.autograd`（动力传动系统）

### 层级定位

架在`torch`张量之上，负责**动态计算图构建+反向梯度求解**，深度学习训练的核心动力，连接张量数值与参数更新。

### 核心原理

运行代码时实时记录张量运算链路（动态图，区别TF静态图）；标记`requires_grad=True`的张量为可求导变量；调用`.backward()`自动链式求导算出梯度。

### 细分API功能拆解

1. **梯度开关标记**
创建张量时 `requires_grad=True`；模型参数默认自动开启梯度；叶子节点（输入、权重）才会保留`.grad`，中间临时张量梯度默认释放节省内存。
2. **反向传播主入口**
`loss.backward(retain_graph=False)`：从loss节点反向遍历整张计算图，累加梯度到各参数`.grad`；`retain_graph=True`用于多轮反向传播不销毁计算图。
3. **梯度屏蔽上下文**
`with torch.no_grad():`：上下文内所有运算不记录计算图、不分配梯度内存，推理/验证必用，大幅提速省显存；
`torch.enable_grad()`：强制开启梯度（极少场景）。
4. **手动精细求导**
`torch.autograd.grad(outputs, inputs)`：不自动累加梯度，直接返回梯度张量，自定义复杂求导逻辑用；
`torch.autograd.Function`：自定义带梯度的算子（层），重写forward/backward，实现不可微分运算自定义梯度。
5. **梯度裁剪防爆炸**
`torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)`：限制梯度最大范数，RNN/大模型常用。

### 该层注意事项

1. 梯度默认**累加**，一轮训练结束必须清空梯度；
2. 只有浮点张量能求导，int/bool张量无法计算梯度；
3. 计算图只存活一次，默认backward后销毁，多反向必须开retain_graph；
4. 不要对模型参数做原地修改，会扰乱autograd追踪。

## 第三层：神经网络组件层 —— `torch.nn`（建筑零件库）

### 层级定位

搭建网络模型的中层封装，完全依赖autograd和torch张量；把重复的神经网络结构（卷积、全连接、激活、归一化、损失）封装成可复用类，不用手写矩阵乘法与求导。

### 四大子模块拆分释义

#### 3.1 模型容器（骨架框架）

1. `nn.Module`：**所有网络层、自定义模型的父类**
    含义：统一规范，自带`.parameters()`遍历权重、`.to(device)`设备迁移、`.train()`/`.eval()`模式切换、保存加载状态字典等全套能力；自定义模型必须`class MyNet(nn.Module)`，重写`__init__`（定义层）和`forward(x)`（前向逻辑）。
2. `nn.Sequential`：顺序堆叠容器
    含义：一层接一层串行执行，无需手写forward，适合简单直筒网络；复杂残差、多分支结构不能用Sequential。
3. `nn.ModuleList/ModuleDict`：批量管理层列表/字典
    含义：循环构建多层网络，保证参数被模型注册、能被优化器捕获；普通list存层会丢失参数追踪。

#### 3.2 基础网络层（运算单元）

每一个层本质都是继承nn.Module的算子，内部封装权重矩阵+forward计算逻辑：

- `nn.Linear(in_dim, out_dim)`：全连接层 y = xW+b
- `nn.Conv1d/Conv2d/Conv3d`：一维时序、二维图像、三维立体卷积
- `nn.MaxPool/AvgPool`：池化下采样；`nn.AdaptiveAvgPool`自适应尺寸池化
- `nn.BatchNorm1d/2d/3d`批归一化、`nn.LayerNorm`层归一化、`nn.GroupNorm`组归一化：稳定分布、加速收敛
- `nn.Dropout/Dropout2d`：训练随机屏蔽神经元，抑制过拟合
- `nn.LSTM/GRU/RNN`循环时序层、`nn.TransformerEncoder/Decoder`Transformer大模型基础单元
- `nn.Embedding`词嵌入层，NLP专用

#### 3.3 激活函数层（非线性转换）

全部是无参数层，只做数值映射，给网络引入非线性，否则多层等价单层：
`nn.ReLU`、`nn.LeakyReLU`、`nn.Sigmoid`、`nn.Tanh`、`nn.Softmax`、`nn.GELU`、`nn.Swish`

#### 3.4 损失函数层（误差度量）

输入预测值与真实标签，输出loss标量张量，用于反向传播起点：

- 分类：`nn.CrossEntropyLoss`（多分类，内置logsoftmax）、`nn.BCELoss/BCELossWithLogits`二分类
- 回归：`nn.MSELoss`均方误差、`nn.L1Loss`绝对值误差
- 特殊任务：`nn.CosineEmbeddingLoss`对比学习、`nn.NLLLoss`负对数似然

### 该层注意事项

1. `model.train()`：开启Dropout、BatchNorm训练行为；`model.eval()`关闭随机丢弃、BN用全局均值方差，推理缺一不可；
2. 层定义写在`__init__`，计算逻辑写`forward`，不要颠倒；
3. 只有注册到Module里的参数才会被优化器更新，临时变量不会；
4. CrossEntropy输入不能提前softmax，内部自带计算。

## 第四层：优化更新层 —— `torch.optim`（调节扳手）

### 层级定位

依赖nn.Module的参数和autograd算出的梯度，专门负责**按照梯度方向迭代更新模型权重**，实现参数收敛最小化loss。

### 核心运行三步固定逻辑

1. `optimizer.zero_grad()`：清空上一轮累积梯度
2. `loss.backward()`：autograd计算所有参数梯度
3. `optimizer.step()`：根据梯度、学习率、动量等公式更新w和b

### 细分API释义

1. **主流优化器算法**

- `optim.SGD`：随机梯度下降，可带动量momentum
- `optim.Adam`/`AdamW`：自适应学习率，工业最常用；AdamW修正权重衰减，比Adam泛化更好
- `optim.RMSprop`、`optim.Adagrad`、`optim.LBFGS`（拟牛顿，小数据集）

2. **优化器配置参数**
初始化必须传入`model.parameters()`锁定要更新的权重；可分组设置不同层学习率：`optim.Adam([{'params':layer1.parameters(),'lr':1e-4},...])`
3. **学习率调度配套（辅助优化，同属优化体系）**
`torch.optim.lr_scheduler`系列：
`StepLR`固定轮次衰减、`CosineAnnealingLR`余弦退火、`ReduceLROnPlateau`验证loss下降再衰减lr；调用`scheduler.step()`更新学习率。

### 该层注意事项

1. zero_grad必须放在backward之前，梯度累加会导致参数跑偏、loss暴涨；
2. 优化器只更新requires_grad=True的参数，冻结层参数不会改动；
3. 断点续训要同时保存优化器state_dict，否则动量、lr调度状态丢失；
4. AdamW权重衰减直接作用参数，不要手动在损失加L2正则。

## 第五层：数据加载工程层 —— `torch.utils.data`（原料输送管道）

### 层级定位

独立工程辅助层，为模型源源不断喂训练/验证数据，解决磁盘读取、分批、打乱、多线程提速问题，不参与数值微分计算，但决定训练速度稳定性。

### 三大核心组件释义

1. `torch.utils.data.Dataset` 抽象数据集父类
    需要自定义继承，必须实现`__len__`(返回样本总数)、`__getitem__(idx)`（根据索引读取单条样本x,y）；支持读取图片、文本、表格、numpy文件。
    内置简易包装：`TensorDataset(x_tensor, y_tensor)`，直接用张量构建数据集。
2. `torch.utils.data.DataLoader` 加载器流水线
    接收Dataset，自动实现：batch打包、shuffle打乱、num_workers多进程并行读数据、pin_memory锁页内存加速GPU拷贝、drop_last舍弃不足batch的尾样本。
3. 工具函数
`random_split(dataset, [train_len, val_len])`：快速划分训练验证集；
`Subset`：截取数据集部分样本；
`ConcatDataset`拼接多个数据集。

### 该层注意事项

1. Windows系统num_workers>0必须放在`if __name__ == '__main__':`内，否则多进程报错；
2. pin_memory=True搭配cuda能小幅提升数据传到显卡速度；
3. 超大文件不要一次性全部载入内存，Dataset里按需逐行读取；
4. shuffle只作用训练集，验证/测试集禁止打乱。

## 配套扩展生态库（不属于内核分层，但高度绑定）

### 1. torchvision（计算机视觉专属扩展）

依附PyTorch内核五层，专门CV任务：

- datasets：MNIST、CIFAR、ImageNet、COCO等标准图像数据集；
- models：ResNet、ViT、EfficientNet等预训练权重模型；
- transforms：图像预处理流水线（缩放、裁剪、归一化、翻转、色彩抖动数据增强）；
- ops：卷积、ROIAlign等CV专用算子。

### 2. torchtext/torchaudio

torchtext：NLP文本分词、词表、序列填充、文本数据集；
torchaudio：音频信号处理、语音数据集、声学模型层。

### 3. 分布式&部署工具

1. `torch.distributed`：多卡多机DDP分布式训练，大幅加速大模型；
2. `torch.cuda.amp`混合精度训练：半精度FP16计算，减半显存、提速；
3. `torch.onnx`/`torch.jit(TorchScript)`：模型导出，部署到C++、移动端、推理引擎；
4. `torch.save/torch.load`：全局序列化工具，保存state_dict参数/优化器/整个模型。

## 层级依赖关系总结

`torch(张量基础)` → `autograd(求导引擎)` → `nn(网络层结构)` → `optim(参数更新)`
`utils.data(数据供给)` 并行供给数据给上面整条计算链路
`torchvision/torchaudio` 是业务层封装，调用内核五层完成特定领域任务
