
# sin/cos/tan 核心作用 + 为什么余弦是相似度算法首选

## 一、sin/cos/tan 到底是干什么的？

这三个是**三角函数**，本质是**"角度与边长的转换工具"**——它们把抽象的角度，转换成了具体的边长比例，让我们能通过角度算边长，也能通过边长反推角度。

### 1. 最基础的几何定义（直角三角形）

在任意直角三角形中，对于一个锐角θ：

- **sinθ（正弦）** = 对边 / 斜边
- **cosθ（余弦）** = 邻边 / 斜边
- **tanθ（正切）** = 对边 / 邻边 = sinθ / cosθ

**形象比喻**：
想象你站在一个斜坡底部，抬头看坡顶：

- 角度θ就是你抬头的仰角
- sinθ决定了坡的**高度**（你需要爬多高）
- cosθ决定了坡的**水平长度**（你需要走多远）
- tanθ决定了坡的**陡峭程度**（坡度）

### 2. 核心作用：连接"角度"和"位置/运动"

三角函数的伟大之处在于，它把**旋转和周期性**这种抽象的运动，变成了可以计算的数值。所有涉及"角度、旋转、周期、波动"的问题，都离不开它们。

### 3. 各领域具体应用

| 领域 | 典型应用 | 用到的函数 |
|-----|---------|-----------|
| **几何/测绘** | 计算建筑物高度、桥梁跨度、地图距离 | sin/cos |
| **物理** | 单摆运动、弹簧振动、声波/光波传播、力的分解 | sin/cos |
| **工程** | 机械齿轮设计、电路交流电、建筑结构受力 | sin/cos/tan |
| **计算机图形学** | 3D模型旋转、相机视角变换、动画制作 | cos/sin（旋转矩阵） |
| **AI/大模型** | 位置编码（Transformer核心）、向量相似度计算 | cos（余弦相似度） |
| **信号处理** | 傅里叶变换（把复杂信号分解成正弦波） | sin/cos |

### 4. 扩展到任意角度（单位圆定义）

当角度超过90度时，三角函数的定义扩展到**单位圆**（半径为1的圆）：

- 点(x,y)在单位圆上，对应角度θ
- cosθ = x坐标
- sinθ = y坐标
- tanθ = y/x

这就是为什么cosθ的取值范围永远是[-1,1]——因为单位圆上x坐标最大是1，最小是-1。

## 二、为什么偏偏用**余弦**作为相似度算法？

这是AI领域最经典的问题之一。答案很简单：**余弦相似度衡量的是"方向的相似性"，而不是"大小的相似性"，这恰好完美匹配了"语义相似性"的本质**。

### 1. 先搞懂：向量相似度到底在比什么？

在RAG和所有向量检索场景中，我们把文本、图像等转换成了高维向量。两个向量的"相似"，本质是**它们代表的语义相似**。

举个最直观的例子：

- 文本A："大语言模型是基于深度学习的自然语言处理技术"（长文本）
- 文本B："大语言模型是深度学习技术"（短文本）
- 文本C："苹果发布了最新的iPhone手机"（无关文本）

显然，A和B语义完全相同，只是长度不同；A和C语义无关。

### 2. 为什么不用其他方法？（对比三种最常见的距离）

我们来对比三种可能的相似度计算方法，看看为什么只有余弦是最合适的。

#### 方法1：欧氏距离（Euclidean Distance）

**公式**：`d = √[(x1-x2)² + (y1-y2)² + ... + (xn-xn)²]`
**几何意义**：两个向量**端点之间的直线距离**。

**致命问题**：**极度受向量长度影响**。

- 上面的例子中，A和B语义相同，但A的向量长度远大于B，欧氏距离会很大
- 反而A和C的欧氏距离可能更小，导致错误匹配

**适用场景**：聚类、图像检索（像素值大小有意义）
**不适用场景**：文本语义匹配（文本长度不影响语义）

#### 方法2：点积（Dot Product）

**公式**：`dot(A,B) = x1x2 + y1y2 + ... + xnxn`
**几何意义**：`dot(A,B) = |A| × |B| × cosθ`，其中|A|是向量A的长度，θ是夹角。

**致命问题**：**同时受向量长度和夹角影响**。

- 长文本的向量长度大，即使和查询语义无关，点积也可能很大
- 短文本即使语义完全匹配，点积也可能很小

**适用场景**：向量已归一化的场景（此时点积=余弦相似度）
**不适用场景**：原始向量相似度计算

#### 方法3：余弦相似度（Cosine Similarity）

**公式**：`cosθ = (A·B) / (|A| × |B|)`
**几何意义**：两个向量**夹角的余弦值**，只关心方向，不关心长度。

**完美特性**：

- 当两个向量方向完全相同时，cosθ=1（相似度100%）
- 当两个向量方向垂直时，cosθ=0（完全不相关）
- 当两个向量方向完全相反时，cosθ=-1（完全相反）

**回到上面的例子**：

- A和B方向完全相同，cosθ≈1（相似度极高）
- A和C方向几乎垂直，cosθ≈0（相似度极低）
- 完全不受文本长度的影响

### 3. 余弦相似度的四大核心优势

#### 优势1：**天生免疫向量长度差异**

这是它最不可替代的优势。在文本场景中，**语义和文本长度没有必然联系**——一句话和一段话可以表达完全相同的意思。

#### 优势2：**高维空间下表现稳定**

在RAG常用的768/1024维高维空间中，所有向量的长度差异会被放大，但余弦相似度通过除以长度，消除了这种影响。

#### 优势3：**计算简单高效**

只需要一次点积和两次长度计算，时间复杂度O(d)（d是向量维度），非常适合大规模向量检索。

#### 优势4：**取值范围固定在[-1,1]**

结果直观，容易理解和比较。0.8以上就是高度相关，0.3以下就是不相关。

### 4. 特殊情况：什么时候不用余弦？

余弦相似度不是万能的，在以下场景中，其他方法更合适：

- **当向量长度有实际意义时**：比如用户行为向量（点击次数、购买金额），长度代表用户活跃度，此时用点积或欧氏距离更好
- **稀疏向量场景**：比如TF-IDF向量，有时用Jaccard相似度（交集/并集）效果更好
- **聚类任务**：K-Means默认使用欧氏距离，因为它更适合衡量"簇内紧密程度"

## 三、RAG场景下的余弦相似度最佳实践

1. **永远归一化向量**：
   生成向量时使用`normalize_embeddings=True`，此时余弦相似度和点积完全等价，计算更快。

2. **阈值设置参考**：
   - 0.8-1.0：高度相关，直接使用
   - 0.6-0.8：中度相关，需要重排序
   - 0.3-0.6：弱相关，谨慎使用
   - <0.3：不相关，过滤掉

3. **不要混淆余弦相似度和余弦距离**：
   余弦距离 = 1 - 余弦相似度，取值范围[0,2]，用于需要"距离"概念的场景（如聚类）。

## 四、总结

1. **sin/cos/tan**是描述"角度与边长关系"的基础工具，是所有涉及旋转、周期、波动问题的数学基础，在AI中最核心的应用是**位置编码**和**余弦相似度**。

2. **余弦相似度**之所以成为RAG和所有语义匹配场景的首选，是因为它**只关心向量的方向，不关心长度**，完美匹配了"语义相似性"的本质——语义相同的文本，无论长短，向量方向都应该相同。

3. 欧氏距离关心"端点距离"，点积关心"方向+长度"，只有余弦相似度纯粹关心"方向"，这就是它不可替代的原因。
