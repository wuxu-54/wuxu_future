# Tool Use 完整详解：从基础原理到生产级落地

Tool Use（工具使用）是大模型从“**文本生成器**”进化为“**任务执行者**”的关键能力，也是所有 Agent、智能体与行动增强系统的基础。  
在实践中，**一个完整的 Tool Use 系统**通常包含意图理解、工具选择、参数生成、执行调度、错误处理与结果融合等环节，而不仅仅是单次函数调用。

> 注：由于不同厂商的命名差异，`Tool Use` 与 `Function Calling` 在文档中经常混用。本文将从**机制层**和**系统层**两个角度加以区分，帮助你在工程中做出更清晰的设计决策。

---

## 一、什么是 Tool Use？与 Function Calling 的关系

### 1. 行业术语现状

| 厂商 | 官方术语 | 本质 |
|------|----------|------|
| OpenAI | Function Calling（后称 Tool Calling） | 模型输出结构化调用请求的能力 |
| Anthropic | Tool Use | 同上，强调“使用”而非“函数” |
| Google Gemini | Function Calling | 同上 |
| 社区通用 | 两者混用，常并列写作 `Function Calling / Tool Use` | — |

因此，严格来说 **两者并非本质对立的两个概念**，而是不同厂商对同一能力的命名。  
但在**系统架构**层面，我们可以将“Tool Use”扩展为更完整的能力集合，从而与单纯的“Function Calling 机制”区分开。
>二者是近义词，平常与人沟通可以当做一种东西！

### 2. 从两个层次理解

| 层次 | 名称 | 定义 | 谁负责 |
|------|------|------|--------|
| **机制层** | Function Calling / Tool Use（狭义） | 模型根据工具描述输出结构化调用请求（函数名 + 参数）的能力 | 大模型（API 原生支持） |
| **系统层** | Tool Use 系统（广义） | 包含工具注册、选择、参数校验、执行、错误处理、多轮融合的完整工程实现 | 应用层 / Agent 框架 |

**一句话总结**：  

- **机制层**：模型“会输出调用指令”  
- **系统层**：程序“让这个指令真正完成事情”

### 3. 核心定义（系统层视角）

一个完整的 Tool Use 系统实现了：  
> 自主理解用户意图 → 选择合适的外部工具 → 生成正确的调用参数 → 安全执行 → 处理结果 → 最终回答用户  

它建立的是“**自然语言意图 ↔ 可执行操作 ↔ 结果反馈**”的闭环。

---

## 二、核心架构与组件（系统层）

一个生产级的 Tool Use 系统通常包含以下 7 个组件：

```
用户输入 → 意图理解器 → 工具选择器 → 参数生成器 → 执行引擎 → 结果融合器 → 最终回答
                ↑                     ↓
                └──── 反馈处理器 ─────┘
```

| 组件 | 职责 |
|------|------|
| **工具注册表** | 存储所有可用工具的元数据（名称、描述、参数 schema、权限等） |
| **意图理解器** | 从自然语言中提取核心需求与约束 |
| **工具选择器** | 根据意图选出最合适的工具（可基于关键词、向量检索或模型推理） |
| **参数生成器** | 从上下文中提取/生成参数，并进行校验与缺失处理 |
| **执行引擎** | 实际调用工具（支持同步/异步、串行/并行、超时控制） |
| **结果融合器** | 将工具返回的结构化数据转化为自然语言回答 |
| **反馈处理器** | 根据执行结果决定下一步（重试、降级、追问或结束） |

---

## 三、完整工作流程（7步闭环）

1. **用户输入与意图解析**  
   接收自然语言 → 判断是否需要使用工具（简单问题可直接回答）

2. **工具检索与选择**  
   从注册表中选择最相关的工具；对复杂任务可生成调用序列（链式/并行）

3. **参数生成与校验**  
   提取/生成参数 → 校验类型、范围、必填 → 缺失时主动询问

4. **工具调用与执行**  
   调用函数/API → 处理超时、网络错误 → 记录日志

5. **结果解析与评估**  
   解析返回值 → 判断是否满足需求 → 决定是否需要更多工具

6. **多轮迭代**  
   如需继续调用工具，回到步骤2（需设置最大迭代次数防止无限循环）

7. **结果融合与回答生成**  
   整合所有结果 → 生成自然语言回答 → 可选附带来源

## 四、核心技术详解

### 1. 工具定义最佳实践

工具定义的质量直接影响调用成功率。推荐使用 **JSON Schema** 格式（兼容 OpenAI/Anthropic/Google）：

```json
{
  "type": "function",
  "function": {
    "name": "get_weather",
    "description": "获取指定城市未来几天的天气预报。当用户询问天气时使用，例如'明天北京会下雨吗？'。",
    "parameters": {
      "type": "object",
      "properties": {
        "city": {
          "type": "string",
          "description": "城市名称，如'北京'、'上海'"
        },
        "days": {
          "type": "integer",
          "description": "预报天数，默认1天，最多7天",
          "default": 1,
          "minimum": 1,
          "maximum": 7
        }
      },
      "required": ["city"]
    }
  }
}
```

**黄金法则**：

- 名称：动词+名词，如 `get_weather`
- 描述：说明**做什么**以及**何时使用**（包含触发关键词示例）
- 参数：类型、描述、默认值、取值范围明确
- 避免歧义，明确能力边界

### 2. 参数校验与错误处理

使用 Pydantic 等库进行严格校验：

```python
from pydantic import BaseModel, Field, ValidationError

class GetWeatherInput(BaseModel):
    city: str = Field(..., description="城市名称")
    days: int = Field(1, ge=1, le=7)

def validate_tool_params(tool_name: str, params: dict):
    if tool_name == "get_weather":
        return GetWeatherInput(**params)  # 自动校验
    # ...
```

**错误处理策略**：

- **可重试错误**（网络超时）→ 指数退避重试 2～3 次
- **参数错误**（类型不匹配）→ 尝试自动修正或请求用户重新输入
- **不可恢复错误** → 返回友好提示并记录日志

### 3. 并行工具调用

当多个工具相互独立时，使用异步并行提升效率：

```python
import asyncio

async def parallel_call(tool_calls: list):
    tasks = [call_tool(tc.name, tc.args) for tc in tool_calls]
    return await asyncio.gather(*tasks)
```

### 4. 工具检索（当工具数量 > 50）

若工具超过模型上下文限制，先对用户输入做向量检索，选出 Top-K 相关工具。

```python
from sentence_transformers import SentenceTransformer
import faiss

model = SentenceTransformer('all-MiniLM-L6-v2')
# 为每个工具生成描述向量
tool_embeddings = model.encode([t.description for t in tools])
index = faiss.IndexFlatL2(tool_embeddings.shape[1])
index.add(tool_embeddings)

def retrieve_tools(query: str, k=5):
    q_emb = model.encode([query])
    _, idxs = index.search(q_emb, k)
    return [tools[i] for i in idxs[0]]
```

### 5. 工具链规划

复杂任务可分解为多个步骤，形成有依赖关系的工具链。  
例如：“分析 2024 年 AI 市场规模并生成报告” →  
`search_web` → `extract_data` → `generate_report`

## 五、生产级代码实战（可直接运行）

> 完整代码已包含工具定义、参数校验、并行调用、日志与错误处理。  
> 依赖：`openai`, `pydantic`, `python-dotenv`, `asyncio`

```python
import asyncio
import json
import logging
from typing import Dict, Any
from pydantic import BaseModel, Field, ValidationError
from openai import OpenAI
from dotenv import load_dotenv
import os

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)
load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# ---------- 工具实现 ----------
def get_weather(city: str, days: int = 1) -> str:
    logger.info(f"get_weather({city}, {days})")
    return f"{city}未来{days}天：晴，20~25°C"

def calculate_math(expression: str) -> str:
    logger.info(f"calc({expression})")
    try:
        return f"结果: {eval(expression)}"
    except Exception as e:
        return f"计算错误: {e}"

# ---------- 工具注册 ----------
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取城市天气。用户问天气时使用。",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string"},
                    "days": {"type": "integer", "default": 1}
                },
                "required": ["city"]
            }
        },
        "impl": get_weather,
        "input_model": type("WeatherInput", (BaseModel,), {
            "city": str,
            "days": Field(1, ge=1, le=7)
        })
    },
    {
        "type": "function",
        "function": {
            "name": "calculate_math",
            "description": "计算数学表达式。",
            "parameters": {
                "type": "object",
                "properties": {"expression": {"type": "string"}},
                "required": ["expression"]
            }
        },
        "impl": calculate_math,
        "input_model": type("MathInput", (BaseModel,), {"expression": str})
    }
]

tool_map = {t["function"]["name"]: t for t in tools}
openai_tools = [{"type": "function", "function": t["function"]} for t in tools]

async def call_tool(tool_name: str, arguments: dict) -> str:
    try:
        tool = tool_map[tool_name]
        # 参数校验
        validated = tool["input_model"](**arguments)
        return tool["impl"](**validated.dict())
    except ValidationError as e:
        return f"参数错误: {e}"
    except Exception as e:
        logger.error(f"{tool_name} 执行失败: {e}")
        return f"执行失败: {e}"

async def run_agent(user_query: str, max_rounds=5) -> str:
    messages = [
        {"role": "system", "content": "你是助手，可使用工具回答问题。需要工具时调用，否则直接回答。"},
        {"role": "user", "content": user_query}
    ]
    for _ in range(max_rounds):
        resp = client.chat.completions.create(
            model="gpt-3.5-turbo-1106",
            messages=messages,
            tools=openai_tools,
            tool_choice="auto"
        )
        msg = resp.choices[0].message
        messages.append(msg)
        if not msg.tool_calls:
            return msg.content
        # 并行执行所有工具调用
        tasks = []
        for tc in msg.tool_calls:
            args = json.loads(tc.function.arguments)
            tasks.append(call_tool(tc.function.name, args))
        results = await asyncio.gather(*tasks)
        for tc, res in zip(msg.tool_calls, results):
            messages.append({
                "role": "tool",
                "tool_call_id": tc.id,
                "content": res
            })
    return "达到最大轮次，未能完成请求。"

async def main():
    print(await run_agent("北京明天天气？"))
    print(await run_agent("2+2等于多少？顺便问问上海天气"))

if __name__ == "__main__":
    asyncio.run(main())
```

## 六、进阶优化与陷阱规避

### 常用优化技巧

| 目标 | 方法 |
|------|------|
| 成本控制 | 缓存常用结果、小模型路由、限制迭代次数 |
| 上下文管理 | 截断历史、生成摘要、只保留关键信息 |
| 安全 | 沙箱执行、输入验证、审计日志 |
| 可观测性 | 记录调用耗时、成功率、错误类型，配置告警 |

### 常见陷阱与解决方案

| 陷阱 | 表现 | 解决方案 |
|------|------|----------|
| 参数幻觉 | 生成不存在的参数或错误的值 | 严格校验 + 自动修正 + 示例引导 |
| 工具选错 | 用天气工具查新闻 | 优化描述 + 工具检索（Top-K）+ 提供示例 |
| 无限循环 | 反复调用同一工具 | 设置最大迭代次数、检测重复调用 |
| 上下文溢出 | Token 超限 | 实现历史压缩、支持更长上下文的模型 |

## 八、最佳实践与落地建议

1. **从简单开始**：先实现 2～3 个核心工具，验证流程再扩展
2. **工具粒度适中**：不要太细（每个算术运算一个工具）也不要太粗（一个工具做所有事）
3. **能力边界清晰**：描述里明确“能做什么”和“不能做什么”
4. **错误处理完善**：考虑网络超时、参数缺失、权限不足等场景
5. **持续迭代**：根据日志反馈优化工具描述和提示词
6. **安全第一**：敏感操作需用户确认，避免危险命令被执行

## 九、Tool Use 与 RAG / Agent 的关系

- **RAG 是一种特殊的 Tool Use**：将知识库检索视为一个“检索工具”
- **Agent 是 Tool Use 的扩展**：增加长期记忆、自主规划与多智能体协作
- 实践中常组合使用：RAG 提供知识 → Tool Use 执行操作 → Agent 统筹调度
