# JeecgBoot 多租户模式核心体系（租户/用户/角色/部门）详解

## 一、核心概念定义（笔记重点）

| 体系       | 核心定义                                                                 | 隔离性       | 归属关系                     |
|------------|--------------------------------------------------------------------------|--------------|------------------------------|
| 租户（Tenant） | 多租户系统中独立的“业务单元”（如子公司、项目组、客户），是数据隔离的最高层级 | 完全隔离     | 无归属，是顶层容器           |
| 部门（Dept）   | 租户内部的组织架构单元（如技术部、财务部），用于归类用户                   | 租户内隔离   | 归属某个租户                 |
| 用户（User）   | 系统的操作用户，必须绑定租户和部门                                       | 租户内隔离   | 归属某个租户+某个部门        |
| 角色（Role）   | 权限的集合（菜单/按钮/数据权限），用于批量给用户授权                       | 租户内隔离   | 归属某个租户                 |
| 权限（Permission） | 细粒度的操作许可（如查看菜单、点击删除按钮、查看指定数据） | 租户内隔离 | 绑定到角色，通过角色赋予用户 |

## 二、各体系的创建/配置/使用流程（实操步骤）

### 1. 租户体系（核心顶层）

#### （1）创建条件

- 操作人：**系统超级管理员（默认admin）**（只有超级管理员能管理租户）
- 前置：JeecgBoot已开启多租户模式（配置文件中 `jeecg.tenant.open = true`）

#### （2）创建步骤

1. 登录系统 → 进入「系统管理」→ 「租户管理」→ 「新增租户」
2. 填写租户信息：
   - 必填：租户名称（如“XX分公司”）、租户编码（唯一标识，如“branch01”）、联系人/手机号
   - 可选：租户有效期、备注
3. 保存后，系统自动生成该租户的“租户管理员账号”（可自定义账号/密码）
4. （可选）配置租户参数：如租户logo、数据存储规则（默认按租户ID隔离）

#### （3）使用规则

- 租户创建后，超级管理员可“切换租户”（系统顶部租户切换按钮）进入该租户视角
- 每个租户有独立的“租户ID”，所有业务表都会自动关联该ID实现数据隔离
- 支持禁用/删除租户（删除前需确认租户内无重要数据）

### 2. 部门体系（租户内组织）

#### （1）创建条件

- 操作人：超级管理员（切换到目标租户后）或**该租户的管理员**
- 前置：已创建目标租户

#### （2）创建步骤

1. 切换到目标租户（如“XX分公司”）→ 进入「系统管理」→ 「部门管理」→ 「新增部门」
2. 填写部门信息：
   - 必填：部门名称（如“技术部”）、部门编码（唯一）、上级部门（支持多级架构，如“总公司→技术部→前端组”）
   - 可选：部门负责人、联系电话、排序号
3. 保存后，部门自动关联当前租户ID，仅该租户可见

#### （3）使用规则

- 部门支持多级嵌套（如集团→子公司→部门→小组）
- 一个部门只能归属一个租户，跨租户无法共享（开源版无全局部门功能）
- 部门可修改/删除（删除前需确保该部门下无用户，否则需先转移用户）

### 3. 用户体系（租户内操作用户）

#### （1）创建条件

- 操作人：超级管理员（切换到目标租户后）或该租户的管理员
- 前置：已创建目标租户+对应部门

#### （2）创建步骤

1. 切换到目标租户 → 进入「系统管理」→ 「用户管理」→ 「新增用户」
2. 填写用户核心信息：
   - 必填：用户名（登录账号）、密码、姓名、手机号、所属租户（自动默认当前租户，不可修改）、所属部门（选择该租户内的部门）
   - 可选：邮箱、性别、状态（启用/禁用）、过期时间
3. 保存后，用户只能用该账号登录所属租户的系统

#### （3）使用规则

- 一个用户只能归属一个租户，若需跨租户操作，需在每个租户下单独创建账号
- 用户状态为“禁用”时，无法登录系统
- 支持批量导入用户（模板在系统内可下载，需指定所属租户和部门）
- 忘记密码：租户管理员可重置本租户用户密码，超级管理员可重置所有租户用户密码

### 4. 角色体系（权限集合）

#### （1）创建条件

- 操作人：超级管理员（切换到目标租户后）或该租户的管理员
- 前置：已创建目标租户

#### （2）创建步骤（分3步）

##### 步骤1：创建角色

1. 切换到目标租户 → 进入「系统管理」→ 「角色管理」→ 「新增角色」
2. 填写角色信息：
   - 必填：角色名称（如“技术部普通员工”）、角色编码（唯一）
   - 可选：角色描述、排序号
3. 保存角色（此时角色无任何权限）

##### 步骤2：配置菜单/按钮权限

1. 进入角色详情页 → 点击「权限配置」→ 进入权限树页面
2. 勾选该角色可访问的菜单（如“客户管理”“订单管理”）
3. 勾选菜单下的按钮权限（如“新增客户”“编辑订单”“删除订单”）
4. 保存权限（系统自动关联租户ID，仅该租户生效）

##### 步骤3：配置数据权限（可选但重要）

1. 角色详情页 → 「数据权限」→ 选择数据权限规则：
   - 全部数据：可查看该租户下所有数据
   - 本部门数据：仅查看所属部门的数据
   - 本部门及下级部门：查看所属部门+子部门数据
   - 仅本人数据：仅查看自己创建的数据
   - 自定义：通过SQL条件筛选数据（需开发能力）
2. 保存数据权限规则

#### （3）给用户分配角色

1. 进入「用户管理」→ 选择目标用户 → 「编辑」→ 「角色分配」
2. 勾选该租户内的角色（可多选）→ 保存
3. 用户登录后，自动继承角色的所有权限

#### （4）使用规则

- 角色仅在所属租户内生效，跨租户无法复用
- 一个用户可分配多个角色，权限自动叠加
- 支持角色复制（同租户内复制角色权限，减少重复配置）

## 三、核心使用原则（笔记必记）

1. **隔离原则**：租户是数据隔离的核心，所有用户/部门/角色/权限均“隶属于某个租户”，跨租户完全不可见（开源版无全局共享能力）。
2. **层级原则**：超级管理员管租户，租户管理员管本租户的部门/用户/角色，普通用户仅能操作授权范围内的数据。
3. **授权原则**：先建租户→再建部门→再建角色（配置权限）→最后建用户并分配角色，按此顺序可避免权限配置混乱。
4. **运维原则**：
   - 不要用超级管理员（admin）直接操作租户内的业务数据，建议为每个租户创建专属的租户管理员。
   - 定期备份租户数据（尤其是用户/角色/部门配置），避免误删。

## 四、常见场景实操示例

### 场景：给“XX分公司”租户配置一套完整的权限体系

1. 超级管理员创建“XX分公司”租户，生成租户管理员账号（如branch01_admin）。
2. 用branch01_admin登录系统（自动进入XX分公司租户）。
3. 创建部门架构：XX分公司→技术部→前端组、后端组；XX分公司→财务部。
4. 创建角色：
   - 技术部员工：权限=产品管理（查看/新增/编辑）+ 开发文档（全部），数据权限=本部门数据。
   - 财务部员工：权限=财务报表（查看）+ 费用管理（全部），数据权限=本部门数据。
5. 创建用户：
   - 张三：所属部门=技术部-前端组，分配角色=技术部员工。
   - 李四：所属部门=财务部，分配角色=财务部员工。
6. 张三登录后，仅能看到技术部相关菜单和数据；李四仅能看到财务部相关内容。

### 总结

1. JeecgBoot多租户模式下，**租户是顶层隔离单元**，所有用户、部门、角色均归属某一租户，跨租户完全隔离。
2. 操作流程遵循“建租户→建部门→建角色（配权限）→建用户（配角色）”的顺序，可高效完成权限体系搭建。
3. 权限分为“菜单/按钮权限（功能访问）”和“数据权限（数据范围）”，两者结合实现细粒度管控。
