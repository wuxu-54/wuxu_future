# MySQL导出

## 一、整体导出的核心原则（必遵守）

整体导出（结构+数据）需满足以下要求，避免脚本执行失败或数据污染：

1. **完整性**：包含所有表结构、索引、外键、触发器（如需）和业务/基础数据；
2. **安全性**：去掉`DROP TABLE`等高危语句，避免误删目标库数据；
3. **适配性**：字符集（如`utf8mb4`）、存储引擎（如`InnoDB`）匹配目标环境；
4. **幂等性**：脚本可多次执行不报错（如插入数据加`ON DUPLICATE KEY`）；
5. **精简性**：过滤测试表、临时表、日志表等无关数据/结构。

## 二、核心方法：命令行（mysqldump）导出（生产环境首选）

`mysqldump`是MySQL官方自带的导出工具，可控性最高，支持精准配置导出内容，是生产环境的首选方式。

### 1. 基础语法

```bash
mysqldump [核心参数] -u 用户名 -p 数据库名 > 导出文件.sql
```

**整体导出必用核心参数**（按重要性排序）：

| 参数                          | 作用                                                                 |
|-------------------------------|----------------------------------------------------------------------|
| `-u`                          | 指定MySQL登录用户名（如`root`）|
| `-p`                          | 登录密码（执行后会提示输入，不建议直接写在命令中，避免密码泄露）|
| `--default-character-set=utf8mb4` | 强制指定字符集为utf8mb4，避免乱码（生产环境标配）|
| `--create-options`            | 保留建表时的核心配置（如`ENGINE=InnoDB`、字符集）|
| `--skip-add-drop-table`       | 去掉自动生成的`DROP TABLE IF EXISTS`（防止误删目标库数据，关键！）|
| `--skip-comments`             | 去掉无关注释，精简脚本                                               |
| `--ignore-table=库名.表名`    | 忽略指定表（如测试表`test_table`、日志表`sys_log`），可多次使用       |
| `--single-transaction`        | 导出时开启事务，保证数据一致性（InnoDB引擎必备，避免导出过程中数据变更） |
| `--set-gtid-purged=OFF`       | 关闭GTID相关语句（非主从架构的目标环境需加，避免语法报错）|

### 2. 不同场景的整体导出示例

#### 示例1：基础完整导出（结构+所有数据）

适合测试环境/新库初始化，导出整个数据库的结构和所有数据：

```bash
# 导出xxx_db数据库的所有结构+数据，适配生产字符集和引擎
mysqldump -u root -p --default-character-set=utf8mb4 --create-options --skip-add-drop-table --single-transaction --set-gtid-purged=OFF xxx_db > full_export.sql
```

执行后输入MySQL密码，即可在当前目录生成`full_export.sql`。

#### 示例2：过滤测试表的完整导出（生产环境首选）

整体导出时忽略测试表、日志表，只保留核心业务表：

```bash
# 忽略test_table（测试表）和sys_log（日志表），导出核心数据
mysqldump -u root -p --default-character-set=utf8mb4 --create-options --skip-add-drop-table --single-transaction --set-gtid-purged=OFF --ignore-table=xxx_db.test_table --ignore-table=xxx_db.sys_log xxx_db > core_export.sql
```

#### 示例3：只导出指定表的完整数据

仅导出核心业务表（如`sys_user`、`sys_order`）的结构+数据：

```bash
# 只导出sys_user和sys_order两张表
mysqldump -u root -p --default-character-set=utf8mb4 --create-options --skip-add-drop-table --single-transaction --set-gtid-purged=OFF xxx_db sys_user sys_order > specified_tables_export.sql
```

#### 示例4：导出多个数据库的整体数据

如需同时导出`db1`和`db2`两个数据库：

```bash
mysqldump -u root -p --default-character-set=utf8mb4 --create-options --skip-add-drop-table --single-transaction --set-gtid-purged=OFF --databases db1 db2 > multi_db_export.sql
```

## 三、新手友好：可视化工具导出（Navicat/HeidiSQL）

如果不熟悉命令行，可通过Navicat、HeidiSQL等可视化工具快速导出，步骤以Navicat为例：

### 步骤1：连接本地MySQL

打开Navicat，连接目标MySQL实例，找到需要导出的数据库（如`xxx_db`）。

### 步骤2：选择导出方式

右键点击数据库 → 选择「转储SQL文件」→ 选择「结构和数据」（整体导出）。

### 步骤3：配置生产适配选项（关键）

点击「高级」按钮，配置以下选项（避免脚本执行异常）：

- ✅ 勾选「使用UTF8编码」（保证字符集一致）；
- ✅ 勾选「包含CREATE TABLE选项」（保留引擎、字符集等配置）；
- ❌ 取消勾选「添加 DROP TABLE / VIEW / PROCEDURE...」（防止误删目标库数据）；
- ❌ 取消勾选「添加注释」（精简脚本）；
- ✅ 勾选「锁定表」（仅InnoDB，保证数据一致性）。

### 步骤4：保存脚本

选择保存路径（如`full_export.sql`），点击「开始」，等待导出完成。

## 四、导出后脚本的生产环境优化（关键步骤）

整体导出的原始脚本可能包含测试数据、高危语句，需手动优化后再在生产环境执行：

### 1. 移除高危语句

- 删除所有`DROP TABLE IF EXISTS`、`TRUNCATE TABLE`语句（防止误删生产数据）；
- 移除`USE xxx_db;`语句（生产库名可能与本地不同，执行前手动指定库）；
- 删除`AUTO_INCREMENT=xxx`（避免主键自增起始值冲突）。

### 2. 保证幂等性

- 建表语句添加`IF NOT EXISTS`（如`CREATE TABLE IF NOT EXISTS sys_user (...)`）；
- 插入数据的`INSERT`语句改为`INSERT ... ON DUPLICATE KEY UPDATE`（避免重复插入报错）：

  ```sql
  -- 原始INSERT（重复执行会报错）
  INSERT INTO sys_user (username, password) VALUES ('admin', '123456');
  
  -- 优化后（重复执行不报错，更新字段）
  INSERT INTO sys_user (username, password) VALUES ('admin', '123456')
  ON DUPLICATE KEY UPDATE password = VALUES(password);
  ```

### 3. 清理无关数据/结构

- 删除测试数据行（如`username='test_user'`的记录）；
- 移除临时表、调试用索引/触发器；
- 过滤日志表、统计表的历史数据（只保留基础配置）。

### 4. 适配生产配置

- 确认所有表的引擎为`InnoDB`（替换`MyISAM`）；
- 统一字符集为`utf8mb4`（替换`utf8`）；
- 执行前添加`SET FOREIGN_KEY_CHECKS=0;`（关闭外键检查，避免建表顺序导致的外键报错），执行后恢复：

  ```sql
  -- 脚本开头添加
  SET FOREIGN_KEY_CHECKS=0;
  
  -- 脚本结尾添加
  SET FOREIGN_KEY_CHECKS=1;
  ```

## 五、SQL脚本的执行方法（生产/测试环境）

导出并优化后的脚本，可通过以下方式执行：

### 1. 命令行执行（推荐，适合大脚本）

```bash
# 登录MySQL执行脚本（需生产库账号有读写权限）
mysql -u 生产用户名 -p 生产数据库名 < full_export.sql
```

### 2. 可视化工具执行（适合小脚本）

- 连接目标MySQL（生产/测试）；
- 打开优化后的SQL脚本；
- 点击「运行」（或按F5），按提示执行；
- 执行完成后，检查是否有报错，验证数据/结构是否完整。

## 六、验证导出&执行结果

执行脚本后，需验证以下内容，确保导出/执行成功：

1. **结构验证**：查询表、索引、约束是否完整（如`desc sys_user`、`show indexes from sys_user`）；
2. **数据验证**：查询核心数据是否存在（如`select * from sys_dict where dict_type='user_status'`）；
3. **功能验证**：启动应用，调用核心接口，确认数据库读写正常。

## 总结

1. MySQL整体导出SQL脚本的核心方式是`mysqldump`命令行（生产首选），通过`--skip-add-drop-table`、`--single-transaction`等参数保证脚本安全、完整；
2. 可视化工具（Navicat）适合新手，需重点配置“取消DROP语句、UTF8编码”；
3. 导出后的脚本必须优化：移除高危语句、保证幂等性、清理测试数据，才能在生产环境执行；
4. 执行前备份生产库，执行后验证结构/数据完整性，异常时立即回滚。
