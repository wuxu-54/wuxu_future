# 目录结构

## 一、Spring Boot 标准目录结构（Maven/Gradle通用）

先给出一个完整的、符合行业最佳实践的目录树形结构，你可以直接参考：

```
your-project-name/          # 项目根目录
├── src/
│   ├── main/               # 主程序代码和资源
│   │   ├── java/           # Java源代码目录
│   │   │   └── com/        # 基础包名（反向域名规则，如com.xxx.yyy）
│   │   │       └── demo/   # 项目专属包名（示例：demo）
│   │   │           ├── DemoApplication.java  # Spring Boot主启动类（核心！）
│   │   │           ├── controller/           # 控制器层：处理HTTP请求
│   │   │           ├── service/              # 业务逻辑层：核心业务处理
│   │   │           │   └── impl/             # service接口的实现类（可选但推荐）
│   │   │           ├── repository/          # 数据访问层（DAO/Mapper）：操作数据库
│   │   │           ├── entity/              # 实体类：对应数据库表结构
│   │   │           ├── dto/                 # 数据传输对象：前后端交互的数据结构
│   │   │           ├── vo/                  # 视图对象：给前端返回的展示数据（可选）
│   │   │           ├── config/              # 配置类：自定义Bean、拦截器、数据源等
│   │   │           ├── exception/           # 异常处理：全局异常处理器、自定义异常
│   │   │           └── util/                # 工具类：通用方法（如日期、加密、字符串处理）
│   │   └── resources/      # 资源文件目录（Spring Boot自动识别）
│   │       ├── application.yml             # 核心配置文件（推荐yml，也可用properties）
│   │       ├── application-dev.yml         # 开发环境配置（多环境隔离）
│   │       ├── application-prod.yml        # 生产环境配置（多环境隔离）
│   │       ├── static/                     # 静态资源：CSS、JS、图片、字体等
│   │       ├── templates/                  # 模板文件：Thymeleaf/Freemarker等模板引擎文件
│   │       ├── mapper/                     # MyBatis的XML映射文件（如果用MyBatis）
│   │       └── config/                     # 额外的配置文件（如mybatis-config.xml）
│   └── test/               # 测试代码目录（结构和main/java对应）
│       └── java/
│           └── com/
│               └── demo/
│                   ├── DemoApplicationTests.java  # 基础测试类
│                   ├── controller/               # 控制器测试
│                   └── service/                  # 业务逻辑测试
├── pom.xml                 # Maven依赖配置文件（Gradle用build.gradle）
├── .gitignore              # Git忽略文件（如target、.idea、*.iml等）
├── README.md               # 项目说明文档（描述功能、启动方式、依赖等）
└── target/                 # Maven编译输出目录（自动生成，无需手动修改）
```

## 二、核心目录/文件的作用详解

### 1. 主启动类（DemoApplication.java）

这是Spring Boot项目的**入口**，必须放在基础包的**最外层**（如`com.demo`），因为Spring Boot默认会扫描主启动类所在包及其子包下的所有组件（`@Controller`/`@Service`/`@Repository`等）。示例代码：

```java
package com.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

// 核心注解：包含@ComponentScan（组件扫描）、@EnableAutoConfiguration（自动配置）等
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args); // 启动Spring Boot应用
    }
}
```

### 2. 配置文件（application.yml）

- 核心配置文件，支持多环境隔离：通过`spring.profiles.active=dev`指定激活的环境（如开发环境dev、生产环境prod）。
- 常用配置示例（application.yml）：

```yaml
spring:
  profiles:
    active: dev  # 激活开发环境配置
  datasource:
    url: jdbc:mysql://localhost:3306/test_db
    username: root
    password: 123456
server:
  port: 8080  # 项目启动端口
```

### 3. 各业务分层目录

| 目录         | 作用                                                                 | 核心注解                  |
|--------------|----------------------------------------------------------------------|---------------------------|
| controller   | 接收前端HTTP请求，返回响应（JSON/页面），不处理复杂业务逻辑           | `@RestController`/`@Controller` |
| service      | 封装业务逻辑，调用repository层，是项目的核心业务层                   | `@Service`                |
| repository   | 操作数据库（CRUD），可基于JPA/MyBatis/MyBatis-Plus实现               | `@Repository`/`@Mapper`   |
| entity       | 映射数据库表，通常用`@Entity`（JPA）或`@Data`（Lombok）简化开发       | `@Entity`/`@Data`         |
| config       | 自定义配置，如拦截器、跨域、Redis配置等，替代XML配置                 | `@Configuration`          |
| exception    | 全局异常处理，统一返回格式，避免前端收到零散的异常信息               | `@RestControllerAdvice`   |

## 三、非必需但推荐的优化

1. **Lombok依赖**：在pom.xml中引入Lombok，简化entity/dto的getter/setter/构造方法：

```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <optional>true</optional>
</dependency>
```

2. **多模块项目**：如果项目复杂，可拆分为`common`（通用工具）、`core`（核心业务）、`api`（接口层）等子模块，每个子模块仍遵循上述目录结构。

## 总结

1. Spring Boot项目核心代码在`src/main/java`，主启动类需放在基础包根目录，保证组件扫描范围覆盖所有子包。
2. `src/main/resources`是核心资源目录，配置文件优先用`application.yml`，通过多环境配置隔离开发/生产环境。
3. 业务代码按“控制器-业务逻辑-数据访问”分层组织，符合Spring Boot“约定大于配置”的最佳实践，便于维护和扩展。
