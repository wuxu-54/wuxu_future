# 完整流程

## 标准化 SpringBoot 完整处理流程（企业级）

按「启动准备 → 请求处理 → 业务增强 → 进阶优化」四个阶段划分，逻辑更清晰，覆盖从启动到高并发的全链路：

### 阶段1：项目启动阶段（基础准备，核心是初始化环境和组件）

| 步骤 | 核心动作 | 详细说明 |
|------|----------|----------|
| 1. 项目启动 | 入口类执行 | 运行 `@SpringBootApplication` 标注的启动类，触发 Spring 上下文初始化；<br>核心：加载 JVM 环境、读取配置文件（application.yml/properties）。 |
| 2. 自动装配 | SpringBoot 核心特性 | 通过 `@EnableAutoConfiguration` 自动加载核心配置类（如数据源、Web 容器、MyBatis、Redis 等自动配置类），无需手动配置；<br>核心：根据依赖（starter）自动初始化组件（如引入 `spring-boot-starter-web` 则自动装配 Tomcat、DispatcherServlet）。 |
| 3. IoC 容器初始化 & 依赖注入 | 管理 Bean 生命周期 | 1. 扫描 `@Controller`/`@Service`/`@Repository` 等注解，注册 Bean 定义；<br>2. 实例化所有单例 Bean，并完成依赖注入（`@Autowired`/`@Resource`）；<br>3. 初始化核心组件（数据源连接池、Redis 连接池、MyBatis 映射器等）。 |
| 4. 接口/组件配置生效 | 加载业务配置 | 1. 加载 Controller 层的接口映射（`@GetMapping`/`@PostMapping`）；<br>2. 加载拦截器/过滤器（如登录拦截、跨域配置）；<br>3. 加载自定义配置（如分页插件、全局异常处理器）。 |

### 阶段2：请求处理核心流程（用户交互，核心是处理前端请求）

| 步骤 | 核心动作 | 详细说明 |
|------|----------|----------|
| 5. 请求接收与路由 | 前端请求进入后端 | 1. 前端发送 HTTP 请求（GET/POST）到服务器，由 Tomcat 接收；<br>2. Spring MVC 的 `DispatcherServlet`（前端控制器）根据 URL 匹配对应的 Controller 方法；<br>核心：完成「请求→控制器」的路由分发。 |
| 6. 令牌校验（JWT）& 权限控制 | 请求前置校验 | 1. 拦截器/过滤器校验请求头中的 JWT 令牌（是否过期、签名是否合法）；<br>2. 解析令牌中的用户信息（如 userId、角色），完成权限校验（如判断是否有接口访问权限）；<br>核心：非合法请求直接返回，不进入业务层。 |
| 7. 参数接收与校验 | 保证请求数据合法性 | 1. Controller 层通过 `@RequestParam`/`@PathVariable`/`@RequestBody` 接收参数；<br>2. 通过 `@Valid`/`@Validated` 配合校验注解（`@NotBlank`/`@NotNull`）完成参数合法性校验；<br>核心：过滤脏数据，避免无效请求进入业务层。 |
| 8. 业务逻辑处理 | 核心业务实现 | 1. Controller 调用 Service 层方法；<br>2. Service 层处理核心业务逻辑（如用户注册的手机号校验、订单创建的库存扣减）；<br>3. 必要时通过 `@Transactional` 控制事务（保证数据一致性）。 |
| 9. 缓存操作（Redis） | 性能增强 | 1. 优先从 Redis 读取数据（如查询用户信息时，先查缓存，未命中再查数据库）；<br>2. 写入/更新数据时，同步更新 Redis 缓存（或删除过期缓存）；<br>核心：减少数据库访问，提升接口响应速度。 |
| 10. 数据库交互（MyBatis） | 数据持久化 | 1. Service 层调用 Mapper/Repository 层；<br>2. MyBatis 执行 SQL（注解/XML 方式），完成数据库增删改查；<br>核心：仅做数据交互，不处理业务逻辑。 |
| 11. 响应封装与返回 | 统一返回格式 | 1. 将业务处理结果（数据/异常）封装为统一响应格式（如 `code`/`msg`/`data`）；<br>2. 通过 `@ResponseBody` 转换为 JSON 返回到前端；<br>核心：方便前端统一解析，降低对接成本。 |

### 阶段3：异常处理（兜底保障，企业级必备）

| 步骤 | 核心动作 | 详细说明 |
|------|----------|----------|
| 12. 全局异常处理 | 统一异常兜底 | 1. 通过 `@ControllerAdvice + @ExceptionHandler` 捕获全项目异常；<br>2. 分类处理异常（业务异常 `BusinessException`、系统异常 `NullPointerException`、参数校验异常 `MethodArgumentNotValidException` 等）；<br>3. 返回友好的异常响应（不暴露服务器内部信息）；<br>核心：避免接口返回原生异常堆栈，提升系统稳定性。 |

### 阶段4：进阶优化（高并发/高性能，非核心但大型项目必备）

| 步骤 | 核心动作 | 详细说明 |
|------|----------|----------|
| 13. 高并发处理 | 提升系统吞吐量 | 1. 服务端优化：接口限流（RateLimiter）、异步处理（`@Async`）、线程池配置；<br>2. 数据库优化：分库分表、读写分离、索引优化；<br>3. 缓存优化：Redis 集群、缓存击穿/穿透/雪崩防护；<br>4. 架构优化：微服务拆分、负载均衡（Nginx）、分布式锁；<br>核心：解决高并发下的性能瓶颈，保证系统可用。 |

## 流程简化版（贴合你最初的梳理，调整顺序+修正错误）

```
# 完整流程（简洁版）
1. 项目启动（入口类执行，加载配置）
2. 自动装配（SpringBoot 加载核心组件）
3. IoC 容器初始化 & 依赖注入（创建 Bean、注入依赖）
4. 接口配置生效（Controller 映射、拦截器加载）
5. 请求接收与路由（前端请求→匹配 Controller）
6. 令牌校验（JWT）& 参数校验
7. 业务逻辑处理（Service 层）
8. Redis 缓存操作（查缓存/更缓存）
9. 数据库交互（MyBatis）
10. 响应封装与返回
11. 全局异常处理（兜底）
12. 高并发处理（性能优化）
```

## 总结

1. 核心逻辑：SpringBoot 完整流程遵循「**启动准备→请求处理→异常兜底→性能优化**」，你的环节覆盖了核心，但需调整顺序（自动装配/依赖注入在最前，JWT 是请求前置步骤）；
2. 关键修正：MyBits 改为 MyBatis，它属于「数据库交互」环节；Redis 是业务处理中的缓存动作，而非独立步骤；
3. 企业级必备：全局异常处理、事务控制是核心兜底环节，高并发是基于核心流程稳定后的进阶优化。

这套流程完全贴合实际开发中 SpringBoot 项目的全链路处理逻辑，从启动到高并发优化都覆盖，也是面试中考察「SpringBoot 全流程」的标准答案。
