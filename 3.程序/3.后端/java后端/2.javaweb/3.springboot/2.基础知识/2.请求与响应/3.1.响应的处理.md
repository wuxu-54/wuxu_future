# 响应处理

## 一、响应处理的核心环节

接口响应的完整链路：`业务层返回数据` → `Controller封装响应` → `Jackson序列化Java对象为JSON` → `设置HTTP状态码/响应头` → `Tomcat将响应转为HTTP数据包` → `客户端接收并解析`。以下按核心环节详解：

### 1. 统一响应体：响应格式标准化（核心基础）

**核心目标**：所有接口返回格式一致，避免前端适配多种响应结构（如有的返回纯数据、有的返回带状态码的JSON）。

#### （1）规范的统一响应体设计（必含字段）

```java
package com.demo.common;

import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

/**
 * 全局统一响应体：覆盖所有接口场景（成功/失败/异常）
 */
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Result<T> {
    /**
     * 业务响应码：200成功，400参数错误，401未认证，403无权限，404资源不存在，500系统异常
     */
    private Integer code;

    /**
     * 提示信息：成功时简洁，失败时具体（如“用户ID不能为空”）
     */
    private String msg;

    /**
     * 响应数据：泛型支持任意类型（单个对象/列表/分页数据）
     */
    private T data;

    /**
     * 响应时间戳：便于排查问题（前端/后端定位请求时间）
     */
    private Long timestamp;

    // ========== 静态工具方法：简化响应封装 ==========
    public static <T> Result<T> success() {
        return new Result<>(200, "操作成功", null, System.currentTimeMillis());
    }

    public static <T> Result<T> success(T data) {
        return new Result<>(200, "操作成功", data, System.currentTimeMillis());
    }

    public static <T> Result<T> error(Integer code, String msg) {
        return new Result<>(code, msg, null, System.currentTimeMillis());
    }

    public static <T> Result<T> error(String msg) {
        return new Result<>(500, msg, null, System.currentTimeMillis());
    }
}
```

#### （2）使用规范

- ✅ 正确：所有Controller方法必须返回`Result`，禁止直接返回原始数据

  ```java
  @GetMapping("/user/{id}")
  public Result<User> getUserById(@PathVariable Long id) {
      User user = userService.getUserById(id);
      return Result.success(user);
  }
  ```

- ❌ 错误：直接返回实体类/列表（前端需适配不同格式，易出bug）

  ```java
  @GetMapping("/user/{id}")
  public User getUserById(@PathVariable Long id) { // 禁止！
      return userService.getUserById(id);
  }
  ```

### 2. 响应数据序列化（Jackson核心配置）

Spring默认使用Jackson将Java对象序列化为JSON，这是响应处理的核心环节，也是坑点高发区。

#### （1）全局序列化配置（application.yml）

```yaml
spring:
  jackson:
    # 统一日期格式（解决前端接收时间戳/乱格式问题）
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: GMT+8 # 必须设置时区，否则日期会差8小时
    # 序列化规则
    serialization:
      fail-on-empty-beans: false # 空对象不报错
      write-null-map-values: false # 不序列化null值字段（减少响应体积）
    # 反序列化规则（请求体用，响应也关联）
    deserialization:
      fail-on-unknown-properties: false # 忽略前端传的未知字段（避免解析报错）
    # 字段命名策略（下划线转驼峰，前后端统一）
    property-naming-strategy: SNAKE_CASE
```

#### （2）实体类序列化注解（局部配置）

```java
package com.demo.entity;

import com.fasterxml.jackson.annotation.JsonFormat;
import com.fasterxml.jackson.annotation.JsonIgnore;
import com.fasterxml.jackson.annotation.JsonInclude;
import com.fasterxml.jackson.annotation.JsonProperty;
import lombok.Data;

import java.time.LocalDate;

@Data
public class User {
    private Long id;

    // 自定义前端接收的字段名（覆盖全局下划线转驼峰）
    @JsonProperty("user_name")
    private String userName;

    // 忽略敏感字段（不返回给前端）
    @JsonIgnore
    private String password;

    // null值时不序列化该字段（避免前端读取null.length报错）
    @JsonInclude(JsonInclude.Include.NON_NULL)
    private Integer age;

    // 日期格式化（覆盖全局配置）
    @JsonFormat(pattern = "yyyy-MM-dd", timezone = "GMT+8")
    private LocalDate createTime;
}
```

### 3. HTTP状态码与响应头处理

**核心原则**：HTTP状态码需与响应体`code`一致，避免“HTTP 200但业务code=500”的混乱场景。

#### （1）状态码规范映射

| HTTP状态码 | 响应体code | 适用场景 | 代码示例 |
|------------|------------|----------|----------|
| 200        | 200        | 成功     | `Result.success(user)` |
| 400        | 400        | 参数错误 | `ResponseEntity.status(HttpStatus.BAD_REQUEST).body(Result.error(400, "用户ID不能为空"))` |
| 401        | 401        | 未认证   | `ResponseEntity.status(HttpStatus.UNAUTHORIZED).body(Result.error(401, "Token失效"))` |
| 403        | 403        | 无权限   | `ResponseEntity.status(HttpStatus.FORBIDDEN).body(Result.error(403, "无操作权限"))` |
| 404        | 404        | 资源不存在 | `ResponseEntity.status(HttpStatus.NOT_FOUND).body(Result.error(404, "用户不存在"))` |
| 500        | 500        | 系统异常 | `ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(Result.error(500, "服务器异常"))` |

#### （2）响应头配置（特殊场景）

```java
// 文件下载时设置响应头（解决中文文件名乱码、指定下载类型）
@GetMapping("/download")
public void download(String fileName, HttpServletResponse response) throws IOException {
    File file = new File("uploads/" + fileName);
    // 1. 设置响应类型（二进制流，避免被序列化为JSON）
    response.setContentType("application/octet-stream");
    // 2. 设置下载文件名（URL编码解决中文乱码）
    response.setHeader("Content-Disposition", "attachment; filename=" + URLEncoder.encode(fileName, "UTF-8"));
    // 3. 设置字符集
    response.setCharacterEncoding("UTF-8");
    // 4. 禁用缓存
    response.setHeader("Cache-Control", "no-cache");
    // 5. 写入响应流
    FileCopyUtils.copy(new FileInputStream(file), response.getOutputStream());
}
```

### 4. 特殊响应场景处理

#### （1）跨域响应（CORS）

前后端分离必配，否则前端报跨域错误：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**") // 所有接口
                .allowedOriginPatterns("https://www.your-domain.com") // 生产环境指定具体域名（禁止用*）
                .allowedMethods("GET", "POST", "PUT", "DELETE") // 允许的请求方法
                .allowedHeaders("*") // 允许的请求头
                .allowCredentials(true) // 允许携带Cookie
                .maxAge(3600); // 预检请求缓存1小时（减少OPTIONS请求）
    }
}
```

#### （2）大响应/流式响应（避免内存溢出）

返回超大数据（如100MB文件、10万条数据）时，需流式返回：

```java
// 流式返回大文件，避免加载到内存导致OOM
@GetMapping("/stream/download")
public StreamingResponseBody streamDownload() throws FileNotFoundException {
    File file = new File("large_file.zip");
    FileInputStream inputStream = new FileInputStream(file);
    // 流式写入响应，逐块传输
    return outputStream -> {
        byte[] buffer = new byte[1024]; // 1KB缓冲区
        int bytesRead;
        while ((bytesRead = inputStream.read(buffer)) != -1) {
            outputStream.write(buffer, 0, bytesRead);
        }
        inputStream.close();
    };
}
```

## 二、响应处理的高频坑点（附解决方案）

| 坑点描述 | 典型案例 | 解决方案 |
|----------|----------|----------|
| 响应体code与HTTP状态码不一致 | HTTP 200，但响应体code=500（系统异常） | ① 异常场景：HTTP状态码必须与响应体code一致（如400/404/500）；<br>② 代码示例：<br>`return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(Result.error(400, "参数错误"));` |
| 日期序列化格式混乱 | 前端接收日期为时间戳（1700000000000）或ISO格式（2024-01-01T08:00:00.000+00:00） | ① 全局配置Jackson的`date-format`和`time-zone`；<br>② 实体类用`LocalDateTime`（而非`Date`）+ `@JsonFormat`注解；<br>③ 禁止返回时间戳（前端需手动转换，体验差） |
| null值字段导致前端报错 | 响应体中`age: null`，前端执行`age.length`时报`Cannot read property 'length' of null` | ① 全局配置`write-null-map-values: false`；<br>② 实体类加`@JsonInclude(JsonInclude.Include.NON_NULL)`；<br>③ 业务层给null字段设默认值（如`age=0`、`name=""`） |
| 敏感字段泄露 | 响应体返回`password: "123456"`、`token: "xxx"` | ① 实体类加`@JsonIgnore`忽略敏感字段；<br>② 用DTO返回数据（而非数据库实体类），只包含前端需要的字段；<br>③ 敏感字段脱敏（如手机号：`138****1234`） |
| 响应数据体积过大 | 列表接口返回10000条数据，前端加载卡顿/超时 | ① 强制分页（必做）：返回`Result<PageInfo<User>>`，默认页大小≤20；<br>② DTO裁剪：只返回前端需要的字段（如用户列表只返回id/name，不返回createTime/email）；<br>③ 大字段按需返回：前端传`needRemark=true`才返回备注字段 |
| 文件下载响应被序列化为JSON | 前端接收文件下载接口的响应是`{"code":200,"msg":"操作成功",...}`，而非二进制流 | ① 接口返回`void`或`StreamingResponseBody`，禁止返回`Result`；<br>② 确保响应头`Content-Type`为`application/octet-stream`；<br>③ 文件下载接口用`@Controller`（而非`@RestController`），避免自动序列化 |
| 中文响应头/文件名乱码 | 文件下载时文件名“张三.txt”变为“å¼ ä¸.txt” | ① 文件名URL编码：`URLEncoder.encode(fileName, "UTF-8")`；<br>② 设置响应字符集：`response.setCharacterEncoding("UTF-8")`；<br>③ 避免用`GBK`编码（前端解码不一致） |
| 重复写入响应流 | 异常处理时先写了响应，业务层又写一次，报`getWriter() has already been called for this response` | ① 异常处理后调用`response.getWriter().flush()`并终止流程；<br>② 优先用`ResponseEntity`封装响应，而非直接操作`HttpServletResponse`；<br>③ 过滤器/拦截器中避免提前写入响应 |
| 跨域响应头冲突 | 全局配置了CORS，又在Controller手动设置`Access-Control-Allow-Origin: *` | ① 只保留全局CORS配置，禁止手动设置跨域头；<br>② 生产环境禁止用`allowedOriginPatterns("*")`，指定具体域名（如`https://www.your-domain.com`） |

## 三、响应处理的核心注意点

### 1. 格式统一是第一原则

- 所有接口（包括异常接口）必须返回`Result`，全局异常处理器也需返回`Result`；
- 禁止为了“省事”让部分接口返回纯数据（如`List<User>`），前端需适配多种格式，极易引发线上问题。

### 2. 数据安全是底线

- 绝对禁止返回明文密码、Token、身份证号、银行卡号等敏感信息；
- 脱敏规则标准化：
  - 手机号：保留前3后4，中间用`*`（如`138****1234`）；
  - 身份证：保留前6后4，中间用`*`（如`110101********1234`）；
  - 邮箱：保留前缀和域名，中间用`*`（如`zhangsan***@test.com`）。

### 3. 性能优化不可少

- 分页：所有列表接口必须分页，无分页的列表接口是“性能炸弹”；
- 序列化优化：禁止序列化null值、空集合，减少响应体积；
- 避免大响应：单次响应数据量≤10KB（分页后），超大数据拆分为多个接口。

### 4. 提示语与状态码规范

- 提示语：
  - 成功：简洁（如“操作成功”“查询成功”）；
  - 失败：具体（如“用户ID不能为空”而非“参数错误”，“用户不存在”而非“资源不存在”）；
  - 系统异常：不暴露具体原因（如“服务器内部异常，请联系管理员”而非“空指针异常：xxx”）；
- 状态码：严格遵循HTTP语义，禁止自定义非标准状态码（如用201表示“参数错误”）。

### 5. 特殊场景特殊处理

- 文件下载：
  - 必须设置`Content-Disposition`（指定下载/预览）；
  - 大文件用流式返回，避免加载到内存；
- 流式响应：
  - 设置`Transfer-Encoding: chunked`（分块传输）；
  - 增加接口超时配置：`server.servlet.async.request-timeout=300000`（5分钟）。

## 四、总结

1. **响应处理核心**：
   - 格式统一：所有接口返回`Result`，异常场景也不例外；
   - 序列化规范：统一日期格式、处理null值、过滤敏感字段；
   - 状态码一致：HTTP状态码与响应体code一一对应；
   - 性能安全：分页返回、脱敏处理、流式传输。

2. **坑点规避核心**：
   - 禁止响应体code与HTTP状态码不一致；
   - 敏感字段必须过滤/脱敏；
   - 特殊响应（文件下载）避免JSON序列化；
   - 中文编码统一用UTF-8。

3. **注意点核心**：
   - 格式统一是前端适配的基础，数据安全是系统的底线；
   - 性能优化（分页/裁剪）直接影响用户体验；
   - 提示语具体、状态码规范，可大幅降低前后端联调成本。
