# 过滤器与拦截器

## 一、过滤器（Filter）

### 1. 核心定义

过滤器是**Servlet规范**的一部分，由Servlet容器（如Tomcat）管理，运行在请求进入Servlet之前、响应返回客户端之前的阶段。它基于**函数回调**实现，能拦截所有Web请求（包括静态资源如JS/CSS/图片、API接口等），主要用于对请求/响应进行统一的预处理和后处理。

### 2. 核心特性

- 属于Java EE标准，不依赖Spring框架，任何Web项目（即使不用Spring）都能使用；
- 拦截范围广：覆盖所有请求（静态资源、Servlet、Controller等）；
- 生命周期由Servlet容器控制：`init()`（初始化）→ `doFilter()`（核心处理）→ `destroy()`（销毁）；
- 只能获取到`HttpServletRequest`和`HttpServletResponse`对象，无法直接获取Spring容器中的Bean（需手动获取）。

### 3. 实战代码示例

#### 步骤1：实现Filter接口（日志过滤器）

```java
import javax.servlet.*;
import javax.servlet.annotation.WebFilter;
import javax.servlet.http.HttpServletRequest;
import java.io.IOException;

// 拦截所有请求（/*）
@WebFilter(urlPatterns = "/*")
public class LogFilter implements Filter {

    // 初始化：容器启动时执行一次
    @Override
    public void init(FilterConfig filterConfig) throws ServletException {
        System.out.println("LogFilter 初始化");
    }

    // 核心方法：处理请求/响应
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) 
            throws IOException, ServletException {
        // 预处理：获取请求信息
        HttpServletRequest req = (HttpServletRequest) request;
        String url = req.getRequestURL().toString();
        String method = req.getMethod();
        System.out.println("Filter拦截到请求：" + method + " " + url);

        // 放行：让请求继续走后续流程（如到Servlet/Controller）
        chain.doFilter(request, response);

        // 后处理：响应返回前的操作（如记录响应状态）
        System.out.println("Filter处理响应完成：" + response.getContentType());
    }

    // 销毁：容器关闭时执行一次
    @Override
    public void destroy() {
        System.out.println("LogFilter 销毁");
    }
}
```

#### 步骤2：启用Filter（Spring Boot中）

如果是Spring Boot项目，需在启动类添加`@ServletComponentScan`注解，扫描Filter注解：

```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.web.servlet.ServletComponentScan;

@SpringBootApplication
@ServletComponentScan // 扫描@WebFilter/@WebServlet等注解
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

### 4. 典型应用场景

- 统一设置请求编码（如`request.setCharacterEncoding("UTF-8")`）；
- 跨域请求处理（设置CORS响应头）；
- 静态资源缓存控制；
- 请求参数过滤（如防XSS攻击）；
- 全局日志记录（包括静态资源请求）。

## 二、拦截器（Interceptor）

### 1. 核心定义

拦截器是**Spring MVC框架**的组件，基于AOP（面向切面编程）思想实现，运行在Spring容器中，仅拦截`Controller`层的方法调用（无法拦截静态资源、Servlet）。它能更精细地控制请求流程，且可以直接使用Spring容器中的Bean。

### 2. 核心特性

- 依赖Spring MVC，仅在Spring项目中生效；
- 拦截范围窄：只针对Controller的请求（不包括静态资源）；
- 生命周期由Spring容器管理，支持依赖注入（@Autowired）；
- 提供三个核心方法，覆盖请求处理的全流程：
  - `preHandle()`：Controller方法执行前（返回boolean，false则拦截请求）；
  - `postHandle()`：Controller方法执行后、视图渲染前；
  - `afterCompletion()`：视图渲染完成后（无论是否异常都会执行）。

### 3. 实战代码示例

#### 步骤1：实现HandlerInterceptor接口（登录验证拦截器）

```java
import org.springframework.web.servlet.HandlerInterceptor;
import org.springframework.web.servlet.ModelAndView;

import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import javax.servlet.http.HttpSession;

public class LoginInterceptor implements HandlerInterceptor {

    // 示例：依赖注入Spring Bean（过滤器需手动获取，拦截器可直接注入）
    // @Autowired
    // private UserService userService;

    // Controller方法执行前（核心拦截逻辑）
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        // 获取Session，判断是否登录
        HttpSession session = request.getSession();
        Object user = session.getAttribute("loginUser");
        if (user == null) {
            // 未登录：重定向到登录页
            response.sendRedirect("/login");
            return false; // 拦截请求
        }
        // 已登录：放行
        return true;
    }

    // Controller方法执行后、视图渲染前
    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response, Object handler, ModelAndView modelAndView) throws Exception {
        // 可修改ModelAndView（如添加全局数据）
        if (modelAndView != null) {
            modelAndView.addObject("globalMsg", "欢迎访问");
        }
    }

    // 视图渲染完成后（可做资源清理）
    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) throws Exception {
        // 记录异常（如果有）
        if (ex != null) {
            System.out.println("请求异常：" + ex.getMessage());
        }
    }
}
```

#### 步骤2：配置拦截器（注册到Spring MVC）

```java
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    // 注册拦截器，并指定拦截/放行规则
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LoginInterceptor())
                .addPathPatterns("/**") // 拦截所有Controller请求
                .excludePathPatterns("/login", "/register", "/static/**"); // 放行登录、注册、静态资源
    }
}
```

### 4. 典型应用场景

- 登录/权限校验（仅拦截业务接口，不影响静态资源）；
- Controller层方法调用日志（记录接口耗时）；
- 请求参数校验/响应数据格式化；
- 全局异常处理（配合afterCompletion）；
- 接口限流、防重复提交。

## 三、过滤器与拦截器的核心区别

为了让你更清晰对比，整理了关键维度的差异表：

| 维度                | 过滤器（Filter）                          | 拦截器（Interceptor）                    |
|---------------------|-------------------------------------------|------------------------------------------|
| 所属规范            | Servlet规范（Java EE标准）                | Spring MVC框架（非标准，依赖Spring）     |
| 拦截范围            | 所有Web请求（静态资源、Servlet、Controller）| 仅Controller层请求（不拦截静态资源）     |
| 底层实现            | 函数回调                                  | AOP（动态代理）                          |
| 生命周期            | 由Servlet容器管理（init/doFilter/destroy）| 由Spring容器管理（支持IOC/DI）           |
| 注入Bean能力        | 无法直接注入，需手动获取Spring上下文      | 可直接@Autowired注入Spring Bean          |
| 核心方法            | 仅doFilter（包含预处理+后处理）           | preHandle/postHandle/afterCompletion     |
| 执行时机            | 请求进入Servlet之前                       | DispatcherServlet分发请求到Controller之前 |
| 异常处理            | 只能捕获doFilter内的异常                  | afterCompletion可捕获Controller异常      |
| 配置方式            | @WebFilter + @ServletComponentScan 或 web.xml | 实现WebMvcConfigurer + 注册到InterceptorRegistry |

---

## 四、过滤器与拦截器的执行顺序

过滤器是Servlet容器层面的拦截，执行时机更早；拦截器是Spring MVC层面的拦截，穿插在DispatcherServlet分发请求到Controller的过程中。整体遵循“过滤器包裹拦截器执行”的规律。

### 1. 正常请求流程（核心顺序）

#### 可视化流程图

```mermaid
graph TD
    A[客户端发送请求] --> B[Filter.init<br/>(仅容器启动时执行一次)]
    B --> C[Filter.doFilter 预处理<br/>(如编码设置、日志记录)]
    C --> D[DispatcherServlet<br/>(Spring MVC核心分发器)]
    D --> E[Interceptor.preHandle<br/>(Controller执行前，返回true放行)]
    E --> F[Controller方法执行<br/>(业务逻辑处理)]
    F --> G[Interceptor.postHandle<br/>(Controller执行后，视图渲染前)]
    G --> H[视图渲染<br/>(如Thymeleaf/Freemarker渲染页面)]
    H --> I[Interceptor.afterCompletion<br/>(视图渲染完成后，资源清理)]
    I --> J[Filter.doFilter 后处理<br/>(响应返回前的操作)]
    J --> K[响应返回客户端]
    L[容器关闭] --> M[Filter.destroy<br/>(仅容器关闭时执行一次)]
```

#### 代码验证（日志顺序）

结合前文的Filter和Interceptor示例，新增测试Controller：

```java
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class TestController {
    @GetMapping("/test")
    public String test() {
        System.out.println("【Controller】执行业务逻辑");
        return "success";
    }
}
```

运行后日志输出顺序：

```
【Filter】预处理 - 请求URL：/test
【Interceptor】preHandle - Controller执行前
【Controller】执行业务逻辑
【Interceptor】postHandle - Controller执行后，视图渲染前
【Interceptor】afterCompletion - 视图渲染完成后
【Filter】后处理 - 响应完成
```

### 2. 异常场景的执行顺序

如果Controller执行过程中抛出异常，执行顺序会有变化（核心：`postHandle`不会执行，`afterCompletion`仍会执行）：

#### 异常代码（修改Controller）

```java
@GetMapping("/test")
public String test() {
    System.out.println("【Controller】执行业务逻辑（抛异常）");
    throw new RuntimeException("模拟Controller异常");
}
```

#### 异常日志输出顺序：

```
【Filter】预处理 - 请求URL：/test
【Interceptor】preHandle - Controller执行前
【Controller】执行业务逻辑（抛异常）
【Interceptor】afterCompletion - 视图渲染完成后
【Filter】后处理 - 响应完成
```

⚠️ 关键变化：`postHandle`未执行（Controller抛异常后视图渲染环节被跳过），但`afterCompletion`仍执行（用于资源清理、异常记录）。

### 3. 多过滤器/多拦截器的执行顺序

#### （1）多过滤器

- 执行顺序：由`@WebFilter`的`order`属性（数值越小越先执行）或web.xml中`<filter-mapping>`的顺序决定；
- 预处理：Filter1 → Filter2 → Filter3（正序）；
- 后处理：Filter3 → Filter2 → Filter1（倒序）。

#### （2）多拦截器

- 执行顺序：由注册到`InterceptorRegistry`的顺序决定（先add的先执行）；
- preHandle：Interceptor1 → Interceptor2（正序）；
- postHandle：Interceptor2 → Interceptor1（倒序）；
- afterCompletion：Interceptor2 → Interceptor1（倒序）。

---

### 总结

1. **核心定位**：过滤器是Servlet层面的全局拦截器，无Spring依赖、范围广，适合处理所有请求的通用逻辑；拦截器是Spring MVC层面的精细拦截器，仅针对Controller，支持依赖注入，适合业务相关的拦截逻辑。
2. **正常执行顺序**：Filter预处理 → Interceptor.preHandle → Controller → Interceptor.postHandle → Interceptor.afterCompletion → Filter后处理。
3. **异常/多组件规则**：Controller抛异常时Interceptor.postHandle不执行；多Filter/Interceptor执行遵循“预处理正序、后处理倒序”的规律。
