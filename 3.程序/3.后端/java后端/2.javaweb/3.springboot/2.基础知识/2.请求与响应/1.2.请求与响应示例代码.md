### 3. 统一响应体（Result.java）

```java
package com.demo.common;

import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

/**
 * 全局统一响应体：所有接口返回格式一致
 */
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Result<T> {
    /**
     * 响应码：200成功，400参数错误，404资源不存在，500系统异常
     */
    private Integer code;
    /**
     * 提示信息
     */
    private String msg;
    /**
     * 响应数据（泛型支持任意类型）
     */
    private T data;

    // 静态工具方法：简化响应封装
    public static <T> Result<T> success() {
        return new Result<>(200, "操作成功", null);
    }

    public static <T> Result<T> success(T data) {
        return new Result<>(200, "操作成功", data);
    }

    public static <T> Result<T> error(Integer code, String msg) {
        return new Result<>(code, msg, null);
    }

    public static <T> Result<T> error(String msg) {
        return new Result<>(500, msg, null);
    }
}
```

### 4. 自定义业务异常（BusinessException.java）

```java
package com.demo.exception;

import lombok.Data;
import lombok.EqualsAndHashCode;

/**
 * 业务异常：用于业务逻辑中的异常抛出（如用户不存在）
 */
@Data
@EqualsAndHashCode(callSuper = true)
public class BusinessException extends RuntimeException {
    private Integer code; // 异常状态码

    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
    }

    public BusinessException(String message) {
        super(message);
        this.code = 500; // 默认系统异常
    }
}
```

### 5. 全局异常处理器（GlobalExceptionHandler.java）

```java
package com.demo.exception;

import com.demo.common.Result;
import lombok.extern.slf4j.Slf4j;
import org.springframework.validation.BindException;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.servlet.NoHandlerFoundException;

/**
 * 全局异常处理器：捕获所有Controller层异常，统一返回格式
 */
@RestControllerAdvice // 作用于所有@RestController，返回JSON响应
@Slf4j // 日志注解
public class GlobalExceptionHandler {

    // 捕获自定义业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        log.error("业务异常：{}", e.getMessage(), e);
        return Result.error(e.getCode(), e.getMessage());
    }

    // 捕获@RequestBody参数校验异常
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldError().getDefaultMessage();
        log.error("参数校验异常：{}", msg, e);
        return Result.error(400, msg);
    }

    // 捕获@PathVariable/@RequestParam参数校验异常
    @ExceptionHandler(BindException.class)
    public Result<Void> handleBindException(BindException e) {
        String msg = e.getBindingResult().getFieldError().getDefaultMessage();
        log.error("参数绑定异常：{}", msg, e);
        return Result.error(400, msg);
    }

    // 捕获404异常
    @ExceptionHandler(NoHandlerFoundException.class)
    public Result<Void> handle404(NoHandlerFoundException e) {
        log.error("404异常：{}", e.getMessage(), e);
        return Result.error(404, "请求路径不存在");
    }

    // 捕获所有未处理的异常（兜底）
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常：", e); // 打印完整异常栈，便于排查
        return Result.error(500, "服务器内部异常，请联系管理员");
    }
}
```

### 8. Service层（UserService.java）

```java
package com.demo.service;

import com.demo.entity.User;
import com.demo.exception.BusinessException;
import com.demo.mapper.UserMapper;
import lombok.RequiredArgsConstructor;
import org.springframework.cache.annotation.Cacheable;
import org.springframework.stereotype.Service;

/**
 * 用户业务层：核心业务逻辑（缓存+数据库）
 */
@Service // 标记为服务层Bean，注册到IOC容器
@RequiredArgsConstructor // 生成final属性的构造方法，替代@Autowired
public class UserService {
    // 注入Mapper（final保证不可变，避免空指针）
    private final UserMapper userMapper;

    /**
     * 根据ID查询用户（优先查Redis缓存，未命中查数据库）
     * @Cacheable：缓存注解，核心规则见注解解析
     */
    @Cacheable(cacheNames = "user", key = "#id", unless = "#result == null")
    public User getUserById(Long id) {
        // 1. 业务参数校验
        if (id == null || id <= 0) {
            throw new BusinessException(400, "用户ID必须为正整数");
        }

        // 2. 缓存未命中时，查询数据库
        User user = userMapper.selectById(id);

        // 3. 数据不存在则抛业务异常
        if (user == null) {
            throw new BusinessException(404, "用户不存在");
        }

        return user;
    }
}
```

### 9. Controller层（UserController.java）

```java
package com.demo.controller;

import com.demo.common.Result;
import com.demo.entity.User;
import com.demo.service.UserService;
import lombok.RequiredArgsConstructor;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import jakarta.validation.constraints.Positive;

/**
 * 用户控制层：接收请求、返回响应（无业务逻辑）
 */
@RestController // 标记为REST控制器，返回JSON
@RequestMapping("/user") // 类级别路径：/api/user
@RequiredArgsConstructor // 注入Service
@Validated // 开启参数校验，使@Positive生效
public class UserController {
    private final UserService userService;

    /**
     * 根据ID查询用户
     * @param id 用户ID（@Positive要求必须为正整数）
     */
    @GetMapping("/{id}") // 方法级别路径：/api/user/{id}
    public Result<User> getUserById(
            @PathVariable 
            @Positive(message = "用户ID必须为正整数") Long id) {
        // 调用Service层处理业务
        User user = userService.getUserById(id);
        // 封装统一响应体返回
        return Result.success(user);
    }
}
```

## 三、测试验证（全链路验证）

1. **启动应用**：运行`UserApplication.java`的`main`方法，控制台输出`Started UserApplication in xxx seconds`表示启动成功。

2. **接口测试**：
   使用Postman/浏览器访问`http://localhost:8080/api/user/1`，验证不同场景：
   - **正常场景（缓存未命中）**：
     第一次请求会打印SQL日志（查询数据库），Redis中新增Key `demo:user:1`，响应结果：

     ```json
     {
       "code": 200,
       "msg": "操作成功",
       "data": {"id":1,"userName":"张三","age":25,"email":"zhangsan@test.com"}
     }
     ```

   - **缓存命中**：
     第二次请求无SQL日志（直接查Redis），响应速度更快，结果同上。
   - **参数异常（ID=0）**：
     访问`http://localhost:8080/api/user/0`，响应：

     ```json
     {
       "code": 400,
       "msg": "用户ID必须为正整数",
       "data": null
     }
     ```

   - **资源不存在（ID=2）**：
     访问`http://localhost:8080/api/user/2`，响应：

     ```json
     {
       "code": 404,
       "msg": "用户不存在",
       "data": null
     }
     ```

## 四、核心总结

1. **链路完整性**：代码覆盖`Controller`（接收请求）→`Service`（业务+缓存）→`Redis`（缓存）→`Mapper`（数据库）→`全局异常`（异常处理）全流程，与前文解析的链路完全对应。
2. **注解作用落地**：每个核心注解（如`@RestController`/`@Cacheable`/`@Validated`）都按解析的作用使用，无冗余/错误注解。
3. **最佳实践**：统一响应体+全局异常处理保证接口格式一致，缓存优先策略提升性能，参数校验避免脏数据，符合企业级开发规范。
