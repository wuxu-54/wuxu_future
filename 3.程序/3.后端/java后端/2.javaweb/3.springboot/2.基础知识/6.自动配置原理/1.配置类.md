# 配置类

## 一、配置类的核心概念

在 Spring 中，**配置类是替代传统 XML 配置的核心方式**，通过 `@Configuration` 注解标记的类，本质上是一个特殊的 Spring Bean（派生自 `@Component`），用于集中声明 Bean 定义、配置组件扫描、导入外部配置、绑定配置属性等。

### 核心价值

1. **替代 XML 配置**：完全摆脱 `<beans>`、`<bean>` 等 XML 标签，实现“零 XML”的纯注解开发。
2. **集中化配置**：将分散的 Bean 声明、配置逻辑聚合到统一的配置类中，便于维护。
3. **可编程性**：配置类是普通 Java 类，支持条件判断、循环、方法调用等编程逻辑，灵活性远超 XML。
4. **与 Spring Boot 深度融合**：Spring Boot 的自动配置核心就是基于配置类实现的（`@EnableAutoConfiguration`）。

### 配置类 vs 传统 XML 配置（对比）

| 特性                | 配置类（@Configuration）| 传统 XML 配置                |
|---------------------|---------------------------------|-----------------------------|
| 声明 Bean           | `@Bean` 注解的方法              | `<bean>` 标签                |
| 组件扫描            | `@ComponentScan` 注解           | `<context:component-scan>`  |
| 导入外部配置        | `@Import`/`@ImportResource`     | `<import>` 标签              |
| 配置属性绑定        | `@ConfigurationProperties`      | `<context:property-placeholder>` |
| 可编程性            | 支持 Java 代码逻辑（条件、循环） | 仅支持固定标签，无编程能力   |
| 可读性              | 代码结构化，易读                | 标签嵌套，可读性差           |
| 调试难度            | 直接调试 Java 代码              | 需解析 XML，调试困难         |

## 二、配置类的核心注解详解

配置类的核心是一系列注解的组合，以下是所有关键注解的详细说明：

### 1. 核心注解：`@Configuration`

这是标记配置类的**必选注解**，其核心属性和特性如下：

#### 核心属性

| 属性名           | 类型    | 默认值 | 说明                                                                 |
|------------------|---------|--------|----------------------------------------------------------------------|
| `value`          | String  | ""     | 配置类的 Bean 名称（同 `@Component` 的 value，默认类名首字母小写）|
| `proxyBeanMethods` | boolean | true   | 是否开启 Bean 方法的代理模式（核心！下文重点讲解）|

#### 核心特性

- **代理模式（proxyBeanMethods = true）**：默认开启，配置类会被 CGLIB 动态代理，确保 `@Bean` 方法之间的调用返回**同一个 Bean 实例**（单例保证）。
- **轻量级模式（proxyBeanMethods = false）**：关闭代理，配置类不会被代理，`@Bean` 方法调用会返回**新实例**，适用于无 Bean 依赖的场景，性能更高。

#### 示例：proxyBeanMethods 效果对比

```java
// 1. 代理模式（默认 true）
@Configuration // 等价于 @Configuration(proxyBeanMethods = true)
public class ProxyConfig {
    @Bean
    public UserService userService() {
        return new UserService();
    }

    @Bean
    public OrderService orderService() {
        // 调用 userService() 方法，返回同一个实例（代理拦截）
        UserService userService = userService(); 
        return new OrderService(userService);
    }
}

// 2. 轻量级模式（false）
@Configuration(proxyBeanMethods = false)
public class NonProxyConfig {
    @Bean
    public UserService userService() {
        return new UserService();
    }

    @Bean
    public OrderService orderService() {
        // 调用 userService() 方法，返回新实例（无代理）
        UserService userService = userService(); 
        return new OrderService(userService);
    }
}
```

**验证代码**：

```java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        ConfigurableApplicationContext context = SpringApplication.run(DemoApplication.class, args);
        
        // 代理模式：两个 userService 是同一个实例
        ProxyConfig proxyConfig = context.getBean(ProxyConfig.class);
        System.out.println(proxyConfig.userService() == proxyConfig.userService()); // true
        
        // 轻量级模式：两个 userService 是不同实例
        NonProxyConfig nonProxyConfig = context.getBean(NonProxyConfig.class);
        System.out.println(nonProxyConfig.userService() == nonProxyConfig.userService()); // false
        
        // 注意：通过上下文 getBean 获取的始终是单例（无论 proxyBeanMethods 取值）
        UserService user1 = context.getBean("userService", UserService.class);
        UserService user2 = context.getBean("userService", UserService.class);
        System.out.println(user1 == user2); // true
    }
}
```

### 2. 声明 Bean：`@Bean`

配置类中通过 `@Bean` 注解的方法声明 Bean，是替代 XML `<bean>` 标签的核心方式，其核心属性如下：

| 属性名         | 类型    | 默认值 | 说明                                                                 |
|----------------|---------|--------|----------------------------------------------------------------------|
| `name/value`   | String[]| {}     | Bean 的名称/别名（默认是方法名）|
| `initMethod`   | String  | ""     | Bean 初始化方法（替代 XML 的 init-method）|
| `destroyMethod`| String  | "(inferred)" | Bean 销毁方法（默认推断 close/shutdown 方法）|
| `autowire`     | Autowire| Autowire.NO | 自动装配模式（已过时，推荐构造器注入）|
| `primary`      | boolean | false  | 是否为首选 Bean（解决同类型多个 Bean 的注入冲突）|

#### 示例：@Bean 完整用法

```java
@Configuration
public class BeanConfig {
    // 1. 基础声明：指定名称、初始化/销毁方法
    @Bean(
        name = {"dataSource", "mysqlDataSource"},
        initMethod = "init",
        destroyMethod = "close"
    )
    public DataSource dataSource() {
        DruidDataSource dataSource = new DruidDataSource();
        dataSource.setUrl("jdbc:mysql://localhost:3306/test");
        dataSource.setUsername("root");
        dataSource.setPassword("123456");
        return dataSource;
    }

    // 2. 依赖注入：通过方法参数注入（推荐）
    @Bean
    public JdbcTemplate jdbcTemplate(DataSource dataSource) {
        return new JdbcTemplate(dataSource);
    }

    // 3. 首选 Bean：解决同类型多个 Bean 冲突
    @Bean
    @Primary
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);
        return template;
    }

    // 4. 条件化 Bean：仅当配置文件中开启 Redis 时创建
    @Bean
    @ConditionalOnProperty(name = "redis.enable", havingValue = "true")
    public RedisUtil redisUtil(RedisTemplate<String, Object> redisTemplate) {
        return new RedisUtil(redisTemplate);
    }
}
```

### 3. 组件扫描：`@ComponentScan`

用于指定 Spring 扫描注解 Bean（`@Component`/`@Service`/`@Controller` 等）的包路径，替代 XML 的 `<context:component-scan>`。

#### 核心属性

| 属性名            | 类型                | 默认值 | 说明                                                                 |
|-------------------|---------------------|--------|----------------------------------------------------------------------|
| `basePackages`    | String[]            | {}     | 要扫描的基础包路径（默认是配置类所在包）|
| `basePackageClasses` | Class<?>[]      | {}     | 以指定类所在包作为扫描路径（类型安全，推荐）|
| `includeFilters`  | Filter[]            | {}     | 包含过滤器（仅扫描符合条件的类）|
| `excludeFilters`  | Filter[]            | {}     | 排除过滤器（不扫描符合条件的类）|
| `useDefaultFilters` | boolean         | true   | 是否启用默认过滤器（扫描 @Component 及其派生注解）|

#### 示例：自定义组件扫描

```java
@Configuration
// 扫描 com.example.demo.service 和 com.example.demo.dao 包，排除 TestService
@ComponentScan(
    basePackages = {"com.example.demo.service", "com.example.demo.dao"},
    excludeFilters = {
        // 排除指定类
        @ComponentScan.Filter(type = FilterType.ASSIGNABLE_TYPE, value = TestService.class),
        // 排除标注 @Deprecated 的类
        @ComponentScan.Filter(type = FilterType.ANNOTATION, value = Deprecated.class)
    }
)
public class ScanConfig {}
```

### 4. 导入配置：`@Import`

用于导入其他配置类、普通类或自定义导入器，实现配置的模块化和复用，替代 XML 的 `<import>` 标签。

#### 三种导入场景

| 导入类型                | 效果                                                                 |
|-------------------------|----------------------------------------------------------------------|
| 导入普通类              | 直接将类注册为 Spring Bean（无需加 `@Component`）|
| 导入 `@Configuration` 类 | 导入并执行该配置类中的 `@Bean` 声明                                  |
| 导入 `ImportSelector`   | 动态选择要导入的类（返回类全限定名数组）|
| 导入 `ImportBeanDefinitionRegistrar` | 自定义 BeanDefinition 注册逻辑（最高灵活性）|

#### 示例：@Import 完整用法

```java
// 1. 普通类（无 @Component）
public class PayService {}

// 2. 其他配置类
@Configuration
public class RedisConfig {
    @Bean
    public RedisTemplate<String, Object> redisTemplate() {
        return new RedisTemplate<>();
    }
}

// 3. 自定义 ImportSelector
public class MyImportSelector implements ImportSelector {
    @Override
    public String[] selectImports(AnnotationMetadata importingClassMetadata) {
        // 动态返回要导入的类全限定名
        return new String[]{"com.example.demo.service.RefundService"};
    }
}

// 4. 主配置类：导入上述所有
@Configuration
@Import({PayService.class, RedisConfig.class, MyImportSelector.class})
public class MainConfig {}
```

### 5. 导入 XML 配置：`@ImportResource`

用于兼容传统 XML 配置，将 XML 中的 Bean 导入到 Spring 容器中。

#### 示例：

```java
// 导入 classpath 下的 applicationContext.xml
@Configuration
@ImportResource(locations = "classpath:applicationContext.xml")
public class XmlConfig {}
```

### 6. 配置属性绑定：`@PropertySource + @ConfigurationProperties`

`@PropertySource` 用于加载自定义配置文件，`@ConfigurationProperties` 用于将配置属性绑定到 Java 类（替代 `@Value` 批量注入）。

#### 示例：

```properties
# application-db.properties
db.url=jdbc:mysql://localhost:3306/test
db.username=root
db.password=123456
db.driver-class-name=com.mysql.cj.jdbc.Driver
```

```java
// 加载自定义配置文件 + 绑定属性
@Configuration
@PropertySource(value = "classpath:application-db.properties", encoding = "UTF-8")
@ConfigurationProperties(prefix = "db") // 绑定前缀为 db 的属性
public class DbConfig {
    private String url;
    private String username;
    private String password;
    private String driverClassName; // 自动映射 db.driver-class-name

    // 生成 getter/setter
    // 声明数据源 Bean
    @Bean
    public DataSource dataSource() {
        DruidDataSource dataSource = new DruidDataSource();
        dataSource.setUrl(url);
        dataSource.setUsername(username);
        dataSource.setPassword(password);
        dataSource.setDriverClassName(driverClassName);
        return dataSource;
    }
}
```

### 7. 条件配置：`@Conditional` 及派生注解

用于实现“条件化配置”——仅当满足指定条件时，配置类/Bean 才会生效，是 Spring Boot 自动配置的核心。

#### 核心派生注解（Spring Boot 提供）

| 注解                          | 条件说明                                                                 |
|-------------------------------|--------------------------------------------------------------------------|
| `@ConditionalOnClass`         | 类路径中存在指定类时生效                                                 |
| `@ConditionalOnMissingClass`  | 类路径中不存在指定类时生效                                               |
| `@ConditionalOnBean`          | 容器中存在指定 Bean 时生效                                               |
| `@ConditionalOnMissingBean`   | 容器中不存在指定 Bean 时生效（避免重复注册）|
| `@ConditionalOnProperty`      | 配置文件中存在指定属性（且值匹配）时生效                                 |
| `@ConditionalOnWebApplication`| 当前应用是 Web 应用（Servlet/Reactive）时生效                            |
| `@ConditionalOnNotWebApplication` | 当前应用不是 Web 应用时生效                                          |

#### 示例：条件化配置类

```java
// 仅当类路径中有 Redis 客户端时，该配置类才生效
@Configuration
@ConditionalOnClass(RedisTemplate.class)
// 仅当配置文件中 redis.enable = true 时生效
@ConditionalOnProperty(name = "redis.enable", havingValue = "true", matchIfMissing = true)
public class RedisAutoConfig {
    @Bean
    // 仅当容器中没有 RedisTemplate Bean 时才创建
    @ConditionalOnMissingBean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);
        // 设置序列化器
        Jackson2JsonRedisSerializer<Object> serializer = new Jackson2JsonRedisSerializer<>(Object.class);
        template.setValueSerializer(serializer);
        template.setKeySerializer(new StringRedisSerializer());
        return template;
    }
}
```

### 8. 懒加载：`@Lazy`

用于配置类级别或 `@Bean` 方法级别的懒加载，使 Bean 延迟到第一次使用时才创建（默认 singleton Bean 在容器启动时创建）。

#### 示例：

```java
@Configuration
@Lazy // 配置类中所有 @Bean 都默认懒加载
public class LazyConfig {
    @Bean
    @Lazy(false) // 覆盖配置类的懒加载，强制立即创建
    public DataSource dataSource() {
        return new DruidDataSource();
    }

    @Bean
    public RedisTemplate<String, Object> redisTemplate() {
        return new RedisTemplate<>();
    }
}
```

## 三、配置类的高级特性

### 1. 配置类的继承

配置类支持继承（extends），子类会继承父类的 `@Bean` 声明和注解配置（除非子类重写）。

#### 示例：

```java
// 父配置类
@Configuration
public class BaseConfig {
    @Bean
    public String appName() {
        return "demo-app";
    }
}

// 子配置类：继承并扩展
@Configuration
public class ChildConfig extends BaseConfig {
    // 重写父类的 Bean
    @Override
    @Bean
    public String appName() {
        return "demo-app-v2";
    }

    // 新增 Bean
    @Bean
    public String appVersion() {
        return "1.0.0";
    }
}
```

### 2. 嵌套配置类

配置类支持嵌套（内部类），用于将相关配置聚合到一个主配置类中，提高内聚性。

#### 示例：

```java
@Configuration
public class MainConfig {
    // 数据源配置（嵌套配置类）
    @Configuration
    static class DataSourceConfig {
        @Bean
        public DataSource dataSource() {
            return new DruidDataSource();
        }
    }

    // Redis 配置（嵌套配置类）
    @Configuration
    static class RedisConfig {
        @Bean
        public RedisTemplate<String, Object> redisTemplate() {
            return new RedisTemplate<>();
        }
    }

    // 主配置类的 Bean
    @Bean
    public JdbcTemplate jdbcTemplate(DataSource dataSource) {
        return new JdbcTemplate(dataSource);
    }
}
```

### 3. 配置类的优先级

当存在多个配置类时，Spring 会按以下优先级加载：

1. `@Order` 注解：数值越小，优先级越高（仅对 `@Configuration` 类生效）。
2. 加载顺序：手动导入的配置类 > 自动配置类（`@EnableAutoConfiguration`）。
3. `@Primary`：同类型 Bean 中，标记为 `@Primary` 的 Bean 优先被注入。

#### 示例：

```java
// 高优先级配置类
@Configuration
@Order(1)
public class HighPriorityConfig {
    @Bean
    @Primary // 首选 Bean
    public DataSource dataSource() {
        return new HikariDataSource();
    }
}

// 低优先级配置类
@Configuration
@Order(2)
public class LowPriorityConfig {
    @Bean
    public DataSource mysqlDataSource() {
        return new DruidDataSource();
    }
}
```

### 4. 配置类的刷新（Environment 变化）

Spring Boot 支持配置属性动态刷新（通过 `@RefreshScope`），配置类中绑定的属性可在运行时更新。

#### 示例：

```java
@Configuration
@ConfigurationProperties(prefix = "app")
@RefreshScope // 开启动态刷新
public class AppConfig {
    private String name;
    private String version;

    // getter/setter

    @Bean
    public String appInfo() {
        return name + "-" + version;
    }
}
```

### 5. 配置类的测试

Spring Test 提供 `@ContextConfiguration` 注解，用于指定测试用的配置类，替代启动类的自动配置。

#### 示例：

```java
// 测试类
@SpringBootTest
// 指定测试用的配置类（覆盖默认启动类的配置）
@ContextConfiguration(classes = {TestConfig.class, BeanConfig.class})
public class ConfigTest {
    @Autowired
    private DataSource dataSource;

    @Test
    public void testDataSource() {
        assertNotNull(dataSource);
    }
}

// 测试配置类
@Configuration
public class TestConfig {
    @Bean
    public DataSource dataSource() {
        // 测试用的内存数据源
        return new EmbeddedDatabaseBuilder()
                .setType(EmbeddedDatabaseType.H2)
                .build();
    }
}
```

## 四、配置类的最佳实践

### 1. 模块化拆分配置类

按功能拆分配置类（如 DataSourceConfig、RedisConfig、WebConfig），避免单个配置类过于臃肿。

### 2. 优先使用构造器注入

在 `@Bean` 方法中，优先通过方法参数注入依赖（而非调用其他 `@Bean` 方法），提高可读性和可测试性。

### 3. 合理设置 proxyBeanMethods

- 当 `@Bean` 方法之间有依赖调用时，保持 `proxyBeanMethods = true`（默认），确保单例。
- 当 `@Bean` 方法无依赖调用时，设置 `proxyBeanMethods = false`，提高性能。

### 4. 避免字段注入

配置类中避免使用 `@Autowired` 字段注入，优先使用构造器或方法参数注入（同普通 Bean）。

### 5. 配置属性绑定优先用 `@ConfigurationProperties`

批量配置属性时，优先使用 `@ConfigurationProperties`（类型安全、自动提示），而非多个 `@Value` 注解。

### 6. 条件化配置提高适配性

使用 `@ConditionalOnXxx` 注解，使配置类适配不同环境（开发/测试/生产），提高代码复用。

---

### 总结

1. **配置类核心本质**：`@Configuration` 标记的特殊 Bean，替代 XML 配置，用于集中声明 Bean、管理配置逻辑，是 Spring 注解驱动开发的核心。
2. **核心注解组合**：
   - `@Configuration`（核心）+ `@Bean`（声明 Bean）是基础；
   - `@ComponentScan`（扫描注解 Bean）、`@Import`（导入配置）实现模块化；
   - `@ConfigurationProperties`（绑定配置）、`@ConditionalOnXxx`（条件配置）适配不同环境。
3. **关键特性**：
   - `proxyBeanMethods` 控制 Bean 方法调用的代理行为（默认 true 保证单例）；
   - 配置类支持继承、嵌套、懒加载、动态刷新等高级特性；
   - 最佳实践是模块化拆分、优先构造器注入、合理使用条件配置。
4. **与 Spring Boot 融合**：Spring Boot 的自动配置核心是 `@EnableAutoConfiguration` 导入的自动配置类，本质是带条件注解的 `@Configuration` 类。
