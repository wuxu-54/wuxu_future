# `redis.conf`配置

Redis的`redis.conf`配置项数量较多（不同版本略有差异，如Redis6+新增ACL相关、Redis7+优化部分参数），以下按**功能模块**整理最常用、覆盖开发/生产环境的核心配置项，并标注作用：

---

## 一、redis.conf 核心配置项（按功能分类）

### 1. 基础网络配置（控制Redis网络监听）

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `bind` | `127.0.0.1` | 绑定Redis监听的IP地址，`127.0.0.1`仅允许本地访问；设为`0.0.0.0`允许所有IP访问（开发/生产必改） |
| `port` | `6379` | Redis监听的TCP端口，可自定义（如6380），需保证端口未被占用 |
| `tcp-backlog` | `511` | TCP连接队列长度，处理并发连接请求，高并发场景可适当调大（如1024） |
| `timeout` | `0` | 客户端空闲超时断开时间（单位：秒），`0`表示禁用超时（永不断开） |
| `tcp-keepalive` | `300` | TCP保活机制，每隔N秒检测客户端是否为死连接，`0`禁用，建议保持300秒 |

### 2. 安全配置（防止未授权访问/恶意操作）

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `protected-mode` | `yes` | 保护模式，开启时仅允许本地访问；配合`bind 0.0.0.0`时必须设为`no`（否则远程无法连接） |
| `requirepass` | 无 | 设置Redis连接密码，客户端需通过`AUTH 密码`验证后才能操作（生产环境必配） |
| `rename-command` | 无 | 重命名/禁用危险命令（如`CONFIG`/`FLUSHDB`/`FLUSHALL`），例：`rename-command CONFIG ""`（禁用CONFIG） |
| `aclfile` | 无 | Redis6+专属，指定ACL规则文件路径，实现细粒度用户权限控制（替代简单密码） |

### 3. 持久化配置（RDB+AOF，保证数据不丢失）

#### 3.1 RDB快照（默认开启）

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `save <秒> <修改数>` | `save 900 1`<br>`save 300 10`<br>`save 60 10000` | 触发RDB快照的条件：N秒内至少M次数据修改；`save ""`禁用RDB |
| `rdbcompression` | `yes` | 是否压缩RDB文件（LZF算法），节省磁盘但消耗CPU，生产建议保持`yes` |
| `rdbchecksum` | `yes` | 写入/加载RDB时校验文件完整性，防止文件损坏，建议保持`yes` |
| `dbfilename` | `dump.rdb` | RDB文件名称，可自定义（如`redis-6379.rdb`） |
| `dir` | `./` | RDB/AOF文件的存储目录（默认当前目录），生产需指定绝对路径（如`/usr/local/redis/data`） |

#### 3.2 AOF日志（默认关闭，生产建议开启）

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `appendonly` | `no` | 是否开启AOF持久化（比RDB更安全），生产建议设为`yes` |
| `appendfilename` | `appendonly.aof` | AOF文件名称 |
| `appendfsync` | `everysec` | AOF刷盘策略：<br>- `always`：每次写入都刷盘（最安全，性能最差）<br>- `everysec`：每秒刷盘（平衡安全/性能，推荐）<br>- `no`：交给操作系统刷盘（性能最好，数据风险高） |
| `auto-aof-rewrite-percentage` | `100` | AOF文件重写的增长阈值：文件大小比上次重写后增长100%触发重写 |
| `auto-aof-rewrite-min-size` | `64mb` | AOF重写的最小文件大小，低于该值不触发重写 |
| `aof-load-truncated` | `yes` | 加载损坏的AOF文件时是否截断（保证Redis能启动，丢失末尾损坏数据） |

### 4. 内存管理配置（防止内存耗尽）

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `maxmemory` | `0` | Redis最大可用内存（单位：字节，`0`表示无限制），生产**必须配置**（如`1gb`/`2048mb`） |
| `maxmemory-policy` | `noeviction` | 内存达到`maxmemory`时的淘汰策略：<br>- `volatile-lru`：淘汰过期键中最近最少使用的<br>- `allkeys-lru`：淘汰所有键中最近最少使用的（最常用）<br>- `volatile-ttl`：淘汰过期键中TTL最短的<br>- `noeviction`：不淘汰，返回错误（默认，生产需修改） |
| `maxmemory-samples` | `5` | LRU/TTL算法的采样数，值越高越准确但消耗CPU（建议5-10） |

### 5. 客户端连接配置

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `maxclients` | `10000` | 最大客户端连接数，超出则拒绝新连接（需保证系统文件描述符足够） |
| `client-output-buffer-limit` | `normal 0 0 0`<br>`slave 256mb 64mb 60` | 客户端输出缓冲区限制：<br>- `normal`：普通客户端（无限制）<br>- `slave`：从库客户端（防止大响应撑爆内存） |
| `tcp-nodelay` | `yes` | 是否禁用TCP_NODELAY，`yes`提升实时性（小数据包即时发送） |

### 6. 进程/日志配置

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `daemonize` | `no` | 是否以守护进程（后台）运行，`no`为前台运行（开发），`yes`为后台（生产必改） |
| `pidfile` | `/var/run/redis_6379.pid` | PID文件路径（`daemonize yes`时生效） |
| `loglevel` | `notice` | 日志级别：`debug`（调试）/`verbose`（详细）/`notice`（普通）/`warning`（警告） |
| `logfile` | `""` | 日志文件路径，`""`表示输出到标准输出（生产建议指定路径，如`/var/log/redis/redis.log`） |

### 7. 主从复制配置

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `replicaof <masterip> <masterport>` | 无 | 配置当前Redis为从库，指向主库IP和端口（Redis5+用`replicaof`替代旧版`slaveof`） |
| `masterauth <password>` | 无 | 主库的连接密码（主库设了`requirepass`时必须配置） |
| `replica-read-only` | `yes` | 从库是否只读，生产建议保持`yes`（防止误写） |
| `repl-ping-replica-period` | `10` | 从库向主库发送PING的间隔（单位：秒） |

### 8. 集群配置（Redis Cluster）

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `cluster-enabled` | `no` | 是否开启集群模式 |
| `cluster-config-file` | `nodes-6379.conf` | 集群节点配置文件（自动生成，无需手动修改） |
| `cluster-node-timeout` | `15000` | 集群节点超时时间（毫秒），超时则标记节点下线 |
| `cluster-require-full-coverage` | `yes` | 集群是否需要全槽覆盖，`no`表示部分槽不可用时仍可提供服务 |

### 9. 其他优化配置

| 配置项 | 默认值 | 作用 |
|--------|--------|------|
| `lazyfree-lazy-eviction` | `no` | 内存淘汰时是否异步释放内存（`yes`提升性能，避免阻塞） |
| `lazyfree-lazy-expire` | `no` | 过期键删除时是否异步释放内存 |
| `hash-max-ziplist-entries` | `512` | 哈希类型使用ziplist编码的最大元素数，超出则转为hashtable |
| `list-max-ziplist-size` | `-2` | 列表类型使用ziplist编码的最大大小（`-2`表示每个节点最大64字节） |

## 二、Redis 通用配置原则（所有环境通用）

Redis.conf没有“固定的最后一个配置项”（不同版本配置顺序、新增/删减项不同），但以下是**所有环境（开发/生产）都需遵循的通用配置核心原则**（可视为“通用最终配置准则”）：

```ini
# 通用配置核心（可直接添加到redis.conf末尾，覆盖默认值）
# 1. 基础安全
bind 0.0.0.0
protected-mode no
requirepass your_strong_password  # 替换为强密码
# 2. 持久化（生产必开AOF）
appendonly yes
appendfsync everysec
dir /usr/local/redis/data  # 统一数据存储目录
# 3. 内存限制（根据服务器配置调整）
maxmemory 2gb
maxmemory-policy allkeys-lru
# 4. 进程与日志
daemonize yes
logfile /var/log/redis/redis.log
loglevel notice
# 5. 禁用危险命令（可选）
rename-command FLUSHDB ""
rename-command FLUSHALL ""
```

---

### 总结

1. `redis.conf`核心配置按功能可分为**网络、安全、持久化、内存、客户端、日志、主从/集群**七大模块，生产环境需重点配置密码、内存限制、持久化、后台运行；
2. 无统一的“最后一个配置项”，但所有环境通用的核心配置需包含：绑定所有IP+关闭保护模式+设置密码+开启AOF+限制内存+后台运行；
3. 配置修改后需重启Redis生效，建议通过`redis-cli CONFIG GET 配置项`验证配置是否生效（如`CONFIG GET requirepass`）。
