# JDBC

## 一、JDBC 基础认知

### 1.1 什么是JDBC？

JDBC（Java Database Connectivity）是**Java官方提供的一套数据库访问标准（接口）**，而非具体实现。它定义了Java程序与各类关系型数据库（MySQL、Oracle、PostgreSQL等）交互的统一API，屏蔽了不同数据库的底层实现差异，让开发者无需关注数据库的具体类型，只需编写一套代码即可适配多种数据库。

### 1.2 JDBC 核心设计目标

- **统一接口**：提供标准化的类/接口，如`Connection`、`Statement`、`ResultSet`，适配所有遵循JDBC规范的数据库驱动；
- **解耦**：Java程序与数据库驱动解耦，更换数据库时只需替换驱动包和少量配置，无需修改核心业务代码；
- **可扩展**：数据库厂商只需实现JDBC接口，即可让Java程序访问其数据库（如MySQL驱动`mysql-connector-java`就是JDBC接口的实现）。

### 1.3 JDBC 核心组件（接口/类）

JDBC的核心组件都位于`java.sql`和`javax.sql`包下，关键组件如下：

| 组件 | 作用 | 核心方法/说明 |
|------|------|---------------|
| `DriverManager` | 驱动管理器，用于加载数据库驱动并获取`Connection` | `getConnection(url, user, password)`：获取数据库连接 |
| `Connection` | 数据库连接对象，代表Java程序与数据库的一次会话 | `createStatement()`：创建Statement<br>`prepareStatement(sql)`：创建PreparedStatement<br>`commit()`/`rollback()`：事务控制 |
| `Statement` | 执行静态SQL的对象（存在SQL注入风险） | `executeQuery(sql)`：执行查询，返回ResultSet<br>`executeUpdate(sql)`：执行增删改，返回影响行数 |
| `PreparedStatement` | 执行预编译SQL的对象（推荐使用） | 继承Statement，支持参数占位符`?`，可防止SQL注入 |
| `CallableStatement` | 执行存储过程的对象 | `prepareCall(sql)`：调用数据库存储过程 |
| `ResultSet` | 结果集对象，存储查询返回的数据 | `next()`：遍历行<br>`getXxx(column)`：获取列值（如getString、getInt） |
| `SQLException` | JDBC操作的异常类 | 封装数据库操作的错误信息（错误码、描述） |

## 二、原生JDBC 完整使用示例

以MySQL为例，展示原生JDBC的完整操作流程（查询用户信息），让你直观理解其使用方式：

### 2.1 步骤1：引入数据库驱动（Maven）

```xml
<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-java</artifactId>
    <version>8.0.33</version>
    <scope>runtime</scope>
</dependency>
```

### 2.2 步骤2：原生JDBC代码实现

```java
import java.sql.*;

public class JdbcDemo {
    // 数据库连接信息
    private static final String URL = "jdbc:mysql://localhost:3306/mybatis_demo?useSSL=false&serverTimezone=UTC";
    private static final String USER = "root";
    private static final String PASSWORD = "你的数据库密码";

    public static void main(String[] args) {
        // 声明资源对象（需手动关闭）
        Connection conn = null;
        PreparedStatement pstmt = null;
        ResultSet rs = null;

        try {
            // 1. 加载驱动（MySQL 8.0+可省略，自动加载）
            Class.forName("com.mysql.cj.jdbc.Driver");

            // 2. 获取数据库连接
            conn = DriverManager.getConnection(URL, USER, PASSWORD);

            // 3. 编写预编译SQL，使用?占位符
            String sql = "SELECT id, username, age FROM user WHERE id = ?";
            pstmt = conn.prepareStatement(sql);

            // 4. 设置参数（索引从1开始）
            pstmt.setInt(1, 1);

            // 5. 执行查询，获取结果集
            rs = pstmt.executeQuery();

            // 6. 遍历结果集
            while (rs.next()) {
                int id = rs.getInt("id");
                String username = rs.getString("username");
                int age = rs.getInt("age");
                System.out.println("用户信息：id=" + id + ", username=" + username + ", age=" + age);
            }

        } catch (ClassNotFoundException e) {
            e.printStackTrace(); // 驱动加载失败
        } catch (SQLException e) {
            e.printStackTrace(); // 数据库操作异常
        } finally {
            // 7. 关闭资源（逆序关闭：ResultSet → PreparedStatement → Connection）
            try {
                if (rs != null) rs.close();
                if (pstmt != null) pstmt.close();
                if (conn != null) conn.close();
            } catch (SQLException e) {
                e.printStackTrace();
            }
        }
    }
}
```

### 2.3 原生JDBC 的核心痛点

从上述示例可明显看出，原生JDBC存在大量重复且繁琐的工作，这也是JDBC框架诞生的核心原因：

1. **资源管理繁琐**：需手动创建/关闭`Connection`、`Statement`、`ResultSet`，漏关会导致连接泄漏；
2. **代码冗余**：每次数据库操作都要写加载驱动、获取连接、处理异常、关闭资源等重复代码；
3. **SQL硬编码**：SQL直接写在Java代码中，修改需重新编译，维护成本高；
4. **参数设置/结果映射繁琐**：手动设置`?`参数、手动遍历`ResultSet`映射为Java对象；
5. **事务控制手动化**：需手动调用`commit()`/`rollback()`，无自动事务管理；
6. **无连接池**：每次获取连接都新建，性能极低（数据库连接创建开销大）；
7. **异常处理复杂**：`SQLException`需手动捕获，无统一的异常转换机制。

## 三、主流JDBC 框架（解决原生JDBC痛点）

为解决原生JDBC的痛点，开发者基于JDBC规范封装了各类框架，按「封装程度」可分为两类：**轻量级封装框架**（仅简化操作，保留SQL可控性）和**全ORM框架**（自动生成SQL，屏蔽JDBC细节）。

### 3.1 轻量级JDBC框架（核心：简化操作，SQL可控）

#### 3.1.1 Spring JDBC（Spring内置）

Spring JDBC是Spring框架对JDBC的轻量级封装，核心是`JdbcTemplate`，它解决了原生JDBC的**资源管理、代码冗余、异常转换**问题，但仍需手动编写SQL和结果映射。

##### 核心优势

- 自动管理连接/Statement/ResultSet的创建与关闭，无需手动finally；
- 将`SQLException`转换为Spring统一的`DataAccessException`（非检查异常），简化异常处理；
- 提供模板方法（如`query()`、`update()`），减少重复代码；
- 支持JdbcTemplate、NamedParameterJdbcTemplate（支持命名参数）、SimpleJdbcInsert（简化插入）等工具类。

##### Spring JDBC 使用示例

1. 引入依赖（Spring Context + Spring JDBC + MySQL驱动）：

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework</groupId>
        <artifactId>spring-context</artifactId>
        <version>5.3.30</version>
    </dependency>
    <dependency>
        <groupId>org.springframework</groupId>
        <artifactId>spring-jdbc</artifactId>
        <version>5.3.30</version>
    </dependency>
    <dependency>
        <groupId>com.zaxxer</groupId>
        <artifactId>HikariCP</artifactId> <!-- 连接池（推荐） -->
        <version>5.0.1</version>
    </dependency>
    <dependency>
        <groupId>mysql</groupId>
        <artifactId>mysql-connector-java</artifactId>
        <version>8.0.33</version>
    </dependency>
</dependencies>
```

2. 配置数据源和JdbcTemplate（Spring配置类）：

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.jdbc.core.JdbcTemplate;
import com.zaxxer.hikari.HikariDataSource;

import javax.sql.DataSource;

@Configuration
public class SpringJdbcConfig {
    // 配置数据源（HikariCP连接池）
    @Bean
    public DataSource dataSource() {
        HikariDataSource dataSource = new HikariDataSource();
        dataSource.setJdbcUrl("jdbc:mysql://localhost:3306/mybatis_demo?useSSL=false&serverTimezone=UTC");
        dataSource.setUsername("root");
        dataSource.setPassword("你的数据库密码");
        dataSource.setDriverClassName("com.mysql.cj.jdbc.Driver");
        return dataSource;
    }

    // 配置JdbcTemplate
    @Bean
    public JdbcTemplate jdbcTemplate(DataSource dataSource) {
        return new JdbcTemplate(dataSource);
    }
}
```

3. 业务代码（查询用户）：

```java
import org.springframework.jdbc.core.BeanPropertyRowMapper;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class SpringJdbcDemo {
    public static void main(String[] args) {
        // 初始化Spring容器
        ApplicationContext context = new AnnotationConfigApplicationContext(SpringJdbcConfig.class);
        JdbcTemplate jdbcTemplate = context.getBean(JdbcTemplate.class);

        // 1. 查询单个对象（自动映射为User对象）
        String sql = "SELECT id, username, age FROM user WHERE id = ?";
        User user = jdbcTemplate.queryForObject(
            sql,
            new BeanPropertyRowMapper<>(User.class), // 结果映射器（字段名→属性名）
            1 // SQL参数
        );
        System.out.println(user);

        // 2. 执行更新操作（插入/更新/删除）
        String insertSql = "INSERT INTO user (username, age) VALUES (?, ?)";
        int affectedRows = jdbcTemplate.update(insertSql, "test", 20);
        System.out.println("插入行数：" + affectedRows);
    }
}

// User实体类（需与数据库字段名对应）
class User {
    private Integer id;
    private String username;
    private Integer age;
    // getter/setter/toString 省略
}
```

#### 3.1.2 MyBatis（半自动ORM，主流）

MyBatis是基于JDBC的半自动ORM框架，在Spring JDBC的基础上进一步解决了**SQL解耦、结果映射、动态SQL**问题，是目前Java后端最主流的JDBC框架（详细内容见上一轮讲解）。

核心特点：

- SQL与Java代码解耦（XML/注解存储SQL）；
- 自动完成参数设置和结果集到Java对象的映射；
- 支持动态SQL（`<if>`/`<where>`/`<foreach>`）；
- 内置一级/二级缓存，支持分页插件（PageHelper）；
- 保留SQL可控性（区别于全ORM框架）。

#### 3.1.3 Apache DBUtils（极简封装）

Apache DBUtils是Apache提供的极简JDBC工具类，仅解决「结果集映射」和「资源关闭」问题，代码量极少，适合小型项目或快速原型开发。

使用示例：

```java
import org.apache.dbutils.DbUtils;
import org.apache.dbutils.QueryRunner;
import org.apache.dbutils.handlers.BeanHandler;

import java.sql.Connection;
import java.sql.DriverManager;

public class DbUtilsDemo {
    public static void main(String[] args) throws Exception {
        // 1. 获取连接
        Connection conn = DriverManager.getConnection(
            "jdbc:mysql://localhost:3306/mybatis_demo?useSSL=false&serverTimezone=UTC",
            "root",
            "你的数据库密码"
        );

        // 2. 创建QueryRunner
        QueryRunner queryRunner = new QueryRunner();

        // 3. 执行查询，自动映射为User对象
        String sql = "SELECT id, username, age FROM user WHERE id = ?";
        User user = queryRunner.query(conn, sql, new BeanHandler<>(User.class), 1);
        System.out.println(user);

        // 4. 关闭资源（DbUtils自动处理null）
        DbUtils.close(conn);
    }
}
```

### 3.2 全ORM框架（自动生成SQL，屏蔽JDBC）

这类框架完全屏蔽了JDBC和SQL的细节，通过对象模型自动生成SQL，适合快速开发，但SQL可控性低（优化困难）。

#### 3.2.1 Hibernate（经典全ORM框架）

Hibernate是最早的全ORM框架，核心是「对象-关系映射」，开发者只需定义实体类与数据库表的映射关系，无需编写SQL，框架自动完成CRUD操作。

核心特点：

- 全自动ORM：无需编写SQL，通过HQL（Hibernate查询语言）或Criteria API查询；
- 缓存机制：一级缓存（Session）、二级缓存（SessionFactory）、查询缓存；
- 跨数据库兼容：自动生成适配不同数据库的SQL；
- 缺点：复杂查询的SQL优化困难，性能低于MyBatis。

#### 3.2.2 JPA（Java持久化规范）

JPA（Java Persistence API）是Java官方的ORM规范，Hibernate是其最主流的实现（还有EclipseLink、OpenJPA等）。JPA通过注解（如`@Entity`、`@Table`、`@Id`）定义实体映射，简化ORM开发。

使用示例（JPA查询）：

```java
// 1. 定义实体类
@Entity
@Table(name = "user")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;
    private String username;
    private Integer age;
    // getter/setter 省略
}

// 2. 定义Repository接口
public interface UserRepository extends JpaRepository<User, Integer> {
    // 自动生成SQL：SELECT * FROM user WHERE age = ?
    List<User> findByAge(Integer age);
}

// 3. 业务代码
UserRepository userRepository = context.getBean(UserRepository.class);
List<User> userList = userRepository.findByAge(18); // 无需编写SQL
```

#### 3.2.3 MyBatis-Plus（MyBatis增强版）

MyBatis-Plus是MyBatis的增强工具，在保留MyBatis SQL可控性的基础上，增加了全ORM的特性（自动生成基础CRUD SQL），兼顾了灵活性和开发效率，是目前最主流的「中间态」框架。

核心特点：

- 无侵入：完全兼容MyBatis，可无缝切换；
- 自动CRUD：继承`BaseMapper`即可获得增删改查方法，无需编写SQL；
- 条件构造器：通过Lambda表达式构建动态SQL；
- 内置分页、逻辑删除、自动填充等功能。

## 四、JDBC框架对比与选型建议

| 框架/方式 | 封装程度 | SQL可控性 | 开发效率 | 性能 | 适用场景 |
|-----------|----------|-----------|----------|------|----------|
| 原生JDBC | 无封装 | 完全可控 | 极低 | 高（无框架开销） | 学习/底层开发 |
| Spring JDBC | 轻量封装 | 完全可控 | 中 | 高 | 小型项目、简单SQL场景 |
| MyBatis | 中等封装 | 完全可控 | 中高 | 高 | 大部分企业级项目（推荐） |
| MyBatis-Plus | 中等封装 | 完全可控 | 高 | 高 | 企业级项目（兼顾效率与性能） |
| Hibernate/JPA | 完全封装 | 低 | 极高 | 中 | 快速开发、简单查询场景 |

### 选型核心原则

1. **优先选MyBatis/MyBatis-Plus**：兼顾SQL可控性和开发效率，适配90%以上的业务场景；
2. **小型项目/简单SQL**：可选Spring JDBC或Apache DBUtils；
3. **快速原型/无复杂查询**：可选JPA/Hibernate；
4. **底层优化/特殊场景**：原生JDBC（如高并发连接池开发）。

---

### 总结

1. **JDBC本质**：是Java访问数据库的标准接口，原生使用存在资源管理繁琐、代码冗余等痛点，因此衍生出各类封装框架；
2. **框架分类**：按封装程度分为「轻量级框架」（Spring JDBC、MyBatis，SQL可控）和「全ORM框架」（Hibernate/JPA，自动生成SQL）；
3. **选型建议**：企业级项目优先选择MyBatis/MyBatis-Plus，兼顾开发效率和SQL优化能力；小型项目可选用Spring JDBC，快速开发场景可选用JPA。
