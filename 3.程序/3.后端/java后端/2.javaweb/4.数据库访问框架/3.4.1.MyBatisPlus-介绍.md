# MyBatis-Plus

你希望我对 MyBatis-Plus（简称 MP）进行**全面、细致**的讲解，涵盖它的定义、核心特性、使用方法、高级功能及配置等所有关键维度，帮助你从基础到进阶彻底掌握这个框架。

## 一、MyBatis-Plus 基础认知

### 1. 什么是 MyBatis-Plus？

MyBatis-Plus 是基于 MyBatis 的**增强工具**，在 MyBatis 原有功能基础上做了无侵入式扩展（即不修改 MyBatis 核心代码），目的是**简化 CRUD 操作**，减少重复的 XML 或注解编写工作，同时提供丰富的高级特性（分页、逻辑删除、乐观锁等）。

核心定位：`MyBatis + 增强 = MyBatis-Plus`，开发者只需关注业务逻辑，无需编写大量基础 SQL。

### 2. 核心特性（无侵入是最大亮点）

| 特性                | 说明                                                                 |
|---------------------|----------------------------------------------------------------------|
| 无侵入              | 完全基于 MyBatis 扩展，不影响原有 MyBatis 逻辑                       |
| 自动 CRUD 操作      | 内置通用 Mapper/Service，无需编写基础增删改查 SQL                   |
| 条件构造器          | 强大的 Wrapper 条件查询，支持动态 SQL 拼接，告别字符串拼接的麻烦     |
| 分页插件            | 内置分页插件，支持多种数据库（MySQL、Oracle、PostgreSQL 等），分页零配置 |
| 主键生成策略        | 支持雪花算法、UUID、自增等多种主键生成方式，可自定义                 |
| 逻辑删除            | 无需手动处理逻辑删除，框架自动拦截 SQL 实现“假删除”                  |
| 乐观锁              | 内置乐观锁插件，解决并发更新问题                                     |
| 代码生成器          | 支持快速生成 Entity、Mapper、Service、Controller 等代码，减少重复工作 |
| 全局拦截器          | 支持自定义全局拦截，统一处理 SQL（如数据权限、字段加密）             |
| 多数据源            | 内置多数据源插件，轻松实现读写分离                                   |

### 3. 支持的数据库

MySQL、Oracle、PostgreSQL、SQL Server、MariaDB、SQLite、H2 等主流关系型数据库。

### 步骤 3：编写实体类（Entity）

```java
package com.example.mpdemo.entity;

import com.baomidou.mybatisplus.annotation.*;
import lombok.Data;
import java.time.LocalDateTime;

@Data // Lombok 注解，自动生成 getter/setter/toString 等
@TableName("t_user") // 指定数据库表名（如果表名和类名一致，可省略）
public class User {
    /**
     * 主键 ID
     * @TableId：标记主键字段，type 指定主键生成策略
     * ASSIGN_ID：雪花算法生成 Long 类型 ID
     * AUTO：数据库自增
     */
    @TableId(type = IdType.ASSIGN_ID)
    private Long id;

    /**
     * 用户名
     * @TableField：标记普通字段（如果字段名和属性名一致，可省略）
     */
    @TableField("username")
    private String username;

    /**
     * 密码
     */
    private String password;

    /**
     * 年龄
     */
    private Integer age;

    /**
     * 逻辑删除标记（0：未删除，1：已删除）
     * @TableLogic：标记逻辑删除字段
     */
    @TableLogic
    private Integer isDeleted;

    /**
     * 创建时间（自动填充）
     * @TableField(fill = FieldFill.INSERT)：插入时自动填充
     */
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    /**
     * 更新时间（自动填充）
     * @TableField(fill = FieldFill.INSERT_UPDATE)：插入/更新时自动填充
     */
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

## 三、核心功能详解（重点）

### 1. 通用 CRUD 接口

MP 提供了两套通用接口：

- `BaseMapper<T>`：Mapper 层接口，封装单表 CRUD（最基础）。
- `IService<T>` + `ServiceImpl<M extends BaseMapper<T>, T>`：Service 层接口，封装更丰富的 CRUD（如批量操作、分页查询）。

#### 1.1 BaseMapper 核心方法（常用）

| 方法名                | 功能                     | 参数说明                          |
|-----------------------|--------------------------|-----------------------------------|
| `insert(T entity)`    | 新增单条数据             | entity：要新增的实体对象          |
| `deleteById(Serializable id)` | 根据 ID 删除 | id：主键 ID                       |
| `deleteByMap(Map<String, Object> map)` | 根据条件删除 | map：key=字段名，value=字段值     |
| `delete(Wrapper<T> wrapper)` | 条件删除 | wrapper：条件构造器               |
| `deleteBatchIds(Collection<? extends Serializable> idList)` | 批量删除 | idList：主键 ID 集合              |
| `updateById(T entity)` | 根据 ID 更新 | entity：要更新的实体对象（非 null 字段才更新） |
| `update(T entity, Wrapper<T> wrapper)` | 条件更新 | entity：更新内容，wrapper：更新条件 |
| `selectById(Serializable id)` | 根据 ID 查询 | id：主键 ID                       |
| `selectBatchIds(Collection<? extends Serializable> idList)` | 批量查询 | idList：主键 ID 集合              |
| `selectByMap(Map<String, Object> map)` | 条件查询 | map：key=字段名，value=字段值     |
| `selectOne(Wrapper<T> wrapper)` | 查询单条 | wrapper：条件构造器（需确保结果唯一） |
| `selectCount(Wrapper<T> wrapper)` | 查询总数 | wrapper：条件构造器               |
| `selectList(Wrapper<T> wrapper)` | 查询列表 | wrapper：条件构造器               |
| `selectPage(IPage<T> page, Wrapper<T> wrapper)` | 分页查询 | page：分页参数，wrapper：条件构造器 |

#### 1.2 IService 核心方法（Service 层推荐使用）

先编写 Service 接口和实现类：

```java
// Service 接口
public interface UserService extends IService<User> {
    // 可自定义业务方法
}

// Service 实现类
@Service
public class UserServiceImpl extends ServiceImpl<UserMapper, User> implements UserService {
    // 无需编写基础方法，ServiceImpl 已实现
}
```

常用方法示例：

```java
@Autowired
private UserService userService;

// 批量新增
@Test
public void testSaveBatch() {
    List<User> userList = new ArrayList<>();
    userList.add(new User(null, "李四", "123456", 22, 0, null, null));
    userList.add(new User(null, "王五", "123456", 23, 0, null, null));
    boolean success = userService.saveBatch(userList); // 批量新增（默认批量大小 1000）
    System.out.println("批量新增是否成功：" + success);
}

// 分页查询
@Test
public void testPage() {
    // 构建分页参数：第 1 页，每页 2 条
    Page<User> page = new Page<>(1, 2);
    // 分页查询（无条件）
    IPage<User> userPage = userService.page(page);
    System.out.println("总记录数：" + userPage.getTotal());
    System.out.println("总页数：" + userPage.getPages());
    System.out.println("当前页数据：" + userPage.getRecords());
}

// 条件查询（链式调用）
@Test
public void testChainQuery() {
    List<User> userList = userService.lambdaQuery()
            .eq(User::getAge, 20) // 年龄等于 20
            .like(User::getUsername, "张") // 用户名包含“张”
            .list();
    userList.forEach(System.out::println);
}
```

### 2. 条件构造器（Wrapper）

MP 最强大的功能之一，用于动态拼接 SQL 条件，无需手动写 WHERE 子句。核心接口是 `Wrapper`，常用实现类：

| 实现类                | 适用场景                     | 特点                                  |
|-----------------------|------------------------------|---------------------------------------|
| `QueryWrapper<T>`     | 查询/删除条件构造            | 直接用字段名（字符串），易出错        |
| `UpdateWrapper<T>`    | 更新条件构造                 | 支持 SET 子句设置                     |
| `LambdaQueryWrapper<T>` | 查询/删除条件构造         | 用 Lambda 表达式，字段名编译期检查，无拼写错误 |
| `LambdaUpdateWrapper<T>` | 更新条件构造             | Lambda 表达式 + SET 子句             |

#### 2.1 常用条件方法（以 LambdaQueryWrapper 为例）

| 方法名         | SQL 等价条件       | 示例                                  |
|----------------|--------------------|---------------------------------------|
| `eq(R column, Object val)` | =                 | `eq(User::getAge, 20)` → age = 20     |
| `ne(R column, Object val)` | !=                | `ne(User::getAge, 20)` → age != 20    |
| `gt(R column, Object val)` | >                 | `gt(User::getAge, 20)` → age > 20     |
| `ge(R column, Object val)` | >=                | `ge(User::getAge, 20)` → age >= 20    |
| `lt(R column, Object val)` | <                 | `lt(User::getAge, 20)` → age < 20     |
| `le(R column, Object val)` | <=                | `le(User::getAge, 20)` → age <= 20    |
| `like(R column, Object val)` | LIKE '%val%' | `like(User::getUsername, "张")` → username LIKE '%张%' |
| `likeLeft(R column, Object val)` | LIKE '%val' | `likeLeft(User::getUsername, "张")` → username LIKE '%张' |
| `likeRight(R column, Object val)` | LIKE 'val%' | `likeRight(User::getUsername, "张")` → username LIKE '张%' |
| `isNull(R column)` | IS NULL           | `isNull(User::getAge)` → age IS NULL  |
| `isNotNull(R column)` | IS NOT NULL       | `isNotNull(User::getAge)` → age IS NOT NULL |
| `in(R column, Collection<?> coll)` | IN (coll) | `in(User::getAge, Arrays.asList(20,21,22))` → age IN (20,21,22) |
| `notIn(R column, Collection<?> coll)` | NOT IN (coll) | 同上，取反                            |
| `between(R column, Object val1, Object val2)` | BETWEEN val1 AND val2 | `between(User::getAge, 20, 30)` → age BETWEEN 20 AND 30 |
| `notBetween(R column, Object val1, Object val2)` | NOT BETWEEN val1 AND val2 | 同上，取反                            |
| `orderByAsc(R... columns)` | ORDER BY 字段 ASC | `orderByAsc(User::getAge)` → ORDER BY age ASC |
| `orderByDesc(R... columns)` | ORDER BY 字段 DESC | `orderByDesc(User::getAge)` → ORDER BY age DESC |
| `and(Consumer<LambdaQueryWrapper<T>> consumer)` | AND 嵌套条件 | 用于复杂 AND 条件                     |
| `or(Consumer<LambdaQueryWrapper<T>> consumer)` | OR 嵌套条件 | 用于复杂 OR 条件                      |

#### 2.2 条件构造器示例

```java
// 示例 1：LambdaQueryWrapper 查询
@Test
public void testLambdaQuery() {
    LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<User>()
            .eq(User::getAge, 20) // 年龄等于 20
            .like(User::getUsername, "张") // 用户名包含“张”
            .orderByDesc(User::getCreateTime); // 按创建时间降序

    List<User> userList = userMapper.selectList(queryWrapper);
    userList.forEach(System.out::println);
}

// 示例 2：UpdateWrapper 更新
@Test
public void testUpdateWrapper() {
    UpdateWrapper<User> updateWrapper = new UpdateWrapper<User>()
            .set("age", 25) // 设置要更新的字段和值
            .eq("username", "张三"); // 更新条件

    int rows = userMapper.update(null, updateWrapper);
    System.out.println("更新成功，受影响行数：" + rows);
}

// 示例 3：动态条件（避免拼接 null 条件）
@Test
public void testDynamicCondition() {
    String username = "张"; // 可能为 null
    Integer age = 20; // 可能为 null

    LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<User>();
    // 只有当 username 不为 null 时，才添加 like 条件
    if (username != null) {
        queryWrapper.like(User::getUsername, username);
    }
    // 只有当 age 不为 null 时，才添加 eq 条件
    if (age != null) {
        queryWrapper.eq(User::getAge, age);
    }

    List<User> userList = userMapper.selectList(queryWrapper);
    userList.forEach(System.out::println);
}
```

### 3. 分页插件

MP 内置分页插件，支持物理分页（真正的 LIMIT 分页），配置简单：

#### 3.1 配置分页插件（Spring Boot）

```java
package com.example.mpdemo.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MyBatisPlusConfig {

    /**
     * 配置分页插件
     */
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 添加分页插件，指定数据库类型（MySQL）
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

#### 3.2 分页查询示例

```java
// Mapper 层分页
@Test
public void testSelectPage() {
    // 1. 构建分页参数：第 1 页，每页 2 条
    Page<User> page = new Page<>(1, 2);

    // 2. 构建查询条件
    LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<User>()
            .gt(User::getAge, 18); // 年龄大于 18

    // 3. 分页查询
    Page<User> userPage = userMapper.selectPage(page, queryWrapper);

    // 4. 解析结果
    System.out.println("总记录数：" + userPage.getTotal()); // 符合条件的总记录数
    System.out.println("总页数：" + userPage.getPages());     // 总页数
    System.out.println("当前页：" + userPage.getCurrent());   // 当前页码
    System.out.println("每页条数：" + userPage.getSize());     // 每页条数
    System.out.println("当前页数据：" + userPage.getRecords()); // 当前页的实体列表
}

// Service 层分页（更简洁）
@Test
public void testServicePage() {
    Page<User> page = new Page<>(1, 2);
    LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<User>().gt(User::getAge, 18);
    IPage<User> userPage = userService.page(page, queryWrapper);
    // 解析结果同上
}
```

### 4. 主键生成策略

MP 支持多种主键生成策略，通过 `@TableId(type = IdType.XXX)` 配置，核心策略：

| IdType 枚举值 | 说明                                                                 |
|---------------|----------------------------------------------------------------------|
| `AUTO`        | 数据库自增（需确保数据库表主键设置为 AUTO_INCREMENT）                |
| `NONE`        | 无策略（需手动设置主键，否则插入时会报错）                           |
| `INPUT`       | 手动输入（需手动设置主键，和 NONE 类似，语义更明确）                 |
| `ASSIGN_ID`   | MP 生成雪花算法 ID（Long 类型，分布式环境下唯一，推荐）              |
| `ASSIGN_UUID` | MP 生成 UUID（String 类型，去掉横线，如：550e8400e29b41d4a716446655440000） |

**全局配置主键策略**（无需每个实体类单独配置）：

```yaml
mybatis-plus:
  global-config:
    db-config:
      id-type: assign_id # 全局默认雪花算法
```

### 5. 逻辑删除

逻辑删除是指：删除数据时不真正删除，而是修改一个“删除标记字段”（如 is_deleted），查询时自动过滤已删除的数据。

#### 5.1 配置逻辑删除

```yaml
mybatis-plus:
  global-config:
    db-config:
      # 逻辑删除字段名（数据库字段名）
      logic-delete-field: is_deleted
      # 逻辑未删除值
      logic-not-delete-value: 0
      # 逻辑已删除值
      logic-delete-value: 1
```

#### 5.2 实体类标记逻辑删除字段

```java
@TableLogic // 标记逻辑删除字段
private Integer isDeleted;
```

#### 5.3 逻辑删除效果

- 调用 `deleteById(1L)`：实际执行 `UPDATE t_user SET is_deleted=1 WHERE id=1 AND is_deleted=0`。
- 调用 `selectById(1L)`：实际执行 `SELECT * FROM t_user WHERE id=1 AND is_deleted=0`。
- 如需查询已删除的数据：手动编写 SQL，或使用 `wrapper.eq("is_deleted", 1)`。

### 6. 乐观锁

乐观锁用于解决并发更新时的“脏写”问题，核心思路：更新时检查版本号，只有版本号匹配才更新，更新后版本号+1。

#### 6.1 配置乐观锁插件

```java
@Configuration
public class MyBatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 分页插件
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        // 乐观锁插件
        interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
        return interceptor;
    }
}
```

#### 6.2 实体类添加版本号字段

```java
@Version // 标记乐观锁版本号字段
private Integer version;
```

#### 6.3 乐观锁使用示例

```java
@Test
public void testOptimisticLock() {
    // 1. 查询用户（获取当前版本号）
    User user = userMapper.selectById(1L); // 假设 version=1

    // 2. 修改用户信息
    user.setAge(25);

    // 3. 模拟并发：另一个线程先更新了该用户，version 变为 2
    User user2 = userMapper.selectById(1L);
    user2.setAge(30);
    userMapper.updateById(user2); // 更新成功，version=2

    // 4. 当前线程更新（version=1 不等于数据库的 version=2，更新失败）
    int rows = userMapper.updateById(user);
    System.out.println("更新受影响行数：" + rows); // 输出 0，表示更新失败
}
```

执行的 SQL：

- 第一次更新（user2）：`UPDATE t_user SET age=30, version=2 WHERE id=1 AND version=1`。
- 第二次更新（user）：`UPDATE t_user SET age=25, version=2 WHERE id=1 AND version=1`（无匹配数据，受影响行数 0）。

### 7. 自动填充

对于 `create_time`、`update_time`、`create_by`、`update_by` 等通用字段，可通过 MP 的自动填充功能，无需手动设置。

#### 7.1 编写自动填充处理器

```java
package com.example.mpdemo.handler;

import com.baomidou.mybatisplus.core.handlers.MetaObjectHandler;
import org.apache.ibatis.reflection.MetaObject;
import org.springframework.stereotype.Component;
import java.time.LocalDateTime;

@Component // 必须交给 Spring 管理
public class MyMetaObjectHandler implements MetaObjectHandler {

    /**
     * 插入时自动填充
     */
    @Override
    public void insertFill(MetaObject metaObject) {
        // 填充 createTime 字段（字段名是实体类的属性名，不是数据库字段名）
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, LocalDateTime.now());
        // 填充 updateTime 字段
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }

    /**
     * 更新时自动填充
     */
    @Override
    public void updateFill(MetaObject metaObject) {
        // 填充 updateTime 字段
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }
}
```

#### 7.2 实体类标记填充字段

```java
// 插入时填充
@TableField(fill = FieldFill.INSERT)
private LocalDateTime createTime;

// 插入/更新时填充
@TableField(fill = FieldFill.INSERT_UPDATE)
private LocalDateTime updateTime;
```

## 四、高级特性

### 1. 自定义 SQL

MP 支持自定义 SQL，可结合条件构造器使用：

#### 1.1 XML 自定义 SQL

```xml
<!-- src/main/resources/mapper/UserMapper.xml -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.mpdemo.mapper.UserMapper">
    <!-- 自定义查询：根据年龄范围查询用户名 -->
    <select id="selectUsernameByAgeRange" resultType="java.lang.String">
        SELECT username FROM t_user WHERE age BETWEEN #{minAge} AND #{maxAge}
    </select>

    <!-- 结合 Wrapper 自定义 SQL -->
    <select id="selectUserByWrapper" resultType="com.example.mpdemo.entity.User">
        SELECT * FROM t_user ${ew.customSqlSegment}
    </select>
</mapper>
```

#### 1.2 Mapper 接口定义方法

```java
public interface UserMapper extends BaseMapper<User> {
    // 自定义 SQL（基础）
    List<String> selectUsernameByAgeRange(@Param("minAge") Integer minAge, @Param("maxAge") Integer maxAge);

    // 结合 Wrapper 自定义 SQL
    List<User> selectUserByWrapper(@Param(Constants.WRAPPER) LambdaQueryWrapper<User> wrapper);
}
```

#### 1.3 测试自定义 SQL

```java
@Test
public void testCustomSql() {
    // 基础自定义 SQL
    List<String> usernameList = userMapper.selectUsernameByAgeRange(20, 30);
    System.out.println(usernameList);

    // 结合 Wrapper 的自定义 SQL
    LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<User>().eq(User::getIsDeleted, 0);
    List<User> userList = userMapper.selectUserByWrapper(wrapper);
    System.out.println(userList);
}
```

### 2. 多数据源

MP 结合 `dynamic-datasource-spring-boot-starter` 可快速实现多数据源（读写分离），核心步骤：

1. 引入依赖；
2. 配置多数据源；
3. 用 `@DS` 注解指定数据源。

## 五、核心注解总结

| 注解                | 作用                                                                 |
|---------------------|----------------------------------------------------------------------|
| `@TableName`        | 指定实体类对应的数据库表名（表名和类名不一致时使用）                 |
| `@TableId`          | 标记主键字段，指定主键生成策略                                       |
| `@TableField`       | 标记普通字段（字段名和属性名不一致、自动填充、忽略字段等）           |
| `@TableLogic`       | 标记逻辑删除字段                                                     |
| `@Version`          | 标记乐观锁版本号字段                                                 |
| `@EnumValue`        | 标记枚举字段的数据库存储值                                           |
| `@Ignore`           | 忽略该字段（不参与 CRUD 操作）                                       |

## 总结

MyBatis-Plus 是 MyBatis 的高效增强工具，核心优势和关键知识点如下：

1. **无侵入扩展**：基于 MyBatis 封装，不修改原有逻辑，学习成本低，可平滑过渡。
2. **通用 CRUD 简化开发**：BaseMapper/IService 封装了基础增删改查，无需编写重复 SQL。
3. **核心功能提升效率**：条件构造器（Wrapper）解决动态 SQL 拼接问题，分页/逻辑删除/乐观锁等插件开箱即用。
4. **灵活扩展**：支持自定义 SQL、多数据源、代码生成器等高级特性，满足复杂业务需求。

掌握 MP 的核心是：理解通用 CRUD 接口、熟练使用条件构造器、配置核心插件（分页、逻辑删除、乐观锁），在此基础上结合自定义 SQL 可应对绝大部分业务场景。
