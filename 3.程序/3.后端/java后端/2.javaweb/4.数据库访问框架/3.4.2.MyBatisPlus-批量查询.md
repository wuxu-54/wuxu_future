# 批量查询

## 一、核心前提（通用准备）

先准备基础实体类和Mapper，后续示例基于此：

```java
// 1. 数据库实体类（对应t_user表）
@Data
@TableName("t_user")
public class UserEntity {
    @TableId(type = IdType.AUTO)
    private Long id;         // 主键ID
    private String userName; // 用户名
    private Integer age;     // 年龄
    private String status;   // 状态（normal/disabled）
}

// 2. Mapper接口（继承MP的BaseMapper）
public interface UserMapper extends BaseMapper<UserEntity> {
}

// 3. Service层（可选，MP的IService提供更便捷的批量方法）
public interface UserService extends IService<UserEntity> {
}

@Service
public class UserServiceImpl extends ServiceImpl<UserMapper, UserEntity> implements UserService {
}
```

## 二、批量查询的核心场景与实现

### 场景1：根据主键ID批量查询（最常用）

MP的`BaseMapper`和`IService`都提供了直接根据主键集合查询的方法，是最简单、性能最优的批量查询方式。

#### 方式1：使用BaseMapper（DAO层）

```java
@Autowired
private UserMapper userMapper;

public List<UserEntity> batchQueryByIds(List<Long> idList) {
    // 核心方法：selectBatchIds，参数为主键集合（List/Set/数组）
    // 底层生成SQL：SELECT * FROM t_user WHERE id IN (1,2,3,...)
    List<UserEntity> userList = userMapper.selectBatchIds(idList);
    return userList;
}
```

#### 方式2：使用IService（Service层，更推荐）

IService封装了更友好的批量操作，还内置了空值校验：

```java
@Autowired
private UserService userService;

public List<UserEntity> batchQueryByIdsWithService(List<Long> idList) {
    // 核心方法：listByIds，功能和selectBatchIds一致，更符合Service层命名习惯
    List<UserEntity> userList = userService.listByIds(idList);
    return userList;
}
```

#### 关键注意点：

- 若传入的`idList`为空（size=0），MP会生成`WHERE id IN ()`的无效SQL，导致数据库报错！
- 优化写法（必加）：

  ```java
  public List<UserEntity> batchQueryByIdsSafe(List<Long> idList) {
      if (CollectionUtils.isEmpty(idList)) { // 导入org.springframework.util.CollectionUtils
          return Collections.emptyList(); // 返回空列表，避免SQL错误
      }
      return userService.listByIds(idList);
  }
  ```

### 场景2：根据自定义条件批量查询（IN条件）

若需要根据非主键字段（如`userName`、`status`）批量查询，使用MP的`QueryWrapper`/`LambdaQueryWrapper`构建IN条件。

#### 示例1：单字段IN批量查询

```java
public List<UserEntity> batchQueryByStatus(List<String> statusList) {
    if (CollectionUtils.isEmpty(statusList)) {
        return Collections.emptyList();
    }
    // LambdaQueryWrapper：类型安全，避免字段名拼写错误
    LambdaQueryWrapper<UserEntity> queryWrapper = new LambdaQueryWrapper<UserEntity>()
            .in(UserEntity::getStatus, statusList); // 等价于 WHERE status IN ('normal','disabled')
    
    // Service层方法：list(Wrapper)
    List<UserEntity> userList = userService.list(queryWrapper);
    return userList;
}
```

#### 示例2：多字段组合批量查询

```java
public List<UserEntity> batchQueryByAgeAndStatus(List<Integer> ageList, List<String> statusList) {
    if (CollectionUtils.isEmpty(ageList) || CollectionUtils.isEmpty(statusList)) {
        return Collections.emptyList();
    }
    LambdaQueryWrapper<UserEntity> queryWrapper = new LambdaQueryWrapper<UserEntity>()
            .in(UserEntity::getAge, ageList)       // age IN (20,25,30)
            .in(UserEntity::getStatus, statusList) // status IN ('normal')
            .gt(UserEntity::getId, 10);            // 额外条件：id > 10
    
    return userService.list(queryWrapper);
}
```

### 场景3：批量查询并分页（大数据量）

若批量查询的结果集很大（比如IN列表有1000+条），直接查全部会导致内存溢出，需结合MP的分页插件实现批量分页查询。

#### 步骤1：配置MP分页插件（SpringBoot）

```java
@Configuration
public class MyBatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 添加分页插件（适配MySQL，其他数据库需调整方言）
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

#### 步骤2：分页批量查询

```java
public IPage<UserEntity> batchQueryWithPage(List<String> statusList, int pageNum, int pageSize) {
    if (CollectionUtils.isEmpty(statusList)) {
        return new Page<>(pageNum, pageSize); // 返回空分页对象
    }
    // 1. 构建分页对象（页码从1开始，页大小自定义）
    IPage<UserEntity> page = new Page<>(pageNum, pageSize);
    
    // 2. 构建查询条件
    LambdaQueryWrapper<UserEntity> queryWrapper = new LambdaQueryWrapper<UserEntity>()
            .in(UserEntity::getStatus, statusList);
    
    // 3. 分页查询：page(分页对象, 查询条件)
    return userService.page(page, queryWrapper);
}

// 使用示例
public void testPageQuery() {
    List<String> statusList = Arrays.asList("normal");
    // 查询第1页，每页20条
    IPage<UserEntity> pageResult = batchQueryWithPage(statusList, 1, 20);
    System.out.println("总条数：" + pageResult.getTotal());
    System.out.println("总页数：" + pageResult.getPages());
    System.out.println("当前页数据：" + pageResult.getRecords());
}
```

### 场景4：复杂批量查询（自定义SQL）

若MP的内置方法无法满足复杂需求（比如多表联查、复杂函数计算），可自定义SQL实现批量查询。

#### 方式1：注解式自定义SQL（Mapper层）

```java
public interface UserMapper extends BaseMapper<UserEntity> {
    // 自定义批量查询：根据用户名列表+年龄范围查询
    @Select("SELECT * FROM t_user WHERE user_name IN (@Param('userNameList') userNameList) AND age BETWEEN #{minAge} AND #{maxAge}")
    List<UserEntity> batchQueryByUserNameAndAge(
            @Param("userNameList") List<String> userNameList,
            @Param("minAge") Integer minAge,
            @Param("maxAge") Integer maxAge);
}

// 使用
public List<UserEntity> testCustomBatchQuery() {
    List<String> userNameList = Arrays.asList("张三", "李四");
    return userMapper.batchQueryByUserNameAndAge(userNameList, 20, 30);
}
```

#### 方式2：XML文件自定义SQL（推荐复杂SQL）

1. 在resources/mapper下创建`UserMapper.xml`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.mapper.UserMapper">
    <!-- 批量查询：多表联查示例 -->
    <select id="batchQueryUserWithOrder" resultType="com.example.entity.UserEntity">
        SELECT u.* FROM t_user u
        LEFT JOIN t_order o ON u.id = o.user_id
        WHERE u.id IN
        <foreach collection="idList" item="id" open="(" separator="," close=")">
            #{id}
        </foreach>
        AND o.order_status = #{orderStatus}
    </select>
</mapper>
```

2. Mapper接口声明方法：

```java
public interface UserMapper extends BaseMapper<UserEntity> {
    List<UserEntity> batchQueryUserWithOrder(
            @Param("idList") List<Long> idList,
            @Param("orderStatus") String orderStatus);
}
```

3. 使用：

```java
public List<UserEntity> testXmlBatchQuery() {
    List<Long> idList = Arrays.asList(1L, 2L, 3L);
    return userMapper.batchQueryUserWithOrder(idList, "PAID");
}
```

## 三、批量查询最佳实践（避坑指南）

### 1. 避免IN列表过长

- 数据库对IN子句的参数数量有限制（MySQL默认无硬限制，但超过1000条会导致性能骤降）；
- 解决方案：分批次查询（比如每1000条查一次）：

  ```java
  public List<UserEntity> batchQueryByBatch(List<Long> idList) {
      if (CollectionUtils.isEmpty(idList)) {
          return Collections.emptyList();
      }
      List<UserEntity> result = new ArrayList<>();
      // 按每1000条分批次
      int batchSize = 1000;
      for (int i = 0; i < idList.size(); i += batchSize) {
          int end = Math.min(i + batchSize, idList.size());
          List<Long> subList = idList.subList(i, end);
          result.addAll(userService.listByIds(subList));
      }
      return result;
  }
  ```

### 2. 索引优化

- 批量查询的字段（如id、status、age）需建立索引，避免全表扫描；
- 示例：给`status`字段建索引：`CREATE INDEX idx_t_user_status ON t_user(status);`

### 3. 只查需要的字段

避免`SELECT *`，通过`select`方法指定字段，减少数据传输：

```java
LambdaQueryWrapper<UserEntity> queryWrapper = new LambdaQueryWrapper<UserEntity>()
        .in(UserEntity::getStatus, statusList)
        .select(UserEntity::getId, UserEntity::getUserName); // 只查id和userName
```

### 4. 空值与边界处理

- 必校验入参集合是否为空，避免生成`IN ()`的无效SQL；
- 分页查询时，校验页码（pageNum≥1）和页大小（pageSize≤1000），防止恶意请求。

## 总结

1. **基础批量查询**：根据主键用`listByIds/selectBatchIds`，自定义条件用`QueryWrapper.in`，是最常用的两种方式；
2. **大数据量场景**：结合分页插件分页码查询，或分批次（每1000条）执行IN查询，避免内存溢出；
3. **复杂场景**：通过自定义SQL（注解/XML）实现多表联查、复杂条件的批量查询；
4. **核心避坑**：校验入参空值、控制IN列表长度、优化索引、只查必要字段。

掌握这些方法，你可以高效处理MyBatis Plus中所有批量查询场景，兼顾性能和代码可读性。

## `LambdaQueryWrapper`和`QueryWrapper`的核心区别

### 一、核心区别（维度对比）

先通过表格直观对比两者的核心差异，这是理解的关键：

| 对比维度                | QueryWrapper                          | LambdaQueryWrapper                          |
|-------------------------|---------------------------------------|---------------------------------------------|
| **字段引用方式**        | 字符串指定字段名（如`"status"`）      | Lambda表达式引用实体类方法（如`User::getStatus`） |
| **类型安全**            | 无类型校验（字符串硬编码）            | 编译期类型校验（Lambda绑定实体类字段）      |
| **字段名错误检测**      | 运行时报错（字段名拼错只有查库时才发现） | 编译期报错（字段名拼错直接编译失败）        |
| **语法风格**            | 简洁但不直观，依赖字符串              | 稍繁琐但直观，强绑定实体类                  |
| **支持动态字段名**      | 支持（可传入变量字符串）              | 不支持（Lambda必须绑定固定实体类字段）      |
| **适用场景**            | 1. 动态字段查询（字段名是变量）<br>2. 非实体类字段查询（如联查表的字段） | 1. 常规实体类字段查询<br>2. 追求类型安全的场景<br>3. 团队协作（避免字段名拼写错误） |
| **核心缺点**            | 易因字段名拼写错误导致运行时异常      | 无法处理动态字段名、非实体类字段            |

### 二、具体示例对比（最直观理解）

基于之前的`UserEntity`（字段：id、userName、age、status），实现相同的查询需求（查询status为"normal"且age>20的用户），对比两者的写法：

#### 1. QueryWrapper 实现（字符串字段名）

```java
// QueryWrapper：通过字符串指定字段名
QueryWrapper<UserEntity> queryWrapper = new QueryWrapper<UserEntity>()
        .eq("status", "normal")  // 字符串"status"对应实体类的status字段
        .gt("age", 20);          // 字符串"age"对应实体类的age字段

List<UserEntity> userList = userService.list(queryWrapper);
```

##### 关键问题：

- 若不小心把`"status"`写成`"statues"`，**编译时完全不报错**，只有运行时执行SQL才会抛出「字段不存在」的异常；
- 若实体类字段名修改（比如`status`改`userStatus`），字符串引用的地方不会自动同步，需手动逐个修改，极易遗漏。

#### 2. LambdaQueryWrapper 实现（Lambda表达式）

```java
// LambdaQueryWrapper：通过Lambda表达式引用实体类的getter方法
LambdaQueryWrapper<UserEntity> lambdaQueryWrapper = new LambdaQueryWrapper<UserEntity>()
        .eq(UserEntity::getStatus, "normal")  // 绑定实体类的getStatus()方法
        .gt(UserEntity::getAge, 20);          // 绑定实体类的getAge()方法

List<UserEntity> userList = userService.list(lambdaQueryWrapper);
```

##### 核心优势：

- 若把`UserEntity::getStatus`写成`UserEntity::getStatues`（不存在的方法），**编译直接报错**，提前规避错误；
- 若实体类字段名修改（如`status`改`userStatus`），IDE会提示Lambda表达式中的方法引用错误，可一键批量重构，无需手动查找所有引用处。

### 三、补充说明（共性与特殊场景）

#### 1. 两者的共性

- 都继承自`AbstractWrapper`，支持所有MP的查询条件（eq/ne/gt/lt/in/like等）；
- 都可用于构建复杂查询条件（多条件组合、分组、排序、分页等）；
- 都支持动态条件拼接（比如通过if判断是否添加某个条件）。

### 2. 特殊场景：只能用QueryWrapper的情况

当需要**动态指定字段名**或**查询非实体类字段**（如多表联查的字段）时，LambdaQueryWrapper无法满足，只能用QueryWrapper：

```java
// 场景1：动态字段名（字段名是变量）
String fieldName = "age"; // 动态传入的字段名
QueryWrapper<UserEntity> wrapper = new QueryWrapper<UserEntity>()
        .gt(fieldName, 20); // 支持变量字段名，LambdaQueryWrapper做不到

// 场景2：多表联查（查询非当前实体类的字段）
QueryWrapper<UserEntity> wrapper = new QueryWrapper<UserEntity>()
        .select("u.id", "u.user_name", "o.order_no") // 联查订单表的order_no字段
        .leftJoin("t_order o on u.id = o.user_id")
        .eq("u.status", "normal");
```

#### 3. LambdaQueryWrapper的简化写法

MP提供了`Wrappers.lambdaQuery()`静态方法，可简化LambdaQueryWrapper的创建：

```java
// 简化写法（无需new LambdaQueryWrapper）
List<UserEntity> userList = userService.list(
        Wrappers.lambdaQuery(UserEntity.class)
                .eq(UserEntity::getStatus, "normal")
                .gt(UserEntity::getAge, 20)
);
```

### 四、最佳实践（怎么选？）

1. **优先使用LambdaQueryWrapper**：
   常规业务查询（基于实体类字段）、团队协作项目、追求代码健壮性时，首选LambdaQueryWrapper，利用编译期校验避免字段名拼写错误，降低维护成本。
2. **特殊场景用QueryWrapper**：
   动态字段名、多表联查（非实体字段）、自定义SQL拼接等场景，使用QueryWrapper。
3. **混合使用**：
   若既有固定字段又有动态字段，可基于QueryWrapper构建，核心固定字段尽量用Lambda方式（MP也支持`QueryWrapper.lambda()`切换）：

   ```java
   // QueryWrapper切换为Lambda模式，兼顾动态字段和类型安全
   QueryWrapper<UserEntity> wrapper = new QueryWrapper<UserEntity>()
           .lambda() // 切换为Lambda模式
           .eq(UserEntity::getStatus, "normal") // 类型安全的固定字段
           .gt("age", 20); // 动态字段（仍需字符串）
   ```

#### 总结

1. **核心差异**：LambdaQueryWrapper通过Lambda表达式绑定实体类字段，编译期校验（类型安全）；QueryWrapper通过字符串指定字段，无编译期校验（易出错）。
2. **使用选择**：常规场景优先LambdaQueryWrapper，动态字段/非实体字段场景用QueryWrapper。
3. **核心价值**：LambdaQueryWrapper解决了QueryWrapper「字段名硬编码易出错」的核心痛点，是MP推荐的主流写法。
