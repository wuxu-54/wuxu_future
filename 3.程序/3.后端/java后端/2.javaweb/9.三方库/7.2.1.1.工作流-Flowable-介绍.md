## 一、Flowable核心概念（先理清基础，避免混淆）

Flowable是基于Activiti发展而来的轻量级开源工作流引擎，完全兼容**BPMN 2.0** 规范，用于自动化企业级业务流程（如请假、审批、报销等）。
>不会一直保留任务进程，核心理念是存储流程状态到数据库里，所以无需关心任务task执行，但要关注数据库升级等处理。

### 1.1 核心术语（必须掌握）

| 术语                | 含义                                                                 |
|---------------------|----------------------------------------------------------------------|
| 流程定义（Process Definition） | 基于BPMN 2.0编写的静态流程模板（.bpmn20.xml文件），是流程的"蓝图"     |
| 流程实例（Process Instance）  | 流程定义的一次具体执行（如"张三2026-01-27的请假申请"）               |
| 任务（Task）        | 流程中需要人/系统处理的节点，核心分为：用户任务（人工处理）、服务任务（系统自动处理） |
| 网关（Gateway）     | 流程分支/聚合的控制节点（如排他网关、并行网关）                       |
| 执行实例（Execution）| 流程实例的执行路径（并行流程中一个流程实例对应多个执行实例）         |
| 流程变量（Variable）| 流程运行时的动态数据（如请假天数、申请人、审批意见）                 |
| 历史数据（History） | 流程执行的全量记录（实例启动/结束时间、任务处理人/时间、变量变更等） |
| 身份链接（IdentityLink） | 任务与用户/组的关联关系（如"审批任务分配给李四"）                   |

### 1.2 Flowable核心服务（SpringBoot自动注入）

Flowable的核心功能通过以下Service接口暴露，SpringBoot中可直接`@Autowired`注入：

- **RepositoryService**：流程定义的部署、查询、删除（操作静态流程定义）
- **RuntimeService**：流程实例的启动、挂起、终止、变量操作（操作运行时流程）
- **TaskService**：用户任务的查询、认领、完成、委派（操作人工任务）
- **HistoryService**：历史流程/任务/变量的查询（审计、统计）
- **IdentityService**：用户/组的管理（一般结合业务系统用户体系，不推荐用内置）
- **FormService**：流程表单相关（可选）
- **ManagementService**：引擎管理（如作业、定时器）

### 2.3 自动建表说明

Flowable启动时会自动在配置的数据库中创建约60张表，表名前缀规则：

- `ACT_RE_*`：Repository（流程定义、资源）
- `ACT_RU_*`：Runtime（运行时流程实例、任务、变量）
- `ACT_HI_*`：History（历史数据）
- `ACT_ID_*`：Identity（内置用户/组，生产环境建议不用）
- `ACT_GE_*`：General（通用数据，如二进制资源）

## 三、流程设计（BPMN 2.0实战）

以**请假流程**为例，讲解流程设计的核心步骤（新手推荐用Camunda Modeler工具，免费且易用）。

### 3.1 设计工具准备

1. 下载Camunda Modeler：<https://camunda.com/download/modeler/>
2. 打开工具，新建“BPMN Diagram”，绘制如下流程：

   ```
   开始事件 → 用户任务（填写请假单） → 用户任务（经理审批） → 排他网关 → 
   ✅ 审批通过 → 结束事件
   ❌ 审批拒绝 → 结束事件
   ```

### 3.2 核心元素配置（关键）

#### （1）流程基础信息

- ID：`leave-process`（流程定义唯一标识）
- 名称：`请假流程`
- 版本：自动生成（部署时递增）

#### （2）用户任务配置

| 任务ID        | 任务名称   | 分配方式       | 配置值                          |
|---------------|------------|----------------|---------------------------------|
| fillLeaveForm | 填写请假单 | 固定分配       | `applyUser`（流程变量，动态传值） |
| managerApprove | 经理审批   | 表达式分配     | `${manager}`（流程变量）        |

#### （3）排他网关配置

- 网关ID：`approvalGateway`
- 出口序列流（连线）配置：
  - 审批通过：条件`${approvalResult == 'approved'}`，目标结束事件
  - 审批拒绝：条件`${approvalResult == 'rejected'}`，目标结束事件

### 3.3 导出BPMN文件

将设计好的流程保存为`leave-process.bpmn20.xml`，放入`src/main/resources/processes`（Flowable默认扫描此目录的流程文件，自动部署）。

## 四、Flowable核心API实战（完整代码）

### 4.1 流程部署（RepositoryService）

```java
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.RepositoryService;
import org.flowable.engine.repository.Deployment;
import org.flowable.engine.repository.ProcessDefinition;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
@Slf4j
@RequiredArgsConstructor
public class FlowDeployService {

    private final RepositoryService repositoryService;//通过Engine获取 ProcessEngines.getDefaultProcessEngine().getRepositoryService();

    /**
     * 手动部署流程（Flowable会自动部署resources/processes下的文件，此方法用于手动部署）
     */
    public String deployProcess() {
        // 部署流程文件（支持classpath/文件系统/输入流）
        Deployment deployment = repositoryService.createDeployment()
                .name("请假流程-手动部署") // 部署名称
                .addClasspathResource("processes/leave-process.bpmn20.xml") // 流程文件路径
                .deploy(); // 执行部署

        // 查询部署后的流程定义
        ProcessDefinition processDefinition = repositoryService.createProcessDefinitionQuery()
                .deploymentId(deployment.getId())
                .singleResult();

        log.info("流程部署成功：部署ID={}, 流程定义ID={}, 流程Key={}, 版本={}",
                deployment.getId(),
                processDefinition.getId(),
                processDefinition.getKey(),
                processDefinition.getVersion());

        return deployment.getId();
    }

    /**
     * 查询所有流程定义
     */
    public List<ProcessDefinition> listProcessDefinitions() {
        return repositoryService.createProcessDefinitionQuery()
                .orderByProcessDefinitionVersion()
                .desc()
                .list();
    }

    /**
     * 挂起/激活流程定义（挂起后无法启动新实例）
     */
    public void suspendProcessDefinition(String processDefinitionId, boolean suspend) {
        if (suspend) {
            repositoryService.suspendProcessDefinitionById(processDefinitionId);
            log.info("流程定义{}已挂起", processDefinitionId);
        } else {
            repositoryService.activateProcessDefinitionById(processDefinitionId);
            log.info("流程定义{}已激活", processDefinitionId);
        }
    }
}
```

### 4.2 启动流程实例（RuntimeService）

```java
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.RuntimeService;
import org.flowable.engine.runtime.ProcessInstance;
import org.springframework.stereotype.Service;

import java.util.HashMap;
import java.util.Map;

@Service
@Slf4j
@RequiredArgsConstructor
public class FlowInstanceService {

    private final RuntimeService runtimeService;

    /**
     * 启动请假流程实例
     * @param applyUserId 申请人ID
     * @param managerId 审批经理ID
     * @param leaveDays 请假天数
     * @return 流程实例ID
     */
    public String startLeaveProcess(String applyUserId, String managerId, Integer leaveDays) {
        // 流程变量（传递给任务分配、网关条件等）
        Map<String, Object> variables = new HashMap<>();
        variables.put("applyUser", applyUserId); // 填写请假单的任务分配人
        variables.put("manager", managerId); // 经理审批的任务分配人
        variables.put("leaveDays", leaveDays); // 业务变量：请假天数

        // 启动流程实例（根据流程Key，自动使用最新版本）
        ProcessInstance processInstance = runtimeService.startProcessInstanceByKey(
                "leave-process", // 流程定义Key（设计时的ID）
                variables // 流程变量
        );

        log.info("流程实例启动成功：实例ID={}, 流程定义ID={}, 申请人={}",
                processInstance.getId(),
                processInstance.getProcessDefinitionId(),
                applyUserId);

        return processInstance.getId();
    }

    /**
     * 终止流程实例
     */
    public void terminateProcessInstance(String processInstanceId) {
        runtimeService.deleteProcessInstance(
                processInstanceId,
                "用户主动终止" // 终止原因
        );
        log.info("流程实例{}已终止", processInstanceId);
    }

    /**
     * 设置流程变量（运行时动态修改）
     */
    public void setProcessVariable(String processInstanceId, String varName, Object varValue) {
        runtimeService.setVariable(processInstanceId, varName, varValue);
        log.info("流程实例{}设置变量{}={}", processInstanceId, varName, varValue);
    }
}
```

### 4.3 任务处理（TaskService）

```java
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.TaskService;
import org.flowable.task.api.Task;
import org.springframework.stereotype.Service;

import java.util.HashMap;
import java.util.List;
import java.util.Map;

@Service
@Slf4j
@RequiredArgsConstructor
public class FlowTaskService {

    private final TaskService taskService;

    /**
     * 查询用户待办任务
     */
    public List<Task> listTodoTasks(String userId) {
        return taskService.createTaskQuery()
                .taskAssignee(userId) // 分配给当前用户的任务
                .active() // 激活的任务
                .orderByTaskCreateTime()
                .desc()
                .list();
    }

    /**
     * 完成“填写请假单”任务
     */
    public void completeFillLeaveForm(String taskId) {
        // 填写请假单无需额外变量，直接完成
        taskService.complete(taskId);
        log.info("任务{}（填写请假单）已完成", taskId);
    }

    /**
     * 完成“经理审批”任务
     */
    public void completeManagerApprove(String taskId, boolean approved) {
        // 审批结果变量（用于网关判断）
        Map<String, Object> variables = new HashMap<>();
        variables.put("approvalResult", approved ? "approved" : "rejected"); // 审批结果
        variables.put("approvalComment", approved ? "同意请假" : "请假天数过多，拒绝"); // 审批意见

        // 完成任务并传递变量
        taskService.complete(taskId, variables);
        log.info("任务{}（经理审批）已完成，审批结果={}", taskId, approved ? "通过" : "拒绝");
    }

    /**
     * 认领任务（任务未分配时，用户手动认领）
     */
    public void claimTask(String taskId, String userId) {
        taskService.claim(taskId, userId);
        log.info("用户{}认领任务{}", userId, taskId);
    }

    /**
     * 委派任务（将任务转给其他人处理）
     */
    public void delegateTask(String taskId, String userId) {
        taskService.delegateTask(taskId, userId);
        log.info("任务{}委派给用户{}", taskId, userId);
    }
}
```

### 4.4 历史数据查询（HistoryService）

```java
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.HistoryService;
import org.flowable.engine.history.HistoricProcessInstance;
import org.flowable.engine.history.HistoricTaskInstance;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
@Slf4j
@RequiredArgsConstructor
public class FlowHistoryService {

    private final HistoryService historyService;

    /**
     * 查询流程实例历史
     */
    public HistoricProcessInstance getHistoricProcessInstance(String processInstanceId) {
        return historyService.createHistoricProcessInstanceQuery()
                .processInstanceId(processInstanceId)
                .singleResult();
    }

    /**
     * 查询流程所有历史任务
     */
    public List<HistoricTaskInstance> listHistoricTasks(String processInstanceId) {
        return historyService.createHistoricTaskInstanceQuery()
                .processInstanceId(processInstanceId)
                .orderByHistoricTaskInstanceEndTime()
                .asc()
                .list();
    }

    /**
     * 查询用户已完成的任务
     */
    public List<HistoricTaskInstance> listCompletedTasks(String userId) {
        return historyService.createHistoricTaskInstanceQuery()
                .taskAssignee(userId)
                .finished() // 已完成
                .list();
    }
}
```

## 五、Flowable高级特性（实战）

### 5.1 网关使用（核心）

#### （1）排他网关（Exclusive Gateway）

- 作用：根据条件只走一条分支（如审批通过/拒绝）
- 配置：序列流的`Condition`填写EL表达式（`${approvalResult == 'approved'}`）
- 注意：必须设置默认分支（否则无匹配条件时流程报错）

#### （2）并行网关（Parallel Gateway）

- 作用：同时触发多个分支（如请假流程中，经理审批+HR审批并行）
- 配置：
  - 入网关：拆分流程为并行分支
  - 出网关：等待所有分支完成后聚合
- 代码：无需特殊处理，Flowable自动并行执行

#### （3）包含网关（Inclusive Gateway）

- 作用：根据条件触发多个分支（非全部并行）
- 配置：每个序列流设置条件，满足条件的分支都会执行

### 5.2 监听器（流程/任务事件监听）

#### （1）执行监听器（Process Execution Listener）

监听流程实例的生命周期（启动、结束、进入节点、离开节点）：

```java
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.delegate.DelegateExecution;
import org.flowable.engine.delegate.ExecutionListener;
import org.springframework.stereotype.Component;

@Component
@Slf4j
public class LeaveProcessListener implements ExecutionListener {

    @Override
    public void notify(DelegateExecution execution) {
        // 获取事件类型（START/END/TAKE）
        String eventName = execution.getEventName();
        String processInstanceId = execution.getProcessInstanceId();
        String activityId = execution.getCurrentActivityId(); // 当前节点ID

        if ("START".equals(eventName)) {
            log.info("流程实例{}启动，触发节点{}", processInstanceId, activityId);
            // 可执行：发送通知、初始化数据等
        } else if ("END".equals(eventName)) {
            log.info("流程实例{}结束，触发节点{}", processInstanceId, activityId);
            // 可执行：更新业务状态、记录日志等
        }
    }
}
```

在BPMN文件中配置监听器：

```xml
<process id="leave-process" name="请假流程">
  <extensionElements>
    <flowable:executionListener event="start" delegateExpression="${leaveProcessListener}"/>
    <flowable:executionListener event="end" delegateExpression="${leaveProcessListener}"/>
  </extensionElements>
  <!-- 其他节点 -->
</process>
```

#### （2）任务监听器（Task Listener）

监听任务的生命周期（创建、分配、完成、删除）：

```java
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.delegate.DelegateTask;
import org.flowable.engine.delegate.TaskListener;
import org.springframework.stereotype.Component;

@Component
@Slf4j
public class LeaveTaskListener implements TaskListener {

    @Override
    public void notify(DelegateTask delegateTask) {
        String eventName = delegateTask.getEventName();
        String taskId = delegateTask.getId();
        String assignee = delegateTask.getAssignee();

        if ("create".equals(eventName)) {
            log.info("任务{}创建，分配给{}", taskId, assignee);
            // 可执行：发送待办通知（短信/邮件）
        } else if ("complete".equals(eventName)) {
            log.info("任务{}已完成，处理人{}", taskId, assignee);
            // 可执行：更新任务状态、记录操作日志
        }
    }
}
```

在BPMN文件的用户任务中配置：

```xml
<userTask id="managerApprove" name="经理审批">
  <extensionElements>
    <flowable:taskListener event="create" delegateExpression="${leaveTaskListener}"/>
    <flowable:taskListener event="complete" delegateExpression="${leaveTaskListener}"/>
  </extensionElements>
  <potentialOwner>
    <resourceAssignmentExpression>
      <formalExpression>${manager}</formalExpression>
    </resourceAssignmentExpression>
  </potentialOwner>
</userTask>
```

### 5.3 服务任务（Service Task）

用于执行系统自动逻辑（无需人工干预），如：调用接口、更新数据库、发送消息。

#### 实现方式1：JavaDelegate（推荐）

```java
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.delegate.DelegateExecution;
import org.flowable.engine.delegate.JavaDelegate;
import org.springframework.stereotype.Component;

@Component
@Slf4j
public class SendLeaveNotifyService implements JavaDelegate {

    @Override
    public void execute(DelegateExecution execution) {
        // 获取流程变量
        String applyUser = (String) execution.getVariable("applyUser");
        Integer leaveDays = (Integer) execution.getVariable("leaveDays");
        String approvalResult = (String) execution.getVariable("approvalResult");

        // 执行自动逻辑：发送通知（示例）
        String notifyContent = String.format("用户%s的%s天请假申请，审批结果：%s",
                applyUser, leaveDays, approvalResult);
        log.info("发送请假通知：{}", notifyContent);

        // 可扩展：调用短信/邮件接口、更新业务表等
    }
}
```

在BPMN文件中配置服务任务：

```xml
<serviceTask id="sendNotify" name="发送请假通知">
  <extensionElements>
    <flowable:class>org.example.flowable.service.SendLeaveNotifyService</flowable:class>
  </extensionElements>
</serviceTask>
```

#### 实现方式2：表达式（简化）

```xml
<serviceTask id="sendNotify" name="发送请假通知">
  <extensionElements>
    <flowable:expression>${leaveService.sendNotify(applyUser, leaveDays, approvalResult)}</flowable:expression>
  </extensionElements>
</serviceTask>
```

### 5.4 多实例任务（会签）

用于“多人审批，需满足一定条件（如半数通过）”的场景（如部门多人审批请假）：

```xml
<userTask id="multiApprove" name="多人会签审批">
  <multiInstanceLoopCharacteristics isSequential="false"> <!-- false：并行会签；true：串行 -->
    <loopCardinality>${approvers.size()}</loopCardinality> <!-- 会签人数 -->
    <completionCondition>${nrOfCompletedInstances >= nrOfInstances * 0.5}</completionCondition> <!-- 半数通过 -->
    <collection>${approvers}</collection> <!-- 审批人列表（流程变量） -->
    <elementVariable>approver</elementVariable> <!-- 单个审批人变量 -->
  </multiInstanceLoopCharacteristics>
  <potentialOwner>
    <resourceAssignmentExpression>
      <formalExpression>${approver}</formalExpression>
    </resourceAssignmentExpression>
  </potentialOwner>
</userTask>
```

## 六、生产环境关键注意事项（重中之重）

### 6.1 性能优化

1. **数据库优化**：
   - 给Flowable核心表加索引（如`ACT_RU_TASK.ACT_ID_`、`ACT_HI_TASKINST.PROC_INST_ID_`）；
   - 分库分表：高并发场景下，将`ACT_RU_*`（运行时）和`ACT_HI_*`（历史）分库存储；
   - 定期清理历史数据：`ACT_HI_*`表会持续增长，写定时任务清理过期数据（保留核心审计数据）。
2. **异步执行**：
   - 耗时的服务任务（如调用外部接口）改为异步执行（配置`async="true"`），避免阻塞流程；
   - 开启Flowable异步执行器（`flowable.async-executor-activate=true`），配置合理的线程池大小。
3. **缓存优化**：
   - 开启流程定义缓存（Flowable默认开启），避免重复解析BPMN文件；
   - 对高频查询的待办任务，增加本地缓存（如Redis），减少数据库查询。

### 6.2 事务管理

1. **Flowable与Spring事务整合**：
   - Flowable默认使用Spring事务管理器，确保流程操作（如启动实例、完成任务）在事务内执行；
   - 避免在监听器/服务任务中执行非事务操作（如发送MQ），建议用`TransactionSynchronization`在事务提交后执行。
2. **事务边界**：
   - 单个流程操作（如`completeTask`）不要跨多个事务；
   - 批量操作（如批量完成任务）建议手动控制事务（`@Transactional(rollbackFor = Exception.class)`）。

### 6.3 流程版本管理

1. **版本策略**：
   - 流程定义修改后，重新部署会生成新版本（版本号递增）；
   - 已启动的流程实例仍使用旧版本，新实例使用新版本（兼容升级）。
2. **避免硬编码**：
   - 流程Key、任务ID、变量名不要硬编码在代码中，建议抽为常量；
   - 流程变更时，做好版本兼容（如旧实例的变量缺失处理）。

### 6.4 异常处理

1. **流程中断处理**：
   - 服务任务执行失败时，配置重试机制（`flowable:failedJobRetryTimeCycle="R3/PT5M"`：重试3次，每次间隔5分钟）；
   - 无法重试的失败任务，手动介入处理（通过`ManagementService`查询失败作业）。
2. **任务回退/驳回**：
   - Flowable无原生回退API，需自定义实现（如：删除当前任务，重新创建上一节点任务）；
   - 回退时注意流程变量的一致性（如重置审批结果）。
3. **避免流程死锁**：
   - 并行网关必须成对出现（入+出），否则会导致流程卡死；
   - 排他网关必须设置默认分支，避免无匹配条件导致流程中断。

### 6.5 数据安全与权限

1. **用户体系整合**：
   - 不要使用Flowable内置的`ACT_ID_*`表（用户/组），对接业务系统的用户体系；
   - 任务分配通过流程变量动态传值，避免硬编码用户ID。
2. **权限控制**：
   - 接口层增加权限校验（如：用户只能查询自己的待办任务）；
   - 敏感流程变量（如薪资、审批意见）加密存储。

### 6.6 监控与审计

1. **核心监控指标**：
   - 流程实例总数、活跃实例数、失败实例数；
   - 任务平均处理时长、超时任务数；
   - 异步作业执行成功率、重试次数。
2. **审计日志**：
   - 记录流程关键操作（启动、完成任务、终止）的操作人、时间、原因；
   - 保留`ACT_HI_*`表的核心数据，满足审计合规要求。

### 6.7 常见坑与避坑指南

1. **变量类型问题**：
   - 流程变量尽量使用基础类型（String、Integer、Long），避免自定义对象（序列化/反序列化易出问题）；
   - 大对象（如文件）不要存为流程变量，可存文件ID，业务系统单独存储。
2. **EL表达式问题**：
   - EL表达式中避免复杂逻辑（如调用多层方法），建议在服务任务中处理；
   - 表达式中的变量必须存在，否则流程报错（可提前判空）。
3. **部署问题**：
   - BPMN文件的XML格式必须严格符合BPMN 2.0规范（标签大小写、属性名）；
   - 流程文件编码统一为UTF-8，避免中文乱码。

## 七、总结

1. **核心基础**：Flowable基于BPMN 2.0规范，核心通过`RepositoryService`（部署）、`RuntimeService`（实例）、`TaskService`（任务）、`HistoryService`（历史）四大服务实现流程全生命周期管理。
2. **实战关键**：流程设计需明确任务分配、网关条件、变量传递；API使用需结合业务场景，重点处理任务完成、流程变量、监听器逻辑。
3. **生产注意**：性能优化（数据库、异步）、事务管理、版本兼容、异常处理、权限控制是生产环境稳定运行的核心，需重点关注。

通过以上内容，你可以完整掌握Flowable从环境搭建、流程设计、API使用到生产优化的全流程，满足企业级工作流开发的核心需求。
