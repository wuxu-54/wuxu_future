# Flowable RepositoryService 全API清单（作用+注意事项+避坑）

`RepositoryService`是Flowable**流程仓储核心服务**，核心负责**流程部署、流程定义管理、部署资源操作、决策表/表单定义管理**等静态流程资源的全生命周期操作，所有操作围绕Flowable的静态表（`ACT_RE_*`部署/定义表、`ACT_GE_BYTEARRAY`资源表）展开，**不涉及流程运行时数据**（运行时用`RuntimeService`，任务用`TaskService`）。

以下基于**Flowable 6.8.0**（稳定版，兼容JDK8+）整理，按**功能分类**列出所有核心API，包含**方法名、重载说明、核心作用、注意事项/避坑**，格式统一、准确清晰，重点标注实战高频API和易踩坑点，**无工具类封装，纯原生API**。

> 通用前置：所有API均通过`ProcessEngine.getRepositoryService()`获取实例，Spring Boot中直接`@Autowired`注入即可，流程引擎为**全局唯一重量级对象**，禁止重复创建。
>
> ```java
> // 纯Java工程
> RepositoryService repositoryService = ProcessEngines.getDefaultProcessEngine().getRepositoryService();
> // Spring Boot工程
> @Autowired
> private RepositoryService repositoryService;
> ```

## 一、部署（Deployment）相关API（实战最高频）

核心操作`ACT_RE_DEPLOYMENT`（部署表）和`ACT_GE_BYTEARRAY`（资源表），是流程部署的核心API，所有部署操作均通过`DeploymentBuilder`链式构建后执行。

### 1. 创建部署器

```java
DeploymentBuilder createDeployment();
```

- **作用**：创建部署构建器`DeploymentBuilder`，用于链式配置部署信息（名称、分类、资源文件等），是所有部署操作的入口。
- **注意事项**：
  1. `DeploymentBuilder`支持**链式调用**（如`.name().category().addClasspathResource()`），最终通过`.deploy()`执行部署；
  2. 可通过`tenantId(String)`设置多租户ID，实现多租户流程隔离。

### 2. DeploymentBuilder 核心链式方法（部署配置）

`createDeployment()`返回`DeploymentBuilder`，以下是其核心配置方法，**必须配合`.deploy()`执行才生效**：

| 方法 | 作用 | 注意事项/避坑 |
|------|------|---------------|
| `name(String deploymentName)` | 设置部署名称，便于后续查询和管理 | 建议命名规范（如「员工请假流程-V1」），包含流程名和版本 |
| `category(String category)` | 设置部署分类，用于流程归类（如「人事流程」「财务流程」） | 分类为自定义字段，无固定规则，便于批量查询筛选 |
| `description(String desc)` | 设置部署描述，记录流程部署的备注信息 | 建议填写流程用途，便于后期维护 |
| `tenantId(String tenantId)` | 设置多租户ID，实现多租户流程隔离 | 多租户场景必设，非多租户可忽略，默认空 |
| `addClasspathResource(String resourcePath)` | 添加类路径下的部署资源（BPMN/PNG/决策表等） | 1. 路径为**类路径**（如`processes/leave-process.bpmn20.xml`），根路径为`resources`；<br>2. 可多次调用添加多个资源（如同时加BPMN和流程图图片）；<br>3. 直接传文件夹路径（如`processes/`）可**批量扫描**该目录下所有资源 |
| `addInputStream(String resourceName, InputStream is)` | 通过字节流添加部署资源 | 适用于动态获取资源（如从数据库/文件服务器读取BPMN），替代`addClasspathResource` |
| `addString(String resourceName, String content)` | 通过字符串添加部署资源（如动态生成的BPMN字符串） | 需保证字符串为**合法的BPMN 2.0/xml格式**，否则部署解析失败 |

### 3. 执行部署

```java
// DeploymentBuilder的方法，最终执行部署
Deployment deploy();
```

- **作用**：执行流程部署，将配置的资源文件持久化到数据库，生成部署记录（`ACT_RE_DEPLOYMENT`）和资源记录（`ACT_GE_BYTEARRAY`），并解析BPMN生成流程定义（`ACT_RE_PROCDEF`）。
- **注意事项/避坑**：
  1. **核心坑点**：多次调用无校验的`deploy()`，**无论BPMN内容是否变化，都会生成新部署记录+流程定义版本**，导致数据冗余，**必须先做「流程key+MD5内容校验」再执行**；
  2. 部署成功后返回`Deployment`实体，包含部署ID、名称、时间等核心信息；
  3. 若BPMN文件语法错误（如节点ID重复、缺失`isExecutable=true`），会抛`BPMNParseException`，需捕获异常并记录日志。

### 4. 部署查询

```java
DeploymentQuery createDeploymentQuery();
```

- **作用**：创建部署查询器`DeploymentQuery`，用于多条件查询`ACT_RE_DEPLOYMENT`中的部署记录，支持分页、排序、多条件筛选。
- **DeploymentQuery 常用筛选方法**（链式调用，最终用`list()`/`singleResult()`/`count()`执行）：
  - `deploymentId(String id)`：按部署ID精确查询；
  - `deploymentName(String name)`：按部署名称精确查询；
  - `deploymentNameLike(String nameLike)`：按部署名称模糊查询（如`%请假流程%`）；
  - `category(String category)`：按部署分类精确查询；
  - `categoryLike(String categoryLike)`：按部署分类模糊查询；
  - `tenantId(String tenantId)`：按多租户ID精确查询；
  - `orderByDeploymentTime()`：按部署时间排序（`asc()`/`desc()`）；
  - `list()`：查询所有符合条件的部署列表；
  - `singleResult()`：查询单个符合条件的部署（无结果/多结果会抛异常）；
  - `count()`：查询符合条件的部署总数；
  - `page(int firstResult, int maxResults)`：分页查询，适用于大量部署记录。

### 5. 删除部署（2个重载）

```java
// 非级联删除
void deleteDeployment(String deploymentId);
// 级联删除
void deleteDeployment(String deploymentId, boolean cascade);
```

- **作用**：删除指定部署ID的部署记录，**实战核心，生产环境谨慎使用**；
  1. 非级联删除：仅删除`ACT_RE_DEPLOYMENT`的部署记录，保留流程定义、运行时实例、历史数据；
  2. 级联删除：删除部署记录+流程定义+运行时实例（`ACT_RU_*`）+历史数据（`ACT_HI_*`）+资源文件。
- **注意事项/避坑**：
  1. **核心坑点**：非级联删除时，若该部署下有**运行时流程实例**（`ACT_RU_EXECUTION`有数据），会抛`FlowableException`，删除失败；
  2. 生产环境**禁止随意使用级联删除**，执行前必须**备份数据库**，并确认无重要的运行时实例/历史数据；
  3. 删除部署后，对应的流程定义会被标记为「已删除」，无法再启动新实例，已运行的实例（非级联删除）可继续执行。

### 6. 获取部署的资源名称列表

```java
List<String> getDeploymentResourceNames(String deploymentId);
```

- **作用**：根据部署ID，查询该部署下的所有资源文件名称（如`leave-process.bpmn20.xml`、`leave-process.png`）。
- **注意事项**：资源名称与部署时`addClasspathResource()`传入的路径**最后一级名称一致**（如部署时传`processes/leave.bpmn`，资源名称为`leave.bpmn`）。

## 二、流程定义（ProcessDefinition）相关API（实战高频）

核心操作`ACT_RE_PROCDEF`（流程定义表），是部署后对流程定义的管理API，流程定义是启动流程实例的核心依据，**Flowable通过流程key自动管理版本**。

### 1. 流程定义查询

```java
ProcessDefinitionQuery createProcessDefinitionQuery();
```

- **作用**：创建流程定义查询器`ProcessDefinitionQuery`，用于多条件查询流程定义，支持分页、排序、筛选，是部署验证、流程启动前的必用API。
- **ProcessDefinitionQuery 核心筛选/执行方法**（链式调用）：

  | 方法 | 作用 | 关键说明 |
  |------|------|----------|
  | `processDefinitionId(String id)` | 按流程定义ID精确查询 | 流程定义ID格式：`流程key:版本号:随机ID`（如`leaveProcess:1:4`） |
  | `processDefinitionKey(String key)` | 按流程key精确查询 | **最常用**，流程key是版本管理核心，上线后禁止修改 |
  | `processDefinitionKeyLike(String keyLike)` | 按流程key模糊查询 | 适用于批量查询同前缀流程（如`hr-%`） |
  | `processDefinitionName(String name)` | 按流程名称精确查询 | 对应BPMN中`process`标签的`name`属性 |
  | `latestVersion()` | 仅查询**最新版本**的流程定义 | **实战必用**，避免查询到历史冗余版本 |
  | `deploymentId(String deploymentId)` | 按部署ID查询所属流程定义 | 一个部署可包含多个流程定义（多BPMN文件） |
  | `tenantId(String tenantId)` | 按多租户ID查询 | 多租户场景必用 |
  | `isExecutable()` | 仅查询可执行的流程定义 | 对应BPMN中`process`标签的`isExecutable=true` |
  | `orderByProcessDefinitionVersionDesc()` | 按版本号倒序排序 | 最新版本在前，便于筛选 |
  | `list()`/`singleResult()`/`count()` | 执行查询：返回列表/单个/总数 | `singleResult()`无结果/多结果会抛异常，需注意 |
  | `page(int first, int max)` | 分页查询 | 大量流程定义时使用，避免内存溢出 |

### 2. 流程定义挂起/激活（2组重载，共8个方法）

流程定义默认**激活状态**（可启动实例），挂起后**禁止启动新实例**，**已运行的实例不受影响**（继续执行），激活后恢复正常，支持按**ID/Key/Key+版本/租户ID**精准操作，核心重载如下（其余为多租户/版本组合，逻辑一致）：

```java
// 按流程key挂起/激活【所有版本】
void suspendProcessDefinitionByKey(String processKey);
void activateProcessDefinitionByKey(String processKey);

// 按流程定义ID挂起/激活【单个版本】
void suspendProcessDefinitionById(String processDefId);
void activateProcessDefinitionById(String processDefId);

// 按流程key+版本挂起/激活【指定版本】
void suspendProcessDefinitionByKeyAndVersion(String processKey, int version);
void activateProcessDefinitionByKeyAndVersion(String processKey, int version);
```

- **作用**：暂停/恢复流程定义的可执行状态，适用于流程下线、维护时禁止启动新实例。
- **注意事项/避坑**：
  1. **核心坑点**：`byKey`方法会**挂起/激活该流程key下的所有版本**，若仅需操作指定版本，必须用`byKeyAndVersion`或`byId`；
  2. 挂起/激活会修改`ACT_RE_PROCDEF`的`SUSPENSION_STATE_`字段（1=激活，2=挂起）；
  3. 尝试启动挂起的流程定义，会抛`FlowableException`，需在启动前做状态校验。

### 3. 获取流程定义详情

```java
ProcessDefinition getProcessDefinition(String processDefId);
```

- **作用**：根据流程定义ID，获取流程定义完整实体`ProcessDefinition`，包含key、版本、部署ID、是否可执行、挂起状态等所有信息。
- **注意事项**：流程定义ID为**完整格式**（`key:version:id`），可通过查询器获取。

### 4. 检查流程定义是否挂起

```java
boolean isProcessDefinitionSuspended(String processDefId);
```

- **作用**：根据流程定义ID，判断该流程定义是否为挂起状态，返回`true`（挂起）/`false`（激活）。
- **注意事项**：启动流程实例前**建议做该校验**，避免启动挂起的流程定义抛异常。

### 5. 获取流程定义的部署ID

```java
String getDeploymentIdForProcessDefinition(String processDefId);
```

- **作用**：根据流程定义ID，获取其所属的部署ID，用于关联查询部署信息或部署资源。
- **注意事项**：流程定义与部署为**多对一**关系（一个部署可包含多个流程定义）。

## 三、部署资源（Resource）相关API（实战常用）

核心操作`ACT_GE_BYTEARRAY`（资源表），用于获取部署时上传的BPMN、流程图图片、决策表等原始资源，适用于**前端展示流程图、下载BPMN文件、动态解析流程模型**。

### 1. 获取部署资源字节流

```java
InputStream getResourceAsStream(String deploymentId, String resourceName);
```

- **作用**：根据**部署ID**和**资源名称**，获取数据库中存储的资源原始字节流（BPMN/PNG等）。
- **注意事项/避坑**：
  1. 资源名称必须与`getDeploymentResourceNames(deploymentId)`返回的名称**完全一致**，区分大小写；
  2. 返回的`InputStream`使用后**必须手动关闭**，避免数据库连接泄漏；
  3. 可将字节流转为文件/图片流，用于前端展示流程图（如PNG图片）。

### 2. 获取BPMN流程模型

```java
BpmnModel getBpmnModel(String processDefId);
```

- **作用**：根据流程定义ID，解析并获取BPMN模型对象`BpmnModel`，包含流程的所有节点（事件、任务、网关）、流转线、属性等信息。
- **注意事项/避坑**：
  1. `BpmnModel`是Flowable的BPMN内存模型，可用于**动态修改流程定义、生成流程图、解析流程逻辑**；
  2. 仅支持BPMN文件，非BPMN资源（如PNG）调用会抛异常；
  3. 解析复杂流程时可能耗时，建议缓存结果。

### 3. 生成流程定义的流程图（2个重载）

```java
// 生成流程图字节流（PNG格式）
byte[] getProcessDiagram(String processDefId);
// 生成流程图并写入输出流
void generateProcessDiagram(OutputStream os, String processDefId, boolean highLight);
```

- **作用**：根据流程定义ID，自动生成流程图图片的字节流/写入输出流，适用于前端展示流程可视化图。
- **注意事项/避坑**：
  1. **核心坑点**：若部署时未上传流程图PNG，Flowable会**根据BPMN模型自动生成**，但**中文乱码需提前配置字体**（宋体/微软雅黑），否则中文显示为方框；
  2. 生成的流程图为PNG格式，`highLight`参数为是否高亮当前节点（仅流程实例时生效，流程定义时无意义）；
  3. 生成大流程的流程图时可能耗时，建议缓存生成的图片。

## 六、缓存与通用配置API（底层操作，实战少用）

主要用于Flowable引擎的缓存管理、配置获取，一般无需手动调用，引擎会自动处理，仅在特殊场景（如动态修改流程后清缓存）使用。

### 1. 清除流程定义缓存

```java
void clearCache();
// 清除指定流程定义的缓存
void clearProcessDefinitionCache(String processDefId);
```

- **作用**：清除Flowable引擎中缓存的流程定义/BPMN模型，适用于**动态修改流程定义后强制刷新缓存**。
- **注意事项**：部署新流程版本时，引擎会**自动清除对应流程key的缓存**，无需手动调用；手动清缓存会有性能损耗，非必要不使用。

### 2. 获取流程引擎配置

```java
ProcessEngineConfiguration getProcessEngineConfiguration();
```

- **作用**：获取Flowable流程引擎的核心配置对象`ProcessEngineConfiguration`，包含数据源、建表策略、字体配置等所有引擎参数。
- **注意事项**：仅用于**读取配置**，不建议手动修改配置参数，可能导致引擎运行异常。

### 3. 检查资源是否存在

```java
boolean resourceExists(String deploymentId, String resourceName);
```

- **作用**：根据部署ID和资源名称，检查该资源是否存在于数据库中，返回`true`/`false`。
- **注意事项**：可用于获取资源前的前置校验，避免调用`getResourceAsStream()`时抛异常。

## 七、RepositoryService 通用避坑原则（所有API通用）

结合实战经验，整理`RepositoryService`所有操作的核心避坑点，**必须严格遵守**，否则会导致流程部署失败、数据冗余、流程运行异常等问题：

### 1. 部署操作：杜绝无校验部署

所有调用`deploy()`的场景，**必须先做两层校验**：

  1. 根据流程key查询最新流程定义，无则直接部署；
  2. 有则对比**本地BPMN**和**数据库中最新BPMN**的MD5，仅内容不一致时才部署；
  ✅ 核心目的：避免多次调用导致部署记录、流程版本、资源文件冗余。

### 2. 删除操作：谨慎使用级联删除

- 非级联删除`deleteDeployment(deployId)`：仅删部署记录，有运行时实例则删除失败，**相对安全**；
- 级联删除`deleteDeployment(deployId, true)`：删除所有关联数据（部署+流程定义+运行时实例+历史数据），**生产环境严禁随意使用**；
  ✅ 操作前必须：① 备份数据库 ② 确认无运行时实例 ③ 人工复核。

### 3. 流程定义：严格管理流程key

- 流程key是**版本管理的核心**，Flowable根据key自动升级版本（相同key重新部署→版本+1）；
- **流程key一旦上线，永久禁止修改**！若需大幅修改流程逻辑，**新建流程key**（如`leaveProcess`→`leaveProcessV2`），避免同一key版本过多；
  ❌ 禁止手动修改数据库`ACT_RE_PROCDEF`的`KEY_`和`VERSION_`字段，会导致版本管理失效。

### 4. 挂起/激活：精准指定操作范围

- 避免直接使用`byKey`方法挂起/激活流程定义（会操作所有版本）；
- 生产环境建议使用`byId`或`byKeyAndVersion`，**精准操作指定版本**，防止误挂起核心流程的最新版本。

### 5. 资源操作：关闭流+校验存在性

- 调用`getResourceAsStream()`获取的`InputStream`，**使用后必须手动关闭**，避免数据库连接泄漏；
- 获取资源前，建议先调用`resourceExists()`校验资源是否存在，避免抛异常。

### 6. 中文乱码：部署前提前配置

- 流程图中文乱码**必须在部署前解决**，部署后修改字体配置无效，需重新部署；
- 核心配置：在引擎配置中指定**宋体/微软雅黑**（`activityFontName`/`labelFontName`/`annotationFontName`），并保证BPMN文件为UTF-8编码、数据库连接URL带`useUnicode=true&characterEncoding=utf8`。

### 7. 开发/生产环境差异化策略

| 操作 | 开发环境 | 生产环境 |
|------|----------|----------|
| 部署方式 | 可使用`@PostConstruct+校验`实现启动自动部署 | 禁止启动自动部署，通过**带权限的专属部署平台**触发，需审核 |
| 建表策略 | `databaseSchemaUpdate=true`（自动建表/更新） | `databaseSchemaUpdate=false`（手动执行SQL建表，禁止自动修改） |
| API调用 | 可随意测试部署、删除、挂起操作 | 所有写操作（deploy/delete/suspend）必须加**权限控制+操作日志+人工复核** |
| 异常处理 | 可简化异常处理，重点打印日志 | 必须捕获所有异常（`BPMNParseException`/`SQLException`/`FlowableException`），并记录详细操作日志（操作人、时间、结果） |

### 8. 引擎实例：全局唯一，禁止重复创建

- `ProcessEngine`是**重量级对象**，创建时会初始化数据源、缓存、线程池等，**全局仅需一个实例**；
- 禁止在多线程/多方法中重复调用`ProcessEngines.getDefaultProcessEngine()`，可通过工具类/Spring容器单例管理，避免数据库连接泄漏和性能损耗。

## 八、RepositoryService 核心API速查（实战高频）

整理日常开发中**90%场景会用到的核心API**，按操作流程排序，便于快速查阅：

1. **部署流程**：`createDeployment()` → `DeploymentBuilder`配置 → `deploy()`；
2. **查询部署**：`createDeploymentQuery()` → 多条件筛选 → `list()`/`singleResult()`；
3. **查询流程定义**：`createProcessDefinitionQuery()` → `processDefinitionKey(key)` → `latestVersion()` → `singleResult()`；
4. **部署验证**：`getProcessDefinition()` → 校验`isExecutable()`；
5. **获取流程图**：`getProcessDiagram(processDefId)` / `getResourceAsStream(deployId, resourceName)`；
6. **挂起/激活流程**：`suspendProcessDefinitionByKeyAndVersion()` / `activateProcessDefinitionById()`；
7. **删除部署**：`deleteDeployment(deployId, false)`（非级联，生产首选）；
8. **清理冗余**：先通过`createProcessDefinitionQuery()`查询冗余版本，再调用`deleteDeployment()`级联删除（无实例时）。
