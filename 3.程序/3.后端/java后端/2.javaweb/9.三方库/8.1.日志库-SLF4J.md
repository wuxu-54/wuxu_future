# SLF4J

## 一、SLF4J核心概念

SLF4J（Simple Logging Facade for Java）**不是具体的日志实现**，而是一个日志门面/接口层，它定义了统一的日志API，底层可以对接不同的日志实现框架（如Logback、Log4j2、Log4j等）。

### 核心优势：

1. **解耦**：业务代码只依赖SLF4J接口，无需关心底层日志实现，更换日志框架无需修改代码。
2. **性能**：支持参数占位符（`{}`），避免字符串拼接的性能损耗（未达到日志级别时不会执行拼接）。
3. **SpringBoot默认集成**：SpringBoot底层默认使用 `SLF4J + Logback`（Logback是SLF4J作者开发的，性能最优，无需额外依赖）。

## 二、SLF4J基础使用（SpringBoot中）

### 1. 依赖说明

SpringBoot的`spring-boot-starter-web`/`spring-boot-starter`已经内置了SLF4J和Logback依赖，无需手动引入：

```xml
<!-- 核心starter已包含SLF4J+Logback -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

### 2. 基本使用方式

#### 方式1：原生LoggerFactory（无依赖）

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class LogController {
    // 1. 获取Logger实例（参数为当前类的Class，便于日志定位）
    private static final Logger log = LoggerFactory.getLogger(LogController.class);

    @GetMapping("/test/log")
    public String testLog() {
        String userName = "张三";
        Integer age = 25;
        
        // 2. 不同级别日志输出（优先级：TRACE < DEBUG < INFO < WARN < ERROR）
        log.trace("【TRACE】- 最细粒度日志，用于调试（默认不输出）");
        log.debug("【DEBUG】- 调试日志，开发环境使用，如参数接收：userName={}, age={}", userName, age);
        log.info("【INFO】- 关键业务日志，如接口调用成功：用户{}请求接口", userName);
        log.warn("【WARN】- 警告日志，如非致命异常、参数不合法：年龄{}超出常规范围", age);
        log.error("【ERROR】- 错误日志，如异常堆栈：用户{}请求失败", userName, new RuntimeException("接口异常"));
        
        return "日志输出完成";
    }
}
```

#### 方式2：Lombok简化（推荐）

通过Lombok的`@Slf4j`注解自动生成Logger实例，简化代码：

```xml
<!-- 引入Lombok依赖 -->
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <optional>true</optional>
</dependency>
```

```java
import lombok.extern.slf4j.Slf4j;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@Slf4j // 自动生成private static final Logger log = LoggerFactory.getLogger(当前类.class);
public class LogController {

    @GetMapping("/test/log")
    public String testLog() {
        log.info("使用Lombok简化日志声明");
        return "success";
    }
}
```

### 3. 日志级别说明

| 级别   | 适用场景                                  | 默认是否输出（SpringBoot） |
|--------|-------------------------------------------|----------------------------|
| TRACE  | 最细粒度，如变量实时值、循环内部日志      | 否                         |
| DEBUG  | 开发调试，如接口入参、中间结果            | 否（默认INFO级别）         |
| INFO   | 核心业务流程，如接口启动、关键操作成功    | 是                         |
| WARN   | 非致命问题，如参数缺失、资源不足          | 是                         |
| ERROR  | 致命错误，如异常、接口调用失败            | 是                         |

## 三、SLF4J核心配置（SpringBoot中）

SpringBoot支持两种配置方式：**简洁配置（application.yml/properties）** 和 **自定义配置（logback-spring.xml）**。

### 1. 简洁配置（application.yml）

适合快速调整基础日志规则，无需编写XML：

```yaml
spring:
  # 日志核心配置
  logging:
    # 1. 全局日志级别（可针对特定包/类单独配置）
    level:
      root: INFO  # 全局默认级别
      com.example.demo: DEBUG  # 自定义包的日志级别（优先级更高）
      org.springframework.web: WARN  # SpringWeb模块的日志级别
      com.zaxxer.hikari: ERROR  # 数据库连接池日志级别
    # 2. 日志输出格式（控制台+文件）
    pattern:
      console: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{50} - %msg%n"  # 控制台格式
      file: "%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{50} - %msg%n"      # 文件格式
    # 3. 日志文件配置
    file:
      name: ./logs/demo-app.log  # 日志文件路径（相对/绝对路径）
      max-size: 100MB            # 单个日志文件最大大小
      max-history: 30            # 日志文件保留天数
      total-size-cap: 1GB        # 日志文件总大小上限
```

### 2. 自定义配置（logback-spring.xml，推荐生产环境）

当需要更精细的控制（如按时间分割日志、异步日志、多环境配置）时，使用自定义XML配置。

**步骤1**：在`src/main/resources`下创建`logback-spring.xml`（SpringBoot优先加载此文件，支持Spring Profile）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration scan="true" scanPeriod="60 seconds" debug="false">
    <!-- 1. 定义常量（便于复用） -->
    <property name="LOG_PATH" value="./logs"/>  <!-- 日志根目录 -->
    <property name="LOG_PATTERN" value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{50} - %msg%n"/>  <!-- 日志格式 -->

    <!-- 2. 控制台输出Appender -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
        <!-- 过滤：只输出INFO及以上级别 -->
        <filter class="ch.qos.logback.classic.filter.ThresholdFilter">
            <level>INFO</level>
        </filter>
    </appender>

    <!-- 3. 文件输出Appender（按大小+时间分割） -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <!-- 日志文件路径 -->
        <file>${LOG_PATH}/demo-app.log</file>
        <!-- 滚动策略：按时间+大小分割 -->
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <!-- 分割后的日志文件名：demo-app-2026-01-27-01.log -->
            <fileNamePattern>${LOG_PATH}/demo-app-%d{yyyy-MM-dd-HH}.%i.log</fileNamePattern>
            <maxHistory>7</maxHistory> <!-- 保留7天日志 -->
            <totalSizeCap>1GB</totalSizeCap> <!-- 总大小上限 -->
            <!-- 按大小分割：单个文件超过100MB则新建 -->
            <timeBasedFileNamingAndTriggeringPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedFNATP">
                <maxFileSize>100MB</maxFileSize>
            </timeBasedFileNamingAndTriggeringPolicy>
        </rollingPolicy>
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 4. 异步日志Appender（提升性能，避免IO阻塞） -->
    <appender name="ASYNC_FILE" class="ch.qos.logback.classic.AsyncAppender">
        <appender-ref ref="FILE"/> <!-- 关联文件Appender -->
        <queueSize>1024</queueSize> <!-- 队列大小 -->
        <discardingThreshold>0</discardingThreshold> <!-- 不丢弃日志 -->
        <includeCallerData>false</includeCallerData> <!-- 不包含调用者信息（提升性能） -->
    </appender>

    <!-- 5. 多环境配置（结合Spring Profile） -->
    <springProfile name="dev">
        <!-- 开发环境：控制台输出DEBUG，文件输出INFO -->
        <root level="INFO">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="ASYNC_FILE"/>
        </root>
        <logger name="com.example.demo" level="DEBUG" additivity="false">
            <appender-ref ref="CONSOLE"/>
        </logger>
    </springProfile>

    <springProfile name="prod">
        <!-- 生产环境：控制台输出WARN，文件输出INFO，禁用DEBUG -->
        <root level="INFO">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="ASYNC_FILE"/>
        </root>
        <logger name="com.example.demo" level="INFO" additivity="false">
            <appender-ref ref="ASYNC_FILE"/>
        </logger>
        <logger name="org.springframework" level="WARN"/>
    </springProfile>
</configuration>
```

## 四、高级用法

### 1. MDC（映射诊断上下文）

用于追踪分布式系统中的请求链路（如请求ID、用户ID），在日志中统一输出，方便排查问题：

```java
import lombok.extern.slf4j.Slf4j;
import org.slf4j.MDC;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;
import java.util.UUID;

@RestController
@Slf4j
public class MdcController {

    @GetMapping("/test/mdc")
    public String testMdc() {
        // 1. 设置MDC参数（请求ID）
        String requestId = UUID.randomUUID().toString().replace("-", "");
        MDC.put("requestId", requestId);
        
        // 2. 日志中输出MDC参数（需修改日志格式：添加%X{requestId}）
        log.info("【MDC示例】用户请求接口，请求ID：{}", requestId); // 手动输出
        log.info("【MDC示例】业务逻辑处理中"); // 日志格式自动包含requestId
        
        // 3. 移除MDC参数（避免内存泄漏）
        MDC.remove("requestId");
        // 或 MDC.clear(); // 清空所有MDC参数
        
        return "success";
    }
}
```

**修改日志格式（添加%X{requestId}）**：

```xml
<property name="LOG_PATTERN" value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] [%X{requestId}] %-5level %logger{50} - %msg%n"/>
```

### 2. 避免常见坑

- **不要使用字符串拼接**：`log.debug("用户：" + userName + " 年龄：" + age)` → 未达到DEBUG级别时仍会执行拼接，性能差；应使用`log.debug("用户：{} 年龄：{}", userName, age)`。
- **不要吞异常**：`log.error("接口失败", e)` 而非 `log.error("接口失败：" + e.getMessage())`（需保留异常堆栈）。
- **避免日志重复输出**：设置`logger`的`additivity="false"`（避免日志传递到root重复输出）。

## 五、总结

1. **核心定位**：SLF4J是日志门面，SpringBoot默认集成SLF4J+Logback，业务代码只依赖SLF4J接口即可。
2. **配置方式**：简单场景用`application.yml`配置级别/路径；复杂场景（分割、异步、多环境）用`logback-spring.xml`。
3. **最佳实践**：
   - 使用Lombok的`@Slf4j`简化Logger声明；
   - 日志级别按环境区分（开发DEBUG、生产INFO/WARN）；
   - 生产环境使用异步日志+按时间/大小分割；
   - 用MDC追踪请求链路，日志中保留异常堆栈。

通过以上配置和使用方式，你可以在SpringBoot服务端开发中规范、高效地使用SLF4J日志库，满足开发调试和生产排查的需求。
