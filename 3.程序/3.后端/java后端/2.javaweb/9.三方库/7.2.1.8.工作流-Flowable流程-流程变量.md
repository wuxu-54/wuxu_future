# Flowable 核心概念：流程变量（Process Variable）全解析 + 实战操作 + 避坑指南

**（结合执行对象、全实战、零误区、生产级）**
流程变量是 Flowable 流程引擎的**数据核心**，所有流程流转、业务交互、条件判断都依赖它；且**流程变量与执行对象强绑定**，结合之前学的 Execution 知识，你能彻底吃透。

本文严格按照你要求的结构：**基础定义→核心作用→原理实现→实战操作→避坑指南**，通俗易懂、全面严谨。

---

## 一、基础定义与本质

### 1.1 官方核心定义

**流程变量（Process Variable）**：流程运行时存储业务数据的**键值对（Key-Value）**，是流程引擎与业务系统之间、流程节点之间传递数据的唯一标准载体。

### 1.2 通俗比喻（结合执行对象）

- **执行对象 = 流程的行走指针/路线**
- **流程变量 = 指针随身携带的「行李」**
  - 全局变量：全队共享的公共行李
  - 局部变量：个人私人物品
  - 瞬态变量：临时用的一次性物品，用完就丢

### 1.3 三大核心分类（Flowable 标准划分）

| 类型 | 全称 | 绑定对象 | 作用域 | 存储方式 |
|------|------|----------|--------|----------|
| **全局变量** | Process Variable | 根执行对象（流程实例） | 全流程所有节点/分支可见 | 持久化到数据库 |
| **局部变量** | Local Variable | 子执行对象（分支/多实例/子流程） | 仅当前执行路径可见 | 持久化到数据库 |
| **瞬态变量** | Transient Variable | 任意执行对象 | 内存级别，流程流转一次后失效 | **不存库**，仅内存 |

### 1.4 关键结论

1. 流程变量**必须绑定在执行对象（Execution）上**，没有执行对象就没有变量；
2. 全局变量 ≠ 局部变量，二者存储位置、作用域完全隔离；
3. 瞬态变量仅用于临时计算，**不能用于持久化业务数据**。

---

## 二、流程变量的核心作用

流程变量是 Flowable 的「血液」，没有它流程无法运转，核心作用：

1. **流程流转控制**
   排他网关、并行网关、包容网关的**条件判断**（如 `${approveResult=='pass'}`）；
2. **业务数据传递**
   表单数据、审批结果、业务ID在节点之间无缝传递；
3. **动态任务分配**
   动态指定审批人、候选人、候选组（如 `${assignee}`）；
4. **代码逻辑入参**
   服务任务、执行监听器、任务监听器的入参/出参；
5. **历史数据追溯**
   流程结束后，变量存入历史表，用于审计、复盘。

## 三、底层原理与实现机制

### 3.1 数据存储原理（核心数据库表）

Flowable 通过两张表管理变量，**永不丢失数据**：

1. **`ACT_RU_VARIABLE`**：运行时变量表
   存储**正在运行**的流程变量，流程结束后自动删除；
2. **`ACT_HI_VARIABLE`**：历史变量表
   存储**所有流程**的变量，永久留存（可配置清理）。

核心字段：

- `EXECUTION_ID_`：绑定的执行对象ID（核心关联）
- `PROC_INST_ID_`：流程实例ID
- `NAME_`：变量Key
- `TEXT_`/`LONG_`/`DOUBLE_`：基本类型值
- `BYTEARRAY_ID_`：序列化对象（JavaBean）

### 3.2 与执行对象的绑定关系（核心！）

1. 全局变量 → 绑定 **根执行对象（ProcessInstance）**
2. 局部变量 → 绑定 **当前子执行对象**
3. 变量查找规则（引擎自动递归）：
   从当前执行对象 → 父执行 → 根执行，逐级查找变量

### 3.3 作用域原理

1. **继承性**：子执行默认继承父执行的**全局变量**；
2. **隔离性**：局部变量仅当前执行可见，其他分支无法访问；
3. **优先级**：局部变量 > 全局变量（同名变量优先取局部）。

### 3.4 变量生命周期

1. 创建：通过 API/表单/监听器设置变量；
2. 使用：流程节点、网关、代码读取/修改；
3. 销毁：流程结束 → 运行时变量删除，历史变量保留；局部变量随执行对象销毁而销毁。

### 3.5 数据类型与序列化

1. **支持类型**：
   基本类型（String/Integer/Long/Boolean/Double）、Date、List、Map、JavaBean；
2. **序列化规则**：
   基本类型直接存字段；JavaBean/复杂对象自动序列化为二进制存储；
3. **瞬态变量**：
   仅存在内存，不序列化、不存库，流转一次后自动清空。

## 四、实战操作大全（开发直接复制使用）

### 4.1 核心 API 操作（RuntimeService）

#### 1. 全局变量（全流程共享）

```java
// 设置全局变量（绑定根执行）
runtimeService.setVariable(executionId, "username", "张三");
runtimeService.setVariable(processInstanceId, "orderId", 1001);

// 获取全局变量（自动递归查找根执行）
String username = (String) runtimeService.getVariable(executionId, "username");
```

#### 2. 局部变量（仅当前执行可见，并发必用）

```java
// 设置局部变量（绑定当前子执行）
runtimeService.setVariableLocal(executionId, "approveComment", "同意");

// 仅获取当前执行的局部变量（不递归父执行）
String comment = (String) runtimeService.getVariableLocal(executionId, "approveComment");
```

#### 3. 瞬态变量（临时计算，不存库）

```java
// 设置瞬态变量
runtimeService.setTransientVariable(executionId, "tempData", "临时数据");

// 获取瞬态变量
String temp = (String) runtimeService.getTransientVariable(executionId, "tempData");
```

#### 4. 批量操作

```java
Map<String, Object> variables = new HashMap<>();
variables.put("name", "李四");
variables.put("age", 25);
// 批量设置全局变量
runtimeService.setVariables(executionId, variables);
```

---

### 4.2 任务操作变量（简化写法，最常用）

用户任务中，直接通过 `TaskService` 操作变量，自动绑定执行对象：

```java
// 完成任务时直接设置变量
taskService.complete(taskId, variables);

// 单独设置任务关联的变量
taskService.setVariable(taskId, "key", "value");
taskService.setVariableLocal(taskId, "localKey", "localValue");
```

---

### 4.3 监听器 / 服务任务中操作变量

```java
@Override
public void notify(DelegateExecution execution) {
    // 1. 设置全局变量
    execution.setVariable("globalKey", "全局值");
    // 2. 设置局部变量
    execution.setVariableLocal("localKey", "局部值");
    // 3. 设置瞬态变量
    execution.setTransientVariable("tempKey", "临时值");

    // 4. 获取变量
    String global = (String) execution.getVariable("globalKey");
    String local = (String) execution.getVariableLocal("localKey");
}
```

### 4.4 流程 XML 中使用变量（可视化设计器）

#### 1. 排他网关条件判断

```xml
<exclusiveGateway id="gateway">
  <sequenceFlow sourceRef="gateway" targetRef="passTask">
    <conditionExpression xsi:type="tFormalExpression">
      ${approveResult == 'pass'} <!-- 变量直接使用 -->
    </conditionExpression>
  </sequenceFlow>
</exclusiveGateway>
```

#### 2. 动态指定审批人

```xml
<userTask id="approveTask">
  <humanPerformer>
    <resourceAssignmentExpression>
      <formalExpression>${assignee}</formalExpression> <!-- 变量分配审批人 -->
    </resourceAssignmentExpression>
  </humanPerformer>
</userTask>
```

#### 3. 多实例任务变量（会签）

```xml
<multiInstanceLoopCharacteristics isSequential="false">
  <loopCardinality>${userList.size()}</loopCardinality> <!-- 变量控制人数 -->
</multiInstanceLoopCharacteristics>
```

## 五、生产级避坑指南（高频坑+解决方案）

### 坑1：全局/局部变量混用（90%的人踩过）

- **问题**：并行分支/会签中用全局变量，导致数据互相覆盖；
- **场景**：3人同时审批，全局变量 `approveResult` 被反复改写；
- **解决方案**：**并发场景强制使用局部变量（setVariableLocal）**。

### 坑2：存储大对象导致数据库性能爆炸

- **问题**：把文件、大JSON、富文本存在变量中，导致表体积暴涨；
- **解决方案**：变量只存**业务ID/URL**，大文件存文件服务器/业务库。

### 坑3：同名变量覆盖，数据丢失

- **问题**：局部变量和全局变量同名，引擎优先取局部，导致逻辑错误；
- **解决方案**：变量名规范命名，局部变量加前缀（如 `local_approve`）。

### 坑4：JavaBean 序列化异常

- **问题**：实体类修改字段后，历史变量反序列化失败；
- **解决方案**：
  1. 实体类加 `serialVersionUID`；
  2. 尽量用 Map/基本类型替代 JavaBean。

### 坑5：瞬态变量误用（数据丢失）

- **问题**：把业务数据存为瞬态变量，流程跳转后数据消失；
- **解决方案**：瞬态变量仅用于**临时计算**，核心业务数据必须用全局/局部变量。

### 坑6：子流程变量无法传递

- **问题**：子流程设置的变量，父流程读取不到；
- **解决方案**：
  1. 子流程通过 `dataOutputAssociation` 配置输出变量；
  2. 手动将子流程变量设置到**根执行对象**。

### 坑7：乐观锁异常（变量更新冲突）

- **问题**：多线程同时修改同一个执行对象的变量，报 `OptimisticLockingException`；
- **解决方案**：加分布式锁，避免并发操作同一流程实例。

### 坑8：变量为空导致网关异常

- **问题**：网关条件判断的变量为 `null`，流程直接卡死；
- **解决方案**：条件增加空值判断 `${approveResult != null && approveResult == 'pass'}`。

### 坑9：滥用变量，历史数据冗余

- **问题**：存储大量无用变量，历史表查询极慢；
- **解决方案**：及时删除无用变量，定期清理历史变量表。

### 坑10：执行监听器中修改变量，事务回滚

- **问题**：监听器抛异常，变量修改全部回滚；
- **解决方案**：监听器必须 `try-catch` 捕获异常，禁止向外抛出。

---

## 六、终极总结（牢记这6句，永远不踩坑）

1. **流程变量 = 执行对象的行李**，全局绑根执行、局部绑子执行；
2. **并发/多实例/子流程必用局部变量**，全局变量仅用于共享数据；
3. **瞬态变量不存库**，只能临时用，核心数据别碰；
4. **变量不存大对象**，只存ID/链接，保护数据库性能；
5. **网关条件必做空判断**，避免流程卡死；
6. **监听器不抛异常**，变量修改才不会回滚。
