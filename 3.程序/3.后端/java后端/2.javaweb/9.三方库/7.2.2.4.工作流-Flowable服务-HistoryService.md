# Flowable HistoryService 全API清单（作用+注意事项+避坑）

`HistoryService`是Flowable**历史数据管理核心服务**，专门负责**所有流程运行产生的历史数据的查询、筛选、统计及清理**，所有操作围绕Flowable**历史表（`ACT_HI_*`）**展开，是流程审计、数据追溯、报表统计的**唯一核心入口**。

其与其他核心服务的**功能边界绝对清晰**：仅处理**已完成/已挂起/已删除**的流程相关历史数据，不涉及任何运行时数据（`ACT_RU_*`，由`RuntimeService`/`TaskService`管理）；历史数据默认**永久持久化**，仅可通过专属API清理，无修改/更新API（保证审计数据的不可篡改）。

以下基于**Flowable 6.8.0**（稳定版，兼容JDK8+）整理，完全沿用前序服务的说明格式，**按功能分类**列出核心API，包含**方法名、重载说明、核心作用、注意事项/避坑**，重点标注实战高频API和易踩坑点，纯原生API无封装，明确历史表与运行时表的对应关系。

> 通用前置：所有API均通过`ProcessEngine.getHistoryService()`获取实例，Spring Boot中直接`@Autowired`注入即可，流程引擎为**全局唯一重量级对象**，禁止重复创建。
>
> ```java
> // 纯Java工程
> HistoryService historyService = ProcessEngines.getDefaultProcessEngine().getHistoryService();
> // Spring Boot工程
> @Autowired
> private HistoryService historyService;
> ```
>
> 核心特性：
>
> 1. 历史数据为**运行时数据的快照**，流程节点完成/实例结束后，运行时数据会同步固化到历史表；
> 2. 历史表默认**永久保存**，可通过Flowable配置历史数据保留策略，或通过API手动清理；
> 3. 无历史数据修改/更新API，仅支持**查询**和**删除**，保证审计数据的完整性和不可篡改。

## 一、历史流程实例（HistoricProcessInstance）API（实战最高频）

**历史流程实例**对应历史表`ACT_HI_PROCINST`，是**整个流程实例的历史总览**，记录了流程实例的启动时间、结束时间、启动人、业务键、删除原因、持续时长等核心信息，是**流程审计、业务关联追溯的入口**，对应运行时表`ACT_RU_PROCINST`。

### 核心方法

```java
// 创建历史流程实例查询器（实战最高频入口）
HistoricProcessInstanceQuery createHistoricProcessInstanceQuery();

// 根据流程实例ID删除历史流程实例（物理删除，生产谨慎）
void deleteHistoricProcessInstance(String processInstanceId);

// 根据流程实例ID获取历史流程实例详情
HistoricProcessInstance getHistoricProcessInstance(String processInstanceId);
```

### `HistoricProcessInstanceQuery` 核心筛选/执行方法

链式调用，最终通过`list()`/`singleResult()`/`count()`/`listPage()`执行，**覆盖所有实战查询场景**：

| 方法 | 核心作用 | 实战说明/避坑 |
|------|----------|---------------|
| `processInstanceId(String instanceId)` | 按流程实例ID精确查询 | 最常用，单流程实例审计的核心入口 |
| `businessKey(String businessKey)` | 按业务键精确查询 | **业务系统核心**，关联业务主键（如订单ID）追溯流程，实战高频 |
| `businessKeyLike(String businessKeyLike)` | 按业务键模糊查询 | 如`%order_2024%`查2024年所有订单流程 |
| `processDefinitionKey(String processKey)` | 按流程Key查询 | 查某类流程的所有历史实例（如所有请假流程） |
| `processDefinitionId(String processDefId)` | 按流程定义ID查询 | 查指定版本流程的历史实例 |
| `startedBy(String userId)` | 按流程启动人查询 | 需在启动流程时通过`IdentityService`设置启动人，否则为null |
| `finished()` | 仅查询**已完成**的流程实例 | 实战默认筛选，区分未完成/已完成历史 |
| `unfinished()` | 仅查询**未完成**的历史实例（挂起/中断） | 适用于异常流程追溯 |
| `finishedAfter(Date date)`/`finishedBefore(Date date)` | 按流程结束时间范围查询 | 报表统计常用（如查本月完成的流程） |
| `startedAfter(Date date)`/`startedBefore(Date date)` | 按流程启动时间范围查询 | 报表统计常用 |
| `deleteReason(String reason)` | 按删除原因精确查询 | 查被手动删除的流程实例（如`订单取消`） |
| `deleteReasonLike(String reasonLike)` | 按删除原因模糊查询 | 如`%取消%`查所有取消的流程 |
| `orderByProcessInstanceEndTimeDesc()` | 按结束时间倒序排序 | 最新完成的流程在前，符合审计/查询习惯 |
| `orderByProcessInstanceStartTimeDesc()` | 按启动时间倒序排序 | 未完成流程追溯常用 |
| `listPage(int first, int max)` | 分页查询 | 大量历史实例必用，避免内存溢出 |

### 注意事项/避坑

1. **业务键必用**：查询历史流程时，**优先通过`businessKey`关联**，而非仅靠流程实例ID，这是业务系统与流程引擎联动的核心；
2. **finished()默认筛选**：若无特殊需求，查询时必加`finished()`，避免混合查询已完成/未完成实例，导致结果混乱；
3. **删除为物理删除**：`deleteHistoricProcessInstance()`会**永久删除**该实例的所有关联历史数据（任务、变量、批注等），生产环境仅用于清理测试数据，严禁随意调用；
4. **启动人需手动设置**：`startedBy(userId)`需在启动流程时通过`IdentityService.setAuthenticatedUserId(userId)`设置，否则启动人为null，无法通过该条件筛选。

## 二、历史任务实例（HistoricTaskInstance）API（实战高频）

**历史任务实例**对应历史表`ACT_HI_TASKINST`，记录了所有`userTask`的历史信息（创建时间、认领时间、完成时间、处理人、候选人、任务名称等），是**人工任务审计、审批追溯**的核心，对应运行时表`ACT_RU_TASK`。

### 核心方法

```java
// 创建历史任务实例查询器
HistoricTaskInstanceQuery createHistoricTaskInstanceQuery();

// 根据任务ID获取历史任务实例详情
HistoricTaskInstance getHistoricTaskInstance(String taskId);
```

### `HistoricTaskInstanceQuery` 核心筛选/执行方法

| 方法 | 核心作用 | 实战说明/避坑 |
|------|----------|---------------|
| `taskId(String taskId)` | 按任务ID精确查询 | 单任务审批追溯的核心入口 |
| `assignee(String userId)` | 按任务处理人查询 | 查“某用户的所有已办审批任务”，实战高频 |
| `processInstanceId(String instanceId)` | 按流程实例ID查询 | 查某流程实例的所有历史审批任务，流程审计必备 |
| `taskName(String taskName)` | 按任务名称精确查询 | 对应BPMN中`userTask`的`name`属性（如“经理审批”） |
| `taskNameLike(String taskNameLike)` | 按任务名称模糊查询 | 如`%审批%`查所有审批类历史任务 |
| `finished()` | 仅查询**已完成**的历史任务 | 实战默认筛选，排除未完成的挂起任务 |
| `unfinished()` | 仅查询**未完成**的历史任务 | 异常任务追溯常用 |
| `completedAfter(Date date)`/`completedBefore(Date date)` | 按任务完成时间范围查询 | 个人/部门审批统计常用 |
| `assigneeLike(String userIdLike)` | 按处理人模糊查询 | 适用于按用户前缀/部门筛选 |
| `orderByTaskCompletionTimeDesc()` | 按任务完成时间倒序 | 最新完成的审批任务在前，符合查询习惯 |

### 注意事项/避坑

1. **与运行时任务区分**：历史任务仅包含**已完成/已删除/已挂起**的任务，运行中任务需用`TaskService`查询，不可混淆；
2. **处理人字段规则**：`assignee`为最终完成任务的用户ID，若任务被委派/转办，该字段为**最终处理人**，原认领人需通过历史批注/执行流追溯；
3. **无候选人筛选的直接方法**：历史任务表不直接存储候选人信息，需通过`HistoricIdentityLinkQuery`关联查询。

## 三、历史活动实例（HistoricActivityInstance）API（实战常用）

**历史活动实例**对应历史表`ACT_HI_ACTINST`，是**流程实例的最小执行单元历史**，记录了流程实例中**所有节点**（开始事件、用户任务、服务任务、网关、结束事件等）的执行信息，包括节点ID、节点类型、开始/结束时间、处理人、持续时长等，是**流程执行轨迹追溯、节点耗时分析**的核心（如分析“某流程哪个节点耗时最长”）。

### 核心方法

```java
// 创建历史活动实例查询器
HistoricActivityInstanceQuery createHistoricActivityInstanceQuery();

// 根据活动实例ID获取详情
HistoricActivityInstance getHistoricActivityInstance(String activityInstanceId);
```

### `HistoricActivityInstanceQuery` 核心筛选/执行方法

| 方法 | 核心作用 | 实战说明/避坑 |
|------|----------|---------------|
| `processInstanceId(String instanceId)` | 按流程实例ID查询 | **最常用**，查某流程的完整执行轨迹，流程审计必备 |
| `activityId(String activityId)` | 按BPMN节点ID查询 | 查某流程实例中指定节点的执行信息（如“经理审批”节点） |
| `activityType(String activityType)` | 按节点类型查询 | 核心筛选，如`userTask`（用户任务）、`serviceTask`（服务任务）、`exclusiveGateway`（排他网关） |
| `finished()` | 仅查询**已完成**的节点活动 | 实战默认筛选，排除未完成的节点 |
| `assignee(String userId)` | 按用户任务处理人查询 | 查某用户处理的所有节点活动 |
| `orderByActivityEndTimeDesc()` | 按节点结束时间倒序 | 查流程执行轨迹时常用 |
| `durationGreaterThan(Long ms)` | 按节点执行时长筛选 | 性能分析常用（如查耗时超过1小时的节点） |

### 注意事项/避坑

1. **节点类型规范**：`activityType`为Flowable内置的节点类型标识，**必须按BPMN标准类型填写**（如用户任务为`userTask`，不可自定义）；
2. **网关/事件无处理人**：仅`userTask`（用户任务）、`manualTask`（手动任务）有`assignee`字段，网关、事件、服务任务的处理人为null；
3. **耗时分析核心**：通过`getDurationInMillis()`可获取节点执行的毫秒数，是流程性能优化、瓶颈分析的唯一依据。

## 四、历史变量实例（HistoricVariableInstance）API（实战常用）

**历史变量实例**对应历史表`ACT_HI_VARINST`，记录了流程实例/任务在运行过程中的**所有变量快照**，包括变量名、变量值、变量类型、所属流程实例/任务ID等，是**流程数据追溯**的核心（如查某流程实例的请假天数、审批结果等），对应运行时表`ACT_RU_VARIABLE`。

### 核心方法

```java
// 创建历史变量实例查询器
HistoricVariableInstanceQuery createHistoricVariableInstanceQuery();
```

### `HistoricVariableInstanceQuery` 核心筛选/执行方法

| 方法 | 核心作用 | 实战说明/避坑 |
|------|----------|---------------|
| `processInstanceId(String instanceId)` | 按流程实例ID查询 | 查某流程的所有历史变量，数据追溯必备 |
| `taskId(String taskId)` | 按任务ID查询 | 查某任务的局部历史变量 |
| `variableName(String varName)` | 按变量名精确查询 | 查指定变量的值（如`approveResult`（审批结果）） |
| `variableNameLike(String varNameLike)` | 按变量名模糊查询 | 如`%leave%`查所有请假相关变量 |
| `variableValueEquals(String varName, Object value)` | 按变量名+值精确匹配 | 统计常用（如查所有审批通过的流程：`variableValueEquals("approve", true)`） |
| `orderByVariableName()` | 按变量名排序 | 批量变量查询时常用 |

### 注意事项/避坑

1. **变量快照特性**：历史变量是**运行时变量的最终快照**，若流程运行中变量被修改，历史表仅保存**最终值**（需通过运行时日志追溯中间修改记录）；
2. **类型与运行时一致**：变量类型与`RuntimeService`/`TaskService`设置的类型一致，建议仅用基础类型（String/Integer/Date），避免自定义对象（反序列化风险）；
3. **全局/局部变量区分**：按`processInstanceId`查询的是**流程全局变量**，按`taskId`查询的是**任务局部变量**，可通过`getTaskId()`判断变量归属。

## 五、历史批注/评论（HistoricComment）API（实战必备）

**历史批注**对应历史表`ACT_HI_COMMENT`，与`TaskService`的`Comment`为同一数据，记录了用户在处理任务时添加的**审批意见、备注**，是**企业流程审计的核心依据**（如查某流程的审批驳回原因），**永久保存**且无修改/删除API。

### 核心方法

```java
// 创建历史批注查询器（实战必备）
HistoricCommentQuery createHistoricCommentQuery();
```

### `HistoricCommentQuery` 核心筛选/执行方法

| 方法 | 核心作用 | 实战说明/避坑 |
|------|----------|---------------|
| `processInstanceId(String instanceId)` | 按流程实例ID查询 | **最常用**，查某流程的所有审批意见，审计必备 |
| `taskId(String taskId)` | 按任务ID查询 | 查某任务的审批意见 |
| `type(String type)` | 按批注类型查询 | 按自定义类型筛选（如`APPROVE`（同意）、`REJECT`（驳回）、`REMIND`（提醒）） |
| `orderByTimeDesc()` | 按批注添加时间倒序 | 最新的审批意见在前，符合查询习惯 |

### 注意事项/避坑

1. **与TaskService的Comment互通**：通过`TaskService.addComment()`添加的批注，会自动同步到`ACT_HI_COMMENT`，可通过本API统一查询；
2. **批注不可篡改**：Flowable未提供任何修改/删除历史批注的API，生产环境需在添加前做内容校验，避免错误批注；
3. **必传关联ID**：批注必须关联`processInstanceId`和`taskId`，否则无法通过流程/任务追溯，添加时需严格遵守。

## 六、历史身份链接（HistoricIdentityLink）API（实战进阶）

**历史身份链接**对应历史表`ACT_HI_IDENTITYLINK`，记录了用户任务的**候选人、候选组、处理人**等身份关联的历史信息，是**任务分配追溯**的补充（如查某历史任务的原始候选人列表），对应运行时表`ACT_RU_IDENTITYLINK`。

### 核心方法

```java
// 创建历史身份链接查询器
HistoricIdentityLinkQuery createHistoricIdentityLinkQuery();
```

### 核心筛选方法

- `processInstanceId(String instanceId)`：按流程实例ID查询；
- `taskId(String taskId)`：按任务ID查询（最常用，查某历史任务的身份关联）；
- `userId(String userId)`：按用户ID查询（查某用户参与的所有历史任务身份关联）；
- `groupId(String groupId)`：按组ID查询（查某组参与的所有历史任务身份关联）；
- `type(String type)`：按身份类型查询（如`candidate`（候选人）、`assignee`（处理人））。

### 注意事项/避坑

1. **仅记录用户任务的身份信息**：网关、服务任务等无身份关联的节点，无对应的历史身份链接记录；
2. **追溯委派/转办的补充**：若任务被委派/转办，可通过该API查询原始候选人/认领人，配合历史批注完成完整追溯。

## 七、历史数据清理API（生产环境必备，谨慎使用）

Flowable默认**永久保存所有历史数据**，随着业务运行，历史表会持续膨胀，导致查询性能下降，`HistoryService`提供了**历史数据手动清理API**，支持按流程实例ID删除或按**时间/保留策略**批量清理，**生产环境需配合Flowable的自动清理配置使用**，严禁随意手动清理。

### 核心方法

```java
// 1. 按流程实例ID删除历史数据（级联删除，物理删除）
void deleteHistoricProcessInstance(String processInstanceId);

// 2. 异步清理历史数据（按Flowable配置的清理策略）
void cleanUpHistoryAsync();

// 3. 批量删除历史流程实例（Flowable 6.7+，按查询条件）
void deleteHistoricProcessInstances(HistoricProcessInstanceQuery query);
```

### 注意事项/避坑

1. **级联删除特性**：删除某历史流程实例时，会**自动级联删除**其关联的所有历史数据（任务、活动、变量、批注、身份链接等），无需逐个删除；
2. **手动清理仅作应急**：生产环境**优先使用Flowable的自动历史清理配置**（如设置历史数据保留30天），而非手动调用API，避免误删；
3. **清理前必须备份**：所有历史数据清理操作均为**物理删除**，不可恢复，执行前必须全量备份历史表；
4. **异步清理**：`cleanUpHistoryAsync()`会触发Flowable的异步清理作业，按`flowable.cfg.xml`/`application.yml`中配置的**保留时间/清理策略**执行，不会阻塞主线程。

### 生产环境核心配置（Spring Boot示例）

```yaml
flowable:
  # 开启历史数据自动清理
  history:
    cleanup:
      enabled: true
      # 清理策略：保留30天的历史数据，删除超过30天的已完成流程
      history-time-to-live: 30
      # 每天凌晨2点执行清理
      cron-expression: 0 0 2 * * ?
  # 设置历史级别（生产建议用audit，记录核心审计数据）
  history-level: audit
```

> 历史级别说明：
>
> - `none`：不保存任何历史数据（仅测试用）；
> - `activity`：保存流程实例和活动实例历史；
> - `audit`：保存核心审计数据（实例、任务、变量、批注），**生产环境首选**；
> - `full`：保存所有历史数据（含执行流、作业日志），适用于严格审计的场景，查询性能较低。

## 八、其他历史辅助API（实战少用，按需使用）

此类API用于查询Flowable的**历史执行流、历史作业日志、历史表单**等小众历史数据，适用于特殊场景的追溯/排查，使用频率较低，仅做基础说明。

1. **历史执行流**：`createHistoricExecutionQuery()`——查询历史执行流信息，适用于并行流程/子流程的追溯；
2. **历史作业日志**：`createHistoricJobLogQuery()`——查询定时器、异步任务的执行日志，适用于定时任务异常追溯；
3. **历史表单**：`createHistoricFormPropertyQuery()`——查询历史表单属性，适用于使用Flowable内置表单的场景；
4. **历史流程实例统计**：`createHistoricProcessInstanceReportQuery()`——流程实例报表统计，如按流程Key统计完成数量。

## 九、HistoryService 通用避坑原则（所有API通用）

结合企业实战经验，整理`HistoryService`所有操作的核心避坑点，**必须严格遵守**，否则会导致审计数据丢失、流程追溯失败、查询性能低下等严重问题：

### 1. 历史数据：谨慎删除，永久保存为默认原则

- 历史数据是**企业流程审计、合规检查的核心依据**，默认**永久保存**，仅在**磁盘空间不足、查询性能严重下降**时，按**合理的保留策略**清理（如保留3/6个月）；
- 所有清理操作必须**先备份、再执行**，且仅清理**已完成、无审计价值**的历史数据，严禁删除近期/重要业务的历史数据。

### 2. 区分查询：历史查询≠运行时查询，不可混淆

严格区分历史服务与运行时服务的查询边界，**禁止用HistoryService查询运行中数据**，反之亦然：

| 数据状态 | 查询服务 | 操作表 |
|----------|----------|--------|
| 运行中/激活 | RuntimeService/TaskService | ACT_RU_* |
| 已完成/已删除/已挂起 | HistoryService | ACT_HI_* |

### 3. 关联查询：必用businessKey，避免孤立历史数据

查询历史流程时，**必须通过`businessKey`与业务系统关联**，而非仅靠流程实例ID——`businessKey`是流程实例与业务数据（如订单、请假单）的唯一关联标识，无`businessKey`的历史实例会成为“孤立数据”，无法追溯业务背景。

### 4. 性能优化：批量查询必加分页，避免大数据量加载

历史表数据量会随业务持续增长，**所有批量查询必须使用分页（`listPage()`）**，禁止直接使用`list()`加载全量数据，否则会导致内存溢出、查询超时。

### 5. 历史级别：生产环境按需配置，避免过度存储

Flowable的**历史级别**直接决定历史数据的存储量和查询性能，生产环境**优先使用`audit`级别**（保存核心审计数据），而非`full`级别（保存所有数据）——过度存储会导致历史表快速膨胀，查询性能大幅下降。

### 6. 启动人：启动流程时必须手动设置，保证追溯完整性

`startedBy(userId)`是按启动人查询历史流程的核心条件，**启动流程时必须通过`IdentityService`设置启动人**，否则启动人为null，无法按用户/部门做流程统计：

```java
// 启动流程前设置启动人
identityService.setAuthenticatedUserId("zhangsan");
// 再启动流程
runtimeService.startProcessInstanceByKey("leaveProcess", "leave_1001", variables);
```

### 7. 多租户场景：查询必加tenantId筛选

多租户场景下，**所有历史查询必须加`tenantId(String tenantId)`筛选**，避免不同租户的历史数据相互混淆，导致数据泄露/查询结果错误。

### 8. 变量/批注：仅用基础类型，保证可追溯性

- 历史变量仅使用**基础类型（String/Integer/Date）**，禁止使用自定义对象，避免反序列化失败导致数据无法读取；
- 历史批注必须**清晰、规范**，包含处理结果、原因，禁止空批注/无意义批注，保证审计追溯的完整性。

## 十、HistoryService 核心API速查（实战90%场景覆盖）

整理日常开发中**最常用的核心API**，按**企业实战使用频率排序**，便于快速查阅和使用，覆盖流程审计、数据追溯、报表统计的核心场景：

1. **查某业务的历史流程**：`createHistoricProcessInstanceQuery().businessKey(businessKey).finished().singleResult()`；
2. **查某流程的所有审批意见**：`createHistoricCommentQuery().processInstanceId(instanceId).orderByTimeDesc().list()`；
3. **查某流程的完整执行轨迹**：`createHistoricActivityInstanceQuery().processInstanceId(instanceId).finished().list()`；
4. **查某用户的所有已办审批任务**：`createHistoricTaskInstanceQuery().assignee(userId).finished().orderByTaskCompletionTimeDesc().list()`；
5. **查某流程的所有历史变量**：`createHistoricVariableInstanceQuery().processInstanceId(instanceId).list()`；
6. **查某时间段完成的流程**：`createHistoricProcessInstanceQuery().processDefinitionKey(key).finished().finishedAfter(startDate).finishedBefore(endDate).listPage()`；
7. **单流程历史数据清理（应急）**：`deleteHistoricProcessInstance(instanceId)`；
8. **查某历史任务的候选人**：`createHistoricIdentityLinkQuery().taskId(taskId).type("candidate").list()`。
