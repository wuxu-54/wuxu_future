# Flowable 工作流框架全解析

Flowable 是一款**开源的轻量级企业级工作流框架**，基于Java开发，继承并优化了Activiti 5.x的核心能力，全面遵循**BPMN 2.0（业务流程建模与标注）** 工业标准，同时支持CMMN（案例管理模型）、DMN（决策模型和符号）等规范，可快速实现业务流程的自动化、标准化与可视化管理。

Flowable 设计理念为**模块化、可扩展、低侵入**，与Spring/Spring Boot生态无缝集成，支持集群部署、高性能异步执行，适用于OA审批、订单流转、供应链协同、风控审核等几乎所有需要流程驱动的业务场景。

本文将从**核心定位、模块体系、架构设计、核心概念、API、使用流程、BPMN 2.0详解、高级特性、UI工具、数据库、集群部署**等维度，进行全方位、精细化讲解。

## 一、Flowable 核心模块体系

Flowable 采用**松耦合的模块化设计**，核心功能拆分为独立引擎，可根据业务需求按需引入，避免冗余依赖，各模块共享统一的核心基础组件（如持久化、身份认证）。

### 1. 核心引擎模块（必选/核心）

| 模块名称         | 核心包名                  | 功能说明                                                                 |
|------------------|---------------------------|--------------------------------------------------------------------------|
| 流程引擎（Process Engine） | `flowable-engine`          | Flowable 核心，实现BPMN 2.0流程的解析、部署、执行、调度，是所有流程能力的基础 |
| 身份管理引擎（IDM Engine） | `flowable-idm-engine`      | 提供统一的身份认证与授权，管理**用户（User）、组（Group）、权限（Privilege）**，为流程任务分配、权限控制提供支撑 |
| 内容引擎（Content Engine） | `flowable-content-engine`  | 流程附件管理，支持流程/任务关联文档、文件，实现流程与内容的一体化管理       |
| 案例管理引擎（CMMN Engine） | `flowable-cmmn-engine`     | 支持CMMN 1.1规范，处理**非结构化、动态化的案例流程**（如客户服务、应急处理） |
| 决策引擎（DMN Engine）     | `flowable-dmn-engine`      | 支持DMN 1.3规范，实现业务规则的可视化配置与自动化决策（如风控规则、审批条件） |

### 2. 附加功能模块（可选）

| 模块名称         | 核心包名                  | 功能说明                                                                 |
|------------------|---------------------------|--------------------------------------------------------------------------|
| 表单引擎（Form Engine）| `flowable-form-engine`| 支持流程表单的定义、渲染与数据校验，可与人工任务无缝绑定                   |
| REST API 模块    | `flowable-rest`            | 提供标准化的RESTful接口，支持跨语言/跨系统调用Flowable所有核心能力         |
| UI 模块          | `flowable-ui-*`            | 可视化操作平台，包含流程设计、任务处理、后台管理等功能（下文单独详解）     |
| 集成模块         | `flowable-spring-boot-starter` | Spring Boot快速集成启动器，自动配置引擎、数据源、Bean等，简化开发 |

## 二、Flowable 整体架构设计

Flowable 采用**分层架构**，各层职责清晰、低耦合，便于扩展和定制，整体分为四层，从下到上支撑业务流程的全生命周期管理：

### 1. 持久层（Persistence Layer）

- 核心技术：基于**MyBatis**实现ORM映射，封装数据库操作，屏蔽不同数据库的语法差异；
- 事务管理：支持Spring声明式事务、JDBC本地事务，保证流程操作的原子性；
- 支持数据库：MySQL、Oracle、PostgreSQL、SQL Server、H2等主流关系型数据库；
- 核心作用：负责流程所有数据（部署、运行、历史、身份）的持久化与读取。

### 2. 核心引擎层（Core Engine Layer）

Flowable 的**核心能力层**，包含上文所有引擎模块，是流程处理的“大脑”：

- 核心职责：流程定义解析、流程实例调度、任务生命周期管理、事件触发、异步作业执行、规则决策等；
- 核心组件：流程引擎配置器（ProcessEngineConfiguration）、作业执行器（JobExecutor）、监听器管理器、表达式解析器等；
- 设计特点：所有引擎基于统一的抽象接口实现，可独立初始化也可集成使用。

### 3. 服务API层（Service API Layer）

Flowable 对外暴露的**标准化编程接口**，所有接口均为面向抽象的设计（接口+实现），屏蔽底层引擎细节，是开发人员的核心操作入口。

- 设计原则：单一职责、易用性、通用性，支持同步/异步调用；
- 核心服务：RepositoryService、RuntimeService、TaskService等（下文单独详解）；
- 集成方式：支持原生Java调用、Spring依赖注入、REST远程调用。

### 4. 应用层（Application Layer）

- 业务系统：开发者基于Flowable API开发的业务应用（如OA系统、订单系统）；
- Flowable 官方UI：可视化的流程设计、任务处理、后台管理平台（无需编码即可完成基础操作）；
- 第三方集成：支持与ESB、消息队列、监控系统等第三方组件集成，实现流程的分布式扩展。

**架构核心入口**：`ProcessEngine`（流程引擎实例），所有Service API均通过`ProcessEngine`获取，是连接应用层与核心引擎层的桥梁。

## 三、Flowable 核心概念（必懂）

Flowable 的所有操作均围绕核心概念展开，理解这些概念是掌握框架的基础，同时这些概念也与BPMN 2.0规范高度一致：

### 1. 流程引擎（ProcessEngine）

- 定义：Flowable 核心实例，是所有流程操作的**统一入口**，负责初始化引擎、管理各Service API、协调流程执行；
- 特性：一个应用中通常只有一个`ProcessEngine`实例（单例），由`ProcessEngineConfiguration`创建并配置；
- 作用：封装底层引擎的初始化、资源管理、组件协调，对外提供标准化的Service API。

### 2. 流程定义（ProcessDefinition）

- 定义：BPMN 2.0 XML文件经过Flowable 解析后生成的**持久化对象**，是流程的“模板/蓝图”；
- 核心属性：`key`（流程标识，唯一，用于区分不同流程）、`name`（流程名称）、`version`（版本号，同key的流程多次部署会自动升级版本）、`deploymentId`（部署ID，关联部署信息）；
- 作用：作为创建**流程实例**的依据，一个流程定义可创建多个流程实例（如“请假流程”模板可生成多个员工的请假流程）。

### 3. 流程部署（Deployment）

- 定义：将BPMN 2.0 XML、表单、附件等流程相关资源**上传并解析**到Flowable 引擎的过程，部署后流程定义才会生效；
- 特性：部署操作是原子性的，支持批量部署多个资源，部署后生成唯一的`deploymentId`；
- 作用：将开发/设计好的流程模板发布到引擎中，供业务系统调用启动。

### 4. 流程实例（ProcessInstance）

- 定义：根据**流程定义**创建的**一次具体的流程运行实例**，代表一个业务流程的全生命周期（如“张三2026年2月3日的请假流程”）；
- 核心属性：`processInstanceId`（唯一ID）、`processDefinitionId`（关联的流程定义ID）、`businessKey`（业务主键，关联业务系统数据，如订单ID、请假单ID，**关键联查字段**）；
- 特性：流程实例从**开始事件**启动，到**结束事件**终止，期间经历所有配置的节点/活动。

### 5. 执行实例（Execution）

- 定义：流程实例的**具体执行路径**，是Flowable 内部用于跟踪流程运行状态的核心对象；
- 与流程实例的关系：
  - 简单流程（无分支、无并行）：一个流程实例对应**一个执行实例**；
  - 复杂流程（有网关、并行、多实例）：一个流程实例对应**多个执行实例**（如并行网关会生成多个执行实例，分别走不同分支）；
- 作用：Flowable 引擎通过执行实例跟踪流程的当前运行节点、执行状态、流转路径。

### 6. 任务（Task）

- 定义：流程执行过程中需要**人工处理**或**自动执行**的具体工作项，是流程与用户/系统交互的核心载体；
- 核心分类：
  - 人工任务（UserTask）：需要人为操作的任务（如审批、填写表单），是最常用的任务类型；
  - 自动任务：服务任务（ServiceTask）、脚本任务（ScriptTask）等，由引擎自动执行；
- 核心属性：`taskId`、`assignee`（处理人）、`candidateUsers`（候选用户）、`candidateGroups`（候选组）、`processInstanceId`（关联流程实例）。

### 7. 活动（Activity）

- 定义：流程中**具体的工作步骤**，是BPMN 2.0的核心元素之一，对应流程执行的最小单元；
- 常见类型：人工任务、服务任务、脚本任务、接收任务、发送任务、子流程等；
- 特性：每个活动有唯一的`id`和`name`，可配置监听器、异步执行、条件等属性。

### 8. 网关（Gateway）

- 定义：流程中的**分支/聚合控制节点**，用于实现流程的条件判断、并行执行、聚合合并，类似编程中的`if/else`、`for`、`并行执行`；
- 常见类型：排他网关、并行网关、包容网关、事件网关（下文BPMN 2.0部分详解）；
- 作用：控制流程的执行路径，实现复杂的流程逻辑。

### 9. 序列流（SequenceFlow）

- 定义：连接流程中各个节点（事件、活动、网关）的**连线**，代表流程的**流转方向**；
- 核心类型：
  - 普通序列流：无条件流转；
  - 条件序列流：配置`conditionExpression`（条件表达式），满足条件时才流转；
  - 默认序列流：网关的默认流转路径，当所有条件序列流都不满足时触发；
- 核心属性：`sourceRef`（源节点ID）、`targetRef`（目标节点ID）、`conditionExpression`（条件表达式）。

### 10. 流程变量（Variable）

- 定义：流程运行过程中需要传递的**业务数据**，是流程与业务系统交互的核心载体，类似编程中的“全局变量/局部变量”；
- 分类：
  - 全局变量：关联**流程实例**，整个流程生命周期内有效，所有节点均可访问；
  - 局部变量：关联**任务/执行实例**，仅在当前任务/执行实例范围内有效；
- 支持类型：基本类型（String/Integer/Boolean）、对象类型（自定义POJO）、集合类型（List/Map），支持序列化存储。

### 11. 身份信息（User/Group/Privilege）

- 由IDM Engine管理，是流程权限控制和任务分配的基础：
  - User（用户）：系统的具体操作人员，如审批人、发起人，有唯一`userId`；
  - Group（组/角色）：用户的集合，如“部门经理组”、“财务组”，便于批量分配任务，有唯一`groupId`；
  - Privilege（权限）：Flowable 引擎的操作权限，如“部署流程”、“管理用户”，用于控制Flowable UI/API的访问权限。

### 12. 历史数据（History）

- 定义：流程运行过程中产生的**所有历史记录**，包括流程实例、任务、变量、活动执行记录等；
- 特性：运行时数据（ACT_RU_*）在流程/任务结束后，会被移到历史表（ACT_HI_*），运行时表仅保留未完成的流程数据，保证性能；
- 作用：用于流程追溯、统计分析、报表生成。

## 四、Flowable 核心服务API（开发核心入口）

Flowable 所有核心能力均通过**标准化的Service API**对外暴露，所有Service均为接口设计，由引擎自动实现，开发人员无需关注底层细节。

所有Service API均可通过`ProcessEngine`实例获取，Spring Boot环境中可直接通过`@Autowired`注入使用，**核心Service及功能如下（开发高频使用）**：

### 1. RepositoryService（仓库服务）

**核心职责：流程资源的部署、查询、管理**，操作的是**流程定义（ProcessDefinition）** 和**部署（Deployment）** 相关数据，是流程使用的“前置服务”（流程必须先部署才能启动）。

- 核心方法：
  - 部署流程：`createDeployment()`（创建部署构建器）→ `addClasspathResource()`（添加BPMN资源）→ `deploy()`（执行部署）；
  - 查询流程定义：`createProcessDefinitionQuery()`（流程定义查询器），支持按key、name、version、部署ID等条件查询；
  - 查询部署：`createDeploymentQuery()`；
  - 其他：删除部署、挂起/激活流程定义、获取流程资源文件（如BPMN XML）。

### 2. RuntimeService（运行时服务）

**核心职责：流程实例的启动、运行时管理**，操作的是**流程实例（ProcessInstance）** 和**执行实例（Execution）** 相关数据，是流程运行的核心服务。

- 核心方法：
  - 启动流程实例：`startProcessInstanceByKey(String processDefinitionKey)`（按流程key启动，自动使用最新版本）、`startProcessInstanceById(String processDefinitionId)`，支持设置`businessKey`和流程变量；
  - 流程变量管理：`setVariable()`/`setVariables()`（设置全局变量）、`getVariable()`/`getVariables()`（获取全局变量）；
  - 流程实例查询：`createProcessInstanceQuery()`，支持按processDefinitionKey、businessKey、变量等条件查询；
  - 其他：触发流程信号（signal）、消息（message）、挂起/激活流程实例。

### 3. TaskService（任务服务）

**核心职责：人工任务的全生命周期管理**，是开发中**使用频率最高**的服务，主要处理UserTask的查询、认领、完成、委派等操作。

- 核心方法：
  - 任务查询：`createTaskQuery()`，支持按assignee（处理人）、candidateUser（候选用户）、candidateGroup（候选组）、processInstanceId等条件查询（如查询“我的待办任务”、“部门待办任务”）；
  - 认领任务：`claim(String taskId, String userId)`（将候选任务分配给具体用户，变为“我的待办”）；
  - 完成任务：`complete(String taskId)`、`complete(String taskId, Map<String, Object> variables)`（完成任务并传递任务变量）；
  - 任务变量管理：`setLocalVariable()`/`setLocalVariables()`（设置任务局部变量）、`getLocalVariable()`/`getLocalVariables()`；
  - 其他：委派任务（delegateTask）、转办任务（setAssignee）、挂起/激活任务、添加任务附件。

### 4. IdentityService（身份服务）

**核心职责：用户、组、权限的管理**，由IDM Engine提供支撑，用于流程的身份认证和权限控制。

- 核心方法：
  - 用户管理：`createUser()`/`saveUser()`/`deleteUser()`/`createUserQuery()`；
  - 组管理：`createGroup()`/`saveGroup()`/`deleteGroup()`/`createGroupQuery()`；
  - 用户与组关联：`createMembership(String userId, String groupId)`（将用户加入组）、`deleteMembership()`；
  - 注意：生产环境中若已有统一的身份认证系统（如LDAP、企业统一账号），可**禁用Flowable 内置IDM**，通过自定义身份处理器集成外部系统。

### 5. HistoryService（历史服务）

**核心职责：历史数据的查询与统计**，操作的是历史表（ACT_HI_*）中的数据，用于流程追溯、报表分析。

- 核心方法：
  - 历史流程实例查询：`createHistoricProcessInstanceQuery()`，支持按businessKey、processDefinitionKey、结束时间等条件查询；
  - 历史任务查询：`createHistoricTaskInstanceQuery()`，查询已完成的任务；
  - 历史活动查询：`createHistoricActivityInstanceQuery()`，查询流程中所有活动的执行记录；
  - 历史变量查询：`createHistoricVariableInstanceQuery()`，查询流程运行过的所有变量；
  - 统计分析：支持按流程、用户、时间等维度统计流程执行次数、耗时等。

### 6. ManagementService（管理服务）

**核心职责：Flowable 引擎的底层管理与监控**，主要用于运维和高级开发，开发人员一般较少使用。

- 核心方法：
  - 作业（Job）管理：查询/执行/删除异步作业、定时器作业；
  - 引擎配置查询：获取流程引擎的配置信息；
  - 数据库操作：执行数据库脚本、查询表结构；
  - 监控：获取引擎运行状态、统计数据。

### 7. FormService（表单服务，可选）

**核心职责：流程表单的定义、渲染与数据处理**，支持将表单与人工任务绑定，实现任务表单的自动化加载。

- 核心方法：查询流程表单、渲染表单、保存表单数据。

## 五、Flowable 环境搭建（两种主流方式）

Flowable 支持**原生Java**和**Spring Boot**两种搭建方式，其中**Spring Boot**是目前企业开发的主流（自动配置、快速集成），下文分别讲解核心步骤。

### 方式1：Spring Boot 集成（推荐）

#### 1. 引入Maven依赖（核心starter）

```xml
<!-- Flowable 核心Spring Boot启动器（包含Process Engine、IDM、Content等核心引擎） -->
<dependency>
    <groupId>org.flowable</groupId>
    <artifactId>flowable-spring-boot-starter</artifactId>
    <version>7.0.1</version> <!-- 推荐使用最新稳定版，需与Spring Boot版本兼容 -->
</dependency>
<!-- 数据库驱动（以MySQL8为例） -->
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
<!-- 数据库连接池（Spring Boot默认HikariCP） -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>
</dependency>
<!-- Spring Boot Web（用于业务接口开发） -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

> 版本兼容：Flowable 7.x 兼容Spring Boot 2.7.x+、3.x；Flowable 6.x 兼容Spring Boot 2.x。

#### 2. 配置application.yml（核心配置）

```yaml
spring:
  # 数据库配置
  datasource:
    url: jdbc:mysql://localhost:3306/flowable?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&nullCatalogMeansCurrent=true
    username: root
    password: 123456
    driver-class-name: com.mysql.cj.jdbc.Driver
# Flowable 核心配置
flowable:
  # 流程引擎配置
  process:
    # 自动部署classpath下的流程资源（默认路径：classpath:/processes/,具体是指 resources/processes/，BPMN文件放此目录会自动部署。  可以看上一文章了解）
    auto-deploy-designated-process-definitions: true
    # 历史级别（核心配置，下文详解）
    history-level: audit
  # 关闭内置IDM引擎（若使用外部身份系统，需开启此配置）
  # idm:
  #   enabled: false
  # 作业执行器（异步执行、定时器任务核心，默认开启）
  job-executor:
    enabled: true
  # 数据库表初始化策略（默认：create-drop，生产环境改为none）
  # database-schema-update: none
```

#### 3. 启动项目

Flowable 会**自动初始化数据库表结构**（约60+张表），并自动部署`classpath:/processes/`下的BPMN文件，启动后即可通过`@Autowired`注入核心Service。

### 方式2：原生Java 搭建（无Spring）

#### 1. 引入Maven依赖

```xml
<dependency>
    <groupId>org.flowable</groupId>
    <artifactId>flowable-engine</artifactId>
    <version>7.0.1</version>
</dependency>
<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-java</artifactId>
    <version>8.0.33</version>
</dependency>
<dependency>
    <groupId>com.alibaba</groupId>
    <artifactId>druid</artifactId>
    <version>1.2.18</version> <!-- 数据库连接池 -->
</dependency>
```

#### 2. 初始化ProcessEngine

```java
import org.flowable.engine.ProcessEngine;
import org.flowable.engine.ProcessEngineConfiguration;
import org.flowable.engine.impl.cfg.StandaloneProcessEngineConfiguration;

public class FlowableInit {
    public static void main(String[] args) {
```

## 六、Flowable 核心使用流程（完整示例）

以**员工请假流程**为例，讲解从**流程设计**→**部署**→**启动实例**→**任务处理**→**流程结束**→**历史查询**的完整流程，覆盖开发核心场景。

### 步骤1：设计BPMN 2.0流程文件

在`classpath:/processes/`下创建`leave-process.bpmn20.xml`（Flowable 识别`.bpmn`/`.bpmn20.xml`后缀），设计一个简单的请假流程：
**流程逻辑**：开始事件 → 填写请假单（发起人任务） → 部门经理审批（排他网关：同意/拒绝） → 结束事件（同意/拒绝）。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<definitions
        xmlns="http://www.omg.org/spec/BPMN/20100524/MODEL"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="http://www.omg.org/spec/BPMN/20100524/MODEL http://www.omg.org/spec/BPMN/2.0/20100501/BPMN20.xsd"
        id="Definitions_1"
        targetNamespace="http://flowable.org/processdef"
        xmlns:flowable="http://flowable.org/bpmn">

    <!-- 流程定义：key为leave-process（唯一标识），name为员工请假流程 -->
    <process id="leave-process" name="员工请假流程" isExecutable="true">
        <!-- 开始事件 -->
        <startEvent id="startEvent1" name="开始请假"/>

        <!-- 任务1：填写请假单（发起人任务，assignee通过流程变量动态分配） -->
        <userTask id="fillLeaveForm" name="填写请假单" flowable:assignee="${applyer}"/>

        <!-- 排他网关：部门经理审批（条件分支：同意/拒绝） -->
        <exclusiveGateway id="managerApprovalGateway" name="部门经理审批"/>

        <!-- 任务2：部门经理审批（候选组：dept-manager，可配置为具体用户） -->
        <userTask id="managerApproval" name="部门经理审批" flowable:candidateGroups="dept-manager"/>

        <!-- 结束事件：请假同意 -->
        <endEvent id="endEventAgree" name="请假同意"/>

        <!-- 结束事件：请假拒绝 -->
        <endEvent id="endEventRefuse" name="请假拒绝"/>

        <!-- 序列流：开始 → 填写请假单 -->
        <sequenceFlow id="flow1" sourceRef="startEvent1" targetRef="fillLeaveForm"/>

        <!-- 序列流：填写请假单 → 部门经理审批任务 -->
        <sequenceFlow id="flow2" sourceRef="fillLeaveForm" targetRef="managerApproval"/>

        <!-- 序列流：部门经理审批任务 → 排他网关 -->
        <sequenceFlow id="flow3" sourceRef="managerApproval" targetRef="managerApprovalGateway"/>

        <!-- 序列流：排他网关 → 同意结束（条件：审批结果为agree） -->
        <sequenceFlow id="flow4" sourceRef="managerApprovalGateway" targetRef="endEventAgree">
            <conditionExpression xsi:type="tFormalExpression">${approvalResult == 'agree'}</conditionExpression>
        </sequenceFlow>

        <!-- 序列流：排他网关 → 拒绝结束（条件：审批结果为refuse，默认序列流） -->
        <sequenceFlow id="flow5" sourceRef="managerApprovalGateway" targetRef="endEventRefuse" isDefault="true"/>
    </process>
</definitions>
```

> 关键配置说明：
>
> 1. `process id="leave-process"`：流程key，启动流程时的核心标识；
> 2. `flowable:assignee="${applyer}"`：动态分配处理人，`applyer`为流程变量；
> 3. `flowable:candidateGroups="dept-manager"`：设置候选组，组内所有用户均可认领任务；
> 4. `conditionExpression="${approvalResult == 'agree'}"`：条件表达式，`approvalResult`为任务完成时传递的变量。

### 步骤2：流程部署（RepositoryService）

Spring Boot环境中，将BPMN文件放入`classpath:/processes/`，Flowable 会**自动部署**；若需手动部署，代码如下：

```java
import org.flowable.engine.RepositoryService;
import org.flowable.engine.repository.Deployment;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import javax.annotation.PostConstruct;

@Component
public class ProcessDeployer {
    @Autowired
    private RepositoryService repositoryService;

    // 项目启动时手动部署
    @PostConstruct
    public void deployProcess() {
        Deployment deployment = repositoryService.createDeployment()
                .name("员工请假流程部署") // 部署名称
                .addClasspathResource("processes/leave-process.bpmn20.xml") // 添加BPMN资源
                .deploy(); // 执行部署
        System.out.println("流程部署成功，部署ID：" + deployment.getId());
    }
}
```

部署成功后，Flowable 会将流程定义存入数据库（ACT_RE_PROCDEF表），生成唯一的`processDefinitionId`（格式：leave-process:1:xxxx）。

### 步骤3：启动流程实例（RuntimeService）

发起请假时，通过RuntimeService启动流程实例，设置**业务主键（businessKey）** 和**流程变量（applyer：发起人）**：

```java
import org.flowable.engine.RuntimeService;
import org.flowable.engine.runtime.ProcessInstance;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.HashMap;
import java.util.Map;

@RestController
@RequestMapping("/leave")
public class LeaveController {
    @Autowired
    private RuntimeService runtimeService;

    /**
     * 启动请假流程实例
     * @param applyer 发起人ID
     * @param leaveId 请假单ID（业务主键）
     * @return 流程实例ID
     */
    @PostMapping("/start")
    public String startLeaveProcess(@RequestParam String applyer, @RequestParam String leaveId) {
        // 设置流程变量：applyer（发起人，对应BPMN中的填写请假单处理人）
        Map<String, Object> variables = new HashMap<>();
        variables.put("applyer", applyer);

        // 启动流程实例：按流程key启动，自动使用最新版本
        ProcessInstance processInstance = runtimeService
                .startProcessInstanceByKey("leave-process", leaveId, variables);

        return "流程实例启动成功，流程实例ID：" + processInstance.getId() + "，业务主键：" + processInstance.getBusinessKey();
    }
}
```

> 关键：`startProcessInstanceByKey(String processDefinitionKey, String businessKey, Map variables)`
>
> - businessKey：关联业务系统的请假单ID，后续可通过此关键字联查流程与业务数据；
> - variables：传递流程变量，供BPMN中的表达式使用。

启动成功后，流程会执行到第一个任务**填写请假单**，并将任务存入数据库（ACT_RU_TASK表），处理人为`applyer`指定的用户。

### 步骤4：处理人工任务（TaskService）

包含**查询待办任务**、**认领任务**、**完成任务**三个核心操作，是员工/审批人的核心操作入口。

#### 4.1 查询待办任务（如：发起人查询“填写请假单”任务）

```java
import org.flowable.engine.TaskService;
import org.flowable.task.api.Task;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

    /**
     * 查询我的待办任务
     * @param userId 用户ID

     */
    @GetMapping("/todo")
    public List<Task> getTodoTasks(@RequestParam String userId) {

                .list();

     * @return 候选组任务列表

    @GetMapping("/candidate/group")
    public List<Task> getCandidateGroupTasks(@RequestParam String groupId) {

                .taskCandidateGroup(groupId) // 查询指定候选组的任务
                .orderByTaskCreateTime()
                .desc()
                .list();
    }
}
```

#### 4.2 认领候选组任务（如：部门经理认领审批任务）

```java

 * @param taskId 任务ID
```

#### 4.3 完成任务（如：发起人填写请假单、经理审批）

完成任务时可传递**任务变量**（如经理审批的`approvalResult`），Flowable 会根据变量执行流程流转：

```java
/**

 * @param taskId 任务ID
 * @param variables 任务变量（如：approvalResult=agree/refuse）
 * @return 完成结果
 */
```

## 七、BPMN 2.0 核心元素详解（流程设计基础）

BPMN 2.0 是Flowable 的设计基础，所有流程均通过BPMN 2.0元素组合实现，核心元素分为**事件、活动、网关、序列流**四大类，下文详解各类元素的用途和配置。

### 1. 事件（Event）

代表流程中**发生的事情**，用**圆形图标**表示，分为**开始事件、中间事件、结束事件**，核心用于标记流程的开始、结束和中间触发点。

#### （1）开始事件（Start Event）

- 用途：标记**流程的开始**，一个流程只能有一个主开始事件；
- 类型：无触发开始事件（最常用，默认启动）、定时器开始事件（定时启动流程）、消息开始事件（接收消息启动）；
- 配置：`<startEvent id="start1" name="流程开始"/>`。

#### （2）结束事件（End Event）

- 用途：标记**流程的结束**，一个流程可有多个结束事件（不同分支）；
- 类型：无结果结束事件（最常用）、终止结束事件（强制终止整个流程）；
- 配置：`<endEvent id="end1" name="流程结束"/>`。

#### （3）中间事件（Intermediate Event）

- 用途：发生在流程**中间节点**，分为**捕获事件（Catching）** 和**抛出事件（Throwing）**；
- 捕获事件：等待某个事件发生后，流程继续执行（如定时器捕获事件、信号捕获事件）；
- 抛出事件：流程执行到此处，抛出一个事件（如信号抛出事件、消息抛出事件），可触发其他流程/节点；
- 常用场景：定时器中间事件（流程暂停，定时后继续执行）、错误中间事件（捕获异常并处理）。

### 2. 活动（Activity）

代表流程中**需要执行的具体工作**，用**圆角矩形图标**表示，是流程的核心执行单元，分为**人工任务、自动任务**两大类，下文讲解开发中最常用的活动类型。

#### （1）用户任务（UserTask）

- 用途：需要**人工处理**的任务（如审批、填写表单），Flowable 中最常用的活动类型；
- 核心配置：任务分配（关键），支持4种分配方式：
  1. 直接分配：`flowable:assignee="zhangsan"`（固定处理人）；
  2. 动态分配：`flowable:assignee="${userId}"`（通过流程变量动态获取）；
  3. 候选用户：`flowable:candidateUsers="zhangsan,lisi"`（多个候选用户，可认领）；
  4. 候选组：`flowable:candidateGroups="dept-manager,finance"`（多个候选组，组内用户可认领）；
- 配置示例：

  ```xml
  <userTask id="task1" name="部门经理审批" flowable:candidateGroups="dept-manager"/>
  ```

#### （2）服务任务（ServiceTask）

- 用途：由**引擎自动执行**的任务，用于调用**业务系统接口、执行Java代码、调用外部服务**；
- 核心配置方式（3种）：
  1. 执行Java类：`flowable:class="com.example.service.MyServiceTask"`（实现`JavaDelegate`接口）；
  2. 调用Spring Bean：`flowable:delegateExpression="${myServiceTaskBean}"`（推荐，解耦）；
  3. 执行表达式：`flowable:expression="${userService.doSomething()}"`（调用Bean的方法）；
- 配置示例（调用Spring Bean）：

  ```xml
  <serviceTask id="service1" name="调用订单接口" flowable:delegateExpression="${orderService.createOrder}"/>
  ```

- JavaDelegate 实现示例：

  ```java
  import org.flowable.engine.delegate.DelegateExecution;
  import org.flowable.engine.delegate.JavaDelegate;
  import org.springframework.stereotype.Component;

  @Component("myServiceTaskBean")
  public class MyServiceTask implements JavaDelegate {
      @Override
      public void execute(DelegateExecution execution) {
          // 获取流程变量
          String orderId = (String) execution.getVariable("orderId");
          // 执行业务逻辑：调用接口、操作数据库等
          System.out.println("服务任务执行，订单ID：" + orderId);
          // 设置流程变量
          execution.setVariable("orderStatus", "success");
      }
  }
  ```

#### （3）脚本任务（ScriptTask）

- 用途：执行**脚本代码**（Groovy、JavaScript、Python等），用于简单的逻辑处理，无需编写Java类；
- 配置示例（执行Groovy脚本）：

  ```xml
  <scriptTask id="script1" name="计算请假天数" scriptFormat="groovy">
      <script>
          // 获取流程变量
          def startDate = execution.getVariable("startDate");
          def endDate = execution.getVariable("endDate");
          // 计算天数
          def days = (endDate - startDate).days + 1;
          // 设置流程变量
          execution.setVariable("leaveDays", days);
      </script>
  </scriptTask>
  ```

#### （4）子流程（SubProcess）

- 用途：将**复杂的流程逻辑拆分为子流程**，提高流程的可读性和复用性；
- 类型：
  1. 内嵌子流程（Embedded SubProcess）：直接定义在主流程中，与主流程共享流程变量；
  2. 调用子流程（Call Activity）：调用独立部署的流程定义，实现流程复用，支持传递入参和出参；
- 配置示例（调用子流程）：

  ```xml
  <callActivity id="call1" name="调用财务审批流程" flowable:processDefinitionKey="finance-approval-process">
      <!-- 传递入参 -->
      <extensionElements>
          <flowable:in source="leaveDays" target="leaveDays"/>
          <flowable:in source="applyer" target="applyer"/>
      </extensionElements>
      <!-- 接收出参 -->
      <extensionElements>
          <flowable:out source="financeResult" target="financeResult"/>
      </extensionElements>
  </callActivity>
  ```

### 3. 网关（Gateway）

代表流程的**分支/聚合控制**，用**菱形图标**表示，核心用于控制流程的执行路径，Flowable 支持4种核心网关，是实现复杂流程逻辑的关键。

#### （1）排他网关（Exclusive Gateway）

- 核心特点：**多选一**，只有**一条分支**会被执行；
- 执行规则：按序列流的顺序判断条件，第一个满足条件的序列流会被执行；若所有条件都不满足，执行**默认序列流**（isDefault="true"）；
- 适用场景：二选一/多选一的分支判断（如审批同意/拒绝、请假天数是否超过3天）；
- 配置示例：上文请假流程中的部门经理审批网关（核心）。

#### （2）并行网关（Parallel Gateway）

- 核心特点：**多分支同时执行**，**所有分支执行完成后聚合**；
- 执行规则：
  - 分支时：进入并行网关后，所有外出序列流**同时启动**，生成多个执行实例；
  - 聚合时：等待所有进入的序列流对应的执行实例**全部完成**后，流程继续执行；
- 适用场景：需要并行处理的任务（如请假流程中，部门经理审批和HR备案同时进行）；
- 配置示例：

  ```xml
  <!-- 并行网关（分支） -->
  <parallelGateway id="parallelGateway1" name="并行分支"/>
  <!-- 并行网关（聚合） -->
  <parallelGateway id="parallelGateway2" name="并行聚合"/>
  ```

#### （3）包容网关（Inclusive Gateway）

- 核心特点：**多分支可选执行**，**满足条件的分支都执行**，**所有执行的分支完成后聚合**；
- 执行规则：
  - 分支时：所有满足条件的外出序列流**同时启动**；
  - 聚合时：等待所有**启动的分支**执行完成后，流程继续执行；
- 适用场景：多条件可选的并行处理（如请假流程中，若请假天数>7天，需总经理审批+财务审批；若>3天，仅需总经理审批）；
- 配置：与排他网关类似，序列流配置条件表达式，无默认序列流。

#### （4）事件网关（Event-based Gateway）

- 核心特点：**基于事件的分支**，等待**第一个事件发生**后，执行对应的分支，其他分支自动取消；
- 适用场景：流程需要等待多个事件中的一个（如订单支付：等待微信支付成功或支付宝支付成功，其中一个发生后，另一个等待自动取消）；
- 配置：事件网关后必须跟**中间捕获事件**（如消息捕获、定时器捕获）。

### 4. 序列流（SequenceFlow）

代表流程节点之间的**流转关系**，用**带箭头的直线**表示，核心用于连接事件、活动、网关，分为**普通、条件、默认**三种类型，前文已详细讲解，核心注意：

1. 条件序列流仅在**网关后**或**任务后**生效；
2. 排他/包容网关必须配置**默认序列流**（防止所有条件都不满足导致流程卡死）；
3. 条件表达式支持**UEL表达式**（Flowable 默认），可调用流程变量、Spring Bean方法。

## 八、Flowable 高级特性（企业级开发必备）

基础流程仅能满足简单场景，企业级开发中需要处理**动态任务分配、流程监听、异步执行、会签、定时器**等复杂需求，Flowable 提供了丰富的高级特性，下文详解开发中高频使用的特性。

### 1. 流程监听器（Listener）

用于**监听流程/任务的生命周期事件**，在事件触发时执行自定义逻辑（如流程启动时发送通知、任务完成时更新业务状态），分为**执行监听器**和**任务监听器**，是实现流程与业务系统解耦的核心方式。

#### （1）执行监听器（Execution Listener）

- 监听对象：**流程实例/执行实例**的生命周期事件；
- 触发时机（核心）：
  - `start`：流程实例/执行实例**启动时**；
  - `end`：流程实例/执行实例**结束时**；
  - `take`：流程**流转时**（序列流触发时）；
- 配置位置：流程定义、活动、网关；
- 实现方式：Java类（实现`ExecutionListener`）、UEL表达式、脚本。

#### （2）任务监听器（Task Listener）

- 监听对象：**用户任务**的生命周期事件；
- 触发时机（核心）：
  - `create`：任务**创建时**（最常用，如任务创建时发送待办通知）；
  - `assign`：任务**分配人变更时**；
  - `complete`：任务**完成时**；
  - `delete`：任务**删除时**；
- 配置位置：仅能配置在**UserTask**上；
- 配置示例（BPMN中配置，任务创建时调用Spring Bean发送通知）：

  ```xml
  <userTask id="managerApproval" name="部门经理审批" flowable:candidateGroups="dept-manager">
      <extensionElements>
          <flowable:taskListener event="create" delegateExpression="${taskNotifyListener}"/>
      </extensionElements>
  </userTask>
  ```

- 实现类示例：

  ```java
  import org.flowable.task.service.delegate.DelegateTask;
  import org.flowable.task.service.delegate.TaskListener;
  import org.springframework.stereotype.Component;

  @Component("taskNotifyListener")
  public class TaskNotifyListener implements TaskListener {
      @Override
      public void notify(DelegateTask delegateTask) {
          // 获取任务信息
          String taskId = delegateTask.getId();
          String taskName = delegateTask.getName();
          String assignee = delegateTask.getAssignee();
          // 执行通知逻辑：发送短信、邮件、企业微信通知等
          System.out.println("任务创建通知：任务ID=" + taskId + "，任务名称=" + taskName + "，处理人=" + assignee);
      }
  }
  ```

### 2. 异步执行（Async）

Flowable 中**同步执行**会导致流程等待任务完成（如服务任务调用慢接口、复杂脚本执行），造成请求阻塞，**异步执行**可将耗时任务交给Flowable **作业执行器（JobExecutor）** 异步处理，提高系统性能和吞吐量。

#### 核心配置

在活动（ServiceTask、UserTask等）上添加**异步属性**，支持两种方式：

1. `flowable:asyncBefore="true"`：**执行活动前**异步处理（活动执行前加入作业队列）；
2. `flowable:asyncAfter="true"`：**执行活动后**异步处理（活动执行完成后加入作业队列）；

#### 配置示例

```xml
<!-- 服务任务异步执行，避免调用慢接口阻塞流程 -->
<serviceTask id="service1" name="调用第三方支付接口" 
             flowable:delegateExpression="${payService}"
             flowable:asyncBefore="true"/>
```

#### 核心原理

1. 配置异步的活动会被Flowable 封装为**作业（Job）**，存入数据库（ACT_RU_JOB表）；
2. Flowable 内置的**作业执行器（JobExecutor）** 是一个线程池，不断轮询Job表，取出作业并异步执行；
3. 作业执行失败会自动重试（可配置重试次数和间隔），保证任务最终执行。

### 3. 多实例任务（Multi-instance Task）

又称**会签任务**，用于处理**需要多个用户/组共同处理**的任务（如请假流程中，需要所有部门经理审批通过才算通过，或任意一个审批通过即可），支持**并行会签、串行会签、顺序会签**三种类型。

#### 核心配置属性（均为UEL表达式，引用流程变量）

- `flowable:collection`：参与会签的**用户/组集合**（如`${approvers}`，类型为List<String>）；
- `flowable:elementVariable`：集合中元素的**变量名**（如`${approver}`，代表单个处理人）；
- `flowable:multiInstanceType`：会签类型（`parallel`：并行，`sequential`：串行，默认并行）；
- `flowable:completionCondition`：完成条件（如`${nrOfCompletedInstances/nrOfInstances >= 0.5}`，表示50%以上审批通过即可完成）；
  - 内置变量：`nrOfInstances`（总实例数）、`nrOfCompletedInstances`（已完成数）、`nrOfActiveInstances`（未完成数）。

#### 配置示例（并行会签，所有审批人需全部通过）

```xml
<userTask id="multiApproval" name="多部门经理会签">
    <extensionElements>
        <flowable:multiInstanceLoopCharacteristics
                flowable:collection="${approvers}"
                flowable:elementVariable="approver"
                flowable:multiInstanceType="parallel">
            <!-- 完成条件：所有审批人完成 -->
            <completionCondition>${nrOfCompletedInstances == nrOfInstances}</completionCondition>
        </flowable:multiInstanceLoopCharacteristics>
    </extensionElements>
    <!-- 动态分配单个会签任务的处理人 -->
    <flowable:assignee="${approver}"/>
</userTask>
```

> 启动流程时，需设置流程变量`approvers`为用户ID集合：`variables.put("approvers", Arrays.asList("zhangsan", "lisi", "wangwu"))`。

### 4. 边界事件（Boundary Event）

绑定在**活动/网关**上的**中间事件**，用**圆形图标+虚线边框**表示，核心用于**处理流程中的异常、暂停、触发**等场景，分为**中断型**和**非中断型**（默认中断），开发中高频使用的边界事件如下：

#### （1）定时器边界事件（Timer Boundary Event）

- 用途：流程执行到绑定的活动时，**暂停并等待指定时间**，时间到后继续执行（或中断活动）；
- 适用场景：任务超时提醒、流程暂停审批、定时自动处理；
- 配置示例（任务创建后24小时未处理，自动执行超时逻辑）：

  ```xml
  <userTask id="managerApproval" name="部门经理审批" flowable:candidateGroups="dept-manager"/>
  <!-- 定时器边界事件：24小时后触发，中断原任务 -->
  <boundaryEvent id="timerBoundary" attachedToRef="managerApproval" cancelActivity="true">
      <timerEventDefinition>
          <timeDuration>PT24H</timeDuration> <!-- ISO 8601时间格式：PT24H=24小时，PT30M=30分钟 -->
      </timerEventDefinition>
  </boundaryEvent>
  <!-- 超时后执行的服务任务（自动拒绝） -->
  <serviceTask id="timeoutService" name="任务超时自动处理" flowable:delegateExpression="${timeoutHandler}"/>
  ```

#### （2）错误边界事件（Error Boundary Event）

- 用途：**捕获活动执行过程中的异常**，并跳转到指定的异常处理节点，避免流程卡死；
- 适用场景：服务任务调用接口失败、脚本任务执行出错时的异常处理；
- 配置：需要与**错误定义（Error Definition）** 配合，指定错误编码。

#### （3）信号边界事件（Signal Boundary Event）

- 用途：接收**全局信号**，触发流程分支（如取消审批、紧急提交流程）；
- 适用场景：流程暂停后，接收外部信号继续执行；或取消正在执行的任务。

### 5. 流程变量高级用法

流程变量是流程与业务系统交互的核心，除基础的全局/局部变量外，Flowable 还支持：

1. **变量序列化**：自定义POJO变量需实现`Serializable`接口，或配置Flowable 使用Jackson序列化（推荐，避免序列化问题）；
2. **变量作用域**：通过`execution.setVariableLocal()`/`task.setVariableLocal()`设置局部变量，仅当前执行实例/任务可见；
3. **变量类型**：支持`ByteArrayType`（二进制数据）、`DateType`（日期）、`ListType`（集合）等，可自定义变量类型；
4. **变量查询**：通过`RuntimeService`/`TaskService`/`HistoryService`的查询器，按变量值查询流程/任务（如查询“请假天数>3天”的流程实例）。

### 6. 流程挂起与激活、任务委派与转办

#### （1）流程挂起与激活

用于**暂停/恢复**流程实例的执行，挂起后流程无法继续处理任务，激活后恢复正常：

```java
// 挂起流程实例
runtimeService.suspendProcessInstanceById(processInstanceId);
// 激活流程实例
runtimeService.activateProcessInstanceById(processInstanceId);
// 挂起流程定义（所有该定义的流程实例均被挂起）
repositoryService.suspendProcessDefinitionByKey(processDefinitionKey);
```

#### （2）任务委派与转办

- 委派任务：将任务委派给其他用户处理，处理完成后任务**回到原处理人**手中（如经理将任务委派给助理处理，助理完成后经理需确认）；

  ```java
  taskService.delegateTask(taskId, delegateUserId);
  ```

- 任务转办：将任务直接转移给其他用户，原处理人失去任务处理权限（如经理将任务转交给其他经理审批）；

  ```java
  taskService.setAssignee(taskId, newUserId);
  ```

### 7. 历史级别配置（核心性能配置）

Flowable 支持4种**历史级别**，通过`flowable.process.history-level`配置，级别越高，记录的历史数据越详细，性能消耗也越大，需根据业务需求选择：

1. `none`：不记录任何历史数据（仅适用于测试环境）；
2. `activity`：记录流程实例、活动实例的开始/结束时间，不记录任务、变量；
3. `audit`（**默认/推荐**）：审计级别，记录流程实例、活动实例、任务实例、变量的核心信息，满足大部分企业的追溯需求；
4. `full`：全量级别，记录所有历史数据（包括流程流转的每一步、变量的修改记录），适用于对追溯要求极高的场景（如金融、风控），但性能消耗大。

> 生产环境建议使用`audit`级别，若需要更详细的历史数据，可通过**监听器**自定义记录，避免使用`full`级别导致历史表数据量过大。

## 九、Flowable UI 可视化工具（开发/运维必备）

Flowable 提供了一套**开箱即用的可视化UI平台**，包含流程设计、任务处理、后台管理、身份管理等功能，无需编码即可完成流程设计、部署、任务处理，极大提高开发和运维效率。

### 1. Flowable UI 核心模块

Flowable UI 分为4个独立模块，可单独部署也可集成在一起：

| 模块名称 | 核心功能 | 访问路径 |
|----------|----------|----------|
| Modeler | 流程设计器，**拖拽式**设计BPMN 2.0、CMMN、DMN模型，支持在线编辑、保存、导出 | /modeler |
| Task | 任务处理平台，供业务用户查询待办/已办任务、认领、完成、委派任务，查看流程进度 | /task |
| Admin | 后台管理平台，供运维人员部署流程、挂起/激活流程、管理作业、查看引擎状态 | /admin |
| IDM | 身份管理平台，供管理员管理用户、组、权限，配置UI平台的访问权限 | /idm |

### 2. Spring Boot 集成Flowable UI

#### （1）引入Maven依赖

```xml
<dependency>
    <groupId>org.flowable</groupId>
    <artifactId>flowable-ui-modeler-starter</artifactId>

</dependency>
<dependency>
    <groupId>org.flowable</groupId>

    <groupId>org.flowable</groupId>
    <artifactId>flowable-ui-idm-starter</artifactId>
    <version>7.0.1</version>

```

#### （2）配置application.yml

```yaml
flowable:
  ui:
    idm:
      admin:
        user: admin # 超级管理员账号
        password: test # 超级管理员密码
```

#### （3）启动项目并访问

项目启动后，访问`http://localhost:8080/flowable-ui`，使用账号`admin/test`登录，即可进入Flowable UI平台，核心操作：

1. 进入Modeler：设计请假流程，拖拽节点完成配置，保存并发布（自动部署到引擎）；
2. 进入IDM：创建用户（如zhangsan、lisi）、创建组（dept-manager），将用户加入组；
3. 进入Task：使用zhangsan账号登录，启动请假流程，填写流程变量；使用lisi账号（属于dept-manager组）登录，认领并完成审批任务。

## 十、Flowable 数据库表结构详解

Flowable 启动时会自动初始化**60+张数据库表**，所有表名均以**ACT_** 为前缀，按**模块/功能**分类，表名采用**ACT_<模块>_<表名>** 命名规则，核心分类如下，便于开发和运维时定位表结构：

### 1. 通用表（ACT_GE_*）

- GE = General（通用），用于存储所有模块共享的通用数据；
- 核心表：`ACT_GE_BYTEARRAY`（存储流程部署的资源文件，如BPMN XML、表单、附件）、`ACT_GE_PROPERTY`（引擎配置属性，如版本、主键生成策略）。

### 2. 流程引擎表（核心，ACT_RE_*/ACT_RU_*/ACT_HI_*）

按**流程生命周期**分为部署表、运行时表、历史表，是Flowable 最核心的表结构：

- RE = Repository（仓库）：存储**流程部署、流程定义**等静态数据（部署后不会修改）；
  核心表：`ACT_RE_PROCDEF`（流程定义表）、`ACT_RE_DEPLOYMENT`（部署表）；
- RU = Runtime（运行时）：存储**流程实例、任务、执行实例、变量**等动态数据，**流程/任务结束后会自动删除**，表数据量小，性能高；
  核心表：`ACT_RU_PROCINST`（流程实例表）、`ACT_RU_TASK`（任务表）、`ACT_RU_EXECUTION`（执行实例表）、`ACT_RU_VARIABLE`（运行时变量表）；
- HI = History（历史）：存储**流程运行的所有历史数据**，流程/任务结束后数据从运行时表移到此处，永久保存（可配置清理策略）；
  核心表：`ACT_HI_PROCINST`（历史流程实例表）、`ACT_HI_TASKINST`（历史任务表）、`ACT_HI_ACTINST`（历史活动实例表）、`ACT_HI_VARINST`（历史变量表）。

### 3. 身份管理表（ACT_ID_*）

- ID = Identity（身份），由IDM Engine管理，存储**用户、组、用户组关联、权限**等数据；
- 核心表：`ACT_ID_USER`（用户表）、`ACT_ID_GROUP`（组表）、`ACT_ID_MEMBERSHIP`（用户组关联表）、`ACT_ID_PRIV`（权限表）。

### 4. 其他模块表

- ACT_CM_*：CMMN引擎表（案例管理）；
- ACT_DM_*：DMN引擎表（决策模型）；
- ACT_CO_*：Content引擎表（内容/附件管理）；
- ACT_RU_JOB/ACT_RU_TIMER_JOB：运行时作业/定时器作业表（异步执行、定时器任务）。

## 十一、Flowable 集群部署（企业级生产必备）

单节点部署无法满足企业级应用的**高可用、高并发**需求，Flowable 支持分布式集群部署，核心原则是**共享数据库+统一作业执行器**，集群部署的核心要点如下：

### 1. 核心部署架构

- 多台应用服务器部署相同的Flowable 应用；
- 所有应用服务器**连接同一个数据库**（共享所有流程数据：部署、运行时、历史、作业）；
- 所有应用服务器的Flowable 配置**完全一致**（尤其是作业执行器、历史级别、异步配置）。

### 2. 关键配置要点

#### （1）作业执行器（JobExecutor）配置

作业执行器是集群中**异步任务、定时器任务**的核心，必须保证集群中**只有一个节点执行同一个作业**，避免重复执行：

```yaml
flowable:
  job-executor:
    enabled: true
    core-threads: 5 # 核心线程数
    max-threads: 20 # 最大线程数
    queue-capacity: 100 # 任务队列容量
    lock-time-in-millis: 300000 # 作业锁定时间（5分钟），避免节点宕机导致作业永久锁定
    wait-time-in-millis: 5000 # 轮询作业的间隔时间
```

> 核心原理：Flowable 作业执行器轮询作业表时，会通过**数据库行锁**锁定作业，其他节点无法获取已锁定的作业，保证作业唯一执行。

#### （2）禁用本地缓存

集群中若开启本地缓存，会导致各节点缓存不一致（如流程定义缓存、用户缓存），需禁用或配置分布式缓存：

```yaml
flowable:
  process:
    definition-cache-limit: 0 # 禁用流程定义本地缓存
  idm:
    cache:
      enabled: false # 禁用IDM本地缓存
```

> 若性能要求高，可集成**Redis/Ehcache**作为分布式缓存，缓存流程定义、用户等静态数据。

#### （3）数据库配置

- 数据库必须支持**行锁**（如MySQL InnoDB、Oracle），MyISAM不支持行锁，无法用于集群部署；
- 配置数据库**连接池最大连接数**，满足集群多节点的连接需求；
- 开启数据库**慢查询日志**，优化流程相关的SQL（如任务查询、流程实例查询）。

### 3. 集群部署注意事项

1. 所有节点的Flowable **版本必须一致**，避免版本兼容问题；
2. 流程部署操作**只需在一个节点执行**，部署后所有节点均可访问（因为流程定义存储在共享数据库）；
3. 避免在流程中使用**本地资源**（如本地文件、本地缓存），需使用分布式存储/缓存；
4. 对**高并发的任务查询**（如“我的待办任务”），可添加数据库索引（如ACT_RU_TASK的ASSIGNEE_、CANDIDATE_USER_ID_字段）；
5. 配置**历史数据清理策略**，避免历史表数据量过大，影响集群性能。

## 十二、Flowable 性能优化（高并发场景）

Flowable 性能的核心瓶颈在**数据库**（尤其是运行时表、作业表、历史表），高并发场景下需从**配置、数据库、代码**三个维度进行优化，核心优化策略如下：

### 1. 配置优化

1. 合理设置**历史级别**：优先使用`audit`级别，避免使用`full`级别；
2. 禁用不必要的**监听器/日志**：减少流程执行时的额外操作；
3. 调优**作业执行器**：根据业务场景调整线程池大小、轮询间隔，避免线程池阻塞；
4. 开启**流程定义缓存**：若禁用本地缓存，可使用分布式缓存缓存流程定义（静态数据，无需频繁刷新）。

### 2. 数据库优化

1. **添加索引**：对高频查询的字段添加索引（如ACT_RU_TASK的ASSIGNEE_、PROCESS_INSTANCE_ID_；ACT_HI_PROCINST的BUSINESS_KEY_）；
2. **分表分库**：对历史表（ACT_HI_*）进行**按时间分表**（如按月份拆分ACT_HI_TASKINST），因为历史表数据量会持续增长；
3. **数据库调优**：开启数据库查询缓存、优化连接池配置、调整InnoDB缓冲池大小；
4. **批量操作**：使用Flowable 提供的批量API（如批量完成任务、批量删除历史数据），减少数据库交互次数。

### 3. 代码优化

1. **减少查询范围**：任务/流程查询时，添加**分页、时间范围、业务主键**等条件，避免全表查询；
2. **使用异步执行**：将耗时的服务任务、脚本任务配置为异步执行，避免阻塞流程主线程；
3. **减少流程变量大小**：避免将大文件、大集合存入流程变量，大文件可通过Content Engine存储，仅将文件ID存入流程变量；
4. **避免频繁的流程部署**：流程定义是静态数据，频繁部署会增加数据库压力，建议一次性部署，通过版本管理实现流程迭代。

### 4. 历史数据管理

1. 配置**历史数据清理策略**：通过Flowable 的`HistoryService`或自定义定时任务，定期删除过期的历史数据；
2. 历史数据**归档**：将超过一定时间的历史数据归档到离线数据库，不影响在线业务的查询性能。
