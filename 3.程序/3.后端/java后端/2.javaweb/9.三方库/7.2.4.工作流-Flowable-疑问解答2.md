# 解答

问题: Flowable 怎么将实际业务关联，比如  请假审批，怎么关联到审批人，申请人，以及请假所需的部门等多表数据

你想知道在Flowable中如何将请假审批流程与业务系统的多表数据（申请人、审批人、部门等）深度关联，核心是解决「Flowable流程实例与业务表（用户表、部门表、请假申请表）脱节」的问题——这也是Flowable落地实际业务的核心环节，其核心思路是：**以「业务主键」为桥梁，通过流程变量传递业务数据ID，动态从业务表读取关联数据，而非让Flowable存储完整业务数据**。

下面我会从「架构设计」「分步实现（含完整代码）」「高级场景」「最佳实践」四个维度，结合请假审批场景详细讲解，确保流程与多表业务数据无缝绑定。

## 一、核心关联原理：Flowable与业务表的绑定逻辑

Flowable的定位是「流程状态管理器」，**不负责存储业务数据**（如申请人详情、部门信息、请假天数），仅通过以下两种方式关联业务数据：

### 1. 双向绑定核心：业务主键+流程实例ID

- **业务表→Flowable**：在业务表（如请假申请表）中新增字段 `process_instance_id`（VARCHAR(64)），存储Flowable流程实例ID，实现“通过请假单查流程状态”；
- **Flowable→业务表**：启动流程时，将业务表主键（如请假单ID `leave_id`）作为**流程变量**存入Flowable，实现“通过流程实例查请假单详情”。

### 2. 动态获取业务数据：流程变量传递ID，而非完整数据

- 申请人、审批人、部门等数据，仅将其**主键ID**（如`user_id`、`dept_id`、`manager_id`）作为流程变量传入Flowable；
- 当需要展示/使用这些数据时（如任务分配、审批通知、页面展示），通过ID从业务表（用户表、部门表）动态查询，避免Flowable存储冗余业务数据，也避免数据同步问题。

### 3. 核心表关系（以请假审批为例）

| 表类型       | 表名          | 核心字段                                                                 | 与Flowable的关联字段                |
|--------------|---------------|--------------------------------------------------------------------------|-------------------------------------|
| 业务核心表   | t_leave_apply | id（请假单主键）、apply_user_id（申请人ID）、dept_id（部门ID）、leave_days（天数）、process_instance_id（流程实例ID）、approval_status（审批状态） | process_instance_id → Flowable流程实例ID |
| 基础业务表   | t_sys_user    | id（用户ID）、username（姓名）、dept_id（所属部门）、mobile（手机号）     | apply_user_id/manager_id → 此表id   |
| 基础业务表   | t_sys_dept    | id（部门ID）、dept_name（部门名）、manager_id（部门经理ID）              | dept_id → 此表id；manager_id → t_sys_user.id |
| Flowable表   | ACT_RU_EXECUTION | id（流程实例ID）、proc_def_id（流程定义ID）、state_（运行状态）          | 与t_leave_apply.process_instance_id双向绑定 |
| Flowable表   | ACT_RU_VARIABLE | proc_inst_id（流程实例ID）、name_（变量名：leave_id/apply_user_id/dept_id）、value_（变量值：对应ID） | proc_inst_id → 流程实例ID；value_ → 业务表ID |

### 步骤3：Flowable流程设计（BPMN）

创建`leave-process.bpmn20.xml`（放入`src/main/resources/processes`），核心是**通过流程变量动态分配审批人**，而非硬编码：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<definitions xmlns="http://www.omg.org/spec/BPMN/20100524/MODEL"
             xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
             xmlns:flowable="http://flowable.org/bpmn"
             xsi:schemaLocation="http://www.omg.org/spec/BPMN/20100524/MODEL http://www.omg.org/spec/BPMN/2.0/20100501/BPMN20.xsd"
             id="Definitions_1"
             targetNamespace="http://flowable.org/processdef">

    <process id="leave-process" name="请假审批流程" isExecutable="true">
        <!-- 流程变量：leaveId（请假单ID）、applyUserId（申请人ID）、deptId（部门ID）、managerId（审批人ID） -->
        <startEvent id="startEvent1"/>

        <!-- 部门经理审批任务：通过流程变量${managerId}动态分配审批人 -->
        <userTask id="managerApprove" name="部门经理审批">
            <potentialOwner>
                <resourceAssignmentExpression>
                    <formalExpression>${managerId}</formalExpression>
                </resourceAssignmentExpression>
            </potentialOwner>
        </userTask>

        <!-- 排他网关：审批通过/拒绝分支 -->
        <exclusiveGateway id="approvalGateway" default="flowToEndRejected"/>

        <!-- 审批通过：更新业务状态为通过 -->
        <serviceTask id="updateApprovedStatus" name="更新审批状态（通过）" flowable:expression="${leaveBizService.updateLeaveStatus(leaveId, 'APPROVED')}"/>
        <!-- 审批拒绝：更新业务状态为拒绝 -->
        <serviceTask id="updateRejectedStatus" name="更新审批状态（拒绝）" flowable:expression="${leaveBizService.updateLeaveStatus(leaveId, 'REJECTED')}"/>

        <endEvent id="endEventApproved"/>
        <endEvent id="endEventRejected"/>

        <!-- 流程连线 -->
        <sequenceFlow id="flow1" sourceRef="startEvent1" targetRef="managerApprove"/>
        <sequenceFlow id="flow2" sourceRef="managerApprove" targetRef="approvalGateway"/>
        <!-- 审批通过条件：${approvalResult == 'approved'} -->
        <sequenceFlow id="flowToApproved" sourceRef="approvalGateway" targetRef="updateApprovedStatus">
            <conditionExpression xsi:type="tFormalExpression">${approvalResult == 'approved'}</conditionExpression>
        </sequenceFlow>
        <sequenceFlow id="flowToEndApproved" sourceRef="updateApprovedStatus" targetRef="endEventApproved"/>
        <!-- 审批拒绝（默认分支） -->
        <sequenceFlow id="flowToRejected" sourceRef="approvalGateway" targetRef="updateRejectedStatus">
            <conditionExpression xsi:type="tFormalExpression">${approvalResult == 'rejected'}</conditionExpression>
        </sequenceFlow>
        <sequenceFlow id="flowToEndRejected" sourceRef="updateRejectedStatus" targetRef="endEventRejected"/>
    </process>
</definitions>
```

### 步骤4：核心业务逻辑实现（关联Flowable与业务数据）

#### （1）请假业务Service（核心绑定逻辑）

```java
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.RuntimeService;
import org.flowable.engine.runtime.ProcessInstance;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.HashMap;
import java.util.Map;
import java.util.UUID;

@Service
@Slf4j
@RequiredArgsConstructor
public class LeaveBizService {
    // Flowable核心服务
    private final RuntimeService runtimeService;
    // 业务表服务
    private final LeaveApplyMapper leaveApplyMapper;
    private final SysOrgService sysOrgService;

    /**
     * 第一步：创建请假单 + 启动Flowable流程（核心绑定逻辑）
     */
    @Transactional(rollbackFor = Exception.class)
    public String createLeaveApplyAndStartFlow(LeaveApply leaveApply) {
        // 1. 生成请假单ID，保存业务数据
        String leaveId = UUID.randomUUID().toString().replace("-", "");
        leaveApply.setId(leaveId);
        leaveApply.setApprovalStatus("PENDING"); // 初始状态：待审批
        leaveApplyMapper.insert(leaveApply);
        log.info("创建请假单成功，请假单ID：{}", leaveId);

        // 2. 从业务表动态获取审批人（部门经理ID）
        String deptId = leaveApply.getDeptId();
        String managerId = sysOrgService.getDeptManagerId(deptId);
        log.info("获取部门{}的经理ID：{}", deptId, managerId);

        // 3. 构造Flowable流程变量（仅传递ID，不传递完整业务对象）
        Map<String, Object> variables = new HashMap<>();
        variables.put("leaveId", leaveId); // 绑定请假单ID（核心：Flowable→业务表）
        variables.put("applyUserId", leaveApply.getApplyUserId()); // 申请人ID
        variables.put("deptId", deptId); // 部门ID
        variables.put("managerId", managerId); // 审批人ID（动态分配任务）

        // 4. 启动Flowable流程实例
        ProcessInstance processInstance = runtimeService.startProcessInstanceByKey(
                "leave-process", // 流程定义Key
                variables // 流程变量
        );
        String processInstanceId = processInstance.getId();
        log.info("启动请假审批流程成功，流程实例ID：{}", processInstanceId);

        // 5. 更新请假单的流程实例ID（核心：业务表→Flowable）
        leaveApplyMapper.updateProcessInstanceId(leaveId, processInstanceId);
        log.info("绑定请假单{}与流程实例{}成功", leaveId, processInstanceId);

        return processInstanceId;
    }

    /**
     * 流程回调：更新请假单审批状态（BPMN中服务任务调用）
     */
    public void updateLeaveStatus(String leaveId, String approvalStatus) {
        leaveApplyMapper.updateApprovalStatus(leaveId, approvalStatus);
        log.info("更新请假单{}审批状态为：{}", leaveId, approvalStatus);
    }

    /**
     * 关联查询：通过流程实例ID查询请假单详情（Flowable→业务表）
     */
    public LeaveApply getLeaveApplyByProcessInstanceId(String processInstanceId) {
        // 先从Flowable获取leaveId变量
        String leaveId = (String) runtimeService.getVariable(processInstanceId, "leaveId");
        // 再通过leaveId查询业务表
        return leaveApplyMapper.selectById(leaveId);
    }
}
```

#### （2）完成审批任务（关联业务数据）

```java
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.flowable.engine.TaskService;
import org.flowable.task.api.Task;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.HashMap;
import java.util.Map;

@Service
@Slf4j
@RequiredArgsConstructor
public class LeaveTaskService {
    private final TaskService taskService;
    private final SysOrgService sysOrgService;
    private final LeaveBizService leaveBizService;

    /**
     * 第二步：查询审批人的待办任务（关联业务数据展示）
     */
    public Task getManagerTodoTask(String managerId) {
        return taskService.createTaskQuery()
                .taskAssignee(managerId)
                .processDefinitionKey("leave-process")
                .active()
                .singleResult();
    }

    /**
     * 第三步：完成审批任务（传递审批结果，触发流程后续逻辑）
     */
    @Transactional(rollbackFor = Exception.class)
    public void completeManagerApprove(String taskId, boolean approved) {
        // 1. 获取任务关联的流程实例ID
        Task task = taskService.createTaskQuery().taskId(taskId).singleResult();
        String processInstanceId = task.getProcessInstanceId();

        // 2. 构造审批结果变量（供网关判断）
        Map<String, Object> variables = new HashMap<>();
        variables.put("approvalResult", approved ? "approved" : "rejected");

        // 3. 完成Flowable任务（触发后续流程：更新业务状态）
        taskService.complete(taskId, variables);
        log.info("完成审批任务{}，流程实例{}，审批结果：{}", taskId, processInstanceId, approved ? "通过" : "拒绝");

        // （可选）关联查询业务数据，做后续操作（如发送通知）
        LeaveApply leaveApply = leaveBizService.getLeaveApplyByProcessInstanceId(processInstanceId);
        String applyUserName = sysOrgService.getUserById(leaveApply.getApplyUserId()).getRealName();
        log.info("申请人{}的{}天{}请假，审批结果：{}",
                applyUserName, leaveApply.getLeaveDays(), leaveApply.getLeaveType(), approved ? "通过" : "拒绝");
    }
}
```

## 三、高级场景：复杂业务关联处理

### 1. 动态多审批人（如多级审批、跨部门审批）

如果需要“申请人→部门经理→总监→HR”多级审批，或跨部门审批，核心是**从业务表/配置表读取审批人列表**，而非硬编码：

```java
// 从审批配置表获取多级审批人
List<String> approvalUserIds = approvalConfigService.getMultiApprovalUsers(deptId, leaveDays);
// 将审批人列表作为流程变量传入
variables.put("approvalUserIds", approvalUserIds);
// BPMN中使用多实例任务（会签）处理
```

### 2. 流程变量中关联多表数据（展示用）

如果需要在流程任务中展示多表关联数据（如申请人姓名、部门名称），**不建议将完整对象存为流程变量**（序列化易出问题），而是：

- 流程变量仅存ID；
- 查询任务时，通过ID关联查询多表数据，组装后返回给前端：

```java
// 查询待办任务时，关联多表数据
public Map<String, Object> getTaskWithBizData(String taskId) {
    Task task = taskService.createTaskQuery().taskId(taskId).singleResult();
    String leaveId = (String) runtimeService.getVariable(task.getProcessInstanceId(), "leaveId");
    LeaveApply leaveApply = leaveApplyMapper.selectById(leaveId);
    
    // 关联查询用户表、部门表
    SysUser applyUser = sysOrgService.getUserById(leaveApply.getApplyUserId());
    SysDept dept = sysOrgService.getDeptById(leaveApply.getDeptId());
    SysUser manager = sysOrgService.getUserById(dept.getManagerId());
    
    // 组装多表数据返回
    return Map.of(
            "taskId", taskId,
            "leaveApply", leaveApply,
            "applyUserName", applyUser.getRealName(),
            "applyUserMobile", applyUser.getMobile(),
            "deptName", dept.getDeptName(),
            "managerName", manager.getRealName()
    );
}
```

## 四、核心最佳实践（避坑指南）

### 1. 坚决不做：Flowable中存储完整业务对象

- 错误做法：将`LeaveApply`、`SysUser`等对象直接存为流程变量；
- 问题：序列化/反序列化易出错（类结构变更、版本升级），Flowable表冗余，性能下降；
- 正确做法：仅存业务ID（`leaveId`/`userId`/`deptId`），用时动态查询。

### 2. 事务一致性：流程操作与业务操作在同一事务

- 启动流程、创建业务数据、绑定流程实例ID，必须放在同一个`@Transactional`事务中；
- 避免“业务数据创建成功，但流程启动失败”导致数据不一致。

### 3. 拒绝硬编码：审批人/流程规则从业务表读取

- 错误做法：BPMN中硬编码审批人（如`formalExpression>user002</formalExpression>`）；
- 正确做法：从部门表、审批配置表动态读取审批人，支持业务规则灵活调整（如部门经理换人，无需修改BPMN）。

### 4. 双向绑定必须做：业务表存流程实例ID，流程存业务主键

- 缺失业务表的`process_instance_id`：无法通过请假单查流程状态；
- 缺失流程变量的`leaveId`：无法通过流程实例查请假单详情；
- 两者缺一不可，是关联的核心桥梁。

### 5. 流程结束后：清理无用的运行时数据（可选）

流程结束后，Flowable的`ACT_RU_*`表中对应数据会自动清理，仅保留`ACT_HI_*`历史数据，业务表无需清理，只需保证状态同步。

## 五、总结

Flowable关联多表业务数据的核心是**“ID为桥，变量为载体，双向绑定，动态查询”**，核心要点可总结为3点：

1. **绑定桥梁**：业务表新增`process_instance_id`关联Flowable流程实例ID，Flowable流程变量存储业务主键（如`leaveId`），实现双向查询；
2. **数据传递**：申请人、审批人、部门等多表数据，仅将ID作为流程变量传入Flowable，用于任务分配、网关判断，完整数据用时从业务表动态查询；
3. **状态同步**：流程关键节点（审批通过/拒绝）通过服务任务/监听器同步更新业务表状态，保证流程状态与业务状态一致。

这种方式既发挥了Flowable“管流程状态”的核心优势，又避免了Flowable与业务系统的耦合，是企业级落地Flowable的标准方案。
