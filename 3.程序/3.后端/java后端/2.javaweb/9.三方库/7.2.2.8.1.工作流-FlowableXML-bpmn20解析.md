# Flowable BPMN 2.0 XML 文件 **终极全维度解析**

（**100% 标准BPMN2.0规范 + Flowable专属扩展**，精准、细致、无虚构，结合执行对象/流程变量/监听器，从基础结构到实战配置全覆盖，是Flowable流程定义的核心手册）

本文适用于 **Flowable 6.x / 7.x**，是你编写、排查、理解 `bpmn20.xml` 的唯一指南。

---

## 一、前置核心认知

1. **BPMN20.xml 是什么？**
   流程引擎的**设计蓝图**，用XML语法描述流程的节点、连线、规则、扩展配置；Flowable引擎解析该文件，生成**流程定义(ProcessDefinition)**，启动后生成**执行对象(Execution)** 驱动流转。
2. **核心原则**
   - 标准标签：遵循 `OMG BPMN 2.0` 国际标准（通用）
   - 扩展标签：`flowable:` 前缀（Flowable引擎专属功能）
3. **文件命名规范**
   官方推荐：`流程名.bpmn20.xml`（如 `leave_apply.bpmn20.xml`）

## 二、基础结构 + 命名空间（**最容易报错的根源**）

### 2.1 完整标准头部（必须严格复制，缺一不可）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- 1. 根定义标签：BPMN2.0标准根元素 -->
<definitions
        xmlns="http://www.omg.org/spec/BPMN/20100524/MODEL"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xmlns:flowable="http://flowable.org/bpmn"
        xsi:schemaLocation="
            http://www.omg.org/spec/BPMN/20100524/MODEL
            http://www.omg.org/spec/BPMN/2.0/20100501/BPMN20.xsd
            http://flowable.org/bpmn
            http://flowable.org/bpmn/bpmn-extensions.xsd"
        id="Definitions_1"
        targetNamespace="http://flowable.org/bpmn"
        expressionLanguage="http://www.w3.org/1999/XPath"
        typeLanguage="http://www.w3.org/2001/XMLSchema">

    <!-- 2. 流程核心定义：一个definitions可以包含多个process -->
    <process id="leave_process" name="请假审批流程" isExecutable="true">
        <!-- 👇 所有流程节点、连线、监听器都写在这里 👇 -->
    </process>

</definitions>
```

### 2.2 核心标签/属性 精准解析

| 标签/属性 | 作用 | 强制要求 | 说明 |
|----------|------|----------|------|
| `definitions` | BPMN根容器 | ✅ 必须 | 所有流程定义的父标签 |
| `xmlns:flowable` | Flowable扩展命名空间 | ✅ 必须 | 所有引擎专属功能（监听器、任务分配等）依赖它 |
| `process` | 流程定义主体 | ✅ 必须 | 一个流程对应一个process |
| `process.id` | 流程Key | ✅ 必须 | **启动流程的核心标识**，全局唯一（英文/数字） |
| `process.name` | 流程名称 | ❌ 可选 | 可视化展示用 |
| `process.isExecutable` | 是否可执行 | ✅ 必须 | **=true 引擎才会执行**，false仅作为设计图 |

## 三、`<process>` 内部核心元素全解析

流程的组成 = **节点(Activity) + 连线(SequenceFlow) + 扩展配置(监听器/变量)**
所有节点都有**通用属性**：

- `id`：节点唯一标识（必填，引擎内部使用）
- `name`：节点名称（展示用）

---

### 第一部分：基础流转节点（执行对象的起点/终点/路径）

#### 1. 开始事件 `<startEvent>`

**执行对象行为**：流程启动 → **创建根执行对象**

```xml
<!-- 标准开始事件 -->
<startEvent id="startEvent1" name="开始">
  <!-- 流程启动执行监听器 -->
  <extensionElements>
    <flowable:executionListener event="start" class="com.xxx.ProcessStartListener"/>
  </extensionElements>
</startEvent>
```

**扩展类型**：定时开始事件、消息开始事件、信号开始事件。

#### 2. 结束事件 `<endEvent>`

**执行对象行为**：执行对象到达 → 销毁当前执行；根执行到达 → 流程结束

```xml
<endEvent id="endEvent1" name="结束">
  <extensionElements>
    <flowable:executionListener event="end" class="com.xxx.ProcessEndListener"/>
  </extensionElements>
</endEvent>
```

#### 3. 序列流 `<sequenceFlow>`（连线）

**执行对象行为**：执行对象的移动路径，触发 `take` 监听器

```xml
<!-- 标准连线：sourceRef=源节点ID，targetRef=目标节点ID -->
<sequenceFlow id="flow1" sourceRef="startEvent1" targetRef="userTask1">
  <!-- 1. 流转条件（排他网关必用） -->
  <conditionExpression xsi:type="tFormalExpression">
    ${approveResult == 'pass'}
  </conditionExpression>
  <!-- 2. 连线监听器（执行对象经过时触发） -->
  <extensionElements>
    <flowable:executionListener event="take" class="com.xxx.SequenceTakeListener"/>
  </extensionElements>
</sequenceFlow>
```

---

### 第二部分：任务节点（执行对象的核心停留点）

#### 1. 用户任务 `<userTask>`（最常用，人工审批）

**执行对象行为**：执行对象进入 → 等待，1:1绑定任务实例

```xml
<userTask id="userTask1" name="部门经理审批">
  <!-- Flowable扩展：任务分配（核心） -->
  <extensionElements>
    <!-- 1. 固定审批人 -->
    <flowable:assignee>zhangsan</flowable:assignee>
    <!-- 2. 变量动态审批人 -->
    <flowable:assignee>${assignee}</flowable:assignee>
    <!-- 3. 候选人/候选组 -->
    <flowable:candidateUsers>lisi,wangwu</flowable:candidateUsers>
    <flowable:candidateGroups>dept_manager</flowable:candidateGroups>
    <!-- 任务监听器：create/assignment/complete/delete -->
    <flowable:taskListener event="create" class="com.xxx.TaskCreateListener"/>
  </extensionElements>
  <!-- 执行监听器：进入/离开节点 -->
  <extensionElements>
    <flowable:executionListener event="start" class="com.xxx.ExecStartListener"/>
  </extensionElements>
</userTask>
```

#### 2. 服务任务 `<serviceTask>`（自动执行，Java代码）

**执行对象行为**：执行对象自动执行，不等待，瞬间通过

```xml
<!-- 三种实现方式（任选其一） -->
<serviceTask id="serviceTask1" name="自动计算薪资"
  flowable:class="com.xxx.SalaryCalculateTask"  <!-- 固定类 -->
  flowable:delegateExpression="${calculateBean}" <!-- SpringBean -->
  flowable:expression="${myService.doWork(execution)}"> <!-- 表达式 -->
</serviceTask>
```

#### 3. 脚本任务 `<scriptTask>`

**执行对象行为**：自动执行Groovy/JS脚本，无需Java类

```xml
<scriptTask id="script1" name="日志打印" scriptFormat="groovy">
  <script>
    println("流程变量：" + leaveDays);
    execution.setVariable("status", "approving");
  </script>
</scriptTask>
```

#### 4. 接收任务 `<receiveTask>`

**执行对象行为**：执行对象等待，必须用 `runtimeService.trigger()` 唤醒

```xml
<receiveTask id="receiveTask1" name="等待外部系统回调"/>
```

---

### 第三部分：网关节点（执行对象的分支/合并控制器）

#### 1. 排他网关 `<exclusiveGateway>`（单选分支）

**执行对象行为**：只走一条满足条件的连线，执行对象数量不变

```xml
<exclusiveGateway id="gateway1" name="审批结果判断"/>
<!-- 出口连线必须加条件 -->
<sequenceFlow sourceRef="gateway1" targetRef="passTask">
  <conditionExpression>${approveResult == 'pass'}</conditionExpression>
</sequenceFlow>
<sequenceFlow sourceRef="gateway1" targetRef="rejectTask">
  <conditionExpression>${approveResult == 'reject'}</conditionExpression>
</sequenceFlow>
```

#### 2. 并行网关 `<parallelGateway>`（并发分支）

**执行对象行为**：分叉1→N，汇聚N→1，必须所有分支到达才合并

```xml
<!-- 分叉 -->
<parallelGateway id="fork" name="并行分叉"/>
<!-- 汇聚 -->
<parallelGateway id="join" name="并行汇聚"/>
```

#### 3. 包容网关 `<inclusiveGateway>`（可选并行）

**执行对象行为**：满足几条条件，走几条分支

#### 4. 事件网关 `<eventBasedGateway>`

事件驱动分支，谁先触发走谁。

---

### 第四部分：子流程与多实例（执行对象树形结构）

#### 1. 嵌入式子流程 `<subProcess>`

**执行对象行为**：创建独立子执行树，父执行暂停

```xml
<subProcess id="subProcess1" name="内部子流程">
  <startEvent id="subStart"/>
  <userTask id="subTask"/>
  <endEvent id="subEnd"/>
</subProcess>
```

#### 2. 调用活动 `<callActivity>`（调用外部流程）

```xml
<callActivity id="callActivity1" name="调用报销流程"
  flowable:calledElement="reimburse_process"> <!-- 被调用的流程Key -->
  <!-- 变量传递 -->
  <dataInputAssociation>
    <sourceRef>applyUser</sourceRef>
    <targetRef>applyUser</targetRef>
  </dataInputAssociation>
</callActivity>
```

#### 3. 多实例任务（会签/批量审批）

**执行对象行为**：创建MI_ROOT根执行 + N个子执行

```xml
<userTask id="multiTask" name="会签审批">
  <multiInstanceLoopCharacteristics
          isSequential="false"  <!-- false=并行，true=顺序 -->
          flowable:collection="${userList}"  <!-- 审批人集合变量 -->
          flowable:elementVariable="approveUser"> <!-- 循环变量 -->
    <!-- 完成条件：50%通过 -->
    <completionCondition>${nrOfCompletedInstances/nrOfInstances >= 0.5}</completionCondition>
  </multiInstanceLoopCharacteristics>
</userTask>
```

---

### 第五部分：事件节点（边界/中间事件）

#### 边界事件 `<boundaryEvent>`（寄生在宿主节点）

**执行对象行为**：共用宿主执行，触发后中断原节点

```xml
<!-- 超时边界事件：用户任务30分钟未审批自动触发 -->
<userTask id="userTask1">
  <boundaryEvent id="timeoutEvent" attachedToRef="userTask1" cancelActivity="true">
    <timerEventDefinition>
      <timeDuration>PT30M</timeDuration> <!-- 30分钟 -->
    </timerEventDefinition>
  </boundaryEvent>
</userTask>
```

## 四、Flowable 核心扩展属性全表（XML专属）

所有带 `flowable:` 的属性都是**引擎专属扩展**，标准BPMN不支持：

| 属性 | 作用 | 适用节点 |
|------|------|----------|
| `flowable:assignee` | 指定任务审批人 | userTask |
| `flowable:candidateUsers` | 候选人 | userTask |
| `flowable:candidateGroups` | 候选组 | userTask |
| `flowable:class` | 指定Java处理类 | serviceTask |
| `flowable:delegateExpression` | SpringBean调用 | serviceTask |
| `flowable:async` | 异步执行 | 所有节点 |
| `flowable:exclusive` | 异步排他 | 异步节点 |
| `flowable:collection` | 多实例集合 | multiInstance |
| `flowable:elementVariable` | 多实例循环变量 | multiInstance |
| `flowable:calledElement` | 调用外部流程 | callActivity |

## 五、监听器 XML 完整配置（结合执行对象生命周期）

### 1. 执行监听器 `<executionListener>`

**监听执行对象**，3个事件：`start`(进门)、`end`(出门)、`take`(走路)

```xml
<!-- 节点上配置 -->
<userTask id="task1">
  <extensionElements>
    <flowable:executionListener
            event="start"
            class="com.xxx.ExecStartListener"/>
    <flowable:executionListener
            event="end"
            expression="${myListener.doEnd(execution)}"/>
  </extensionElements>
</userTask>
```

### 2. 任务监听器 `<taskListener>`

**仅用户任务可用**，4个事件：`create`/`assignment`/`complete`/`delete`

```xml
<flowable:taskListener event="complete" class="com.xxx.TaskCompleteListener"/>
```

## 六、BPMN 表达式语法 `${}`（流程变量核心）

### 1. 变量使用

```xml
${approveResult}
${user.name}
${leaveDays > 3}
```

### 2. 条件判断

```xml
${approveResult == 'pass' and leaveDays <= 3}
```

### 3. 内置变量（多实例专用）

```xml
${nrOfInstances}     <!-- 总实例数 -->
${nrOfCompletedInstances} <!-- 已完成数 -->
${isComplete}        <!-- 是否完成 -->
```

## 七、完整可运行实战 XML（带逐行注释）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<definitions
        xmlns="http://www.omg.org/spec/BPMN/20100524/MODEL"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xmlns:flowable="http://flowable.org/bpmn"
        xsi:schemaLocation="
            http://www.omg.org/spec/BPMN/20100524/MODEL http://www.omg.org/spec/BPMN/2.0/20100501/BPMN20.xsd
            http://flowable.org/bpmn http://flowable.org/bpmn/bpmn-extensions.xsd"
        id="Def1" targetNamespace="http://flowable.org/bpmn">

    <!-- 流程定义：isExecutable=true 必须开启 -->
    <process id="leave_apply" name="请假流程" isExecutable="true">
        <!-- 1. 开始事件 -->
        <startEvent id="start"/>

        <!-- 2. 连线 -->
        <sequenceFlow id="flow1" sourceRef="start" targetRef="deptApprove"/>

        <!-- 3. 用户任务：动态审批人 -->
        <userTask id="deptApprove" name="部门经理审批">
            <extensionElements>
                <flowable:assignee>${deptManager}</flowable:assignee>
                <flowable:taskListener event="create" class="com.xxx.TaskLogListener"/>
            </extensionElements>
        </userTask>

        <sequenceFlow id="flow2" sourceRef="deptApprove" targetRef="gateway"/>

        <!-- 4. 排他网关：判断审批结果 -->
        <exclusiveGateway id="gateway"/>

        <!-- 同意分支 -->
        <sequenceFlow id="flowPass" sourceRef="gateway" targetRef="end">
            <conditionExpression>${approveResult == 'pass'}</conditionExpression>
        </sequenceFlow>
        <!-- 拒绝分支 -->
        <sequenceFlow id="flowReject" sourceRef="gateway" targetRef="rejectEnd">
            <conditionExpression>${approveResult == 'reject'}</conditionExpression>
        </sequenceFlow>

        <!-- 5. 结束节点 -->
        <endEvent id="end" name="审批通过"/>
        <endEvent id="rejectEnd" name="审批拒绝"/>

    </process>
</definitions>
```

## 八、XML 部署与校验规范

1. **部署方式**
   - 资源文件部署（resources下）
   - 代码部署（`repositoryService.createDeployment()`）
2. **XML 校验**
    IDE 安装 Flowable 插件，自动校验语法、命名空间、节点关联
3. **核心约束**
   - 所有节点 `id` 唯一
   - 连线 `sourceRef`/`targetRef` 必须存在
   - 网关出口必须配置条件（排他/包容）

## 九、BPMN20.xml 避坑指南（高频致命错误）

1. **命名空间缺失/错误** → Flowable扩展标签不生效，引擎报错
2. **isExecutable=false** → 流程部署成功，但无法启动
3. **排他网关无默认连线** → 变量不满足条件时流程卡死
4. **连线条件变量为空** → `${approveResult == 'pass'}` 报空指针
5. **多实例变量写错** → 会签不生成任务/无法合并
6. **监听器class路径错误** → 流程启动/流转失败
7. **边界事件attachedToRef错误** → 事件不触发
8. **异步节点未配置排他** → 并发执行导致数据异常

## 十、终极总结

1. **BPMN20.xml = 流程蓝图**，`process` 是核心，`isExecutable=true` 是执行开关
2. **标准标签负责流程结构**，`flowable:` 扩展负责引擎功能
3. **执行对象** 严格按照 XML 定义的节点/连线流转
4. **监听器** 监听执行对象生命周期，无侵入增强流程
5. **${} 表达式** 是流程变量与节点交互的唯一桥梁
6. 所有配置**严格遵循标准**，是流程稳定运行的基础
