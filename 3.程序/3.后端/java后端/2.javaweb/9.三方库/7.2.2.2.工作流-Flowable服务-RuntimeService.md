# Flowable RuntimeService 全API清单（作用+注意事项+避坑）

`RuntimeService`是Flowable**流程运行时核心服务**，核心负责**流程实例的全生命周期管理、流程变量操作、执行流控制、信号/消息/事件触发、作业与定时器管理**等动态运行时操作，所有操作围绕Flowable**运行时表（`ACT_RU_*`）**展开，与`RepositoryService`（静态资源）、`TaskService`（任务管理）共同构成Flowable核心服务体系，是流程运行阶段的最核心API。

以下基于**Flowable 6.8.0**（稳定版，兼容JDK8+）整理，完全沿用`RepositoryService`的说明格式，**按功能分类**列出核心API，包含**方法名、重载说明、核心作用、注意事项/避坑**，重点标注实战高频API和易踩坑点，纯原生API无封装，同时明确与其他服务的功能边界。

> 通用前置：所有API均通过`ProcessEngine.getRuntimeService()`获取实例，Spring Boot中直接`@Autowired`注入即可，流程引擎为**全局唯一重量级对象**，禁止重复创建。
>
> ```java
> // 纯Java工程
> RuntimeService runtimeService = ProcessEngines.getDefaultProcessEngine().getRuntimeService();
> // Spring Boot工程
> @Autowired
> private RuntimeService runtimeService;
> ```
>
> 核心边界：`RuntimeService`**不负责任务节点的具体操作**（如认领、完成任务，由`TaskService`处理），仅负责流程实例的整体运行和节点间的流转控制。

## 一、流程实例（ProcessInstance）管理API（实战最高频）

流程实例是**流程定义的一次具体运行实例**（对应BPMN的`process`标签），核心操作`ACT_RU_EXECUTION`（执行流表，流程实例为根执行流）、`ACT_RU_PROCINST`（流程实例表），是`RuntimeService`最核心的功能模块，所有流程运行均从启动流程实例开始。

### 1. 启动流程实例（核心重载，6个常用）

流程实例启动有**按流程Key**（推荐，自动用最新激活版本）、**按流程定义ID**（指定版本）两大类，支持带**流程变量**、**业务键（businessKey）**启动，`businessKey`是**流程实例与业务系统关联的核心字段**（如订单ID、请假单ID），推荐所有场景都设置。

```java
// 1. 按流程Key启动（最新激活版本，无变量，无业务键）
ProcessInstance startProcessInstanceByKey(String processKey);

// 2. 按流程Key启动 + 业务键（最常用基础版，无变量）
ProcessInstance startProcessInstanceByKey(String processKey, String businessKey);

// 3. 按流程Key启动 + 流程变量（Map封装，无业务键）
ProcessInstance startProcessInstanceByKey(String processKey, Map<String, Object> variables);

// 4. 按流程Key启动 + 业务键 + 流程变量（实战首选，全覆盖）
ProcessInstance startProcessInstanceByKey(String processKey, String businessKey, Map<String, Object> variables);

// 5. 按流程定义ID启动（指定版本，精准控制，无变量）
ProcessInstance startProcessInstanceById(String processDefId);

// 6. 按流程定义ID启动 + 业务键 + 变量（指定版本+全覆盖）
ProcessInstance startProcessInstanceById(String processDefId, String businessKey, Map<String, Object> variables);
```

- **作用**：根据流程Key/流程定义ID，启动一个新的流程实例，生成运行时数据（`ACT_RU_PROCINST`/`ACT_RU_EXECUTION`），流程进入第一个节点（如开始事件→用户任务/服务任务）。
- **返回值**：`ProcessInstance`实体，包含流程实例ID、流程定义ID、业务键、是否结束等核心信息，**流程实例ID是后续所有运行时操作的核心标识**。
- **注意事项/避坑**：
  1. **核心坑点**：按流程Key启动时，只会使用**该Key下最新的「激活状态」流程定义**，若最新版本被挂起（`RepositoryService`挂起），会直接抛`FlowableException`，启动前建议先通过`RepositoryService`校验流程定义状态；
  2. **businessKey规范**：建议设置为**业务系统的唯一主键**（如订单ID：`order_1001`），便于流程实例与业务数据关联查询，**一旦设置不可修改**；
  3. 流程变量：启动时传入的变量为**全局流程变量**，作用域覆盖整个流程实例，变量类型建议用基础类型（String/Integer/Date等），避免自定义对象（序列化风险）；
  4. 流程定义ID格式：`流程Key:版本号:随机ID`（如`leaveProcess:1:4`），指定版本启动时必须用完整ID；
  5. 启动失败场景：流程定义不存在、流程定义被挂起、BPMN模型有执行错误（如网关条件无效），均会抛异常，需捕获并记录日志。

### 2. 流程实例查询

```java
ProcessInstanceQuery createProcessInstanceQuery();
```

- **作用**：创建流程实例查询器`ProcessInstanceQuery`，用于多条件查询**运行中**的流程实例（`ACT_RU_PROCINST`），支持分页、排序、多条件筛选，是流程监控、业务关联查询的必用API。
- **ProcessInstanceQuery 核心筛选/执行方法**（链式调用，最终用`list()`/`singleResult()`/`count()`执行）：

  | 方法 | 核心作用 | 实战说明 |
  |------|----------|----------|
  | `processInstanceId(String instanceId)` | 按流程实例ID精确查询 | 最常用，根据运行时标识查询 |
  | `processDefinitionKey(String processKey)` | 按流程Key查询 | 查某类流程的所有运行实例 |
  | `processDefinitionId(String processDefId)` | 按流程定义ID查询 | 查指定版本的运行实例 |
  | `businessKey(String businessKey)` | 按业务键精确查询 | **业务系统核心**，关联业务主键查流程 |
  | `businessKeyLike(String businessKeyLike)` | 按业务键模糊查询 | 如`%order_%`查所有订单流程 |
  | `tenantId(String tenantId)` | 按多租户ID查询 | 多租户场景必用 |
  | `suspended()` | 仅查询**挂起状态**的流程实例 | 区分运行/挂起实例 |
  | `active()` | 仅查询**激活状态**的流程实例 | 实战默认筛选，避免查挂起实例 |
  | `orderByProcessInstanceId()` | 按流程实例ID排序 | 可搭配`asc()`/`desc()` |
  | `orderByStartTimeDesc()` | 按启动时间倒序排序 | 最新启动的实例在前，监控常用 |
  | `page(int firstResult, int maxResults)` | 分页查询 | 大量运行实例时使用，避免内存溢出 |
  | `singleResult()` | 查询单个实例 | 无结果/多结果抛异常，需谨慎使用 |

### 3. 流程实例挂起/激活（2组核心重载）

流程实例默认**激活状态**（正常执行），挂起后**暂停所有执行动作**（如定时器不触发、任务无法完成、网关不流转），已分配的任务仍存在但无法操作；激活后恢复正常执行，支持按**流程实例ID**/**流程Key**/**流程定义ID**操作，核心重载如下：

```java
// 按流程实例ID挂起/激活【单个实例，实战首选】
void suspendProcessInstanceById(String instanceId);
void activateProcessInstanceById(String instanceId);

// 按流程Key挂起/激活【该Key下所有运行实例】
void suspendProcessInstancesByProcessDefinitionKey(String processKey);
void activateProcessInstancesByProcessDefinitionKey(String processKey);
```

- **作用**：暂停/恢复指定流程实例的运行，适用于流程异常、业务暂停（如订单取消）时临时终止流程执行。
- **注意事项/避坑**：
  1. **核心区别**：与`RepositoryService`的流程定义挂起/激活完全不同——**定义挂起**是禁止启动**新实例**，已运行实例不受影响；**实例挂起**是暂停**单个/多个运行中实例**，流程定义仍可启动新实例；
  2. **坑点**：`byProcessDefinitionKey`方法会**挂起/激活该Key下所有运行实例**，生产环境禁止随意使用，避免误暂停核心业务流程；
  3. 状态标识：挂起/激活会修改`ACT_RU_PROCINST`和`ACT_RU_EXECUTION`的`SUSPENSION_STATE_`字段（1=激活，2=挂起）；
  4. 挂起后影响：定时器作业会被暂停、信号/消息无法触发、任务完成时抛`FlowableException`，必须激活后才能继续操作。

### 4. 删除流程实例（2个重载）

```java
// 基础删除，带删除原因
void deleteProcessInstance(String instanceId, String deleteReason);
// 级联删除，带删除原因（Flowable 6.5+）
void deleteProcessInstance(String instanceId, String deleteReason, boolean cascade);
```

- **作用**：删除**运行中**的流程实例，清理运行时数据，适用于流程异常、业务取消时的手动清理，**生产环境谨慎使用**。
  1. 基础删除：删除`ACT_RU_*`所有运行时数据（实例、执行流、变量、作业等），**保留历史数据**（`ACT_HI_*`），可在历史表中查询删除原因；
  2. 级联删除：删除运行时数据+**关联的历史数据**，彻底清除该实例的所有记录。
- **注意事项/避坑**：
  1. **核心坑点**：删除已结束的流程实例会抛异常，需先通过`processInstanceQuery()`校验实例是否为运行中（`active()`）；
  2. 生产环境**禁止使用级联删除**，历史数据是流程审计的重要依据，仅在特殊场景（如测试数据清理）使用；
  3. 删除原因：建议填写清晰的业务原因（如`订单取消，流程终止`），会存入`ACT_HI_PROCINST`的`DELETE_REASON_`字段，便于后续追溯；
  4. 事务一致性：删除操作建议放在事务中，避免部分运行时数据被删除导致脏数据。

### 5. 检查流程实例状态

```java
// 判断流程实例是否为挂起状态
boolean isProcessInstanceSuspended(String instanceId);
// 判断流程实例是否存在（运行中）
boolean processInstanceExists(String instanceId);
```

- **作用**：前置校验API，避免操作不存在/已挂起的流程实例抛异常，建议在**挂起/激活/删除/设置变量**前执行校验。
- **注意事项**：`processInstanceExists()`仅判断**运行中**的实例（`ACT_RU_PROCINST`），已结束/已删除的实例会返回`false`。

### 6. 获取流程实例详情

```java
ProcessInstance getProcessInstance(String instanceId);
```

- **作用**：根据流程实例ID，获取运行中流程实例的完整实体`ProcessInstance`，包含实例ID、流程定义ID、业务键、启动时间、挂起状态等所有信息。
- **注意事项**：仅能获取**运行中**的实例，已结束/已删除的实例调用会返回`null`，需先通过`processInstanceExists()`校验。

## 二、流程变量（Process Variable）管理API（实战高频）

流程变量是Flowable流程运行的**动态数据载体**，用于存储流程运行过程中的业务数据（如请假人、请假天数、审批意见），支持**全局作用域**（流程实例级别）和**局部作用域**（执行流/任务级别），`RuntimeService`主要负责**全局变量**和**执行流局部变量**的管理（任务局部变量由`TaskService`管理），核心操作`ACT_RU_VARIABLE`（运行时变量表）。

### 1. 设置流程变量（全局+局部，核心重载）

#### （1）设置**全局流程变量**（作用域：整个流程实例，所有节点/执行流均可访问）

```java
// 设置单个全局变量
void setVariable(String instanceId, String varName, Object varValue);
// 批量设置全局变量（Map封装，推荐）
void setVariables(String instanceId, Map<String, Object> variables);
```

#### （2）设置**执行流局部变量**（作用域：指定执行流，仅该执行流及子执行流可访问）

```java
// 设置单个执行流局部变量
void setVariableLocal(String executionId, String varName, Object varValue);
// 批量设置执行流局部变量
void setVariablesLocal(String executionId, Map<String, Object> variables);
```

- **作用**：向运行中的流程实例/执行流中添加/修改变量，变量会持久化到`ACT_RU_VARIABLE`，流程节点（如网关条件、任务分配）可通过EL表达式引用（如`${leaveDays > 3}`）。
- **注意事项/避坑**：
  1. **作用域优先级**：局部变量（执行流/任务）优先级高于全局变量，同名变量局部会覆盖全局；
  2. **变量类型规范**：**推荐仅使用基础类型**（String/Integer/Long/Date/Boolean）和简单集合（List/Map，元素为基础类型），**禁止使用自定义对象**——自定义对象会通过Java序列化存储，存在版本兼容、序列化失败的风险，若需传递复杂数据，可序列化为JSON字符串（String类型）；
  3. **实例/执行流校验**：操作前必须校验流程实例/执行流是否存在且为激活状态，否则抛异常；
  4. **变量名规范**：使用英文小写+下划线（如`leave_user_id`），避免中文/特殊字符，防止EL表达式解析失败；
  5. 执行流ID：可通过`ProcessInstance.getExecutionId()`获取根执行流ID（流程实例与根执行流ID一致），子执行流ID需通过`ExecutionQuery`查询。

### 2. 获取流程变量（全局+局部，核心重载）

#### （1）获取**全局流程变量**

```java
// 获取单个全局变量，指定返回类型
<T> T getVariable(String instanceId, String varName, Class<T> varType);
// 获取单个全局变量，返回Object
Object getVariable(String instanceId, String varName);
// 获取所有全局变量，返回Map
Map<String, Object> getVariables(String instanceId);
// 批量获取指定名称的全局变量
Map<String, Object> getVariables(String instanceId, Collection<String> varNames);
```

#### （2）获取**执行流局部变量**

```java
// 获取单个执行流局部变量，指定返回类型
<T> T getVariableLocal(String executionId, String varName, Class<T> varType);
// 获取所有执行流局部变量，返回Map
Map<String, Object> getVariablesLocal(String executionId);
```

- **作用**：从运行中的流程实例/执行流中读取变量，是流程节点获取业务数据的核心方式。
- **注意事项/避坑**：
  1. 指定返回类型时，需保证变量实际类型与指定类型一致，否则抛`ClassCastException`；
  2. 获取不存在的变量名会返回`null`，建议做非空判断；
  3. 读取大量变量时，使用`getVariables(instanceId, varNames)`批量获取，减少数据库查询次数。

### 3. 删除流程变量（全局+局部）

```java
// 删除单个全局变量
void removeVariable(String instanceId, String varName);
// 批量删除全局变量
void removeVariables(String instanceId, Collection<String> varNames);
// 删除单个执行流局部变量
void removeVariableLocal(String executionId, String varName);
// 批量删除执行流局部变量
void removeVariablesLocal(String executionId, Collection<String> varNames);
```

- **作用**：删除流程实例/执行流中的指定变量，适用于流程节点执行完成后清理无用数据。
- **注意事项**：删除不存在的变量名**不会抛异常**，可直接调用；删除后变量从`ACT_RU_VARIABLE`中永久移除，无法恢复。

### 4. 检查变量是否存在

```java
// 检查全局变量是否存在
boolean hasVariable(String instanceId, String varName);
// 检查执行流局部变量是否存在
boolean hasVariableLocal(String executionId, String varName);
```

- **作用**：前置校验API，避免获取/删除不存在的变量时出现`null`或无意义操作，建议在变量操作前执行。

## 三、执行流（Execution）管理API（实战常用）

执行流`Execution`是Flowable**流程运行的最小执行单元**，代表流程实例的一次具体执行路径：**单个流程实例对应一个根执行流**（根执行流ID与流程实例ID一致），当流程包含**并行网关、多实例任务、子流程**时，会生成**子执行流**，多个执行流并行执行，核心操作`ACT_RU_EXECUTION`（执行流表）。

### 1. 执行流查询

```java
ExecutionQuery createExecutionQuery();
```

- **作用**：创建执行流查询器`ExecutionQuery`，用于查询运行中的执行流（根执行流+子执行流），适用于**并行流程、子流程**的精准控制（如触发子执行流的信号、设置子执行流局部变量）。
- **ExecutionQuery 核心筛选方法**：
  - `executionId(String executionId)`：按执行流ID精确查询；
  - `processInstanceId(String instanceId)`：按流程实例ID查询（查该实例下所有执行流）；
  - `processDefinitionKey(String processKey)`：按流程Key查询；
  - `activityId(String activityId)`：按**当前活动节点ID**查询（如查所有停在「经理审批」节点的执行流，activityId为BPMN中节点ID）；
  - `suspended()`/`active()`：按挂起/激活状态筛选。

### 2. 触发执行流继续执行

```java
// 触发指定执行流执行下一个节点
void signal(String executionId);
// 触发执行流并传入临时变量（仅本次执行有效）
void signal(String executionId, Map<String, Object> variables);
// 触发执行流，指定信号名称+变量（配合BPMN信号捕获事件）
void signal(String executionId, String signalName, Map<String, Object> variables);
```

- **作用**：手动触发执行流继续流转，适用于**等待状态的执行流**（如信号捕获事件、消息捕获事件、人工等待节点），触发后执行流会按BPMN模型执行下一个节点。
- **注意事项/避坑**：
  1. 仅能触发**处于等待状态**的执行流，若执行流正在执行节点（如服务任务），调用会抛异常；
  2. 临时变量：`signal(executionId, variables)`传入的变量为**本次执行临时变量**，执行完成后不会持久化到`ACT_RU_VARIABLE`，若需持久化需提前用`setVariable`设置；
  3. 信号名称：需与BPMN中**信号捕获事件**的信号名称完全一致，否则信号无法被识别。

### 3. 获取流程实例的根执行流ID

```java
String getExecutionIdForProcessInstance(String instanceId);
```

- **作用**：根据流程实例ID，获取其根执行流ID（流程实例与根执行流ID一致，该方法主要为兼容低版本）。
- **注意事项**：可直接通过`ProcessInstance.getExecutionId()`获取，无需额外调用该方法。

## 四、信号/消息/事件触发API（Flowable核心特性）

Flowable支持**信号（Signal）、消息（Message）、定时器（Timer）**等事件机制，是实现流程异步执行、跨实例通信、定时触发的核心，`RuntimeService`负责**信号广播、消息发送、事件触发**，配合BPMN中的「信号捕获事件、消息捕获事件、定时器事件」使用，实战中常用于**并行流程同步、跨流程通信、定时任务触发**（如请假超时提醒）。

### 1. 信号（Signal）广播（跨实例通信）

信号是**广播机制**，发送信号后，**所有匹配该信号名称的运行中执行流**（绑定了信号捕获事件）都会被触发，支持全局广播和按租户ID广播：

```java
// 全局广播信号，所有租户均可接收
void signalEventReceived(String signalName);
// 广播信号并传入变量，所有匹配执行流接收
void signalEventReceived(String signalName, Map<String, Object> variables);
// 按租户ID广播信号，仅指定租户的执行流接收
void signalEventReceived(String signalName, String tenantId);
```

- **作用**：触发BPMN中的**信号捕获事件**，实现跨流程实例、跨执行流的通信，如「订单支付成功」信号广播，触发所有待支付的订单流程继续执行。
- **注意事项/避坑**：
  1. 信号名称：需与BPMN中**信号捕获事件**的`signalRef`属性**完全一致**，区分大小写；
  2. **广播风险**：全局信号会触发**所有**匹配的执行流，若流程实例数量大，会造成数据库压力陡增，生产环境需控制信号使用场景，避免大范围广播；
  3. 变量传递：传入的变量为**临时变量**，仅在信号触发的本次执行中有效，若需持久化需在流程节点中手动保存。

### 2. 消息（Message）发送（点对点通信）

消息是**点对点/定向机制**，发送消息时需指定**流程实例/执行流**，仅目标执行流会被触发，适用于**单个流程实例的精准触发**，与信号的广播机制形成互补：

```java
// 向指定执行流发送消息，指定消息名称
void messageEventReceived(String messageName, String executionId);
// 向指定执行流发送消息并传入变量
void messageEventReceived(String messageName, String executionId, Map<String, Object> variables);
```

- **作用**：触发BPMN中的**消息捕获事件**，实现单个流程实例的精准触发，如「单个订单支付成功」消息，仅触发该订单的流程实例。
- **注意事项/避坑**：
  1. 消息名称：需与BPMN中**消息捕获事件**的`messageRef`属性完全一致；
  2. 执行流校验：目标执行流必须绑定了对应的消息捕获事件，且处于等待状态，否则消息会被忽略，无任何执行动作；
  3. 与信号的区别：**消息是定向的，信号是广播的**，根据业务场景选择——跨实例通信用信号，单个实例触发用消息。

### 3. 触发定时器事件（手动触发）

BPMN中的**定时器捕获事件**会由Flowable的作业调度器自动触发，若需**手动提前触发**定时器，可通过以下API：

```java
// 手动触发指定执行流的定时器事件
void trigger(String executionId);
// 手动触发并传入变量
void trigger(String executionId, Map<String, Object> variables);
```

- **作用**：提前触发执行流上的定时器事件，适用于业务需要提前执行的场景（如请假流程提前审批，手动触发超时提醒定时器）。
- **注意事项**：仅能触发**处于等待状态**的定时器事件，若定时器已被触发/已过期，调用无效果。

## 五、作业与定时器管理API（底层支撑，实战按需使用）

Flowable中的**定时器、异步任务、邮件任务**等均会被封装为**作业（Job）**，由Flowable的**作业调度器（JobExecutor）**异步执行，`RuntimeService`负责作业的暂停、恢复、执行、删除，核心操作`ACT_RU_JOB`（作业表）、`ACT_RU_TIMER_JOB`（定时器作业表），适用于流程定时任务的监控和手动干预。

### 1. 作业查询

```java
// 查询普通作业（异步任务、邮件任务等）
JobQuery createJobQuery();
// 查询定时器作业（定时器事件、定时边界事件等）
TimerJobQuery createTimerJobQuery();
// 查询暂停的作业
SuspendedJobQuery createSuspendedJobQuery();
```

- **作用**：查询运行中的作业/定时器作业，适用于定时任务监控（如查询所有未触发的请假超时提醒定时器）。

### 2. 作业暂停/恢复

```java
// 暂停指定作业
void suspendJob(String jobId);
// 恢复指定作业
void activateJob(String jobId);
// 批量暂停流程实例下的所有作业
void suspendJobsByProcessInstanceId(String instanceId);
// 批量恢复流程实例下的所有作业
void activateJobsByProcessInstanceId(String instanceId);
```

- **作用**：暂停/恢复作业的执行，适用于流程实例挂起时同步暂停定时器，避免流程暂停后定时器仍被触发。
- **注意事项**：流程实例挂起时，Flowable会**自动暂停**其下所有作业，激活时自动恢复，无需手动调用。

### 3. 手动执行作业

```java
// 手动执行指定作业（忽略定时器时间，立即执行）
void executeJob(String jobId);
```

- **作用**：手动触发作业执行，适用于定时器未自动触发（如作业调度器异常）时的手动干预。
- **注意事项**：仅能执行**激活状态**的作业，暂停/已执行的作业调用会抛异常。

### 4. 删除作业

```java
// 删除指定作业
void deleteJob(String jobId);
// 批量删除流程实例下的所有作业
void deleteJobsByProcessInstanceId(String instanceId);
```

- **作用**：删除无用的作业，适用于流程实例删除/挂起时清理定时器作业。
- **注意事项**：流程实例删除时，Flowable会**自动删除**其下所有作业，无需手动调用。

## 六、通用工具API（实战辅助，少用）

主要用于Flowable运行时的底层配置获取、缓存管理，一般无需手动调用，引擎会自动处理，仅在特殊场景（如动态修改流程后清缓存）使用。

```java
// 获取流程引擎配置
ProcessEngineConfiguration getProcessEngineConfiguration();
// 清除运行时缓存（流程实例、执行流、变量等）
void clearCache();
// 获取流程实例的当前活动节点ID列表（如[startEvent, applyTask]）
List<String> getActiveActivityIds(String executionId);
```

- **核心实用API**：`getActiveActivityIds(executionId)`——查询指定执行流当前停留的节点ID，适用于流程监控（如查某流程实例当前处于哪个审批节点）。

## 七、RuntimeService 通用避坑原则（所有API通用）

结合实战经验，整理`RuntimeService`所有操作的核心避坑点，**必须严格遵守**，否则会导致流程启动失败、运行异常、数据不一致、性能问题等严重后果：

### 1. 流程实例：强制绑定业务键，避免孤立实例

启动流程实例时，**必须设置`businessKey`**，且为业务系统的**唯一主键**（如订单ID、请假单ID）——无业务键的流程实例无法与业务数据关联，成为“孤立实例”，后续无法通过业务系统查询和管理，是生产环境最常见的问题之一。

### 2. 流程变量：禁用自定义对象，使用基础类型

**禁止将自定义Java对象作为流程变量**，自定义对象会通过Java序列化存储，存在以下风险：

- 类结构修改后（如新增字段），反序列化会失败；
- 序列化后的字节流较大，增加数据库存储和查询开销；
- 跨服务部署时，类加载器不一致会导致序列化失败。
✅ 解决方案：复杂数据序列化为**JSON字符串（String类型）**，读取后再反序列化为对象。

### 3. 操作前置：必做实例/执行流状态校验

所有对流程实例/执行流/变量的操作，**必须先执行2个校验**：

1. `processInstanceExists(instanceId)`：校验实例是否存在（运行中）；
2. `!isProcessInstanceSuspended(instanceId)`：校验实例是否为激活状态。
✅ 目的：避免操作不存在/已挂起/已删除的实例，抛无意义的异常。

### 4. 挂起/激活：区分实例与定义，精准操作

严格区分`RuntimeService`（**实例挂起**）和`RepositoryService`（**定义挂起**）的挂起/激活操作：

- 需**禁止启动新实例**→用`RepositoryService`挂起流程定义；
- 需**暂停运行中实例**→用`RuntimeService`挂起流程实例；
❌ 禁止用`byProcessDefinitionKey`批量挂起实例，避免误操作核心业务流程。

### 5. 信号/消息：按业务场景选择，避免广播风险

- **跨实例通信、批量触发**→用**信号（Signal）**，但需控制触发范围（如按租户ID广播），避免全局广播造成数据库压力；
- **单个实例精准触发**→用**消息（Message）**，这是生产环境的首选，无广播风险；
✅ 信号仅用于真正需要批量触发的场景（如系统级别的状态变更），大部分业务场景用消息即可。

### 6. 删除操作：禁止级联删除，保留历史数据

- 运行中实例删除→使用**基础删除**（`deleteProcessInstance(instanceId, reason)`），仅删运行时数据，**保留历史数据**（审计必备）；
- 级联删除→仅用于**测试数据清理**，生产环境**严禁使用**；
✅ 删除原因必须填写清晰的业务描述，便于后续历史数据追溯。

### 7. 性能优化：批量操作代替单次操作

对流程变量的操作（设置/获取/删除），**优先使用批量方法**（如`setVariables`/`getVariables`），代替多次单次操作（如`setVariable`），减少数据库连接次数，提升性能——单次操作每次都会执行一次数据库SQL，批量操作仅需一次。

### 8. 事务管理：运行时操作必须加事务

`RuntimeService`的所有写操作（启动实例、设置变量、挂起/激活、删除实例、触发信号）**必须放在Spring事务（`@Transactional`）**中，避免因异常导致的**脏数据**（如流程实例已创建，但变量未保存）。
✅ 建议在Service层添加`@Transactional`，事务传播行为使用默认的`REQUIRED`。

### 9. 避免重复启动：通过业务键做唯一约束

同一业务数据（如一个订单）仅需启动一个流程实例，生产环境需**通过业务键做唯一约束**，避免重复启动：

```java
// 启动前查询是否已存在该业务键的运行中实例
long count = runtimeService.createProcessInstanceQuery()
        .processDefinitionKey("orderProcess")
        .businessKey("order_1001")
        .active()
        .count();
if (count == 0) {
    // 仅当不存在时才启动
    runtimeService.startProcessInstanceByKey("orderProcess", "order_1001", variables);
}
```

### 10. 开发/生产环境差异化策略

| 操作 | 开发环境 | 生产环境 |
|------|----------|----------|
| 流程启动 | 可随意启动测试实例，无需业务键 | 强制绑定业务键，做唯一约束，禁止测试实例 |
| 实例删除 | 可随意删除测试实例，无需记录原因 | 禁止随意删除，需加权限控制，记录详细删除原因 |
| 信号触发 | 可全局广播测试 | 禁止全局广播，按租户/业务范围精准触发，加操作日志 |
| 作业执行 | 可手动执行所有定时器 | 仅在作业调度器异常时手动执行，需记录操作日志 |
| 异常处理 | 简化异常处理，打印日志即可 | 捕获所有异常（`FlowableException`/`SQLException`），记录详细日志并告警 |

## 八、RuntimeService 核心API速查（实战90%场景覆盖）

整理日常开发中**最常用的核心API**，按流程运行**生命周期排序**，便于快速查阅和使用：

1. **启动流程实例**（实战首选）：`startProcessInstanceByKey(processKey, businessKey, variables)`；
2. **查询流程实例**（业务关联）：`createProcessInstanceQuery().businessKey(businessKey).active().singleResult()`；
3. **查询流程实例**（精准查询）：`createProcessInstanceQuery().processInstanceId(instanceId).singleResult()`；
4. **设置全局变量**（批量）：`setVariables(instanceId, variables)`；
5. **获取全局变量**（单个）：`getVariable(instanceId, varName, String.class)`；
6. **获取全局变量**（所有）：`getVariables(instanceId)`；
7. **挂起/激活实例**（精准操作）：`suspendProcessInstanceById(instanceId)`/`activateProcessInstanceById(instanceId)`；
8. **删除流程实例**（生产首选）：`deleteProcessInstance(instanceId, deleteReason)`；
9. **触发消息事件**（精准触发）：`messageEventReceived(messageName, executionId)`；
10. **查询当前节点**（流程监控）：`getActiveActivityIds(executionId)`；
11. **状态校验**（前置操作）：`processInstanceExists(instanceId)`/`isProcessInstanceSuspended(instanceId)`；
12. **查询执行流**（并行流程）：`createExecutionQuery().processInstanceId(instanceId).list()`。
