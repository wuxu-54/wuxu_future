# Flowable FormService 全API清单（作用+注意事项+避坑）

`FormService`是Flowable**流程表单管理核心服务**，专门负责**Flowable内置表单**的定义部署、表单数据获取、表单提交与流程/任务联动，所有表单定义操作围绕`ACT_RE_FORMDEF`（表单定义表）展开，**表单数据最终会转换为流程/任务变量**（存储在`ACT_RU_VARIABLE`/`ACT_HI_VARINST`），无单独的表单数据持久化表。

Flowable仅提供**轻量级内置表单能力**，支持**动态表单（dynamicForm，可视化设计）**和**普通表单（regularForm，自定义模板）**，适用于简单的流程表单场景（如快速开发、测试环境）；**生产环境复杂表单场景**（如自定义UI、表单校验、文件上传、复杂数据联动），**建议放弃Flowable内置表单**，采用前端自定义表单+手动将表单数据转为流程变量的方式，仅将`FormService`作为兜底方案。

以下基于**Flowable 6.8.0**（稳定版，兼容JDK8+）整理，完全沿用前序服务的说明格式，**按功能分类**列出核心API，包含**方法名、重载说明、核心作用、注意事项/避坑**，重点标注实战高频API和易踩坑点，纯原生API无封装，明确与`RuntimeService`/`TaskService`的联动关系。

> 通用前置：所有API均通过`ProcessEngine.getFormService()`获取实例，Spring Boot中直接`@Autowired`注入即可，流程引擎为**全局唯一重量级对象**，禁止重复创建。
>
> ```java
> // 纯Java工程
> FormService formService = ProcessEngines.getDefaultProcessEngine().getFormService();
> // Spring Boot工程
> @Autowired
> private FormService formService;
> ```
>
> 核心特性：
>
> 1. 表单定义**需与流程一起部署**（通过`RepositoryService`的`DeploymentBuilder`添加.form资源），无单独的表单部署API；
> 2. 表单提交的参数会**自动转换为流程/任务变量**，底层联动`RuntimeService`启动流程、`TaskService`完成任务；
> 3. 仅支持**String类型的表单参数**，Flowable会根据表单定义的类型自动转换为对应的数据类型（如Integer/Boolean）；
> 4. 内置表单的渲染需依赖Flowable Modeler生成的模板，自定义程度极低，复杂场景不适用。

## 一、表单定义（FormDefinition）管理API（实战基础）

表单定义对应`ACT_RE_FORMDEF`表，是Flowable内置表单的**静态配置载体**（由Flowable Modeler设计生成，后缀为`.form`的XML文件），负责表单的查询、删除等管理操作，**表单部署依赖`RepositoryService`，FormService无单独部署方法**。

### 1. 表单定义查询（实战常用，核心入口）

```java
// 创建表单定义查询器（所有表单定义查询的唯一入口）
FormDefinitionQuery createFormDefinitionQuery();
```

#### `FormDefinitionQuery` 核心筛选/执行方法（链式调用，最终用`list()`/`singleResult()`/`count()`）

| 方法 | 核心作用 | 实战说明/避坑 |
|------|----------|---------------|
| `formDefinitionId(String formDefId)` | 按表单定义ID精确查询 | 表单定义ID格式：`表单key:版本号:随机ID`，与流程定义ID规则一致 |
| `formDefinitionKey(String formKey)` | 按表单key精确查询 | **版本管理核心**，相同key重新部署版本号自动+1，上线后禁止修改 |
| `formDefinitionName(String formName)` | 按表单名称精确查询 | 对应Flowable Modeler中设计的表单名称 |
| `formDefinitionNameLike(String formNameLike)` | 按表单名称模糊查询 | 如`%请假%`查询所有请假相关表单 |
| `latestVersion()` | 仅查询最新版本的表单定义 | 实战必用，避免查询历史冗余版本 |
| `deploymentId(String deploymentId)` | 按部署ID查询 | 表单与流程一起部署，一个部署可包含多个表单定义 |
| `processDefinitionId(String processDefId)` | 按流程定义ID关联查询 | 查某流程定义绑定的表单，实战高频 |
| `orderByFormDefinitionVersionDesc()` | 按版本号倒序排序 | 最新版本在前，便于筛选 |
| `listPage(int first, int max)` | 分页查询 | 大量表单定义时使用，避免内存溢出 |

### 2. 表单定义基础操作

```java
// 根据表单定义ID获取表单定义详情
FormDefinition getFormDefinition(String formDefinitionId);

// 根据表单定义ID获取部署ID
String getDeploymentIdForFormDefinition(String formDefinitionId);
```

- **作用**：获取表单定义的完整信息、关联的部署ID，用于表单与部署/流程的关联追溯。
- **注意事项**：表单定义删除**需通过`RepositoryService.deleteDeployment()`级联删除**（因表单与流程一起部署），`FormService`无单独的删除API。

## 二、表单数据获取API（实战最高频）

此类API是`FormService`的核心能力，用于**获取流程启动表单**和**用户任务表单**的配置与模板数据，为前端渲染表单提供数据源，是开发内置表单的**前置必用操作**，分为**启动表单**（流程启动前加载）和**任务表单**（处理用户任务前加载）两类，边界清晰。

### 1. 流程启动表单数据获取

```java
// 根据流程定义ID获取启动表单数据（核心，实战高频）
StartFormData getStartFormData(String processDefinitionId);

// 根据流程定义ID+租户ID获取启动表单数据（多租户场景）
StartFormData getStartFormData(String processDefinitionId, String tenantId);
```

- **返回值**：`StartFormData`实体，包含**表单模板内容、表单字段配置、流程定义信息、部署资源**等，前端可基于该实体渲染流程启动表单。
- **`StartFormData`核心属性**：
  - `formKey`：表单key，与表单定义key一致；
  - `formProperties`：表单字段列表（`FormProperty`），包含字段名、类型、默认值、是否必填等；
  - `deploymentId`：关联的部署ID；
  - `processDefinition`：关联的流程定义实体。
- **注意事项/避坑**：
  1. 启动表单**与流程定义绑定**，而非流程实例，需传入**流程定义ID**（而非流程实例ID）；
  2. 若流程定义未绑定任何表单，调用会返回空的`StartFormData`，不会抛异常，前端需做判空处理；
  3. `formProperties`中的字段类型为Flowable内置类型（如`string`/`integer`/`boolean`/`date`），前端渲染需适配。

### 2. 用户任务表单数据获取

```java
// 根据任务ID获取任务表单数据（核心，实战高频）
TaskFormData getTaskFormData(String taskId);
```

- **返回值**：`TaskFormData`实体，包含**表单模板内容、表单字段配置、任务信息、流程实例信息**等，前端可基于该实体渲染用户任务处理表单。
- **`TaskFormData`核心属性**：
  - `formKey`：表单key；
  - `formProperties`：表单字段列表（`FormProperty`）；
  - `taskId`：关联的任务ID；
  - `processInstanceId`：关联的流程实例ID。
- **注意事项/避坑**：
  1. 任务表单**与用户任务绑定**，仅适用于`userTask`，自动任务（如`serviceTask`）无对应的任务表单；
  2. 任务完成后，该任务的表单数据不可再通过此API获取，需通过`HistoryService`查询历史变量；
  3. 表单字段会自动回显流程实例中已有的变量值，无需前端手动处理。

### 3. 表单字段属性查询（辅助）

```java
// 根据流程定义ID获取启动表单的字段属性列表
List<FormProperty> getStartFormProperties(String processDefinitionId);

// 根据任务ID获取任务表单的字段属性列表
List<FormProperty> getTaskFormProperties(String taskId);
```

- **作用**：直接获取表单的字段配置列表，无需封装为`StartFormData`/`TaskFormData`，适用于前端仅需字段信息、无需模板的场景。
- **注意事项**：返回的`FormProperty`仅包含字段基础配置，无关联的流程/任务信息，需配合其他API使用。

## 三、表单提交核心API（实战最高频，与流程/任务联动）

此类API是`FormService`的**核心价值所在**，实现**表单提交与流程启动/任务完成的一键联动**，提交的表单参数会**自动转换为流程/任务变量**，底层无需手动调用`RuntimeService.startProcessInstance`或`TaskService.complete`，是内置表单的核心操作。

### 1. 提交启动表单并启动流程

```java
// 提交启动表单，启动流程实例（核心，无业务键）
ProcessInstance submitStartFormData(String processDefinitionId, Map<String, String> properties);

// 提交启动表单，启动流程实例并指定业务键（实战首选，全覆盖）
ProcessInstance submitStartFormData(String processDefinitionId, String businessKey, Map<String, String> properties);

// 多租户场景：提交启动表单并启动流程
ProcessInstance submitStartFormData(String processDefinitionId, String businessKey, Map<String, String> properties, String tenantId);
```

- **参数说明**：
  - `processDefinitionId`：流程定义ID（绑定启动表单）；
  - `businessKey`：流程业务键（与业务系统关联，推荐必传）；
  - `properties`：表单提交的参数（String类型），key为表单字段名，value为字段值；
- **返回值**：`ProcessInstance`流程实例实体，与`RuntimeService`启动流程返回的实例一致。
- **核心逻辑**：表单参数→Flowable自动类型转换→生成流程全局变量→调用`RuntimeService`启动流程→返回流程实例。
- **注意事项/避坑**：
  1. **参数类型转换**：Flowable会根据`StartFormData`中表单字段的定义类型，将String类型的`properties`自动转换为对应类型（如`integer`→Integer、`date`→Date），转换失败会抛`FlowableFormException`；
  2. **业务键必传**：与`RuntimeService`启动流程一致，建议始终指定`businessKey`，便于后续业务追溯；
  3. **启动人绑定**：若需设置流程启动人，仍需在调用前通过`IdentityService.setAuthenticatedUserId`绑定，表单提交不会自动设置；
  4. **事务控制**：该操作包含“参数转换+变量创建+流程启动”，**必须放在Spring事务（`@Transactional`）**中，避免部分操作失败导致脏数据。

### 2. 提交任务表单并完成任务

```java
// 提交任务表单，完成当前用户任务（核心，实战唯一）
void submitTaskFormData(String taskId, Map<String, String> properties);
```

- **参数说明**：
  - `taskId`：用户任务ID（绑定任务表单）；
  - `properties`：表单提交的参数（String类型），key为表单字段名，value为字段值；
- **核心逻辑**：表单参数→自动类型转换→生成任务/流程变量→调用`TaskService.complete`完成任务→引擎自动推进流程实例。
- **注意事项/避坑**：
  1. **任务权限校验**：与`TaskService.complete`一致，任务必须已被认领（assignee为当前用户）或直接指定处理人，否则抛`FlowableTaskException`；
  2. **参数作用域**：提交的参数默认生成为**流程全局变量**，作用于整个流程实例，若需仅作为任务局部变量，需放弃FormService，改用`TaskService`手动完成；
  3. **审批批注**：FormService的表单提交**无添加批注的入口**，若需记录审批意见，需在提交后通过`TaskService.addComment`手动添加，或在表单中增加批注字段，提交后转为变量再生成批注。

## 四、表单资源与模板获取API（实战辅助）

此类API用于获取Flowable内置表单的**渲染模板内容**（如HTML/XML模板），为前端渲染表单提供模板数据源，适用于使用Flowable Modeler设计的动态表单/普通表单，自定义表单场景无需使用。

```java
// 根据部署ID和资源名称获取表单模板的输入流
InputStream getFormResource(String deploymentId, String resourceName);

// 根据表单定义ID获取表单模板的输入流（实战首选，无需关注部署ID）
InputStream getFormDefinitionResource(String formDefinitionId);
```

- **作用**：获取Flowable Modeler生成的表单模板原始字节流（如HTML模板），前端可读取流并渲染表单页面。
- **注意事项/避坑**：
  1. 资源名称需与表单部署时的`.form`文件名称完全一致，可通过`FormDefinition`的`getResourceName()`获取；
  2. 返回的`InputStream`使用后**必须手动关闭**，避免数据库连接泄漏；
  3. 动态表单的模板为Flowable内置的HTML格式，仅支持Flowable自带的渲染组件，自定义样式难度大，生产环境不推荐使用。

## 五、通用辅助API（实战少用）

此类API为表单管理的辅助操作，用于快速获取表单关联信息、判断表单状态，使用频率较低，仅适用于特殊场景的排查与适配。

```java
// 根据流程实例ID获取其启动时绑定的表单定义ID
String getStartFormDefinitionIdByProcessInstance(String processInstanceId);

// 根据任务ID获取其绑定的表单定义ID
String getTaskFormDefinitionId(String taskId);

// 判断流程定义是否绑定了启动表单
boolean hasStartForm(String processDefinitionId);

// 判断任务是否绑定了任务表单
boolean hasTaskForm(String taskId);
```

- **实战实用点**：
  1. `hasStartForm`/`hasTaskForm`：前端渲染前的**前置判空校验**，避免为无表单的流程/任务加载表单页面；
  2. `getStartFormDefinitionIdByProcessInstance`：通过流程实例追溯其启动表单，适用于流程审计场景。

## 六、FormService 通用避坑原则（所有API通用）

结合企业实战经验，整理`FormService`所有操作的核心避坑点，**必须严格遵守**，同时明确**内置表单的适用边界**，避免在复杂场景中强行使用导致开发效率低下、扩展性差等问题。

### 1. 核心边界：轻量场景用内置，复杂场景必自定义

Flowable的`FormService`仅为**轻量级内置能力**，**绝对禁止在生产环境复杂表单场景中使用**，以下场景建议直接放弃FormService，采用**前端自定义表单+手动设置流程变量**的方式：

- 需自定义表单UI、样式、交互逻辑；
- 包含文件上传、富文本编辑、复杂数据联动（如级联下拉）；
- 需自定义表单校验规则（如正则、跨字段校验）；
- 需与第三方表单系统（如帆软、金蝶）集成；
- 需支持移动端自适应、多端表单同步。

✅ 仅以下场景可使用内置表单：测试环境、快速原型开发、小型系统的简单流程表单（如无样式要求的审批单）。

### 2. 表单部署：依赖RepositoryService，与流程一起部署

`FormService`**无单独的表单部署API**，表单定义文件（.form）必须与BPMN文件**一起通过`RepositoryService`部署**，步骤为：

```java
// 流程+表单一起部署，核心：添加.form资源文件
repositoryService.createDeployment()
        .name("请假流程+表单")
        .addClasspathResource("processes/leave-process.bpmn20.xml")
        .addClasspathResource("processes/leave-start.form") // 启动表单
        .addClasspathResource("processes/leave-approve.form") // 任务表单
        .deploy();
```

❌ 禁止单独部署.form文件，避免表单与流程定义失去关联。

### 3. 表单提交：参数仅支持String，需适配类型转换

FormService的表单提交参数`properties`**仅支持`Map<String, String>`**，Flowable会根据表单定义的字段类型自动转换，需注意：

- 日期类型（`date`）的参数需符合**ISO-8601格式**（如`2024-05-20T12:00:00`），否则转换失败；
- 布尔类型（`boolean`）的参数仅支持`true`/`false`（小写），其他值（如`1`/`0`）会转换为`false`；
- 数值类型（`integer`/`long`）的参数需为纯数字字符串，否则抛`NumberFormatException`；
✅ 前端提交时需严格按Flowable的类型规则格式化参数，或在后端手动转换后再提交。

### 4. 联动操作：表单提交≠万能，需配合其他服务补充能力

FormService的表单提交仅实现**参数转变量+流程启动/任务完成**，缺失企业实战所需的核心能力，需配合其他服务补充：

- **流程启动人**：需通过`IdentityService.setAuthenticatedUserId`在表单提交前绑定；
- **审批批注**：需通过`TaskService.addComment`在表单提交后手动添加（或表单中增加批注字段，提交后转为变量再生成批注）；
- **任务委派/转办**：表单提交仅能完成任务，无法实现委派/转办，需通过`TaskService`单独操作；
- **流程变量校验**：表单提交无变量校验能力，需在提交前通过代码手动校验（如必填项、值范围）。

### 5. 历史追溯：表单数据=流程变量，通过HistoryService查询

Flowable**无单独的表单数据历史表**，表单提交的所有数据最终都会转为流程/任务变量，历史表单数据的追溯需通过`HistoryService`实现：

- 查历史表单字段值：`historyService.createHistoricVariableInstanceQuery().processInstanceId(instanceId).list()`；
- 查表单关联的历史任务/流程：`historyService.createHistoricTaskInstanceQuery()`/`createHistoricProcessInstanceQuery()`；
❌ 禁止尝试通过FormService查询历史表单数据，其仅支持运行时表单操作。

### 6. 多租户场景：所有操作必加租户ID，避免数据混用

多租户场景下，表单定义与流程定义一样受租户ID隔离，所有FormService操作**必须指定租户ID**：

- 获取表单数据：使用带`tenantId`的重载方法（如`getStartFormData(processDefinitionId, tenantId)`）；
- 提交表单：使用带`tenantId`的重载方法（如`submitStartFormData(processDefinitionId, businessKey, properties, tenantId)`）；
- 查询表单定义：`formService.createFormDefinitionQuery().tenantId(tenantId)`；
❌ 禁止在多租户场景中使用无租户ID的方法，避免跨租户查询/操作表单数据。

### 7. 异常处理：捕获表单专属异常，做精细化错误提示

FormService操作会抛出**表单专属异常`FlowableFormException`**，同时会抛出流程/任务相关的异常（如`FlowableTaskException`/`FlowableProcessEngineException`），开发时需精细化捕获：

- `FlowableFormException`：表单相关错误（如类型转换失败、表单不存在）；
- `FlowableTaskException`：任务相关错误（如任务已完成、无权限操作）；
- `FlowableProcessEngineException`：引擎底层错误（如流程定义不存在、挂起）；
✅ 捕获异常后需向前端返回明确的错误信息，避免统一返回“操作失败”。

## 七、FormService 核心API速查（实战90%场景覆盖）

整理日常开发中**最常用的核心API**，按**内置表单的使用流程排序**，便于快速查阅和使用，覆盖表单渲染、提交、联动的核心场景：

1. **判断流程是否有启动表单**：`hasStartForm(processDefinitionId)`；
2. **获取启动表单数据（渲染）**：`getStartFormData(processDefinitionId)`；
3. **提交启动表单并启动流程（带业务键）**：`submitStartFormData(processDefinitionId, businessKey, properties)`；
4. **判断任务是否有任务表单**：`hasTaskForm(taskId)`；
5. **获取任务表单数据（渲染+回显）**：`getTaskFormData(taskId)`；
6. **提交任务表单并完成任务**：`submitTaskFormData(taskId, properties)`；
7. **仅获取表单字段配置**：`getStartFormProperties(processDefinitionId)`/`getTaskFormProperties(taskId)`；
8. **获取表单模板资源**：`getFormDefinitionResource(formDefinitionId)`；
9. **通过流程实例追溯启动表单ID**：`getStartFormDefinitionIdByProcessInstance(instanceId)`；
10. **表单定义精准查询**：`createFormDefinitionQuery().formDefinitionKey(formKey).latestVersion().singleResult()`。
