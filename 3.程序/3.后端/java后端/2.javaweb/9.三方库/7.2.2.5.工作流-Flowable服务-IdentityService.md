# Flowable IdentityService 全API清单（作用+注意事项+避坑）

`IdentityService`是Flowable**身份认证与权限管理核心服务**，专门负责**用户（User）、用户组（Group/角色）、用户-组关联关系（Membership）**的全生命周期CRUD操作，同时提供**流程启动人绑定、内置简单身份认证**能力，所有操作围绕Flowable**身份表（`ACT_ID_*`）**展开（`ACT_ID_USER`/用户表、`ACT_ID_GROUP`/用户组表、`ACT_ID_MEMBERSHIP`/用户-组关联表）。

其**核心功能边界**需明确：Flowable的内置身份服务为**轻量级实现**，仅提供基础的用户/组管理和简单密码校验，**无会话管理、角色继承、细粒度权限控制、Token认证**等企业级特性。因此**生产环境复杂场景（如统一认证、多系统权限互通）**，建议集成Spring Security、OAuth2、CAS等专业认证框架，仅将`IdentityService`作为**流程任务分配的用户/组数据源**；**轻量场景（如小型系统、测试环境）**可直接使用其完整能力。

以下基于**Flowable 6.8.0**（稳定版，兼容JDK8+）整理，完全沿用前序服务的说明格式，**按功能分类**列出核心API，包含**方法名、重载说明、核心作用、注意事项/避坑**，重点标注实战高频API和易踩坑点，纯原生API无封装，明确与外部认证框架的协作原则。

> 通用前置：所有API均通过`ProcessEngine.getIdentityService()`获取实例，Spring Boot中直接`@Autowired`注入即可，流程引擎为**全局唯一重量级对象**，禁止重复创建。
>
> ```java
> // 纯Java工程
> IdentityService identityService = ProcessEngines.getDefaultProcessEngine().getIdentityService();
> // Spring Boot工程
> @Autowired
> private IdentityService identityService;
> ```
>
> 核心特性：
>
> 1. 无单独的**更新**API，新增/更新均通过`saveUser`/`saveGroup`实现（根据ID是否存在判断）；
> 2. 用户密码支持内置加密，生产环境建议自定义加密策略；
> 3. `setAuthenticatedUserId`是**流程启动人绑定**的核心API，与`HistoryService`的`startedBy`查询强关联；
> 4. 身份表无外键约束，删除用户/组前需手动删除关联关系，否则抛异常。

## 一、用户（User）管理API（实战核心）

用户管理是`IdentityService`的基础能力，对应历史表`ACT_ID_USER`，负责用户的创建、查询、保存（新增/更新）、删除、密码管理，是流程任务分配、启动人绑定的基础。

### 1. 核心基础方法（新增/更新/删除）

```java
// 创建空的User对象，需设置ID后通过saveUser持久化
User newUser(String userId);

// 保存用户：ID不存在则**新增**，ID存在则**更新**（无单独update方法，实战核心）
void saveUser(User user);

// 根据用户ID删除用户（物理删除，生产谨慎）
void deleteUser(String userId);
```

- **`User`对象核心属性**：`id`（用户唯一ID，必填）、`firstName`（名）、`lastName`（姓）、`email`（邮箱）、`password`（密码，密文存储），可通过`user.setXxx()`设置。
- **注意事项/避坑**：
  1. `newUser`仅创建内存对象，**必须调用`saveUser`才会持久化到数据库**；
  2. 无单独的`updateUser`方法，修改用户信息时，先通过`createUserQuery`查询到`User`对象，修改属性后再次调用`saveUser`即可；
  3. 删除用户前**必须先删除其所有关联关系**（用户-组、任务候选人），否则抛`FlowableIdentityException`；
  4. 密码设置：直接通过`user.setPassword()`设置的密码，**默认以明文存储**（测试环境），生产环境需开启**密码加密**（见下文通用配置）。

### 2. 用户查询（实战高频，核心入口）

```java
// 创建用户查询器（所有用户查询的唯一入口）
UserQuery createUserQuery();
```

#### `UserQuery` 核心筛选/执行方法（链式调用，最终用`list()`/`singleResult()`/`count()`）

| 方法 | 核心作用 | 实战说明/避坑 |
|------|----------|---------------|
| `userId(String userId)` | 按用户ID精确查询 | 最常用，单个用户信息查询的前置操作 |
| `userName(String userName)` | 按用户名精确查询 | 此处`userName`对应`User`对象的`id`（Flowable无单独的用户名属性，用id作为唯一标识） |
| `userNameLike(String userNameLike)` | 按用户ID模糊查询 | 如`%zhangsan%`，批量查询用户时常用 |
| `email(String email)` | 按邮箱精确查询 | 适用于通过邮箱查找用户 |
| `emailLike(String emailLike)` | 按邮箱模糊查询 | 如`%@company.com%`，查询企业内所有用户 |
| `orderByUserId()` | 按用户ID排序 | 可搭配`asc()`/`desc()`，批量查询排序用 |
| `listPage(int first, int max)` | 分页查询 | 大量用户时必用，避免内存溢出 |

### 3. 密码管理API（实战常用，含校验/修改）

```java
// 检查用户密码是否正确（内置简单校验，生产轻量场景用）
boolean checkPassword(String userId, String password);

// 为用户设置密码（直接修改数据库，覆盖原有密码）
void setUserPassword(String userId, String password);
```

- **作用**：实现用户密码的校验和修改，是内置身份认证的核心方法。
- **注意事项/避坑**：
  1. `checkPassword`会**自动适配加密策略**：若密码为密文存储，会用对应加密算法校验明文密码，无需手动加密；
  2. `setUserPassword`直接修改数据库密码，**生产环境需添加权限控制**（仅管理员可操作）；
  3. 该方法仅适用于Flowable内置身份认证，集成外部认证框架时，密码校验由外部框架负责，此API作废。

## 二、用户组（Group）管理API（实战核心）

用户组即**角色/部门**（如经理组、财务组、管理员组），对应历史表`ACT_ID_GROUP`，负责组的创建、查询、保存（新增/更新）、删除，是**流程任务候选组分配**的核心依据，与用户的关联关系通过`Membership`API实现。

### 1. 核心基础方法（新增/更新/删除）

```java
// 创建空的Group对象，需设置ID后通过saveGroup持久化
Group newGroup(String groupId);

// 保存组：ID不存在则**新增**，ID存在则**更新**（无单独update方法）
void saveGroup(Group group);

// 根据组ID删除组（物理删除，生产谨慎）
void deleteGroup(String groupId);
```

- **`Group`对象核心属性**：`id`（组唯一ID，必填）、`name`（组名称，如“经理组”）、`type`（组类型，Flowable内置标识，如`assignment`表示**任务分配组**，实战常用）。
- **注意事项/避坑**：
  1. 与用户管理一致，`newGroup`仅创建内存对象，**必须调用`saveGroup`才会持久化**；
  2. 无单独的`updateGroup`方法，修改组信息时查询后重新`saveGroup`即可；
  3. 删除组前**必须先删除其所有用户-组关联关系**，否则抛`FlowableIdentityException`；
  4. 组类型`type`建议使用`assignment`（Flowable默认的任务分配组类型），避免自定义类型导致任务候选组筛选失败。

### 2. 组查询（实战高频，核心入口）

```java
// 创建组查询器（所有组查询的唯一入口）
GroupQuery createGroupQuery();
```

#### `GroupQuery` 核心筛选/执行方法（链式调用，最终用`list()`/`singleResult()`/`count()`）

| 方法 | 核心作用 | 实战说明/避坑 |
|------|----------|---------------|
| `groupId(String groupId)` | 按组ID精确查询 | 最常用，单个组信息查询的前置操作 |
| `groupName(String groupName)` | 按组名称精确查询 | 如`groupName("经理组")` |
| `groupNameLike(String groupNameLike)` | 按组名称模糊查询 | 如`%财务%`，批量查询组时常用 |
| `groupType(String groupType)` | 按组类型精确查询 | 实战高频，如`groupType("assignment")`筛选所有任务分配组 |
| `orderByGroupId()`/`orderByGroupName()` | 按组ID/名称排序 | 搭配`asc()`/`desc()`使用 |
| `listPage(int first, int max)` | 分页查询 | 大量组时必用 |

## 三、用户-组关联（Membership）API（实战最高频）

用户-组关联即**用户分配到指定角色/部门**，对应历史表`ACT_ID_MEMBERSHIP`，是实现**基于角色的任务分配**的核心（如BPMN中设置候选组为“经理组”，该组下所有用户均可认领任务），也是`IdentityService`实战中使用频率最高的API。

### 核心方法（创建/删除/查询关联关系）

```java
// 为用户分配组：创建用户-组关联关系（实战最高频）
void createMembership(String userId, String groupId);

// 解除用户-组关联关系
void deleteMembership(String userId, String groupId);

// 查询某用户所属的所有组（实战高频，如查“某用户的所有角色”）
List<Group> getGroupsForUser(String userId);

// 查询某组下的所有用户（实战高频，如查“经理组的所有用户”）
List<User> getUsersInGroup(String groupId);
```

- **作用**：实现用户与组的多对多关联，是Flowable**基于角色的权限控制**的核心，与`TaskService`的候选组筛选强关联。
- **注意事项/避坑**：
  1. **关联唯一性**：同一用户-组组合只能创建一次关联，重复调用`createMembership`会直接抛`FlowableIdentityException`，**生产环境必须做前置校验**（通过`getGroupsForUser`判断）；
  2. **删除关联的前提**：用户/组未被删除，且关联关系存在，否则抛异常；
  3. **与任务候选组的联动**：BPMN中`userTask`的`flowable:candidateGroups`设置为组ID后，该组下所有用户（通过`createMembership`关联）均可通过`TaskService.createTaskQuery().candidateGroup()`查询到该任务；
  4. 无批量关联API，需批量分配用户到组时，循环调用`createMembership`即可，建议添加事务控制。

## 四、身份认证与流程启动人API（实战核心，与其他服务联动）

这是`IdentityService`与`RuntimeService`/`HistoryService`联动的核心能力，包含**Flowable内置简单身份认证**和**流程启动人绑定**，其中**流程启动人绑定**是企业实战中**必用API**，与历史流程的追溯强关联。

### 1. 流程启动人绑定（实战最高频，核心）

```java
// 为当前线程设置认证用户ID：即流程启动人（与HistoryService的startedBy强关联）
void setAuthenticatedUserId(String userId);

// 清除当前线程的认证用户ID（避免线程污染，实战必备）
void clearAuthenticatedUserId();
```

- **核心作用**：绑定**流程实例的启动人**，设置后通过`RuntimeService`启动的流程，其启动人会被记录到`ACT_HI_PROCINST`的`START_USER_ID_`字段，后续可通过`HistoryService.createHistoricProcessInstanceQuery().startedBy(userId)`查询该用户启动的所有流程。
- **注意事项/避坑**：
  1. **调用时机**：**必须在启动流程前调用**，且仅作用于**当前线程**，流程启动后建议立即调用`clearAuthenticatedUserId`清除，避免线程池复用导致的**启动人串号**（核心坑点）；
  2. **实战标准写法**：

     ```java
     try {
         // 绑定启动人
         identityService.setAuthenticatedUserId("zhangsan");
         // 启动流程
         runtimeService.startProcessInstanceByKey("leaveProcess", "leave_1001", variables);
     } finally {
         // 无论是否成功，都清除当前线程的认证用户ID
         identityService.clearAuthenticatedUserId();
     }
     ```

  3. 启动人ID必须是`ACT_ID_USER`中存在的用户ID，否则历史表中`START_USER_ID_`为该值，但无法关联到用户信息；
  4. 若未调用该方法，流程启动人为`null`，`HistoryService`无法通过`startedBy`筛选，**生产环境强制要求绑定**。

### 2. 内置简单身份认证（轻量场景用）

```java
// 内置用户认证：校验用户ID和密码是否正确，返回认证结果
boolean authenticate(String userId, String password);
```

- **作用**：Flowable内置的极简身份认证，仅校验`ACT_ID_USER`中的用户ID和密码，无会话管理、Token生成等能力。
- **注意事项/避坑**：
  1. 仅适用于**测试环境/轻量小型系统**，企业级系统**禁止使用**，需集成Spring Security/OAuth2/CAS等专业认证框架；
  2. 认证成功后仅返回`boolean`，无任何会话信息，需自行实现会话管理；
  3. 与`checkPassword`功能一致，`authenticate`是更上层的认证封装，底层仍调用`checkPassword`。

## 五、通用辅助API（实战辅助，少用）

此类API为用户/组管理的辅助操作，用于快速获取用户/组详情、判断关联关系是否存在，使用频率较低，但可提升代码健壮性。

```java
// 根据用户ID获取用户完整实体（不存在返回null）
User getUser(String userId);

// 根据组ID获取组完整实体（不存在返回null）
Group getGroup(String groupId);

// 判断用户是否属于某组（校验关联关系是否存在，实战前置校验用）
boolean isUserInGroup(String userId, String groupId);
```

- **实战实用点**：
  1. `getUser`/`getGroup`可替代`createUserQuery().userId().singleResult()`，简化单个用户/组的查询代码；
  2. `isUserInGroup`是`createMembership`的**前置必用校验**，避免重复创建关联关系抛异常，示例：

     ```java
     if (!identityService.isUserInGroup("zhangsan", "managerGroup")) {
         identityService.createMembership("zhangsan", "managerGroup");
     }
     ```

## 六、IdentityService 通用避坑原则（所有API通用）

结合企业实战经验，整理`IdentityService`所有操作的核心避坑点，**必须严格遵守**，否则会导致身份数据混乱、流程启动人串号、任务分配失败、权限泄露等严重问题，同时明确与外部认证框架的协作原则。

### 1. 核心定位：轻量场景自用，复杂场景仅做流程数据源

**Flowable的内置IdentityService并非企业级认证框架**，无会话管理、角色继承、细粒度权限、统一认证等能力，生产环境需按场景区分使用：

- **轻量场景**（测试/小型系统）：可直接使用其完整能力（用户/组管理+密码认证+流程启动人绑定）；
- **复杂场景**（中大型系统/多系统互通）：**仅将IdentityService作为流程任务分配的用户/组数据源**，用户认证、权限管理由**Spring Security/OAuth2/CAS**等外部框架负责，禁止混用两套身份体系。

### 2. 流程启动人：强制绑定+finally清除，避免线程污染

- 启动流程时**必须绑定启动人**（`setAuthenticatedUserId`），保证历史流程的可追溯性；
- **无论流程启动是否成功，都要在finally块中调用`clearAuthenticatedUserId`**，清除当前线程的认证用户ID，避免线程池复用导致的**启动人串号**（生产环境最常见的坑点）。

### 3. 关联关系：操作前必做唯一性校验，避免抛异常

- 创建用户-组关联（`createMembership`）前，必须通过`isUserInGroup(userId, groupId)`校验关联关系是否存在；
- 删除用户/组前，必须先通过`getGroupsForUser`/`getUsersInGroup`查询关联关系，并循环调用`deleteMembership`删除，否则抛`FlowableIdentityException`。

### 4. 密码管理：生产环境必须开启加密，禁止明文存储

Flowable默认将用户密码**明文存储**在`ACT_ID_USER`的`PWD_`字段，存在严重的安全风险，**生产环境必须开启密码加密**，核心配置如下（Spring Boot/纯Java通用）：

#### Spring Boot 配置（application.yml）

```yaml
flowable:
  # 开启用户密码加密
  identity:
    password:
      encoder:
        enabled: true
        # 加密算法：支持md5/sha256/BCrypt（推荐BCrypt，不可逆加密）
        algorithm: BCrypt
```

#### 纯Java 配置（flowable.cfg.xml）

```xml
<bean id="processEngineConfiguration" class="org.flowable.engine.impl.cfg.StandaloneProcessEngineConfiguration">
    <!-- 其他配置（数据源/字体） -->
    <property name="passwordEncoder" ref="bCryptPasswordEncoder"/>
</bean>
<!-- 配置BCrypt加密器 -->
<bean id="bCryptPasswordEncoder" class="org.flowable.idm.api.password.BCryptPasswordEncoder"/>
```

> 注意：加密策略一旦开启，**原有明文密码将失效**，需重新设置用户密码；推荐使用**BCrypt**（不可逆加密），禁止使用md5/sha256（可逆加密，仍有安全风险）。

### 5. 数据操作：生产环境添加权限控制，禁止无限制操作

`IdentityService`的所有写操作（创建/修改/删除用户/组、绑定关联关系）**必须添加细粒度的权限控制**：

- 仅管理员可执行用户/组的创建、删除、密码修改操作；
- 普通用户仅可查看自身/所属组的信息，无修改/删除权限；
- 避免前端直接暴露API，防止恶意操作导致身份数据混乱。

### 6. 无更新API：修改数据需“查询-修改-重保存”

Flowable的`IdentityService`**无单独的update方法**，修改用户/组信息的标准流程为：

1. 通过`createUserQuery`/`getUser`查询到目标用户/组对象；
2. 通过`user.setXxx()`/`group.setXxx()`修改属性；
3. 再次调用`saveUser`/`saveGroup`完成持久化。
✅ 示例（修改用户邮箱）：

```java
User user = identityService.getUser("zhangsan");
if (user != null) {
    user.setEmail("zhangsan@company.com");
    identityService.saveUser(user);
}
```

### 7. 多租户场景：用户/组需按租户隔离，避免数据混用

多租户场景下，Flowable的身份表**无内置租户ID字段**，需通过**自定义扩展**或**表名隔离**实现用户/组的租户隔离：

1. 自定义扩展：为`ACT_ID_USER`/`ACT_ID_GROUP`添加`TENANT_ID_`字段，通过自定义查询器筛选；
2. 表名隔离：为每个租户创建独立的身份表（如`ACT_ID_USER_TENANT1`），通过Flowable的多租户配置实现。
❌ 禁止多租户共享一套用户/组数据，避免任务分配、流程追溯时的数据泄露/混乱。

## 七、IdentityService 核心API速查（实战90%场景覆盖）

整理日常开发中**最常用的核心API**，按**企业实战使用频率排序**，便于快速查阅和使用，覆盖流程启动人绑定、用户/组管理、任务分配的核心场景：

1. **绑定流程启动人**：`setAuthenticatedUserId(userId)`（启动前）+ `clearAuthenticatedUserId()`（finally中）；
2. **创建用户**：`identityService.saveUser(identityService.newUser("zhangsan").setFirstName("张").setLastName("三"))`；
3. **创建组**：`identityService.saveGroup(identityService.newGroup("managerGroup").setName("经理组").setType("assignment"))`；
4. **用户分配到组**：`if(!isUserInGroup(u,g)) createMembership(u,g)`；
5. **查询某用户的所有组**：`getGroupsForUser(userId)`；
6. **查询某组的所有用户**：`getUsersInGroup(groupId)`；
7. **查询单个用户**：`getUser(userId)` / `createUserQuery().userId(userId).singleResult()`；
8. **校验用户密码**：`checkPassword(userId, password)`（轻量场景）；
9. **解除用户-组关联**：`deleteMembership(userId, groupId)`；
10. **判断用户是否在某组**：`isUserInGroup(userId, groupId)`（前置校验）。
